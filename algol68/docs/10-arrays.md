# 10 · 数组与行（multiple / row）

> 示例：[`examples/10_arrays/10_arrays.a68`](../examples/10_arrays/10_arrays.a68)
> 运行：`./run-all.sh 10`

Algol 68 的"数组"叫**行（row）**，类型层面叫 multiple 值。它与 C 系语言最大的
不同有三处：**边界是类型的一部分**（`[1:5] INT` 和 `[0:3] INT` 是两种界）、
**下界可以是任何整数**（不是必须从 0 或 1 开始）、**切片会重新基化**。本章按示例逐节展开。

## 1. 定长行：`[下界:上界] 模 名 := (初值行列)`

```algol68
[1:5] INT a := (10, 20, 30, 40, 50);
print(("a[3] = ", whole(a[3], 0), "   LWB a = ", whole(LWB a, 0),
       "   UPB a = ", whole(UPB a, 0), new line));
```

- `[1:5]` 是**边界（bounds）**：下界 1、上界 5，共 5 个元素。
- 初值 `(10, 20, 30, 40, 50)` 是一个**行显示（row display）**——逗号分隔的值列表。
- `LWB a` 取下界（lower bound），`UPB a` 取上界（upper bound）。实测输出
  `a[3] = 30   LWB a = 1   UPB a = 5`。
- 元素访问写下标 `a[3]`；**没有** C 那种"名字退化成指针"的玩法，行是值。

## 2. 就地改元素，界不变

```algol68
a[2] := 99;                          # 就地改元素
print(("a[2] 改成 99 后 = ", whole(a[2], 0), new line));
assert(a[2] = 99 AND UPB a = 5, "元素可改，上界不变");
```

定长行的元素可以随时改写，但 `LWB`/`UPB` 恒定——**定长行不能增长或缩短**，
要变长得用 FLEX（§6）。这次改动会"污染"后面的输出：§7 的 `sum_row(a) = 229`
正是因为 `a[2]` 已经变成 99。

## 3. 坑：行显示的隐含下界恒为 1

`(1,2,3,4)` 这样的行显示，其隐含边界**永远是 `[1:4]`**。给一个非 1 下界的行整体
赋行显示，边界对不上直接崩：

```algol68
# 实测 [0:3] INT z := (1,2,3,4); → runtime error: rows have different bounds
[0:3] INT z; z[0] := 1; z[1] := 2; z[2] := 3; z[3] := 4;
print(("z 下界 0：z[0] = ", whole(z[0], 0), "  LWB z = ", whole(LWB z, 0), new line));
```

本机复跑确认，报错原文是：

```text
a68g: runtime error: 1: rows have different bounds, in VOID closed-clause ...
```

对策（示例采用后者）：要么把声明写成 `[1:4]` 与行显示一致，要么**逐元素赋值**。
下界 0 完全合法——实测 `LWB z = 0`、`z[3] = 4`。

## 4. 切片 `a[i:j]`：结果重新基化到 `[1:n]`

```algol68
[1:5] INT b := (10, 20, 30, 40, 50);
print(("b[2:4] 的元素 = ", whole(b[2:4][1], 0), " ", whole(b[2:4][2], 0),
       " ", whole(b[2:4][3], 0), new line));
print(("UPB b[2:4] = ", whole(UPB b[2:4], 0), "  (是 3 不是 4：切片基化到 1)", new line));
```

`b[2:4]` 取出第 2..4 个元素，但**切片结果的界不是 `[2:4]`，而是重新基化成
`[1:3]`**——所以要写 `b[2:4][1]`（得 20）而不是 `b[2:4][2]`。实测 `UPB b[2:4] = 3`。
这是从别的语言转过来最容易踩的坑之一。

## 5. 多维行：`[r1:r2, c1:c2]`

```algol68
[1:2, 1:3] INT m := ((1, 2, 3), (4, 5, 6));
print(("m[1,2] = ", whole(m[1, 2], 0), "   m[2,3] = ", whole(m[2, 3], 0), new line));
m[2, 1] := 40;
INT msum := 0;
FOR i TO 2 DO FOR j TO 3 DO msum +:= m[i, j] OD OD;
print(("二维求和 = ", whole(msum, 0), new line));
```

- 声明里逗号分隔两维边界：`[1:2, 1:3]` 是 2 行 3 列。
- 初值是**嵌套的行显示**：`((1,2,3), (4,5,6))`，外层每元素又是一行。
- 访问写 `m[1, 2]`（一个下标框里逗号分隔），实测 `m[1,2] = 2   m[2,3] = 6`。
- 双层 `FOR` 遍历求和：把 `m[2,1]` 从 4 改成 40 之后，总和 = 1+2+3+**40**+5+6 =
  **57**，与实测一致。

## 6. FLEX 行：运行时整体改大小

```algol68
FLEX [1:1] INT g := (1);
print(("初始 UPB g = ", whole(UPB g, 0), new line));
g := (1, 2, 3, 4);                   # 整体重赋，界随之改变
print(("重赋后 UPB g = ", whole(UPB g, 0), "  g[4] = ", whole(g[4], 0), new line));
```

`FLEX` 声明的行可以**整体重新赋值成不同长度的行显示**，边界跟着变：实测
`UPB g` 从 1 变 4，`g[4] = 4`。注意 FLEX 改大小的方式只有"整体重赋"——
`g[5] := x` 这种越界单点写并不在示例演示范围内，增长请整体重赋。

## 7. 行整体运算与"合规过程"

**整体赋值是值拷贝**。本机实测：

```algol68
[1:5] INT c; c := a; a[1] := 99;
# c[1] 仍是 10——整行赋值拷的是值，不是引用
```

想把过程写成"任何界的行都能传"，形参写**空界** `[] INT`，这叫合规过程
（conformistic）——实参传进来时界被"抹平"适配：

```algol68
PROC sum_row = ([] INT xs) INT:
  ( INT t := 0; FOR k FROM LWB xs TO UPB xs DO t +:= xs[k] OD; t );
print(("sum_row(a) = ", whole(sum_row(a), 0), new line));
print(("sum_row(z) = ", whole(sum_row(z), 0), "  (下界 0 也能用)", new line));
```

循环写 `FOR k FROM LWB xs TO UPB xs` 而不是 `FOR k TO 5`，过程就不依赖具体界。
实测 `sum_row(a) = 229`（10+99+30+40+50，§2 改过的 a）、`sum_row(z) = 10`
（下界 0 的 z：1+2+3+4）。同一个过程吃下了两种不同界的行。

## 8. 行不止放数值：STRING 行

```algol68
[1:3] STRING names := ("Ada", "Bob", "Cid");
print(("names[2] = ", names[2], new line));
```

行的元素可以是任何模——STRING、STRUCT（第 11 章）都行。实测 `names[2] = Bob`。

## 9. 坑：直接 print 一个 INT 行是"宽格式带符号"

```algol68
# 实测 print((a)) 打成 "        +10        +99 ..."（每元素右对齐占宽）
print(("紧凑打印 a: "));
FOR k FROM LWB a TO UPB a DO print((whole(a[k], 0), " ")) OD;
print((new line));
```

`print((a))` 把整行按 transput 默认格式输出：每个 INT 元素**带 `+` 号、右对齐、
各占固定宽度**（本机实测每元素 11 字符，如 `        +10`）。想要紧凑输出，就像
示例这样逐元素套 `whole(x, 0)` 转最短字符串再打。实测紧凑行为
`紧凑打印 a: 10 99 30 40 50 `（末尾跟一个空格，因为循环里每元素后都打了 `" "`）。

## 10. 实测输出（本机 a68g 3.13.3）

`./run-all.sh 10` 双通道运行：check 通道 `a68g --warnings --notices`（解释器，全

一致**，且退出码 0、stderr 为空、含结束标记。check 通道真实 stdout：


## 11. 坑位清单（实测）

1. **行显示的隐含下界恒为 1**：`[0:3] INT z := (1,2,3,4)` 报
   `runtime error: rows have different bounds`；非 1 下界要逐元素赋值（§3）。
2. **切片重新基化到 `[1:n]`**：`b[2:4]` 的元素是 `b[2:4][1..3]`，`UPB b[2:4] = 3`
   不是 4（§4）。
3. **定长行不能变长**：改大小必须用 `FLEX` 行整体重赋（§6）。
4. **整行赋值是值拷贝**：`c := a` 之后改 `a` 不影响 `c`（§7）。
5. **直接 print INT 行是宽格式**：每元素带 `+` 号右对齐占宽；紧凑输出逐元素套
   `whole(x, 0)`（§9，另见第 09 章 `map` 那行输出）。
6. **遍历行用 `FOR k FROM LWB xs TO UPB xs`**：写 `[] INT` 形参的合规过程才能
   适配任意下界（§7）。
7. **多维行下标写在一个框里**：`m[1, 2]`，不是 `m[1][2]`（§5）。
