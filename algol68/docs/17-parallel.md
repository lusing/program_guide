# 17 · 并行：PAR、SEMA 信号量、竞态与确定性

> 示例：[`examples/17_parallel/17_parallel.a68`](../examples/17_parallel/17_parallel.a68)
> 运行：`./run-all.sh 17`

Algol 68 是极少数把**并行写进语言本体**的老语言（1968 年！）。它不需要线程库、不需要
`#include <pthread.h>`——两个关键字就够了：

- **`PAR`**（parallel clause）：`PAR (子句1, 子句2, ...)` 让多个封闭子句**并发执行**，
  全部完成后在 PAR 结束处**汇合（join）**。
- **`SEMA`**（semaphore，信号量）：并发子句之间的**同步原语**。`DOWN s` 获取一个许可
  （没有许可就阻塞等待），`UP s` 释放一个许可。

本章用五个递进的小节把并行讲透：汇合语义 → 不相交写入的确定性 → 切片并行 →
SEMA 互斥 → SEMA 握手，最后讲清**竞态（race）为什么阴险**——以及为什么本示例在
check（解释器）与 release（-O2 编译到 C）两条通道下 stdout 仍然**逐字节一致**。

## 1. PAR 基本形：并发执行，结束处汇合

语法是 `PAR (u1, u2, ...)`——操作数是一个**并列子句**（collateral clause），每个成分
都是一个封闭子句（通常写成 `BEGIN ... END`，简单赋值可直接写）：

```algol68
INT a := 0, b := 0, c := 0;
PAR (a := 10, b := 20, c := 30);            # 三个子句并发，PAR 返回时都已完成 #
print(("PAR 汇合后：a=", whole(a, 0), " b=", whole(b, 0), " c=", whole(c, 0), new line));
assert(a = 10 AND b = 20 AND c = 30, "PAR 汇合后各子句结果都可见");
```

两条语义要点：

1. **汇合（join）是 PAR 自带的**：`PAR (...)` 这个单元求值结束时，所有子句都已完成。
   所以紧跟 PAR 之后的 `print`/`assert` 一定能看到每个子句写入的结果——不需要任何
   额外的"等待"代码。
2. **语法坑**：并列成分直接放进**圆括号**，用逗号分隔。不是 `PAR BEGIN ... AND ... END`
   之类的形态；a68g 只认 `PAR ( ... )` 这种并列形式。

> 本章的 `assert` 是自定义断言过程（第 18 章的纪律）：条件为假时把 `FAIL: 消息` 写进
> `stand error` 并给 `fails` 计数——**失败信号走 stderr**，让验证脚本能判定
> （a68g 没有可移植的自定义退出码设施，第 18 章细讲）。

## 2. 并行"独立计算"：不相交写入保证确定性

并行的第一纪律：**并行子句里不要 print**。多个子句同时往 stdout 写，输出会**交错**，
交错方式取决于调度——每次运行的字节都可能不同，双通道逐字节比对必然失败。

正确做法：**并行只算，各写各的（互不相交的）变量；PAR 汇合之后再统一 print**：

```algol68
INT s1 := 0, s2 := 0;
PAR (
  BEGIN FOR i TO 1000 DO s1 +:= i OD END,        # 子句1：1+2+...+1000 #
  BEGIN FOR i TO 1000 DO s2 +:= 2 * i OD END     # 子句2：2+4+...+2000 #
);
print(("并行独立求和：s1=", whole(s1, 0), " s2=", whole(s2, 0), new line));
assert(s1 = 500500, "1..1000 之和");
assert(s2 = 1001000, "2..2000 偶数和");
```

**为什么这样就是确定性的？** 子句 1 只写 `s1`，子句 2 只写 `s2`——两个变量**不相交**，
谁先谁后、交错与否都不影响各自的最终值。汇合后统一打印，字节序列就与调度无关。
这是并行设计里成本最低的确定性来源：**能不相交就不共享**。

## 3. 并行处理数组的不同切片：下标不相交 → 无需加锁

不相交原则同样适用于数组——只要各子句写的**下标区间不重叠**，就无需任何锁：

```algol68
[1:8] INT data;
FOR i TO 8 DO data(i) := i * i OD;
[1:8] INT out;
PAR (
  BEGIN FOR i TO 4 DO out(i) := data(i) * 10 OD END,        # 前半 [1:4] #
  BEGIN FOR i FROM 5 TO 8 DO out(i) := data(i) * 10 OD END  # 后半 [5:8] #
);
INT checksum := 0;
FOR i TO 8 DO checksum +:= out(i) OD;
print(("并行切片处理 checksum=", whole(checksum, 0), new line));
# data = 1,4,9,16,25,36,49,64；×10 求和 = (1+4+9+16+25+36+49+64)*10 = 204*10 #
assert(checksum = 2040, "切片各写各的下标，结果确定");
```

两个子句都**读** `data`（只读共享是安全的），但分别只写 `out(1..4)` 和 `out(5..8)`
——写入集合不相交，结果必然确定。`checksum` 的求和放在汇合之后，读到的是完整的 `out`。

## 4. SEMA 信号量：互斥保护共享变量

有时不得不共享——比如多个子句更新**同一个**计数器。这时用 `SEMA`：

```algol68
# 声明并初始化：SEMA mtx := LEVEL n;（n 是初始许可数，通常 1 = 互斥锁）。 #
SEMA mtx := LEVEL 1;
INT shared := 0;
PROC bump = (INT times) VOID:
  BEGIN
    INT k := 0;
    WHILE k < times DO
      k +:= 1;
      DOWN mtx;                             # 进入临界区 #
      shared +:= 1;                         # 共享变量自增 #
      UP mtx                                # 离开临界区 #
    OD
  END;
PAR (bump(2000), bump(2000), bump(2000), bump(2000));   # 4 个子句各加 2000 次 #
print(("SEMA 保护的共享计数器 shared=", whole(shared, 0), new line));
assert(shared = 8000, "4×2000，加锁后结果精确");
```

工作机制：

- `SEMA mtx := LEVEL 1;`——初始 **1 个许可**，即经典**互斥锁（mutex）**。
- `DOWN mtx`：获取许可。许可为 0 时**阻塞**，直到别的子句 `UP`。
- `UP mtx`：释放许可，唤醒一个等待者（若有）。
- `DOWN ... shared +:= 1 ... UP` 把共享变量的读-改-写包成**临界区**：任意时刻最多
  一个子句在里面，4×2000 次自增一次不丢，精确得到 8000。

**SEMA 声明的两个实测坑**（源码注释原样记录）：

1. `SEMA s;` **不初始化就用** → 运行期错误 `use an uninitialised STRUCT(REF INT)`。
   SEMA 必须初始化。
2. 初始化必须用 **`LEVEL n`**：`SEMA s := LEVEL 1;`。写 `SEMA s := 0` 不行——
   INT 不能强转成 SEMA，`LEVEL` 是专门的强制转换记号。

## 5. SEMA 做"握手"：生产者-消费者

SEMA 不只能当锁，还能当**信号**：初始 `LEVEL 0`（零许可），消费者的 `DOWN` 会一直
阻塞，直到生产者 `UP` 发信号——这就是最小形态的**生产者-消费者握手**：

```algol68
SEMA ready := LEVEL 0;                      # 初始 0 许可：DOWN 会阻塞直到有人 UP #
INT produced := 0;
PAR (
  BEGIN produced := 42; UP ready END,       # 生产者：算完发信号 #
  BEGIN DOWN ready;                         # 消费者：等信号 #
        print(("  消费者拿到 produced=", whole(produced, 0), new line)) END
);
# 注意：上面消费者在并行子句里 print 是【安全】的——因为 DOWN ready 保证它 #
#       只在生产者 UP 之后运行，且此刻只有一个子句在输出，不会交错。 #
assert(produced = 42, "握手后消费者看到生产者的结果");
```

两个要点：

1. **同步即排序**：`DOWN ready` 保证消费者只在生产者 `UP ready` 之后继续——它读到
   `produced` 时，42 一定已经写入。没有这个握手，消费者可能读到 0。
2. **第 2 节纪律的合法例外**：消费者在并行子句里 `print` 竟然安全？安全——因为
   握手保证了这行 print 只在唯一确定的时刻发生（生产者已 UP，生产者自己没有 print），
   此刻**只有一个子句可能输出**，不存在交错。纪律的本质不是"并行里禁止 print"，
   而是"**输出顺序必须与调度无关**"。

## 6. 竞态（race）pitfall：无锁改共享变量是未定义行为

反面教材——本示例**不执行**它，只讲清后果：

```algol68
# INT shared := 0;                                            #
# PROC unsafe = (INT n) VOID: FOR k TO n DO shared +:= 1 OD;  #
# PAR (unsafe(20000), unsafe(20000), unsafe(20000), unsafe(20000)); #
```

`shared +:= 1` 不是一条原子指令，它是**读-改-写三步**：读出旧值 → 加一 → 写回。两个
子句同时执行这三步时会**丢更新**：都读到 5、都写回 6，两次自增只剩一次。最终结果
**小于** 80000，且小多少完全取决于调度。

竞态阴险之处在于：它**可能恰好跑出正确的 80000**（时间片凑巧没撞上），让你误以为
没问题——换台机器、换个优化级别、换个负载就出错。凡并发写同一变量，一律用 SEMA
保护，**不要靠运气**。示例里对应的正面输出是：

```algol68
print(("竞态教训：无锁并发改共享变量结果不可靠，必须用 SEMA 保护", new line));
```

## 7. 为什么 check/release 两通道 stdout 逐字节一致

本仓库的 `run-all.sh` 对每个示例跑两条通道并要求 stdout **逐字节一致**：

```text
check   通道：a68g --warnings --notices   解释器（全运行时检查）
release 通道：a68g -O2                     编译到 C 后端（优化，真实出货形态）
```

一个满是并行的程序凭什么两次运行字节相同？因为**确定性是被设计出来的**，本章五节
各贡献一条：

| 设计 | 消除的不确定性 |
|---|---|
| 并行只算不 print，汇合后统一输出（§2） | 输出交错顺序 |
| 各子句写入集合不相交（§2、§3） | 共享写竞态 |
| 共享写一律 SEMA 临界区（§4） | 丢更新 |
| 跨子句依赖用 SEMA 握手排序（§5） | 读取时机 |
| 竞态代码只描述不执行（§6） | 靠运气的"正确" |

解释器和 C 后端的线程调度几乎必然不同，但只要程序语义不依赖调度，两条通道的 stdout
就必然一致——实测也确实一致。反过来说，**双通道逐字节比对本身就是竞态探测器**：
谁在并行子句里裸 print、谁无锁改共享变量，都可能在这里现形（表现为 `[DIFF]`）。

## 8. 实测输出（本机 a68g 3.13.3）

`./run-all.sh 17`，check 通道的真实 stdout（release 通道逐字节一致）：

```text
PAR 汇合后：a=10 b=20 c=30
并行独立求和：s1=500500 s2=1001000
并行切片处理 checksum=2040
SEMA 保护的共享计数器 shared=8000
  消费者拿到 produced=42
竞态教训：无锁并发改共享变量结果不可靠，必须用 SEMA 保护
==== 17 结束 ====
自检全部通过
```

逐行解释：

| 输出 | 来自 | 为什么是这个值 |
|---|---|---|
| `a=10 b=20 c=30` | §1 | 三子句并发赋值，PAR 汇合后全部可见 |
| `s1=500500 s2=1001000` | §2 | 1..1000 之和 = 500500；2..2000 偶数和 = 2×500500 = 1001000 |
| `checksum=2040` | §3 | (1+4+9+16+25+36+49+64)×10 = 204×10 |
| `shared=8000` | §4 | 4 个子句 × 2000 次，SEMA 临界区一次不丢 |
| `  消费者拿到 produced=42` | §5 | 握手后消费者才 print，值必为 42（缩进两格是源码里写的） |
| `竞态教训：...` | §6 | 反面教材不执行，只打印教训 |
| `==== 17 结束 ====` | 尾 | 结束标记：脚本据此确认程序跑到了最后一句 |
| `自检全部通过` | 尾 | `fails = 0`；若有断言失败，FAIL 行进 stderr、此处改打失败项数 |

注意 §5 的消费者 print 出现在固定位置（第 5 行）：虽然它在并行子句里输出，但握手
保证了顺序，所以每次运行、每条通道它都在 `shared=8000` 之后、`竞态教训` 之前。

## 9. 坑位清单（实测）

1. **PAR 的语法形态**：`PAR (子句1, 子句2, ...)`——并列成分放圆括号里逗号分隔；
   不存在 `PAR BEGIN ... AND ... OD/END` 这种写法，a68g 只认并列形式（§1）。
2. **并行子句里不要 print**：多子句同时输出会交错，每次运行字节不同，双通道比对必炸。
   并行只算、写不相交变量，汇合后统一 print（§2）。唯一例外：用 SEMA 握手保证
   "此刻只有一个子句可能输出"（§5）。
3. **SEMA 必须初始化，且必须用 LEVEL**：`SEMA s;` 不初始化 → 运行期
   `use an uninitialised STRUCT(REF INT)`；`SEMA s := 0` 不行（INT 不能强转成 SEMA），
   要写 `SEMA s := LEVEL 0;`（§4）。
4. **`+:=` 不是原子的**：`shared +:= 1` 是读-改-写三步，无锁并发下丢更新，结果小于
   理论值——而且**可能碰巧正确**，最阴险（§6）。凡并发写同一变量，一律 SEMA 临界区。
5. **切片并行要真不相交**：两个子句写下标区间重叠的数组元素，等价于竞态；只有下标
   集合不相交（如 [1:4] 与 [5:8]）才能免锁（§3）。只读共享是安全的。
6. **汇合是免费的，顺序不是**：PAR 结束即 join，无需手动等待；但子句**之间**的先后
   顺序不存在——需要顺序就用 SEMA 握手显式表达（§5）。
