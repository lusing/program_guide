# 05 · 合一与同一性

> 对应示例：[`examples/05_unification/05_unification.pl`](../examples/05_unification/05_unification.pl)

## 5.1 `=` 是合一，不是赋值

命令式语言用 `x = 3` 把值塞进盒子。Prolog 的 `=/2` 是**让两边变成同一个项**：

```text
  X = 42            成功后 X = 42
  f(A,b) = f(a,B)   成功后 A = a，B = b
  f(1,2) = f(1,2)   成功
  f(1,2) = f(1,3)   失败
  f(1)   = f(1,2)   失败
  a = b             失败
  a = 1             失败
  1 = 1.0           失败
  [a,b] = [a|T]     成功
  [a,b] = [a|T] 成功后 T 被绑成 [b]
```

合一算法的规则很短，但推出来的结论很长：

1. 变量与任何项都能合一 —— 结果是**变量被绑定**。
2. 复合项与复合项：**函子名和元数必须相同**，然后**参数递归地合一**。
3. 原子/数字与自己合一，与其他失败。
4. **整数与浮点不是同一个项** —— `1 = 1.0` 失败（ISO 规定）。

第 2 条是「合一能穿透结构」的来源，这是它区别于字符串比较的关键：

```prolog
f(g(X), b) = f(g(a), Y).      % 一次同时绑定 X=a, Y=b
```

第 4 条是常见惊讶点：`1 = 1.0` 失败，但 `1 =:= 1.0` 成功（07 章）——**合一比的是项的
结构，`=:=` 才比数值**。

> **绑定只能做一次。** `X = 1, X = 2` 直接失败，因为 `X` 已经是 `1` 了，「让 `1` 和 `2`
> 变成同一个东西」做不到。
>
> 想「改变」一个变量的值，你要么造一个新变量，要么写进动态数据库（17 章）。**「不能改」
> 不是缺陷，是 Prolog 全部威力的来源** —— 它让回溯能安全地撤销绑定。

## 5.2 `==` 是同一性，不建立绑定

```text
  X == Y  （都是空变量）失败
  X =  Y  （都是空变量）成功
  V1 = V2 之后 V1 == V2 : true
  V1 == V2（已合一）    成功
  f(1) \== f(2)         成功
  f(1) \=  f(2)         成功
```

| 写法 | 名字 | 行为 | 代价 |
|---|---|---|---|
| `X = Y` | 合一 | 尝试让两边**变成同一个东西**，会绑定 | 递归走结构 |
| `X == Y` | 同一性 | 检查两边**现在是否已经是同一个东西**，绝不绑定 | 比地址，O(1) |
| `X \= Y` | 不能合一 | `=/2` 的否定 | |
| `X \== Y` | 不同一 | `==/2` 的否定 | |
| `X =@= Y` | 结构等价 | 忽略变量名，只比结构（**两套引擎都有**） | |

看前两行的对比就明白差别了：两个不同的空变量 `V1`、`V2`，**`==` 失败**（它们不是一个
东西），**`=` 成功**（合一之后它们就成了一个东西）。一次 `V1 = V2` 之后，`V1 == V2` 就
变成成功了。

口诀：**`=` 会绑定，`==` 不绑定；`\=` 问「能不能合一」，`\==` 问「是不是同一个」。**

实现上 `==/2` 拿两个项的地址比，是 O(1)；`=/2` 要递归走结构。所以**只问「有没有变」的
时候用 `==`，更快也更安全**（它不会顺手把变量绑掉）。

## 5.3 `\+/1` 不是「不」，而是「推不出来」

```text
  \+ (a = b)            成功
  \+ (a = a)            失败
  \+ member(c,[a,b])    成功
  \+ member(X,[a,b]) 失败 —— 确实存在 X 让成员关系成立
  \+ \+ member(X,[a,b]) 成功，但 X 仍是空的（双重否定只回答真假）
```

`\+ Goal` 的语义是「`Goal` 不可证明」，并且**`\+` 内部的变量绑定全部丢弃**。这是
closed-world assumption：证明不了就当作假。

第三、四行是同一个陷阱的两面：

- `\+ member(c,[a,b])` 成功，因为真的推不出来；
- `\+ member(_X,[a,b])` **失败**，因为「存在某个 X 使成员关系成立」是能证明的。

所以 `\+` 里的自由变量语义很微妙。`\+ likes(mary, X)` 读作「**mary 什么都不喜欢**」，
而不是「存在某个 mary 不喜欢的东西」—— 想要后者得写
`\+ forall(likes(mary, X), ...)` 或者干脆用 `findall` + 手工判断。

第五行说明另一个事实：**双重否定只回答真假，不生成绑定**。
`\+ \+ member(X,[a,b])` 成功后 `X` 仍然是空的 —— 因为外层 `\+` 也会把内层的绑定丢掉。

**口诀：`\+` 只回答「能不能推出来」，绝不作为生成解的手段。**

## 5.4 出现检查

```text
  unify_with_occurs_check(X, f(X))失败
  unify_with_occurs_check(X, f(a))  成功后 X = f(a)
  默认的 =/2 不做出现检查，Y = f(Y) 会成功并造出环状项。
  环状项的打印方式两套引擎不同，本教程一律不打印它。
  要可移植就别造环；需要检查时显式调用 unify_with_occurs_check/2。
```

```prolog
?- X = f(X).
X = f(X).          % 默认不做出现检查，造出一个「自己装自己」的环状项
```

ISO 提供 `unify_with_occurs_check/2` 防止这件事。默认不开是因为**检查要遍历整个项**，
代价高；而实际代码里几乎不会写 `X = f(X)`，所以各家实现都把性能放在前面。

环状项一旦造出来，`write` 打它会无限循环（有些实现会打 `...`）。**本教程一律不造、不打，
也不比较** —— 因为两套引擎对环的处理方式不同，会污染逐字节比对。

## 5.5 操作「带变量的项」

```text
  term_variables(pair(_,_)) 个数 = 2
  term_variables(triple(_,_,_)) 个数 = 2
  原件第一个参数改成 1 之后：原件 = pair(1,A)
                             副本 = pair(A,B)（副本不受影响）
  先给第一个参数赋值再编号  = pair(keep_me,A)
```

三个工具各有分工：

| 工具 | 作用 |
|---|---|
| `term_variables(T, Vars)` | 收集项里所有变量（**按首次出现顺序**，重复出现的只算一个） |
| `copy_term(T, Copy)` | 复制项，**变量换成全新的**，两边互不干扰 |
| `numbervars(T, 0, _)` | 把变量按顺序绑定成 `'$VAR'(0)`、`'$VAR'(1)`… 打印时显示为 `A`、`B`… |

`term_variables(triple(C1, _D, C1), Vs)` 只有 **2 个**变量而不是 3 个 —— 因为 `C1`
出现了两次，它是**同一个**变量。

`copy_term/2` 的价值在最后两行的对比里：原件被绑成 `pair(1,A)` 之后，**副本还是
`pair(A,B)`，完全不受影响**。这就是「模板」的实现方式：模板里放变量，每次要用就
`copy_term` 一份新鲜的。

> **`numbervars/3` 会把变量真的绑掉**（绑成 `'$VAR'(N)` 这种项），所以任何赋值必须放在
> 它之前。示例最后一段就是在演示这件事：
>
> ```prolog
> T4 = pair(I1, _J),
> I1 = keep_me,              % 必须在 numbervars 之前
> numbervars(T4, 0, _),
> format("  先给第一个参数赋值再编号  = ~w~n", [T4]).   % pair(keep_me,A)
> ```

## 5.6 坑位清单

1. **当赋值用** → `X = 1, X = 2` 失败是**故意的**，不是 bug。想改就造新变量。
2. **`1 = 1.0`** → 合一是结构比较，失败；数值比较要用 `=:=`。
3. **用 `==` 判断「相等」** → `1 == 1.0` 也失败，`f(1) == f(1)` 才是成功。要的是哪个
   「相等」得先想清楚。
4. **`\+` 里放自由变量** → `\+ member(X, L)` 的意思是「L 里一个元素都没有」，不是
   「有某个元素不匹配」。
5. **指望 `\+ \+` 带出绑定** → 它只回答真假，绑定全丢。
6. **`X = f(X)`** → 造环，两套引擎打出来的东西不一样；要检查用
   `unify_with_occurs_check/2`。
7. **打印含自由变量的项** → 引擎内部编号两边不同（`_1234` vs `_G123`），先 `numbervars/3`。
8. **`numbervars/3` 之后还想绑定变量** → 晚了，变量已经被绑成 `'$VAR'(N)` 项。
9. **`copy_term/2` 之后以为还共享** → 副本的变量是全新的，绑副本不影响原件；反过来也一样。
