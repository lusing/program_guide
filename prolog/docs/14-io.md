# 14 · 输入输出

> 对应示例：[`examples/14_io/14_io.pl`](../examples/14_io/14_io.pl)

## 14.1 流模型：一切都是流

Prolog 的 I/O 是**流（stream）模型**。标准输入 `user_input`、标准输出 `user_output`、
标准错误 `user_error` 都是流，`open/3` 打开的也是流 —— 三种东西一视同仁。

由此得到一条贯穿全章的设计规律：

> **所有写谓词都有「标准输出版」与「指定流版」两个成对的形态。**

| 标准输出版 | 指定流版 | 说明 |
|---|---|---|
| `write/1` | `write/2` | 原样输出，不加引号 |
| `writeq/1` | `writeq/2` | 必要时加引号（q = quoted） |
| `format/2` | `format/3` | 唯一能精确控制排版的 |
| `nl/0` | `nl/1` | 换行 |
| `put_char/1` | `put_char/2` | 写一个字符 |
| `tab/1` | — | **只有标准输出版**（没有 `tab/2`） |

流版本的第一或最后一个参数就是流。本教程的 `say/1` 其实就是 `format/2` 的封装。

## 14.2 写到标准输出

```text
write(hello)        -> hello
write('a b')        -> a b
writeq('a b')       -> 'a b'
writeq([a,'b c'])   -> [a,'b c']
format(~w)         -> f(1,a)
format(~q)         -> 'a b'
put_char + tab      -> x   y
put_char(Stream,C)  -> z
```

**`write/1` 不加引号，`writeq/1` 加** —— 区别只在原子需要引号时体现出来：

```prolog
write('a b'),  nl.        % 输出 a b      —— 再读回来会变成两个原子！
writeq('a b'), nl.        % 输出 'a b'    —— 能读回来
```

**这个区别在「写了再读」的场景里是致命的**（14.4）。凡是自造格式，用 `writeq`。

`format/2` 的格式串里，**字面的 `~` 要写成 `~~`**：

```prolog
format("  format(~~w)  -> ~w~n", [f(1, a)]).
```

否则 `~w` 会被当成说明符，去实参列表里找参数 —— 参数不够就报错。

> **只写一行的输出，推荐用 `format/2` 而不是串 `write/1` + `nl/0`** —— 前者只要调一次，
> 参数都在一处，读起来清楚。本教程所有示例都遵守这条。

## 14.3 写文件：`open` / `format` / `close`

```prolog
open(F, write, S),
format(S, "line one~n", []),
format(S, "line two~n", []),
put_char(S, 'X'),          % put_char/2 直接写流
nl(S),
close(S).
```

```text
已写入 /tmp/prolog_tutorial_14.txt
write 模式会清空原文件；要追加用 open(F, append, S)。
再用 append 模式追加了一行。
读回第 1 行: line one
读回第 2 行: line two
读回第 3 行: X
读回第 4 行: line three
```

**三种打开模式**：`read` / `write`（清空）/ `append`（追加到尾部）。
**`write` 模式会清空原文件** —— 这是最常见的「我的数据哪去了」的原因。

**读「一整行」要自己写**，因为标准接口里没有 `read_line`：

```prolog
read_line(S, Codes) :-
    get_code(S, C),
    (   C =:= -1   ->  Codes = []          % -1 = 文件尾
    ;   C =:= 10   ->  Codes = []          % 10 = 换行
    ;   Codes = [C | Rest], read_line(S, Rest)
    ).
```

注意用的是 **`get_code/2`（拿整数码）而不是 `get_char/2`（拿单字符原子）**，因为
`format/2` 的 `~s` 说明符要吃**整数码列表**。两套引擎都是这个约定 —— 所以本教程每个
文件开头都写 `:- set_prolog_flag(double_quotes, codes).`。

## 14.4 读写「项」而不是字符

把项写出去再读回来，是配置文件、缓存、日志最常用的手法：

```prolog
open(F, write, S),
forall(member(T, [point(1,2), edge(a,b), size(3.5)]),
       (  write_term(S, T, [quoted(true)]),
          write(S, '.'),
          nl(S)
       )),
close(S).
```

```text
已写入 3 个项到 /tmp/prolog_tutorial_14_terms.txt
write_term 一定要配 quoted(true)：原子带空格时才会加引号，
否则写出去的文件读不回来（这是最常见的自造格式 bug）。
读回全部项: [point(1,2),edge(a,b),size(3.5)]
第一个项 = point(1,2)，其中未绑定变量有 0 个
```

三个要点：

1. **`quoted(true)` 必须加** —— 见 14.2。不加的话 `'a b'` 写出去是 `a b`，读回来变两个原子。
2. **句号要自己写**。`read/1` 以 `'.'` 为项的分隔符，`write_term` **不会**替你补。
3. **读到文件尾时 `read/1` 返回 `end_of_file`**（一个原子，不是异常），所以循环要判它：

```prolog
read_loop(S, Terms) :-
    read(S, T),
    (   T == end_of_file
    ->  Terms = []
    ;   Terms = [T | Rest], read_loop(S, Rest)
    ).
```

**`read_term/3` 能顺便拿到变量信息**（这是个很实用的能力）：

```prolog
read_term(S, First, [variables(Vs)]),      % Vs 是 First 里未绑定变量的列表
length(Vs, NV).
```

`variables/1` 这类选项对「读模板、填模板」特别有用（12 章）：先读一个含变量的模板，
数一数有几个空位，再决定要不要去要输入。

## 14.5 `see/1` 与 `tell/1`（ISO 老接口）

```prolog
tell('/tmp/x.txt'), write(legacy_style), write('.'), nl, told.
see('/tmp/x.txt'),  read(X), seen.
```

```text
tell 写 / see 读回来: legacy_style
```

`see` / `tell` / `seen` / `told` 是 **ISO 之前的接口**，它们**全局切换**「当前输入流」
和「当前输出流」。这是危险的设计：

> **一旦忘记 `seen` / `told`，后面所有 I/O 都被污染** —— 你以为在写标准输出，
> 其实在写旧文件。

两套引擎都还支持它们（读老代码会遇到），但**新代码一律用 `open/3` + 流参数** ——
流是局部变量，作用域清晰，不会泄漏。

## 14.6 标准错误：让诊断信息不污染数据

```text
format(user_error, ...) 可以把诊断信息写到 stderr，
这样它就不会混进正常输出里（本教程的 main/0 出错时就是这么做的）。
本示例故意不往 stderr 写东西 —— 验证脚本会检查 stderr 必须为空。
```

这是本教程所有示例的 `main/0` 的统一结构：

```prolog
main :-
    (   catch(run, E, (format(user_error, "*** 异常: ~q~n", [E]), halt(1)))
    ->  halt(0)
    ;   format(user_error, "*** run/0 失败~n", []),
        halt(1)
    ).
```

**正常输出走 stdout，诊断信息走 stderr** —— 这条分工让输出可以被脚本直接按字节比较
（`run-all.sh` 的六条判定里就有一条「stderr 必须为空」）。

## 14.7 不可移植的 I/O 工具

这一章踩到的引擎差异，比前面任何一章都多：

| 工具 | 状况 |
|---|---|
| `with_output_to/2` | 把输出收集成原子/串 —— **SWI 专有** |
| `open/4` 的 `encoding(utf8)` 选项 | GNU 报 `domain_error` |
| `atom_to_term/3` `term_string/2` `read_term_from_atom/3` | **SWI 专有** |
| `exists_file/1` vs `file_exists/1` | **连「文件是否存在」都不能统一** |

```text
with_output_to/2   把输出收集成原子/串（SWI 专有）
open/4 的 encoding(utf8) 选项（GNU 报 domain_error）
atom_to_term/3  term_string/2  read_term_from_atom/3（SWI 专有）
exists_file/1（SWI）  vs  file_exists/1（GNU）——连文件是否存在都不能统一
```

**替代方案**：要「序列化到内存」就自己写 DCG 生成器（18、19 章）——
不但可移植，而且**格式你完全可控**。本教程的 22 章要在两个引擎之间写出字节完全一致的文件，
用的就是这个办法。

> **`format/1` 不存在。** 两套引擎都只有 `format/2` 和 `format/3`。想打一行固定文字必须写
> `format("...", [])` 或 `format("...~n", [])` —— 只给一个参数会报
> `existence_error(procedure, format/1)`（GNU）/ 未定义符号（`gplc`）。

## 14.8 坑位清单

1. **`write/1` 写带空格的原子** → 读回来会变成多个原子。用 `writeq/1` 或 `quoted(true)`。
2. **`write_term` 之后忘了写 `'.'`** → `read/1` 一直读不到项，最后返回 `end_of_file`。
3. **`open(F, write, S)` 以为是在追加** → `write` 会**清空**原文件，追加用 `append`。
4. **`format/1` 只有一个参数** → 不存在这个谓词，必须给实参列表（哪怕是 `[]`）。
5. **`~` 想输出字面量没写成 `~~`** → 被当说明符，去实参列表里找参数。
6. **`read/1` 返回的 `end_of_file` 当普通项处理** → 循环不终止。要显式判 `== end_of_file`。
7. **`read_line` 用 `get_char` 又交给 `~s`** → 类型不匹配。用 `get_code` 拿整数码。
8. **忘记 `close/1`** → 缓冲区没刷盘，文件内容是空的或截断的。
9. **在生产代码里用 `see`/`tell`** → 全局流状态，忘 `seen`/`told` 就污染后续所有 I/O。
10. **调 `encoding(utf8)`、`format/1`、`atom_to_term/3` 之类** → 至少一个引擎不支持。
