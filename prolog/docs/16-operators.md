# 16 · 运算符

> 对应示例：[`examples/16_operators/16_operators.pl`](../examples/16_operators/16_operators.pl)

## 16.1 运算符只是函子的糖

**`a + b` 在 Prolog 里不是一个「运算」，它就是复合项 `+(a, b)`。**

```prolog
X = 1 + 2,  X =.. L.        % L = [+, 1, 2]
Y = +(1, 2),
X == Y.                     % 成立 —— 两者严格同一个项
```

```text
X = 1 + 2，X =.. L  ->  L = [+,1,2]
+(1,2) 与 1+2 完全同一个项（== 成立）
Z = must go，Z =.. L  ->  L = [must,go]
functor(1+2, F, A)  ->  F = +，A = 2
```

也就是说：**「中缀写法」和「前缀函子写法」完全等价**，`1 + 2` 只是 `+(1,2)` 的省括号写法。
所以：

> **要判断「这是不是加法」，比较的是 `functor`，不是「运算符」。**
> 「运算符」这个概念只在**读入**的时候存在，一旦解析成项就没了。

## 16.2 `op/3`：三个信息

运算符由 `op(优先级, 类型, 名字)` 声明：

```prolog
:- op(700, xfx, ===>).      % 非结合中缀
:- op(200, xfy, vv).        % 右结合中缀
:- op(200, yfx, ww).        % 左结合中缀
:- op(100, fy,  must).      % 前缀
```

| 信息 | 含义 |
|---|---|
| **优先级** | 1–1200，**数字越大越松**（越晚结合） |
| **类型** | `xfx`/`xfy`/`yfx`（中缀）、`fy`/`fx`（前缀）、`xf`/`yf`（后缀） |
| **名字** | 一个原子 |

**`x` 与 `y` 的区别是理解类型的关键**：

- **`x` 表示该侧的优先级必须严格小于本运算符** —— 所以 `xfx` 是**非结合**的，
  一行里不能出现两个同优先级的 `xfx`。
- **`y` 表示该侧可以等于本运算符的优先级** —— 所以 `yfx` 左结合、`xfy` 右结合。

三个 `x`/`y` 各一个字母，分别管**左操作数**、**运算符本身**、**右操作数**。

```text
a ===> b        读成 ===>(a,b)
a vv b vv c     读成 vv(a,vv(b,c))      右结合
a ww b ww c     读成 ww(ww(a,b),c)      左结合
must go         读成 must(go)            前缀
```

> **`op/3` 是全局副作用**：声明之后**整个会话**都用新语法读入。所以本教程里所有自定义
> 运算符都集中在文件开头声明，并在注释里说明占用理由。

## 16.3 优先级与结合性：解析结果可以直接看

```text
1 + 2 * 3     读成 +(1,*(2,3))
(1 + 2) * 3   读成 *(+(1,2),3)
1 - 2 - 3     读成 -(-(1,2),3)
2 ** 3        读成 **(2,3)
```

`*` 优先级 400 比 `+` 的 500 **小**（数字越小越紧），所以 `2*3` 先结合：

```prolog
T = 1 + 2 * 3,
write_canonical(T).        % +(1,*(2,3))
```

**`write_canonical/1` 是看解析结果的最佳工具** —— 它把所有运算符**还原成函子写法**，
一眼就能看出树形结构。本教程的 16 章用它来「把解析结果打给人看」。

**`-` 是 `yfx`（左结合），所以 `1-2-3` 读成 `(1-2)-3`** —— 这和数学上一致。

**`**` 是 `xfx`（非结合），所以 `1 ** 2 ** 3` 直接是语法错误**，必须写 `(1**2)**3`。

```text
注意 ** 是 xfx：1 ** 2 ** 3 直接是语法错误，必须写 (1**2)**3。
```

> **本教程不用 `**`。** 除了上面的语法麻烦，两套引擎的**结果类型**也不一样（07 章）。
> 幂运算请用 `^` 或自己写循环乘法。

## 16.4 「`- 3`」这个坑

这是本章最实用的一条：

```text
坑：写 - 3（带空格）时，SWI 读成一元项 -(3)，GNU Prolog 读成整数 -3，
    univ 结果一个是 [-,3]、一个是 [-3]。所以本教程一律写 -3（不留空格），
    负数常量就写负号紧贴数字，千万别写「- 3」。
```

**根因**：`-` 既是**中缀减号**（`yfx`，优先级 500），又是**前缀负号**（`fy`，优先级 200）。
写 `- 3`（中间有空格）时，解析器要在两个角色之间选，而**两套引擎的选择不同**：

| 写法 | SWI | GNU |
|---|---|---|
| `-3`（紧贴） | 整数 `-3` | 整数 `-3` |
| `- 3`（带空格） | 一元项 `-(3)` | 整数 `-3` |
| `X = - 3, X =.. L` | `L = [-, 3]` | `L = [-3]` |

**所以规则就一条：负数常量永远写 `-3`（负号紧贴数字）。** 需要一元取负就明确写
`-(X)` 或者 `0 - X`。

## 16.5 自定义运算符：能干什么，别干什么

```prolog
:- op(700, xfx, ===>).

T = (a ===> b),
write_canonical(T).        % ===>(a,b)
T =.. L.                   % L = [===>, a, b]     —— 照样能 univ 拆
```

```text
自定义运算符让 DSL 读起来像自然语言的写法：
  if X > 0 then positive
  但它是纯语法，不会自动给你任何语义 —— 语义还得自己写谓词。
工程建议：只在定义清晰的 DSL 里用，别乱占优先级空间。
```

**自定义运算符的唯一价值是「让 DSL 读起来像自然语言」** —— 比如：

```prolog
:- op(700, xfx, then).

规则(if 条件 then 结论).
```

> **它不会自动给你任何语义。** 上面那行只是造了个 `then/2` 的项，**没有任何逻辑**。
> 语义还得你自己写谓词去解释这个项（12 章、24 章）。
>
> **工程建议**：只在**定义清晰的 DSL** 里用，别乱占优先级空间。
> 一个项目里定义十几个运算符，半年后没人记得住谁的优先级高 —— 那是技术债。

## 16.6 常用运算符优先级速查（`current_op/3` 实测）

```prolog
check_op(P, T, N) :-
    format("  ~w ~w ~q", [P, T, N]),
    (   current_op(P, T, N) -> say("   -> 引擎确认") ; say("   -> 引擎不认") ).
```

```text
1200 xfx :-   -> 引擎确认
1200 xfx -->  -> 引擎确认
1100 xfy ;    -> 引擎确认
1050 xfy ->   -> 引擎确认
1000 xfy ','  -> 引擎确认
 900 fy  \+   -> 引擎确认
 700 xfx =    -> 引擎确认
 700 xfx is   -> 引擎确认
 700 xfx =..  -> 引擎确认
 600 xfy :    -> 引擎确认
 500 yfx +    -> 引擎确认
 400 yfx *    -> 引擎确认
 200 xfx ^    -> 引擎不认          ← 注意！
 200 fy  -    -> 引擎确认
 700 xfx ===> -> 引擎确认
```

**用 `current_op/3` 去问引擎，比背表格靠谱** —— 因为不同实现的内建运算符不完全一样。
上表里 **`^` 在 `200 xfx` 上是「引擎不认」**（它是 `200 xfy`），
这就是为什么要实测而不是背。

**这张表（优先级 / 类型 / 名字）就是 Prolog 语法的全部秘密。** 记住四个锚点就够用：

| 优先级 | 典型运算符 | 含义 |
|---|---|---|
| 1200 | `:-` `-->` | 子句、DCG 规则（最松） |
| 1100–1000 | `;` `->` `,` | 控制结构 |
| 700 | `=` `is` `=..` | 关系与求值 |
| 500 / 400 | `+` / `*` | 算术 |

> **`xfx` 的一行里不能出现两个同优先级的 `xfx`** —— 这就是 11 章里
> `(X ===> Y) = (a ===> b)` 必须加括号的原因：`=` 和 `===>` 都是 `700 xfx`，
> 不加括号就是**语法错误**。
>
> **这是初学者最容易撞的坑**：`700 xfx` 的 `=` 遇上一堆自定义运算符。
>
> **要可移植，就永远用括号把优先级讲清楚，别指望读者（包括三个月后的自己）记住数字。**

顺带一个好消息：**`:- op(P, xfx, '===>')` 在两种引擎上都能生效，可以放心用** ——
和 22 章的模块系统不同，运算符声明是完全可移植的。

## 16.7 坑位清单

1. **用「运算符」判断项的类型** → 运算符只在读入时存在，判断要看 `functor`。
2. **写 `- 3`（带空格）** → SWI 与 GNU 解析不同，永远写 `-3`。
3. **`1 ** 2 ** 3`** → `**` 是 `xfx`，语法错误。要 `(1**2)**3`。
4. **两个同优先级 `xfx` 并列** → 语法错误（`=` 与自定义 `700 xfx` 混用最常见）。
5. **`^` 当 `200 xfx`** → 实测是 `200 xfy`，用 `current_op/3` 查。
6. **自定义运算符以为自带语义** → 只是语法糖，逻辑要自己写。
7. **`op/3` 声明放在文件中间** → 全局副作用，之前读入的项不受影响，容易困惑。
8. **一个项目里定义十几个运算符** → 优先级记忆负担爆炸，是技术债。
9. **忘了给 `op/3` 的运算符名字加引号** → 名字里有特殊字符时必须写 `'===>'`。
10. **跨引擎背运算符表** → 用 `current_op/3` 问引擎，不同实现有差异。
