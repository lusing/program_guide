# 18 · 定子句文法（DCG）

> 对应示例：[`examples/18_dcg/18_dcg.pl`](../examples/18_dcg/18_dcg.pl)

## 18.1 DCG 是什么

**DCG（Definite Clause Grammar）把「吃输入」这件事变成谓词参数，于是文法和代码合二为一。**

一条 DCG 规则长这样：

```prolog
ab --> [a], [b].
```

它读作「吃一个 `a`，再吃一个 `b`」。用起来靠 `phrase/2,3`：

```prolog
phrase(ab, [a, b]).            % 成功
phrase(ab, [a, b, c], Rest).   % 成功，Rest = [c]
phrase(ab, [b, a]).            % 失败（顺序不对）
phrase(ab, [a]).               % 失败（少一个终结符）
```

```text
phrase(ab, [a,b])        成功
phrase(ab, [a,b,c], Rest)  成功，剩下 [c]
phrase(ab, [b,a])        失败（顺序不对）
phrase(ab, [a])          失败（少一个终结符）
```

`phrase/3` 的第三个参数就是**没有消耗掉的尾巴** —— 这一条是理解 DCG 的关键。

**递归能力才是 DCG 的价值** —— `aⁿbⁿ`（a 和 b 数量必须相等）只要两条规则：

```prolog
anbn --> [].
anbn --> [a], anbn, [b].
```

```text
phrase(anbn, [a,a,b,b])  成功（两个 a 配两个 b）
phrase(anbn, [a,a,b])    失败（数量不配）
```

> **这是上下文无关文法，用正则表达式写不出来。** 因为「a 的个数 = b 的个数」不是正则语言 ——
> 需要计数能力，而计数需要递归。

**收集 token 也是个经典模式**：

```prolog
tokens([]) --> [].
tokens([T | Ts]) --> [T], tokens(Ts).
```

```prolog
phrase(tokens(Ts), [p, q, r]).      % Ts = [p, q, r]
```

## 18.2 `{Goal}`：在 DCG 里插普通目标

`{}` 是 DCG 与普通谓词之间的桥 —— **里面的目标不消耗输入**，纯粹做计算与校验：

```prolog
%% 吃掉三个 x，同时把个数算出来
three_x(N) -->
    [x], [x], [x],
    { N is 3 }.

%% 校验型：吃掉一个数，并断言它在 1..9 内
small(N) -->
    [N],
    { number(N), N >= 1, N =< 9 }.
```

```text
phrase(three_x(N), [x,x,x])   N = 3
phrase(small(N), [7])         N = 7
phrase(small(N), [70])        失败（70 不在 1..9）
```

**坑位与惯例**：

- **`{}` 里可以访问 DCG 外面的变量，但绑定会留在里面** —— 这正是我们要的（语义动作）。
- **副作用（打印、`assert`）都放在 `{}` 里** —— DCG 规则本身必须是纯的。
- **反面教材：在 DCG 里做重计算** —— 会让「生成」方向变得不可用，慎用（见下面）。

**最典型的用途是语义动作** —— 边解析边算：

```prolog
double(X, Y) -->
    [X],
    { Y is X * 2 }.

phrase(double(8, D), [8]).      % D = 16
```

> **`{...}` 里的谓词必须「对输入的模式都成立」。** DCG 有两种用法：
> **识别**（输入给定，判定能不能吃下去）和**生成**（输入变量，枚举可能的串）。
> 在 `{}` 里做 `is/2` 这类「要求参数已绑定」的计算，**会让生成方向直接抛
> `instantiation_error`** —— 所以「生成方向可用」的 DCG 里，`{}` 要尽量干净。

## 18.3 或 / 参数 / 递归

和普通谓词一样，**一个非终结符可以有多条规则（这就是「或」）**：

```prolog
atom_or_num(X) --> [X], {number(X)}.
atom_or_num(X) --> [X], {atom(X)}.
```

```text
atom_or_num(42)   X = 42
atom_or_num(foo)  X = foo
```

**也可以带参数，把「识别到的结果」传出来**：

```prolog
numlist([N | Rest]) --> [N], {number(N)}, numlist_rest(Rest).
numlist_rest([N | Rest]) --> [','], [N], {number(N)}, numlist_rest(Rest).
numlist_rest([]) --> [].
```

```text
numlist([1,',',2,',',3]) = [1,2,3]
numlist([9])             = [9]
```

注意这个「**头一个 + `_rest` 继续**」的拆分：因为逗号只在元素**之间**出现，
所以第一个元素和后续元素必须用不同规则描述。这是处理「分隔列表」的标准形态。

> **DCG 里没有「if-then-else」的概念。** 要条件分支就写在 `{}` 里，
> 或者靠**规则顺序 + `!`**（06、10 章）。
>
> 想「先把 token 全收下来，再自己处理」也是个很实用的模式：
>
> ```prolog
> phrase(tokens(Ts), [a,b,c,d]), length(Ts, N).      % N = 4
> ```

## 18.4 实用例：把一行文本切成单词

输入是字符码列表（15 章），输出是单词列表。思路：**交替吃「空白」与「非空白」**。

```prolog
words([]) --> blanks.
words([W | Ws]) --> blanks, word(W), words(Ws).

blanks --> [].
blanks --> [C], {C =:= 32}, blanks.        % 32 是空格

%% 关键：word//1 必须吃掉至少一个字符
word([C | Cs]) --> [C], {C =\= 32}, word_rest(Cs).
word_rest([C | Cs]) --> [C], {C =\= 32}, word_rest(Cs).
word_rest([]) --> [].
```

```text
输入 "the quick brown fox"
切出 [[116,104,101],[113,117,105,99,107],[98,114,111,119,110],[102,111,120]]
转成原子：[the,quick,brown,fox]
输入 "hello" 切出 [[104,101,108,108,111]]
连续空格与首尾空格也照切：[[97],[98]]
```

注意：

- **每个词是「字符码列表」**（15 章的双引号串）。要变成原子就
  `maplist(atom_codes, Atoms, Ws)`。
- 注意 `atom_codes/2` 的参数顺序是 `(原子, 码列表)` —— 所以 `maplist` 的第一个参数写
  `atom_codes` 时，两个列表的顺序要**反着给**（`Atoms` 在前、`Ws` 在后）。
- **首尾空格与连续空格自动处理掉**（`blanks` 吃任意多个），这正是这个写法漂亮的地方。

> **写 DCG 时最常见的死循环来源：忘了保证「每次递归都在前进」。**
>
> `word//1` 必须**吃掉至少一个字符**。如果写成 `word([]) --> []`，那么
> 「跳过空白 + 空单词 + 继续」这条路径**不消耗任何输入**，`words//1` 就会无限递归下去。
>
> **判据**：递归调用前，必须已经消费了至少一个输入符号。

## 18.5 DCG 展开成了什么

这是 `ab//0` 的手写版本，与 `ab --> [a], [b]` 完全等价：

```prolog
ab_expanded(S0, S) :-
    S0 = [a | S1],
    S1 = [b | S].
```

```text
手写版 ab_expanded([a,b], Rest)      Rest = []
DCG 版  ab([a,b], Rest)              Rest = []

ab --> [a],[b].  展开后等价于：
    ab(S0, S) :- S0 = [a|S1], S1 = [b|S].   % 也就是 S0 = [a,b|S]
```

**每个 `//N` 的 DCG 非终结符，展开后就是 `N+2` 元的普通谓词** —— 多出来的两个参数就是
「进来时的输入」和「出去时的剩余输入」：

```prolog
current_predicate(ab/2).       % 成立 —— ab//0 就是 ab/2
```

所以 **`ab//0` 可以直接当普通谓词 `ab/2` 调用**（本节演示就是这么干的）。

> **DCG 不过是把你从没写过的「差值表」参数替你补上了。** 理解了这一点：
>
> - `phrase/3` 的第三个参数（剩下的尾巴）就顺理成章了；
> - 也就明白了为什么 DCG 能**嵌套**、能**回溯** —— 它就是普通谓词的调用。
>
> **实战价值**：不用 DCG 也能解析，但只要涉及**「嵌套 + 回溯」**，
> 手写差值表会迅速变成一团乱麻 —— **这是 DCG 存在的全部理由**（19 章会用它写出一个
> 完整的表达式解析器）。

## 18.6 坑位清单

1. **DCG 规则里写普通目标不加 `{}`** → 被当成非终结符，报 `existence_error`。
2. **递归不消费输入** → 无限递归（`word//1` 忘吃字符是最经典的例子）。
3. **`word//1` 允许空词** → 同样导致无限递归。
4. **`phrase/2` 要求吃光输入** → `phrase(ab, [a,b,c])` 失败；要部分匹配用 `phrase/3`。
5. **`{}` 里做重计算/`is`** → 生成方向抛 `instantiation_error`，可用的方向少了一半。
6. **`{}` 里以为绑定不会传出来** → 会传出来（这正是语义动作的原理）。
7. **`atom_or_num` 之类忘了 `{}` 里的类型检查** → 两条规则都「成功」，选错分支。
8. **`maplist(atom_codes, Ws, Atoms)` 参数顺序搞反** → `atom_codes/2` 是 `(原子, 码)`。
9. **以为 `//N` 的元数就是 `N`** → 展开后是 `N+2` 元。
10. **用 DCG 做词法分析（一个个字符）** → 能行，但性能差；19 章会说明为什么分开做。
