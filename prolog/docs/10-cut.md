# 10 · 剪枝与否定

> 对应示例：[`examples/10_cut/10_cut.pl`](../examples/10_cut/10_cut.pl)

## 10.1 `!` 是什么

`!/0`（cut，剪枝）的作用是两件事同时发生：

1. **丢掉当前谓词中「这个 `!` 之后的所有子句」**；
2. **丢掉「这个 `!` 之前的所有选择点」**。

一句话：**`!` 把「到这里为止已经确定的结论」变成不可撤销的。**

最直观的例子 —— 求最大值，不用 `!`：

```prolog
max_bad(X, Y, X) :- X >= Y.
max_bad(_X, Y, Y).
```

```text
  findall(M, max_bad(3,1,M), L)  L = [3,1]（3 和 1 都在）
  换成 max_ok                     L = [3]
  语句层面 max_bad 的第二个解「1」是错的，
  但 max_bad(1,3,M) 又是对的 —— 它只是「有时」错，最难查。
  max_ok(3,1,_) 跑完就不再留选择点（! 已经砍掉了）
```

`max_bad(3,1,M)` 会先给出 `M=3`（第一条子句成立），**但它不阻止回溯** —— 再来一次就得到
`M=1`。而在 `max_bad(1,3,M)` 里第一条不成立，第二条给出 `M=3`，结果恰好对。

**这样一个「在某些输入下悄悄给出错误答案」的谓词是最难查的 bug**：测试写 `max_bad(1,3,M)`
会通过，线上遇到 `max_bad(3,1,M)` 就崩。

加上 `!` 就定死了：

```prolog
max_ok(X, Y, X) :- X >= Y, !.
max_ok(_X, Y, Y).
```

> **`!` 顺手砍掉的还有「还有别的选择点」这个事实。** 所以 `max_ok(3,1,_)` 跑完之后调用方
> 再回溯也不会得到第二个解 —— 这正是我们想要的（最大化是确定性的），但它也意味着**调用方
> 无法再「多要几个答案」**。`!` 的这个副作用会一路影响外层谓词的行为。

## 10.2 绿切与红切

这是 `!` 最重要的分类：

**绿切（green cut）**：剪掉的都是本来就会失败的分支。删掉 `!`，程序语义不变，只是慢。

```prolog
grade_green(S, a) :- S >= 90, !.
grade_green(S, b) :- S >= 80, !.
grade_green(S, c) :- S >= 70, !.
grade_green(_,  f).
```

这里 `!` 之后的条件（`S >= 90`）本来就会让下面的子句失败，`!` 只是省掉白费的尝试。

**红切（red cut）**：靠 `!` 来保证正确性。删掉 `!` 程序就错了。

```text
  first_even([1,3,4,6,8])    = 4
  first_even_alt（once 版）  = 4
  如果不加 ! 也不加 once，收集到的会是全部偶数：[4,6,8]
```

```prolog
first_even(L, X) :- member(X, L), 0 =:= X mod 2, !.

% 等价但意图写在脸上的写法
first_even_alt(L, X) :- once(( member(X, L), 0 =:= X mod 2 )).
```

「第一个偶数」**在逻辑上没有唯一性** —— 逻辑上 `member(X,L)` 给出的是「存在某个偶数」
的集合。`!` 强行让它唯一，**改变了语义**，所以是红切。

红切的危险在于**它依赖调用者对 `member/2` 枚举顺序的信任**。把列表顺序换一下，
`first_even` 的答案就变了 —— 而这一点在谓词的名字和签名上完全看不出来，**必须写进文档**。

> **经验法则：能写 `once/1` 就别写裸 `!`。**
>
> `once(G)` 展开就是 `call(G), !`，但它的意图（只要第一个解）写在脸上了；裸 `!` 混在
> 一长串目标中间，读者得自己推断「作者到底想剪什么」。**这是可维护性差别，不是性能差别。**

## 10.3 `;` 与 `->`、`*->` 的区别

```text
  (N>1, R=gt ; R=le)   共 5 个解：[le,gt,le,gt,le]
  (N>1 -> R=gt ; R=le) 共 3 个解：[le,gt,gt]
  (N>1 *-> R=gt ; R=le) 共 3 个解：[le,gt,gt]
  N=2 时第一种写法给出了 gt 与 le 两个解 —— 这正是
  「分号只是或」与「箭头才会剪枝」的差别。
```

三种写法在**同一个查询**下的行为：

```prolog
findall(R, ( member(N, [1,2,3]), ( N > 1, R = gt ; R = le ) ), Rs).
% Rs = [le,gt,le,gt,le] —— 5 个解
%
%   N=1: 条件假 → le
%   N=2: 条件真 → gt，但 ; 是真正的「或」，回溯后还能得 le   ← 多余！
%   N=3: 条件真 → gt，回溯后还能得 le                       ← 多余！
```

| 写法 | 语义 | 展开 |
|---|---|---|
| `(C, T ; E)` | **真正的逻辑或**，两边都能回溯出解 | `;` |
| `(C -> T ; E)` | 条件只取**第一个解**，然后走 `T`；失败才走 `E` | `(C, !, T ; E)` |
| `(C *-> T ; E)` | 条件可以**继续回溯**，但 `E` 不参与 | 软切 |

**`->` 本身就带剪枝。** 这一点经常被忽略：`(member(X,[1,2,3]) -> true ; true)` 只产生
**一个**解，不是三个。

`*->` 与 `->` 的差别只在**条件本身能回溯出多个解**时才显现。示例里条件 `N > 1` 对每个 `N`
只判一次，所以两者结果相同 —— 要看差别得写：

```prolog
?- findall(X, ( member(X, [1,2,3]) -> true ; true ), L).     L = [1].
?- findall(X, ( member(X, [1,2,3]) *-> true ; true ), L).    L = [1,2,3].
```

> **`*->` 不是所有实现都有。** 本教程只要求你**认识**它；要写可移植代码就用 `;` 加显式
> 条件，或者用 `findall` + 选择。

## 10.4 `\+` 与 `once/1` 都是 `!` 的封装

```text
  my_not(member(9,[1,2,3]))  成立
  findall(X, my_once(member(X,[a,b,c])), L)  L = [a]
  once = 只取第一个解；\+ = 取第一个解再取反。
  my_not(member(X,[a,b]))    不成立，而且 X 没被绑定
```

ISO 标准里两者的展开式：

```prolog
\+ G      ≡  (G, !, fail ; true)
once(G)   ≡  (G, !)
```

自己写一遍就看得一清二楚：

```prolog
my_not(G) :- call(G), !, fail.
my_not(_).

my_once(G) :- call(G), !.
```

- **`once/1` = 只取第一个解**，掐掉不确定性。
- **`\+` = 取第一个解再取反**，同时**把所有绑定丢掉**。

两者都「掐掉了不确定性」，所以适合放在需要**判定**的位置（if-then-else 的条件、`forall`
的测试）。示例最后一行再次演示了 `\+` 的经典陷阱：`my_not(member(X, [a,b]))` 不成立，
而且 `X` 没被绑定 —— **`\+` 绝不作为生成解的手段**（05 章）。

## 10.5 `!` 与「没有答案」的表达

```text
  find_first([1,3,5,8,9], >6)  = 8
  在不含 >6 的列表里：目标直接失败
  Prolog 用「失败」表示「没有」，不返回 null 也不抛异常 ——
  这是从命令式／函数式过来的第二大坎（第一坎是第 05 章的合一）。
  想显式表达「可能没有」，就自己包一层：返回 none / some(X)（第 20 章）。
```

```prolog
find_first(L, P, X) :-
    member(X, L),
    call(P, X),
    !.                      % 找到就砍掉 member 的其余选择点

bigger_than_6(X) :- X > 6.
```

两点：

- **`!` 在最后一行保证了确定性**：找到就停，不给调用方留选择点。
- **找不到就是失败**，不是返回「空」或「假」。

**Prolog 用「失败」表示「没有」。** 这一点是从命令式/函数式过来的人最难适应的地方：
没有 `null`、没有 `None`、没有 `-1`、也不抛异常，就是简单地不成立。

> 这在写库的时候会成为一个问题：调用方分不清「不成立」和「出错了」。**20 章会给出解决
> 方案 —— 用 `some(X)` / `none` 把「可能没有」变成一个显式的值。**

## 10.6 `!` 只作用于它所在的谓词

这是最反直觉的语义之一：

```prolog
outer(X)     :- inner(X).
inner(X)     :- member(X, [1,2,3]).

outer_cut(X) :- inner_cut(X).
inner_cut(X) :- member(X, [1,2,3]), !.     % 这个 ! 管不到 outer_cut
```

`outer_cut` 依然只有一个解，但**原因不是「cut 传上去了」**，而是 `inner_cut` 本身只有一解。
`!` 的作用域严格限制在**它所在的那个谓词**内，**不会穿过谓词边界**。

**别指望用内层谓词的 `!` 去剪外层的选择点。** 反过来，`!` 会**砍掉调用方在本谓词内留下的
选择点** —— 也就是说 `!` 的影响是**向外**（通过「本谓词是否还有选择点」）而不是向内。

## 10.7 坑位清单

1. **不给最大/最小值加 `!`** → 回溯给出多余解，「有时对有时错」的 bug 最难查。
2. **红切不写文档** → 语义依赖枚举顺序，重构时必炸。
3. **裸 `!` 代替 `once/1`** → 能跑但意图不清。**优先 `once/1`**。
4. **`(C -> T ; E)` 里条件有多解** → `->` 砍掉了其余，只走第一个。
5. **`;` 当 `->` 用** → `;` 是真正的逻辑或，两边都回溯，会多出解。
6. **`*->` 当可移植写法** → 不是所有实现都有。
7. **`\+` 里放自由变量** → 语义变成「不存在任何一个」，且绑定全丢。
8. **指望 `\+ \+` 带出绑定** → 只回答真假。
9. **以为内层 `!` 能剪外层** → `!` 不穿谓词边界。
10. **`!` 放在条件前** → 条件还没判就把选择点砍了，逻辑直接错。
11. **`!` 放在最后一个目标之后但子句还有别的目标** → `!` 之后的目标失败时**不会**回溯到
    前面的选择点，调用方只能失败。这是「红切」最伤人的形态。
