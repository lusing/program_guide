# 数据表示与运算基础

计算机里只有比特。「整数」「负数」「小数」都是**解释方式**。
这一章把 x86-64 程序员必须内化的几套编码一次讲透：补码、溢出的双视角、
IEEE 754 位级结构、定点数、BCD。它们是读懂数值 bug 的地基。

配套示例在 [`examples/12_data_repr/`](../examples/12_data_repr/)（4 支，
全部在 Windows 实测通过）：

| 示例 | 讲什么 |
|------|--------|
| `complement.asm` | 补码：同一比特的两种解释、`neg` = NOT+INC、INT64_MIN 陷阱 |
| `overflow.asm` | OF/CF 双视角：四种组合各一例，`seto`/`setc` 取标志 |
| `ieee754_bits.asm` | double 的位级解剖：符号/指数/尾数、0.1 为什么不精确 |
| `fixed_point.asm` | 16.16 定点：乘法右移、除法左移、SAR 保符号 |

## 1. 补码：负数是「模运算的补」

n 位补码：负数 `-x` 的编码是 `2^n - x`。由此推出一组速算：

| 操作 | 位运算 | 例子（8 位） |
|------|--------|--------------|
| 求负 `neg x` | `not x; inc x` | 5 (`00000101`) → NOT=`11111010` → +1=`11111011` = -5 |
| 减法 | 加补码 | `a - b == a + (not b) + 1` |

同一串比特 `0xFF` 作为 u8 是 255，作为 i8 是 -1——**CPU 不区分，
`add` 指令永远做同一件事**，解释权在后续的跳转/扩展指令：

- `ja/jb`（above/below）按**无符号**比较读 CF；
- `jg/jl`（greater/less）按**有符号**比较读 OF/SF/ZF；
- `movzx` 零扩展、`movsx` 符号扩展，是「声明解释」的两条指令。

`complement.asm` 实测输出：

```
0xFF as u8 = 255, as i8 = -1
neg(5) = -5, bits = 0xFFFFFFFFFFFFFFFB
~42 + 1 = -42
INT64_MIN = 0x8000000000000000, neg(INT64_MIN) = 0x8000000000000000
sign-extend 0x80 (i8) -> movsx -> 0xFFFFFFFFFFFFFF80
zero-extend 0x80 (u8) -> movzx -> 0x0000000000000080
```

注意第 4 行：**`neg INT64_MIN` 还是 INT64_MIN**（-2^63 的补是 +2^63，
超出表示范围，结果回卷）。这正是 C 标准把有符号溢出定为未定义行为
的原因之一——硬件能执行，但数学上错了。检测它只能靠 OF 标志。

## 2. 溢出：OF 与 CF 是两套独立的真相

同一条 `add`，CPU 同时算两个标志：

- **OF（Overflow Flag）**：有符号视角溢出——正+正=负、负+负=正等「符号崩坏」；
- **CF（Carry Flag）**：无符号视角溢出——最高位向外产生了进位/借位。

两者**独立**，四种组合都会出现。`overflow.asm` 凑齐全部四格：

```
INT64_MAX + 1        : result=0x8000000000000000  OF=1 CF=0
UINT64_MAX + 1       : result=0x0000000000000000  OF=0 CF=1
1 + 2                : result=0x0000000000000003  OF=0 CF=0
INT64_MIN + INT64_MIN: result=0x0000000000000000  OF=1 CF=1
```

解读：

- 第 1 行：无符号没到顶（CF=0），有符号翻到负数（OF=1）；
- 第 2 行：无符号顶到头回卷（CF=1）；有符号视角其实是 `-1 + 1 = 0`，合法（OF=0）；
- 第 4 行：两个视角同时爆——无符号 2^63+2^63 回卷（CF=1），
  有符号负+负得 0（OF=1）。

取标志用 `seto`/`setc`（条件置字节），比 `pushf`+位测试简洁得多。

## 3. IEEE 754：double 的 64 位解剖

```
 63   62        52 51                                    0
[符号][  指数 11  ][            尾数 52                  ]
```

- **指数**是移码，偏置 1023：真实指数 = 字段值 - 1023；
- **尾数**隐含前导 1：`1.xxxxx × 2^e`，52 位字段只存小数部分；
- 特殊编码：指数全 1 尾数 0 = ±∞；指数全 1 尾数非 0 = NaN；
  指数全 0 = 非规格化数 / ±0。

把同一块内存分别按 `double` 读和按 `u64` 读（`movq`/`movsd` 互转），
就能看到编码本身。`ieee754_bits.asm` 实测：

```
+1.0: bits=0x3FF0000000000000  sign=0 exp=1023 mantissa=0x0000000000000
-2.0: bits=0xC000000000000000  sign=1 exp=1024 mantissa=0x0000000000000
0.1 : bits=0x3FB999999999999A  sign=0 exp=1019 mantissa=0x999999999999A
+inf: bits=0x7FF0000000000000  sign=0 exp=2047 mantissa=0x0000000000000
0.1+0.2 -> bits=0x3FD3333333333334
0.3     -> bits=0x3FD3333333333333   (differ by 1 ULP!)
```

读法示例（`+1.0`）：符号 0，指数字段 1023 = 1023（真实指数 0），
尾数 0 → `1.0 × 2^0 = 1.0`。`-2.0`：指数字段 1024 → 真实 +1，
`1.0 × 2^1 = 2.0`，符号 1。

**0.1 为什么不精确**：0.1 的二进制是 `0.0001100110011001100...` 无限循环，
52 位尾数装不下，被截断成 `...1001 1010`（末位四舍五入进位）。
著名的 `0.1 + 0.2 != 0.3` 就是这么来的——两者恰好差 1 个 ULP
（最低有效位单位），上面最后两行直接给出了位模式证据。

## 4. 定点数：没有 FPU 的年代怎么算小数

定点数 = 用整数运算模拟小数，**比例因子由程序员约定**。
最常用的是 16.16：高 16 位整数、低 16 位小数，1.0 = `0x00010000`。

四则运算的规则（记住「两个 16.16 相乘，比例因子平方」）：

| 运算 | 定点写法 | 说明 |
|------|----------|------|
| a + b / a - b | 直接 `add`/`sub` | 比例因子相同，直接算 |
| a × b | `(a as i64 * b as i64) >> 16` | 结果右移 16 位回来；**必须 SAR** |
| a ÷ b | `(a as i64 << 16) / b` | 被除数先左移 16 位补比例 |
| a 与整数 n 比较 | `a` vs `n << 16` | 统一到同一坐标系 |

`fixed_point.asm` 实测：

```
1.500 * 2.000 = 3.0
1.000 / 4.000 = 0.250
-0.500 * 3.000 = -1.500   (SAR keeps the sign)
pi as fixed = 3.141586  (resolution 1/65536 ~ 1.5e-5)
```

两个实测坑值得复述：

1. **负数乘法必须用 SAR 不能用 SHR**：`shr` 会把负结果的符号位填 0，
   `-1.5` 变成天文数字。逻辑右移只属于无符号。
2. **拆小数时的乘法位数**：pi 的小数部分 `0x243F × 1000000 ≈ 9.28×10^9`
   超出 32 位（2^31 ≈ 2.15×10^9），`imul r32` 静默截断，打出 `3.010514`。
   小数位乘 10^6 这类「放大再看」的操作要用 64 位乘法。

## 5. BCD 与十进制的执念

用二进制位直接存十进制数字（每 4 位一个 0-9）的历史方案：
压缩 BCD 每字节两个数字。8086 时代配套了 `DAA`/`DAS` 等**调整指令**，
但它们在 64 位模式下已被删除（`#UD`）。

今天的出路：

- 精确十进制显示：整数 → `fbstp`（x87 出口，见[第 13 章](13_x87_fpu.md)第 5 节）；
- 精确十进制运算：软件大数库（乘 10^k 的定点/数组表示）。

`fixed_point` 与 `fpu_bcd` 合起来就是「小数表示法」的两条活路：
二进制定点（快）与十进制（准）。

## 6. 立即数的编码限制（顺带的重要坑）

`overflow.asm` 开发时踩到并实测记录：**`add`/`sub` 不支持 64 位立即数**
——imm 只有 imm8 / imm32（符号扩展）两种。写 `add rax, 0x8000000000000000`
NASM 只给一条 `signed dword exceeds bounds` **警告**然后静默截断成
`add rax, 0`，运算结果全错。大立即数必须先 `mov` 进寄存器：

```nasm
mov rdx, 0x8000000000000000    ; mov r64, imm64 是合法的
add rax, rdx
```

（`mov r64, imm64` 是唯一吃 64 位立即数的常见指令。）

## 7. 本章坑清单

1. `neg INT64_MIN` = INT64_MIN，别指望它变正；检测靠 OF。
2. OF 和 CF 各管一个视角，`ja/jb` 与 `jg/jl` 用的标志不同。
3. 0.1 的 double 位模式是 `0x3FB999999999999A`，`0.1+0.2` 与 `0.3`
   差 1 ULP——「浮点相等比较」要么用容差，要么比较位模式。
4. 定点负数乘法用 SAR；放大检查小数用 64 位乘。
5. `add rax, imm64` 编不出来，NASM 警告后截断——先 `mov` 进寄存器。
6. NASM 里 `mov eax, var` 取的是**地址**（立即数），`mov eax, [var]`
   才是取值——写错会触发 MSVC 链接器的 ADDR32 重定位错误（详见
   [第 20 章](20_masm_nasm.md)语法对照）。
