# 长模式：进入 64 位

2000 年 AMD 在 K8 上推出 x86-64（AMD64），Intel 随后跟进为 Intel 64，
两者合流即 **IA-32e / 长模式（Long Mode）**。它没有推倒重来——
而是在保护模式之上叠一层：先满足保护模式的全部入场条件，
再打开 EFER 里的开关。这就是为什么「进入 64 位」的代码要从
16 位实模式一路演完。

本章参考李忠《x86汇编语言：编写64位多处理器多线程操作系统》第 2 章
（x64 架构总览）与第 3 章（完整引导链），Intel SDM Vol.3 第 9 章。
可运行示例 [`boot/04_long64.asm`](../boot/04_long64.asm)——
实模式 → 保护模式 → PAE + 4 级分页 → EFER.LME → CR0.PG → 64 位，
一条龙（`cd boot && ./build-boot.sh 04`）。

## 1. 工作模式全景

```
                 ┌─ 传统模式（实模式 / 16、32 位保护模式 / SMM）
x86-64 处理器 ───┤
                 └─ IA-32e（长模式）
                     ├─ 兼容模式（ Compatibility：跑 32/16 位老代码，4GB 限）
                     └─ 64 位模式（寄存器 64 位、48 位有效虚拟地址）
```

- **一个 CPU 可以在模式间按代码段切换**：64 位内核里跑 32 位程序
  就是切到兼容模式的代码段；
- 「长模式」关闭（EFER.LMA=0）就退化回传统模式；
- 我们写 `bits 64` 的代码只在 64 位模式下合法。

## 2. 64 位模式带来了什么

| 变化 | 内容 |
|------|------|
| 寄存器 | 16 个通用寄存器（rax–rdi + **r8–r15**），全 64 位 |
| 寻址宽度 | 虚拟地址 **48 位有效**（57 位需 5 级分页），物理 46+ 位 |
| 立即数 | **imm 仍是 32 位符号扩展**（`mov r64, imm64` 是唯一例外） |
| 寻址 | 新增 **RIP 相对寻址**；`[rsp]` 可直接寻址（SIB 变化） |
| 一批指令删除 | 半寄存器高字节组合（`ah` 与新寄存器混用）、`push cs/ds/es/ss`、BCD 调整等 |
| 段 | **段基址/界限被架空**（见第 6 节），FS/GS 例外保留 |
| 栈 | `push/pop` 一次 8 字节，不允许 32 位 push/pop 立即数（`push imm32` 会扩成 64 位） |

「立即数仍是 32 位」直接呼应[第 14 章](14_data_representation.md)的坑：
`add rax, 0x8000000000000000` 编不出来，NASM 还只给个警告。

## 3. 进入长模式的完整序列（顺序敏感）

`boot/04_long64.asm` 的主干，顺序**不能乱**：

```
实模式
  ├─ 开 A20、建 GDT（额外加一个 L=1 的 64 位代码段描述符）
  ├─ CR0.PE=1 → 远跳 → 32 位保护模式（重载数据段、建栈）
  ├─ CR4.PAE=1                          ← ① 长模式的前提是 PAE 分页
  ├─ 建好 4 级分页表，CR3=PML4          ← ② 先有表后有开关
  ├─ wrmsr：EFER(0xC0000080) 的 LME=1   ← ③ 允许长模式
  ├─ CR0.PG=1                           ← ④ 开分页：LMA 自动置位，进入 IA-32e
  │      （此刻仍在兼容模式——CS 还是 32 位描述符）
  └─ 远跳到 L=1 的代码段选择子          ← ⑤ 真正进入 64 位模式
64 位模式（bits 64）
```

两个容易忽略的点：

- **EFER 是 MSR**，编号 `0xC0000080`，要 `rdmsr/wrmsr` 读写
  （ECX=编号，结果/输入在 EDX:EAX）；
- 第 ④ 步之后处理器处在**兼容模式**——指令集还是 32 位的！
  必须等第 ⑤ 步远跳进 L=1 的段，才是 64 位模式。GDT 里那个
  64 位描述符（byte5=0x9A、byte6=**0x20**（L=1 D=0））就是为这一跳准备的。

### 3.1 4 级分页与 2MB 大页

48 位线性地址按 **9-9-9-9-12** 拆分：

```
 47      39 38     30 29     21 20     12 11      0
[ PML4 索引][ PDPT 索引][ PD 索引 ][ PT 索引 ][ 页内偏移]
```

四级表（PML4 → PDPT → PD → PT）每级 512 项 ×8 字节 = 4KB，
CR3 指向 PML4。`boot/04` 用 2MB 大页省掉最后一级：
PD 项 PS=1（bit7）直出页框，512×2MB = **1GB 恒等映射**只要三张表：

```nasm
        mov eax, 0x83            ; PS=1 | P | RW，物理页 0 起
        mov ecx, 512
.fill_pd:
        mov [edi], eax
        add eax, 0x200000        ; 每项递增 2MB
        add edi, 8               ; x64 表项 8 字节！
        loop .fill_pd
```

QEMU 实测输出（`./build-boot.sh 04`）：

```
S1: loaded 32 sectors, jumping to 0x8000
S2: A20 on, GDT ready (incl. 64-bit code seg), switching to PM...
[LM32] PML4@0x10000 PDPT@0x11000 PD@0x12000, 512x2MB identity
[LM32] PAE=1 CR3 loaded EFER.LME=1 PG=1 -> IA-32e active
[LM64] Hello from 64-bit long mode!
[LM64] RAX=123456789ABCDEF0  (64-bit register works)
[LM64] RIP=00000000000081B8
[LM64] EFER=0000000000000500  (bit10 LMA=1)
[LM64] paging still active: CR3=0000000000010000
[LM64] full chain done: real -> PM32 -> paging -> long mode
```

`EFER=0x500` = LME(bit8) + **LMA(bit10)**——后者由处理器在开 PG 时
自动置位，「长模式真的激活了」的硬件证据。RIP 那行是 RIP 相对寻址
`lea rax, [rel .here]` 打出来的——与位置无关代码的标配。

## 4. Canonical 地址：48 位的边界

x86-64 的虚拟地址虽然寄存器 64 位，**只有低 48 位参与翻译**，
第 47-63 位必须全是第 47 位的复制（符号扩展），否则 #GP：

```
0x00007FFF_FFFFFFFF  ✓ canonical（用户区上半）
0xFFFF8000_00000000  ✓ canonical（内核区）
0x00008000_00000000  ✗ 非法（「空洞」）
```

所以 64 位进程的地址空间是两个 128TB 的半区，中间是空洞。
Linux/Windows 的用户区、内核区恰好分居两侧（Windows 进程用户区
约 0x0–0x7FF7'FFFFFFFF，内核 0xFFFF8000'00000000 起）。

## 5. 64 位下的段：还在，但被架空

长模式里 CS/DS/ES/SS 的**基址强制 0、界限强制不检查**——
分段保护彻底退休，权限全由分页接管（呼应[第 16 章](16_paging.md)）。
但段寄存器与 GDT **没有消失**：

- CS 仍承载 CPL（低 2 位）与 L/D 位（决定模式）——`syscall` 的
  段选择子切换正依赖它（李忠 2024 第 4.2 节的快速系统调用）；
- **FS/GS 是仅存的两个「有基址」的段**——基址存放在 MSR
  （`IA32_FS_BASE=0xC0000100`、`IA32_GS_BASE=0xC0000101`）里，
  是 TLS（线程局部存储）与内核 per-CPU 数据的标准载体
  （`swapgs` 指令在系统调用入口交换 GS 基址，见
  [第 19 章](19_multicore_atomic.md)的 per-CPU 话题）。

## 6. 64 位编码速览（写给反汇编读代码的人）

- **REX 前缀**（0x40-0x4F）：访问 r8-r15、64 位操作数（W 位）、
  B/W/X 扩展寄存器编号——`48 89 C3` = `mov rbx, rax`（48=REX.W）；
- **操作数默认 32 位**：`89 C3` 是 `mov ebx, eax`（写 32 位寄存器
  自动零扩展到 64——**32 位运算清高 32 位**，这是免费的
  `movzx eax, eax`）；
- **RIP 相对**：`48 8D 05 xx xx xx xx` = `lea rax, [rip+disp32]`；
  NASM 写法 `lea rax, [rel 标号]`（配 `default rel`）；
- **绝对地址不能直接做位移**：`mov rax, [标号]` 在 default rel 下
  自动 RIP 相对；带索引寄存器的 `[标号 + rbx]` 无法 RIP 相对，
  NASM 退回 ABS 寻址产生 ADDR32 重定位——MSVC link 直接报
  LNK2017/LNK1165（本教程 fpu_bcd、atomic_inc 都实测踩过：
  **先用 `lea r10, [标号]` 取基址，再 `[r10 + rbx]`**）。

## 7. TSS 在 64 位下的新工作：只有栈

任务状态段（TSS）在 32 位时代是硬件任务切换的大本营（80X86 教程
10.5-10.6 节的五个切换实例全靠它）；长模式删除了硬件任务切换，
**TSS 只剩一件事**：给 `RSP0`（以及 IST1-7）——中断/异常从低特权级
进入 0 环时，处理器从 TSS 取内核栈指针切栈（[第 18 章](18_interrupts_exceptions.md)
的 IST 就是这里的 IST 槽）。李忠 2024 第 4.4 节创建了 64 位 TSS
描述符并 `ltr` 装载——那是每个 64 位内核的必做步骤。

| 时代 | TSS 的职责 |
|------|-----------|
| 32 位 | 完整任务上下文（寄存器、LDT、SS0-2/ESP0-2、I/O 位图）+ 硬件切换 |
| 64 位 | 只剩 RSP0 + IST1-7（IST 供 NMC/DF 等用独立栈）+ I/O 位图 |

## 8. 本章坑清单

1. **顺序不能乱**：PAE → CR3 → EFER.LME → CR0.PG → 远跳 L=1 段。
   少了 PAE 或 CR3，开 PG 直接 #GP。
2. **EFER.LME 置位后开 PG 才是长模式**；开完 PG 还停在兼容模式，
   别忘了最后那记远跳。
3. **64 位代码段描述符 byte6 的 L 位（bit5）是 0x20**，且 D 必须为 0
   （L=1 D=1 保留，#GP）。
4. **x64 页表项 8 字节**，填表循环 `add edi, 8` 不是 4。
5. **wrmsr 前 ECX 要清高 32 位**（`mov ecx, 0xC0000080` 自带零扩展）。
6. **48 位 canonical**：地址数学要当心空洞，两个半区各 128TB。
7. **`[标号+索引]` 的 ADDR32 陷阱**：MSVC 链接器不收，`lea` 基址 + 索引。
