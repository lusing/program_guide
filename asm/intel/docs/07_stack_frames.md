# 栈和栈帧

栈（Stack）是程序运行时用于管理函数调用、局部变量和临时数据的内存区域。理解栈的工作原理是掌握汇编函数调用的关键。

## 栈的工作原理

x86-64 的栈具有两个核心特征：

1. **向低地址增长**：压栈时 RSP 减小，弹栈时 RSP 增大。
2. **后进先出（LIFO）**：最后压入的数据最先弹出。

```
高地址 ┌──────────────┐ ← 栈底（高地址）
       │  ...          │
       │  早压入的数据  │
       ├──────────────┤
       │  后压入的数据  │
       │  ← RSP 栈顶   │  栈向低地址增长 ↓
低地址 └──────────────┘
```

> RSP（栈指针）始终指向当前栈顶（最后压入的数据所在地址）。`PUSH` 先减 RSP 再写入，`POP` 先读出再加 RSP。

## PUSH / POP 机制

| 指令 | 操作 |
|------|------|
| `PUSH rax` | `RSP -= 8`，然后将 RAX 写入 `[RSP]` |
| `POP rax` | 将 `[RSP]` 读入 RAX，然后 `RSP += 8` |

```nasm
push rax           ; 保存 RAX 到栈上
push rbx           ; 保存 RBX
; ... 此处可自由使用 RAX/RBX ...
pop  rbx           ; 恢复 RBX（后进先出，逆序弹出）
pop  rax           ; 恢复 RAX
```

> **必须成对使用**：每个 `PUSH` 都要有对应的 `POP`，且顺序相反，否则栈失衡导致 `RET` 跳到错误地址。在 64 位模式下，`PUSH`/`POP` **仅支持 64 位（默认）或 16 位操作数，不支持 32 位或 8 位**。例如 `push rax`（8 字节）与 `push ax`（2 字节）合法，而 `push eax`、`push al` 非法，汇编器会报错。

## 函数栈帧结构

函数调用时，栈上会形成一段属于该函数的区域，称为**栈帧（Stack Frame）**。`[rbp]` 存旧 RBP、`[rbp+8]` 存返回地址、`[rbp-8]` 起是局部变量——这几项两个平台完全一致。**分叉点在于返回地址之上**：Windows 要求调用者预留 32 字节影子空间，System V（Linux/macOS）不需要。

### Windows x64 布局

```
高地址
┌─────────────────────┐
│  调用者栈帧 ...      │
├─────────────────────┤
│  栈传参数 5, 6, ...   │  ← 被调用者通过 [rbp+48], [rbp+56] 访问（前4个参数走寄存器）
├─────────────────────┤
│  影子空间 32 字节     │  ← [rbp+16] ~ [rbp+47]（调用者为本函数预留）
├─────────────────────┤
│  返回地址（CALL压入）  │  ← [rbp+8]
├─────────────────────┤
│  保存的 RBP（旧值）   │  ← [rbp]   (push rbp)
├─────────────────────┤
│  局部变量2           │  ← [rbp-8]
│  局部变量1           │  ← [rbp-16]
│  ...                │
└─────────────────────┘  ← RSP 指向此处
低地址
```

> 图中偏移基于标准序言 `push rbp; mov rbp, rsp` 后的布局：`[rbp]` 存旧 RBP、`[rbp+8]` 存返回地址、`[rbp+16]` 起是调用者预留的 32 字节影子空间，因此第 5 个栈传参数位于 `[rbp+48]`（16+32）。

### System V AMD64 布局（Linux / macOS）

```
高地址
┌─────────────────────┐
│  调用者栈帧 ...      │
├─────────────────────┤
│  栈传参数 7, 8, ...   │  ← 第 5 个参数在 [rbp+16]，第 6 个在 [rbp+24]（前6个走寄存器）
├─────────────────────┤
│  返回地址（CALL压入）  │  ← [rbp+8]
├─────────────────────┤
│  保存的 RBP（旧值）   │  ← [rbp]   (push rbp)
├─────────────────────┤
│  局部变量2           │  ← [rbp-8]
│  局部变量1           │  ← [rbp-16]
│  ...                │
└─────────────────────┘  ← RSP 指向此处
低地址
```

> System V 把前 **6** 个整数参数放进寄存器（见 [调用约定](06_calling_convention.md)），且**没有影子空间**，所以第 7 个参数直接落在 `[rbp+16]`——比 Windows 少了 32 字节的偏移。

### 两平台对照

| 项目 | Windows x64 | System V AMD64 |
|------|-------------|----------------|
| 返回地址位置 | `[rbp+8]` | `[rbp+8]` |
| 影子空间 | 32 字节，`[rbp+16]`~`[rbp+47]` | **无** |
| 第 1 个栈传参数 | `[rbp+48]`（第 5 个参数） | `[rbp+16]`（第 7 个参数） |
| 入栈顺序 | 从右到左 | 从右到左 |
| 调用前 RSP 对齐 | 16 字节 | 16 字节 |
| 局部变量空间 | `sub rsp, N`，N 需覆盖影子空间 | `sub rsp, N`，**无需**为影子空间留位 |

## RBP 帧指针用法

RBP（基址指针）作为帧指针，在函数执行期间保持不变，为访问局部变量和参数提供稳定的基准点。标准的函数序言（Prologue）与结语（Epilogue）如下：

```nasm
my_function:
    ; ─── 序言 (Prologue) ───
    push rbp              ; 保存调用者的 RBP
    mov  rbp, rsp         ; 建立新帧指针
    sub  rsp, 32          ; 分配局部变量空间

    ; ─── 函数体 ───
    ; 访问局部变量: [rbp-8], [rbp-16], ...
    ; 访问栈传参数: 第 1 个栈参数在 [rbp+16]（SysV）或 [rbp+48]（Win64）
    mov  qword [rbp-8], 42      ; 局部变量 = 42
    mov  rax, [rbp-8]           ; 读取局部变量

    ; ─── 结语 (Epilogue) ───
    add  rsp, 32          ; 释放局部变量空间（或用 leave）
    pop  rbp              ; 恢复调用者 RBP
    ret
```

> 如果你把这段序言/结语原样用在一个会被 C 库调用的函数上（比如 macOS 的 `_main`），**`ret` 返回是正确做法**——`_main` 的返回地址是 libSystem 的启动代码压进去的。但在 Windows 上用 `/entry:main` 指定入口时，栈上没有合法返回地址，必须 `call ExitProcess` 而**不能** `ret`。这是移植时最容易翻车的一处，详见 [macOS 移植指南](10_macos_porting.md)。

### LEAVE 指令

`LEAVE` 是结语的高速等价写法，一条指令完成两步操作：

```nasm
leave     ; 等价于: mov rsp, rbp ; pop rbp
```

因此标准结语可简写为：

```nasm
leave
ret
```

## 局部变量分配

局部变量不通过 `PUSH` 分配，而是通过移动 RSP 留出连续空间，再用 RBP 偏移访问：

```nasm
func_with_locals:
    push rbp
    mov  rbp, rsp
    sub  rsp, 48          ; 分配 48 字节局部空间（含对齐填充）

    ; 3 个局部变量（每个8字节）
    mov  qword [rbp-8],  100    ; var_a = 100
    mov  qword [rbp-16], 200    ; var_b = 200
    mov  qword [rbp-24], 300    ; var_c = 300

    ; 计算并存放结果
    mov  rax, [rbp-8]
    add  rax, [rbp-16]
    add  rax, [rbp-24]
    mov  [rbp-32], rax          ; result = 600

    mov  rax, [rbp-32]          ; 返回值

    leave
    ret
```

## 栈帧图示

下面是一个调用 `sum(10, 20)` 的完整栈帧示例（参数寄存器按 **System V** 写成 `rdi`/`rsi`，Windows 下换成 `rcx`/`rdx` 即可，其余结构完全相同）：

```nasm
sum:
    push rbp              ; [1] 保存旧 RBP
    mov  rbp, rsp         ; [2] RBP = 当前 RSP
    sub  rsp, 16          ; [3] 分配 16 字节局部空间
    mov  [rbp-8], rdi     ; 局部变量存第1个参数（Win64 是 rcx）
    mov  [rbp-16], rsi    ; 局部变量存第2个参数（Win64 是 rdx）
    mov  rax, [rbp-8]
    add  rax, [rbp-16]    ; 相加
    leave                 ; 恢复 RSP 和 RBP
    ret
```

> 在 macOS / Linux 上，序言里还可以加一句 `sub rsp, 8` 让 `sub rsp, 16` 后的 RSP 保持 16 字节对齐（进入函数时 RSP ≡ 8 mod 16，`push rbp` 后 ≡ 0 mod 16）。Windows 因为调用者预留影子空间，对齐由调用方负责。

执行时栈的变化：

```
进入函数后 (CALL 已压入返回地址):

高地址
┌───────────────────┐
│  调用者栈帧        │
├───────────────────┤
│  返回地址  (0x...)  │ ← [rbp+8]
├───────────────────┤ ← push rbp 后
│  旧 RBP            │ ← [rbp]   (RBP指向此处)
├───────────────────┤ ← sub rsp,16 后
│  局部: arg2 (20)   │ ← [rbp-16]
│  局部: arg1 (10)   │ ← [rbp-8]
│  (8字节未用填充)    │
└───────────────────┘ ← RSP
低地址
```

> 两个平台都通过寄存器传递前几个参数（SysV 传 6 个，Win64 传 4 个），因此参数通常先存入局部变量区域再使用。若需调试或用 RBP 偏移统一管理，可手动将寄存器参数存入栈帧（如上例所示）。
