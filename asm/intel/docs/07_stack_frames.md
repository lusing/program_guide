# 栈和栈帧

栈（Stack）是程序运行时用于管理函数调用、局部变量和临时数据的内存区域。理解栈的工作原理是掌握汇编函数调用的关键。

## 栈的工作原理

x86-64 的栈具有两个核心特征：

1. **向低地址增长**：压栈时 RSP 减小，弹栈时 RSP 增大。
2. **后进先出（LIFO）**：最后压入的数据最先弹出。

```
高地址 ┌──────────────┐ ← 栈底（高地址）
       │  ...          │
       │  早压入的数据  │
       ├──────────────┤
       │  后压入的数据  │
       │  ← RSP 栈顶   │  栈向低地址增长 ↓
低地址 └──────────────┘
```

> RSP（栈指针）始终指向当前栈顶（最后压入的数据所在地址）。`PUSH` 先减 RSP 再写入，`POP` 先读出再加 RSP。

## PUSH / POP 机制

| 指令 | 操作 |
|------|------|
| `PUSH rax` | `RSP -= 8`，然后将 RAX 写入 `[RSP]` |
| `POP rax` | 将 `[RSP]` 读入 RAX，然后 `RSP += 8` |

```nasm
push rax           ; 保存 RAX 到栈上
push rbx           ; 保存 RBX
; ... 此处可自由使用 RAX/RBX ...
pop  rbx           ; 恢复 RBX（后进先出，逆序弹出）
pop  rax           ; 恢复 RAX
```

> **必须成对使用**：每个 `PUSH` 都要有对应的 `POP`，且顺序相反，否则栈失衡导致 `RET` 跳到错误地址。在 64 位模式下，`PUSH`/`POP` **仅支持 64 位（默认）或 16 位操作数，不支持 32 位或 8 位**。例如 `push rax`（8 字节）与 `push ax`（2 字节）合法，而 `push eax`、`push al` 非法，汇编器会报错。

## 函数栈帧结构

函数调用时，栈上会形成一段属于该函数的区域，称为**栈帧（Stack Frame）**。一个典型的栈帧包含：

```
高地址
┌─────────────────────┐
│  调用者栈帧 ...      │
├─────────────────────┤
│  栈传参数 5, 6, ...   │  ← 被调用者通过 [rbp+48], [rbp+56] 访问（前4个参数走寄存器）
├─────────────────────┤
│  影子空间 32 字节     │  ← [rbp+16] ~ [rbp+47]（调用者为本函数预留）
├─────────────────────┤
│  返回地址（CALL压入）  │  ← [rbp+8]
├─────────────────────┤
│  保存的 RBP（旧值）   │  ← [rbp]   (push rbp)
├─────────────────────┤
│  局部变量2           │  ← [rbp-8]
│  局部变量1           │  ← [rbp-16]
│  ...                │
└─────────────────────┘  ← RSP 指向此处
低地址
```

> 图中偏移基于标准序言 `push rbp; mov rbp, rsp` 后的布局：`[rbp]` 存旧 RBP、`[rbp+8]` 存返回地址、`[rbp+16]` 起是调用者预留的 32 字节影子空间，因此第 5 个栈传参数位于 `[rbp+48]`（16+32）。

## RBP 帧指针用法

RBP（基址指针）作为帧指针，在函数执行期间保持不变，为访问局部变量和参数提供稳定的基准点。标准的函数序言（Prologue）与结语（Epilogue）如下：

```nasm
my_function:
    ; ─── 序言 (Prologue) ───
    push rbp              ; 保存调用者的 RBP
    mov  rbp, rsp         ; 建立新帧指针
    sub  rsp, 32          ; 分配局部变量空间

    ; ─── 函数体 ───
    ; 访问局部变量: [rbp-8], [rbp-16], ...
    ; 访问栈传参数: [rbp+16], [rbp+24], ...
    mov  qword [rbp-8], 42      ; 局部变量 = 42
    mov  rax, [rbp-8]           ; 读取局部变量

    ; ─── 结语 (Epilogue) ───
    add  rsp, 32          ; 释放局部变量空间（或用 leave）
    pop  rbp              ; 恢复调用者 RBP
    ret
```

### LEAVE 指令

`LEAVE` 是结语的高速等价写法，一条指令完成两步操作：

```nasm
leave     ; 等价于: mov rsp, rbp ; pop rbp
```

因此标准结语可简写为：

```nasm
leave
ret
```

## 局部变量分配

局部变量不通过 `PUSH` 分配，而是通过移动 RSP 留出连续空间，再用 RBP 偏移访问：

```nasm
func_with_locals:
    push rbp
    mov  rbp, rsp
    sub  rsp, 48          ; 分配 48 字节局部空间（含对齐填充）

    ; 3 个局部变量（每个8字节）
    mov  qword [rbp-8],  100    ; var_a = 100
    mov  qword [rbp-16], 200    ; var_b = 200
    mov  qword [rbp-24], 300    ; var_c = 300

    ; 计算并存放结果
    mov  rax, [rbp-8]
    add  rax, [rbp-16]
    add  rax, [rbp-24]
    mov  [rbp-32], rax          ; result = 600

    mov  rax, [rbp-32]          ; 返回值

    leave
    ret
```

## 栈帧图示

下面是一个调用 `sum(10, 20)` 的完整栈帧示例：

```nasm
sum:
    push rbp              ; [1] 保存旧 RBP
    mov  rbp, rsp         ; [2] RBP = 当前 RSP
    sub  rsp, 16          ; [3] 分配 16 字节局部空间
    mov  [rbp-8], rcx     ; 局部变量存第1个参数
    mov  [rbp-16], rdx    ; 局部变量存第2个参数
    mov  rax, [rbp-8]
    add  rax, [rbp-16]    ; 相加
    leave                 ; 恢复 RSP 和 RBP
    ret
```

执行时栈的变化：

```
进入函数后 (CALL 已压入返回地址):

高地址
┌───────────────────┐
│  调用者栈帧        │
├───────────────────┤
│  返回地址  (0x...)  │ ← [rbp+8]
├───────────────────┤ ← push rbp 后
│  旧 RBP            │ ← [rbp]   (RBP指向此处)
├───────────────────┤ ← sub rsp,16 后
│  局部: arg2 (20)   │ ← [rbp-16]
│  局部: arg1 (10)   │ ← [rbp-8]
│  (8字节未用填充)    │
└───────────────────┘ ← RSP
低地址
```

> 在 Windows x64 中，前 4 个参数通过寄存器传递（不压栈），因此参数通常先存入局部变量区域再使用。若需调试或用 RBP 偏移统一管理，可手动将寄存器参数存入栈帧（如上例所示）。
