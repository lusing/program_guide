# 实模式与保护模式：x86 地址空间的两次革命

今天写的每一条 x86-64 指令，都背负着 1978 年 8086 的遗产。要真正理解
「为什么 64 位模式下段寄存器还在、却又不怎么管用了」「为什么引导代码
要从 16 位开始」，必须走一遍**实模式 → 保护模式**这条路。

本章参考李忠《x86汇编语言：从实模式到保护模式（第 2 版）》第 3、5、6、
11–14 章（实模式寻址、主引导扇区、GDT 与特权级），Intel SDM Vol.3
第 2、3 章，并引用本教程 `boot/` 目录下**可实际运行的 QEMU 引导链**：

| 示例 | 演示 | 本章位置 |
|------|------|----------|
| [`boot/01_mbr_hello.asm`](../boot/01_mbr_hello.asm) | 实模式主引导扇区：段:偏移计算、串口输出 | 第 1-2 节 |
| [`boot/stage1.asm`](../boot/stage1.asm) | BIOS 扩展读（INT 13h AH=42h）加载第二阶段 | 第 3 节 |
| [`boot/02_pm32.asm`](../boot/02_pm32.asm) | 进入 32 位保护模式：GDT、CR0.PE、平坦模型 | 第 4-6 节 |

> 运行方法：`cd boot && ./build-boot.sh 01`（或 `02`）。需要 PATH 里有
> `qemu-system-x86_64`。脚本会无头启动 QEMU、把串口接到 stdout、
> 并校验期望输出。

## 1. 实模式：8086 的世界

加电（或复位）后，x86 CPU 从实模式开始：**完全的 16 位环境**，
地址线 20 根（1MB 寻址），没有保护、没有虚拟地址。

### 1.1 段:偏移 —— 用两个 16 位拼出 20 位

8086 的寄存器只有 16 位（能表达 64K），地址总线却有 20 根（1MB）。
当年的解法：**物理地址 = 段值 × 16 + 偏移**。

```
CS:IP = 0000:7C00  ->  0x0000 << 4 + 0x7C00 = 0x07C00
CS:IP = 07C0:0000  ->  0x07C0 << 4 + 0x0000 = 0x07C00   （同一字节！）
```

`boot/01_mbr_hello.asm` 在 QEMU 里的实测输出：

```
Hello from real-mode MBR!
CS=0000  IP=7C00  linear=7C00
ES=07C0  DI=0000  linear=7C00  byte=H'
Same byte, different segment:offset. Halting.
```

两行分别演示：`CS<<4 + IP` 的线性地址计算，以及**同一个物理字节
可以用不同的段:偏移写法访问**（这正是「程序重定位难题」的原始解药，
也是一切混乱的开端——同一个地址有 4096 种写法）。

段寄存器各司其职：CS 代码、DS 数据、ES 附加、SS 栈（配 SP）。

### 1.2 主引导扇区：一切从 0x7C00 开始

BIOS 加电自检后，把磁盘第一扇区（512 字节）加载到 `0x7C00` 并跳过去。
「主引导扇区」的门票是**最后两字节必须是 0x55 0xAA**：

```nasm
        org 0x7c00               ; 告诉 NASM：标号按 0x7C00 计
        bits 16
start:
        ...
        times 510-($-$$) db 0    ; 填充到 510 字节
        dw 0xaa55                ; 签名（小端存放即 55 AA）
```

为什么偏偏是 0x7C00？BIOS 自己要住在低地址（中断向量表 0x0000 起 1KB +
BIOS 数据区），DOS 时代又想留出 32KB 给自己——0x7C00 是历史妥协，
x86 传承至今改不动了（李忠 R2P 第 5 章有完整叙述）。

### 1.3 实模式的三大局限

1. **1MB 天花板**：段+偏移最多拼出 0xFFFFF（开启 A20 后可以「回卷」
   争议区，见 4.1），再多物理内存也够不着；
2. **没有任何保护**：任何程序可写任何地址、执行任何指令（包括 I/O、
   `hlt`），一个野指针就能踩死整个系统；
3. **多任务无从谈起**：没有「这是谁的地盘」的概念。

## 2. 显存与串口：实模式下的输出

文本模式显存在 0xB8000（色彩字符属性各一字节），向它写内存即上屏——
李忠的书用显存输出；本教程的引导链改用 **COM1 串口（0x3F8）**，
因为 QEMU 可以把串口直接接到 stdout，便于自动验证：

```nasm
putc:                           ; 轮询式发送 AL
        mov dx, 0x3FD           ; LSR 线路状态寄存器
.wait:  in al, dx
        test al, 0x20           ; bit5 = 发送保持寄存器空
        jz .wait
        mov dx, 0x3F8
        out dx, al
        ret
```

实测坑（QEMU 8.x，本机验证）：

1. **不初始化 UART 就发送，输出全是垃圾**（实测全部字节变 0x60）。
   要先按 115200-8N1 初始化：置 DLAB → 写除数 1 → LCR=0x03；
2. **例程必须完整保存寄存器**。曾把待发字符暂存 AH 却不恢复，而调用方
   `print_hex16` 的 `rol ax,4` 依赖完整 AX——结果第二个数位起全打成 '3'
   （AH 里的 0x30 高位被轮转进了 AL）。教训：**16 位代码里 rol 的是
   整个 AX，任何被调用例程都别碰调用者的 AH**；
3. 数字转字符串**先落缓冲区再整体输出**（`puts` 路径稳定），
   比在循环里逐字符嵌套 `call` 稳健。

## 3. BIOS 服务与两段式加载

一个扇区只有 510 字节可用，进了保护模式就再也不能调 BIOS（BIOS 是
16 位代码）。所以超过 512 字节的引导程序都是**两段式**：

1. 扇区 0（stage1）：仍处实模式，用 BIOS 磁盘服务把后续扇区读进内存，
   然后远跳过去；
2. 第二阶段：完成其余工作（进保护模式、开分页、进长模式……）。

读磁盘用 **BIOS 扩展读（INT 13h AH=42h）**——直接给 LBA 线性扇区号，
不用算老式 CHS（柱面/磁头/扇区）几何。它需要一个 16 字节的
**磁盘地址包（DAP）**：

```nasm
dap:
        db 0x10, 0               ; 包大小 16
        dw 32                    ; 读 32 个扇区（16KB）
        dw 0x0000, 0x0800        ; 目标 0800:0000 = 0x8000
        dq 1                     ; 起始 LBA = 1（扇区 0 是自己）
```

`boot/stage1.asm` 全文只有百余行：初始化段和栈 → 初始化串口 →
发一条扩展读 → `jmp 0x0000:0x8000`。实测输出：

```
S1: loaded 32 sectors, jumping to 0x8000
```

## 4. 32 位保护模式

### 4.1 先开 A20

8086 只有 20 根地址线，`0xFFFF:0x000F + 1` 这类地址会**回卷到 0**。
80286 地址线变多后，为兼容老程序，键盘控制器上专门加了一个
「A20 门」模拟回卷。要访问 1MB 以上内存，先得**打开 A20**。
最常用的 fast A20（端口 0x92）：

```nasm
        in  al, 0x92
        or  al, 0x02             ; bit1 = A20 enable
        and al, 0xFE             ; bit0 是复位位，绝不能置 1！
        out 0x92, al
```

（QEMU 默认 A20 已开，但真机和部分虚拟机不是——写上才稳。）

### 4.2 GDT：段的「户口本」

保护模式的段不再是「左移 4 位」，而是**查表**：段寄存器装的是
**选择子（selector）**——一个索引，指向**全局描述符表 GDT** 里的
**段描述符（descriptor）**。每个描述符 8 字节，描述一个段的真实属性：

```
 63  62  61  60   59   58  57  56  55  54  53  52   51   50  49  48
[ 基地址 31:24 ][G ][D/B][L ][AVL][界限 19:16][P ][DPL][S ][TYPE][基地址 23:16]
 47                              32  31                           16
[          基地址 15:0           ][          界限 15:0             ]
 15                                                           0
```

| 字段 | 含义 |
|------|------|
| 基地址（32 位，拆三段） | 段在线性地址空间的起点 |
| 界限（20 位，拆两段） | 段长度-1；**G=1 时粒度 4KB**（实际界限 = 界限×4096+0xFFF） |
| G | 粒度位：0=字节，1=4KB |
| D/B | 默认操作宽度（代码段 D，数据/栈段 B）：1=32 位 |
| L | 64 位代码段标志（长模式用，见[第 17 章](17_long_mode.md)） |
| P | 存在位：0 = 该段不在内存，访问即异常 |
| DPL | 描述符特权级 0-3 |
| S | 0=系统描述符（门/TSS），1=代码/数据段 |
| TYPE | 4 位类型：代码段（可执行/可读/一致性）或数据段（可写/扩展方向） |

这套「基地址和界限都拆开」的怪格式是 80286 的历史遗产——286 的描述符
只有 6 字节有效，386 扩展到 32 位时只能见缝插针（李忠 R2P 12.3 节
对此有详细考证）。

**平坦模型（flat model）** 是现代操作系统的标准玩法：基地址 0、
界限 4GB，一个代码段 + 一个数据段走天下，段的职责移交给分页：

```nasm
; 代码段：base=0, limit=0xFFFFF, G=1(→4GB), P=1, S=1, TYPE=1010(可执行可读)
        mov word [gdt+8+0], 0xFFFF       ; 界限 15:0
        mov word [gdt+8+2], 0x0000       ; 基地址 15:0
        mov byte [gdt+8+4], 0x00         ; 基地址 23:16
        mov byte [gdt+8+5], 0x9A         ; P=1 DPL=0 S=1 TYPE=1010
        mov byte [gdt+8+6], 0xCF         ; G=1 D=1 界限 19:16=F
        mov byte [gdt+8+7], 0x00         ; 基地址 31:24
; 数据段：TYPE=0010（可读写），其余同上 → byte5 = 0x92
```

GDT 第 0 项**必须是全零的空描述符**（选择子 0 = 「未装段」，加载即异常）。

装载用 `lgdt [mem]`——内存里放 6 字节：16 位界限 + 32 位基地址：

```nasm
        mov word  [gdtr], 23          ; 3 个描述符 ×8 -1
        mov dword [gdtr+2], gdt_addr
        lgdt [gdtr]
```

### 4.3 选择子与特权级

段寄存器（CS/DS/ES/SS/FS/GS）里装的 16 位选择子：

```
 15                 3  2  1  0
[      表内索引      |TI | RPL ]
```

- **TI**：0=查 GDT，1=查 LDT（进程私有表，现代系统基本弃用）；
- **RPL**：请求特权级——**CPL = 当前特权级 = CS 选择子的低 2 位**，
  0 是内核、3 是用户程序；
- **DPL** 是描述符里的「门票等级」。访问段要过 `max(CPL, RPL) ≤ DPL`
  的检查——这就是「保护」二字的落点：用户程序拿不到内核段的描述符，
  想装进 DS 都会被处理器以 #GP 拒绝。

### 4.4 切换序列：CR0.PE 与远跳

```nasm
        cli                     ; 切换期间不要来中断
        mov eax, cr0
        or  eax, 1              ; CR0.PE = 1
        mov cr0, eax
        jmp 0x08:pm_entry       ; 远跳转：立刻用新规则取指
pm_entry:
        bits 32
        mov ax, 0x10            ; 数据段选择子，重载所有数据段寄存器
        mov ds, ax
        mov es, ax
        mov ss, ax
        mov esp, 0xFFF0
```

两个不可省的细节：

1. **置 PE 后必须立刻远跳**——既刷新流水线里预取的 16 位指令，
   也把 CS 换成新世界的选择子；
2. **所有数据段寄存器要立刻重载**（实模式留下的值在保护模式下
   是不合法的「未定义」状态），SS 配合 ESP 重建栈。

`boot/02_pm32.asm` 的实测输出（QEMU）：

```
S2: A20 on, GDT at 0xC000, switching to PM...
[PM32] Hello from 32-bit protected mode!
[PM32] CR0=00000011  (PE=1, PG=0)
[PM32] GDTR: base=0000C000 limit=00000017
[PM32] CS=0008 (CPL=0)  DS=0010  ESP=0000FFF0
[PM32] byte at 0x7C00 (stage1 CLI) = 0xFA, flat model works
```

可以读出：CR0 = 0x11（PE=1、ET=1）；GDTR 里是我们刚建的表
（3×8-1 = 0x17）；CS=0x08（选择子 = 索引 1×8）且 CPL=0；
最后一行用 32 位寻址直接读到了实模式时代放在 0x7C00 的 stage1——
平坦模型下「历史内存」无缝可及。

## 5. 32 位模式下什么变了、什么没变

| 方面 | 实模式 | 32 位保护模式 |
|------|--------|---------------|
| 寻址 | 段×16+偏移（1MB） | 查 GDT → 线性地址（4GB，可再分页） |
| 指令默认宽度 | 16 位 | 32 位（前缀 0x66 反转） |
| 越界访问 | 静默回卷/踩内存 | #GP 异常 |
| 特权指令 | 无限制 | CPL=0 才能执行（`lgdt`/`mov cr0`/IO…） |
| BIOS 中断 | 可用 | **不可用**（BIOS 是 16 位代码） |

通用指令本身几乎不变——`mov`/`add`/`loop` 一套走天下，
变的是「地址怎么算、谁能访问哪」。

## 6. 本章实测坑清单

1. **fast A20 的 bit0 是 fast reset**，置 1 立刻复位机器——`or` 完必须 `and al, 0xFE`。
2. **GDT 第 0 项必须空**，`lgdt` 前先把它清零。
3. **SGDT 存的是 6 字节：16 位 limit 在前、32 位 base 在 +2**——
   按 8 字节结构从 +4 读 base 会得到 0（本教程实测翻车点）。
4. **进入 32 位后先重载 DS/ES/SS 再干活**；栈顶 ESP 给个 16 字节对齐的值。
5. **QEMU 串口不初始化就输出全垃圾；连续快写也偶发错位**——先 115200-8N1
   初始化，数字先转缓冲再 `puts`。
6. **16 位例程别碰调用者的 AH**（`rol ax` 类循环依赖完整 AX）。

## 7. IOPL 与 I/O 许可位图：I/O 的特权保护

保护模式对 **I/O 端口访问**（`in`/`out`）还有一层专门机制（《80X86汇编语言
程序设计教程》10.9 节的专题）：

- EFLAGS 的 **IOPL**（bit13:12）两位字段：只有 `CPL ≤ IOPL` 的代码才能
  执行 I/O 指令（以及开中断等敏感指令）；
- 用户程序（CPL=3）默认 IOPL=0，碰 `in`/`out` 直接 #GP；
- 但 TSS 里有一张 **I/O 许可位图**：每个端口一位，0=放行——操作系统
  可以精确到端口地给某个进程开 I/O 权限（老声卡/游戏杆时代的 DOS
  程序在 Windows 下跑就是靠这个 + V86）。

这也是[第 18 章](18_interrupts_exceptions.md)里 VEH 拦不住 `in/out`
越权的原因——I/O 保护不走页故障，直接 #GP。

## 8. V86 方式：在 386 里虚拟出一台 8086

32 位 CPU 还提供过第三种运行方式——**虚拟 8086（V86）**（80X86 教程
10.11 节用了整节 + 一个完整实例）：在**任务级**把 EFLAGS 的 VM 位置 1，
该任务就以 8086 语义运行（1MB 回卷寻址、IVT 中断），但仍在分页和
保护框架内——**每个 V86 任务是一台「软件 8086」**。

- 386 时代的 Windows 3.x 增强模式、Windows 9x 的 DOS 箱、NT 系的
  NTVDM，全靠 V86（或其模拟）跑 DOS 程序；
- V86 下的敏感指令（`cli/sti/hlt/in/out`、`pushf` 读 IOPL 的行为）
  会触发 #GP 陷入虚拟机监视器——这正是「虚拟化」的雏形；
- 64 位长模式**删除了 V86**（兼容模式最高只到 16/32 位保护模式），
  所以 64 位 Windows 跑不了 16 位 DOS 程序——NTVDM 只存在于 32 位
  系统。今天想要同样的东西，得用 VT-x（硬件虚拟化）或模拟器。
