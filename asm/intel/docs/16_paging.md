# 分页与虚拟内存

分段解决了「段的户口」，但只靠分段做不到：按需调页（内存不够用磁盘顶）、
写时复制、页级权限（可读不可写）、进程间隔离同一套线性地址……
这些都要靠**分页（paging）**——在段之上再盖一层「线性地址 → 物理地址」
的翻译机构。

本章参考李忠《从实模式到保护模式》第 19 章、李忠《x86汇编语言：编写64位
多处理器多线程操作系统》第 2.6-2.7 节与 3.7 节、Intel SDM Vol.3 第 4 章。
可运行示例是 [`boot/03_paging.asm`](../boot/03_paging.asm)——在
[第 15 章](15_real_protected_mode.md)的保护模式基础上开启 32 位分页。

## 1. 为什么分段之后还需要分页

分段以「段」为单位，最小也得 4KB，而且**每个段的基地址要程序员/加载器
操心**；分页以 4KB 页为单位，由硬件页表翻译，软件只管虚拟地址：

| 能力 | 只分段 | 分页 |
|------|--------|------|
| 线性地址 ≠ 物理地址 | 是（基地址平移） | 是（任意页粒度映射） |
| 同一虚拟地址在不同进程指向不同物理页 | 难（换 GDT/LDT） | 天生如此（每进程一张表） |
| 不存在的页访问时再分配 | 否 | 是（#PF 异常 + 按需调页） |
| 页粒度权限（R/W、U/S、NX） | 无 | 有（每页 3+ 个权限位） |

现代 x86-64 内核实际上把段「拉平」（base=0、limit=4GB），
**保护与映射全靠分页**——所谓「段页式」在 64 位下退化为「纯分页」。

## 2. 32 位两级分页

32 位线性地址按 **10-10-12** 三段拆开：

```
 31        22 21        12 11         0
[ 页目录索引 ][ 页表索引 ][ 页内偏移  ]
```

翻译过程（硬件每次内存访问都做一遍，靠 TLB 缓存结果）：

```
CR3 ──> 页目录（1024 项 ×4B，4KB 对齐）
          └─[目录项]──> 页表（1024 项 ×4B）
                          └─[表项]──> 物理页基址 + 偏移 = 物理地址
```

### 2.1 页目录项 / 页表项（PDE / PTE）格式

```
 31                            12  9  8  7  6  5  4  3  2  1  0
[        页表/页框基址 31:12   ][AVL][G][PS|0][A|D][A][U/S][R/W][P]
```

| 位 | 名称 | 含义 |
|----|------|------|
| P（0） | Present | 1=在内存；0=访问即 #PF（页故障） |
| R/W（1） | 读写 | 0=只读；1=可写（对 U/S=1 的页由 U/S 决定对谁只读） |
| U/S（2） | 用户/内核 | 0=CPL<3 才能访问；1=任何特权级 |
| PWT/PCD（3/4） | 缓存策略 | 写穿透 / 禁用缓存 |
| A（5） | Accessed | 处理器访问过自动置 1（换页算法的依据） |
| D（6） | Dirty | 写过自动置 1 |
| PS（7） | Page Size | **PDE 里=1 表示 4MB 大页**（跳过页表） |
| G（8） | Global | 切换 CR3 不失效该页的 TLB 项 |

注意基址字段只存高 20 位——页表和页框天然 4KB 对齐，低 12 位拿来
存属性，这是页表项的通用设计。

### 2.2 开启分页的序列

1. 建页目录、页表（内存清零后逐项填写）；
2. `mov cr3, 页目录物理地址`；
3. `mov eax, cr0; or eax, 0x80000000; mov cr0, eax`（CR0.PG=1）。

**开了 PG 的下一条指令取指立刻走页表翻译**——所以页表必须先映射好
当前正在执行的代码（最简单：低 4MB 恒等映射，虚拟地址 == 物理地址）。

## 3. 实测：一张页表，两个虚拟区间

`boot/03_paging.asm` 的设计直接演示「翻译」的本质：**同一张页表**
挂进页目录的两个槽位——

- `PDE[0]`：虚拟 `0x00000000~0x003FFFFF`（恒等映射物理 0-4MB）；
- `PDE[768]`：虚拟 `0xC0000000~0xC03FFFFF`（映射**同一个**物理 0-4MB）。

768 = `0xC0000000 >> 22`。于是一个物理字节有了两个虚拟地址。
QEMU 实测输出：

```
[PG32] Hello from 32-bit protected mode!
[PG32] PD at 0x10000, PT at 0x11000 (identity 0-4MB, high 0xC0000000)
[PG32] CR3=00010000
[PG32] Paging enabled. CR0=80000011 (PG=1)
[PG32] high[0xC0000000]=F000FF53 low[0x00000000]=F000FF53 (same phys page)
[PG32] write [0xC0000100]=DEADBEEF, read [0x0100]=DEADBEEF -> read back OK
```

两个验证各有含义：

1. 高端地址 `0xC0000000` 读出的 32 位值与低端 `0x0` 完全一致
   （`F000FF53` 是 QEMU 物理地址 0 处 IVT 首项的值）——翻译指向同一页；
2. 往 `0xC0000100` 写魔数 `DEADBEEF`、从 `0x00000100` 读回一致——
   **写路径和读路径走的是同一个物理页**，虚实分离但物理唯一。

这也正是 Linux 内核把自身映射到 `0xC0000000+` 的同一手法。

## 4. TLB 与性能

每次访存都走两三次页表（目录→表→页框）太慢，x86 用 **TLB**
（Translation Lookaside Buffer，翻译后备缓冲）缓存「虚拟页 → 物理页」
结果。要点：

- TLB 对软件透明，但**不主动失效**：改了页表内容要主动失效对应项——
  `invlpg [线性地址]`，或整个换掉 CR3（非全局页全部失效）；
- PTE 的 **G 位**让常用内核页在 CR3 切换时保留（这就是每个进程
  切换不全清 TLB 的原因）；
- 多核下改页表还要**处理器间 TLB 击落（shootdown）**——这是内核里
    最微妙的一类代码，见[第 19 章](19_multicore_atomic.md)。
- **PCID**（CR4.PCIDE）给 TLB 项打「地址空间编号」标签，切 CR3
  时不 flush 而是「换标签」，减少无谓失效（李忠 2024 第 3.7.12 节
  有展开，x86-64 时代默认可用）。

## 5. 大页

4KB 页对大内存太碎。x86 提供大页：

| 模式 | 大页 | 开启方式 |
|------|------|----------|
| 32 位（非 PAE） | 4MB | PDE 的 PS=1（CR4.PSE 开） |
| 32 位 PAE | 2MB | PDPT 直出到页框 |
| x86-64 4 级 | 2MB / 1GB | PD/PDPT 的 PS=1 |

大页省页表内存、提 TLB 命中率——内核映像、大数组值得用。
[第 17 章](17_long_mode.md)的 `boot/04` 就用 2MB 大页一次恒等映射 1GB。

## 6. #PF：页故障是特性不是错误

P=0 的页被访问 → **#PF（向量 14）**，CR2 自动存下出错的线性地址，
栈上压入的错误码给出原因（读/写、用户/内核、页不存在/权限）。
操作系统的页故障处理程序据此实现：

- **按需调页**：磁盘换入再返回重执行（fault 语义，见
  [第 18 章](18_interrupts_exceptions.md)的 fault/trap/abort 分类）；
- **写时复制**：只读页被写 → 复制一份再改权限；
- **缺页换出**：物理内存不足时逐页换到磁盘。

「异常驱动」是虚拟内存的灵魂——访问不存在的页不是崩溃，是机会。

## 7. 从 32 位到 64 位：表变四级

物理地址超过 4GB 后两级页表不够用，x86-64 采用 **4 级分页**
（PML4 → PDPT → PD → PT，线性地址 48 位有效，见[第 17 章](17_long_mode.md)
第 4 节）与 5 级（57 位，LaSP 级服务器）。32 位时代还有过渡方案
**PAE**（Physical Address Extension）：36 位物理地址、三级表、
表项变 8 字节——它恰恰是进入长模式的**前置要求**，所以
`boot/04` 的第一页代码里就有 `CR4.PAE=1`。

## 8. 本章坑清单

1. **开 PG 前必须先备好 CR3 与恒等映射**，否则「打开分页的那条
   `mov cr0` 之后」的下一条取指直接 #PF——而且此时还没异常处理程序。
2. **页目录/页表必须先清零再填**——残留的「P=1 + 随机基址」项
   是定时炸弹（表项只填 dword 时高 4 字节别忘清）。
3. **CR3 装的是物理地址**，且 4KB 对齐。
4. **改页表后要 invlpg / 重装 CR3**，TLB 不会自己发现你改了表。
5. 32 位表项是 **4 字节**、PAE 与 x86-64 是 **8 字节**——同一份
   「填表循环」代码在两种模式下的 `add edi, 4/8` 不一样。
