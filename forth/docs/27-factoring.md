# 27 · 风格与分解：Thinking Forth 实践

对应示例：`../examples/27-factoring.fs`

素材：《Thinking Forth》第 5 章 Implementation（Choosing Names）、
第 6 章 Factoring、《第四代计算机高级语言 FORTH》摩尔序（1985）。

## Brodie 的分解判据

1. **起不出好名字** → 这段逻辑本身不对劲；
2. **栈注释写不清**（`( a b c d -- c a*b+d )` 这种）→ 拆；
3. **同样的栈序戏法出现第二次** → 提成词；
4. **一个词超过 7~9 行**、一块屏幕要翻页 → 拆；
5. 注释在解释「怎么做」而不是「为什么」→ 换个分解角度。

## kata：罗马数字，同一个题写两遍

版本 1（反面教材）：13 段雷同的 `begin/while` 一路堆下去——每段只是
「值」和「符号」不同，复制粘贴的坏味道扑面而来。

版本 2：把「值/符号」提进数据表，代码只剩一个循环：

```forth
create 罗马对  1000 , s-M ,  900 , s-CM ,  ...  1 , s-I ,
: 罗马-表  ( n -- )
  13 0 do
    begin  dup i 罗马值 >=  while
      i 罗马符 count type   i 罗马值 -
    repeat
  loop  drop ;
```

示例里两版**对拍**（1988 → MCMLXXXVIII、3888 → MMMDCCCLXXXVIII），
输出逐字符一致。这就是 Brodie「**数据结构能消灭控制结构**」的落点。

## 横向 vs 纵向

```forth
: 摄氏→华氏-横  ( f -- f )  9e0 f* 5e0 f/ 3.2e1 f+ ;   \ 64 列时代遗产
: 摄氏→华氏  ( c -- f )
  9e0 f*          \ ( -- c*9 )
  5e0 f/          \ ( -- c*9/5 )
  3.2e1 f+ ;      \ ( -- c*9/5+32 )
```

纵向排版 + 逐行栈注释，是最便宜的文档。

## 命名就是设计

反面例子在示例里排成一列：`proc2`（过程流水账名）→ `总价`（暴露不了
魔法数）→ `含运费总价`（把魔法数请成 `constant 运费`）。
**起名的过程会逼你想清楚这个词的边界**——想不清楚的名字 = 想不清楚的
设计。

## Moore 说（中文版序言原话，1985）

> 「FORTH 的成功之处在于简明性。但简明并不意味着简单，而是指精巧。」

> 「只有找到有合适名称的单词，才是更有用的单词。」

> 「你可以为 FORTH 的每一个词严格挑选一个恰当的名称……要使单词容易
> 记忆、解释和形成文件。」
