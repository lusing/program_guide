# 20 变量——一个存放资料的地方

> 本章对应原书第 18 章"变量：一个存放资料的地方"。到这里你已经是熟练的 Shell 用户；从本章起的四章（20–23）把"语言"正式补齐——变量、字符串、数组、哈希表这些所有脚本的地基。

## 20.1 变量是什么：带名字的盒子

**变量是内存里一个带名字的盒子**：放进去一个对象，之后按名字取用。PowerShell 的变量哲学宽松得可爱：

- **不用声明**：第一次赋值即创建（`$name = 'value'`）；
- **类型随便换**：这一刻装字符串、下一刻装服务集合，语言不拦你（但换着装是自找麻烦，见 20.6）；
- **`$` 不是名字的一部分**：`$var` 的名字是 `var`，`$` 只是"后面跟的是变量"的信号；
- **名字规则**：字母/数字/下划线，以字母或下划线开头；要含空格等特殊字符得用花括号 `${My Variable}`（能不用就不用）；
- **会话即寿命**：关掉 Shell 全部清零（要持久化就写文件或进 profile）。

命名是可读性的一半：`$computername`、`$services`、`$failedDisks` 这样的名字让脚本自解释；`$x`、`$tmp2` 是给未来读代码的你挖坑。

## 20.2 引号规则：单引号、双引号与反引号

字符串是变量里最常装的东西，而引号规则是新手错误的重灾区。一次讲透。

**单引号=字面**：里面是什么就是什么，**什么都不展开**。

```powershell
$name = 'ServerR2'
'the name is $name'      # 输出：the name is $name（原样）
```

**双引号=展开**：`$变量` 换成值，子表达式 `$(命令)` 先执行再嵌入。

```powershell
"name = $name"                        # name = ServerR2
"count = @(1,2,3).Count"              # count = @(1,2,3).Count —— 属性不展开！
"count = $(@(1,2,3).Count)"           # count = 3 —— 要子表达式 $() 包一层
"today = $(Get-Date -Format 'yyyy-MM-dd')"
```

第三行是高频坑：**双引号只展开"裸的 `$变量`"，属性访问、方法调用、表达式必须包进 `$(...)`**。

**反引号 `` ` `` = 转义**（仅在双引号里有意义；单引号里它就是普通字符）：

| 转义 | 含义 |
|---|---|
| `` `$ `` | 字面美元符（不让它当变量） |
| `` `n `` | 换行 |
| `` `t `` | Tab |
| `` `" `` | 字面双引号（双引号串里嵌引号） |
| `` `` ` `` ``（行尾） | **续行**——长命令折行不断句 |

体验原书的经典例子：

```powershell
$computername = 'SERVER-R2'
$phrase = "`$computername`ncontains`n$computername"
$phrase      # $computername↵contains↵SERVER-R2 —— 转义的 $ 原样、`n 换行、裸 $ 展开
```

**引号选择的纪律**：默认用单引号（字面最安全），只在确实要展开时换双引号——这能防住一大类"字符串里恰好有 `$` 被意外展开"的事故（正则、密码、JSON 里尤其重要）。

**Here-string（多行字符串）**：以 `@"`（展开）或 `@'`（字面）开头，**内容任意换行**，以顶格的 `"@`/`'@` 结束：

```powershell
$report = @"
巡检报告
机器：$name
磁盘：$(@(Get-CimInstance Win32_LogicalDisk).Count) 枚
"@
```

收尾标记**必须顶格**（前面不能有空格）是 here-string 第一坑；展开规则与对应引号一致（`@'...'@` 全字面，写正则、写 JSON 模板首选）。

## 20.3 数组：一个盒子装一排

逗号创建数组（**逗号在引号外**）：

```powershell
$computers = 'SERVER-R2', 'SERVER1', 'localhost'    # 3 个字符串对象
```

访问与计数：

```powershell
$computers[0]        # SERVER-R2 —— 索引从 0 起
$computers[-1]       # localhost —— 负索引从尾部数
$computers[0..1]     # SERVER-R2, SERVER1 —— 切片（区间）
$computers.Count     # 3
```

**单元素陷阱**（本章头号坑）：`$one = 'a'` 后 `$one.Count` 在 5.1 里**报不出 3 而可能出错或为空**（字符串没有 Count……其实 3.0 起标量 `.Count` 返回 1，但 `+=` 累积、管道单结果等场景下"标量还是数组"的歧义从未消失）。两个防御姿势：

```powershell
$safe = @('a')                     # 显式数组子表达式 @()，永远明确
$count = @($maybe).Count           # @() 包裹再计数，标量/数组通吃
$oneItem = @('only')               # 真要单元素数组：@('only') 或 ,'only'
```

**`@()` 数组子表达式**是本章最重要的工具：包住任何表达式，结果**保证是数组**——管道零结果给空数组、单结果给单元素数组。第 21 章讲它还有个孪生兄弟 `@{}`。

增删与拼接：

```powershell
$all = $computers + 'NEWSRV'       # + 拼接出新数组
$computers += 'ANOTHER'            # 追加——注意：数组不可变，这句是"复制整个数组再追加"！
$computers -eq 'localhost'         # 第 11 章的数组过滤特性
```

`+=` 的隐藏成本值得知道：**PowerShell 数组定长**，每次 `+=` 都全量复制。循环里 `+=` 千次 = 千次复制，正确写法是收集到 `List` 或直接用管道输出让引擎收集：

```powershell
$list = [System.Collections.Generic.List[string]]::new()
foreach (...) { $list.Add($x) }        # 或者更 PowerShell：$result = foreach (...) { $x }
```

## 20.4 哈希表：一个盒子装一对对

`@{}` 创建**键值对集合**（.NET 的 Hashtable）：

```powershell
$svc = @{ Name = 'Spooler'; Machine = 'SRV1'; Port = 9100 }
$svc.Name            # 点访问：键名是简单标识符时
$svc['Machine']      # 索引访问：键含特殊字符、键在变量里、键要拼接时——唯一全能写法
$svc.Keys; $svc.Values; $svc.Count
$svc['Location'] = 'BJ'      # 加一对；$svc.Remove('Port') 删一对
```

两种键访问的分界：**点访问快而好读，但键必须"长得像标识符"且是字面量**；要 `$key` 变量、要 `'含空格 键'`、要运行时拼键名，只有方括号。原书特意提的坑：键名与**哈希表自带成员**撞车时（如 `Keys`、`Count`），点访问命中自带成员——此时也必须方括号。

**有序哈希表**：`@{}` 不保证键序（哈希表的天然属性），要"按插入顺序枚举"用 `[ordered]`：

```powershell
$ordered = [ordered]@{ First = 1; Second = 2; Third = 3 }
[pscustomobject]$ordered          # 顺手一转：哈希表 → 对象（第 08 章 PSCustomObject 的出生地！）
```

第二行是极常用的桥：**哈希表是"造对象"的字面量语法**——CSV 行、计算属性内部、对象模板都靠它。遍历：

```powershell
foreach ($kv in $ordered.GetEnumerator()) { "$($kv.Key) = $($kv.Value)" }
```

（`.GetEnumerator()` 而不是直接遍历哈希表本身——后者在遍历中会因"集合已修改"类问题绊倒修改操作。）

## 20.5 类型：给盒子贴标签

变量可以**显式约束类型**（方括号类型字面量，第 08 章 `::` 的同族语法）：

```powershell
[int]$port = 9100          # 以后赋值会被强转：'9200' 字符串也能进（转成功）；'abc' 直接报错
[string]$name = 'srv'
[datetime]$due = '2026-10-06'    # 字符串自动解析成日期！
[double]$ratio = '0.85'    # 隐式转换的福利
```

类型约束的价值：**把"运行到一半才发现装错了东西"提前到赋值瞬间报错**。常用类型速记：`[int]/[long]`、`[double]`、`[string]`、`[bool]`、`[datetime]`、`[string[]]`（类型加 `[]` = 该类型数组）、`[scriptblock]`（脚本块本身也是值！）。

配套的"温和转型"运算符 `-as`（失败给 `$null` 不抛错）与类型判断 `-is`（第 11 章已见）：

```powershell
'42' -as [int]        # 42
'abc' -as [int]       # $null —— 不炸，判空即可
'42' -is [string]     # True
```

**解析与转型的分界**：`[int]'3.14'` 报错（整型装不下小数）而 `[double]'3.14'` 成功；`[int]'42'` 成功因为字符串解析包含了转换——理解"目标类型能否容纳源值"这一层，转型报错就都能读通了。

## 20.6 特殊变量与判空方向

三个特殊值值得单独点名：

- **`$null`**：空。**判空必须 `$null -eq $x`（把 $null 放左边）**——`$x -eq $null` 在 `$x` 是数组时会变成"过滤 null 元素"（第 11 章数组比较特性的直接后果），结果静默错误。这条纪律全教程强制。
- **`$true` / `$false`**：布尔字面量。比较的结果就是它们：`(5 -gt 3) -eq $true` 恒真，但直接 `$result` 判断更地道（布尔本来就用在条件里）。
- **`$_` / `$PSItem`**：管道当前对象（第 11 章起的老朋友，本质是自动变量）。

**Set-StrictMode**：把"未定义变量当空值"的宽松行为变成报错：

```powershell
Set-StrictMode -Version Latest
$undefinedVar        # 报错：未定义 —— 脚本开发的标配防线
```

交互会话嫌它烦可以不开，**写进脚本/模块的头部**（第 22 章起会这么干）——拼写错误的变量名从"静默空值"变成"当场报错"，值得。

变量清单随时可查（第 05 章的伏笔）：`Get-ChildItem Variable:` 列出当前会话全部变量（含 `$PID`、`$PSVersionTable` 等自动变量）。

## 20.7 本章高频坑位

| 现象 | 原因 | 对策 |
|---|---|---|
| 字符串里 `$` 意外展开/没展开 | 引号选错或忘了 `$()` 包表达式 | 默认单引号；要展开用双引号+`$()` |
| `"$x.Length"` 打出 `.Length` 字面量 | 属性不展开 | `"$($x.Length)"` |
| here-string 结尾报语法错 | 收尾 `"@` 没顶格 | 顶格，前面零空格 |
| `.Count` 时有时无 | 单元素（标量）与数组歧义 | `@($x).Count` 或赋值时 `@()` |
| 循环 `+=` 越跑越慢 | 数组不可变，全量复制 | List 或管道收集 |
| 判空结果诡异 | `$x -eq $null` 撞上数组语义 | **`$null -eq $x`** 方向铁律 |
| 点访问哈希键拿错东西 | 键名撞自带成员/含特殊字符 | 方括号 `$h['键']` |
| 转型报错"无法转换" | 目标类型装不下源值 | 检查目标类型；解析场景用 `[datetime]` 这类自带解析的类型 |

## 20.8 本章要点

- 变量=免声明、可换型的盒子；`$` 是信号不是名字；命名即文档。
- 引号三律：**单引号字面、双引号展开（表达式要 `$()`）、反引号转义**（`` `$ ``/`` `n ``/`` `t ``/行尾续行）；here-string 收尾顶格。
- 数组：逗号创建、`[0]`/`[-1]`/`[0..2]`、**`@()` 保证数组形态**、`+=` 有复制成本、`-eq` 兼职过滤。
- 哈希表：`@{}`、两种键访问分界、`[ordered]` 保序、**哈希表→`[pscustomobject]` 是造对象的字面量**。
- 类型：`[int]$x` 约束防装错、`-as` 温和转型、`-is` 判型；`$null -eq $x` 方向铁律；StrictMode 进脚本头。

**动手实验**：① 把 20.2 的转义例子逐条跑一遍；② `$a='x'; $a.Count`、`@($a).Count`、`@('x').Count` 三个表达式对比；③ 循环 1000 次 `$arr+=1` 与 List.Add 各测一次耗时（`Measure-Command`）；④ 造有序哈希表转对象，`gm` 看 TypeName；⑤ `[int]'3.14'`、`[double]'3.14'`、`'3.14' -as [int]` 三连看谁报错谁温和；⑥ `Set-StrictMode -Version Latest` 后引用未定义变量看报错；⑦ `$x=1..3; $x -eq $null` 与 `$null -eq $x` 各看一眼，把方向铁律刻进肌肉。

实验参考：②标量 `.Count` 在 3.0+ 意外返回 1（语言后来的补丁），但 `@()` 包裹仍是唯一可移植写法——两个引擎都稳；⑤`'3.14' -as [int]` 返回空——转型失败温和给 null；⑦数组在左时 `-eq $null` 返回空数组（假值成立但语义全错），是方向铁律的实锤。
