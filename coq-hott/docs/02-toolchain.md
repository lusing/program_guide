# 02 三条设计选择 —— HoTT 与普通类型论差在哪

> 对照代码：[`examples/02_toolchain.v`](../examples/02_toolchain.v)

Coq-HoTT 不是装在 Coq 上的一个插件，而是**替换了 Coq 的地基**。这一章不讲安装和编译，只讲三件读下去之前必须理解的事：它为什么没有 `Prop`、它为什么把公理做成假设而不是全局事实、以及同一个记号为什么会有好几种含义。这三条都是设计选择，每一条都对应同伦类型论的一个立场。

## 2.1 一切都在 `Type` 里

标准 Coq 把世界分成两层：`Prop` 装着命题（证明之间不可区分），`Type` 装着数据。这个分层默认接受了 proof irrelevance：一个命题至多一种证明方式。

HoTT 不能接受这个分层。第 01 章已经说了：`x = y` 是一个普通类型，它的居民可以有很多个。如果硬把它塞进 `Prop`，圆的环路、球面的高阶同伦从一开始就被抹平了。

所以这个库做了三件事：

- 相等类型 `paths` 落在 `Type` 里，被认真对待，而不是被 proof irrelevance 压扁。
- `nat`、`Bool`、乘积、和、Σ 都重新定义一遍，带着自己的宇宙层级。
- **没有 `Prop` 这个宇宙。** “是不是命题”变成了一个可以证明的性质（第 09 章的 `IsHProp`），而不是语法上的分类。

这就是为什么示例文件永远以 `Require Import HoTT` 开头，并且编译时要挡住标准库。基础类型同名不同义：你在别处学的 `nat` 和这里的 `nat` 不是同一个定义。作为读者，把它们当成“为同伦论重新铺过的地基”即可。

一个直接后果：命题和数据用同一套规则。后面会看到，这不是混乱，而是统一——命题是路径结构特别简单的那些类型。

## 2.2 公理是假设，不是空气

HoTT 有两条著名公理：**函数外延**（逐点相等的函数相等）和**泛等**（等价的类型相等）。许多基础把公理写成全局事实，一旦加载就永远在。这个库的做法不同：

- 把每条公理做成一个**空的类型类**：没有构造子，本身不断言任何事。
- 需要公理的定理把它写成参数：`Context `{Funext}` 的意思是“假设函数外延”。
- 真正断言“公理成立”的实例放在单独的模块里，用的时候才导入。

这样做的好处是概念上的：**每一条定理用到了什么公理都可以被列出来。** 路径代数、transport、等价论，全部零公理。函数外延和泛等只在真正需要它们的地方出现。你始终知道自己信了什么。

一个常见的误解由此而来：`Require Import HoTT` **不给你公理的实例**。导入的是定义和定理。当你看到某个函数的类型里挂着“请提供泛等”，那是在说调用方必须做出选择——要么把公理当假设，要么显式导入实例。第 10、11 章会演示这两种方式。

第 23 章会说明如何审计任意一条定理的公理依赖。现在只需记住原则：**零公理的结论和依赖公理的结论，地位不同。** 本教程会一直标明这个差别。

## 2.3 记号跟着工作走

同一个符号在不同语境里指不同的东西，这不是缺陷，而是因为这本书同时谈论路径、等价、类型和算术。最重要的几组：

| 语境 | `1` 的含义 | `+` / `*` 的含义 |
|---|---|---|
| 路径 | 恒等路径 `idpath` | （不用） |
| 等价 | 恒等等价 | （不用） |
| 类型 | （不用） | 和类型 / 乘积 |
| 自然数 | 数字 1 | 加法 / 乘法 |
| 截断层级 | （不用；`0` 是 0 层） | （不用） |

库默认工作在路径语境里，所以**裸写的 `1` 是恒等路径**。这和第 01 章的立场一致：路径是主角。想写算术就显式标记，想写等价的单位元也显式标记。

`^-1` 也有两个版本：一个是等价的反函数（类型 `B -> A`），一个是逆等价（类型 `B <~> A`）。日常使用它们可以互换，但它们不是同一个东西——一个是函数，一个是打包了逆与证据的等价。

读下去时，看到不认识的符号，先问“当前在谈论路径、等价、还是算术”，十有八九就能判读。

## 2.4 一个语义开关，不是编译选项

编译命令里有一个叫 `-indices-matter` 的开关。它的含义是数学的，不是工程的。

Coq 默认在计算一个归纳类型所在的宇宙时，只看参数不看索引。对 `paths` 这样的索引族，这会让 `x = y` 落在比 `A` 更低的宇宙里，进而在某些推理里产生不一致。HoTT 要求索引也参与宇宙计算。作为读者你不需要操心它，只需知道：这不是可选优化，而是恒等类型作为空间这一立场的技术后果。

## 读例子时的四条问询

正文里几乎不再依赖这些命令。但如果你打开对应的 `.v` 文件，它们能帮你看清一个名字到底是什么：

- 看类型，确认一条引理在说什么。
- 看完整信息：隐式参数、作用域、定义位置——用来排查“为什么它被解析成了别的东西”。
- 看定义体：一个引理是怎么证的、一个类型有哪些构造子。
- 查记号属于哪个作用域。

其中最有概念含量的一次查看：相等类型的真身是“起点为参数、终点为索引、只有一个构造子”。这个区分决定了路径归纳的形状，第 04 章会用到。

## 小结

- HoTT 没有 `Prop`：一切都在 `Type` 里，“是命题”是可以证明的性质。
- 公理是显式假设，不是全局空气。大部分几何零公理；函数外延和泛等按需引入。
- 记号跟着工作走；默认语境是路径，所以裸写的 `1` 是恒等路径。
- `-indices-matter` 是恒等类型作为空间的语义要求。

## 常见误区

1. **以为导入库就已经承认了泛等。** 没有。公理必须被显式请求。
2. **以为 `1 + 1` 是算术。** 在默认语境下它根本不是加法。
3. **把“这条定理不依赖任何公理”当成报错。** 那是好消息：结论是纯构造性的。
4. **把尚未确定的隐式参数当成错误。** 给足信息它们会消失；它们不是类型错误。

## 练习

1. 预测：路径复合的单位律、函数外延、泛等，这三者里哪些需要公理？读到第 11 章后再回来核对。
2. 想一想：如果库把 `Prop` 留下来，并规定 `x = y` 落在 `Prop` 里，哪些后文中的现象会立刻消失？
