# 23 公理意味着什么

> 对照代码：[`examples/23_metatheory.v`](../examples/23_metatheory.v)

前 22 章在做数学。这一章换一个视角：一条定理到底信了什么，以及这个区分为什么是同伦类型论的一部分，而不只是工程习惯。找引理、读定义、排查类型类——这些技能是为了让你能把前面学的东西用到自己的推理里，它们服务于理解，而不是反过来。

## 23.1 零公理核心很大

HoTT 库把两条公理做成显式假设，于是每条定理的公理用量都可以被列出来。这是一种诚实：你始终知道自己信了什么。

三个层次：

- 路径代数、transport、伴随等价、纤维可缩 ⟺ 等价——全部零公理。HoTT 的“无公理核心”很大。
- 从逐点同伦造函数相等——函数外延。
- 把等价变成类型之间的路径、圆的覆叠、`loop ≠ 1`、π₁(S¹) = ℤ——泛等。

规律很清楚：**只有在把等价提升为路径，或比较两个函数时，才需要公理。** 等价论的几乎全部内容是零公理的。

读公理清单时要知道三件事：

1. **泛等蕴含函数外延。** 用了泛等的定理会自动带上函数外延。这不表示多用了一条公理。
2. **HIT 规则会出现在清单里。** 路径构造子和计算规则在数学上是构造性的归纳规则，不是逻辑公理；但 Coq 没有原生 HIT，库用公理模拟它们，机器分不出来。名字里带 glue、beta、ind 的通常是 HIT 规则。
3. **清单会随实现变动。** 数学上的依赖关系不会变：比较函数要外延，等价变路径要泛等。

## 23.2 看懂路径引理的真身

路径复合、搬运，定义都是只有一个分支的情形分析——因为恒等类型只有一个构造子。返回类型里出现目标，这就是路径归纳在实现里的样子。看懂这两段，就看懂了第 04、05 章的全部：它们不是巧妙的 tactic，而是 J 规则的直接书写。

一个相关的设计：复合和搬运被标记为“化简时不要暴露内部的情形分析”。这解释了为什么盲目化简对它们“什么都不做”——那是刻意的，防止目标变成一团无法阅读的匹配。要化简它们，用它们满足的律（单位律、结合律、搬运的函子性）。化简不动不是失败，是在要求你用数学而不是用计算。

## 23.3 找事实，而不是找名字

库很大，名字记不住。记住形状：

- 给具体类型缩小范围，否则形状模式会刷出几百条。
- 按结论的形状找，不按名字找。移项家族、搬运在路径类型上的公式，都是形状一旦写出就能认出来的。
- 找到候选后确认方向。库里大量事实成对出现、方向相反。名字只能提示，类型才能确认。

类型类搜索失败时，按频率排：公理没引入；截断层级的实例找不到（先单独问“`Bool` 是不是集合”，能找到就说明实例在库里）；目标形状不对（比如截断的消去要求目标已经是 n-型）。前两个是“假设没给够”，第三个是证明策略的问题。

记号出乎意料时，八成是语境问题：当前默认的是路径、等价还是算术？类型类缺信息时会随便挑一个匹配的实例，打印出奇怪的类型变量——给具体类型就恢复正常。这不是 bug。

## 23.4 零公理、外延、泛等

把本教程的结论按公理分组：

| 零公理 | 需要函数外延 | 需要泛等 |
|---|---|---|
| 路径群胚律 | 函数相等 | `Type` 不是集合 |
| transport 的全部性质 | Π 类型的截断层级 | 结构搬运 |
| 伴随等价 | “是等价”“是命题”为命题 | 圆的覆叠、`loop ≠ 1` |
| 纤维可缩 ⟺ 等价 | HIT 的泛性质 | π₁(S¹) = ℤ |
| 乘积、Σ、和的路径刻画 | | 范畴的单叶性 |
| 截断层级的基本推理 | | |
| HIT 的消去子与计算规则 | | |

一个值得记住的事实：几何的大部分——空间、路径、纤维、等价、截断——不依赖那两条著名公理。公理只在两个接口进场。

## 23.5 几条服务于理解的习惯

- 写定理时先决定公理立场。库代码把公理当参数，让使用者选择；应用代码可以直接承认。
- 路径证明先写类型再写步骤。把每一步的路径类型写出来，方向错误会立刻暴露。
- HIT 的路径计算规则是命题性的，化简不会动它们。
- 由等价造出的路径用行为律化开，别指望计算。
- 遇到对称孪生的引理，看类型而不是猜名字。

## 小结

- 每条定理的公理用量可以列出来；“不依赖任何公理”是好消息。
- 泛等蕴含外延；HIT 规则会出现在清单里，它们不是逻辑公理。
- 路径引理的真身是 J 规则；化简不动是在要求你用律，而不是用计算。
- 只有两个接口需要公理：比较函数，以及等价变路径。

## 常见误区

1. **把 HIT 规则当成逻辑公理。** 它们是构造性规则。
2. **以为化简不动搬运是失败。** 那是设计，用律化简。
3. **靠名字猜引理方向。** 成对出现的事实一定要看类型。
4. **把缺约束时的任意统一当成类型错误。** 给具体类型即可。
