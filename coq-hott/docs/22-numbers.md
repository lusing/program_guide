# 22 自然数与整数 —— 集合层面的 HoTT 就是普通数学

> 对照代码：[`examples/22_numbers.v`](../examples/22_numbers.v)

读到这里，你可能会怀疑 HoTT 是不是把一切都搞复杂了。这一章的目的是打消这个怀疑：当类型是集合时，HoTT 和你熟悉的数学**毫无差别**。算术、序、归纳证明，全是老样子。HoTT 并没有改造 ℕ 和 ℤ，它只是把“集合”从默认假设变成了一个可以证明的性质。

## 22.1 自然数还是那个自然数

自然数由零和后继生成，加法在第一个参数上递归，乘法由加法定义——和任何一本类型论教材一样。交换律、结合律、分配律都在，证明方法也是归纳。

需要适应的只有记号优先级：在一本以路径为主角的库里，裸写的 `+`、`*`、`0`、`1` 优先表示类型运算和路径。写算术时加上“这是自然数”的标记即可。这不是数学的改变，是语境的改变。

## 22.2 序关系是命题，可判定是另一回事

`n ≤ m` 是一个类型，它的元素是“n ≤ m 的证明”。这是“命题即类型”的直接体现。它恰好是命题：任意两个“n ≤ m”的证明相等。

“是命题”和“可判定”是两个概念。可判定意味着 `A` 或 `¬A` 有一个构造性的选择。自然数上的序当然可判定，但一般的命题不必可判定——HoTT 是构造性的，排中律不是默认成立的（虽然可以作为公理加入，与泛等相容）。

## 22.3 自然数是集合

这是定理，不是默认。来源是 Hedberg 定理：相等可判定的类型是集合。自然数的相等可以逐位比较，所以是集合。于是任意两条平行路径相等——UIP 在自然数上成立，因为它是集合。

后继是单射，而且不需要任何公理：造一个“去掉一层后继”的类型族，沿 `S n = S m` 搬运。这正是第 05 章“造族 + 搬运”套路，用在最普通的数学对象上。

## 22.4 归纳证明没有新花样

`0 + n = n` 按定义成立（加法在第一个参数上递归）。`n + 0 = n` 需要归纳：零情形是恒等路径，后继情形让后继作用在归纳假设上。这里的“作用”就是第 04 章的 `ap`——在集合里它只是“两边同时套函数”，但它也是在高阶类型里把路径映到路径的那个 `ap`。**同一个工具，不同层级的用法。**

零加 n 等于 n 的证明是恒等路径，因为两边定义性相等。这又一次提醒：默认的 `1` 是路径不是数字——而在这里，路径恰好是我们要的证明。

## 22.5 整数：两份自然数背靠背

整数的一种无冗余表示：负的后继、零、正的后继。每个整数恰好一种写法，没有“+0 和 −0”。后继与前驱互逆，于是后继是自等价。

这个自等价在第 13 章的编码-解码里扮演关键角色：它的泛等路径就是圆上螺旋覆叠绕一圈的效果。整数也是集合，并且有整环结构。自然数的减法是截断的（不够减就得零），整数的减法是真正的减法——同一套符号，两种语义，这是分语境的理由之一。

## 22.6 这一章想说的话

HoTT 的高阶机器——路径代数、等价、截断、泛等——是为**非集合**的类型准备的：`Type`、圆、球面、范畴。在集合里，所有这些机器要么退化为平凡（UIP），要么退化为熟悉的概念（等价 = 双射，嵌入 = 单射，“仅仅”= 经典存在）。

这意味着：从 HoTT 做普通数学没有额外成本。它只是比传统基础多了两件事——一是把“是集合”变成了可证明的性质而非默认假设，二是在需要的时候，给了你一整层以前不存在的工具。

名字偶尔会撞车：代数模块里的零元、序关系与这里的同名。给具体类型就能分开。这是工程，不是数学。

## 小结

- 自然数和整数还是原来那些；集合层面的证明与普通类型论完全一致。
- 序关系是命题；可判定性是另一个概念。
- 它们是集合，因为相等可判定（Hedberg）。
- 整数的后继是自等价，这是螺旋覆叠的代数输入。
- 高阶机器为非集合准备；在集合里 HoTT 就是普通数学。

## 常见误区

1. **以为 HoTT 改写了算术。** 没有；只是默认记号优先给了路径。
2. **以为 `n ≤ m` 是布尔值。** 它是命题；判定要用可判定性。
3. **期待自然数减法给出负数。** 截断减法给零；要负数用整数。
4. **看到名字重载就以为定义错了。** 给具体类型即可。

## 练习

1. `n + S m = S (n + m)` 需要归纳吗？`S n + m = S (n + m)` 呢？哪一个是定义性的？
2. 整数后继为什么是等价？反函数是什么？
3. 泛等之下，`Int = Int` 有多少个元素？提示：等于整数的自同构。比 `Bool = Bool` 多得多。
