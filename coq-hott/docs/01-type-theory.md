# 01 类型即空间

> 对照代码：[`examples/01_type_theory.v`](../examples/01_type_theory.v)

同伦类型论建立在三个观念上：

- **命题即类型**：一个命题就是一个类型，证明就是这个类型的元素。
- **证明即程序**：写证明就是写程序，引入规则是构造子，消去规则是函数。
- **类型即空间**：类型是空间，元素是点，相等证明是路径。

前两个是 Martin-Löf 类型论的老传统。第三个是同伦类型论的新贡献，也是整本教程的起点。如果你用过 Coq、Agda 或 Lean，前两个会很熟；请特别留意 1.3 节——HoTT 对“相等”的处理和你习惯的那一套不是一回事。后面所有新鲜的现象都从这里长出来。

## 1.1 命题就是类型

先问一个朴素的问题：在编程语言里，“证明”是什么？

Martin-Löf 的回答是：**一个命题就是一个类型，这个命题的一个证明就是这个类型的一个元素。** “A 为真”不是别的，就是“类型 A 有居民”。于是逻辑连接词不再是特殊的原始概念，它们就是普通的类型构造器：

| 逻辑 | 读法 | 类型 |
|---|---|---|
| 真 ⊤ | 平凡地有一个证明 | 单元素类型 `Unit` |
| 假 ⊥ | 没有任何证明 | 空类型 `Empty` |
| A ∧ B | 一个 A 的证明和一个 B 的证明 | 乘积 `A * B` |
| A ∨ B | 要么 A 的证明，要么 B 的证明 | 和类型 `A + B` |
| A → B | 把 A 的证明变成 B 的证明的方法 | 函数类型 `A -> B` |
| ¬A | 从 A 的证明造出矛盾 | `A -> Empty` |
| ∀x:A. P x | 对每个 x 给出 P x 的证明 | 依赖函数 `forall x : A, P x` |
| ∃x:A. P x | 一个见证 x，外加 P x 的证明 | 依赖对 `{x : A & P x}` |

这张表的妙处在于：**每条引入规则就是一个构造子，每条消除规则就是一个函数。** “从 A ∧ B 推出 A”就是取有序对的第一分量。没有任何魔法。

既然命题是类型，写一个定理的证明就是写一个那个类型的程序。肯定前件（modus ponens）就是函数应用：有 `a : A` 和 `f : A -> B`，就有 `f a : B`。存在引入就是打包：`(a; p)` 是 Σ 类型的有序对——分号是库给 Σ 用的记号，以区别于乘积的 `(a, p)`。

证明既然是程序，就可以运行。这一点后面会反复起作用：一个“相等的证明”是可以计算的对象，而不是写完就扔掉的勾号。

## 1.2 谓词就是 `A -> Type`

一个关于 `n : nat` 的性质，比如“n 是零”，在类型论里就是一个从 `nat` 到类型的函数：给每个 n 一个类型，这个类型的居民就是“n 是零”的证明。

于是“存在一个 n 使得 n 是零”就是一个依赖对：见证加证据。Π 类型（`forall`）和 Σ 类型（`{x : A & P x}`）是本教程最基本的两块积木。第 03 章会把它们单独拎出来。现在只需记住：

- 全称量词的证明是一个函数：输入任意 x，输出 P x 的证明。
- 存在量词的证明是一个有序对：里面真的装着那个 x。这是**构造性的**存在。数学里“存在但不告诉你是谁”是另一件事，要到第 15 章才出现。

## 1.3 相等的特殊地位

到这里为止一切都和普通 Coq 一样。分水岭在于：**`x = y` 是什么？**

在类型论里，相等由一个归纳类型族给出，只有一个构造子：

```coq
Inductive paths (A : Type) (a : A) : A -> Type :=
  idpath : paths A a a.
```

`x = y` 是 `paths x y` 的记号。表面上看这和标准库的 `eq` 一模一样，差别在于我们**怎样对待它**：

1. 标准 Coq 的习惯是把 `x = y` 看成命题，证明之间没有区别（UIP / proof irrelevance）。
2. HoTT 拒绝这个假设。`x = y` 是一个普通的类型，**它的居民可以有很多个、彼此不同**。

一个相等命题的居民叫**路径**。路径之间可以运算：`1` 是恒等路径（停在原地），`p @ q` 是把两条路径首尾相接，`p^` 是把路径倒过来走。

为什么要这样？因为这样做之后，类型论和拓扑学之间出现了一个精确的字典。

## 1.4 类型即空间

| 类型论 | 同伦论 |
|---|---|
| 类型 `A` | 空间 |
| 元素 `x : A` | 点 |
| 路径 `p : x = y` | 从 x 到 y 的连续道路 |
| 2-路径 `r : p = q` | 两条道路之间的同伦（连续形变） |
| 3-路径 … | 同伦之间的同伦 … |

同一个相等命题的两个不同证明，就是两点之间两条不同的道路。两个证明之间的相等，就是两条道路之间的形变。这个阶梯可以一直往上走。

一个立刻能写下来的例子：`1` 与 `1 @ 1` 是 `true = true` 里的两条路径。它们看起来不同（一个是停在原地，一个是走了两段恒等），但可以连续形变成彼此——这条 2-路径的存在不靠公理，而是靠一条可以计算的事实：恒等路径接在任何路径前面都等于原路径。

有了这个字典，“所有路径都相同”就成了一个**性质**而不是一条**公理**。满足这个性质的类型叫 **h-set**（集合）；而允许非平凡环路的类型（比如圆，第 13 章）就不是集合。类型按“路径结构有多复杂”分级，这条标尺叫截断层级：

- **-2 层，可缩**：只有一个点，连路径也只有一条。
- **-1 层，命题**：任意两点之间有路径，因此知道它有居民就知道了一切。
- **0 层，集合**：任意两条平行路径相等（这就是 UIP，但现在是性质，不是公理）。
- **1 层**：路径类型是集合。圆落在这一层。

第 09 章会解释这些层级为什么从 -2 开始数。现在只需接受：不是所有类型都是集合，而这正是好事。

## 1.5 为什么值得这么做

把相等搞复杂有什么好处？

**结构的同一性。** 在集合论数学里，“同构的结构有相同的性质”是口头禅，但在形式系统里必须逐个证明。HoTT 的泛等公理（第 11 章）让“等价的类型就是相等的类型”，于是沿着相等搬运性质就自动完成了这件事。

**拓扑直觉可以直接用。** 圆、球面、覆叠空间、基本群——这些拓扑对象在 HoTT 里是具体的类型，拓扑定理变成了可以机器检查的证明。第 13 章会算出 π₁(S¹) = ℤ。

**公理用量可审计。** 函数外延和泛等被做成显式假设，每条定理用了什么公理一查便知。这不是工程细节，而是一种诚实：你始终知道自己信了什么。

本章的任务只是把字典立起来。接下来的几章会把字典里的每一行变成可以操作的工具。

## 一个必须先知道的记号约定

HoTT 库里，`0` 和 `1` 默认**不是**自然数。`1` 是恒等路径，`0` 是截断层级里的 -2。想写自然数要加标记：`(0%nat)`、`(2 + 3)%nat`。`+` 和 `*` 默认也是和类型与乘积，不是算术。

这不是恶作剧，而是优先级的选择：在一本以路径为主角的书里，路径比自然数更常用。读例子时看到裸写的 `1`，把它读成“停在原地的那条路径”。

## 小结

- 命题是类型，证明是元素；逻辑连接词是类型构造器，推理规则是构造子和投影。
- 证明是程序，可以运行。
- `x = y` 是一个类型，叫路径类型；它的居民可以不止一个。
- 类型 ↔ 空间，元素 ↔ 点，路径 ↔ 道路，路径之间的路径 ↔ 同伦。
- 路径结构的复杂度用截断层级衡量：可缩、命题、集合、……

## 常见误区

1. **“相等有多个证明”不等于“相等不可靠”。** 两条不同的路径都是真实的相等证明，只是它们携带了不同的信息（比如“绕圆几圈”）。
2. **不要指望 UIP。** `forall p q : x = y, p = q` 在 HoTT 里一般不成立，它是集合的定义性质，必须对具体类型证明。
3. **`{x : A & P x}` 和 `{x : A | P x}` 不同。** 前者的第二分量是任意数据；后者要求第二分量是命题。本教程绝大多数时候用前者。
4. **把 `1`、`0`、`+`、`*` 读成算术。** 默认它们分别是恒等路径、截断层级、和类型、乘积。

## 练习

1. 在脑子里（或纸上）写出“A ∧ B → B ∧ A”和“(A → B) → (B → C) → (A → C)”的证明。它们作为程序分别做什么？
2. 自己定义否定 `Not A := A -> Empty`，并说服自己：为什么总有 `A -> Not (Not A)`，而反过来一般没有。
3. 凭直觉猜：`Bool` 是不是集合？`Type` 呢？第 09 与 11 章会给出答案。猜错了也没关系，重要的是先有一个预期。
