# 04 恒等类型与路径归纳

> 对照代码：[`examples/04_identity_types.v`](../examples/04_identity_types.v)

这一章是整个 HoTT 的引擎室。关于路径的一切——倒转、拼接、函数作用、搬运——都由**一条规则**派生：路径归纳，也叫 J 规则。学会它，后面所有“看起来很神奇”的路径引理都会变成同一句话：这条性质在恒等路径上成立，所以处处成立。

## 4.1 定义为什么长这样

```coq
Inductive paths (A : Type) (a : A) : A -> Type :=
  idpath : paths a a.
```

注意冒号两侧：`A` 和起点 `a` 在左边，是**参数**，整个归纳定义过程中固定不变；终点在右边，是**索引**，可以随构造子变化。只有一个构造子 `idpath`，它把索引定为 `a` 本身。

把这句话翻译成几何语言：

> **固定起点 a，所有从 a 出发的路径构成的类型族，是由“停在原地”这一条路径生成的。**

这不是说只有一条路径——而是说任何关于“从 a 出发的路径”的性质，只要在恒等路径上成立，就处处成立。这就是路径归纳。

## 4.2 J 规则

要对所有终点 `y` 和所有路径 `p : a = y` 证明某个断言 `P y p`，**只需要证明 `P a 1`**——断言在“停在原地”时成立。

直觉上为什么合理？想象 `P y p` 是关于“终点 y 和到达它的路径 p”的某个断言。路径可以连续收缩：把 `p` 从终点那一端往起点拉，拉到底就是 `a` 上的恒等路径。如果断言在收缩过程中保持（类型论里这是自动的），那么它在恒等路径上成立就足够了。

**关键限制：不能把起点和终点同时固定。** “对所有 `p : a = a` 证明 `P p`”不是路径归纳能处理的——环路不能收缩到一个点（否则圆就没有非平凡环路了）。J 规则总是把终点当成自由变量。这个限制不是技术瑕疵，而是几何事实：基于一点的路径空间可缩（第 08 章），基于两点的路径空间一般不可缩。

在 Coq 里，路径归纳就是对路径做情形分析：把终点替换成起点，把路径替换成恒等路径。后文写 `destruct p`，读成“对 p 做路径归纳”。

## 4.3 逆与复合：J 的第一批果实

自己想一遍逆路径，是理解 J 的最好方式。给定 `p : x = y`，要造 `y = x`。对 `p` 做路径归纳：现在 `y` 就是 `x`，目标变成 `x = x`，恒等路径就行。复合也一样：对两条路径都做归纳，三个点合并成一个，目标变成恒等路径等于恒等路径。

库里的 `p^`（逆）和 `p @ q`（复合）就是这样定义的。几乎所有关于路径的引理都是这个节奏：**先问它在恒等路径上是不是显然成立；如果是，证明就写完了。**

注意一个微妙之处：这些运算满足的律本身是**路径**，不是定义上的相等。`p @ 1` 和 `p` 不是同一个项，它们之间有一条路径。到第 06 章会看到，这些路径之间又有路径（二维同伦），而且它们的结构是有内容的。

## 4.4 函数把路径映到路径

函数把点映到点，自然也把路径映到路径。这件事叫 `ap`（action on paths）：

> 给定 `f : A -> B` 和 `p : x = y`，得到 `ap f p : f x = f y`。

它也是由 J 定义的：`p` 是恒等时，结果就是恒等。`ap` 是函子性的——它保持所有路径运算：保恒等、保复合、保逆、与函数复合相容。常值函数把任何路径压成恒等：想证明某条路径是平凡的，可以让一个常值函数作用在它上面。

如果 `f` 是依赖函数，`f x` 和 `f y` 属于**不同的类型**，写 `f x = f y` 根本不合法。必须先把 `f x` 搬到 `f y` 所在的纤维里去，这就是下一章的 `transport`。依赖版本叫 `apD`：沿底空间的路径走，截面在起点的值被平行移动到终点的纤维里，和截面在终点的值之间有一条路径。

现在只需记住：**非依赖用 `ap`，依赖用 `apD`，后者的类型里有搬运。**

## 4.5 群胚律预告

逆与复合立刻给出一组律：左单位、右单位、左右逆、反同态、对合。每一条都是“在恒等路径上显然，所以处处成立”。

这些律说的是：一个类型里的点与路径构成一个**群胚**——每个态射都可逆的范畴。第 06 章会把这个结构展开，并往上走一层：路径之间的路径也有代数。

## 4.6 恒等类型不是布尔值

标准 Coq 的用户习惯了 UIP：同一等式的任意两个证明相等。在 HoTT 里**这不成立**——它是集合的定义性质（第 09 章），而 `Type` 本身就不是集合（第 11 章）。

于是“所有路径都相等”不能当定理，只能当假设，或者对具体类型去证。`Unit` 满足它：任意两点之间的路径类型是命题。`Bool` 也满足。圆不满足。

为什么放弃 UIP 值得？因为保留它就等于宣布所有类型都是集合，圆、球面、泛等这些东西从一开始就被排除了。放弃它，相等才有了几何。

## 小结

- `paths` 以起点为参数、终点为索引，只有一个构造子：停在原地。
- 路径归纳（J）：要对所有 `p : a = y` 证明某个断言，只需证明断言在恒等路径上成立。终点必须是自由变量。
- 逆、复合、`ap`、`apD`、单位律、消去律全部由 J 派生。
- `ap` 处理非依赖函数，`apD` 处理依赖函数。
- 没有 UIP；“所有路径相等”是集合的性质，要对具体类型证明。

## 常见误区

1. **以为路径归纳能处理环路。** J 要求终点自由。对两端固定的路径做归纳会失败或改变目标。环路的性质要用覆叠、编码-解码（第 13 章）。
2. **以为 `p @ 1` 就是 `p`。** 它们之间有一条路径，不是同一个项。在集合里这无所谓，在高阶类型里这条路径可能携带信息。
3. **用 `ap` 处理依赖函数。** `f x = f y` 类型不合法时，要用 `apD`。
4. **期待 UIP 或 proof irrelevance。** 它们在 HoTT 里是假设，不是定理。

## 练习

1. 用路径归纳说服自己：`(p @ q)^ = q^ @ p^`。为什么逆要交换顺序？
2. 为什么函数作用保持复合：`ap f (p @ q) = ap f p @ ap f q`？
3. 思考：为什么恒等路径接在恒等路径前面等于恒等路径是**定义性的**，而 `p @ 1 = p` 对一般的 `p` 只是一条路径？提示：哪一个发生在归纳已经把 `p` 变成恒等之后？
