# 04 · 流程控制与方法

> 对应示例：`examples/04_control_methods`

> **本章你将学会**：switch 表达式的现代写法、循环选型、方法参数的五种形态、重载与局部函数。
> **前置章节**：[03 变量与运算符](03-variables-operators.md)。

## 1. if 与老 switch：够用但不是最优

`if/else if` 链和 C 家族的 switch 语句你大概已经会了。C# 8 之后有了更锋利的武器——**switch 表达式**，本教程默认用它。

## 2. switch 表达式：值形态的分支

```csharp
static string GradeOf(int score) => score switch
{
    >= 90 => "优秀",
    >= 80 => "良好",
    >= 60 => "及格",
    _     => "不及格",          // _ 是丢弃模式：兜底
};
```

和老 switch 语句的三点本质差异：

1. **它是表达式**（有值），可以直接接 return/赋值/插值；老 switch 是语句
2. **模式可以写条件**（`>= 90`、`int n when n > 0`），不只是常量
3. **编译器检查穷尽性**：没有 `_` 兜底且分支覆盖不全 → 编译错误（好事）

规则从上到下匹配，命中即止——**顺序即优先级**。条件更复杂的形态（属性模式、列表模式）在第 19 章展开，这里记住骨架即可。

## 3. 循环选型

| 循环 | 场景 |
|---|---|
| `for` | 已知次数 / 需要下标 |
| `while` / `do-while` | 条件驱动（do-while 至少跑一次） |
| `foreach` | **遍历集合的默认选择**（不操心下标；第 18 章讲它背后的 IEnumerator） |

三个控制关键字：`break`（跳出整层）、`continue`（跳过本轮）、`goto`（仅限 switch 穿透和极端场景，新代码别用）。嵌套循环要跳出多层时，用**标志位或把内层提成方法**，别 goto。

## 4. 方法参数的五种形态

示例逐一演示，这里给速查表：

```csharp
// ① 可选参数：有默认值，调用时可省
static string Greet(string name, string greeting = "你好") => $"{greeting}，{name}！";

// ② 命名参数：跳过前面的可选参数、或让调用更可读
Greet("小明", greeting: "早上好");

// ③ out：方法"多返回值"（TryParse 的签名就是它）
static bool TryParsePair(string input, out int left, out int right) { ... }
if (TryParsePair("3,7", out var a, out var b)) { ... }   // out var 内联声明

// ④ ref：把变量本身传进去——方法改的是调用方的那个变量
static void Bump(ref int n) => n++;

// ⑤ params：可变数量参数（收进数组）
static int Sum(params int[] numbers) => numbers.Sum();
```

选型经验：

- **多返回值优先**：现代 C# 用元组 `return (a, b)`（第 11 章解构）比 out 干净；out 主要用于 TryXxx 惯例和互操作
- **ref 别当输出用**：它是指针语义的口子，误用让数据流不可见。留给性能交换大结构体和互操作（第 26/27 章有其变体 `in`/`ref readonly`）
- 可选参数代替一串重载构造；**命名参数**在布尔参数前救场：`Enable(true)` 不如 `Enable(detailed: true)`

## 5. 重载与局部函数

**重载**：同名方法不同参数列表，编译器按实参挑——`Show(42)` 与 `Show("42")` 各走各的。注意**局部函数不能重载**（同名直接 CS0128），重载必须发生在类型成员层面。

**局部函数**：方法里声明的方法，只在当前作用域可见：

```csharp
int Fib(int n) => n <= 1 ? n : Fib(n - 1) + Fib(n - 2);   // 递归也没问题
```

适用：一个算法的内部步骤（不值得占类的公开面）、递归辅助。与 lambda（第 15 章）的区别：局部函数能递归、无委托开销、可以泛型。

**表达式体方法**：单表达式成员用 `=>`：

```csharp
public int Count => _items.Count;                  // 表达式属性
public void Clear() => _items.Clear();             // 表达式方法
```

现代 C# 的常用形态，本教程满篇都是。

## 6. 写"好方法"的三条军规

1. **一个方法一件事**：名字说清楚这件事（`LoadConfig`/`ParseHeader`）；要写"和"注释才能概括的方法，拆
2. **参数 ≤ 4 个**：再多就聚合成一个类型（第 11 章 record 一行搞定）或用命名参数救场
3. **避免输出参数链**：三个 out 的方法 → 返回一个 record

## 常见坑

**switch 表达式忘 `_` 兜底**：非穷尽 → 编译错误。这是特性不是缺陷：逼你想清楚所有情况。

**分支顺序错**：`>= 60` 写在 `>= 90` 前面，90 分也被"及格"截胡——从上到下匹配，范围条件**从窄到宽**排。

**do-while 条件反了**：先执行后判断，首次就退出用 while；至少执行一次才 do-while。

**可选参数不是随意的**：带默认值的参数必须在必选参数**之后**；默认值必须是编译期常量。

**ref/out 传属性**：`Bump(ref obj.Count)` 编译错误——属性不是变量。先取局部变量再传。

## 实战建议

- 分支超过三层 if 链就换 switch 表达式或字典映射（`Dictionary<State, Action>`）
- 循环体内超过 20 行 → 提方法，循环只留"遍历骨架"
- TryXxx 模式（bool 返回 + out 结果）设计自家 API：调用方零异常处理负担
- 递归深度不可控的数据（链表可百万长）改迭代——栈是有限的（默认 1MB，第 27 章 stackalloc 同理）

## 自测

1. **switch 表达式相比语句的三个优势？** —— 是表达式有值；支持条件模式；穷尽性检查。
2. **out 与 ref 的语义区别？** —— out 只出不进（写入前必须赋值）；ref 进出都行（传变量本身）。
3. **局部函数为什么不能重载？替代方案？** —— 同作用域同名即冲突（CS0128）；重载放类型成员层面，或改名。
4. **可选参数的两条限制？** —— 必须在必选参数后；默认值须编译期常量。
