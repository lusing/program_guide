# 08 · 类与封装

> 对应示例：`examples/08_classes`

> **本章你将学会**：字段/属性/初始化器的分工、构造函数与主构造函数、init 与静态成员、索引器与分部类。
> **前置章节**：[05 值与引用](05-value-reference.md)。

## 1. 类是什么

类是**自定义引用类型**的模具：把"数据（字段/属性）+ 行为（方法）+ 约束（构造）"打包成一个概念。`new Account("小明", 100m)` 造出一个对象——数据装在堆上，方法是全类共享的代码。

**封装**是第一原则：数据私有（`private`），外界通过你**设计的门面**（属性/方法）访问。示例的 Account：余额只能通过 `Deposit` 变化，"存负数"这种非法状态在门口就被拦下——**对象自己保证自己永远合法**，这就是封装的全部意义。

## 2. 字段与属性：三兄弟

```csharp
private decimal _balance;                  // 字段：私有储物间
public string Owner { get; }               // 只读属性：构造后不可变
public decimal Balance => _balance;        // 表达式属性：只读对外（算出来的）
public string? City { get; set; }          // 自动属性：可读可写（编译器生成隐藏字段）
public int Timeout { get; init; }          // init：只能初始化时赋值
```

现代 C# **几乎不写公开字段**——属性与字段外观相同（`obj.Balance`），但属性是方法，可以：只读/只写、加验证逻辑、参与绑定/序列化（WPF 的依赖属性、JSON 序列化都认属性）。

`init` 的意义：**对象创建后不可变**的第三档——比 `set` 安全（不会被顺手改），比纯只读灵活（初始化器能赋值）。想表达"定下来就不该变"的状态用它。

## 3. 构造函数与对象初始化器

```csharp
public Person(string name, int age = 18)   // 可选参数减少重载数量
{
    Name = name;
    Age = age;
    Created++;                              // 副作用：计数
}

var p1 = new Person("张三", 24) { City = "北京" };   // 括号后 { } 是初始化器：对可写属性补刀
```

**初始化器**（`{ City = ... }`）与构造函数分工：构造管"必填、需要验证"的核心状态；初始化器管"可选、直接赋值"的外围属性——两个机制配合，构造重载数量骤减。

**主构造函数（C# 12）**：参数直接挂在类声明上，整个类的成员都能用：

```csharp
class Circle(double radius)                 // 第 09 章示例用过
{
    public double Radius { get; } = radius; // 落成属性暴露
    public double Area() => Math.PI * radius * radius;   // 直接用
}
```

适合小类；需要验证逻辑或多个重载时回到经典构造。

## 4. static：属于类而不是实例

```csharp
class Person
{
    public static int Created { get; private set; }    // 全类共享一份
    ...
}
Person.Created                                        // 通过类名访问
```

- **静态成员**：全类一份（实例计数器、全局配置）；实例成员：每个对象各一份
- **static 类**：不能 new，全是静态成员（工具类：`Math`、第 20 章的扩展方法宿主）
- **const vs static readonly**：const 编译期定死（调用方把值拷进自己程序集，改了要全部重编）；static readonly 运行期初始化（改了只需换 dll）——**跨程序集共享的"常量"用 static readonly**

## 5. 索引器与分部类

**索引器**：让对象像数组一样用 `[]` 取值——本质是带参数的属性：

```csharp
class WeekDays
{
    private readonly string[] _days = { "一", "二", ..., "日" };
    public string this[int i] => $"周{_days[i]}";    // this[参数]
}
var week = new WeekDays();
week[0]        // 周一
```

典型用户：包装内部集合的类（矩阵 `m[1,2]`、字典的 `dict["key"]` 本质也是索引器）。

**分部类（partial）**：一个类拆多个文件/多个来源，编译时合并。最大用户是**代码生成器**（WPF 的 XAML 编译、第 24 章源生成器）——生成的代码和你手写的代码拼成同一个类。业务代码里少主动用，但**必须认识它**：`partial class Program { }` 那行（第 02 章）与 obj 目录里的 `.g.cs` 就是这套机制。

## 6. 类设计的起手式

写一个新类时自问四个问题：

1. **不变量是什么**？（Account：余额经受过验证才变）→ 决定哪些成员 private
2. **什么必须构造时给**？→ 构造函数参数；其余给默认或 init
3. **要不要可变**？默认向不可变靠（record 第 11 章），确需可变才 set
4. **静态还是实例**？全类一份的事实/工具 → static

## 常见坑

**公开字段裸奔**：`public decimal Balance;`——外部可绕过一切检查直接赋值。属性是最低门槛。

**构造函数里调虚方法**：子类还没构造完，虚分发到子类会读到未初始化状态。构造里只干初始化。

**静态成员当全局变量用**：static 可变状态 = 隐形耦合 + 多线程坑（第 30 章）。静态只放真正的单份数据/无状态函数。

**init 属性想在运行时改**：编译错误是特性——要可变当初就声明 set，别跟编译器较劲。

**对象初始化器依赖属性顺序**：`{ A = 1, B = A + 1 }` 里 B 看到的是默认值——初始化器逐个执行但别写依赖。

## 实战建议

- 字段一律 private；对外只暴露属性和方法——从第一个类就养成
- 构造参数能可选就可选（默认值），构造重载数量立刻减半
- 不可变优先：`get`-only / `init` 是默认档位，`set` 是需要理由的档位
- "工具方法"集中到 static class；跨项目复用的常量用 static readonly

## 自测

1. **封装解决什么问题？怎么落地？** —— 对象自己保证状态合法；私有字段 + 受控的属性/方法门面。
2. **get / get+set / get+init / 表达式属性各表达什么语义？** —— 只读；可变；仅初始化时可赋；计算的只读。
3. **const 与 static readonly 的关键差异？** —— 编译期拷贝（改了要重编全部）vs 运行期初始化（换 dll 即可）。
4. **分部类存在的意义？** —— 多来源合并一个类，代码生成器与手写代码的接缝。
