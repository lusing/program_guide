# 05 · 值类型、引用类型与内存

> 对应示例：`examples/05_value_reference`

> **本章你将学会**：赋值语义的分岔（拷贝 vs 别名）、相等性的分岔、装箱拆箱、栈与堆的心智模型。
> **前置章节**：[04 流程控制与方法](04-control-methods.md)。

这是全书**最重要的一章之一**——C# 一半的疑难杂症（"改了它为什么那边也变""Equals 为什么是 false"）都源于没想通本章内容。

## 1. 赋值的那一刻就分岔了

示例的第一组实验，两个几乎一样的类型，行为完全相反：

```csharp
// struct：值类型——赋值 = 整体拷贝，两份独立
var p1 = new Point { X = 1, Y = 2 };
var p2 = p1;
p2.X = 99;
// p1.X = 1, p2.X = 99   ← 互不影响

// class：引用类型——赋值 = 复制"地址"，两个名字指同一个对象
var c1 = new Coord { X = 1, Y = 2 };
var c2 = c1;
c2.X = 99;
// c1.X = 99, c2.X = 99   ← 同一个对象
```

**规则一句话：值类型赋值拷内容，引用类型赋值拷地址。** 方法传参同理（默认就是赋值）——传 struct 是拷一份进去，传 class 是把门牌号给人家。

哪些是值类型哪些是引用：

| 值类型（拷贝） | 引用类型（别名） |
|---|---|
| `int`/`long`/`double`/`decimal`/`bool`/`char` | `string`（特殊的引用类型，第 06 章） |
| `enum`（第 07 章） | `class`、`interface`、`delegate` |
| `struct`（含自定义、第 11 章） | `object`、数组（第 07 章） |
| `Nullable<T>`（第 21 章） | `record`（本质是 class；record struct 除外） |

## 2. 内存心智图：栈与堆

```text
栈（快，随方法帧生灭）         堆（GC 管理，活得久）
┌──────────────────┐       ┌──────────────────┐
│ p1  [1, 2]       │       │ c1 ──────────┐   │
│ p2  [99, 2]      │       │              ▼   │
│ c1 (引用/地址)────┼──────►│ Coord 对象 [99,2] │
│ c2 (引用/地址)────┼──────►│   ↑ 同一个        │
└──────────────────┘       └──────────────────┘
```

- **栈**：方法调用帧所在。局部变量（值类型的值、引用类型的地址）在这里，方法返回整帧回收——快、自动、免管理
- **堆**：引用类型的对象本体在这里，由 **GC**（第 25 章）回收——分配慢一些、但能活得比方法久

**注意**："值类型在栈"是简化说法——准确的是"值类型的**值**直接存在变量所在处"：局部变量在栈；而类里的 int 字段跟着对象在堆上。记这条而不是记位置，推断才不会错。

## 3. 相等性的分岔

```csharp
p1.Equals(p3)               // true  ← 值类型：按内容比
ReferenceEquals(c1, c3)     // false ← 引用类型：按身份（地址）比
```

引用类型默认"长得一样也是两个对象"。想要按内容比：class 要自己重写 `Equals/GetHashCode`（第 09 章示例做过）；**record（第 11 章）编译器免费合成**——这是 record 诞生的主要动机之一。

`==` 的行为：内置数值/bool/char 比值；string 比内容（重载过的特例）；自定义类型默认比引用（除非重载运算符，第 20 章）。拿不准就 `Equals`。

## 4. 装箱与拆箱

值类型要装进"万物容器" object（或非泛型集合/接口）时，发生**装箱**：

```csharp
int number = 42;
object boxed = number;          // 装箱：堆上造一个包装对象，值拷进去
int unboxed = (int)boxed;       // 拆箱：显式强转取回（类型必须精确匹配）
```

代价：装箱 = 一次堆分配 + 拷贝；拆箱 = 类型检查 + 拷贝。循环里反复装箱是隐形性能杀手——示例用 `ArrayList`（非泛型）和 `List<int>`（泛型）做了对比，差距一个数量级。**根治手段是泛型（第 12 章）**：`List<int>` 存的就是裸 int，零装箱。

什么时候还会遇到它：把 struct 传给 `object`/`interface` 参数、调用 struct 上的"被重写的方法"（如 struct 的 ToString）、字符串插值里混入值类型。偶发无妨，**热路径要警觉**。

## 5. 引用类型的"引用"不是指针

- 引用不能算术（不像 C 指针加减）；它是**受管句柄**，GC 移动对象后会自动更新（第 27 章 fixed 才谈真地址）
- 传引用 ≠ 引用传参：默认传的是"引用的拷贝"（ callee 换掉自己的拷贝不影响 caller 的变量）；真要换，加 `ref`（第 04 章）
- 值类型也可以通过 `ref` 避免拷贝——大 struct 性能优化的正道（第 26 章 ref struct/Span 的基础）

## 6. string 的特殊性（预告）

`string` 是引用类型，但**不可变**（immutable）：一切"修改"都返回新对象（第 06 章主题）。它还有驻留机制让相同字面量共享实例——所以 `ReferenceEquals("abc", "abc")` 是 true，一个引用类型的"反常"。

## 常见坑

**"改了副本以为改了原件"**（struct 拷贝）：函数里改 struct 参数，外面没变——传的是拷贝。要改加 ref。

**"两个对象明明一样 Equals 却 false"**：class 默认按引用比。用 record 或重写 Equals。

**拆箱类型不匹配**：`(long)boxedInt` 装的是 int 拆成 long → InvalidCastException。装箱什么类型就拆什么类型，再转换。

**值类型当字典键忘了重写**：自定义 struct 做 Dictionary 键，默认的 Equals/GetHashCode 按字段逐个反射比较——又慢又可能不符合预期语义；record struct 一步到位。

**null 的赋值歧义**：`p1 = null`（struct）编译错误——值类型没有 null（除非 Nullable，第 21 章）；引用类型随便 null。

## 实战建议

- 每写一个赋值/传参，花半秒想"这是拷贝还是别名"——习惯后本章内容就内化了
- 数据载体默认 class 或 record（第 11 章的选型表）；小而高频的值（坐标、金额、颜色）用 struct
- 疑惑时用 `ReferenceEquals(a, b)` 验证"是不是同一个对象"——比猜快
- 性能敏感路径看三样：装箱（本篇）、分配（第 25 章）、拷贝（大 struct）

## 自测

1. **struct 和 class 赋值行为的差异？** —— struct 拷贝内容（两份独立）；class 拷贝引用（同一对象）。
2. **装箱发生在什么时机？代价是什么？** —— 值类型转 object/接口/非泛型容器时；一次堆分配 + 两次拷贝。
3. **引用类型的 Equals 默认比什么？怎么改成比内容？** —— 比引用（身份）；重写 Equals/GetHashCode 或用 record。
4. **"值类型在栈上"的准确表述？** —— 值类型的值直接存在变量所在处：局部变量在栈，字段随对象在堆。
