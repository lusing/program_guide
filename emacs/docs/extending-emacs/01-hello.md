# 01 · 第一个程序：输出与 quote

> 所属部分：第 1 部分 · 语言基础
>
> 示例：`examples/01-hello.el`

从「跑起来」到「看懂 Lisp 的求值与读取两层机制」，这是第一章的任务。内容不多，但每一节都是后续所有章节的地基。所有输出都是示例真跑出来的。

## 1.1 最小程序

```elisp
(princ "Hello, Emacs!\n")
```

```bash
$ emacs -Q --batch -l examples/01-hello.el
Hello, Emacs!
```

一个「函数调用」就是一个被括号包起来的列表：第一个元素是函数名，后面是参数。**没有语句结束符，没有操作符优先级问题**——一切都是「列表第一个位置放函数，其余放参数」。缩进只是给人看的，括号才是语法。

## 1.2 唯一的输出组合

日常只需要记住这一个写法：

```elisp
(princ (format "1 + 1 = %d，列表 = %S，字符串 = %s，pi = %.2f\n"
               (+ 1 1) '(1 2 3) "abc" float-pi))
```

```
1 + 1 = 2，列表 = (1 2 3)，字符串 = abc，pi = 3.14
```

`format` 的四个常用控制符：

| 控制符 | 用途 | 例子 → 结果 |
|---|---|---|
| `%s` | 「给人看」的形式 | `(format "%s" "abc")` → `"abc"` |
| `%d` | 整数 | `(format "%d" 42)` → `"42"` |
| `%f` / `%.2f` | 浮点，可指定小数位 | `(format "%.2f" float-pi)` → `"3.14"` |
| `%S` | **能被 `read` 回来的 Lisp 语法形式** | 见下 |

`%S` 和 `%s` 的区别在调试时特别重要：

```elisp
(princ (format "prin1 形式：%s\n" (prin1-to-string "带\"引号\"的字符串")))
```

```
prin1 形式："带\"引号\"的字符串"
```

字符串带着引号和转义一起打印出来了——这正是「能被读回来」的意思。想看一个对象的**准确结构**（而不是友好的显示），就用 `%S` / `prin1-to-string`。

> **注意** `%S` 有时会把原始字节写进输出，比如键序列（第 14 章）。真要在输出里展示这类对象，先用 `key-description` 之类的函数转成人读形式。本仓库的验证脚本会拦截这类「脏输出」（见 00 章）。

## 1.3 quote：阻止求值

Lisp 的求值规则是「**先求值所有参数，再把结果传给函数**」。所以：

```elisp
(1 2 3)      ;; 错误！会被当成「调用一个名叫 1 的函数」
'(1 2 3)     ;; 正确，三元素列表
```

`'x` 是 `(quote x)` 的语法糖。它做两件事：

- 对列表：阻止「当函数调用」，原样返回这个列表；
- 对符号：阻止「当变量求值」，返回**符号本身**。

```elisp
(princ (format "quote 后：%S\n" (quote (1 2 3))))
(princ (format "等价写法：%S\n" '(1 2 3)))
(princ (format "符号本身：%S，符号的名字：%S\n" 'foo (symbol-name 'foo)))
```

```
quote 后：(1 2 3)
等价写法：(1 2 3)
符号本身：foo，符号的名字："foo"
```

区分「符号」和「符号的名字」在元编程里很关键：`'foo` 是一个符号对象，`(symbol-name 'foo)` 才得到字符串 `"foo"`。反过来 `(intern "foo")` 能从字符串造出符号。第 3 部分的宏会大量用到这个区分。

## 1.4 reader 语法：代码在读入时发生了什么

`emacs -l file` 做的第一件事不是「执行」，而是 **read**（读取）：把文本变成 Lisp 对象。读取器认这些语法，写代码时随处可见：

```elisp
(princ (format "数字读法: #x1F=%S #b101=%S #o17=%S 1e3=%S\n"
               #x1F #b101 #o17 1e3))
(princ (format "字符读法: ?\\n=%S ?\\C-a=%S ?a=%S\n" ?\n ?\C-a ?a))
```

```
数字读法: #x1F=31 #b101=5 #o17=15 1e3=1000.0
字符读法: ?\n=10 ?\C-a=1 ?a=97
```

- `#x1F` 十六进制、`#b101` 二进制、`#o17` 八进制；`1e3` 是科学计数法的**浮点**（1000.0，注意有小数点）；
- `?a` 是字符字面量（就是整数 97）；`?\n`、`?\C-a`（Ctrl-A）是转义写法；
- 字符串里 `\n` `\t` `\"` `\\` 同理。

还有一个和 Common Lisp **相反**的坑：Elisp 的符号**区分大小写**。

```elisp
(princ (format "符号大小写: %S 与 %S 是同一个吗？%S\n"
               'Hello 'hello (eq 'Hello 'hello)))
```

```
符号大小写: Hello 与 hello 是同一个吗？nil
```

`'Hello` 和 `'hello` 是两个不同的符号。所以拼写必须处处一致——包括变量名和函数名。

## 1.5 注释的三种惯例

这不是编译器的要求，而是整个 Emacs 生态的约定，`checkdoc`、`package-lint`、`outline-minor-mode` 和 `imenu` 都依赖它：

```elisp
;;; 三个分号 —— 文件头、以及顶格的「分节标题」
;;   两个分号 —— 普通注释，跟代码缩进对齐
;    一个分号 —— 行尾的简短说明
```

分节标题写成 `;;; 1) 说明` 而不是 Markdown 那种标题，是因为 Emacs 的 `outline-minor-mode` 和 `imenu` 会把它们识别成结构，可以折叠、可以跳转。本仓库所有示例文件都按这个惯例分节。

## 1.6 本章小结

| 概念 | 一句话 |
|---|---|
| 函数调用 | 括号列表，第一个元素是函数 |
| 求值规则 | 先求值参数，再传给函数；符号当变量求值 |
| `quote` / `'` | 阻止求值，拿符号或列表本身 |
| `%S` vs `%s` | 前者保留 Lisp 语法（可读回），后者友好显示 |
| reader 语法 | `#x`/`#b`/`#o`/`?a`/`\n`，在读入时生效 |
| 符号大小写 | **区分**——和 Common Lisp 相反 |
| 注释惯例 | `;;;` 分节 / `;;` 普通 / `;` 行尾 |
