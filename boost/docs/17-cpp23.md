# 17 · C++23 波次：charconv / stacktrace / decimal / outcome /（mdspan 对照）

> 对应示例：`examples/17_cpp23/`（5 个例程）

C++23 是"Boost 毕业仍在进行时"的证明：这一章的每个库都对应一个**最近三年才进标准或正在进标准**的特性。std::stacktrace 是直系毕业（Boost.Stacktrace 几乎原样进标准）；std::expected 与 Outcome 是同题异答；std::charconv 早有但扩展浮点是 C++23 的新篇；std::decimal 与 Boost.Decimal 平行赛跑；mdspan 则是 Boost 反而缺席的_std 侧新贵_。

## 17.1 Boost.Charconv（2024）：数值转换的终点站

`to_chars`/`from_chars` 的三无原则（无 locale、无分配、无异常）是 C++17 确立的，但实现残缺多年——boost 版是全平台全类型的补完：

```cpp
boost::charconv::to_chars(buf, buf + n, 1234567);                    // 整数
boost::charconv::to_chars(buf, buf + n, 3.14159);                    // 浮点最短往返
boost::charconv::to_chars(buf, buf + n, 0.000123,
                          boost::charconv::chars_format::scientific);
boost::charconv::from_chars(buf, end, v);                            // 失败给 ec，不抛
```

运行输出（`charconv.cpp`）：

```text
整数写出: 1234567（写入了 7 字节）
整数读回: 1234567 错误码=0? true
浮点写出: 3.14159265358979
浮点读回相等? true
科学计数: 1.23e-04
std 版: 42
自检通过
```

**毕业档案**：`std::to_chars`/`from_chars`（C++17 主体 + C++23 扩展浮点）。boost 版价值：老标准支持、浮点在 std 实现残缺的平台救急、`chars_format` 全家。**选型**：新代码 std 优先，遇到平台浮点缺失再回落 boost。

> 实测坑（跨平台）：`chars_format::scientific` 的**位数不保证跨平台一致**——MSVC 侧打出 `1.230000e-04`（6 位小数，走的 printf 回落），Apple clang 侧打出 `1.23e-04`（最短往返）。断言要比"解析回来相等"，别比字符串。
>
> 实测坑：例程里三处布尔都显式加了 `std::boolalpha`。不加的话打出来是 `1`/`0`，跟上一行的"错误码=0?"混在一起看不出是布尔还是数值（Windows 侧文档里那两个 `true` 是手写的）。

## 17.2 Boost.Stacktrace（2016）：本波次最标准的毕业

`std::stacktrace`（C++23）就是照着它长的——连"取帧、流输出、落盘后处理"的使用姿势都一致：

```cpp
std::ostringstream oss;
oss << boost::stacktrace::stacktrace();       // 当前调用链
boost::stacktrace::stacktrace st; st[0].name(); st.size();
std::ofstream("dump.txt") << st;              // 崩溃现场序列化
```

运行输出（`stacktrace.cpp`）：

```text
栈里能找到 inner/middle? 1/1
当前栈帧数 >= 2? true
第 0 帧非空名? true
落盘字节数 > 0? true
std::stacktrace（C++23）同构见文档
自检通过
```

> **三个函数都标了 `BOOST_NOINLINE`**：开优化（`-O2`）时 `middle` 会被内联进
> `outer`，栈里只剩 `inner`，第一行会变成 `1/0`——本机 macOS 侧正是这么翻的车
> （Windows 侧的 `build.ps1` 不开优化，所以一直是 `1/1`）。回溯示例要的是
> "这几个函数确实还在栈上"，那件事得由代码保证，不能指望编译器的优化档位。

三个实战要点：**异常处理器里打印**（`std::set_terminate` 配套）、**崩溃落盘**（`.dump` 文件 + 离线 addr2line/符号化）、**帧数上限**（构造 `stacktrace(N)` 限深防递归爆栈）。C++26 前 MSVC 的 `std::stacktrace` 也已可用——但 boost 版在老标准/老平台仍是答案。

## 17.3 Boost.Decimal（2024）：十进制浮点的先行者

`0.1 + 0.2 == 0.3` 在二进制浮点里是 `false`（0.1 是无限循环小数）——钱、计量、税的场景必须用十进制：

```cpp
boost::decimal::decimal64_t a{1, -1};       // 1 × 10^-1 = 0.1
boost::decimal::decimal64_t b{2, -1};       // 0.2
a + b == decimal64_t{3, -1};                // true！
sqrt(decimal64_t{4});                        // 自带数学函数族
```

运行输出（`decimal.cpp`）：

```text
二进制 0.1f 的真实值 ≈ 0.100000001
decimal32_t(5,-1) 打印 = 0.5
0.1+0.2 == 0.3 ? true（二进制 float 下为 false）
1.99 × 3 = 5.97
sqrt(4) = 2
自检通过
```

**毕业档案**：`std::decimal32_t/64_t/128_t`（C++23 扩展浮点，平行推进——boost 类型名已对齐 std 命名）。⭐ 金融/计量代码的现在进行时。

## 17.4 Boost.Outcome（2018）：std::expected 的同题兄长

错误处理的值语义路线：成功带值、失败带错误码，**不用异常**：

```cpp
outcome::result<int, std::error_code> parse_port(const std::string& s);
auto ok = parse_port("8080"); ok.value();
BOOST_OUTCOME_TRY(auto port, parse_port(s));   // 失败即 return，一行传播
outcome::outcome<int> oc = outcome::success(7); // 三态：值/错误/异常指针
```

运行输出（`outcome.cpp`；`消息 =` 那串是**平台给的 strerror 文案**）：

```text
成功值 = 8080 失败吗? true 消息 = Invalid argument
TRY 链: 886
outcome 值 = 7（三态：值/错误/异常）
自检通过
```

**毕业档案**：**不是直系**——`std::expected`（C++23）来自 tl::expected 谱系。Outcome 与 expected 的真正差异：

| | `std::expected<T,E>` | Outcome `result<T,EC>` |
|---|---|---|
| 空态 | 无（必须装 T 或 E） | 有（默认构造为空） |
| 第三态 | 无 | `outcome<T>` 可带 `std::exception_ptr` |
| 传播 | `and_then` 链 | `BOOST_OUTCOME_TRY` 宏（早于 monadic 十年） |
| 生态 | 标准件 | Boost/ABI 稳定承诺 |

**选型**：新代码 `std::expected`（C++23 就位后）；需要在 result/exception 间架桥、或 C++14 支持时 Outcome。

> 实测坑（跨平台）：`消息 =` 那串来自 `std::error_code::message()`，即平台的 `strerror`——MSVC 给小写 `invalid argument`，macOS 给 `Invalid argument`。**错误文案不是契约**，断言要比错误值/类别。另：判断失败要用 `has_error()`，不要 `static_cast<bool>`（Outcome 的默认构造空态下 `operator bool` 会直接 UB）。

## 17.5 std::mdspan（C++23）：Boost 缺席的对照

Boost 1.92 没收 mdspan（Kokkos 谱系进了 std）——这个"缺席"本身就是教材：**毕业不总是从 Boost 出发**。mdspan 是"裸内存上的多维视图"，与 `boost::multi_array`（22 章）的关系如同 `string_view` 之于 `string`：

```cpp
std::mdspan mat(data.data(), 3, 4);          // 一维裸数组看成 3×4
mat[std::array{2, 3}];                        // C++23 多维下标
```

运行输出（`mdspan.cpp`）：

```text
维度 = 3×4
mat[2,3] = 12（C++23 逗号下标）
mat[1,1] = 6
全元素和 = 78
第 1 行首元素 = 5
选型：拥有数据 multi_array / 仅视图 mdspan
自检通过
```

**选型口诀**：拥有数据、可重定形 → `multi_array`；跨 ABI 传视图、配合线性代数 → `std::mdspan`。
