# 18 · C++26 展望：反射前夜的"穷人反射"与 asio 的 std 化终点

> 对应示例：`examples/18_cpp26/`（describe.cpp、pfr.cpp）

C++26 的两大明星特性都和 Boost 有直接血缘：**静态反射**（P2996）与 **std::execution**（P2300 senders/receivers）。前者的落地将重估两个"穷人反射"库（Describe/PFR）的价值；后者是 asio 作者二十年执行模型思考的标准答案。本章讲透这两个库，并给四个"血缘展望"（execution↔asio、linalg↔ublas、hive↔container、inplace_vector↔static_vector）一张导览图——它们的例程分别在 28/25/21 章。

## 18.1 Boost.Describe（2020）：宏注册的元数据

给枚举和结构体挂上可遍历的元信息，序列化/日志/配置编辑器全靠它：

```cpp
enum class Color { red, green, blue };
BOOST_DESCRIBE_ENUM(Color, red, green, blue)

struct Point { int x = 0; int y = 0; };
BOOST_DESCRIBE_STRUCT(Point, (), (x, y))

// 泛型打印任意已注册结构体——D.name/D.pointer 就是"成员的成员"
boost::mp11::mp_for_each<boost::describe::describe_members<T, mod_any_access>>(
    [&](auto D) { std::cout << D.name << " = " << t.*D.pointer; });
```

运行输出（`describe.cpp`）：

```text
枚举遍历: red=0 green=1 blue=2
green 的名字 = green
Point 反射:
  x = 3
  y = 4
自检通过
```

枚举的名字↔值双向映射是日常刚需（配置解析、日志、ORM）——Describe 一行宏解决。**它要宏，但换来"任意类型"的能力**（非聚合、私有成员、继承体系都行）。

## 18.2 Boost.PFR（2016）：零注册的聚合透视

PFR（Precise Flat Reflection）不需要任何宏——**聚合类型**（无自定义构造、无私有、无虚函数）自动可透视：

```cpp
boost::pfr::tuple_size_v<Sensor>;              // 字段数
boost::pfr::for_each_field(s, [](auto&& f, auto i){ ... });
boost::pfr::get<0>(s);                          // 按下标取
boost::pfr::eq(a, b);                           // 自动合成比较
```

运行输出（`pfr.cpp`）：

```text
字段数 = 3
字段遍历: 0:温度, 1:23.5, 2:7
第 0 字段 = 温度
自动相等比较? 1
分界：聚合用 PFR（零注册）/ 任意类型用 Describe（宏）/ 未来用反射
自检通过
```

`for_each_field` + 结构化打印已经好用，**但字段名拿不到**（`boost::pfr::get_name` 只在带编译器扩展时可用）——要名字就回 Describe。

## 18.3 两库分界 + 反射后的重估

| | PFR | Describe | C++26 反射（P2996） |
|---|---|---|---|
| 注册 | 零 | 宏 | 零 |
| 范围 | 仅聚合 | 任意类型 | 任意类型 |
| 字段名 | 编译器扩展限定 | ✅ | ✅ |
| 标准档位 | C++14 | C++14 | C++26 |

反射落地后的重估：两者退化为"老标准桥接层"——但 P2996 落地到全编译器可用还要数年（现实里 MSVC/GCC/clang 的实现进度是 2026-2029），**这期间 Describe/PFR 仍是生产答案**。
