# 02 · 第一个程序：从源码到 exe

> 对应示例：`examples/02_hello/`

## 2.1 最小的程序：main 与返回值

```cpp
int main() {
    // ═══ 2.1 最小的程序：main 与返回值 ═══
    std::println("你好，C++23！");  // println 自动换行
    // ……
    // ═══ 2.4 退出码：0 表示成功 ═══
    return 0;  // 脚本/CI 按退出码判断成败
}
```

四件事钉死：`main` 是程序入口，签名就是 `int main()`；返回 `int`，**0 表示成功、非零表示失败**——CI 脚本、build.ps1 都靠这个判断（它就是第 1.5 节三层验证的"运行层"）；`return 0;` 可以省略（main 特例，编译器自动补），但教程里显式写出来；花括号换行风格随团队，本教程用 K&R（`{` 不换行）。

示例源码里的 `// ═══ N.M 小节名 ═══` 分节注释是本教程的**导航系统**：N.M 与本章小节号一一对应，代码和文档互相对照着看。

## 2.2 std::print / std::println：占位符格式化

C++23 之前，输出是 C++ 最尴尬的角落：`printf` 类型不安全（`%d` 配错了直接未定义行为）、`cout` 冗长。**`<print>` 一锤定音**：

```cpp
std::print("姓名：{}，年龄：{}\n", "阿 C", 25);
std::print("编号 {:03}，PI ≈ {:.2f}\n", 7, 3.14159);
std::print("{:*^24}\n", "居中标题");  // 填充对齐
```

`{}` 是占位符，参数按顺序填入。三输出的实际效果：

```text
姓名：阿 C，年龄：25
编号 007，PI ≈ 3.14
********居中标题********
```

花括号里可以带**格式说明**（冒号后）：

| 写法 | 效果 | 说明 |
|---|---|---|
| `{}` | 默认 | 类型自己决定怎么显示 |
| `{:03}` | `007` | 宽度 3，前补零 |
| `{:.2f}` | `3.14` | 定点小数 2 位 |
| `{:*^24}` | `********居中标题********` | 填充 `*`、居中、宽 24 |
| `{:>10}` / `{:<10}` | 右/左对齐宽度 10 | 报表对齐 |
| `{{` / `}}` | 字面 `{` `}` | 转义 |

`std::println` = `std::print` + 自动换行，**优先用它**，忘 `\n` 的经典 bug 从此消失。占位符数量与参数数量必须匹配，多了少了都是**编译期错误**（不是运行时坑）——这正是第 01 章说的"编译期优先"哲学的日常体现。第 22 章有完整格式说明书。

## 2.3 老朋友 iostream：认得即可

```cpp
std::cout << "iostream 也能输出："
          << "int " << 42 << "，double " << 3.14 << "\n";
```

二十年存量代码里 `std::cout` 遍地都是：`<<` 把数据"推"进流，可以链式写。它不差，只是输个变量要写一串。新代码用 `print`（更短、类型安全、格式化能力强），但**读旧代码**必须认识 cout。混用注意：两者的缓冲独立，交错输出可能乱序——同一程序统一用一种；调试期要立刻看到输出时用 `std::endl`（换行+刷新）。

## 2.4 亲手编译一次

build.ps1 一键搞定，但第一次必须手工走一遍，理解它替你做了什么：

```bash
cd /g/code/guide/cpp20/examples/02_hello
# 进入 VS 编译环境（设置 PATH/INCLUDE/LIB），然后编译
cat > /tmp/cc.bat << 'EOF'
@echo off
call "G:\Program Files\Microsoft Visual Studio\18\Community\VC\Auxiliary\Build\vcvars64.bat" >nul
cl /nologo /std:c++latest /EHsc /utf-8 /permissive- /Zc:__cplusplus /W4 /Fe:demo.exe main.cpp
EOF
cmd //c "$(cygpath -w /tmp/cc.bat)" && ./demo.exe
```

三步：`vcvars64.bat` 把编译器请进命令行（不设这个，`cl` 就是"不是内部或外部命令"）；`cl … main.cpp` 一步完成编译+链接出 `demo.exe`（单文件时没有显式链接阶段的感觉，第 18 章拆开看）；运行。

正常输出长这样：

```text
main.cpp            ← cl 回显它正在编译的文件（/nologo 已压掉版本横幅）
你好，C++23！
姓名：阿 C，年龄：25
……
```

**C++ 的"运行"永远比解释型语言多一步构建**——改代码后要重新编译才能看到效果，这是节奏上的最大不适应。参数含义见[第 01 章](01-overview.md)工具链一节。中文正常显示的前提：源文件存成 UTF-8（`/utf-8` 参数配合），控制台 `chcp 65001`（build.ps1 已代设）。

## 2.5 注释与源码组织

```cpp
// 单行注释到行尾
/* 块注释，可以
   跨行 */
```

注释里可以写中文。块注释**不支持嵌套**（`/* /* */ */` 在第一个 `*/` 就结束了）。单文件能写到几千行，但真实项目按**翻译单元**拆分：一个 .cpp 一个单元，声明进头文件，C++20 之后还有新玩具"模块"（第 18 章）。教程的示例都刻意单文件（模块章除外），让你聚焦语言本身。

## 2.6 坑位清单

1. **忘分号**：`std::println("hi")` 少写 `;`，报错指向**下一行**——C++ 编译器读到别处才发现断了。报错行号是"发现处"不是"肇事处"。
2. **全角符号混入**：中文输入法的 `；`、`"`、`（）` 看着一样，编译器当垃圾字符，报"未知字符"类错误。写代码切半角，这是中文用户第一大坑。
3. **`std::` 前缀丢了**：`print(...)` 报"找不到标识符"。教程不使用 `using namespace std;`（污染命名空间，大项目雷区），所有标准库名字带全前缀——多打五个字符，换全局清晰。
4. **双击 exe 闪退**：控制台程序跑完即关。在终端里运行它，而不是资源管理器双击。
5. **占位符与参数不匹配**：`std::print("{} {}", 42)`——两个坑一个实参，编译期报错。这属于"好坑"：构建失败总好过输出错。
6. **vcvars 没跑就 cl**：`'cl' 不是内部或外部命令`。要么开"开发者命令行"，要么像 2.4 那样先 call vcvars64.bat。
