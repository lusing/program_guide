# 01 · C++ 全景：一门不断进化的语言

> 本章无独立示例，代码引用 `examples/02_hello/`。

## 1.1 C++ 是什么

C++ 是一门**编译型、静态类型、多范式**的系统级语言：既能贴着硬件写（内存布局、位运算、无 GC 暂停），又能搭出高层的抽象（类、模板、概念）。它被用来造操作系统、游戏引擎、数据库、浏览器——以及如今的大模型推理框架。性能敏感的地方，最后多半落在 C++ 上。

代价是**语言复杂、坑多**。四十年向后兼容的历史沉积，让"C++ 怎么写"的答案总量远超任何一门主流语言。本教程的态度：教"现代子集"——C++20/23 的惯用写法（`std::print`、智能指针、ranges、concepts），老式写法（裸 new、printf、char* 手工管理）只在"认得旧代码"的最低限度内出现。你已经会编程，所以重点不是"什么是循环"，而是**C++ 与你熟悉的语言在思维上的差异**。

三个贯穿全教程的思维方式，先挂在这：

- **所有权**：每个值有明确的归属者，归属者负责它的生死（第 09 章起反复出现）。
- **编译期优先**：能在一构建期暴露的错误，绝不留到运行时（static_assert、concepts、`{}` 初始化都是这个哲学）。
- **零开销抽象**：高级写法不高级在性能上让步——你不用为"写得像人"付机器的钱。

## 1.2 编译模型：先懂这个，再写代码

用 Python/JS 的经验直接套 C++ 会处处别扭，根子在执行模型：

| | 解释型（Python） | 编译型（C++） |
|---|---|---|
| 运行前 | 直接跑源码 | 源码 → **预处理** → **编译** → 目标文件(.obj) → **链接** → exe |
| 类型检查 | 运行时 | **编译期**（错误在构建阶段暴露） |
| 依赖 | import 时找模块 | 编译期看声明（头文件/模块），链接期找实现 |
| 部署 | 带解释器 | 一个 exe（基本自包含） |
| 改代码 | 存盘即生效 | **必须重新编译**才能看到效果 |

C++ 的一个**翻译单元**（translation unit，基本等于一个 .cpp 文件）单独编译成目标文件，链接器再把多个 .obj 缝成可执行文件。两阶段带来两个直接后果：

1. **"声明与定义分离"**：编译 main.cpp 时只需要知道 `add` 的签名（声明），实现（定义）可以在别的文件里，链接时再对接。头文件就是"把声明分享给多个 .cpp"的机制。
2. **链接错误长得不一样**：`无法解析的外部符号`（unresolved external symbol）= 声明有了但实现没链上——文件没编译、函数没定义、库名没写对，都在这一层报。

这两条现在混个脸熟即可，第 18 章正面展开（还有 C++20 的"模块"这个新接班人）。

## 1.3 标准演进：98 → 23

C++ 每三年发一版标准，**C++11 是现代 C++ 的分水岭**（auto、智能指针、lambda、移动语义都从这来），C++20 是第二次大跃进：

| 标准 | 关键词 | 一句话 |
|---|---|---|
| C++98/03 | STL、类 | 最初的面向对象 + 泛型 |
| **C++11** | auto、unique_ptr、lambda、range-for、move | "现代 C++"开始 |
| C++14/17 | 结构化绑定、if 初始化、optional/string_view | 打磨补齐 |
| **C++20** | **concepts、ranges、协程、模块、spaceship、format** | 四大件 + 格式化库 |
| **C++23** | **print、expected、generator、flat_map、mdspan** | 库层面的现代化 |
| C++26 | 反射（草案） | 展望，本教程一句话带过 |

本教程以 **C++23 为运行基线**（编译开关 `/std:c++latest`），凡是 C++20/23 的新特性都会标注版本；没标注的就是"很久以前就有"。这是刻意的教学选择：直接学现代写法，比"先学 98 再逐版打补丁"快得多——就像没必要先学会拨号上网再学光纤。

## 1.4 编译器与工具链

三大主流编译器：

| 编译器 | 厂商 | Windows 入口 | 备注 |
|---|---|---|---|
| **MSVC** (`cl`) | Microsoft | VS 开发者命令行 | 本教程主线，C++23 库支持最全之一 |
| GCC (`g++`) | GNU | MinGW/WSL | Linux 默认，`-std=c++23` |
| Clang (`clang++`) | LLVM | LLVM 官方包 | 错误信息最友好 |

各家对最新标准的**库特性**支持有先后差（比如某个 C++23 特性 MSVC 有了、GCC 还没有）。具体矩阵不背——查 [cppreference 编译器支持页](https://en.cppreference.com/w/cpp/compiler_support)，以本机实测为准。第 23 章会集中讲跨编译器差异与 CMake。

本教程工具链（`build.ps1` 已内置）：

```
cl /nologo /std:c++latest /EHsc /utf-8 /permissive- /Zc:__cplusplus /W4 文件.cpp
```

参数速记：`/std:c++latest` 最新语言标准；`/EHsc` 启用 C++ 异常；`/utf-8` 源码按 UTF-8 解释（含中文必需）；`/permissive-` 严格一致性（拒绝老式歧义代码）；`/Zc:__cplusplus` 让 `__cplusplus` 宏如实反映标准；`/W4` 高级别警告——**本教程要求零告警**，警告就是没写干净的代码。

## 1.5 读报错：第一个生存技能

C++ 编译错误信息以"长"著称，但结构固定。看一个真实例子（把 `std::println` 写成了 `std::printline`）：

```
main.cpp(7): error C2039: "printline": 不是 "std" 的成员
G:\...\include\print(21): note: 参见 "std" 的声明
```

读法三步：**先看文件名和行号**（`main.cpp(7)`）——去那里；**再看 error 代码后的人话**（C2039 不是 std 的成员——名字拼错/头文件没含）；**最后才看 note**（线索补充）。链接错误则看符号名里的函数签名，反推"声明有、实现无"差在哪。

心态上把编译器当**最严格的代码评审员**：它报的每一条都是真问题（虽然真问题的位置可能在报错行上一行）。教程各章的坑位清单会持续喂你"报错长相 → 病因"的对照。

## 1.6 本教程的工作流

每章的学法固定三步：**读讲解 → 跑示例 → 改代码再跑**。第三步最值钱——把示例改坏、看它怎么报错，是建立"报错长相"直觉的最快路径。比如把 `02_hello` 里 `"阿 C"` 的引号改成中文引号再编译，你就永远记得全角符号的报错长什么样。

```bash
cd cpp20                                    # 换成你自己的检出位置
pwsh -NoProfile -ExecutionPolicy Bypass -File build.ps1 -All      # 全部 23 个示例（Windows）
./run-all.sh                                                      # 同上（macOS / Linux）
pwsh -NoProfile -ExecutionPolicy Bypass -File build.ps1 -Example 12_ranges   # 单个示例
./run-all.sh 12                                                   # 同上，按编号
```

（Windows 上若 `pwsh` 不在 PATH，用它的绝对路径调用，例如
`"/g/Program Files/PowerShell/7/pwsh"`；macOS / Linux 上 MacPorts 装的在 `/opt/local/bin/pwsh`。）

build.ps1 做三层验证：**编译（/W4 零告警）→ 运行（退出码 0）→ 示例内置 assert 自检**。示例不满足这三层就进不了仓库——你在文档里看到的每段代码都是真编译真跑过的。每章示例的预期输出写在该章末尾的"运行输出"注释或文中，跑出来对不上就说明你改过了什么。

直接双击/命令行运行 exe 时中文会乱码（控制台默认 GBK）：先 `chcp 65001`。经 build.ps1 运行无此问题（脚本已设 UTF-8）。

## 1.8 学习心态

- **C++ 是工具箱不是宗教**：过程式、面向对象、泛型、函数式都有。教程教你选现代惯用的那把。
- **遇到"为什么这么怪"，答案通常是历史兼容或性能**。接受它，用现代写法绕开它。
- **先学安全子集**：`std::string`/`vector`/智能指针/ranges 覆盖 90% 日常；指针运算、裸内存这些"著名 C++"内容，本教程刻意延后并少讲——需要时你会认出来的。
- **不要试图一次学全**：C++ 没有人全懂。到第 24 章你能写出安全、现代、可维护的 C++，就已经超过大多数存量代码了。

## 1.9 坑位清单

1. **拿 C++98 时代的资料入门**：教程/博客里的 `new`/`delete`、`char*`、裸数组优先写法都是历史。识别标志：没有智能指针、没有 `auto`。本教程即解药。
2. **标准与编译器对不上**：代码用了 C++23 特性却用默认标准编译——报一堆"不认识"的错。先确认 `/std:c++latest`，再查 cppreference 支持矩阵。
3. **忽略警告**：/W4 的每条警告都是潜在 bug（未初始化、窄化、未用返回值）。教程铁律：零告警。
4. **中文乱码就怀疑代码**：先 `chcp 65001`，八成是控制台编码不是程序问题。
5. **跳章学并发/模板**：19–21 章押着前面所有章节的积累（RAII、移动、类型推导），跳过去只能抄不能懂。
