# 03 · 元语言 Standard ML

> 对应示例：[`examples/03_ml/03_ml.sml`](../examples/03_ml/03_ml.sml)

HOL4 的元语言是 Standard ML —— 项、类型、定理都是 SML 的值，战术是 SML 的
函数。本章只讲写 HOL4 脚本真正用到的那一小块 SML：**够用就停**，
不展开类型系统、模块系统、functor 那些。

## 03.1 值绑定

```text
n = 3
n 的类型由推断给出（int）：4
```

```sml
val n = 1 + 2
val _ = out ("n = " ^ Int.toString n)
```

> 交互式 REPL 里顶层最后一个值会留在 `it` 里；**批处理入口 `hol run` 没有
> `it`**。脚本不能依赖 `it` —— 这是"能交互"和"能重跑"之间的一处真实差别。

## 03.2 函数

```text
add_t (3,4) = 7
add_c 3 4   = 7
偏应用 add_c 3 : int -> int，13
```

```sml
fun add_t (x, y) = x + y        (* 元组版：一个参数 *)
fun add_c x y = x + y           (* curried 版：可以偏应用 *)
val _ = out ("偏应用 add_c 3 : int -> int，" ^ Int.toString (add_c 3 10))
```

HOL4 的库函数大多是 curried 的（便于偏应用），但 `Definition` 定义的
HOL 函数可以两种都用。

## 03.3 模式匹配与 option

```text
first []     = NONE
first [7;8]  = 7
len [1;2;3] = 3
```

```sml
fun first l = case l of [] => NONE | x :: _ => SOME x
fun len [] = 0
  | len (_ :: t) = 1 + len t
```

`option` 是 SML 里表示"可能没有"的标准手段；HOL 项里也有同名同形的
`option`（19.7 节），两者不是一回事但长得一样。

## 03.4 异常

```text
3 div 0 被兜住 = ~1
hd [] 被兜住   = ~1
```

```sml
val _ = out ("3 div 0 被兜住 = " ^ Int.toString (3 div 0 handle _ => ~1))
val _ = out ("hd [] 被兜住   = " ^ Int.toString (hd ([] : int list) handle _ => ~1))
```

> **`^` 的优先级比 `handle` 高**。`Int.toString (hd [] handle _ => ~1)` 里的
> 括号是必需的；写成 `Int.toString (hd []) handle _ => ~1` 会按
> `(Int.toString (hd [])) handle _ => ~1` 解析，类型直接错。

`handle` 在 HOL4 脚本里还有一个专门的用途：`SIMP_CONV` 在"什么都没改"时抛
`UNCHANGED`，演示代码必须显式兜住（20 章）。

## 03.5 组合子

```text
(Int.toString o (fn x => x + 1)) 41 = 42
41 |> (fn x => x + 1) |> Int.toString = 42
$ 是中缀的右结合应用：42
用在定理上：1 + 1 = 2
```

```sml
val _ = out ("$ 是中缀的右结合应用：" ^ Int.toString ((fn x => x + 1) $ 40 + 1))
val _ = out ("用在定理上：" ^ (EVAL ``1 + 1`` |> concl |> term_to_string))
```

`|>` 是本教程用得最多的：`EVAL t |> concl |> term_to_string` 读起来就是
"求值、取结论、转字符串"。

> `$` 在 SML 里是**中缀的右结合应用**，不是"取函数"操作符。
> 想当前缀函数用要写 `(fn x => x + 1) $ 40 + 1`。

## 03.6 列表与字符串

```text
map (fn x => x * 2) [1;2;3] 的 SML 写法 = 2;4;6
foldl 求和 = 10
String.concatWith = a, b, c
```

```sml
val _ = out ("map (fn x => x * 2) [1;2;3] 的 SML 写法 = " ^
             String.concatWith ";" (map Int.toString (map (fn x => x * 2) [1, 2, 3])))
```

注意这一行用了**两次** `map`：外层 `map` 是 SML 的（作用在 `int list` 上），
内层的 `1, 2, 3` 是 SML 列表。写成 HOL 列表要用分号 —— 两层的分隔符不一样，
这也是 02 章说的"边界"。

## 03.7 `val _ =` 惯用法

```text
  1
  2
  3
遍历结束，返回 unit，不污染环境
```

```sml
val _ = List.app (fn x => print ("  " ^ Int.toString x ^ "\n")) [1, 2, 3]
```

脚本里几乎每个顶层声明都是 `val _ = …`：我们只要副作用（打印 / 定义 / 登记
定理），不要新的 ML 绑定。这样脚本**不会污染环境**，也让每一行都是
"做完一件事就走"。

## 03.8 坑位清单

1. **脚本里没有 `it`** → 交互式 REPL 才有；批处理入口下 `it` 未声明，直接报错。
2. **`^` 比 `handle` 优先级高** → `Int.toString (hd [] handle _ => ~1)` 的括号不能省。
3. **`~1` 是负一** → SML 里负数用 `~` 不用 `-`；`-` 是二元减。
4. **`$` 是中缀不是前缀函数** → 要 `(fn x => x + 1) $ 40`。
5. **`Int.toString` 只吃 int** → 项里的 `num` 和 SML 的 `int` 是两套数，别混。
6. **`case ... of` 的分支要用 `|` 分隔且对齐** → 多个子句的 `fun` 写法里，第二个子句前必须有 `|`。
7. **`open` 不能写在 `val _ =` 里** → 必须顶层单独一行（01 章踩过）。
8. **`List.app` 返回 unit** → 想拿结果用 `map`；`app` 只为副作用。
9. **`String.concatWith` 的参数顺序是 (分隔符, 列表)** → 跟其它语言的 `join(list, sep)` 相反。
10. **`foldl` 的函数参数是 `(元素, 累加器)`** → 顺序容易记反；`foldl (fn (x, a) => x + a) 0 [...]`。
