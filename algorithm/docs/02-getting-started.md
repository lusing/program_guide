# 02 · 入门：插入排序、循环不变式与归并排序

> 对应 CLRS 第 2 章 *Getting Started*（英文 3rd ed. pp.16–39）。这一章用一个
> 真正的算法（插入排序）把三件事一次讲全：**怎么证明它对**（循环不变式）、

1. 会写插入排序，并能说出它每一步在维护什么性质；
2. 能完整陈述并证明一个循环不变式（初始化/保持/终止三段论）；

7. 会把「逐对、一前一后」的过程性描述直接翻译成下标模式（对称排序），
   并用独立的链表移动过程对账。

## 动机：排序问题

**输入**：n 个数的一个序列 ⟨a₁, a₂, …, aₙ⟩。
**输出**：输入序列的一个排列 ⟨a′₁, a′₂, …, a′ₙ⟩，满足 a′₁ ≤ a′₂ ≤ … ≤ a′ₙ。

排序是算法课的「果蝇」：问题定义人人秒懂，解法的优劣差异却极其丰富——比较型、
分布型、增量式、分治式、随机化……第 6–9 章会把它做成一条完整的技术路线。CLRS
选择从插入排序开始，因为它就是你打扑克牌整手牌的动作。

## 插入排序

### 直觉

手里拿着一堆已排好的牌，摸一张新牌，从右往左找到合适的位置插进去。每一时刻，
「手里的牌是有序的」这个事实从不被破坏——这句话写成精确的数学陈述，就是下面
的循环不变式，也是本章的主角。

### 伪代码与 C++23 实现

CLRS 的 INSERTION-SORT（1 基下标）：

```clrs
INSERTION-SORT(A)
1  for j = 2 to A.length
2      key = A[j]
3      // 把 A[j] 插入已排序序列 A[1..j-1]
4      i = j - 1
5      while i > 0 and A[i] > key
6          A[i+1] = A[i]
7          i = i - 1
8      A[i+1] = key
```

C++23 版（0 基下标，`std::span<int>` 视图传参——不拷贝、不涉及所有权）：

```cpp
static void insertion_sort(std::span<int> a, Counters& c) {
    for (std::size_t j = 1; j < a.size(); ++j) {
        int key = a[j];                    // 待插入元素
        std::size_t i = j;                 // 从有序前缀的尾部往左找位置
        while (i > 0 && (++c.compares, a[i - 1] > key)) {
            a[i] = a[i - 1];               // 右移一格
            ++c.shifts;
            --i;
        }
        a[i] = key;                        // 插入
    }
}
```

与伪代码的三处刻意差异：

1. **移位而非交换**：CLRS 第 6 行把元素右移一格（A[i+1]=A[i]），而不是 swap——
   一次移位是一次赋值，交换是三次。手写版常见的错误是写成 swap，慢三倍还看不出
   为什么。示例同时统计了移位次数。
2. **计数器的位置**：`(++c.compares, a[i-1] > key)` 必须放在 `&&` 的**右侧**。
   写成 `(a[i-1] > key && ++c.compares)` 会因为短路（i==0 时直接假）而漏计；
   顺序反了则先计数后比较，计数总是准确的。这个细节见坑位清单第 3 条。
3. **`i > 0` 前置**：`std::size_t` 无符号，`i` 减到 0 再减会回绕成天文数字。
   把边界检查放在下标访问之前是 span 时代的肌肉记忆（坑位第 1 条）。

```

第 1 趟后 j=1: [2 5 4 6 1 3]

第 3 趟后 j=3: [2 4 5 6 1 3]
```

下面分析的主角。

## 循环不变式：怎么证明插入排序是对的

**不变式陈述**：第 4 行 `i` 赋值之前（即每轮 for 迭代开始、key 已取出时），
子数组 A[1..j−1] 由原来 A[1..j−1] 中的元素构成，且**已按序排列**。

证明分三段，一段都不能少（CLRS p.19）：

1. **初始化**：j=2 时 A[1..j−1] = A[1..1] 只有一个元素，平凡地有序，且就是
   原来的那一个元素。不变式成立。
2. **保持**：设某轮开始时不变式成立（A[1..j−1] 有序）。循环体把 A[1..j−1] 中
   严格大于 key 的元素各右移一格，停下位置 i 满足 A[i] ≤ key < A[i+1]（这里
   A[i] 指 key 腾出位置后的左侧邻居）。把 key 放进 A[i+1] 后，A[1..j] 有序，
   且元素集合与原 A[1..j] 相同——下一轮的 j 已经递增，不变式对新的 j 成立。
3. **终止**：for 循环终止时 j = n+1 > n。把 j = n+1 代入不变式：A[1..n] 由原
   数组的全部 n 个元素按序组成——**这正是排序的定义**。证毕。

三段论的力量在于第 3 段：不变式本身只谈循环中间态，把它「推到循环出口」就
恰好得到我们要的结论。写不出第 3 段的不变式（即终止时陈述不到目标性质），
说明陈述选错了。

示例 02.2 把三段论做成了可执行抽样：每趟开始前断言
`is_sorted(A[0..j))` 且 `is_permutation(A[0..j), 原 A[0..j) 排序后的样子)`——
不变式的两个要件（有序 + 同一集合）各占一条 assert。断言过不了，不变式陈述
或实现必有错。

## 分析：最好、最坏与平均

CLRS 的分析在**随机访问机（RAM）模型**上进行：一条指令一步、整数运算与
下标访问都是单位代价。本教程统一用**比较次数**当代价（决定性：同一输入三台
编译器得到同一数字；见 docs/01 的纪律）。

- **最好情形（已序输入）**：每趟 while 只比较一次就退出，共 n−1 次。
  示例实测 n=16 → 15 = n−1。
- **最坏情形（逆序输入）**：第 j 趟要与前缀全部 j−1 个元素比较，共
  1+2+…+(n−1) = n(n−1)/2 次。示例实测 n=16 → 120 = 16·15/2。移位次数同为
  n(n−1)/2（每次比较成功都伴随一次移位）。
- **平均情形**：固定种子的随机排列上，期望比较约 n²/4——直觉是「key 平均
  要穿过半个前缀」。严格推导靠**逆序对**计数（一个排列的平均逆序数是
  n(n−1)/4，插入排序的比较次数与逆序数同阶），CLRS 第 8 章练习 8.1 会回收
  这条线。示例 n=16 随机排列实测 57，落在 n²/4 = 64 附近。

三行实测（示例 02.3）：

```
n=16：最好(已序)比较 15（理论 n-1=15）
n=16：最坏(逆序)比较 120（理论 n(n-1)/2=120）
n=16：随机排列比较 57（理论期望 ~n^2/4=64）
```

顺带一个设计策略的观察：插入排序是**增量法**——已解决一个子问题（前缀有序），
扩展一步（多放一个元素），保持子问题的解仍成立。第 17 章贪心算法是增量法的
另一种形态；而下面要出场的**分治法**则是先把问题切成互不相干的小块，分别
解决后再拼起来。

## 归并排序：分治登场

分治三步曲（CLRS §2.3.1）：

- **分解**：把 n 个元素切成含 n/2 个元素的两半；
- **解决**：递归地对两半排序；
- **合并**：合并两个有序序列（关键操作 MERGE，Θ(n)）。

### MERGE：哨兵版与边界版

CLRS 的 MERGE（p.31）把两个子数组各复制一份，**尾部放一个 ∞ 哨兵**，然后
每次取两边较小者——循环条件里就永远不用检查「哪边先用完」（∞ 不会先被取走）：

```clrs
MERGE(A, p, q, r)        // A[p..q] 与 A[q+1..r] 各自有序
1  n1 = q - p + 1,  n2 = r - q
2  let L[1..n1+1] 和 R[1..n2+2] 为新数组
3  把 A[p..q] 拷入 L，A[q+1..r] 拷入 R
4  L[n1+1] = ∞,  R[n2+1] = ∞     // 哨兵
5  i = 1,  j = 1
6  for k = p to r
7      if L[i] ≤ R[j]
8          A[k] = L[i],  i = i + 1
9      else A[k] = R[j],  j = j + 1
```

哨兵技巧漂亮但有前提：**元素类型得有「∞」可用**。对 int 可以用 INT_MAX，
对一般的 `std::weakly_ordered` 类型就没有了。C++ 版本更自然的是**下标边界**：
两个 while 收尾把剩余元素直接搬过去：

```cpp
while (i < mid && j < a.size()) {            // 两边都非空：比较后取小
    if (++c.compares, buf[i] <= buf[j]) {    // ≤：相等取左 → 稳定性
        a[k++] = buf[i++];
    } else {
        a[k++] = buf[j++];
    }
}
while (i < mid)      { a[k++] = buf[i++]; }  // 左边有剩：直接搬
while (j < a.size()) { a[k++] = buf[j++]; }  // 右边有剩：直接搬
```

两个版本的比较次数**完全相同**：比较只发生在两边都非空时，每比较一次恰好
归并一个元素，所以单次 MERGE 至多 `左长 + 右长 − 1` 次比较。对 CLRS 图 2.3
的 ⟨2,4,5,7⟩ ⊕ ⟨1,2,3,6⟩ 实测（示例 02.4）：

```
  取右 1（比较 #1）
  取左 2（比较 #2）
  取右 2（比较 #3）
  取右 3（比较 #4）
  取左 4（比较 #5）
  取左 5（比较 #6）
  取右 6（比较 #7）
MERGE 结果[1 2 2 3 4 5 6 7]
单次 MERGE 比较实测 7（理论 ≤ 左+右-1 = 4+4-1 = 7）
```

第 2 行的「取左 2」值得注意：两边相等时**取左边**（`≤`）。这个选择保证了
归并排序是**稳定排序**——相等元素的相对次序不变。稳定性有什么用？第 8 章
基数排序的整座大厦就建在「底层排序必须稳定」之上。

### 递归式与递归树

归并排序的运行时间满足 T(n) = 2T(n/2) + Θ(n)（两个一半规模的子问题 + 一次
线性合并）。递归树直觉（示例 02.5 打印 n=8 的树）：

```
                [整棵 n=8]  本层合并代价 c·8
              /            \
        [n=4]            [n=4]      每层两半，共 c·8
       /      \          /      \
    [n=2]  [n=2]   [n=2]  [n=2]   共 c·8
    叶子 8 个（n=1，不再合并）
```

树高 lg n（每层规模减半），每层合并总代价 cn（每层元素总数就是 n），共
**cn·lg n** → T(n) = Θ(n·lg n)。第 4 章会把「递归树」升级成三种系统方法之一
（代入法/递归树法/主定理），现在只要这幅图在脑子里。

对 n=8 的 CLRS 图 2.4 数组 ⟨5,2,4,7,1,3,2,6⟩，本实现实测 17 次比较，上界
n·lg n = 24——注意 17 < 24：上界是「最坏情形每比较都归并」的粗界，具体输入
下有子问题提前用完的节省。第 4 章练习会让你算精确的最坏比较次数
（恰好是 n·lg n − 2^lg n + 1 = n·lg n − n + 1 = 17）。

回到第 1 章的问题：同机同 n=2048 逆序输入，插入排序 2,096,128 次 vs 归并
11,264 次——**186 倍**。Θ(n²) 与 Θ(n lg n) 的差距在任何硬件上都追不回来。

## 两个计数问题：累积计数与周期取模

循环不变式不只属于排序。这里用它解决两个「计数」问题（整理自《趣题学算法》
第 1 章的问题 1-1 与 1-7，内容自包含）——一个练**累积**，一个练**取模**。

### 问题一：骑士的金币（累积计数）

国王的赏赐规律：第 1 天 1 枚；接下来 2 天每天 2 枚；接下来 3 天每天 3 枚……
连续 k 天每天 k 枚之后是连续 k+1 天每天 k+1 枚。给定天数 N，求金币总数。

**问题模型**：天数轴被切成分段等差的「段」：段 k 占 k 天。设 k 是满足
1+2+…+k ≤ N 的最大值（三角形数 T(k) = k(k+1)/2 ≤ N），令 j = N − T(k)，
则答案 = Σᵢ₌₁ᵏ i² + (k+1)·j。

**循环不变式版本**（示例 02.6 的 `golden_coins`）：两个计数器 days 与 coins，
每轮把一整个「k 枚段」累加进去。不变式：**每轮循环开始时，coins 等于前
days 天按赏赐规则应得的总数，且 days 是完整段的长度和**。终止时 days ≤ N <
days + k，剩下的 j = N − days 天落在第 k+1 段，每天 k 枚——尾段一次乘法
收尾。这与插入排序的增量法同构：已解决一个子问题（前 days 天），扩展一步，
保持子问题的解仍成立。

**复杂度**：while 循环每轮 k 增 1，最多跑 √(2N) 轮（三角形数超过 N 即停），
即 O(√N)。

**闭式对账**：Σᵢ₌₁ᵏ i² = k(k+1)(2k+1)/6 是经典闭式（可对 6 整除恒成立，
整数除法无舍入）。示例对每个 N 同时算「逐段累加版」与「闭式版」并 assert
相等——两种独立推导在机器上对账，是第 1 章纪律的又一次落地：

```
金币问题（1-1）：连续 k 天每天 k 枚，天数与金币总数：
  N=   10：金币     30（= Σi^2 闭式 k(k+1)(2k+1)/6 + (k+1)·0）
  N=    7：金币     18（= Σi^2 闭式 k(k+1)(2k+1)/6 + (k+1)·1）
  N=  100：金币    945（= Σi^2 闭式 k(k+1)(2k+1)/6 + (k+1)·9）
  N=10000：金币 942820（= Σi^2 闭式 k(k+1)(2k+1)/6 + (k+1)·130）
```

手算复核 N=7：7 = 1+2+3+1，前三段贡献 1+4+9 = 24，尾段 1 天 × 4 枚，
24 + 4 = 18 ✓。

### 问题二：糟糕的公交调度（周期取模）

车站只公布各路车的**发车间隔序列**，每路车按自己的间隔序列**循环**发车。
给定到达时刻 arrival，求下一班车的最短等待。

**关键观察（取模降维）**：一路车的发车模式以 T = Σ间隔 为周期无限重复，
所以「arrival 之后最近的一班车」只依赖 R = arrival mod T——取模把无穷的
时间轴压回一个长度为 T 的圈。圈内的发车时刻恰是间隔的**前缀和**：
P(0)=0 < P(1) < … < P(m) = T。等第一班「圈内发车时刻 ≥ R」的车：

- 若存在 P(i) ≥ R：等待 P(i) − R（P(i) = R 时等待 0——到站即上车）；
- 否则等下一圈头一班车：等待 T − R。

对每路车各算一个等待，取最小值。整题一次线性扫描，O(Σmᵢ)：

```
公交调度（1-7）：周期取模 + 前缀和扫描：
  第 1 路：周期 T=600，arrival mod T = 400 ⟹ 等待 200
  第 2 路：周期 T=1500，arrival mod T = 1000 ⟹ 等待 500
  第 3 路：周期 T=2400，arrival mod T = 1000 ⟹ 等待 500
  最短等待 = 200（arrival=1000 取模后只需看圈内的第 400 个时间单位）
```

第 1 路的手算复核：周期 100+200+300 = 600，R = 1000 mod 600 = 400；圈内
发车时刻 100、300、600，第一个 ≥ 400 的是 600，等待 200 ✓。

### 两题合起来看

| | 骑士的金币 | 公交调度 |
|---|---|---|
| 核心动作 | 累加（段贡献 → 计数器） | 取模（无穷轴 → 一个周期） |
| 不变式/关键量 | coins = 前 days 天总数 | R = arrival mod T |
| 收尾 | 尾段 (k+1)·j 一次乘法 | 圈内前缀和第一处 ≥ R |
| 复杂度 | O(√N) | O(Σmᵢ) |

两题都不需要任何数据结构——但都需要**先找到正确的循环状态量**（天数计数器
对、周期内时刻），这正是循环不变式思维的迁移。

## 能量转换：先预判、后乘法的模拟

### 问题

开门需要能量 N，手里只有 M。可以反复做「转换」：若当前能量为 A（A ≥ V），
消耗 V 再放大 K 倍，即

```
A ← (A − V)·K
```

任何时刻能量不能为负。求最少转换几次能达到 N；不可能则输出 −1。

四个小例与一个大例（输出原文）：

```
能量转换（1-3）：A ← (A−V)·K，求最少转换次数：
  N=10 M=3 V=1 K=2 ⟹ 3 次
  N=10 M=2 V=1 K=2 ⟹ -1 次
  N=10 M=9 V=7 K=3 ⟹ -1 次
  N=10 M=10 V=10000 K=0 ⟹ 0 次
  N=1e8 M=2 V=1 K=1e8 ⟹ 1 次（预判命中，无中间乘积）
  随机 3000 例模拟 vs BFS：不一致 0 例
```

### 三类失败先排掉

1. **M ≥ N**：能量本来就够，0 次。
2. **M < V**：连第一次转换都做不了（转换要求 A ≥ V），−1。
3. **转换不增**：某次 `(A−V)·K ≤ A`，能量从此再也涨不起来——注意转换是
   **确定性**规则，参数不变，同样的动作永远给出同样的结果，能量一旦不增，
   以后每一步都重复同样的不增。

第三类最容易只想到 K = 1。其实它覆盖一整族情形：

- K = 0：结果恒为 0；
- K = 1：结果是 A−V，V = 0 时持平、V > 0 时减少；
- K ≥ 2 但 A 不够大：`(A−V)·K ≤ A` 也可能成立，例如 A = 9、V = 7、K = 3，
  `2·3 = 6 < 9`——放大倍数再大，被扣掉的 V 太多，仍然亏。

正确的推进是 A = 3、V = 1、K = 2 那样：3 → 4 → 6 → 10，三步。

### 关键纪律：先预判「这一步够不够」，再决定要不要乘

题面 N、M、V、K 都可达 10⁸，直接写 `next = (A−V)*K` 再和 N 比，中间积最大
到 10¹⁶（64 位装得下，但这是 N 只有 10⁸ 的侥幸——换个值域就炸）。干净的
写法是把「这一步就达标」翻译成**不含乘法**的判据：

```
(A−V)·K ≥ N  ⟺  A−V ≥ ⌈N/K⌉
```

命中就直接返回当前次数 +1；不命中时乘积严格小于 N，算出来也安全。于是全程
出现过的数没有一个超过 N，溢出从结构上消失，而不是靠更宽的类型硬扛。

### BFS 对账

「每次必转换」看起来显然，但凭什么它给出的是**最少**次数？把能量值
0..N 当状态、一次转换当一条有向边（跳过 N 的边直接通向开门），跑 BFS：
最短路径才是最少次数。示例在 3000 个随机小例上让朴素模拟与 BFS 逐例对账，
不一致数为 0——BFS 不依赖贪心直觉，专门给模拟的正确性背书。

## 对称排序：把长度升序「折」成对称形状

### 问题

马戏团有 n 个明星，名单**已按姓名字符串长度非降序排好**。老板嫌这种
排法一头长一头短，要求改成**首尾短、中间长**：把名单逐对处理
（第 0、1 个一对，第 2、3 个一对……），每对的前者放到序列的**前部**、
后者放到序列的**后部**。输出重排后的名单。

### 从「过程」直接读出下标模式

模拟「逐对放置」：第 0 对的前者 Bo 占第 0 个输出位、后者 Pat 占倒数
第 0 位；第 1 对的前者 Jean 占第 1 个输出位、后者 Kevin 占倒数第 1
位；第 k 对占正数第 k 位与倒数第 k 位。于是输出的**原下标序列**为

```
0, 2, 4, …（偶数下标升序），…, 5, 3, 1（奇数下标降序）
```

n=7 时：`0,2,4,6,5,3,1`，即 Bo, Jean, Claude, Marybeth, William,
Kevin, Pat——最长的 Marybeth 恰在正中，两边长度对称地降下来。n 为
奇数时落单的中间名（下标 n−1，偶数）自然接在升序段末尾、成为峰顶；
n 为偶数时峰顶是下标 n−2 与 n−1 两个等长名（升序段末尾 + 降序段
开头）。

这也说明「放前部」不能按字面用 push_front：第 1 对的前部元素要排在
第 0 对前部元素的**后面**——偶数下标按升序追加即可。

### 实现

直接按两段下标构造，O(n)、一遍走完：

```cpp
for (int i = 0; i < n; i += 2) { out.push_back(names[i]); }
for (int i = (n % 2 == 0 ? n - 1 : n - 2); i >= 1; i -= 2) {
    out.push_back(names[i]);
}
```

第二段首值按奇偶取值：n 偶时最大奇数下标是 n−1，n 奇时是 n−2；
n=1 时算出 −1，整段跳过。这里刻意用 `int` 而不是 `size_t`：
`size_t(0) − 2` 会静默回绕成天文数字，循环边界反而失效。

### 对账：链表上的「移动插入」过程

不直接用下标结论，另写一版老老实实执行「把第 i 个元素移到第 j 个
位置之前」（i=2、j=n+1 起步，1 基位置，每轮 ++i、−−j）。用
`std::list`，按位置取迭代器、擦除后插到目标迭代器前——链表擦除不
失效其他迭代器，插、删都是 O(1)，按位定位 O(n)。3000 个随机案例
（n≤15，长度非降）两版逐例相等，且输出长度都满足「先非降、过峰后
非增」的形状性质。

> 复杂度对照：直接构造是 O(n)；移动过程若用数组实现，每次插、删各
> Θ(n)、共 Θ(n²)，换链表降为 O(n)（按位定位若用双向游标也只需
> O(1) 摊还）。数据结构的选择在这个小问题上差一个数量级。

## C++23 语言点：std::span

`std::span<int>`（C++20 起，本教程全程使用）是「连续元素的一段视图」：

- **零拷贝**：传参只带 (指针, 长度)，不搬数据——递归归并的
  `a.first(mid)` / `a.subspan(mid)` 就是 O(1) 地切一刀；
- **只读视图**用 `std::span<const int>`（本例 `print_span` 的参数）；
- **陷阱**：`size()` 返回无符号 `std::size_t`，`i - 1` 在 i=0 时回绕（见坑位）；
  与 `ptrdiff_t` 混算要显式 `static_cast`。

## 与 STL 对照

| 需求 | 标准库 | 底层 |
|---|---|---|
| 通用排序 | `std::ranges::sort` | introsort（快排+堆排+插入混合，Θ(n lg n)，不稳定） |
| 稳定排序 | `std::ranges::stable_sort` | 归并排序（本章），Θ(n lg n)，稳定 |
| 两段已序拼接 | `std::ranges::inplace_merge` | 本章 MERGE 的原地版 |
| 有序结构维护 | `std::map`（第 12–13 章红黑树） | — |

工程结论：**永远先用 `std::ranges::sort`**。手写插入排序的价值在两处——小数组
上它真的快（introsort 的递归底部就是切到插入排序，通常阈值 16–32），以及它是
理解循环不变式的最短教具。

## 坑位清单

1. **`std::size_t` 下溢成天文数字**
   （现象：while 里 `a[i-1]` 在 i==0 时读到数组外，或 `i` 回绕成 2⁶⁴−1 死循环；
   原因：`std::span::size()` 与下标习惯用无符号数，`0−1` 不报错而是回绕；
   后果：越界 UB 或挂死；对策：边界检查前置——`while (i > 0 && …)`，
   且检查必须放在下标表达式的左边靠 `&&` 短路保护。）
2. **输出 helper 与标签各管一半括号**
   （现象：示例第一版打出 `初始数组 [[5 2 4…`——标签带了 `[`，helper 又补一个；
   原因：职责重叠；后果：纯外观瑕疵但破坏文档对账的整洁；对策：约定标签只写
   文案与冒号，`[` `]` 一律由 `print_span` 独家负责，改一处全局生效——本例
   实测修了三遍才收敛，写进坑位。）
3. **比较计数被短路求值吞掉**
   （现象：统计出的比较次数比理论少，随机输入下忽对忽错；原因：把
   `++c.compares` 放在 `&&` 左侧时它总会执行，但放在比较表达式**内部**且 i==0
   可短路时，`A && ++c` 形态会漏计；后果：分析实验的数字失去可信度；
   对策：统一写成 `while (i > 0 && (++c.compares, a[i-1] > key))`——计数永远
   先于比较发生，且不受短路影响。）
4. **哨兵 MERGE 搬进泛型代码**
   （现象：元素类型是 string/自定义类型时没有「∞」可用，写死 `INT_MAX` 对
   int 恰好、对 double 错（有 NaN/精度）；原因：哨兵技巧依赖类型有全序最大元；
   后果：泛型排序出静默错误；对策：用下标边界版收尾 while，或 CLRS 练习
   2.3-2 正是让你写无哨兵版。）
5. **交换版「插入排序」慢三倍**
   （现象：实现写成 `std::swap(a[i], a[i-1])` 逐对交换；原因：一次移位是一
   次赋值，交换是三次；后果：常数变大，教学上还掩盖了「key 先取出、最后落位」
   的结构；对策：先存 key，移位腾位，最后 `a[i] = key`。）
6. **「等下一圈头一班车」的分支漏掉**
   （现象：公交调度里乘客到站后一路车当圈再无班车时算出负等待或漏等；
   原因：只扫了圈内前缀和、没写「前缀和全 < R 时等待 T − R」的兜底分支；
   后果：边界时刻（R 大于圈内所有发车点）答案错；对策：初值设 wait = T − R
   再扫描覆盖——扫描找到更小的就更新，找不到自然落到兜底值。）
7. **「到站即上车」用 `>` 判成要再等一班**
   （现象：R 恰等于某班发车时刻时算出「等一整圈」；原因：扫描条件写成
   `prefix > R`，把「发车瞬间到站也算搭上」的规则排除了；后果：恰逢发车
   时刻的测试点全错；对策：条件用 `prefix >= R`，等待 = prefix − R 取 0。）
8. **Σi² 闭式除以 6 前先取模**
   （现象：对 k(k+1)(2k+1)/6 想先取模再除，结果错；原因：取模破坏了
   「k(k+1)(2k+1) 恒被 6 整除」这一整除结构——除法必须在取模之前做；
   后果：需要模余的变体题里闭式版与累加版对不上；对策：先除后模，或改用
   逐段累加（每步可模）。本章 N ≤ 10⁴ 无溢出之虞，规模放大时按 64 位算。）
9. **把「不前进」只等同于 K=1**
   （现象：只在 K=1 时返回 −1，K≥2 的低能量算例给出错误答案或死循环；
   原因：条件必须直接写 `(A−V)·K ≤ A`——K=0、V=0 持平、能量太低导致放大后
   仍亏，都由这一个比较统一兜住；后果：如 A=9,V=7,K=3 这种样例点全错；
   对策：每轮先判不前进、再更新 A。）
10. **先乘出来再比较，中间积炸值域**
    （现象：`next = (A−V)*K` 直接乘，值域放大后乘法溢出；原因：把「这一步
    达标」的判定和乘法捆在一起；后果：溢出后符号翻转，可能误判前进/不前进；
    对策：用 `A−V ≥ ⌈N/K⌉` 预判，命中即返回——不命中时乘积 < N，安全。）
11. **BFS 把「跳过 N」也当成普通状态编号**
    （现象：对账 BFS 想给 ≥N 的跳跃分配数组下标，越界；原因：开门只关心
    「是否达到」，所有 ≥N 的值是同一个终止状态；后果：越界访问；对策：转移
    结果 b ≥ N 时直接当作到达终点返回，状态数组只开 0..N−1。）
12. **奇数下标段用 `size_t` 从 −1 / n−2 起步**
    （现象：n=1 时输出乱序或越界；原因：`std::size_t(0) − 2` 不报错而是
    回绕成 2⁶⁴−2，循环条件 i≥1 永远成立；后果：越界 UB；对策：下标
    变量用有符号 `int`，n 奇取 n−2、n=1 自然得 −1 整段跳过。）
13. **「放首部」按字面写成 push_front**
    （现象：前段名字整体倒序（输出成 Jean、Bo…）；原因：后处理的对要
    排在已放前部元素的**后面**，奇数个名字时峰顶位置也随之错位；对策：
    偶数下标按升序向输出末尾追加，奇数下标降序追加——先写下标模式
    `0,2,4,…,…,5,3,1` 再写代码。）
