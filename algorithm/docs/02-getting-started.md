# 02 · 入门：插入排序、循环不变式与归并排序

> 对应 CLRS 第 2 章 *Getting Started*（英文 3rd ed. pp.16–39）。这一章用一个
> 真正的算法（插入排序）把三件事一次讲全：**怎么证明它对**（循环不变式）、
> **怎么分析它快不快**（最好/最坏/平均）、**怎么设计更好的**（分治与归并）。
> 这三个模板会贯穿全书 35 章。

## 学习目标

1. 会写插入排序，并能说出它每一步在维护什么性质；
2. 能完整陈述并证明一个循环不变式（初始化/保持/终止三段论）；
3. 能推导插入排序三种情形的比较次数：n−1、n(n−1)/2、约 n²/4；
4. 理解归并排序的分治结构，会手推 MERGE 的比较上界「左长+右长−1」；
5. 会用递归树直觉解 T(n) = 2T(n/2) + Θ(n) = Θ(n·lg n)；
6. 掌握 `std::span` 作为数组视图的正确用法（0 基下标、无符号边界）。

## 动机：排序问题

**输入**：n 个数的一个序列 ⟨a₁, a₂, …, aₙ⟩。
**输出**：输入序列的一个排列 ⟨a′₁, a′₂, …, a′ₙ⟩，满足 a′₁ ≤ a′₂ ≤ … ≤ a′ₙ。

排序是算法课的「果蝇」：问题定义人人秒懂，解法的优劣差异却极其丰富——比较型、
分布型、增量式、分治式、随机化……第 6–9 章会把它做成一条完整的技术路线。CLRS
选择从插入排序开始，因为它就是你打扑克牌整手牌的动作。

## 插入排序

### 直觉

手里拿着一堆已排好的牌，摸一张新牌，从右往左找到合适的位置插进去。每一时刻，
「手里的牌是有序的」这个事实从不被破坏——这句话写成精确的数学陈述，就是下面
的循环不变式，也是本章的主角。

### 伪代码与 C++23 实现

CLRS 的 INSERTION-SORT（1 基下标）：

```clrs
INSERTION-SORT(A)
1  for j = 2 to A.length
2      key = A[j]
3      // 把 A[j] 插入已排序序列 A[1..j-1]
4      i = j - 1
5      while i > 0 and A[i] > key
6          A[i+1] = A[i]
7          i = i - 1
8      A[i+1] = key
```

C++23 版（0 基下标，`std::span<int>` 视图传参——不拷贝、不涉及所有权）：

```cpp
static void insertion_sort(std::span<int> a, Counters& c) {
    for (std::size_t j = 1; j < a.size(); ++j) {
        int key = a[j];                    // 待插入元素
        std::size_t i = j;                 // 从有序前缀的尾部往左找位置
        while (i > 0 && (++c.compares, a[i - 1] > key)) {
            a[i] = a[i - 1];               // 右移一格
            ++c.shifts;
            --i;
        }
        a[i] = key;                        // 插入
    }
}
```

与伪代码的三处刻意差异：

1. **移位而非交换**：CLRS 第 6 行把元素右移一格（A[i+1]=A[i]），而不是 swap——
   一次移位是一次赋值，交换是三次。手写版常见的错误是写成 swap，慢三倍还看不出
   为什么。示例同时统计了移位次数。
2. **计数器的位置**：`(++c.compares, a[i-1] > key)` 必须放在 `&&` 的**右侧**。
   写成 `(a[i-1] > key && ++c.compares)` 会因为短路（i==0 时直接假）而漏计；
   顺序反了则先计数后比较，计数总是准确的。这个细节见坑位清单第 3 条。
3. **`i > 0` 前置**：`std::size_t` 无符号，`i` 减到 0 再减会回绕成天文数字。
   把边界检查放在下标访问之前是 span 时代的肌肉记忆（坑位第 1 条）。

## 循环不变式：怎么证明插入排序是对的

**不变式陈述**：第 4 行 `i` 赋值之前（即每轮 for 迭代开始、key 已取出时），
子数组 A[1..j−1] 由原来 A[1..j−1] 中的元素构成，且**已按序排列**。

证明分三段，一段都不能少（CLRS p.19）：

1. **初始化**：j=2 时 A[1..j−1] = A[1..1] 只有一个元素，平凡地有序，且就是
   原来的那一个元素。不变式成立。
2. **保持**：设某轮开始时不变式成立（A[1..j−1] 有序）。循环体把 A[1..j−1] 中
   严格大于 key 的元素各右移一格，停下位置 i 满足 A[i] ≤ key < A[i+1]（这里
   A[i] 指 key 腾出位置后的左侧邻居）。把 key 放进 A[i+1] 后，A[1..j] 有序，
   且元素集合与原 A[1..j] 相同——下一轮的 j 已经递增，不变式对新的 j 成立。
3. **终止**：for 循环终止时 j = n+1 > n。把 j = n+1 代入不变式：A[1..n] 由原
   数组的全部 n 个元素按序组成——**这正是排序的定义**。证毕。

三段论的力量在于第 3 段：不变式本身只谈循环中间态，把它「推到循环出口」就
恰好得到我们要的结论。写不出第 3 段的不变式（即终止时陈述不到目标性质），
说明陈述选错了。

示例 02.2 把三段论做成了可执行抽样：每趟开始前断言
`is_sorted(A[0..j))` 且 `is_permutation(A[0..j), 原 A[0..j) 排序后的样子)`——
不变式的两个要件（有序 + 同一集合）各占一条 assert。断言过不了，不变式陈述
或实现必有错。

## 分析：最好、最坏与平均

CLRS 的分析在**随机访问机（RAM）模型**上进行：一条指令一步、整数运算与
下标访问都是单位代价。本教程统一用**比较次数**当代价（决定性：同一输入三台
编译器得到同一数字；见 docs/01 的纪律）。

- **最好情形（已序输入）**：每趟 while 只比较一次就退出，共 n−1 次。
  示例实测 n=16 → 15 = n−1。
- **最坏情形（逆序输入）**：第 j 趟要与前缀全部 j−1 个元素比较，共
  1+2+…+(n−1) = n(n−1)/2 次。示例实测 n=16 → 120 = 16·15/2。移位次数同为
  n(n−1)/2（每次比较成功都伴随一次移位）。
- **平均情形**：固定种子的随机排列上，期望比较约 n²/4——直觉是「key 平均
  要穿过半个前缀」。严格推导靠**逆序对**计数（一个排列的平均逆序数是
  n(n−1)/4，插入排序的比较次数与逆序数同阶），CLRS 第 8 章练习 8.1 会回收
  这条线。示例 n=16 随机排列实测 57，落在 n²/4 = 64 附近。

三行实测（示例 02.3）：

```
n=16：最好(已序)比较 15（理论 n-1=15）
n=16：最坏(逆序)比较 120（理论 n(n-1)/2=120）
n=16：随机排列比较 57（理论期望 ~n^2/4=64）
```

顺带一个设计策略的观察：插入排序是**增量法**——已解决一个子问题（前缀有序），
扩展一步（多放一个元素），保持子问题的解仍成立。第 17 章贪心算法是增量法的
另一种形态；而下面要出场的**分治法**则是先把问题切成互不相干的小块，分别
解决后再拼起来。

## 归并排序：分治登场

分治三步曲（CLRS §2.3.1）：

- **分解**：把 n 个元素切成含 n/2 个元素的两半；
- **解决**：递归地对两半排序；
- **合并**：合并两个有序序列（关键操作 MERGE，Θ(n)）。

### MERGE：哨兵版与边界版

CLRS 的 MERGE（p.31）把两个子数组各复制一份，**尾部放一个 ∞ 哨兵**，然后
每次取两边较小者——循环条件里就永远不用检查「哪边先用完」（∞ 不会先被取走）：

```clrs
MERGE(A, p, q, r)        // A[p..q] 与 A[q+1..r] 各自有序
1  n1 = q - p + 1,  n2 = r - q
2  let L[1..n1+1] 和 R[1..n2+2] 为新数组
3  把 A[p..q] 拷入 L，A[q+1..r] 拷入 R
4  L[n1+1] = ∞,  R[n2+1] = ∞     // 哨兵
5  i = 1,  j = 1
6  for k = p to r
7      if L[i] ≤ R[j]
8          A[k] = L[i],  i = i + 1
9      else A[k] = R[j],  j = j + 1
```

哨兵技巧漂亮但有前提：**元素类型得有「∞」可用**。对 int 可以用 INT_MAX，
对一般的 `std::weakly_ordered` 类型就没有了。C++ 版本更自然的是**下标边界**：
两个 while 收尾把剩余元素直接搬过去：

```cpp
while (i < mid && j < a.size()) {            // 两边都非空：比较后取小
    if (++c.compares, buf[i] <= buf[j]) {    // ≤：相等取左 → 稳定性
        a[k++] = buf[i++];
    } else {
        a[k++] = buf[j++];
    }
}
while (i < mid)      { a[k++] = buf[i++]; }  // 左边有剩：直接搬
while (j < a.size()) { a[k++] = buf[j++]; }  // 右边有剩：直接搬
```

两个版本的比较次数**完全相同**：比较只发生在两边都非空时，每比较一次恰好
归并一个元素，所以单次 MERGE 至多 `左长 + 右长 − 1` 次比较。对 CLRS 图 2.3
的 ⟨2,4,5,7⟩ ⊕ ⟨1,2,3,6⟩ 实测（示例 02.4）：

```
  取右 1（比较 #1）
  取左 2（比较 #2）
  取右 2（比较 #3）
  取右 3（比较 #4）
  取左 4（比较 #5）
  取左 5（比较 #6）
  取右 6（比较 #7）
MERGE 结果[1 2 2 3 4 5 6 7]
单次 MERGE 比较实测 7（理论 ≤ 左+右-1 = 4+4-1 = 7）
```

第 2 行的「取左 2」值得注意：两边相等时**取左边**（`≤`）。这个选择保证了
归并排序是**稳定排序**——相等元素的相对次序不变。稳定性有什么用？第 8 章
基数排序的整座大厦就建在「底层排序必须稳定」之上。

### 递归式与递归树

归并排序的运行时间满足 T(n) = 2T(n/2) + Θ(n)（两个一半规模的子问题 + 一次
线性合并）。递归树直觉（示例 02.5 打印 n=8 的树）：

```
                [整棵 n=8]  本层合并代价 c·8
              /            \
        [n=4]            [n=4]      每层两半，共 c·8
       /      \          /      \
    [n=2]  [n=2]   [n=2]  [n=2]   共 c·8
    叶子 8 个（n=1，不再合并）
```

树高 lg n（每层规模减半），每层合并总代价 cn（每层元素总数就是 n），共
**cn·lg n** → T(n) = Θ(n·lg n)。第 4 章会把「递归树」升级成三种系统方法之一
（代入法/递归树法/主定理），现在只要这幅图在脑子里。

对 n=8 的 CLRS 图 2.4 数组 ⟨5,2,4,7,1,3,2,6⟩，本实现实测 17 次比较，上界
n·lg n = 24——注意 17 < 24：上界是「最坏情形每比较都归并」的粗界，具体输入
下有子问题提前用完的节省。第 4 章练习会让你算精确的最坏比较次数
（恰好是 n·lg n − 2^lg n + 1 = n·lg n − n + 1 = 17）。

回到第 1 章的问题：同机同 n=2048 逆序输入，插入排序 2,096,128 次 vs 归并
11,264 次——**186 倍**。Θ(n²) 与 Θ(n lg n) 的差距在任何硬件上都追不回来。

## C++23 语言点：std::span

`std::span<int>`（C++20 起，本教程全程使用）是「连续元素的一段视图」：

- **零拷贝**：传参只带 (指针, 长度)，不搬数据——递归归并的
  `a.first(mid)` / `a.subspan(mid)` 就是 O(1) 地切一刀；
- **只读视图**用 `std::span<const int>`（本例 `print_span` 的参数）；
- **陷阱**：`size()` 返回无符号 `std::size_t`，`i - 1` 在 i=0 时回绕（见坑位）；
  与 `ptrdiff_t` 混算要显式 `static_cast`。

## 与 STL 对照

| 需求 | 标准库 | 底层 |
|---|---|---|
| 通用排序 | `std::ranges::sort` | introsort（快排+堆排+插入混合，Θ(n lg n)，不稳定） |
| 稳定排序 | `std::ranges::stable_sort` | 归并排序（本章），Θ(n lg n)，稳定 |
| 两段已序拼接 | `std::ranges::inplace_merge` | 本章 MERGE 的原地版 |
| 有序结构维护 | `std::map`（第 12–13 章红黑树） | — |

工程结论：**永远先用 `std::ranges::sort`**。手写插入排序的价值在两处——小数组
上它真的快（introsort 的递归底部就是切到插入排序，通常阈值 16–32），以及它是
理解循环不变式的最短教具。

## 坑位清单

1. **`std::size_t` 下溢成天文数字**
   （现象：while 里 `a[i-1]` 在 i==0 时读到数组外，或 `i` 回绕成 2⁶⁴−1 死循环；
   原因：`std::span::size()` 与下标习惯用无符号数，`0−1` 不报错而是回绕；
   后果：越界 UB 或挂死；对策：边界检查前置——`while (i > 0 && …)`，
   且检查必须放在下标表达式的左边靠 `&&` 短路保护。）
2. **输出 helper 与标签各管一半括号**
   （现象：示例第一版打出 `初始数组 [[5 2 4…`——标签带了 `[`，helper 又补一个；
   原因：职责重叠；后果：纯外观瑕疵但破坏文档对账的整洁；对策：约定标签只写
   文案与冒号，`[` `]` 一律由 `print_span` 独家负责，改一处全局生效——本例
   实测修了三遍才收敛，写进坑位。）
3. **比较计数被短路求值吞掉**
   （现象：统计出的比较次数比理论少，随机输入下忽对忽错；原因：把
   `++c.compares` 放在 `&&` 左侧时它总会执行，但放在比较表达式**内部**且 i==0
   可短路时，`A && ++c` 形态会漏计；后果：分析实验的数字失去可信度；
   对策：统一写成 `while (i > 0 && (++c.compares, a[i-1] > key))`——计数永远
   先于比较发生，且不受短路影响。）
4. **哨兵 MERGE 搬进泛型代码**
   （现象：元素类型是 string/自定义类型时没有「∞」可用，写死 `INT_MAX` 对
   int 恰好、对 double 错（有 NaN/精度）；原因：哨兵技巧依赖类型有全序最大元；
   后果：泛型排序出静默错误；对策：用下标边界版收尾 while，或 CLRS 练习
   2.3-2 正是让你写无哨兵版。）
5. **交换版「插入排序」慢三倍**
   （现象：实现写成 `std::swap(a[i], a[i-1])` 逐对交换；原因：一次移位是一
   次赋值，交换是三次；后果：常数变大，教学上还掩盖了「key 先取出、最后落位」
   的结构；对策：先存 key，移位腾位，最后 `a[i] = key`。）
