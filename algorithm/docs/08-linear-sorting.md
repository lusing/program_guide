# 08 · 线性时间排序

> 对应 CLRS 第 8 章 *Sorting in Linear Time*（英文 3rd ed. pp.191–212）。
> 第 2–7 章的排序全部基于「比较」——本章先证明比较模型的**下界** Θ(n lg n)，
> 然后换模型（数数、按键分桶）做出真正的线性排序。稳定性的角色也从「性质」
> 升级为「公理」：基数排序整座大厦建在它上面。

## 学习目标

1. 能用决策树模型证明比较排序的下界 ⌈lg n!⌉ = Ω(n lg n)；
2. 能手推计数排序的稳定性（倒序分配），并说清它为什么不受下界约束；
3. 能解释基数排序「低位优先 + 每趟必须稳定」的正确性；
4. 能陈述桶排序的均匀输入假设与期望 O(n) 分析；
5. 会判断一个具体排序任务该选哪条技术路线（比较/计数/基数/桶）。

## 决策树下界（§8.1）

比较排序的执行过程可以画成一棵**二叉决策树**：每个内节点是一次比较
（aᵢ ≤ aⱼ?），两个分支是答案，每个叶是一种输入排列对应的输出。正确性
要求 n! 种排列各有一个叶——于是

树高 ≥ ⌈lg n!⌉ = n lg n − 1.4427n + Θ(lg n)（斯特林）。

最坏路径长度 ≥ 树高，所以**任何**比较排序最坏要 Ω(n lg n) 次比较。示例
08.1 的对账表（归并最坏 = n·lg n − n + 1，n 为 2 的幂时的精确值）：

```
n= 4：⌈lg n!⌉=5，归并最坏=5，插入最坏=6
n= 8：⌈lg n!⌉=16，归并最坏=17，插入最坏=28
n=16：⌈lg n!⌉=45，归并最坏=49，插入最坏=120
```

n=8 时归并（17）离绝对下界（16）只差 1 次比较——归并排序在比较模型里
几乎榨干了；插入排序（28）还远。`⌈lg m⌉ = bit_width(m−1)` 用整数运算
精确拿到（第 3 章的恒等式在这里干活）。

## 计数排序（§8.2）

**前提**：键是不超过 k 的小非负整数。算法三步（图 8.2 数据 ⟨2,5,3,0,2,3,0,3⟩）：

1. **数个数**：C[x] = 键为 x 的元素数；
2. **前缀和**：C[x] 变成「≤ x 的元素数」；
3. **倒序落位**：从右往左扫描输入，`out[--C[a[i].key]] = a[i]`。

```cpp
for (std::size_t i = a.size(); i-- > 0;) {   // 倒序 → 稳定
    out[--c[a[i].key]] = a[i];
}
```

**稳定性证明级断言**（示例 08.2）：给每个元素带上下标 id，排序后同键的
id 严格保序。机制就在「倒序」两个字：C[x] 从右往左递减，同键元素里
**后见者先落位**（更靠右的输出格）——正序扫描会把稳定性翻过来丢掉。

**为什么它能线性**：全程 **0 次比较**（示例实测打印「比较次数 = 0」）。
下界 Ω(n lg n) 只约束比较模型；计数排序用「按键直接寻址」绕开了比较，
时间 Θ(n + k)——当 k = O(n) 时就是 Θ(n)。

## 基数排序（§8.3）

扑克牌机的老算法：d 位数按 **低位优先**（LSD）做 d 趟稳定排序（每趟
计数排序，基数 r）。正确性论证（归纳于趟数）：第 t 趟结束后，所有元素按
**低 t 位**有序——第 t+1 趟按第 t+1 位稳定排序时，同位者保持低 t 位
的相对次序。**每趟必须稳定**，否则前功尽弃。

CLRS 图 8.3 数据的三趟追踪（示例 08.3 的输出）：

```
输入:       329 457 657 839 436 720 355
按 个 位排序: 720 355 436 457 657 329 839
按 十 位排序: 720 329 436 839 355 457 657
按 百 位排序: 329 355 436 457 657 720 839
```

注意第二趟后（720 排最前）看起来「更乱了」——它是正确的：按低两位有序。
复杂度 Θ(d(n + r))；把 b 位二进制数按 r = b/d 位分趟，总时间
Θ((b/r)(n + r))，取 r = lg n 得 Θ(b·n/lg n)——当 b = O(lg n)（常规整数）
时就是**线性**。

## 桶排序（§8.4）

**前提**：输入均匀分布于 [0, 1)。n 个桶，`bucket[⌊n·x⌋]` 收纳 x，桶内
插入排序，顺序拼接。图 8.4 数据实测（示例 08.4）：

```
桶 1: 0.12 0.17
桶 2: 0.21 0.23 0.26
桶 3: 0.39
桶 6: 0.68
桶 7: 0.72 0.78
桶 9: 0.94
```

**期望分析**：均匀输入下第 i 个桶的元素数 nᵢ 是二项 B(n, 1/n)，
E[nᵢ²] = 2 − 1/n（练习 8.4-2），桶内插入期望 O(nᵢ²)，总期望
Θ(n) + Θ(n·E[nᵢ²]) = Θ(n)。**均匀假设是命门**：输入扎堆时桶退化为
一个大桶（练习 8.4-1 的反例），最坏 Θ(n²)。

## 技术路线选择表

| 条件 | 选择 | 复杂度 |
|---|---|---|
| 通用对象、任意比较器 | `std::ranges::sort`（introsort） | Θ(n lg n) 最坏 |
| 要求稳定 | `std::ranges::stable_sort`（归并） | Θ(n lg n) |
| 小整数键（k = O(n)） | 计数排序 | Θ(n + k) |
| 定长数字键 / 多字段 | 基数排序（LSD + 每趟稳定） | Θ(d(n+r)) |
| 已知分布均匀的浮点 | 桶排序 | 期望 Θ(n) |

示例 08.5 的总账：n=10000、键域 0..99，计数排序 20099 次操作（≈ 2n+k）
排序完成，与 `std::sort` 结果逐元素一致。

## C++23 语言点

- **稳定性断言的模式**：`(key, id)` 成对排序后检查同键 id 保序——任何
  稳定排序（含 `stable_sort`）都能用这把尺子验货；
- `⌈lg m⌉ = std::bit_width(m − 1)`（m ≥ 1）：整数对数上取整的标准姿势；
- 桶排序的 `vector<vector<double>>` 是「桶数组」的直接翻译；工程上可换
  成单层数组 + 边界索引（省一次分配）。

## 坑位清单

1. **计数排序的落位循环写成正序**
   （现象：排序结果正确但稳定性消失——同键 id 逆序出现；原因：C[x] 的
   游标从右往左走，正序扫描时同键元素中**先见者**拿了更右的格子；后果：
   基数排序用它做子程序时整体翻车（第 2 趟就把第 1 趟的成果洗掉）；
   对策：`for (i = n; i-- > 0;)` 倒序，配 (key,id) 稳定性断言。）
2. **基数排序某一趟用了不稳定排序**
   （现象：某些输入对、某些输入错——最难查的一类 bug；原因：LSD 的正确性
   证明要求每趟稳定，换 `std::sort` 做一趟就破坏归纳前提；后果：间歇性
   错序，随机测试都未必命中；对策：每趟固定用计数排序或 `stable_sort`，
   并把「每趟后低 t 位有序」写成断言。）
3. **桶排序用在非均匀输入上**
   （现象：数据扎堆一个桶，性能塌回 Θ(n²)；原因：期望分析的前提是
   均匀分布——E[nᵢ²] = 2 − 1/n 依赖它；后果：生产上把「平均快」当
   「保证快」；对策：先验采样确认分布，或改基数排序（整数键时它没有
   分布假设）。）
4. **把「0 次比较」误当「0 代价」**
   （现象：n 大 k 也大（如 k = n²）时计数排序比快排还慢；原因：Θ(n + k)
   的 k 项在键域稀疏时主导；后果：选型错误；对策：键域大先压回
   「比较模型」（n lg n）或改基数分趟，k = O(n) 才值得计数。）
5. **稳定性断言只查相邻对，漏了全局**
   （现象：手写断言 `out[i-1].key==out[i].key` 的两三个 case 通过，以为
   稳了；原因：稳定性是全体同键元素的**全序保持**，抽查不等于证明；
   后果：假信心；对策：对每个键值收集 id 序列，断言严格递增——示例的
   写法。）

## 练习

1. （CLRS 练习 8.1-1）比较排序最好情形的下界是多少？（n−1：至少要
   确认每个元素都不是最小……准确答案见习题册。）
2. （CLRS 练习 8.1-3）证明：不可能存在「多数排列都只花 O(n) 比较」的
   排序（2^{O(n)} 个叶覆盖不了 n!/2 个排列）。
3. （CLRS 练习 8.2-3）COUNTING-SORT 改成正序扫描还稳定吗？（本例坑位 1
   的答案：不稳定。）
4. （CLRS 练习 8.2-4）给定 n 个数与区间 [a,b]，O(n + k) 数出落在区间内
   的元素个数（计数数组前缀和一行的事）。
5. （CLRS 练习 8.3-2）插入/归并/堆排/快排哪些稳定？不稳定者怎么改稳定
   （代价多少）？（附键法：比较 (key, index)，多 O(n) 空间。）
6. （CLRS 练习 8.3-4）n 个 [0, n³−1] 的整数，O(n) 排序（按 n 进制三位
   基数——为什么基数是 n？）。
7. （CLRS 练习 8.4-1/8.4-2）桶排序在 ⟨.79,.13,.16,.64,.39,.20,.89,.53,.71,.42⟩
   上的桶分布；证明 E[nᵢ²] = 2 − 1/n。
8. （本教程）把示例的稳定性断言推广成 `assert_stable(in, out)` 通用
   函数（按 key 分桶收集 id 序列），跑 1000 个固定随机用例。
