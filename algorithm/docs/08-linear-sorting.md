# 08 · 线性时间排序

> 对应 CLRS 第 8 章 *Sorting in Linear Time*（英文 3rd ed. pp.191–212）。
> 第 2–7 章的排序全部基于「比较」——本章先证明比较模型的**下界** Θ(n lg n)，
> 然后换模型（数数、按键分桶）做出真正的线性排序。稳定性的角色也从「性质」
> 升级为「公理」：基数排序整座大厦建在它上面。

## 学习目标

1. 能用决策树模型证明比较排序的下界 ⌈lg n!⌉ = Ω(n lg n)；
2. 能手推计数排序的稳定性（倒序分配），并说清它为什么不受下界约束；
3. 能解释基数排序「低位优先 + 每趟必须稳定」的正确性；
4. 能陈述桶排序的均匀输入假设与期望 O(n) 分析；
5. 会判断一个具体排序任务该选哪条技术路线（比较/计数/基数/桶）；
6. 能用「前缀计数Θ(n)」与「归并计数 Θ(n lg n)」两种方法求逆序对，
   说清「值域小用计数、值域任意用归并」这个选择判据，并写出「每个逆序对
   恰在处理其右端点时计一次」的不变式。

## 决策树下界（§8.1）

比较排序的执行过程可以画成一棵**二叉决策树**：每个内节点是一次比较
（aᵢ ≤ aⱼ?），两个分支是答案，每个叶是一种输入排列对应的输出。正确性
要求 n! 种排列各有一个叶——于是

树高 ≥ ⌈lg n!⌉ = n lg n − 1.4427n + Θ(lg n)（斯特林）。

最坏路径长度 ≥ 树高，所以**任何**比较排序最坏要 Ω(n lg n) 次比较。示例
08.1 的对账表（归并最坏 = n·lg n − n + 1，n 为 2 的幂时的精确值）：

```
n= 4：⌈lg n!⌉=5，归并最坏=5，插入最坏=6
n= 8：⌈lg n!⌉=16，归并最坏=17，插入最坏=28
n=16：⌈lg n!⌉=45，归并最坏=49，插入最坏=120
```

n=8 时归并（17）离绝对下界（16）只差 1 次比较——归并排序在比较模型里
几乎榨干了；插入排序（28）还远。`⌈lg m⌉ = bit_width(m−1)` 用整数运算
精确拿到（第 3 章的恒等式在这里干活）。

## 计数排序（§8.2）

**前提**：键是不超过 k 的小非负整数。算法三步（图 8.2 数据 ⟨2,5,3,0,2,3,0,3⟩）：

1. **数个数**：C[x] = 键为 x 的元素数；
2. **前缀和**：C[x] 变成「≤ x 的元素数」；
3. **倒序落位**：从右往左扫描输入，`out[--C[a[i].key]] = a[i]`。

```cpp
for (std::size_t i = a.size(); i-- > 0;) {   // 倒序 → 稳定
    out[--c[a[i].key]] = a[i];
}
```

**稳定性证明级断言**（示例 08.2）：给每个元素带上下标 id，排序后同键的
id 严格保序。机制就在「倒序」两个字：C[x] 从右往左递减，同键元素里
**后见者先落位**（更靠右的输出格）——正序扫描会把稳定性翻过来丢掉。

**为什么它能线性**：全程 **0 次比较**（示例实测打印「比较次数 = 0」）。
下界 Ω(n lg n) 只约束比较模型；计数排序用「按键直接寻址」绕开了比较，
时间 Θ(n + k)——当 k = O(n) 时就是 Θ(n)。

## 基数排序（§8.3）

扑克牌机的老算法：d 位数按 **低位优先**（LSD）做 d 趟稳定排序（每趟
计数排序，基数 r）。正确性论证（归纳于趟数）：第 t 趟结束后，所有元素按
**低 t 位**有序——第 t+1 趟按第 t+1 位稳定排序时，同位者保持低 t 位
的相对次序。**每趟必须稳定**，否则前功尽弃。

CLRS 图 8.3 数据的三趟追踪（示例 08.3 的输出）：

```
输入:       329 457 657 839 436 720 355
按 个 位排序: 720 355 436 457 657 329 839
按 十 位排序: 720 329 436 839 355 457 657
按 百 位排序: 329 355 436 457 657 720 839
```

注意第二趟后（720 排最前）看起来「更乱了」——它是正确的：按低两位有序。
复杂度 Θ(d(n + r))；把 b 位二进制数按 r = b/d 位分趟，总时间
Θ((b/r)(n + r))，取 r = lg n 得 Θ(b·n/lg n)——当 b = O(lg n)（常规整数）
时就是**线性**。

## 桶排序（§8.4）

**前提**：输入均匀分布于 [0, 1)。n 个桶，`bucket[⌊n·x⌋]` 收纳 x，桶内
插入排序，顺序拼接。图 8.4 数据实测（示例 08.4）：

```
桶 1: 0.12 0.17
桶 2: 0.21 0.23 0.26
桶 3: 0.39
桶 6: 0.68
桶 7: 0.72 0.78
桶 9: 0.94
```

**期望分析**：均匀输入下第 i 个桶的元素数 nᵢ 是二项 B(n, 1/n)，
E[nᵢ²] = 2 − 1/n（练习 8.4-2），桶内插入期望 O(nᵢ²)，总期望
Θ(n) + Θ(n·E[nᵢ²]) = Θ(n)。**均匀假设是命门**：输入扎堆时桶退化为
一个大桶（练习 8.4-1 的反例），最坏 Θ(n²)。

| 条件 | 选择 | 复杂度 |
|---|---|---|

| 要求稳定 | `std::ranges::stable_sort`（归并） | Θ(n lg n) |
| 小整数键（k = O(n)） | 计数排序 | Θ(n + k) |
| 定长数字键 / 多字段 | 基数排序（LSD + 每趟稳定） | Θ(d(n+r)) |

## 逆序对计数：值域小就用计数代替比较

前面四节都在讲「怎样把排序做快」。这一节反过来：**当排序的键本身携带
信息时，能否让排序顺便把某个统计量算出来**？逆序对是最典型的例子。

**问题**：m 个等长 DNA 串，按其**逆序数**升序排序。逆序数定义为

$$\mathrm{inv}(s)=\#\{(i,j): i<j \text{ 且 } s_i > s_j\}$$

它是「把s 排成升序所需**交换相邻元素**的最少次数」——排序问题里最常出现的
次序键（冒泡排序的趟数、CLRS 练习 2-1-1 的答案都是它）。

### 方法一：小字母表前缀计数 Θ(n)

朴素做法是双层循环数所有 (i,j) 对，Θ(n²)。但 DNA 只有 4 个字母——
**值域小就可以用计数代替比较**：不再问「s_i 和 s_j 谁大」，而是问
「我前面已经出现过多少个比我大的」。

维护三个计数器，**不变式是这一切的核心**：

> **c_X = 已扫描前缀 s[0..i-1] 中字母 X 的出现次数。**

处理 s[i] 时，新增的逆序对数 = 「前缀中比 s[i] 大的字母的个数之和」：

| s[i] | 新增逆序对 | 然后 |
|---|---|---|
| `A` | c_C + c_G + c_T | c_A++ |
| `C` | c_G + c_T | c_C++ |
| `G` | c_T | c_G++ |
| `T` | 0 | c_T++ |

```cpp
static long long inv_count_small_alpha(std::string_view s) {
    long long cA = 0, cC = 0, cG = 0, cT = 0;   // 已扫描前缀中各字母出现次数
    long long inv = 0;
    for (char ch : s) {
        switch (ch) {
        case 'A': inv += cC + cG + cT; ++cA; break;   // 比 A 大的都算
        case 'C': inv += cG + cT;       ++cC; break;   // 比 C 大的：G、T
        case 'G': inv += cT;             ++cG; break;   // 比 G 大的：T
        case 'T':                       ++cT; break;   // T 最大，前面没人比它大
        default: break;
        }
    }
    assert(cA + cC + cG + cT == static_cast<long long>(s.size()));
    return inv;
}
```

每个字符 O(1) ⟹ 每串 **Θ(n)**，全部 m 串 Θ(mn)。

**「只统计前缀」这层语义是全部难点**。c_X 里若混入了已扫过的当前位置，
就变成「全局计数」，每个字符会被重复计入，答案系统性偏大。写代码前先把
不变式写下来——这一条比算法本身重要。示例里 c_A 从不参与加法（没有比 A
更大的字母），但**必须保留它**：不变式说的是「前缀中**各**字母的计数」，
少一个字母这个语义就残缺了。示例用
`assert(cA+cC+cG+cT == s.size())` 把不变式钉死。

**正确性**只有一句话：$\mathrm{inv}(s)=\sum_i \#\{j<i: s_j>s_i\}$，按第 i 位
切分求和即得上述递推。每个逆序对 (i,j) **恰在处理其右端点 j 时被计一次**，
不重不漏。

### 推广：σ 字母表

把上面的三个 if 换成数组与后缀和，就是通用版：

1. **动态编号**：把串里**实际出现的**字符按**字符值升序**编号成 0..σ−1
   （不要硬编码 a=0,b=1——那是样例特例，通用实现必须自己编号）；
2. 维护 `ge[k]` = 前缀中「编号 ≥ k」的字符个数。处理编号 j 时，前缀中
   比它大的个数就是 `ge[j+1]`；插入 j 时对所有 k ≤ j 执行 `++ge[k]`
   （这就是后缀和的增量维护）。

每个位置 O(σ) ⟹ 总 **O(nσ)**。σ 较大但可枚举时（如整个字节范围 256），
把 `ge` 换成**树状数组**，查询与更新都是 O(lg σ) ⟹ **O(n lg σ)**。

三个复杂度档次的取舍：

| 值域 σ | 方法 | 复杂度 |
|---|---|---|
| 常数（4 字母 / 小整数键） | 前缀计数（几个寄存器变量） | **Θ(n)** |
| σ 可枚举、不大 | 计数数组 + 后缀和 | O(nσ) |
| σ 大 / 与值域无关 | 归并计数法（见下）/ 树状数组 | Θ(n lg n) / O(n lg σ) |

### 方法二：归并排序计数法 Θ(n lg n)

上面所有方法都**依赖值域小**。值域任意时用这招——它是**通用解**，
且与本章主题严丝合缝：把计数融进归并排序本身，**不额外开一趟**。

归并 `a[l..m)` 与 `a[m..r)` 时两半各自已升序。若 `a[i] > a[j]`（i 在左半、
j 在右半），则左半的 `a[i..m)` **全部** ≥ a[i] > a[j]——于是**一次性**
产生 m − i 个逆序对，累加后取 a[j]；否则取 a[i]：

```cpp
static long long merge_count(std::vector<int>& a, std::vector<int>& tmp,
                             std::size_t l, std::size_t r) {
    if (r - l <= 1) { return 0; }
    const std::size_t m = l + (r - l) / 2;
    long long inv = merge_count(a, tmp, l, m) + merge_count(a, tmp, m, r);
    std::size_t i = l, j = m, k = l;
    while (i < m && j < r) {
        if (a[i] <= a[j]) {
            tmp[k++] = a[i++];       // 相等时取左边：稳定，且不误计
        } else {
            inv += static_cast<long long>(m - i);   // 左半剩余全部与 a[j] 成逆序
            tmp[k++] = a[j++];
        }
    }
    while (i < m) { tmp[k++] = a[i++]; }
    while (j < r) { tmp[k++] = a[j++]; }
    for (std::size_t t = l; t < r; ++t) { a[t] = tmp[t]; }
    return inv;
}
```

正确性：逆序对要么**全在左半**（递归）、要么**全在右半**（递归）、要么
**跨半区**（归并时统计）——三类不重不漏。而跨半区的对被「m − i 一次
全算」正是利用了「两半已有序」这个归纳假设：一旦某次比较判定 a[i] > a[j]，
左半剩余元素全部 ≥ a[i]，无需再逐个比较。

递归式 T(n) = 2T(n/2) + Θ(n)（比较次数与 2.1.2 的归并排序同阶）⟹
**Θ(n lg n)**。

### 两法对照

```
三法对账（每个串的逆序数）：
  串       前缀计数Θ(n) 归并Θ(n lg n) 朴素Θ(n^2)
  ACGT              0            0          0
  GATC              3            3          3
  ACGT              0            0          0
  TGCA              6            6          6
  GGCC              4            4          4
  ATAT              1            1          1
  手算复核：GATC = 3（G>A、G>C、A>C、T>C；注意 G>T 不成立）
            ACGT = 0（升序）；TGCA = 6 = n(n-1)/2（完全降序的上界）
```

手算复核这一行值得单独看：GATC 的 4 个可能对里 G>T **不成立**（字母序
A<C<G<T），所以是 3 不是 4。**这类「少算一个」的错误靠读代码是查不出来的**
——示例对 6 个串 + 5 组随机串（长 40~79）做了三法对账，才把它钉住。

规模对照（n = 50，同一串）：

```
  规模对照（n = 50，同一串）：朴素 1225 次比较 / 归并 250 次比较 / 前缀计数 150 次加法
  ⟹ 值域为常数（4 个字母）时，计数法是三者中最省的，且是唯一的 Θ(n)
```

**选择的判据不是「哪个更快」而是「值域是否可枚举」**：

| | 前缀计数 Θ(n) | 归并计数 Θ(n lg n) |
|---|---|---|
| 前提 | 值域 σ 是常数（小字母表、小整数键） | **无前提**，与值域无关 |
| 空间 | O(σ)，常数级 | O(n)（归并的辅助数组） |
| 排序 | 需**额外**排一次（按 inv 排 m 个串） | 归并本身**就是**排序 |
| 常数 | 极小（几个寄存器变量 + 3 次加法） | 较大（指针搬运 + 递归） |
| 推广 | σ 大时退化到 O(nσ) 或 O(n lg σ) | 始终 Θ(n lg n) |

一句话：**小字母表用计数（换模型），通用场景用归并（顺带算）**。
两者并不互斥——示例对同一份数据同时跑了两者并断言相等。

排序时把 (inv, 串) 打包成 `std::pair` 一次 `std::ranges::sort` 即可
（Θ(m lg m)）；若 m 很大而 inv 值域小（inv ≤ n(n−1)/2），可以对 inv 做
计数排序降到 Θ(m + 值域)。

## 两个来自「趟数与代价」的问题：冒泡趟数与最小交换代价

排序的**度量本身**也可以成为问题：趟数、交换代价。这两个问题（整理自
《趣题学算法》第 1 章的问题 1-8 与 1-10，自包含）都把「排序过程」当成
组合对象来计数或求最优。

### 问题一：冒泡排序趟数的计数（T = max 左位移）

冒泡排序反复扫描、交换相邻逆序对，直到一整趟无交换。恰用 T 趟（各含
交换）排好的输入有多少种？第一步是把「趟数」翻译成统计量：

**一趟冒泡把每个向左移动的元素恰好左移一格**（它只与左邻交换一次）；
向右移动则一趟可滑很远。所以初始位置 i、最终位置 f(i) 的元素要左移
i − f(i) 格，就需要那么多趟各移一格。于是

**T = max_i (i − f(i))**（已序输入为 0）。

这个统计量可以穷举验证（示例 08.7 对 n ≤ 7 的全部 5913 个排列逐个对账：
逐趟模拟 = 位移统计量）。n=4 的趟数分布：

```
  n=4 趟数分布：T=0:1 T=1:7 T=2:10 T=3:6 （合计 24 = 4!）
  n=4：count(T=1) 真值 7，书式 n(n-1)/2 = 6 —— 书式漏计
  count(T=1) = 2^(n-1) − 1（n=3..6 全验）：恰一个元素左移一格 ⟹
  在 n-1 个「相邻对换与否」的二选一中排除全不换的那一种。
```

注意 n=3 时 count(T=1) = 3 = 1+2 恰好与「1+2+…+(n−1)」的直观求和一致——
**但那是巧合**：n=4 真值是 7 不是 6，n=5 是 15 不是 10。正确公式
count(T=1) = 2^(n−1) − 1 的组合直觉：「恰一个元素左移一格」的排列中，
每个相邻位置对独立地决定「是否对换」，排除全不换的一种。「小 n 验证通过」
不等于公式正确——这正是本教程坚持机器对账的原因。

### 问题二：最小交换代价排序（置换轮换分解）

按升序重排，每次可交换**任意**两个元素、代价 = 两元素值之和，求最小总
代价。任意交换 ⟹ 交换图按**置换轮换**分解，各轮换独立计代价（轮换分解
的系统讲述见第 23 章）。含 k ≥ 2 个元素的轮换、元素和 s、轮换内最小值 t、
全局最小值 a，两条路：

- **方法一**（只用轮换内元素，t 当搬运工）：代价 s + (k−2)·t；
- **方法二**（借全局最小 a）：a 与 t 交换进来（a+t），以 a 为搬运工转一圈
  （s − t + a + (k−2)·a），全程结束 a 恰好归位——合计 **s + t + (k+1)·a**。

每轮换取二者较小。原书把方法二写成 s + (k+1)a、**漏了 +t**——其自带的两
个算例都恰好 t = a，试不出错。反例：

```
  [1,102,100,103,101] → 511（4-轮换 {102,100,103,101}：s=406, t=100, a=1：min{606, 511} = 511）
随机 200 组小数据（n=3..5）Dijkstra 最优对账：轮换公式全一致 = 1
原书公式（方法二漏 +t）在这 200 组里给出错值的组数 = 4
```

511 = 406 + 100 + 5·1 怎么来的：a=1 换进来（101），转一圈把四个元素送回
（各一次交换含 a），a 停在 t 的原位——此时整轮换已序，**不需要**换出。
漏掉 +t 的 411 是任何交换序列都达不到的数（示例用「排列为节点、交换为
带权边」的 Dijkstra 暴力验证了 200 组小数据的最优值）。

### 两题的公共骨架

| | 冒泡趟数 | 最小交换代价 |
|---|---|---|
| 度量对象 | 过程的**步数** | 过程的**代价** |
| 关键翻译 | 趟数 → max 左位移 | 交换图 → 轮换分解 |
| 验证手段 | 全排列穷举（n ≤ 7） | Dijkstra 暴力最优（n ≤ 5） |
| 复杂度 | 计数本身 Θ(n·n!)（枚举）/ 判定 Θ(n²) | Θ(n) （排序 + 分解） |

## C++23 语言点

- **稳定性断言的模式**：`(key, id)` 成对排序后检查同键 id 保序——任何
  稳定排序（含 `stable_sort`）都能用这把尺子验货；
- `⌈lg m⌉ = std::bit_width(m − 1)`（m ≥ 1）：整数对数上取整的标准姿势；
- 桶排序的 `vector<vector<double>>` 是「桶数组」的直接翻译；工程上可换
  成单层数组 + 边界索引（省一次分配）。

## 坑位清单

1. **计数排序的落位循环写成正序**
   （现象：排序结果正确但稳定性消失——同键 id 逆序出现；原因：C[x] 的
   游标从右往左走，正序扫描时同键元素中**先见者**拿了更右的格子；后果：
   基数排序用它做子程序时整体翻车（第 2 趟就把第 1 趟的成果洗掉）；
   对策：`for (i = n; i-- > 0;)` 倒序，配 (key,id) 稳定性断言。）
2. **基数排序某一趟用了不稳定排序**
   （现象：某些输入对、某些输入错——最难查的一类 bug；原因：LSD 的正确性
   证明要求每趟稳定，换 `std::sort` 做一趟就破坏归纳前提；后果：间歇性
   错序，随机测试都未必命中；对策：每趟固定用计数排序或 `stable_sort`，
   并把「每趟后低 t 位有序」写成断言。）
3. **桶排序用在非均匀输入上**
   （现象：数据扎堆一个桶，性能塌回 Θ(n²)；原因：期望分析的前提是
   均匀分布——E[nᵢ²] = 2 − 1/n 依赖它；后果：生产上把「平均快」当
   「保证快」；对策：先验采样确认分布，或改基数排序（整数键时它没有
   分布假设）。）
4. **把「0 次比较」误当「0 代价」**
   （现象：n 大 k 也大（如 k = n²）时计数排序比快排还慢；原因：Θ(n + k)
   的 k 项在键域稀疏时主导；后果：选型错误；对策：键域大先压回
   「比较模型」（n lg n）或改基数分趟，k = O(n) 才值得计数。）
5. **稳定性断言只查相邻对，漏了全局**
   （现象：手写断言 `out[i-1].key==out[i].key` 的两三个 case 通过，以为
   稳了；原因：稳定性是全体同键元素的**全序保持**，抽查不等于证明；
   后果：假信心；对策：对每个键值收集 id 序列，断言严格递增——示例的
   写法。）
6. **逆序对计数把「前缀计数」写成「全局计数」**
   （现象：小规模用例全对，长串上答案系统性偏大；原因：不变式是
   「c_X = **已扫描前缀**中 X 的次数」，若在`++c_X` 之后又用它参与加法，
   或把计数累加到全局变量里，就重复计入了每个字符自己；后果：inv偏大，
   排序结果整体错乱但「看起来有序」；对策：**先写不变式再写代码**，并
   用 `assert(cA+cC+cG+cT == s.size())` 把不变式钉死；三个字母里
   那个从不参与加法的也必须保留。）
7. **错误直觉：动态编号可以按「首次出现顺序」**
   （现象：通用版（计数数组 + 后缀和）在随机串上与前缀计数法不一致，
   assert 齐炸；原因：按**首次出现顺序**编号把大小关系全弄反了——
   "GATC" 会编成 G=0, A=1, T=2, C=3，于是 `G>T` 被判成成立，逆序数
   从 3 变成 4；后果：静默算错，且样例串往往太短看不出来；对策：编号
   必须**按字符值升序**做。「动态」要动态的是「**用哪几个字符**」，
   不是编号顺序。本示例实测翻车此坑。）
8. **错误直觉：前缀计数法可以推广到任意值域**
   （现象：把三个字母的版本推广成「计数数组 + 循环找更大元素」，在
   σ = 256 的字节串上跑出 O(n·256) 甚至更慢；原因：每个位置付了O(σ)
   的代价，总复杂度是 O(nσ)，σ 大时**比归并的 Θ(n lg n) 还差**；
   后果：以为「推广了就是通用解」，实际是退化；对策：σ 可枚举但不小
   时改用**树状数组**（O(n lg σ)），σ 任意时用**归并计数法**
   （Θ(n lg n)，与值域无关）。三档复杂度要在表里写清再选。）
9. **错误直觉：小 n 验证通过的计数公式就是对的（趟数公式 n(n−1)/2）**
   （现象：「恰 T 趟排好的排列数」按 K 个失位元素、乘法原理配出的
   Σ∏ 公式在 n=3 全对，n=4 起开始漏计（count(T=1) 真值 7，公式给 6）；
   原因：公式数的是「失位元素的取位组合」，但「多个元素左移」与「一个
   元素左移多格」产生同样的趟数，组合数不按趟数分解；后果：n=3 的全对
   造成假信心；对策：正确统计量 T = max_i(i − f(i))，count(T=1) =
   2^(n−1) − 1，其余 T 没有简单闭式——用穷举表而不是猜公式。）
10. **最小交换代价的方法二漏记 +t**
    （现象：借全局最小值 a 进出轮换的代价写成 s + (k+1)·a，答案系统性
    偏小；原因：a 换进、a 归位共两次「a 与轮换元素」的交换，每次都带着
    轮换侧的那个元素——正确代价 s + **t** + (k+1)·a；原书两个算例恰好
    t = a，暴露不出；后果：t ≫ a 时（如 [1,102,100,103,101]，真值 511
    被算成 411）给出不可达的「最优值」；对策：用「排列为节点、交换为
    带权边」的 Dijkstra 暴力做小 n 对账——本示例 200 组随机数据揪出
    4 组错值。）
