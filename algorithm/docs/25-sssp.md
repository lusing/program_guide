# 25 · 单源最短路径

> 对应 CLRS 第 24 章 *Single-Source Shortest Paths*（英文 3rd ed.
> pp.643–703）。松弛（relaxation）是全章唯一的原语：`if d[u]+w < d[v] then
> d[v] = d[u]+w`。一切最短路算法 = **以什么顺序做松弛**：全边 V−1 轮
>（Bellman-Ford，容忍负权）、按贪心近者先（Dijkstra，要求非负）、
> 拓扑序（DAG 图，线性）。

## 学习目标

1. 能陈述最短路的**最优子结构**（引理 24.1 的路径前缀性质）；
2. 会实现 Bellman-Ford（V·E）并解释第 V 轮如何检测负环；
3. 会实现 Dijkstra（堆 + lazy 删除）并解释**为什么禁止负权边**；
4. 知道负环的正确性含义（「无最短路」而非「无路」）。

## 松弛与三条性质

**路径松弛性质**：按 p₀→p₁→…→pₖ 的边序松弛，则 d[pₖ] 最终 ≤ w(p)。
**收敛性质**：d[u] 定型后再松弛 (u,v)，d[v] ≤ d[u]+w(u,v)。**上界性质**：
一旦 d[v] 达到 δ(s,v) 就不再变。三者合起来：**只要松弛的次序覆盖了
最短路的边序，正确性白送**——各算法的差别只是「怎么保证覆盖」。

## Bellman-Ford（§24.1）

V−1 轮、每轮松弛**全部** E 条边——暴力但全面，**容忍负权**：

```cpp
for (round = 1; round < n; ++round) {
    changed = false;
    for (每条边 (u,v,w)) if (d[u]+w < d[v]) { d[v] = d[u]+w; changed = true; }
    if (!changed) break;      // 提前收敛
}
for (每条边) if (d[u]+w < d[v]) return 负环;
```

V−1 轮够用的理由：最短路至多 V−1 条边（有 V 个点的简单路径），第 i
轮结束时所有「i 条边以内」的距离已正确（归纳 + 路径松弛性质）。第 V
轮仍能松弛 ⟺ 某条最短路还在变长 ⟺ **负环可达**。

实测（图 24.4 的负权图，源 s）：d = t:2 x:4 y:7 z:−2——z 的 −2 靠
s→t→z 的 6−4，t 的 2 靠 s→y→x→t 的 7−3−2：**负权边的收益链**，40 次
松弛操作（提前收敛省了整轮）。

## Dijkstra（§24.2）

**要求所有边权非负**。贪心：堆里取 d 最小的未定型点 u，松 u 的所有
出边。为什么非负是命门：u 出队时 d[u] 已定型（上界性质 + 非负保证后来
者不可能更短——任何绕路 ≥ d[u] + 0）；有负权时「先到的」可能被后来
的负权路反超，贪心序失效。

```cpp
while (!pq.empty()) {
    auto [du, u] = pq.top(); pq.pop();
    if (du > d[u]) continue;          // lazy 删除：过期条目跳过
    for (auto [v, w] : adj[u]) if (d[u]+w < d[v]) { d[v] = d[u]+w; pq.push({d[v], v}); }
}
```

**lazy 删除**：`std::priority_queue` 不支持 decrease-key（第 6 章坑位 3
的老朋友），工程解法是「改进就重插，弹出时验日期」——同一顶点可能
在堆里多份，过期份被 `du > d[u]` 拦下。实测（图 24.6，源 s）：d =
t:8 x:9 y:5 z:7，出队序 s y z t x（按距离升序出队的贪心序可视化），
8 次弹出里 3 次是过期条目——lazy 的代价与简单。

复杂度 O((V+E) lg V)（二叉堆）或 O(E + V lg V)（斐波那契堆——第 20 章
摊还账本的兑现现场）。

## 负环检测实测

三点环 a→b 1, b→c −3, c→a 1（环权 −1）：第 V 轮仍松弛成功 → 报负环。
语义要点：负环**可达**时「最短路」不存在（绕圈无限便宜），但**别的
点对之间**可能仍有最短路——差分约束系统（练习 24.4）与 Johnson 算法
（第 26 章）都靠这个检测兜底。

## 选型表

| 场景 | 算法 | 复杂度 |
|---|---|---|
| 非负权、单源 | Dijkstra + 堆 | O((V+E) lg V) |
| 有负权、无负环 | Bellman-Ford | O(V·E) |
| DAG（无论权值） | 拓扑序松弛 | O(V+E) |
| 负环检测 | BF 第 V 轮 | — |
| 全源（第 26 章） | Johnson / Floyd | — |

DAG 最短路值得一提：拓扑序一轮松弛即完成（每条 (u,v) 恰在 u 定型后
松弛）——「关键路径」（PERT 图）就是这个的 longest 变体（权取反）。

## 时间依赖最短路：时刻表、候车与 FIFO 性质

到目前为止所有边权都是**常数**：w(u,v) 与何时出发无关。但公交、地铁、
轮渡、快递、限速路段的边权是**出发时间的函数**——「你在时刻 t 位于 u，
最早何时到 v」记作 f(t)。本节把 Dijkstra 搬到这一场景，并指出它成立的
**精确条件**。

### 建模：f(t) 的两种形态

**步行边**（任何时刻都能走）：

```
f(t) = t + w
```

**车行边**（要等车）。一条线路 L 有 h 个站点（按行驶顺序
p₁..p_h）、相邻站行驶时间 d₁..d_{h−1}、k 个发车时刻 t₁ < t₂ < … < t_k。
**关键是把累计行驶时间编码进班次时刻**：

```
S_x = Σ_{i<x} d_i        从起点站累计行驶到 p_x 的时间（S_1 = 0）
```

第 j 趟车在 p_x 的**发车时刻**是 `t_j + S_x`，在 p_{x+1} 的**到达时刻**
是 `t_j + S_{x+1}`。于是「在 p_x 时刻 τ 最早何时到 p_{x+1}」是

```
f(τ) = min{ t_j + S_{x+1} : t_j + S_x ≥ τ }      （即 t_j ≥ τ − S_x）
```

**这个式子就是全节的技术核心**——它把「等车 + 乘车」两件事并成了一个
`lower_bound` 查询。

### FIFO 性质：为什么 Dijkstra 还能用

> **FIFO（First In First Out）**：f 单调不减，即 τ₁ ≤ τ₂ ⟹ f(τ₁) ≤ f(τ₂)。
> 口语说法是「**到得早从不更差**」。

**上面两种边都满足 FIFO**：

- 步行：τ₁ ≤ τ₂ ⟹ τ₁ + w ≤ τ₂ + w ✓
- 车行：τ 增大 ⟹ 下界 `τ − S_x` 增大 ⟹ 可选班次集合**缩小** ⟹ min 只增
  不减 ✓

**FIFO 是 Dijkstra 贪心证明的全部前提**。回看 §24.2：贪心取 d 最小的未
定型点 u、断定 `d[u] = δ(s,u)`，用的理由是"任何绕路都 ≥ d[u]"。在时间
依赖图里，"绕路"的收益要用 `f` 复合来比较，**单调不减**正是保证
"早到的状态支配晚到的状态"的那条性质——若 f 单调，则

```
τ₁ ≤ τ₂  ⟹  f(τ₁) ≤ f(τ₂)  ⟹  从 τ₁ 出发走任何后续路径都不晚于从 τ₂ 出发
```

于是"更早到达"这个状态**支配**所有更晚到达的状态，堆里先弹出的那个一定
定型，Dijkstra 的贪心序合法。所以**时间依赖最短路的算法与普通 Dijkstra
一字不差**，只是松弛式子从 `d[u] + w` 换成 `f(d[u])`。

**实现上唯一的变化**：`d[u]` 存**绝对时刻**而不是耗时，`d[s] = S`（出发
时刻），输出时再减 S。

### 没有 FIFO 则 Dijkstra 失效

这是本节最重要的理论点，必须给出反例。两条从 s 到 t 的通道：

- **慢船**：任何时刻出发，10 小时后到 ⟹ f_A(t) = t + 10
- **快船**：只在 t ≥ 5 时可用，1 小时后到 ⟹ f_B(t) = t + 1（t ≥ 5），否则 ∞

于是

```
f(0) = min(10, ∞) = 10        早到的人只能坐慢船
f(5) = min(15, 6)  = 6         晚到 5 小时的人坐快船，反而更早到
```

**f(5) < f(0)**，单调不减性被破坏。后果正是直觉里的那句话：**先到的船要
等 10 小时，后到的立刻走，早到的反而更晚到**。Dijkstra 会先把 s 定型、
按 f(0) = 10 松弛，把 t 标成 10 并定型；那条更优的 6 永远不会被发现
（因为它藏在"更晚出发"这个事实上，而 Dijkstra 从此不再看 s）。

**怎么办**：非 FIFO 图要用 **time-dependent Bellman–Ford**（同样把
`d[u]+w` 换成 `f(d[u])`，放弃定型承诺、靠 V−1 轮松弛覆盖所有边序），
或者对一般的时间依赖图用**标签设定/优先队列的 Bellman-Ford 变体**。
代价从 O((V+E) lg V) 升到 O(V·E)。**FIFO 不是一个可以忽略的技术细节，
它是 Dijkstra 适用性的判据。**

### 班次表不要展开

最朴素的建模方式是「把每趟车的每一段都变成一个节点」：节点 = (线路, 段号,
趟次)，边 = 沿车前进 + 换乘边。总节点数

```
K · k · h        K 条线 × k 趟车 × h 段
```

按题面规模 K = 50、k = 1000、h = 1000，这是 **5×10⁷ 个节点**（每个 8 字节
的 (时刻, 弧) 就是 400 MB）——时间与空间都不可接受。

**正确做法：每条线路只存两样东西**

- `S_x`（h 个累计行驶时间常数）；
- 发车时刻数组 `t`（k 个），**全线路共享同一份语义**（都是"从起点站
  出发"的口径）。

空间 **Θ(K(h + k))** = 50 × 2000 = **10⁵**，比朴素小 500 倍。而且查询就是
一次 `lower_bound`：

```cpp
// 在 p_x 时刻 τ 最早何时到 p_{x+1}
const auto it = std::lower_bound(line.departures.begin(), line.departures.end(), tau - S_x);
return (it == line.departures.end()) ? INF : (*it + S_{x+1});
```

**Θ(log k) 查询，Θ(k) 预处理**。把 `τ − S_x` 而不是 `τ` 送进 `lower_bound`
是这一步的全部诀窍——`S_x` 被**减掉**了，所以不需要为每个 (线, 段, 趟)
单独存一个时刻。

**Θ(log k) vs Θ(1) 摊还**：Dijkstra 弹出的 `d[u]` 单调不减，于是每条线
路上传给 `lower_bound` 的查询值也单调不减 ⟹ 可以给每条线路维护一个
**只前进的游标**，总代价 O(k) 摊还。两种写法都对；`lower_bound` 更简单
且不依赖"查询单调"这个前提（一旦有人改成"多源同时跑"或从终点反向推，
单调性就没了），本示例用 `lower_bound`。

### 连续乘坐为什么自动免费

题目常要求「上了车可以一直坐下去，不用下车换乘」。这个语义**不需要额外
处理**，拆边建模已经包含：

在 p_{x+1} 时刻 τ = t_j + S_{x+1}（某趟车 j 把你送到 p_{x+1}），你要坐该
线路的**下一段**。查询条件是 `t_{j'} + S_{x+1} ≥ τ = t_j + S_{x+1}`，
即 `t_{j'} ≥ t_j` ⟹ `lower_bound` 恰好返回 **j' = j**（同一趟车）⟹
**候车时间 = t_j + S_{x+1} − τ = 0**。

换乘则不同：换到**另一条**线路时，`τ` 与那条线自己的 `S_y` 毫无关系，
`lower_bound` 返回的是真正的未来班次 ⟹ 付出**真实的等待时间**。

**同一个式子同时表达了"连续乘坐免费"和"换乘要等车"**，不需要任何特判
——这是"把累计行驶时间编码进班次时刻"这个建模的精妙处。

### 复杂度

```
读入           O(M + K(h + k))
建图           O(M + K·h) 条边
Dijkstra       O((M + K·h) · lg N + K·h · log k)
空间           O(N + M + K(h + k))
```

与 §24.2 的 O((V+E) lg V) 相比只多了每个乘车段一次 `lower_bound` 的
log k。**班次展开的 Θ(K·k·h) 完全没有出现**——这是本节的核心收益。

实测（示例 25.5）：

```text
=== 25.5 时间依赖最短路：时刻表、候车与 FIFO 性质 ===
  线路（发车时刻存在**起点站**，S_x = 累计行驶时间）：
    L1: 站点 0→1→2→3，段耗时 [5,7,3]，S = [0,5,12,15]，发车时刻 [0,20,40,60,80]
    L2: 站点 1→4→5，段耗时 [6,9]，S = [0,6,15]，发车时刻 [0,30,60]
  步行边（分钟）: 0↔1=12, 0↔3=30, 1↔2=9, 2↔3=14, 4↔5=8
  从站点 0、时刻 S = 4 出发，各点最早到达时刻（耗时 = 时刻 − S）：

    站点 2: 时刻 25（耗时 21）
    站点 3: 时刻 34（耗时 30）
    站点 4: 时刻 36（耗时 32）
    站点 5: 时刻 44（耗时 40）
  班次查询次数 = 5（每条乘车段被松弛一次 ⟹ Θ(M_edges)，每次 lower_bound Θ(log k)）
  连续乘坐验证：时刻 0 上 L1 → 站 1 时刻 5 → 站 2 时刻 12（两段衔接处候车 = 0）
  候车验证：时刻 6 才到站 1（L1 第 2 段）⟹ 最早到站 2 时刻 32（改乘 20 点那趟，等 19 分）
```

注意 d[3] = 34 来自**步行直达**（0→3 = 30 分钟）——虽然 L1 的 20 点那趟
35 分钟也能到，但步行更快。这说明时间依赖最短路里"哪种交通方式"和
"常数最短路"完全不是一回事：**早出发的优势可能被等待吃掉**。

## C++23 语言点

- `std::priority_queue<pair<int,int>, vector<...>, std::greater<...>>`
  小顶堆的 lazy 删除模式（值得背下来）；
- INF 用 `INT32_MAX` 并在松弛前判 `d[u] == INF`——**INF + 负权的
  溢出伪松弛**是本类实现的头号坑（第 26 章实测同款）；
- 结构化绑定 `auto [du, u] = pq.top()` 解包堆条目。

## 与 STL 对照

无标准最短路。工程常态：自己维护 50 行 Dijkstra 模板；地理/路由系统用
双向 Dijkstra、A*（带启发式的 Dijkstra）、Contraction Hierarchies
（现代地图导航的 O(lg) 查询预处理）。

## 坑位清单

1. **INF 与负权的溢出伪松弛**
   （现象：d[u]=INT_MAX 的边被「松弛」成功——INF + (−4) 回绕成小值；
   原因：溢出后比较意外为真；对策：松弛前 `if (d[u] == INF) continue;`
   （本例 BF 的写法）。第 26 章 Floyd-Warshall 同款实测翻车。）
2. **Dijkstra 图里有负权边还照跑**
   （现象：部分答案错（先定型的点被负权路反超）；原因：贪心出队的
   「定型」承诺只在非负下成立；对策：入口断言所有权 w ≥ 0，或负权
   直接换 Bellman-Ford/Johnson。）
3. **lazy 删除的过期判断写成 ≥**
   （现象：正确距离的条目也被跳过，答案偏大；原因：`du > d[u]` 才过期
   ——du == d[u] 是有效条目；对策：严格大于（本例写法），配合一个
   「出队序严格递增」的调试断言。）
4. **BF 的轮数写成 V**
   （现象：无负环的图被误报负环；原因：V−1 轮松弛 + 1 轮检测是三段
   式——松弛轮多跑一轮等于把检测混进松弛；对策：循环边界 V−1，检测
   单独一段（本例写法）。）
5. **提前收敛 break 放错位置**
   （现象：偶发错答案；原因：changed 标志应在一轮结束后判——放循环
   内层会在「本轮后半还有边要松」时提前退；对策：changed 的检查在
   轮尾（本例写法）。）
6. **把每趟车的每一段都展开成节点**
   （现象：节点数 Θ(K·k·h) = 5×10⁷，内存 400 MB 直接 MLE；原因：把
   "时刻表"这个**共享的**数据结构复制成了每趟车一份；后果：时间与
   空间都爆炸，且与线路数、班次数、站数三者相乘——增长过快；对策：每
   线只存 h 个 `S_x` + 共享的 k 个发车时刻，查询 `lower_bound(t, τ −
   S_x)`（Θ(log k)），空间降到 Θ(K(h+k))，差 500 倍。）
7. **`lower_bound` 送错参数（送 τ 而不是 τ − S_x）**
   （现象：查询总是命中过早的班次，到达时刻偏小、看起来"更快"但其实
   等车时间算漏了；原因：`S_x` 是"从起点站累计到 p_x"的偏移，判据是
   `t_j + S_x ≥ τ` ⟺ `t_j ≥ τ − S_x`；后果：得到的是"根本赶不上的车"
   （时间穿越），实测会得到比纯步行还早的荒谬到达时刻；对策：牢记送进
   `lower_bound` 的是"折算到起点站口径"的下界 `τ − S_x`，返回时再加回
   `S_{x+1}`；用「时刻 0 上车连续乘坐、衔接处候车 = 0」做回归断言。）
8. **在非 FIFO 图上照跑 Dijkstra**
   （现象：部分点的最早到达时刻偏大；原因：Dijkstra 的"定型"承诺依赖
   "早到从不更差"，非 FIFO 时该性质被破坏——先到的可能要等，而后到的
   立刻走反而更早；后果：贪心定型后再无机会发现更优路径；对策：入场
   断言 FIFO（对每条边验证 `f(t₁) ≤ f(t₂)`），或改用 time-dependent
   Bellman–Ford（V−1 轮松弛，放弃定型承诺）。**FIFO 是适用性判据，不是
   优化项。**）
9. **时刻用 `int` 存，累加行驶时间后溢出**
   （现象：出发时刻 S ≤ 10⁵、线路周期可达 10⁷，累加后超过 2³¹；原因：
   §24.2 的权是"分钟数"，本节 `d[u]` 是**绝对时刻**且要跨线路累加，比
   权长大得多；后果：UB 或静默错值；对策：本节统一用 `long long`，
   `S_x` 与 `d[]` 都是 64 位。）
10. **把 `d[u]` 存成"已耗时"却又在松弛时与班次时刻比较**
    （现象：到达时刻与出发时刻混用，差值出现巨大负数或恒不换乘；原因：
    `d[u]` 有两种合法约定（绝对时刻 / 相对出发时刻的耗时），但班次
    时刻表是**绝对时刻**口径，两者不可混用；后果：查询恒不命中或恒命中；
    对策：全文统一"绝对时刻"，`d[s] = S`，输出时统一减 S；与 §24.2 的
    `d[s] = 0` 口径在注释里写清差异（本例写法）。)
