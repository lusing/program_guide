## 图的表示（§22.1）

- **邻接表**：`adj[u]` 存 u 的邻居列表。空间 Θ(V+E)，扫一个点的邻域
  O(deg(u))——**遍历型算法**（BFS/DFS/最短路）的标配；
- **邻接矩阵**：`vector<vector<char>>`，空间 Θ(V²)，查「有边吗」O(1)——
  **稠密图或反复查边**的场景（Floyd-Warshall 第 26 章）。

示例 23.1 复刻 CLRS 图 22.3（8 顶点 11 边无向图）的邻接表，并用握手
定理对账：Σdeg = 2|E| = 22。

## BFS：层序与最短边数（§22.2）

队列驱动的逐层扩张。灰 = 已发现未处理（在队列里），黑 = 处理完。

```cpp
r.dist[s] = 0;  q = {s};
while (!q.empty()) {
    u = q.pop_front();
    for (v : adj[u]) if (dist[v] == -1) {   // 白才入队
        dist[v] = dist[u] + 1; parent[v] = u; q.push_back(v);
    }
}
```

**正确性骨架**（定理 22.5）：BFS 计算的是**最短边数**距离——队列里
距离值单调不降（先 0 后 1 后 2…），先发现的路径不可能更长。归纳于
出队次序即可。BFS 树（parent 指针）本身是**最短路径树**的一棵。

实测（图 22.3，从 s 出发）：dist 场 r=1 s=0 t=2 u=3 v=1 w=1 x=2 y=3，
s→y 的 BFS 树路径 s→w→x→y（三条边，与 u=3 的下界一致）。注意 v=1：
v 与 s 直接相邻（s–v 边存在）——首版示例把 v 的距离算成 2，就是
「漏看一条边」的实测翻车（坑位 1）。

## DFS：时间戳与括号化（§22.3）

DFS 不用队列，一路走到底再回溯；给每个点记发现/完成时间
（disc/finish），形成**括号化结构**：

```
disc/finish: r=1/16 s=2/15 t=6/13 u=8/11 v=3/4 w=5/14 x=7/12 y=9/10
括号化定理（区间嵌套或不相交）= 1
```

**括号化定理**（定理 22.10）：任意两点的 [disc, finish] 区间要么嵌套
（祖先/后代）要么不相交（无亲戚关系）——**交错不可能**。示例对所有
36 对顶点验证了这一点。边分类是它的直接推论（白=树边、灰=后向边、
黑=前向/交叉边——有向图四类、无向图只有树边与后向边）：

**无向图的两个小坑**：①树边的反向弧（v 探索到父亲 u 时看到灰色）会
被误记为后向边——要跳过；②某条边的另一侧先探索时会记过后向边，本侧
再看是黑色——去重不记。处理完这两条，无向图 DFS 恰好「7 树边 +
4 后向边 = 11 边」（11 − (8−1) = 4 条非树边，每条对应图上一个环——
**后向边 ⟺ 有环**，拓扑排序正是用它判环）。

## 拓扑排序（§22.4）

DAG 的「线性化」：u→v 有边则 u 排 v 前。两条等价路线：

- **DFS 完成时间倒序**（TOPOLOGICAL-SORT）：一条链完成时间最晚的
  一定是最「上游」的；
- **Kahn 零入度法**（练习 22.4-2）：反复摘当前入度 0 的点。天然给出
  判环：若摘不完（剩余点入度皆 > 0）则**有环**。

示例 23.4 用 Kahn 跑穿衣 DAG（0 内裤→1 裤子→3 鞋；2 袜子→3 鞋；
4 衬衣→5 腰带→6 外套；1→5）：序 0 2 4 1 3 5 6，六条边全部满足
pos(u) < pos(v)（逐边断言）。拓扑序不唯一（0/2/4 可互换）——判定
「某个拓扑序合法」用边检查，「是否唯一」看是否每步零入度点唯一。

## 强连通分量：Kosaraju（§22.4 SCC? 22.5）

有向图的「双向可达」等价类。**Kosaraju 两遍 DFS**：

1. 原图 DFS，按**完成时间降序**排列；
2. 在**转置图**（所有边反向）上按该序 DFS，每棵 DFS 树恰是一个 SCC。

**为什么转置图**：SCC 缩点后的分量图是 DAG（定理 22.16 的骨架）；
第一遍 DFS 保证「最晚完成的分量」在分量 DAG 里是汇（sink）——转置后
变成源，第二遍 DFS 从源分量出发只淹到自己这一块。实测（图 22.9）：

```
{a,b,e} {c,d} {f,g} {h}
```

四个 SCC 与原书一致。Tarjan 单遍 DFS 版（dfn/low 数组）是工程主流
（省一次转置），思考题 22-3；分量缩点 + 拓扑 = 「2-SAT」类问题的
标准流水线。

## 割点与桥：一次 Tarjan 搞定

割点（关节点）与桥都是 **DFS 树的边性质**，和 Kosaraju 的 `low` 是同一个数组。
一次 DFS 同时出两个答案，Θ(V+E)。

### low 的定义与赋值形式

`d[u]` 是发现时间。**low[u] = u 的 DFS 子树（含 u 本身）出发，沿树边向下再沿至多一条回边，能到达的最小 d 值**。展开：

```
low[u] = min( d[u],
              d[w]   对每条回边 (u, w)（w 是 u 在 DFS 树中的祖先）,
              low[v] 对 u 的每个 DFS 树孩子 v )
```

写成赋值形式（这就是全部代码）：

```cpp
color[u] ← GRAY;  low[u] ← d[u] ← time++;
for each v ∈ Adj[u]:
    if color[v] == WHITE:                  // 树边
        parentEdge[v] ← id(u, v);  parent[v] ← u
        ARTICULATION(u → v);               // 递归
        low[u] ← min(low[u], low[v]);
        if u ≠ root && low[v] ≥ d[u]:  A.insert(u);   // u 是割点
    else if color[v] == GRAY:              // 回边
        low[u] ← min(low[u], d[v]);
color[u] ← BLACK;
if u == root && 孩子数 ≥ 2:  A.insert(u);              // 根的特殊判定
```

### ≥ 与 > 的区别（本节最要紧的一处）

| 判据 | 含义 | 结论 |
|---|---|---|
| 根 s：孩子数 ≥ 2 | s 是 DFS 树的根，删掉它至少两棵子树 | s 是割点 |
| 非根 u：∃ 树孩子 w 使 `low[w] ≥ d[u]` | w 的子树**回不到 u 的严格祖先**，最多回到 u 自己 ⟹ 绕过 u 走不通 | u 是割点 |
| 树边 (u,v)：`low[v] > d[u]` | v 的子树**连 u 都回不去** ⟹ (u,v) 不在任何环上 | (u,v) 是桥 |

一句话记法：**`≥` 是「回不到我上面」所以我是割点；`>` 是「连我都回不来」所以这条边是桥。**
`low[v] = d[u]` 这个边界值同时体现两者：边 (u,v) 有回边 (v 的子树里的点 → u)，
因而成环、不是桥；但这条回边只能回到 u 自身，删掉 u 之后 w 的子树就与上面隔绝了，
所以 u 仍是割点。实测里 `low[4] = 4 = d[3]` 正是这个边界：

```te  ≥ 与 > 的分水岭：low[4] = 4 = d[3] —— 边 (3,4) 不成桥（> 不成立），但 3 是割点（≥ 成立）
立）
```

无重边的无向图里有恒等式 `low[v] ≤ d[v]`（父边本身就是一条到 d[v] 的路径），
所以 `low[v] > d[u]` 可改写为 `low[v] ≥ d[v]`——**这个改写在有重边时不成立**。

### 坑：判父边必须用边 id

无向图的 DFS 会把树边 (u,v) 存成两条邻接项。重边让「跳过父边」这一步变脆：

- 若判据写成「`v == parent[u]` 就跳过」，那么 u→v 走树边、v→u 走**另一条平行边**时
  也会被跳过——那条平行边本该是回边，把 `low[v]` 压到 `d[u]`，现在没压；
- 于是 `low[v] > d[u]` 成立，**一条有平行边的非桥边被误判成桥**。

正确做法是给每条边唯一 id，邻接表存 `(to, id)`，DFS 记 `parentEdge[v] = id(u,v)`，
判父边用 `id == parentEdge[u]`。这样另一条平行边正常地当回边处理。
等价的补丁是「记 (u,v) 之间的边数 `e_cnt`，判据 `low[v] > d[u] && e_cnt == 1`」——
注意 `e_cnt` 必须是**这对顶点之间**的边数，不是「v 的平行边总数」。

实测（0-1 两条平行边 + 1-2，答案 1 条桥）：

```te  重边坑（0-1 两条平行边 + 1-2）：边 id 判父边 = 1 条桥，父顶点判父边 = 2 条桥（多算一条）
条）
```

**用「顶点颜色 / 父顶点」代替「这条边是否已用」在带重边的图上必错**——这是本章
反复出现的一个模式：flood fill 用字符就地标记、欧拉与桥用边 id + `used[]`、
Tarjan 用颜色 + `low[]`，判据必须与「对象类型」匹配。

### 迭代版：n = 10⁵ 会爆栈

递归 DFS 在 n = 10⁵ 的链上必爆栈（每帧几十字节，栈默认 8 MB）。改成**显式栈 +
游标**：栈存「当前 DFS 路径上的顶点」，`cur[u]` 记 u 的邻域扫到第几项；
`cur[u] < deg(u)` 就下潜（树边），否则回溯（把 low 往父亲合并 + 判割点/桥），
回溯完把 u 弹栈。这样 `low` 的合并时机与递归完全一致：

```cpp
const auto [v, eid] = g.adj[u][cur[u]++];

## 欧拉回路：Hierholzer 与无向边的有向化

### 存在性定理

- **无向连通图**有欧拉回路 ⟺ **每点度数为偶**（连通性通常由题面保证）；
- **有向图**（缩点后强连通）有欧拉回路 ⟺ **每点入度 = 出度**。

### Hierholzer：线性构造 + 逆序出栈

维护一个顶点栈：能走未用边就沿着走，走不动就**弹栈并把边记进答案**，
最后把答案**整体反转**。反转这一步是全部诀窍：弹栈序是「每条子回路闭合的顺序」，
反序才把子回路拼成一条大回路。每条边进栈出栈各一次 ⟹ Θ(V+E)。

```cpp
// adj[u] = {v, arcId}；arcCount = 弧总数
std::vector<int> hierholzerArc(const std::vector<std::vector<std::pair<int,int>>>& adj,
                              int arcCount, int start) {
    std::vector<std::size_t> cur(adj.size(), 0);
    std::vector<char> used(arcCount, 0);
    std::vector<int> vstk{start}, astk{-1}, out;
    while (!vstk.empty()) {
        const int u = vstk.back();
        while (cur[u] < adj[u].size() && used[adj[u][cur[u]].second]) { ++cur[u]; }
        if (cur[u] == adj[u].size()) {          // 无路 ⟹ 弹栈（模拟 return）
            out.push_back(astk.back()); vstk.pop_back(); astk.pop_back();
        } else {
            const auto [v, aid] = adj[u][cur[u]++];
            used[aid] = 1; vstk.push_back(v); astk.push_back(aid);
        }
    }
    std::ranges::reverse(out);                   // ★ 逆序出栈
    if (!out.empty() && out.front() == -1) { out.erase(out.begin()); }
    return out;
}
```

**为什么不能「一路走到卡死」**：朴素走法在有桥的图上一定半途失败。
实测（0-1-2 成环 + 桥 2-3 + 3-4，起点 0）：朴素法走 3 条边就卡住，还剩 2 条没用；
Hierholzer 靠「弹栈时记账」把两个子回路拼起来，用满 5 条。

```te  有桥图上对比：朴素走到卡死用了 3 条边（剩 2 条没用），Hierholzer 用满 5 条
 条
```

### 字典序最小欧拉回路

**升序选边 + Hierholzer**：邻接表按边 id 升序（`sortAdjByEdgeId`），
其余一字不改。原理：优先走小编号边 ⟹ 在「能闭合的那些子回路」里优先展开小编号边，
得到的就是全部欧拉回路中字典序最小者。示例对账（暴力枚举全部欧拉回路取最小）：

```te  任意回路（插入序取边）边号: 1 4 5 6 2 3 
  字典序最小回路（升序选边）边号: 1 4 5 6 2 3 
  暴力枚举全部欧拉回路，字典序最小者: 
1 4 5 6 2 3 
 3
```

两个易错细节：**起点取 min(边号 1 的两个端点)**（输入不保证 x < y）；
**输出元素是街道编号而不是路口**，所以邻接表必须同时存 `{to, id}`。

### 双欧拉回路：无向边的有向化技巧

问题：给定连通无向图，求一条从 1 出发、**每条边往返各一次**（共 2m 次）、回到 1 的路线。

**做法：把每条无向边 (u,v) 替换成两条有向弧 u→v 与 v→u，对这个有向图跑 Hierholzer。**

- 存在性：每个点入度 = 出度 = 度数（自动满足）；无向连通 ⟹ 替换后强连通
  ⟹ **欧拉回路必存在，对任何连通无向图都有解，无需度偶条件**；
- 输出恰好 2m+1 个顶点（起点 + 2m 步 + 回起点），这也解释了「为什么答案总是 2m+1」。

实测（3 边路径图 0-1-2-3，端点度为奇、单回路根本不存在）：

`  双欧拉回路（每条边走两次，3 边路径图，端点度为奇）顶点数 = 7，终点 = 0：
0 1 2 3 2 1 0 
 2 1 0
```

**如果写成 DFS 遍历**，守卫必须是 `if (used[e]) continue;`（按**边 id** 判是否已用）。
用「`v` 是白点吗 / `v ≠ π[u]` 吗」这类顶点判据必错：与 u 相邻且非 u 父亲的顶点
要么是祖先（GRAY），要么是后代（已完成访问）；对后者那条边在 v 的递归里**已经被消耗掉了**，
但外层 `for each (u,v) ∈ Adj[u]` 的迭代仍会走到它，于是代码会再插一次
「瞬移到 v 再瞬移回 u」的假移动——输出的相邻元素之间根本没有边。

### 半定向图：双行道方向待定的线性判定

场景：m 个路口、s 条街道，单行道方向已定、双行道方向待定，问能否定向出一条欧拉回路。
对 2^t 种定向逐一判定是 O(2^t·(n+m))，t ≤ 200 时不可行。**线性做法**：

对每个顶点 u 记

- `Δ[u] = |indeg(u) − outdeg(u)|`，**只统计单行道**贡献的出入度；
- `a[u] = 与 u 关联的双行道条数`。

则可行性的**充要条件**是两条都满足：

```
① a[u] ≥ Δ[u]                        // 有足够的双行道补差额
② (a[u] − Δ[u]) mod 2 == 0           // 剩下的双行道能两两成对地在 u 处一进一出
```

**推导**：设分配给 u 的双行道中「指向 u」的有 x 条、「从 u 出发」的有 y 条。
双行道每条只有一个朝向，所以 x + y = a[u]；定向完成后 u 的入度须等于出度，
即 `indeg(u) + x = outdeg(u) + y`。记 δ = indeg(u) − outdeg(u)（可正可负，|δ| = Δ[u]），
联立

```
x + y = a[u]
x − y = δ
⟹ x = (a[u] + δ)/2,  y = (a[u] − δ)/2
```

要求 x, y 是**非负整数**：非负性给出 `a[u] ≥ |δ| = Δ[u]`（条件①）；
整除性给出 `a[u] ≡ δ (mod 2)`，等价于 `a[u] ≡ Δ[u] (mod 2)`，
即 `a[u] − Δ[u]` 为偶数（条件②）。∎ 各顶点的方向选择互相独立（一条双行道只连两个点），
所以逐点满足充要条件就是全局可行。

**别忘了检查连通性**：条件①②只管每个点的度数平衡，管不到「一次遍历能不能走遍所有边」。
严格判定要对**忽略方向的无向底图**（单行道与双行道都算）做一次连通性检查，
很多参考实现漏掉这一步。判定本身 Θ(s+m)。

实测三个案例（有解 / 奇偶失败 / 差额不足）：

  [有解] 双向 0-1 + 单行 1→2 + 双向 2-3 + 单行 3→0（有解，定向成 0→1→2→3→0）
       判定依据：两条充要条件 + 连通性全部满足
  [无解] 双向 0-1 + 单行 0→2（顶点 1 处 a − Δ = 1 为奇数，无解）
       判定依据：顶点 1：a − Δ = 1 为奇数，剩下的双行道无法两两成对地一进一出
  [无解] 双向 0-1 + 单行 2→0 + 单行 2→1（顶点 2 处 a = 0 < Δ = 2，无解）
       判定依据：顶点 2：双行道 0 < |Δ| = 2，补不齐差额
2，补不齐差额
```

## 网格 flood fill 与函数迭代的环检测

### flood fill：不需要显式建图

网格上求连通块，朴素做法是**先把每个 `*` 编号成点，再两两枚举判相邻建图，最后 BFS**——
建图那一步就是 Θ(n²)（n = `*` 的个数，n 可达 8 万 ⟹ 6.4×10⁹ 次比较，不可行）。

**根本不需要建图**：把每个 `*` 直接当栈元素，在网格上迭代 DFS，
**in-place 把访问过的 `*` 改成 `.`**（入栈即标记，这一步保证每格只入栈一次）：

```cpp
best = 0
for r in 0..H-1: for c in 0..W-1:
    if grid[r][c] == '*':
        grid[r][c] = '.';  stack.push((r,c));  size = 0
        while stack 非空:
            (y,x) = stack.pop();  ++size
            for each of 4 neighbours (ny,nx):
                if in range and grid[ny][nx] == '*':
                    grid[ny][nx] = '.';  stack.push((ny,nx))   // 入栈即标记
        best = max(best, size)
```

复杂度 **Θ(WH)**：外层扫 WH 格，每格**只入栈一次**（in-place 标记保证），
每次出栈检查 4 个邻居 ⟹ 总操作数 ≤ 4WH。额外空间 O(WH)（显式栈）。

**必须用显式栈而不是递归**：最坏情况（长蛇形）的递归深度等于 `*` 的个数，
8 万层递归必爆栈。给矩阵加一圈哨兵 padding 可以省掉越界判断。

实测（5×7 网格 9 个 `*`；以及 400×400 全 `*` 网格的规模对照）：

  5×7 网格共 9 个 '*'，4-连通块数 = 6，最大块 = 3，总入栈次数 = 9
  规模对照：400×400 全 '*' 网格 —— flood fill 入栈 160000 次（Θ(WH)），先建图要两两判相邻 12799920000 ≈ 1.3×10^10 次（Θ(n²)）
（Θ(n²)）
```

第二行是本节的要点：同一份工作，Θ(WH) 与 Θ(n²) 差了六个数量级。
**「先建图再跑图算法」是复合 O(n) 建图开销的常见来源**——网格、棋盘、
隐式状态空间（第 26 章的 APSP）都有这个问题，能在状态上直接迭代就别建图。

### 函数迭代的环检测：Floyd 与 Brent

问题：迭代 `x_{k+1} = f(x_k)`，f 的值域有限。求**尾长 μ**（进环前的步数）与
**环长 λ**，并判断是否进环。

**抽屉原理**：N 个状态上迭代，考虑 x_0, x_1, …, x_N 这 **N+1** 项，必有两项相等
（否则要装 N+1 个不同的值进 N 个格子）。设 x_i = x_j（i < j）且取 j 最小，
则 x_i 在环上、i = μ，且环长 λ = j − i。于是 **μ + λ ≤ N**。

三步走（**Floyd 快慢指针，O(1) 空间**）：

1. **相遇**：slow 走一步、fast 走**两步**。步数 t 满足 t ≥ μ 且 t ≡ 0 (mod λ) 时
   slow 与 fast 首次落在同一点，该点必在环上；
2. **求 λ**：把一个指针钉在相遇点，另一个绕环走一圈数步数（计数器从 0 起、每移一次自增）；
3. **求 μ**：slow 复位到 x_0，**fast 留在相遇点**，两者**都走一步**。
   它们第一次同时落在 x_μ 上 ⟹ 计数器就是 μ。

```cpp
int slow = f(x0), fast = f(f(x0));
while (slow != fast) { slow = f(slow); fast = f(f(fast)); }   // fast 走两步
const int meet = slow;
long long lambda = 0;
for (fast = meet; ; ++lambda) { fast = f(fast); if (fast == meet) break; }
long long mu = 0;
slow = x0;                              // fast 留在相遇点，不能一起复位
while (slow != fast) { slow = f(slow); fast = f(fast); ++mu; }
```

**Brent 变体**只用一个指针：把 `tortoise` 固定、`hare` 前进，步长按 1,2,4,8… 倍增，
每个阶段末把 tortoise 挪到 hare 当前位置重新开始。空间更省、无需第三步的「双指针齐走」。

实测（8 个状态，x_0 = 7，轨道 7→0→1→2→3→4→5→6→3→…）：

  迭代轨道 x0 = 7: 7 0 1 2 3 4 5 6 3 4 
  抽屉原理：N = 8 个状态，x0..x8 这 9 项必有两项相等 ⟹ 轨道至多含 N 个不同状态，即 μ + λ ≤ N = 8
  参照（first[] 数组，O(N) 空间）: μ = 4, λ = 4，访问了 8 个不同状态
  Floyd 快慢指针: μ = 4, λ = 4（相遇阶段 4 步）
  Brent 倍增:     μ = 4, λ = 4（相遇阶段 11 步）
段 11 步）
```

μ + λ = 8 = N，抽屉原理在这里取到等号。

## 拓扑排序的两条应用

### 应用一：最小换碟（闭包贪心，O(V+E)）

问题：包分布在两张碟上，依赖 x 必须在 y 之前装。求最少换碟次数
（插入首片计 1、取出末片计 1）。给定一个拓扑序 p，答案是

```
相邻异色段数 + 1 = (换碟次数 + 1) + 1，  disk(x) = (x ≤ N₁ ? 碟1 : 碟2)
```

因为「在哪张碟上」只是顶点的一个二值属性，段数 = 换碟次数 + 1。

**相邻交换式贪心是错的**。直觉是「相邻两片不同碟且 p[k+1] 不依赖 p[k] 时交换它们，
就省一次换碟」——方向对，但**只做一次局部调整无法保证最优**：交换后 p[k+1] 与 p[k+2]
是否又同碟没有再检查，需要反复扫描；而扫描的终止性本身不平凡。
更麻烦的是局部交换的顺序会影响结果，无法保证收敛到全局最优。

**正确贪心：闭包贪心——只要当前碟上还有「可安装」的包，就继续装它；没有才换碟。**

```
avail[0], avail[1] = 两张碟上的「当前可装」栈
remaining[v] = v 的未满足前置数（入度）
cur = 0;  switches = 0
while 还有包未装:
    if avail[cur] 非空:  装 avail[cur] 里的包 u
        for v in Succ(u):  if --remaining[v] == 0:  avail[disk(v)].push(v)
    else:                switches++;  cur = 1 - cur      // 换碟
answer = switches + 2
```

## 最小割视角下的桥：Tarjan × 倍增 LCA × 树上差分

问题：初始图给定（n 个点 m 条边，**允许重边**），依次加入 Q 条新边，
每次输出当前图的桥数。朴素做法是每加一条边就重跑一次完整 Tarjan：
O((N+M+Q)·Q)，Q = 10³ 时约 2×10⁸ 次边访问——能过，但不是最好的。

**一次 DFS + 树上差分/倍增**，复杂度降到 **O((N+M) + (N+Q)·α(N))**，与 Q 基本无关。

### 三条关键结论

1. **桥的失效判据**：一条树边 e 在加边后不再是桥 ⟺ 新边 (u,v) 的树上路径 P(u,v) 包含 e
   （新边把 e 切开的两块重新连起来，于是 e 进了某个环）。
2. **静态计数（前缀和 + LCA）**：给树边赋权（原本是桥则 1，否则 0）放到**较深端点**上，
   根做前缀和 `sum[]`，则
   ```
   P(u,v) 上的桥数 = sum[u] + sum[v] − 2·sum[lca] + w[lca]
   ```
   求 LCA O(log N)、计数 O(1)。（`w[lca]` 这一项就是 LCA 自己那条父边，
   少加它就恰好漏掉 LCA 处的那条边。）
3. **动态清零**：加第 i 条边后，被它覆盖的桥**永久失效**（桥只减不增）。
   于是沿 P(u,v) 把「仍为 1 的边」清零即可，每条桥最多被清一次 ⟹ **全部查询的
   更新总量 O(N)**。实现上用**并查集跳指针 + 路径压缩**（`skip[v]` 指向最近的
   「父边仍活」的祖先）跳过已失效的长链，单次查询摊还 O(α(N))。

### Σ dist(u, v) 的形式

同一套 LCA 设施换个问法：树 + M 条新连接，每次**同时**删一条原树边和一条新边，
问有多少种方式能把网络拆成至少两部分。答案是**有序对计数**

```
答案 = Σ_{(u,v) ∈ 新边} dist_T(u,v)，   dist_T(u,v) = depth[u] + depth[v] − 2·depth[lca(u,v)]
```

每条新边贡献它两端在树上的距离条数：树边 e 被删后树分两块，新边 s 能「复原」连通
⟺ s 的两端分别落在两块里 ⟺ e 在 s 两端的树上路径上。不同新边贡献的 (e, s) 对天然不同，
同一条树边被多条新边覆盖也**应当分别计数**（不同的 (e,s) 组合是不同方法）。答案用 `long long`。

实测（6 顶点、初始只有 4-5 是桥，4 条加边查询，每步与「重跑 Tarjan  初始：6 顶点 6 边，桥数 = 1（0-1-2-3-4 已成环，只有 4-5 还是桥）

## 图的两个计数问题：握手定理与状态空间 BFS

图论的第一课（度数）与图搜索的第一课（BFS）各能解决一类计数问题。这两题
（整理自《趣题学算法》第 1 章的问题 1-9 与 1-6，自包含）正好一个用「图长什么
样」的全局性质，一个用「图怎么走」的搜索框架。

### 问题一：聚会游戏（握手定理判谎）

N 人聚会（含主持人 Robin），各报认识的人数，认识互相 ⟹ 把人当顶点、认识当
边就是一个无向图。**握手定理**（第 23.1 节已实证 Σd(v) = 2|E|）说度数之和必为
偶数——所以**报数之和为奇 ⟹ 必有说谎**。Robin 认识所有人 ⟹ 他的度恰为
N − 1，其余各人至少报 1。

```
=== 23.13a 聚会游戏（1-9）：握手定理判谎 ===
  N=7：报到 5 4 2 3 2 5 + 主持人 6 ⟹ Σ度 = 27（奇）⟹ Lie absolutely
  N=7：报到 3 4 2 2 2 3 + 主持人 6 ⟹ Σ度 = 22（偶）⟹ Maybe truth（Havel–Hakimi 可图）
  偶和不可图例 {2,2,0,0}：Σ度 = 4（偶）但 Havel–Hakimi 可图 = 0
```

关键在第二行的措辞：奇偶只是**必要**条件，{2,2,0,0} 度和为偶却画不出来
（两个报 0 的人不可能与报 2 的人有两条公共边还不认识彼此）。所以偶和只能答
「Maybe truth」。想把 Maybe 升级成 Truth，用 **Havel–Hakimi** 贪心消解：反复
取最大度 d、删掉它、把剩下 d 个最大的各减一——中途出现负数或剩余度超过剩余
人数即不可图。整题 Θ(N lg N)。

### 问题二：找到牛妞（BFS 的一般化）

农夫在数轴点 N、牛在点 K（≤ 100000），每分钟可走 ±1 或**飞跃 ×2**，求最少
分钟数。把「位置」当顶点、三种移动当边——**隐式建图**（不存边表，转移现场
算）——BFS 一遍即答案。状态空间不必是网格或显式图，「状态 + 转移」就行，
这是 BFS 最重要的一般化。

原书给了一个「六方案」数学法（走到 2^t / 2^{t+1}、飞到 2^p / 2^{p+1} 附近，
六式取最小）——它对本题的**自带样例就已经错了**：

```
  N=5 → K=17：4 分钟（5→4→8→16→17：先走回 4=2² 再飞）
  N=3 → K=21：5 分钟（3→4→5→10→20→21：走两步到 5 再连飞两次）
    —— 原书样例给 6，是六方案公式的值：它数不出这条「任意点起飞」路
  书式六方案 vs BFS（1≤N≤150, 0≤K≤150 全对账）：不一致 7595 组
  反例 N=15, K=100：BFS = 6 分钟（15→14→13→26→25→50→100），书式 = 23 —— 六方案漏了「走回任意点再起飞」
```

N=3, K=21 的真相：走两步到 5、连飞两次到 20、再走一步——5 分钟。六方案
只能从 2 的幂附近起飞，数不出「从 5 起飞」这一手；N=15, K=100 更夸张
（13 → 26 → **25** → 50 → 100，中途还要退一格再飞）。2.2 万组全对账里
7595 组不一致——**构造式数学法的方案枚举未必齐全**，而 BFS 的穷举恰好是
它的裁判。正确姿势：先写 BFS（不易错、可验证），数学法若要省时间，拿 BFS

## 旅程：树上的最短覆盖步行

### 问题

n 个城市由 n−1 条双向车道连成**一棵树**，每条车道有长度。旅行者从
城市 k 出发，要不计顺序地游历给定的 j 个城市，**不必回到 k**。求
最短路程。

### 最小连接子树：哪些边非走不可

把 k 与所有目标城市两两之间的树上路径并起来（树上路径唯一，所以
并集也是一棵树），得到唯一的**最小连接子树 T′**，记其边权总和为 W。

把树以 k 为根，边 e =（parent[v], v）是否属于 T′ 有机械判据：

> e ∈ T′ ⟺ v 的子树里至少有一个目标城市。

因为根在 k 一侧：子树里有目标，就必须经过 e 才能从 k 到达它；子树
里没有目标，整棵子树与任务无关。

### 从 2W 里省掉最后一条回程

把 T′ 的每条边都走两遍（进分支、退出分支），就是一次从 k 出发、
回到 k 的 DFS 巡览，总长 2W。题目不要求回到 k ⟹ 可以指定一个
终点 z，**k 到 z 路径上的边只走一次**（走到 z 后步行结束），其余
边仍然两次：

```
答案 = 2W − dist(k, z)
```

为了让答案最小，z 应取 T′ 中离 k 最远的点。T′ 的叶子除 k 外都
是目标城市（若某叶子不是目标，它没有必要留在连接子树里），所以
只需在目标城市中取距 k 最远者：

```
答案 = 2W − max_{m 是目标} dist(k, m)
```

### 算法三步

1. 从 k 迭代遍历：记 parent、父边权、dist 与遍历序；
2. 按遍历序**逆序**传播：`needed[v] = v 是目标 ∨ 有 needed 孩子`；
   needed[v] 的父边 (parent[v], v) 权计入 W；
3. 取目标点 dist 最大值 f ⟹ 2W − f。

全程 Θ(n)。

### 为什么「每次去最近的未去目标」不对

一个自然想法是先算 k 到各点距离，再按就近顺序逐个赶目标。它在
样例 2 上就给出 9（正解 8）：在浅目标间来回横穿之后，还得整条
深入最长分支。更清楚的分叉反例——k 外分三叉：a1 距 2，a1 再
往深处的 a2 距 k 为 100，另一支 b 距 3，目标是 {a1, a2, b}：

```
就近贪心：k→a1 (2)，a1→b (5)，b→a2 (103)        = 110
最优：    k→b (3)，b→k (3)，k→a2 (100，顺路 a1) = 106
```

树上覆盖问题没有「就近」的最优性保证；**结构公式 2W − f 才是
精确答案**，它根本不枚举访问顺序。

### 对账

三个样例答案 5/8/3；3000 个随机小树（n ≤ 8）上与**状态图
Dijkstra**（状态 =（当前位置，目标覆盖掩码），沿树边转移，掩码
只增）求的最短步行 0 例不一致；200 个随机大树（n ≤ 50000）
答案均落在 [W, 2W]。

## 循序：枚举全体拓扑序

### 问题

给定 2～20 个单字母变量与若干 x < y 关系，输出保持全部关系的
全体排列，按**字典序**排列。

### 回溯判据：前驱 ⊆ 已输出

不需要先生成全部 n! 排列再筛选。构造序列的每一步，能放的下一个
变量恰是「**尚未使用，且它的所有前驱都已经在序列里**」的顶点。
用位掩码表达：`pre[v]` 是 v 的前驱位集，`used` 是已输出位集，则

```
v 可放 ⟺ (pre[v] & ~used) == 0
```

候选 v 按编号**升序**尝试 ⟹ 产出顺序天然字典序；每个 v 的前驱都
已先输出，所以叶子处无需再检查约束，合法性在构造中保证。n ≤ 20，
一个 `std::uint32_t` 装得下全部状态。

### 两个似是而非的捷径

1. **位置区间、只查重复。** 统计每个变量的前驱/后继个数，划出
   允许位置区间，回溯时只排除重复变量。直接的入度/出度计数连
   传递闭包都不是：在链 a < b < c < d 上，区间法会吐出 `acbd`，
   违反 b < c。
2. **即使把传递闭包算全，区间仍不能代替就绪判据。** 约束
   a < c、b < d（变量 a,b,c,d）的位置区间允许序列 `adbc`，而
   b < d 被破坏（d 排在 b 之前）。位置区间最多充当剪枝；能不能
   放，必须回到「前驱 ⊆ 已输出」。

### 对账

两个样例分别输出 4 条、6 条，与期望逐字一致且已排序；2000 个
随机例（变量为字母表任意子集、n ≤ 8、边只从小索引指向大索引以
保证无圈）与「全排列逐个过滤约束」的计数 0 例不一致。

## 最优工程布线：网格上的 BFS

### 问题

一块 m×n 的电路板，部分格子被元件占用（封锁）。要从起点格 s 到
终点格 e 布一条线，线只能沿格子中心上下左右走、不能穿过封锁格，
求经过格子最少的布线；不可达时明确报告。

### 网格即无权图

把**每个格子当一个顶点**；两个格子若上下左右相邻且都未封锁，就
在它们之间连一条权为 1 的边。"经过格子最少" = 边权全 1 的最短
路 ⟹ BFS 一遍求出。距离表用三种状态编码：

```
-2：封锁格（永久不可入）
-1：未访问
≥0：距起点经过的格子距离（起点标 0）
```

### 围墙技巧：消灭边界判断

直接在 m×n 数组上扩展邻居，每一步都要判断"会不会踏出板外"。
改用 `(m+2)×(n+2)` 的距离表：真实格 (x,y) 存在 (x+1,y+1)，
第 0 行、第 m+1 行、第 0 列、第 n+1 列全部预先标成 −2。这样
四向扩展时越界位本身就是"封锁格"，**循环体里没有任何边界
分支**。

BFS 从 s 标 0 入队；弹出一格，若它是 e 即可提前收队；邻居为
−1 才标 `当前距离+1` 入队（−1 之外的 −2 与已标号都不动）。

### 路径逆向重建

BFS 只给出距离场，不直接给路径。从 e 出发反复找一个**距离恰为
当前 −1** 的可通行邻居走过去，直到退回 s，再整体反转。为什么
这样的邻居一定存在：e 拿到距离 d，说明它是在某轮从距离 d−1
的邻居被标记的；沿标记链回溯即是一条最短路。注意判据必须是
"恰小 1"而不是"更小"——−2/−1 都更小，但根本走不通。

### 复杂度与对账

每个格至多入队一次：O(mn) 时间、O(mn) 空间。示例给出 5×6
障碍板（10 格，路径覆盖在板上打印）、不可达 2×2、s=e 三个
确定例，并与 **Floyd-Warshall** 全源最短路（O(V³)，把网格当
一般加权图，与 BFS 代码路径完全独立）逐例对账；3000 个
≤4×4 随机障碍板 0 例不一致；100×100 大例（20% 障碍）对角
布线恰好达到无障碍下界 199。

## 八数字谜题：隐式图上的 BFS

3×3 棋盘上放数字 1..8 和一个空格；一步是空格与上下左右相邻的数字交换
位置。给定初态，求到达目标格局

```
1 2 3
4 5 6
7 8 _
```

的最少步数。

### 把棋盘格局当顶点

图不会显式给出，但它存在：每个**棋盘格局是一个顶点**，一次合法交换是两个
格局之间一条权 1 的边。最少步数 = 这个隐式图上的最短边数路，BFS 照样
适用——只是「列举邻居」从查邻接表换成了「找空格、试四个方向、交换生成
新格局」。

格局必须编码成能放进哈希表/队列的标量。示例把九格压进一个 64 位整数
（每格 4 位，共 36 位）：`code = Σ tile[i]·16ⁱ`。BFS 的 visited 是
`unordered_map<格局码, 前驱格局码>`——命中目标后沿前驱链还原整条路径。

### 一半的初态永远无解：先判可解性

盲目 BFS 搜不到目标时会遍历全部 9! = 362880 个格局才报告失败。更聪明的
判据：把九格按行展开、去掉空格，数这个序列的**逆序对数**。

```
一次水平交换：逆序对数不变；
一次竖直交换：数字在序列里跨越两个位置，逆序对数改变 0 或 ±2。
```

两种步子都保持逆序对数的奇偶不变；目标格局逆序对数为 0（偶数），故
**逆序对为奇数的初态不可解**。反过来，逆序对为偶数的格局全部互相可达
（可达集恰为 9!/2 = 181440 个）——所以偶数判据既是必要条件也是充分
条件，搜索前一次 O(9²) 过滤即可。

### 独立对账：IDA*

BFS 的正确性可以靠「无权图 BFS 必出最短路」这句话本身，但示例仍安排一个
算法上完全独立的对账：**IDA\* **。启发式 h = 每个数字到它目标位置的
曼哈顿距离之和。每一步至多让一个数字接近目标 1 格，故 h ≤ 实际剩余步数
（可采纳性）。迭代加深 DFS 以 h 剪枝，第一次到达目标的深度必然是最短
长度——它与 BFS 的代码路径没有任何共享。

### 复杂度与实测

显式图规模上界 9! 个顶点、每点至多 4 条边：整层 BFS O(9!)。示例对一个
从目标退步 6 步的确定初态打印完整解路径（逐步核对相邻格局恰差一次合法
交换）、对 1/2 对调的不可解例验证奇偶过滤、500 个退步 1..22 步的随机例
上 BFS 距离与 IDA* 距离 0 例不一致；大例取已知最远格局之一，BFS 给出
31 步并登记全部 181440 个可达格局。

## n 皇后：逐行回溯与三个冲突集合

n×n 棋盘上放 n 个皇后，使任意两个不同行、不同列、也不在同一条斜线上。
求所有摆法（或只要找到一个）。

### 每行恰好一个：候选空间从 nⁿ 缩到 n!

逐行放置：第 r 行的皇后选第 c 列。由于每行只放一个，「不同行」自动满足，
需要维护的冲突只有两类：

- **列冲突**：第 c 列已有皇后；
- **斜线冲突**：过格子 (r,c) 有两条斜线。主对角线（左上—右下）上所有格子
  r−c 相同，取值范围 −(n−1)..n−1，加偏移 n−1 后得下标 r−c+n−1；副对角线
  （右上—左下）上 r+c 相同，下标 r+c。

三个布尔集合 `used_col[c]`、`used_d1[r−c+n−1]`、`used_d2[r+c]` 各占一次
检查与一次置位/复位。回溯骨架：

```
dfs(row):
  对每个未被三个集合封锁的列 c：
      置位 → 放皇后 → dfs(row+1) → 取皇后 → 复位
  row == n：找到一个完整摆法
```

候选空间因此不是 nⁿ（每格独立放），而是列号的排列 n!；斜线检查再从 n! 中
剪掉大部分——n=8 时回溯实际访问的「部分摆法」节点仅 1965 个（示例打印
了该数），约为排列空间 40320 的 1/20，而完整摆法只有 92 个。

### 正确性与解数

任何完整摆法恰好经过搜索树的一片叶子，任何被剪掉的分支都确实存在一对互相
攻击的皇后——不漏解、也不产生伪解。n = 1..10 的解数是

```
1, 0, 0, 2, 10, 4, 40, 92, 352, 724
```

n=2、3 无解（搜索树全被剪光，解数 0、首方案为空）。

### 独立对账：n! 排列全枚举

示例另写一个与回溯零共享的口径：枚举列号的全部 n! 个排列（每行皇后的列
号），对每对皇后直接算 `|列差| == 行差` 判定斜线。n≤8 两口径解数逐一断
言相等；n=24 的大例只取第一个解（`stop_at_first`），再独立做逐对合法性
复核——注意 n=24 若统计全部解数代价过大，大例不参与计数。

## 地图着色：按顶点回溯

给定无向图 G = (V,E) 和 k 种颜色，给每个顶点分配一种颜色，使每条边两端
异色——求合法着色（也称 **k-着色**）并统计方案数。这个问题是「判断图的
色数 ≤ k」的计数版本；本节处理小规模全枚举，第 35 章会说明判定版本在
一般 k 上的 NP 完全性。

### 按顶点固定颜色

顶点编号 0..n−1，逐个确定颜色 `colors[v]`。顶点 v 尝试颜色 c 时，只检查
**已经着色的邻点**：

```
dfs(v):
  对每种颜色 c = 0..k−1：
      若没有邻点 u 使 colors[u] == c：colors[v]=c → dfs(v+1) → 复位
  v == n：找到一个合法着色
```

未着色的顶点之间将来如何不冲突，交给递归——与 n 皇后同一套回溯范式，只
是「合法性判据」从三个全局集合换成邻接表扫描。搜索空间 kⁿ 在第一层冲突时
即被整片剪枝。

### 两个能手算的结构

- **三角形**（三个顶点两两相邻）的 k 色方案：第一个顶点 k 种，第二个避开
  它 k−1 种，第三个避开前两个 k−2 种，共 k(k−1)(k−2)——2 色时为 0，
  3 色时为 6。再挂一个只与三角形一个顶点相邻的顶点，方案数乘 k−1：
  k=3 时共 12，示例固定例直接断言此数；
- **n 个顶点的环 Cₙ**：k 色方案数为色多项式 (k−1)ⁿ + (−1)ⁿ(k−1)。偶数环
  2 色恰有 2 种（两种交替方式）；奇数环 2 色为 0。示例大例取 C₁₂₀：2 色
  计数得 2；3 色总数约 2¹²⁰ 既数不完也超出 long long，只核对第一个着色的
  逐边合法性。

### 独立对账：kⁿ 颜色串

示例把全部 kⁿ 个颜色串编码成 n 位 k 进制数（`code` 反复取模/整除展开），
对每条边独立检查两端异色。1500 个随机小图（n=2..8，边概率 20%–70%，
k=2..4）上回溯计数与该暴力计数 0 例不一致。

## 点双连通分支：Tarjan 边栈

无向图去掉所有桥后按连通性得到的是**边双连通分支**（分支之间不共享
顶点）；本节处理另一种更细的分解——**点双连通分支**（vertex-biconnected
component，简称 BCC，也称**块**）：

> BCC 是边的极大集合，其中任意两条边都同处在某条简单环上。

等价说法：一个 BCC 内部没有割点，删掉其中任何一个顶点，块内其余边仍
连通。各 BCC 之间**至多共享一个顶点**，而这个共享点恰好就是割点；单边
BCC（两条边环都成不了）恰好是一座桥。把每个 BCC 和每个割点都当成
节点、割点属于哪个 BCC 就连边，得到一棵**块割树**（block-cut tree）——
图的「环结构」全在 BCC 节点里，树边全是割接关系。

### 边栈三条规则

在 23.6 的 Tarjan 骨架之外再加一个**边 id 栈**，全部规则只有三条：

1. **树边入栈**：发现新孩子、压入树边 (u,v)；
2. **回边入栈一次**：扫到指向祖先的边（`d[v] < d[u]`）时压入——必须
   从子孙这一侧判，否则同一条无向边会进栈两次；
3. **弹栈成块**：孩子 v 回溯到 u 且 `low[v] ≥ d[u]` 时，从栈顶一直弹
   到 v 的父边（含），弹出的边构成一个 BCC。根的每个孩子都照此处理。

规则 3 与 23.6 的割点判定是**同一个时机**：`low[v] ≥ d[u]` 意味着 v 的
子树没有任何边能绕回 u 的祖先——u 把这棵子树与图的其余部分割开，栈中
从父边往上攒下的边，正是由子树内部的环互相拴住的极大边集。

### 对账口径

- **边不重不漏**：每条边恰好出现在一个 BCC 里（边栈每条边入一次、
  出一次）；
- **共享点即割点**：属于 ≥2 个 BCC 的顶点集合，与 23.6 独立实现的
  `tarjanBcc` 给出的割点集合逐个相等；
- **单边块即桥**：只有一条边的 BCC 数等于桥数，且每条这样的边都被判
  为桥。

### 迭代实现：边栈也不能放在调用栈上

DFS 仍沿用显式顶点栈 + 邻接表游标的写法（23.6 的模式），边栈本身用

## 色多项式：删边–收缩递推

n 种化学产品、x 间储藏室、不兼容者必须分室——安全配置的方式数记
P(G,x)。这个计数对任意 x 都成立，且**是 x 的多项式**：无边的 n 点图
方案数是 xⁿ；完全图 K_n 是 x(x−1)⋯(x−n+1)；三角形是 x³−3x²+2k…
即 x³−3x²+2x。P(G,k) 同时回答两个问题：

- P(G,0) = 0（没有颜色必然无解）；
- 色数 χ(G) = 最小的使 P(G,k) > 0 的正整数 k。

### 删边–收缩（fundamental reduction）

对图 G 的任一边 e = (u,v)，全部 k 着色按「u、v 是否同色」划分：

> **P(G,k) = P(G−e,k) − P(G/e,k)**

- G−e（删边）：u、v 不再约束，着色数 = G 的着色数 + 同色的着色数；
- G/e（收缩）：把 u、v 合并成一个顶点（邻接取并，可能产生重边与
  自环）——每个「u、v 同色」的 G−e 着色与 G/e 的着色一一对应。

右边两项都比 G 少一条边（收缩还会少一个顶点），递推必然终结于无边
图（答案 kⁿ）。两个已知闭式：树 P = k(k−1)^{n−1}；环
P(Cₙ) = (k−1)ⁿ + (−1)ⁿ(k−1)。

### 记忆化与两个必须处理的退化

朴素递归是指数级——同构子图（顶点数与边集都相同的图）会被反复求
解。把**规范化边集**（每条边小端在前、整体排序）连同 n 拼成字符串
当键做记忆化，收缩产生的图沿递推自然到达小图，规模骤减。收缩时：

1. **自环直接丢弃**：e=(u,v) 收缩后 u 侧的邻边 (u,v) 变成 (u,u)——
   自环意味着「合并点与自己不兼容」，该着色分支数为 0？不——丢弃
   自环即可（收缩语境下它只来自被合并的那条边本身）；
2. **重边合并成一条**：两条平行边约束同色，等价于一条；
3. **下标压缩**：被并掉的顶点 v 消失，大于 v 的编号整体减一，否则
   后续递归会引用到不存在的顶点。

## C++23 语言点

## 坑位清单

1. **转写图的边集漏边**
   （现象：BFS 距离场与书上答案对不上（v=1 被算成 2）；原因：手抄
   11 条边漏了 s–v；后果：后续所有对账全歪；对策：边数断言
   （Σdeg = 2|E|）+ 距离场与已知答案逐点 assert——本例实测翻车。）
2. **无向 DFS 把「回到父亲」记成后向边**
   （现象：后向边数 = 11 而非 4，「图有环」的判定失效；原因：树边
   的反向弧从孩子侧看到灰色父节点；后果：环检测误报；对策：分类时
   跳过 `v == parent[u]`，黑色相遇去重——本例修正后的写法。）
3. **Kahn 摘完不检查剩余**
   （现象：有环图也输出了「拓扑序」（短一截）；原因：剩余点入度皆
   > 0 时循环提前结束，没报错；后果：环图被当 DAG 用，下游崩；对策：
   `assert(order.size() == n)`——摘不完就是有环（本例写法）。）
4. **SCC 忘了在转置图上跑第二遍**
   （现象：第二遍直接在原图 DFS，得到的「分量」大小不对；原因：
   Kosaraju 的正确性依赖转置（汇变源）；后果：分量划分错乱；对策：
   构造 radj 的循环单独写，并断言分量数/成员与手工答案一致。）
5. **BFS 队列重复入队**
   （现象：同一顶点多次处理、复杂度翻倍；原因：入队判据写在出队后
   而不是发现时；对策：**发现即入队**（灰白判据在 push 前查 dist），
   白才进队——这是 BFS 不重复的关键不变式。）
6. **判父边用「父顶点相等」而不是边 id**
   （现象：0-1 之间有两条平行边时，非桥边被误判成桥（本例 1 条桥报成 2 条）；
   原因：`if (v == parent[u]) continue;` 把那条**平行边**也当成父边丢掉了，
   本该起作用的回边没进 `low`；对策：邻接表存 `(to, id)`、记 `parentEdge[v]`、
   判父边用 `id == parentEdge[u]`。**一般化：「顶点颜色 / 父顶点」不能代替
   「这条边是否已用」**——flood fill 用字符就地标记、欧拉与桥用边 id + `used[]`、
   Tarjan 用颜色 + `low[]`，判据必须与对象类型匹配，否则在重边 / 需走两次的图上必错。）
7. **割点用 ≥、桥用 >，差一个重边判断**
   （现象：桥数偏多或割点漏判；原因：`low[v] = d[u]` 这个边界值同时满足
   「不成桥」（有回边到 u，成环）与「是割点」（回不到 u 的严格祖先）；
   对策：非根 u 是割点 ⟺ ∃ 树孩子 w 使 `low[w] ≥ d[u]`；树边 (u,v) 是桥 ⟺
   `low[v] > d[u]`。又因为无重边图里恒有 `low[v] ≤ d[v]`，有人会把桥的条件
   改写成 `≥`——**这个改写在有重边时不成立**。）
8. **「(u,v) 平行边总数 num[v] = 1」是错的补丁**
   （现象：合法的桥被判成非桥；原因：`num[v]` 是 **v 的平行边总数**，
   不是 (v,t) 之间的边数——v 上挂着别处的平行边就会误判；对策：记
   `(v,t)` 之间的边数 `e_cnt`，判据 `low[v] > d[t] && e_cnt == 1`；
   更稳妥的是直接用边 id，重边自然被正确处理为非桥。）
9. **递归 DFS 在 n = 10⁵ 的链上爆栈**
   （现象：小图全对、十万级图直接崩或莫名超时；原因：递归深度 = DFS 树深度，
   每帧几十字节，8 MB 栈约容 10⁵ 帧；对策：显式栈 + 游标 `cur[]` 模拟回溯——
   `cur[u]` 记邻域扫到第几项，扫完就做递归 `return` 该做的事（low 往父亲合并 +
   判割点/桥）再弹栈。本例 16 万顶点网格实测通过。）
10. **欧拉回路写成「一路走到卡死」**
   （现象：输出的边序列只覆盖一部分边就停了，且相邻元素之间可能根本没有边；
   原因：贪心走法在**有桥的图**上必然半途失败（走到桥头就无路可走），
   而且弹栈补录的时机完全缺失；对策：Hierholzer 用**显式栈 + 逆序出栈**——
   走不动就弹栈记账、最后整体反转，子回路由此拼成大回路。
   若坚持 DFS 写法，守卫必须是 `if (used[e]) continue;`（按边 id 判已用），
   用「v 是白点吗 / v ≠ π[u] 吗」这类**顶点**判据必错：
   与 u 相邻且非 u 父亲的顶点要么是祖先（GRAY）、要么是后代（已完成访问），
   对后者那条边在 v 的递归里已被消耗，外层迭代仍会走到它，于是会再插一次
   「瞬移到 v 再瞬移回 u」的**假移动**。）
11. **先建图再跑图算法，复合掉 Θ(n²) 建图开销**
   （现象：网格连通块在 8 万个 `*` 上超时（两两判相邻要 6.4×10⁹ 次比较）；
   原因：把「状态」先编号成点再两两枚举建边，建图本身就是 Θ(n²)；
   对策：直接在网格上迭代 DFS/BFS，**in-place 把访问过的格标记掉**，
   每格只入栈一次 ⟹ Θ(WH)。本例 400×400 网格实测：入栈 160000 次，
   而建图路线要 1.28×10¹⁰ 次比较——**六个数量级的差距**。
   同一模式在棋盘最短路、隐式状态空间上反复出现。）
12. **环检测的 Floyd 第三步把两个指针一起复位**
   （现象：求 μ 的循环永不终止（或 μ 恒为 0）；原因：相遇后 `slow` 复位到 x_0 时
   若 `fast` 也被复位，两个指针就同起同落，永远追不上；正确写法是
   **fast 留在相遇点、slow 复位到 x_0，两者都走一步**；
   另外第一步里 fast 必须走**两步**（写成 `fast = f(fast)` 就退化成两个同速指针，
   同样永不相遇）。求 λ 的计数器从 0 起、每移一次自增——从 1 起会多算一格。）
13. **相邻交换式贪心换碟**
   （现象：换碟次数系统性偏小；原因：局部交换只调整一次，
   交换后新产生的跨碟相邻对没有再检查，需要反复扫描且终止性不保证；
   对策：改用**闭包贪心**「当前介质上还有可装包就继续装，没有才换碟」——
   换碟只发生在「当前碟无可执行任务」时，此时**任何方案都不得不换**，
   贪心给出下界故最优；实现上 Kahn 过程中每条边只处理一次 ⟹ O(V+E)。）
14. **枚举全部拓扑排序时字典序没保证**
   （现象：输出顺序不是字典序；原因：把变量按输入顺序而非编号升序塞进候选集；
   对策：`for i` **升序** + 深度优先 ⟹ 输出天然字典序，无需事后排序。
   可行性判据用位掩码 `pre[i] & ~mask == 0` 精确表达「所有前驱都已输出」。）
15. **「无割点 ⟹ 所有顶点在同一个环上」是错的**
   （现象：分离对计数漏解；原因：2-连通图不必有哈密顿回路——
   反例 K_{2,3}：无割点、2-连通，却没有哈密顿回路，所以「枚举环上不相邻点对」
   在它身上直接漏掉 {两側} 这一对；对策：改用**完全标准的割点判据**——
   `{u,v}` 可分离 ⟺ v 是 `G−u` 中的割点（u 非割点时 G−u 连通，两条件等价），
   枚举 u 各跑一次 Tarjan 再除以 2。）
16. **割点对计数公式 m·n − m(m+1)/2 漏掉叶子例外**
   （现象：本例公式给 15、暴力枚举给 14，多算了 `{5,6}`；原因：6 是挂在割点 5 上的
   叶子，摘掉 5 把它隔离了、再摘掉 6 隔离就白做了，`G−{5,6}` 反而连通；
   对策：修正为 `m·(n−1) − C(m,2) − |L|`，其中 L = {度为 1 且唯一邻居是割点的顶点}，
   并**断言与 O(n²(n+m)) 的暴力枚举对账**——公式类结论必须有一份独立实现兜底。）
17. **把握手定理的奇偶判据当充要条件**
   （现象：聚会游戏里度数和为偶就答「真」，在 {2,2,0,0} 这类序列上误判；
   原因：Σ度 = 2|E| 只给你「非图序列必无奇和」，逆命题不成立——偶和序列
   仍可能不可图；后果：把「Maybe truth」错答成「Maybe」以外的断言；
   对策：需要判定时上 Havel–Hakimi（贪心消解最大度），输出措辞保持
   「必要/充分」的层次。）
18. **数学构造法只枚举「整齐」的方案（六方案找牛妞）**
   （现象：六方案公式对原书自带的样例 N=3, K=21 就给出 6，真值 5
   （3→4→5→10→20→21）；N=15, K=100 处差距更大（6 vs 23）；原因：方案
   枚举假设「起飞点在 2 的幂附近」，但「走回任意点再飞」（甚至飞过头
   退一格再飞）常更优；后果：样例级的巧合掩盖系统性漏解——2.2 万组
   对账 7595 组不一致；对策：状态转移明确的问题先写 BFS 拿精确解，
   数学法要么拿 BFS 当裁判，要么证明自己的方案族完备。）
19. **隐式图 BFS 的状态范围裁剪错**
   （现象：数轴 BFS 越过 100000 后数组越界，或裁得太狠漏解；原因：×2
   的转移会把状态推到 2×10⁵，而题面域是 [0, 100000]；后果：越界 UB 或
   「不可能到达」；对策：显式写下「为什么边界裁剪不丢最优解」（K ≤ 100000
   时飞到 >100000 的点再折返必不优于在 ≤100000 内可达的镜像方案），并让
   转移函数集中检查 `0 ≤ w ≤ kMaxP`。）
20. **旅程把「每次去最近目标」当最优算法**
    （现象：样例 2 上输出 9、正解 8；分叉反例上 110 对 106；原因：
    就近选择只在当前一步最短，可能逼出横穿与整条深入的叠加——树上
    覆盖没有就近最优性；对策：用连接子树公式 2W − 最远目标距离，
    贪心保留仅作对照。）
21. **旅程的 needed 传播顺序错，或把无关节点的边计入 W**
    （现象：W 漏边或少边，答案整体偏移；原因：父节点的结论依赖全部
    孩子——必须按遍历序**逆序**计算；边只在「子树含目标」时计入，
    通往不带目标分支的边不该算；对策：一遍逆序传播 + needed 父边
    才累加，并用删边 BFS 可达性在小例上独立核对 W。）
22. **循序用「直接计数位置区间 + 只查重复」**
    （现象：链 a<b<c<d 上输出 acbd；原因：入度/出度是直接计数、不是
    传递闭包，且叶子没有约束终检；对策：回溯判据用「pre[v] ⊆ used」，
    并在样例链上保留区间法的对照输出专门钉住这个错误。）
23. **循序候选不按升序尝试，或变量是字母表非连续子集时不做映射**
    （现象：输出集合对、但顺序不是字典序；或下标按字母 ASCII 取值
    导致掩码位数与数组错位；对策：候选 v 严格升序遍历，先把变量行
    排序、建立字母→0 基索引映射，关系与输出都走映射。）
24. **围墙只封边、漏封，或真实格的 (+1,+1) 偏移写错**
    （现象：邻居扩展走出数组、或距离值对错了格子；原因：围墙要求
    四行四列全部 −2（含四角），且代码中每个真实坐标访问都带 +1
    偏移——漏一处围墙技巧就失效；对策：先把围墙六条赋值写全，再
    用"走到紧贴边界"的小例检查绝不越界。）
25. **逆向重建时判据写成「距离更小」而非「恰小 1」**
    （现象：路径跳上封锁格/未访问格，或重建死循环；原因：−2、−1
    都"更小"但不可通行；对策：严格判 `dist == dcur−1`，重建后对
    相邻两格做曼哈顿距离 =1 断言，并断言路径首尾恰为 s、e。）
26. **不可达时不判 target<0，逆向重建直接开跑**
    （现象：从 −1 开始找 −2 邻居，死循环或返回伪路径；对策：
    BFS 结束先看 e 的标号，负值即返回空路径，由调用方断言
    "不可达 ⟺ 路径为空"；重建循环也要有"必能回到 s"的断言保护。）
27. **用 DFS 第一次走到 e 的路径当最短布线**
    （现象：路径明显绕远；原因：DFS 不按距离层次扩展，首次到达
    不保证最短——无权最短路是 BFS 的专属；对策：BFS 求距离场；
    随机障碍板与 Floyd-Warshall 对账能立即抓出 DFS 路径偏长。）
28. **状态编码碰撞（位数不够/解码越界）**
    （现象：两个不同棋盘被当成同一格局，路径张冠李戴；原因：每格 4 位
    可表示 0..8 共 9 个值恰好够，9 格共需 36 位——必须用 uint64；用
    base-9 编码时 9⁹ = 387,420,489 勉强装进 int32 但留不出余量；
    对策：编码用 uint64 并在解码掩码处取 0xF，最小写一组双格局断言。）
29. **跳过逆序对判据，不可解例靠 BFS 超时**
    （现象：不可解输入让搜索遍历 9! 个格局才返回，线上表现为 TLE；
    原因：不可解集占全部排列的一半，奇偶判据 O(9²) 即可滤掉；注意
    竖直交换的逆序对改变数必为偶数（跨两位），这才是奇偶守恒的根据；
    对策：搜索前先判逆序对奇偶，并保留「偶数 ⟹ 必可达」的认知
    （可达集恰 9!/2）。）
30. **IDA* 启发式忘记除以「每步移动一个数字」的口径**
    （现象：IDA* 给出的长度比 BFS 大，或启发式不可采纳；原因：曼哈顿
    和是「每步至多减少 1」的下界——若误把行列距离加权（如竖直代价 2）
    而问题里竖直移动仍只算 1 步，h 就可能超过真实剩余步数，最优解被
    剪掉；对策：启发式必须与问题的步数口径一致，用 BFS 在随机例上对账
    距离而不只是「能找到解」。）
31. **皇后斜线数组下标算成 r+c 与 r−c 却忘记偏移与宽度**
    （现象：r−c 为负时下标越界，或两个方向数组大小只开 n（应 2n−1）；
    原因：主对角下标 r−c+n−1 取 0..2n−2；漏偏移直接 UB，且越界数据多半
    不会当场崩，而是读到邻接内存的标记产生伪剪枝；对策：三个集合的大小
    与下标表达式成对写，先在 n=4 上逐格打印下标核对，再与 n! 排列口径
    对账。）
32. **回溯复位时把 place/colors 清成 0 而非 −1**
    （现象：偶发剪枝错误或恢复出的方案里出现非法 0 号；原因：−1 表示
    「未着色/未放置」，0 是合法颜色与合法列号；后果：下一分支检查已着色
    邻点时把未放置的行误判为颜色 0；对策：置位/复位严格对称，复位回到
    与初始化相同的哨兵值，并在每轮递归返回后断言哨兵已恢复。）
33. **只数解数不验内容，n=24 大例试图全计数**
    （现象：大例跑不完，或「解数对但方案非法」无人发现；原因：解数随 n
    增长极快（n 皇后序列 724,2680,14200,…），大例必须 `stop_at_first`，
    而只取一解时计数没被核对，合法性要靠逐对独立复核兜底；对策：计数
    断言只在小例（n≤10）做，大例打印节点数并独立检查列互异与斜线。）
34. **着色检查邻点时把未着色顶点的 −1 与颜色混判**
    （现象：颜色 0 永远放不下去，或所有颜色都被认为冲突；原因：冲突检查
    必须是 `colors[u] == c`——若先把哨兵写成 0，则第一个顶点就放不了
    颜色 0；另一种翻车是遍历了全部邻点（含未着色者）却只比较大小关系；
    对策：哨兵用 −1、判等比较，固定例第一步先断言顶点 0 能取到颜色 0。）
35. **环 Cₙ 的方向边重复加入邻接表造成邻接点被检查两次**
    （现象：计数意外翻倍或节点数偏大；原因：环上每条边从两端各 push 一次
    是正确的无向图表示，但用 `i→i+1` 循环时最后一条闭合边 (n−1,0) 若在
    两个方向都重复加入，邻接表里就出现重边——重边不改变合法着色数，但
    节点/检查次数统计失真，更危险的是在别处把重边误当多重边逻辑；对策：
    构造后断言每条边恰出现两次（每个端点各一次），随机对账以「计数相等」
    为准不以节点数为准。）
36. **把「计数全部着色」与「只要可着」两个问题用同一跑法**
    （现象：C120 的 3 色计数让程序跑不完——本教程实测 300 秒超时；原因：
    环的 3 色方案约 2¹²⁰ 个，全枚举即「无限」；判定「能否 k 着色」只需
    一片叶子，计数却要遍历全部叶子；对策：函数显式区分 `stop_at_first`，
    输出措辞区分「方案数」与「存在首方案」；大数计数前先估算答案是否
    装得进整数类型（色多项式）。）
37. **回边从两端各入栈一次（或一条都不入）**
    （现象：弹块时边对不上、边出现两次，或 BCC 缺边；原因：无向边
    (u,v) 在两端的邻接表里各出现一次，必须规定只有「子孙端见到祖先端」
    时入栈，判据 `d[v] < d[u]`——漏了判据则进两次，错写成 `d[v] > d[u]`
    则一次不进；对策：入栈语句紧跟祖先判定，随机例上做「每条边恰入一个
    BCC」的对账。）
38. **弹块停止条件写错（弹过头 / 弹不到父边）**
    （现象：BCC 混入别的环的边，或留下残余边最后乱成一块；原因：停止
    哨兵必须是孩子 v 的**父边 id**——`low[v] ≥ d[u]` 时边栈从父边到栈顶
    都属于这个块；用父子顶点对当哨兵会被重边/平行边击穿；对策：入栈的
    是边 id、比对的也是边 id，固定例逐块打印边表核对。）
39. **根收尾处理与孤立顶点想当然**
    （现象：根的多个孩子各自弹块后以为还会剩边，又补弹一次产生空块；
    或给孤立顶点硬造单点 BCC，导致「每条边恰入一块」的口径自相矛盾；
    原因：根孩子的弹栈条件 `low ≥ d[根]` 必然成立，正常情况下边栈已
    清空，残余兜底分支只防御非常态时序；BCC 是**边**的划分，孤立点
    无块；对策：兜底弹栈前先判栈非空，不为孤立点生成组件。）
40. **把点双与边双两套分解混为一谈**
    （现象：以为 BCC 互不相交，看到割点同时出现在两个 BCC 里以为是
    bug；原因：边双按「删桥后连通」划分**顶点**，互不重叠；点双划分
    **边**、在割点处重叠，重接关系构成块割树；对策：先报问题口径
    （删一点还是删一桥），再选分解算法。）
41. **收缩后的自环/重边没处理**
    （现象：递推出负数系数之外的怪值、或同一图不同键反复重算；原因：
    收缩 v 并入 u 时，原本 u、v 的公共邻居产生平行边，边 (u,v) 自身
    变成 (u,u) 自环；自环若保留会污染删边递推（自环图着色数为 0）；
    对策：收缩时跳过 x==y 的边、排序后 unique 去重——这两步正是
    「简单图范式」的全部。）
42. **记忆化键不含顶点数、或边表不规范化**
    （现象：不同的图命中同一条缓存、色多项式串味；原因：3 点无边图
    与 4 点无边图的键都是空边集；边 (2,1) 与 (1,2) 视为不同；对策：
    键 = to_string(n) + 全部规范化边（小端在前、字典序），构造入口
    make_poly_graph 统一做规范化。）
43. **多项式系数数组方向搞反（低次在头还是尾）**
    （现象：打印 k³−k² 变成 1 −1 0 0、求值结果全错；原因：vector
    下标＝次数的约定（poly[i] 是 k^i 系数）与「自高向低打印」的输出
    序相反；对策：Horner 求值从尾往头扫（v=v*k+p[i]），打印循环
    逆序遍历——两处方向都写死后，用手算闭式（三角形、4 环）断言。）
