5. 会用 `<version>` + `#if` 梯子做跨标准库的能力探测；

## 算法是什么

CLRS 的定义（p.5）：

> 算法是**定义良好的计算过程**：它取一个或一组值作为**输入**，并产生一个或一组
> 值作为**输出**。直白地说，算法就是把输入变换成输出的一个计算步骤的序列。

这个定义刻意宽泛——排序是算法，求最大公约数是算法，判断一个数是否素数也是
算法。但对每个算法我们都会追问同样两个问题：

- **正确吗？** 对每一个合法输入，它都在有限步内给出满足规格说明的输出。
  CLRS 用数学证明回答（第 2 章起你会看到循环不变式怎么写）；本教程每个示例
  里的 `assert` 是证明的"可执行抽样"——不代替证明，但能拦住低级错误。
- **多快、多省？** 运行时间与空间随输入规模 n 如何增长。这正是第 3 章渐近
  记号要形式化的东西。

CLRS 还强调：算法的**输入规模**、**运行时间的度量**要先说清楚。本教程统一约定：
输入规模记作 n，"代价"用**比较次数/交换次数/基本操作计数器**度量——不用墙上
时钟，原因见下文「确定性输出纪律」。

## 算法作为技术

CLRS §1.2 的核心论证：假设同样一台机器，插入排序处理 n 个元素约需 c₁·n² 次操作，
归并排序约需 c₂·n·lg n 次。常数上插入排序更小（c₁ < c₂），但增长速度上归并
完胜——**n 大到一定程度，n² 与 n·lg n 的差距任何常数与硬件都追不回来**。

这就是「算法作为技术」的含义：系统性能 = 硬件 × 编译器 × **算法**，三者是同一
层面的技术选型。举 CLRS 的例子：现代计算机每秒 10⁹ 次操作，排序一亿个数——

- 插入排序：10⁸ 平方 ≈ 10¹⁶ 次操作 ≈ 10⁷ 秒 ≈ **116 天**；
- 归并排序：10⁸·lg(10⁸) ≈ 2.7×10⁹ 次操作 ≈ 3 秒。

买快 10 倍的机器，插入排序还要 11.6 天；换一个算法，只要 3 秒。第 34–36 章会
把这条逻辑推到极限：有些问题被认为**不存在**多项式时间算法（NP 完全），此时
「近似到什么程度」本身成为算法设计的目标。

本教程示例 01.4 用**比较次数**把这件事做成了可复现的实验（n = 2048 逆序输入）：

```
n=2048（lg n=11）：插入排序最坏比较 2096128（理论 n(n-1)/2=2096128）
n=2048：归并排序比较 11264（~n·lg n=22528）
比值 插入/归并 = 186.09
```

插入排序的 2,096,128 恰好等于 n(n−1)/2——这不是巧合，第 2 章会证明它就是最坏
情况的精确值；归并排序的 11,264 落在理论界 n·lg n = 22,528 的一半附近，第 2 章
同样会算出它的精确来源。**比值 186 倍**：这就是同一台机器上纯算法选型的差距。

`std::__open_terminal` 终端符号，**编译能过、链接必挂**——于是该通道自动带上
`-DALGO_NO_PRINT` 降级宏继续参赛（教程所有示例顶部都有一段 10 行 IO 垫片兜底）：

```cpp
#ifdef ALGO_NO_PRINT // MinGW libstdc++ 缺 std::__open_terminal 符号时的降级（build.ps1 探针注入）
#include <cstdio>
#include <format>
template <class... A> void print(std::format_string<A...> f, A&&... a) {
    std::printf("%s", std::format(f, std::forward<A>(a)...).c_str()); }
template <class... A> void println(std::format_string<A...> f, A&&... a) {
    std::printf("%s\n", std::format(f, std::forward<A>(a)...).c_str()); }

using std::println;
#endif
```

看到的每一行输出，都是机器从当前二进制里重新长出来验证过的。

## 确定性输出纪律

三通道逐字节一致是硬约束，它逼出四条纪律（每条背后都是一次真实翻车）：

1. **计数器代替计时**：耗时跨机器/跨通道不可复现；比较次数是纯逻辑量。
   插入排序在逆序输入上的比较次数恒为 n(n−1)/2，无论谁编译。
2. **`rand_below` 代替 `uniform_int_distribution`**：`std::mt19937` 的输出由
   标准逐位规定（三家实现完全相同），但 `uniform_int_distribution` 的**分布
   算法未规定**——MSVC 与 libstdc++ 用同一种子给出不同序列。本教程用 Lemire
   乘法-移位法自造无偏取整：

   ```cpp
   static std::uint32_t rand_below(std::mt19937& rng, std::uint32_t n) {
       std::uint64_t m = static_cast<std::uint64_t>(rng()) * n; // [0, n·2^32)
       return static_cast<std::uint32_t>(m >> 32);              // [0, n)
   }
   ```

   种子固定 5489（对齐 datastruct 教程惯例）。第 5 章会专门讲随机与偏倚。
3. **浮点定点化**：不打印裸浮点（尾数实现可异），打 `"{:.6f}"` 定点值 +
   容差布尔（`|x−期望|<1e-9`）。第 29–31 章的数值章节全程整数例题。
4. **不遍历打印 unordered 容器**：哈希序跨实现不同。散列章（11）的高压线，
   打印前排序或改用 `std::map`。

## 算法代码的工程标准

前五节讲的是"怎么让算法可验证"。这一节讲另一件同样决定成败、却在算法书
里几乎不提的事：**算法代码本身怎么写才配得上十年后的维护者**。三件事：
资源管理、错误处理、防御性编程的分工。

### ① RAII 与 copy-and-swap：赋值运算符的唯一正确姿势

手写 `operator=` 要同时处理四件事，而它们的**顺序**决定了对错：

| 朴素写法 | 出错时机 | 后果 |
|---|---|---|
| 先 `delete` 旧资源，再拷贝新的 | 新拷贝抛异常时 | 对象已被掏空（空指针/野指针） |
| 不写 `if (this != &other)` | `a = a` 自赋值 | 刚 `delete` 掉自己又读已释放内存 |
| 边释放边拷贝 | 中途抛异常 | 成员处于半修改状态（连**基本安全保证**都违反） |

`copy-and-swap` 把三件事一次性消掉：**参数按值收**（先构造一份临时对象），
拿它与 `*this` 交换。于是"怎么造新内存"全归拷贝构造管，`operator=` 只剩
一次**不会失败**的 `swap`：

```cpp
Buffer& operator=(Buffer other) noexcept {   // 按值收，不是 const&
    tag_.swap(other.tag_);
    return *this;
}
```

顺带免费得到两样东西：

- **自赋值天然正确**——临时对象已经持有了副本，`a = a` 走的路径和 `a = b`
  完全一样，不需要任何特判；
- **整个函数是 `noexcept`**——因为 `swap` 不抛，赋值可以参与 vector 的
  `noexcept` 优化（`std::vector` 扩容时若搬移不抛就不会逐个拷贝）。

代价正是上面那次**多余的拷贝**（示例实测：恰好触发 1 次拷贝构造、
0 次搬移构造——因为按值收参时源是 ，编译器只能拷贝）
加一次交换。现代编译器在源是非 const 右值时能消掉这个拷贝
（"implicit move from by-value parameter"），但在算法代码里这个代价几乎
永远可以忽略——**正确性优先于这一次拷贝**。

有一个容易踩的细节：**不要**再补一个 `operator=(const Buffer&) = delete`
来"禁止更弱的赋值"。按值收参的版本已经能接住 `const` 实参，多一个重载会
造成**歧义**（两个候选互不占优，编译器直接报错——本教程实测踩到）。

C++11 起 `std::string`/`std::vector` 这类标准类型都自带
`noexcept` 的 copy-and-swap，所以这个模式只在自定义类型时需要手写。

### ② `std::expected`：失败是返回值的一部分

算法代码里的"输入不合法"是**常态而非意外**：二分的区间反了、图的邻接表
为空、用户传了 `"abc"`。用异常表达它是错配——调用点必须写 `try`/`catch`，
忘了就编译不过还好，忘了在某个分支就静默漏掉。

C++23 的 `std::expected<T, E>` 把失败做成返回值的一部分：

```cpp
std::expected<int, std::string> parse_int(std::string_view sv);
// 返回成功：return 42;            （隐式构造 expected<int,...>）
// 返回失败：return std::unexpected("空输入");
```

调用点的形态：

```cpp
if (auto r = parse_int(s)) { use(*r); }        // 成功
else { log(r.error()); }                      // 失败：拿到错误对象
```

三种取值方式各有用途：`.value()` 失败会抛 `bad_expected_access`（调试期
快速暴露漏掉的分支）、`.value_or(x)` 给默认值、`*r` / `r.has_value()`
则要求你先判。

相比异常的好处有两个：失败路径**无法被静默忽略**（配合 `[[nodiscard]]`
连编译器都会拦），以及没有 `try`/`catch` 的运行时开销，也没有异常跨
边界时的栈展开成本——跨 ABI 边界的调用用异常还有 ABI 兼容问题。

它是 `std::optional<T>` 的"带原因"版本：当你需要区分"没有值"和"出错了，
错误是这个"时用它。

### ③ 防御性编程的三种形态，别混用

| 形态 | 用于 | 违反时| 成本 |
|---|---|---|---|
| `assert` | **程序员之间的契约**（这不该发生） | 终止 + 保留现场 | 零（NDEBUG 下消失） |
| 异常 | **调用方违约**（外部输入、网络、文件） | 可恢复 / 可传播 | 栈展开（较贵） |
| 返回值 | **正常业务分支**（没找到、二分失败） | 无 | 零 |

三者的边界经常被搞错，最典型的两个错误是：

1. **用异常表达"没找到"**。"没找到"不是错误，是二分查找的**正常分支**。
   用返回值或 `std::optional`。抛出异常会让调用方不得不写 `catch`，
   而其中 99% 的分支只是想继续往下走。（本教程第 04 章的 `bin_search`
   就返回下标、`npos` 表示未命中。）
2. **用 `assert` 检查用户输入**。`assert` 在 `NDEBUG` 下会被完全编译掉，
   拿它守外部数据等于不设防。守外部数据要么返回错误、要么抛异常。

判断口径很简单：**这个条件不成立时，谁能修？** 调用方能修 → 异常或返回值；
只有程序员能修（说明代码写错了）→ 断言。

## C++23 语言点（本节新增）

- `std::expected<T,E>` / `std::unexpected`（`<expected>`，C++23）；
- `operator=(T)` 按值收参 + `noexcept` 的 copy-and-swap 惯用法；
- `[[nodiscard]]` 用于让"忘记处理失败"变成编译错误；
- RAII 与确定性析构：作用域结束即释放，不依赖 `delete` 的位置正确。

## 坑位清单（本节新增）

1. **按值收参的 `operator=` 旁边又加一个 `const&` 重载**
（现象：`a = b` 报"ambiguous overload"；原因：按值版本已能接住 `const`
实参，两个候选互不占优；后果：编译失败；对策：删掉多余重载——copy-and-swap
的按值版本已经是唯一入口。）
2. **copy-and-swap 里忘了 `noexcept`**
   （现象：`std::vector<Buffer>` 扩容时逐个拷贝而不是搬移，性能塌陷；
   原因：`noexcept` 缺失导致 vector 保守策略；后果：3~5 倍的扩容开销；
   对策：swap 不抛，就标 `noexcept`。）
3. **漏掉 copy-and-swap 后顺手加的 `if (this != &other)`**
   （现象：自赋值安全了，但拷贝构造的语义被改坏；原因：特判掩盖了根本
   问题——手写 operator= 的顺序错了；后果：代码仍然不是异常安全的；
   对策：回到 copy-and-swap，让特判自然变得不必要。）
4. **`assert` 守外部输入**
   （现象：Release 版（`-DNDEBUG`）下非法输入直接穿过去；原因：assert
   是契约不是校验；后果：崩溃点被推迟到别处；对策：外部输入走返回值/
   `std::expected`。）

   「程序员契约」还是「外部输入校验」，并列出所有用错地方的地方。

## 坑位清单

1. **`std::ranges::sort` 编译报「不是 std::ranges 的成员」**
   （现象：三通道齐红，错误指向 `<ranges>` 头；原因：算法住在 `<algorithm>`，
   `<ranges>` 只提供视图，视图与算法分家是 ranges 设计的刻意为之；后果：新手
   以为编译器坏了去乱动工具链；对策：`#include <algorithm>`，本示例第一版
   实测踩中。）
2. **特性宏「MSVC 有、g++ 无」的假象**
   （现象：同一个 `#ifdef __cpp_lib_print`，msvc/clang 通道报 1，gcc 通道报 0，
   而 `g++ -dM -E` 又说宏存在；原因：libstdc++ 把特性宏拆散在各头文件里，
   包哪个头只带出它自己的宏，MSVC STL 则是任意标准头给全集；后果：能力探测
   看起来像"实现缺失"，其实是"没请对头文件"；对策：探测前先
   `#include <version>`——它是特性宏的全家福。）
3. **MinGW libstdc++ 的 `<print>` 编译过、链接挂**
   （现象：undefined reference to `std::__open_terminal`；原因：MinGW 终端
   补丁的两个符号没进 libstdc++.dll；后果：教程若直接用 std::print，gcc 通道
   全灭；对策：build.ps1 两级探针注入 `-DALGO_NO_PRINT` + 示例顶部 IO 垫片，
   `std::format`+`printf` 与 `std::print` 字节流一致，对账不受影响。）
4. **打印特性宏的「数值」导致对账炸裂**
   （现象：msvc↔gcc 输出不一致；原因：同一特性宏的值可以不同——
   `__cpp_lib_ranges_zip` 一边 202207、一边 202110，数值是「版本进度」，
   布尔才是「有没有」；后果：逐字节对账失败且看似无解；对策：探测表只打
   0/1，宏值差异写进文档静态表。）
5. **无符号数 `assert(n > 0)` 触发 gcc `-Wextra` 告警**
   （现象：`warning: comparison of unsigned expression '> 0' is always true`；
   原因：-Wextra 含 -Wtype-limits，uint32_t 恒 ≥ 0；后果：零告警判定失败；
   对策：写 `assert(n != 0)`。）

=== 01.6 算法代码的工程标准 ===

  (1) RAII / copy-and-swap：赋值运算符的正确写法
      a = b 之后 a.tag() = beta-longer-string（拷贝构造 1 次、搬移构造 0 次）
      a = a（自赋值）后 a.tag() = beta-longer-string——未被破坏
      作用域结束时析构自动执行，无任何手动 delete
      手写版本的三个经典漏洞：
        (a) 先 delete 旧、再拷贝新 → 拷贝抛异常则对象已被掏空；
        (b) 漏掉 if (this != &other) → 自赋值时 delete 掉自己；
        (c) 边改边拷 → 中途抛异常，成员处于半修改状态。
      copy-and-swap 把三者一起消灭：operator= 只做一次 noexcept 的 swap。
      代价：多一次拷贝 + 一次交换（现代编译器下常常被优化掉）。

  (2) std::expected：失败是返回值的一部分，不是异常
      parse_int(42          ) = 42（成功）
      parse_int(-17         ) = -17（成功）
      parse_int(+8          ) = 8（成功）
      parse_int(abc         ) -> 失败：非法字符: a
      parse_int(            ) -> 失败：空输入
      parse_int(99999999999 ) -> 失败：超出 int32 范围
      好处：失败路径**无法被静默忽略**（可加 [[nodiscard]]）；
      且没有 try/catch 的运行时开销，也没有异常跨边界的栈展开代价。
      取值三式：.value()（失败则抛 bad_expected_access，调试用）、
      .value_or(x)（给默认）、*r / r.has_value()（先判再用）。

  (3) 防御性编程三形态：各管一段区间
      断言管「程序员违约」：push两次后 size = 2
      返回值管「正常分支」：找 5 得下标 2，找 4 得 true（= kNotFound）
      三者取舍：断言 = 程序员错（终止并留现场）、
      异常 = 调用方错（可恢复、可传播）、返回值 = 不是错（正常枚举）。
      最糟的混用是拿异常表达「没找到」——那本该是 optional 或下标；
      二分查找返回「没找到」是正常分支，不是异常（见第 04 章）。
自检通过
```
