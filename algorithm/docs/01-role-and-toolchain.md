## 学习目标

1. 能复述 CLRS 对算法的定义，并说出衡量算法的两个基本问题（正确性、效率）；
2. 能用具体数字解释「算法是一种技术」——同样的机器，插入排序与归并排序差多少；
3. 知道本教程三条编译通道、六条判定与逐字节对账的验证体系，以及为什么它重要；
4. 掌握本教程的确定性输出纪律（计数器代替计时、`rand_below` 代替
   `uniform_int_distribution`、浮点定点化），明白每条纪律背后的一次真实翻车；
5. 会用 `<version>` + `#if` 梯子做跨标准库的能力探测。

## 算法是什么

CLRS 的定义（p.5）：

> 算法是**定义良好的计算过程**：它取一个或一组值作为**输入**，并产生一个或一组
> 值作为**输出**。直白地说，算法就是把输入变换成输出的一个计算步骤的序列。

这个定义刻意宽泛——排序是算法，求最大公约数是算法，判断一个数是否素数也是
算法。但对每个算法我们都会追问同样两个问题：

- **正确吗？** 对每一个合法输入，它都在有限步内给出满足规格说明的输出。
  CLRS 用数学证明回答（第 2 章起你会看到循环不变式怎么写）；本教程每个示例
  里的 `assert` 是证明的"可执行抽样"——不代替证明，但能拦住低级错误。
- **多快、多省？** 运行时间与空间随输入规模 n 如何增长。这正是第 3 章渐近
  记号要形式化的东西。

CLRS 还强调：算法的**输入规模**、**运行时间的度量**要先说清楚。本教程统一约定：
输入规模记作 n，"代价"用**比较次数/交换次数/基本操作计数器**度量——不用墙上
时钟，原因见下文「确定性输出纪律」。

## 算法作为技术

CLRS §1.2 的核心论证：假设同样一台机器，插入排序处理 n 个元素约需 c₁·n² 次操作，
归并排序约需 c₂·n·lg n 次。常数上插入排序更小（c₁ < c₂），但增长速度上归并
完胜——**n 大到一定程度，n² 与 n·lg n 的差距任何常数与硬件都追不回来**。

这就是「算法作为技术」的含义：系统性能 = 硬件 × 编译器 × **算法**，三者是同一
层面的技术选型。举 CLRS 的例子：现代计算机每秒 10⁹ 次操作，排序一亿个数——

- 插入排序：10⁸ 平方 ≈ 10¹⁶ 次操作 ≈ 10⁷ 秒 ≈ **116 天**；
- 归并排序：10⁸·lg(10⁸) ≈ 2.7×10⁹ 次操作 ≈ 3 秒。

买快 10 倍的机器，插入排序还要 11.6 天；换一个算法，只要 3 秒。第 34–36 章会
把这条逻辑推到极限：有些问题被认为**不存在**多项式时间算法（NP 完全），此时
「近似到什么程度」本身成为算法设计的目标。

本教程示例 01.4 用**比较次数**把这件事做成了可复现的实验（n = 2048 逆序输入）：

```
n=2048（lg n=11）：插入排序最坏比较 2096128（理论 n(n-1)/2=2096128）
n=2048：归并排序比较 11264（~n·lg n=22528）
比值 插入/归并 = 186.09
```

插入排序的 2,096,128 恰好等于 n(n−1)/2——这不是巧合，第 2 章会证明它就是最坏
情况的精确值；归并排序的 11,264 落在理论界 n·lg n = 22,528 的一半附近，第 2 章
同样会算出它的精确来源。**比值 186 倍**：这就是同一台机器上纯算法选型的差距。

## 工具链与验证体系

本教程的每一段代码都在**三条编译通道**上验证（Windows 11 本机）：

| 通道 | 工具 | 角色 |
|---|---|---|
| msvc | MSVC cl，`/std:c++23 /EHsc /utf-8 /permissive- /Zc:__cplusplus /W4 /O2` | 主线 |
| clang | scoop clang++ 23（`-std=c++23 -Wall -Wextra -O2`，共享 MSVC STL、独立前端） | 交叉核对 |
| gcc | scoop MinGW g++ 15.2（`-std=c++23 -Wall -Wextra -O2 -pthread`，独立 libstdc++） | 独立标准库对照 |

每个示例在每条通道上要过**六条判定**（缺一不可）：退出码 0；stderr 为空（编译
期告警也算失败）；stdout 非空；无多余控制字符；含结束标记「自检通过」；编译
日志零告警。此外 msvc 的输出要与其他通道**逐字节一致**——这一条逼出了本教程
几乎全部的确定性纪律（见下）。

通道不是配好环境就完事。build.ps1 先用一个含 `<print>`、`views::zip/chunk_by`、
`<generator>` 的**探针程序**给每条通道做体检：MinGW g++ 15.2 的 libstdc++ 缺
`std::__open_terminal` 终端符号，**编译能过、链接必挂**——于是该通道自动带上
`-DALGO_NO_PRINT` 降级宏继续参赛（教程所有示例顶部都有一段 10 行 IO 垫片兜底）：

```cpp
#ifdef ALGO_NO_PRINT // MinGW libstdc++ 缺 std::__open_terminal 符号时的降级（build.ps1 探针注入）
#include <cstdio>
#include <format>
template <class... A> void print(std::format_string<A...> f, A&&... a) {
    std::printf("%s", std::format(f, std::forward<A>(a)...).c_str()); }
template <class... A> void println(std::format_string<A...> f, A&&... a) {
    std::printf("%s\n", std::format(f, std::forward<A>(a)...).c_str()); }
#else
#include <print>
using std::print;
using std::println;
#endif
```

`std::format` 与 `std::print` 对同一格式串产出逐字节相同的 UTF-8，所以垫片
**不破坏逐字节对账**——这段垫片不是将就，它本身是第 5 条坑位的活教材。

文档侧另有一道 `tools/check_docs.py` **五关核查**：章号与示例号一一对应、每章
` ```text ` 输出块能在示例**现场重跑**的产物里按**顺序敏感子序列**找到、坑位
清单 ≥3 条、链接与 CLRS 出处标注有效、README 导航齐全。也就是说：你在文档里
看到的每一行输出，都是机器从当前二进制里重新长出来验证过的。

## 确定性输出纪律

三通道逐字节一致是硬约束，它逼出四条纪律（每条背后都是一次真实翻车）：

1. **计数器代替计时**：耗时跨机器/跨通道不可复现；比较次数是纯逻辑量。
   插入排序在逆序输入上的比较次数恒为 n(n−1)/2，无论谁编译。
2. **`rand_below` 代替 `uniform_int_distribution`**：`std::mt19937` 的输出由
   标准逐位规定（三家实现完全相同），但 `uniform_int_distribution` 的**分布
   算法未规定**——MSVC 与 libstdc++ 用同一种子给出不同序列。本教程用 Lemire
   乘法-移位法自造无偏取整：

   ```cpp
   static std::uint32_t rand_below(std::mt19937& rng, std::uint32_t n) {
       std::uint64_t m = static_cast<std::uint64_t>(rng()) * n; // [0, n·2^32)
       return static_cast<std::uint32_t>(m >> 32);              // [0, n)
   }
   ```

   种子固定 5489（对齐 datastruct 教程惯例）。第 5 章会专门讲随机与偏倚。
3. **浮点定点化**：不打印裸浮点（尾数实现可异），打 `"{:.6f}"` 定点值 +
   容差布尔（`|x−期望|<1e-9`）。第 29–31 章的数值章节全程整数例题。
4. **不遍历打印 unordered 容器**：哈希序跨实现不同。散列章（11）的高压线，
   打印前排序或改用 `std::map`。

## 坑位清单

1. **`std::ranges::sort` 编译报「不是 std::ranges 的成员」**
   （现象：三通道齐红，错误指向 `<ranges>` 头；原因：算法住在 `<algorithm>`，
   `<ranges>` 只提供视图，视图与算法分家是 ranges 设计的刻意为之；后果：新手
   以为编译器坏了去乱动工具链；对策：`#include <algorithm>`，本示例第一版
   实测踩中。）
2. **特性宏「MSVC 有、g++ 无」的假象**
   （现象：同一个 `#ifdef __cpp_lib_print`，msvc/clang 通道报 1，gcc 通道报 0，
   而 `g++ -dM -E` 又说宏存在；原因：libstdc++ 把特性宏拆散在各头文件里，
   包哪个头只带出它自己的宏，MSVC STL 则是任意标准头给全集；后果：能力探测
   看起来像"实现缺失"，其实是"没请对头文件"；对策：探测前先
   `#include <version>`——它是特性宏的全家福。）
3. **MinGW libstdc++ 的 `<print>` 编译过、链接挂**
   （现象：undefined reference to `std::__open_terminal`；原因：MinGW 终端
   补丁的两个符号没进 libstdc++.dll；后果：教程若直接用 std::print，gcc 通道
   全灭；对策：build.ps1 两级探针注入 `-DALGO_NO_PRINT` + 示例顶部 IO 垫片，
   `std::format`+`printf` 与 `std::print` 字节流一致，对账不受影响。）
4. **打印特性宏的「数值」导致对账炸裂**
   （现象：msvc↔gcc 输出不一致；原因：同一特性宏的值可以不同——
   `__cpp_lib_ranges_zip` 一边 202207、一边 202110，数值是「版本进度」，
   布尔才是「有没有」；后果：逐字节对账失败且看似无解；对策：探测表只打
   0/1，宏值差异写进文档静态表。）
5. **无符号数 `assert(n > 0)` 触发 gcc `-Wextra` 告警**
   （现象：`warning: comparison of unsigned expression '> 0' is always true`；
   原因：-Wextra 含 -Wtype-limits，uint32_t 恒 ≥ 0；后果：零告警判定失败；
   对策：写 `assert(n != 0)`。）

## 练习

1. （CLRS 思考题 1.1-1）给一个现实生活中需要排序的例子；再给一个需要计算
   凹多边形面积的例子（如果面积可以是负的——CLRS 提示这种情况真的存在）。
2. （CLRS 思考题 1.1-4）最短路径问题与旅行商问题有何相似之处？有何本质
   不同？（提示：答案将在第 34/35 章回来——一个多项式可解，一个 NP难。）
3. （CLRS 思考题 1.2-2）同机比较：插入排序跑 8n² 步，归并排序跑 64n·lg n 步。
   n 在哪个范围内插入排序更快？（提示：解 8n² = 64n·lg n，答案是 n ≤ 43。）
4. （CLRS 思考题 1.2-3）100n² 的算法何时跑得比 2ⁿ 的算法快？（答案：n = 15
   起反超，n ≥ 15 时 100n² < 2ⁿ。）
5. （本教程）把 `rand_below` 推广成 `rand_range(rng, a, b)`（返回 [a,b] 闭区间
   整数），并用 60000 次抽样验证 [1,10] 每个值的频数都在 6000±200 内。
6. （本教程）把示例 01.4 的 n 改成 4096 与 8192，观察「插入/归并比值」大约
   翻倍——用 n²/n·lg n = n/lg n 解释这个现象。
