# 33 · 字符串匹配

> 对应 CLRS 第 32 章 *String Matching*（英文 3rd ed. pp.985–1013）。
> 在长 n 的文本 T 里找长 m 的模式 P 的全部出现。朴素 Θ((n−m+1)·m)；
> 本章三条升级路线——**Rabin-Karp**（哈希）、**有限自动机**（预建表）、
> **KMP**（前缀函数）——把匹配压到 O(n+m)，且文本指针**永不回退**。

## 学习目标

1. 能写出朴素匹配并分析最坏情形（T = aⁿ, P = a^m）；
2. 会写 Rabin-Karp 的滚动哈希（去头加尾 O(1)）并解释假阳性验证；
3. 会构建有限自动机的转移表 δ(state, c)；
4. 会手推 KMP 的前缀函数 π 并用它匹配（滑而不回）；
5. 记住各算法的适用场景（多模式 → RK/Aho-Corasas；流式 → FA/KMP）。

## 四算法一台戏

实测（T = "abababacabaababac"，P = "ababac"，命中位置 2 与 11——
四算法对账逐位一致）：

```
  四算法命中位置: 2 11
  KMP 前缀函数 π（含哨兵）: 0 0 0 1 2 3 0
  计数画像：朴素比较 35 次；RK 哈希步 17+验证比较 12 次；FA 查表 17 次；KMP 比较 17 次（文本指针永不回退）
```

**朴素 35 次**：每个对齐从头比，"ababa…" 前缀反复重比。**KMP 恰 17 次
= |T|**——amortized 上界 2n 的现场达成（本例连 2 倍都没用满）。

## 朴素匹配（§32.1）

每个对齐位置 s 从 P[0] 比到失配——最坏 Θ((n−m+1)·m)（T = aⁿ、
P = a^m 时每个对齐都比 m−1 次）。**「重复比较已看过的字符」**是它
慢的全部原因——后面三条路线都是对这个浪费的反击。

## Rabin-Karp（§32.2）

把比较改成**比哈希**：P 的哈希一次算好；文本每个窗口的哈希用**滚动
更新** O(1) 换新（去头 ×d⁻¹、加尾）——哈希命中后再逐字符验证（防
假阳性，模 q 的碰撞率 1/q）。预处理 Θ(m)、匹配期望 O(n+m)。

多模式匹配的天选之子：P₁..Pₖ 全算进一张哈希表，一趟扫文本——
防抄袭/入侵检测的实用内核（Boyer-Moore 与 KMP 都做不了多模式；
多模式的正统是 Aho-Corasick——KMP 自动机的 trie 化推广）。

## 有限自动机匹配器（§32.3）

状态 = 「当前已匹配的 P 前缀长度」；δ(state, c) = 拼上 c 后仍是 P
前缀的最长后缀。建表后**匹配是纯查表**——每字符恰好一次转移，O(n)
与 m 无关（流式场景的王者）。实测转移表（P = ababac，σ = {a,b,c}）：

```
δ(0, a)=1  δ(0, b)=0  δ(0, c)=0
δ(1, a)=1  δ(1, b)=2  δ(1, c)=0
δ(2, a)=3  δ(2, b)=0  δ(2, c)=0
δ(3, a)=1  δ(3, b)=4  δ(3, c)=0
δ(4, a)=5  δ(4, b)=0  δ(4, c)=0
δ(5, a)=1  δ(5, b)=4  δ(5, c)=6   ← 接受态（匹配成功）
δ(6, a)=1  δ(6, b)=0  δ(6, c)=0
```

看点：δ(5,a)=1（"ababa"+"a" 的最长前缀后缀是 "a"）、δ(5,b)=4
（"ababab" 的最长前缀后缀是 "abab"）——**转移表就是「失配后该滑到
哪」的预计算答案**，与 KMP 的 π 同源（KMP 是它的空间压缩版：
π 直接给出滑到的状态，表从 m·|Σ| 缩到 m）。

## KMP（§32.4）

**前缀函数** π[q] = P[0..q) 的「最长相等真前后缀」长度——P 自匹配
的产物。P = ababac 的 π（含哨兵 π[0]=0）= 0 0 0 1 2 3 0：
"aba"→1（a）、"abab"→2（ab）、"ababa"→3（aba）、"ababac"→0。

匹配：文本指针 i 只前进；失配时模式指针 q 沿 π 链回跳——

```cpp
while (q > 0 && p[q] != t[i]) { q = pi[q]; }   // 滑动，i 不回退
if (p[q] == t[i]) { ++q; }
```

**摊还分析**（第 18 章的应用）：q 每次字符至多 +1，而 π[q] < q——
总回跳次数 ≤ 总前进次数 ≤ n——**比较次数 ≤ 2n**（本例 17 = n，
连上界的一半都没碰）。构造 π 用「P 自己匹配自己」的同款循环，
Θ(m)。

## 选型表

| 场景 | 选择 | 理由 |
|---|---|---|
| 单模式、一次性 | 库函数（`strstr`/`std::search`/`ranges::search`） | 实现早已优化 |
| 单模式、多次查询同一 P | KMP / FA | 预处理复用、线性匹配 |
| 多模式 | RK 哈希表 / Aho-Corasick | 一趟扫全部模式 |
| 二进制/高重复文本 | KMP 系（跳过已知前缀） | 最坏界硬 |
| 生物序列模糊匹配 | DP（编辑距离，第 16 章） | 精确匹配不够用 |

## C++23 语言点

- `std::string_view` 全程传参（零拷贝切片）；
- `std::array<int,3>` 存每状态转移（小字母表）；大字母表用 256 桶
  或哈希稀疏表；
- 滚动哈希的模乘注意先 `% q` 再乘（中间量 < q² < 2⁶⁴ 才安全——
  第 32 章同款纪律）。

## 与 STL 对照

`std::ranges::search`/`std::string::find` 是标准库的匹配器（实现自选，
通常是 Boyer-Moore 变体或 memchr 加速）；C++17 `std::boyer_moore_searcher`
显式暴露 BM。手写的价值：多模式、流式、与 KMP 的 next 数组打交道的
竞赛场景。

## 坑位清单

1. **RK 的滚动更新漏 + q 防负**
   （现象：哈希错位、命中全丢；原因：`ht − h·t[s]` 可能负——先 `+ q`
   再模；对策：`(ht + q − h * t[s] % q) % q`（本例写法），并用已知
   命中对账（本例四解互锁）。）
2. **π 表的哨兵与下标差一**
   （现象：KMP 死循环或漏匹配；原因：π[0]=0 哨兵、循环里比较的是
   p[q]（q 个已匹配后）——「前缀函数」与「next 数组」两种约定
   （差一位）混用必错；对策：钉死一种（本例 π 含哨兵、失配跳
   π[q]），先手推 ababac 的全表对账再上机。）
3. **FA 建表的「最长 k」忘了从大到小试**
   （现象：转移表退化（k=0 优先）——匹配变成逐字符重来；原因：δ 要
   **最大** k 使 P[0..k) 是候选串后缀；对策：k 从 min(len, m) 递减
   （本例写法）。）
4. **四算法对「重叠出现」口径不一**
   （现象：命中数不同——某算法匹配成功后跳过整个模式（非重叠）而
   另一个允许重叠；对策：钉死「报告所有（含重叠）出现」，KMP 匹配
   后 `q = pi[m]` 恰好保留重叠信息（本例的 2 与 11 相距 9 > 6 无
   重叠，练习 5 会遇到重叠例）。）

## 练习

1. （CLRS 练习 32.1-2/32.1-3?）朴素在 T=aⁿ/P=a^{m−1}b 上的比较次数；
   最好情形 Θ(n) 的输入形态。
2. （CLRS 练习 32.2-1/32.2-3）手推 RK 的窗口哈希序列；合理的 q 与 d
   的选取（d = |Σ|、q 避开 d 的幂）。
3. （CLRS 练习 32.3-1/32.3-2?）对 P = ababaca 手推转移表（对照本例
   ababac 的表）；建表的 O(m³|Σ|) 朴素版如何到 O(m|Σ|)。
4. （CLRS 练习 32.4-1/32.4-5?）对 P = ababbababab? 32323232 手推 π；
   KMP 是「在线算法」（文本流式到达）的论证。
5. （本教程）构造 T = aaaaaa、P = aaa（重叠出现）——四算法的命中
   位置必须是 {0,1,2,3}；再给 RK 换 q=13（故意小）统计假阳性次数。
6. （本教程进阶）实现 Aho-Corasick（trie + fail 指针 = KMP 的 π 推广
   到 trie），模式集 {he, she, his, hers} 在 "ushers" 上的命中对账。
