# 33 · 字符串匹配

> 对应 CLRS 第 32 章 *String Matching*（英文 3rd ed. pp.985–1013）。
> 在长 n 的文本 T 里找长 m 的模式 P 的全部出现。朴素 Θ((n−m+1)·m)；
> 本章三条升级路线——**Rabin-Karp**（哈希）、**有限自动机**（预建表）、
> **KMP**（前缀函数）——把匹配压到 O(n+m)，且文本指针**永不回退**。

## 学习目标

1. 能写出朴素匹配并分析最坏情形（T = aⁿ, P = a^m）；
2. 会写 Rabin-Karp 的滚动哈希（去头加尾 O(1)）并解释假阳性验证；
3. 会构建有限自动机的转移表 δ(state, c)；
4. 会手推 KMP 的前缀函数 π 并用它匹配（滑而不回）；
5. 记住各算法的适用场景（多模式 → RK/Aho-Coras；流式 → FA/KMP）；
6. 能构造 Aho-Corasick 自动机（trie + BFS 建 fail + 转移表补全），
   并解释**输出传播**为什么不可省；
7. 会用位掩码承载 `out`，并说清 AC 的三个实现陷阱（指针失效 / 漏传播 /
   缺边不补全）以及**什么时候不该上 AC**；
8. 会写 `[qx]` 压缩符的单遍展开器（多位数字、整段追加、先算长度
   reserve），并能正确处理「模式或其逆向命中」的计数口径。

## 四算法一台戏

实测（T = "abababacabaababac"，P = "ababac"，命中位置 2 与 11——
四算法对账逐位一致）：

```
  四算法命中位置: 2 11
  KMP 前缀函数 π（含哨兵）: 0 0 0 1 2 3 0
  计数画像：朴素比较 35 次；RK 哈希步 17+验证比较 12 次；FA 查表 17 次；KMP 比较 17 次（文本指针永不回退）
```

**朴素 35 次**：每个对齐从头比，"ababa…" 前缀反复重比。**KMP 恰 17 次
= |T|**——amortized 上界 2n 的现场达成（本例连 2 倍都没用满）。

## 朴素匹配（§32.1）

每个对齐位置 s 从 P[0] 比到失配——最坏 Θ((n−m+1)·m)（T = aⁿ、
P = a^m 时每个对齐都比 m−1 次）。**「重复比较已看过的字符」**是它
慢的全部原因——后面三条路线都是对这个浪费的反击。

## Rabin-Karp（§32.2）

把比较改成**比哈希**：P 的哈希一次算好；文本每个窗口的哈希用**滚动
更新** O(1) 换新（去头 ×d⁻¹、加尾）——哈希命中后再逐字符验证（防
假阳性，模 q 的碰撞率 1/q）。预处理 Θ(m)、匹配期望 O(n+m)。

多模式匹配的天选之子：P₁..Pₖ 全算进一张哈希表，一趟扫文本——
防抄袭/入侵检测的实用内核（Boyer-Moore 与 KMP 都做不了多模式；
多模式的正统是 Aho-Corasick——KMP 自动机的 trie 化推广）。

## 有限自动机匹配器（§32.3）

状态 = 「当前已匹配的 P 前缀长度」；δ(state, c) = 拼上 c 后仍是 P
前缀的最长后缀。建表后**匹配是纯查表**——每字符恰好一次转移，O(n)
与 m 无关（流式场景的王者）。实测转移表（P = ababac，σ = {a,b,c}）：

```
δ(0, a)=1  δ(0, b)=0  δ(0, c)=0
δ(1, a)=1  δ(1, b)=2  δ(1, c)=0
δ(2, a)=3  δ(2, b)=0  δ(2, c)=0
δ(3, a)=1  δ(3, b)=4  δ(3, c)=0
δ(4, a)=5  δ(4, b)=0  δ(4, c)=0
δ(5, a)=1  δ(5, b)=4  δ(5, c)=6   ← 接受态（匹配成功）
δ(6, a)=1  δ(6, b)=0  δ(6, c)=0
```

看点：δ(5,a)=1（"ababa"+"a" 的最长前缀后缀是 "a"）、δ(5,b)=4
（"ababab" 的最长前缀后缀是 "abab"）——**转移表就是「失配后该滑到
哪」的预计算答案**，与 KMP 的 π 同源（KMP 是它的空间压缩版：
π 直接给出滑到的状态，表从 m·|Σ| 缩到 m）。

## KMP（§32.4）

**前缀函数** π[q] = P[0..q) 的「最长相等真前后缀」长度——P 自匹配
的产物。P = ababac 的 π（含哨兵 π[0]=0）= 0 0 0 1 2 3 0：
"aba"→1（a）、"abab"→2（ab）、"ababa"→3（aba）、"ababac"→0。

匹配：文本指针 i 只前进；失配时模式指针 q 沿 π 链回跳——

```cpp
while (q > 0 && p[q] != t[i]) { q = pi[q]; }   // 滑动，i 不回退
if (p[q] == t[i]) { ++q; }
```

**摊还分析**（第 18 章的应用）：q 每次字符至多 +1，而 π[q] < q——
总回跳次数 ≤ 总前进次数 ≤ n——**比较次数 ≤ 2n**（本例 17 = n，
连上界的一半都没碰）。构造 π 用「P 自己匹配自己」的同款循环，
Θ(m)。

## 选型表

| 场景 | 选择 | 理由 |
|---|---|---|
| 单模式、一次性 | 库函数（`strstr`/`std::search`/`ranges::search`） | 实现早已优化（twoway） |
| 单模式、多次查询同一 P | KMP / FA | 预处理复用、线性匹配 |
| 多模式、k ≲ 10 | `std::search` 逐模式搜 | 免建树、吃到 stdlib 常数 |
| 多模式、k 大或模式集常变 | **Aho-Corasick** | 一趟扫全部，Θ(Σ·L_tot + |T|) |
| 多模式、模式短且要抗哈希碰撞 | AC（或后缀自动机） | RK 在短模式上退化 |
| 二进制/高重复文本 | KMP 系（跳过已知前缀） | 最坏界硬 |
| 生物序列模糊匹配 | DP（编辑距离，第 16 章） | 精确匹配不够用 |

## Aho-Corasick 自动机：多模式匹配

### 动机：单模式的工具不够用

前面三条路线都是**单模式**的。现实需求往往是「n 个模式 + 一段文本」
（防抄袭、病毒特征库、DNA  motif 扫描、多模式关键字过滤）。朴素做法是
对每个模式各跑一次 KMP，代价 **Θ(k·(|T| + 模式长))**——模式数一多就爆。

Rabin-Karp 能撑住多模式（把 k 个模式的哈希塞进一张表，一趟扫文本），但
它有哈希碰撞的假阳性，且**短模式退化严重**（步长小于模式长时哈希窗口
滑动浪费）。多模式的正统解是 **Aho-Corasick**：它是 KMP 的 π 函数在
**Trie 上的推广**——KMP 处理「一个模式的自重叠」，AC 处理「一堆模式在
同一棵树上的自重叠」。

### 构造：Trie + fail 指针 + 转移表补全

数据结构是 Trie（字典树），每个节点额外挂两个东西：

- **fail 指针**：`fail(u)` = 「`u` 对应的串的最长真后缀，且该后缀是某个
  模式的前缀」的那个节点。根节点的 fail 指向自己。这与 KMP 的 `π` 逐字对应
  （`π[q]` = `P[0..q)` 的最长相等真前后缀）——只是「前后缀」换成了
  Trie 上的「祖先链」。
- **out 掩码**：`out(u)` 的第 `i` 位 = 「模式 i 在 `u` 处结束」。

建树一趟 BFS 就够，**三个动作**：

1. 对节点 `u` 的每个真实儿子 `v`：`fail(v) = next[fail(u)][c]`；
2. **输出传播**：`out(v) |= out[fail(v)]`——这是最容易漏的一步；
3. **转移表补全**：`u` 上缺失的边 `next[u][c]`，补成 `next[fail(u)][c]`。

第 3 步做完，扫描就从「循环沿 fail 链回跳」变成**每字符恰好一次数组
查表**——这正是 33.3 节有限自动机的思路。总复杂度
**Θ(Σ·L_tot + |T|)**，`L_tot` 是所有模式长度之和（`Σ` 是字符集大小）。

### 输出传播：为什么它不可省

扫描到状态 `u` 时，**fail 链上所有模式都被命中**——不只是 `u` 自己。
若只在 `u` 恰是模式末尾时报，fail 链上的那些就全漏了。

现场例子（本例实测）：模式集 `{he, she, his, hers, abc, cba}`。模式
`she` 的最长真后缀是 `he`，而 `he` **恰好也是另一个模式**——于是
`fail(she) = he`，`out(she) = 0b11`（含 bit 1 的 she 与 bit 0 的 he），
而 `out(he) = 0b01`。文本 `"ushers abc cba she hers his he"` 里两处
`she` 的结束下标是 3 与 17，而 `he` 的四个命中里**有 3 和 17 这两个**
——正是输出传播把它们对齐的。漏掉 `out(v) |= out[fail(v)]`，`she` 那两处
就不会报出 `he`。

用**位掩码**（`uint32_t`，`std::bitset` 同理）承载 `out`，传播就是一次
按位或，命中报告就是一次 `mask & (1<<i)`——**k ≤ 32 个模式时，传播与
报告都是 O(1) 机器字操作**，这是 AC 工程实现的关键。

### 实现要点：为什么用下标而不是指针

Trie 的节点要在建树过程中不断追加，最自然的写法是持有 `Node*` 或
`Node&`。**这是错的**，而且错得隐蔽：

```cpp
// ✗ 错误：push_back 会搬迁整个 vector，所有指针/引用/迭代器全部失效
std::vector<Node> nodes_;
Node* u = &nodes_[0];
nodes_.emplace_back();      // 搬迁！u 现在指向旧内存
u->next[c] = ...;           // 写进了已释放的内存（UB）

// ✓ 正确：只用 int 下标 + 预分配
std::vector<Node> nodes_;
nodes_.reserve(totalLen + 1);   // 预分配，避免搬迁
nodes_.emplace_back();          // 根 = 0
int u = 0;
u = nodes_[u].next[c];          // 下标访问，搬迁也安全
```

三条纪律：**① 用 `std::vector<Node>` + `int` 下标，绝不存指针**；
**② `reserve` 预分配**（模式长度之和 + 1）让搬迁根本不发生；
**③ `next` 数组用 `0` 当「无边的哨兵」**——因为根节点编号就是 0，
省掉一个 `-1` 的分支（代价是根不能被任何真实边指向，这天然满足）。

本例实测：6 个模式、`L_tot = 18`，建出的 Trie 有 16 个节点；扫描 30 字符
的文本，转移次数 **30 = |T|** 严格相等——补全转移表后没有任何回跳。

### 选型：什么时候**不该**写 AC

这是本节最实用的判断：**模式数很少（≲10）时，`std::search` 比手写 AC
更快也更简单**。libstdc++ 的 `std::search` 用的是 **twoway** 算法
（两路比对 + 跳过表），对单模式是 `O(|T| + m)` 且常数极小；你手写 AC 还要
付建树的 `Θ(Σ·L_tot)`。

- `k` 是常数时，两者同阶（`k(|T| + m)` 与 `Σ·L_tot + |T|` 都是线性），
  而 `std::search` 白拿 stdlib 的常数优化，**这就是「够用即最优」的边界**；
- `k` 达到几十上百时，`k` 次全文扫描变成 `k·|T|`，而 AC 仍是 `|T|`——
  **差距随 k 线性拉开，AC 才显现价值**。

实测对照（文本 30 字符、6 个模式）：`k = 1` 时 `std::search` 约 32 步、
AC 约 30 步 + 建树 416 步（AC 亏）；`k = 6` 时 `std::search` 约 198 步、
AC 仍是 30 步 + 建树 416 步（开始占优）。**分界线就在 k ≈ 5 附近。**

## 压缩符展开：`[qx]` 与病毒扫描

### 问题

给定若干两两不同的病毒模式串和一个程序串。程序可能是压缩格式：除普通
大写字母外，可用压缩符 `[qx]`，其中 q 是十进制正整数、x 是一个大写
字母，表示 q 个连续的 x。例如 `AB[2D]E[7K]G` 展开为
`ABDDEKKKKKKKG`。一个模式若为程序的子串，**或为程序逆向串的子串**，
即计一种感染。求感染种数。

### 解析器：单遍状态机

程序的字母表只有 A–Z，`[` 与 `]` 仅充当标记，没有任何歧义，因此一个
单遍扫描的状态机就够了：

- 普通字母：直接抄入结果；
- 遇到 `[`：逐位读入十进制数字 q（`q = q·10 + digit`，**q 可以有多位**），
  再读紧跟的字母 x，跳过 `]`，一次性追加 q 个 x。

写法上两个工程细节：

1. **先跑一遍同构的 dry-run 算展开长度**，用它 `reserve` 输出串，避免
   长串反复扩容；
2. q 个 x 用 `out.append(q, x)` 一次写入——不要写成
   `out.push_back(char(q))`（那只会追加一个编码为 q 末字节的字符）。

展开后的长度上限约 5.1×10⁶，即 5 MB 上下，直接物化是划算的选择。
若 q 的上界再大几个数量级、物化不可行，就只能在**游程序列**
`(x, q)` 上匹配：单字符重复模式（如 `BBB`）命中当且仅当存在一个 B
游程长度 ≥ 3；其他模式的任何一次出现都必然跨过至多「模式长度」个
游程边界，只需在边界附近对齐检查——把全文扫描降成边界扫描。

### 计数口径：模式的逆向而非程序的逆向

感染条件「v 是 text 的子串，或 v 是 text 逆向串的子串」有一个省时的
等价改写：后者等于「**v 的逆向串**是 text 的子串」。于是程序只需展开
一次、保持不动，把每个模式反转一次各查两遍即可，省掉对 5 MB 程序的
反转拷贝。

压缩案例的逐步判定（`A[2B]CD[4E]F` 展开为 `ABBCDEEEEF`）：

```
  ABB     命中（开头）
  ACDEE   不命中，逆向 EEDCA 也不命中
  BBB     不命中（B 游程长度为 2），逆向仍是 BBB
  FEEE    不命中，但逆向 EEEF 命中尾部
```

⇒ 感染 2 种。三个案例的实测感染数分别为 0、3、2。

## C++23 语言点

- `std::string_view` 全程传参（零拷贝切片）；
- `std::array<int,3>` 存每状态转移（小字母表）；大字母表用 256 桶
  或哈希稀疏表；**AC 则是 `std::array<int,26>` + `int` 下标**
  （`0` 当无边哨兵，省一个分支）；
- 滚动哈希的模乘注意先 `% q` 再乘（中间量 < q² < 2⁶⁴ 才安全——
  第 32 章同款纪律）。
- 33.5 的 `out` 掩码用 `std::uint32_t`：k ≤ 32 时传播是**一次按位或**、
  报告是**一次位测试**，都是 O(1) 机器字操作；`std::bitset<N>` 更灵活但
  掩码版在 k 小的时候更快（一个寄存器放得下）；
- 解析器与匹配器解耦：`decompress` 只管物化，产出标准 `std::string`，
  下游任何匹配器（朴素/KMP/AC）都能直接复用——压缩是词法问题、感染
  判定是匹配问题，两层不混写。

## 与 STL 对照

`std::ranges::search`/`std::string::find` 是标准库的匹配器（实现自选，
通常是 Boyer-Moore 变体或 memchr 加速）；C++17 `std::boyer_moore_searcher`
显式暴露 BM。手写的价值：多模式、流式、与 KMP 的 next 数组打交道的
竞赛场景。

## 坑位清单

1. **RK 的滚动更新漏 + q 防负**
   （现象：哈希错位、命中全丢；原因：`ht − h·t[s]` 可能负——先 `+ q`
   再模；对策：`(ht + q − h * t[s] % q) % q`（本例写法），并用已知
   命中对账（本例四解互锁）。）
2. **π 表的哨兵与下标差一**
   （现象：KMP 死循环或漏匹配；原因：π[0]=0 哨兵、循环里比较的是
   p[q]（q 个已匹配后）——「前缀函数」与「next 数组」两种约定
   （差一位）混用必错；对策：钉死一种（本例 π 含哨兵、失配跳
   π[q]），先手推 ababac 的全表对账再上机。）
3. **FA 建表的「最长 k」忘了从大到小试**
   （现象：转移表退化（k=0 优先）——匹配变成逐字符重来；原因：δ 要
   **最大** k 使 P[0..k) 是候选串后缀；对策：k 从 min(len, m) 递减
   （本例写法）。）
4. **四算法对「重叠出现」口径不一**
   （现象：命中数不同——某算法匹配成功后跳过整个模式（非重叠）而
   另一个允许重叠；对策：钉死「报告所有（含重叠）出现」，KMP 匹配
   后 `q = pi[m]` 恰好保留重叠信息（本例的 2 与 11 相距 9 > 6 无
   重叠，练习 5 会遇到重叠例）。）
5. **AC 的 `out` 漏做输出传播**
   （现象：只报出「当前状态恰好是模式末尾」的那些命中，fail 链上的
   全漏；本例 `she` 的两处（结束下标 3、17）不会报出同时结束的 `he`；
   原因：以为「到达模式末尾 = 命中」，忘了 AC 的状态是「当前已匹配
   的最长后缀」，模式可以藏在它的 fail 链上；后果：**少报**——一个
   静默的假阴性，测试往往只查「有没有找到」而查不出「有没有多报/少报」；
   对策：`out(v) |= out[fail(v)]` 写在 BFS 里（fail 指针已算完的那一层），
   并用「同结束下标的多模式必须都报出」来断言。）
6. **AC 节点用指针/引用持有**
   （现象：UB、随机崩、`next` 写进已释放内存；原因：`push_back` 触发
   搬迁，`vector` 内部缓冲区换地址，所有指针/引用/迭代器失效；
   后果：越界写、难复现的崩溃；对策：**只用 `int` 下标** + `reserve`
   预分配（模式长度之和 + 1）让搬迁不发生；本节的三条纪律就是这条。）
7. **AC 的 `next` 缺边没补全，退化成裸 fail 链**
   （现象：扫描时字符数 ≠ |T|，复杂度退化到 `O(|T|·深度)`；原因：只填了
   Trie 的真实边，靠扫描时循环跳 fail；后果：**正确但慢**，在大字母表 +
   公共后缀多时慢一个量级；对策：BFS 里补 `next[u][c] = next[fail(u)][c]`，
   补全后每次转移是**严格 O(1)** 查表；实测转移次数恰等于 |T|。）
8. **多模式场景无脑上 AC**
   （现象：k = 3 个短模式，手写 80 行 AC，比 `std::search` 还慢；原因：AC
   要付 `Θ(Σ·L_tot)` 的建树成本，k 小时纯属浪费；后果：**过度工程**；
   对策：k ≲ 10 时用 `std::search`（libstdc++ 的 twoway）；k 大或需要
   「模式集频繁增删」时才上 AC，并注意 AC 的建树是一次性投入。）
9. **压缩符的 q 只按一位数字解析**
   （现象：遇到 `[12K]` 这类多位 q 时展开错乱——只追加 1 个字符，随后
   把 `2`、`K`、`]` 当成普通内容；原因：数字解析没写循环累加
   `q = q·10 + digit`；后果：展开长度与内容全错；对策：数字部分循环
   吃到非数字字符为止（本例写法），dry-run 与正式解析共用同一套逻辑，
   并用「展开 vs 逐段参考构造」随机对账。）
10. **整段追加写成单字符追加**
	（现象：`[6K]` 展开后只有一个乱码字符；原因：误用
	`push_back(char(q))`——char(q) 只是 q 末字节对应的单个字符，正确
	写法是 `append(q, x)`，由标准库写入 q 个 x；对策：追加重复段一律
	`out.append(static_cast<std::size_t>(q), x)`（本例写法）。）
11. **逆向口径做错方向或漏查**
	（现象：压缩案例答案错成 1——FEEE 本体不命中就没计，但它的逆向
	EEEF 明明命中尾部；另一种浪费是真的去反转 5 MB 程序再查一遍；
	对策：利用「v 命中 text 的逆向串 ⟺ v 的逆向命中 text」，只反转
	短模式、程序保持不动（本例写法），每个模式查本体与逆向两次。）

1. （CLRS 练习 32.1-2/32.1-3?）朴素在 T=aⁿ/P=a^{m−1}b 上的比较次数；
   最好情形 Θ(n) 的输入形态。
2. （CLRS 练习 32.2-1/32.2-3）手推 RK 的窗口哈希序列；合理的 q 与 d

4. （CLRS 练习 32.4-1/32.4-5?）对 P = ababbababab? 32323232 手推 π；
   KMP 是「在线算法」（文本流式到达）的论证。

   位置必须是 {0,1,2,3}；再给 RK 换 q=13（故意小）统计假阳性次数。

   到 trie），模式集 {he, she, his, hers} 在 "ushers" 上的命中对账。
7. （本教程）把示例 33.5 的 `out` 掩码改成 `std::bitset<64>`，
   支持 64 个模式；验证 k > 32 时掩码传播依然正确（对比手写
   「遍历 fail 链逐个检查」的结果与传播结果必须一致）。
8. （本教程）**故意删掉** `out(v) |= out[fail(v)]` 与转移表补全这两行，
   各跑一次并记录：① 少了哪些命中（少报清单）；② 转移次数从 |T|
   变成多少（退化成多少）。这两个数字就是这两行代码的价值。
