# 32 · 数论与位运算

> 对应 CLRS 第 31 章 *Number-Theoretic Algorithms*（英文 3rd ed. pp.949–
> 980），并延伸到本章后半的位运算与高精度。欧几里得辗转相除是史上最古老
> 算法（公元前 300 年）；它的现代后裔——模幂、Miller-Rabin、RSA——撑起
> 了整座公钥密码学。本章整数运算全程 64 位精确、无浮点（三通道对账天然
> 友好）；代价是**溢出成为一等公民**，32.6 会专门处理它。

## 学习目标

1. 会写欧几里得与扩展 gcd（Bézout 系数），知道逆元从它来；
2. 会写平方-相乘的模幂（Θ(lg b) 次乘法）；
3. 能解释 Fermat 测试为何被 Carmichael 数骗、Miller-Rabin 如何拆穿；
4. 能走完 RSA 的完整流程（选 pq / 求 φ / 配 ed / 加解密）；
5. 熟练使用 `x & (x-1)` 这一族恒等式（判 2 的幂 / popcount / 掩码 /
   格雷码），并知道它们各自替代掉了哪个循环；
6. 能写出带溢出预判的整数次方，并解释**为什么快速幂不改变溢出点**；
7. 能用位向量实现最小可用的高精度（加减 + 乘小数），并说清"打印
   1..10ⁿ"的真实代价在 I/O 而不在算法。

## 欧几里得与扩展 gcd（§31.2）

gcd(a,b) = gcd(b, a mod b)——辗转序列每步严格递减，对数步收敛
（Lamé 定理：步数 ≤ 5·位数，与斐波那契最坏例挂钩——第 5 章的老朋友
再登场）。**扩展版**顺带产出 Bézout 系数：

```
欧几里得 gcd(99, 78)：
  辗转序列: 99 → 78 → 21 → 15 → 6 → 3
  gcd = 3（辗转 5 步）
  扩展 gcd：99·(-11) + 78·(14) = 3（Bézout 恒等式 = gcd）
```

Bézout 的直接应用：gcd(a,n) = 1 时 a 的**模逆元** a⁻¹ (mod n) 就是
扩展 gcd 的 x 系数（取正模）。

## 模运算：快速幂（§31.6）

a^b mod n 用**平方-相乘**：按 b 的二进制位，每步平方、逢 1 再乘 a——
Θ(lg b) 次模乘。实测 7⁵⁶⁰ mod 561 只花 13 次乘法（朴素要 560 次）；
中途值永远 < n²（64 位装得下）——**不取模先算幂会溢出宇宙**。

```
模幂 7^560 mod 561 = 1（平方-相乘 13 次乘法 vs 朴素 560 次）
乘法逆元：17⁻¹ mod 3120 = 2753（检查 17·2753 mod 3120 = 1，gcd = 1）
```

## 素性测试：Fermat 的坑与 Miller-Rabin（§31.8）

**Fermat 小定理**：p 素 ⟹ a^{p−1} ≡ 1 (mod p)。拿它当测试（a^{n−1}
≠ 1 则 n 必合）单向有效；**反向不成立**——Carmichael 数（561 是最小
者）对所有互素 a 都满足 a^{n−1} ≡ 1，Fermat 测试集体被骗。实测：
7⁵⁶⁰ mod 561 = 1，假象完美。

**Miller-Rabin** 加一步「平方根检查」：n−1 = 2^s·d，算 a^d 后连续
平方——途中若得到 ±1 之外的「1 的平方根」（x ≠ ±1 但 x² ≡ 1），
n 必合（mod 素数只有 ±1 两个平方根）。实测（基 = {2,3,5,7}）：

```
素性测试（基 = {2,3,5,7}）：
  561 = 3·11·17（Carmichael 数）：Fermat 测试 7^560≡1 被骗，Miller-Rabin 判为素 = 0（基 2 即为 witness，拆穿 = 1）
  7919 判素 = 1（第 1000 个素数），104729 判素 = 1（第 10000 个），3233 判素 = 0（= 61·53，正确识破）
```

Miller-Rabin 是**随机化**测试：k 个随机基把错误率压到 4⁻ᵏ（无 Carmichael
式漏洞——「强伪素」对固定基存在但对随机基稀少）。确定性变体：对
64 位整数，固定 12 个基即是决定性的（工程事实）。

## RSA 全流程（§31.7）

```
RSA（p=61, q=53）：n = 3233, φ(n) = 3120, e = 17, d = e⁻¹ = 2753
  加密：c = 65^17 mod 3233 = 2790
  解密：m = 2790^2753 mod 3233 = 65（= 原文 65，RSA 闭环）
  正确性：ed = 17·2753 = 46801 = 15·φ + 1（费马小定理 + CRT ⇒ m^{ed} ≡ m）
```

- 公钥 (e, n)、私钥 d：ed ≡ 1 (mod φ(n))（d 用扩展 gcd 求）；
- 加密 c = mᵉ mod n、解密 m = c^d mod n——都是快速幂；
- 正确性：m^{ed} = m^{15φ+1} ≡ m（费马小定理在 mod p、mod q 各来一次，
  CRT 合并）——**欧拉定理是引擎，中国剩余定理是变速箱**；
- 安全性依赖「分解 n = pq 不可行」——与算法复杂度的边界（第 35 章
  NP 理论）一线相牵。真实 RSA 的 n 是 2048 位（617 位十进制），大数
  运算库（GMP）就位后同一套代码。

## 位运算技巧：把"逐位判断"压成一次算术

位运算不是杂技。它们是同一件事的不同侧面：**用位运算把 O(词长) 次循环
压成 O(1) 次算术操作**（对固定宽度整数而言）。这一节把它们按"能替换掉什么
循环"组织。

### 核心恒等式：`x & (x-1)` 清最低位的 1

```cpp
x &= (x - 1);      // 清掉 x 最低的一个 1
```

- **判 2 的幂**：`x > 0 && (x & (x-1)) == 0`。因为 2 的幂只有一个 1，
  清掉它就归零；反之若归零说明只有一个 1。
  C++20 起直接写 `std::has_single_bit(x)`——它对 `x == 0` 返回 `false`，
  而手写 `(x & (x-1)) == 0` 对 `x = 0` **也成立**（因为 `-1` 的补码全是
  1，`0 & -1 == 0`）。这是本节最容易漏的边界。
- **计数 1 的个数（Brian Kernighan）**：`while (x) { x &= x-1; ++k; }`，
  循环次数**恰好等于 1 的个数**。对比"逐位移位"版本：要扫满 64 位。
  示例里 7 个样本走完 n&(n-1) 版共 54 次循环，正好等于这些数里 1 的总数
  （0+1+8+10+1+32+2 = 54），而逐位版要走7×64 = 448 次。
- **`std::popcount`**（`<bit>`）编译到 x86-64 的 `POPCNT` 指令（需
  `-mpopcnt` 或 `-march=native`）。它是并行前缀和、位排序、霍夫曼编码
  的底层原语。

### 掩码与隔位操作

Brian Kernighan 那个经典练习（造出 `1010…1010`）的答案是常量
`0x5555555555555555`，互补掩码 `0xAAAAAAAAAAAAAAAALL` 与它按位与得 0。
这类掩码在 SIMD、图片打包、字节序转换（`bswap` 的软件版）里反复出现。
**能用常量说清的东西不要用循环算**——掩码是一次性的，循环是每次的。

### 格雷码：`g = n ^ (n >> 1)`

相邻两个格雷码**恰好差 1 位**。性质"差1 位"意味着在机械式编码器
（格雷码盘）里不会跳过中间位置——相邻物理位置不会产生非法的中间读数，
这就是它在硬件编码器、跨步进电机、以及哈希打散（`i ^ (i >> 16)`）
里的用途。示例验证了 n = 0..7 的相邻差位数都是 1。

## 整数次方 `a^n`：三种实现与溢出边界

§31.6 的 `mod_pow` 是"带模"的快速幂。去掉模就是**不带模**的版本，而它
多出一个模版本没有的问题：**溢出是静默且不可逆的**。

| 实现 | 乘法次数（n=40） | 溢出行为 |
|---|---|---|
| 朴素连乘 | 40 | 静默溢出 |
| 快速幂 | 11 | 静默溢出，**溢出点与朴素完全相同** |
| 快速幂 + 预判检测 | 11 | 返回 false，不产出垃圾值 |

第二个要点容易被误解：**快速幂并不能避免溢出**。`3^39` 装得下、
`3^40 = 12157665459056928801` 装不下——这个边界是真实值决定的，与你用
几次乘法算它无关。示例里 n=40 时朴素与快速幂给出**同一个**错误值
`-6289078614652622815`（这就是 3⁴⁰ 的补码），这恰好证明了两者算的是
同一个数，只是这个数表示不下。**快速幂省的是时间，不是表示范围。**

要真正"知道装不装得下"，得**在乘法之前预判**。示例的 `pow_checked`
有两个必须绕开的坑：

1. **不能用"先乘再看符号"**。有符号溢出是 UB，编译器有权假设它不发生，
   进而删掉检查分支。正确做法是用 `__int128` 做中间量，或用除法预判：
   `|r| > mag / |base|` ⟺ `|r * base| > mag`。
2. **不能用 `abs(INT64_MIN)`**。`|−2^63| = 2^63 = INT64_MAX + 1` 装不进
   int64，`abs(INT64_MIN)` 本身就是 UB。正确做法是让 API 接受
   **最大绝对值** `mag = 2^63`（用 `__int128` 表达），而不是
   "int64 上限"。示例因此能正确判定 `-2^63` 装得下、`-2^64` 装不下。

还有一个"平方本身会溢出"的坑：即使最终结果装得下，**中间步骤的
`base * base` 仍可能溢出**（`a = -2, n = 63` 时base 会一路平方到 2⁶⁴）。
示例用**哨兵**处理：一旦发现 `base²` 超界，就把 base 换成一个绝对值大于
`mag` 的哨兵值。之后任何一次累乘都会立刻判定溢出；若剩余二进制位全为 0，
哨兵根本不会被用到，结果依然正确。

## 高精度：位向量大数

高精度不是什么魔法，就是"**用数组存每一位 + 逐位进位**"。示例的
`BigDec` 存十进制位（低位在前），三个操作各对应小学竖式的一步：

- `add`：逐位加 + 连锁进位（999 + 1 = 1000）；
- `mul_small(k)`：乘一个小整数，这是最常用的一步（乘 10、加 1、
  阶乘递推全都用它）；
- `pow10(k)`：直接塞 k 个 0。

两个设计细节值得注意：

1. **符号位的表示**：负数在最高位存 `-1`。这样 `d_.back() < 0` 就是
   `negative()`，判断是O(1)；但打印时**必须跳过最高位**，否则会多打一个
   字符。这是本节实测踩到的坑。
2. **反直觉的代价**：打印 `1..10^n` 的复杂度是 `O(n · 10^n)`——n 每加 1，
   工作量乘 10。`10^6` 本身就一百万位，这类题的真正瓶颈**不在算法而在
   I/O**。所以工程上人们改问"末k位是什么"（`n! mod 10^12`，示例给了
  n = 10/15/20/25 四组），答案才是可计算的。

### 高精度 + 模：最常用的组合

真实场景里很少要`10^100` 的精确值，要的是"`mod m` 的值"。这时不需要
高精度，只需要**边乘边取模**——中间量始终在 `[0, m)`，用 `long long`
装得下（若 m < 3×10⁹，见坑位清单第 3 条）。示例给了
n! 的末 12 位。

顺带一个数论结论：`n!` 末尾零的个数 = Legendre 公式
`Σ_{k≥1} ⌊n/5^k⌋`（每个 10 = 一个 2 和一个 5，而 2 永远比 5 多）。
n = 1000 时是 249。示例给了迭代版与递归版两套实现并逐项对账——
这类"迭代 ↔ 递归"的对等实现是验证递归式正确性的最省力手段。

## C++23 语言点

- 全程 `long long`（64 位）：模乘 a·b < n² ≤ 63 位才安全——n > 3×10⁹
  时要 `__int128`（GCC/clang 有、MSVC 无——三通道纪律下用「乘法拆分」
  或限制 n 范围，本例 n=3233 远离边界）；
- 递归版 ext_gcd 的引用多返回值（x/y 出参）——与第 4 章 struct 返回
  两种风格任选；
- `std::format` 的字面花括号要转义（`m^{ed}` 写成 `m^{{ed}}`——本例
  实测翻车的编译错）。

## 与 STL 对照

`std::gcd`/`std::lcm`（`<numeric>`，C++17）覆盖欧几里得；无模幂/
Miller-Rabin（密码学不走标准库——OpenSSL/libsodium 的领地）。
`std::mt19937` 在密码场景**禁用**（可预测）——需要 CSPRNG。

## 坑位清单

1. **φ(n) 算错（本例实测翻车）**
   （现象：逆元断言挂——17⁻¹ mod 3220 ≠ 2753；原因：φ(3233) =
   φ(61·53) = 60·52 = **3120**，手滑写成 3220（像 p+q 的和）；对策：
   φ 由 (p−1)(q−1) 现场计算，别手抄常数（本例修正版）。）
2. **试除捷径吃掉见证检验（本例实测翻车）**
   （现象：对 561 的「witness 拆穿」断言不触发；原因：基列表含 3，
   而 3 | 561，试除提前返回「合数」（结论对）但没走 Miller-Rabin 的
   平方根检查（演示失效）；对策：试除只留 2，基列表专用于见证。）
3. **模乘溢出**
   （现象：大 n 下结果随机错；原因：a·b 在 long long 里溢出（n > 3×10⁹
   时 n² > 2⁶³）；对策：__int128 / 乘法拆分（俄罗斯农民式）/ 限制
   n < 3×10⁹，并把「安全范围」写成注释与断言。）
4. **Fermat 测试当确定性用**
   （现象：561 被判素；原因：Carmichael 数对全部互素基撒谎；对策：
   Miller-Rabin（平方根检查）+ 随机基，或对小 n 用试除打表。）
5. **格式串里的 `^{...}`**
  （现象：编译错误指向 consteval；原因：`{ed}` 被当占位符；对策：
  转义为 `{{ed}}`——数学文案进 format 的通例（本例实测翻车）。）
6. **判 2 的幂漏掉 x = 0（本例实测翻车）**
  （现象：`is_power_of_two(0)` 返回 true；原因：`-1` 的补码全 1，
  `0 & (0-1) == 0` 成立；后果：0 被当成 2 的幂参与后续除法；对策：
  显式加 `x != 0`，或直接用 `std::has_single_bit`（对 0 返回 false）。）
7. **用"先乘再看符号"探测溢出**
   （现象：优化版下溢出检查分支被整条删掉；原因：有符号溢出是 UB，
  编译器有权假设它不发生；后果：静默错值或行为不可预测；对策：
   用 `__int128` 中间量，或用 `|r| > mag / |base|` 在乘法前预判。）
8. **`abs(INT64_MIN)` 与"负向多一位"**
   （现象：溢出检测把 `-2^63` 误判为装不下；原因：int64 的值域是
   `[−2^63, 2^63−1]`，负向多一位，`|−2^63| = INT64_MAX+1`；后果：
   边界判定差一；对策：API 接受"最大绝对值" mag（用 `__int128` 表达
   2^63），而不是"整数上限"。）
9. **倒序循环起点差一位（本例实测翻车）**
   （现象：`999 + 1` 打印成 `000`；原因：`for (i = d_.size()-1; i-- > 0;)`
   中后置递减在**比较之后**才执行，循环体看到的第一个下标是
   `size()-2`，最高位被跳过；后果：漏一位；对策：写
  `for (i = d_.size(); i-- > 0;)`——这也是全教程统一的倒序写法
   （见第 8 章稳定排序）。负数还需额外跳过符号位。）

  0xF0F0F0F0F0F0F0F0    32        32   32
  0x8000000000000001     2         2    2
  n&(n-1) 全程共 54 次循环——恰等于样本里 1 的总个数；
  差别在于它每轮只碰一个 1（x 直接缩到下一个 1），逐位法要扫全 64 位。

判 2 的幂（x > 0 且 (x & (x-1)) == 0）：
                     0x1 -> true
                     0x2 -> true
                     0x3 -> false
                    0x10 -> true
                   0x400 -> true
      0x4000000000000000 -> true
      0x4000000000000001 -> false
  等价物 std::has_single_bit 对 0 返回 false，比手写更安全——
  手写 (x & (x-1)) == 0 对 x=0 也成立，这是最容易漏的边界。

=== 32.6 整数次方 a^n：朴素 vs 快速幂 ===
   n            3^n（朴素）          3^n（快速幂）  朴素乘法 / 快速幂乘法
   1                      3                      3         1 / 1
   2                      9                      9         2 / 3
   5                    243                    243         5 / 5
  10                  59049                  59049        10 / 7
  19             1162261467             1162261467        19 / 9
  20             3486784401             3486784401        20 / 9
  39    4052555153018976267    4052555153018976267        39 / 11
  40   -6289078614652622815   -6289078614652622815        40 / 11
  朴素 = n 次乘法，快速幂 ≈ 2*ceil(lg2 n) - 1 次；n=40 时 40 -> 11 次。
  但两者的溢出点完全一样（都停在 3^39）——真实值不会因为乘法变少而变小。
  快速幂省的是时间，不是表示范围。

  溢出边界（int64 负向能到 -2^63，正向上限 9223372036854775807）：
    3^39 = 4052555153018976267   <- 最后一个装得下的
    3^40 = 12157665459056928801 已超上限 -> 转高精度（32.7）

  负底数边界：-2^63 = -9223372036854775808 装得下（正是 INT64_MIN），-2^64 装不下
  pow_checked 的参数是**最大绝对值** mag = 2^63，而不是 INT64_MAX：
  int64 的负向空间比正向多一位，|-2^63| = INT64_MAX + 1，恰好装得下。
  所以实现用「除法预判」而不是「先乘再看符号」——后者依赖 UB。

=== 32.7 高精度：位向量大数 ===
  999 + 1 = 1000（连进位：最高位 9 -> 0 再进 1）
  7 * 999 = 6993（逐位乘 + 连锁进位）
  10^0..10^6 = 1 10 100 1000 10000 100000 1000000
  负数 -25：位向量长度 = 3（含符号位），字符串 = -25
  3^40 = 12157665459056928801（20 位；long long 到 3^39 就满了）

  位数与代价：10^k 有 k+1 位，两数相乘是 O(位数之积) 次单步运算
    10^3  需要  4 位
    10^5  需要  6 位
    10^7  需要  8 位
    10^10 需要 11 位
    10^20 需要 21 位
  所以「打印 1 到 10^n」在高精度下是 O(n * 10^n)：n 每加 1 工作量乘 10。
  真要打印 10^6 本身就一百万位——这类题的难度不在算法，在 I/O。

  n! 末 12 位（mod 10^12，模数装得进 long long）：
    10! =       3628800
    15! =  307674368000
    20! =    8176640000
    25! =  985984000000
  对照：25! = 15511210043330985984000000，末 12 位 = 985984000000
