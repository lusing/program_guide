# 19 · B 树

> 对应 CLRS 第 18 章 *B-Trees*（英文 3rd ed. pp.484–504）。B 树是为
> **磁盘**设计的多路平衡搜索树：每个节点一大块（对齐一次页/扇区读），
> 高度被分叉率压到对数的底变大——10⁹ 行数据只要 3 层。数据库索引
>（MySQL InnoDB、PostgreSQL）与文件系统（NTFS、ext4）的骨架全是它。

## 学习目标

1. 能陈述最小度数 t 的约束（节点键数 ∈ [t−1, 2t−1]）与高度界
   h ≤ log_t((n+1)/2)；
2. 会实现「主动分裂」的插入（下降前先拆满孩子）；
3. 能走完删除的三情形（叶删 / 换前驱后继 / 借与并）与下钻补厚；
4. 会写 B 树不变式验证器（叶同深、键数范围、全序）。

## 结构与不变式

最小度数 t ≥ 2 约束每个节点：

- 键数：根 ∈ [1, 2t−1]，其余 ∈ [t−1, 2t−1]；
- 内点的孩子数 = 键数 + 1；叶全部同深；
- 键在中序下全局有序。

高度界（定理 18.1）：n 个键的 B 树高 h ≤ log_t((n+1)/2)。t=3、n=1000
时界为 7，实测 5（示例 19.4）——**每层一次页读取**，3~5 次 IO 定位
10 亿行里的任意键，这是 B 树存在的全部理由。t 的选取是「节点大小 ÷
(键+指针) 尺寸」的工程决定：4KB 页、16B 键 + 16B 指针 → t ≈ 128。

## 插入：主动分裂（§18.2）

朴素想法（插入叶、满了再回头分裂并上移中位键）需要回溯父路径；CLRS
的技巧是**下降路上顺手拆掉满孩子**：

```cpp
void insert_nonfull(Node* x, int k) {
    if (x->leaf()) { /* 叶内有序插入 */ return; }
    std::size_t i = /* 找到孩子区间 */;
    if (x->ch[i]->keys.size() == 2*t - 1) {
        split_child(x, i);           // 先拆：中位键上移，右半成新孩子
        if (k > x->keys[i]) { ++i; }
    }
    insert_nonfull(x->ch[i], k);     // 保证下降目标绝不满
}
```

根满时先建新根再分裂旧根——**B 树唯一的长高方式是从根部长高**（叶
同深的不变式因此天然保持，这也是 B 树比红黑树「好实现」的根源）。
split_child 把 2t−1 键的孩子拆成两个 t−1 键的，中位键上移给父亲。

示例 19.2 复刻 CLRS 图 18.8：19 个字母按 G M P X A C D E J K N O R S
T U V Y Z 顺序插入 t=2 的 B 树，终态不变式验证通过、高度 3、19 键全
命中、中序即字母序。

## 删除：三情形与下钻补厚（§18.3）

删除的难点：删完可能让某节点掉到 t−2 键（违约）。CLRS 的对策是
**下降前保证目标孩子至少有 t 个键**（有富余可挥霍）：

- **情况 1（键在叶）**：直接删（叶至少 t 键，删后 ≥ t−1 ✓）；
- **情况 2（键在内点 x）**：
  - 2a：键左侧孩子有 ≥ t 键 → 取左子树**前驱**（左孩子的最右叶的
    最大键）顶上来，去左子树删那个前驱；
  - 2b：右侧孩子富余 → 对称地换**后继**；
  - 2c：两个孩子都恰 t−1 → 合并（父键下移夹中间成 2t−1 键的新节点），
    在合并节点里递归删；
- **情况 3（键不在 x）**：要下降的孩子若只有 t−1 键，先「补厚」：
  从富余的兄弟**借**一个（兄弟键上移、父键下移），否则与兄弟**合并**
  （父键下移粘合）。然后才下降。

整棵树短高的唯一方式是根只剩两个 t−1 孩子被合并——根撤编，高度减一。
示例 19.3 删 'G' 后全量重验证（多次删除与结构打印留作练习）。

## 磁盘视角：为什么是 B 树

搜索代价 = 高度次**节点访问**。示例 19.4 的实测口径（t=3、n=1000）：

```
B 树（t=3，n=1000 随机插入）：高度 = 5（界 log_3((n+1)/2)+1 = 7）
  1000 次成功搜索共访问节点 4689 个（均 4.69，≤ 高度 5）
```

平均 4.69 次节点访问 = 磁盘场景的 4.69 次页读取。对比二叉树（同一千
键期望 ~10 次节点访问、且节点散落各页）——**B 树把「比较次数」换成
「IO 次数」的优化目标**，节点内的线性/二分扫描（页内 CPU 操作）几乎
免费。缓存友好版二叉树（如第 13 章的 arena 红黑树）在纯内存里仍能赢
B 树，但换到磁盘/SSD 页模型 B 树碾压——**复杂度的「单位」要对着
存储层次选**。

## C++23 语言点

- 节点用裸 `new`/`delete`（教学聚焦算法本身；arena 版见第 13 章模式，
  生产 B 树用页缓冲池管理节点生命周期）；
- `std::ranges::lower_bound` 做节点内定位（t 大时可换二分，渐进不变）；
- 不变式验证器的三件套：键数范围 / 叶同深 / 中序全局有序——每次改动
  后全量重验（示例 assert 的写法）。

## 与 STL 对照

无标准库 B 树容器（`std::map` 是内存红黑树）。生态：

- 数据库引擎的索引页（InnoDB 的 B+ 树变体：内节点只存键、数据全在
  叶、叶成链表便于范围扫描）；
- `std::flat_map`（VS18 起）是排序向量不是 B 树——cache 友好但插入
  O(n)，与本教程的「特性禁用清单」一致（未过三通道一致性）；
- LMDB/LevelDB/RocksDB：B 树 vs LSM-Tree 的现代路线之争（写放大 vs
  读放大）——B 树一系的工程化终点。

## 坑位清单

1. **插入走「先插叶再回溯分裂」**
   （现象：实现冗长且根分裂路径漏情况；原因：CLRS 的主动分裂把「孩子
   绝不满」做成了下降不变式，回溯版要处理父路径上每一层；后果：边界
   bug 多、难验证；对策：下降前 split_child，保证 insert_nonfull 的
   前提永真。）
2. **删除下钻前忘补厚**
   （现象：某些删除序列让节点掉到 t−2 键，验证器亮红；原因：情况 3 的
   fill_child（借/并）是下降的守门员——跳过它，深层删除无富余可挥霍；
   后果：不变式破坏；对策：递归入口统一「目标孩子 ≥ t 键」断言。）
3. **借兄弟时只移键不移子树**
   （现象：中序序断裂、搜索丢失子树；原因：内点的借要三件套——兄键
   上移、父键下移、兄弟的孩子指针过继——只动键不动孩子即错；后果：
   结构性损坏；对策：借操作封装成一个函数，键/孩子同步搬，验证器
   兜底。）
4. **根撤编忘收缩高度**
   （现象：根只剩一个孩子仍占一层，「高度」虚高，验证器报叶深不一；
   原因：merge 后根键空了要下移到独子；后果：不变式与高度界双双失真；
   对策：erase 尾部统一 shrink_root。）
