# 28 · 多线程算法：CLRS 模型的 C++23 适配

> 对应 CLRS 第 27 章 *Multithreaded Algorithms*（英文 3rd ed. pp.772–
> 801）。CLRS 用 `spawn`/`sync` 伪代码关键字讲并行；C++23 没有 spawn，
> 对应物是 `std::jthread`（自动 join 的线程）+ `std::barrier`（相位
> 汇合）。本章把 CLRS 的**工作-跨度模型**（T₁/T∞）翻译成可运行的
> C++23，并用「确定性对账」代替「墙钟计时」——本教程输出纪律在并行
> 场景的延续。

## 学习目标

1. 能定义工作 T₁ 与跨度 T∞，陈述贪心调度定理 T_p ≤ T₁/P + T∞；
2. 会用 `std::jthread`/`std::barrier` 写 CLRS spawn/sync 的等价物；
3. 理解并行归并排序的 T∞ = Θ(lg n) 为什么「免费」（深度即串行链）；
4. 知道并行算法验证的坑：结果要对账、输出要确定（不能按完成序打印）。

## CLRS 的动态多线程模型

```clrs
P-SUM(A)              // 数组求和的并行分治
1  spawn P-SUM(左半)   // 并行子任务（不等它）
2  右半自己算          // 本线程继续
3  sync                // 等全部孩子归队
4  合并两半结果
```

**工作量 T₁**：单处理器上的总操作数（串行模拟）；**跨度 T∞**：无限
处理器下的关键路径长度（串行依赖链）。加速比被两头夹：

**贪心调度定理（27.1）**：T_p ≤ T₁/P + T∞。P 个处理器把工作摊薄，
但**深度兜底**——再多的核也救不了长串行链（Amdahl 定律的算法版）。
并行归并排序：T₁ = Θ(n lg n)（工作没省），T∞ = Θ(lg n)（树深）——
理论加速上限 T₁/T∞ = Θ(n)：**并行不减少工作，只压缩墙钟**。

实测账本（示例 28.4，示意常数）：

```
n=1024：工作 T1 ~ n·lg n = 10240，跨度 T∞ ~ 2·lg n = 20，理论加速上限 T1/T∞ ~ n/2 = 512
n=65536：工作 T1 ~ n·lg n = 1048576，跨度 T∞ ~ 2·lg n = 32，理论加速上限 T1/T∞ ~ n/2 = 32768
```

## C++23 适配一：分块并行排序（jthread）

CLRS 的递归 spawn 在 C++ 的务实对应物是「顶层切 K 块、每块一个线程、
join 后归并」（真实运行库里线程创建有开销，递归 spawn 到叶子得不偿失
——OpenMP/Cilk 的任务池才是 spawn 的正统工程化身）：

```cpp
std::vector<std::thread> pool;
for (k in 0..K) {
    pool.emplace_back([&, k] {          // CLRS 的 spawn ≈ 开线程干这块
        msort_span(parts[k], partCompares[k]);
    });
}
for (auto& th : pool) { th.join(); }    // CLRS 的 sync ≈ join
// 之后顺序两两归并（真正的 P-MERGE 可再并行化，教学版从简）
```

**确定性对账**（示例 28.2/28.3，n=200000、固定种子）：

```
K=1：比较 3479481 次，spawn 1 次
K=4：比较 3529480 次，spawn 4 次（与 K=1 结果逐元素一致）
K=4/K=1 比较数比值 = 1.0144（分块边界 ± 小常数，渐近同为 n lg n）
```

K=1 与 K=4 用**同一份代码**（K 是参数）——排序结果逐元素相等（assert），
比较计数在 1.014 倍内（分块边界让小段插入排序的常数略变，渐近不变）。
**为什么不用墙钟**：并行计时受调度/频率/核占用影响，同机两次运行都
不同——本教程的逐字节对账纪律在并行场景自动升级为「结果对账 +
计数对账」。`hardware_concurrency()`（本机 8）只作结构性事实打印。

## C++23 适配二：相位同步（barrier）

CLRS 的 `sync` 在多相位算法里对应 `std::barrier`（C++20）：

```cpp
std::barrier syn(kThreads);
for (int t = 0; t < kThreads; ++t) {
    pool.emplace_back([&, t] {
        for (int ph = 0; ph < kPhases; ++ph) {
            total[t] += (t + 1) * (ph + 1);       // 本相位的工作
            syn.arrive_and_wait();                // 相位汇合（sync）
        }
    });
}
```

实测（4 线程 × 3 相位）：累加合计 60 = (1+2+3+4)×(1+2+3)——**相位的
顺序无关性**使结果确定（每相位每线程只动自己的段）。`std::jthread`
的析构自动 join（RAII 线程），异常路径不漏线程——它比裸 `std::thread`
更适合教学与工程。

## 并行算法的验证学

1. **结果对账**：并行版结果 == 串行版结果（逐元素）——最强的正确性
   信号；
2. **输出纪律**：绝不能「谁干完谁打印」（完成序随机）——要么按索引
   回收（第 01 章纪律），要么只在汇合后由主线程打印；
3. **数据竞争**：每线程写自己的段/槽，共享只读；需要共享写时用
   `std::atomic` 或按相位划分——示例的 `partCompares[k]` 按线程分槽；
4. **`std::execution::par` 为什么被本教程禁用**（docs/01）：MSVC STL
   有并行后端、libstdc++ 没有——三通道不一致，手写 jthread 是唯一
   可对账的路线。

## 与 STL 对照

- `std::jthread`（C++20）：RAII 线程 + 协作取消（`stop_token`）；
- `std::barrier`/`std::latch`（C++20）：多相位汇合 / 一次性倒计时；
- `std::async`/`std::future`：任务级并行（返回值管道）——与 jthread
  的取舍是「任务图」vs「工作线程」；
- `std::execution` 并行算法（C++17 起）：`sort(par, ...)` 一行并行——
  本教程禁用（通道不一致），但它是生产代码的首选。

## 坑位清单

1. **按完成序打印输出**
   （现象：三通道/两次运行的输出行序不同，对账必炸；原因：线程调度
   决定完成序；对策：结果按索引回收、汇合后主线程统一打印（本例与
   docs/01 的纪律）。）
2. **`<span>` 忘包含（gcc 侥幸过、MSVC/clang 红线）**
   （现象：gcc 通道绿灯、另两通道「no member named span」；原因：gcc
   的传递包含链碰巧带了它——三通道一致性才能暴露；对策：显式包含
   全部使用的标准头（本例实测翻车）。）
3. **共享计数器裸加**
   （现象：偶发的合计错误（丢更新）；原因：`counter++` 非原子，多线程
   读写竞争；对策：`std::atomic` 或按线程分槽后汇总（本例两种都示范）。）
4. **递归 spawn 到底层**
   （现象：线程数爆炸（n=10⁶ 递归切到叶子 = 百万线程）或开销大于计算；
   原因：线程创建是微秒级、小任务摊不平；对策：顶层固定 K 块（本例）
   或阈值切串行（与第 7 章快排 cutoff 同一思想）。）
5. **把 hardware_concurrency 当保证**
   （现象：K = hardware_concurrency 写死，换机器性能漂移；原因：它只
   是提示（可为 0）；对策：K 作参数、对账不依赖 K（本例 K=1/4 同码
   对账）。）

## 练习

1. （CLRS 练习 27.1-1/27.1-4）spawn/sync 图展开成计算 dag；P-FIB 的
   T₁ = Θ(φⁿ)、T∞ = Θ(n) 推导（为什么递归 spawn 斐波那契不划算）。
2. （CLRS 练习 27.2-1/27.2-2）P-SUM 与 P-MERGE-SORT 的 T₁/T∞ 表
   （对账本章的账本）。
3. （CLRS 练习 27.3-1/27.3-2）P-MERGE 的跨步工作 T∞ = Θ(lg²n)——真正
   并行归并的深度代价。
4. （CLRS 思考题 27-4/27-5）并行归约的下界（任何二叉归约 dag 深度
   ≥ lg n）；SPMD 矩阵乘的静态调度。
5. （本教程）把示例的顺序归并段改成两两树形归并（每层一个 barrier
   相位），对账结果与 K=1 仍逐元素一致；再给 barrier_demo 加
   `arrive_and_drop` 的动态参与人数变体。
