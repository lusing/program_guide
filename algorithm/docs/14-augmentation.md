# 14 · 数据结构扩张：顺序统计树与区间树

> 对应 CLRS 第 14 章 *Augmenting Data Structures*（英文 3rd ed. pp.339–357）。
> 主题只有一句话：**在现成结构上加一个字段，让新查询变 O(lg n)**——但要
> 证明这个字段在每次修改下仍能高效维护。这是工程里「改造标准容器」的
> 理论化版本。

## 学习目标

1. 能复述扩张方法论四步（选底座/选附加信息/验证可维护/设计新操作）；
2. 会实现顺序统计树的 OS-SELECT/OS-RANK 并证明 size 的可维护性；
3. 会实现区间树的 max 扩张与 INTERVAL-SEARCH 的左优先论证；
4. 理解「维护代价 = 底座单次修改代价」这一关键的免费性论证。

## 扩张方法论（§14.1）

四步走（CLRS p.339）：

1. **选底座**：红黑树（要 O(lg n) 的最坏保证）；
2. **选附加信息**：每个节点多存一个字段（如子树 size、子树 max）；
3. **验证可维护**：证明一次更新（插入/删除/旋转）只影响「沿路 O(lg n)
   个节点 + 旋转的 O(1) 个节点」的字段，且每个能 O(1) 重算——于是
   **维护不改变底座的渐近代价**；
4. **设计新操作**：利用附加字段把新查询做到 O(lg n)。

第 3 步是灵魂：**附加信息的维护规则必须局部化**。判断标准（定理 14.1）：
字段 f[x] 只依赖 x 及其**直接孩子**的信息 ⇒ 旋转/插入/删除时沿 O(lg n)
路径维护即可。size 和 max 都满足（size[x] = size[left]+size[right]+1；
max[x] = max(hi[x], max[left], max[right])）。

> 教学取舍：示例底座用朴素 BST（随机固定输入下深度健康）——维护规则
> 与红黑树版完全一致，红黑版只是把「沿路 +1」放进插入路径、把「重算
> 两节点」放进旋转。`std::map` 没有扩张钩子（模板参数里塞不进附加
> 维护逻辑），真实工程用 `__gnu_pbds::tree`（gcc 扩展）或手写。

## 顺序统计树（§14.2）

每个节点加 **size**（子树节点数）。两个新操作：

**OS-SELECT(i)——找第 i 小**：在节点 x 处，r = size[left[x]] + 1 是 x
自己的名次；i == r 命中，i < r 进左，i > r 进右并扣掉 r。一次下行，
O(h)。示例 14.2 实测（20 键、随机固定插入序）：

```
顺序统计树（size 扩张 BST，20 键）：
  OS-SELECT(5) = 14（排序后第 5 位 = 14，对账一致）
  OS-SELECT(i) ∀i=1..20 与排序表逐位一致 = 1
```

**OS-RANK(x)——x 的名次**：从 x 上行到根，初值 r = size[left[x]]+1
（子树内名次）；每当 x 是父亲的**右**孩子，r += size[left[父]] + 1
（父亲左子树全体 + 父亲本人都排在 x 前面）。O(h)。

对账方式（示例的做法）：select 是 rank 的逆——`select(i) 的键 ==
sorted[i−1]` 对所有 i 成立，两个操作的正确性互锁。第 9 章的
`nth_element` 也能选第 i 小（期望 O(n)），顺序统计树赢在**动态**：
混合插入/删除/选择，每次都 O(lg n)。

## 区间树（§14.3）

节点存闭区间 [lo, hi]，按 **lo**（中序键）组织，附加字段 **max** =
子树中所有 hi 的最大值。

**INTERVAL-SEARCH(i)**（找任一与 i 重叠的区间，重叠定义 lo ≤ i.hi ∧
i.lo ≤ hi）：

```cpp
while (x != NIL && !overlap(int[x], i)) {
    if (n[x].l != NIL && n[n[x].l].mx >= i.lo) x = n[x].l;  // 左子树可能有解
    else                                               x = n[x].r;
}
```

**左优先的正确性**：进右子树的前提是「左子树 max < i.lo（左子树整棵
不可能重叠）且本节点不重叠」——若存在重叠区间而在这一步进了右子树，
该区间只能在中序序里 x 的右侧……关键引理：若 i 与树中某区间重叠但
与 x 不重叠，则重叠者**或**在右子树，**或**左子树的 max ≥ i.lo
（因为重叠 ⟺ lo ≤ i.hi ≤ hi，而左子树任何区间的 lo < x.lo）。
于是算法永不漏解——返回 NIL 时全树确实无重叠。示例 14.3 用 CLRS
图 14.4 的 10 个区间实测：

```
区间树（max 扩张，图 14.4 的 10 个区间）：
  INTERVAL-SEARCH(14,16) → [16,21]（与 (14,16) 重叠）
  35 个点查询与暴力「是否存在重叠」全部一致 = 1
```

注意语义：INTERVAL-SEARCH 只要**存在**重叠就返回**某一个**（不必是
中序最先者——那是更强的「 stabbing 查询」问题，思考题 14.4-6 的线段
树才是它的正解）。

## C++23 语言点

- 附加字段直接进 arena 数组（`std::vector<std::size_t> size`）——
  「扩张」在数组表示下就是多一列，直观到没有解释成本；
- 查询操作的 `const` 全量标注（os_select/search 不改树）；
- 结构化绑定遍历区间对：`for (auto [lo, hi] : ivs)`。

## 与 STL 对照

`std::map` 无法扩张（无钩子）；能用的现成方案：

- `__gnu_pbds::tree`（gcc/clang 扩展）——真正的 order-statistics tree，
  `find_by_order` / `order_of_key` 就是 OS-SELECT/OS-RANK；
- 线段树/树状数组（竞赛语境）——区间 max 的另一种扩张形态（第 22 章
  并查集之外的「另一棵实用主义树」）；
- 手写：本章路线（底座 + 字段 + 验证器）。

## 坑位清单

1. **max 维护漏了「节点自身」**
   （现象：偶尔返回 NIL 但暴力说有解；原因：max[x] 应取
   max(hi[x], 左 max, 右 max)——忘了 hi[x] 自己，恰好 x 是候选时判空；
   后果：查询漏解；对策：维护式写成三元的完整形式 + 暴力对账测试
   （示例 35 个点查询就是干这个的）。）
2. **区间树按 hi 做中序键**
   （现象：左优先论证失效，查询漏解；原因：区间树的 BST 键是 **lo**，
   hi 只进 max——按 hi 组织时「左子树 lo 更小」不成立；后果：正确性
   证明的根基塌掉；对策：键与附加字段别混，插入比较用 lo、维护用
   max(hi)。）
3. **OS-SELECT 的名次扣减忘了做**
   （现象：进右子树后仍用原 i，选出的总是偏小；原因：进右时右子树的
   名次从 i−r 重新数起；后果：全量对账立刻全错；对策：`i -= r` 与
   教科书逐行对照，加 select(i)==sorted[i−1] 的逆命题断言。）
4. **扩张破坏了底座的性能**
   （现象：加了字段后插入变 O(n)；原因：维护规则没有局部化——比如
   每次插入后全量重算所有 size；后果：扩张的白赚变白亏；对策：先过
   定理 14.1 的检核（只依赖直接孩子），再写代码。）
