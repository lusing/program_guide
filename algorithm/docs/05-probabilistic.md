## 附录 C 速览：概率的公理与期望

样本空间 S、事件 A ⊆ S、概率函数 P 满足：非负、P(S)=1、可列可加。对本教程
最要紧的三件套：

- **均匀随机**：S 上每个基本事件等概率 1/|S|，则 P(A) = |A|/|S|（计数登场，
  C(n,k) 排列组合是附录 C.2 的主角）；
- **期望的线性性**：E[aX+b]=aE[X]+b，**E[X+Y]=E[X]+E[Y] 无需独立性**——
  这是本章最重要的一个「免费午餐」，示例 05.1 里「伯努利(1/4) 数组中 1 的
  个数期望 = n/4」就是它一行推出来的（实测 25098 vs 期望 25000）；
- **方差** Var(X)=E[(X−E[X])²]=E[X²]−E[X]²，独立时可加——第 11 章散列的
  期望探测链长会用。

## 指示器随机变量（§5.2）

对事件 A 定义 I{A} = 1（A 发生）或 0（不发生），则 E[I{A}] = P(A)。

**引理 5.1**：X = Σᵢ Xᵢ（Xᵢ 为指示器）⇒ E[X] = Σᵢ P(Aᵢ)。

为什么它无处不在：把「数某个东西的个数」改成「每个候选东西贡献 0/1」，期望
就化成一堆概率的加法，而概率往往比分布好算。

## 雇佣问题（§5.1–5.2）

**问题**：每天面试一个候选人，面试费 cᵢ 小；面试后如果比在职者强就换人，
雇佣费 cₕ 大（cₕ ≫ cᵢ）。总代价 = n·cᵢ +（雇佣次数 m）·cₕ——要分析的
随机变量是 m。

```clrs
HIRE-ASSISTANT(n)
1  best = 0        // 虚拟候选人，资质为 0
2  for i = 1 to n
3      interview candidate i
4      if candidate i better than best
5          best = candidate i
6          hire candidate i
```

**期望分析**：Xᵢ = I{第 i 人被雇佣} = I{第 i 人是前 i 人中最好}。随机排列下
这个概率恰是 1/i（最好的在前 i 个位置等可能）。于是

E[m] = Σᵢ₌₁ⁿ 1/i = H_n = ln n + O(1) = Θ(lg n)。

示例 05.2 的对账：n=20 时 H₂₀ = 3.5977（≈ ln 20 + 欧拉常数 0.5772 = 3.5729），
五个固定种子的实际雇佣次数 3、5、1、4、2——围绕期望波动，最坏 20（严格
递增资质）最好 1（第一个就是最强者）。

注意分析的**随机性来自哪里**：这里假设候选人到达顺序是随机排列（概率分析，
算法本身是确定的）。§5.3 把随机性搬进算法——**随机化雇佣**：先自己洗牌再
面试，期望雇佣数同样是 H_n，但不再依赖「输入本来随机」的假设。这一个转向
（分析输入的分布 vs. 主动引入随机）就是概率分析与随机化算法的分界线。

## 生日悖论（§5.4.1）

**问题**：房间里最少多少人，能使两人同生日的概率过半？直觉答案 ~183
（365 的一半）；真答案是 **23**。

**视角一：精确概率。** k 人生日互异的概率

P(互异) = Π_{i=1}^{k−1} (365−i)/365（第 i+1 人要避开前 i 人的生日）。

逐项连乘（固定顺序的浮点乘法是确定的），找到第一个 ≤ 1/2 的 k：

```
k=23：P(互异) = 0.492703 → 碰撞概率 0.507297
```

**视角二：指示器期望（CLRS 的分析）。** 令 Xᵢⱼ = I{i 与 j 同生日}，P = 1/365：

E[同生日对数] = C(k,2)/365。k=23 时 = 253/365 ≈ 0.693。

**两个视角回答不同的问题**：期望对数 0.693 ≠ P(至少一对) 0.507。期望 > 0
只说明「平均有 0.69 对」，而「至少一对」要精确乘积才算。反过来用
C(k,2)/365 ≥ 1 去推「至少一对」会得到 k=28——偏大（马尔可夫不等式只给
上界 P ≥ E[X]/1 在 E>1 时才强制碰撞）。示例 05.3 同时打印两个数并做了
20000 组模拟（0.5105 vs 精确 0.5073）。

## 球与箱子、最长连续正面（§5.4.2–5.4.4）

- **球与箱子**：m 个球独立均匀扔进 n 个箱，期望每箱 m/n 个球；「某箱空」的
  期望个数为 n·(1−1/n)^m ≈ n·e^{−m/n}（思考题里反复出现，第 11 章散列
  的装填因子同构）；
- **最长连续正面**：n 次抛硬币，考察「某个长度为 k 的窗口全正」的指示器——
  期望出现次数约 n/2^k。取 k = lg n + c：窗口数 × 概率 ≈ 2^{−c}；于是最长
  连续正面的典型长度是 Θ(lg n) 量级、常数因子内浮动。示例 05.4：n=100 抛
  2000 组，平均最长正面 **5.99**（lg 100 = 6.64 附近），组间最大冲到 15——
  「典型 Θ(lg n)、尾部可到 c·lg n」的实证。

这两节的方法论与生日悖论一致：**用指示器把「存在性/极值」问题化成期望
加法**，阈值取在「期望次数 ≈ 1」的分界上。

## RANDOM(a,b) 与模偏倚

CLRS 的 RANDOM(a,b) 由 RANDOM(0,1)（抛硬币）构造：取 k = ⌈lg(b−a+1)⌉ 位，
生成 r ∈ [0, 2^k)，若 r ≤ b−a 则返回 a+r，否则重抛（拒绝采样）——无偏但
期望 2 次以内。工程实现更常用 Lemire 的**乘法-移位法**（本教程的
`rand_below`，docs/01 讲过）：

```cpp
static std::uint32_t rand_below(std::mt19937& rng, std::uint32_t n) {
    std::uint64_t m = static_cast<std::uint64_t>(rng()) * n; // [0, n·2^32)
    return static_cast<std::uint32_t>(m >> 32);              // [0, n)
}
```

对比天真的 `rng() % n`：2³² 不是 n 的倍数时小余数多分到概率（n=6 时前
4 个余数多 2³²/6 的小数尾巴），模偏倚就这么来的。Lemire 法把 [0,2³²)
放大 n 倍再取高 32 位，每个值分到恰好 ⌈2³²·?⌉ 区间，偏差为零（严格说
是「无偏到测度零级别」）。

再强调一次 `std::uniform_int_distribution` 为什么被本教程禁用（docs/01 坑位
4）：引擎（mt19937）逐位规定、跨实现相同；**分布算法是实现自由**——MSVC 与
libstdc++ 用同一种子产出不同序列。模拟实验要做跨通道逐字节对账，就必须
引擎+分布都自己钉死。

## RANDOMIZE-IN-PLACE：均匀洗牌的证明（§5.3）

```clrs
RANDOMIZE-IN-PLACE(A)
1  n = A.length
2  for i = 1 to n
3      swap A[i] with A[RANDOM(i, n)]
```

**概率版循环不变式**：第 2–3 行的 for 第 i 轮迭代开始时，对每个可能的
(i−1)-排列，A[1..i−1] 恰以 1/(n−i+1)!·… 等概率——准确陈述：A[1..i−1] 包含
前 i−1 轮选出的特定 (i−1) 排列的概率是 (n−i+1)!/n!，即每个 (i−1)-排列
等概率。

三段论与第 2 章同构（初始化 i=1 平凡；保持：第 i 轮从「每个 (i−1)-排列
等概」+「第 i 位均匀选自剩余 n−i+1 个」推出每个 i-排列等概；终止 i=n+1：
每个 n-排列等概 1/n!）。细节见 CLRS p.126–127 的引理 5.4/5.5。

**错误版本长什么样**：把 RANDOM(i,n) 写成 RANDOM(1,n)——每步全范围交换。
它不均匀：示例 05.5 用 n=3、270000 次实测，六种排列的计数是

```
正确版： 44786 45284 45170 44836 44762 45162（期望 45000，±5% 内）
错误版： 39855 49893 50138 50083 40033 39998（4:5 两档，差 10283）
```

错误版的 27 条等概率交换路径映射到 6 个排列时，有的排列被 4 条路径命中、
有的被 5 条——4:5 两档偏倚就这么留在数据里。而 CLRS 方向（j 从 i 到 n）
保证每轮恰好把「剩余元素的均匀选择」编入前缀，计数才有 1/n! 的证明。

## 最小割：随机收缩（Karger 算法）

**边割**是一个边集，删掉它图就不连通；**全局最小割**是边数最少的那个。注意它
不指定源点汇点——和第 27 章的 s-t 割不是同一个问题。

### 一次试验

```clrs
CONTRACT-TRIAL(G):
  while G 中顶点数 > 2:
      从当前边里等概率随机选一条 (u,v)
      把 u、v 收缩成一个顶点（连接二者的边变自环，丢弃；其他边全部保留，
      平行边也保留）
  返回两个剩余顶点之间的边数（以及它们各自包含哪些原顶点）
```

收缩 n−2 次后恰剩两个超顶点，它们之间的边就是某个割。平行边必须保留——一方连
到另一方有几条边，割的权重就是几。实现中自环在「随机选中」时才被发现丢弃；
拒绝重抽保证每条**非自环**当前边仍以相等概率被选中。

### 一次试验成功的概率

设最小割 C 有 k 条边。

1. 每个顶点的度都 ≥ k——否则把那个顶点与其邻居分开就是一个小于 k 的割。故
   边数 m ≥ nk/2。第一步不选中 C 中边的概率 ≥ 1 − k/m ≥ 1 − 2/n。
2. 收缩后新顶点的度不小于 2k − 2（两个被合并顶点的度相加，再扣掉它们之间
   至多 k 条边的重复计数）——归纳可得第 i 步后剩余图仍以 C 为一个最小割，
   于是第 i 步幸存概率 ≥ 1 − 2/(n−i+1)。
3. n−2 步全部幸存的概率：

```
Π_{t=2..n} (1 − 2/t) = Π (t−2)/t = 2/(n(n−1)) ≥ 2/n²
```

单次试验像乱枪打鸟，但它**有独立于 k 的成功下界 2/n²**。做 s 次独立试验，全部
失败的概率 ≤ (1 − 2/n²)ˢ。取 s = (n²/2)·ln n 时失误率 ≤ 1/n；取 s = c·n² 时
失误率 ≤ e⁻²ᶜ。总代价 O(s·n²)（单次试验 O(n²) 朴素实现），即高概率的
O(n⁴ ln n)——后续有更优的 Karger-Stein 递归版把它降到近 O(n² ln³ n)，但随机
收缩这个核心想法不变。

### 示例怎么对账

最小割没有简单的「标准答案」，示例用第 27 章的最大流当精确值：**固定一个顶点
s=0，全局最小割必然把 s 与某个 t 分开，故 min_{t≠0} maxflow(0,t) 就是精确
全局最小割**。无向边按正反两条容量 1 的有向弧建模，平行边各自计数。实测：

- 固定例（两个 K₄ 团用 2 条边相连）800 次试验找出 2，与精确值一致；
- 600 个 n=4..8 的随机图（含不连通图，最小割可为 0），每图 n² 次试验，逐图
  与精确值对账，0 图不一致；同时统计单次试验命中的经验频率（0.70，远高于
  2/n² 的最坏下界——下界只在极端实例取等）；
- n=60 的大例：两个 30 顶点完全图（半侧内部任何割都 ≥29 条边）之间放 3 条
  跨边，保证植入的 3 就是最小割，4n² = 14400 次试验找出 3。

## C++23 语言点

- **`std::mt19937` 是逐位规定的算法**（Mersenne Twister，19937 位状态），
  这就是它能跨实现对账的原因；`std::random_device` 则不可复现，只用来
  （在真实程序里）播种；
- `std::iota`（`<numeric>`）生成 1..n 排列，配合洗牌是最短路径；
- 模拟实验的结构模板：`外层固定种子 rng → 内层实验循环`，统计量只打印
  **定点小数**（{:.6f}）与整数计数。

## 与 STL 对照

`std::shuffle(beg, end, urbg)` 是标准库的 RANDOMIZE-IN-PLACE（要求 URBG
可移植时照样有分布不可移植问题？不——`std::shuffle` 的算法是**标准规定的**
（Libraray TS 起钉死为「从剩余中均匀取」的实现语义），跨实现可复现的前提
是引擎相同。所以工程上用 `std::shuffle` + `std::mt19937` 是安全的；本教程
手写是为了教学可见性。`std::sample`（无放回抽样）同理。

## 坑位清单

1. **`uniform_int_distribution` 序列跨实现不同**
   （现象：同一种子同一循环，MSVC 与 MinGW 的模拟计数不同，逐字节对账
   失败；原因：分布算法是实现自由，只有引擎被逐位规定；后果：模拟实验
   不可复现；对策：`rand_below`（Lemire）自造无偏取整，见 docs/01。）
2. **洗牌方向写反造成 4:5 偏倚**
   （现象：n=3 洗 27 万次的六排列计数分成 4 万/5 万两档；原因：j 取
   RANDOM(1,n) 全范围时，27 条等概率路径不均匀映射到 6 个排列；后果：
   「随机化」算法默默带偏，统计结论失真；对策：j 必须取 RANDOM(i,n)——
   CLRS 证明的前提；写完做均匀性直方图断言（示例 05.5 的做法）。）
3. **拿「期望对数」冒充「至少一次」的概率**
   （现象：用 C(k,2)/365 ≥ 1 推出生日碰撞需要 28 人，比真答案 23 大；
   原因：E[对数] > 0 甚至 > 1 都不等于 P(≥1 对) 大——后者要精确乘积；
   后果：阈值估计系统性偏大；对策：「至少一次」用 1 − Π(1−pᵢ)，期望
   加法只用于「平均次数」。）
4. **模拟次数不够就断言「符合理论」**
   （现象：1000 次生日模拟频率 0.52 被当成推翻 0.5073 的证据；原因：二项
   分布的标准差 σ = √(p(1−p)/N)，N=1000 时 σ≈0.0158，0.52 只离理论 0.8σ；
   后果：把噪声当信号；对策：断言窗口按 σ 设定（示例用 20000 次 +
   ±0.03 窗口 ≈ ±2σ），或者干脆打印频率让读者自己看。）
5. **`rng() % n` 的模偏倚在小 n 时隐形**
   （现象：n=6、十万次抽样直方图肉眼均匀；原因：2³² mod 6 = 4，偏倚
   量级 4/2³² ≈ 10⁻⁹，十万次根本看不见；后果：换大 n（如接近 2³¹ 的
   区间）或安全敏感场景（密钥、抽奖）时偏倚变成真问题；对策：一律用
   拒绝采样或 Lemire 乘法-移位，与可见性无关。）
6. **收缩时删掉平行边 / 不丢自环**
   （现象：算出的割系统性偏小或偏大；原因：平行边是割权重的一部分，收缩后
   必须保留；自环不属于任何「两侧之间」的边，标准算法丢弃。若保留自环并
   在选中时空转，选出的边分布被污染，成功概率分析不再成立；后果：大例
   找不到植入割；对策：发现自环即删除并重抽，其他边原样保留，用最大流
   精确值逐图对账。）
7. **试验次数按「常数次」或 n 设置**
   （现象：偶尔能过、换种子就翻车；原因：单次成功概率随 n 以 1/n² 衰减，
   总失败率 (1−2/n²)ˢ——s 与 n² 同阶才有常数失败率，要失败率随 n 缩小需
   s = Θ(n² ln n)；后果：随机算法在评测机上概率性 WA，最难排查；对策：
   试验数写成 n² 的显式倍数，并在输出里核对经验命中率。）
8. **把 s-t 最小割的算法当全局最小割用**
   （现象：只算一次 maxflow 就声称是全局答案——那只对选定的 s、t 对成立；
   原因：全局最小割不指定端点，可能根本不经过选定的 s；对策：固定 s 后
   枚举所有 t 取 min（本示例的精确口径），生产场景用 Stoer-Wagner 或
   Karger-Stein；反过来也别用 Karger 直接答 s-t 题——返回的割不保证分开
   指定的两点。）

## 练习

1. （CLRS 练习 5.1-2）只用 RANDOM(0,1) 实现 RANDOM(a,b)，期望 O(1) 次
   调用（提示：取 k 位二进制 + 拒绝重抛；证明期望调用次数 < 2）。
2. （CLRS 练习 5.1-3）借助有偏硬币 BIASED-RANDOM（以 p 出 1）造无偏的
   01 输出（提示：抛两次，「10」→1、「01」→0、其余重来；算期望次数
   1/(2p(1−p))）。
3. （CLRS 练习 5.2-1）雇佣恰好 1 次与恰好 n 次的概率各是多少？
   （1/n! 与 1/n!——最好者第一个到 / 严格递增。）
4. （CLRS 练习 5.2-5）随机排列中**逆序对**的期望个数（提示：指示器
   I{i<j 且 π(i)>π(j)}，每对 1/2 → C(n,2)/2 = n(n−1)/4——第 8 章排序
   下界会回收它）。
5. （CLRS 练习 5.3-2）KARGE 那道「OFF」的洗牌题：swap A[i]↔A[RANDOM(i+1,n)]
