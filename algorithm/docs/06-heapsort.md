# 06 · 堆与堆排序

> 对应 CLRS 第 6 章 *Heapsort*（英文 3rd ed. pp.151–171）。堆是全书第一个
> 「用数组造出来的树」——零指针、完全二叉、原地排序；它的优先队列化身会在
> 第 17 章 Huffman、第 20 章斐波那契堆、第 25 章 Dijkstra 反复登场。

## 学习目标

1. 能写出 0 基与 1 基两套父/子下标公式并互推；
2. 能陈述 MAX-HEAPIFY 的前提（左右子树已是堆）与递归式，解释 2n/3 的来源；
3. 能推 BUILD-MAX-HEAP 的 O(n) 紧界（按高度分桶求和）；
4. 能用循环不变式证明 HEAPSORT 的正确性，并解释它的「原地 + Θ(n lg n)」
   双料优势；
5. 会实现最大优先队列四操作，知道 `std::priority_queue` 缺什么、怎么补。

## 动机

第 2 章的归并排序 Θ(n lg n) 但要 Θ(n) 辅助数组；插入排序原地但 Θ(n²)。
**堆排序两头都要**：原地 + Θ(n lg n)。代价是常数更大（实测比较数约为
2n·lg n，归并的一半偏多）且**不稳定**（相同元素次序会乱，第 8 章的计数
排序线会回收「稳定性」这个话题）。此外，堆本身是一个重要的**优先队列**
实现——「取最值 O(lg n)、插入 O(lg n)」的接口先于排序出现。

## 堆：数组的二叉树（§6.1）

（二叉）**堆**是数组 + 一个「用下标当边」的视角：

- 1 基（CLRS）：PARENT(i) = ⌊i/2⌋，LEFT(i) = 2i，RIGHT(i) = 2i+1；
- 0 基（C++）：parent(i) = (i−1)/2，left(i) = 2i+1，right(i) = 2i+2。

两套公式数学同构，只差一个偏移。**最大堆性质**：除根外每个节点
a[parent(i)] ≥ a[i]。高度（节点到叶的最长边数）与深度（到根的边数）注意
区分：n 元素的堆高度为 ⌊lg n⌋，深度 d 至多 min(d, ⌊lg n⌋) 个节点。

CLRS 图 6.1 的堆（示例 06.1 打印，`std::ranges::is_heap` 断言通过）：

```
图 6.1 的最大堆（数组视图）: [15 13 9 5 12 8 7 4 0 6 2 1]
  深度 0: 15
  深度 1: 13 9
  深度 2: 5 12 8 7
  深度 3: 4 0 6 2 1
```

## MAX-HEAPIFY：让一个节点下沉（§6.2）

前提：**i 的左右子树各自已是最大堆**，只有 a[i] 可能小于孩子。做法：在三
个节点（自己 + 两孩子）里选最大者；若是孩子，交换并把问题递归到那个孩子。

```clrs
MAX-HEAPIFY(A, i)
1  l = LEFT(i),  r = RIGHT(i)
2  if l ≤ A.heap-size and A[l] > A[i]
3      largest = l
4  else largest = i
5  if r ≤ A.heap-size and A[r] > A[largest]
6      largest = r
7  if largest ≠ i
8      exchange A[i] with A[largest]
9      MAX-HEAPIFY(A, largest)
```

示例用迭代版（循环代替尾递归，栈深 O(1)）。图 6.2 的数据实测：元素 4 从
深度 1 下沉到深度 3——比较 4 次（每层两次，比左、比右）、交换 2 次：

```
MAX-HEAPIFY 追踪（图 6.2 数据 [16,4,10,14,7,9,3,2,8,1]，i=1 的 4 违反）：
  修复后（数组视图）: [16 14 10 8 7 9 3 2 4 1]
  下沉比较 4 次，交换 2 次（4 的下沉路径：换 14，再换 8，成为叶）
```

**递归式**：T(n) ≤ T(最坏子树规模) + Θ(1)。最坏情形子树取到 2n/3（当底层
恰好填满「靠左的 2/3」时：整树 n = 2^{h+1} − 1 满二叉减调整，底层最后一
层的叶只在左侧，左子树 = 2/3 总量）。于是 T(n) ≤ T(2n/3) + Θ(1) =
Θ(lg n)（主定理情形 2，a=1, b=3/2）。

## BUILD-MAX-HEAP：自底向上 O(n)（§6.3）

叶（下标 ≥ ⌊n/2⌋）天然是堆，所以**倒序**对内部节点逐个 MAX-HEAPIFY：

```clrs
BUILD-MAX-HEAP(A)
1  A.heap-size = A.length
2  for i = ⌊A.length/2⌋ downto 1
3      MAX-HEAPIFY(A, i)
```

图 6.3 数据实测（14 次比较、7 次交换，结果与图 6.3(e) 逐元素一致）：

```
BUILD-MAX-HEAP（图 6.3 数据 [4,1,3,2,16,9,10,14,8,7]）：
  建堆结果（数组视图）: [16 14 10 8 7 9 3 2 4 1]
  建堆比较 14 次，交换 7 次
```

**紧界 O(n) 的证明思路**（这界比「n 次 O(lg n) = O(n lg n)」的粗界紧）：
高度为 h 的节点至多 ⌈n/2^{h+1}⌉ 个，每个的 heapify 代价 O(h)，于是总代价

Σ_{h=0}^{⌊lg n⌋} ⌈n/2^{h+1}⌉·O(h) = O(n · Σ h/2^h) = O(n · 2) = O(n)。

关键在**大多数节点在底层、高度小、几乎不动**。这个「按位置分桶、每桶
代价不同」的分析手法是第 18 章摊还分析的预告片。

## HEAPSORT（§6.4）

```clrs
HEAPSORT(A)
1  BUILD-MAX-HEAP(A)
2  for i = A.length downto 2
3      exchange A[1] with A[i]      // 当前最大值就位
4      A.heap-size = A.heap-size - 1
5      MAX-HEAPIFY(A, 1)            // 剩余前缀重新成堆
```

**循环不变式**：第 2 行循环每轮开始时，A[i..n] 是原数组最大 n−i+1 个元素的
**升序后缀**，A[1..i−1] 是剩余元素的最大堆。三段论照旧（初始化：建堆后
A[1..n] 是包含全部元素的堆；保持：堆顶是 A[1..i−1] 的最大值，交换后它进入
后缀且后缀仍升序、heapify 恢复堆性质；终止：i=2 时全部有序）。

实测（示例 06.4）：n=1000 固定随机排列上 heapsort 比较 16864 次
（≈ 2n·lg n = 20000 的量级），同一排列插入排序 249655 次——15 倍差距，
与第 3 章的渐近账目一致。

## 优先队列（§6.5）

堆的「动态集合」形态。四个操作（最大堆）：

| 操作 | 语义 | 代价 |
|---|---|---|
| HEAP-MAXIMUM | 返回堆顶 | Θ(1) |
| HEAP-EXTRACT-MAX | 取出并删除堆顶 | O(lg n) |
| HEAP-INCREASE-KEY(i, k) | 把元素 i 的键升到 k（须 ≥ 原值），上浮 | O(lg n) |
| MAX-HEAP-INSERT | 加键为 k 的元素（-∞ 占位再 increase） | O(lg n) |

INCREASE-KEY 是**上浮**（与 heapify 的下沉互为对偶）：沿父链比较、交换，
直到不再大于父亲。示例 06.5 的对账：手工队列与 `std::priority_queue` 做
同一插入序列 + 一次 increase-key（std 版用「移除再插入」模拟），弹出序列
逐元素一致（20 16 14 10 9 7 4 3 2 1）。

## C++23 语言点与 STL 对照

- **堆算法族**：`std::make_heap` / `std::push_heap` / `std::pop_heap`
  （在任意随机访问区间上操作，与本章四操作一一对应）；
  `std::ranges::is_heap` / `is_heap_until` 直接给出堆性质检查（本例的
  assert 全靠它）；
- **`std::priority_queue`** 是 make_heap 族的容器适配器，默认 `vector` 底层；
  它**没有 increase/decrease-key**——Dijkstra/Prim 用它得走「lazy 删除」
  （插入新键、弹出时跳过过期条目）或改用手写堆/`std::multiset`；
- 自写堆把操作显式摊开（示例 `MaxPriorityQueue`），把 CLRS 伪代码到
  C++ 的映射保持一一对应——这是本教程「教具优先于工程」的取舍。

## 坑位清单

1. **0 基与 1 基的父子公式混用**
   （现象：heapify 走错分支或数组越界；原因：CLRS 的 LEFT(i)=2i 在 0 基
   数组上会访问 2i+1 的位置——偏移差一；后果：静默错堆或 UB；对策：文件
   顶部放三个函数 `parent/left/right`（0 基版），全文只用函数名不写裸算式，
   换基只改一处。）
2. **increase-key 忘验「新键不小于旧键」前提**
   （现象：键变小后上浮循环直接不动，堆性质已破坏却不报错；原因：CLRS
   INCREASE-KEY 的前提是 key ≥ A[i]，违反时「上浮」语义不成立；后果：
   堆悄悄变成非法状态，后续 extract 全错；对策：入口 `assert(heap[i] <= key)`
   ——示例就是这么写的，前提即断言。）
3. **用 `find` 定位「值」再 increase-key，重复值时找错元素**
   （现象：数组里有双份 8，提升的是另一个 8；原因：increase-key 语义是
   按**位置**的，不是按值的——优先队列没有「按值寻址」接口；后果：语义
   级错误（改了不该改的条目）；对策：真实系统给元素配 id→句柄映射
   （第 20 章斐波那契堆会认真处理句柄问题）；示例数据保证值唯一才敢用
   find。）
4. **`std::priority_queue` 默认是最大堆，Dijkstra 要最小堆**
   （现象：用默认比较器写 Dijkstra，每次弹的是距离最大者，答案全错但不
   崩；原因：priority_queue 的 Compare 与 sort 的语义相反——`less<T>` 给出
   大顶堆；后果：算法方向性错误；对策：`std::priority_queue<int, vector<int>,
   std::greater<int>>` 或手写比较器，配一个单测用例锁语义。）
5. **把堆顶当最小值（最小堆/最大堆混淆）**
   （现象：`a[0]` 取出的是最大值却当最小值用；原因：CLRS 用最大堆讲
   HEAPSORT、用最小堆讲优先队列双线并行，读者容易串台；后果：升序/降序
   排反；对策：记住「HEAPSORT = 最大堆 + 堆顶甩尾」，Dijkstra = 最小堆 +
   堆顶即取」。）
