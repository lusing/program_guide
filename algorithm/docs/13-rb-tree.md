# 13 · 红黑树

> 对应 CLRS 第 13 章 *Red-Black Trees*（英文 3rd ed. pp.308–330）。第 12 章
> 的 BST 在有序输入上退化成链；红黑树用**每节点一个颜色位**换来**最坏
> O(lg n)** 的全部字典操作。它是 `std::map`/`std::set` 的真身，也是全书
> 最考验「不变式思维」的一章——四条性质像四根柱子，插入/删除的每个分支
> 都是在「修一根时别碰塌另外三根」。

## 学习目标

1. 能背出红黑性质四条，并证明「黑高 bh ≥ h/2 → n ≥ 2^{bh}−1 → h ≤ 2lg(n+1)」；
2. 理解旋转的指针操作与「哨兵节点」方案为什么必要；
3. 能走完插入修复三情况（叔红上推/内侧转正/外侧旋转）与删除修复四情况；
4. 会写全量性质验证器（BST 序 + 根黑 + 红红禁 + 黑高一致）；
5. 体会「用修复保持不变式」的设计模式——第 14 章扩张数据结构的根基。

## 红黑性质与高度界

1. 每个节点非红即黑；
2. 根是黑的；
3. 每个叶（**NIL/哨兵**）是黑的；
4. **红节点的两个孩子都是黑的**（红红不相邻）；
5. **任一节点到其所有后代叶的黑节点数相同**（黑高 bh）。

性质 4+5 ⇒ 从任一节点到叶的最长路径 ≤ 最短路径的 2 倍（红只能夹在黑之间）。
于是高度 h ≤ 2·lg(n+1)：子树至少含 2^{bh}−1 个内点，而 bh ≥ h/2。
**全部操作 Θ(h) = Θ(lg n)，最坏情形**——对比 BST 的「期望 lg、最坏 n」。

## 哨兵：NIL 必须是「真节点」

CLRS p.274 的工程要点：**用一个真实的哨兵节点 T.nil 代替所有 NIL 指针**
（颜色恒黑，parent 字段随旋转/移植更新）。两个理由：

- 省掉无边界的判空分支（旋转代码少一半 if）；
- **删除修复需要「从 NIL 上行」**——被删黑节点的孩子可能是 NIL，修复要
  以它为起点向上走，NIL 必须记得自己的父亲。

本例用 arena 数组的 0 号槽当哨兵（`NIL = 0`，真实节点从 1 起）。第二个
理由正是本例实测踩的坑（坑位 1）：漏写 CLRS 伪代码里 `x.p = y` 这行
（它专门为哨兵而设），压力测试在数千次随机删除后性质崩坏。

## 旋转（§13.2）

旋转是红黑树的「局部手术」：改变 O(1) 个指针，保持 BST 序（中序不变），
把一侧高度加一、另一侧减一。LEFT-ROTATE(x) 让右孩子 y 上位，x 沉为 y
的左孩子，y 的原左子树过继给 x 当右子树。哨兵方案下，`parent[哨兵] = x`
这类赋值**不需要判空**——写进去恰好是删除修复要用的语义。

## 插入与修复（§13.3）

新节点染**红**（不碰黑高，只可能违反性质 4 红红）。修复循环以「z 与父
皆红」为条件，看**叔叔**脸色：

- **情况 1（叔红）**：父、叔变黑、祖变红——把红红冲突上推两层；
- **情况 2（叔黑，z 是内侧孩子）**：旋转父，把自己转成外侧孩子 → 情况 3；
- **情况 3（叔黑，z 是外侧孩子）**：父变黑、祖变红，对祖反向旋转——
  冲突就地终结。

情况 1 每轮上推两层（树高减半地收敛），情况 2→3 一轮终结，修复总计
O(lg n) 次颜色操作、至多 2 次旋转。CLRS 图 13.4 序列 ⟨41,38,31,12,19,8⟩
的终态（示例 13.3 实测，逐层 key+颜色）：

```
插入 41 38 31 12 19 8（图 13.4 序列）后的红黑树（key+颜色）:
  38B
  19R 41B
  12B 31B
  8R
```

与图 13.4(f) 逐节点一致；树高 4 ≤ 2·lg 7 = 6，黑高验证通过。

## 删除与修复（§13.4）

删除的框架同 BST 三情况，但被「摘下来」的节点 y 若是**黑**的，黑高就
缺了一层——delete-fixup 补黑。想象 x（接管 y 位置的孩子，可能是哨兵）
「多背了一层黑」，四种情况消化它：

- **情况 1（兄弟红）**：旋转把兄弟转黑 → 进入 2/3/4；
- **情况 2（兄弟黑，双侄全黑）**：兄弟变红，把「多一层黑」上推给父；
- **情况 3（兄弟黑，远侄黑近侄红）**：旋成情况 4；
- **情况 4（兄弟黑，远侄红）**：一次旋转 + 重新着色，终结。

情况 2 上推（每轮升一层），其余情况一轮终结；至多 3 次旋转。示例 13.4
在删除 8/41/19/55 后各自全量验证；压力测试 20000 次随机操作（每 1000 步
验一次）全程绿灯。

## 验证器：教学实现的「正确性安全网」

```cpp
long long check(std::size_t x, std::size_t& cnt) const {
    if (x == NIL) { return 1; }                    // 哨兵贡献 1 黑
    ++cnt;
    if (color[x] == RED && (color[left[x]] == RED || color[right[x]] == RED)) return -1;
    const long long lh = check(left[x], cnt), rh = check(right[x], cnt);
    if (lh < 0 || rh < 0 || lh != rh) return -1;   // 黑高必须一致
    /* BST 序检查 */
    return lh + (color[x] == BLACK ? 1 : 0);
}
```

一次性验证四条性质 + BST 序，返回黑高。它对红黑树实现的价值怎么强调
都不过分：本例的哨兵 bug 就是**它**在 20000 次随机操作中间抓出来的——
单个手造用例全绿，随机压力下才现形。

## C++23 语言点

- arena 五数组（key/left/right/parent/color）+ 0 号哨兵槽——第 10/12 章
  表示纪律的完全体；颜色用 `enum Color : std::uint8_t` 压到一个字节；
- 旋转/移植不判空的写法依赖哨兵语义，注释里写明「写进哨兵恰好是对的」；
- 压力测试的「真值双账」模式：一个 `std::vector<char>` 位图当参照物，
  每步操作两侧同步、定期对账——比 mock 对象简单且确定。

## 与 STL 对照

`std::map`/`std::set`/`std::multimap` 的标准规定最坏 O(lg n)，主流实现
（libstdc++/libc++/MSVC）全是红黑树。差异点：节点分配（真指针 vs 本例
arena）、header 哨兵（begin/end 迭代器的锚）、以及**删除的实现策略**
（有的实现移动键值而非节点——第 12 章坑位 1 讨论过的取舍）。

## 坑位清单

1. **漏写 CLRS 的 `x.p = y`（哨兵之父）**
   （现象：手造用例全绿，数千次随机删除后黑高断裂；原因：删除双子节点
   且 y 是 z 右孩子时，接管的 x 若是哨兵，修复循环要沿 parent[NIL] 上行
   ——这行赋值就是干这个的，跳过它哨兵的父亲是陈年旧值；后果：修复从
   错误位置开始，性质静默崩坏；对策：逐行照抄 CLRS 时**连看似多余的行
   一起抄**，并用随机压力 + 全量验证器把它抓出来——本例实测翻车实录，
   是红黑树实现的头号经典错误。）
2. **修复循环的终止条件写成 `color[x] == RED`**
   （现象：部分用例死循环或早退；原因：插入修复的条件是「父红」（z 自身
   恒红），删除修复是「x 黑且非根」——两者都要求你先想清楚「什么状态
   才算修好了」；后果：挂死或性质漏检；对策：循环条件对着性质写——
   插入修性质 4（父黑即停），删除补黑高（到根或变红即停）。）
3. **旋转后忘更新 root**
   （现象：树「看起来」对，遍历却丢节点或验证器报 BST 序违规；原因：
   旋转的节点是根时，root 指针必须跟着换——散在三个 if 分支里；后果：
   整棵子树失联；对策：旋转函数内部处理（本例 rotate_* 的 if 链），
   调用方永不管 root。）
4. **把「红」节点的孩子判空当黑用**
   （现象：验证器漏报红红；原因：NIL 孩子该记黑（性质 3），哨兵方案下
   color[NIL] 初始化为 BLACK 后再没改过——但如果哪段代码「顺手」改了
   哨兵颜色就全盘报废；后果：验证器与实现一起错（假绿）；对策：验证器
   开头断言 color[NIL] == BLACK，把哨兵的恒黑也纳入验证范围。）
5. **删除后直接复用被删槽位**
   （现象：迭代中读到已死节点；原因：arena 实现删除后 key/parent 字段
   还在，但节点已不可达——复用需要自由表（第 10 章）；后果：悬空引用
   类 bug；对策：教学实现明确「槽位只增不复用」，或引入第 10 章的
   allocate/free 纪律。）

## 练习

1. （CLRS 练习 13.1-1/13.1-3）画 h=4 的黑高最大/最小的红黑树；最长与
   最短简单路径的长度关系。
2. （CLRS 练习 13.1-4）红黑树里黑高相同的节点的叶深度可能差多少？
   （2 倍以内——性质 4 的直接推论。）
3. （CLRS 练习 13.2-1/13.2-2）RIGHT-ROTATE 的完整伪代码；旋转改变中序
   序吗？（不——这是旋转合法性的全部根据。）
4. （CLRS 练习 13.3-1）插入为什么染红不染黑？（染黑必违性质 5 且难以
   局部修复；染红只可能违性质 4。）
5. （CLRS 练习 13.3-3/13.3-6）情况 1 上推的终止性；不用 parent 指针的
   红黑树（用栈回溯）可行吗？
6. （CLRS 练习 13.4-1/13.4-3/13.4-7）删除修复各情况的性质推导与终止
   论证（哪些情况会继续循环、哪些就地终止）。
7. （CLRS 思考题 13-1/13-3）持久化红黑树（版本化 O(lg n) 空间）；
   AVL 与红黑树的高度界对比（AVL 更严：h ≤ 1.44 lg n）。
8. （本教程）给验证器加「parent 双向一致性」（parent[child] 自反），
   重跑 20000 步压力——它能比黑高检查更早抓到结构损坏吗？
