# 03 · 函数的增长：渐近记号

> 对应 CLRS 第 3 章 *Growth of Functions*（英文 3rd ed. pp.43–64），并串联
> 附录 A 的求和技术（A.1 求和记号与性质、A.2 求界技术）。这一章是全书最短的
> 「数学章」，但后面 34 章的每一行复杂度都要用它的语言书写。

## 学习目标

1. 能写出 Θ / O / Ω 的集合论定义（含全部量词），并解释三者「夹逼/上界/下界」
   的直觉；
2. 会用定义做机器检验：给定 f、g 与常数 c₁、c₂、n₀，遍历 n 验证定义成立；
3. 记住转换性质表（自反、传递、对称、转置对称）并会现推；
4. 能区分 O 与 o（≤ 与 < 的差别）；
5. 熟悉常用函数的增长速度排序：lg n ≪ √n ≪ n ≪ n lg n ≪ n² ≪ n³ ≪ 2ⁿ ≪ n!；
6. 掌握本教程的整数运算纪律（为什么分析实验里不出现 `std::log`）。

## 动机：为什么需要渐近

第 2 章我们看到插入排序「最坏 n(n−1)/2 次比较」、归并排序「至多 n·lg n」。
但换一台快一倍的机器、或者把「移位」也计入代价，这些具体数字就全变了。
我们想要一种**机器无关、常数无关**的语言，只保留「增长形状」这一本质——
这就是渐近记号。它是压缩：n(n−1)/2、2n²+3n、n²/4 这些函数在「大到离谱的 n」
面前没有区别，都记 Θ(n²)。

## Θ、O、Ω：定义与机器检验

**定义（Θ 记号，CLRS p.44）** 对给定的函数 g(n)：

Θ(g(n)) = { f(n) ：存在正常数 c₁、c₂ 和 n₀，使得对所有的 n ≥ n₀，
          0 ≤ c₁·g(n) ≤ f(n) ≤ c₂·g(n) }

读法：f ∈ Θ(g) 当且仅当「对足够大的 n，f 被 g 乘两个正常数**夹住**」。
类似地（p.45–48）：

- **O(g)** = { f ：存在 c > 0、n₀ > 0，使 0 ≤ f(n) ≤ c·g(n) 对 n ≥ n₀ }——
  渐近**上界**（≤）；
- **Ω(g)** = { f ：存在 c > 0、n₀ > 0，使 0 ≤ c·g(n) ≤ f(n) 对 n ≥ n₀ }——
  渐近**下界**（≥）；
- 三者关系：f ∈ Θ(g) ⇔ f ∈ O(g) 且 f ∈ Ω(g)。

定义是量词化的，**正好可以写成程序**。示例 03.1 取 f(n) = n²、g(n) = 2n²+3n，
声称 c₁ = 1/4、c₂ = 1、n₀ = 8 使 f ∈ Θ(g)——机器对 n 从 8 到 100000 逐个验证
两个不等式（分数常数用整数比 `c1_num·g ≤ c1_den·f` 表达，全程不落浮点）：

```
f=n^2 ∈ Θ(2n^2+3n)：下界 c1=1/4 成立 = 1，上界 c2=1 成立 = 1（n0=8..100000 全验）
```

为什么要「机器检验」？因为手推常数最容易错的地方就是 n₀ 附近——c₁·g(n) ≤ f(n)
在小 n 时未必成立（这里 2n²+3n 是 n² 的 2 倍多，c₁ 必须 ≤ 1/2 才行）。写个
循环，n₀ 从猜的值起全验一遍，定义的「存在 ∀」结构就落了地。

**小 o 与小 ω（p.50–51）**：

- o(g)：对**任意**常数 c > 0，存在 n₀ > 0 使 0 ≤ f(n) < c·g(n) 对 n ≥ n₀。
  直觉：g 增长得**严格更快**。例如 n ∈ o(n²)。
- ω(g)：对任意 c > 0，存在 n₀ 使 0 ≤ c·g(n) < f(n)。n² ∈ ω(n)。

O 与 o 的区别就是 ≤ 与 <：n² ∈ O(n²) 但 n² ∉ o(n²)。示例用整数版验证了
n ∈ o(n²)：「任取 k（对应 c = 1/k），对一切 n ≥ k 有 k·n ≤ n·n」。

## 转换性质

CLRS 图 3.1（p.51）的性质表值得背下来，更要会现推：

| 性质 | 对 Θ/O/Ω |
|---|---|
| 自反性 | f ∈ O(f)、f ∈ Ω(f)、f ∈ Θ(f) |
| 传递性 | f ∈ O(g) 且 g ∈ O(h) ⇒ f ∈ O(h)（Ω、Θ 同） |
| 对称性 | f ∈ Θ(g) ⇔ g ∈ Θ(f)（仅 Θ） |
| 转置对称 | f ∈ O(g) ⇔ g ∈ Ω(f)；f ∈ o(g) ⇔ g ∈ ω(f) |

推论（p.51）：f = O(g) ⇔ g = Ω(f)——「上界与下界互为转置」。所以当 CLRS
说「最坏情形运行时间为 Θ(n²)」时，它同时给出了上界（O）与下界（Ω）：不存在
更松的上界也没有更紧的下界。

工程提醒：Θ 里的常数不是没用——`2n²+3n` 与 `n²/4` 同属 Θ(n²)，但快 8 倍。
渐近先定「量级生死」，常数再定「同量级内的名次」。示例 03.3 的拟合实验
展示的正是「常数藏在比值里」：插入排序随机输入的比较数除以 n² 稳定在
0.25 附近（理论期望 n²/4 的实证），归并除以 n·⌈lg n⌉ 稳定在 0.86 附近。

## 常用函数与记号速览（§3.2）

- **单调性**：⌊·⌋、⌈·⌉ 单调不减；⌊n/2⌋ + ⌈n/2⌉ = n（示例全验 0..1000）。
- **取整与 mod**：a = ⌊a/n⌋·n + (a mod n)；n | a 表示 n 整除 a。
- **多项式**：p(n) = Σ aᵢnⁱ 是 Θ(nᵈ)（d 为最高次数）。「多项式时间」是
  第 34 章 P/NP 的分界线。
- **指数**：对任意 r > 1、d > 0：nᵈ = o(rⁿ)——任何多项式输给任何指数。
  这是「NP 完全问题为什么可怕」的根源。
- **对数**：lg = log₂、ln = logₑ。换底只差常数因子：log_b n = lg n / lg b，
  所以算法分析里「对数的底不重要」常写 Θ(lg n) 任底。
- **多重对数 lg\* n**：「取 lg 多少次才 ≤1」。n = 2^65536（宇宙原子数远不及）
  也只要 lg\* n = 5。第 21 章并查集的 α(n) 比 lg\* n 增长还慢。
- **斐波那契**：F₀=0，F₁=1，Fₙ=Fₙ₋₁+Fₙ₋₂；Fₙ = ⌊φⁿ/√5⌉+… 与 φ = (1+√5)/2
  ≈ 1.618034 相关，Fₙ ∈ Θ(φⁿ)。示例打印 F₄₁/F₄₀ = 1.618034 实证收敛。

对 C++23 有一个可爱的新工具：**`std::bit_width(n)` = ⌊lg n⌋ + 1**（`<bit>` 头，
C++20 起）。示例对 n = 1..10⁶ 全验了这条恒等式，以后所有「⌊lg n⌋」都能用
整数运算精确拿到，不必碰浮点对数。

### 串联附录 A：求和

- **算术级数** Σₖ₌₁ⁿ k = n(n+1)/2 = Θ(n²)（第 2 章插入排序最坏情形的来源）；
- **几何级数** Σₖ₌₀ⁿ 2ᵏ = 2ⁿ⁺¹−1；一般的 Σₖ₌₀ⁿ rᵏ = (rⁿ⁺¹−1)/(r−1) = Θ(rⁿ)
  （r > 1 时首项与总和同阶——「最后一项占大头」）；
- **调和级数** Hₙ = Σₖ₌₁ⁿ 1/k = ln n + O(1)。示例实测 H₁₀ = 2.928968、
  H₁₀₀ = 5.187378、H₁₀₀₀₀₀₀ = 14.392727 ≈ ln 10⁶ + 0.5772（欧拉常数）。
  快速排序平均分析（第 7 章）和并查集势能分析（第 21 章）都会用到它；
- **积分法**：单调递增 f 有 Σₖₘ₌₁ⁿ f(k) ≤ ∫ₘⁿ⁺¹ f(x)dx（上界）与
  ∫ₘⁿ f(x)dx ≤ Σₖₘ₌₁ⁿ f(k)（下界）。

## 增长实测：让数据自己说话

示例 03.3 复用第 2 章的两个排序，在固定种子的随机排列上统计比较数并做
常数拟合（全部整数运算，比值才落浮点定点打印）：

```
插入排序（随机排列）比较数与 c·n^2 的拟合：
  n=   100：比较         2207，c = 比较/n^2 = 0.2207
  n=  1000：比较       249655，c = 比较/n^2 = 0.2497
  n= 10000：比较     24727542，c = 比较/n^2 = 0.2473
归并排序（随机排列）比较数与 c·n·lg n 的拟合：
  n=   100：比较        534，c = 比较/(n·⌈lg n⌉) = 0.7629
  n=  1000：比较       8674，c = 比较/(n·⌈lg n⌉) = 0.8674
  n= 10000：比较     120474，c = 比较/(n·⌈lg n⌉) = 0.8605
```

三个观察：

1. 插入排序的拟合常数收敛到 **0.25 ≈ 1/4**——这正是「期望比较 ~n²/4」的实证
   （每个 key 平均穿过半个前缀）；
2. 归并的拟合常数收敛到 0.86 附近而不是 1——Θ(n lg n) 的上界没骗人，但常数
   里还有结构（提前用完的子数组省比较）；
3. **n 翻 100 倍时**：插入的比较数 ×100（2207 → 247 万，n² 的形状），归并只
   ×225/1000→ 检查 n lg n：100→10000 是 100·(7/14) ≈ 200 倍——渐进曲线可以
   用手算核。

时间估算表（10⁹ 次操作/秒的 RAM 模型，示例 03.4）：

```
换算：n=10^8 时 n·lg n ≈ 2.7×10^9 步 ≈ 2.70 秒；n^2 = 10^16 步 ≈ 116 天
```

第 1 章的「算法作为技术」在这里有了精确的度量衡。

## 两个增长反演：调和级数悬挂与尾数计数

渐近记号最有用的一步是**反演**：知道 c = Θ(lg n)，就能断言 n = Θ(2^c)。
这里用两个问题（整理自《趣题学算法》第 1 章的问题 1-2 与 1-5，自包含）
把它落成可运行的数字。

### 问题一：扑克牌魔术（调和级数悬挂）

n 张牌悬出桌边的最大总长是 1/2 + 1/3 + … + 1/(n+1) = Hₙ₊₁ − 1（物理上：
每张牌下面的牌垛以自身长度分摊重心）。给定目标悬挂长度 c，求最少牌数 n——
即最小的 n 使 Hₙ₊₁ ≥ c + 1。

Hₙ = ln n + 0.5772 + O(1/n) ⟹ c ≈ ln n，即 **c = Θ(lg n)，反演 n = Θ(2^c)**。
这个「指数爆炸」方向的实证非常直观——c 每加 1，牌数大约 ×e：

```
c 每加 1，最少牌数约 ×e —— n = Θ(2^c) 的实证：
  c=1 →   3 张
  c=2 →  10 张（/上一点 = 3.33）
  c=3 →  30 张（/上一点 = 3.00）
  c=4 →  82 张（/上一点 = 2.73）
  c=5 → 226 张（/上一点 = 2.76）
```

书上四个测试点的机器复核（示例 03.5）：

```
  c=0.04 →   1 张（1/2 = 0.5 ≥ 0.04）
  c=1.00 →   3 张（1/2+1/3+1/4 = 1.083333 ≥ 1.00（1.00 本身不够：H_3-1 = 0.833333））
  c=3.71 →  61 张（H_62 - 1 = 3.712393 ≥ 3.71，而 H_61 - 1 = 3.696264 不够）
  c=5.19 → 273 张（H_274 - 1 = 6.192168 ≥ 5.19）
```

两个纪律点：其一，c 以「百分之一」为单位是**有限精度输入**，c=3.71 与
H₆₂−1 = 3.712393 之间留有 0.002 的真间隙，双精度比较毫无压力——「浮点比较
不可靠」的担心只针对间隙小于 10⁻¹⁵ 的场景；其二，逐项 1.0/k 按固定顺序累加
是 IEEE 确定的（03.2 的 Hₙ 已验证三通道逐字节一致）。若 c 可以任意大，
枚举 n 的算法是 Θ(2^c)——「幸好 c 介于 0.01 与 5.20 之间」，否则必须直接
解 Hₙ₊₁ ≥ c+1（用 ln 的有理逼近或查表），这本身就是渐近思维的价值。

### 问题二：尾数计数（用除法代替枚举）

求 [a, b] 内十进制表示以 x 结尾的整数个数，x、a、b ≤ 10¹⁸。枚举 Θ(b−a)
在 10¹⁸ 面前毫无意义；设 m = 10^{x 的位数}，「以 x 结尾」⟺ i mod m = x，
模 m 余 x 的数构成公差 m 的等差数列——用两次除法直接定位两端：

1. 记 aq = a/m、ar = a mod m（b 同理得 bq、br）；
2. ar > x 说明 a 自己所在的剩余类已越过 x ⟹ ++aq；br < x ⟹ −−bq；
3. 答案 = max(0, bq − aq + 1)。

书上例子 x=36, a=237, b=893：m=100，ar=37 > 36 ⟹ aq=3；br=93 不减；
8 − 3 + 1 = **6**（即 336, 436, …, 836）。整题 Θ(lg x)——**数学代替枚举**
与第 2 章「插入排序换归并排序」是同一件事的不同侧面：一个靠换算法，一个靠
换公式。示例对 1000 组随机小数据做了除法版 vs 枚举版的对账（0 处不等）。

### 本章埋的两颗溢出雷

- **m = 10¹⁹ 装不进 int64**：x 可达 10¹⁸（19 位），模数 m = 10¹⁹ 已超
  INT64_MAX = 9.22×10¹⁸——示例升 `unsigned long long`（上限 1.84×10¹⁹）
  才装下。这与第 4 章「unsigned 恰好多一倍量级」是同一根杠杆。
- **x = 0 的位数是 1 不是 0**：「以 0 结尾」⟺ i mod 10 = 0，m 必须取 10；
  写成「m 从 1 翻倍/乘十直到 m > x」会让 x=0 时 m 停在 1，答案变成
  「区间内所有整数」。示例的 `modulus_of` 显式特判 x=0。

## C++23 语言点：`<bit>` 与整数运算纪律

- `std::bit_width(x)`：⌊lg x⌋+1，最宽类型的整数运算，无浮点；
- `std::gcd` / `std::lcm`（`<numeric>`，C++17 起）：第 31 章数论章的主角预告；
- **纪律：分析实验里禁用 `std::log`/`std::pow`**。它们的尾数实现是各标准库
  的自由度，MSVC 与 MinGW libm 可能在最后几位不同——定点打印 `{:.6f}` 虽然
  通常掩盖得住，但「通常」不是本教程的验收标准（逐字节一致才是）。对数用
  bit_width、幂用整数乘、黄金分割比用「精确整数做除法」（IEEE 除法确定）。
- `std::format` 的宽度对齐（`{:>12}`）可以安全用于表格——对齐不改变数值，
  但**不要**用 `{:e}` 科学计数法打印跨库算出的浮点（尾数可能不同）。

## 与 STL 对照

渐近记号没有直接的标准库对应物，但 `<bit>`、`<numeric>`（accumulate/gcd）
和 `<chrono>`（真实计时——仅限不参与对账的本地实验）是本章的三个邻居。
工程上的「Θ 视角」对应一个朴素习惯：看到 O(n²) 的代码在 n > 10⁴ 的输入上
跑，先数一数循环层数再谈优化。

## 坑位清单

1. **n(n−1)/2 在 int 里静默溢出**
   （现象：n=100000 时算出负数或错误小数字；原因：4,999,950,000 超过
   INT_MAX = 2,147,483,647，32 位有符号回绕是 UB；后果：分析实验的「理论值」
   本身就是错的，assert 反而把对的实测拦下来；对策：计数器与规模乘积一律
   `long long`，示例实测 4999950000 必须用 64 位才装得下。）
2. **浮点对数跨标准库尾数不同**
   （现象：用 `std::log` 算 lg n 再格式化，三通道偶发最后一位不同，逐字节
   对账失败；原因：超越函数的实现精度是标准库的自由度；后果：假 DIFF、
   真 UB 分不清；对策：⌊lg n⌋ 用 `bit_width(n)−1`，比值用「整数算完最后
   一次除法」，调和级数按固定顺序逐项累加（IEEE 加法对固定顺序是确定的）。）
3. **非 2 的幂的 n 用错 lg 取整**
   （现象：归一化 n=1000 的比较数时除以 n·⌊lg n⌉=n·9 或 n·⌈lg n⌉=n·10，
   拟合常数差 10%；原因：1000 的 ⌊lg⌋=9、⌈lg⌉=10，递归深度是 ⌈lg n⌉；
   后果：「常数收敛」的结论被取整误差淹没；对策：先说清用哪个取整——
   归并树的深度是 ⌈lg n⌉，本例分母用它，打印里也写明 ⌈lg n⌉。）
4. **把 O 当 Θ 用**
   （现象：「快排是 O(n²)」被人反驳「明明平均 O(n lg n)」；原因：O 只是上界，
   说「O(n²)」在逻辑上没错但信息量少；后果：沟通歧义，面试与论文被批；
   对策：上界说 O、下界说 Ω、紧的说 Θ——「最坏 Θ(n²)」才是完整表述。）
5. **机器验证常数时忘了 n₀ 附近不成立**
   （现象：声称 c₁=1/2 对 2n²+3n ≥ n²/2 成立，n=1 时 5 ≥ 0.5 碰巧对，换
   更小的 c₁ 或不同 g 就在 n₀ 附近翻车；原因：定义的量词是「存在 n₀，对
   一切 n ≥ n₀」——小 n 允许例外，但不能假设没有例外；后果：手工「证明」
   漏验边界；对策：像示例 03.1 一样从声称的 n₀ 起循环全验。）
6. **模数 10¹⁹ 硬塞进 int64**
   （现象：尾数计数里 x=10¹⁸ 时 `long long m = 10^19` 溢出成未定义行为，
   三通道给出不同垃圾值；原因：19 位的 x 对应 19 位模数 10¹⁹ >
   INT64_MAX = 9.22×10¹⁸；后果：静默错误答案；对策：升 unsigned long long
   （上限 1.84×10¹⁹），并在注释里写明「为什么这里升一档就够、什么时候不够」。）
7. **x=0 时模数取成 1**
   （现象：数「以 0 结尾的整数」时答案恒等于区间长度；原因：`while (m <= x)
   m *= 10` 对 x=0 停在 m=1，i mod 1 == 0 永远成立；后果：边界输入全错且
   枚举对账若用同一个 m 就查不出来——错在「位数」的定义；对策：x=0 特判
   m=10，对账的枚举版与除法版**共享**同一个 modulus 函数，只对各自动机
   逻辑负责，才能暴露「语义」而非「实现」的分歧。）
8. **调和级数逐项累加的顺序被「优化」**
   （现象：把 `for (k=2..n+1) length += 1.0/k` 改成从大 k 往小加或用
   parallel reduce「提速」后，三通道输出对不上；原因：浮点加法不满足结合律，
   求和顺序是结果的一部分；后果：逐字节对账失败；对策：固定顺序从小 k 到
   大 k 逐项累加（IEEE 确定性），并把「顺序是契约」写进注释。）

## 练习

1. （CLRS 练习 3.1-1）设 f(n) 与 g(n) 都是渐近非负函数。证明
   max(f(n), g(n)) = Θ(f(n) + g(n))。
2. （CLRS 练习 3.1-4）2^(n+1) = O(2ⁿ) 成立吗？2^(2n) = O(2ⁿ) 呢？
   （提示：前者恒等于 2·2ⁿ，常数因子；后者是 2ⁿ 的平方。）
3. （CLRS 练习 3.1-8）把 Θ 记号推广到多变量：定义 Θ(g(n, m)) 并证明
   nm ∈ Θ(n² + m²) 不成立、nm ∈ Θ((n+m)²) 成立。
4. （CLRS 练习 3.2-3）证明/反驳：2^(n+1) = O(2ⁿ)；n! = o(2ⁿ)？n! = ω(2ⁿ)？
   （斯特林近似 ln n! = n ln n − n + Θ(ln n)——第 31 章数论会再遇它。）
5. （CLRS 练习 3.2-4）lg\* n ≤ ⌈lg lg n⌉ 对哪些 n 成立？函数
   ⌈lg(lg\* n)⌉ 与 ⌈lg\* n⌉ 谁增长快？
6. （CLRS 思考题 3-6，弦外之音）多重对数变体：lg⁽ᵏ⁾ n（迭代 k 次 lg）与
   lg\* n 的区别——第 21 章并查集的 α(n) 分析里它们会排队出场。
7. （本教程）把示例 03.3 的插入排序拟合常数与「期望 = 逆序对数」对账：
   实现 O(n lg n) 的逆序对计数（归并排序改一改），在同一固定排列上验证
   「插入排序比较数 ≈ 逆序对数 + (n−1)·0.5±」的近似关系。
8. （趣题 1-2）证明 Hₙ₊₁ − 1 ≥ c 的最小 n 满足 n = Θ(2^c)：上界用
   1/2+1/3+…+1/(n+1) ≤ 1 + (1/2)⌈lg n⌉ 的分组估计，下界用积分法；
   再解释为什么「牌数 ×e per unit c」与 2^{log₂ e} 是同一件事。
9. （趣题 1-5）把尾数计数推广到「i mod m ≡ r」的一般形式（m 任意、r 任意），
   给出 O(1) 公式并说明 x 结尾版是它在 m=10^t、r=x 下的特例。
