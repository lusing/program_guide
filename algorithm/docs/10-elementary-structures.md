## 栈与队列（§10.1）

**栈**（LIFO）：数组 + top 指针，push/pop 均摊 O(1)。示例的 `ArrayStack`
直接用 `std::vector` 尾部（vector 的倍增摊还见第 18 章）。下溢用 `assert`
拦——教学实现里 assert 即规格。

**循环队列**（FIFO）：定长数组 + head/tail 环形前进。经典设计问题：head
== tail 既可能是「空」也可能是「满」。三条路：

1. **留一个空位**（容量 n 只装 n−1）——满的判据 `tail+1 == head`；
2. **计数器**（示例的做法）——逻辑直白，多一个字段；
3. 时间戳/镜像位——省内存但绕。

示例实测（容量 4）：enqueue 4 9 16 → dequeue 4（head=1, tail=3）→
enqueue 25 36 时 **tail 环绕到 0** → 依次出队 9 16 25 36。环绕的正确性
靠 `% capacity` 的取模运算保证——head/tail 永远只增不减（模意义下），
这是循环结构「不回退」的纪律。

## 哨兵双链表（§10.2）

CLRS 的 LIST-INSERT/DELETE 满是「如果是头节点/尾节点就……」的分支。
**哨兵**节点 nil 把它们全部消掉：nil.next 是头、nil.prev 是尾，空表也
是 nil 自环——从此「表头」和「中间节点」代码路径合一：

```cpp
void list_insert(std::size_t x) {   // 插到链头，无任何分支
    next[x] = next[nil];
    prev[next[nil]] = x;
    next[nil] = x;
    prev[x] = nil;
}
void list_delete(std::size_t x) {   // O(1) 删除，同样无分支
    next[prev[x]] = next[x];
    prev[next[x]] = prev[x];
}
```

代价：多一个节点的空间 + 「下标 == nil」的判断从「下标 == −1」改成
「下标 == 哨兵下标」（语义不变）。示例用 `constexpr std::size_t NIL =
SIZE_MAX` 表示哨兵槽位。

**给下标即 O(1) 删除**是链表对数组的本质优势：数组删除要搬移 Θ(n)。
反过来数组按下标读是 O(1)、链表要 O(n) 走过去（`list_search`）——
`search(9)` 找到、`search(16)`（已删）返回哨兵，示例都断言了。

## 对象数组与自由表（§10.3）

CLRS 的经典 trick：不用指针不用 new，用**三个平行数组**（key/next/prev）
+ 下标当指针。分配/回收交给**自由表**（free list）——空闲槽位自身串成
单链表：

```cpp
std::size_t allocate_object() {      // 从自由表摘一个槽
    const std::size_t x = freeHead;
    freeHead = next[x];
    return x;
}
void free_object(std::size_t x) {    // 挂回自由表头
    next[x] = freeHead;
    freeHead = x;
}
```

实测（示例 10.2/10.3 联演）：槽 16 号节点被 free 后，下一次 allocate
**恰好复用同一个槽**（自由表 LIFO）——`assert(d == b)` 一行验证。这个
表示法的价值：

- **无 GC/无碎片**：定长槽位，分配回收各 O(1)；
- **可持久化/可序列化**：整个结构是三个数组，memcpy/落盘即快照
  （真实系统：数据库页、游戏 ECS、编译器 AST arena 全是它的化身）；
- **缓存友好**：槽位连续（对比 `std::list` 的节点满天飞）。

## 有根树的表示（§10.4）

**二叉树**：left/right（+ 可选 parent）三数组，−1 表空。示例搭了
6 节点小树并跑两种遍历：

- **中序**（left, 自身, right）：递归版用 C++23 的**显式对象形参递归
  lambda**——`auto inorder = [&](this auto&& self, ptrdiff_t i) { … self(…); }`，
  `this auto&& self` 让 lambda 引用自己，不再需要 `std::function` 的
  类型擦除开销；
- **先序**（自身, left, right）：**显式栈**版——递归消除的标准姿势，
  压栈顺序 right 后 left（LIFO 反转）。

**任意分支树**：first-child/next-sibling 两数组（左孩子右兄弟）——不管
节点有多少孩子都只需两个槽。B 的孩子 D、E 表示为 `fc[B]=D, ns[D]=E`。
DFS 的孩子循环就是一个 for 沿 ns 链走。两套表示的 DFS 序一致
（示例断言 `1 2 4 5 3 6`）。

```
下标:      0  1  2  3  4  5
key:       1  2  3  4  5  6
left:      1  3 -1 -1 -1 -1     ← 二叉树三件套
right:     2  4  5 -1 -1 -1
first-child: 1  3  5 -1 -1 -1   ← 左孩子右兄弟两件套
next-sibling:-1 2 -1 4 -1 -1
```

## 单链表上的经典算法（§10.2–10.3 的算法层）

前面的 10.2/10.3 讲的是**表示**，这一节讲在表示之上的**算法**。承接
「下标当指针」的纪律：链表结点用 `key[]`/`next[]` 两个平行数组表示，
`NIL` 表尾——这样能写真·指针的算法，又不必手写 `delete`。

五个算法覆盖链表的三种基本手法：

| 手法 | 算法 | 复杂度 |
|---|---|---|
| 前后指针 | 反转链表（prev/cur/next 三件套） | Θ(n) 时间 O(1) 空间 |
| 快慢指针 | 倒数第 k 个结点 | Θ(n) 时间 O(1) 空间 |
| 替身删除 | 拿不到前驱时覆盖后继的值再摘后继 | O(1)（尾结点退化 Θ(n)） |
| 归并 | CLRS §2.3 的 MERGE 搬到链表上 | Θ(n) 时间，可原地 |
| 显式栈 | 逆向输出 | Θ(n) 时间 O(n) 空间 |

**反转**的三个指针各司其职：`cur` 走当前结点，`next` 必须在改 `cur->next`
**之前**存下来（否则原后继就丢了），`prev` 承担已反转部分的头。循环退出
时 `cur == NIL`，此时 `prev` 恰是原表的尾——它成了新头。

**倒数第 k 个**用「快慢指针相隔 k 步」：先让 fast 走 k−1 步，然后两指针
同步前进到表尾，此时 slow 正好是倒数第 k 个。一次遍历 Θ(n)，不用第二个
遍历。**前提是 k ≥ 1 且 k ≤ 结点总数**——两个非法输入（k=0、k>n）必须
显式返回「无解」，示例对三种非法情形（k=0 / k>n / 空链表）都断言了返回
`NIL`，而不是读越界。

**替身删除**是这五个里唯一「技巧性」的：题目只给待删结点、不给前驱时，
你无法改动前驱的 `next`，于是把**后继的值搬过来覆盖自己**，再把后继摘掉。
必须说出口的假设：**待删结点不是尾结点**（尾结点没有后继可搬）。示例对
尾结点显式退化成一个 Θ(n) 的「从头找前驱」，并把 `used_substitute` 打成
`false` 让这件事在输出里看得见。

**归并**有个容易踩的坑：链表归并若直接改 `next`，会撞上**下标空间**问题
——两个独立链表的结点下标都从 0 开始，`a.next[i]` 根本无法表达「指向 b
的第 j 个结点」，重接时必然串链。两条出路：

- **共享节点池**（示例的 `merge_in_place`）：两条链躺在同一个池子里，下标
  全局唯一，于是可以只改 `next`、零新结点——这才是真正的原地归并。收尾
  那一行 `next[order.back()] = NIL` 不可省，否则残留的 `next` 会让链绕成
  环（示例的 `to_vector()` 会死循环）；
- **归并到新表**（`merge_by_value`）：每元素一次 `append`，多花 O(n) 空间
  但绝不可能串链。这里的收尾必须用**剩余指针** `y` 而不是 `rest.head`——
  用后者会把已消费的结点再接一遍（示例实测翻车，见坑位清单第 6 条）。

两条路线结果必须一致，示例对同一份输入双向断言。

**逆向输出**的对照实验很说明问题：显式栈版与递归版输出完全一致，但递归版
在 n 个结点上产生 n 层调用栈帧。链表可以很长，栈不一定够——所以「代码短」
的代价要按调用深度算，不能按字符数算。

## 用两个栈实现一个队列（§10.1 的组合技）

`QueueWithTwoStacks` 的不变式一句话：**`in_` 收新元素；只有当 `out_` 空了，
才把 `in_` 整摞倒进 `out_`**。倒一次之后，最早入队的元素就压在 `out_` 的
栈顶，于是栈顶恰好是队首。

摊还代价（第 18 章记账法的教科书例子）：**每个元素最多被倒一次**，所以
n 次操作里总搬运次数 ≤ n，摊还到每次操作是 O(1)。示例用 `moves()` 把
搬运次数打出来对账——4 次出队操作，元素搬运总计 4 次（第一次倒 3 个、
第二次倒 1 个），摊还代价恰是 1.0。注意「倒了几轮」和「搬了几个元素」
是两个不同的计数：前者是 2，后者是 4，混淆这两个口径会写出错的断言。

镜像题是**两个队列实现栈**：出栈时把队首之外的全搬到另一个队列，剩下的
那个才是栈顶。代价 Θ(n) **且没有摊还 O(1) 的好性质**——每次出栈都要搬
n−1 个元素，n 次出栈就是 Θ(n²)。示例实测：4 次出栈共搬运 5 次。两种
「双容器」方案一个摊还 O(1)、一个 Θ(n)，差别全在「能否只在必要时重排」。

## 数组上的两个经典问题

**行主序有序矩阵的查找**。矩阵每行、每列都递增时，查找的关键是**起步
位置**：只有右上角（或左下角）具备「一刀切」性质。

- 从右上角 `v > target`：`v` 是**本列最小**的，整列都不可能是 target → 剔除该列；
- 从右上角 `v < target`：`v` 是**本行最大**的，整行都不可能是 target → 剔除该行。

每步必然剔除一行或一列，所以步数上界 = `rows + cols − 1`，最坏
O(m+n)。为什么另外三个角不行：

- **从中间选**：会把待查区域切成两块且**重叠**，无法递归式地排除；
- **从左上角选**（如 1）：比 1 大的目标既可能在右边也可能在下，一行一列都剔不掉；
- **从右下角选**：对称地，一行一列同样剔不掉。

这个算法有意思的地方在于：它比「每行二分 + 行内线性找」的 O(m log n)
**还小**——因为它把二维结构当成了一个整体在走，而不是拆成 m 个独立问题。

**原地替换空格**。空格换成 `"%20"` 会让字符串**变长**，所以动手前必须
问清：是在原串上改（后面有足够空余）还是新建字符串？两种写法：

- **从前往后**：每个空格都要把它后面 O(n) 个字符整体右移两格，总代价 O(n²)；
- **从后向前**：先数一遍空格数并一次 `resize` 到位，然后从原串末尾往前读、
  从新串末尾往前写，每个字符**只写一次**，总代价 O(n)。

示例用移动次数把这两种写法的差距量化出来（串形如 `"x x x ... x"`）：

| 空格数 k | 从前往后 | 从后向前 | 倍数 |
|---|---|---|---|
| 4 | 16 | 17 | 0.9 |
| 16 | 256 | 65 | 3.9 |
| 64 | 4096 | 257 | 15.9 |

小 k 时从后向前反而略贵（多出的正是那 2k 次 `%20` 字符的写操作，两者同阶）；
k 一大就是压倒性的 16 倍——**这就是 O(n²) 与 O(n) 的分水岭**。

## 表达式：中缀 / 前缀 / 后缀的互转与求值

前面讲的都是「怎么存」（表示法），这一节讲「怎么算」——**栈最经典的应用**。

### 三种遍历与三种表达式一一对应

把二元表达式建成树（运算符为父节点，两个运算数为孩子），三种遍历
**恰好**对应三种写法：

| 遍历 | 顺序 | 对应表达式 | 名称 |
|---|---|---|---|
| 前序 | 根-左-右 | `* x + y z` | 前缀式（Polish） |
| 中序 | 左-根-右 | `x * (y + z)` | 中缀式 |
| 后序 | 左-右-根 | `x y + z *` | 后缀式（逆波兰 RPN） |

三者各访问每个节点**恰好一次**，所以互转都是 **Θ(n)**。这不是巧合——
它们是同一棵树的三个「投影」。

### ★ 关键结论：哪种表示可以被「反解」回来

| 表示 | 能否唯一确定运算顺序 | 能否唯一重建树 |
|---|---|---|
| **前缀式** | **能**（无需括号） | **能**（逆序扫描 + 栈） |
| **后缀式** | **能**（无需括号） | **能**（顺序扫描 + 栈） |
| 无括号中缀式 | **不能**（有歧义） | **不能** |
| 带括号中缀式 | 能（括号即优先级） | 能（Shunting-yard） |

歧义的证据（示例实测）：两棵**不同**的树，去掉括号后的中序串完全相同，
而先序不同：

```
★ 无括号中缀式的歧义（为什么中缀不能唯一重建树）：
    树 A = x*(y+z)   去括号中序 = x * y + z   先序 = * x + y z
    树 B = (x*y)+z   去括号中序 = x * y + z   先序 = + * x y z
    两棵树的**去括号中序串完全相同**（x * y + z），而先序**不同**——
    ⟹ 前缀/后缀式能唯一确定运算顺序，中缀式不能（除非给优先级
       或加括号）。这正是「前缀式可唯一重建、中缀式不可逆」。
```

**为什么前缀式无歧义**？因为每个运算符的**操作数个数在它的位置就确定了**
（栈里剩几个就是几个），不需要括号去消歧。中缀式的运算符夹在两个操作数
中间，左边到底延伸到哪里全靠优先级约定，于是「x*y+z」的读法在「不知道
优先级」的前提下是二义的。

这个结论有直接的工程价值：**传输/存储表达式时用前缀或后缀式**——
不需要传括号，也不怕接收方的优先级配置不同。

### 前缀式 → 树：逆序扫描 + 栈

前缀是「根-左-右」，**从右往左**读就变成「右-左-根」：右子树先完整读完，
于是可以「弹两棵已建好的子树、自底向上合并」：

```cpp
static std::ptrdiff_t build_from_prefix(const std::vector<std::string>& tok,
                                        ExprForest& f) {
    std::vector<std::ptrdiff_t> stk;
    for (std::size_t i = tok.size(); i-- > 0;) {      // ★ 必须逆序
        const std::string& t = tok[i];
        if (!isOperator(t)) {
            stk.push_back(f.add_atom(t));
        } else {
            const auto l = stk.back(); stk.pop_back();   // ★ 先弹的是左子树
            const auto r = stk.back(); stk.pop_back();   //   后弹的是右子树
            stk.push_back(f.add_binary(t, l, r));
        }
    }
    return stk.empty() ? -1 : stk.back();
}
```

**为什么必须逆序**：正序扫描时，运算符先出现而它的两个操作数都还没读到，
无从合并。逆序则保证「读到运算符时，它的操作数已经全部读完并压栈」。

**★ 这里有个极易写反的地方**：本函数**先弹的是左子树**，而下面
Shunting-yard 的消解**先弹的是右操作数**——两者**恰好相反**。
记法：右往左扫时「先读到的是右儿子」，但「**先弹的是左儿子**」。

### 中缀式 → 树：Shunting-yard

维护运算符栈 `op` 与运算数栈 `val`，一条 token 流走完：

- 遇**原子**：进 `val`；
- 遇**运算符**：先把 `op` 栈顶优先级 **≥** 当前的运算符**弹栈消解**，再 push；
- 遇 `(`：直接 push；
- 遇 `)`：弹到 `(` 为止，再弹掉 `(`。

```cpp
} else if (isOperator(t)) {
    // 左结合 ⟹ 优先级**相等也弹**（关键：(a-b)-c 不能弹成 a-(b-c)）
    while (!op.empty() && op.back() != "("
           && priority(op.back()) >= priority(t)) {
        reduce();
    }
    op.push_back(t);
}
```

**「≥」而不是「>」**：所有这些运算符都是**左结合**的。
`(a-b)-c` 消解时必须让前一个 `-` 先归约，才能得到 `a-(b-c)` 的反面
`a-b-c`。写成 `>` 会让同优先级的后一个运算符先归约，把 `(a-b)-c`
错算成 `a-(b-c)`——**值直接变错**。这一条与下一节的括号规则是同一件事
的两面（都在伺候「左结合」）。

### 一元负号的统一化

一元 `-u` 让「孩子数」从 2 变成 1，会让求值、求导、输出三处逻辑各写一遍
特例。标准做法是在**词法分析阶段**归一：

> 把一元 `-u` 改写成 `0-u`，于是整个系统**只需一套二元规则**。

判据很简单：`-` 出现在串首，或前一个 token 是运算符 / 左括号时，它就是
一元负号：

```cpp
const bool atStart = out.empty();
const std::string prev = atStart ? std::string() : out.back();
const bool afterOperandish = prev == "+" || prev == "-" || prev == "*"
    || prev == "/" || prev == "^" || prev == "(";
if (ch == '-' && (atStart || afterOperandish)) {
    out.push_back("0");          // ★ 归一：一元 -u ⟹ 0-u
}
```

实测（示例输出）：`-x*y` 的 token 流变成 `0 - x * y`，树里只剩二元 `-` 节点；
负常量 `-45.78` 变成 `0 - 45.78`，**字面量原样透传**（不转 double，
否则 `-45.78` 会变成 `-45.780000` 并丢精度）。

### 后缀式求值：单栈

最简单也最有用的一种：遇原子 push，遇运算符弹所需个数、算完 push。
扫完栈里那一个数就是值。`ln` 是一元，弹 1 个；`^` 与四则一样弹 2 个。

实测（示例输出）：

```
后缀式求值（单栈，Θ(n)）：
    3 4 +              = 7       （期望 7）
    3 4 2 * + 5 -      = 6       （期望 6）
    5 2 ^              = 25      （期望 25）
    2 3 ^ 4 +          = 12      （期望 12）
    8 5 /              = 1.6     （期望 1.6）
    2 3 + 4 *          = 20      （期望 20）
```

注意求值栈的深度等于**表达式嵌套深度**，与串长无关——`((((1+2))))`
这种串也不会把栈撑深。栈深度的这个性质是表达式求值不会爆栈的原因。

## 表达式树求导：结构归纳与优先级括号规则

这一节把上一节的表达式树当**程序**来处理：给它一个变换（求导），
输出它的中缀式。求导本身不难，**难的是输出时的括号**。

### 求导公式（必须写准）

$$
\begin{aligned}
(u+v)' &= u' + v'\\
(u-v)' &= u' - v'\\
(uv)' &= u'v + uv'&&\text{乘积法则}\\
(u/v)' &= (u'v - uv')/v^2&&\text{商法则，分母写成 } v^2 \text{（不是 } v*v\text{）}\\
\ln(u)' &= u'/u&&\text{分子是导数、分母是原式}\\
x' &= 1,\qquad c' = 0&&(c \text{ 为常数})
\end{aligned}
$$

两处容易写反的地方：

- **商法则的分母是 v² 而不是 v·v**——题目要求输出 `v^2` 这种幂形式，
  虽然数值相等但**输出串不同**，评测机按字符串比对就会判错；
- **`ln(u)' = u'/u`**——分子是导数 u'、分母是原式 u。写反成 `u/u'`
  在数学上是错的（u 常为 0），且与样例输出矛盾。

### ★ 括号规则：本节的核心

输出中缀式时，设**父节点**优先级为 p、**孩子子树根**的优先级为 c：

- **左孩子**：子树根**不是原子**（常数/变量）**且 c < p** ⟹ 加括号；
- **右孩子**：子树根**不是原子**且 **c ≤ p** ⟹ 加括号。

**注意右边是 ≤ 不是 <。** 这是本节最容易错的一行，理由如下。

`+ - * /` 全都是**左结合**运算：

- `(a-b)-c` 写成 `a-b-c` **恰好是对的** ⟹ 左孩子同优先级**不能**加括号
  （加了只是多余，不算错但形态不美）；
- `a-(b-c)` 写成 `a-b-c` **是错的** ⟹ 右孩子同优先级**必须**加括号。
  带括号是 `a-(b-c)`，值是 b-c；去掉括号变成 `(a-b)-c`，值差了一截。

所以「左严格、右相等」不是笔误，而是**左结合在括号规则上的镜像**：
凡是「同优先级时默认先算左边」的地方，左边省略、右边保留。

实测的对照（示例输出）：

```
★ 右孩子为什么必须用「≤」（左结合的镜像）：
  x-(x-x)    ⟹ 1 - (1 - 1)                   （括号必须保留）
  x-(x*x)    ⟹ 1 - (1 * x + x * 1)           （括号必须保留）
  x*(x+x)    ⟹ 1 * (x + x) + x * (1 + 1)     （括号必须保留）
    若右孩子也只用「<」，x-(x-x) 会输出成 1-1-1 =
    (1-1)-1 = -1，而正确值是 1-(1-1) = 1 —— 值直接错了。
    左孩子同优先级**不能**加括号：(x-x)-x 输出 x-x-x 恰好正确。
```

**「是不是原子」这个条件也不能省**：常量和变量（`3`、`x`）的优先级
按定义是 0，但它们**永远不需要括号**——`(3)` 是废话。所以判据是
「非原子 **且** 优先级满足条件」，两个都要查。

### 检验规则的关键样例：x*x/x

这个表达式同时压测左、右孩子的两种判定：

```
★ 括号规则的钥匙 x*x/x（根是 `/`，左孩子是同优先级的 `*`）：
  x*x/x  ⟹ ((1 * x + x * 1) * x - x * x * 1) / x ^ 2
    根 `/`（p=4），左孩子子树根是 `*`（c=4，同优先级）——
    左孩子判**严格小于** ⟹ 不加括号 ⟹ `(...) * x` 而非 `(...) * (x)`。
    右孩子是 x^2（c=6 > 4）⟹ 也不加括号。
    若左孩子也用 ≤，会多出一层无谓括号（值虽同，形态不对）。
```

逐项拆解（这题把四条规则都用上了）：

1. 根是 `/`，p=4。左孩子是 `(1*x+x*1)*x`，子树根 `*` 的 c=4，
   **左孩子判 c < p ⟹ 4 < 4 为假 ⟹ 不加括号**；
2. 根的右孩子是 `x^2`，c=6 > 4 ⟹ 不加括号；
3. 那个 `*` 的左孩子是 `1*x+x*1`，子树根 `+` 的 c=3 < 4 ⟹ **加括号**；
4. 商法则生成了 `x^2`：新节点 `^` 的右孩子是原子 `2`，不触发括号。

### 输出用流式拼接，不要反复 `+`

把导数字符串逐段 `out = out + ...` 拼起来，每次都重新分配内存并拷贝已有
内容 ⟹ **Θ(n·L)**（n 个片段、最终长度 L）。正确做法是**流式 append**
或**一次性 `reserve`**：

```cpp
static void emit_infix(const ExprForest& f, std::ptrdiff_t i, int parentPri,
                       bool isRightChild, std::string& out) {
    if (i == -1) { return; }
    const ExprNode& nd = f.node[static_cast<std::size_t>(i)];
    const int p = priority(nd.text);
    const bool atomic = (nd.kind == 0);
    // ★ 括号规则：左孩子判严格小于、右孩子判小于等于（左结合）
    const bool need = !atomic && (isRightChild ? (p <= parentPri) : (p < parentPri));
    if (need) { out += '('; }
    if (nd.kind == 2) {
        emit_infix(f, nd.l, p, false, out);          // 左孩子
        out += ' '; out += nd.text; out += ' ';
        emit_infix(f, nd.r, p, true, out);           // 右孩子
    } else if (nd.kind == 1) {
        out += nd.text; out += '(';                   // ln(...)
        emit_infix(f, nd.l, 0, false, out);
        out += ')';
    } else {
        out += nd.text;
    }
    if (need) { out += ')'; }
}
// 调用侧：std::string out; out.reserve(256);  ⟹ append 不再重新分配
```

复杂度 **Θ(n + L)**。这与本章 10.7(b) 的「原地替换空格」是同一个道理：
输出长 L 时，唯一该做的优化就是「每个字符只写一次」。

要注意的是**不化简的固有代价**：连乘 n 个 x 的导数在不化简时长度是
Θ(2ⁿ)（每层 `u'v + uv'` 翻倍）——拼接方式不该再给它加一层平方，但
**题目必须保证输出长度有界**，否则任何算法都救不了。示例用 8 个 x 的
连乘实测：输入 29 字符 → 导数 181 字符。

### 正确性：结构归纳

对表达式的结构做归纳，分三种情形：

- **叶子**：`x' = 1`、常数 `c' = 0`，符合导数定义；
- **一元**（只有 `ln`）：由归纳假设 u 的子树导数 `u'` 正确，按
  `ln(u)' = u'/u` 组合即得；
- **二元**：由归纳假设 u、v 的子树导数都正确，按 `+ − * /` 四条法则
  组合即得正确的父节点导数。

最后 `emit_infix` 只做「加括号以保持原语义」的机械变换——由括号规则的
正确性（见上）保证输出的中缀式与树**语义等价**。

## 占用数组：花园种花

### 问题

F 个坑沿篱笆排成一排（坑号 1..F）。K 种花，第 j 种从坑 L[j] 开始、每隔
I[j]−1 个坑种一株，即占据一条等差数列：

```
L[j], L[j]+I[j], L[j]+2I[j], L[j]+3I[j], …（不超过 F）
```

一个坑不管被几种花命中，只算被占用一次。问最后空坑数。样例 F=30，三种花
(L=1,I=3)、(L=3,I=7)、(L=1,I=4)，答案 13。输出原文：

```
美丽的花园（1-4）：占用数组 + 等差数列：
  F=30，玫瑰 L1/I3、秋海棠 L3/I7、雏菊 L1/I4
  占用数组版空坑 13，逐坑核对版 13（答案 13）
  随机 2000 例两版对账：不一致 0 例
```

### 表示：下标即坑号

最朴素的集合表示在这里恰好最好：一个 `vector<char>(F)`，**下标 = 坑号−1**，
值 = 是否被占。成员检测与置位都是 O(1)。对每种花沿等差数列走一遍置 1，
最后数一遍 0 的个数。总代价 O(F + 全部栽种点数)；即便每种花种满 F 个坑，
也只是 O(FK)，F ≤ 10⁴、K ≤ 100，毫无压力。

相比「对每个坑逐一问 K 种花谁占它」的双重循环（同样 O(FK) 上界），这个写法
内层循环只跑真正的栽种点，且不需要「最小 L 之前的坑必然空」那类手工优化——
初始 0 已经把所有坑一视同仁地表达了。

### 占据条件的两种等价写法（右边不能写错）

核对版逐坑判定「坑 i 是否被花 j 占据」，两种等价形式：

```
(i − L[j]) mod I[j] == 0
(i − 1) mod I[j] == (L[j] − 1) mod I[j]
```

第二种右边**必须是 L[j]−1**。因为等差数列是从 L[j] 起步的，换成 0 基坐标后
起点是 L[j]−1；若把右边写成 L[j]，判定就整体错位一格——用样例的玫瑰检验：
L=1、I=3，正确的坑是 1、4、7……按错式坑 1 处 `0 mod 3 = 1` 不成立，整串判定
一株都种不上。这类「1 基题面翻译成 0 基下标时漏 −1」是数组题里最常见的
off-by-one。示例让占用数组版与逐坑核对版在 2000 个随机案例上对账。

## 后缀表达式与终态周期序列

### 问题

给定函数 f: {0…N} → {0…N}，从某个 n ≤ N 出发不断迭代：

```
x₀ = n,   x₁ = f(x₀),   x₂ = f(x₁),   …
```

f 的计算规则以**后缀表达式（RPN）**给出，运算数为无符号整数常量、
符号 N、变量 x，二元运算符为 `+`、`*`、`%`；`%` 恰好出现一次、在最
后，第二运算数必为 N（所以 f 的值天然落在 0..N−1）。由于状态只有 N+1
个，轨道必然在有限步内重复，此后周而复始。要求计算周期部分的长度。

轨道的一般形状是「一条尾巴接上一个环」，例如 {1, 2, 7, 5, 4, 6, 5,
4, 6, …}，本题只问**环长**，不问尾巴多长。

### 第一步：栈式 RPN 求值

后缀式的好处是无需括号、无需优先级，一个栈线性扫完：遇运算数压栈，遇
运算符弹出两个栈顶、计算后压回。以 `x x 1 + * N %`（即
f(x) = x(x+1) mod N）为例：

```
x   → [x]
x   → [x, x]
1   → [x, x, 1]
+   → [x, x+1]
*   → [x(x+1)]
N   → [x(x+1), N]
%   → [x(x+1) mod N]
```

实现里栈元素用 `unsigned long long`：取模发生在最后一步，此前的中间乘
积不受 N 约束；N ≤ 1.1·10⁶ 时三个因子连乘约 1.3·10¹⁸，仍在 64 位范围
内。若表达式因子更多，就得换成大整数类型——求值器本身与字长无关，只
改栈元素类型即可。

### 第二步：首次出现表测周期

准备一个长度 N+1 的表 `first`，记录每个值第一次出现的序号，初值 −1。
从 k=0、x=n 起，只要当前值未见过就记下 `first[x] = k`，再令
x = f(x)、k 自增。一旦 x 已在表中，答案就是

```
周期 = k − first[x]
```

为什么这既是周期又是**最小**周期：设第一个重复的值是 x_k = x_i
（i < k）。因为 f 是确定的函数，x_k = x_i 蕴含 x_{k+1} = f(x_k) = f(x_i)
= x_{i+1}，归纳可得此后整段 x_i, x_{i+1}, …, x_{k−1} 无限重复；而这
k−i 个值在第一次重复前两两不同（否则重复更早发生），所以不存在更小的
周期。尾巴 x₀..x_{i−1} 则再也不会被访问。

### 对账：Floyd 快慢指针

首次出现表用 O(N) 空间换 O(1) 的成员检测。一个完全不同的测圈方法只需
O(1) 空间：让慢指针每拍走 1 步、快指针走 2 步，二者必在环内相遇；相遇
后按住一个指针、另一个再走一圈并计数，即得环长。

```cpp
tortoise = f(start); hare = f(f(start));
while (tortoise != hare) { tortoise = f(tortoise); hare = f(f(hare)); }
period = 1; hare = f(tortoise);
while (tortoise != hare) { hare = f(hare); ++period; }
```

两种算法在 5 个样例上答案 1、3、6、6、369 全部一致；示例还对 3000 个
随机仿射后缀式 `(x·a+b) mod N` 和 1000 个完全任意的映射表做了对账，
0 例不一致。

## 反转数相加：数位层面的三步操作

### 问题

一个数的**反转数**：把它的十进制位顺序颠倒，第一位与最后一位互换。
以 0 结尾的数，0 在反转后成为前导零、按整数写法丢弃——1200 的反转数
是 21。给定两个正整数，把它们**各自反转后相加，再把和反转**，输出
结果（同样舍弃前导零）。题设保证反转过程不丢失 0，即可以认为输入
不以 0 结尾。

三个样例：

```
24 与 1：42 + 1 = 43，反转 43 ⟹ 34
4358 与 754：8534 + 457 = 8991，反转 ⟹ 1998
305 与 794：503 + 497 = 1000，反转剥零 ⟹ 1
```

### 内置整数版

反转一个整数不需要真的拆成数组：循环做 `r = r*10 + x%10; x /= 10`——
每次把 x 的个位接到 r 的右边。以 4358 为例：4358→（取 8）r=8；
（取 5）r=85；（取 3）r=853；（取 4）r=8534。于是整个程序是两次
反转夹一次普通加法：

```cpp
middle = reverse_number(x) + reverse_number(y);
answer = reverse_number(middle);
```

注意**中间和不要反转后忘记再反转**：第一步产出的 43 是中间结果不是
答案，43 与 34 是两个不同的数。

### 数字串版：让位数不受限

这类问题的实际输入可以有几百位——反转数可能比任何内置整数都长，
中间和更宽。把输入当**字符数字数组**处理就没有宽度问题：

1. 反转两个字符串；
2. 从两串**右端对齐**做十进制列加法（逐列求和、留进位），列输出按
   低位到高位收集，反序后得到中间和 z' 的普通写法；
3. 再反转 z' 得到 z，剥掉前导零。

以 305、794 走一遍：反转得 `503`、`497`；列加法从低位起各列依次
产生 0、0、0 并进位 1（3+7=10；0+9+1=10；5+4+1=10），z' =
`1000`；反转得 `0001`，剥前导零 ⟹ **1**。

> 一个容易被忽略的细节：反转串若以 0 开头（原数以 0 结尾），列加法
> 必须无视这些前导零——它们在整数语义里已被丢弃。若把它们当成有效
> 列参与相加，就会在答案末尾凭空多出 0：10 与 60 会被算成 `70` 而
> 不是 `7`。题设的「不丢零」假设让输入根本不出现这种情形，但数字串
> 实现本身仍应按整数写法处理这些零。
>
> 还有一个可以简化实现的观察：答案 z 的数位按正常顺序，恰好就是列
> 加法从低位到高位的原始列输出——「列收集后反序成 z'」与「再反转
> z' 成 z」两次反序互相抵消。示例保留两次反转的显式写法，让三步
> 过程在代码里可见。

### 对账

三个样例上内置整数版与数字串版答案一致；20 个 9 的超长输入与 1
相加（两者都塞不进 64 位整数），数字串版给出 `1`；3000 个随机
≤8 位案例（首位、末位都非零）两版 0 例不一致。

## Web 导航：两个栈模拟浏览器历史

### 问题

浏览器有后退、前进两个按钮，还能在地址栏输入新网址。需要支持四条
命令：

- **BACK**：回到上一个页面。没有可回的页面时忽略本命令；
- **FORWARD**：前进到后退前所在页面。没有可前进的页面时忽略；
- **VISIT url**：直接访问 url；
- **QUIT**：结束，不产生输出。

浏览器启动时当前页固定为 `http://www.acm.org/`。每条被执行的
命令输出执行后的当前 URL；被忽略的命令输出 `Ignored`。

### 状态与不变量

状态只有三样东西：当前页 `current`、**后退栈** `back`、**前进栈**
`forward`。核心不变量是：

> **当前页不属于任何一个栈。** 后退栈顶是「当前页的前一页」，
> 前进栈顶是「当前页的后一页」。

于是三个操作只是栈顶搬运，每一步都先把当前页推到目标栈，再把
新当前页从来源栈弹出：

```
BACK（back 空 ⟹ Ignored）：
    forward.push(current)           ← 当前页变成「未来」
    current = back.top(); back.pop() ← 栈顶变成「现在」

FORWARD（forward 空 ⟹ Ignored）：
    back.push(current)
    current = forward.top(); forward.pop()

VISIT url：
    back.push(current)
    current = url
    forward 清空                     ← 关键
```

在样例上走前六步（初始页记为 ACM）：

```
VISIT ashland   back=[ACM]              current=ashland  forward=[]
VISIT baylor    back=[ACM,ashland]      current=baylor
BACK            back=[ACM]  forward=[baylor]  current=ashland
BACK            back=[]     forward=[baylor,ashland] current=ACM
BACK            back 为空 ⟹ Ignored（什么都不动）
FORWARD         back=[ACM]  forward=[baylor] current=ashland
```

### 为什么 VISIT 必须清空前进栈

历史在 VISIT 的一刻**分叉**：旧的前进链是「沿旧历史继续走」的产物，
新页面之后再按 FORWARD，没有任何理由到达旧链上的页面。若不
清空，样例第七步 VISIT ibm 后，前进栈里还躺着 baylor，一次
FORWARD 就会把用户带到一个与新历史毫无关系的地址。真实浏览器
在这一点上行为完全一致。

### 复杂度

BACK/FORWARD 都是 O(1)。VISIT 的清栈看起来要 Θ(|forward|)，
但每个被弹出的页面都对应之前的一次 push，**整段命令流里 push
总次数等于 pop 总次数**，故 n 条命令总耗时 O(n)。

### 对账：单历史 + 游标模型

另一种等价实现根本不用栈：一条 `history` 数组保存访问过的全部
页面，`pos` 是当前页下标。BACK 把游标 −1，FORWARD 把游标 +1，
VISIT **砍掉游标之后的尾巴**再追加新页。两种结构错法完全不同
（一个错在栈顶搬运顺序，一个错在游标与截断），示例让它们逐条
命令对账：12 条样例命令 + 3000 条随机命令（VISIT/BACK/FORWARD
按 4:3:3 混合），0 例不一致。

## C++23 语言点

- **递归 lambda（显式对象形参）**：`[&](this auto&& self, auto… args)`
  是 C++23 「deducing this」对 lambda 的应用，等价于 Y 组合子的受控版；
- 平行数组的下标即指针：`std::size_t` 全程无符号，空位用 `SIZE_MAX`
  （或 ptrdiff_t 的 −1）——两套纪律别混；
- `std::vector` 当栈用（back/push_back/pop_back）就是 ArrayStack；
- `std::expected` 风格的「无解」返回也可以用 `std::optional<std::size_t>`
  表达（本章 kth_from_end 返回 NIL 而非 optional，是延续 10.2 的下标纪律：
  NIL 本身就是「无此结点」的唯一表示，再包一层 optional 反而多一种状态）。

## 与 STL 对照

| 本章结构 | STL 对应 | 底层 |
|---|---|---|
| ArrayStack | `std::stack`（默认） | deque |
| CircularQueue | `std::queue` | deque（环形缓冲的分段实现） |
| 哨兵双链表 | `std::list` | 真指针节点 + 哨兵（libstdc++/MSVC 都是 `_M_node` 哨兵——**本章的工业化版本**） |
| 对象数组+自由表 | `std::pmr::monotonic_buffer_resource` + arena | 槽位复用思想 |
| 定容环形缓冲 | `boost::circular_buffer` / 手写 | 环形 head/tail |
| 单链表（key/next 平行数组） | `std::forward_list`（C++11 起的单链表标准容器） | 同样只有 next；本章多一个 free list |
| 两栈队列 | 无（`std::deque` 单容器即可） | 摊还 O(1) 的教学模型 |

## 坑位清单

1. **把两次 `pop()` 写进同一个 println 的实参**
   （现象：输出「3 2」变「2 3」——顺序反了；原因：函数实参求值顺序
   未指定，MSVC/clang 实测从右往左、先求值右边的 pop；后果：输出语义
   错乱但三通道恰好一致（都右到左），逐字节对账还发现不了；对策：有副
   作用的表达式先落局部变量再打印——本例实测翻车，改后输出恢复
   「3 2」「9 16 25 36」。）
2. **注释行尾的反斜杠触发 -Wcomment**
   （现象：gcc 报 `warning: multi-line comment`，零告警判定失败；原因：
   ASCII 树形注释里 `/  \` 的行尾 `\` 恰在换行前——反斜杠续行把下一行
   注释吞了；后果：gcc 通道全红而 msvc 无感；对策：树形注释行尾不落
   反斜杠（加尾随空格或换画法）——本例实测翻车。）
3. **循环队列的空/满判据混用**
   （现象：enqueue 抛 assert「full」而实际没满，或满时静默覆盖；原因：
   「留空位」与「计数器」两种方案各有一套判据，代码里混用（比如 full
   用计数器、empty 用 head==tail）；后果：off-by-one 类边界 bug；
   对策：一种方案走到底，capacity/count/head/tail 的不变式写成 assert
   （每步 `count ≤ capacity` 且 `(head+count)%capacity == tail`）。）
4. **自由表忘把回收槽位的 next 清理/复用未重置 prev**
   （现象：遍历链表偶发走到「已删除」节点或成环；原因：free_object 后
   槽位的 next 仍指向自由表外的节点（或 prev 残留），allocate 后若调用方
   只设 key 不重接 prev 就成环；后果：数据结构损坏，且时机随机难复现；
   对策：allocate 返回后由 insert 负责四指针全部赋值——绝无「只接一半」
   的路径，示例 list_insert 四行全覆盖。）
5. **左孩子右兄弟的 next-sibling 与 first-child 混写**
   （现象：DFS 走出环或漏子树；原因：fc 指向**第一个**孩子、ns 指向
   **下一个兄弟**——把 ns 当「下一个孩子」接是同一类错；后果：遍历
   序错乱；对策：不变式断言「fc 与 ns 的终点都必须是 −1，且每节点被
   至多一个 fc/ns 指向」。）
6. **链表归并的「下标空间冲突」**
   （现象：把两个**独立**链表的结点下标混进同一个序列，重接 next 后
   得到错乱甚至成环的链；原因：下标是「池内局部编号」，两个池的 0 号
   结点不是同一个结点，`a.next[i]` 无法表达「指向 b 的第 j 个」；后果：
   assert 在 to_vector() 处炸掉，或更糟——遍历时死循环；对策：原地
   归并必须让两条链躺在**同一个节点池**（下标全局唯一），或者干脆输出
   到新表。收尾的 `next[order.back()] = NIL` 也不能省，残留 next 会成环。）
7. **归并收尾用了 `rest.head` 而不是剩余指针**
   （现象：结果里出现重复元素（已消费的结点被再接一遍）；原因：一侧
   先耗尽后，另一侧的剩余部分是 `y`（当前游标）而不是它的 `head`——
   `head` 指向的是**已经被合并过**的段首；后果：输出序列局部有序但
   整体重复，测试若只查「是否有序」会漏过；对策：收尾循环从游标而非
   head 起步。本教程 10.5 的 merge_by_value 实测翻车过此坑。）
8. **「倒了几轮」与「搬了几个元素」两个计数混淆**
   （现象：两栈队列的摊还断言恒失败（写了 pours()==2 实测是 4）；原因：
   一次倒栈搬 k 个元素，轮数计 1、搬运计 k，两种口径差 k 倍；后果：
   断言失败但算法本身完全正确，容易误判成实现有 bug；对策：计数器
   名字要说清计的是什么——本章统一用 moves() 计元素搬运次数。）
9. **有序矩阵查找的起步位置选错**
   （现象：从左上角或中心起步，查找要么漏解要么死循环；原因：只有
   右上角/左下角具备「一刀切」性质（见正文表）；左上角起步时大于
   它的目标可能出现在任一方向，无法整行整列剔除；后果：逻辑错误且
   小规模用例仍能过（退化用例全等矩阵）；对策：先在纸上问「这一步
   能排除一整行还是一整列」，答不上就别写。）
10. **错误直觉：输出括号的左右孩子都判「严格小于」**
   （现象：求导/输出里 `x-(x-x)` 输出成 `1-1-1`，值从 1 变成 −1；
   原因：只判 `c < p`，同优先级时一律不加括号——但 `+ - * /` 都是
   **左结合**的，`a-(b-c)` 的括号**必须**保留，去掉就变成 `(a-b)-c`；
   后果：**值直接算错**，且样例若不含减法右孩子就查不出来；对策：
   **左孩子判 `c < p`、右孩子判 `c ≤ p`**——「前严格后相等」是左结合
   在括号规则上的镜像。示例的x*(x+x) 就是右孩子同优先级必须加括号的
   活证据。）
11. **错误直觉：括号规则只查优先级，不查「是不是原子」**
   （现象：常量子树被套上无谓括号，输出 `(3)` 而不是 `3`；原因：常数
   与变量的优先级按定义是 0，判据若写成「c < p」在某些组合下会被误判
   为需要括号；后果：值虽同但**输出串与评测机不一致**；对策：判据是
   「**不是原子**（常数/变量）**且** 优先级满足条件」，两个条件都要查。）
12. **商法则的分母写成 v*v 而不是 v^2**
   （现象：数值全对但评测机判错——它按字符串比对`(u'v-uv')/v^2` 与
   `(u'v-uv')/(v*v)`；原因：两者数学上相等但输出形态不同，题目要求
   幂写成 `b^2`；后果：Wrong Answer 且极难自查；对策：商法则生成分母
   时显式构造 `^` 节点（`priority['^']` 设为最高，使它作右孩子时永
   不需要括号）。同理 `ln(u)' = u'/u` 的分子是导数、分母是原式，写反
   既算错值又与样例矛盾。）
13. **前缀式建树时把弹栈顺序写成「先右后左」**
   （现象：`* x + y z` 重建出的树变成 `*(+(x,y),z)`，先序输出变成
   `+ * x y z`，与输入不符；原因：**逆序扫描**时栈顶是**左**子树
   （离当前运算符更近），而 Shunting-yard 的消解是先弹**右**操作数
   ——两者恰好相反，混用就错；后果：重建出的树**左右子树互换**，
   数值大多仍对（乘法交换律）但结构错，随机数据下不易发现；对策：
   记住口诀「右往左扫时，先读到的是右儿子，但**先弹的是左儿子**」，
   并断言重建后的先序与输入逐字相同。）
14. **字符串反复拼接 `out = out + ...`**
   （现象：输出长度一大就超时（复杂度 Θ(n·L)）；原因：每次 `+` 都
   重新分配并拷贝已有全部内容；后果：TLE；对策：改用 `out += ...`
   流式追加，并先 `out.reserve(256)` 让 append 不再重新分配 ⟹
   Θ(n + L)。本章 10.7(b) 的「原地替换空格」是同一模式。）
15. **1 基起点翻译成 0 基下标时漏 −1**
    （现象：逐坑判定写成 `(i−1) mod I == L`，整种花错位一格、一株都种不上；
    原因：等差数列的 0 基起点是 L−1 不是 L；后果：空坑数被算成 F 等离谱值，
    但若 I=1（每坑都种）反而碰巧正确，小样例可能漏检；对策：统一写成
    `(i−L) mod I == 0`，避开下标基转换；且写两个独立实现互相对账。）
16. **用 `vector<bool>` 的代理元素做 += 累加**
    （现象：`empty += occupied[i] == 0` 类型怪异，或取引用编译失败；原因：
    `vector<bool>` 的元素不是真 bool 而是代理对象，行为是特例；后果：可移植性
    坑；对策：位图用途直接用 `vector<char>`（每元素 1 字节，无代理），需要省
    内存时才手写位图结构（见第 11 章 Bitmap）。）
17. **RPN 二元运算的弹栈顺序搞反**
    （现象：非交换运算（%）结果错；原因：后缀式 `a b op` 中先压 a 后压
    b，栈顶是 b——运算符要先弹 op2 再弹 op1，算 `op1 % op2`；写成
    `op2 % op1` 则把 `x N %` 算成 N % x；对策：固定「后弹的是左操作数」，
    并拿 `x N %` 这类含 % 的样例逐案断言。）
18. **周期检测在「首次重复」时取了 k − 0 或直接返回 k**
    （现象：带尾巴的轨道周期被算大；原因：重复的值 x_k = x_i 未必是起点
    n——周期是 k − **first[x]**（环长），尾巴长度 i 不该计入；对策：表里
    存序号而非布尔，命中重复时查表取 i，并用 Floyd 独立测圈对账（两种
    方法错法不同，同错的概率很低）。）
19. **取模前中间积溢出 64 位**
    （现象：大 N、多因子样例（如周期 369 一案）结果偶发性错误；原因：
    唯一的 % 在末尾，此前的乘法结果不受 N 约束——三因子约 1.3·10¹⁸ 还
    装得下 unsigned long long，因子再多就回绕；对策：确认表达式因子数
    上界后选整数宽度，不确定时用大整数（求值器只需改栈元素类型）；常量
    解析也要用 stoll 并转无符号，避免 `12345` 被当成逐字符处理。）
20. **反转、相加之后忘了再反转**
    （现象：24/1 输出 43 而非 34；原因：任务是三个动作——各自反转、
    相加、**和再反转**，第一步的反转数只是中间量；对策：代码写成
    reverse(reverse(x)+reverse(y)) 的显式结构，并用三个样例逐案断言。）
21. **用内置整数承载长位数输入，或列加法把反转串前导零当有效列**
    （现象：长输入上整数溢出、结果回绕；或末尾添零（10+60 算成 70）；
    原因：反转数位数等于输入位数、中间和更长——应按数字串做列加法；
    反转串开头的 0 是已丢弃的尾零，不是有效列；对策：数字串实现
    右端对齐列加、列上只加有效数字，并保留一个超长（20 位）案例
    专门走字符串版验证。）
22. **栈顶搬运的先后写反或漏推当前页**
    （现象：BACK 后旧当前页从历史里消失、或新当前页与旧页重复；
    原因：正确顺序是**先把 current 推入目标栈，再从来源栈弹出新
    current**——两步缺一不可、次序不可换；对策：按「当前页不属于
    任何栈」的不变量写完后逐条断言：任一页面在两栈与 current 中
    恰好出现一次（在其存活期内）。）
23. **VISIT 不清空前进栈**
    （现象：FORWARD 能到达分叉前的旧页面，历史出现「穿越」；
    原因：旧前进链依附于旧历史，新 URL 处历史已经分叉；对策：
    VISIT 末尾 while 弹空 forward，并保留样例第七步这种
    「VISIT 后再 BACK/FORWARD」的命令序列专门验证。）
24. **被忽略的命令仍然输出当前 URL**
    （现象：初始页连续 BACK，第二行起输出一堆
    http://www.acm.org/ 而不是 Ignored；原因：来源栈为空时命令
    必须**整体无副作用**、输出固定为 Ignored——既不动栈也不
    报当前页；对策：back()/forward() 返回 bool，调用处按
    返回值二选一输出。）

=== 10.8 表达式：中缀 / 前缀 / 后缀的互转与求值 ===
三种遍历 ⟷ 三种表达式（一一对应，各 Θ(n)）：
  中缀输入 x + y        → 前缀 + x y        后缀 x y +
  中缀输入 x * y + z    → 前缀 + * x y z    后缀 x y * z +
  中缀输入 (x * y) + z  → 前缀 + * x y z    后缀 x y * z +
  中缀输入 x * (y + z)  → 前缀 * x + y z    后缀 x y z + *
  中缀输入 x - y - z    → 前缀 - - x y z    后缀 x y - z -

  注意第 2、3 行：输入的中缀**不同**（有无括号），但因代数上
  x*y+z 本就该加括号，前缀相同；第 4 行才是真正不同的结构。

★ 无括号中缀式的歧义（为什么中缀不能唯一重建树）：
    树 A = x*(y+z)   去括号中序 = x * y + z   先序 = * x + y z
    树 B = (x*y)+z   去括号中序 = x * y + z   先序 = + * x y z
    两棵树的**去括号中序串完全相同**（x * y + z），而先序**不同**——
    ⟹ 前缀/后缀式能唯一确定运算顺序，中缀式不能（除非给优先级
       或加括号）。这正是「前缀式可唯一重建、中缀式不可逆」。

前缀式 → 树（逆序扫描 + 栈）→ 三种表达式：
    前缀输入: * x - y z
    重建后先序: * x - y z（与输入逐字相同 ⟹ 重建唯一）
    重建后中序: x * y - z
    重建后后序: x y z - *
    中序**加括号**后: x * (y - z)
    ⟹ 中序遍历本身不恢复括号，必须靠优先级规则「补」回来（见 10.9）。

一元负号归一化（`-u` ⟹ `0-u`，只需一套二元规则）：
    输入 -x*y 的 token 流: 0 - x * y
    建树后先序: - 0 * x y
    ⟹ 树里只有二元 `-` 节点，一元的处理逻辑完全消失。
    （归一后 -x*y 成了 0-(x*y)：与 (0-x)*y 数值相同，
      但树形由优先级决定——补的0 是二元 `-` 的左孩子。）
    负常量 -45.78 的 token 流: 0 - 45.78（字面量原样保留，不转 double）

=== 10.9 表达式树求导：结构归纳与优先级括号规则 ===
求导（不化简，允许 0*x、1*x；幂写成 v^2）：
  x*x      ⟹ 1 * x + x * 1                 
  x+x      ⟹ 1 + 1                         
  x-x      ⟹ 1 - 1                         
  x/x      ⟹ (1 * x - x * 1) / x ^ 2       
  x/3      ⟹ (1 * 3 - x * 0) / 3 ^ 2       
  x+x*x    ⟹ 1 + (1 * x + x * 1)           
  ln(x)    ⟹ 1 / x                         
  -x       ⟹ 0 - 1                         

★ 括号规则的钥匙 x*x/x（根是 `/`，左孩子是同优先级的 `*`）：
  x*x/x  ⟹ ((1 * x + x * 1) * x - x * x * 1) / x ^ 2
    根 `/`（p=4），左孩子子树根是 `*`（c=4，同优先级）——
    左孩子判**严格小于** ⟹ 不加括号 ⟹ `(...) * x` 而非 `(...) * (x)`。
    右孩子是 x^2（c=6 > 4）⟹ 也不加括号。
    若左孩子也用 ≤，会多出一层无谓括号（值虽同，形态不对）。

★ 右孩子为什么必须用「≤」（左结合的镜像）：
  x-(x-x)    ⟹ 1 - (1 - 1)                   （括号必须保留）
  x-(x*x)    ⟹ 1 - (1 * x + x * 1)           （括号必须保留）
  x*(x+x)    ⟹ 1 * (x + x) + x * (1 + 1)     （括号必须保留）
    若右孩子也只用「<」，x-(x-x) 会输出成 1-1-1 =
    (1-1)-1 = -1，而正确值是 1-(1-1) = 1 —— 值直接错了。
    左孩子同优先级**不能**加括号：(x-x)-x 输出 x-x-x 恰好正确。

ln(u)' = u'/u（分子是**导数**、分母是**原式**，别写反）：
  ln(x)      ⟹ 1 / x                 （u=x, u'=1 ⟹ 1/x）
  ln(x*x)    ⟹ (1 * x + x * 1) / (x * x)（u=x*x, u'=1*x+x*1）
  ln(2*x)    ⟹ (0 * x + 2 * 1) / (2 * x)（u=2*x, u'=0*x+2*1）
    ⟹ 分母是**原式 u**（未求导）；u 的根若是 `*`（c=4 ≤ 4）
       则右孩子必须加括号 —— 这正是 ≤ 规则的第二个用武之地。

正确性（结构归纳，对树的每个节点分三种情形）：
  叶子  ：x'=1、c'=0，符合导数定义。
  一元  ：ln(u)' = u'/u，由归纳假设 u' 正确即得。
  二元  ：按 + − * / 四个法则组合两个孩子（归纳假设保证孩子正确）。
  输出  ：括号规则只做「保持语义」的机械变换 ⟹ 中缀式与树等价。
