# 17 · 贪心算法

> 对应 CLRS 第 16 章 *Greedy Algorithms*（英文 3rd ed. pp.414–450）。
> 贪心 = 每一步都做「当前最优」且**从不回头**。它比 DP 快（通常少一个
> 因子甚至降到 O(n lg n)），但正确性需要证明——本章给两个证明范式
>（贪心选择保持最优 / 拟阵理论），也给反例直觉（什么时候贪心翻车）。

## 学习目标

1. 会用「贪心选择性质 + 最优子结构」两步证明贪心正确（活动选择）；
2. 能陈述 Huffman 的贪心正确性引理（最小两频率必同为最深叶的兄弟）；
3. 理解拟阵 (M, ℐ) 三公理与「拟阵上的加权贪心最优」定理 16.12；
4. 能举出贪心失效的反例（找零硬币、区间加权）并知道怎么验。

## 活动选择（§16.1）

**问题**：n 个活动各占 [sᵢ, fᵢ)，选**两两兼容**的最大子集。

**贪心策略：按最早结束时间选**。直觉：早结束给后面留最多的空间。

```cpp
static std::vector<int> greedy_activity() {
    std::vector<int> pick;
    int lastEnd = 0;
    for (std::size_t i = 0; i < kS.size(); ++i) {
        if (kS[i] >= lastEnd) { pick.push_back(i); lastEnd = kF[i]; }
    }
    return pick;
}
```

**正确性两步**（定理 16.1）：

1. **贪心选择性质**：存在某个最优解包含「最早结束的活动 a₁」——交换
   论证：任取最优解，把它的第一个活动换成 a₁（结束更早，不与后续冲突），
   规模不减；
2. **最优子结构**：去掉 a₁ 后，剩余问题（sᵢ ≥ f₁ 的活动集）的最优解
   + a₁ = 原问题最优解。

CLRS 图 16.1 的 11 个活动实测（示例 17.1）：贪心选 a1、a4、a8、a11
（共 4 个），并与 DP（区间 DP：c[i,j] = max 1 + c[fᵢ, j]）对账——
4 = 4，两条路同值。**贪心 O(n)（已排序时）vs DP O(n³)**：能证明贪心
正确时，它是降维打击。

注意同一问题加权重就变天：**加权活动选择**（每个活动有收益，最大化
总收益）贪心失效（最早结束≠收益最大），要回到 DP（或按结束排序 +
二分跳转的 O(n lg n) DP）——「贪心正确性是问题属性，不是策略属性」。

## Huffman 编码（§16.3）

**问题**：给字符频率造**前缀码**（任何码不是其他码的前缀——保证解码
无歧义），最小化平均码长。前缀码 ⟺ 二叉树（字符=叶，码=路径）。

**贪心**：每次取频率最小的两棵树合并（引理 16.2/16.3：存在最优前缀码
使频率最小的两个字符是最深的兄弟叶；交换论证把任意最优树整成这个
形状）。用小顶堆，O(n lg n)。

CLRS 图 16.3 频率（a45 b13 c12 d16 e9 f5）实测（示例 17.2）：

```
Huffman（频率 a45 b13 c12 d16 e9 f5）：
  a: 0   b: 101   c: 100   d: 111   e: 1101   f: 1100
  平均码长 = 224/100 = 2.24 位/符号（定长 3 位，压缩比 25%）
  前缀性质（任一码不是其他码的前缀）= 1
```

高频的 a 只花 1 位、低频的 e/f 花 4 位——**频率倾斜越狠收益越大**
（熵 H = 2.14 位是这个分布的理论下界，Huffman 至多多 1 位——
Huffman 最优性的信息论表述）。实现要点：arena 存树 + `priority_queue`
（`std::greater` 反转成小顶，第 6 章坑位 4 的操刀现场）。

## 拟阵：贪心正确性的公理化（§16.5）

**拟阵** M = (S, ℐ)，ℐ 是 S 的「独立集」族，满足：

1. ∅ ∈ ℐ；
2. **遗传性**：A ∈ ℐ 且 B ⊆ A ⇒ B ∈ ℐ；
3. **交换性**：A, B ∈ ℐ 且 |A| < |B| ⇒ 存在 x ∈ B−A 使 A∪{x} ∈ ℐ。

**定理 16.12**：在拟阵上按权重降序贪心（能加就加）得到最大权独立集
——**不需要 DP**。证明骨架：贪心在每一步保持「与某最优解在当前前缀
上等权」（交换性保证替换不亏）。

**单位时间任务调度**（CLRS 16.5）：任务 aᵢ 有期限 dᵢ、收益 wᵢ，每个
时间槽干一件，逾期作废。独立集 = 「能在期限内全部排下」的任务集——
它是拟阵（遗传显然、交换用「晚期限换早期限」论证）。按收益降序贪心，
示例 17.3 实测（7 任务，图 16.19 数据）：

```
拟阵任务调度（按收益降序贪心）：选中 a1 a2 a3 a4 a7 （总收益 230）
```

70+60+50+40+10 = 230（a5 期限 1 已被占、a6 挤不进期限 4 的槽）。
拟阵贪心 O(n²) 起步（独立判定每次重排）——用并查集（第 22 章！）的
「最晚空闲槽」技巧压到 O(n lg n)，两章在这里会师。

**拟阵之外**：很多贪心问题不是拟阵（Kruskal 是「图拟阵」、Huffman 是
拟阵变体），贪心正确性要逐题证明——这就是「贪心是艺术，DP 是工程」
的意思。

## 交换论证：把分配问题归约为选 top-k

前两节的贪心（Huffman、活动选择）都是"直接选"，本节换一个套路：
**先把问题变形，使最优解的结构变得显然，再用一次排序解决**。变形用的
工具是**差值**与**交换论证**。

### 差值化归约

**问题**：n 个朋友，第 i 个有属性 (Xᵢ, Yᵢ)；两种礼物属性 (A₁,B₁)、
(A₂,B₂)，数量 k₁、k₂（k₁ + k₂ ≥ n，礼物可以剩）。每人一件礼物，最大化
总开心值，其中

```
v₁(i) = A₁·Xᵢ + B₁·Yᵢ     拿礼物 1 的开心值
v₂(i) = A₂·Xᵢ + B₂·Yᵢ     拿礼物 2 的开心值
```

**第一步：定义差值**

```
Δᵢ = v₁(i) − v₂(i) = (A₁−A₂)·Xᵢ + (B₁−B₂)·Yᵢ
```

**第二步：写出总开心值**。设 S = 「拿到礼物 1 的人」的集合，则

```
总开心值 = Σ_{i∈S} v₁(i) + Σ_{i∉S} v₂(i)
         = Σ_{i∈S} v₂(i) + Σ_{i∈S} Δᵢ + Σ_{i∉S} v₂(i)     （把 v₁ 拆成 v₂ + Δ）
         = Σ_{all i} v₂(i)  +  Σ_{i∈S} Δᵢ
              ↑ 与 S 无关，是常数
```

**归约完成**：「选 |S| ≤ k₁ 最大化 Σ_{i∈S} Δᵢ」——**选最大的 t 个数**，
t = min(k₁, #{i : Δᵢ > 0})。一趟排序，Θ(n log n)，不需要分组、不需要
二次搬运。

可行性自动满足：n − t ≤ k₂ ⟸ t ≥ n − k₂，而 t = min(k₁, 正 Δ 个数) 时若
正 Δ 个数 ≤ k₁ 则 t = 正 Δ 个数；否则 t = k₁ ≥ n − k₂（用 k₁ + k₂ ≥ n）。
两种情况都成立。

### 交换论证：为什么最优解必取 Δ 最大的 t 个

这是本节的核心证明，套路与活动选择完全一致。

> 设 S 是任一最优解。若存在 i ∈ S、j ∉ S 且 Δᵢ < Δ_j，令 S' =
> (S \ {i}) ∪ {j}，则总开心值的变化是
>
> ```
> [Σ v₂ + Σ_S' Δ] − [Σ v₂ + Σ_S Δ] = Δ_j − Δᵢ > 0
> ```
>
> 与 S 最优矛盾。故最优解中不存在"收了 Δ 小的、放出了 Δ 大的"这种情形
> ⟹ **S 必是 Δ 最大的 t 个元素的集合**。∎

对 Δᵢ ≤ 0 的元素，收入 S 只会让 Σ_S Δ 不增，所以 t 取
min(k₁, 正 Δ 个数) 而非 k₁。

同时注意：**这个交换论证只用到 Δ 的序，从不需要 v₁ 与 v₂ 的绝对值**——
常数项被差值消掉了。

### 错误直觉：搬「开心值最小」的人是错的

一个很自然但**错误**的贪心：先按 v₁ > v₂ 把人分成 S₁/S₂，若 |S₁| > k₁
就把 S₁ 里"礼物 1 开心值最小"的若干人搬到 S₂。

**正确规则是搬 Δ 最小的**，两者不是一回事。原因是 **v₁ 与 Δ 的权重不同，
两个序不同构**：

```
v₁ = A₁·X + B₁·Y     Δ = (A₁−A₂)·X + (B₁−B₂)·Y
```

以 A₁=3, B₁=4, A₂=4, B₂=3 为例：v₁ = 3X + 4Y，Δ = −X + Y。X 的系数
一个是 3、一个是 −1；Y 的系数一个是 4、一个是 1。**权重完全不同**，
"v₁ 小"与"Δ 小"是两个不同的偏序。

**小反例**（示例 17.4 实测）：两人，k₁ = 1

| | X | Y | v₁ | v₂ | Δ |
|---|---|---|---|---|---|
| p1 | 1 | 5 | 23 | 19 | **4** |
| p2 | 3 | 4 | 25 | 24 | **1** |

- 正确解（拿 Δ 大的 p1）：总开心值 = 23 + 24 = **47**
- 错误直觉（搬 v₁ 最小者 = 把 p1 搬走）：总开心值 = 19 + 25 = **44**

搬错了人，损失 3 = Δ_p1 − Δ_p2 = 4 − 1。**更直接的证据**：(0,3) 与
(3,6) 的 Δ 都是 3，但 v₁ 分别是 12 与 33——**Δ 相等时 v₁ 可以差很远**，
所以谈 Δ 时根本不能看 v₁。

第二个错误：**`if (|S₁| > k₁) … else if (|S₂| > k₂) …` 的分支结构漏处理**。
当 k₁ + k₂ ≥ n 时两侧可能**同时**超限（n = 3、k₁ = k₂ = 1、三人的 Δ 全
为正：移 2 人到 S₂ 后 |S₂| = 2 > k₂，但 `else if` 不执行）。正确解法根本
不需要分组，也就没有这个问题。

### 与本节其余部分的联系

差值化是一个通用套路：**凡是"二选一分配/指派"型问题，先算差值**。
第 24 章的最小生成树、第 26 章的指派问题、第 27 章的 max-flow 都能看到
它的影子——把所有方案按某个"基准 + 增量"分解，问题就退化成"选若干个最大
增量"，而这正是贪心最擅长的形态。

## 稳定匹配：Gale-Shapley 与拒绝不动点论证

第二个范本：**贪心 + 交换论证**的又一实例，但它比活动选择更难——因为
"局部最优"涉及**两个人**的偏好，必须证明全局最优解不会因此被破坏。

**问题**：n 男 n 女，各自给出对异性的**完整**偏好序。找**稳定完美匹配**：
没有"阻塞对"（blocking pair，即 (m, w) 互相更偏好对方而非自己的配对），
且每人恰好配一人。求**男性最优**（man-optimal）的那个。

### 算法

Gale-Shapley（"男求婚"版）：

1. 所有男生都是自由身，进入**自由男队列**；
2. 队首男生 m 向 his-list 里还没求过的第一位 w **求婚**；
3. w 若自由 ⟹ 接受，m 订婚；
   w 若已有未婚夫且**更喜欢 m** ⟹ 接受 m 并解除原婚约（原丈夫重新入队）；
   否则 ⟹ 拒绝 m；
4. 队列空 ⟹ 结束。

**关键实现点：内层判定必须 O(1)**。w 要做的判断只是"m 比我现在的丈夫
更好吗"，用一张 `rank[w][m]`（w 眼中 m 的名次，越小越好）比较即可：

```cpp
// rank[w][m] < worstRank[w] ⟹ w 更想要 m
```

`worstRank[w]` = w 当前丈夫的 rank。配上一个只前进不后退的提案游标
`nextIdx[m]`，每次求婚 O(1)，总提案次数 ≤ n² ⟹ **总复杂度 Θ(n²)**。

**如果用 BST 存婚约集合**（为了输出时有序），内层操作变成 O(lg n)，总
复杂度 **Θ(n² lg n)**——多带一个 lg n。n 小的时候无所谓，但这是"数据结构
选型影响复杂度量级"的干净例子。

### 四个引理

#### 引理 1（终止性）

每个男最多提 n 次婚（游标只前进），故总提案 ≤ n²。每次提案要么发生一次
接受（配对数 +1），要么被拒（男生重新入队）。接受最多 n 次，队列长度有界
⟹ 算法有限步内结束。∎

#### 引理 2（完美性：结束时人人有伴）

关键观察：**一旦某个女生接受求婚，她永远不会再变成自由身**（只会换人，
换的只会是更喜欢的）。所以「已订婚的女生集合」是**单调不减**的。

设算法结束时男生 m 仍未配对。则 m 的提案游标已走完 his-list，即他向
**全部 n 个女生**求过婚且**全被拒**。每次被拒都意味着"该女生当时已有
丈夫"⟹ n 个女生**都曾订过婚**⟹ 由单调性，结束时 n 个女生**仍然全部订婚**
⟹ 已有 n 对 ⟹ 男生全部配对，与 m 未配对矛盾。∎

（这个证明比"由对称性不可能"这类说法干净：它只用"接受后不回到自由"这一
条单调性。）

#### 引理 3（稳定性：拒绝不动点论证）

设最终匹配 M 不稳定，则存在阻塞对 (m, w')：m 更偏好 w'，且 w' 更偏好 m。

m 一定向 w' 求过婚（否则 w' 的丈夫无从"更差"）。m 的求婚顺序由 his-list
决定，设 m 是先向 w 求婚被拒、之后才向 w' 求婚的。w 拒绝 m 意味着当时 w
已与某位 w₀ 订婚且

```
rank[w][w₀] < rank[w][m]        （w 更喜欢 w₀）
```

**不动点论证**：由引理 2 的单调性，w 的丈夫序列沿 rank **严格递减**（只
接受更喜欢的），故最终丈夫 w* 满足

```
rank[w][w*] ≤ rank[w][w₀] < rank[w][m]
```

即 w* 比 m 更受 w 喜欢。这与"w' = w 更偏好 m"矛盾。∎

证明的骨架是**"拒绝的单调性"**：一旦拒绝了谁，就再也不会比被拒的那个更差。
这条骨架在近似算法与在线算法里反复出现（第 36 章）。

#### 引理 4（男性最优性）

Gale-Shapley 求出的是**所有**稳定匹配中**对每个男人都最好**的那个。

**证明骨架**是对称归纳，两个子句必须同时成立：

- **(P)** 对每个男生 m：他在 M 中的妻子**不劣于**他在任何稳定匹配中的妻子；
- **(Q)** 对每个女生 w：她在 B 中的丈夫**不劣于**她在 M 中的丈夫。

（P 与 (Q) 合起来正是"男最优 / 女最优"的严格版本；注意 Q 的方向是**反
的**——GS 让男的最优必然让女的最劣，这正是本例两个版本给出不同匹配的原因。）

归纳沿**提案步数**推进，核心的一步来自引理 3 的同一个单调性：

> 若 m 向 w 求婚被拒，则由"接受后只换更喜欢的"，**w 在 M 中的丈夫一定
> 比 m 更受 w 偏好**。把这条代入稳定匹配 B 的稳定性要求（否则 (m, w) 或
> (M(w), w) 之一必成阻塞对），就迫使 (P) 对 m 成立；对 w 施加 (Q) 的对称
> 版本，闭合成对 m 的归纳。∎

完整的两子句对称归纳见 Gale–Shapley 原论文；这里强调的是它的**结构**：
与引理 3 同源的"拒绝单调性"，只是要多跑一层**关于女生的对称归纳**才能
闭合成环——这正是"男性最优"比"稳定"难证明的地方。

**可执行的证明**（本示例采用）：n 小时枚举比归纳更有说服力，因为它检验
**全部情形**而不是一条论证链。示例 17.5 枚举全部 n! 个完美匹配，筛出
所有稳定匹配，再检查其中没有任何一个能让某个男更满意：

- n = 4 时 4! = 24 个完美匹配中恰有 **2 个**稳定匹配；
- Gale-Shapley 算出的那个在两者中对每个男人都**不差** ⟹ (P) 成立。

同时验证另外两个引理：配对数 = n（引理 2），阻塞对数 = 0（引理 3）。∎

### 为什么它与第 36 章相通

Gale-Shapley 是"贪心 + 交换论证"的又一范本，但它的独特之处是**贪心的
正确性不靠"局部最优可扩展"，而靠"拒绝的单调性"**：

- 活动选择：交换论证（把最优解的某个元素换成贪心选的，不亏）；
- Huffman：交换论证 + 归纳（最小的两个必为最深兄弟叶）；
- Gale-Shapley：**不动点**（拒绝集单调收缩 ⟹ 稳定）+ **归纳**（最早被拒的
  女生在任何稳定匹配里都不会更差）。

「拒绝/丢弃的单调性」这套论证骨架正是**近似算法**（第 36 章贪心近似
的可行性证明）与**在线算法**的核心直觉：无法撤销的决策必须靠"已排除的
选项不会在将来变好"来保证正确。Gale-Shapley 甚至可以看作一个**在线**
算法——提案一旦被拒就永不回头。

### 与本节其余部分的联系

- 「男提议」得到**男最优**稳定匹配；「女提议」得到**女最优**稳定匹配。
  两者不同时存在（示例 17.5 实测两版给出不同匹配），**都不唯一**这件事
  本身就是稳定匹配理论的重要结论：稳定匹配可以有多于一个。
- 有偏好不完整（只有部分女生可接受）时，问题变成**带 capacities 的医院
  住院医分配**（第 35 章 NP 完全性里会重新出现），Gale-Shapley 失效。

实测（示例 17.4 / 17.5）：

```text

  编号   X   Y    v₁    v₂    Δ
   p1    1   4    19    16     3
   p2    3   5    29    27     2
   p3    5   3    27    29    -2
   p4    2   6    30    26     4
  常数项 Σv₂ = 98（与 S 无关）
  按 Δ 降序取 top-3：拿礼物 1 的是 p4、1、2，总开心值 = 107 = Σv₂ + Σ_S Δ = 98 + 9
  暴力枚举 2^4 个分配的最大值 = 107（对账一致 = 1）
  错误直觉反例：两人 (1,5) 与 (3,4)，k₁ = 1
    p1 = (1,5)：v₁ = 23，Δ = 4    p2 = (3,4)：v₁ = 25，Δ = 1
    正确（按 Δ 最大拿礼物 1 = p1）总开心值 = 47；错误直觉（搬 v₁ 最小者 = p1）= 44
    ⟹ 「搬 v₁ 最小者」搬错了人：v₁ 与 Δ 的权重不同（v₁ 中 X、Y 系数为 3、4；Δ 中为 −1、1），两个序不同构
    佐证：(0,3) 与 (3,6) 的 Δ 都是 3，但 v₁ 分别是 12 与 33 ⟹ 谈 Δ 时不能看 v₁
  else-if 漏处理：3 人 Δ 全为正，k₁ = k₂ = 1（两侧同时超限）⟹ 正确答案 = 52（1 人拿礼物 1）
=== 17.5 稳定匹配：Gale-Shapley（内层 O(1) ⟹ Θ(n²)）===
  n = 4，男生按提案顺序依次尝试
  男 m0..m3 的偏好 = [w3 w1 w0 w2] [w2 w1 w0 w3] [w2 w0 w1 w3] [w1 w0 w2 w3]
  匹配（本例男方提议所得）: m0→w3 m1→w1 m2→w2 m3→w0 
  总提案次数 = 6（最坏 n² = 16，每次内层 O(1) ⟹ 总 Θ(n²)）
  引理「完美性」：匹配边数 = 4 = n，全部人均已配对 = 1
  引理「稳定性」：遍历全部 4×4 = 16 对（m, w），阻塞对（互相更偏好）数 = 0
  引理「男性最优」：枚举全部 n! = 4 个完美匹配，稳定匹配共 2 个，其中没有任何一个能让某个男更满意 = 1
  对账：女方提议版（= 女性最优稳定匹配）: m0→w3 m1→w1 m2→w0 m3→w2 
  两版相同 = 0（本例不同 ⟹ 男最优与女最优是**两个不同的稳定匹配**，Gale-Shapley 只会算出男最优那个）
```

## C++23 语言点

- `std::priority_queue<pair<int,int>, vector<...>, std::greater<...>>`
  小顶堆的正确姿势（第 6 章坑位的现场应用）；
- `std::ranges::sort(tasks, std::ranges::greater{}, &Task::weight)`：
  投影 + 比较器一次到位的降序排序（C++20 ranges，投影参数在 C++23
  语境下属于日常工具）；
- 递归 DFS 用 `std::function<void(int,string)>`（编码生成；对拍第 16 章
  的显式对象形参写法）。

## 与 STL 对照

- 无 `std::huffman`；压缩库（zlib 的 deflate 用 LZ77+Huffman）是工业级
  实现——变长码 + 滑动窗口；
- 活动选择 = 区间调度的无权版；带权版就是「会议室安排」类面试题的
  正统 DP；
- `std::priority_queue` 直接实现 Huffman 的堆步骤（本例）与 Dijkstra
  （第 25 章）。

## 坑位清单

1. **贪心策略没有证明就上**
   （现象：小样例全对、上线后大案例错；原因：贪心正确性是定理不是
   直觉——最早开始/最短时长/最少冲突三种活动选择贪心都有反例，只有
   「最早结束」对；后果：算法性错误难以用测试兜底；对策：写出贪心
   选择性质的交换论证，写不出就换 DP——并用小规模 DP 对账测试
   （示例 17.1 的做法）。）
2. **ranges::sort 投影忘了比较器方向**
   （现象：按权重「降序」实际升序，贪心选反；原因：
   `sort(tasks, {}, &Task::weight)` 默认 less 升序——降序要显式
   `std::ranges::greater{}`；后果：拟阵贪心选成最小权集；对策：排序后
   打印前三个元素断言方向（本例实测翻车后补的比较器）。）
3. **Huffman 堆用成大顶**
   （现象：生成的码完全「反频率」（高频 4 位、低频 1 位），平均码长
   反而变大；原因：`priority_queue` 默认 `less` = 大顶；后果：压缩变
   膨胀；对策：`std::greater` 模板参，与第 6 章坑位同源。）
4. **前缀码验证跳过**
   （现象：编码能编码不能唯一解码；原因：手工/变长的码表可能违反
   前缀性质而 Huffman 算法本身保证——手写码表没有这个保证；后果：
   解码歧义；对策：双循环前缀检查（示例的 prefixFree 断言）。）
5. **独立判定用「逐个塞最早槽」而不排序**
   （现象：把任务按「先来先服务」塞槽，明明可排的集合判成不可排；
   原因：独立判定要按**期限排序**后贪心（EDF）才正确；后果：贪心把
   独立集错杀，解次优；对策：判定函数先 sort 再逐槽，复杂度无所谓
   （不是热点路径）。）
6. **错误直觉：分配超限时搬「开心值最小」的人**
   （现象：礼物分配答案偏小；原因：v₁ = A₁X+B₁Y 与 Δ = (A₁−A₂)X+(B₁−B₂)Y
   **权重不同**，两个序不同构——搬 v₁ 最小者并不等于搬 Δ 最小者；小反例
   （A₁=3,B₁=4,A₂=4,B₂=3）：(1,5) 的 v₁=23、Δ=4，(3,4) 的 v₁=25、Δ=1，
   k₁=1 时正确解 47、错误直觉 44；更直接的证据是 (0,3) 与 (3,6) 的 Δ
   都是 3 而 v₁ 分别是 12 与 33；后果：系统性搬错人；对策：先算 Δ 再按
   Δ 排序取 top-k，并用 2ⁿ 暴力枚举对账（示例 17.4）。）
7. **错误直觉：`if (|S₁| > k₁) … else if (|S₂| > k₂) …` 的单侧处理**
   （现象：两侧同时超限时答案错；原因：k₁+k₂ ≥ n 时两侧可能同时超限
   （n=3、k₁=k₂=1、三人 Δ 全为正：移 2 人过去后 |S₂|=2 > k₂，但
   `else if` 不执行）；后果：漏掉第二次调整；对策：归约成"选 top-k Δ"后
   根本不需要分组，问题自动消失——这也是差值化归约的价值。）
8. **稳定匹配用 `|=`/max 累积 `worstRank`，或漏掉被甩掉的一方**
   （现象：匹配结果不是稳定匹配，或答案错；原因两处：① 女生接受 m 后
   `worstRank[w]` 必须**直接赋值** rm，取 max 累积的是"她历史上收到过
   的最差 rank"，被甩掉的旧丈夫不再占位 ⟹ 累积值偏大 ⟹ 后来的**更差**
   的人被误判为"比当前丈夫好"而顶替之；② 自由男队列里被顶替的男生必须
   **重新入队**继续提案，漏掉则他永远配不上；后果：得到的匹配不满足
   稳定性/最优性；对策：每个接受都写 `husband[w] = m; worstRank[w] = rm;`
   并把旧丈夫 push 回队列，然后用「枚举 n! 个完美匹配 + 数阻塞对」验证
   ——本例首版两处都实测翻车。）
9. **rank 表的下标方向搞反**
   （现象：`rankOf(w, wife[w])` 一类写法把**女**下标拿去查**男**排名表，
   越界或错位，阻塞对数算出来是 0 却什么都没验证；后果：稳定性检查变成
   空转，看起来"通过"实则无效（最危险的一种错：断言全绿）；对策：
   `rank[w][m]` 的两个下标分别是女、男，查"w 自己的丈夫"必须用
   `husband[w]` 而不是 `wife[w]`；验证手段：故意构造一个已知有阻塞对的
   匹配，确认检查确实报非零（本例首版实测翻车。）
10. **`manPrefers(m, w, w')` 写成"扫到 w 就 true"**
    （现象：w 与 w' 相同时返回 true，把"完全相同"误判成"更偏好"；
    原因：`for (k) { if (p[k]==w1) return true; if (p[k]==w2) return
    false; }` 在 w1 == w2 时先命中 w1 分支；后果：男性最优性的枚举检查
    出现假阳性（把自己判成"更好"），断言失败；对策：直接返回名次比较
    `rankOfMan(m, w1) < rankOfMan(m, w2)`，并对同一 w 单独测（本例首版
    实测翻车。）
11. **误以为"稳定匹配唯一"**
    （现象：把 Gale-Shapley 的输出当唯一答案写进文档；原因：稳定匹配
    可以有多于一个（示例 17.5 的 n=4 就有 2 个），男提议给男最优、女
    提议给女最优；后果：误判"换个性别提议结果应该一样"；对策：明确
    算法给的是**男最优**那一个；需要"任选一个稳定匹配"时要额外说明。）
