# 09 · 中位数与顺序统计量

> 对应 CLRS 第 9 章 *Medians and Order Statistics*（英文 3rd ed. pp.213–227）。
> **第 i 顺序统计量**＝集合中第 i 小的元素。排序当然能解（Θ(n lg n)），但
> 「只取一个名次」理应更快——本章给出期望线性（随机化）与确定性线性
>（BFPRT）两条路，全部长在快排的分区骨架上。

## 学习目标

1. 会用成对比较同时取最小最大（3⌊n/2⌋ 次比较）；
2. 能推 RANDOMIZED-SELECT 的期望 T(n) ≤ 4n，并说清它与快排分析的差异；
3. 能完整陈述 BFPRT 的三步与递归式 T(n) = T(n/5) + T(7n/10+6) + Θ(n)；
4. 会解释「为什么每组 5 个」——3 个不行、7 个也行，常数不同；
5. 知道 `std::nth_element` 的工程定位；
6. 会用天平三结果把候选集切成**三份**：信息论下界 ⌈log₃ n⌉ 与三分最优；
7. 会对「是/否」问答做范围中点二分：最坏 ⌈log₂(n+1)⌉，并讲清它与
   09.4 天平问题为何底数不同（2 结局 vs 3 结局）。

## 同时取最小与最大（§9.1）

朴素做法每个元素与 min、max 各比一次：2(n−1)。**成对处理**：两两互比
（1 次），小者只挑战 min、大者只挑战 max（2 次）——每两个元素 3 次比较：

- n 偶数：3n/2 − 2 次；n 奇数：3(n−1)/2 次（统一界 3⌊n/2⌋）。

实测（示例 09.1，n=101）：朴素 200 次 vs 成对 **150 次**，恰等于精确值。
「一次比较买两个信息」是本章反复出现的主题。

## 期望线性选择：RANDOMIZED-SELECT（§9.2）

快排分区后**只递归一侧**（i == q 命中返回；否则进含 i 的那半）：

```clrs
RANDOMIZED-SELECT(A, p, r, i)
1  if p == r return A[p]
2  q = RANDOMIZED-PARTITION(A, p, r)
3  k = q - p + 1                 // q 是本段第 k 小
4  if i == k return A[q]
5  elseif i < k return RANDOMIZED-SELECT(A, p, q-1, i)
6  else return RANDOMIZED-SELECT(A, q+1, r, i-k)
```

**期望分析**（为什么是线性而快排是 n lg n）：快排两半**都要**递归，每层
成本 cn，共 lg n 层；这里只递归**一侧**，期望规模每次乘 ≤ 某个 < 1 的
因子——CLRS 用指示器算出 E[T(n)] ≤ 4n（把「分区 ≥ n/4 的概率 ≥ 1/2」
的分摊算进去）。最坏仍是 Θ(n²)（分区恒 (0, n−1)），期望的把戏与第 7 章
同源：随机化把「输入的最坏」变成「硬币的最坏」，而硬币的期望可控。

实测（示例 09.2）：n=1001 找中位数，单次 3511 次比较（≤ 4n = 4004 ✓）；
100 个固定种子的经验分布：平均 3267、最少 1691、最多 6253——均值安静地
待在 4n 内，尾部偶有超标但概率被期望兜住。

## 确定性线性：BFPRT（§9.3，中位数的中位数）

随机化的尾巴（最坏 Θ(n²)）能不能剪掉？**BFPRT**（Blum–Floyd–Pratt–
Rivest–Tarjan, 1973）用一个**精心设计的确定性主元**做到了：

1. 把 n 个元素 ⌈n/5⌉ 组、每组 5 个，插入排序取**组内中位数** → Θ(n)；
2. 递归求这些中位数的**中位数 x** → T(n/5)；
3. 以 x 为轴分区，只递归含目标名次的一侧。

**为什么 x 足够好**：⌈n/5⌉ 个组中位数里，至少一半 ≥ x；这些组里每组
又有 3 个元素 ≥ 本组中位数 ≥ x——所以 **≥ 3n/10 − 6 个元素 ≥ x**，
对称地 ≤ 3n/10 − 6 个元素 ≤ x。递归侧规模 ≤ 7n/10 + 6：

```
T(n) = T(n/5) + T(7n/10 + 6) + Θ(n) = Θ(n)
```

（代入法验证：猜 T(n) ≤ cn，右端 c·n/5 + c·7n/10 + an ≤ cn 当
c ≥ 20a——两项系数和 9/10 < 1 是收敛的全部理由。）

**为什么每组 5**：组大小 g 的一侧保证是 (3g−…)/4 比例，递归式系数
1/g + 3/(4·(g−…)) 必须小于 1——g=3 时恰好卡到 1（不收敛），g=5 时
0.2 + 0.7 = 0.9 < 1 ✓，g=7 更快收敛但组内排序常数变大。5 是让
「取中位数的中位数」这件事本身严格便宜的最小组。

示例 09.3 的实测（n=10001）：比较 89684 次，**比值 8.97n**——线性，但
常数近 9。这暴露了 BFPRT 的工程真相：理论 Θ(n) 赢在渐近，常数却让它在
n < 数十万时跑不过 `std::nth_element`（快排式选择 + 深度保险）。确定性
线性的价值在于**最坏情形保证**（实时系统、对抗性输入）。

分组可视化（15 个数、3 组，示例打印）：

```
BFPRT 分组示例：15 个数按 5 一组，组内中位数 6、7、10；中位数的中位数 = 7
```

## 找坏蛋：天平上的修剪与搜索（09.4）

n 颗蛋里恰有一颗**偏轻**的坏蛋，工具是一架天平——每次称量有**三种**
结果：左盘轻、右盘轻、平衡。目标是最坏情况下称量次数最少。这正是
「修剪与搜索」的小型剧场：每次称量把候选集切小，直到剩一颗。

**书式对半策略**。候选 s 颗时，左右各放 a=⌊s/2⌋ 颗，余 s−2a（0 或 1）：

- 左盘轻 → 坏蛋在左盘（a 颗）；右盘轻 → 在右盘（a 颗）；
- 平衡 → 坏蛋在**没上秤**的余数里（s−2a 颗）。

最坏递推 H(s) = 1 + H(⌊s/2⌋)（余数至多 1 颗，不会是最坏支），解出
**H(n) = ⌊log₂ n⌋**。

**三分策略**。天平一次给出三结果，为什么只切两份？取 a=⌈(s−1)/3⌉
（代码写 (s+1)/3），分成 a、a、s−2a 三份，两盘各称一份：倾斜时坏蛋
在轻盘那份，平衡时在第三份。三份尽量等大，最坏递推

T(s) = 1 + T(max(a, s−2a)) ⟹ **T(n) = ⌈log₃ n⌉**。

实测 n=10、坏蛋在第 8 颗：对半要 3 次（10→5→2→1），三分只要 2 次
（10→4→1）。

**信息论下界：三分为什么是最优的**。k 次称量每次 3 种结果，总共至多
产生 3ᵏ 种可区分的结局；坏蛋有 n 个可能位置——要全部分辨，必须
3ᵏ ≥ n，即 **k ≥ ⌈log₃ n⌉**。三分策略恰好达到这个下界，所以它不只是
「比对半好」，而是**最优**。对半策略只利用了「左/右」两种结局，浪费了
「平衡」携带的信息——每次称量只买 1 比特而非 log₂ 3 ≈ 1.585 比特。

实测还有个细腻处：n=5、坏蛋恰是没上秤的那颗时，对半法 2v2 一次平衡
即锁定——**只要 1 次**，少于最坏值 ⌊log₂ 5⌋=2。最坏计数是「对位置取
最大」，单个位置的实际次数可以更少：示例对每个 n 穷举全部坏蛋位置，
逐例只断言「实际 ≤ 最坏闭式」，再断言「最坏位置上的计数恰等于闭式」。

n=10¹⁸ 的大例：对半最坏 59 次，三分最坏 38 次——差距随 n 拉开
（log₃ n = log₂ n / log₂ 3 ≈ 0.63·log₂ n）。

## 猜数字：范围中点二分（09.5）

主持人在 **1..n** 中选定一个整数，你每次报一个数 g，对方只回答
「大了」或「小了」（猜中即停）。这是 09.4 的姊妹题，但注意结局数
变了：「我的数 ≤ g 吗」只有**两种**答案——每次提问只买 1 比特。

**中点策略**。维护候选区间 [lo, hi]，每次猜区间中点

```
g = lo + (hi − lo) / 2          // 向零取整：偏左中点
```

g 偏小则 lo = g+1，偏大则 hi = g−1，猜中结束。每问一次，新区间长度
至多 ⌊旧长度/2⌋——最坏次数不是 ⌊log₂ n⌋，而是

```
⌈log₂(n+1)⌉
```

**为什么是 n+1**。深度 k 的二叉判定树至多有 2ᵏ−1 个节点，n 个数都
要能停在某个节点上 ⟹ 2ᵏ−1 ≥ n ⟹ k ≥ ⌈log₂(n+1)⌉。边界值得亲手
验算：n=63 时最坏 6 次（2⁶−1=63 恰好），n=64 就得 7 次——用
⌊log₂ n⌋ 会在所有 2ᵏ 边界上少算 1。中点策略在每次回答后把区间切成
「⌊(s−1)/2⌋ 与 ⌈(s−1)/2⌉」两份，最大份恰为 ⌈s/2⌉−1，递推恰好
取到下界，所以它**最优**。

实测 n=100、目标 27 的完整问答：50 → 25 → 37 → 31 → 28 → 26 → 27，
**7 次**——27 恰好落在最坏位置。n=100 的全目标平均 5.8 次、最坏 7 次
（⌈log₂101⌉=7）。小表对照：

```
n:      1    2    3    4    5    6    7    8
最坏:   1    2    2    3    3    3    3    4
```

n=10¹⁸ 的大例：最坏 60 次；角落目标 10¹⁸ 实际也是 60 次。60 次
回答分辨 10¹⁸ 个数——这就是「1 比特/问」在 60 层里买到的分辨率。

**与 09.4 的对照**：天平一次三结果 ⟹ 底数 3；是/否问题两结果 ⟹
底数 2。n=10¹⁸ 时 38 次 vs 60 次，差距完全来自单次提问的结局数。
两个下界是同一句话：**k 次提问至多分辨 bᵏ 种结局，b = 结局数**。

- 递归 + 计数器引用穿透（老朋友）；

## 与 STL 对照

`std::ranges::nth_element(first, nth, last)`：平均 Θ(n) 的选择（introselect
——随机/三点取中 + 深度超限时退化到 BFPRT 或堆策略，实现各异）。它**就是**
本章内容的工程化身：期望线性 + 尾部保险。实测选型：

| 场景 | 选择 |
|---|---|
| 只要第 k 小 / 前 k 个 | `nth_element` / `partial_sort` |
| 要最坏保证（对抗输入） | 手写 BFPRT |
| 顺便要全序 | 老老实实 `sort` |

## 坑位清单

1. **成对 min-max 的公式记岔**
   （现象：对奇数 n 断言 3⌈n/2⌉−2 失败；原因：精确值是 n 偶 → 3n/2−2、
   n 奇 → 3(n−1)/2，统一界才是 3⌊n/2⌋；后果：示例 assert 误报「实现
   有 bug」；对策：奇偶分开算精确值，或统一用 ≤ 3⌊n/2⌋ 的弱断言——本例
   实测翻车后改的写法。）
2. **分区的「≤」把相等元素全堆一侧**
   （现象：多重复值输入下选择退化为 Θ(n²)；原因：与第 7 章同病——
   Lomuto 分区对重复值失衡；后果：期望 4n 的前提被破坏；对策：分区后
   断言递归侧 ≤ 7n/10 + 6（BFPRT 天然免疫，因为主元保证两侧配额）。）
3. **BFPRT 的组内取「任意元素」而非中位数**
   （现象：递归式不成立，最坏回到 Θ(n²)；原因：两侧 ≥ 3n/10 的保证依赖
   「x 是中位数的中位数」——取组内任意元素则 x 可能极端；后果：确定性
   线性的证明整体失效；对策：组内必须精确取中位数（≤5 个元素插入排序
   取中位，最坏 6 次比较——练习 9.3-1 让你做出来）。）
4. **RANDOMIZED-SELECT 递归两侧**
   （现象：跑出了 Θ(n lg n) 甚至 Θ(n²)，与快排无异；原因：手滑写成快排
   的双递归；后果：渐进退化；对策：单侧递归是选择的本质——另一侧**直接
   扔掉**，写完检查「每个分支恰好一个递归调用」。）
5. **对半法奇数规模时更新候选集写错**
   （现象：n=5 倾斜后候选变成 3 而非 2，后续计数全乱；原因：倾斜时候选
   是秤盘上的 a 颗，与总数奇偶无关——若手滑写成 s−a 就把余数也带进来；
   对策：更新式 s = 平衡 ? s−2a : a，两个分支都实测对账（本例翻车后
   改的写法）。）
6. **把「最坏次数」断言到每个坏蛋位置上**
   （现象：n=5、坏蛋在余数里时 1 次称出，断言「实际 == ⌊log₂ n⌋」炸；
   原因：最坏值是对位置取的最大值，余数位置天然更便宜；对策：逐位置
   断言 ≤ 闭式，另记每 n 的最坏位置断言 == 闭式——本例实测的双层写法。）
7. **三分分组不等大却以为是 log₃ n**
   （现象：按 a=⌊s/3⌋ 分，s=8 时三份 2,2,4，最坏链 8→4→2→1 要 3 次
   超过 ⌈log₃ 8⌉=2；原因：最大份 4 > ⌈8/3⌉=3；对策：a=⌈(s−1)/3⌉
   让最大份恰为 ⌈s/3⌉，下界才能被取到。）
8. **最坏次数写成 ⌊log₂ n⌋**
   （现象：n=64 时断言最坏 6 次失败，实际 7 次；原因：深度 k 的二叉
   判定树容纳 2ᵏ−1 个键而非 2ᵏ 个——正确闭式 ⌈log₂(n+1)⌉，在每个
   n=2ᵏ 边界上朴素 log 都少算 1；对策：本例用「逐次倍增 p 直到 p ≥ n+1」
   的整数循环计数，不依赖浮点 log 的取整。）
9. **中点写成 (lo+hi)/2 溢出**
   （现象：int 区间接近 2×10⁹ 时 lo+hi 溢出成负数，中点跑出区间；
   原因：两数之和先于除法发生；对策：lo + (hi−lo)/2——差值不溢出，
   本例 n=10¹⁸ 全程只用这个形式。）
10. **更新边界忘记 ±1**
    （现象：目标不在区间时循环退不出，或在边界目标上死循环；原因：
    g 已经被回答排除，新边界必须是 g−1 / g+1——写成 hi=g 时区间永远
    至少含 g；对策：写完核对「每次迭代 hi−lo 严格缩小」，并对 n=1
    与角落目标 1、n 各跑一遍。）
11. **把追踪问答序列当成「随便写」的常量**
    （现象：断言「目标 27 六次猜中」失败，实际序列 50,25,**37**,31,
    28,26,27 共 7 次；原因：偏左中点在第三问给出 37 而非心算的 38，
    且 27 恰是最坏位置；对策：追踪序列必须让程序自己打印，断言照
    实际输出写——本例实测翻车后改的写法。）
