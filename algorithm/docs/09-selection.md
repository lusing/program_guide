# 09 · 中位数与顺序统计量

> 对应 CLRS 第 9 章 *Medians and Order Statistics*（英文 3rd ed. pp.213–227）。
> **第 i 顺序统计量**＝集合中第 i 小的元素。排序当然能解（Θ(n lg n)），但
> 「只取一个名次」理应更快——本章给出期望线性（随机化）与确定性线性
>（BFPRT）两条路，全部长在快排的分区骨架上。

## 学习目标

1. 会用成对比较同时取最小最大（3⌊n/2⌋ 次比较）；
2. 能推 RANDOMIZED-SELECT 的期望 T(n) ≤ 4n，并说清它与快排分析的差异；
3. 能完整陈述 BFPRT 的三步与递归式 T(n) = T(n/5) + T(7n/10+6) + Θ(n)；
4. 会解释「为什么每组 5 个」——3 个不行、7 个也行，常数不同；
5. 知道 `std::nth_element` 的工程定位。

## 同时取最小与最大（§9.1）

朴素做法每个元素与 min、max 各比一次：2(n−1)。**成对处理**：两两互比
（1 次），小者只挑战 min、大者只挑战 max（2 次）——每两个元素 3 次比较：

- n 偶数：3n/2 − 2 次；n 奇数：3(n−1)/2 次（统一界 3⌊n/2⌋）。

实测（示例 09.1，n=101）：朴素 200 次 vs 成对 **150 次**，恰等于精确值。
「一次比较买两个信息」是本章反复出现的主题。

## 期望线性选择：RANDOMIZED-SELECT（§9.2）

快排分区后**只递归一侧**（i == q 命中返回；否则进含 i 的那半）：

```clrs
RANDOMIZED-SELECT(A, p, r, i)
1  if p == r return A[p]
2  q = RANDOMIZED-PARTITION(A, p, r)
3  k = q - p + 1                 // q 是本段第 k 小
4  if i == k return A[q]
5  elseif i < k return RANDOMIZED-SELECT(A, p, q-1, i)
6  else return RANDOMIZED-SELECT(A, q+1, r, i-k)
```

**期望分析**（为什么是线性而快排是 n lg n）：快排两半**都要**递归，每层
成本 cn，共 lg n 层；这里只递归**一侧**，期望规模每次乘 ≤ 某个 < 1 的
因子——CLRS 用指示器算出 E[T(n)] ≤ 4n（把「分区 ≥ n/4 的概率 ≥ 1/2」
的分摊算进去）。最坏仍是 Θ(n²)（分区恒 (0, n−1)），期望的把戏与第 7 章
同源：随机化把「输入的最坏」变成「硬币的最坏」，而硬币的期望可控。

实测（示例 09.2）：n=1001 找中位数，单次 3511 次比较（≤ 4n = 4004 ✓）；
100 个固定种子的经验分布：平均 3267、最少 1691、最多 6253——均值安静地
待在 4n 内，尾部偶有超标但概率被期望兜住。

## 确定性线性：BFPRT（§9.3，中位数的中位数）

随机化的尾巴（最坏 Θ(n²)）能不能剪掉？**BFPRT**（Blum–Floyd–Pratt–
Rivest–Tarjan, 1973）用一个**精心设计的确定性主元**做到了：

1. 把 n 个元素 ⌈n/5⌉ 组、每组 5 个，插入排序取**组内中位数** → Θ(n)；
2. 递归求这些中位数的**中位数 x** → T(n/5)；
3. 以 x 为轴分区，只递归含目标名次的一侧。

**为什么 x 足够好**：⌈n/5⌉ 个组中位数里，至少一半 ≥ x；这些组里每组
又有 3 个元素 ≥ 本组中位数 ≥ x——所以 **≥ 3n/10 − 6 个元素 ≥ x**，
对称地 ≤ 3n/10 − 6 个元素 ≤ x。递归侧规模 ≤ 7n/10 + 6：

```
T(n) = T(n/5) + T(7n/10 + 6) + Θ(n) = Θ(n)
```

（代入法验证：猜 T(n) ≤ cn，右端 c·n/5 + c·7n/10 + an ≤ cn 当
c ≥ 20a——两项系数和 9/10 < 1 是收敛的全部理由。）

**为什么每组 5**：组大小 g 的一侧保证是 (3g−…)/4 比例，递归式系数
1/g + 3/(4·(g−…)) 必须小于 1——g=3 时恰好卡到 1（不收敛），g=5 时
0.2 + 0.7 = 0.9 < 1 ✓，g=7 更快收敛但组内排序常数变大。5 是让
「取中位数的中位数」这件事本身严格便宜的最小组。

示例 09.3 的实测（n=10001）：比较 89684 次，**比值 8.97n**——线性，但
常数近 9。这暴露了 BFPRT 的工程真相：理论 Θ(n) 赢在渐近，常数却让它在
n < 数十万时跑不过 `std::nth_element`（快排式选择 + 深度保险）。确定性
线性的价值在于**最坏情形保证**（实时系统、对抗性输入）。

分组可视化（15 个数、3 组，示例打印）：

```
BFPRT 分组示例：15 个数按 5 一组，组内中位数 6、7、10；中位数的中位数 = 7
```

## C++23 语言点

- 递归 + 计数器引用穿透（老朋友）；
- `std::span` 子区间递归只递归一侧——与快排共享 `partition_at` 骨架，
  一份分区代码服务第 7/9 两章（复用的样板）。

## 与 STL 对照

`std::ranges::nth_element(first, nth, last)`：平均 Θ(n) 的选择（introselect
——随机/三点取中 + 深度超限时退化到 BFPRT 或堆策略，实现各异）。它**就是**
本章内容的工程化身：期望线性 + 尾部保险。实测选型：

| 场景 | 选择 |
|---|---|
| 只要第 k 小 / 前 k 个 | `nth_element` / `partial_sort` |
| 要最坏保证（对抗输入） | 手写 BFPRT |
| 顺便要全序 | 老老实实 `sort` |

## 坑位清单

1. **成对 min-max 的公式记岔**
   （现象：对奇数 n 断言 3⌈n/2⌉−2 失败；原因：精确值是 n 偶 → 3n/2−2、
   n 奇 → 3(n−1)/2，统一界才是 3⌊n/2⌋；后果：示例 assert 误报「实现
   有 bug」；对策：奇偶分开算精确值，或统一用 ≤ 3⌊n/2⌋ 的弱断言——本例
   实测翻车后改的写法。）
2. **分区的「≤」把相等元素全堆一侧**
   （现象：多重复值输入下选择退化为 Θ(n²)；原因：与第 7 章同病——
   Lomuto 分区对重复值失衡；后果：期望 4n 的前提被破坏；对策：分区后
   断言递归侧 ≤ 7n/10 + 6（BFPRT 天然免疫，因为主元保证两侧配额）。）
3. **BFPRT 的组内取「任意元素」而非中位数**
   （现象：递归式不成立，最坏回到 Θ(n²)；原因：两侧 ≥ 3n/10 的保证依赖
   「x 是中位数的中位数」——取组内任意元素则 x 可能极端；后果：确定性
   线性的证明整体失效；对策：组内必须精确取中位数（≤5 个元素插入排序
   取中位，最坏 6 次比较——练习 9.3-1 让你做出来）。）
4. **RANDOMIZED-SELECT 递归两侧**
   （现象：跑出了 Θ(n lg n) 甚至 Θ(n²)，与快排无异；原因：手滑写成快排
   的双递归；后果：渐进退化；对策：单侧递归是选择的本质——另一侧**直接
   扔掉**，写完检查「每个分支恰好一个递归调用」。）

## 练习

1. （CLRS 练习 9.1-1）证明：找**第二小**最少要 n + ⌈lg n⌉ − 2 次比较
   （锦标记败者树——第 3 章的树形结构在这里回收）。
2. （CLRS 练习 9.2-1）证明 RANDOMIZED-SELECT 在最坏输入上的递归深度可以
   是 Θ(n)（但期望浅）。
3. （CLRS 练习 9.2-3）写出 RANDOMIZED-SELECT 的迭代版（while 循环代替
   尾递归——与第 7 章尾循环消除同款）。
4. （CLRS 练习 9.3-1）5 个元素取中位数最少几次比较？（6 次——给出方案。）
5. （CLRS 练习 9.3-3）最坏情形线性时间的排序存在吗？（是——SELECT 当
   主元的快排，T(n)=T(⌊n/2⌋)+Θ(n)……但常数让它只是理论构造。）
6. （CLRS 思考题 9-2/9-3）加权中位数（Σwᵢ=1，找 x 使两侧权和各 ≤ 1/2）；
   k 分位数组 O(n lg k)。
7. （本教程）给示例的 BFPRT 加「每层递归侧 ≤ 0.72n」断言，跑 1000 个
   固定随机输入验证 7n/10+6 的界。
