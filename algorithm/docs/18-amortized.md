# 18 · 摊还分析

> 对应 CLRS 第 17 章 *Amortized Analysis*（英文 3rd ed. pp.451–478）。
> 摊还分析回答的问题是：**单次操作贵、但贵得极少**时，怎么把代价公平地
> 分摊。第 6 章 BUILD-MAX-HEAP 的 O(n) 紧界、`std::vector` 的扩容、
> 第 20 章斐波那契堆的全部魅力，都靠这套语言陈述。

## 学习目标

1. 会用聚合法（求 n 次操作的总代价再除 n）分析二进制计数器；
2. 会用记账法给操作「定价」并维护信用非负不变式；
3. 会用势能法：选 Φ、验证 Φ(D₀)=0 且 Φ≥0、逐操作算摊还代价；
4. 能解释动态表「扩张倍增 + 收缩 1/4 阈值」为什么不能改成 1/2。

## 三种方法，一个问题：二进制计数器

INCREMENT 翻转尾部连续的 1（变 0）再进一位（0 变 1）。单次最坏翻转
k 位（111...1 + 1），但 n 次总计：

**聚合法**：位 i 每 2ⁱ 次操作翻转一次，总翻转 Σ⌊n/2ⁱ⌋ < 2n——平均
每次 < 2 位。示例 18.1 实测 n=16：总翻转 31 ≤ 32 = 2n。

**记账法**：每次自增收 2 元「摊还价」——1 元付当下的 0→1 翻转，另 1 元
存成**信用**押在那个 1 位上；将来它 1→0 时用押金支付。不变式：信用 =
1 的位数 ≥ 0，永不透支。贵操作（翻转 k 位）由前面积累的押金买单。

**势能法**（最强大，不依赖「给谁记账」的具体账本）：定义势函数
Φ(D) = 计数器中 1 的个数。摊还代价

âᵢ = 实际代价 cᵢ + Φ(Dᵢ) − Φ(Dᵢ₋₁)。

每次自增翻转 t+1 位（t 个 1→0、一个 0→1）：ΔΦ = (1−t)，于是
â = (t+1) + (1−t) = **恰好 2**——不依赖 t！示例 18.3 逐操作验证 16 次
全部等于 2（和 = 32）。

三法的关系：聚合看总量、记账看账本、势能看状态函数。**势能法通吃**
——只要 Φ(D₀) = 0 且 Φ ≥ 0（初态最弱），总实际代价 ≤ 总摊还代价，
任何操作序列都成立。第 20 章斐波那契堆的势函数 Φ = #roots + 2·#marks
是这一法的最高应用。

## 动态表（§17.4）：`std::vector` 的扩容账本

表满时**倍增**容量（搬运旧元素）。第 i 次扩容搬运 2^i 个元素，总搬运
Σ2^i < 2n——几何级数，摊还 O(1)。示例 18.4 实测：连续插入 16 个元素
总拷贝 15 次 ≤ 2n。

**收缩的阈值必须是 1/4 而不是 1/2**——这是本章最著名的反例直觉。
若「元素少于容量一半就减半」，在半满边界交替增删，每次都触发整表搬运：

```
收缩策略对比（容量 64、元素 33 起交替增删 200 次）：
  1/4 阈值（CLRS）：额外拷贝 64 次
  1/2 阈值（抖动）：额外拷贝 25600 次（差 400 倍）
```

400 倍的实测差距来自**抖动（thrashing）**：1/2 阈值下增删各触发一次
整表搬。1/4 阈值把「扩张线」与「收缩线」拉开一个 2 倍的缓冲带——
增删交替最多在带内震荡，不触碰搬运转折点。势能法证明：取
Φ = 2·num − cap（num ≥ cap/2 时）或 cap/2 − num（num < cap/4 时），
两种搬运的摊还代价都是 O(1)。`std::vector` 只扩不缩（shrink_to_fit
是显式一次性操作）——工程上干脆绕开收缩问题。

## C++23 语言点

- 计数器用 `std::vector<int>` 当位图（`bit[0]` 最低位）——与 CLRS 的
 位数组一一对应；`std::bitset` 也可但要编译期定长；
- 动态表演示用「虚拟拷贝计数」——真实 `vector::resize` 搬了多少不必
  关心，我们统计的是**算法意义上的搬运**（教学实现的透明性）。

## 坑位清单

1. **收缩阈值取 1/2 造成抖动**
   （现象：边界负载下每次操作都搬整表，性能塌方 400 倍；原因：扩张与
   收缩的转折点重合，交替操作反复踩线；后果：摊还从 O(1) 变 O(n)；
   对策：转折点之间留常数倍缓冲带（CLRS 用 1/4 扩张带），示例的实测
   对比就是判词。）
2. **势函数不满足 Φ(D₀)=0 或 Φ<0**
   （现象：摊还上界「证明」了但实测超出；原因：总实际 = 总摊还 +
   Φ(D₀) − Φ(Dₙ)，Φ(D₀)>0 时上界从第一刻就漏；后果：假证明；
   对策：换算势函数使其在初态为 0（平移或取 min），并全程验证非负。）
3. **把「均摊 O(1)」当「单次 O(1)」用在实时系统**
   （现象：单次 push_back 偶发毫秒级尖刺，实时任务超时；原因：摊还
   是平均值，单次扩容的真实代价 Θ(n)；后果：尾延迟违约；对策：实时
   路径用 reserve 预分配，或换定长环形缓冲（第 10 章）。）
4. **聚合法只验一个序列**
   （现象：对「先全插后全删」验证通过，换「交替增删」就塌；原因：
   聚合法的界必须对**任意**操作序列成立，单一序列的漂亮数字不代表
   最坏；对策：用势能法补严格证明，聚合数字只当佐证。）
