# 07 · 快速排序

> 对应 CLRS 第 7 章 *Quicksort*（英文 3rd ed. pp.170–190）。快排是实践中
> 最快的通用排序，也是「随机化让最坏情形消失」的第一课：它的最坏 Θ(n²)、
> 期望 Θ(n lg n)，而随机化主元让**任何输入**都落到期望上——第 5 章的概率
> 工具在这里第一次产粮。

## 学习目标

1. 能手推 PARTITION 的循环不变式（三段证明），并解释主元落位；
2. 能说出快排最坏 Θ(n²) 何时发生、期望 Θ(n lg n) 的指示器证明思路；
3. 会实现随机化主元并解释它为什么「消灭输入敏感性」；
4. 能对比 Lomuto（CLRS 正文）与 Hoare（练习 7.1）两种分区的计数画像；
5. 会用「递归较小侧 + 循环较大侧」把栈深度压到 O(lg n)；
6. 理解三路分区对重复元素的关键救场（思考题 7-2）。

## 分治的「分区」形态

归并排序的骨架是**合并**（分解平凡），快排正相反：分解（PARTITION）是
主角，合并是空操作——排完左右两段，整段自然有序。

```clrs
QUICKSORT(A, p, r)
1  if p < r
2      q = PARTITION(A, p, r)
3      QUICKSORT(A, p, q-1)
4      QUICKSORT(A, q+1, r)

PARTITION(A, p, r)          // 主元 x = A[r]
1  x = A[r]
2  i = p - 1
3  for j = p to r - 1
4      if A[j] ≤ x
5          i = i + 1
6          exchange A[i] with A[j]
7  exchange A[i+1] with A[r]
8  return i + 1
```

**PARTITION 的循环不变式**（第 3 行 for 的每轮迭代开始时）：

- 若 p ≤ k ≤ i，则 A[k] ≤ x；
- 若 i+1 ≤ k ≤ j−1，则 A[k] > x；
- 若 k = r，则 A[k] = x；
- 若 j ≤ k ≤ r−1，则 A[k] 尚未见过。

初始化（i=p−1、j=p，两个已见区间皆空）、保持（A[j] ≤ x 则扩张左区、否则
留在右区，都是一次交换）、终止（j=r 时交换主元到 i+1——它恰是「左区右端
再进一格」，于是 A[p..i+1] ≤ x < A[i+2..r] 全部就位）。示例 07.1 对图 7.1
数组实测：`[2,8,7,1,3,5,6,4]` 分区后 `2 1 3 4 7 5 6 8`，主元 4 落位 q=3。

注意断言语义：分区**只保证**左段 ≤ x ≤ 右段，**不保证**左右各自有序——
左段 [2,1,3] 恰好无序（本例的第一版 assert 就在这里翻过车，见坑位 1）。

## 最坏、最好与期望

**最坏 Θ(n²)**：分区恒为 (n−1, 0)——已序输入取末元素（或首元素）做主元
正是这种输入。T(n) = T(n−1) + Θ(n)。示例实测 n=512 已序输入：比较
130816 = n(n−1)/2，递归深度 512。

**最好 Θ(n lg n)**：分区恒平衡。T(n) = 2T(n/2) + Θ(n)。

**期望 Θ(n lg n)**（§7.4 的指示器证明，思路）：比较发生在「同一对元素
最终被放进同一个子问题」时。zᵢ、zⱼ（第 i、j 小）被比较的概率是
2/(j−i+1)（两者中恰有一个成为「它们的公共祖先区间」的主元）。于是

E[比较] = Σᵢ Σⱼ>ᵢ 2/(j−i+1) ≤ 2n·ln n ≈ 1.39·n·lg n。

这个推导是第 5 章「指示器 + 期望线性性」的满分应用——**期望不用算分布，
只算每对元素被比较的概率**。示例 07.4 的经验验证：n=512、200 个固定种子
随机排列，平均比较 4951（下界 ~n·lg n = 4608，CLRS 上界 6388），最少
4291 / 最多 5896。

## 随机化主元：把期望装进算法（§7.3）

概率分析版假设「输入是随机排列」——但输入由不得我们。RANDOMIZED-PARTITION
把随机性搬进算法：

```clrs
RANDOMIZED-PARTITION(A, p, r)
1  i = RANDOM(p, r)
2  exchange A[r] with A[i]
3  return PARTITION(A, p, r)
```

无论输入是什么（包括别人故意构造的「杀手输入」），主元都均匀随机——
**期望 Θ(n lg n) 对一切输入成立**（「期望」是在算法自己的硬币上取的）。
示例实测同一已序输入：确定性 130816 次 vs 随机化 5241 次（深度 512 → 20）。

这也是快排与归并/堆排的性格差异：后两者「稳定地 Θ(n lg n)」，快排
「期望 Θ(n lg n) + 尾部风险」。实践选择快排是因为常数小、缓存友好、
内层是紧凑的顺序扫描——三个引擎（glibc/MSVC/LLVM 的 std::sort）全是
快排族的 introsort（快排 + 深度超限切堆排 + 小段切插入），introsort 的
**深度监控**正是治尾部风险的工程答案。

## Hoare 分区（练习 7.1）

CLRS 正文的分区如今常被称作 Lomuto 版；Hoare 的原始分区用双指针从两端
夹逼（i 停在 ≥x，j 停在 ≤x，交换后继续，交叠即返回 j）。同一随机排列上
的计数画像（示例 07.3）：

```
Hoare ：比较 7557，交换 1049
Lomuto：比较 5039，交换 2145
```

Lomuto 比较少（每元素恰一次比较）、Hoare 交换减半（每轮交换把两个元素
同时归位）。计数口径不同（Hoare 的 do-while 把终止测试也计作比较），
但两者都是 Θ(n) 次分区代价，渐近无异——工程里 Hoare 版对「多重复元素」
更鲁棒（相等的元素被平衡分到两侧，而不是全堆到一边）。

## 栈深度 O(lg n)：尾循环消除（§7.4 的收尾讨论）

朴素 QUICKSORT 的栈深度最坏 Θ(n)（已序输入退化链）。改写：**递归进较小
的一半，较大的一半用循环继续**：

```cpp
static void quicksort_tail(std::span<int> a, Counters& c, std::size_t depth = 1) {
    while (a.size() > 1) {
        const std::size_t q = partition(a, c);
        if (q + 1 > a.size() - q - 1) {      // 左半更大：递归右半
            quicksort_tail(a.subspan(q + 1), c, depth + 1);
            a = a.first(q);
        } else {
            quicksort_tail(a.first(q), c, depth + 1);
            a = a.subspan(q + 1);
        }
    }
}
```

递归侧的规模 ≤ ⌊(n−1)/2⌋，所以栈深度 ≤ ⌊lg n⌋ + 1。示例实测已序输入
n=512：朴素版深度 512，尾循环版**深度 2**（每层递归进的是空侧，循环把
主链吃掉）——比上界还松，因为退化输入的「较小侧」是空集。

## 三路分区：重复元素的救场（思考题 7-2）

Lomuto 把「≤ x」全放左侧——**相等元素也只往一边堆**。于是：

- 全相等数组 n=2048：两路分区比较 2,096,128 次——恰好 n(n−1)/2，最坏情形
  被重复元素触发，与已序输入同病；
- 三值域随机数组 n=10000：两路比较 16,679,634 次（≈ 1.67n²，失衡的分区
  链），三路只 33,373 次——**比值 499.79**。

三路分区（荷兰国旗问题，第 8 章预告）把数组切成 `< x | = x | > x` 三段，
相等段**整体出局**不再递归：

```cpp
while (i < gt + 1) {
    if (++c.compares, a[i] < pivot)      { std::swap(a[lt], a[i]); ++lt; ++i; }
    else if (++c.compares, a[i] > pivot) { std::swap(a[i], a[gt]); --gt; }
    else                                 { ++i; }
}
```

全相等时每个元素恰好两次比较（< 吗？> 吗？），总比较 2n——示例实测 4096
= 2×2048，一分不差。现实数据里重复键非常常见（枚举字段、日期、状态码），
`std::sort` 的实现（如 LLVM 的 Lambdasort/pdqsort 路线）内建了这类处理。

## 按谓词分区：partition 的通用抽象（07.6 的收尾）

07.1 的 CLRS PARTITION 和 07.6 的三路分区都把比较**写死**了（前者比
`pivot`、后者比 `< pivot` 与 `> pivot`）。把这两个比较换成**任意谓词**
`pred(x) == true 表示该去左段`，就得到 partition 的真正通用形态：

```cpp
template <class T, class Pred>
std::size_t partition_by(std::span<T> a, Pred pred, Counters& c) {
    std::size_t i = 0;
    for (std::size_t j = 0; j < a.size(); ++j) {
        if (++c.compares, pred(a[j])) {
            if (i != j) { std::swap(a[i], a[j]); ++c.swaps; }
            ++i;
        }
    }
    return i;          // [0, i) 满足 pred，[i, n) 不满足
}
```

**不变式**（07.1 那个的直白版）：循环到 `j` 时，`a[0..i)` 全部满足 pred、
`a[i..j)` 全部不满足。`j` 走完（`j == n`），不变量退化成「`a[0..i)` 满足
pred、`a[i..n)` 不满足」——`i` 就是分界点。

代价恒为 **Θ(n) 时间 + Θ(1) 额外空间**：一趟扫描，不递归、不分配、不管
谓词多复杂（谓词本身的时间另算）。**换谓词就是换问题**：

| 谓词 | 得到的问题 | 示例实测 |
|---|---|---|
| `x % 2 == 1` | 奇偶分类 | 10 元素：分界点 7，10 次比较、5 次交换 |
| `x < k` | 阈值分类（0-1 型分桶） | 10 元素（k=25）：小端 7 个、大端 3 个 |
| `x.ok`（业务字段） | 筛选合格记录 | 7 条记录：合格 4 条聚到前段 |

最后一例说明了这个抽象的价值：**谓词不必是比较**。它可以是任意布尔函数
——业务校验、状态判断、正则匹配。对 CLRS 07.1 的结构化同构对账也做了：
当谓词取 `x <= pivot` 时，`partition_by` 与 07.1 的 PARTITION 是**同一段
循环骨架**（同样的交换条件、同样的比较次数），说明抽象没丢任何信息。

**三个必查的后置条件**（示例都断言了）：

1. **分段正确**：`[0, i)` 全部满足 pred，`[i, n)` 全部不满足；
2. **多重集不变**：分区是**重排**，不是增删——示例对输入输出各排一次序
   断言相等；
3. **边界不越界**：全满足 → `i == n`；全不满足 → `i == 0`；空数组 → `i == 0`。
   这三种情形都要显式处理，不要指望「循环自然不会越界」。

**这个分区是不稳定的**：交换会把远处元素换到前面，谓词相等的元素之间
相对次序会被打乱（示例里「筛选合格记录」输出的 `1 3 5 6` 保持有序纯属
输入构造的巧合，`2 4 7` 那三行则明显被打乱）。要**稳定**分区，唯一办法
是多开一个输出数组做一趟 Θ(n) 归并——**不存在既 Θ(1) 空间又稳定的单趟
版本**。这个取舍在第 2 章归并排序处已经见过一次。

## C++23 语言点

- `std::span` 的 `first/subspan` 切片让「递归排序区间」零拷贝传递；
- 计数器沿递归链引用穿透（与第 4 章同款）；
- `std::max/min_element` 做分区后置条件检查（左段最大 ≤ x ≤ 右段最小）。

## 与 STL 对照

- `std::ranges::sort`：introsort——快排骨架 + 深度超 2·lg n 切堆排 + 小段
  插入排序，最坏 Θ(n lg n)。本章的三件武器（随机化/深度监控/小段切换）
  全部内建；
- `std::ranges::nth_element`（第 9 章预告）：快排的分区骨架直接复用成
  「选择」算法；
- 手写快排的现代意义：理解 introsort 为什么那样组装，以及在「比较器有
  副作用/自定义三路比较」时知道会发生什么。

## 坑位清单

1. **断言写成「分区后左段有序」**
   （现象：assert(is_sorted(左段)) 三通道齐炸；原因：PARTITION 只保证
   左段 ≤ 主元，不保证有序——左段 [2,1,3] 无序是**设计内**；后果：误以为
   分区实现有 bug 而去「修」正确的代码；对策：后置条件写成
   max(左段) ≤ x ≤ min(右段)，本例第一版实测踩中。）
2. **随机化主元忘了交换到主元位**
   （现象：RANDOMIZED-PARTITION 选了随机 i 但没 swap 到 r，主元仍是末
   元素，随机化失效；原因：PARTITION 读死 A[r]，随机选出的元素必须先
   落座；后果：杀手输入照打最坏 Θ(n²)，且很难从输出看出；对策：对已序
   输入断言「比较次数远小于 n(n−1)/2」——示例的 assert 就是这道的哨兵。）
3. **Hoare 分区的递归区间差一**
   （现象：越界或死循环；原因：HOARE-PARTITION 返回 j 后应递归
   (p, j) 与 (j+1, r)——不是 Lomuto 的 (p, q−1) 与 (q+1, r)；两个分区的
   「返回值语义」不同；后果：区间重叠 → 死循环，或漏元素；对策：每个
   分区函数头注释写清返回值语义，配 min/max 后置条件断言。）
4. **重复元素场景用两路分区**
   （现象：全相等数组跑出 n² 比较、三值域数组 500 倍劣化；原因：Lomuto
   的 ≤ 把相等元素全部堆向一侧，分区失衡；后果：现实数据（枚举键）上
   「随机化也救不了」——随机主元仍是重复值；对策：三路分区或改用
   `std::sort`（introsort 有重复处理）。）
5. **朴素快排递归深度当 Θ(lg n) 用**
   （现象：大数组上栈溢出；原因：最坏栈深 Θ(n)，n=10⁷ 时栈帧 ×几十字节
   就是几百 MB 栈；后果：崩溃且难复现（依赖输入）；对策：尾循环消除版
   （本例深度 2 实测）或显式栈 + 较小侧优先。）

```text
边界：全满足 → 分界点 = size；全不满足 → 0；空数组 → 0（都不越界）
注意：本分区**不稳定**——交换会把远处元素换到前面，
      要稳定就得多开一个数组做 Θ(n) 归并，没有又省空间又稳的单趟版。
自检通过
```
