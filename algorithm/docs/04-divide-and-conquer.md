## 分治三步曲

一个分治算法递归地把自己分解成若干规模更小的子问题：

- **分解**（divide）：把问题切成 a 个规模 n/b 的子问题；
- **解决**（conquer）：递归求解；规模足够小直接解；
- **合并**（combine）：把子问题的解拼成原问题的解。

运行时间的通式：**T(n) = a·T(n/b) + f(n)**，f 是分解+合并的代价。第 2 章的
归并排序是 a=2、b=2、f(n)=Θ(n) 的特例；本章把「怎么解这个方程」系统化。

## 最大子数组问题（§4.1）

**问题**：给定 n 个数的数组，找非空连续子数组使其和最大。CLRS 的包装是
「何时买进何时卖出股票收益最大」——股价的**变化量**数组里找最大子数组。

图 4.1 的 17 天股价给出的变化量（16 个数）：

```
[13 -3 -25 20 -3 -16 -23 18 20 -7 12 -5 -22 15 -4 7]
```

### 解法一：暴力 Θ(n²)

固定起点 i，向右累加，顺手记录最大和——两重循环。每个起点内层是递推累加，
不必重算前缀（那是 Θ(n³) 版本，CLRS 练习 4.1-2 让你写出来再被嫌弃）。

### 解法二：分治 Θ(n lg n)

把数组从中点切成两半。**关键观察：最大子数组只有三种可能**——

1. 完全在左半（规模 n/2 的同类子问题）；
2. 完全在右半（同上）；
3. **跨中点**——左半某个以 mid 结尾的后缀 + 右半某个以 mid+1 开头的前缀。

第三种情况**不是**子问题的形态（它被中点锚定），但它线性可解：从中点向左
扫一遍求「最大左后缀」，从中点向右扫一遍求「最大右前缀」，两者拼接。这就是
FIND-MAX-CROSSING-SUBARRAY（CLRS p.70）：

```clrs
FIND-MAX-CROSSING-SUBARRAY(A, lo, mid, hi)
1  left-sum = -∞
2  sum = 0
3  for i = mid downto lo          // 向左扩张
4      sum = sum + A[i]
5      if sum > left-sum
6          left-sum = sum
7          max-left = i
8  right-sum = -∞                 // 向右同理
9  sum = 0
10 for j = mid+1 to hi
11     sum = sum + A[j]
12     if sum > right-sum
13         right-sum = sum
14         max-right = j
15 return (max-left, max-right, left-sum + right-sum)
```

递归式 T(n) = 2T(n/2) + Θ(n)（两个半规模递归 + 线性的跨界扫描），主定理
情形 2 → **Θ(n lg n)**。

### 解法三：Kadane 线性 Θ(n)（练习 4.1-5 的回收）

分治并不是这个故事的最优解。观察：**以 j 结尾的最大子数组**只依赖以 j−1 结尾
者——前缀和为正就延伸，为负就从 j 重开：

```cpp
static Sub kadane(const std::vector<int>& a, OpCounters& c) {
    Sub best{a[0], 0, 0};
    long long endingHere = a[0];
    int start = 0;
    for (std::size_t j = 1; j < a.size(); ++j) {
        if (endingHere > 0) { endingHere += a[j]; }
        else                { endingHere = a[j]; start = static_cast<int>(j); }
        if (endingHere > best.sum) { best = {endingHere, start, static_cast<int>(j)}; }
    }
    return best;
}
```

这其实是**动态规划**的预告片（第 15 章）：状态 =「以 j 结尾的最优值」，转移
一步 O(1)。三种解法在同一数据上的实测（示例 04.1，口径 = 子数组和的累加次数）：

```
暴力   Θ(n^2)：和=43，区间=[7,10]（0 基，即第 8~11 天），累加 136 次
分治 Θ(n lg n)：和=43，区间=[7,10]，累加 64 次
Kadane  Θ(n)：和=43，区间=[7,10]，累加 15 次
```

三者答案一致（43，第 8~11 天，即 18+20−7+12），assert 互为对账。全负数组
（练习 4.1-1）也要验：三种算法都返回最大单元素 −2，而不是空段——Kadane 的
初始化必须用 `a[0]` 而不是 0，这是它的经典坑。

## Strassen 矩阵乘法（§4.2）

朴素方阵乘 Θ(n³)。第一个分治念头：把 A、B、C 各切成四块 n/2 子矩阵，

```
C11 = A11·B11 + A12·B21      C12 = A11·B12 + A12·B22
C21 = A21·B11 + A22·B21      C22 = A21·B12 + A22·B22
```

8 次子矩阵乘法 + 4 次加法 → T(n) = 8T(n/2) + Θ(n²) = Θ(n^{log₂8}) = Θ(n³)——
白忙一场，分块没省任何乘法。**Strassen 的天才之处**：用 7 次子矩阵乘法
（S₁–S₁₀ 是加减的「备料」，P₁–P₇ 是 7 次乘法）拼出同样的四个积：

```clrs
S1  = B12 − B22        S6  = B11 + B22
S2  = A11 + A12        S7  = A12 − A22
S3  = A21 + A22        S8  = B21 + B22
S4  = B21 − B11        S9  = A11 − A21
S5  = A11 + A22        S10 = B11 + B12

P1 = A11·S1    P2 = S2·B22   P3 = S3·B11   P4 = A22·S4
P5 = S5·S6     P6 = S7·S8    P7 = S9·S10

C11 = P5 + P4 − P2 + P6      C12 = P1 + P2
C21 = P3 + P4                C22 = P5 + P1 − P3 − P7
```

（展开代数可以验证。以 C22 为例，把 P5、P1、P3、P7 全部展开：

P5 = A11B11+A11B22+A22B11+A22B22；P1 = A11B12−A11B22；
P3 = A21B11+A22B11；P7 = A11B11+A11B12−A21B11−A21B12。

于是 C22 = P5+P1−P3−P7，逐项消去 A11B11、A11B22、A22B11、A11B12、
A21B11 之后**恰好**剩下 A22B22+A21B12——正是分块定义里的 C22。这种
「设计好的冗余然后消掉」正是它被称为代数魔术的原因。）

CLRS 的 2×2 例（A=[[1,3],[7,5]]，B=[[6,8],[4,2]]）在示例里逐项打印并对朴素
乘法断言相等：

```
  S1..S10: 6 4 12 -2 6 8 -2 6 -6 14
  P1..P7: 6 8 72 -10 48 -12 -84
  C11=P5+P4-P2+P6=18，C12=P1+P2=14，C21=P3+P4=62，C22=P5+P1-P3-P7=66
  朴素乘法 C=[[18,14],[62,66]]
```

递归式 T(n) = 7T(n/2) + Θ(n²)，n^{log₂7} ≈ n^2.807 压过 n² → Θ(n^2.81)。
n³ → n^2.81：n=1024 时乘法次数从 2³⁰ 降到 7¹⁰ ≈ 2^28.1，约 3.5 倍；
渐进上指数差 0.19，n 大到荒谬才碾压——所以工程上 Strassen 都在**大矩阵**
上才开（且在 2×2 或更大处切换回朴素乘，`cutoff` 参数就是干这个的）。
4×4 固定矩阵上三口径实测（示例 04.2）：

```
  朴素 Θ(n^3)          ：乘法 64，加法 64
  Strassen 纯递归(1x1) ：乘法 49（7×7），加法 198
  Strassen 2x2 截断    ：乘法 56（7×8），加法 128
```

读法：一层 Strassen 用 18 次矩阵加减换 1 次矩阵乘法（8→7）。乘法次数确实
降了（49 < 56 < 64），但**加减的账单变厚**——这是所有「降低乘法次数」类
算法（Karatsuba 乘法、FFT 卷积）共同的交易结构：乘法贵、加减便宜，用便宜
的换贵的。小 n 上交易不划算，所以要 cutoff。

## 解递归式的三种方法（§4.3–4.5）

### 代入法（§4.3）：猜一个界，用归纳证明

例：猜 T(n) = 2T(n/2) + n 是 O(n lg n)。设 T(k) ≤ ck lg k 对 k<n 成立，则

T(n) ≤ 2·c(n/2)lg(n/2) + n = cn lg n − cn + n ≤ cn lg n （只要 c ≥ 1）。

两个技巧：**减一项**（猜 T(n) ≤ cn lg n − n 之类更紧的形式才能过归纳），
和**换变量**（T(n)=2T(√n)+lg n 令 m=lg n 化为线性递归）。难点是猜——
递归树就是帮你猜的工具。

### 递归树（§4.4）：把递归展开成树，逐层记账

```
递归树 T(n)=2T(n/2)+cn（归并排序形）：
  第 0 层成本 c·n；第 1 层 2·c(n/2)=c·n；第 2 层 4·c(n/4)=c·n
  每层成本相同，共 lg n + 1 层 → 总成本 Θ(n lg n)
递归树 T(n)=2T(n/2)+cn^2（内部占主导）：
  第 0 层 c·n^2；第 1 层 c·n^2/2；第 2 层 c·n^2/4 —— 几何递减
  总成本 ≤ 2c·n^2 = Θ(n^2)（根节点占一半）
递归树 T(n)=8T(n/2)+cn^2（叶子占主导）：
  内部成本几何收敛于 Θ(n^2)，但叶子有 n^lg2(8)=n^3 个 → Θ(n^3)
```

**每层记账**要看「该层全部节点成本之和」，不是单个节点——这是最常见的
算错点。三种树的结局对应主定理三种情形的直觉：叶重（情形 1）、平衡
（情形 2）、根重（情形 3）。

### 主定理（§4.5，定理 4.1）

设 a ≥ 1、b > 1 为常数，T(n) = aT(n/b) + f(n)，其中 n/b 指 ⌊n/b⌋ 或 ⌈n/b⌉。
把 f(n) 与「叶子规模」n^{log_b a} 比较：

| 情形 | 条件 | 结论 | 直觉 |
|---|---|---|---|
| 1 | f(n) = O(n^{log_b a − ε})，ε>0 | T = Θ(n^{log_b a}) | 叶子占主导 |
| 2 | f(n) = Θ(n^{log_b a}) | T = Θ(n^{log_b a}·lg n) | 每层等重 |
| 3 | f(n) = Ω(n^{log_b a + ε}) 且 a·f(n/b) ≤ c·f(n)（c<1，正则条件） | T = Θ(f(n)) | 根占主导 |

**正则条件不是装饰**——情形 3 的「f 多项式地更大」还不够，必须验证
a·f(n/b) ≤ c·f(n)，否则定理不适用（CLRS 思考题 4-3 有反例）。示例 04.4
对五个教科书递归式逐一定档：

```
T(n)=2T(n/2)+n：情形 2：n^(log_2 2)=n 与 f=n 同阶 → Θ(n lg n)
T(n)=8T(n/2)+n^2：情形 1：n^(log_2 8)=n^3 压过 n^2 → Θ(n^3)
T(n)=4T(n/2)+n：情形 1：n^(log_2 4)=n^2 压过 n → Θ(n^2)
T(n)=4T(n/2)+n^3：情形 3：f=n^3 压过 n^2，正则 4·(n/2)^3=n^3/2 ≤ c·n^3 → Θ(n^3)
T(n)=3T(n/2)+n：情形 1：n^(log_2 3)≈n^1.585 压过 n → Θ(n^1.585)
```

然后做**经验验证**——自底向上按整数递推算出精确 T(n)（T(1)=1），看比值
是否收敛到常数（这就是「Θ」的机器化检验，与第 3 章的定义检查同款）：

```
经验验证（n=2^k，T(1)=1，自底向上精确递推）：
  2T(n/2)+n：n=256 时 T=2304，T/(n·lg n) = 1.1250
  8T(n/2)+n^2：n=256 时 T=33488896，T/n^3 = 1.9961
  4T(n/2)+n^3：n=256 时 T=33488896，T/n^3 = 1.9961
```

两处彩蛋：8T(n/2)+n² 与 4T(n/2)+n³ 的精确值**恰好相同**（33488896）——
不是巧合，两条递推在这组常数下逐层展开后各项一一相等（都是「叶子 8^k 项
+ 几何级数内部成本」），量级同为 Θ(n³) 且常数一致；而 T/(n·lg n) = 1.125
在收敛途中（精确值 T(n) = n·lg n + n，比值 = 1 + 1/lg n → 1）。

**主定理的边界**：f(n) 必须与 n^{log_b a} 多项式地可比。T(n) = 2T(n/2) +
n·lg n 落在情形 2 和 3 之间的「缝隙」里（f 不是多项式地更大），主定理
（这个版本）不适用——用递归树展开能得 Θ(n lg²n)。第 28 章多线递归
（T(n)=T(n/3)+T(2n/3)+cn，子问题规模不均）也超出本定理，仍需递归树。

## C++23 语言点

- **多值返回用聚合 struct**：`struct Sub { long long sum; int lo, hi; }`
  一个函数返回三元组（和/区间），比 `std::tuple` 可读、比出参引用安全，
  聚合初始化 `return {sum, lo, hi}` 一行完成；
- **`std::vector<std::vector<long long>>` 的取舍**：本章矩阵规模 ≤4，
  二维 vector 的清晰度优先；真实数值代码用一维平铺 + `i*n+j` 下标
  （缓存友好、可 `std::span` 化），第 29 章会那样写；
- **递归函数的计数器穿透**：`MatCounters&` 沿递归链传引用，代价统计
  汇总到顶层——后面每一章的分析实验都复用这个模式。

## 与 STL 对照

- `std::valarray`/`std::linalg`（C++26 落地中）是数值矩阵的方向，本章不用；
- 最大子数组无 STL 直接对应（`std::reduce` + 前缀和可做变体）；
- Strassen 的启示反而指向库设计：**BLAS 把「乘法次数最小化」做到了
  工程极致**，但小矩阵仍用朴素乘（cutoff 思想的工业化）。

## 坑位清单

1. **Strassen 公式转写错号（本示例真实翻车）**
   （现象：C22 算出 −102 而非 66，msvc/clang/gcc 三通道同一行 assert 齐炸；
   原因：把 C22 = P5+P1−P3−P7 写成了 `(P5+P1) − (P3 − P7)`——减法对
   括号内**负号分配**搞错，P7 前该是 −，写成了 +；后果：矩阵小错难肉眼
   发现（其他三个角全对）；对策：**永远与朴素乘法断言相等**再谈性能——
   本示例的 `assert(mat_eq(cStr, cNai))` 第一次运行就抓住了它。）
2. **跨界扫描的方向写反**
   （现象：max_crossing 返回的区间不含中点或漏最优；原因：左扫必须从 mid
   **递减**到 lo、右扫从 mid+1 递增到 hi，循环边界差一就丢解；后果：分治
   结果与暴力对不上；对策：三解法同数据对账 assert（本例 43/[7,10] 三方
   一致），跨界单独构造 mid 两侧一正一负的用例。）
3. **递归树按单节点记账**
   （现象：T(n)=2T(n/2)+n 的树被算成每层成本 n/2^i（只看一个节点的规模），
   总和 Θ(n)；原因：某层成本 = 该层**所有**节点成本之和——节点数 2^i 与
   单节点规模 n/2^i 相乘才是层成本；后果：渐近阶整个算错；对策：每层先数
   节点数、再乘单节点成本，像示例 04.3 那样逐层打印。）
4. **Kadane 用 0 初始化被全负数组击穿**
   （现象：全负输入返回 0（空子数组）而非最大元素；原因：`best=0` 隐含
   允许空段，CLRS 定义要求非空；后果：边界用例错答案；对策：用 a[0] 冷启动，
   示例的全负数组三解法对账 (−2,[3,3])。）
5. **主定理情形 3 忘验正则条件**
   （现象：对 f(n)=n²·lg n 之类硬套情形 3 得 Θ(n²lg n)——错；原因：情形 3
   要求 a·f(n/b) ≤ c·f(n)（c<1），非多项式差的 f 常不满足；后果：错的
   渐近阶一路传染到算法选型；对策：套情形 3 前显式验证正则式，像示例
   04.4 的判词里把 4·(n/2)³=n³/2 ≤ c·n³ 写出来。）
