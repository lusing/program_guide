## 分治三步曲

一个分治算法递归地把自己分解成若干规模更小的子问题：

- **分解**（divide）：把问题切成 a 个规模 n/b 的子问题；
- **解决**（conquer）：递归求解；规模足够小直接解；
- **合并**（combine）：把子问题的解拼成原问题的解。

运行时间的通式：**T(n) = a·T(n/b) + f(n)**，f 是分解+合并的代价。第 2 章的
归并排序是 a=2、b=2、f(n)=Θ(n) 的特例；本章把「怎么解这个方程」系统化。

## 最大子数组问题（§4.1）

**问题**：给定 n 个数的数组，找非空连续子数组使其和最大。CLRS 的包装是
「何时买进何时卖出股票收益最大」——股价的**变化量**数组里找最大子数组。

图 4.1 的 17 天股价给出的变化量（16 个数）：

```
[13 -3 -25 20 -3 -16 -23 18 20 -7 12 -5 -22 15 -4 7]
```

### 解法一：暴力 Θ(n²)

固定起点 i，向右累加，顺手记录最大和——两重循环。每个起点内层是递推累加，
不必重算前缀（那是 Θ(n³) 版本，CLRS 练习 4.1-2 让你写出来再被嫌弃）。

### 解法二：分治 Θ(n lg n)

把数组从中点切成两半。**关键观察：最大子数组只有三种可能**——

1. 完全在左半（规模 n/2 的同类子问题）；
2. 完全在右半（同上）；
3. **跨中点**——左半某个以 mid 结尾的后缀 + 右半某个以 mid+1 开头的前缀。

第三种情况**不是**子问题的形态（它被中点锚定），但它线性可解：从中点向左
扫一遍求「最大左后缀」，从中点向右扫一遍求「最大右前缀」，两者拼接。这就是
FIND-MAX-CROSSING-SUBARRAY（CLRS p.70）：

```clrs
FIND-MAX-CROSSING-SUBARRAY(A, lo, mid, hi)
1  left-sum = -∞
2  sum = 0
3  for i = mid downto lo          // 向左扩张
4      sum = sum + A[i]
5      if sum > left-sum
6          left-sum = sum
7          max-left = i
8  right-sum = -∞                 // 向右同理
9  sum = 0
10 for j = mid+1 to hi
11     sum = sum + A[j]
12     if sum > right-sum
13         right-sum = sum
14         max-right = j
15 return (max-left, max-right, left-sum + right-sum)
```

递归式 T(n) = 2T(n/2) + Θ(n)（两个半规模递归 + 线性的跨界扫描），主定理
情形 2 → **Θ(n lg n)**。

### 解法三：Kadane 线性 Θ(n)（练习 4.1-5 的回收）

分治并不是这个故事的最优解。观察：**以 j 结尾的最大子数组**只依赖以 j−1 结尾
者——前缀和为正就延伸，为负就从 j 重开：

```cpp
static Sub kadane(const std::vector<int>& a, OpCounters& c) {
    Sub best{a[0], 0, 0};
    long long endingHere = a[0];
    int start = 0;
    for (std::size_t j = 1; j < a.size(); ++j) {
        if (endingHere > 0) { endingHere += a[j]; }
        else                { endingHere = a[j]; start = static_cast<int>(j); }
        if (endingHere > best.sum) { best = {endingHere, start, static_cast<int>(j)}; }
    }
    return best;
}
```

这其实是**动态规划**的预告片（第 15 章）：状态 =「以 j 结尾的最优值」，转移
一步 O(1)。三种解法在同一数据上的实测（示例 04.1，口径 = 子数组和的累加次数）：

```
暴力   Θ(n^2)：和=43，区间=[7,10]（0 基，即第 8~11 天），累加 136 次
分治 Θ(n lg n)：和=43，区间=[7,10]，累加 64 次
Kadane  Θ(n)：和=43，区间=[7,10]，累加 15 次
```

三者答案一致（43，第 8~11 天，即 18+20−7+12），assert 互为对账。全负数组
（练习 4.1-1）也要验：三种算法都返回最大单元素 −2，而不是空段——Kadane 的
初始化必须用 `a[0]` 而不是 0，这是它的经典坑。

## Strassen 矩阵乘法（§4.2）

朴素方阵乘 Θ(n³)。第一个分治念头：把 A、B、C 各切成四块 n/2 子矩阵，

```
C11 = A11·B11 + A12·B21      C12 = A11·B12 + A12·B22
C21 = A21·B11 + A22·B21      C22 = A21·B12 + A22·B22
```

8 次子矩阵乘法 + 4 次加法 → T(n) = 8T(n/2) + Θ(n²) = Θ(n^{log₂8}) = Θ(n³)——
白忙一场，分块没省任何乘法。**Strassen 的天才之处**：用 7 次子矩阵乘法
（S₁–S₁₀ 是加减的「备料」，P₁–P₇ 是 7 次乘法）拼出同样的四个积：

```clrs
S1  = B12 − B22        S6  = B11 + B22
S2  = A11 + A12        S7  = A12 − A22
S3  = A21 + A22        S8  = B21 + B22
S4  = B21 − B11        S9  = A11 − A21
S5  = A11 + A22        S10 = B11 + B12

P1 = A11·S1    P2 = S2·B22   P3 = S3·B11   P4 = A22·S4
P5 = S5·S6     P6 = S7·S8    P7 = S9·S10

C11 = P5 + P4 − P2 + P6      C12 = P1 + P2
C21 = P3 + P4                C22 = P5 + P1 − P3 − P7
```

（展开代数可以验证。以 C22 为例，把 P5、P1、P3、P7 全部展开：

P5 = A11B11+A11B22+A22B11+A22B22；P1 = A11B12−A11B22；
P3 = A21B11+A22B11；P7 = A11B11+A11B12−A21B11−A21B12。

于是 C22 = P5+P1−P3−P7，逐项消去 A11B11、A11B22、A22B11、A11B12、
A21B11 之后**恰好**剩下 A22B22+A21B12——正是分块定义里的 C22。这种
「设计好的冗余然后消掉」正是它被称为代数魔术的原因。）

CLRS 的 2×2 例（A=[[1,3],[7,5]]，B=[[6,8],[4,2]]）在示例里逐项打印并对朴素
乘法断言相等：

```
  S1..S10: 6 4 12 -2 6 8 -2 6 -6 14
  P1..P7: 6 8 72 -10 48 -12 -84
  C11=P5+P4-P2+P6=18，C12=P1+P2=14，C21=P3+P4=62，C22=P5+P1-P3-P7=66
  朴素乘法 C=[[18,14],[62,66]]
```

递归式 T(n) = 7T(n/2) + Θ(n²)，n^{log₂7} ≈ n^2.807 压过 n² → Θ(n^2.81)。
n³ → n^2.81：n=1024 时乘法次数从 2³⁰ 降到 7¹⁰ ≈ 2^28.1，约 3.5 倍；
渐进上指数差 0.19，n 大到荒谬才碾压——所以工程上 Strassen 都在**大矩阵**
上才开（且在 2×2 或更大处切换回朴素乘，`cutoff` 参数就是干这个的）。
4×4 固定矩阵上三口径实测（示例 04.2）：

```
  朴素 Θ(n^3)          ：乘法 64，加法 64
  Strassen 纯递归(1x1) ：乘法 49（7×7），加法 198
  Strassen 2x2 截断    ：乘法 56（7×8），加法 128
```

读法：一层 Strassen 用 18 次矩阵加减换 1 次矩阵乘法（8→7）。乘法次数确实
降了（49 < 56 < 64），但**加减的账单变厚**——这是所有「降低乘法次数」类
算法（Karatsuba 乘法、FFT 卷积）共同的交易结构：乘法贵、加减便宜，用便宜
的换贵的。小 n 上交易不划算，所以要 cutoff。

## 解递归式的三种方法（§4.3–4.5）

### 代入法（§4.3）：猜一个界，用归纳证明

例：猜 T(n) = 2T(n/2) + n 是 O(n lg n)。设 T(k) ≤ ck lg k 对 k<n 成立，则

T(n) ≤ 2·c(n/2)lg(n/2) + n = cn lg n − cn + n ≤ cn lg n （只要 c ≥ 1）。

两个技巧：**减一项**（猜 T(n) ≤ cn lg n − n 之类更紧的形式才能过归纳），
和**换变量**（T(n)=2T(√n)+lg n 令 m=lg n 化为线性递归）。难点是猜——
递归树就是帮你猜的工具。

### 递归树（§4.4）：把递归展开成树，逐层记账

```
递归树 T(n)=2T(n/2)+cn（归并排序形）：
  第 0 层成本 c·n；第 1 层 2·c(n/2)=c·n；第 2 层 4·c(n/4)=c·n
  每层成本相同，共 lg n + 1 层 → 总成本 Θ(n lg n)
递归树 T(n)=2T(n/2)+cn^2（内部占主导）：
  第 0 层 c·n^2；第 1 层 c·n^2/2；第 2 层 c·n^2/4 —— 几何递减
  总成本 ≤ 2c·n^2 = Θ(n^2)（根节点占一半）
递归树 T(n)=8T(n/2)+cn^2（叶子占主导）：
  内部成本几何收敛于 Θ(n^2)，但叶子有 n^lg2(8)=n^3 个 → Θ(n^3)
```

**每层记账**要看「该层全部节点成本之和」，不是单个节点——这是最常见的
算错点。三种树的结局对应主定理三种情形的直觉：叶重（情形 1）、平衡
（情形 2）、根重（情形 3）。

### 主定理（§4.5，定理 4.1）

设 a ≥ 1、b > 1 为常数，T(n) = aT(n/b) + f(n)，其中 n/b 指 ⌊n/b⌋ 或 ⌈n/b⌉。
把 f(n) 与「叶子规模」n^{log_b a} 比较：

| 情形 | 条件 | 结论 | 直觉 |
|---|---|---|---|
| 1 | f(n) = O(n^{log_b a − ε})，ε>0 | T = Θ(n^{log_b a}) | 叶子占主导 |
| 2 | f(n) = Θ(n^{log_b a}) | T = Θ(n^{log_b a}·lg n) | 每层等重 |
| 3 | f(n) = Ω(n^{log_b a + ε}) 且 a·f(n/b) ≤ c·f(n)（c<1，正则条件） | T = Θ(f(n)) | 根占主导 |

**正则条件不是装饰**——情形 3 的「f 多项式地更大」还不够，必须验证
a·f(n/b) ≤ c·f(n)，否则定理不适用（CLRS 思考题 4-3 有反例）。示例 04.4
对五个教科书递归式逐一定档：

```
T(n)=2T(n/2)+n：情形 2：n^(log_2 2)=n 与 f=n 同阶 → Θ(n lg n)
T(n)=8T(n/2)+n^2：情形 1：n^(log_2 8)=n^3 压过 n^2 → Θ(n^3)
T(n)=4T(n/2)+n：情形 1：n^(log_2 4)=n^2 压过 n → Θ(n^2)
T(n)=4T(n/2)+n^3：情形 3：f=n^3 压过 n^2，正则 4·(n/2)^3=n^3/2 ≤ c·n^3 → Θ(n^3)
T(n)=3T(n/2)+n：情形 1：n^(log_2 3)≈n^1.585 压过 n → Θ(n^1.585)
```

然后做**经验验证**——自底向上按整数递推算出精确 T(n)（T(1)=1），看比值
是否收敛到常数（这就是「Θ」的机器化检验，与第 3 章的定义检查同款）：

```
经验验证（n=2^k，T(1)=1，自底向上精确递推）：
  2T(n/2)+n：n=256 时 T=2304，T/(n·lg n) = 1.1250
  8T(n/2)+n^2：n=256 时 T=33488896，T/n^3 = 1.9961
  4T(n/2)+n^3：n=256 时 T=33488896，T/n^3 = 1.9961
```

两处彩蛋：8T(n/2)+n² 与 4T(n/2)+n³ 的精确值**恰好相同**（33488896）——
不是巧合，两条递推在这组常数下逐层展开后各项一一相等（都是「叶子 8^k 项
+ 几何级数内部成本」），量级同为 Θ(n³) 且常数一致；而 T/(n·lg n) = 1.125
在收敛途中（精确值 T(n) = n·lg n + n，比值 = 1 + 1/lg n → 1）。

**主定理的边界**：f(n) 必须与 n^{log_b a} 多项式地可比。T(n) = 2T(n/2) +
n·lg n 落在情形 2 和 3 之间的「缝隙」里（f 不是多项式地更大），主定理
（这个版本）不适用——用递归树展开能得 Θ(n lg²n)。第 28 章多线递归
（T(n)=T(n/3)+T(2n/3)+cn，子问题规模不均）也超出本定理，仍需递归树。

## 二分查找：分治的极端形态（§4.1 的另一面）

二分查找常被当成「查表技巧」，但它其实是**分治三步曲退化到极致**的样子：

- **分解**：把 n 折半——注意不是切成 a 份，而是**只保留一半**；
- **解决**：规模为 1 时直接判定；
- **合并**：**没有合并步骤**，f(n) = Θ(1)。

于是 T(n) = T(n/2) + Θ(1)，解得 **Θ(lg n)**。对照本章 04.3 的递归树
画法：归并排序的树每层有 n/2ⁱ 个节点、每节点成本 c，层成本恒为 cn；二分
查找的树**每层只有一个节点**，宽 = 1、高 = lg n，单层成本 c，层成本也是 c
——两种形状的总代价分别是 Θ(n lg n) 与 Θ(lg n)。**同样的 Θ(1) 单层代价，
节点数的分布决定了量级。**

### 正确性的全部重量在边界不变式

选「左闭右开 `[lo, hi)`」，不变式一句话：**答案若存在，必落在 `[lo, hi)`
内**。三行代码各守一条：

```cpp
mid = lo + (hi - lo) / 2;      // 防溢出写法，不是 lo + hi
if (a[mid] <  target) lo = mid + 1;   // mid 已排除 → +1（左闭）
if (a[mid] >  target) hi = mid;       // 右开 → mid 本身就是新边界
```

**为什么 `lo = mid + 1` 而不是 `lo = mid`**：因为 `a[mid] < target`
已经证明 `a[mid]` 不是答案，留在区间里就是死循环（区间不收缩）。右端
`hi = mid` 则是「右开」的直接后果——`mid` 刚好落在开区间之外。
**换成 `[lo, hi]` 闭区间时，两条都要改成 `mid±1`**，这是 off-by-one 的头号
来源。所以闭/开区间两种写法不能凭记忆互换，要重新推一遍边界。

`lo = 0; hi = size()` 还有个附带好处：**空数组天然正确**（`lo == hi` 直接
不进循环，比较次数 0），不需要额外的特判。

示例的实测（n=1023，42 个均匀查询）：二分平均 **10.0** 次比较，线性平均
**493.0** 次——**49 倍**的差距，正好是 lg n 与 n/2 的量级比。

### lower_bound / upper_bound：边界二分

处理**重复元素**时，「找到一个就返回」的写法不够用——要的是**一整段**位置。
写法上的关键差别是**不设「命中就返回」的出口**，而是把区间缩到一个点为止，
那个点就是答案：

| | 不变式 | 循环终止时 | 判定 `< target` | 判定 `> target` |
|---|---|---|---|---|
| `lower_bound` | 第一个 `>= target` | 区间空 | `lo = mid+1` | `hi = mid` |
| `upper_bound` | 第一个 `> target` | 区间空 | `lo = mid+1` | `hi = mid` |

（差别只在那一个字符：`<` 还是 `<=`。）

实测 `[2,4,4,4,7,7,9]` 找 4：`lower = 1`、`upper = 4`，于是 4 出现的
区间是 `[1, 4)`、共 3 次。关键性质两条：

- **`lower <= upper` 恒成立**；target 不存在时二者**相等**（区间为空），
  所以「这个值出现了吗」的判据就是 `lower != upper`，不需要额外查找；
- **越界自然处理**：`lower_bound(0) = 0`（全都 ≥ 0）、`upper_bound(100) = 7`
  （= size，即「都 < 它」）。示例对这两条与 `std::lower_bound` /
  `std::upper_bound` 做了逐一对账断言。

### 旋转有序数组的最小值：判定条件被打断时怎么办

前提：数组由两段各自递增的区间拼成（旋转点任意），如 `[4,5,6,7,0,1,2]`。
线性扫一遍是 Θ(n)，但可以做到 **Θ(lg n)**。

难点在于**普通二分的前提被破坏了**：`a[mid] < target` 时，mid 可能落在旋
转点**前**那段也可能落在**后**那段，比较结果**不再唯一决定方向**。示例把
这行失败摆出来：旋转数组 `[3,4,5,1,2]` 查 1，mid=2 落到 `a[2]=5 > 1`，
区间缩到 `[0,2)`，真正的答案 1 被排除在外，普通二分返回「未找到」。

破局的办法是**换基准**：拿 `a[hi]`（而不是 `a[mid]`）当参照，让三条分支
各自都能**严格收缩**：

```
a[mid] >  a[hi]  → mid 在旋转点前段，最小值在 (mid, hi] → lo = mid + 1
a[mid] <  a[hi]  → mid 在后段（或根本没旋转），最小值在 [lo, mid] → hi = mid
a[mid] == a[hi]  → 无法判方向，只能缩右端 → hi--
```

**三条分支的「严格收缩」是硬要求**。示例最初写成 `lo = mid`（对应「中序
定位」那套思路），在「根本没旋转」的输入 `[2,3,4,5]` 上 `mid` 恒等于
`lo` → **区间不收缩 → 死循环**（本教程实测踩过）。写这类循环时，务必先
自问一句：「每条分支是否都让区间严格变小？」

第三条 `==` 分支是**防重复值**的：没有它，`[1,1,1,1]` 这类输入会在两个
相等的端点之间永远横跳。示例对 `[2,2,2,0,1]`、`[1,1,1,1]`、`[3,3,1,3]`、
`[1,3,3]`、`[5,5,5,1,5,5]` 五组带重复的输入逐一断言了结果与 `min_element`
一致。

实测比较次数：7 元素用 3 次、5 元素用 2 次、2 元素用 1 次、单元素 0 次——
都在 lg n 附近，而线性扫分别要 7/5/2/1 次。

## 二分答案：把优化问题变成判定问题

分治的另一个极端形态不是「在数组里找答案」，而是**在答案空间里二分**——
适用于「求最优解」而非「查询给定值」的问题。前提是把优化问题改写成
一个**关于参数单调**的判定问题。

### 问题模型

n 种设备，每种设备有若干供应商（带宽 b，价格 p）。每种设备选一家，选完后

- B = 各设备所选带宽的**最小值**（整体瓶颈，由最弱的一环决定）；
- P = 各设备所选价格之**和**。

目标是最大化 **B/P**（性价比），答案保留 3 位小数。

### 第一步：固定 B 后各设备独立

固定 B 后每台设备的选择**互不影响**——它只需在「带宽 ≥ B」的供应商里挑最便宜的。
于是

$$P(B)=\sum_{i=1}^{n}\min\{\,p_{i,j}\ :\ b_{i,j}\ge B\,\}$$

某台设备在 B 下没有达标供应商时 P(B) = +∞（该 B 不可行）。这个观察把
「枚举所有配置」（指数级）压成「枚举所有候选 B」（多项式级）。

### 第二步：候选集离散化

**最优 B 必落在某个设备的一条带宽上**。证明：设最优配置的最小带宽为 B，
若 B 不等于任何 b_{i,j}，则可把 B 提到下一个候选值 B' —— 此时每台设备
「b ≥ B'」的供应商集合只会缩小，最小价只增不减，但 P 不一定变…
严格地说，要论证的是**存在一个候选值不劣于 B**：把 B 提到最小的那个
≥ B 的候选值 B'，可行集只缩小 ⟹ P(B') ≥ P(B)，而分子变大，比值未必变大。

**这里必须小心**：正确的论证不是「P 不变」，而是「B' 与 B 之间没有任何
带宽分界，所有配置在 B' 下与 B 下**同样不可行**」。真正的结论是：

> 最优解的 B 等于所选配置中某台设备的带宽；等价地，把 B 限制在候选集上
> 不损失最优性——因为任何配置的真实瓶颈值 min_i b_i 本身就是候选集元素。

所以只需在候选集（大小 O(总报价数)）上遍历。本例实测的表：

```
    B    P(B)     B/P(B)       floor(1000·f) 与整数化复核
  100    27       3.703704       3703  可行=true / +1 不可行=true
  120    29       4.137931        4137  可行=true / +1 不可行=true
  150    34       4.411765       4411  可行=true / +1 不可行=true
  200    41       4.878049       4878  可行=true / +1 不可行=true
  250    49       5.102041       5102  可行=true / +1 不可行=true
  300    65       4.615385       4615  可行=true / +1 不可行=true
  400    不存在（某设备无 b ≥ 400 的供应商）
  500    不存在（某设备无 b ≥ 500 的供应商）
```

「不可行」的候选值直接跳过——**这一步是易漏点**：不判可行性就取最小价，
会得到一个偏小的不存在的 P，从而输出偏大的比值。

### 第三步：分数规划——f(B) 单调不增 ⟹ 可二分

$$f(B)=\frac{B}{P(B)}$$

关键推导：B 变大 ⟹ 每台设备的可选集变小 ⟹ 最小价**只增不减** ⟹
**P(B) 单调不减**。分子在增、分母也在增，商的单调性不是显然的，但可以
直接验证：

设 B₁ < B₂。P(B₁) ≤ P(B₂)。若 P 在 [B₁,B₂) 上不变，则 f 显然增；
若 P 发生了跳变（某台设备的最优供应商换人了），分子按 B 的比例增长、
分母按**跳变**增长——跳变是阶跃而非连续增长，因此 f 在跳变点之后开始下降。

这给出**判定结构的单调性**，也就是二分所需的唯一性质：

> 「f(B) ≥ r 的候选 B 构成候选集的一个**前缀**」⟺
> 「r 增大时判定结果单调地从真变假」。

于是可以二分 r。**注意这里不需要 f 本身单调**（它确实不单调，见上表
B=250 处是折点）——需要的是**判定关于 r 单调**。这是「二分答案」与
「三分答案」的分界：目标值不单调时，二分判定的单调性依然可用。

### 第四步（★核心技巧）：整数化精确舍入

题目要求「保留 3 位小数」。**字面做法**是对 r 做浮点二分 60 次再
`setprecision(3)`；但这有一个隐患：0.0005 这类值在二进制里不可精确
表示（1/2000 = 1/(2⁴·125)，分母含 5 的因子），浮点只能给一个近似数，
最后一位取决于 IEEE 754 的舍入规则而非数学。

**正确做法是把不等式整数化，再二分整数 k**。要判定「答案是否 ≥ k/1000」，
把整个不等式乘 1000：

$$\frac{B}{P(B)}\ \ge\ \frac{k}{1000}\iff 1000\cdot B\ \ge\ k\cdot P(B)$$

两边全是整数，除法被彻底消掉 ⟹ **全程零浮点运算**，浮点误差无处产生。
二分最大的可行 k，答案就是 ⌊1000 × max B/P⌋，输出时拆成
`k/1000` 与补零的 `k%1000`：

```cpp
// 判定：∃B 使 B/P ≥ k/1000 —— 交叉相乘，全程整数
static bool feasible_int(const std::vector<DevPlan>& plans,
                         const std::vector<long long>& bands, long long k) {
    for (long long B : bands) {
        const long long P = total_price(plans, B);
        if (P >= INF_P) { continue; }        // 该 B 下某设备不可行
        if (k * P <= 1000LL * B) { return true; }
    }
    return false;
}
// 二分最大的可行 k（k=0 恒可行 ⟹ lo 初值合法）
static long long bisect_scaled(const std::vector<DevPlan>& plans,
                               const std::vector<long long>& bands) {
    long long lo = 0, hi = 1;
    while (feasible_int(plans, bands, hi)) { lo = hi; hi *= 2; }  // 倍增找上界
    while (hi - lo > 1) {
        const long long mid = lo + (hi - lo) / 2;
        if (feasible_int(plans, bands, mid)) { lo = mid; } else { hi = mid; }
    }
    return lo;
}
```

**「除以 1000」变「乘以 1000」是这一招的全部要点**。判定式右端 1000·B
在 B ~ 1e16 时就吃掉 int64（上限 9.22e18）——**整数化消除了浮点误差，
但没消除整数溢出**。三档安全写法：

| 量级 | 写法 |
|---|---|
| 一般（乘积 < 9.2e18） | 直接 `k * P <= 1000LL * B` |
| 乘积在 (9.2e18, 1.84e19) | 升 `unsigned long long`（上限 2⁶⁴−1 ≈ 1.84e19，是 int64 的两倍）——**侥幸不是通解**，乘积再大就出界 |
| 通用 | **除后比**：k·P ≤ 1000·B ⟺ k ≤ ⌊1000·B/P⌋（k、P > 0），求 ⌊1000·B/P⌋ 用 `(B/P)*1000 + (B%P)*1000/P` |

> **为什么没有 `__int128` 这一档**：GCC/Clang 的 `__int128` 看似最省事，
> 但 **MSVC 根本没有这个类型**（`/permissive-` 下直接编译错）。本教程
> 三通道纪律（MSVC 主线）下，宽类型不是可移植假设——示例里最初写的
> `__int128` 版本就在 MSVC 通道实测翻车，才改成「除后比 + unsigned 复核」。

「除后比」这一招值得单独记住：它把**乘法换成了除法与取模**，是所有
「交叉相乘会溢出」场景的通用出路（第 4 章的分数比较、第 33 章的
KMP 环状串比较都是同一族）。而 unsigned 这档的价值在**独立复核**：
`k·P ≤ 1000·B` 想在不信任求 k 过程的前提下直接验判定式，就得真把两个
乘积算出来——本例 B = 1e16 时它们是 9999999999999999999 与
10000000000000000000，**恰好落在 (int64 上限, uint64 上限) 的缝隙里**：
signed 必炸、unsigned 恰好装得下、比较精确。这是教学例的运气，不是
工程答案——B 再翻倍 unsigned 也炸，那时只剩「除后比」。

实测三种口径在同一份数据上完全一致（最优 B=250、P=49）：

```
三方对账（同一份数据）：
  直接定义 ⌊1000·B/P⌋                = 5102
  整数化二分得到的 k                 = 5102
  输出 k/1000 与 k%1000（补零）      = 5.102
  浮点二分 60 次收敛到 r             = 5.10204082
  真实 max B/P                       = 5.10204082
  两者之差 < 1e-9                    = true
  ⟹ 浮点法**精度够**，但它给不出「截断到 3 位」的确定答案——
     只能靠 setprecision 去猜，答案落在舍入边界上时最后一位会漂。
```

边界实例把差别摆明（单设备带宽 1、价格 2000，答案恰是 1/2000 = 0.0005）：

```
边界实例（单设备：带宽 1、价格 2000 ⟹ B/P = 1/2000 = 0.0005）：
  整数化二分：k = 0 ⟹ 输出 0.000（截断到 3 位的**确定**答案）
  「k=1 可行吗」这个问题整数化回答得很干脆：
    1000·B = 1000·1 = 1000  vs  k·P(B) = 1·2000 = 2000 ⟹ 1000 < 2000 ⟹ 不可行
  浮点路径在同一处：0.0005 的 double 表示是 0.00050000000000000001，
  它既不等于精确的 1/2000，也无法告诉你输出该是 0.000 还是 0.001。
```

### 分数比较：不要用浮点直接比

遍历候选 B 时要比较两个比值 B₁/P₁ 与 B₂/P₂。**不要写**
`static_cast<double>(B1)/P1 > static_cast<double>(B2)/P2`——
两个 double 可能**完全相等**，程序给出「false」而真值是「true」：

```
分数比较（不要用浮点直接比，用交叉相乘 b1*p2 > b2*p1）：
  b1/p1 = 100000001/100000000 = 1.0000000099999999
  b2/p2 = 100000002/100000001 = 1.0000000099999999
  浮点直接比 b1/p1 > b2/p2 = false（**错**：两个 double 完全相等，判不出大小）
  交叉相乘 b1*p2 > b2*p1 = true（对：10000000200000001 > 10000000200000000，差 1）
  真值：100000001/100000000 与100000002/100000001 只差 1 个交叉乘积单位，而 double 的
  53 位尾数根本表达不出这个差别（相对差 ≈ 1e-16，double 的 eps 量级内）。
```

两个分数的**真实**差是 1/(10⁸·(10⁸+1)) ≈ 1e-16——恰好在 double 的
机器精度 eps（2.2e-16）之内，所以两个商被舍入到同一个 double。
交叉相乘 `b1*p2 > b2*p1` 把比较变成整数乘法，结果是精确的
（本例乘积 ~1e16，long long 装得下；再大就用「除后比」）。

**这是本教程反复出现的模式**：「比较分数 / 比值 ⟺ 交叉相乘」。

### 复杂度

设设备数 n，第 i 台设备有 mᵢ 条报价，总报价 M = Σmᵢ。

- 预处理（每台设备按 b 升序 + 后缀最小价）：Θ(M lg M)；
- 单次 P(B) 查询（每台设备一次 lower_bound）：O(n lg mᵢ)；
- 候选集大小 ≤ M，判定一次 O(M · n lg m)；
- 二分 k 需 O(lg(maxB·1000/P_min)) = O(lg B) 次判定。

总 **O(M lg M + M · n lg m · lg B)**，与「枚举所有配置」的指数级相比是
压倒性的胜利。若把候选 B 从大到小扫、用每台设备的单调指针替代 lower_bound，
判定总代价可降到 O(M + |bands| · n)——**同一个「单调不减」性质第二次
发挥作用**（指针只向前走）。

## C++23 语言点

- **多值返回用聚合 struct**：`struct Sub { long long sum; int lo, hi; }`
  一个函数返回三元组（和/区间），比 `std::tuple` 可读、比出参引用安全，
  聚合初始化 `return {sum, lo, hi}` 一行完成；
- **`std::vector<std::vector<long long>>` 的取舍**：本章矩阵规模 ≤4，
  二维 vector 的清晰度优先；真实数值代码用一维平铺 + `i*n+j` 下标
  （缓存友好、可 `std::span` 化），第 29 章会那样写；
- **递归函数的计数器穿透**：`MatCounters&` 沿递归链传引用，代价统计
  汇总到顶层——后面每一章的分析实验都复用这个模式。

## 与 STL 对照

- `std::valarray`/`std::linalg`（C++26 落地中）是数值矩阵的方向，本章不用；
- 最大子数组无 STL 直接对应（`std::reduce` + 前缀和可做变体）；
- Strassen 的启示反而指向库设计：**BLAS 把「乘法次数最小化」做到了
  工程极致**，但小矩阵仍用朴素乘（cutoff 思想的工业化）。

## 坑位清单

1. **Strassen 公式转写错号（本示例真实翻车）**
   （现象：C22 算出 −102 而非 66，msvc/clang/gcc 三通道同一行 assert 齐炸；
   原因：把 C22 = P5+P1−P3−P7 写成了 `(P5+P1) − (P3 − P7)`——减法对
   括号内**负号分配**搞错，P7 前该是 −，写成了 +；后果：矩阵小错难肉眼
   发现（其他三个角全对）；对策：**永远与朴素乘法断言相等**再谈性能——
   本示例的 `assert(mat_eq(cStr, cNai))` 第一次运行就抓住了它。）
2. **跨界扫描的方向写反**
   （现象：max_crossing 返回的区间不含中点或漏最优；原因：左扫必须从 mid
   **递减**到 lo、右扫从 mid+1 递增到 hi，循环边界差一就丢解；后果：分治
   结果与暴力对不上；对策：三解法同数据对账 assert（本例 43/[7,10] 三方
   一致），跨界单独构造 mid 两侧一正一负的用例。）
3. **递归树按单节点记账**
   （现象：T(n)=2T(n/2)+n 的树被算成每层成本 n/2^i（只看一个节点的规模），
   总和 Θ(n)；原因：某层成本 = 该层**所有**节点成本之和——节点数 2^i 与
   单节点规模 n/2^i 相乘才是层成本；后果：渐近阶整个算错；对策：每层先数
   节点数、再乘单节点成本，像示例 04.3 那样逐层打印。）
4. **Kadane 用 0 初始化被全负数组击穿**
   （现象：全负输入返回 0（空子数组）而非最大元素；原因：`best=0` 隐含
   允许空段，CLRS 定义要求非空；后果：边界用例错答案；对策：用 a[0] 冷启动，
   示例的全负数组三解法对账 (−2,[3,3])。）
5. **主定理情形 3 忘验正则条件**
   （现象：对 f(n)=n²·lg n 之类硬套情形 3 得 Θ(n²lg n)——错；原因：情形 3
   要求 a·f(n/b) ≤ c·f(n)（c<1），非多项式差的 f 常不满足；后果：错的
   渐近阶一路传染到算法选型；对策：套情形 3 前显式验证正则式，像示例
   04.4 的判词里把 4·(n/2)³=n³/2 ≤ c·n³ 写出来。）
6. **左闭右开写成 `lo = mid`（死循环）**
   （现象：二分查找在某些输入上跑不完；原因：`a[mid] < target` 已证明
   `a[mid]` 不是答案，`lo = mid` 让区间不收缩；后果：死循环（旋转数组
   版本里更隐蔽——本教程实测在「根本没旋转」的 `[2,3,4,5]` 上 `mid` 恒等
   于 `lo` 卡死）；对策：写循环时逐分支自问「区间严格变小了吗」，左闭
   边界收缩要 `mid + 1`、右开边界收缩用 `mid` 本身。）
7. **闭区间与开区间两种写法凭记忆互换**
   （现象：把 `[lo, hi)` 的代码当 `[lo, hi]` 用，或反之，答案对一半错一半；
   原因：两种约定下两条边界的 ±1 完全不同，混用就 off-by-one；后果：漏
   元素或多跳一次；对策：换约定就**重新推一遍**不变式，别靠肌肉记忆。）
8. **旋转数组二分漏掉「相等」分支**
   （现象：带重复值的旋转数组上死循环（如 `[1,1,1,1]`）；原因：只写了
   `>` 与 `<` 两种判定，当 `a[mid] == a[hi]` 时两个分支都不走；后果：
   区间不收缩；对策：补第三条「无法判方向就缩右端」的分支，并专门用
   带重复值的输入做回归测试。）
9. **错误直觉：浮点值本身单调，所以可以三分/二分**
   （现象：把 f(B)=B/P(B) 当成单调函数去做二分或三分；原因：**目标值
   本身确实不单调**——上表实测 f 在 B=250 处是折点（5.102 ⟹ 4.615），
   分子增分母也增，增减方向不可预测；后果：二分收敛到错误答案，或者
   三分直接失效；对策：分清两件事——**判定**「f(B) ≥ r 是否可达」关于
   r 是单调的（这才是可二分的依据），**目标值** f(B) 本身不必单调。
   「二分答案」的正当性永远表述为「判定关于参数单调」。）
10. **错误直觉：「保留 3 位小数」= 浮点算完`setprecision(3)`**
   （现象：答案落在 .0005 这类舍入边界附近时最后一位与数学答案不一致，
   且换编译器/换优化级别就变；原因：0.0005 = 1/2000 在二进制里**不可
   精确表示**（分母 2000 = 2⁴·125 含因子 5），double 只能给近似值，
   最后一位由 IEEE 754 舍入规则决定；后果：答案对不上评测机；
   对策：**整数化**——把判定式乘 1000 变成 `k·P(B) ≤ 1000·B` 再二分整数
   k，全程零浮点，输出 `k/1000` 与补零的 `k%1000`。示例的边界实例
   （B/P = 1/2000）实测：整数化给出确定的 0.000，浮点路径只能给一个
   近似数 0.00050000000000000001。）
11. **错误直觉：整数化之后就万事大吉了**
   （现象：整数化版本在大数据上仍算出离谱答案，甚至两通道结果不同；
   原因：整数化消除了**浮点误差**，但判定式 `k·P(B) ≤ 1000·B` 的右端
   `1000·B` 在 B ~ 1e16 时就超过 int64 上限 9.22e18——「先算 1000·B 再
   比较」是**带符号溢出（UB）**，编译器有权按任意结果优化；后果：静默
   错误答案，且 `-O0`/`-O2` 表现不同；对策：**除后比**
   `k ≤ ⌊1000·B/P⌋`（把乘法换成除法与取模，且
   `⌊1000·B/P⌋ = (B/P)*1000 + (B%P)*1000/P`），判定式本身要独立复核时
   可升 unsigned（见正文）。宽类型 `__int128` 不是出路——MSVC
   没有它，本示例最初版本就在 MSVC 通道编译翻车。）
12. **比值比较用浮点商而非交叉相乘**
   （现象：比较两个「几乎相等」的比值时程序说它们相等，真值却分得开；
   原因：浮点商只有 53 位尾数，两个真值相差 ~1e-16 的分数会被舍入到
   **同一个** double（本例 100000001/100000000 与 100000002/100000001
   的 double 商完全相等，而交叉相乘 b₁p₂ > b₂p₁ 严格成立、差 1）；
   后果：排序/去重/取最优在边界数据上错；对策：**一律用交叉相乘**
   `b1 * p2 > b2 * p1`（乘积会溢出就改「除后比」）。凡出现
   「比较两个分式」的场合都要想到这条。）
13. **把 `__int128` 当可移植设施用**
   （现象：GCC/Clang 两通道全绿，MSVC 报 C4235「非标准扩展不支持」直接
   编译失败；原因：`__int128` 是 GCC/Clang 扩展，MSVC 没有——本示例的
   溢出演示与 `pow_checked` 最初版本都实测翻车；后果：主线通道编译不过，
   且容易被「本地能跑」掩盖；对策：可移植的溢出安全三板斧——除法预判
   （`acc > p / k`）、除后比、乘积落在缝隙里时升 unsigned；确需 128 位时
   按编译器分档（`_mul128`/`_umul128` vs `__int128`），并把「宽类型
   不可移植」写进坑位清单。）

  真实 max B/P                       = 5.10204082

边界实例（单设备：带宽 1、价格 2000 ⟹ B/P = 1/2000 = 0.0005）：
  整数化二分：k = 0 ⟹ 输出 0.000（截断到 3 位的**确定**答案）
  「k=1 可行吗」这个问题整数化回答得很干脆：
    1000·B = 1000·1 = 1000  vs  k·P(B) = 1·2000 = 2000 ⟹ 1000 < 2000 ⟹ 不可行
  浮点路径在同一处：0.0005 的 double 表示是 0.00050000000000000001，
  它既不等于精确的 1/2000，也无法告诉你输出该是 0.000 还是 0.001。

分数比较（不要用浮点直接比，用交叉相乘 b1*p2 > b2*p1）：
  b1/p1 = 100000001/100000000 = 1.0000000099999999
  b2/p2 = 100000002/100000001 = 1.0000000099999999
  浮点直接比 b1/p1 > b2/p2 = false（**错**：两个 double 完全相等，判不出大小）
  交叉相乘 b1*p2 > b2*p1 = true（对：10000000200000001 > 10000000200000000，差 1）
  真值：100000001/100000000 与100000002/100000001 只差 1 个交叉乘积单位，而 double 的
  53 位尾数根本表达不出这个差别（相对差 ≈ 1e-16，double 的 eps 量级内）。

溢出边界（整数化消除了浮点误差，但没消除整数溢出）：
  B = 1e16、P(B) = 3 ⟹ 判定右端 1000·B = 1e+19
  已超 int64 上限 9.22e18 ⟹ 在 long long 里算 1000·B 就是 UB。
  (b) 除后比（先除后乘，全程 long long 无溢出）：
      ⌊1000·B/P⌋ = (B/P)·1000 + ⌊(B mod P)·1000/P⌋
                 = 3333333333333333·1000 + 333 = 3333333333333333333
  (c) 升 unsigned 复核：k·P = 9999999999999999999 ，1000·B = 10000000000000000000
      两个乘积都落在 (int64 上限 9.22e18, uint64 上限 1.84e19)
      区间里 ⟹ signed 通道必炸、unsigned 恰好够 ⟹ k·P ≤ 1000·B = true
      换 (k+1)·P = 10000000000000000002 ⟹ (k+1)·P > 1000·B = true
  ⟹ unsigned 只是**碰巧**多扛一倍量级，不是通用答案；

      跨通道工程里宽类型是**坑**。
