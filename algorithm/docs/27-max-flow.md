# 27 · 最大流

> 对应 CLRS 第 26 章 *Maximum Flow*（英文 3rd ed. pp.708–766）。流网络 =
> 有向容量图 + 源 s + 汇 t。三问一体：**最大流**（能泵多少）、**最小割**
>（哪条瓶颈）、**对偶定理**（两者相等）——线性规划对偶在图上的化身，
> 也是「二分图匹配 / 项目挑选 / 图像分割」一大类问题的统一归约目标。

## 学习目标

1. 能定义流（容量约束、反对称、守恒）与残量网络；
2. 会实现 Edmonds-Karp（BFS 增广），理解 O(V·E²) 的来源；
3. 能陈述并验证最大流最小割定理（定理 26.6/26.7 的三合一：增广路尽头
   = 流 = 割）；
4. 会实现推送-重贴标签的骨架（preflow/高度函数/excess）；
5. 能用 Kuhn 增广路求二部图最大匹配，并援引 König 定理把最小点覆盖
   类问题（机器调度）直接化为匹配问题。

## 流、割、残量网络（§26.1）

**流** f: E→ℤ 满足：容量（0 ≤ f ≤ c）、反对称（f(u,v) = −f(v,u)）、
守恒（中间点进出相抵）。流值 |f| = s 的净出流。**割** (S, T) 把点集
二分（s ∈ S, t ∈ T），割容量 c(S,T) = Σ c(u,v)（u∈S, v∈T）。

**弱对偶**：任何流 ≤ 任何割（流过割的净量 ≤ 割容量）。于是「找到相等
的一对流与割」即同时证明两者最优——最大流最小割定理的证明骨架正是
如此：**残量网络无增广路 ⟹ 流最大 ⟹ 存在容量相等的割**（S = 残量图
中 s 可达点集）。

**残量网络**：c_f(u,v) = c(u,v) − f(u,v)——还剩多少可推；反向残量
= f(v,u) 的绝对值 = 「反悔额度」（把推过去的水收回来）。**增广路径**
= 残量图中 s→t 的路径；沿路推「瓶颈」量的流。

## Edmonds-Karp 实测（§26.2）

Ford-Fulkerson 的 BFS 特化（每次找**最短**增广路）：

> 图 26.1 的图内数字不在 PDF 文本层，无法可靠转写——本例改用 6 顶点
> 自造网络（s→a16, s→b10, a→c13, a→b1, b→c7, b→d9, c→t14, d→t9），
> 最大流 = 最小割 = 23，手算可验。

```
Edmonds-Karp（自造 6 顶点网络，BFS 最短增广路径）：
  增广路径 #1（瓶颈 13）: s→a→c→t（累计流 13）
  增广路径 #2（瓶颈 1）: s→b→c→t（累计流 14）
  增广路径 #3（瓶颈 9）: s→b→d→t（累计流 23）
  最大流 = 23（手算答案 23），共 4 轮 BFS（1 轮检测终止）
```

三条增广路把 23 泵满（13 + 1 + 9）。**合法性验证器**随后逐条核对：
每条边 0 ≤ f ≤ c、反对称、每个中间点净流为零、源的净出流 == 流值——
「流」的四条公理全过。**最小割**：残量图中 s 可达集 S = {s,a,b,c}，
割容量 = b→d 9 + c→t 14 = **23 = 最大流**——定理 26.6 现场兑现。

复杂度 O(V·E²)（定理 26.8/26.9：最短增广路的长度单调不降，每条
「关键边」至多饱和 V/2 次）。朴素 Ford-Fulkerson（DFS 增广）在容量
大时可以慢到 Θ(|f*|·E)——CLRS 图 26.7 的「1 滴 1 滴泵」反例。

## 推送-重贴标签（§26.4，preflow-push）

另一族算法：不找整条路径，让**超额流**（excess）在点间推来推去。
高度函数 h（h(s)=|V|，h(t)=0，残量边 h(u) ≤ h(v)+1）；**预流**允许
中间点有超额（先从 s 饱和推出）。两个原语：

- **PUSH(u→v)**：u 有超额且 h(u) = h(v)+1 且残量 > 0——推
  min(excess(u), c_f(u,v))；
- **RELABEL(u)**：推不动了——h(u) = 1 + min(h(v) : 残量>0)。

直觉：水往低处流，推不动就「把 u 垫高一格」。实测（同一网络，
FIFO 选取活跃点）：流值 23 = Edmonds-Karp，推送 17 次、重贴标签 12 次。
通用的 FIFO 版 O(V³)；最高标号（highest-label）版实践更快——
工程上 SAP/ISAP/Dinic 一路演进，二分图匹配场景 Dinic 仍是利器。

## 二部图匹配与最小点覆盖：König 定理

### 问题：两台机器的模式调度

两台计算机 A、B 分别有 n、m 种工作模式 mode_0～mode_n−1、
mode_0～mode_m−1，**开机时都处于 mode_0**。k 个任务各给出三元组
(id, x, y)：该任务可在 A 的 mode_x 或 B 的 mode_y 下处理。切换模式
必须关机重启。求完成所有任务的最少重启次数。

样例 10 个任务：

```
(0,0,0) (1,0,1) (2,0,2) (3,0,3) (4,1,0)
(5,1,1) (6,1,2) (7,1,3) (8,2,2) (9,3,2)
```

### 建模：任务是边、模式是点

关键观察一：**x=0 或 y=0 的任务白做**。两台机器开机即 mode_0，这些
任务在任何重启发生之前就能处理完——样例中的任务 0～4 全部如此，一个
重启都不用花。

关键观察二：剩下的任务构成二部图。左部 L = A 的 mode_1..mode_n−1，
右部 R = B 的 mode_1..mode_m−1，任务 (id, x, y) 就是边 A_x—B_y。
「在某个模式开机」= 选一个顶点，开机后该模式能处理的任务 = 与该点
相接的所有边。于是问题变成：**选最少的顶点，使每条边都至少有一个端点
被选中**——二部图的最小点覆盖。样例剩下的五条边，选 {A1, B2} 两个点
即可全覆盖：

```
A1─B1, A1─B2, A1─B3        （A1 覆盖任务 5,6,7）
A2─B2, A3─B2               （B2 覆盖任务 6,8,9）
```

对应的执行排法：开机先做任务 0～4；重启 A 到 mode_1 做 5,6,7；
重启 B 到 mode_2 做 8,9——共 2 次重启。

### König 定理与 Kuhn 增广路

二部图有一个一般图不具备的优美等价（**König 定理**）：

> **最大匹配的边数 = 最小点覆盖的点数。**

匹配是两两不共端点的边集。「≤」方向显然：任何点覆盖都必须为每条匹配
边单独付出一个点（它们端点互不重合）；「≥」方向是定理的实质——由一个
最大匹配出发可以构造出同样大小的覆盖（沿交替路从左部未匹配点出发做
BFS，取「左不在可达集 ∪ 右在可达集」即为最小覆盖）。

求最大匹配用 **Kuhn 算法**：依次尝试每个左部点 u，DFS 寻找一条从 u
开始、非匹配边与匹配边交替、终点是未匹配右部点的**增广路**；找到就沿
路翻转匹配关系，匹配数加 1。DFS 中用时间戳数组 `seen` 防止同一次搜索
绕圈，每次搜索换一个新 token，省掉反复清零：

```cpp
static bool kuhn_augment(const BipartiteGraph& g, int u, int token,
                         std::vector<int>& seen, std::vector<int>& match_r) {
    for (int v : g.adj[u]) {
        if (seen[v] == token) { continue; }
        seen[v] = token;
        if (match_r[v] < 0 ||
            kuhn_augment(g, match_r[v], token, seen, match_r)) {
            match_r[v] = u;
            return true;
        }
    }
    return false;
}
```

复杂度 O(VE)：每个左部点至多成功一次，失败的那次 DFS 扫遍邻接。
更大的图走 Dinic（本章前述最大流的二部图特例）可达 O(E√V)。

### 为什么不能「每次选当前任务最多的模式」

最大度贪婪（选当前基数最大的模式开机、删去其任务）在这个问题上有
两重错误：

1. **把开机时的 mode_0 也计作一次重启**。样例的贪婪过程第一轮选
   mode_0 处理任务 0～3 并计数 1，但机器本来就处在 mode_0——这一次
   重启纯属虚设，最终数出 3，而最优是 2。
2. **即使不计 mode_0，贪婪在一般图上也不最优**。枚举全部小二部图即可
   找到反例，最小的一个只有 3×3、四条边：L0 连 R0,R1；L1 连 R1；
   L2 连 R0。最小点覆盖 {R0,R1} 只要 2 个点；最大度贪婪先选度为 2 的
   L0，剩下两条孤立边还得各选一个点，共 3 个。

```
  3×3 反例（L0:R0,R1；L1:R1；L2:R0）：最小覆盖 = 2，最大度贪婪 = 3
```

3000 个随机小二部图的实测里，最大匹配与暴力枚举最小覆盖逐图一致
（König 定理的实证），而最大度贪婪有 117 例严格更差——「看起来
自然」的贪婪策略必须有证明才能用，这正是本案例与第 17 章各种被证明
的贪婪算法的差别所在。

## 归约的应用谱系

- **二分图最大匹配** = 加源汇、边容 1 的最大流（思考题 26-3）；
- **项目挑选**（收益-先决图）：最小割的最小化 −收益（思考题 26-4? 26-5）；
- **图像分割**：像素为点、s/t 为前景/背景标签，容量 = 偏好 + 平滑项
  ——GrabCut 的能量最小化内核；
- **网络可靠性 / 运输调度**：字面意义的最大流。

  反向边成对编号——竞赛标配 `head/next/to/cap` 数组，第 10 章 arena

## 坑位清单

1. **转写教材图数据（图内数字不在文本层）**
   （现象：照记忆抄的容量矩阵跑出的「最大流」与书上答案对不上；
   原因：图的数字是图像不是文本，记忆不可靠；对策：用**手算可验的
   自造网络**替换 + 文档注明（本例的处置）；或从题库找文字化数据。）
2. **反向流没记负值**
   （现象：反对称断言挂、增广时反悔额度丢失；原因：只写 f[u][v] += d
   忘了 f[v][u] −= d——残量网络的反向边就建在这上面；对策：增广循环
   两行成对写，验证器的反对称断言兜底（本例实测防线）。）
3. **BFS 终止条件用「队列空」而非「t 已标记」**
   （现象：功能对但多做无用 BFS；原因：找到 t 即可停——最短路性质
   已定；对策：`while (!q.empty() && parent[t] == -1)`（本例写法），
   与第 23 章 BFS 的「发现即入队」纪律配套。）
4. **最小割的 S 集用「正边可达」算错**
   （现象：割容量 > 最大流；原因：可达性要在**残量网络**上算（含
   反向残量边）——用原容量图算出的 S 不满足「割边全饱和」；对策：
   残量判据 `c[u][v] − f[u][v] > 0`（本例写法），并断言割容量 == 流值。）
5. **推送-重贴标签忘预流初始化 h[s] = n**
   （现象：算法推两下就死锁；原因：h(s) 必须高于全部点，s 的水才有
   「势能」流出（且永不回流——s 不可再被推高）；对策：初始化段
   h[s]=n + s 出边全饱和（本例写法）。）
6. **把开机时的 mode_0 计成一次重启**
   （现象：答案系统性多 1；原因：两台机器开机即处于 mode_0，x=0 或
   y=0 的任务在任何重启发生前就能做完——它们根本不进需要覆盖的边集；
   对策：建图前直接丢弃 x=0∨y=0 的任务（本例写法），模式下标也相应
   平移成 1 基。）
7. **拿最大度贪婪当最优算法**
   （现象：样例都过、评测 WA；原因：「选任务最多的模式」只是可行
   覆盖，没有最优性证明，且确有反例（3×3 图：最优 2、贪婪 3）；
   对策：二部图最小点覆盖走 König——最大匹配即答案，Kuhn/Dinic
   实现；并保留贪婪实现仅作对照。）
8. **DFS 反复重新分配访问数组**
   （现象：结果对但常数大、高频图上超时；原因：每次增广搜索都清空
   一个 visited 数组是 O(V) 的额外摊派；原因反面：不清空又会把上次
   搜索的结论带进来、错失调变；对策：时间戳数组 + 单调 token
   （本例 `seen[v] == token` 写法），一次 O(1) 换新搜索。）
