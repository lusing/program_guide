# 27 · 最大流

> 对应 CLRS 第 26 章 *Maximum Flow*（英文 3rd ed. pp.708–766）。流网络 =
> 有向容量图 + 源 s + 汇 t。三问一体：**最大流**（能泵多少）、**最小割**
>（哪条瓶颈）、**对偶定理**（两者相等）——线性规划对偶在图上的化身，
> 也是「二分图匹配 / 项目挑选 / 图像分割」一大类问题的统一归约目标。

## 学习目标

1. 能定义流（容量约束、反对称、守恒）与残量网络；
2. 会实现 Edmonds-Karp（BFS 增广），理解 O(V·E²) 的来源；
3. 能陈述并验证最大流最小割定理（定理 26.6/26.7 的三合一：增广路尽头
   = 流 = 割）；
4. 会实现推送-重贴标签的骨架（preflow/高度函数/excess）。

## 流、割、残量网络（§26.1）

**流** f: E→ℤ 满足：容量（0 ≤ f ≤ c）、反对称（f(u,v) = −f(v,u)）、
守恒（中间点进出相抵）。流值 |f| = s 的净出流。**割** (S, T) 把点集
二分（s ∈ S, t ∈ T），割容量 c(S,T) = Σ c(u,v)（u∈S, v∈T）。

**弱对偶**：任何流 ≤ 任何割（流过割的净量 ≤ 割容量）。于是「找到相等
的一对流与割」即同时证明两者最优——最大流最小割定理的证明骨架正是
如此：**残量网络无增广路 ⟹ 流最大 ⟹ 存在容量相等的割**（S = 残量图
中 s 可达点集）。

**残量网络**：c_f(u,v) = c(u,v) − f(u,v)——还剩多少可推；反向残量
= f(v,u) 的绝对值 = 「反悔额度」（把推过去的水收回来）。**增广路径**
= 残量图中 s→t 的路径；沿路推「瓶颈」量的流。

## Edmonds-Karp 实测（§26.2）

Ford-Fulkerson 的 BFS 特化（每次找**最短**增广路）：

> 图 26.1 的图内数字不在 PDF 文本层，无法可靠转写——本例改用 6 顶点
> 自造网络（s→a16, s→b10, a→c13, a→b1, b→c7, b→d9, c→t14, d→t9），
> 最大流 = 最小割 = 23，手算可验。

```
Edmonds-Karp（自造 6 顶点网络，BFS 最短增广路径）：
  增广路径 #1（瓶颈 13）: s→a→c→t（累计流 13）
  增广路径 #2（瓶颈 1）: s→b→c→t（累计流 14）
  增广路径 #3（瓶颈 9）: s→b→d→t（累计流 23）
  最大流 = 23（手算答案 23），共 4 轮 BFS（1 轮检测终止）
```

三条增广路把 23 泵满（13 + 1 + 9）。**合法性验证器**随后逐条核对：
每条边 0 ≤ f ≤ c、反对称、每个中间点净流为零、源的净出流 == 流值——
「流」的四条公理全过。**最小割**：残量图中 s 可达集 S = {s,a,b,c}，
割容量 = b→d 9 + c→t 14 = **23 = 最大流**——定理 26.6 现场兑现。

复杂度 O(V·E²)（定理 26.8/26.9：最短增广路的长度单调不降，每条
「关键边」至多饱和 V/2 次）。朴素 Ford-Fulkerson（DFS 增广）在容量
大时可以慢到 Θ(|f*|·E)——CLRS 图 26.7 的「1 滴 1 滴泵」反例。

## 推送-重贴标签（§26.4，preflow-push）

另一族算法：不找整条路径，让**超额流**（excess）在点间推来推去。
高度函数 h（h(s)=|V|，h(t)=0，残量边 h(u) ≤ h(v)+1）；**预流**允许
中间点有超额（先从 s 饱和推出）。两个原语：

- **PUSH(u→v)**：u 有超额且 h(u) = h(v)+1 且残量 > 0——推
  min(excess(u), c_f(u,v))；
- **RELABEL(u)**：推不动了——h(u) = 1 + min(h(v) : 残量>0)。

直觉：水往低处流，推不动就「把 u 垫高一格」。实测（同一网络，
FIFO 选取活跃点）：流值 23 = Edmonds-Karp，推送 17 次、重贴标签 12 次。
通用的 FIFO 版 O(V³)；最高标号（highest-label）版实践更快——
工程上 SAP/ISAP/Dinic 一路演进，二分图匹配场景 Dinic 仍是利器。

## 归约的应用谱系

- **二分图最大匹配** = 加源汇、边容 1 的最大流（思考题 26-3）；
- **项目挑选**（收益-先决图）：最小割的最小化 −收益（思考题 26-4? 26-5）；
- **图像分割**：像素为点、s/t 为前景/背景标签，容量 = 偏好 + 平滑项
  ——GrabCut 的能量最小化内核；
- **网络可靠性 / 运输调度**：字面意义的最大流。

## 坑位清单

1. **转写教材图数据（图内数字不在文本层）**
   （现象：照记忆抄的容量矩阵跑出的「最大流」与书上答案对不上；
   原因：图的数字是图像不是文本，记忆不可靠；对策：用**手算可验的
   自造网络**替换 + 文档注明（本例的处置）；或从题库找文字化数据。）
2. **反向流没记负值**
   （现象：反对称断言挂、增广时反悔额度丢失；原因：只写 f[u][v] += d
   忘了 f[v][u] −= d——残量网络的反向边就建在这上面；对策：增广循环
   两行成对写，验证器的反对称断言兜底（本例实测防线）。）
3. **BFS 终止条件用「队列空」而非「t 已标记」**
   （现象：功能对但多做无用 BFS；原因：找到 t 即可停——最短路性质
   已定；对策：`while (!q.empty() && parent[t] == -1)`（本例写法），
   与第 23 章 BFS 的「发现即入队」纪律配套。）
4. **最小割的 S 集用「正边可达」算错**
   （现象：割容量 > 最大流；原因：可达性要在**残量网络**上算（含
   反向残量边）——用原容量图算出的 S 不满足「割边全饱和」；对策：
   残量判据 `c[u][v] − f[u][v] > 0`（本例写法），并断言割容量 == 流值。）
5. **推送-重贴标签忘预流初始化 h[s] = n**
   （现象：算法推两下就死锁；原因：h(s) 必须高于全部点，s 的水才有
   「势能」流出（且永不回流——s 不可再被推高）；对策：初始化段
   h[s]=n + s 出边全饱和（本例写法）。）
