# 27 · 最大流

> 对应 CLRS 第 26 章 *Maximum Flow*（英文 3rd ed. pp.708–766）。流网络 =
> 有向容量图 + 源 s + 汇 t。三问一体：**最大流**（能泵多少）、**最小割**
>（哪条瓶颈）、**对偶定理**（两者相等）——线性规划对偶在图上的化身，
> 也是「二分图匹配 / 项目挑选 / 图像分割」一大类问题的统一归约目标。

## 学习目标

1. 能定义流（容量约束、反对称、守恒）与残量网络；
2. 会实现 Edmonds-Karp（BFS 增广），理解 O(V·E²) 的来源；
3. 能陈述并验证最大流最小割定理（定理 26.6/26.7 的三合一：增广路尽头
   = 流 = 割）；
4. 会实现推送-重贴标签的骨架（preflow/高度函数/excess）；
5. 能用 Kuhn 增广路求二部图最大匹配，并援引 König 定理把最小点覆盖
   类问题（机器调度）直接化为匹配问题；
6. 会用 α = n − ν 求二部图最大独立集（女孩与男孩），并能识破
   「染色后分量取大」这一貌似合理、实则依赖 Hall 条件的伪论证；
7. 会用**顶点拆点**（v_in → v_out 容量 1）表达「每个参与者至多被
   用一次」的节点容量，从而把食物—牛妞—饮料三方独占问题
   （午餐）建成多层流网络，并能指出食物↔饮料直接匹配错在哪；
8. 会把运输型分配问题（慈善捐款：人/对/院三层上限）建成三层流网络，
   并用「枚举全部 S-T 割」的最小割口径独立对账。

## 流、割、残量网络（§26.1）

**流** f: E→ℤ 满足：容量（0 ≤ f ≤ c）、反对称（f(u,v) = −f(v,u)）、
守恒（中间点进出相抵）。流值 |f| = s 的净出流。**割** (S, T) 把点集
二分（s ∈ S, t ∈ T），割容量 c(S,T) = Σ c(u,v)（u∈S, v∈T）。

**弱对偶**：任何流 ≤ 任何割（流过割的净量 ≤ 割容量）。于是「找到相等
的一对流与割」即同时证明两者最优——最大流最小割定理的证明骨架正是
如此：**残量网络无增广路 ⟹ 流最大 ⟹ 存在容量相等的割**（S = 残量图
中 s 可达点集）。

**残量网络**：c_f(u,v) = c(u,v) − f(u,v)——还剩多少可推；反向残量
= f(v,u) 的绝对值 = 「反悔额度」（把推过去的水收回来）。**增广路径**
= 残量图中 s→t 的路径；沿路推「瓶颈」量的流。

## Edmonds-Karp 实测（§26.2）

Ford-Fulkerson 的 BFS 特化（每次找**最短**增广路）：

> 图 26.1 的图内数字不在 PDF 文本层，无法可靠转写——本例改用 6 顶点
> 自造网络（s→a16, s→b10, a→c13, a→b1, b→c7, b→d9, c→t14, d→t9），
> 最大流 = 最小割 = 23，手算可验。

```
Edmonds-Karp（自造 6 顶点网络，BFS 最短增广路径）：
  增广路径 #1（瓶颈 13）: s→a→c→t（累计流 13）
  增广路径 #2（瓶颈 1）: s→b→c→t（累计流 14）
  增广路径 #3（瓶颈 9）: s→b→d→t（累计流 23）
  最大流 = 23（手算答案 23），共 4 轮 BFS（1 轮检测终止）
```

三条增广路把 23 泵满（13 + 1 + 9）。**合法性验证器**随后逐条核对：
每条边 0 ≤ f ≤ c、反对称、每个中间点净流为零、源的净出流 == 流值——
「流」的四条公理全过。**最小割**：残量图中 s 可达集 S = {s,a,b,c}，
割容量 = b→d 9 + c→t 14 = **23 = 最大流**——定理 26.6 现场兑现。

复杂度 O(V·E²)（定理 26.8/26.9：最短增广路的长度单调不降，每条
「关键边」至多饱和 V/2 次）。朴素 Ford-Fulkerson（DFS 增广）在容量
大时可以慢到 Θ(|f*|·E)——CLRS 图 26.7 的「1 滴 1 滴泵」反例。

## 推送-重贴标签（§26.4，preflow-push）

另一族算法：不找整条路径，让**超额流**（excess）在点间推来推去。
高度函数 h（h(s)=|V|，h(t)=0，残量边 h(u) ≤ h(v)+1）；**预流**允许
中间点有超额（先从 s 饱和推出）。两个原语：

- **PUSH(u→v)**：u 有超额且 h(u) = h(v)+1 且残量 > 0——推
  min(excess(u), c_f(u,v))；
- **RELABEL(u)**：推不动了——h(u) = 1 + min(h(v) : 残量>0)。

直觉：水往低处流，推不动就「把 u 垫高一格」。实测（同一网络，
FIFO 选取活跃点）：流值 23 = Edmonds-Karp，推送 17 次、重贴标签 12 次。
通用的 FIFO 版 O(V³)；最高标号（highest-label）版实践更快——
工程上 SAP/ISAP/Dinic 一路演进，二分图匹配场景 Dinic 仍是利器。

## 二部图匹配与最小点覆盖：König 定理

### 问题：两台机器的模式调度

两台计算机 A、B 分别有 n、m 种工作模式 mode_0～mode_n−1、
mode_0～mode_m−1，**开机时都处于 mode_0**。k 个任务各给出三元组
(id, x, y)：该任务可在 A 的 mode_x 或 B 的 mode_y 下处理。切换模式
必须关机重启。求完成所有任务的最少重启次数。

样例 10 个任务：

```
(0,0,0) (1,0,1) (2,0,2) (3,0,3) (4,1,0)
(5,1,1) (6,1,2) (7,1,3) (8,2,2) (9,3,2)
```

### 建模：任务是边、模式是点

关键观察一：**x=0 或 y=0 的任务白做**。两台机器开机即 mode_0，这些
任务在任何重启发生之前就能处理完——样例中的任务 0～4 全部如此，一个
重启都不用花。

关键观察二：剩下的任务构成二部图。左部 L = A 的 mode_1..mode_n−1，
右部 R = B 的 mode_1..mode_m−1，任务 (id, x, y) 就是边 A_x—B_y。
「在某个模式开机」= 选一个顶点，开机后该模式能处理的任务 = 与该点
相接的所有边。于是问题变成：**选最少的顶点，使每条边都至少有一个端点
被选中**——二部图的最小点覆盖。样例剩下的五条边，选 {A1, B2} 两个点
即可全覆盖：

```
A1─B1, A1─B2, A1─B3        （A1 覆盖任务 5,6,7）
A2─B2, A3─B2               （B2 覆盖任务 6,8,9）
```

对应的执行排法：开机先做任务 0～4；重启 A 到 mode_1 做 5,6,7；
重启 B 到 mode_2 做 8,9——共 2 次重启。

### König 定理与 Kuhn 增广路

二部图有一个一般图不具备的优美等价（**König 定理**）：

> **最大匹配的边数 = 最小点覆盖的点数。**

匹配是两两不共端点的边集。「≤」方向显然：任何点覆盖都必须为每条匹配
边单独付出一个点（它们端点互不重合）；「≥」方向是定理的实质——由一个
最大匹配出发可以构造出同样大小的覆盖（沿交替路从左部未匹配点出发做
BFS，取「左不在可达集 ∪ 右在可达集」即为最小覆盖）。

求最大匹配用 **Kuhn 算法**：依次尝试每个左部点 u，DFS 寻找一条从 u
开始、非匹配边与匹配边交替、终点是未匹配右部点的**增广路**；找到就沿
路翻转匹配关系，匹配数加 1。DFS 中用时间戳数组 `seen` 防止同一次搜索
绕圈，每次搜索换一个新 token，省掉反复清零：

```cpp
static bool kuhn_augment(const BipartiteGraph& g, int u, int token,
                         std::vector<int>& seen, std::vector<int>& match_r) {
    for (int v : g.adj[u]) {
        if (seen[v] == token) { continue; }
        seen[v] = token;
        if (match_r[v] < 0 ||
            kuhn_augment(g, match_r[v], token, seen, match_r)) {
            match_r[v] = u;
            return true;
        }
    }
    return false;
}
```

复杂度 O(VE)：每个左部点至多成功一次，失败的那次 DFS 扫遍邻接。
更大的图走 Dinic（本章前述最大流的二部图特例）可达 O(E√V)。

### 为什么不能「每次选当前任务最多的模式」

最大度贪婪（选当前基数最大的模式开机、删去其任务）在这个问题上有
两重错误：

1. **把开机时的 mode_0 也计作一次重启**。样例的贪婪过程第一轮选
   mode_0 处理任务 0～3 并计数 1，但机器本来就处在 mode_0——这一次
   重启纯属虚设，最终数出 3，而最优是 2。
2. **即使不计 mode_0，贪婪在一般图上也不最优**。枚举全部小二部图即可
   找到反例，最小的一个只有 3×3、四条边：L0 连 R0,R1；L1 连 R1；
   L2 连 R0。最小点覆盖 {R0,R1} 只要 2 个点；最大度贪婪先选度为 2 的
   L0，剩下两条孤立边还得各选一个点，共 3 个。

```
  3×3 反例（L0:R0,R1；L1:R1；L2:R0）：最小覆盖 = 2，最大度贪婪 = 3
```

3000 个随机小二部图的实测里，最大匹配与暴力枚举最小覆盖逐图一致
（König 定理的实证），而最大度贪婪有 117 例严格更差——「看起来
自然」的贪婪策略必须有证明才能用，这正是本案例与第 17 章各种被证明
的贪婪算法的差别所在。

## 女孩与男孩：二部图最大独立集

### 问题

一群学生中，「罗曼蒂克关系」只定义在一个女孩与一个男孩之间。要找出
人数最多的学生集合，使其中**任意两人之间都没有罗曼蒂克关系**，输出
这个人数。

### 建模：从「不选」一侧看破译

把学生画作顶点、关系画作边。关系只跨两性 ⟹ 图是**无向二部图**；
「集合内任意两人无边」正是**独立集**的定义，问题即求最大独立集 α。

对任意图（不限二部）都成立一个补集恒等式：

> **S 是独立集 ⟺ V−S 是点覆盖**（每条边不可能两端都在 S 中
> ⟺ 每条边至少有一端不在 S 中）。

于是 α = n − τ，τ 为最小点覆盖的点数；对二部图再用 König：
τ = ν（最大匹配边数）。两式合一就是本题的解法：

> **α = n − ν。**

做法完全机械：BFS 二染色把连通分量的两性分开（颜色 0/1；孤立点
一律颜色 0）；以颜色 0 为左部、颜色 1 为右部，把边定向后跑上一节的
Kuhn 求 ν，答案打印 n − ν。孤立点不与任何边相接、永远不被匹配，
却被 n 自动计入——不需要为它们写特殊分支。

复杂度继承 Kuhn：O(VE)；大图换 Dinic 为 O(E√V)。

### 一个貌似更直接的伪证：染色后分量取大

「每个连通分量二染色，取人数较多的一色，各分量相加」——这个构造
给出的确实是一个独立集（同色无边、跨分量无边），但它**不一定最大**。
它恰好最优的充要条件是：每个分量里较小的一侧能被匹配全部占满
（该侧满足 Hall 婚配条件），此时 ν 恰为较小侧人数，n_C − ν 才等于
较大侧人数。一般二部图并不满足。

最小的连通反例只有 7 个顶点（左 4 右 3）：

```
        R0   R1   R2
 L0 ─── ●────●────●
 L1 ─── ●
 L2 ─── ●
 L3 ─── ●
 边：L0–R0, L1–R0, L2–R0, L3–R0, L0–R1, L0–R2
```

图是连通的，两侧 4 与 3，染色取大只得 4。但匹配 ν = 2：R1、R2 都
只连 L0，二者只能有一个与 L0 配对，剩下 L1～L3 还要和它争 R0
（R0 只够配一个），任增广路都找不到第 3 条匹配边。于是 α = 7−2 = **5**，
显式见证为 `{L1, L2, L3, R1, R2}`——五人之间确实一条边也没有。
取大法的病根是它只能「整边站」：最优独立集可以在分量内部沿局部结构
**换边**（这里把 L0 换成 R1、R2 两人），而不是非选整侧不可。

2000 个随机二部图（n≤12，顶点再随机重编号）的实测中，n−ν 与 2ⁿ
暴力枚举逐图一致（0 例不一致），而染色取大有 **26 例严格偏小**
——样例数据恰好结构良好、两法同数，这也是伪证最容易蒙混过关的
情形：**「构造出一个可行解」与「证明它最优」之间，隔着一条 Hall
定理。**

> 实现上还有一个会把伪证变成崩溃的陷阱：无向图邻接表必须为每条边
> 存**两个方向**。若只存 L→R 单向弧，BFS 染色时后扫到的起点可能与
> 邻点都被染成颜色 0；随后按颜色分左右部时，这个「右点」拿到的右部
> 下标会越界，Kuhn 在 `seen[v]` 处直接访问违例。本例的随机测试最初
> 就以 0xC0000005 崩溃，补入反向弧后消失。

## 午餐：把「一份食物 + 一杯饮料 + 一头牛妞」压进一条流路

### 问题

农夫做了 F 种食物（每种**一份**）、准备了 D 种饮料（每种**一杯**）。
N 头牛妞各自只接受某些食物和某些饮料；一头牛妞只有**同时**拿到
一份她喜欢的食物**和**一杯她喜欢的饮料才算满意。食物、饮料都
不能共享。求最多能让多少头牛妞满意。

### 先看一个貌似直接的模型：食物↔饮料匹配

把食物放左侧、饮料放右侧，牛妞喜欢的「食物—饮料」搭配连边，
求最大匹配——容量 1 保证了食物、饮料不共享，看似正好。

**它漏掉了牛妞也是独占资源。** 设想只有一头牛妞，她喜欢全部
2 种食物和全部 2 种饮料：四条搭配都连边，匹配能同时取
(food1,drink1) 与 (food2,drink2)，匹配数为 2。但只有一头牛妞，
答案只能是 1——**两条匹配边落在同一头牛妞身上，而匹配对此
毫无约束。**

### 正确模型：牛妞拆成两个点

为了让流能「点名」牛妞，并且让每头牛妞至多承载一个单位流，
把每头牛妞 i 拆成两个节点 **cow_in[i] → cow_out[i]，容量 1**，
然后按四层布局连边：

```
            容量1        容量1        容量1       容量1
s ─────▶ food(f) ─────▶ cow_in(i) ─▶ cow_out(i) ─────▶ drink(d) ─────▶ t
        每种食物一份   i 喜欢 f      每牛妞至多1    i 喜欢 d    每杯饮料一份
```

- `s → food`：每种食物只有一份；
- `food f → cow_in[i]`：当且仅当牛妞 i 喜欢食物 f；
- `cow_in[i] → cow_out[i]`：**每头牛妞至多被满足一次**；
- `cow_out[i] → drink d`：当且仅当 i 喜欢饮料 d；
- `drink → t`：每种饮料只有一杯。

除两条「喜欢」边外，所有边容量都是 1。一条 `s → t` 的单位流路
恰好读出一份完整分配：哪份食物、给了谁、配哪杯饮料；四层
容量 1 **同时**强制了食物、牛妞、饮料三方互不共享。整数流定理
保证最大流可以取整数值，最大流值就是满意牛妞数。

### 为什么必须「拆」而不能直接用牛妞节点

若只放一个牛妞节点、食物连进来、饮料连出去，节点本身没有
容量：流守恒允许**两股**流从不同食物进入、再分头流向两杯
饮料，守恒照样满足，一头牛妞被计了两次。「顶点有容量 c」的
通用处理就是拆点 gadget：

> 将顶点 v 换成 v_in 与 v_out，凡进入 v 的边改接 v_in，凡从
> v 出发的边改从 v_out 出发，再加 v_in → v_out，容量 = c(v)。

边不相交路径改求**顶点不相交路径**、节点带通过能力的运输网，
用的都是这同一个装置。

### 对账

三个确定性案例：样例（4/3/3，答案 3）、单牛妞全喜欢
（食物↔饮料匹配误报 2，拆点流为 1）、两头牛妞只接受同一对
（答案 1）。每个网络都过流公理验证器。2000 个随机小例
（n ≤ 4，F,D ≤ 3）与暴力枚举（每头牛妞在「放弃」或其喜欢的
全部食物×饮料搭配中选一项，再查冲突）0 例不一致；300 个
随机大例（n,F,D ≤ 100）答案均不超过 min(N,F,D)，且逐头
配對的贪心结果从不超过最大流。

## 最小费用最大流

### 问题与模型

每条边除容量外还有**单位费用** cost：1 单位流经过它要付 cost。
要求在 s→t 流量达到指定值（或取最大流）的前提下总费用最小。
应用面：运输调度（路有运价）、指派问题、配电网损耗等——容量
决定"能送多少"，费用决定"走哪条划算"。

### 残量网络的关键：反向边费用取负

邻接表存边，加一条 `from→to`（容量 cap、费用 cost）时同时加入
反向边（容量 0、费用 **−cost**）。正向边送过流以后，反向残量
边允许"退流"：把先前送的单位撤回来，之前付的钱也要**全额
退回**，所以它的费用必须是相反数。

原始费用非负时，残量网络里虽有负边，却不会出现负环（一个环
若全由残量边构成，等价于对当前流做一次不改变流量的调整；
流已是同流量下最优 ⟺ 残量无负环）。

### 逐次最短路（successive shortest path）

每一轮：

1. 在残量网络上求 s→t 的**费用最短路** P。因为有负权边，用
   SPFA（队列化 Bellman-Ford：只有被成功松弛的点才入队）；
2. 沿 P 取残量瓶颈 d，增广 d 单位；
3. 累计费用 `cost ← cost + d·dist[t]`；
4. dist[t] 不可达即已达最大流，停止。

确定例 1：便宜路 s→a→t 单位费用 8、容量 3（增广 3，费用 24），
饱和后只能走 s→b→t 单位 16（增广 4，费用 64），总费用 88。

确定例 2（退流改道）：第 1 单位走 s→1→2→t（费用 4），把
2→t 占满；第 2 单位走 `s→2 → 反向边 2→1（费用 −1）→ 1→t`，
单位费用 4−1+100=103。−1 这一跳把第一次支付中 1→2 段的费用
退回，先前那单位改走 1→t——最终等价于 s→1→t(101) 与
s→2→t(6) 同时存在，总费用 107。**没有反向负边，这种改道
根本表达不出来。**

### 为什么逐次贪心恰好最优

整数容量下，若当前流是"流量 f 下的最小费用流"，沿费用最短
增广路加 d 单位，得到的就是"流量 f+d 下的最小费用流"：
否则存在更便宜的 f+d 流，两个流之差是残量网络中的环流加一
条 s→t 路，其中 s→t 段的费用不可能比最短路更低，矛盾。
这就是逐次最短路的最优性依据。

### 对账

示例对 4 节点网络逐流量（f=1..fmax）与**边流量整数枚举**
（每条正向边流量取 0..cap，叶端查守恒、记录每个流量的最小
费用）对账；2000 个随机例 0 例不一致；50 节点大例的流量
与无费用 Edmonds-Karp 最大流一致。

## 方格取数：最大权独立集的最小割构造

### 问题

m×n 方格，每格有一个权值。选若干格，使任意两个被选格
**不共边**（上下左右相邻只能取其一），求权值和最大的方案。

### 棋盘染色：网格天然二部

按 `(x+y) 奇偶`染色后，每条共边关系都恰好跨黑、白两色。
每个格子建一个节点，外加源 s、汇 t：

```
s → 黑格：容量 = 该格权值
白格 → t：容量 = 该格权值
黑格 → 每个相邻白格：容量 = ∞
```

∞ 取 **total+1**（total 为全部权值之和）：任何割的容量都不
超过 total（全弃黑或全选白都只值 total），所以最小割必然
不会切断 ∞ 边。于是"黑格在 s 侧、相邻白格在 t 侧"这种
∞ 跨越被禁止，割两侧读出的取法自动没有相邻对；割容恰好
等于**被放弃的权值**，故

```
最优权值 = total − 最大流
```

### 方案还原：残量可达性，白格方向相反

最大流跑完后，在残量网络里从 s 做一次可达性标记：

- **黑格：可达（在 s 侧）⟹ 入选**（s→它没被切）；
- **白格：不可达（在 t 侧）⟹ 入选**（它→t 没被切）。

白格的方向与黑格相反，是最容易写反的地方。

3×3 例（总权 603）最大流 220，最优权 383，选中 (0,1)、
(2,0)、(2,2) 三格（权 250+75+58），与 2⁹ 子集枚举一致。

### 对账与边界

示例用 2000 个 2~3×2~3 随机棋盘同时核对**最优值**（全子集
枚举）与**方案合法性**（被选格两两曼哈顿距离不为 1、权值
合计恰为答案）；40×40 大例验证答案介于"单色可行解"与总权
之间。该构造是"二部图最大权独立集 = 总权 − 最小权点覆盖
= 总权 − 最大流"的标准归约；一般图没有二部结构，这一
切不成立（第 34 章 NP 完全）。

## 慈善捐款：运输问题的流建模（27.11）

n 位捐款人、k 家孤儿院：人 i 的总捐款上限 d_i；人 i 对院 j 的指定
上限 c_ij（「最多只肯给这家捐这么多」）；院 j 接受总额上限 o_j
（公平条款，防一家独占）。求**总捐款最大**的分配。

三层约束（每人的总额、每对人的指定额、每院的总额）在 LP 里要三组
不等式，在流网络里只是**三排边**：

> S → 人_i（容量 d_i）→ 院_j（容量 c_ij）→ T（容量 o_j）

「容量」正是流网络的母语——每层上限天然表达在边上，最大化总流量
= 最大化总捐款，Edmonds-Karp 直接出答案与分配方案（读正向边的
flow）。

固定例（3 人各 10、2 院 8+12、指定上限 [6,4]/[0,8]/[5,0]）：

```
=== 27.11 慈善捐款：运输问题的最大流（S→人→院→T）===
  固定例（3 人 2 院，人额 10×3、院额 8+12）：最大总捐款 20（= 两院饱和）
  分配方案（人→院 : 额度）：
    人1→院1 : 6
    人1→院2 : 4
    人2→院2 : 8
    人3→院1 : 2
  （容量/守恒/反对称合法性 = 1；逐人不超额、逐院不超额见下）
  随机 200 例（n,k≤4）：最大流 vs 最小割枚举不一致 0 例
  大例（60 人 40 院）：最大总捐款 1270（供 1744 需 1270，上界 1270）
```

两院恰好饱和（8+12=20）：瓶颈在院方。人 3 只捐出 2——它的指定上限
（5/0）与两院剩余额度共同卡住了它。

### 对账：最大流 = 最小割（枚举版）

小实例（n,k ≤ 4，中间点 ≤ 8）可**枚举全部 2^(n+k) 个割**：把中间点
二分为源侧/汇侧，割容量 = Σ（源侧被切的人额）+ Σ（跨侧的指定额）+
Σ（汇侧被切的院额）。最小割与 Edmonds-Karp 的流值在 200 个随机例上
0 例不一致——最大流最小割定理被当成**对账工具**使用（两条独立推理
链：增广 vs 组合枚举）。大例 60 人 40 院只跑 EK：流值 1270 恰等于
「院方总需求 1270」这一显然上界，且流合法性四公理全过。

## 归约的应用谱系

- **二分图最大匹配** = 加源汇、边容 1 的最大流（思考题 26-3）；

- **慈善捐款 / 运输问题**（27.11）：三层上限（人/对/院）全部写成边容量。

## 坑位清单

1. **转写教材图数据（图内数字不在文本层）**
   （现象：照记忆抄的容量矩阵跑出的「最大流」与书上答案对不上；
   原因：图的数字是图像不是文本，记忆不可靠；对策：用**手算可验的
   自造网络**替换 + 文档注明（本例的处置）；或从题库找文字化数据。）
2. **反向流没记负值**
   （现象：反对称断言挂、增广时反悔额度丢失；原因：只写 f[u][v] += d
   忘了 f[v][u] −= d——残量网络的反向边就建在这上面；对策：增广循环
   两行成对写，验证器的反对称断言兜底（本例实测防线）。）
3. **BFS 终止条件用「队列空」而非「t 已标记」**
   （现象：功能对但多做无用 BFS；原因：找到 t 即可停——最短路性质
   已定；对策：`while (!q.empty() && parent[t] == -1)`（本例写法），
   与第 23 章 BFS 的「发现即入队」纪律配套。）
4. **最小割的 S 集用「正边可达」算错**
   （现象：割容量 > 最大流；原因：可达性要在**残量网络**上算（含
   反向残量边）——用原容量图算出的 S 不满足「割边全饱和」；对策：
   残量判据 `c[u][v] − f[u][v] > 0`（本例写法），并断言割容量 == 流值。）
5. **推送-重贴标签忘预流初始化 h[s] = n**
   （现象：算法推两下就死锁；原因：h(s) 必须高于全部点，s 的水才有
   「势能」流出（且永不回流——s 不可再被推高）；对策：初始化段
   h[s]=n + s 出边全饱和（本例写法）。）
6. **把开机时的 mode_0 计成一次重启**
   （现象：答案系统性多 1；原因：两台机器开机即处于 mode_0，x=0 或
   y=0 的任务在任何重启发生前就能做完——它们根本不进需要覆盖的边集；
   对策：建图前直接丢弃 x=0∨y=0 的任务（本例写法），模式下标也相应
   平移成 1 基。）
7. **拿最大度贪婪当最优算法**
   （现象：样例都过、评测 WA；原因：「选任务最多的模式」只是可行
   覆盖，没有最优性证明，且确有反例（3×3 图：最优 2、贪婪 3）；
   对策：二部图最小点覆盖走 König——最大匹配即答案，Kuhn/Dinic
   实现；并保留贪婪实现仅作对照。）
8. **DFS 反复重新分配访问数组**
   （现象：结果对但常数大、高频图上超时；原因：每次增广搜索都清空
   一个 visited 数组是 O(V) 的额外摊派；原因反面：不清空又会把上次
   搜索的结论带进来、错失调变；对策：时间戳数组 + 单调 token
   （本例 `seen[v] == token` 写法），一次 O(1) 换新搜索。）
9. **把「染色后分量取大」当最大独立集算法**
   （现象：样例全过、一般用例 WA；原因：取大给出的只是可行独立集，
   只有每个分量较小侧满足 Hall 条件时它才最优——连通反例（左 4 右 3、
   ν=2）里取大得 4 而 α=5；对策：统一走 α = n − ν，Kuhn/Dinic 求
   匹配，取大实现保留仅作对照，随机对账专门统计其偏小频率。）
10. **无向边只入一个方向的邻接表**
    （现象：随机测试中随机 0xC0000005 崩溃；原因：单向弧使 BFS 把
    弧两端分别染成同色，按颜色分左右部时越界下标被送进 Kuhn 的
    seen/match 数组；对策：建表处两行成对写（u→v 与 v→u），样例
    数据也按无向边表维护、由构造代码补反向弧。）
11. **为孤立点写特殊分支却数错**
    （现象：答案漏掉没有任何关系的学生；原因：孤立点不属任何非平凡
    分量，取大法手算时容易漏加；n−ν 里它们由 n 自动计入、ν 不受
    影响——根本不需要分支；对策：不特殊处理，用 n − 匹配 一条公式
    覆盖全部顶点，暴力枚举对账兜底。）
12. **牛妞节点不拆点，直接让食物、饮料两边连**
    （现象：一头牛妞被计两次，答案偏大；原因：普通节点没有容量，
    守恒允许两股流入、两股流出；对策：每头牛妞拆 in/out、中间
    容量 1，所有入边接 in、出边从 out 接（本例写法），并让流
    公理验证器对整网复核。）
13. **把问题建成食物↔饮料二部匹配**
    （现象：同一头牛妞名下能同时中两条匹配边；原因：匹配只保证
    食物、饮料不共享，牛妞根本不在模型里；对策：四层网络显式
    包含牛妞层，并保留匹配实现仅作对照——单牛妞喜欢 2 食物
    2 饮料一例（匹配 2、正解 1）专门钉住这个错误。）
14. **层次之间连反向边或双向边**
    （现象：网络出现环路、增广路径语义混乱，甚至凭空增大流值；
    原因：食物→牛妞→饮料是单向的消费方向——残量网络里的
    「反向」由算法用 f[v][u] = −f[u][v] 自动提供，不能在容量
    图上再手动加一遍；对策：容量边严格按 s→食物→in→out→
    饮料→t 单向添加（本例写法）。）
15. **最小费用流的反向边费用写成 +cost 或 0**
    （现象：总费用偏大，或改道增广路根本找不到；原因：退流
    必须把已付费用退回 ⟹ 反向费用严格为 −cost；用退流改道
    例（第 2 单位费用必须是 103）专门钉住；对策：加边函数
    两行成对写 `cost` 与 `-cost`。）
16. **残量网络上直接用 Dijkstra、不处理负权**
    （现象：算出的最短路与费用错误——Dijkstra 不能遇负边；
    对策：要么用本例的 SPFA，要么引入势函数（Johnson 重赋权：
    初始势由一次 Bellman-Ford 距离给出，之后每轮更新），重赋权
    后 Dijkstra 可用且更快。）
17. **费用累加漏乘瓶颈（cost += dist[t]）或符号写反**
    （现象：费用值与枚举对不上；原因：增广 d 个单位每个都付
    dist[t]，公式固定 `cost += d·dist[t]`；对策：每轮打印
    "本轮费用 d·dist"，并对每个目标流量与边流量枚举对账。）
18. **原图就有负费用边时仍按老办法跑**
    （现象：残量网络可能含负环，最短路算法失效，或无限沿负环
    套利；对策：先检查/消去负环（负环检测或最小费用环流模型），
    确认无负环后逐次最短路才成立；停止条件统一用 dist[t]
    不可达，不要凭 dist[t] 的正负判断。）
19. **方格取数的 ∞ 取得不够大**
    （现象：最小割切断了"黑→白"冲突边，还原方案出现相邻对；
    原因：∞ 必须严格大于任何有限割 ⟹ 取 total+1 或更大；
    对策：用 total 动态确定 ∞（不要写死 10⁹ 之外的想当然值），
    方案合法性逐对断言兜底。）
20. **方案还原把白格判反（白格"可达"才入选）**
    （现象：选出一堆相邻格、权值对不上答案；原因：白格是
    "它→t"，留在 t 侧（不可达）才没被切 ⟹ 入选；黑格相反；
    对策：代码写"黑 reach、白 !reach"，并用 3×3 样例逐格
    核对（入选恰为 3 格、权 383）。）
21. **权值任意时仍套用无权匹配的「n − 匹配」**
    （现象：答案错误；原因：无权问题容量全 1，割容即被弃格子
    数；权值任意时源边/汇边容量必须是权值，数格子毫无意义；
    对策：区分"最大独立集（计数）"与"最大权独立集（加权）"
    两个问题，后者走本例的容量=权值构造。）
22. **运输网络把「人对院的指定上限」记在人侧总量上**
    （现象：某人给一家的捐款超过了指定上限、总捐款虚高；原因：三层
    约束是**三个不同的量**——人总额（S→人）、指定额（人→院）、院总额
    （院→T），少建任何一排边就丢一层约束；对策：建网函数先写注释
    列全三层，流值之外逐边复核 flow ≤ 对应上限（示例的逐人逐院
    复核写法）。）
23. **最小割枚举的割容量漏算某一排边**
    （现象：枚举最小割恒大于最大流，对账永远失败；原因：三排边各有
    「被切」的几何条件——人在汇侧切 S→人、对跨侧（人源侧院汇侧）切
    人→院、院在源侧切院→T，漏一排割容就系统性偏大；对策：先在
    n=k=1 的单点网络上手算全部 4 个割，再放开随机对账。）
