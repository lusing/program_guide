# 15 · 动态规划（上）：钢条切割、矩阵链与方法论

> 对应 CLRS §15.1–15.3（英文 3rd ed. pp.359–375）。动态规划的本质一句话：
> **把指数级的重叠子问题压成多项式个、每个只解一次**。本章用两个经典
> 例子（钢条切割、矩阵链乘）把「设计 DP」的完整流程走一遍——下一章
> 继续 LCS 与最优 BST。

## 学习目标

1. 能写出钢条切割的递推式，并量化「朴素递归 2ⁿ vs DP n²」的差距；
2. 会手推矩阵链乘的 m/s 表（CLRS 六矩阵例：15125）；
3. 能陈述最优子结构、重叠子问题两大前提，并会检验一个问题时过不过关；
4. 会用「记录选择」的重构法还原最优解本身（不止最优值）；
5. 理解自底向上与备忘录的取舍；
6. 能把斐波那契从朴素递归一路优化到矩阵快速幂，并用
   `2·F(n+1) − 1` 那个恒等式解释指数的来源；
7. 知道溢出边界该用无符号回绕探测而不是带符号 UB。

## 钢条切割（§15.1）

**问题**：长 n 的钢条与价格表 p[1..n]（图 15.1：1,5,8,9,10,17,17,20,24,30），
切成整数长度段卖出，收益最大？

**第一步：递推式**。最优收益 rₙ = max_{1≤i≤n} (pᵢ + r_{n−i})——第一刀
切下长度 i（卖 pᵢ），剩余段继续最优。这天然是**自引用**的结构。

**第二步：朴素递归的灾难**。直接翻译递推式：

```cpp
static int cut_rod_naive(int n, Cnt& c) {
    ++c.calls;
    if (n == 0) { return 0; }
    int q = std::numeric_limits<int>::min();
    for (int i = 1; i <= n; ++i) {
        q = std::max(q, kPrice[i] + cut_rod_naive(n - i, c));
    }
    return q;
}
```

n=10 时调用 **1024 次**（2¹⁰）——每次都把 r₇、r₅……从头再算。递归
树 2ⁿ 个节点，但**不同的子问题只有 n 个**：重复率随 n 指数增长（示例
15.4 的量化：n=10 时朴素/备忘录 = 1024/56 ≈ 18.3 倍，n 每加 2 翻倍）。

**第三步：备忘录版**——「解过就记账」：

```cpp
static int memoized(int n, std::vector<int>& r, Cnt& c) {
    if (r[n] >= 0) { return r[n]; }   // 查表
    /* 与朴素版相同的枚举，但落表 */
    r[n] = q;
}
```

**第四步：自底向上版**——干脆按 j = 1..n 的顺序填表，r[j] 用更小的
r[j−i] 直接查：

```cpp
for (int j = 1; j <= n; ++j)
    for (int i = 1; i <= j; ++i)
        r[j] = max(r[j], p[i] + r[j-i]);
```

三版本实测（示例 15.1）：

```
n=8：最优收益 22；朴素调用 256 次 vs 备忘录 37 次 vs 自底向上填 8 格
n=10：最优收益 30；朴素调用 1024 次 vs 备忘录 56 次 vs 自底向上填 10 格
```

备忘录与自底向上都是 Θ(n²) 时间、Θ(n) 空间。取舍：自底向上无递归
开销、访问模式缓存友好；备忘录只解**真正用到**的子问题（子问题图
不连通/稀疏时占优）。

**第五步：重构最优解**。最优值不等于最优解——让 s[j] 记录「长度 j 的
最优首段」，还原时贪心走表（示例 15.2）：

```
n=10 最优切割方案（收益 30）: 10 （长度段）
```

价格表下整根卖掉最优；换成 n=8 则是 2+6（5+17=22）——表驱动重构
O(n)。

## 矩阵链乘（§15.2）

**问题**：A₁A₂…Aₙ 依次相乘，Ai 的尺寸 pᵢ₋₁×pᵢ；加括号改变结合序，
标量乘法数天差地别。例（(A₁A₂)A₃ 与 A₁(A₂A₃)：30·35·15+30·15·5 = 18000
vs 35·15·5+30·35·5 = 7875）——找最优括号化。

**最优子结构**：最优括号化的**最后一次乘法**必把链切成 Aᵢ..ₖ 与
A_{k+1}..ⱼ 两半，两半各自必须最优（剪切粘贴法证明）。递推：

```
m[i,j] = 0                          若 i = j
       = min_{i≤k<j} { m[i,k] + m[k+1,j] + p_{i-1}·p_k·p_j }
```

s[i,j] 记下最优 k。按**链长 l = 2..n** 的顺序填表（短链是长链的子问题）。
CLRS 六矩阵例 p = ⟨30,35,15,5,10,20,25⟩ 实测（示例 15.3）：

```
矩阵链乘（p = <30,35,15,5,10,20,25>，6 矩阵）：
  最少标量乘法 = 15125（CLRS 答案 15125）
  最优括号化 = ((A1·(A2·A3))·((A4·A5)·A6))
  DP 填表：15 格、分割尝试 35 次；暴力枚举括号化 = Catalan C5 = 42 种
```

15125 与图 15.5 的 m 表逐格一致；括号化由 s 表递归展开（PRINT-OPTIMAL-
PARENS）。复杂度 Θ(n³) 时间、Θ(n²) 空间——对比暴力枚举 Catalan 数
（C₅=42 看似不多，C₂₀ = 6.6×10⁹）。

## 方法论（§15.3）：设计 DP 的四步

1. **刻画最优解的结构**（最优子结构检验：问题的最优解包含子问题的
   最优解吗？用剪切粘贴论证）；
2. **递归地定义最优值**（写出递推式——这一步对了就成功 80%）；
3. **自底向上计算**（确定填表顺序：子问题按规模依赖排好）；
4. **构造最优解**（伴随表 s 记录选择）。

**什么问题适合 DP**：①有**最优子结构**；②子问题**重叠**（子问题图
的边远多于点——朴素递归重复求解同一子问题）。二者缺一：没有①连递推
都写不出；没有①有②只是「记忆化搜索」能加速但仍可能指数个子问题
（如最长简单路径）。分治（第 4 章）与 DP 的分界也在此：归并排序的
子问题**不重叠**（每次都是全新的一半），所以不需要记忆化。

**子问题图**：把「子问题→更小子问题」的依赖画成图，DP 的填表顺序
就是它的拓扑序，时间 = O(顶点数 × 每顶点出度)。钢条切割：n 个顶点、
每点 n 条边 → Θ(n²)。矩阵链：Θ(n²) 个顶点、每点 Θ(n) 条边 → Θ(n³)。

## 案例：斐波那契的四层解法（重叠子问题的教科书标本）

斐波那契 `F(0)=0, F(1)=1, F(n)=F(n-1)+F(n-2)` 本身不是"必须用 DP"的问题
（它可以纯数学求解），但它是**教学重叠子问题**最好的载体：同一个递推式，
四种解法的调用次数能差出 4 万亿倍，而这个差别完全来自"你有没有意识到
子问题被重复计算了"。

### 四层递进

| 解法 | 递推式 | 调用次数（n=30） | 复杂度 |
|---|---|---|---|
| ① 朴素递归 | T(n)=T(n-1)+T(n-2)+Θ(1) | 2 692 537 | Θ(φⁿ)，φ≈1.618 |
| ② 记忆化 | 每个 F(k) 只算一次 | 59 | Θ(n) |
| ③ 自底向上迭代 | 滚动变量 | n | Θ(n) 时间 / Θ(1) 空间 |
| ④ 矩阵快速幂 | [[1,1],[1,0]]ⁿ | 26 次 2×2 乘法 | Θ(lg n) 次 3 算 |

示例 15.5 把四层放在一张表里对账，并且验证了一个漂亮的恒等式：

> 朴素递归对 `F(n)` 的调用次数**恰好等于 `2·F(n+1) − 1`**。

这个恒等式把"递归是指数的"从定性说法变成了等式：`F` 本身满足
`F(n)=Θ(φⁿ)`，所以朴素递归的调用次数也是 `Θ(φⁿ)`。你在第 15.4 节看到的
CUT-ROD 的 `2ⁿ`，和这里的 `φⁿ` 是同一族故事（钢条切割的递归式
`T(n)=1+T(1)+…+T(n-1)` 的解是 2ⁿ，斐波那契是它的"最简版本"）。

### 为什么记忆化只需要 n 次

记忆化的关键不是"缓存"，而是**子问题图是一个 DAG（无环有向图）**：
`F(k)` 只依赖 `F(k-1)`、`F(k-2)`，依赖关系无环，可以按拓扑序（也就是下标
从小到大）求值一次。`n+1` 个节点、`O(1)` 条边 → 记忆化的时间就是节点数。

递归栈把这个 DAG **展开成了树**，同一节点 `F(5)` 会在树的多个位置重复出现，
重复次数恰好是它作为"别人的子问题"被引用的次数——这就是冗余倍数的来源。
示例输出里 n=30 时冗余倍数是 45636 倍，`F(30)` 那个节点本身被算了 4 万多次。

### 记忆化 vs 自底向上：什么时候该用哪个

- **自底向上**是首选：没有函数调用开销、没有栈溢出风险、缓存局部性好。
  斐波那契滚动变量只要两个变量，空间 Θ(1)。
- **记忆化**的价值在于**状态空间不是按一个线性序排列**的时候：
  钢条切割的状态 `OPT(0..n)` 恰好是线性的，自底向上更自然；
  但如果状态是 `(位置, 剩余步数)` 这类二维/树形状态，自底向上就要按
  "层数"填表，而记忆化可以只算**从初始状态可达**的那部分——
  状态空间大而实际可达部分小时，记忆化省下的不是常数而是整个量级。

C++ 里记忆化通常写成"函数 + 缓存容器"，C++23 有更干净的写法：
`std::array` 配合下标，或用 lambda 递归 + 闭包捕获的 `std::vector`。
注意 lambda 递归需要 `this auto&&` 形式的自引用（见第 10 章的
`deducing this` 示例），否则拿不到自己。

### 第四层：矩阵快速幂与"只算 mod"的实用变体

朴素递推写成矩阵形式（O(n) 次乘法）已经够用，但要拿到 `Θ(lg n)` 就得上
快速幂：把 `Qⁿ = [[F(n+1), F(n)], [F(n), F(n-1)]]`（Q 为斐波那契 Q 矩阵）
反复平方。示例验证了 n 从 10 涨到 10¹²，矩阵乘法次数只从 5 涨到 52——
n 涨了 10¹¹ 倍，工作量只涨了 10 倍，这就是 `Θ(lg n)` 的直观含义。

**实践中更重要的是它的 mod 变体**：竞赛与面试里的"F(n) mod m"用快速倍增
（fast doubling）实现，只需维护一对 `(F(k), F(k+1))` 并用恒等式

```
F(2k)   = F(k)·(2·F(k+1) − F(k))
F(2k+1) = F(k)² + F(k+1)²
```

递归到 `Θ(lg n)` 层，全程对 m 取模就能处理巨大的 n。本教程示例把它写成
"只算 mod m"的形式（见示例里 mod 1e9+7 的对照），因为这是这个算法在真实
场景里唯一有用的形态——没人需要 F(10¹²) 的精确值，但人人都需要
F(10¹²) mod 1e9+7。

### 溢出边界：斐波那契是整数溢出最好的教材

`long long`（int64，上限 9223372036854775807 ≈ 9.22×10¹⁸）能装下
`F(92) = 7540113804746346429`，装不下 `F(93) = 12200160415121876738`。
换 `unsigned long long` 能多装一项（到 F(93)），再往上就必须上大数
（第 32 章的高精度）。

这个案例演示了一个**探测溢出的安全技巧**：不要用带符号溢出探测
（`a + b < 0` 是 UB，编译器会利用它做优化，行为不可预测），
而用 `unsigned` 的回绕判定——`F(k)` 单调递增，一旦 `next < cur` 就是回绕：

```cpp
std::uint64_t a = 0, b = 1;
for (int k = 1; ; ++k) {
    const std::uint64_t next = a + b;
    if (next < b) break;      // 回绕 = 装不下了（无 UB）
    a = b; b = next;
}
```

## 从指数到状态压缩：可达性 DP 的三级下沉

前面三节（钢条切割、矩阵链、斐波那契）的 DP 都在优化**同一个指数来源**：
子问题个数从 2ⁿ 降到 Θ(n²)。但还有一类问题的指数来源更极端——**决策本身
就是一条 0/1 串**：n 件行李分两份、在 n−1 个缝隙各插一个 `+`/`−`、从 n
个数里选 k 个。朴素解法是枚举 2ⁿ 个决策串，n = 10⁴ 时是 10⁶ 数量级的
子问题——**不是"慢"，是完全不可行**。

这类问题的共同结构是：**目标只是"能否达到"，不关心"有多少种方法达到"**。
于是三级下沉逐步把它们压回多项式。

### 载体问题：把行李分成重量和尽量接近的两份

n 件行李、重量 w₁..wₙ，总重 W = Σwᵢ。分成不重不漏的两份 A₁、A₂，
使 |Σ_{A₁} − Σ_{A₂}| 最小。

**归约（先做这一步，否则后面无从谈起）**。设 s = Σ_{A₁}，则 A₂ 的和是
W − s，故

```
min |A₁ − A₂| = min |2s − W| = W − 2·max{ s : s ≤ ⌊W/2⌋, s 是可达子集和 }
```

（用到 s ≤ W/2 时 W − 2s ≥ 0，故取 W/2 那一侧；**必须向下取整**。）
于是原问题 ⟺ **子集和可达性**：哪些 s ≤ C = ⌊W/2⌋ 是可达的？最大值是多少？

### 第一级：朴素 Θ(2ⁿ) 枚举子集

直接照抄定义：枚举 2ⁿ 个子集，每个 O(n) 求和，标记 `reach[s]`。

```
时间 Θ(n·2ⁿ)，空间 Θ(C)
```

n = 18 时 2¹⁸ = 262144，尚可；n = 25 时 3.3×10⁷ 个子集 × 25 次加法就开始
难受；n = 100 时 2¹⁰⁰ 远超宇宙原子数。**指数在这里不是"慢"，是"不可能"。**

### 第二级：布尔可达性代替计数（Θ(2ⁿ) → Θ(nK)）

关键观察：目标只问"和 s 可不可达"，**不问"有几种方式得到 s"**。所以状态
不需要记方案数，只需要一个布尔。把值维度从"2ⁿ 种选法"换成"可达和的布尔
集合"，指数就消失了。

以「插 `+`/`−` 能否使结果被 K 整除」为例（K ≤ 100，n ≤ 10⁴）：

- **状态**：`reach[i][r]` = 前 i 个数按某种 `+`/`−` 组合后，表达式值
  mod K 等于 r 是否可能，r ∈ [0, K)。
- **边界**：`reach[1][a₁ mod K] = true`，其余 false。**第一项固定取正**——
  运算符只插在项与项之间，第一项没有前置符号。
- **转移**（对第 i 项，i ≥ 2，该项前只能是 `+` 或 `−`）：

  ```
  reach[i][(r + aᵢ) mod K] |= reach[i−1][r]      // 第 i 项取 +
  reach[i][(r − aᵢ) mod K] |= reach[i−1][r]      // 第 i 项取 −
  ```

  对所有 r ∈ [0, K)。**取模要归一化**到 [0, K)：C++ 里 `(x % K + K) % K`，
  因为 x 可以是负数而 C++ 的 `%` 保留被除数符号。
- **计算顺序**：i 从 1 递增，每层只依赖上一层 ⟹ 可滚动数组，空间 **Θ(K)**。
- **答案**：`reach[n][0]`。

**时间 Θ(N·K) = 10⁴ × 100 = 10⁶**，瞬间完成。

#### 为什么这一步合法：状态充分性

把 2ⁿ 压到 N·K 的**唯一**理由是"未来只依赖状态，与到达路径无关"。这里
必须说清：设前 i 项的表达式值为 Eᵢ，则

```
Eᵢ ± a_{i+1} ± … ± a_N  ≡  (Eᵢ mod K) ± (a_{i+1} ± … ± a_N)   (mod K)
```

右边只通过 `Eᵢ mod K` 依赖 Eᵢ。**余数相同的所有方案对"后续能否达标"的
影响完全一致**，所以可以合并成一个状态。若这条不成立（比如目标是"最长简单
路径"，见本坑位清单第 5 条），同样的压缩会给出错误答案。

子集和版本同理：`reach[s]` 只问"和 s 可不可达"，加一个 w 就是
`reach[s] |= reach[s−w]`，**倒序**扫 s（0-1 背包的规矩），Θ(nC)。

### 第三级：bitset 位并行（Θ(nK) → Θ(nK/w)）

第二级每个布尔是一次独立的访存与比较，而**同一轮的 K 个布尔之间毫无
依赖**——它们只是"新集合 = 老集合 ∪ 平移后的老集合"。既然无依赖，就可以
打包进机器字，让一条指令同时处理 w = 64 个布尔。

子集和版本的全部转移就是一行：

```cpp
bs |= (bs << w);        // 一条语句 = 一轮 0-1 背包转移
```

**为什么位移对应"取或不取"**——把右边的两个操作分开看：

| 表达式 | 语义 |
|---|---|
| `bs`（`\|=` 的左操作数） | **不取** w：和 s 仍然可达 |
| `bs << w` | **取** w：和 s 的可达性搬到 s+w |
| `\|=` | 把"取"的分支**并**进"不取"的分支 |

两个正确性要点：

1. **右侧整体来自更新前的 `bs`**。C++ 的复合赋值 `a op= b` 等价于
   `a = a op b`，且**右侧先求值**。所以 `bs |= bs << w` 里的 `bs << w`
   用的是这一轮开始时的 `bs` ⟹ 同一轮不会重复取 w。如果写成
   `bs = bs | (bs << w) | (bs << 2*w)` 就多算了"取两次 w"的非法方案。
2. **移出去的位自动丢弃**，这恰好等价于"值域裁剪"——和 > C 的状态被
   天然截断，不需要显式判断。

于是复杂度从 Θ(nC) 降到 **Θ(nC/w)**，w = 机器字长（x86-64 上是 64）。
C = 5×10⁶、n = 100 时：Θ(nC) = 5×10⁸ 次布尔操作 vs Θ(nC/64) ≈ 7.8×10⁶ 次
64 位运算。

**模 K 版本**用同一个原语，只是位移换成**循环移位**（因为 r ± x mod K 要
绕过边界）：

```cpp
// reach 的低 K 位有效；K 很小（≤ 100）时用 std::bitset<100> + 一个掩码
bs = ((bs << x) | (bs >> (K - x))) & mask;      // +x 方向（模 K 循环移位）
```

**注意这里有两个易错点**（本示例首版就踩了）：

- 双向转移（`+x` 与 `−x`）需要**四项**：`((bs<<x)|(bs>>(K−x))) |
  ((bs>>x)|(bs<<(K−x)))`。只写两项等于只做单向，答案偏小。
- 这里必须用**赋值**而不是 `|=`。`±` 问题里每一项都必须领一个符号，
  **没有"不取这一项"的分支**；`|=` 会把上一轮的结果额外并进来。对照子集和
  版本那里 `|=` 是对的（不取 w 确实是合法选择）——**同一行代码在两个问题里
  语义不同，差别就在"有没有不取分支"**。

### `std::bitset` 的编译期宽度限制与变长替代

`std::bitset<N>` 的 N 是**编译期常量**。这在竞赛里通常不是问题（题面给了
数据上界，N 取上界即可），但有两种情况会卡住：

- 上界只在**运行时**才确定（如 W 由输入算出才知道 C）；
- 上界太大，`std::bitset<5000001>` 是 625 KB 的**栈对象**——Windows 默认
  栈 1 MB、Linux 8 MB，直接爆栈（`static` 或堆分配能绕过，但宽度仍固定）。

变长做法是 `std::vector<std::uint64_t>` 手写移位-或。跨字移位是唯一的技术
点：`w` 位移位 = 整字移位 `w/64` + 字内移位 `w%64`，字内移位的进位从相邻
低字借来。

```cpp
// bs |= bs << w（变长版，w 可以 ≥ 64）
// 关键：必须**从高位往低位扫**，这样读到的源字都还是本轮更新前的值
for (std::size_t i = bs.size(); i-- > 0;) {
    std::uint64_t v = 0;
    if (i >= w / 64) {
        v = bs[i - w / 64] << (w % 64);
        if (w % 64 != 0 && i > w / 64) { v |= bs[i - w / 64 - 1] >> (64 - w % 64); }
    }
    bs[i] |= v;
}
```

扫完后别忘 `bs.back() &= ~0ull >> (64 - bits % 64)` 清掉超出位宽的高位
（等价于值域裁剪）。本示例把这条路径与 `std::bitset` 版逐位对账，确认两者
给出**完全相同**的可达集合。

### 另一道题：选 K 个数使和能被 K 整除

同一个骨架再加一维计数。「从 n 个数里恰选 K 个，使和被 K 整除」：

- **状态**：`dp[j][r]` = 已扫过的数里**恰选 j 个**、和 ≡ r (mod K) 是否可能。
- **边界**：`dp[0][0] = true`（选 0 个、和为 0）。
- **转移**：`dp[j][(r + aᵢ) mod K] |= dp[j−1][r]`，**j 倒序**扫（每个数只用
  一次）。
- **答案**：`dp[K][0]`。
- **时间** Θ(n·K²) = 10⁴ × 10⁴ = 10⁸ —— 偏慢。

把 r 那一维整体压成一条 K 位位集（`dp[j]` 存一条位集），转移就变成一次
模 K 循环移位：

```cpp
dp[j] |= rot_K(dp[j - 1], aᵢ mod K);      // Θ(n·K²/w)
```

**位集宽度选多大是个真实的权衡**：`std::bitset<100>` 定宽 padding 后，K = 4
时也占满 2 个字，理论字数 ⌈K/64⌉ = 1 却按 2 算——**定宽在小 K 时纯浪费**。
本示例同时打印"按实际位宽 ⌈K/64⌉ 计"与"按 `bitset<100>` 定宽计"两个数，
K = 4/8/12/16 时提速比分别是 2.0/4.0/6.0/8.0 倍（定宽口径则腰斩）。K 越大
位并行越划算；K 很小时老老实实用布尔 DP 也够。

## C++23 语言点

- 备忘录的「未算标记」用 −1 初始化的 `std::vector<int>`（键域非负时
  最直白）；`numeric_limits<int>::min()` 当「负无穷」（收益可能为负的
  变体问题要小心——用 long long 或首个候选初始化更稳）；
- **递归 lambda 重构括号化**：`parens(i, j)` 用显式对象形参自递归
  （第 10 章介绍过的 `this auto&& self` 模式）拼字符串；
- 二维表 `vector<vector<long long>> m(n+2, vector(n+2, 0))`——下标从 1
  起对齐 CLRS（0 行列留空，少一层心智换算）。

## 与 STL 对照

DP 没有直接的库对应物，但工程上它是「缓存」思维的理论核心：备忘录
版 DP = 带缓存的递归（`std::unordered_map` 当 memo 的通用写法）；自底
向上 = 循环顺序的显式化（省掉缓存结构）。编译器的公共子表达式消除、
构建系统的依赖图调度、React 的 memo——同一思想的不同马甲。

## 坑位清单

1. **价格表越界（本例真实翻车）**
   （现象：n=15 的演示在 MSAN/断言下炸或读到垃圾值；原因：CLRS 价格表
   只有 1..10，demo 却演示到 n=15/20——kPrice[11..] 越界；后果：未定义
   行为或收益错值；对策：表驱动数据的规模与表容量一起断言
   （assert(n ≤ kPrice.size()−1)），本例实测翻车后把演示压回 {8,10}。）
2. **「多余的 >」这类笔误在模板噪声里隐身**
   （现象：`numeric_limits<int>::min>();` 编译错误指向括号；原因：手写
   `min>()`，一眼看去与 `min()` 几乎无差；后果：浪费排查时间；对策：
   编译错误先复制原行比对字符——本例真实翻车（gcc 指到 61:48 才看出
   多个 `>`）。）
3. **填表顺序错（先算长的）**
   （现象：算出来全是 0 或部分格是垃圾；原因：m[i,k] 需要 k 的链更短
   ——必须按链长 l 递增填；后果：静默错值；对策：写循环前先画子问题
   图的拓扑序，自底向上的「底」= 最小子问题（链长 1）。）
4. **只存最优值、丢了选择信息**
   （现象：知道 15125 却给不出括号化；原因：m 表只记代价；对策：伴随
   s[i,j] = 最优分割点，重构 O(n)——「值表 + 决策表」双表是 DP 的
   标准姿势。）
5. **把「最优子结构」当信仰而不是证明**
   （现象：照猫画虎写出的递推在某些输入给次优解；原因：不是所有
   「分解」都有最优子结构（最长简单路径是经典反例——子路径最优可能
   互斥）；后果：算法「大部分时候对」；对策：剪切粘贴论证写进注释，
   说不出为什么子问题独立就别上 DP。）
6. **用带符号溢出去探测数值上限**
   （现象：`if (a + b < 0) break;` 在 gcc 优化版下不触发，或直接被优化成
   恒假；原因：有符号整数溢出是 UB，编译器有权假设它不发生并据此删掉
   分支；后果：边界算错或行为不可预测；对策：改用 `unsigned` 的回绕判定
   （`next < b` 即回绕）、除法预判，或直接用第 32 章的大数。）
7. **把递归树的节点数当成"子问题数"**
   （现象：以为斐波那契只有 n 个子问题、记忆化省不了多少；原因：递归
   把 DAG 展开成了树，同一子问题出现多次；后果：低估或高估记忆化收益
   （n=30 时冗余 45636 倍）；对策：区分"不同子问题数"（n+1）和"实际
   求值次数"（2F(n+1)−1），示例的表格里两列都给出来。）
8. **位集转移写成多轮累加，同一件物品被取多次**
   （现象：0-1 背包算出了"最多可取"的完全背包答案；原因：
   `bs = bs | (bs << w) | (bs << 2*w)` 把"取两次 w"也算进去；复合赋值
   `bs |= bs << w` 之所以安全，是因为右侧先求值、整体来自更新前的 `bs`；
   后果：答案偏大且难以察觉（小例常常"看起来对"）；对策：位集转移写成一
   条 `|=`，需要多件同种物品时改用 `bs |= bs << (cnt * w)` 或二进制分组
   拆包（本例首版实测翻车。）
9. **模 K 循环移位只写两项（漏掉 −x 方向）**
   （现象：± 问题的可达余数集合偏小，答案偶尔对、多数错；原因：
   `(bs << x) | (bs >> (K − x))` 只是 `r ↦ r + x (mod K)` 的循环移位，
   `r ↦ r − x` 要另写 `(bs >> x) | (bs << (K − x))`，**共四项**；后果：
   与布尔 DP 对账即暴露；对策：把「±」和「只取 +」两种题面分开写，前者
   四项后者两项，并各配一个逐余数对账的布尔实现（本例首版实测翻车。）
10. **在「每项必须领符号」的问题里用 `|=` 累加**
    （现象：可达集合逐轮膨胀，答案偏大；原因：子集和的 `bs |= bs << w`
    之所以对，是因为"不取 w"是合法分支；`±` 问题里每一项**必须**取 + 或 −，
    没有"不取"分支，正确写法是纯赋值 `bs = (四项移位) & mask`，`|=` 会把
    上一轮的集合额外并进来；后果：与布尔 DP 不一致；对策：写完转移后立刻
    用布尔 DP 逐位对账（本例首版实测翻车。）
11. **变长位集忘了清超出位宽的高位**
    （现象：小 K 时答案偏大，`bs[w−1]` 之后的位置被当成合法状态；原因：
    手写 `or_shift_left` 后高位残留，相当于"和 > C 的状态没被裁剪"，而
    `std::bitset` 会自动保持定长故不暴露这个问题；后果：变长版与定长版
    结果不一致；对策：每轮结束 `bs.back() &= ~0ull >> (64 - bits % 64)`，
    并把两条路径逐位对账（本例的四路对账断言正是为此设置。）
12. **`std::bitset` 宽度取上界导致爆栈**
    （现象：W 很大时 `std::bitset<5000001>` 在栈上分配 625 KB，Windows
    默认 1 MB 栈直接溢出；原因：定宽且按值在栈上构造；后果：运行时崩溃
    （不是编译错误，测试环境小数据时一切正常）；对策：`static` 或
    `std::vector<std::uint64_t>` 堆分配；宽度真要运行时才知道时直接上
    变长位集——这也是本节给出变长实现的原因。）
