# 15 · 动态规划（上）：钢条切割、矩阵链与方法论

> 对应 CLRS §15.1–15.3（英文 3rd ed. pp.359–375）。动态规划的本质一句话：
> **把指数级的重叠子问题压成多项式个、每个只解一次**。本章用两个经典
> 例子（钢条切割、矩阵链乘）把「设计 DP」的完整流程走一遍——下一章
> 继续 LCS 与最优 BST。

## 学习目标

1. 能写出钢条切割的递推式，并量化「朴素递归 2ⁿ vs DP n²」的差距；
2. 会手推矩阵链乘的 m/s 表（CLRS 六矩阵例：15125）；
3. 能陈述最优子结构、重叠子问题两大前提，并会检验一个问题时过不过关；
4. 会用「记录选择」的重构法还原最优解本身（不止最优值）；
5. 理解自底向上与备忘录的取舍。

## 钢条切割（§15.1）

**问题**：长 n 的钢条与价格表 p[1..n]（图 15.1：1,5,8,9,10,17,17,20,24,30），
切成整数长度段卖出，收益最大？

**第一步：递推式**。最优收益 rₙ = max_{1≤i≤n} (pᵢ + r_{n−i})——第一刀
切下长度 i（卖 pᵢ），剩余段继续最优。这天然是**自引用**的结构。

**第二步：朴素递归的灾难**。直接翻译递推式：

```cpp
static int cut_rod_naive(int n, Cnt& c) {
    ++c.calls;
    if (n == 0) { return 0; }
    int q = std::numeric_limits<int>::min();
    for (int i = 1; i <= n; ++i) {
        q = std::max(q, kPrice[i] + cut_rod_naive(n - i, c));
    }
    return q;
}
```

n=10 时调用 **1024 次**（2¹⁰）——每次都把 r₇、r₅……从头再算。递归
树 2ⁿ 个节点，但**不同的子问题只有 n 个**：重复率随 n 指数增长（示例
15.4 的量化：n=10 时朴素/备忘录 = 1024/56 ≈ 18.3 倍，n 每加 2 翻倍）。

**第三步：备忘录版**——「解过就记账」：

```cpp
static int memoized(int n, std::vector<int>& r, Cnt& c) {
    if (r[n] >= 0) { return r[n]; }   // 查表
    /* 与朴素版相同的枚举，但落表 */
    r[n] = q;
}
```

**第四步：自底向上版**——干脆按 j = 1..n 的顺序填表，r[j] 用更小的
r[j−i] 直接查：

```cpp
for (int j = 1; j <= n; ++j)
    for (int i = 1; i <= j; ++i)
        r[j] = max(r[j], p[i] + r[j-i]);
```

三版本实测（示例 15.1）：

```
n=8：最优收益 22；朴素调用 256 次 vs 备忘录 37 次 vs 自底向上填 8 格
n=10：最优收益 30；朴素调用 1024 次 vs 备忘录 56 次 vs 自底向上填 10 格
```

备忘录与自底向上都是 Θ(n²) 时间、Θ(n) 空间。取舍：自底向上无递归
开销、访问模式缓存友好；备忘录只解**真正用到**的子问题（子问题图
不连通/稀疏时占优）。

**第五步：重构最优解**。最优值不等于最优解——让 s[j] 记录「长度 j 的
最优首段」，还原时贪心走表（示例 15.2）：

```
n=10 最优切割方案（收益 30）: 10 （长度段）
```

价格表下整根卖掉最优；换成 n=8 则是 2+6（5+17=22）——表驱动重构
O(n)。

## 矩阵链乘（§15.2）

**问题**：A₁A₂…Aₙ 依次相乘，Ai 的尺寸 pᵢ₋₁×pᵢ；加括号改变结合序，
标量乘法数天差地别。例（(A₁A₂)A₃ 与 A₁(A₂A₃)：30·35·15+30·15·5 = 18000
vs 35·15·5+30·35·5 = 7875）——找最优括号化。

**最优子结构**：最优括号化的**最后一次乘法**必把链切成 Aᵢ..ₖ 与
A_{k+1}..ⱼ 两半，两半各自必须最优（剪切粘贴法证明）。递推：

```
m[i,j] = 0                          若 i = j
       = min_{i≤k<j} { m[i,k] + m[k+1,j] + p_{i-1}·p_k·p_j }
```

s[i,j] 记下最优 k。按**链长 l = 2..n** 的顺序填表（短链是长链的子问题）。
CLRS 六矩阵例 p = ⟨30,35,15,5,10,20,25⟩ 实测（示例 15.3）：

```
矩阵链乘（p = <30,35,15,5,10,20,25>，6 矩阵）：
  最少标量乘法 = 15125（CLRS 答案 15125）
  最优括号化 = ((A1·(A2·A3))·((A4·A5)·A6))
  DP 填表：15 格、分割尝试 35 次；暴力枚举括号化 = Catalan C5 = 42 种
```

15125 与图 15.5 的 m 表逐格一致；括号化由 s 表递归展开（PRINT-OPTIMAL-
PARENS）。复杂度 Θ(n³) 时间、Θ(n²) 空间——对比暴力枚举 Catalan 数
（C₅=42 看似不多，C₂₀ = 6.6×10⁹）。

## 方法论（§15.3）：设计 DP 的四步

1. **刻画最优解的结构**（最优子结构检验：问题的最优解包含子问题的
   最优解吗？用剪切粘贴论证）；
2. **递归地定义最优值**（写出递推式——这一步对了就成功 80%）；
3. **自底向上计算**（确定填表顺序：子问题按规模依赖排好）；
4. **构造最优解**（伴随表 s 记录选择）。

**什么问题适合 DP**：①有**最优子结构**；②子问题**重叠**（子问题图
的边远多于点——朴素递归重复求解同一子问题）。二者缺一：没有①连递推
都写不出；没有①有②只是「记忆化搜索」能加速但仍可能指数个子问题
（如最长简单路径）。分治（第 4 章）与 DP 的分界也在此：归并排序的
子问题**不重叠**（每次都是全新的一半），所以不需要记忆化。

**子问题图**：把「子问题→更小子问题」的依赖画成图，DP 的填表顺序
就是它的拓扑序，时间 = O(顶点数 × 每顶点出度)。钢条切割：n 个顶点、
每点 n 条边 → Θ(n²)。矩阵链：Θ(n²) 个顶点、每点 Θ(n) 条边 → Θ(n³)。

## C++23 语言点

- 备忘录的「未算标记」用 −1 初始化的 `std::vector<int>`（键域非负时
  最直白）；`numeric_limits<int>::min()` 当「负无穷」（收益可能为负的
  变体问题要小心——用 long long 或首个候选初始化更稳）；
- **递归 lambda 重构括号化**：`parens(i, j)` 用显式对象形参自递归
  （第 10 章介绍过的 `this auto&& self` 模式）拼字符串；
- 二维表 `vector<vector<long long>> m(n+2, vector(n+2, 0))`——下标从 1
  起对齐 CLRS（0 行列留空，少一层心智换算）。

## 与 STL 对照

DP 没有直接的库对应物，但工程上它是「缓存」思维的理论核心：备忘录
版 DP = 带缓存的递归（`std::unordered_map` 当 memo 的通用写法）；自底
向上 = 循环顺序的显式化（省掉缓存结构）。编译器的公共子表达式消除、
构建系统的依赖图调度、React 的 memo——同一思想的不同马甲。

## 坑位清单

1. **价格表越界（本例真实翻车）**
   （现象：n=15 的演示在 MSAN/断言下炸或读到垃圾值；原因：CLRS 价格表
   只有 1..10，demo 却演示到 n=15/20——kPrice[11..] 越界；后果：未定义
   行为或收益错值；对策：表驱动数据的规模与表容量一起断言
   （assert(n ≤ kPrice.size()−1)），本例实测翻车后把演示压回 {8,10}。）
2. **「多余的 >」这类笔误在模板噪声里隐身**
   （现象：`numeric_limits<int>::min>();` 编译错误指向括号；原因：手写
   `min>()`，一眼看去与 `min()` 几乎无差；后果：浪费排查时间；对策：
   编译错误先复制原行比对字符——本例真实翻车（gcc 指到 61:48 才看出
   多个 `>`）。）
3. **填表顺序错（先算长的）**
   （现象：算出来全是 0 或部分格是垃圾；原因：m[i,k] 需要 k 的链更短
   ——必须按链长 l 递增填；后果：静默错值；对策：写循环前先画子问题
   图的拓扑序，自底向上的「底」= 最小子问题（链长 1）。）
4. **只存最优值、丢了选择信息**
   （现象：知道 15125 却给不出括号化；原因：m 表只记代价；对策：伴随
   s[i,j] = 最优分割点，重构 O(n)——「值表 + 决策表」双表是 DP 的
   标准姿势。）
5. **把「最优子结构」当信仰而不是证明**
   （现象：照猫画虎写出的递推在某些输入给次优解；原因：不是所有
   「分解」都有最优子结构（最长简单路径是经典反例——子路径最优可能
   互斥）；后果：算法「大部分时候对」；对策：剪切粘贴论证写进注释，
   说不出为什么子问题独立就别上 DP。）
