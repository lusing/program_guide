# 11 · 散列表

> 对应 CLRS 第 11 章 *Hash Tables*（英文 3rd ed. pp.253–285）。字典问题
> （INSERT/SEARCH/DELETE）在「比较」框架下最快 Θ(lg n)（第 12–13 章的树）；
> 散列表直接把期望压到 **Θ(1)**——代价是**最坏**没保证（除非全域散列 +
> 完美散列）。「期望 O(1)、最坏看人品」这条主线贯穿本章。

## 学习目标

1. 能推链址法在装填因子 α 下的期望查找代价 Θ(1+α)；
2. 会实现开地址三法（线性/二次/双重）并解释**一次聚集/二次聚集**；
3. 能陈述定理 11.6（均匀散列：不成功查找期望探查 ≤ 1/(1−α)）并读懂
   装填因子实验的实测对照；
4. 理解全域散列的动机（消灭「被杀手键域打死」）与定理 11.5 的含义；
5. 知道「绝不遍历打印 unordered 容器」背后的哈希序不确定性（本教程
   高压线）。

## 动机：直接寻址的省内存版

键域 U 巨大（比如 64 位整数）但实际键只有 n 个时，直接寻址表
`T[k]`（|U| 个槽）浪费天文数字的空间。散列函数 **h: U → {0..m−1}**
把槽压到 m 个（m = Θ(n)）——代价是**碰撞**（两键同槽）不可避免
（鸽笼原理）。处理碰撞的两大流派：**链址**（每槽一条链）与
**开地址**（碰撞了就按探查序列找别的槽）。

## 散列函数（§11.3）

- **除法法**：h(k) = k mod m。m 别取 2 的幂（低比特全是重复模式），
  取不接近 2 的幂的**素数**最稳；
- **乘法法**：h(k) = ⌊m·(k·A mod 1)⌋，A ≈ (√5−1)/2（黄金分割），m 取
  2 的幂也无妨；
- **字符串**：多项式滚动 h = h·31 + c（Java 的经典做法）。

## 链址法（§11.2）

槽放链表，插入头插 O(1)，查找沿链扫描。CLRS 图 11.3 数据实测
（m=9，除法散列）：

```
T[1] → 28 19 10
T[2] → 20
T[3] → 12
T[5] → 5
T[6] → 15 33
T[8] → 17
```

简单均匀散列假设下，链长期望 α = n/m；**不成功**查找期望探查
Θ(1 + α)，**成功**查找 Θ(1 + α/2)（多扫半个链）。示例：
search(19) 恰好 2 次探查（链 {28,19,10} 第二个命中）。

**删除**在链址法下是 O(1)（双链）或 O(1)（单链但删的是刚查到的
节点——给指针即删）。这为开地址法做不到的 O(1) 删除埋下伏笔。

## 开地址法（§11.4）

所有元素住表内，碰撞沿**探查序列** ⟨h(k,0), h(k,1), …⟩ 前进：

- **线性探查** h(k,i) = (h′(k)+i) mod m：一次聚集（primary clustering）——
  连续占用块越长越容易更长，雪崩；
- **二次探查** h(k,i) = (h′(k)+i²) mod m：二次聚集（同 h′ 的键走同一
  条序列），且 m ≡ 3 (mod 4) 才保证访遍全表（示例的 m=103 特意挑的）；
- **双重散列** h(k,i) = (h₁(k) + i·h₂(k)) mod m：h₂ 与 m 互素时接近
  均匀散列，Θ(m) 条序列——聚集基本消失。

m=13、键 ⟨79,69,98,72,14,50⟩ 的实测（示例 11.2）：三种方法的表状态
几乎一致（稀疏表差异不明显），探查 8/8/10 次；真正的分水岭在装填因子：

```
α=0.50（n=51）：线性 插入1.6/查失3.5  二次 插入1.8/查失1.8  双重 插入1.6/查失2.0  （理论 ≤ 1.98）
α=0.70（n=72）：线性 插入2.8/查失6.6  二次 插入2.2/查失3.4  双重 插入2.0/查失3.1  （理论 ≤ 3.32）
α=0.89（n=92）：线性 插入6.0/查失32.9 二次 插入2.9/查失8.2  双重 插入2.3/查失8.9  （理论 ≤ 9.36）
```

读法：**双重散列贴着理论线**（8.9 vs 9.36），二次因聚集高出一线，
线性在 α=0.89 时查失 32.9 次——一次聚集的雪崩实测。工程结论：
开放定址的表要**保持 α < 0.7**（满了就 rehash 扩容）。

**定理 11.6**（均匀散列假设）：开地址表不成功查找的期望探查 ≤ 1/(1−α)。
α=0.9 时 10 次、α=0.99 时 100 次、α→1 爆炸——这就是「负载阈值」的
理论根据。

## 全域散列（§11.4universal，定理 11.5）

任何**固定**的 h 都存在杀手键域（把键全挤进一个槽——对手知道 h 就能
构造）。全域散列把随机性搬进函数选择：

H = { h_{a,b}(k) = ((a·k + b) mod p) mod m : a ∈ {1..p−1}, b ∈ {0..p−1} }

p 是大于 |U| 的素数。**定理 11.5**：从 H 均匀随机取 h，任两不同键碰撞
的概率 ≤ 1/m。于是**对手无法构造杀手键域**（他不知道 a、b）——与第 7
章随机化快排、第 9 章随机选择同一个思想：把最坏情形从「输入的属性」
变成「硬币的属性」。

实测（示例 11.4，p=10007、m=13、100 键 4950 对、每对换随机 (a,b)）：

```
全域类碰撞率 = 0.0758（理论 ≤ 1/m = 0.0769）
固定 k mod m 碰撞率 = 0.0859（键取自 0..999，与 m=13 的公倍结构有关）
```

全域版 0.0758 卡在理论上界之内；固定函数这组键域恰好偏高（0.0859）——
换更坏的键域（比如全为 13 的倍数）它会冲到 1.0，而全域版纹丝不动。

（§11.5 完美散列是收尾：两级散列、m = n² 的二级表，**最坏 O(1)** 查找、
空间 O(n)——静态键域（编译器关键字表）的专用兵器。）

## C++23 语言点

- `std::vector<int> slot(m, -1)` 用 −1 当空标记（CLRS 的 NIL 化身）；
- 探查序列写成 `h(k, i)` 一个函数，三法一个 switch——对比实验只需换
  枚举值；
- **`std::hash` 与 `std::unordered_map` 的可移植性边界**：桶序、扩容
  时机都是实现自由——本教程全程不遍历打印 unordered 容器（docs/01 纪律），
  实验一律用自造表 + 整数探查计数。

## 与 STL 对照

| 本章 | STL | 差异 |
|---|---|---|
| 链址表 | `std::unordered_map`（标准不锁实现，主流是链址/桶） | 语义对齐，实现细节自由 |
| 开地址表 | 无直接对应（`std::flat_map` VS18 新落、内部是排序向量，且被本教程禁用） | 自写 |
| 全域散列 | 无 | 密码学场景用 SipHash 等更现代的方案 |

`unordered_map` 的工程要点：reserve 预留（避免中途 rehash）、自定义
hash 时注意键域对抗性（服务端用随机化种子防 HashDoS——全域散列的
工程化身）、最坏 O(n) 查找在实时系统里要掂量。

## 坑位清单

1. **二次探查在 m ≡ 1 (mod 4) 时装到一半就「假满」**
   （现象：表明明还有空槽，insert 却返回失败；原因：k+i² 模 m 只能访问
   (m+1)/2 个位置——全覆盖要求 m ≡ 3 (mod 4) 或 m 为 2 的幂+特殊处理；
   后果：α 不到 0.6 就插入失败；对策：m 选 103 这类 3 mod 4 素数——
   本例最初用 m=101（≡1 mod 4）装 92 个键，推演时发现必炸而改。）
2. **开地址法做「删除」直接置空槽**
   （现象：删除后同槽线索上的其他键查找失踪；原因：探查序列被空槽
   截断——中间的洞让后继探查提前「未找到」终止；后果：静默丢数据；
   对策：删除标记（DELETED 哨兵值）或改链址法；插入可复用 DELETED，
   查找遇 DELETED 继续走。）
3. **遍历打印 unordered 容器**
   （现象：三通道输出不一致，对账必炸；原因：桶序由哈希函数与扩容
   历史决定，跨实现/跨版本不同；后果：文档输出块无法对账；对策：
   排序后再打印或换 `std::map`（本教程高压线，示例全部用自造表+计数）。）
4. **m 取 2 的幂 + 键有低位规律**
   （现象：程序员姓名表全挤进几个桶；原因：k mod 2^r 只看低 r 位，
   键的低比特高度相关时等于没散列；后果：链长暴涨，退化成链表扫描；
   对策：m 取素数（除法法）或先乘法混合（乘法法/万能 h）。）
5. **α 不监控、不扩容**
   （现象：负载爬到 0.95 后服务延迟毛刺百倍；原因：1/(1−α) 在 α→1
   处爆炸（0.95 → 20 次、0.99 → 100 次）；后果：性能悬崖无预警；
   对策：装填阈值（典型 0.7~0.75）触发 rehash，容量翻倍重散列。）
