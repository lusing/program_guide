# 21 · van Emde Boas 树

> 对应 CLRS 第 20 章 *van Emde Boas Trees*（英文 3rd ed. pp.531–560）。
> 散列的字典操作期望 O(1) 但**没有顺序语义**（MIN/SUCCESSOR 无力）；
> 平衡树有顺序但 O(lg n)。vEB 树两头都要：**整数全域** [0, u) 上的
> 字典 + 顺序操作，全部 O(lg lg u)。代价是 Θ(u) 的空间。

## 学习目标

1. 能画出 u=16 的递归结构（簇 + 汇总位图）；
2. 能推 INSERT/MEMBER/SUCCESSOR 的递归式 T(u) = T(√u) + O(1) =
   O(lg lg u)；
3. 理解「min 不重复存储在簇里」这一不变式的作用；
4. 知道 vEB 的适用边界（u 巨大时空间不可行 → 位图压缩/X-fast 树）。

## 结构：递归的「平方根簇」

全域 u = 2^{2^k}（本例 u = 16 = 2⁴）。每个 vEB(u) 节点包含：

- **min / max**：直接存字段（O(1) 读）；
- **cluster[√u]**：√u 个 vEB(√u) 子结构，第 i 簇负责整数区间
  [i·√u, (i+1)·√u)；
- **summary**：一个 vEB(√u) 位图，第 i 位 = 「簇 i 是否非空」。

元素的定位：x 的簇号 = ⌊x/√u⌋，簇内偏移 = x mod √u。递归到 u=2 时
只剩 min/max 两个「位」。u=16 → 簇是 vEB(4) → 其簇是 vEB(2)，**递归
深度 3 = lg lg u + 1**。

**关键不变式**：min 存的元素**不再出现**在任何簇中（消除重复表示）——
它让「空树判断」与「最小值读取」都 O(1)，且插入时旧 min 下沉进簇、
新 min 直接置位，账目永远平衡。

## 操作与递归式

**INSERT**（CLRS 20.3）：空树直接置 min=max；否则若新值 < min，换位
（旧 min 下沉进簇）；簇从空变非空时在 summary 里置位；递归插簇。
递归只发生在「簇内」——**每层递归全域开平方**：

T(u) = T(√u) + O(1) ⟹ 令 m = lg u：T'(m) = T'(m/2) + O(1) = O(lg m)
= **O(lg lg u)**。

**SUCCESSOR(x)**：三处候选——min（若 x < min）、x 所在簇的簇内后继、
summary 找下一个非空簇（取其 min）。**至多一次簇内递归 + 一次 summary
递归**，同为 T(√u) + O(1) 的形状。u=16 时 successor(5) 的实测路径：
「簇 1 内偏移 1 之后无 → summary 找到簇 3 → 取簇 3 的 min = 14」。

实测（示例 21，u=16，插入 2 3 4 5 7 14 15）：

```
min = 2，max = 15（O(1) 直接读字段）
successor(5) = 7（跨簇：簇 1 的偏移 1 之后无 → 汇总找簇 3）
16 个值的 member/逐位后继与朴素位图全部一致 = 1,1
```

全量对账的做法：u=16 很小，用朴素位图逐值核对 member 与 successor——
结构正确性与「每层只递归一次」的实现纪律都在这 32 个断言里过一遍。

## 空间与工程边界

Θ(u) 空间是 vEB 的命门：u = 2⁶⁴ 不可行，u = 2¹⁶ 也偏贵。工程变体：

- **位图 + 字/块分桶**（Roaring bitmap）：稀疏区间直接位图、稠密区
  压缩——数据库与搜索引擎的实用路线；
- **X-fast / Y-fast 树**：vEB 思想 + 散列，空间 O(n) 而保持
  O(lg lg u) 期望；
- 竞赛圈的 std::set/平衡树 + 离散化：u 大时先「坐标压缩」到 O(n)，
  再上任意平衡结构——**vEB 的 O(lg lg u) 只有 u 与 n 同量级时才值回票价**。

## C++23 语言点

- `std::countr_zero(u)/2` 求 √u（u 是 2 的幂时 lg u = 尾零数）——
  第 3 章 bit_width 恒等式的姊妹用法；`__builtin_ctz` 不可移植
  （本例首版实测踩雷，MSVC 无此内建）；
- 递归结构用 `Veb*` 指针数组懒分配（空簇不建对象）——空间省在
  「没碰过的簇」上；
- 示例收缩到 u=16（计划注记）：递归深度 3、全量对账便宜，教学清晰度
  优先。

## 与 STL 对照

无对应容器。`std::set` 有顺序但 O(lg n)；`std::bitset`/`std::vector<bool>`
有 O(1) member 但 successor O(u)。vEB 填的是「整数键 + 顺序操作」的
空档——现实工程里 Roaring bitmap 与 B+ 树范围扫描各占了这个生态位的
一半。

## 坑位清单

1. **用 `__builtin_ctz` 这类编译器内建**
   （现象：gcc/clang 过、MSVC 编译错误；原因：内建函数非标准；
   后果：通道全红但代码「看起来没错」；对策：`std::countr_zero`/
   `std::bit_width`（`<bit>`，C++20 起）——本例实测翻车。）
2. **min 同时也存进簇里**
   （现象：member(min) 恒真但簇内重复计数、successor 跳错；原因：vEB
   的「min 不入簇」不变式被破坏，双表示导致两条路径不一致；后果：结构
   语义漂移；对策：插入时 min 换位后旧值才下沉；删除 min 时从簇里取
   新 min 上提（CLRS DELETE 的对称操作）。）
3. **summary 忘记在「簇从空到非空」时置位**
   （现象：successor 跨簇时找不到下一个非空簇，返回 −1；原因：summary
   的语义是簇的存在位图，插入首元素时必须 insert(c)；后果：顺序操作
   静默漏解；对策：全量 successor 对账（本例 16 值扫描）一抓一个准。）
4. **u 不是 2 的幂还硬套 √u 分解**
   （现象：簇大小/偏移计算错位、递归深度不对；原因：vEB 要求
   u = 2^{2^k}（√u 整数且递归同构）；后果：越界与死递归；对策：入口
   断言 u 是 2 的幂，非 2 幂的全域向上取整到 2 幂。）
