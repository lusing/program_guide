# 22 · 不相交集（并查集）

> 对应 CLRS 第 21 章 *Data Structures for Disjoint Sets*（英文 3rd ed.
> pp.561–581）。并查集只回答一个问题：「x 和 y 在同一集合吗？」——
> 但它把这个问题做到近乎免费的代价：按秩合并 + 路径压缩的**摊还
> O(α(n))**，α 是反阿克曼函数（现实 n 下 ≤ 4）。它是第 24 章 Kruskal
> 的发动机，也是「摊还分析 + 聪明启发式 = 理论极致」的教科书案例。

## 学习目标

1. 会实现 find（路径压缩）与 union（按秩合并）；
2. 能陈述联合界 O(m·α(n)) 的含义（α 的定义与「现实 ≤ 4」）；
3. 能读实测数据说话：对抗负载下朴素/按秩/压缩的 471 倍差距；
4. 知道链表版与森林版各自的操作画像与工程取舍。

## 链表版 vs 森林版（§21.2）

**链表版**：每个集合一条单链 + 表头/表尾指针。UNION 是拼接 O(1)；
FIND 沿链走 O(1)（如果每个节点存表头指针）；但**加权合并启发式**
（短链并入长链）下 m 次操作的总代价 O(m + m lg m)——每次「被并入」
让节点换表头，短并长保证每点至多换 lg m 次。链表版的教训：**合并的
方向决定摊还**——这正是森林版「按秩」的雏形。

**森林版**（主流）：每个集合是一棵根树，节点只存 parent。FIND 沿
父链上行到根；UNION 把一棵根树挂到另一棵的根下。两件事决定性能：

1. **按秩合并**（UNION BY RANK）：把浅树挂到深树下（秩 ≈ 未压缩时
   的高度上界）。树高 O(lg n)；
2. **路径压缩**（PATH COMPRESSION）：FIND 顺带把沿途节点直接挂到
   根——链变星。

```cpp
int find(int x) {
    int root = x;
    while (parent[root] != root) { root = parent[root]; ++steps; }
    if (compress) {                     // 二趟压缩（沿途直挂根）
        int cur = x;
        while (parent[cur] != root) {
            const int nxt = parent[cur];
            parent[cur] = root;
            cur = nxt;
            ++steps;                    // 压缩这趟也计账——摊还要算总账
        }
    }
    return root;
}
```

注意示例把压缩的第二趟也计入 steps——**摊还账本不能只算便宜的那趟**
（与第 20 章斐波那契堆同一纪律）。

## 联合界：O(m·α(n))

定理 21.4（Tarjan 1975）：n 个元素上 m 次操作的**总**代价
O(m·α(n))，α 是阿克曼函数的逆——增长慢到 n 是可观测宇宙的原子数也
只有 ~4。证明用**势能法**（第 18 章的巅峰应用）：按等级/层次给节点
分级，势函数吸收压缩的「级联收益」。要点直觉：秩单调不增？不——秩
只增不降（挂树时大根吸收），压缩不改变任何节点的秩；秩 ≤ lg n 的树
构成「平缓」结构，级联压缩每一步都让节点「升级」，而级数被 α 控制。

**工程读法**：α(n) ≤ 4 意味着**并查集的每次操作 ≈ 常数次指针追迹**。
实测（示例 22.3，n=5000，链式对抗负载 (1,0)(2,0)(3,0)…+随机混合，
2500 次 union + 5000 次打链底 find）：

```
A 朴素（不按秩/不压缩）：find 总步数 6670164
B 按秩 + 不压缩         ：find 总步数 14146
C 按秩 + 路径压缩       ：find 总步数 7397（摊还 O(α(n))，α(5000) ≤ 4）
```

471 倍与 900 倍的差距：朴素版长出 2500 级长链，每次 find(0) 走全程；
按秩版树高被 lg n 封顶；压缩版首查拉平、后续近 O(1)。而三种配置的
**等价类划分逐点一致**——启发式只改性能不改语义（示例的分区对账
断言）。

## 应用与变奏

- **Kruskal 最小生成树**（第 24 章）：边按权排序，两端点已连通则弃——
  并查集让「已连通」查询 O(α)；
- **离线 LCA**（Tarjan）：DFS + 并查集把最近公共祖先批量到 O(α)；
- **带权并查集**（扩展）：节点存「到父的相对权」，FIND 压缩时路径
  累加——判「x,y 的大小/奇偶关系」类问题（食物链/关押罪犯）；
- **可撤销并查集**（不压缩、只按秩）：按秩保证 O(lg n)，撤销 = 弹栈
  恢复父指针——回溯搜索（第 26 章? 动态连通性）用。

## C++23 语言点

- `std::iota(parent.begin(), parent.end(), 0)` 一行初始化自指森林；
- 按秩用 `rank_` 命名避开 C++ 的 `std::` 与 Windows 头 `rank` 宏撞名
  （MinGW 的 `<numeric>` 链上偶发）；
- 结构化绑定遍历操作对 `for (auto [x, y] : ops)` 的写法。

## 与 STL 对照

无标准并查集（`std::disjoint_set` 未进标准）。手写 20 行是行业惯例；
竞赛模板几乎人手一份。**别用 `std::set<std::set<...>>` 硬拼**——
集合的集合既慢又难写对。

## 坑位清单

1. **union 只改 parent 不查根**
   （现象：集合「分裂」回旧状态、连通性判断错乱；原因：unite(a,b)
   直接 parent[a]=b 而不是 parent[find(a)]=find(b)；后果：语义错误；
   对策：unite 入口先 find 双根（本例写法），配分区对账断言。）
2. **按秩合并写成「按大小」混用**
   （现象：性能略差但正确——但「按秩 + 压缩」的定理证明依赖秩语义；
   原因：rank 应为高度上界，压缩不更新秩；对策：注释写清「压缩不降秩」，
   按大小的版本叫 union by size，另起字段。）
3. **对抗负载用随机对，测不出差距**
   （现象：三配置步数同量级，怀疑定理白板；原因：随机 union 的链天然
   短，朴素版没有被逼到最坏；后果：性能结论不可信；对策：负载要含
   对抗序列（(i,0) 链式合并）——本例首版实测全随机无差距后重设负载。）
4. **压缩的路径第二趟不计数**
   （现象：C 的步数「奇迹般」小于理论直觉；原因：只统计第一趟（找根），
   压缩这趟的遍历被藏起来；后果：摊还账本造假；对策：两趟都 ++steps
   （本例修正后的写法）。）
