## 最长公共子序列（§15.4）

**问题**：X = ⟨x₁..xₘ⟩、Y = ⟨y₁..yₙ⟩，找最长的公共子序列（可断续、
保序）。X = ABCBDAB、Y = BDCABA 时 LCS 长度 4（如 BCBA）。

**递推**（状态 = 两串的前缀对 (i, j)）：

```
c[i,j] = 0                          若 i=0 或 j=0
       = c[i-1,j-1] + 1             若 x_i = y_j      （对角）
       = max(c[i-1,j], c[i,j-1])    否则              （上/左取大）
```

**最优子结构**：两末字符相等时它必在**某个** LCS 里（去掉它，剩下的
是两个更短前缀的 LCS）；不等时至少一端的末字符不在 LCS 中——两种
「退一格」的子问题必有一个保住最优。Θ(mn) 时间与空间。

**重构**：b 表记录每格的来向（↖/↑/←），从右下角回溯到边界即得 LCS
本身（示例 16.1 从 "ABCBDAB"/"BDCABA" 重构出 `BCBA`，并用
`is_subsequence` 双向验证——重构结果必须同时是两串的子序列）。

```
LCS（图 15.8 数据 X=ABCBDAB, Y=BDCABA）：
  长度 = 4，重构出的 LCS = "BCBA"
  c 表右下角（D A B 行 × 末 3 列）: 2 3 3 / 3 3 4 / 3 4 4
```

## 最优 BST（§15.5）

**问题**：n 个键 k₁<…<kₙ（查找概率 pᵢ）与 n+1 个伪键 d₀..dₙ（ miss
概率 qⱼ，落在键间隙）。造 BST 使**期望搜索代价** Σpᵢ·(depth(kᵢ)+1) +
Σqⱼ·(depth(dⱼ)+1) 最小。平衡 BST 只是最优的特例——概率偏斜时最优树
**故意不平衡**（把高频键放浅处）。

**递推**（状态 = 区间 [i,j] + 根的选择）：

```
e[i,j] = q_{i-1}                                  若 j = i−1（空树，只剩伪键）
       = min_{i≤r≤j} { e[i,r−1] + e[r+1,j] + w[i,j] }
w[i,j] = w[i,j−1] + p_j + q_j                     （区间总概率，增量维护）
```

**关键洞见**：选定根 k_r 后，深度全体 +1 的代价恰是 w[i,j]（子树全体
概率和）——于是 e 由「两半子问题 + 区间概率和」构成。Θ(n³) 时间。

CLRS 图 15.10 的 5 键例（p=⟨.15,.10,.05,.10,.20⟩，
q=⟨.05,.10,.05,.05,.05,.10⟩）实测：

```
最优 BST（图 15.10 数据，5 键）：期望搜索代价 = 2.750000（CLRS 答案 2.75）
  根 = k2（root[1][5]），子树根 root[2][5] = k4
```

最优树把 p=0.20 的 k₅ 放在深度 2、高频 k₁/k₂ 在顶部——与「均匀键就
平衡」的直觉对照鲜明。

## 编辑距离：LCS 骨架的变奏（实战延伸）

d[i,j] = x 前 i 与 y 前 j 的最少编辑数（插/删/改），递推与 LCS 同构、
只是格子值换语义：

```cpp
d[i][j] = min({ d[i-1][j] + 1,          // 删 x_i
                d[i][j-1] + 1,          // 插 y_j
                d[i-1][j-1] + cost });  // cost = 0（相同）或 subCost（改）
```

**恒等式做交叉验证**：替换代价取 2（替换不划算 ⇒ 事实上的只插删）时，
d = m + n − 2·LCS——两个独立实现的 DP 互相锁死（示例 16.4）：

```
编辑距离（Levenshtein，替换代价 1）：kitten→sitting = 3（经典 3 步：改 k→s、改 e→i、插 g）
  ABCBDAB vs BDCABA：Levenshtein = 5，插删距离 = 5（= 7+6−2×LCS4 = 5，恒等式验证）
```

应用谱系：`diff`（插删 + 块移动）、拼写检查（Levenshtein ≤ k 的词典
扫描）、DNA 序列比对（改错罚分不对称的加权版）、`git` 的 Myers diff
（O(ND) 的 D=编辑距离算法——工程版再优化一层）。

## 最长不升子序列：二分尾替换与反链

本节两个小节共享一个主角：**偏序**。前者是「一维偏序（不升关系）上的最长
链」，后者是「二维偏序（网格坐标偏序）上的最小链覆盖」。

### LNIS：尾替换 + 二分把 Θ(n²) 降到 Θ(n log n)

**问题**：n 只鹰，高度 hᵢ。箭必须**依次不升**地射出（后一支不超过前一
支），问最多能射落多少只，并给出这个高度序列。

**状态设计（Θ(n²) DP）**：`f[i]` = 以第 i 只结尾的最长不升子序列长度。

```
f[i] = 1 + max{ f[j] : j < i 且 h[j] ≥ h[i] }        （空集取 0）
```

注意比较是 **≥ 而不是 >**——「不升」允许相等元素接续。这是本节最容易
写错的一个符号。

**归一化：LNIS(h) = LNDS(−h)**。令 bᵢ = −hᵢ，则

```
h_{i₁} ≥ h_{i₂} ≥ … ≥ h_{i_k}    ⟺    b_{i₁} ≤ b_{i₂} ≤ … ≤ b_{i_k}
```

「不升」与「不降」在取负下互换。于是只需要会求**最长不降子序列**（LNDS）。

**尾替换 + 二分（Θ(n log n)）**。维护数组 `d`：

> **不变式**：`d[k]` = 已处理元素中，长度为 k+1 的**不降**子序列的**最小
> 可能末尾值**。`d` 保持非降。

对每个 `b[i]`：

```
p = upper_bound(d.begin(), d.end(), b[i])     // 第一个 d[p] > b[i] 的位置
if p > 0: 存在长度 p 的不降子序列末尾 ≤ b[i]，接上 b[i] 得长度 p+1
d[p] = b[i]                                    // p 可能是 d.size()（追加）
答案 = d.size()
```

正确性两条：

1. **不变式保持**。`d[0..p−1] ≤ b[i] < d[p]`，由 `d[p−1] ≤ b[i]` 知接上后
   长度 p+1 可达；又 `b[i] < d[p]` 使末尾变小，按定义该长度的新最小末尾
   就是 b[i]。`d` 仍非降。
2. **无遗漏**。对任何长度 k+2 的不降子序列，去掉末元素后的长度 k+1 前缀
   末尾 ≤ b[i]，由不变式该末尾 ≥ d[k]，故 d[k] ≤ b[i]，即 b[i] 能接在
   长度 k+1 之后。所有可能都被覆盖。

#### 为什么必须 `upper_bound` 而不是 `lower_bound`

这是本节的核心陷阱，两者差一个字符，答案却不同：

| | 返回位置 p 的条件 | 后果 |
|---|---|---|
| `lower_bound` | 第一个 `d[p] ≥ b[i]` | 相等元素被**截断在更靠前的槽位**，丢��「相等接续」 |
| `upper_bound` | 第一个 `d[p] > b[i]` | 越过所有相等槽位，**相等元素可以接续** |

**最小反例**：`h = [5, 5, 5]`，答案显然是 3（三个 5 互相接续）。

- 用 `upper_bound`（对 b = [−5,−5,−5]）：`d` 依次为 [−5]、[−5,−5]、��−5,−5,−5]，
  得 **3** ✓
- 用 `lower_bound`：每个 −5 都写回 `d[0]`，`d` 始终是 [−5]，得 **1** ✗

原因这样看最清楚：`d` 的语义是"长度 k+1 的**最小**末尾"。来了一个与
`d[p]` **相等**的 b[i] 时，它不能改善 `d[p]`（最小值没变小），但它**应该**
被记到更长的那一档去（长度 p+2 只需要 `d[p+1] ≤ b[i]`，而 d[p] = b[i]
恰好满足）。`upper_bound` 跳到相等段之后的第一个空槽，正是这个意思；
`lower_bound` 停在相等段开头，把它又写回原位，长度就再也涨不上去了。

记忆法：**「允许相等接续」 ⟺ 用 `upper_bound`（默认 `less` 比较器时）**。
如果不用取负而直接对 h 求（配 `std::greater`），配对关系会反过来——这也是
为什么**推荐统一用"取负 + 默认比较器"**：只记一条规则就够了。

**路径还原**（题目要输出序列时）：`d` 的下标是"长度"、`pre` 存的是"元素
下标"，两者语义不同，必须靠 `tailIdx` 桥接：

```cpp
std::vector<int> d, tailIdx;
std::vector<std::size_t> pre(n, /* 无 */);
for (std::size_t i = 0; i < n; ++i) {
    const std::size_t p = std::upper_bound(d.begin(), d.end(), b[i]) - d.begin();
    if (p > 0) { pre[i] = tailIdx[p - 1]; }        // 前驱 = 长度 p 的最优末尾下标
    if (p == d.size()) { d.push_back(b[i]); tailIdx.push_back(i); }
    else { d[p] = b[i]; tailIdx[p] = i; }
}
// 沿 pre 从 tailIdx.back() 回溯
```

### 另一种求法：LCS 归约（Θ(n²)，但通用）

「单调子序列」可以归约到本章的 LCS 骨架上：

```
LNIS(A) = LCS(A, sort_desc(A))
```

B = A 的**降序排序**。双向夹逼证明：

- **(≤)** 任一 A 的最长不升子序列 s：s 是 A 的子序列 ✓；s 本身不升，
  而 B 是降序排列的，**s 的元素在 B 中也保持同样的相对顺序**（相等元素
  可任意交换，不影响"是子序列"这件事）⟹ s 是 B 的子序列。故 s 是公共
  子序列，LNIS ≤ LCS。
- **(≥)** 任一 A 与 B 的公共子序列 s：s 是 B 的子序列，而 B 不升 ⟹ s 也不
  升；s 又是 A 的子序列 ⟹ s 是 A 的不升子序列。故 LCS ≤ LNIS。

两向夹逼得证。注意 `sort_desc` 里的"降序"是**针对目标单调性**的：求
LNIS 用降序，求严格下降子序列则不能这么归约（见下一小节的反链部分）。

**Θ(n²) vs Θ(n log n)**：二分尾替换更快且能直接还原序列；LCS 归约慢一个量级
但**通用**——任何"单调子序列"问题都能这样塞进已有的 LCS 代码。

#### 一个必须澄清的边界：`LCS(A, reverse A)` **不是** LNIS

这是流传很广的一个错误归约。`LCS(A, reverse A)` 求的是**最长回文子序列**
（LPS）——公共子序列必须同时出现在 A 和它的逆序里，那天然是"左右对称"
的结构，与"单调"无关。

反例：A = [2, 1, 3]。LNIS = 2（子序列 [2,1] 不升）；而 reverse A =
[3, 1, 2]，LCS(A, reverse A) = 1（公共子序列只能是 [1] 或 [2] 这类单元素，
[2,1] 在 A 里是 2 先 1，在逆序里 1 在前 2 在后，顺序对不上）。

两个归约的对照：

| 归约 | 求的是 | 正确？ |
|---|---|---|
| `LCS(A, sort_desc(A))` | 最长不升子序列 | ✓ |
| `LCS(A, sort_asc(A))` | 最长不降子序列 | ✓ |
| `LCS(A, reverse A)` | **最长回文子序列** | ✗（不是单调子序列） |

### 反链与最小覆盖：Dilworth 定理的竞赛用法

现在把话题从一维推广到二维。**清洁机器人**问题：m × n 场地，部分格子
有垃圾。机器人从 (1,1) 进场、走到 (m,n) 离场，只能**右**或**下**移动，
经过的格子自动清空。一个格子**可以**被多个机器人经过。求最少机器人数。

#### 第一步：机器人 ↔ 链

在网格上定义偏序

```
(a, b) ⪯ (c, d)   ⟺   a ≤ c 且 b ≤ d
```

（坐标变大 = 走得更远 = 至少一样"靠后"）。垃圾格集合记作 S。

- 一条单调路径上的 S 中元素构成一条**链**（沿路坐标都不减 ⟹ 两两可比较）。
- 反之任何一条**链**都能被一条单调路径覆盖（链上坐标都不减，可以逐步
  右/下走完，中间的空格无所谓）。

**双向对应成立** ⟹ 「用最少的机器人清完」= 把 S 划分成**最少的链**。

#### 第二步：Dilworth 定理 ⟹ 答案 = 最大反链

> **Dilworth 定理**：有限偏序集上，**最小链划分数 = 最大反链大小**。
> 反链（antichain）= 两两**不可比**的集合。

两条直观的解读：

- **下界**（好证）：反链里任意两点都不能被同一条单调路径覆盖（否则它们
  可比），所以至少要 |反链| 个机器人。
- **上界**（定理给的）：存在恰好 |反链| 条链的划分。

**第三个等价形式**（用二分图匹配，第 27 章的工具）：

```
最小链覆盖数 = |S| − 二分图最大匹配数
```

建图：每个格子拆成左点 s_L 与右点 s_R；若 `u ⪯ v` 且 `u ≠ v` 则连边
u_L → v_R。**必须连传递闭包，不是只连相邻格**。一条匹配边 u_L → v_R 表示
"u 后面紧接 v 在同一条链上"，|S| − 匹配数 = 链的条数（每条匹配边把两段
链粘起来，粘一次少一条链）。这条路线 Θ(|S|^{2.5})（Hopcroft–Karp），
|S| ≤ 576 时可行但通常不必用——因为网格偏序有更好的刻画。

#### 第三步：最大反链 = 排序后的 LDS（Θ(|S| log |S|)——竞赛里的标准套路）

网格偏序的最大反链有个**显式刻画**，于是整个偏序理论塌缩成一次排序 +
一次最长下降子序列：

> **结论**：把 S 按 **(i 升, j 降)** 排序，则 **j 序列的最长严格下降子序列
> （LDS）长度 = 最大反链大小 = 答案**。

**为什么？** 反链 = 一组点，**按 i 递增排列时 j 必须严格递减**：

- **不同 i**（i₁ < i₂）：不可比要求 `NOT(j₁ ≤ j₂)`（否则 (i₁,j₁) ⪯
  (i₂,j₂)），即 **j₁ > j₂** ✓ 严格递减。
- **相同 i**：`(a, j₁) ⪯ (a, j₂) ⟺ j₁ ≤ j₂`，故不可比要求 j₁ ≠ j₂。按
  "同 i 内 j **降序**"排序后取**严格**下降子序列，同 i 的两点若都被选中，
  则 j₁ > j₂ ✓ 恰好互不可比。

**"同 i 内按 j 降序"这一步不能省**：输入通常按行优先给出，同一行内是 j
**升序**。若不重排，同 i 的两个点会以 j₁ < j₂ 的顺序进入序列，严格下降
子序列只可能取到其中一个，反链大小被低估。

**求 LDS**：对 `−j` 序列求**最长严格上升**（用 `lower_bound`），或对 j
序列直接用 `lower_bound` + `std::greater`。注意这里是**严格**下降，
所以配 `lower_bound`（上一节的 LNIS 是**不升**，配 `upper_bound`——
两处的"严格性"恰好相反，不是记错而是问题本身不同）。

**LDS 的 Θ(n log n) 实现**：

```cpp
std::vector<int> t;                                  // 对 −j 求严格上升
for (int j : js) {
    const int v = -j;
    const auto it = std::lower_bound(t.begin(), t.end(), v);
    if (it == t.end()) { t.push_back(v); } else { *it = v; }
}
answer = t.size();
```

#### 完整推导链

把四步串起来，每步都有严格依据：

```
最少机器人数
  = 把 S 划分成最少的链            （机器人 ↔ 单调路径，双向对应）
  = 最大反链的大小                  （Dilworth 定理）
  = |S| − 二分图最大匹配            （Dilworth 的匹配形式，Θ(n^2.5)）
  = 按 (i 升, j 降) 排序后 j 序列的最长严格下降子序列长度   （显式刻画，Θ(n log n)）
```

**这是偏序理论在竞赛里的标准套路**：当"最优划分 = 最小链覆盖"出现时，先
找偏序，再用 Dilworth 转成最大反链，然后**在网格/坐标这种特殊偏序上直接
把反链算出来**（排序 + LDS），绕开匹配算法。

本示例给出三条独立路线并要求它们**逐位对账**（示例 16.6）：LDS 解法、
暴力枚举 2^|S| 子集求最大反链、二分图最大匹配。三者一致才算过。

实测（示例 16.6）：

```
=== 16.6 最小单调路径覆盖 = 最大反链 = |S| − 二分图最大匹配 ===
  垃圾格 S = [(1,2), (1,4), (2,4), (2,6), (4,4), (4,7), (6,6)]
  按 (i 升, j 降) 重排后 j 序列 = [4, 2, 6, 4, 7, 4, 6]
  LDS（j 的最长严格下降子序列）= 2
  暴力最大反链（枚举 2^7 子集）= 2
  二分图最大匹配（传递闭包 + 增广路）= 5 ⟹ |S| − 匹配 = 7 − 5 = 2
  三者一致 ⟹ 最少机器人 = 2 个（三步链条：链划分 → Dilworth → 反链 → LDS）
  对照 S = [(1,1),(2,2),(4,4)]：j 序列 = [1,2,4] 全升 ⟹ LDS = 1，最大匹配 = 2 ⟹ |S| − 匹配 = 1（一条单调路径清完）
  空网格 S = []：LDS = 0，最大匹配 = 0 ⟹ 最少机器人 = 0 个
```

顺带说清楚"每轮派一个走最大收益路径"的贪心：它的**下界侧**严格可证
（把每轮标记一层，反链的 |A| 个点必须分布在 ≥ |A| 层 ⟹ 轮数 ≥ 最大反链），
但**上界侧**需要"逐轮取最大权链得到最优链分解"这个结论，证起来远不如上面
那条链直接。**同样结果下，LDS 解法 Θ(|S| log |S|) 比贪心的 Θ(k·mn) 更快
且有完整证明**——这是"把贪心换成偏序语言"的一个典型收益。

### LNIS 实测（示例 16.5）

三条路线（Θ(n²) DP / Θ(n log n) 尾替换 / Θ(n²) LCS 归约）在 8 个高度上
给出同一答案，且三条序列都通过"是 h 的子序列且不升"的双向断言：

```
=== 16.5 最长不升子序列（LNIS）：二分尾替换 vs LCS 归约 ===
  高度序列 h = [389, 207, 155, 300, 299, 170, 158, 65]
  (a) Θ(n²) DP        LNIS = 6，序列 = [389, 300, 299, 170, 158, 65]
  (b) Θ(n lg n) 尾替换 LNIS = 6，序列 = [389, 300, 299, 170, 158, 65]
  (c) Θ(n²) LCS 归约   LNIS = 6，序列 = [389, 300, 299, 170, 158, 65]
  三法长度一致 = 1，三条序列都通过「是 h 的子序列且不升」双向断言 = 1
  反例 h = [5,5,5]：upper_bound 得 3（正确，3 个 5 互相接续），lower_bound 只得 1（错，截断了相等接续）
  边界：LCS(A, reverse A) 是**最长回文子序列**不是 LNIS——A = [2,1,3]：LNIS = 2（[2,1]），而 LCS(A, rev A) = 1（[1] 或 [2]）
```

## 石子合并：区间 DP（直线 / 圆环，最小 / 最大）

### 问题

操场上排成一排的 n 堆石子，每堆有确定的数目。每次可以选**相邻**两堆
合并成一堆，这次合并的花费等于两堆石子数之和。求把全部石子合成一堆
的**最小总花费**与**最大总花费**。再把「一排」改成「一圈」（首尾两堆
也算相邻），重新回答这四个数。

### 状态与递推：最后一次合成为什么总是加区间总和

记区间 `[i,j]` 内石子的总数为 w(i,j)（用前缀和 O(1) 取）。设
`mn[i][j]` 为把第 i～j 堆合成一堆的最小花费。无论内部怎么合，最后
一步必然是把 `[i,k]` 的合成结果与 `[k+1,j]` 的合成结果并成一堆，
切点 k 可取 i～j−1。于是

```
mn[i][j] = min_{i ≤ k < j} ( mn[i][k] + mn[k+1][j] ) + w(i,j)
mx[i][j] = max_{i ≤ k < j} ( mx[i][k] + mx[k+1][j] ) + w(i,j)
边界：mn[i][i] = mx[i][i] = 0（一堆不用合）
```

`+ w(i,j)` 是本问题的灵魂：最后一步两堆的总重就是整个区间的石子和，
**与切点 k 无关**。区间内部的历史由两个子区间的最优值负责——这正是
最优子结构。计算顺序按区间长度 2,3,…,n 递增（长区间只依赖更短的
区间）。同时记录最优切点 `cut[i][j]`，即可像表达式树一样重构整棵
合并树（内层先合并）：

```
6 堆 [5,8,6,9,2,3] 的最小合并树：(((5 8) 6) (9 (2 3)))
```

### 最大值的端点性质：把 O(n³) 观察降成 O(n²)

最大值有一个最小值不具备的性质：**总存在一个最优方案，让端点的某
一堆（第 i 堆或第 j 堆）单独留到最后一次合并才被吸收**。交换论证：
任取方案的最后一次合并，若分界两边都至少含两堆，就沿其中一侧内部
的最后一次合并拆开、把端点堆改成全程单堆，单堆越晚被吸收，它的
重量在逐次合并中被重复计入的次数越多，总花费不减；反复交换即得
端点最后被吸收的最优方案。因此

```
mx[i][j] = max( mx[i][j-1], mx[i+1][j] ) + w(i,j)
```

注意该性质**只对最大值成立**——最小值老老实实枚举切点。示例的 O(n³)
通用枚举与端点公式在随机小例上 0 例不一致。

### 圆环：枚举 n 个切口，等价于 n 个直线问题

圆环上首尾可以相连。任何一个圆环合并方案，取它**最后一次合并**的
接缝处切开，就得到一个直线排列上的合法方案（该接缝在整条历史中
相当于从未被用作「相邻」的那个缺口）；反过来直线方案显然也是圆环
方案。所以圆环最优值 = n 种切口下直线最优值的最小/最大。实现技巧：
把数组复制拼接成长度 2n−1 的数组，一次 DP，再扫描 n 个长度为 n 的
窗口 `[i, i+n−1]`。**不能直接在整段 2n−1 上取答案**——那会允许同一
堆石子被使用两次。

### 复杂度与对账

直线、圆环均为 O(n³) 时间 / O(n²) 空间（最大值可 O(n²)；最小值另有
四边形不等式 O(n²) 优化，见练习）。示例对 6 堆样例给出直线
84/129、圆环 81/130，并与**暴力枚举全部合并历史**（圆环允许合并
首尾）四向对账完全一致；3000 个 n≤6 随机例 0 例不一致、端点性质
0 例违反；300 堆大例验证答案不小于单趟总和这个平凡下界。

## 安排公司聚会：树上的 DP

公司组织是一棵以董事长为根的树，员工 v 有一个快乐值 happy[v]（可能为负）。
规则：**直属上下级不能同时参加聚会**。目标是选择参加者，使快乐值总和最大。

### 子问题与状态

按「前 n−1 个员工」切分子问题没有意义——规则依赖的是树结构。正确的子问题是
子树：对每个节点 v 定义两个状态

| 状态 | 含义 | 取值 |
|---|---|---|
| yes[v] | v **参加**时，v 的子树能达到的最大总和 | happy[v] + Σ no[c] |
| no[v] | v **不参加**时的最大总和 | Σ max(yes[c], no[c]) |

求和范围是 v 的所有孩子 c。第一式：v 参加，所有孩子必须不参加，只有孙子辈开始
自由——所以加的是每个孩子的 no 值；叶子节点 yes = happy、no = 0。第二式：
v 不参加，孩子之间互不影响，每个子树各自取较优状态。根处答案 max(yes[根],
no[根])。

### 方案还原与计算顺序

DP 只给数值，名单要再走一遍树：根取较优状态；沿树向下，若 v 不参加则每个孩子
各自比较决定，若 v 参加则孩子一律不参加。

计算顺序要求「处理 v 之前所有孩子已处理」。对大树**不能写递归 DFS**：一棵两万
层的链会让调用栈溢出。做法是先从根生成遍历序（父在子前），逆序处理该序列就
等价于后序遍历——整个算法无递归、O(n) 时间、O(n) 空间。

### 对账

示例对一棵 10 人组织（快乐值含负数，检验算法不是「正数照单全收」）运行树 DP，
与枚举全部 2¹⁰ 个参加子集（有父子同时在列即非法）的暴力真值一致；还原出的
名单重算总和等于 DP 值，且名单中不存在父子。2000 棵 n≤12 的随机树（每个节
点的父亲在更早节点中随机选取、快乐值 −25..99）上 0 例不一致。大例是 20 万
节点的链（递归必栈溢出）、快乐值 100/−20 交替，答案恰为取所有正快乐节点：
10,000,000。

## 最长相同子串：公共后缀表（16.9）

两串 X、Y，求**最长公共子串**——字符必须**连续**，这是它与最长公共
子序列（LCS，可跳字符）的唯一区别，也是递推时最容易踩空的地方。

### 公共后缀表

定义 `L[i][j]` =「以 X[i−1]、Y[j−1] **结尾**的最长公共后缀」长度——
注意语义是后缀（结尾对齐），不是「前 i/前 j 个字符里的最优值」：

```
X[i−1] == Y[j−1] : L[i][j] = L[i−1][j−1] + 1
X[i−1] != Y[j−1] : L[i][j] = 0     ← 连续！错一个字符后缀即断
答案 = max L[i][j]
```

与 LCS 对照：LCS 在不等时取 `max(L[i−1][j], L[i][j−1])`（允许跳过），
本题必须**清零**——任何跳过都破坏了连续。小例 X=ABABC、Y=BABCA：
最长相同子串 "BABC"（长度 4），比两串的 LCS（5）短，正好示范两个
问题不是一回事。

**滚动行**：L[i][j] 只依赖上一行的对角值。用一行 prev/cur 时要先把
`prev[j−1]` 存进临时变量（被本轮 j−1 覆盖后就丢了）；甚至不用两行：
单个 `prev_diag` + j 递增即可完成，空间 O(min(m,n))。

**独立口径**：直接枚举所有起点对，逐字符延伸 O(mn·min(m,n))——示例
对 2000 对随机字符串做矩阵/滚动行/直接延伸/哈希四向对账。

### 大例：滚动哈希 + 二分答案

2×20 万字符的规模，O(mn) 口径（400 亿格，哪怕滚动行把空间压到
O(n)，时间仍不可接受）。注意判定「长度 L 的公共子串存在吗」是
**单调**的：存在 L 则任何更小长度都存在。于是外层对 L 二分；内层用
**Rabin-Karp 滚动哈希** O(m+n) 判定：

- 取 X 全部长度 L 子串的哈希，Y 的每个哈希在有序表中查找；
- 哈希碰撞不可不防——命中后还须做**真实串比较**，比较通过才算存在。

整体 O((m+n) log min(m,n))。示例的哈希用 64 位无符号自然回推
（基数 1000003，回推减法不用取模——无符号溢出是良定义的）。

独立对账的规模纪律：**中例** 2×8000 植入 1200，O(mn)=6400 万格的
滚动行瞬时跑完，与哈希答案一致——哈希链在此被独立口径钉死；**大例**
2×20 万植入 5000 只跑哈希，答案 5000 由植入构造本身担保（植入段保证
至少 5000；随机部分用字母表 a..j、植入段用 x..z 且两端异种守卫封边，
不可能超过 5000）。

## 最大子矩阵和：列对压缩 + Kadane（16.10）

**问题**：R×C 整数矩阵里选一个非空子矩形（连续的行区间 × 列区间），
使元素总和最大。固定例：

```
-1  0 -9          其最优子矩阵是右下 2×2：
-2  3 14                3 14
-2  4 20                4 20      总和 41
```

### 降维：把二维压成一维

朴素枚举四角 (r₀,r₁,c₀,c₁) 用二维前缀和是 O(R²C²)。压缩法固定
**列对** [l,r]，把第 i 行的 a[i][l..r] 求和成 colsum[i]——任何以列
区间 [l,r] 为横向范围的子矩形，在该列向和上就是一个**连续行段**。
于是一维最大子段（Kadane）接管：

- `cur` 以 i 结尾的最大子段和：`cur<0 则重启（cur=colsum[i]），否则累加`；
- 负前缀只会拖累后面——扔掉重启永远不劣；
- **非空口径**：初值取 `cur=colsum[0]`（不是 0——全负矩阵时答案应
  是最大单元素，空矩形不计入）。

外层 l、内层 r 递增时 colsum 增量累加（每扩一列只加一列），总复杂度
**O(R·C²)**（R≤C 时；否则交换两个循环方向取小者）。

### 对账与边界

- 独立真值：二维前缀和暴力 O(R²C²)，300 个随机小矩阵（R,C ≤ 6，
  值 −15..15）上两法总和 0 例不一致；
- 全负矩阵：非空口径下答案 = 最大单元素（示例 {{-5,-3,-8},{-2,-9,-1}}
  得 −1），检验 Kadane 初值没有偷懒取 0；
- 大例 100×120（值 −15..25，期望为正）压缩法瞬时完成，且对返回的
  矩形坐标**独立回代**求和核对。

```
=== 16.10 最大子矩阵和：列对压缩 + 一维 Kadane（O(n³)）===
  固定例（3×3）：最大和 41，子矩阵 行[2,3]×列[2,3]（1-based）
  全负矩阵：最大和 -1（不允许空矩形，取最大单元素）
  随机 300 个（R,C≤6）：压缩法 vs 前缀暴力不一致 0 例
  大例（100×120，值−15..25）：最大和 59271，尺寸 100×120，回代和一致
```

- `std::min({...})` 的 initializer_list 版一次取三数最小。

## 与 STL 对照

无直接对应。留意两个「近亲」：`std::mismatch`/`std::ranges::mismatch`
（找两序列首个不同点——编辑对齐的基本件）与 `std::string::starts_with`
（C++20 起，前缀判定的标准件）。

## 坑位清单

1. **重构 LCS 时 b 表方向写反**
   （现象：重构出的串是 LCS 的「反序」或空串；原因：回溯时先把字符
   拼接在后面/前面弄错——`lcs(i-1,j-1) + x[i-1]` 才是正序；后果：长度
   对但串错；对策：重构后必须做 `is_subsequence` 双向断言（示例的
   做法——只查长度查不出这种错）。）
2. **最优 BST 的 w 表增量式算错**
   （现象：e 表全盘偏小量；原因：w[i,j] = w[i,j−1] + p_j + q_j 的增量
   里两项都要加——漏 q_j 是常见笔误；后果：整棵树的期望代价系统性
   偏低；对策：小例手算 w 表逐格对（n=5 只有 15 格）；或用
   Σp+Σq 全量重算对账。）
3. **区间 DP 的循环边界差一**
   （现象：e[i][i−1] 越界或空树格漏初始化；原因：区间 DP 的「空区间」
   是合法状态（j = i−1），必须显式初始化；后果：未定义行为或漏最优；
   对策：先写边界态（空树 = 只含伪键），再写 l = 1..n 的主循环。）
4. **把「允许替换的编辑距离」与「插删距离」混为一谈**
   （现象：断言 Levenshtein == m+n−2·LCS 失败；原因：恒等式只对替换
   代价 ≥ 2（或禁止替换）成立；替换代价 1 时距离只能更小或相等；
   后果：错误断言把正确的实现判了死刑；对策：替换代价参数化（示例
   edit_distance(x, y, subCost)），恒等式用 subCost=2 验证——本例
   首版实测翻车。）
5. **最长不升子序列里把 `upper_bound` 写成 `lower_bound`**
   （现象：答案偏小，样例该得 6 只得 4；原因：`lower_bound` 返回第一个
   `d[p] ≥ b[i]`，把相等元素截断在更靠前的槽位，后续再来的相等元素
   反复写回同一格，长度再也涨不上去；`d` 的语义是"长度 k+1 的**最小**
   末尾"，相等元素不能改善 d[p] 但应被记到更长的一档 ⟹ 必须
   `upper_bound`；后果：LNIS/LNDS 静默偏小；对策：记死"允许相等接续
   ⟹ upper_bound"，并用 `h = [5,5,5]` 这个最小反例做回归测试
   （示例 16.5 实测：upper_bound 得 3，lower_bound 只得 1。）
6. **求最长不升子序列时 DP 的比较写成 `>`**
   （现象：全相等序列的答案从 n 掉到 1；原因：「不升」是 `h[j] ≥ h[i]`，
   写成 `>` 就变成了求最长**严格**下降子序列；后果：相等元素无法接续；
   对策：LNIS 用 `>=`、LDS 用 `>`，这与二分侧的 `upper_bound`/
   `lower_bound` 配对关系是同一件事的两面（不升↔upper，严格↔lower）。)
7. **误用 `LCS(A, reverse A)` 求最长不升子序列**
   （现象：得到的是回文子序列长度，与 LNIS 无关；原因：公共子序列要求
   同时是 A 与逆序的子序列 ⟹ 天然"左右对称"；LNIS 的正确归约是
   `LCS(A, sort_desc(A))`；反例：A = [2,1,3] 的 LNIS = 2 而
   `LCS(A, rev A)` = 1；后果：结论看似合理但数值系统性偏小；对策：
   归约到排序序列（目标单调性决定升/降），而不是逆序序列。）
8. **反链求法漏掉「同 i 内按 j 降序」重排**
   （现象：同行有多个垃圾格时答案偏小；原因：输入按行优先给出，同 i 内
   是 j **升序**；不重排的话严格下降子序列在同 i 段只能取一个，而反链
   本应允许同 i 的多个点（它们互不可比）；后果：漏算同行的冗余机器人；
   对策：排序谓词写 `x.i != y.i ? x.i < y.i : x.j > y.j`，并用
   "同行多垃圾"的小例对账（本例首版实测翻车。）
9. **链覆盖建二分图时只连相邻格（漏传递闭包）**
   （现象：|S| − 匹配数 偏大，答案偏保守；原因：匹配边表示"u 后面紧接
   v 在同一条链"，u 与 v 之间可以隔任意多个格子 ⟹ 必须对传递闭包连边；
   后果：多算机器人；对策：连边条件写 `u ⪯ v && u ≠ v` 的全对判定，
   或直接用 LDS 解法绕开匹配（第 27 章的 Hopcroft–Karp 也要求闭包）。)
10. **圆环问题把数组复制后直接在整段 2n−1 上取答案**
    （现象：答案偏小且可能用上同一堆石子两次；原因：窗口长度必须是
    n——`stone_circle` 扫描 `mn[i][i+n−1]` 共 n 个窗口，而不是取
    `mn[0][2n−2]`；后果：圆环↔直线的等价性被破坏；对策：复制长度
    2n−1 只为让所有 n 个切口落在同一张表里，逐窗口取 min/max。）
11. **递推漏掉最后一次合并的「+ w(i,j)」**
    （现象：答案只统计内部合并、系统性偏小；原因：最后一次合龙本身
    也要花区间总和；最小反例 n=2：正确答案 a₀+a₁，漏加得 0；对策：
    先写 n=2 断言，再写 n=3 手算（两次合并 ⇒ 花费 = 2·总和 − 被先合
    走的那对之外的一堆），最后跑随机对账。）
12. **把最大值的端点性质误用到最小值**
    （现象：`w + min(mn[i][j−1], mn[i+1][j])` 给出偏小的伪答案；原因：
    端点最后被吸收会**最大化**重复计费，对最小值恰好要反其道而行——
    最小值不存在该捷径；对策：最小枚举切点、最大才用端点；用 n≤6
    的暴力对账把两种递推分别钉住。）
13. **贪心「每次挑数目和最小的相邻堆先合」求最小花费**
    （现象：部分小样例能过、随机对账失败；原因：局部最小合并不一定
    是全局最优合并树的内部节点——本问题没有贪心选择性质；对策：
    区间 DP 是正解，贪心实现只保留作对照（与 17.1 活动选择恰成对比：
    同样"相邻合并"，一个可贪心一个必须 DP）。）
14. **树上 DP 对深链用递归后序**
    （现象：n 一大（几万）程序栈溢出崩溃，小例全绿；原因：调用栈深度等于
    树高，链形树高为 n；后果：交付后只在大数据崩；对策：显式遍历序逆序
    处理（本示例做法）；一般树还可用 DFS 迭代栈。凡是「输入大小决定递归
    深度」的算法都要先想这个。）
15. **yes 式里错加 max(yes,no)**
    （现象：答案偏大且方案中出现父子同列；原因：v 参加时孩子**强制**不参加
    ——yes[v] 加的是 no[c]，没有选择余地；max 只出现在 no[v]；后果：
    数值与名单双双非法；对策：先写最小例（2 节点树）断言两种状态，再用
    还原名单做「无父子」校验。）
16. **把快乐值默认非负，空集/负值分支不处理**
    （现象：全员负快乐时仍输出最大值——此时最优应是「一个人都不请」的
    空集，总和 0；原因：独立集允许空集，答案 max 必须把 0 作为下界；
    此外负快乐节点仍可能在 DP 内部被「参加」（例如为了……其实不会，
    参加负值永远不如不参加，还原逻辑自洽即可）；对策：暴力真值用 0 初始化
    best（空集），随机数据包含负数。）
17. **子串递推不等时抄了 LCS 的取 max**
    （现象：答案偏大，把不连续片段拼了起来；原因：公共后缀在失配时必须
    归零，取 max 等于允许跳字符——那是 LCS；对策：两个递推并排默写，
    小例 ABABC/BABCA 对账（子串 4 vs 子序列 5，立刻暴露串台）。）
18. **滚动行更新时对角值已被覆盖**
    （现象：长度时大时小、随机对账失败；原因：j 递增时 L[i−1][j−1] 的旧
    值已在处理 j−1 时被覆盖，直接读 prev[j−1] 读到的是本行值；对策：
    每次先把 prev[j−1] 存入 `diag` 再更新，或干脆用「保存旧值+顺延」的
    单行写法（本例 common_substring_row 的做法）。）
19. **哈希命中后当真，不做真实比较**
    （现象：精心构造或大规模随机下偶发「存在」实为碰撞；原因：固定模哈希
    的碰撞概率非零，且存在对抗输入；后果：判定假阳性，二分答案偏大；
    对策：哈希只当筛选器——命中必做真串 compare，本例 2000 对随机数据
    四向对账即包含对这条链的端到端检验。）
20. **植入测试段的守卫没设或两串设成相同字符**
    （现象：中例答案 1201 而非植入的 1200；原因一：植入段紧邻的随机字符
    与另一串对应位置偶然相同，公共段被延长一格；原因二：两端加了守卫却
    两串都放 w——守卫本身又是一格公共匹配，照样 1201；对策：植入段两端
    用不在随机字母表（a..j）里的字符封边，且**两串同位置放不同的守卫**
    （本例 a 侧 w/v、b 侧 v/w）。）
21. **Kadane 初值取 0，把「允许空段」混进「非空」口径**
    （现象：全负矩阵的最大子矩阵和输出 0（或对应空矩形）；原因：一维
    Kadane 的 cur/best 若初值为 0，等于允许空段——空段和恒 0，非空
    口径下全负输入被吞掉；对策：cur 从 colsum[0] 起、best 初始化为
    a[0][0]，用全负固定例断言答案＝最大单元素。）
22. **列对压缩里 colsum 每次重新求和**
    （现象：复杂度从 O(R·C²) 退化到 O(R·C³)，大例变慢；原因：固定 l、
    扫 r 时 colsum[i] 只需在上一列基础上加 a[i][r] 一列；对策：l 循环
    内清零 colsum，r 递增时增量累加——顺便让「扩列」的语义写进循环。）
23. **子矩形坐标回代没用，只比总和**
    （现象：压缩法与暴力总和一致，但返回的坐标错位（r1 少 1、列偏移），
    没人发现；原因：坐标只在更新 best 时记录，start 的维护与 cur 重启
    不同步；对策：对返回的 (r0,r1,c0,c1) 独立双重循环求和，断言等于
    best.sum，并在固定例上断言精确坐标。）

   root[i+1,j] 把 Θ(n³) 压到 Θ(n²)。
7. （本教程）给编辑距离加「操作轨迹重构」（d 表回溯输出「改 k→s」的

   严格下降（`lower_bound` + `greater`）、最长上升（`lower_bound`）、
   允许相等下降（`upper_bound` + `greater`）。用 `h = [5,5,5]` 与
   `h = [5,5,4,4,3]` 两个输入把四种答案全列出来（3/1/1/3）。
9. （本教程）把「最大反链 = 排序后 LDS」推广到三维偏序
   `(a,b,c) ⪯ (a',b',c') ⟺ a≤a' 且 b≤b' 且 c≤c'`：写一个 n = 500 的
   实例，比较 LDS 解法与 Hopcroft–Karp 匹配解法的耗时（体会
   Θ(n log n) vs Θ(n^2.5)）。
10. （本教程）用 Dilworth 的匹配形式复现示例 16.6 的 |S| − 匹配 = 2，
    并把匹配边打印成"链的衔接关系"，验证这些链真的构成合法划分
    （每条链在网格上确实是单调的）。
11. （本教程）证明圆环问题与「n 个切口下直线问题」的等价性（两个
    方向都要说：圆环方案切开 ⇒ 直线方案；直线方案 ⇒ 圆环方案），
    并用 3 堆圆环的全部合并历史验证窗口扫描的答案表。
12. （本教程）用端点性质把最大值单独改成 O(n²) 实现，与 O(n³) 枚举
    在 n=200 的随机数据上对账（必须 0 不一致），并报告两版耗时差。
13. （进阶）四边形不等式优化最小值：当费用函数 w 满足区间包含单调性
    与四边形不等式时，最优切点单调 `cut[i][j−1] ≤ cut[i][j] ≤
    cut[i+1][j]`，据此把最小值压到 O(n²)。实现并与朴素版对账。
14. （本教程）用归纳法证明树上 DP 给出最优值（提示：归纳假设两个状态
    分别是子树在「根参加/不参加」约束下的最优值，核对两式只依赖孩子
    状态），并证明还原规则产出的名单合法。
15. （本教程）若规则改为「员工 v 与 v 的**所有祖先**不能同时参加」
    （等价表述：同一条根到叶路径上至多一人），两状态递推要怎么改？
    给出 O(n) 算法并用暴力对账（提示：路径约束下 DP 只需记录「根到 v
    的路径上已选者的存在」……其实约束更强时 yes[v] 仍加 Σno，no[v]
    仍加 max——想一想为什么两题递推相同、还原又为何可能不同）。
16. （本教程）写出「最长公共子串出现在 X 的哪些位置」的全位置版本
    （一个子串可能多处出现），与只问长度的版本在随机数据上对账。
17. （本教程）用两个不同模数做双哈希重写大例判定，比较单/双哈希下
    真实串比较的触发次数；再构造一个让单哈希产生碰撞的字符串对
    （手工取模可解），验证碰撞不会污染答案。
18. （本教程）证明 Kadane 的正确性：对「以 i 结尾的最大子段 cur[i]」
    写出递推并归纳；再据此证明列对压缩法给出的总和＝该列对下最优
    子矩形（压缩不丢解：任何子矩形都对应 colsum 的一个连续段）。
19. （本教程）把 16.10 推广到**环面**（行列都可循环回绕）：说明矩阵
    复制四份后直接跑 O(4R·4C²) 压缩法为什么会**多算**（同一行被取
    多次），正确做法是「反例矩形 + 总和相减」口径（最大环绕和 =
    总和 − 最小子矩形，何时成立？构造全正矩阵反例），给出适用条件。
20. （本教程）实现三维版本的最大子长方体和（固定两维区间、第三维跑
    Kadane），分析复杂度 O(n⁵)，在 6×6×6 随机例上与 O(n⁶) 暴力对账。
