# 20 · 斐波那契堆

> 对应 CLRS 第 19 章 *Fibonacci Heaps*（英文 3rd ed. pp.505–530）。
> 斐波那契堆用「**懒得整理**」把可合并堆的摊还代价压到极限：插入和
> 降键摊还 O(1)——它是 Dijkstra 从 O((V+E) lg V) 提到 O(E + V lg V)
> 的关键（第 25 章）。代价是 extract-min 的常数大、实现复杂，工程上
> 常输给二叉堆；但它的摊还分析是势能法的巅峰之作。

## 学习目标

1. 能背出可合并堆操作在二叉堆/二项堆/斐波那契堆上的摊还代价表；
2. 理解「懒合并」：根表是个环形双链，插入只挂进去不整理；
3. 会实现 consolidate（按度数合并根）与 cut/cascading-cut；
4. 能陈述势函数 Φ = #roots + 2·#marks 各项的「记账对象」；
5. 知道为什么级联剪切能保住「度数 ≤ log_φ n」（斐波那契数登场）。

## 结构：一堆根构成的森林

- 每个节点：键、度数（孩子数）、**mark 位**、父/子/左右兄弟指针
  （兄弟环是环形双链）；
- **根表**：所有树根连成的环形双链；min 指针指向最小根；
- 每棵树是**堆序**的（父 ≤ 子），但树形任意——**不保持二项树的
  严格形态**，这是「懒」的根源。

## 操作与摊还代价表

| 操作 | 二叉堆 | 二项堆 | 斐波那契堆（摊还） |
|---|---|---|---|
| MAKE-HEAP | Θ(1) | Θ(1) | Θ(1) |
| INSERT | Θ(lg n) | Θ(1) | **Θ(1)** |
| MINIMUM | Θ(1) | Θ(lg n) | Θ(1) |
| EXTRACT-MIN | Θ(lg n) | Θ(lg n) | **O(lg n)** |
| UNION（合并两堆） | Θ(n) | Θ(lg n) | **Θ(1)**（根表拼接） |
| DECREASE-KEY | Θ(lg n) | Θ(lg n) | **Θ(1)** |
| DELETE | Θ(lg n) | Θ(lg n) | O(lg n) |

## 插入与 extract-min

**INSERT**：新节点自环成单树，splice 进根表，可能更新 min。摊还 O(1)
——真实工作量就是三次指针赋值（示例的 insert 计数 +1）。

**EXTRACT-MIN**：删最小根 z，把 z 的孩子全部提升到根表（孩子变根，
父指针清空），然后 **consolidate**：按度数把同度根两两链接（大键挂
到小键下），直到每度至多一棵——根表收缩成 O(lg n) 棵。真实代价可以
很大（根表可能积压了很多没整理的根），摊还分析靠势能买单。

**势函数**：Φ(D) = [#roots(D)] + 2·[#marks(D)]。

- INSERT：roots+1，ΔΦ=+1，实际 1 → 摊还 2 = O(1)；
- EXTRACT-MIN：设提取时根数 r、做 c 次链接、剩 roots ≤ D(n)+1 =
  O(lg n)。实际代价 O(r)；ΔΦ = O(lg n) − r（r 个根消失）……摊还
  O(c + lg n) = O(lg n)。**积压的根是以前插入/剪切「存」进势里的，
  现在一次取出来花**——懒整理的全部经济学。

## DECREASE-KEY 与级联剪切

降键 x 后若破坏堆序（x 的键 < 父），**cut**：把 x 连同子树剪下来挂
到根表（x 的 mark 清掉）。然后 **cascading-cut**：父亲 y 刚失一子——
若 y 未标记则**标记**（记住「丢过一个孩子」）止步；若 y 已标记（丢过
第二个了），把 y 也剪上根表，继续向上问 y 的父亲……一路雪崩。

mark 的语义就是势能里的 2·#marks：每个标记「欠」两单位势，剪上根表
时（mark 清零、roots+1）恰好 ΔΦ = −1，付得起剪的代价——级联再长，
摊还仍是 O(1)。**mark 位的发明是「让多级代价能赊账」的信息结构**。

「斐波那契」之名：级联剪切保证任何节点丢第二个孩子就被剪走 ⇒ 度数
k 的节点的孩子们的度数构成 1,2,...,k−2 递增（Fibonacci 递推的形态）⇒
**size(x) ≥ F_{k+2} ≥ φ^k** ⇒ k ≤ log_φ n ≈ 1.44 lg n——consolidate
的度数数组开 O(lg n) 就够。

## 实测：摊还账本

示例 20.4 的交错负载（4000 插 + 交错 1495 次大幅降键与提取 + 清空）：

```
摊还账本（m=4000：4000 插 + 交错 1495 次降键与提取后清空）：
  实际工作计数 = 171101，摊还预算×实现常数5 = 427475（比值 2.001）
  cut 次数 = 1649，级联剪切步数 = 313（平均 0.21 步/降键——摊还后仍 O(1)）
  合并链接次数 = 39055（集中在 extract-min：9.76 次/取 ≈ lg n 量级）
```

三个读数：总工作量贴着摊还预算的实现常数（比值 2.001 < 5）；级联
剪切平均每次降键只走 0.21 步（**摊还 O(1) 的实证**——大多数降键不
触发剪切，触发的也多为一两级）；consolidate 平均每次提取链接 9.76 次
（lg 4000 ≈ 12 的量级 ✓）。注意工作负载必须「大幅降键」才能触发
cut——小步降键几乎不违反堆序，级联剪切根本不发生（本例调负载时
实测踩过这个坑）。

## 为什么工程上还是二叉堆

斐波那契堆的 O(1) 摊还降键在 Dijkstra 里换成 `E + V lg V`——渐近赢。
但：常数大（指针追迹、环形链表缓存不友好）、实现复杂（本例 ~200 行
对二叉堆 ~40 行）、最坏单操作 O(n)（实时系统忌讳）。**竞赛与工业的
主流仍是二叉堆/配对堆**（配对堆是斐波那契堆的「简单替身」，摊还
O(log n) 降键但实测快）。Brodal 队列达到同摊还界且最坏 O(polylog)，
又是另一段传奇。

## C++23 语言点

- 环形双链的三个指针原语（add_to_list/remove_from_list/自环初始化）
  是全章的机械基础——写成 const 成员函数，操作计数单独记；
- `std::vector<Node*> A(64)` 当度数桶（度数 ≤ 1.44 lg n < 64 对一切
  现实 n 成立）；
- 交错负载的「存活表」：extract 会删节点，句柄数组配 `alive` 位图
  防悬空（第 13 章坑位 5 的现场复用）。

## 与 STL 对照

`std::priority_queue` 无 decrease-key（第 6 章坑位 3）；Dijkstra 的
工程路线是 lazy deletion（把降键做成「插入新条目 + 弹出时跳过过期」），
它本质上就是把「降键」的摊还 O(1) 换成「插入+垃圾」的摊还 O(1)——
同一套经济学。

## 坑位清单

1. **`lastDeleted` 存了已 delete 的指针再读 `->id`**
   （现象：三通道齐崩 0xC0000005；原因：extract_min 里 `lastDeleted = z;
   delete z;` 后调用方读 `lastDeleted->id`——use-after-free；对策：存
   **值**不存指针（`lastDeletedId = z->id`）——本例实测翻车，第 13 章
   「槽位复用」坑位的又一化身。）
2. **降键负载小步微降，级联剪切永不触发**
   （现象：cascadeSteps = 0，摊还账本成了空谈；原因：cut 的前提是
   新键 < 父键——随机键域里小步递减几乎不违反堆序；对策：负载设计
   要对准触发条件（大幅降到父键之下），并断言 cascadeSteps > 0
   （本例实测翻车后重调负载）。）
3. **decrease-key 忘验「新键 ≤ 旧键」**
   （现象：堆序静默破坏，后续 extract 弹序错乱；原因：FibHeap 的
   decrease-key 语义只支持降，升键要「删+插」；对策：入口 assert
   （本例的写法）。）
4. **cascading-cut 里 cut 之后才读 z->parent**
   （现象：级联路径错乱、剪飞子树；原因：cut(y,z) 会改 z 的孩子表，
   若顺手改了 z 在父链上的地位（不会）——真正的问题是要**先**记下
   z 的父亲再剪；对策：`Node* zParent = z->parent;` 置于 cut 之前
   （本例修正后的写法）。）
5. **consolidate 的度数数组按 lg n 精确开**
   （现象：大堆越界写；原因：度数界是 1.44·lg n（φ 的系数！），按
   lg n 开恰好不够；对策：开 2·lg n + 8 或固定 64（现实 n 全覆盖），
   注释写明 1.44 的来源。）
