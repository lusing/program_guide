# 12 · 二叉搜索树

> 对应 CLRS 第 12 章 *Binary Search Trees*（英文 3rd ed. pp.286–307）。
> BST 是「动态有序集合」的第一答案：所有字典操作期望 O(lg n)、中序遍历
> 即有序序列。它的软肋也著名——**输入有序即退化成链**（高 Θ(n)）——
> 第 13 章红黑树就是为治这个病而生的平衡化手术。

## 学习目标

1. 能陈述 BST 性质并用中序遍历证明「BST 中序 = 有序序列」；
2. 会实现 INSERT/SEARCH/MINIMUM/SUCCESSOR/DELETE，并说明各自的最坏/
   期望复杂度；
3. 能完整走一遍删除的三种情况（叶/单孩子/双孩子）；
4. 能复述定理 12.4（随机构建 BST 期望高度 O(lg n)）并读懂实测对照；
5. 能由前序+中序重建二叉树，说清为什么「前序+中序」唯一而
   「前序+后序」不唯一，并把 Θ(n²) 优化到 Θ(n)；
6. 能写子树判定并解释「形状全等」与「键存在」的区别。

## BST 性质

对任何节点 x：左子树所有键 ≤ key[x] ≤ 右子树所有键。**中序遍历恰好
输出有序序列**——这条性质用归纳一行可证（左序 + 自身 + 右序的拼接），
它也是 BST 一切正确性断言的基石（示例的 assert 全是它）。

用第 10 章的 arena 纪律实现（`key/left/right/parent` 四数组 + NIL =
SIZE_MAX），无指针无泄漏。

## 三种删除（§12.3）

删除 z 分三种情况（示例 12.3 各演示一次）：

1. **叶**：父指针置 NIL——删 4，节点 3 的右指针清空；
2. **单孩子**：孩子直接顶位——删 7，孩子 9 接到 6 下面；
3. **双孩子**：找 z 的**中序后继 y**（右子树最小，y 必无左孩子）：
   y 先脱离原位（用自己的右子树替换自己），再整体顶替 z——删根 15，
   后继 17 顶上。两种子情况：y 是 z 的右孩子（直接顶）与不是（先摘
   再接），伪代码统一处理。

TRANSPLANT（用子树 v 替换子树 u）是删除的机械臂：它只改三个指针
（父的孩子指针、v 的父指针、可能的 root）。

**中序后继** SUCCESSOR 是删除情况 3 与有序遍历的核心：x 有右子树 →
右子树最小；否则向上找第一个「左拐祖先」（我是谁的左子，谁就是我的
后继）。示例用 minimum + successor 链做了无递归中序遍历（练习 12.2-3）。

## 复杂度：一切归于树高

所有操作都沿一条根到叶的路径走，代价 Θ(h)：

- **最好**（完全平衡）：h = Θ(lg n)；
- **最坏**（插入有序序列）：退化成链，h = n——「排序数组」输入让
  查找变 O(n)，这是第 13 章的直接动机；
- **随机构建**（定理 12.4）：n 个键随机次序插入，期望高度 O(lg n)
  （精确刻画 ≈ 4.311·ln n；平均节点深度 ≈ 2·ln n——随机 BST 大约
  「比平衡深一倍」）。

实测（示例 12.5，n=1023、50 个固定种子排列）：平均树高 **21**（理论
渐进 ~29.9 的常数内）、平均节点深度 **11.99**（理论 ~13.9）——期望
分析的两个数字都能对上量级。

## 由遍历序列重建二叉树

**问题**：给一棵树的先序与中序遍历，能否唯一还原它？答案是**能**——但
只能靠「先序 + 中序」这个特定组合。

推理只有两步：

1. **前序 = 根 | 左 | 右**，所以 `pre[0]` 永远是根；
2. **中序 = 左 | 根 | 右**，所以在中序里找到根的下标 `p`，**左边恰好 p 个
   节点属于左子树**，右边属于右子树。

于是左右子树的**规模**都确定了，可以把两个序列同时切片、递归重建。每一
层递归至少消费一个节点，递归深度 = n——链状输入下栈深 Θ(n)，和 12.5 的
退化 BST 是同一个灾难。

```cpp
// pre / in 都是「当前子树」的窗口，不是整条序列
const std::size_t p = std::ranges::find(in, pre.front()) - in.begin();
const std::size_t root = out.make(pre.front());
out.left[root]  = rebuild(pre.subspan(1, p),          in.subspan(0, p));
out.right[root] = rebuild(pre.subspan(1 + p), in.subspan(p + 1));
```

**朴素版是 Θ(n²)**：每层递归都要在中序窗口里线性扫一遍找根，总代价
≈ n²/4。用哈希表 `pos[值] → 原始中序下标` 预存后，定位一次变成 O(1)，
总代价降到 **Θ(n)**。示例对同一份输入跑两个版本，规模实验只计「定位根」
的总比较次数（不真跑 n² 次）：

| n | 朴素 Θ(n²)/4 | 哈希 Θ(n) | 倍数 |
|---|---|---|---|
| 100 | 2 500 | 100 | 25 |
| 1 000 | 250 000 | 1 000 | 250 |
| 10 000 | 25 000 000 | 10 000 | 2 500 |

**为什么必须是「先序 + 中序」？** 因为只有中序能**唯一切分左右**。反例
极简：两个节点 `[1,2]`，无论 1 在左还是在右，先序都是 `[1,2]`，后序也
都是 `[2,1]`——但它们是**两棵不同的树**。而中序 `[1,2]` vs `[2,1]` 立刻
分得开。所以先序（或后序）负责「谁是根」，中序负责「根的哪边是谁」，
两者缺一不可。

**前提**：节点键值**互不相同**。有重复键时中序里同一个值出现多次，根的
位置不再唯一——需要额外约定（比如重复键一律进右子树，再配合前序仍可
唯一确定，但算法要加约束判断）。

实现上两个容易踩的点，示例都踩过：

- **坐标系必须显式换算**。哈希表的 `pos` 给的是**原始中序**里的绝对下标，
  而递归时 `in` 已被切成窗口——必须记住窗口的起始偏移 `base`，用
  `p_rel = p_abs − base` 换算回窗口内相对下标。直接把绝对下标当相对下标
  用，边界上会越界读。
- **`make()` 之后不要用旧下标**。`make()` 往 vector 里 push_back，可能触发
  扩容；`A.left[A.root] = A.make(9)` 这种写法里，左侧 `A.root` 与右侧
  `make(9)` 的求值顺序未指定，扩容后 `A.root` 还是扩容前读的值。正确写法
  是先把 `make` 的返回值落到局部变量。

## 子树判定

**问题**：B 是不是 A 的子树？注意这里的「子树」是**形状 + 键值全等**，
与 BST 性质无关。

```cpp
bool is_subtree(a, x, b, y) {
    if (x == NIL && y == NIL) return true;   // 基线 1：都空
    if (x == NIL || y == NIL) return false;  // 基线 2：单边空
    if (a.key[x] != b.key[y]) return false;  // 键值不等，立刻否
    return is_subtree(a, a.left[x],  b, b.left[y])
        && is_subtree(a, a.right[x], b, b.right[y]);
}
```

递归基线只有两条（都空 / 单边空），加一条键值剪枝，就够了。**不要**把它
和 12.3 的中序后继混起来——那套是 BST 键值序的工具，这里比的是形状。

上面这个函数要求 x 与 y 位置对齐，真正的问题还需要一层驱动：**B 的根不
必是 A 的根**，要在 A 的每个节点上试一次。

```cpp
bool contains_subtree(a, x, b) {
    if (x == NIL) return false;
    if (a.key[x] == b.key[b.root] && is_subtree(a, x, b, b.root)) return true;
    return contains_subtree(a, a.left[x], b) || contains_subtree(a, a.right[x], b);
}
```

驱动里那行 `a.key[x] == b.key[b.root]` 的**预检查是必需的剪枝**：没有它，
每个节点都会完整试一遍 `is_subtree`（O(m)），退化成 O(n·m)。有了它，只
在根键相同时才深入，最坏 O(n) 次节点访问。

示例把各种形状/键值组合都对了一遍，几个值得注意的判定：

- `[20,15,7]`（A 的右子树）→ **真**；
- `[21,15,7]`（根键不同）→ 假，键值剪枝直接否掉；
- `[20,15]`（少一孩子）→ 假，单边空基线否掉；
- `[7]`、`[15]`（深处的单侧子树）→ 真；
- **`[3]`（键与 A 的根相同，但 [3] 是叶子）→ 假**。这条最能说明「子树」
  的定义：A 的 3 有两个孩子，而 `[3]` 是叶子，形状不等。这不是 bug，
  「A 里有这个键」与「[3] 是 A 的子树」是两件事；
- A 的完整复制 → 真（子树含自身，后代的定义包含 A 自己）。

## C++23 语言点

- arena 四数组 + `NIL = SIZE_MAX`（第 10 章纪律的再应用：删除后槽位
  不回收也不断链，遍历只认 root 可达的节点——教学实现的取舍，工程版
  加自由表即可回到 O(1) 节点回收）；
- 迭代版 INSERT/SEARCH（while 下行）优于递归版（栈深 O(1)）——与
  第 7 章尾循环消除同一课。

## 与 STL 对照

`std::map`/`std::set` 是**红黑树**（第 13 章），不是朴素 BST——标准
规定最坏 O(lg n)，所以实现必须平衡。朴素 BST 的现代生态位：教学、
以及「输入确实随机」的场景（一次性建索引后只读）。

## 坑位清单

1. **删除双子节点时「拿前驱/后继的键值覆盖」与「节点顶替」混用**
   （现象：带附属数据（迭代器/计数）的节点被覆盖后引用失效；原因：
   教科书简化版「copy key then delete successor」只对纯键成立，节点
   身份变了；后果：外部持有句柄的代码悬空；对策：用本例的节点顶替
   （TRANSPLANT 移动节点），键与数据一起搬家。）
2. **SUCCESSOR 的「左拐祖先」循环写反**
   （现象：后继链提前断或成环；原因：循环条件应为 `while (y ≠ NIL &&
   x == right[y])`——x 是 y 的**右**孩子时继续上行；写成 left 就找成
   前驱了；后果：有序遍历漏元素或死循环；对策：中序遍历断言等于
   排序结果（示例 assert 的写法）。）
3. **删除情况 3 忘了 y 不是 z 右孩子的子情况**
   （现象：某些删除后中序多/少元素；原因：y 深居右子树左下角时，要先
   让 y 的右子树顶替 y、再把 y 挂到 z 的右下——少一步就丢子树；
   后果：结构静默损坏；对策：删除后立即 `inorder() == 排序断言` +
   全量 parent 一致性检查。）
4. **随机高度实验把「期望」当「保证」**
   （现象：某次构造输入让 BST 高度 40，质疑理论错了；原因：4.311·ln n
   是**期望**常数，尾部有波动（50 种子的实测 21 vs 29.9 就是波动内）；
   后果：误判实现有 bug；对策：多样本平均 + 理解「期望高度」的方差。）
5. **重建时把「绝对下标」当「窗口内相对下标」**
   （现象：重建小规模输入正常，稍大就越界读/段错误；原因：哈希表 `pos`
   存的是**原始中序**的绝对下标，而递归中 `in` 已被 `subspan` 切成窗口，
   两者坐标系不同；后果：越界（Release 下可能静默读脏数据）；对策：
   显式携带窗口起始偏移 `base`，用 `p_rel = p_abs − base` 换算——并在
   入口 `assert(p_abs >= base && p_abs < base + in.size())`。本教程 12.6
   实测翻车过此坑。）
6. **`make()` 可能扩容，却用扩容前读到的下标继续访问**
   （现象：搭 3~5 个节点的小树正常、结果随机错乱，Release 下偶发；原因：
   `A.left[A.root] = A.make(9)` 里，`make(9)` 触发 vector 扩容，而
   `A.root` 是扩容前读的下标（且两侧求值顺序未指定）；后果：写错槽位，
   静默破坏结构；对策：先把 `make` 的返回值落到局部变量，再拿当下标。）
7. **子树判定里「键存在」冒充「子树」**
   （现象：单节点 `[3]` 被判为 A 的子树；原因：A 的 3 有两个孩子，`[3]`
   是叶子，形状不等——递归基线「单边空」会正确否掉，是测试期望写错；
   后果：把正确的实现判成 bug（实测翻车）；对策：写测试前先手工画出
   两棵树的形状，逐节点核对，不要凭「A 里有这个键」直觉下结论。）
