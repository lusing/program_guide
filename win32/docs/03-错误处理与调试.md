# 第 3 章 错误处理与调试

> **本章回答的问题**：API 调用失败了怎么知道、怎么查？`GetLastError` 为什么常常"读到错的码"？`HRESULT` 的十六进制数字怎么读？程序崩了怎么办？调试器该怎么上手？
>
> **前置章节**：第 2 章（能编译运行程序）。
>
> **你将做出什么**：一个错误处理工具箱程序（`examples/16_error_handling`）——它故意触发三种典型失败，演示"查询错误码 → 翻译成人话 → 兜底异常"的完整流程。

## 3.1 失败是常态：先认清"失败长什么样"

Win32 API 几乎不抛异常（那是 C++ 的机制），失败信息藏在**返回值**里。返回值有三大家族，失败判据各不相同：

| 返回值家族 | 典型 API | 失败判据 | 成功时拿到什么 |
|-----------|---------|---------|---------------|
| `BOOL`（int） | `CloseHandle`、`DeleteFileW` | 返回 `FALSE`（0），**不能用 `!= nullptr` 判断** | `TRUE`（非 0） |
| 句柄族 | `CreateFileW`（文件/设备） | `INVALID_HANDLE_VALUE`（即 -1） | 可用句柄 |
| 指针/句柄族 | `CreateWindowExW`、`CreateEventW`、`LocalAlloc` | `nullptr`（0） | 可用句柄/指针 |

两个高频踩坑点必须现在钉死：

1. **`CreateFileW` 失败返回 `INVALID_HANDLE_VALUE`，不是 `nullptr`**。写 `if (h == nullptr)` 会把失败当成功，后面全是崩溃。为什么文件 API 特立独行？历史遗留——Win9x 时代 `CreateFile` 的失败值与别的句柄 API 不同，为了兼容一直没改。
2. **每个 API 查文档确认判据**。MSDN 每个函数页都会写明"Return value: If the function fails, the return value is ..."。不确定就查，别猜。

查到失败之后，答案在**线程局部的错误码**里。

## 3.2 `GetLastError`：错误码的读取纪律

每个线程有一个"最近一次错误"槽位，API 失败时把错误码放进去（成功时**通常**不清空——这个含糊后面讲）。你用 `GetLastError()` 读它：

```cpp
HANDLE h = CreateFileW(L"C:\\no_such.txt", GENERIC_READ, 0, nullptr,
                       OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL, nullptr);
if (h == INVALID_HANDLE_VALUE) {
    DWORD err = GetLastError();   // ★ 紧贴失败调用读取
    // err == 2 (ERROR_FILE_NOT_FOUND)
}
```

三条纪律：

1. **紧贴失败调用读**。中间任何一次 API 调用（包括 `wprintf`！）都可能覆盖错误码。错误地在两者之间打了一行日志，读到的就是日志函数的错误码（通常是 0）。
2. **读一次就定性**。不要在多层函数间反复读——每层读到的可能不一样。
3. **调试器里可以直接看**：VS 的 `$err, hr` 监视表达式显示最近错误码及其含义；断点停下时先看它。

常见错误码速查（完整表在 winerror.h / MSDN "System error codes"）：

| 码 | 宏 | 含义 |
|----|-----|------|
| 2 | `ERROR_FILE_NOT_FOUND` | 文件不存在 |
| 3 | `ERROR_PATH_NOT_FOUND` | 路径不存在 |
| 5 | `ERROR_ACCESS_DENIED` | 拒绝访问（权限，第 17 章） |
| 32 | `ERROR_SHARING_VIOLATION` | 文件被别人占用（共享模式，第 16 章） |
| 87 | `ERROR_INVALID_PARAMETER` | 参数不对 |
| 122 | `ERROR_INSUFFICIENT_BUFFER` | 缓冲区太小（两段式 API 的"问尺寸"信号） |
| 183 | `ERROR_ALREADY_EXISTS` | 已存在（比如创建已有的互斥体——单实例检测的原理） |

## 3.3 `FormatMessageW`：把错误码翻译成人话

裸数字没人记得住。`FormatMessageW` 能把错误码翻译成本地化的系统消息：

```cpp
DWORD err = GetLastError();
LPWSTR msg = nullptr;
DWORD n = FormatMessageW(
    FORMAT_MESSAGE_ALLOCATE_BUFFER |   // 让系统分配缓冲区（省得猜长度）
    FORMAT_MESSAGE_FROM_SYSTEM   |     // 来源：系统错误表
    FORMAT_MESSAGE_IGNORE_INSERTS,     // 忽略 %1 之类的插值占位（防格式串误用）
    nullptr,
    err,                               // 要翻译的错误码
    MAKELANGID(LANG_NEUTRAL, SUBLANG_DEFAULT),  // 用户默认语言 → 中文系统出中文
    (LPWSTR)&msg,                      // ★ ALLOCATE_BUFFER 模式下传"指针的地址"
    0, nullptr);
if (n > 0 && msg) {
    wprintf(L"%s", msg);    // 系统消息自带换行
    LocalFree(msg);         // ★ 系统分配的内存，用 LocalFree 归还
}
```

两个配对细节：

- `FORMAT_MESSAGE_ALLOCATE_BUFFER` 模式下，第四个参数要传 `LPWSTR` 的**地址**（系统把分配好的指针写进去）；
- 这块内存**必须 `LocalFree`**——它不是 `new` 出来的，不能 `delete`（跨分配器释放是崩溃，见第 20 章内存边界话题）。

不想碰 API 的场合，命令行有现成的：`net helpmsg 5` 直接输出错误码 5 的含义。

## 3.4 `HRESULT`：COM 世界的错误形态

后面第 22~26 章会大量遇到 `HRESULT`（32 位整数），现在把读法学会：

```text
 31 30        27 26                 16 15                              0
┌───┬──────────┬────────────────────┬──────────────────────────────────┐
│ S │ R │ 设施 │     设施代码        │            错误代码               │
│ 1 │ 1 │ 4 位 │     11 位           │             16 位                 │
└───┴──────────┴────────────────────┴──────────────────────────────────┘
 S=1 失败 0 成功；R 保留；设施=facility（7=Win32 错误，4=接口自定义 ITF...）
```

速读规则：

- **只看最高位判断成败**：`FAILED(hr)` / `SUCCEEDED(hr)` 两个宏替你判断。**永远用宏，不要手写 `hr < 0`**（可读性和正确性都差）。
- `0x80070002` = 失败(8) + 设施 0007(Win32) + 代码 0002 → "Win32 错误 2"。`HRESULT_FROM_WIN32(ERROR_FILE_NOT_FOUND)` 就是打包动作，`HRESULT_CODE(hr)` 反向拆包。
- 记住三个常客：`S_OK`（0，成功）、`S_FALSE`（1，**成功**但语义上"没有/假"——不是失败！）、`E_FAIL`(0x80004005)。
- 用户取消也是"失败码"的一种约定：文件对话框取消返回 `HRESULT_FROM_WIN32(ERROR_CANCELLED)`——**失败不一定是错误**，处理前先想清楚语义。

```cpp
DWORD err = ERROR_FILE_NOT_FOUND;
HRESULT hr = HRESULT_FROM_WIN32(err);      // 0x80070002
if (FAILED(hr)) { /* ... */ }              // 正确姿势
```

第 22 章 COM 入门会给出 HRESULT 的完整设施表与"丰富错误信息"（`IErrorInfo`）机制。

## 3.5 `OutputDebugStringW`：写给调试器的留言

`printf` 在 GUI 程序里没处看（没有控制台）。`OutputDebugStringW` 把字符串发到调试通道：

```cpp
OutputDebugStringW(L"[myapp] 进入初始化，配置文件=xxx\n");
```

- 有调试器（VS）附加时，输出出现在"输出"窗口；
- 没有调试器时，用微软 Sysinternals 的 **DebugView** 工具就能看到全部调试输出——排查"用户机器上的问题"的利器。

它不做格式化（不是 printf），要拼字符串就用 `swprintf_s` 进缓冲区再发。教程示例的守则是：**开发期调试信息走 OutputDebugString，用户可见的运行信息走事件日志（第 27 章）**。

## 3.6 调试器入门：断点、单步与调用栈

会设断点的效率是加打印的十倍。Visual Studio（或 VS Code + cppvsdbg）四件事就够入门：

| 操作 | 快捷键（VS 默认） | 回答的问题 |
|------|------------------|-----------|
| 设/取消断点 | F9 | 程序在哪停下来 |
| 逐过程 | F10 | 下一行执行了什么（不进入函数内部） |
| 逐语句 | F11 | 进到这个函数里面去 |
| 调用栈窗口 | Alt+7 | **我是被谁、按什么路径调到这里的** |

重点说说调用栈：崩溃或断点停下时，从下往上读栈，就是"消息循环 → WndProc → 你的函数"这条完整来路。**Win32 程序的绝大多数崩溃，看一眼调用栈就知道是哪条消息触发的**。

两个补充技巧：

- `__debugbreak()` 内建函数：写在代码里，运行到这里就相当于命中断点（条件断言 `if (bad) __debugbreak();` 很好用）；
- 监视窗口输入 `$err, hr`（见 3.2）与 `$err` 对照，直接看中文错误描述。

## 3.7 SEH：结构化异常处理

C++ 异常（`try/catch`）处理的是"throw 出来的对象"；**SEH 处理的是硬件与内核级异常**——空指针访问、除零、栈溢出。语法：

```cpp
__try {
    // 可能出事的高危代码
} __except (过滤器表达式) {
    // 出事后怎么处理；GetExceptionCode() 可取异常码
}
```

- **过滤器表达式**三态：`EXCEPTION_EXECUTE_HANDLER`（处理它，进入 except 块）、`EXCEPTION_CONTINUE_SEARCH`（我不处理，往外层找）、`EXCEPTION_CONTINUE_EXECUTION`（当作无事发生继续跑——危险，几乎不用）。
- 常见异常码：`0xC0000005` 访问违例（读写非法地址）、`0xC0000094` 整数除零、`0xC00000FD` 栈溢出。

**一条编译器铁律**：含 `__try` 的函数里不能有需要析构的 C++ 对象，否则报 **C2712**（"无法在需要对象展开的函数中使用 __try"）。工程上的标准做法是 SEH 独立成小函数：

```cpp
static int GuardRawMemoryRead(volatile int* p) {   // 只放原始类型
    __try { return *p; }
    __except (EXCEPTION_EXECUTE_HANDLER) { return -1; }
}
// 调用方（可以有 std::string 等）：
int v = GuardRawMemoryRead(badPtr);
```

三个延伸认知：

1. MSVC 下 **C++ 异常建立在 SEH 之上**（`/EHsc` 编译开关就是在配置这套关系），所以"野指针解引用"在 MSVC 里甚至能被 `catch(...)` 抓到——但这是实现细节，跨编译器不可移植，别依赖。
2. `__try/__finally` 组合保证清理代码必被执行（类似 RAII 的底层形态）。
3. **默认别用 SEH 掩盖 bug**：访问违例的正确修法是修指针，不是包一层 `__except` 让它"不崩了"。SEH 的正当用途是**边界防御**（进程外的坏数据、插件崩溃隔离）。

## 3.8 错误处理策略：失败之后做什么

查到错误只是开始，接下来做什么要有章法：

| 情形 | 策略 | 例 |
|------|------|----|
| 瞬时失败（可能自愈） | 重试（带退避） | 网络路径、文件共享冲突（`ERROR_SHARING_VIOLATION` 等半秒再试） |
| 环境不具备 | 降级或明确报错退出 | 缺可选 DLL → 禁用该功能（第 20 章）；缺必需 DLL → 提示安装 |
| 参数/逻辑错误 | 立刻失败，开发期用断言放大 | `assert(ptr)` 在调试版直接停下（发布版不编译进去） |
| 用户操作被拒 | 翻译成人话提示 | `ERROR_ACCESS_DENIED` → "没有权限，请以管理员运行或检查文件属性"（第 17 章讲怎么优雅提升） |
| 异步操作的"假失败" | 特判不算错 | `ERROR_IO_PENDING` 是异步 IO 正常形态（第 16 章） |

总原则：**能处理的处理，不能处理的带着上下文报告，绝不吞掉**。"吞错误"（`if (FAILED(hr)) {}`）是把今天的 bug 变成明天的悬案。

## 3.9 完整示例：错误处理四件套

`examples/16_error_handling`（控制台程序）把本章内容串成一个可运行的检查单：

```cpp
// [1] 失败 API + GetLastError + FormatMessageW —— 3.1~3.3 节
HANDLE h = CreateFileW(L"C:\\__no_such_file__.tmp", ...);
if (h == INVALID_HANDLE_VALUE) {          // 判据用对
    DWORD err = GetLastError();           // 紧贴读取
    FormatMessageW(...);                  // 翻译 + LocalFree
}

// [2] HRESULT 打包与判断 —— 3.4 节
HRESULT hr = HRESULT_FROM_WIN32(ERROR_FILE_NOT_FOUND);
FAILED(hr);                               // true

// [3] SEH 兜底空指针写 —— 3.7 节（注意独立成函数的原因）
__try { *bad = 42; }
__except (EXCEPTION_EXECUTE_HANDLER) { GetExceptionCode(); }

// [4] OutputDebugStringW —— 3.5 节（配 DebugView 观察）
OutputDebugStringW(L"[16_error_handling] ...");
```

运行输出（中文控制台）：

```text
[1] Win32 错误码与消息
    CreateFileW 失败，GetLastError() = 2
    FormatMessageW: 系统找不到指定的文件。
[2] HRESULT
    Win32 错误 2 → HRESULT 0x80070002
    FAILED(hr) = true
[3] SEH 结构化异常
    捕获异常 0xC0000005（EXCEPTION_ACCESS_VIOLATION）
    __except 已兜底，程序继续运行（返回 1）
[4] OutputDebugStringW（用 DebugView/调试器观察）
```

## 3.10 易错清单

| 症状 | 原因 | 解法 |
|------|------|------|
| `CreateFileW` 失败没进 if | 判了 `nullptr`，实际返回 `INVALID_HANDLE_VALUE` | 查文档定判据（3.1 表） |
| `GetLastError()` 返回 0 但明明失败了 | 读取前隔了别的调用，错误码被覆盖 | 紧贴失败调用读（3.2） |
| `FormatMessageW` 输出乱码/崩溃 | 没用 ALLOCATE_BUFFER 的地址传法；或忘 `LocalFree` | 照 3.3 节模板 |
| 把 `S_FALSE` 当失败 | `SUCCEEDED(S_FALSE)` 其实是 true | 只用 `FAILED/SUCCEEDED` 宏 + 知道 S_FALSE 语义 |
| `__try` 里放 `std::string` 编译不过 | C2712：析构对象不能与 SEH 同函数 | SEH 独立成函数（3.7） |
| 用 `catch(...)` 抓空指针崩裂后"能跑" | MSVC 的 C++ 异常骑在 SEH 上的实现细节 | 不依赖；修指针本身 |
| GUI 程序里 printf 看不到输出 | 没有控制台 | `OutputDebugStringW` + DebugView（3.5） |

## 3.11 小结

1. 失败判据三家族：`BOOL` 看 FALSE、`CreateFileW` 看 `INVALID_HANDLE_VALUE`、多数句柄/指针看 `nullptr`——查文档定判据。
2. `GetLastError` 必须紧贴失败调用；`FormatMessageW` + `LocalFree` 把码翻译成人话。
3. `HRESULT` 用 `FAILED/SUCCEEDED` 读；`0x8007xxxx` 段就是 Win32 错误打包。
4. SEH 管硬件级异常，C2712 约束让它独立成函数；默认修 bug 不靠兜底。
5. 调试器四招（断点/逐语句/逐过程/调用栈）+ `$err, hr` + `OutputDebugStringW`，是效率基本盘。
