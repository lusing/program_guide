# 第 11 章 综合应用：计算器、RichEdit 编辑器、绘图板

> **本章回答的问题**：零件都会拼了，怎么组装成完整程序？三个经典案例分别示范什么设计能力：状态机（计算器）、多子系统协作（编辑器）、状态-绘制分离（绘图板）？
>
> **前置章节**：第 4~10 章全部——这是界面层篇的毕业考。
>
> **你将做出什么**：三个完整可用的程序（`examples/05_mini_calculator`、`06_text_editor`、`07_paint_app`），以及一套能套用到任何界面程序的"共同骨架"认知。

本章对应的三个可编译示例：`examples/05_mini_calculator`、`examples/06_text_editor`、`examples/07_paint_app`。建议先自己尝试，卡住了再看答案；本章按"设计要点 → 关键代码"的顺序讲解，不整段贴代码。

## 11.1 案例一：迷你计算器 —— 状态机思维

对应 `examples/05_mini_calculator`。

**界面层**：一个右对齐只读的 `EDIT` 当显示屏 + 16 个按钮按 4×4 网格摆放。按钮不用手写 16 段创建代码，而是建一张"按钮布局表"循环创建：

```cpp
const int grid[] = { IDB_7, IDB_8, IDB_9, IDB_DIV,
                     IDB_4, IDB_5, IDB_6, IDB_MUL,
                     IDB_1, IDB_2, IDB_3, IDB_SUB,
                     IDB_C, IDB_0, IDB_EQ, IDB_ADD };
for (int i = 0; i < 16; ++i) {
    int x = 20 + (i % 4) * 62;
    int y = 70 + (i / 4) * 52;
    CreateWindowExW(0, L"BUTTON", LabelOf(grid[i]), WS_CHILD | WS_VISIBLE | BS_PUSHBUTTON,
                    x, y, 54, 40, hwnd, (HMENU)(UINT_PTR)grid[i], hInst, nullptr);
}
```

**逻辑层**是本章真正的考点。计算器是一个微型**状态机**，状态只有四个变量：

```text
                  ┌─────────────────────────────────────────┐
                  │ 输入数字：waiting? ──是──> 清屏重收 ──┐   │
                  │              │否                    ▼   │
   storedValue ───┤              └──> 追加到当前显示        │
   currentOp   ───┤ 输入运算符：有 pending？先结算 ──> 记新 op，waiting=true
   waitingForOperand ─> 输入 = ：结算 ──> 显示结果，清 op    │
   (显示屏内容)  ───┘ 输入 C ：全部复位                        │
                  └─────────────────────────────────────────┘
```

| 变量 | 含义 |
|------|------|
| `storedValue` | 已累积的左操作数 |
| `hasStoredValue` | 是否已有左操作数 |
| `currentOp` | 待执行的运算符 |
| `waitingForOperand` | 刚按过运算符，下一次输入要**清屏重来**（不能接在结果后面拼数字） |

事件分流全在 `WM_COMMAND`：数字键 → `AppendDigit`（受 `waitingForOperand` 控制）；运算符键 → 若已有待执行运算就先结算，再记录新运算符并置 `waitingForOperand`；`=` → 结算并清除待执行状态；`C` → 全部复位。

把"连续按 2+3+4+5"在脑中逐步走一遍这个状态机，是检验你真的理解了还是背下来了的标准——`05_mini_calculator` 的 `WM_COMMAND` 分支就是完整实现。

**学到的通用能力**：界面（按钮网格）与逻辑（状态机）完全分离；`WM_COMMAND` 里只做"事件 → 状态转移 → 刷新显示"三件事，没有任何运算细节泄漏进 `WndProc`。

## 11.2 案例二：RichEdit 文本编辑器 —— 多子系统协作

对应 `examples/06_text_editor`。它小小一个 exe，其实横跨了前面各章的全部主题：

```text
菜单（第 10 章）──→ WM_COMMAND ──→ GetOpenFileNameW（第 10 章）
                                      │
                                      ▼
                       CreateFileW / ReadFile / WriteFile（第 16 章预演）
                                      │
                                      ▼
                       MultiByteToWideChar（第 12 章预演）
                                      │
                                      ▼
                       SetWindowTextW → RichEdit 控件（第 7 章）
                                      │
WM_SIZE 重排编辑区（第 5 章）←── 主窗口（第 4 章消息循环）
```

四个值得抄走的模式：

**1）布局即一条规则**：编辑区永远铺满客户区，`WM_SIZE` 一行搞定（见 5.6 节）。很多"界面程序"的复杂度来自不必要的布局需求，先问自己"真的需要吗"。

**2）文件读写的标准三段式**（第 16 章展开，这里先见个面）：

```cpp
HANDLE h = CreateFileW(path, GENERIC_READ, FILE_SHARE_READ,
                       nullptr, OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL, nullptr);
if (h == INVALID_HANDLE_VALUE) { /* GetLastError() → 报错 */ return; }

LARGE_INTEGER size;
GetFileSizeEx(h, &size);
std::vector<char> buf((size_t)size.QuadPart + 1);
DWORD read = 0;
ReadFile(h, buf.data(), (DWORD)size.QuadPart, &read, nullptr);
CloseHandle(h);

// 多字节文本 → 宽字符（文件按 UTF-8 假设）：
int wlen = MultiByteToWideChar(CP_UTF8, 0, buf.data(), (int)read, nullptr, 0);
std::wstring wtext(wlen, L'\0');
MultiByteToWideChar(CP_UTF8, 0, buf.data(), (int)read, wtext.data(), wlen);
SetWindowTextW(hEdit, wtext.c_str());
```

注意 `ReadFile` 一次读大文件通常可行，但**严格来说要循环读到返回的字节数达标**——第 16 章讲清楚什么时候必须循环。

**3）EDIT → RichEdit 的升级现场**：示例编辑区用的是 RichEdit 4.1（`RICHEDIT50W`）。升级的完整 diff 只有四处，正对应第 7.6 节的预告：

| 改动 | 内容 |
|------|------|
| ① 加载 | `wWinMain` 开头 `LoadLibraryW(L"msftedit.dll")`，退出 `FreeLibrary` |
| ② 类名 | `L"EDIT"` → `L"RICHEDIT50W"` |
| ③ 字体 | 创建后发 `EM_SETCHARFORMAT`（`CHARFORMAT2W`，twips 字号） |
| ④ 其余 | **零改动**——`Get/SetWindowTextW`、`EN_CHANGE`、`WM_SIZE` 布局全部照旧 |

为什么值得升：64KB 以上文本的编辑性能、无限撤销、查找替换（`EM_FINDTEXTW`）、富文本格式。为什么不是必须：纯展示场景 EDIT 更省——第 7.6 节的取舍表在这里兑现。

**4）脏标记与关闭确认**（练习方向，思路给出）：监听 `EN_CHANGE` 置 `g_dirty = true`；`WM_CLOSE` 时若脏则弹"保存吗？"（`MB_YESNOCANCEL`），YES 走保存流程再 `DestroyWindow`，CANCEL 则 `return 0` 拦住关闭——第 4 章 `WM_CLOSE` 的拦截点在这里第一次派上真用场。

**5）错误要可见**：`CreateFileW` 失败时用 `FormatMessageW` 把 `GetLastError()` 翻译成人话弹出来（第 3 章），而不是静默失败：

```cpp
wchar_t msg[256];
FormatMessageW(FORMAT_MESSAGE_FROM_SYSTEM | FORMAT_MESSAGE_IGNORE_INSERTS,
               nullptr, GetLastError(), 0, msg, 256, nullptr);
MessageBoxW(hwnd, msg, L"打开失败", MB_OK | MB_ICONERROR);
```

## 11.3 案例三：绘图板 —— 状态-绘制分离

对应 `examples/07_paint_app`。第 9.5 节已经给出核心结构，这里提炼设计要点：

1. **数据结构选对，问题就解了一半**：绘图板的内容 = 线段列表 `std::vector<Segment>`。想支持"撤销"？再存一份快照或用命令模式；想支持变色？给 `Segment` 加颜色字段。数据结构决定功能上限。
2. **`SetCapture`/`ReleaseCapture` 处理拖出边界**：按住鼠标拖出窗口后默认收不到 `WM_MOUSEMOVE`，`SetCapture(hwnd)` 让窗口独占鼠标消息直到释放——所有拖拽类交互的标配。
3. **`WM_PAINT` 是全量重画**：几十条线段直接重画毫无压力；上万条才需要第 9 章说的"增量画进内存位图"优化。**先写对的，再写快的**。

## 11.4 三个案例的共同骨架

把三个程序的 `WndProc` 并排看，结构完全同构：

| 消息 | 计算器 | 编辑器 | 绘图板 | 通用职责 |
|------|--------|--------|--------|---------|
| `WM_CREATE` | 建按钮网格 | 建菜单+编辑区 | 初始化状态 | 建界面、初始化状态 |
| `WM_SIZE` | 重排按钮 | 编辑区铺满 | —— | 布局 |
| `WM_COMMAND` | 状态机转移 | 命令分发 | —— | 命令/控件事件 |
| 鼠标/键盘 | —— | —— | 更新线段状态 | 交互状态更新 |
| `WM_PAINT` | 刷显示屏 | （控件自绘） | 重画全部线段 | 渲染状态 |
| `WM_DESTROY` | 清理 | FreeLibrary | 清理 | 收尾 |

这就是 Win32 程序的"五行骨架"——之后的几十种控件、Direct2D 渲染、多文档界面，都是在这个骨架的某个格子里加东西。**把这三个示例亲手敲一遍并各自改动一个功能**（比如给计算器加小数点、给编辑器加"另存为"、给绘图板加撤销），比多读三章书更有效。

## 11.5 易错清单

| 症状 | 原因 | 解法 |
|------|------|------|
| 计算器按运算符后数字接在结果后面 | 没实现 `waitingForOperand` | 11.1 状态机 |
| `2+3*4` 算成 20 | 状态机没有优先级概念——迷你计算器按"立即结算"设计 | 要么文档声明局限，要么练手加优先级（表达式解析） |
| 保存的文件是空/乱码 | 编码转换缺了真正的转换调用（两段式只做了第一段） | 11.2 模式 2 的完整代码 |
| 打开 UTF-8 文件中文乱码 | 文件实际是 GBK/ANSI | 按 BOM/内容探测（第 12 章练习） |
| 编辑器改了没保存就退出丢了内容 | 没做脏标记 | 11.2 模式 4 |
| 拖动画图出窗口就断线 | 没 `SetCapture` | 11.3 |
| 窗口缩放后绘图内容错位 | 线段存的是窗口坐标，缩放语义未定义 | 明确"画布=窗口"或存归一化坐标（练习） |

## 11.6 小结

1. 三个程序一套骨架：`WM_CREATE/WM_SIZE/WM_COMMAND/输入/WM_PAINT/WM_DESTROY` 六格各司其职。
2. 计算器教状态机：四个状态变量决定一切，界面与逻辑零耦合。
3. 编辑器教多子系统协作：命令系统、文件 IO、编码转换、控件四条线在 `WM_COMMAND` 汇合；RichEdit 升级只动四处。
4. 绘图板教状态-绘制分离：数据结构决定功能上限，`InvalidateRect` 是唯一重画请求。

## 11.7 动手练习

1. 计算器加小数点与退格键（提示：小数点要防重复输入——又一个状态位）。
2. 编辑器实现完整脏标记 + 关闭确认 + 标题栏"未保存 *"标记（11.2 模式 4）。
3. 编辑器加查找替换：`EM_FINDTEXTW` + `EM_SETSEL` + `EM_REPLACESEL` 三条消息足够。
4. 绘图板加撤销（Ctrl+Z，配合第 10 章加速键）：每笔压栈，撤销弹栈重画。
