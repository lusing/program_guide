# 第 17 章 内核对象与安全

> **本章回答的问题**：内核对象和 GDI/用户对象差在哪？句柄复制是什么？安全描述符（SD）、DACL、ACE、SID、令牌分别是什么关系？UAC 到底拦了什么？"完整性级别"又是什么？怎么亲手给文件写一条 ACL？
>
> **前置章节**：第 4 章（句柄纪律）、第 14 章（内核对象可等待）、第 16 章（文件对象——本章的安全实验载体）。
>
> **你将做出什么**：一个安全检查工具（`examples/21_security_descriptors`）：查自己的 UAC 状态与完整性级别，亲手给文件写 DACL 再读回来数 ACE。

本章示例：`examples/21_security_descriptors/main.cpp`。

## 17.1 对象三大家族：句柄族谱

Win32 的"句柄"其实分三个世界，归还函数各归各家（第 4 章的表在这里升维）：

| 家族 | 住在哪 | 成员 | 归还 | 特权 |
|------|--------|------|------|------|
| **内核对象** | 内核空间 | 进程/线程/文件/事件/互斥体/信号量/文件映射/Job… | `CloseHandle` 统一 | **可等待**、可命名、可跨进程共享、有安全描述符 |
| **USER 对象** | win32k | 窗口 `HWND`、菜单、钩子、光标 | `DestroyWindow`/`DestroyMenu`… | 不可 `WaitForSingleObject` |
| **GDI 对象** | win32k | 画笔/画刷/字体/位图 | `DeleteObject` | 每进程 10000 个配额 |

内核对象的四个共性，是它撑起系统服务层的原因：

1. **引用计数**：所有句柄关闭（+内核内部引用归零）对象才消失——第 13 章"进程退出但句柄吊着"的真相；
2. **可命名**：`CreateMutexW(nullptr, FALSE, L"Local\\Name")`——命名即跨进程寻址（第 14 章共享内存同理）；
3. **可等待**：统一进 `WaitForSingleObject` 家族；
4. **有安全描述符**：创建时可指定谁能用它——本章主角。

**句柄复制**（`DuplicateHandle`）是跨进程共享内核对象的正规军：A 进程把自己的句柄复制进 B 的句柄表（B 得先给 A 一个自己的进程句柄）。继承（`STARTUPINFOEXW` 属性列表，13.6 节）是父子场景的版本。排查句柄泄漏看任务管理器"句柄"列——只涨不跌的程序就是泄漏现场。

## 17.2 安全描述符：对象的"门禁规则"

每个安全对象（内核对象、文件、注册表键、服务…）挂一份**安全描述符（SD）**，四室一厅：

```text
SECURITY_DESCRIPTOR
┌─────────────────────────────────────────────┐
│ Owner（所有者 SID）   —— 谁拥有它（能改 DACL）  │
│ Group（组 SID）      —— POSIX 兼容用，Win 少用 │
│ ┌─ DACL（自主访问控制表）── 谁能访问 ────────┐ │
│ │  ACE[0]: 允许  XULUN-MAIN\lusin  完全控制   │ │
│ │  ACE[1]: 允许  Everyone            只读     │ │
│ │  ACE[2]: 拒绝  BadGuy             一切      │ │ ← 拒绝优先！
│ └────────────────────────────────────────────┘ │
│ SACL（审计规则）    —— 谁访问要记日志（管理员向）│
└─────────────────────────────────────────────┘
```

三个关键概念：

- **SID**（Security IDentifier）：账户的机器可读身份，形如 `S-1-5-21-...-1001`。著名常客：`S-1-1-0`（Everyone）、`S-1-5-18`（SYSTEM）、`S-1-5-32-544`（Administrators）。**用 SID 而不是账户名写规则**——名字随语言/域变，SID 不变；
- **ACE**（Access Control Entry）：一条"允许/拒绝 + 谁 + 什么权限"的规则。**DACL 按序评估，拒绝 ACE 优先**——放在前面才能挡住后面的允许；
- **DACL 的两个极端**：**空 DACL**（present 但零条目）= **允许所有人一切**；**无 DACL**（present=FALSE）= 同样全允许；想要"谁都不许"得放一条"拒绝 Everyone"。这两者的语义坑倒过来记：**没有限制 = 没有门禁，不是没人能进**。

访问检查一句话：**拿访问者的令牌，从 DACL 头走到尾，第一条匹配的 ACE 说了算；走到头没匹配 = 拒绝**（默认拒绝是安全底线）。

## 17.3 令牌：进程的身份证

登录时系统发给每个进程一份**访问令牌**（token），装着：

- 用户 SID + 所属组 SID 列表；
- 特权列表（`SeDebugPrivilege`、`SeShutdownPrivilege`……）；
- 完整性级别（下节）；
- 登录会话信息。

`OpenProcessToken(GetCurrentProcess(), TOKEN_QUERY, &token)` 后 `GetTokenInformation` 能查的内容包括：用户（`TokenUser`）、组（`TokenGroups`）、特权（`TokenPrivileges`）、提升状态（`TokenElevation`）、完整性级别（`TokenIntegrityLevel`）。

## 17.4 UAC：为什么"以管理员运行"是个开关

Vista 之前：管理员账户的进程拿全权令牌，普通用户的拿受限令牌。UAC 的设计：**管理员登录也发两份令牌**——

```text
管理员登录
   ├─ 完整令牌（High 完整性）── 只给"以管理员运行"提升后的进程
   └─ 过滤令牌（Medium 完整性）── 日常双击的程序用这份
标准用户登录
   └─ 一份受限令牌（Medium 完整性）
```

由此产生的三个日常现象，本章逐一解释：

1. **写 Program Files 失败**：过滤令牌对系统目录只有读权。**虚拟化**是兼容老程序的缓冲垫——标准用户写 `C:\Program Files\X\config.ini`，系统悄悄重定向到 `%LOCALAPPDATA%\VirtualStore\Program Files\X\config.ini`（打开这个目录亲眼看一次，虚拟化就再也不是玄学）。新程序应在 manifest 声明 `asInvoker` 并把可写数据放 `%APPDATA%`；
2. **要求提升**：manifest 里 `requireAdministrator`，双击即弹 UAC 框；运行期提升只能**再启动一个进程**（`runas` 动词 `ShellExecuteW`）——令牌不能"升级"，只能换进程；
3. **`ERROR_ACCESS_DENIED` 的完整排查链**：先看目标对象的 DACL，再看自己的令牌（提升了没？），最后看完整性级别——三层下来，九成权限问题定位。

## 17.5 完整性级别与 UIPI

完整性级别（Integrity Level）是 Vista 引入的**强制**隔离，档位：

| RID | 级别 | 谁在这档 |
|-----|------|---------|
| 0x1000 | Low | 低信任：IE 保护模式的历史用途 |
| 0x2000 | Medium | 普通程序默认档 |
| 0x4000 | High | 管理员提升后的进程 |
| 0x6000+ | System | 系统进程 |

规则：**高完整性进程可以写低完整性对象；反向不行**（No Write Up）。配套的 **UIPI**（User Interface Privilege Isolation）再补一刀：**低完整性进程不能给高完整性窗口发消息**——你在第 4 章的 `PostMessage` 偶发失败、老程序"无法向管理员窗口发送按键"，真相都在这（`ChangeWindowMessageFilterEx` 可按消息豁免）。

## 17.6 亲手写一条 ACL：`BuildSecurityDescriptorW`

给文件/内核对象设 DACL 的现代做法是"描述意图，系统建包"：

```cpp
// ① 拿 SID：Everyone 用权威常量拼（S-1-1-0）
PSID everyone = nullptr;
SID_IDENTIFIER_AUTHORITY worldAuth = SECURITY_WORLD_SID_AUTHORITY;
AllocateAndInitializeSid(&worldAuth, 1, SECURITY_WORLD_RID,
                         0, 0, 0, 0, 0, 0, 0, &everyone);

// ② 描述两条授权（自己全权 + Everyone 只读）
EXPLICIT_ACCESSW ea[2] = {};
ea[0].grfAccessPermissions = GENERIC_ALL;
ea[0].grfAccessMode = GRANT_ACCESS;
ea[0].Trustee.TrusteeForm = TRUSTEE_IS_NAME;   // 自己：账户名方便
ea[0].Trustee.ptstrName = userName;
ea[1].grfAccessPermissions = GENERIC_READ;
ea[1].grfAccessMode = GRANT_ACCESS;
ea[1].Trustee.TrusteeForm = TRUSTEE_IS_SID;    // Everyone：SID 抗本地化
ea[1].Trustee.ptstrName = (LPWSTR)everyone;

// ③ 系统打包成 SD，挂到文件上
PSECURITY_DESCRIPTOR sd = nullptr;
BuildSecurityDescriptorW(nullptr, nullptr, 2, ea, 0, nullptr, nullptr,
                         &sdLen, &sd);
PACL dacl; BOOL present, defaulted;
GetSecurityDescriptorDacl(sd, &present, &dacl, &defaulted);
SetNamedSecurityInfoW(path, SE_FILE_OBJECT, DACL_SECURITY_INFORMATION,
                      nullptr, nullptr, dacl, nullptr);
```

21 示例运行后读回的 ACE 列表是个意外之喜：**不止我们写的 2 条，总共 9 条**——因为 `SetNamedSecurityInfoW` 默认**合并**目标从父目录继承来的 ACE（自己的 2 条在前，继承的 7 条在后，继承条目带 `INHERITED_ACE` 标志）。想要"只有我说了算"的干净 DACL，加 `PROTECTED_DACL_SECURITY_INFORMATION` 标志切断继承。读回的世界同样丰富：`GetNamedSecurityInfoW` + `GetAce` 遍历 + `LookupAccountSidW` 把 SID 翻译回账户名。

## 17.7 进程加固一句话

`SetProcessMitigationPolicy`（Win8+）能给进程开系统级缓解：DEP（数据执行防护）、ASLR 强制、CFG（控制流防护）、子进程禁生……现代软件发布清单的常客。初学知道入口即可。

## 17.8 易错清单

| 症状 | 原因 | 解法 |
|------|------|------|
| 写 Program Files "成功"但程序读不到 | 虚拟化重定向到 VirtualStore | manifest `asInvoker` + 数据放 `%APPDATA%` |
| DACL 全给了 Everyone 完全控制 | 图省事的安全炸弹 | 最小权限原则：默认只给自己 |
| 想让"没人能访问"结果所有人都能 | 空/无 DACL = 全允许 | 放一条"拒绝 Everyone"的 ACE |
| 拒绝 ACE 放在允许后面 | 先匹配到允许，拒绝失效 | 拒绝在前 |
| `OpenProcess` 拿不到系统进程 | 权限不足（要 `SeDebugPrivilege`） | 提升或放弃——这是设计 |
| 低完整性进程 `PostMessage` 给高完整性窗口失败 | UIPI | `ChangeWindowMessageFilterEx` 或提权 |
| SID 硬编码成字节数组 | 换域/系统即失效 | `AllocateAndInitializeSid` 拼权威值 |
| `BuildSecurityDescriptorW` 的返回 SD 忘 `LocalFree` | 泄漏 | 系统分配的都要还（`FreeSid`/`LocalFree`） |

## 17.9 小结

1. 对象三家族：内核对象独享"可等待/可命名/带 SD"；句柄复制与继承是共享的两条正路。
2. SD 四室：Owner/Group/DACL/SACL；DACL 按 ACE 顺序评估、拒绝优先；空/无 DACL = 全允许。
3. 令牌装身份（SID+组+特权+完整性）；访问检查 = 令牌 ∩ DACL。
4. UAC = 双令牌：过滤令牌日常用、完整令牌按需提；虚拟化是兼容垫片不是功能。
5. 完整性级别是强制隔离：No Write Up + UIPI 挡低向高的写入与消息。

## 17.10 动手练习

1. 用 21 示例的套路给一个新建文件写"拒绝自己读"的 ACE（`DENY_ACCESS` + 自己的 SID），然后 `CreateFileW` 读它——亲手收到 `ERROR_ACCESS_DENIED`，再改回。
2. 虚拟化实地验证：标准用户权限下让一个无 manifest 的程序写 `C:\Program Files\demo\test.txt`，然后去 `%LOCALAPPDATA%\VirtualStore\Program Files\demo\` 找它。
3. 给 21 示例加 `PROTECTED_DACL_SECURITY_INFORMATION`，对比读回的 ACE 数量变化，并用 `GetAce` 检查 `INHERITED_ACE` 标志位的有无。
