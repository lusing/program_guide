# 第 2 章 环境搭建与第一个窗口

> **本章回答的问题**：我需要装什么？怎么把一个 Win32 程序从源码变成 exe？`wWinMain` 是什么，为什么不是 `main`？`L""`、`W` 后缀、版本宏这些"咒语"分别是什么意思？编译报错时怎么对照排查？
>
> **前置章节**：第 1 章（知道 Win32 是"操作系统的服务接口"这一定位即可）。
>
> **你将做出什么**：两个程序——0 号程序（一行核心代码的消息框）和 1 号程序（完整的最小窗口）。以及一条亲手走过的"源码 → obj → exe"链路。

## 2.1 需要什么工具

写 Win32 程序只需要"能编译 C++ 并链接 Windows SDK"的工具链，任何一种都行：

| 工具链 | 获取方式 | 适合谁 |
|--------|---------|--------|
| **Visual Studio（MSVC）** | 官方 Community 版免费，安装时勾选"使用 C++ 的桌面开发" | 大多数人；调试体验最好 |
| **MSVC 命令行（cl.exe）** | 随 VS 安装，通过 `vcvars64.bat` 进入环境 | 想理解编译链接细节的人；本仓库 build 脚本用的就是它 |
| MinGW-w64 / Clang | 各自官网或 MSYS2 | 偏好 GCC 系工具的人 |

本教程以 MSVC 为主线。两种进入方式：

- **图形界面**：安装 VS 后，新建项目选"Windows 桌面应用程序"模板，IDE 帮你处理子系统、导入库这些细节。
- **命令行**：开始菜单打开"Developer Command Prompt for VS"（或先执行 `vcvars64.bat`），就有了 `cl`（编译器）和 `link`（链接器）。

自检一下环境是否就绪（在任何命令行里）：

```bat
cl
```

看到编译器版本横幅（例如 "Microsoft (R) C/C++ Optimizing Compiler"）就说明可用；报"不是内部或外部命令"则说明你没在开发者命令行里，先跑 `vcvars64.bat`。

> 建议至少手动编译一次，理解每一步在做什么——IDE 把这些细节藏起来，但它们将来都会变成你的报错。

## 2.2 从源码到 exe：编译与链接

先看全景图，一个 Win32 程序的构建就这两步：

```text
main.cpp ──(cl 编译)──> main.obj ──(link 链接)──> hello.exe
   源码                   目标文件                  + user32.dll 等运行时依赖
```

具体命令：

```bat
:: 1) 编译：main.cpp → main.obj
cl /nologo /std:c++20 /EHsc /DUNICODE /D_UNICODE /utf-8 /c main.cpp

:: 2) 链接：main.obj → hello.exe
link /nologo /MACHINE:X64 /OUT:hello.exe /SUBSYSTEM:WINDOWS main.obj ^
     user32.lib gdi32.lib kernel32.lib
```

初学者必须搞懂这几个开关，它们各自回答一个问题：

| 开关 | 回答的问题 |
|------|-----------|
| `/DUNICODE /D_UNICODE` | 用 A 还是 W 系列 API？（定义 `UNICODE` 宏，让 Windows 头文件里的通用名映射到 W 版本） |
| `/utf-8` | 源文件里的中文字符串按什么编码读？（源码存成 UTF-8 时必须加，否则中文乱码） |
| `/SUBSYSTEM:WINDOWS` | 这是 GUI 程序，入口是 `wWinMain`，不需要控制台（若设成 `CONSOLE` 而又没有 `main`，就会链接错误） |
| `user32.lib gdi32.lib kernel32.lib` | 用到的 API 在哪些 DLL 里？链接器需要对应的**导入库**才知道怎么填地址。窗口程序至少要 user32 + gdi32 + kernel32 |
| `/std:c++20 /EHsc` | C++ 语言标准与异常模型（与本教程示例一致） |

**什么是导入库（.lib）？** 它不是代码，而是一张"欠条清单"：你的 obj 里写着"我要调 `CreateWindowExW`，它在某个 DLL 里"，导入库告诉链接器"这个函数住在 user32.dll 的第几个导出"。链接器据此在 exe 里写入导入表，进程启动时加载器按表把真实地址填上——第 19 章 DLL 基础会把这些机制完全展开。

**亲手验证链接发生了什么**（在开发者命令行里）：

```bat
dumpbin /imports hello.exe
```

输出里能看到 `user32.dll` 的名字和它下面一串你调用的函数（`CreateWindowExW`、`GetMessageW`……）。这就是"链接了导入库"的物证——exe 自己不带这些函数，只带了一张"我要向谁要什么"的清单。

本仓库提供了自动脚本（`win32/build.ps1`），内部就是干上面这两步：

```powershell
cd G:\code\guide\win32
.\build.ps1 -All                # 编译 examples 下全部示例
.\build.ps1 -File 01_hello_window\main.cpp   # 编译单个
```

## 2.3 版本宏：声明你的程序支持多老的 Windows

Windows SDK 的头文件用宏来"裁剪"能看到的 API。你的程序要用的 API 最低需要哪个 Windows 版本，就把宏设到对应值：

```cpp
// 通常放在编译选项或 pch 最前面（必须在 #include <windows.h> 之前）
#define WINVER       0x0A00   // 目标：Windows 10
#define _WIN32_WINNT 0x0A00   // 同上，两个宏保持一致
```

| 宏值 | 最低支持 |
|------|---------|
| `0x0600` `_WIN32_WINNT_VISTA` | Vista（SRWLock、条件变量、线程池） |
| `0x0601` `_WIN32_WINNT_WIN7` | Win7 |
| `0x0603` `_WIN32_WINNT_WIN8` | Win8（`WaitOnAddress`） |
| `0x0A00` `_WIN32_WINNT_WIN10` | Win10（`SetThreadDescription`、DPI V2 等） |

规则很简单：**宏设得太低，新 API 在头文件里根本不存在，编译报"未声明的标识符"；设得太高，程序在老系统上可能缺函数**。本教程所有示例按 Win10+ 编写，用 `/D_WIN32_WINNT=0x0A00` 编译。MSVC 下也可以用 `#pragma comment(lib, "user32.lib")` 直接在源码里指定导入库，省去链接命令里的库名。

## 2.4 `wWinMain`：GUI 程序的入口

控制台程序入口是 `main`，Windows GUI 程序入口是 `wWinMain`：

```cpp
int WINAPI wWinMain(HINSTANCE hInstance,     // 本程序实例句柄
                    HINSTANCE hPrevInstance, // 历史遗留，16 位时代的产物，如今恒为 nullptr
                    PWSTR    lpCmdLine,      // 命令行参数（宽字符）
                    int      nCmdShow);      // 建议的窗口显示方式（最大化/最小化/正常）
```

几个必须澄清的点：

- **它不是你调用的，是操作系统调用的**。程序启动时，C 运行时先执行初始化，然后由启动代码调用你提供的 `wWinMain`。
- **`WINAPI` 是调用约定的标注**，展开为 `__stdcall`——函数参数入栈顺序和清栈方式的约定。Win32 API 的函数指针基本都要带它，照抄即可，X64 上实际已统一为同一约定。
- **`hInstance` 是什么**：本 exe 加载进内存后的"实例句柄"，创建窗口类、加载资源时都要出示它，用于告诉系统"资源来自哪个模块"。
- **`wWinMain` 与 `WinMain` 的区别**：前者收宽字符命令行（`PWSTR`），后者收 ANSI（`LPSTR`）。用 Unicode 就选 `wWinMain`。
- **想要控制台输出的混合程序**：把子系统设为 `CONSOLE` 并用 `main` 也完全可以——Win32 的系统能力（进程、文件、内存）在控制台程序里照用不误，本教程系统服务层的小例子为了简洁就用 `wmain`（宽字符版 `main`）。

## 2.5 第一个程序：两级台阶

### 0 号程序：一行核心代码

完整程序只有 `#include` 加一个函数调用——先感受"程序能跑"：

```cpp
#include <windows.h>

int WINAPI wWinMain(HINSTANCE, HINSTANCE, PWSTR, int) {
    MessageBoxW(nullptr, L"你好，Win32", L"我的第一个程序", MB_OK);
    return 0;
}
```

编译命令与 2.2 相同（只链接 kernel32 足够：`link ... main.obj kernel32.lib user32.lib`）。双击 exe，弹出一个消息框——这就是最短的 GUI 程序。它没有自己的窗口，只是借用系统的消息框；下一步我们造一个**真正属于自己的窗口**。

### 1 号程序：完整的最小窗口

下面是完整、可编译、可直接运行的最小 Win32 窗口程序（对应 `examples/01_hello_window/main.cpp`）：

```cpp
#include <windows.h>

// 1) 窗口过程：系统把发生在窗口上的事件（消息）送到这里
LRESULT CALLBACK WndProc(HWND hwnd, UINT msg, WPARAM wParam, LPARAM lParam) {
    switch (msg) {
    case WM_PAINT: {                       // 窗口需要重绘
        PAINTSTRUCT ps;
        HDC hdc = BeginPaint(hwnd, &ps);   // 开始绘制，拿到绘图上下文
        RECT rect;
        GetClientRect(hwnd, &rect);
        SetBkMode(hdc, TRANSPARENT);
        SetTextColor(hdc, RGB(0, 0, 0));
        DrawTextW(hdc, L"Hello Win32", -1, &rect,
                  DT_SINGLELINE | DT_CENTER | DT_VCENTER);
        EndPaint(hwnd, &ps);               // 结束绘制
        return 0;
    }
    case WM_DESTROY:                       // 窗口被销毁
        PostQuitMessage(0);                // 让消息循环退出
        return 0;
    }
    // 没有处理的消息必须交还给系统默认处理，否则窗口行为残缺
    return DefWindowProcW(hwnd, msg, wParam, lParam);
}

// 2) 程序入口
int WINAPI wWinMain(HINSTANCE hInstance, HINSTANCE, PWSTR, int nCmdShow) {
    // 2.1 注册窗口类：告诉系统"我要造一种叫 HelloWindowClass 的窗口，
    //     它的事件由 WndProc 处理"
    const wchar_t CLASS_NAME[] = L"HelloWindowClass";

    WNDCLASSEXW wc = {};
    wc.cbSize        = sizeof(wc);
    wc.lpfnWndProc   = WndProc;                      // 窗口过程
    wc.hInstance     = hInstance;                    // 属于哪个模块
    wc.hCursor       = LoadCursor(nullptr, IDC_ARROW); // 鼠标形状
    wc.hbrBackground = (HBRUSH)(COLOR_WINDOW + 1);   // 背景刷：系统窗口色
    wc.lpszClassName = CLASS_NAME;                   // 类名，创建窗口时要用

    if (RegisterClassExW(&wc) == 0) {
        return 1;                                    // 注册失败（几乎不会发生，但要检查）
    }

    // 2.2 创建窗口实例
    HWND hwnd = CreateWindowExW(
        0,                    // 扩展样式，暂不用
        CLASS_NAME,           // 用刚才注册的类
        L"Hello Win32",       // 标题栏文字
        WS_OVERLAPPEDWINDOW,  // 带标题栏/边框/最大化按钮等的标准样式
        CW_USEDEFAULT, CW_USEDEFAULT,  // 位置交给系统
        640, 480,             // 宽高
        nullptr,              // 父窗口（顶层窗口没有）
        nullptr,              // 菜单（没有）
        hInstance,            // 实例句柄
        nullptr);             // 附加数据（没有）

    if (hwnd == nullptr) {
        return 1;
    }

    ShowWindow(hwnd, nCmdShow);   // 把窗口显示出来
    UpdateWindow(hwnd);           // 立即发一次 WM_PAINT

    // 2.3 消息循环：程序的心跳，直到收到 WM_QUIT 才结束
    MSG msg = {};
    while (GetMessageW(&msg, nullptr, 0, 0) > 0) {
        TranslateMessage(&msg);   // 把按键消息翻译成字符消息
        DispatchMessageW(&msg);   // 把消息送到 WndProc
    }

    return (int)msg.wParam;       // WM_QUIT 的 wParam 就是退出码
}
```

编译运行，你会看到一个居中显示"Hello Win32"的窗口。**哪怕关闭全部好奇心，也请至少理解三件事**：

1. **注册类 → 创建窗口 → 显示 → 消息循环**，这是每个 Win32 GUI 程序雷打不动的骨架；
2. **`WndProc` 是系统回调你**，不是你调用它——这就是"消息驱动"；
3. **没处理的消息必须 `return DefWindowProcW(...)`**，它负责移动、缩放、关闭按钮等几十种默认行为。初学者最常见的 bug 就是把 `DefWindowProcW` 漏了或写在 `switch` 的某个分支里提前 `return`，导致窗口拖不动、关不掉。

第 4 章会把这三件事背后的机制（消息队列、分发、默认处理）彻底讲透，这里先让程序跑起来。

## 2.6 宽字符与中文字符串

Win32 的字符串规则一句话：**全用 `wchar_t` + `W` 系列 API + `L""` 字面量，源文件存 UTF-8 并加 `/utf-8` 编译**。

```cpp
MessageBoxW(nullptr, L"你好，Win32", L"提示", MB_OK);   // 正确
```

反例（都真实存在于老代码里，别学）：

```cpp
MessageBoxA(nullptr, "你好", "提示", MB_OK);  // ANSI 版本：依赖系统代码页，乱码风险
MessageBox(nullptr, TEXT("你好"), ...);       // 宏切换版本：取决于 UNICODE 宏，不稳定
```

`A` 版本内部其实会把你的 ANSI 字符串转成宽字符再调 `W` 版本——`W` 才是系统的原生形态。为什么 `sizeof(L"中")` 是 4、代码页是什么、UTF-8 与 UTF-16 怎么互转——第 12 章字符编码有完整答案；现在记住规则即可。

## 2.7 常见编译与运行错误对照表

初学者前三天几乎必踩下面的坑，提前对照：

| 症状 | 原因 | 解法 |
|------|------|------|
| `LNK2019: 无法解析的外部符号 wWinMain` | 入口函数签名写错（比如写成 `wWinMain(int, char**)`）或漏写 | 照抄 2.5 节的标准签名 |
| `LNK2019: 无法解析的外部符号 _main` | 子系统是 CONSOLE 但想用 `wWinMain`（或反之） | 入口函数与 `/SUBSYSTEM` 配套 |
| `LNK1561: 必须定义入口点` | 入口名拼写错（如 `WinMain` 配 CONSOLE、`wmain` 配 WINDOWS） | 同上：`wWinMain`↔WINDOWS，`wmain`↔CONSOLE |
| `error C2065: "CreateWindowExW": 未声明的标识符` | 忘了 `#include <windows.h>`；或版本宏太低导致新 API 不可见 | 补头文件；把 `_WIN32_WINNT` 调高（2.3 节） |
| `error C2001: 常量中有换行符` | 源码编码不是 UTF-8 却含中文，或中文字符串被截断成奇数字节 | 源文件另存为 UTF-8；检查字符串完整性 |
| `LNK2019: 无法解析的外部符号 __imp__CreateProcessW` | 用了 API 但没链接对应导入库 | 链接命令加 `kernel32.lib` 等，或源码加 `#pragma comment(lib, ...)` |
| 窗口能出来但拖不动、点 ✕ 没反应 | `WndProc` 漏了 `DefWindowProcW` 兜底 | 见 2.5 节第 3 点 |
| 中文显示乱码 | 源码 UTF-8 但没加 `/utf-8`；或用了 `A` 系列 API | 见 2.6 节 |
| 双击 exe 闪过一个黑色控制台窗口 | 子系统误设为 CONSOLE | `/SUBSYSTEM:WINDOWS` |
| `CreateWindowExW` 返回 nullptr | 类名没注册/已重复注册；`hInstance` 传错 | 检查 `RegisterClassExW` 返回值和参数 |
| exe 拷到别的机器报"缺少 VCRUNTIME140.dll" | 动态链接的 CRT 没随行分发 | 静态链接（`/MT`）或安装运行库；第 19 章会讲 DLL 依赖的分发问题 |

## 2.8 小结

1. 两种工具链进入方式：VS 模板（快）或 vcvars + cl（懂原理）；本仓库走后者。
2. 构建两步：cl 编译出 obj，link 借导入库把 obj 连成 exe；`dumpbin /imports` 能亲眼看到链接结果。
3. `wWinMain` 是系统调用你的入口；`hInstance` 是"我这个模块"的凭证。
4. 骨架四步：注册类 → 创建窗口 → 显示 → 消息循环；`DefWindowProcW` 兜底不可少。
5. 字符串一律 `wchar_t` + `W` + `L""` + `/utf-8`，理由第 12 章揭晓。

## 2.9 动手练习

1. 把 1 号程序的窗口标题改成你的名字、尺寸改成 800×600、背景改成 `COLOR_BTNFACE + 1`——三处小改动，熟悉"改一行、编一次、看效果"的节奏。
2. 故意注释掉 `return DefWindowProcW(...)` 那行（换成 `return 0;`），重新编译，试试拖动和关闭窗口——亲眼看一次"窗口残废"长什么样，再改回来。
3. 对 `01_hello_window` 的产物跑一次 `dumpbin /imports`，数一数它导入了几个 DLL；对照 1.2 节（第 1 章）的 DLL 分工表，每个 DLL 为什么会在列表里？
