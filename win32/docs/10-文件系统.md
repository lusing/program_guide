# 第 10 章 文件系统

> 本章回答的问题：`CreateFileW` 的八个参数到底每个在说什么？"共享模式"是什么？为什么读写要循环？怎么遍历目录？NTFS 的 ADS、Reparse Point 这些 Windows 特有概念是什么？现代 API（`CreateFile2`、`GetFileInformationByHandleEx`）解决了什么？

> 💡 **本章定位**：文件 I/O 是系统服务层里初学者最常用也最容易写出"碰巧能跑"代码的地方。本章目标是让你写的文件代码在失败、并发、长路径下都站得住。

本章示例：`examples/10_file_manager`、`examples/13_file_system_deep_dive`。

## 10.1 路径的世界观

Windows 路径不是简单字符串，先分清几种形态：

```text
C:\dir\file.txt               普通路径（驱动器号）
\\server\share\file.txt       UNC 路径（网络共享）
\\?\C:\very\long\...          长路径前缀：绕过 260 字符 MAX_PATH 限制
\\.\C:                        设备命名空间：把卷当设备打开（扇区级访问）
C:\dir\file.txt:stream        ADS：文件名后跟备用数据流（10.6 节）
```

实用要点：

- 反斜杠转义：C++ 字符串里写 `L"C:\\tmp\\a.txt"`，或用原始字符串 `LR"(C:\tmp\a.txt)"`；
- Windows 文件名不区分大小写、保留 `CON` `PRN` `AUX` `NUL` 等设备名、结尾不能是空格或点——写文件名生成逻辑时要处理；
- MAX_PATH=260 是历史限制，Win10 1607+ 可通过组策略/manifest 启用长路径，稳妥写法是直接用 `\\?\` 前缀（它同时禁用了路径规范化，`/`、`.`、`..` 都不再被解释）。

## 10.2 `CreateFileW`：一个函数，六种身份

"打开文件"的函数叫 **Create**File，因为它真的身兼创建/打开/截断多职，全靠参数表达：

```cpp
HANDLE h = CreateFileW(
    L"C:\\tmp\\demo.txt",
    GENERIC_READ | GENERIC_WRITE,        // ① 访问权限：我要对它做什么
    0,                                   // ② 共享模式：允许别人同时做什么
    nullptr,                             // ③ 安全属性（句柄可继承性），默认
    CREATE_ALWAYS,                       // ④ 处置方式：存在/不存在时各怎么办
    FILE_ATTRIBUTE_NORMAL,               // ⑤ 属性与标志
    nullptr);                            // ⑥ 模板文件句柄，几乎总是 nullptr

if (h == INVALID_HANDLE_VALUE) {         // ★ 失败返回的是 INVALID_HANDLE_VALUE，不是 nullptr！
    DWORD err = GetLastError();
    // ERROR_FILE_NOT_FOUND / ERROR_ACCESS_DENIED / ERROR_SHARING_VIOLATION ...
}
```

逐个说清，这些参数是面试和实战的双料高频：

**① 访问权限**：`GENERIC_READ` / `GENERIC_WRITE` / `GENERIC_EXECUTE`，按需组合。只读打开就别申请写权限——权限越少，在受控目录（Program Files、网络盘）越不容易被拒。

**② 共享模式**——Windows 独有的语义，**声明"我打开期间允许别人怎么打开"**：

| 传值 | 效果 |
|------|------|
| `0` | 独占：我开着谁也别想再打开（哪怕只读） |
| `FILE_SHARE_READ` | 允许别人同时只读打开 |
| `FILE_SHARE_READ \| FILE_SHARE_WRITE` | 允许别人同时读写打开 |

经典的 `ERROR_SHARING_VIOLATION` 就是两个程序对共享模式谈崩了。日志程序想"一边写一边让别人看"就要给 `FILE_SHARE_READ`。

**④ 处置方式**：

| 值 | 文件存在时 | 文件不存在时 |
|----|-----------|-------------|
| `CREATE_NEW` | 失败 | 创建 |
| `CREATE_ALWAYS` | **清空重写** | 创建 |
| `OPEN_EXISTING` | 打开 | **失败**（读文件的标准选择） |
| `OPEN_ALWAYS` | 打开 | 创建 |
| `TRUNCATE_EXISTING` | 清空 | 失败 |

**⑤ 常用标志**：`FILE_ATTRIBUTE_NORMAL`（普通文件）、`FILE_FLAG_OVERLAPPED`（异步 I/O，进阶）、`FILE_FLAG_WRITE_THROUGH`（写穿缓存）、`FILE_FLAG_BACKUP_SEMANTICS`（打开目录用）。

## 10.3 读写与文件指针

```cpp
// 写
const char text[] = "Hello from Win32!\r\n";
DWORD written = 0;
if (!WriteFile(h, text, sizeof(text) - 1, &written, nullptr)) { /* GetLastError */ }
//                          ↑ 字节数    ↑ 实际写出字节数（必查！）

// 读：★ 必须循环——ReadFile 不保证一次读完
std::vector<char> buf(fileSize);
DWORD total = 0;
while (total < fileSize) {
    DWORD got = 0;
    if (!ReadFile(h, buf.data() + total, fileSize - total, &got, nullptr) || got == 0)
        break;                       // got==0 表示到文件尾
    total += got;
}

// 定位（64 位安全的文件指针）
LARGE_INTEGER pos;
pos.QuadPart = 1024;
SetFilePointerEx(h, pos, nullptr, FILE_BEGIN);   // FILE_CURRENT / FILE_END
SetEndOfFile(h);                                  // 截断/扩展到当前位置
```

三个纪律：

1. **检查 `written`/`got`**：API 返回 TRUE 不等于数据全落了；
2. **循环读**：短读在网络盘、命名管道上是常态，本地盘大文件也可能分批；
3. **句柄即关**：`CloseHandle(h)`，句柄纪律第 N 次出现。文件句柄不关，在 Windows 上还有个本地特色后果——**别人删不掉、改不了名这个文件**（共享模式锁着）。

## 10.4 目录枚举：`FindFirstFileW` 家族

```cpp
WIN32_FIND_DATAW fd;
HANDLE hFind = FindFirstFileW(L"C:\\temp\\*", &fd);   // 通配符模式，*.* 或 *.txt 皆可
if (hFind != INVALID_HANDLE_VALUE) {
    do {
        if (fd.cFileName[0] == L'.') continue;        // 跳过 "." 和 ".."
        bool isDir = (fd.dwFileAttributes & FILE_ATTRIBUTE_DIRECTORY) != 0;

        // ★ 大小：两个 32 位拼 64 位。像 %llu 打 nFileSizeLow 是错误的！
        ULARGE_INTEGER size;
        size.LowPart  = fd.nFileSizeLow;
        size.HighPart = fd.nFileSizeHigh;
        wprintf(L"%ls\t%llu bytes\t%s\n", fd.cFileName, size.QuadPart,
                isDir ? L"<DIR>" : L"");
    } while (FindNextFileW(hFind, &fd));
    FindClose(hFind);                                  // Find 开头 → FindClose
}
```

注意返回值配对是 `FindFirstFileW → FindClose`（不是 CloseHandle）。目录递归遍历 = 在 `isDir` 分支里拼接子路径递归调用这套（注意栈深度，或改用显式队列）。`examples/13_file_system_deep_dive` 有完整实现。

目录本身的操作：`CreateDirectoryW`、`RemoveDirectoryW`（须为空）、`MoveFileExW`（跨卷移动+`MOVEFILE_COPY_ALLOWED`）、`CopyFileW`、`DeleteFileW`。原子改名/移动用 `MoveFileExW` + `MOVEFILE_REPLACE_EXISTING`——"先写临时文件再原子改名"是保证文件不写一半崩掉的工程范式。

## 10.5 文件属性与元数据

```cpp
// 按路径查属性（不打开文件）
DWORD attrs = GetFileAttributesW(L"C:\\path");
bool hidden  = attrs & FILE_ATTRIBUTE_HIDDEN;
bool system  = attrs & FILE_ATTRIBUTE_SYSTEM;
bool readonly= attrs & FILE_ATTRIBUTE_READONLY;

// 按句柄查全套（打开着文件时）
BY_HANDLE_FILE_INFORMATION info = {};
GetFileInformationByHandle(h, &info);
// info.dwFileAttributes          属性
// info.ftCreationTime / ftLastWriteTime / ftLastAccessTime   三个时间戳（FILETIME：1601 年起 100ns）
// info.dwVolumeSerialNumber      所在卷序列号
// info.nFileIndexHigh/Low        文件索引（类似 inode 号）
// info.nFileSizeHigh/Low         大小（同样要拼 64 位！）

// FILETIME → 人类时间
FILETIME ft = info.ftLastWriteTime;
SYSTEMTIME st;
FileTimeToSystemTime(&ft, &st);          // 或 FileTimeToLocalFileTime 先转本地时区
```

`FILETIME` 是 64 位 100 纳秒计数（1601-01-01 起），换算 UNIX 时间戳：`(unix = win/10000000 - 11644473600)`。文件大小永远记得拼 `High/Low`——`examples/13` 修正前的版本正是踩了这个坑（只取 Low 当 64 位打印）。

> 💡 **现代视角（Vista+）**：`GetFileInformationByHandleEx` 一次可查多种新信息：`FileIdInfo`（NTFS 128 位文件 ID）、`FileCaseSensitiveInfo`、`FileStorageInfo`；`CreateFile2` 用参数结构体替代八个散参数并支持 `FILE_FLAG_OPEN_REQUIRING_OPLOCK` 等新标志。写兼容库时二选一按 `_WIN32_WINNT` 分支。

## 10.6 NTFS 特性：Windows 文件系统的"隐藏宝藏"

这部分不是 API 说明书，而是理解 Windows 软件生态的背景知识：

- **MFT（Master File Table）**：NTFS 的一切（文件、目录、元数据）都是 MFT 里的记录。`GetFileInformationByHandle` 的文件索引就是 MFT 记录号——这就是 Windows 版的 inode。
- **簇（cluster）**：NTFS 按 4KB 簇分配，1 字节的文件也占 1 簇。所以有"逻辑大小 vs 占用大小"之差。
- **日志（$LogFile）**：元数据变更先记日志再落盘，断电可恢复——NTFS 崩溃一致性的来源（数据内容本身不保证，重要数据要自己 FlushFileBuffers）。
- **Reparse Point（重解析点）**：符号链接（`CreateSymbolicLinkW`）、目录联接（junction）、OneDrive 按需下载、WSL 的 Linux 文件系统挂载，全是它。遍历目录时对 reparse point 递归要防环。
- **ADS（Alternate Data Streams）**：一个文件可挂多个数据流：

  ```text
  report.txt          主流（平时读写的就是它）
  report.txt:zone     备用流：浏览器下载的文件都带这个，记录"来自互联网"
  ```

  用 `file:stream` 路径就能读写流。安全软件必查 ADS（恶意载荷的经典藏身处）；`CreateFileW` 原生支持，无需特殊 API。
- **ReFS**：服务器/数据中心的下一代文件系统（校验和、块克隆），Win10/11 专业工作站版可用。API 层完全透明——这正是 Win32 文件 API 设计的成功之处。

## 10.7 文件监视：`ReadDirectoryChangesW`

监控目录变化（文件被新建/修改/删除）不需要轮询：

```cpp
HANDLE hDir = CreateFileW(L"C:\\watched",
    FILE_LIST_DIRECTORY,
    FILE_SHARE_READ | FILE_SHARE_WRITE | FILE_SHARE_DELETE,  // ★ 别锁死目录
    nullptr, OPEN_EXISTING,
    FILE_FLAG_BACKUP_SEMANTICS | FILE_FLAG_OVERLAPPED,       // 打开目录的固定姿势
    nullptr);

char buffer[64 * 1024];
DWORD bytes = 0;
ReadDirectoryChangesW(hDir, buffer, sizeof(buffer), TRUE,     // TRUE=含子目录
    FILE_NOTIFY_CHANGE_FILE_NAME | FILE_NOTIFY_CHANGE_LAST_WRITE |
    FILE_NOTIFY_CHANGE_DIR_NAME,
    &bytes, nullptr, nullptr);

FILE_NOTIFY_INFORMATION* info = (FILE_NOTIFY_INFORMATION*)buffer;
// info->Action: FILE_ACTION_ADDED / REMOVED / MODIFIED / RENAMED_OLD_NAME ...
// info->FileName（不含路径，且可能含多个事件连成链，要遍历 NextEntryOffset）
```

VS Code、Everything 类工具的实时刷新就是这么来的。异步/线程化用法见第 8 章的线程模型。

## 10.8 易错清单

| 错误 | 后果/修正 |
|------|----------|
| 判空 `if (!h)` 判文件句柄 | 失败值是 `INVALID_HANDLE_VALUE`（-1），判空漏报 |
| 共享模式给 0 打开日志 | 双开程序立刻 `ERROR_SHARING_VIOLATION` |
| `ReadFile` 不循环不查 got | 网络盘/大文件读不全 |
| 大小只用 `nFileSizeLow` | >4GB 文件大小错误；拼 `High/Low` 或用 `GetFileSizeEx` |
| `FindFirstFile` 结果没跳 `.`/`..` | 递归遍历死循环 |
| 路径拼接用字符串 `+` 忘分隔符 | `C:\tempfile.txt`；用 `PathCchCombine`（`pathcch.h`） |
| 忽略 `MAX_PATH` | 长路径失败；`\\?\` 前缀或启用长路径 |
| 删除/改名前没 CloseHandle | `ERROR_SHARING_VIOLATION`：Windows 上文件开着不能删 |
