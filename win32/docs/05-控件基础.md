# 第 5 章 控件基础：按钮、编辑框、列表框与事件

> 本章回答的问题：按钮、输入框这些控件是什么？事件（点击、选中、输入）怎么传回我的代码？`WM_COMMAND` 的 `wParam` 到底怎么拆？控件 ID 为什么要唯一？

本章示例：`examples/03_controls/main.cpp`。

## 4.1 核心认知：控件就是窗口

Win32 里"控件"（button、edit box、list box……）不是特殊机制，**它们就是窗口**——系统预先注册好了一批带默认行为和默认外观的窗口类：

| 窗口类名 | 控件 | 用途 |
|----------|------|------|
| `"BUTTON"` | 按钮 / 复选框 / 单选框（样式区分） | 触发动作、选择 |
| `"EDIT"` | 输入框（单行/多行） | 文本输入与编辑 |
| `"STATIC"` | 静态文本 / 图片 | 显示信息，一般不交互 |
| `"LISTBOX"` | 列表框 | 从一组候选项中选择 |
| `"COMBOBOX"` | 组合框（下拉+可选输入） | 输入兼选择 |
| `"SCROLLBAR"` | 滚动条 | 调节数值/位置 |

所以创建控件就是调用你已经会的 `CreateWindowExW`，只是三个参数换了含义：

```cpp
HWND hBtn = CreateWindowExW(
    0,               // 扩展样式
    L"BUTTON",       // "类名" → 用系统预注册的控件类
    L"确认",          // "窗口标题" → 控件的显示文本
    WS_CHILD | WS_VISIBLE | BS_PUSHBUTTON,  // ★ WS_CHILD：这是子窗口！
    240, 20,         // 相对【父窗口客户区】的位置（不是屏幕）
    80, 30,          // 宽高
    hwnd,            // ★ 父窗口：控件长在这个窗口里面
    (HMENU)(UINT_PTR)1001,  // ★ 控件 ID：唯一的身份编号（下面细讲）
    hInstance,
    nullptr);
```

三个星号就是控件与普通窗口的全部区别：**是 `WS_CHILD` 子窗口、有父窗口、有 ID**。既然控件是窗口，那么第 4 章的一切对它都成立：控件有 `HWND`、控件收消息、控件也能被 `SendMessage` 操纵——**"对控件说话"的基本方式就是发消息**：

```cpp
// 读输入框内容：发 WM_GETTEXT，等它把文本抄进 buffer（SendMessage 同步等结果）
wchar_t buffer[256] = {};
SendMessageW(hEdit, WM_GETTEXT, 255, (LPARAM)buffer);

// 给列表框加一项
SendMessageW(hList, LB_ADDSTRING, 0, (LPARAM)L"C++");
```

每种控件类都定义了自己的一批消息（`LB_*`、`CB_*`、`EM_*`、`BM_*`），这就是控件的"API"。

## 4.2 控件 ID：事件的路由地址

`(HMENU)1001` 那个参数对子窗口而言不是菜单，是 **控件 ID**。为什么需要它？因为事件发生时，父窗口收到的只是一个数字，系统靠这个数字告诉父窗口"是哪个控件在说话"。

工程纪律：

- **同一父窗口下 ID 必须唯一**，否则事件路由会混淆；
- 用常量命名而不是裸数字：`constexpr int IDC_NAME = 1001;`
- 常见命名前缀：`IDC_`（控件）、`IDM_`（菜单命令）、`IDB_`（按钮）——菜单和控件最终走同一个通道（`WM_COMMAND`），ID 命名区分开是为了可读性；
- 转换写法 `(HMENU)(UINT_PTR)id` 是 64 位安全的正规写法（第 1 章讲过 64 位兼容，`HMENU` 是指针宽度，直接 `(HMENU)1001` 在 64 位下有警告）。

## 4.3 `WM_COMMAND`：控件事件的总入口

控件的"用户操作了"事件，统一以 `WM_COMMAND` 送到**父窗口**。按第 4 章的位布局：

```text
wParam:  ┌──────────────────┬──────────────────┐
         │ 高 16 位: 通知码    │ 低 16 位: 控件 ID  │
         └──────────────────┴──────────────────┘
lParam:  事件来源控件的 HWND（菜单通知时为 nullptr）
```

标准处理模板：

```cpp
case WM_COMMAND: {
    int id   = LOWORD(wParam);              // 谁在说话
    int code = HIWORD(wParam);              // 说了什么（通知码）
    HWND from = (HWND)lParam;               // 说话的控件

    if (id == IDC_OK && code == BN_CLICKED) {        // "确认"按钮被单击
        wchar_t name[128] = {};
        SendMessageW(GetDlgItem(hwnd, IDC_NAME), WM_GETTEXT, 127, (LPARAM)name);
        MessageBoxW(hwnd, name, L"输入内容", MB_OK);
        return 0;
    }
    return 0;
}
```

两个必须记住的通知码细节：

1. **`BN_CLICKED` 恰好是 0**，所以 `HIWORD(wParam) == 0` 时就是单击——有的代码不判断通知码直接看 ID，对按钮碰巧能工作，但列表框的 `LBN_SELCHANGE` 等通知码非 0，**判通知码的习惯必须从一开始养成**；
2. **`EDIT` 控件的通知码是 `EN_CHANGE`**（内容变化）、`EN_SETFOCUS`（获得焦点）等，输入框回车确认常见写法：

```cpp
case WM_COMMAND:
    if (LOWORD(wParam) == IDC_NAME && HIWORD(wParam) == EN_CHANGE) {
        // 输入内容实时变化，例如启用/禁用"确定"按钮
        EnableWindow(GetDlgItem(hwnd, IDC_OK), /* 输入非空 */ TRUE);
    }
    return 0;
```

**`GetDlgItem(hwnd, ID)`**：按 ID 查找子控件句柄——因为我们通常在 `WM_CREATE` 里创建控件后不长期保存 `HWND`，用时现查。它等价于 `CreateWindowExW` 时记下返回值，两种风格都可以，小程序用 `GetDlgItem` 更省事。

## 4.4 常用控件速成

### `STATIC`：标签

```cpp
CreateWindowExW(0, L"STATIC", L"用户名：",
    WS_CHILD | WS_VISIBLE | SS_LEFT,
    20, 20, 80, 24, hwnd, nullptr, hInstance, nullptr);
```

纯展示，一般不给 ID。想让它响应点击（如超链接效果）要加 `SS_NOTIFY` 样式。

### `EDIT`：输入框

```cpp
CreateWindowExW(0, L"EDIT", L"",
    WS_CHILD | WS_VISIBLE | WS_BORDER | ES_AUTOHSCROLL,  // 内容超宽自动横向滚动
    110, 20, 180, 24, hwnd, (HMENU)(UINT_PTR)IDC_NAME, hInstance, nullptr);
```

常用样式组合：

| 样式 | 效果 |
|------|------|
| `ES_AUTOHSCROLL` | 单行输入超宽自动滚 |
| `ES_PASSWORD` | 密码框（显示 ●） |
| `ES_MULTILINE` + `WS_VSCROLL` | 多行编辑器 |
| `ES_NUMBER` | 只允许数字 |
| `ES_READONLY` | 只读 |

读写内容三种等价方式（任选其一，别混着记）：

```cpp
SendMessageW(hEdit, WM_GETTEXT, 255, (LPARAM)buf);   // 消息方式
GetWindowTextW(hEdit, buf, 255);                      // 封装函数（内部就是发消息）
SetWindowTextW(hEdit, L"新内容");                      // 写入同理
```

### `BUTTON`：按钮及其变种

`BUTTON` 类通过样式变成完全不同的控件：

```cpp
BS_PUSHBUTTON                          // 普通按钮
BS_AUTOCHECKBOX                        // 复选框：BST_CHECKED / BST_UNCHECKED
BS_AUTORADIOBUTTON                     // 单选框（同组互斥，需 WS_GROUP 分组）
```

复选框的读写：

```cpp
SendMessageW(hCheck, BM_SETCHECK, BST_CHECKED, 0);
LRESULT st = SendMessageW(hCheck, BM_GETCHECK, 0, 0);   // BST_CHECKED / BST_UNCHECKED / BST_INDETERMINATE
```

### `LISTBOX`：列表框

```cpp
HWND hList = CreateWindowExW(0, L"LISTBOX", L"",
    WS_CHILD | WS_VISIBLE | WS_BORDER | WS_VSCROLL
    | LBS_NOTIFY,                      // ★ 允许向父窗口发选择变化通知
    20, 70, 200, 140, hwnd, (HMENU)(UINT_PTR)IDC_LIST, hInstance, nullptr);

SendMessageW(hList, LB_ADDSTRING, 0, (LPARAM)L"Windows");
SendMessageW(hList, LB_SETCURSEL, 0, 0);          // 选中第 0 项
```

选择变化通知：

```cpp
case WM_COMMAND:
    if (LOWORD(wParam) == IDC_LIST && HIWORD(wParam) == LBN_SELCHANGE) {
        int idx = (int)SendMessageW(hList, LB_GETCURSEL, 0, 0);   // 当前选中项（-1 表示无）
        wchar_t text[64] = {};
        SendMessageW(hList, LB_GETTEXT, idx, (LPARAM)text);       // 拿到该项文本
        MessageBoxW(hwnd, text, L"已选中", MB_OK);
    }
    return 0;
```

### `COMBOBOX`：下拉框

```cpp
HWND hCombo = CreateWindowExW(0, L"COMBOBOX", L"",
    WS_CHILD | WS_VISIBLE | CBS_DROPDOWNLIST | CBS_HASSTRINGS,
    250, 70, 160, 200, hwnd, (HMENU)(UINT_PTR)IDC_TYPE, hInstance, nullptr);

SendMessageW(hCombo, CB_ADDSTRING, 0, (LPARAM)L"管理员");
SendMessageW(hCombo, CB_ADDSTRING, 0, (LPARAM)L"普通用户");
SendMessageW(hCombo, CB_SETCURSEL, 0, 0);
```

注意：**`COMBOBOX` 创建时给的高度是"下拉展开后"的总高度**，不是收起时那一行的高度，给小了下拉列表看不到。通知码 `CBN_SELCHANGE`，取当前项用 `CB_GETCURSEL` + `CB_GETLBTEXT`，与 LISTBOX 同构。

### `SCROLLBAR`：滚动条控件

```cpp
HWND hScroll = CreateWindowExW(0, L"SCROLLBAR", L"",
    WS_CHILD | WS_VISIBLE | SBS_HORZ,
    20, 250, 220, 20, hwnd, (HMENU)(UINT_PTR)IDC_SCROLL, hInstance, nullptr);

SetScrollRange(hScroll, SB_CTL, 0, 100, TRUE);
SetScrollPos(hScroll, SB_CTL, 50, TRUE);
```

它的通知不走 `WM_COMMAND` 而走 **`WM_HSCROLL` / `WM_VSCROLL`**，且 `lParam` 是控件句柄（`wParam` 是滚动动作码）：

```cpp
case WM_HSCROLL:
    if ((HWND)lParam == hScroll) {
        int pos = GetScrollPos(hScroll, SB_CTL);
        // pos ∈ [0, 100]，据此更新界面
    }
    return 0;
```

## 4.5 实战：配置面板

`examples/03_controls/main.cpp` 演示标签 + 输入框 + 按钮的经典三件套。下面补一个更完整的组合例（标签、输入框、下拉框、列表框、确认按钮），体会"ID 路由 + `SendMessage` 读写"的完整回路：

```cpp
constexpr int IDC_NAME = 1001;
constexpr int IDC_OK   = 1002;
constexpr int IDC_TYPE = 1003;
constexpr int IDC_LIST = 1004;

case WM_CREATE: {
    HINSTANCE hInst = ((LPCREATESTRUCTW)lParam)->hInstance;  // 创建控件的正确姿势：
                                                             // 从 lParam 里拿 hInstance
    CreateWindowExW(0, L"STATIC", L"用户名：", WS_CHILD | WS_VISIBLE | SS_LEFT,
                    20, 20, 80, 24, hwnd, nullptr, hInst, nullptr);
    CreateWindowExW(0, L"EDIT", L"", WS_CHILD | WS_VISIBLE | WS_BORDER | ES_AUTOHSCROLL,
                    110, 20, 180, 24, hwnd, (HMENU)(UINT_PTR)IDC_NAME, hInst, nullptr);
    CreateWindowExW(0, L"BUTTON", L"确认", WS_CHILD | WS_VISIBLE | BS_PUSHBUTTON,
                    310, 20, 80, 26, hwnd, (HMENU)(UINT_PTR)IDC_OK, hInst, nullptr);
    CreateWindowExW(0, L"COMBOBOX", L"", WS_CHILD | WS_VISIBLE | CBS_DROPDOWNLIST,
                    20, 70, 180, 120, hwnd, (HMENU)(UINT_PTR)IDC_TYPE, hInst, nullptr);
    CreateWindowExW(0, L"LISTBOX", L"", WS_CHILD | WS_VISIBLE | WS_VSCROLL | LBS_NOTIFY,
                    20, 120, 260, 150, hwnd, (HMENU)(UINT_PTR)IDC_LIST, hInst, nullptr);

    HWND type = GetDlgItem(hwnd, IDC_TYPE);
    SendMessageW(type, CB_ADDSTRING, 0, (LPARAM)L"管理员");
    SendMessageW(type, CB_ADDSTRING, 0, (LPARAM)L"普通用户");
    SendMessageW(type, CB_SETCURSEL, 0, 0);
    return 0;
}
```

`WM_CREATE` 里 `hInstance` 从 `((LPCREATESTRUCTW)lParam)->hInstance` 取——因为此时你拿不到 `wWinMain` 的局部变量，而系统贴心地把它装在 `LPCREATESTRUCT` 里传给你。

## 4.6 窗口缩放时重新布局：`WM_SIZE`

控件位置是创建时写死的像素值，窗口一拉大就歪了。标准解法是在 `WM_SIZE` 里重新摆位置：

```cpp
case WM_SIZE: {                       // lParam 低/高 16 位 = 新客户区宽/高（见第 4 章）
    int w = LOWORD(lParam), h = HIWORD(lParam);
    MoveWindow(GetDlgItem(hwnd, IDC_LIST), 20, 70, w - 40, h - 100, TRUE);
    return 0;
}
```

`MoveWindow(hwnd, x, y, w, h, bRepaint)` 一次改位置和大小。真正简单的程序甚至可以整窗只放一个控件、让它铺满客户区——`examples/06_text_editor` 的编辑框就是这样。

## 4.7 控件编程的四条工程纪律

1. **ID 唯一并命名**：`constexpr` 常量 + 前缀，杜绝魔法数字；
2. **父窗口是事件中心**：控件自己不含业务逻辑，一切事件汇到父窗口的 `WM_COMMAND` 统一分发——这保证"哪个按钮触发什么"在一处可查；
3. **控件是窗口，消息是接口**：读状态、改状态、增删项，第一反应都应该是"给它发什么消息"，查文档关键词就是控件类名（LISTBOX → `LB_` 消息）；
4. **界面代码收进函数**：`WM_CREATE` 里超过几十行就该拆 `CreateControls(HWND)`、`LayoutControls(HWND)` 这类函数，别让 `WndProc` 膨胀成千行巨物。
