# 第 8 章 输入与调节控件

> **本章回答的问题**：滑块、微调箭头、热键输入框、IP 地址框这些"小控件"各自的消息族是什么？为什么轨迹条的通知不走 `WM_NOTIFY`？增减数的 buddy 是什么？下拉框想带图标怎么办？
>
> **前置章节**：第 6 章（comctl32 注册、`WM_NOTIFY`、mask 纪律）、第 7 章（控件家族三板斧）。
>
> **你将做出什么**：一个"设置页"式的控件陈列室（`examples/33_input_controls`）：轨迹条 + 微调编辑框 + 热键框 + IP 地址框 + 带图标的下拉框，五件输入控件一屏看全。

本章示例：`examples/33_input_controls/main.cpp`。

> 本章素材参考《Win32 开发人员参考库·第 4 卷：Windows 通用控件》（微软著，2000）第 7/10/16/17/26/27 章的控件清单与消息参考，消息名以现代 SDK 头文件为准。

## 8.1 一批"小而专"的输入控件

第 7 章的五件套解决"应用骨架"，本章的控件解决**数值、键位、地址这类专门输入**。它们个头小、消息少，学会"类名 + 三五条消息 + 一两个通知"就能用：

| 控件 | 类名常量 | ICC 家族 | 干什么 |
|------|---------|----------|--------|
| 轨迹条 | `TRACKBAR_CLASSW` | `ICC_BAR_CLASSES` | 拖动滑块选一个范围值（音量、进度调节） |
| 增减数 | `UPDOWN_CLASSW` | `ICC_UPDOWN_CLASS` | 一对箭头让数值 +1/−1，常与编辑框搭档 |
| 热键 | `HOTKEY_CLASSW` | `ICC_HOTKEY_CLASS` | 让用户按出一个组合键（如 Ctrl+Alt+K） |
| IP 地址 | `WC_IPADDRESSW` | `ICC_INTERNET_CLASSES` | 四段式 IP 输入框 |
| 扩展组合框 | `WC_COMBOBOXEXW` | `ICC_USEREX_CLASSES` | 带图标（可缩进）的下拉框 |

注册时可以按家族分开登记，也可以偷懒一次 `ICC_WIN95_CLASSES`（全家桶）。参考库第 7 章还强调一点：**多次调用 `InitCommonControlsEx` 的效果是累加的**——先注册 A 家族再注册 B 家族，两个都可用。

## 8.2 轨迹条：唯一走 WM_HSCROLL 的通用控件

轨迹条（trackbar，也译"轨迹条/滑杆"）的创建与消息都简单，但有一个**全家族唯一**的知识点（参考库第 6 章明确指出）：通用控件的通知几乎都走 `WM_NOTIFY`，**唯独轨迹条走 `WM_HSCROLL` / `WM_VSCROLL`**——和第 5 章的滚动条控件一个通道，`lParam` 是控件句柄：

```cpp
HWND track = CreateWindowExW(0, TRACKBAR_CLASSW, nullptr,
    WS_CHILD | WS_VISIBLE | TBS_HORZ | TBS_AUTOTICKS,
    20, 20, 260, 40, hwnd, (HMENU)(INT_PTR)IDC_TRACK, hInst, nullptr);

SendMessageW(track, TBM_SETRANGE, TRUE, MAKELONG(0, 100));   // 范围 0~100，TRUE=重画
SendMessageW(track, TBM_SETPOS,   TRUE, 30);                 // 初始位置

// 通知：不是 WM_NOTIFY！
case WM_HSCROLL:
    if ((HWND)lParam == g_track) {
        int pos = (int)SendMessageW(g_track, TBM_GETPOS, 0, 0);
        swprintf_s(buf, 64, L"音量：%d", pos);
        SetWindowTextW(g_label, buf);
    }
    return 0;
```

`wParam` 的低 16 位是动作码（`TB_LINEUP`/`TB_LINEDOWN`/`TB_PAGEUP`/`TB_PAGEDOWN`/`TB_THUMBTRACK`/`TB_THUMBPOSITION`），高 16 位是拖动时的位置——但既然能 `TBM_GETPOS` 随时问，初学直接问最省心。样式速查：`TBS_AUTOTICKS`（自动刻度）、`TBS_ENABLESELRANGE`（可拖选区间）、`TBS_VERT`（竖放）；消息族 `TBM_*`：`SETRANGE(32)`/`SETPOS`/`GETPOS`/`SETTICFREQ`（刻度密度）。

## 8.3 增减数：buddy 搭档机制

增减数控件（up-down，"微调按钮"）单独出现没意义——它总是黏在某个控件旁边，为那个控件提供 +1/−1。被黏的控件叫 **buddy（伙伴窗口）**：

```cpp
HWND edit = CreateWindowExW(WS_EX_CLIENTEDGE, L"EDIT", L"25",
    WS_CHILD | WS_VISIBLE | ES_NUMBER, 20, 80, 70, 24, hwnd,
    (HMENU)(INT_PTR)IDC_AGE, hInst, nullptr);

HWND ud = CreateWindowExW(0, UPDOWN_CLASSW, nullptr,
    WS_CHILD | WS_VISIBLE
    | UDS_SETBUDDYINT      // ★ 自动把当前位置写进 buddy 的文本
    | UDS_ALIGNRIGHT       // 自动贴到 buddy 右缘
    | UDS_ARROWKEYS        // ↑↓ 键也能调
    | UDS_WRAP,            // 到头回绕
    0, 0, 0, 0, hwnd, (HMENU)(INT_PTR)IDC_AGE_UD, hInst, nullptr);

SendMessageW(ud, UDM_SETBUDDY, (WPARAM)edit, 0);     // 结拜
SendMessageW(ud, UDM_SETRANGE32, 0, 120);            // 32 位范围（UDM_SETRANGE 只有 16 位）
SendMessageW(ud, UDM_SETPOS32, 0, 25);
```

`UDS_SETBUDDYINT | UDS_ALIGNRIGHT` 组合后，位置变化自动同步成 buddy 文本，**你不需要手工搬运字符串**——这是 buddy 机制的核心便利。要拦截/修改每一步增量，处理 `UDN_DELTAPOS` 通知（这次倒是走 `WM_NOTIFY`，`NMUPDOWN*` 里有当前值与增量）：

```cpp
if (nm->code == UDN_DELTAPOS) {
    NMUPDOWN* nmud = (NMUPDOWN*)lParam;
    // 例如：限制只能调到 100
    if (nmud->iPos + nmud->iDelta > 100) return 1;   // 返回非零 = 取消这次调整
}
```

buddy 不一定是 EDIT——静态文本、甚至列表框都能当伙伴，只要你想让它"按箭头换内容"。

## 8.4 热键控件：捕获"用户按了什么组合"

热键控件是个小输入框，用户点进去按任意组合键，它负责显示（如 "Ctrl+Alt+K"）并交给你键码。两条核心消息：

```cpp
HWND hk = CreateWindowExW(0, HOTKEY_CLASSW, nullptr,
    WS_CHILD | WS_VISIBLE, 20, 130, 140, 24, hwnd,
    (HMENU)(INT_PTR)IDC_HOTKEY, hInst, nullptr);

DWORD hkVal = (DWORD)SendMessageW(hk, HKM_GETHOTKEY, 0, 0);
WORD  vk    = LOBYTE(hkVal);        // 虚拟键码
WORD  mods  = HIBYTE(hkVal);        // 修饰键位组合 HOTKEYF_*
```

`HIBYTE` 里是 `HOTKEYF_SHIFT`/`HOTKEYF_CONTROL`/`HOTKEYF_ALT` 的位组合；反过来 `HKM_SETHOTKEY` 可预设。配套的全局函数是 `RegisterHotKey`（第 31 章托盘程序会用系统级热键，届时回来取这个值）；只想在本窗口内响应则发 `WM_SETHOTKEY`。注意用户可能只按一个单键（vk 有效、mods 为 0）——存储配置时两个字段都要存。

## 8.5 IP 地址控件：四个字段的编辑框

`WC_IPADDRESSW` 长得像编辑框，但内部是四个独立的字段（各有光标、各受 0~255 约束）。参考库第 17 章特意提醒：**"IP 地址控件不是编辑控件"**——不要往它身上套 `WM_GETTEXT`/`EM_*` 那套，它有自己的消息族 `IPM_*`：

```cpp
HWND ip = CreateWindowExW(WS_EX_CLIENTEDGE, WC_IPADDRESSW, nullptr,
    WS_CHILD | WS_VISIBLE, 20, 170, 150, 24, hwnd,
    (HMENU)(INT_PTR)IDC_IP, hInst, nullptr);

SendMessageW(ip, IPM_SETADDRESS, 0, MAKEIPADDRESS(192, 168, 1, 1));   // 打包四段

DWORD addr;  int n = (int)SendMessageW(ip, IPM_GETADDRESS, 0, (LPARAM)&addr);
if (n == 4) {   // 返回填好的字段数：没填完就不是 4
    swprintf_s(buf, 64, L"%u.%u.%u.%u",
               FIRST_IPADDRESS(addr), SECOND_IPADDRESS(addr),
               THIRD_IPADDRESS(addr), FOURTH_IPADDRESS(addr));
}
SendMessageW(ip, IPM_CLEARADDRESS, 0, 0);                             // 清空
```

`IPM_ISBLANK` 判空；通知只有 `IPN_FIELDCHANGED`（走 `WM_NOTIFY`），字段切换/编辑时触发。四段的拆装宏（`MAKEIPADDRESS`/`FIRST_IPADDRESS`…）比手写移位可读，直接用。

## 8.6 扩展组合框：给下拉项加图标

第 5 章的 COMBOBOX 只能显示纯文本。`WC_COMBOBOXEXW`（ComboBoxEx，"扩展组合框"）内建图像列表支持，项还能缩进（做层级下拉时不用自己画空格）：

```cpp
HWND cbex = CreateWindowExW(0, WC_COMBOBOXEXW, nullptr,
    WS_CHILD | WS_VISIBLE | CBS_DROPDOWNLIST, 20, 210, 200, 200, hwnd,
    (HMENU)(INT_PTR)IDC_CBX, hInst, nullptr);

HIMAGELIST imgs = ImageList_Create(16, 16, ILC_COLOR32, 0, 4);
ImageList_AddIcon(imgs, LoadIconW(nullptr, IDI_APPLICATION));
ImageList_AddIcon(imgs, LoadIconW(nullptr, IDI_INFORMATION));
SendMessageW(cbex, CBEM_SETIMAGELIST, 0, (LPARAM)imgs);   // 挂给控件

COMBOBOXEXITEMW ci = { .mask = CBEIF_TEXT | CBEIF_IMAGE | CBEIF_INDENT };
ci.iItem = -1;                                          // -1 = 追加到末尾
ci.pszText = (LPWSTR)L"项目 A";
ci.iImage = 0;
ci.iIndent = 0;
SendMessageW(cbex, CBEM_INSERTITEMW, 0, (LPARAM)&ci);    // 注意：CBEM_，不是 CB_
```

三个要点（参考库第 10 章的归纳）：

1. **插入用 `CBEM_INSERTITEMW` + `COMBOBOXEXITEMW`**（又是 mask 纪律——第 6 章的老朋友），但**查询选中项仍用 `CB_GETCURSEL`**：它兼容普通组合框的大部分 `CB_*` 消息，选中的**文本**要用 `CBEM_GETITEMW` 取回（`CB_GETLBTEXT` 拿不到）；
2. 图标索引指向控件自己的图像列表（`CBEM_SETIMAGELIST` 挂的那个），销毁责任仍在创建者；
3. 通知族是 `CBEN_*`（如编辑框形态下的 `CBEN_BEGINEDIT`），外加转发自组合框的 `CBN_*`。

普通下拉加图标 → ComboBoxEx；要"每项挂任意数据/多列" → 第 6 章的 ListView 报表视图才是正解。

## 8.7 完整示例解剖

`examples/33_input_controls/main.cpp` 的四段结构：

1. `WM_CREATE`：注册 `ICC_BAR_CLASSES | ICC_UPDOWN_CLASS | ICC_HOTKEY_CLASS | ICC_INTERNET_CLASSES | ICC_USEREX_CLASSES`，一次建齐五件（轨迹条、编辑框+增减数、热键、IP、ComboBoxEx）；
2. `WM_HSCROLL`：轨迹条唯一的通知通道，实时刷新标签；
3. `WM_NOTIFY`：收 `UDN_DELTAPOS`（演示拦截超界增量）与 `IPN_FIELDCHANGED`（状态栏提示第几段）；
4. `WM_COMMAND`："汇报"按钮把五件控件的当前值拼成一段文本弹出——热键拆 vk/mods、IP 拆四段，都是本章的消息活。

## 8.8 易错清单

| 症状 | 原因 | 解法 |
|------|------|------|
| 拖轨迹条没反应 | 等 `WM_NOTIFY`——轨迹条走 `WM_HSCROLL/VSCROLL` | 8.2（全家族唯一例外） |
| 轨迹条范围设了没刻度 | 没加 `TBS_AUTOTICKS`，或忘了 `TBM_SETRANGE` 的重画参数 | 8.2 |
| 增减数与编辑框各过各的 | 没发 `UDM_SETBUDDY`（或创建时没用 `UDS_SETBUDDYINT`） | 8.3（先结拜再干活） |
| 增减数范围只能到 3 万多 | 用了 16 位的 `UDM_SETRANGE` | `UDM_SETRANGE32`/`UDM_SETPOS32` |
| 热键只按单键时解析错 | 只取了 vk 没取修饰键字节 | `LOBYTE`+`HIBYTE` 都要（8.4） |
| 对 IP 控件发 `WM_GETTEXT` 得到空 | 它不是编辑框，没有那条消息路 | `IPM_GETADDRESS` 四段宏（8.5） |
| IP 判空用 `IPM_ISBLANK` 之外的姿势 | `IPM_GETADDRESS` 返回值是字段数 | 返回 4 才算填完（8.5） |
| ComboBoxEx 取文本用 `CB_GETLBTEXT` | 该消息在扩展组合框上不工作 | `CBEM_GETITEMW` + `CBEIF_TEXT`（8.6） |
| ComboBoxEx 没图标 | 图像列表没挂或 mask 漏 `CBEIF_IMAGE` | 8.6（mask 纪律） |

## 8.9 小结

1. 五件小控件的共同套路：`InitCommonControlsEx` 注册家族 → 类名建窗 → 消息族驱动（`TBM_`/`UDM_`/`HKM_`/`IPM_`/`CBEM_`）。
2. **轨迹条是唯一走 `WM_HSCROLL/VSCROLL` 的通用控件**——写 `WM_NOTIFY` 处理器等不到它。
3. 增减数的价值在 buddy 机制：`UDS_SETBUDDYINT` 让位置与文本自动同步，`UDN_DELTAPOS` 可拦截增量。
4. IP 地址控件与 ComboBoxEx 都"长得像、但不是"基础控件：前者不是编辑框（`IPM_*` 专属），后者半兼容组合框（插入用 `CBEM_`、取选中文本也要 `CBEM_`）。
5. 热键控件存的是 vk+修饰键两个字节——配置持久化时两个字段都存。

## 8.10 动手练习

1. 给轨迹条加"刻度每 10 一格"（`TBM_SETTICFREQ`），并改成竖直样式（`TBS_VERT`），通知消息相应换成 `WM_VSCROLL`。
2. 把增减数改成 buddy 为静态文本的"循环选择器"（星期一~星期日）：拦截 `UDN_DELTAPOS`，用 `iPos` 取模数组下标——体会 buddy 不限于编辑框。
3. 挑战：用 `RegisterHotKey` 把热键控件捕获的组合注册成全局热键，按下去弹出消息框（注意 `HKM_GETHOTKEY` 的修饰位与 `RegisterHotKey` 的 `MOD_*` 常量不是一套，需要映射）。
