# 第 7 章 更多通用控件

> **本章回答的问题**：工具栏的系统图标从哪来？状态栏怎么分栏、为什么窗口缩放它自己会跟？进度条谁驱动？Tab 页切换的本质是什么？RichEdit 为什么要先 `LoadLibrary`？
>
> **前置章节**：第 6 章（comctl32 注册、`WM_NOTIFY`、mask 纪律——本章直接沿用）。
>
> **你将做出什么**：一个"现代窗口骨架"（`examples/18_common_controls`）：工具栏 + 三栏状态栏 + 定时器驱动的进度条 + Tab 双页 + RichEdit 编辑区，五件套齐活。

本章示例：`examples/18_common_controls/main.cpp`。

## 7.1 五件套全家福

| 控件 | 类名常量 | 一句话定位 |
|------|---------|-----------|
| 工具栏 | `TOOLBARCLASSNAMEW` | 命令的图形入口（与菜单共用 ID） |
| 状态栏 | `STATUSCLASSNAMEW` | 窗口底部的信息条 |
| 进度条 | `PROGRESS_CLASSW` | "进行到哪了"的可视化 |
| Tab | `WC_TABCONTROL` | 同屏多页的切换器 |
| RichEdit | `L"RICHEDIT50W"` | 专业文本编辑（EDIT 的成年形态） |

共同点：全部住在 comctl32（RichEdit 例外，见 7.6），全走第 6 章的注册/创建/`WM_NOTIFY` 套路。下面逐个过。

> 这只是"外围骨架"五件。家族其余成员按主题分三章：**输入与调节**（轨迹条、增减数、热键、IP 地址、扩展组合框——第 8 章）、**日期时间与反馈**（日期检出器、月历、动画、工具提示——第 9 章）、**容器**（Rebar、Pager、属性页——第 10 章）。完整类名总表见 6.9 节。

## 7.2 工具栏：标准图库起步

工具栏按钮要图标，但新手没有美术资源——系统有一套**标准图标集**，一句消息装载：

```cpp
HWND tb = CreateWindowExW(0, TOOLBARCLASSNAMEW, nullptr,
    WS_CHILD | WS_VISIBLE | TBSTYLE_TOOLTIPS,     // TOOLTIPS：悬停显示提示
    0, 0, 0, 0, hwnd, (HMENU)(INT_PTR)IDC_TOOL, hInst, nullptr);

SendMessageW(tb, TB_BUTTONSTRUCTSIZE, sizeof(TBBUTTON), 0);  // 版本协商，必写
// HINST_COMMCTRL + IDB_STD_SMALL_COLOR：comctl32 自带的标准小图标集
SendMessageW(tb, TB_LOADIMAGES, IDB_STD_SMALL_COLOR, (LPARAM)HINST_COMMCTRL);

TBBUTTON btns[] = {
    { STD_FILEOPEN, IDM_OPEN,  TBSTATE_ENABLED, BTNS_BUTTON, {}, 0, (INT_PTR)L"打开" },
    { STD_FILESAVE, IDM_SAVE,  TBSTATE_ENABLED, BTNS_BUTTON, {}, 0, (INT_PTR)L"保存" },
    { 0, 0, TBSTATE_ENABLED, BTNS_SEP, {}, 0, 0 },           // 分隔线：前两字段为 0
    { STD_PRINT,    IDM_PRINT, TBSTATE_ENABLED, BTNS_BUTTON, {}, 0, (INT_PTR)L"打印" },
};
SendMessageW(tb, TB_ADDBUTTONSW, 4, (LPARAM)btns);
SendMessageW(tb, TB_AUTOSIZE, 0, 0);
```

`TBBUTTON` 七个字段里初学最关心的三个：

| 字段 | 含义 |
|------|------|
| `iBitmap` | 图标索引——装的是标准图库时直接填 `STD_FILEOPEN` 这类**标准图标编号**（它们恰好从 0 连续排） |
| `idCommand` | **命令 ID**：点击后照常发 `WM_COMMAND`，和菜单走同一条分发线（第 13 章的"统一命令路由"） |
| `iString` | 提示文本：直接给字符串字面量地址（配合 `TBSTYLE_TOOLTIPS` 出气泡） |

`HINST_COMMCTRL` 是个魔法值（`(HINSTANCE)-1`），含义是"图像列表在 comctl32 自己的资源里"。两个必写细节：`TB_BUTTONSTRUCTSIZE`（告诉 DLL 你这边的结构体多大，版本协商）和 `TB_AUTOSIZE`（按内容自算尺寸）。

## 7.3 状态栏：分栏与"自动跟版"

创建后先分栏（`SB_SETPARTS`，单位像素，`-1` 表示"到窗口右边缘"）：

```cpp
HWND sb = CreateWindowExW(0, STATUSCLASSNAMEW, nullptr,
    WS_CHILD | WS_VISIBLE | SBARS_SIZEGRIP, ...);

int parts[] = { 220, 420, -1 };
SendMessageW(sb, SB_SETPARTS, 3, (LPARAM)parts);
SendMessageW(sb, SB_SETTEXTW, 0, (LPARAM)L"就绪");      // 写第 0 栏
SendMessageW(sb, SB_SETTEXTW, 2, (LPARAM)L"共 5 个控件");
```

一个反直觉但重要的机制：**状态栏收到 `WM_SIZE` 会自己重排贴底**——但父窗口收到 `WM_SIZE` 时不会自动转发给它。所以父窗口的 `WM_SIZE` 处理里要补一句：

```cpp
case WM_SIZE:
    Layout(hwnd);                                  // 摆其他控件
    SendMessageW(g_status, WM_SIZE, 0, 0);         // ★ 转发给状态栏
    return 0;
```

忘转发的症状：窗口拉宽，状态栏的右边缘和拖拽把手停在原地，露出一截底色——"布局乱了"的常见元凶之一。

## 7.4 进度条：定时器驱动

进度条自己是死的，要有谁不断更新位置。GUI 里最轻的驱动源是第 4 章的 `WM_TIMER`：

```cpp
// 创建
SendMessageW(g_prog, PBM_SETRANGE32, 0, 100);
SetTimer(hwnd, TIMER_PROGRESS, 100, nullptr);      // 每 100ms 一拍

// WM_TIMER 里推一格
case WM_TIMER:
    if (wParam == TIMER_PROGRESS) {
        int pos = (int)SendMessageW(g_prog, PBM_GETPOS, 0, 0) + 1;
        if (pos > 100) pos = 0;
        SendMessageW(g_prog, PBM_SETPOS, pos, 0);
    }
    return 0;
```

消息家族就三条：`PBM_SETRANGE32`（范围）、`PBM_SETPOS/GETPOS`（位置）、外加 `PBM_SETSTEP` + `PBM_STEPIT`（步进式）。真实验场景里"推进度条的人"是工作线程——第 17 章的 `PostMessage` 回传模式，届时进度条是标准受益控件。

## 7.5 Tab：切换的本质是"显隐一组窗口"

Tab 控件本体只是"那排标签头"，**内容区要自己造**：给每个页建一组子窗口，切换时换可见性：

```cpp
// 建两个页（挂在 tab 里，初始只显示第一页）
g_page1 = CreateWindowExW(0, L"STATIC", L"第一页", WS_CHILD | WS_VISIBLE, ...);
g_page2 = CreateWindowExW(0, L"EDIT",   L"第二页", WS_CHILD, ...);        // 先藏

// 切换通知
case WM_NOTIFY:
    if (nm->idFrom == IDC_TAB && nm->code == TCN_SELCHANGE) {
        int cur = (int)SendMessageW(g_tab, TCM_GETCURSEL, 0, 0);
        ShowWindow(g_page1, cur == 0 ? SW_SHOW : SW_HIDE);
        ShowWindow(g_page2, cur == 1 ? SW_SHOW : SW_HIDE);
    }
```

配套细节：`TCM_ADJUSTRECT`（FALSE 方向）能把 tab 的客户区换算成"扣掉标签头之后的内容矩形"，页面控件按它摆位就不会钻到标签底下去。"显隐切换"这个模式不止 Tab 用——单窗口向导、可折叠面板全是它。

## 7.6 RichEdit：为什么要先 LoadLibrary

RichEdit 是本章唯一的例外：**它不在 comctl32，也不在 user32**，而是独立的 DLL（历史原因：微软把它当"可替换组件"发布，应用自己选版本）：

| 版本 | DLL | 窗口类名 | 能力 |
|------|-----|---------|------|
| 1.0 | riched32.dll | `"RichEdit"` | 基础多行 |
| 2.0/3.0 | riched20.dll | `"RichEdit20W"` | Unicode、撤销增强 |
| 4.1 | msftedit.dll | `"RICHEDIT50W"` | 现代版，**新代码用它** |

DLL 不随进程自动加载，所以**创建控件之前必须 `LoadLibraryW`**，否则类名未注册，`CreateWindowExW` 直接失败：

```cpp
HMODULE riched = LoadLibraryW(L"msftedit.dll");      // RichEdit 4.1
if (riched) {
    HWND re = CreateWindowExW(WS_EX_CLIENTEDGE, L"RICHEDIT50W",
        L"初始文本", WS_CHILD | WS_VISIBLE | ES_MULTILINE | WS_VSCROLL, ...);
}
```

装载后的用法与 EDIT 一脉相承：`GetWindowTextW/SetWindowTextW` 读写全文照用；`WM_SETTEXT`、`EN_CHANGE` 通知也都在。升级后新增的能力以 `EM_*` 消息暴露，最常用的默认字体：

```cpp
CHARFORMAT2W cf = { sizeof(cf) };
cf.dwMask = CFM_FACE | CFM_SIZE;
cf.yHeight = 320;                              // ★ 字号单位 twips：1pt = 20，320 = 16pt
lstrcpynW(cf.szFaceName, L"微软雅黑", LF_FACESIZE);
SendMessageW(re, EM_SETCHARFORMAT, SCF_ALL, (LPARAM)&cf);
```

EDIT 与 RichEdit 的取舍：只读展示、单行输入 → EDIT 足够（还免加载）；要富文本/大文本/查找替换/自动 URL → RichEdit。第 14 章的编辑器案例会做一次"EDIT 升级 RichEdit"的现场对比。

## 7.7 可定制工具条：把排版权交给用户

静态工具栏有个老问题：屏幕宽度有限，你的按钮编排未必是用户想要的。comctl32 内置了整套**工具栏定制**机制（参考库第 6.1 节的专题）——IE 时代每条工具栏都有的"自定义工具栏"对话框，就是它。

打开方式：创建工具栏时加 **`CCS_ADJUSTABLE`** 样式，用户**双击工具栏**（或程序发 `TB_CUSTOMIZE` 消息）即弹出系统自带的定制对话框（左列"可用工具栏按钮"、右列"当前工具栏按钮"，拖动即增删）。

定制过程是一串 `TBN_*` 通知（走 `WM_NOTIFY`），你的程序在每个关口表态：

| 通知 | 时机 | 你的响应 |
|------|------|---------|
| `TBN_BEGINADJUST` / `TBN_ENDADJUST` | 对话框开关 | 初始化/收尾 |
| `TBN_INITCUSTOMIZE` | 对话框将显示 | 返回 `TBNRF_HIDEHELP` 可隐藏 Help 按钮 |
| `TBN_QUERYINSERT` / `TBN_QUERYDELETE` | 每个按钮能否插入/删除 | 返回 FALSE 拒绝（如锁定最左的"新建"） |
| `TBN_GETBUTTONINFO` | 对话框要"左列"的下一个候选按钮 | 填 `NMTOOLBAR` 返回 TRUE；给完返回 FALSE |
| `TBN_TOOLBARCHANGE` | 用户增/删/移动了按钮 | 使配置"变脏"，提示保存 |
| `TBN_RESET` | 用户点了"重置" | 恢复默认编排 |

第二种定制是**拖放**：按住 **Shift** 拖按钮即可移动、拖出工具栏即删除——工具栏自动处理，仍以 `TBN_QUERYDELETE`/`TBN_QUERYINSERT` 征求你的意见。没按 Shift 的拖动则只是 `TBN_BEGINDRAG`/`TBN_ENDDRAG` 两个通知，想支持"无 Shift 拖动"就得自己实现（第 32 章的拖放机制派上用场）。

**保存与恢复**：定制后用户重启程序还想保持原样——控件不替你记，要发 `TB_SAVERESTORE` 消息（lParam 为 TRUE 是保存、FALSE 是恢复），真正的存储介质由你接管：comctl32 5.80+ 会把每条数据通过 `TBN_SAVE`/`TBN_RESTORE` 通知交给你写进自己的文件/注册表（第 24 章的套路）。IE 的"锁定工具栏"功能，本质上就是拒绝一切 `TBN_QUERY*`。

## 7.8 完整示例解剖

`examples/18_common_controls/main.cpp` 五段对应五控件，骨架值得抄走：

- `WM_CREATE`：建齐五件套（工具栏 → 状态栏 → 进度条+定时器 → Tab+双页 → RichEdit）；
- `Layout(hwnd)`：工具栏高度 `GetWindowRect` 实测（别硬编码——不同 DPI 高度不同），状态栏转发 `WM_SIZE`，Tab/RichEdit 按剩余空间分栏；
- `WM_TIMER` 推进度条并同步状态栏第 1 栏文本；
- `WM_NOTIFY` 处理 `TCN_SELCHANGE` 切页；
- `WM_COMMAND` 收工具栏命令（ID 与第 13 章菜单共用一套）。

## 7.9 易错清单

| 症状 | 原因 | 解法 |
|------|------|------|
| RichEdit 创建不出来 | 忘 `LoadLibraryW(L"msftedit.dll")` | 7.6 |
| 工具栏按钮没反应 | `idCommand` 填了 0 或与菜单 ID 不一致 | 7.2（ID 即命令） |
| 工具栏布局异常/消息失败 | 忘 `TB_BUTTONSTRUCTSIZE` | 7.2 |
| 状态栏不贴底/露底色 | 父窗口没转发 `WM_SIZE` | 7.3 |
| Tab 点了没反应 | 只切了选中态，没显隐页面 | 7.5（显隐模式） |
| 页面控件钻到标签下面 | 直接用 tab 客户区摆位 | `TCM_ADJUSTRECT` 换算 |
| RichEdit 字号怪异 | `yHeight` 当"磅数"填 | twips：pt × 20 |
| 进度条到 99 就停/跳 | 边界条件 off-by-one | 范围与取模对齐（7.4） |
| 双击工具栏没反应 | 没加 `CCS_ADJUSTABLE` | 7.7 |
| 定制对话框"左列"是空的 | 没处理 `TBN_GETBUTTONINFO` | 7.7（逐条喂给控件） |
| 重启后工具栏编排丢失 | 定制结果没人保存 | `TB_SAVERESTORE` + `TBN_SAVE/RESTORE`（7.7） |

## 7.10 小结

1. 五件套同住 comctl32（RichEdit 除外）：注册、创建、`WM_NOTIFY` 三板斧不变。
2. 工具栏：标准图库零资源起步；按钮第二字段就是命令 ID，与菜单同一条 `WM_COMMAND` 通道；`CCS_ADJUSTABLE` + `TBN_*` 一串通知把定制权交给用户。
3. 状态栏：`SB_SETPARTS` 分栏；**父窗口 `WM_SIZE` 必须转发**它才自动贴底。
4. Tab 的本质是"标签头 + 显隐切换的内容窗口"，`TCM_ADJUSTRECT` 求内容区。
5. RichEdit = 独立 DLL，先 `LoadLibrary` 后创建；`CHARFORMAT2W` 字号单位是 twips。

## 7.11 动手练习

1. 给工具栏加第五个按钮"帮助"（`STD_HELP` 标准图标），点击后状态栏第 2 栏显示"帮助"。
2. 把进度条改成"不确定模式"（提示：`PBM_SETMARQUEE`，需要 `PBS_MARQUEE` 样式——查文档完成，体验"消息即 API"的工作方式）。
3. 给 Tab 加第三页，页内放一个 ListView（第 6 章）显示三条假数据——三个控件家族串起来。
4. 给工具栏开 `CCS_ADJUSTABLE`，在 `TBN_QUERYDELETE` 里拒绝删除"打开"按钮（锁定关键命令），并用 `TB_SAVERESTORE` + `TBN_SAVE` 把编排存进文件。
