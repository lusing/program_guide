# 第 12 章 字符编码与字符串

> **本章回答的问题**：中文为什么乱码？代码页是什么？`wchar_t` 和 `char` 到底差在哪？`MultiByteToWideChar` 的两段式怎么用？为什么教材都禁用 `strcpy`？
>
> **前置章节**：第 2 章（`L""` 与 `/utf-8` 的规则已见过，本章讲透原理）。
>
> **你将做出什么**：一个编码转换工具箱（`examples/20_encoding_convert`）：亲眼看同一段中文在 UTF-8 和 GBK 下的字节形态，完成互转、非法检测与安全复制。

本章示例：`examples/20_encoding_convert/main.cpp`。

## 12.1 三代编码史：一张图看懂乱码

字符要在计算机里存成数字，"字符 → 数字"的约定叫编码。Windows 编码史三代：

```text
第一代：ASCII（1963）          第二代：代码页（1980s）           第三代：Unicode（1991–）
┌──────────────────┐      ┌──────────────────────────┐   ┌────────────────────────┐
│ 1 字节，128 个字符   │      │ 1~2 字节，每页 ~几千字符      │   │ 给全世界每个字符一个编号     │
│ 'A'=65，没有中文    │ ──→ │ 第 936 页 = 简体中文 GBK      │ ─→│ UTF-16：Win32 原生（wchar_t）│
│                   │      │ 第 1252 页 = 西欧            │   │ UTF-8 ：变长 1~4 字节，互联网通用 │
└──────────────────┘      └──────────────────────────┘   └────────────────────────┘
                          同一串字节在不同页里是不同字 → 乱码
```

**乱码的完整解释**：一段字节序列本身没有含义，含义来自"用哪页来解读"。写文件的人用 936 页写"编码"（`B1 E0 C2 EB`），读文件的人按 UTF-8 解读——`B1` 不是合法 UTF-8 起始字节，于是显示 替换符。**乱码从来不是"字符坏了"，而是"读写的页没对上"**。

## 12.2 `wchar_t` 与 UTF-16：Win32 的原生形态

Win32 内部（`W` 系列 API）用的是 **UTF-16**：每个单元 2 字节（`wchar_t`），基本汉字一个单元装下：

```cpp
sizeof("编") == 2;      // char 版：GBK 下 2 字节
sizeof(L"编") == 4;     // wchar_t 版：字符 2 字节 + 结尾 L'\0' 2 字节
wcslen(L"编码") == 2;   // 按字符计
```

一个必须听过的事实：**代理对（surrogate pair）**。Unicode 超过 65536 的字符（Emoji、生僻字，U+10000 起）用**两个** `wchar_t` 表示。日常影响很小，但要知道：`wcslen` 会把 😀 数成 2；截断字符串时砍在代理对中间会产生烂字符。遍历显示字符可用 `CharNextW` 自动跨代理对。

`char` 没有死：文件 IO、网络协议、C 标准库大量使用——所以"两种世界"的翻译是 Windows 开发的日常，主角就是下面这对 API。

## 12.3 代码页：`char` 世界的"页号"

`char` 字符串的含义取决于**当前代码页**。查本机默认页：

```cpp
UINT cp = GetACP();     // 简体中文系统 = 936（GBK）
```

| 代码页 | 名字 | 哪里常见 |
|--------|------|---------|
| 936 | GBK | 中文 Windows 默认、老中文文件 |
| 65001 | UTF-8 | 现代 default；`chcp 65001` 后的控制台 |
| 437 / 850 | DOS 西文 | 老控制台程序 |
| 1252 | Windows 西欧 | 西文软件 |

`A` 系列 API（`MessageBoxA`）的参数就按当前代码页解读——**这就是第 2 章"别用 A 系列"的完整原因**：你的 `char` 串在 936 机器和 1252 机器上是不同的字。

## 12.4 两段式转换：`MultiByteToWideChar` / `WideCharToMultiByte`

两个方向的翻译，签名对称，用法都是**两段式**——先问需要多大，再真正转换：

```cpp
// char(UTF-8) → wchar_t
int need = MultiByteToWideChar(CP_UTF8, 0, src, -1, nullptr, 0);   // ① 问长度
std::wstring w(need, L'\0');
MultiByteToWideChar(CP_UTF8, 0, src, -1, w.data(), need);          // ② 真转

// wchar_t → char(UTF-8)
int bytes = WideCharToMultiByte(CP_UTF8, 0, w.c_str(), -1, nullptr, 0, nullptr, nullptr);
std::string s(bytes, '\0');
WideCharToMultiByte(CP_UTF8, 0, w.c_str(), -1, s.data(), bytes, nullptr, nullptr);
```

参数逐个讲（两函数对称）：

| 参数 | 含义 | 初学要点 |
|------|------|---------|
| 第 1 参 CodePage | 按哪页解读/输出 | `CP_UTF8` 或 `GetACP()` 页号；写死 936 只在明确处理老中文文件时 |
| 第 2 参 flags | 转换策略 | `MB_ERR_INVALID_CHARS`（坏序列**报错**而不是替换成 U+FFFD）——做数据校验必开 |
| 第 3/4 参 | 源串 + 长度 | `-1` = "以 NUL 结尾，长度含结尾 NUL"；显式长度 = 不看 NUL（处理二进制里的片段） |
| 第 5/6 参 | 目标缓冲 | 两段式：第一遍传 `nullptr, 0` 只问尺寸 |
| 第 7/8 参（W2M） | 默认字符 | 不可表示字符的替换；传 `nullptr` 接受系统默认 |

两段式的收益：不用估缓冲。为什么不能一次到位？因为**变长编码无法从字节数推出字符数**——必须先扫一遍。

易踩坑：两段之间**源串不能变**；第一遍返回 0 就是失败（`GetLastError()` 常见 `ERROR_INVALID_PARAMETER` 页号错 / `ERROR_NO_UNICODE_TRANSLATION` 坏序列）。

## 12.5 A 系列 API 内部：兼容壳的真相

`MessageBoxA` 收到 `char` 串后做的是什么？**调 `MultiByteToWideChar`（当前代码页）转成 UTF-16，再调 `MessageBoxW`**。所以：

- `W` 是本体，`A` 是壳——性能与正确性都该直接用 `W`；
- "通用名" `MessageBox` 是宏，随 `UNICODE` 定义展开成 A 或 W——这就是编译参数 `/DUNICODE` 的作用链：宏 → W 版本 → 原生路径。

## 12.6 控制台、文件与 BOM

三个实践场景：

1. **控制台**：`chcp` 查/设当前代码页，`65001` 即 UTF-8。控制台程序输出中文的两难：`wprintf` 依赖 locale（示例里 `_wsetlocale(LC_ALL, "")` 的作用），`printf` 依赖代码页——工程上常建议"程序内统一 UTF-8 + 启动时 `SetConsoleOutputCP(CP_UTF8)`"。
2. **文件编码探测**：文本文件开头的 **BOM**（字节顺序标记）能自报家门：`FF FE`=UTF-16LE、`EF BB BF`=UTF-8（带 BOM）、无 BOM=猜（先试 UTF-8 严格转换，失败按 ANSI/GBK）。第 11 章编辑器的"按 UTF-8 假设"就是最简单的探测策略。
3. **源码**：`/utf-8` 告诉编译器"源文件与执行字符集都按 UTF-8"——不加它，MSVC 按当前代码页读你的中文注释/字符串，换台机器就编译出乱码（第 2 章错误表的"error C2001"就是它）。

## 12.7 StrSafe：长度感知的字符串函数

`strcpy`/`sprintf` 家族不知道目标缓冲多大——历史上一半的安全漏洞源于此（缓冲区溢出）。Windows 提供 **StrSafe** 家族（`<strsafe.h>`）统一替换，命名规律 `StringCch` = "按字符数"（Cch = count of characters）：

| 老函数 | StrSafe 替代 | 行为 |
|--------|-------------|------|
| `strcpy` | `StringCchCopyW(dst, 8, src)` | 装不下→截断 + 返回 `STRSAFE_E_INSUFFICIENT_BUFFER`，**绝不越界** |
| `strcat` | `StringCchCatW` | 同上 |
| `sprintf` | `StringCchPrintfW` | 同上 |
| `strlen` | `StringCchLengthW(str, 8, &len)` | 顺带校验"串是否在容量内" |

```cpp
wchar_t dst[8];
HRESULT hr = StringCchCopyW(dst, 8, L"1234567890");
if (FAILED(hr)) {
    // 0x8007007A = STRSAFE_E_INSUFFICIENT_BUFFER；dst 已安全截断为 "1234567"
}
```

返回值是 `HRESULT`（第 3 章的判断宏直接用）。C 层的等价物是 `_TRUNCATE` 系（`wcsncpy_s`）；C++ 层直接 `std::wstring` 生命周期内零操心——StrSafe 主要用于必须用原始缓冲的接口边界（拷进结构体、拷进栈数组）。

## 12.8 完整示例解剖

`examples/20_encoding_convert` 五段对应本章五个知识点：

1. **UTF-8 输出**：`Win32 编码` → 12 字节 `57 69 6E 33 32 20 E7 BC 96 E7 A0 81`（ASCII 部分 1 字节/字符，中文 3 字节/字）；
2. **往返校验**：转回来 `wcscmp` 相等——任何编码管线都该有这道自检；
3. **GBK 对照**：同串在 936 页是 10 字节，中文 2 字节/字——"同字不同形"的直观证据；
4. **非法检测**：`MB_ERR_INVALID_CHARS` 下 `FF FE` 被拒（错误 1113），否则会被替换成 替换符悄悄混过；
5. **StrSafe**：10 字符塞 8 容量被拒并安全截断。

## 12.9 易错清单

| 症状 | 原因 | 解法 |
|------|------|------|
| `sizeof(buf)` 当字符数传给 W 系函数 | 字节 ≠ 字符，差一倍 | 容量用 `_countof(buf)`/`sizeof/sizeof(wchar_t)` |
| 转换目标缓冲按"字符数"传"字节数" | 两段式返回的是**字符**数（M2W） | M2W 按字符分配，W2M 按字节分配 |
| 两段式只做了第一段 | 尺寸查询 ≠ 转换 | 见 12.4 完整代码（第 11 章编辑器曾有此 bug） |
| UTF-16 下用 `str*` 函数 | 操作了窄字符函数 | 全换 `wcs*`/`lstr*W` |
| 截断字符串出现"半个字" | 砍在 UTF-8 多字节序列或代理对中间 | 按完整序列边界截（`CharNextW`） |
| 编译报 C2001/字符串常量怪错 | 源码编码与编译器假设不符 | 存 UTF-8 + `/utf-8` |
| `StringCchCopy` 返回值没查 | 截断被当成功 | `FAILED(hr)` 分支（12.7） |

## 12.10 小结

1. 乱码 = 读写页码不匹配；UTF-16 是 Win32 本体（`wchar_t`/W 系列），UTF-8 是交换格式，代码页是历史包袱。
2. 转换永远两段式：先问尺寸再转；`MB_ERR_INVALID_CHARS` 做校验必开。
3. A 系列是 W 系列的兼容壳；`UNICODE` 宏决定通用名展开方向。
4. 文件编码三步探测：BOM → 严格 UTF-8 试转 → 按 ANSI。
5. 原始缓冲边界用 StrSafe 家族，返回 `HRESULT` 必查。
