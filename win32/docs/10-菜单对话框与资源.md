# 第 10 章 菜单、对话框与资源

> 本章回答的问题：菜单栏怎么建？为什么菜单、工具栏、快捷键要共用一套命令 ID？模态对话框怎么弹？文件打开/保存对话框（`GetOpenFileNameW`）怎么用？资源脚本（.rc）在其中的角色是什么？

本章示例：`examples/06_text_editor/main.cpp`（带菜单与文件打开/保存的完整文本编辑器）。

## 6.1 命令路由的统一模型

先看全章的总纲。一个 Windows 程序里，"新建文件"这个动作通常有四个入口：菜单项、工具栏按钮、快捷键（Ctrl+N）、右键菜单。**它们必须执行同一段代码**，Win32 的做法是给动作一个唯一的**命令 ID**，所有入口都往同一个通道发：

```text
菜单项 "新建" (IDM_NEW)      ─┐
工具栏按钮 (IDM_NEW)          ├─→ WM_COMMAND (LOWORD(wParam)==IDM_NEW) → 你的处理函数
快捷键 Ctrl+N (IDM_NEW)      ─┘
```

好处立现：新增一个入口（比如工具栏按钮）只是"多一个发件人"，处理逻辑零改动；想禁用某个功能，一个 `EnableMenuItem` 全部入口联动。这就是第 5 章控件 ID 纪律的延伸——**ID 是动作的身份，不是控件的身份**。

## 6.2 用代码创建菜单

菜单是句柄对象（`HMENU`），最直白的建法是纯代码：

```cpp
case WM_CREATE: {
    // 1) 弹出式菜单：文件
    HMENU hFile = CreatePopupMenu();
    AppendMenuW(hFile, MF_STRING, IDM_NEW,  L"新建(&N)\tCtrl+N"); // (&N)=Alt+N 助记符，\t 后是对齐提示
    AppendMenuW(hFile, MF_STRING, IDM_OPEN, L"打开(&O)...");
    AppendMenuW(hFile, MF_STRING, IDM_SAVE, L"保存(&S)");
    AppendMenuW(hFile, MF_SEPARATOR, 0, nullptr);                 // 分隔线
    AppendMenuW(hFile, MF_STRING, IDM_EXIT, L"退出(&X)");

    // 2) 弹出式菜单：编辑、帮助（同法，略）

    // 3) 顶层菜单栏：把弹出菜单挂上去，注意 MF_POPUP + 句柄
    HMENU hBar = CreateMenu();
    AppendMenuW(hBar, MF_POPUP | MF_STRING, (UINT_PTR)hFile, L"文件(&F)");
    // AppendMenuW(hBar, MF_POPUP | MF_STRING, (UINT_PTR)hEdit, L"编辑(&E)");
    // AppendMenuW(hBar, MF_POPUP | MF_STRING, (UINT_PTR)hHelp, L"帮助(&H)");

    // 4) 装到窗口上
    SetMenu(hwnd, hBar);
    return 0;
}
```

层级关系：**菜单栏（`CreateMenu`）→ 弹出菜单（`CreatePopupMenu`）→ 菜单项**。`AppendMenuW` 挂菜单时用 `MF_POPUP` 并把子菜单句柄塞进 ID 位置——这是该函数唯一的"双义"用法。

菜单命令到达父窗口，就是标准 `WM_COMMAND`（通知码为 0）：

```cpp
case WM_COMMAND:
    switch (LOWORD(wParam)) {
    case IDM_NEW:   /* 新建 */ return 0;
    case IDM_OPEN:  /* 打开 */ return 0;
    case IDM_SAVE:  /* 保存 */ return 0;
    case IDM_EXIT:
        DestroyWindow(hwnd);          // 触发 WM_CLOSE → WM_DESTROY 链
        return 0;
    }
    return 0;
```

运行期控制菜单状态：

```cpp
EnableMenuItem(hFile, IDM_SAVE, MF_BYCOMMAND | MF_GRAYED);   // 置灰：没有可保存的内容时
CheckMenuItem(hFile, IDM_WRAP,  MF_BYCOMMAND | MF_CHECKED);  // 打勾：切换自动换行
```

## 6.3 快捷键（Accelerator）

菜单文字里的 `Ctrl+N` 只是提示，真正响应快捷键要两步：

```cpp
// 1) 定义加速键表（通常放资源脚本 .rc，这里用数组演示）
ACCEL accels[] = {
    { FCONTROL | FVIRTKEY, 'N', IDM_NEW  },
    { FCONTROL | FVIRTKEY, 'O', IDM_OPEN },
    { FCONTROL | FVIRTKEY, 'S', IDM_SAVE },
};
HACCEL hAccel = CreateAcceleratorTableW(accels, 3);

// 2) 消息循环里加一道翻译：按键先过加速键表
MSG msg = {};
while (GetMessageW(&msg, nullptr, 0, 0) > 0) {
    if (!TranslateAcceleratorW(hwnd, hAccel, &msg)) {   // 命中则直接投 WM_COMMAND
        TranslateMessage(&msg);
        DispatchMessageW(&msg);
    }
}
```

`TranslateAcceleratorW` 命中组合键时把 `WM_KEYDOWN` 翻译成 `WM_COMMAND` 投给窗口并返回非 0——所以命令 ID 一致，处理代码自然复用。

## 6.4 工具栏

工具栏属于"通用控件"，在 `comctl32.dll` 里，类名是常量 `TOOLBARCLASSNAME`（即 `"ToolbarWindow32"`）：

```cpp
#include <commctrl.h>
#pragma comment(lib, "comctl32.lib")

case WM_CREATE: {
    HWND hTB = CreateWindowExW(0, TOOLBARCLASSNAME, nullptr,
        WS_CHILD | WS_VISIBLE | TBSTYLE_FLAT | CCS_TOP,
        0, 0, 0, 0, hwnd, (HMENU)(UINT_PTR)IDC_TOOLBAR,
        ((LPCREATESTRUCTW)lParam)->hInstance, nullptr);

    // 通用控件创建后要先发 TB_BUTTONSTRUCTSIZE（版本协商，照写）
    SendMessageW(hTB, TB_BUTTONSTRUCTSIZE, sizeof(TBBUTTON), 0);

    TBBUTTON buttons[] = {
        { 0, IDM_NEW,  TBSTATE_ENABLED, BTNS_BUTTON, {0}, 0, 0 },  // 图像索引, 命令 ID
        { 1, IDM_OPEN, TBSTATE_ENABLED, BTNS_BUTTON, {0}, 0, 0 },
        { 2, IDM_SAVE, TBSTATE_ENABLED, BTNS_BUTTON, {0}, 0, 0 },
    };
    SendMessageW(hTB, TB_ADDBUTTONS, 3, (LPARAM)buttons);
    SendMessageW(hTB, TB_AUTOSIZE, 0, 0);   // 适应内容
    return 0;
}
```

要点：工具栏按钮的第二个字段直接填**命令 ID**，点击后照常发 `WM_COMMAND`——不需要新写任何分发逻辑。按钮图像用 `TB_ADDBITMAP` 装载位图（或现代的 `TB_LOADIMAGES`/ imagelist），初学阶段用无图按钮也能跑通机制。工具栏自动把"高度随 DPI 调整、停靠顶部"都处理了（`CCS_TOP`）。

## 6.5 模态对话框

**模态**：弹出的对话框不关掉，主窗口不可操作（`DialogBoxW` 系）；**非模态**：两者可切换操作（`CreateDialogW` 系）。先讲模态。

对话框由两部分组成：

1. **模板**：描述"有哪些控件、摆在哪"。规范做法写在资源脚本（`.rc` 文件）里，由资源编译器（`rc.exe`，VS 工程自动处理）编进 exe：

   ```rc
   IDD_SETTINGS DIALOGEX 0, 0, 200, 100
   STYLE DS_SETFONT | DS_MODALFRAME | WS_POPUP | WS_CAPTION | WS_SYSMENU
   CAPTION "设置"
   FONT 9, "Microsoft YaHei UI"
   BEGIN
       LTEXT   "用户名:", IDC_STATIC, 10, 12, 40, 12
       EDITTEXT IDC_NAME,  55, 10, 130, 14, ES_AUTOHSCROLL
       PUSHBUTTON "确定", IDOK,     85, 70, 50, 14
       PUSHBUTTON "取消", IDCANCEL, 140, 70, 50, 14
   END
   ```

   资源脚本的价值：界面布局与代码分离、可被资源编辑器可视化调整。纯代码创建对话框（`CreateDialogIndirectParam` + 内存模板）也可行但繁琐，初学建议走 `.rc`。

2. **对话框过程**（DialogProc）：和 `WndProc` 同构的回调，两个惯例差异——返回 `BOOL`（`TRUE`=已处理，不交给系统默认处理；`FALSE`=交给默认），且**不调 `DefWindowProc`**（对话框管理器内部自己有默认过程）：

   ```cpp
   INT_PTR CALLBACK SettingsDlgProc(HWND hDlg, UINT msg, WPARAM wParam, LPARAM lParam) {
       switch (msg) {
       case WM_INITDIALOG:                      // ★ 对话框版的 WM_CREATE：控件已建好，做初始化
           SetWindowTextW(GetDlgItem(hDlg, IDC_NAME), L"guest");
           return TRUE;

       case WM_COMMAND:
           switch (LOWORD(wParam)) {
           case IDOK: {                          // 模板里 PUSHBUTTON "确定", IDOK 的 ID
               wchar_t name[128] = {};
               GetDlgItemTextW(hDlg, IDC_NAME, name, 128);
               // ... 校验/保存 ...
               EndDialog(hDlg, IDOK);            // ★ 关闭模态对话框，返回值 = IDOK
               return TRUE;
           }
           case IDCANCEL:
               EndDialog(hDlg, IDCANCEL);
               return TRUE;
           }
           return TRUE;
       }
       return FALSE;
   }
   ```

   调用方（`DialogBoxW` 返回的就是 `EndDialog` 的第二参）：

   ```cpp
   INT_PTR result = DialogBoxW(hInstance, MAKEINTRESOURCEW(IDD_SETTINGS),
                               hwnd, SettingsDlgProc);
   if (result == IDOK) { /* 读取对话框收集到的设置 */ }
   ```

   传数据进对话框：`DialogBoxParamW` 的最后一个参数经 `WM_INITDIALOG` 的 `lParam` 送达——这是"参数传入、`EndDialog` 返回值传出"的标准会话模式。

3. **`IDOK`/`IDCANCEL` 是系统预定义 ID（1/2）**：模板里的确定/取消按钮用它们，系统还免费附送 Esc=取消、Enter=默认按钮的行为。

## 6.6 通用对话框：文件打开/保存

"打开文件"不要自己造对话框——Shell 提供 `GetOpenFileNameW`（`comdlg32.dll`）：

```cpp
#include <commdlg.h>
#pragma comment(lib, "comdlg32.lib")

wchar_t filePath[MAX_PATH] = L"";

OPENFILENAMEW ofn = {};
ofn.lStructSize = sizeof(ofn);
ofn.hwndOwner   = hwnd;                       // 模态归属
ofn.lpstrFilter = L"文本文件 (*.txt)\0*.txt\0所有文件 (*.*)\0*.*\0";
                 // ★ 过滤器用 \0 分隔且以 \0\0 结尾（字符串对：描述|通配）
ofn.lpstrFile   = filePath;                   // 传入初始值 / 返回所选路径
ofn.nMaxFile    = MAX_PATH;
ofn.Flags       = OFN_FILEMUSTEXIST | OFN_PATHMUSTEXIST;

if (GetOpenFileNameW(&ofn)) {
    // filePath 现在是用户选中的完整路径
}
// 对应的保存对话框：GetSaveFileNameW（多了"覆盖确认"，OFN_OVERWRITEPROMPT）
```

现代一点的替代是 COM 接口 `IFileOpenDialog`（Vista+，支持多选、更好的体验），`GetOpenFileNameW` 在内部会自动加一层兼容壳——初学用后者足够，知道前者的存在即可。

## 6.7 实战：带菜单与文件 I/O 的文本编辑器

`examples/06_text_editor/main.cpp` 把本章与前几章整合：菜单（打开/保存/退出）+ 多行 EDIT 控件 + 通用文件对话框 + `CreateFileW`/`ReadFile`/`WriteFile` 读写。骨架：

```cpp
case WM_CREATE:
    BuildMenu(hwnd);                       // 6.2 节的代码收进函数
    CreateWindowExW(0, L"EDIT", L"",
        WS_CHILD | WS_VISIBLE | WS_VSCROLL | ES_MULTILINE | ES_AUTOVSCROLL
        | ES_WANTRETURN,
        0, 0, 100, 100, hwnd, (HMENU)(UINT_PTR)IDC_EDIT, hInst, nullptr);
    return 0;

case WM_SIZE:                              // 编辑框永远铺满客户区（5.6 节）
    MoveWindow(GetDlgItem(hwnd, IDC_EDIT), 0, 0, LOWORD(lParam), HIWORD(lParam), TRUE);
    return 0;

case WM_COMMAND:
    switch (LOWORD(wParam)) {
    case IDM_OPEN: {
        wchar_t path[MAX_PATH] = L"";
        if (PromptOpen(hwnd, path))        // GetOpenFileNameW 封装
            LoadFileToEdit(hwnd, path);    // CreateFileW → GetFileSizeEx → ReadFile → SetWindowTextW
        return 0;
    }
    case IDM_SAVE:
        /* GetSaveFileNameW → GetWindowTextW → CreateFileW → WriteFile */
        return 0;
    }
```

这个不足 200 行的程序就是"真实 Win32 程序"的最小完备样本：菜单命令 → 通用对话框收集参数 → 系统 API 执行 → 控件呈现结果，每个环节都来自前面章节。

## 6.8 非模态对话框与资源加载常识

- **非模态对话框**：`CreateDialogW(hInst, MAKEINTRESOURCEW(IDD_X), hwnd, Proc)`，立即返回，对话框作为独立窗口存活；关闭要在收到 `WM_DESTROY`/`WM_CLOSE` 时调 `DestroyWindow`（不是 `EndDialog`）。工具面板（如画图的调色板）用这种。
- **资源不只是对话框**：图标（`LoadIconW`）、光标、字符串表（`LoadStringW`）、版本信息、manifest 都住在资源段。多语言程序尤其依赖字符串表。
- **查资源 ID 的返回值**：`LoadXXX` 失败返回 `nullptr`/0，别忘了判。
