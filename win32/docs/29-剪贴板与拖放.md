# 第 29 章 剪贴板与拖放

> **本章回答的问题**：复制粘贴在系统层怎么运作？`SetClipboardData` 之后为什么不能 `GlobalFree`？`WM_DROPFILES` 和 `IDropTarget` 什么关系、怎么选？拖动方（把东西拖出去）怎么写？
>
> **前置章节**：第 15 章（`GlobalAlloc` 家族——剪贴板的内存约定）、第 22~24 章（COM——`IDropTarget` 是你第三次手写接口）。
>
> **你将做出什么**：一个双通道数据程序（`examples/32_clipboard_dnd`）：剪贴板读写按钮 + 窗口级 `WM_DROPFILES` + 手写 `IDropTarget` 的列表框拖放。

本章示例：`examples/32_clipboard_dnd/main.cpp`。

## 29.1 剪贴板模型：全局共享 + 格式协商

剪贴板是**全系统共享**的一块"待取数据"空间，两个设计决定了一切写法：

1. **所有权制**：任一时刻只有一个窗口"拥有"剪贴板；`OpenClipboard(hwnd)` 独占打开（别的程序此刻打不开），`EmptyClipboard` 清空并把所有权判给你；
2. **多格式并存**：同一份内容可以同时以多种格式登记（HTML + 纯文本 + 自定义格式），粘贴方按能力挑最好的——Word 粘进记事本自动降级，就是这个机制。

标准格式是整数编号（`CF_UNICODETEXT`、`CF_DIB` 位图、`CF_HDROP` 文件列表），自定义格式用 `RegisterClipboardFormatW(L"MyApp.Block")` 申请全局唯一号。

写剪贴板的**四步协议**（32 示例的 `CopyToClipboard`）：

```text
① OpenClipboard(hwnd)      独占打开（失败=别人开着，稍后重试）
② EmptyClipboard()         清空 + 拿到所有权
③ SetClipboardData(格式, HGLOBAL)   登记数据 —— ★ 所有权同时移交剪贴板
④ CloseClipboard()         关门
```

## 29.2 写：`GlobalAlloc` 与所有权移交

第 ③ 步的内存有两个铁规：

```cpp
size_t bytes = (lstrlenW(text) + 1) * sizeof(wchar_t);
HGLOBAL mem = GlobalAlloc(GMEM_MOVEABLE, bytes);   // ① 必须可移动内存
CopyMemory(GlobalLock(mem), text, bytes);
GlobalUnlock(mem);
SetClipboardData(CF_UNICODETEXT, mem);             // ② 移交后绝不能 GlobalFree！
```

- **`GMEM_MOVEABLE`**：16 位时代的"可移动堆"遗风（15 章的博物馆展品），剪贴板 API 指名要它——这是 `GlobalAlloc` 活到今天的头号理由；
- **所有权移交**是本章最重要的概念：`SetClipboardData` 成功后，这块内存归剪贴板（系统）管理，**你再 `GlobalFree` 就是双重释放**。同理，读到的是别人的内存，`GlobalLock` 用完 `GlobalUnlock`，**不释放**。

## 29.3 读：探格式 → 取数据 → 只读不还

```cpp
if (!OpenClipboard(hwnd)) return false;
if (IsClipboardFormatAvailable(CF_UNICODETEXT)) {   // 先探（也可 GetPriorityClipboardFormat 挑最优）
    HANDLE h = GetClipboardData(CF_UNICODETEXT);    // 拿到的是剪贴板自己的内存
    if (const wchar_t* p = (const wchar_t*)GlobalLock(h)) {
        lstrcpynW(buf, p, cap);                     // ★ 拷进自己的缓冲再用
        GlobalUnlock(h);                            // 只解锁，不释放
    }
}
CloseClipboard();
```

跨程序粘贴的本质：两个进程通过系统中介交换一块内存——你从不直接碰对方地址空间（第 13 章的进程隔离在数据交换上同样成立）。

## 29.4 拖放三档：从"能收文件"到"任意数据"

"拖放"有两件不同的事，能力与成本差一档：

| 档 | 机制 | 能收什么 | 代码量 |
|----|------|---------|--------|
| ① 文件拖入 | `DragAcceptFiles` + `WM_DROPFILES` | 只能文件 | 5 行 |
| ② OLE 拖放 | `IDropTarget` + `RegisterDragDrop` | 任意格式（文本/图/自定义）、带反馈效果 | 一节 |
| ③ 拖出 | `DoDragDrop` + 实现 `IDataObject` | 把自己的数据拖给别人 | 最长（29.7） |

**选型**：只要"把文件拖进来"→ ①；要做拖放目标且收非文件（如从浏览器拖文字/图片）→ ②；程序要作为拖动源 → ③。①②可共存（32 示例故意同屏两档对照）。

## 29.5 ① `WM_DROPFILES`：文件拖入的最短路径

```cpp
DragAcceptFiles(hwnd, TRUE);            // WM_CREATE 里声明一次

case WM_DROPFILES: {
    HDROP hDrop = (HDROP)wParam;
    UINT n = DragQueryFileW(hDrop, 0xFFFFFFFF, nullptr, 0);  // 问数量（0xFFFFFFFF 的魔法值）
    for (UINT i = 0; i < n; ++i) {
        wchar_t path[MAX_PATH];
        DragQueryFileW(hDrop, i, path, MAX_PATH);             // 逐个取路径
        // ...
    }
    DragFinish(hDrop);                  // 释放拖放数据块
    return 0;
}
```

注意 `HDROP` 其实是个内存句柄，用完 `DragFinish`——句柄纪律在拖放界的重现。

## 29.6 ② 手写 `IDropTarget`：COM 实战第二回

OLE 拖放把"拖放目标"定义成 COM 接口——你在 24 章写 `Calc` 的功力直接复用：实现 `IUnknown` 三件套 + 四个 `IDropTarget` 方法：

| 方法 | 谁调 | 你该干什么 |
|------|------|-----------|
| `DragEnter` | 拖着东西进入你的区域 | 查数据格式，决定 `*effect`（接不接、什么光标） |
| `DragOver` | 悬停移动 | 维持/更新 effect（多数场景不变） |
| `DragLeave` | 拖出区域 | 清掉高亮 |
| `Drop` | 松手 | 取数据、处理、清理 |

数据长在 `IDataObject*` 里——**格式查询用 `QueryGetData`，取数用 `GetData`**，都按 `FORMATETC`（格式+介质描述）说话：

```cpp
STDMETHODIMP DragEnter(IDataObject* obj, DWORD, POINTL, DWORD* effect) override {
    FORMATETC fmt = { CF_HDROP, nullptr, DVASPECT_CONTENT, -1, TYMED_HGLOBAL };
    *effect = (obj->QueryGetData(&fmt) == S_OK) ? DROPEFFECT_COPY   // 接：加号光标
                                                : DROPEFFECT_NONE;  // 不接：禁止光标
    return S_OK;
}

STDMETHODIMP Drop(IDataObject* obj, DWORD, POINTL, DWORD* effect) override {
    *effect = DROPEFFECT_COPY;
    FORMATETC fmt = { CF_HDROP, nullptr, DVASPECT_CONTENT, -1, TYMED_HGLOBAL };
    STGMEDIUM medium = {};
    if (SUCCEEDED(obj->GetData(&fmt, &medium))) {
        HDROP hDrop = (HDROP)GlobalLock(medium.hGlobal);
        // ... DragQueryFileW 遍历（同 29.5，数据形态完全一样！）...
        GlobalUnlock(medium.hGlobal);
        ReleaseStgMedium(&medium);      // ★ STGMEDIUM 用完必释放（COM 的内存规矩）
    }
    return S_OK;
}
```

挂接两行 + 初始化一个前提：

```cpp
OleInitialize(nullptr);                 // ★ 前提：OLE 拖放要求 OleInitialize（CoInitialize 不行）
RegisterDragDrop(g_dropList, g_drop);   // 目标窗口 ↔ 你的 IDropTarget 绑定
// 退出：RevokeDragDrop(g_dropList); g_drop->Release(); OleUninitialize();
```

**`OleInitialize` vs `CoInitialize`**：前者在 COM 之上再初始化 OLE 子系统（拖放/嵌入用），内部会调 `CoInitialize`——用了 Ole 就别再 Co，两边重复初始化会返回 `RPC_E_CHANGED_MODE` 类错误。

## 29.7 ③ 拖出：`DoDragDrop` 一段

做拖动源的骨架：构造一个 `IDataObject`（数据 + 格式），调 `DoDragDrop(dataObj, dropSource, 允许的效果, &实际效果)`——它内部转消息循环直到拖放结束（模态的！）。`IDropSource` 的小接口负责"Esc 取消了吗"这类反馈。剪贴板与拖放共用 `IDataObject` 抽象：**"复制"和"拖"是同一份数据管道的两种交付方式**——这也是 ① 的文件拖入与 ② 的 `CF_HDROP` 取数一模一样的原因。

## 29.8 易错清单

| 症状 | 原因 | 解法 |
|------|------|------|
| `SetClipboardData` 后崩溃 | 之后又 `GlobalFree`（双重释放） | 所有权已移交（29.2） |
| `OpenClipboard` 失败 | 别的程序开着（剪贴板查看器等） | 重试/提示，别硬闯 |
| 内存没拷直接用 `GetClipboardData` 的指针 | 跨进程内存随时失效 | `GlobalLock` 拷贝 + 解锁 |
| `RegisterDragDrop` 返回错误 | 没先 `OleInitialize`（或先 Co 了） | 只用 Ole 系（29.6） |
| 拖放目标收不到 | 没 `RegisterDragDrop`，或窗口没在 STA 线程 | 29.6 两行 + GUI 线程 |
| `ReleaseStgMedium` 忘调 | 泄漏 | COM 数据介质的固定配对 |
| 拖入文件数总是 0 | `DragQueryFileW` 第一参传了索引而非 0xFFFFFFFF | 问数量用魔法值（29.5） |
| `DragFinish` 忘调 | HDROP 泄漏 | 29.5 |

## 29.9 小结

1. 剪贴板 = 所有权制 + 多格式协商；写四步（开→清→设→关），内存 `GMEM_MOVEABLE` 且移交后禁释放。
2. 读 = 探格式 → `GlobalLock` 拷贝 → 只解锁；从不释放别人的内存。
3. 拖放三档：文件拖入 5 行（`WM_DROPFILES`）；任意格式收拖做 `IDropTarget`（QueryGetData 定夺、GetData 取数、`ReleaseStgMedium` 配平）。
4. OLE 拖放的前提是 `OleInitialize`；拖动源走 `DoDragDrop` + `IDataObject`。
5. 剪贴板与拖放共用 `IDataObject`——同一份数据、两种交付。
