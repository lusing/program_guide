# 第 30 章 现代 Win32 与学习路线

> **本章回答的问题**：到 Windows 11 为止，Win32 新增了哪些值得知道的东西？Win32 与 UWP / WinRT / WinUI / .NET 是什么关系？什么时候该留在 Win32、什么时候上高层框架？全书易错点汇总与后续学习地图。
>
> **前置章节**：全部——这是收束章。
>
> **你将做出什么**：不再有新代码；你将带走一张"能力-版本"对照表、一张技术栈全景图、一份全书避坑复习卡和一张学习地图。

## 30.1 Win10 / Win11 时代的新增能力清单

第 1 章的历史视角在这里变成一张可查的表。这些 API 在 Win32 头文件与 SDK 里都是一等公民，编译时把 `_WIN32_WINNT` 设为 `0x0A00` 即可见；本教程各章的"现代视角"栏目就是它们的家。

### 显示与 UI（第 9 章已讲）

| API | 版本 | 作用 |
|-----|------|------|
| `SetProcessDpiAwarenessContext`（Per-Monitor V2） | 10 1703 | 每显示器 DPI 感知，`WM_DPICHANGED` 驱动动态缩放 |
| `GetDpiForWindow` / `GetDpiForMonitor` | 10 | 查询窗口/显示器 DPI |
| `DwmSetWindowAttribute` + `DWMWA_WINDOW_CORNER_PREFERENCE` | 11 | 圆角窗口 |
| `DWMWA_SYSTEMBACKDROP_TYPE`（Mica/Acrylic） | 11 22H2 | 系统级窗口背景材质 |
| `DwmExtendFrameIntoClientArea` / 深色模式 `DWMWA_USE_IMMERSIVE_DARK_MODE` | Vista / 10 1809 | 玻璃边框 / 标题栏深色 |

### 进程与线程（第 13/14 章已讲）

| API | 版本 | 作用 |
|-----|------|------|
| `SetThreadDescription` | 10 1607 | 线程命名，调试器直接显示 |
| `WaitOnAddress` | 8 | 无内核对象的"等内存值变化" |
| 线程池 API（`SubmitThreadpoolWork` 等） | Vista | 系统级线程池 |
| Job 对象增强（CPU 速率控制等） | 8+ | 进程组治理（浏览器沙箱基座） |
| `SetProcessMitigationPolicy` | 8+ | 进程级缓解策略（DEP/CFG/ASLR 加固，17 章） |

### 内存（第 15 章已讲）

| API | 版本 | 作用 |
|-----|------|------|
| `VirtualAlloc2` / `MapViewOfFile3` | 10 1803 | 占位符分配、内存分区、指定 NUMA 节点 |
| 大页（`MEM_LARGE_PAGES`） | 长期可用 | 2MB 页减少 TLB miss，服务器场景 |

### 文件与 I/O（第 16 章已讲）

| API | 版本 | 作用 |
|-----|------|------|
| `CreateFile2` / `GetFileInformationByHandleEx` | 8 | 参数结构体化；新元数据查询 |
| 长路径（`\\?\` + 系统开关） | 10 1607 | 突破 MAX_PATH 260 |
| `ReadDirectoryChangesW` 持续增强 | 长期 | 目录监视（一切实时同步工具的地基） |
| ConPTY（`CreatePseudoConsole`） | 10 1809 | 伪控制台：Windows Terminal、VS Code 终端的基座 |

### 系统信息与安全（第 17/18 章已讲）

| API | 版本 | 作用 |
|-----|------|------|
| `RtlGetVersion` | 长期 | 不受 manifest 影响的真实版本 |
| `RegisterServiceCtrlHandlerExW` 等服务现代接口 | Vista+ | 服务控制扩展（27 章） |
| 完整性级别 / UIPI | Vista+ | 强制隔离档位（17 章） |

### 与"现代 Windows"的接驳（第 19~26 章已讲）

| 技术 | 说明 |
|------|------|
| API Set | 第 20 章：逻辑 DLL 名机制，系统模块化的基石 |
| COM per-user 注册 | 第 24 章：HKCU\Software\Classes 免管理员 |
| C++/WinRT | 第 26 章：从 Win32 调用现代 API 的标准通道 |
| MSIX / 桌面桥 | Win32 程序可打包为现代分发格式，获得干净卸载与增量更新，无需放弃 Win32 |
| Windows App SDK（WinUI 3） | 新 UI 框架，运行在 Win32 窗口模型之上 |
| Microsoft Store | 已允许完整 Win32 应用上架 |

**整体判断**：UI 层被反复重写（GDI → DWM 合成 → Direct2D → WinRT XAML → WinUI 3），而进程/线程/同步/内存/文件/DLL/COM/安全这层三十年只有加法、没有替换。你在这本教程里花的时间，大部分花在不会过时的那一半。

## 30.2 技术栈关系图谱

把 Windows 桌面开发的全家福画成一张图：

```text
                      ┌─────────────────────────────┐
     你的选择空间        │  WinUI 3 / WPF / WinForms / │   高层 UI 框架
                      │  Electron / Qt / Flutter    │   （生产力优先）
                      └──────────────┬──────────────┘
                                     │ 各框架最终都要落下来
                      ┌──────────────▼──────────────┐
                      │   Win32 API（本教程 30 章）  │   系统服务接口
                      │   窗口/消息 │ 进程/线程/同步   │   ——稳定边界
                      │   GDI/D2D  │ 内存/文件/DLL   │
                      │   COM/安全 │ 注册表/服务/Shell│
                      └──────────────┬──────────────┘
                          ┌──────────┴──────────┐
                          ▼                     ▼
                  WinRT（26 章的通道）        Windows 内核
                  现代能力唯一入口          （ntdll 之下，非官方契约）
```

三个常见误解澄清（保留自初版，依然常真）：

1. **"UWP/WinUI 是 Win32 的替代品"**——不是。WinUI 3 程序的进程里有消息循环、有 HWND；它的文件访问、进程管理照样是 Win32。替代的只是 UI 层。
2. **"C#/WPF 程序和 Win32 无关"**——无关的是你写的代码；`FileStream`、`Process.Start`、P/Invoke `[DllImport]` 都在 Win32 这层汇合。学过 Win32 的人看 .NET 异常栈里的 `kernel32!CreateFileW` 会心一笑。
3. **"学 Win32 过时了"**——过时的是"用纯 Win32 手搓大型商业 UI"这种做法（该用框架）；不过时的是理解机器与系统的真实工作方式。**用框架开发，按 Win32 调试**，是资深 Windows 工程师的常态。

选型建议：

| 你要做的事 | 建议 |
|-----------|------|
| 学习 Windows 的真实工作方式 / 系统级工具 | 纯 Win32（本教程路线） |
| 小型实用工具，追求极小体积零依赖 | 纯 Win32 或 Win32+一两层薄封装 |
| 商业桌面产品、复杂界面 | 高层框架 + Win32 知识做底座 |
| 需要深入的性能/崩溃/兼容性排查 | 无论上层是什么，都必须懂 Win32 |
| 现代系统集成（通知/设备/后台） | Win32 + C++/WinRT（26 章） |

## 30.3 全书避坑总表（按篇复习卡）

写完代码扫一遍，每篇只收最要命的几条：

**入门篇（2~3 章）**
- [ ] 每种返回值用对失败判据：`BOOL`/`INVALID_HANDLE_VALUE`/`nullptr` 三族
- [ ] `GetLastError` 紧贴失败调用；`FormatMessageW` 配 `LocalFree`
- [ ] `FAILED/SUCCEEDED` 判 HRESULT；`__try` 函数里不放大 C++ 对象（C2712）

**界面层（4~11 章）**
- [ ] `WndProc` 兜底 `DefWindowProcW`；`BeginPaint/EndPaint` 成对；`WM_PAINT` 外不直画
- [ ] 控件事件判 ID 也判通知码；mask 不写的字段静默失效（6 章）
- [ ] GDI 四步配平、双缓冲防闪、DPI 用 Per-Monitor V2（9 章）

**系统服务层（12~18 章）**
- [ ] 转换 API 两段式；REG_SZ 字节数含 NUL；StrSafe 查返回值（12 章）
- [ ] `CreateProcessW` 命令行可写 + 双句柄关闭；条件等待用 `while`；`PostMessage` 回传（13/14 章）
- [ ] 分配释放同层配对；`MEM_RELEASE` 传 0；文件大小拼 High/Low（15/16 章）
- [ ] 空 DACL=全允许、拒绝 ACE 在前；版本用 `RtlGetVersion`；FILETIME 用 `ULARGE_INTEGER` 比（17/18 章）

**模块与 COM（19~26 章）**
- [ ] `GetProcAddress` 签名逐字核对；`DllMain` 最小化；不依赖当前目录找 DLL（19 章）
- [ ] 插件三原则：纯 C/版本握手/内存不跨界（20 章）
- [ ] HKCU 优先；WOW64 重定向谨记（21 章）
- [ ] COM：拿到指针就 Release；HKCU per-user 注册；ThreadingModel 别写错（22~24 章）
- [ ] D2D 设备资源与 target 同生死；WinRT 别忘 `WindowsApp.lib`（25/26 章）

**平台专题（27~29 章）**
- [ ] 服务五要素状态必报全；事件日志代替一切 UI 输出（27 章）
- [ ] 托盘退出必 `NIM_DELETE`；`TaskbarCreated` 自愈（28 章）
- [ ] `SetClipboardData` 后禁 `GlobalFree`；`ReleaseStgMedium` 配平（29 章）

## 30.5 结语

回到第 1 章的定位：**Win32 API 是 Windows 操作系统的服务接口**。这本教程带你走完的路线——错误处理 → 窗口与消息 → 控件与事件 → GDI 与现代显示 → 菜单与对话框 → 三个完整应用 → 编码 → 进程线程 → 内存 → 文件 → 安全 → 系统信息 → DLL → 注册表 → COM 三部曲 → Direct2D → WinRT → 服务 → Shell → 剪贴板与拖放——覆盖了这个接口的全部两大板块：会被 UI 框架层层封装的界面部分，和三十年来从未被替代的系统服务部分。

学完的标志不是记住多少函数名，而是四个转变：

1. 看到"程序卡死/界面失灵/文件删不掉"，能想到消息循环、句柄、共享模式这几个嫌疑对象；
2. 拿到任何 Windows 程序崩溃转储，敢打开看 `ntdll`、`kernel32`、`user32` 的调用栈；
3. 上手任何新 UI 框架时，能一眼认出它底下那个熟悉的窗口模型；
4. 看到 `IUnknown`/`QueryInterface` 不再害怕——因为你亲手写出过自己的 COM 服务器、自己的插件宿主、自己的 IDropTarget。

从这里开始，无论你走向哪个方向——游戏引擎、桌面产品、系统工具、安全研究——脚下的地基都是同一块。
