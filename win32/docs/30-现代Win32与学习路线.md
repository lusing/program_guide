# 第 12 章 现代 Win32 与学习路线

> 本章回答的问题：到 Windows 11 为止，Win32 新增了哪些值得知道的东西？Win32 与 UWP / WinRT / WinUI / .NET 是什么关系？什么时候该留在 Win32、什么时候上高层框架？全书易错点汇总与后续学习地图。

## 12.1 Win10 / Win11 时代的新增能力清单

第 1 章的历史视角在这里变成一张可查的清单。这些 API 在 Win32 头文件与 SDK 里都是一等公民，编译时把 `_WIN32_WINNT` 设为 `0x0A00` 即可见。

### 显示与 UI（第 9 章已讲）

| API | 版本 | 作用 |
|-----|------|------|
| `SetProcessDpiAwarenessContext`（Per-Monitor V2） | 10 1703 | 每显示器 DPI 感知，`WM_DPICHANGED` 驱动动态缩放 |
| `GetDpiForWindow` / `GetDpiForMonitor` | 10 | 查询窗口/显示器 DPI |
| `DwmSetWindowAttribute` + `DWMWA_WINDOW_CORNER_PREFERENCE` | 11 | 圆角窗口 |
| `DWMWA_SYSTEMBACKDROP_TYPE`（Mica/Acrylic） | 11 22H2 | 系统级窗口背景材质 |
| `DwmExtendFrameIntoClientArea` / 深色模式 `DWMWA_USE_IMMERSIVE_DARK_MODE` | Vista / 10 1809 | 玻璃边框 / 标题栏深色 |

### 进程与线程（第 13/14 章已讲）

| API | 版本 | 作用 |
|-----|------|------|
| `SetThreadDescription` | 10 1607 | 线程命名，调试器直接显示 |
| `WaitOnAddress` | 8 | 无内核对象的"等内存值变化" |
| 线程池 API（`SubmitThreadpoolWork` 等） | Vista | 系统级线程池 |
| Job 对象增强（CPU 速率控制等） | 8+ | 进程组治理（浏览器沙箱基座） |
| `SetProcessMitigationPolicy` | 8+ | 进程级缓解策略（DEP/CFG/ASLR 加固） |

### 内存（第 15 章已讲）

| API | 版本 | 作用 |
|-----|------|------|
| `VirtualAlloc2` / `MapViewOfFile3` | 10 1803 | 占位符分配、内存分区、指定 NUMA 节点 |
| 大页（`MEM_LARGE_PAGES`） | 长期可用 | 2MB 页减少 TLB miss，服务器场景 |

### 文件与 I/O（第 16 章已讲）

| API | 版本 | 作用 |
|-----|------|------|
| `CreateFile2` / `GetFileInformationByHandleEx` | 8 | 参数结构体化；新元数据查询 |
| 长路径（`\\?\` + 系统开关） | 10 1607 | 突破 MAX_PATH 260 |
| `ReadDirectoryChangesW` 持续增强 | 长期 | 目录监视（一切实时同步工具的地基） |
| ConPTY（`CreatePseudoConsole`） | 10 1809 | 伪控制台：Windows Terminal、VS Code 终端的基座 |

### 与"现代 Windows"的接驳

| 技术 | 说明 |
|------|------|
| API Set | 第 20 章：逻辑 DLL 名机制，系统模块化的基石 |
| MSIX / 桌面桥 | Win32 程序可打包为现代分发格式，获得干净卸载与增量更新，无需放弃 Win32 |
| Windows App SDK（WinUI 3） | 新 UI 框架，运行在 Win32 窗口模型之上 |
| Microsoft Store | 已允许完整 Win32 应用上架 |

**整体判断**：UI 层被反复重写（GDI → DWM 合成 → WinRT XAML → WinUI 3），而进程/线程/同步/内存/文件这层三十年只有加法、没有替换。你在这本教程里花的时间都花在不会过时的那一半。

## 12.2 技术栈关系图谱

把 Windows 桌面开发的全家福画成一张图，逐层看：

```text
                      ┌─────────────────────────────┐
     你的选择空间        │  WinUI 3 / WPF / WinForms / │   高层 UI 框架
                      │  Electron / Qt / Flutter    │   （生产力优先）
                      └──────────────┬──────────────┘
                                     │ 各框架最终都要落下来
                      ┌──────────────▼──────────────┐
                      │   Win32 API（本教程）        │   系统服务接口
                      │   窗口/消息 │ 进程/线程/同步   │   ——稳定边界
                      │   GDI/DWM  │ 内存/文件/DLL   │
                      └──────────────┬──────────────┘
                                     │
                              Windows 内核
```

三个常见误解澄清：

1. **"UWP/WinUI 是 Win32 的替代品"**——不是。WinUI 3 程序的进程里有消息循环、有 HWND；它的文件访问、进程管理照样是 Win32。替代的只是 UI 层。
2. **"C#/WPF 程序和 Win32 无关"**——无关的是你写的代码；`FileStream`、`Process.Start`、P/Invoke `[DllImport]` 都在 Win32 这层汇合。学过 Win32 的人看 .NET 异常栈里的 `kernel32!CreateFileW` 会心一笑。
3. **"学 Win32 过时了"**——过时的是"用纯 Win32 手搓大型商业 UI"这种做法（该用框架）；不过时的是理解机器与系统的真实工作方式。**用框架开发，按 Win32 调试**，是资深 Windows 工程师的常态。

选型建议：

| 你要做的事 | 建议 |
|-----------|------|
| 学习 Windows 的真实工作方式 / 系统级工具 | 纯 Win32（本教程路线） |
| 小型实用工具，追求极小体积零依赖 | 纯 Win32 或 Win32+一两层薄封装 |
| 商业桌面产品、复杂界面 | 高层框架 + Win32 知识做底座 |
| 需要深入的性能/崩溃/兼容性排查 | 无论上层是什么，都必须懂 Win32 |

## 12.3 全书避坑总表

把各章的易错清单合并成一张"复习卡"，写完代码扫一遍：

**句柄与资源**（3.1、5.3、9.8）
- [ ] 每种句柄的归还函数都成对调用：`CloseHandle` / `DeleteObject` / `DeleteDC` / `ReleaseDC` / `FindClose` / `DestroyMenu`
- [ ] GDI 对象"创建→选中→换回→删除"四步配平
- [ ] 文件句柄用完即关（Windows 上不关还挡住别人删除/改名）

**窗口与消息**（2、3）
- [ ] `WndProc` 末尾 `DefWindowProcW` 兜底，`return` 位置不吞默认处理
- [ ] `WM_PAINT` 里 `BeginPaint/EndPaint` 成对（漏了 → `WM_PAINT` 连发 CPU 100%）
- [ ] 坐标用 `GET_X_LPARAM`（负坐标安全）；`WM_COMMAND` 判通知码不只判 ID
- [ ] `WndProc` 内无耗时操作，后台任务走工作线程 + `PostMessage`

**字符串与编译**（2）
- [ ] 一律 `W` 系列 + `wchar_t` + `L""`，`/utf-8` 编译，不碰 `TCHAR`
- [ ] 版本宏 `_WIN32_WINNT` 与想用的 API 匹配
- [ ] 链接错误先查：入口函数签名、`/SUBSYSTEM`、导入库

**进程线程同步**（8）
- [ ] `CreateProcessW` 命令行传可写缓冲区；子进程两个句柄都 `CloseHandle`
- [ ] 线程函数 `return` 结束，不用 `ExitThread`/`TerminateThread`
- [ ] 共享数据必同步；条件等待用 `while` 防虚假唤醒
- [ ] 工作线程不碰 UI；跨线程通知用 `PostMessage`；`LPARAM` 传堆指针接收方释放

**内存**（9）
- [ ] 分配/释放同层配对：`VirtualAlloc/VirtualFree`、`HeapAlloc/HeapFree`、`new/delete`
- [ ] `VirtualFree` 用 `MEM_RELEASE` 时大小传 0
- [ ] 文件映射四件套：`UnmapViewOfFile` + `CloseHandle` ×2

**文件**（10）
- [ ] `CreateFileW` 失败判 `INVALID_HANDLE_VALUE` 不是 `nullptr`
- [ ] 共享模式按"别人还要不要同时访问"声明
- [ ] `ReadFile` 循环读、查实际字节数；文件大小拼 `High/Low`

**DLL**（11）
- [ ] `GetProcAddress` 的函数指针签名逐字核对
- [ ] `DllMain` 最小化；复杂初始化推到显式导出函数
- [ ] 不依赖当前目录找 DLL

## 12.4 后续学习地图

按目标选路：

```text
从这里出发（12 章）
│
├── 图形与渲染
│     Direct2D + DirectWrite（GDI 的现代继任，COM 接口风格的第一课）
│     → Direct3D 12（3D/游戏）
│
├── 深入 Windows 内部
│     《Windows Internals》第 7 版（Sysinternals 出品，内核视角）
│     Sysinternals 工具集：Process Explorer / Process Monitor / VMMap
│       —— 用 Process Monitor 看任何程序的真实文件/注册表行为，
│          是验证本教程概念的最好玩具
│
├── COM：Windows 对象模型
│     IUnknown、引用计数、接口——DirectX、Shell、WinRT 的共同语言
│
├── 安全与加固
│     UAC/manifest、完整性级别、Job 沙箱、SetProcessMitigationPolicy
│
└── 现代化交付
      MSIX 打包、Windows App SDK / WinUI 3（用你已懂的 Win32 地基快速上手）
```

## 12.5 结语

回到第 1 章的定位：**Win32 API 是 Windows 操作系统的服务接口**。这本教程带你走完的路线——窗口与消息 → 控件与事件 → GDI 与现代显示 → 菜单与对话框 → 三个完整应用 → 进程/线程/同步 → 内存 → 文件 → DLL——覆盖了这个接口的两大板块：会被 UI 框架层层封装的界面部分，和三十年来从未被替代的系统服务部分。

学完的标志不是记住多少函数名，而是三个转变：

1. 看到"程序卡死/界面失灵/文件删不掉"，能想到消息循环、句柄、共享模式这几个嫌疑对象；
2. 拿到任何 Windows 程序崩溃转储，敢打开看 `ntdll`、`kernel32`、`user32` 的调用栈；
3. 上手任何新 UI 框架时，能一眼认出它底下那个熟悉的窗口模型。

从这里开始，无论你走向哪个方向——游戏引擎、桌面产品、系统工具、安全研究——脚下的地基都是同一块。
