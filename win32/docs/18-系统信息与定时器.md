## 18.1 版本检测：一部"谎言进化史"

"这程序在哪个 Windows 上跑"看似简单，其实有三代答案——因为微软**故意让 API 撒谎**：

| 时代 | API | 行为 |
|------|-----|------|
| XP 时代 | `GetVersionExW` | 说真话 → 装 XP 的程序在 Win7 上崩溃 → 微软让后来的系统"装老" |
| Win8.1+ | `VerifyVersionInfoW` | 按**程序 manifest 声明**的兼容范围回答——没声明的程序一律被告知 Win8 |
| 永远的真话 | **`RtlGetVersion`**（ntdll） | 无视 manifest，返回真实版本号 |

`RtlGetVersion` 没有导入库，标准姿势是 `GetProcAddress` 动态取——这段代码你在 22 示例已经写过，它同时也是**第 19 章显式链接的预习课**：

```cpp
typedef LONG(WINAPI* RtlGetVersionFn)(void*);
RtlGetVersionFn rtlGetVersion =
    (RtlGetVersionFn)GetProcAddress(GetModuleHandleW(L"ntdll.dll"), "RtlGetVersion");
OSVERSIONINFOW vi = { sizeof(vi) };
rtlGetVersion(&vi);     // vi.dwMajorVersion / dwMinorVersion / dwBuildNumber 全是真话
```

工程建议：功能检测优先于版本检测（"问这个 API 在不在"好过"问系统是几"）；要展示版本给用户看，就用 `RtlGetVersion`。

## 18.2 处理器与内存

```cpp
SYSTEM_INFO si = {};
GetSystemInfo(&si);          // WOW64 下报的是 32 位视角
GetNativeSystemInfo(&si);    // 报真实硬件视角（64 位程序在 32 位进程也能用）
// si.dwNumberOfProcessors  逻辑核数
// si.dwPageSize            页大小（一般 4096）
// si.dwAllocationGranularity  分配粒度 64KB（第 15 章）

MEMORYSTATUSEX ms = { sizeof(ms) };
GlobalMemoryStatusEx(&ms);   // 老规矩：先自报结构体大小
// ms.dwMemoryLoad / ullTotalPhys / ullAvailPhys / ullTotalVirtual...
```

`GetSystemInfo` vs `GetNativeSystemInfo` 的差异只在 32 位进程跑在 64 位系统（WOW64）时出现——写跨位数工具时的细节题。

## 18.3 环境变量：进程的配置空气

```cpp
// 读单个
wchar_t buf[256];
GetEnvironmentVariableW(L"PATH", buf, 256);        // 返回 0 = 没这个变量

// 展开（把串里的 %VAR% 替换成值）
ExpandEnvironmentStringsW(L"%USERPROFILE%\\docs", buf, 256);

// 设/删（只影响本进程及之后创建的子进程！）
SetEnvironmentVariableW(L"MYAPP_MODE", L"debug");
SetEnvironmentVariableW(L"MYAPP_MODE", nullptr);   // nullptr = 删除

// 遍历全部：返回一整块"NUL 分隔、空串收尾"的内存
LPWCH env = GetEnvironmentStringsW();
for (LPWCH p = env; *p; p += lstrlenW(p) + 1) { /* 每条 "NAME=VALUE" */ }
FreeEnvironmentStringsW(env);
```

两个认知：环境变量是**进程创建时从父进程拷贝**的快照，改系统的 PATH 不影响已运行的程序；"系统变量+用户变量"的合并发生在登录时。

## 18.4 时间的三种形态

```cpp
SYSTEMTIME st;  GetLocalTime(&st);    // 本地时间（用户看到的）
                GetSystemTime(&st);    // UTC（协调世界时）
FILETIME ft;    GetSystemTimeAsFileTime(&ft);   // UTC 的 64 位打包形态
```

- **FILETIME**：1601-01-01 起的 100ns 计数，两个 `DWORD` 打包。**直接比较两个 FILETIME 结构是未定义行为**——拆进 `ULARGE_INTEGER` 再比：
  ```cpp
  ULARGE_INTEGER u = { .LowPart = ft.dwLowDateTime, .HighPart = ft.dwHighDateTime };
  ```
- 互转全家：`SystemTimeToFileTime`（→FILETIME）、`FileTimeToSystemTime`（→SYSTEMTIME）、`FileTimeToLocalFileTime`（UTC→本地）——注意最后这个**没有**逆函数可靠存在（夏令时歧义），存时间用 UTC、显示时才转本地，是系统程序的铁律；
- UNIX 时间戳换算：`unix = filetime / 10000000 - 11644473600`。

## 18.5 高精度计时：QPC

测耗时别用 `GetTickCount`（毫秒级、约 49 天回绕）。**QPC（QueryPerformanceCounter）**是标准答案：

```cpp
LARGE_INTEGER freq, t0, t1;
QueryPerformanceFrequency(&freq);      // 本机频率（每机器不同，不能硬编码）
QueryPerformanceCounter(&t0);
// ... 被测代码 ...
QueryPerformanceCounter(&t1);
double ms = (t1.QuadPart - t0.QuadPart) * 1000.0 / freq.QuadPart;
```

QPC 三性质：**单调递增**（用户改时钟不影响）、高分辨率（纳秒级）、跨核一致。对比 `Sleep(100)` 实测常见 100~110ms——顺带揭穿 `Sleep` 的精度真相：默认粒度 ~15.6ms，`Sleep(1)` 实际可能睡 15ms；要细粒度得 `timeBeginPeriod(1)`（多媒体定时器库）或改用可等待定时器。

## 18.6 三种定时器对比：按需选型

| | `WM_TIMER` | 可等待定时器 | 线程池定时器 |
|---|---|---|---|
| API | `SetTimer` | `CreateWaitableTimerW`+`SetWaitableTimer` | `CreateThreadpoolTimer` |
| 到期表现 | 发消息给 UI 线程 | 内核对象变有信号 | 回调在线程池线程跑 |
| 精度 | ~15ms 级 | 可到 ms 级 | 可到 ms 级 |
| 场景 | 界面刷新、轮询 | 多线程等待、超时控制 | 后台周期任务，不想开线程 |
| 纪律 | `KillTimer` 配对 | `CloseHandle`；负 due = 相对时间 | `CloseThreadpoolTimer`+等回调 |

可等待定时器的 due 时间是本套 API 最反直觉的参数：

```cpp
LARGE_INTEGER due;
due.QuadPart = -10'000'000;   // 负数 = "从现在起"；单位 100ns → 1 秒
                                // 正数 = 绝对 FILETIME（1601 纪元）
SetWaitableTimer(timer, &due, 0/*不周期*/, nullptr, nullptr, FALSE);
WaitForSingleObject(timer, INFINITE);   // 到点变有信号——第 14 章可等待家族
```

## 18.7 电源与设备通知

```cpp
SYSTEM_POWER_STATUS ps = {};
GetSystemPowerStatus(&ps);
// ps.ACLineStatus（1=交流电） ps.BatteryLifePercent（0~100，255=无电池）
```

设备插拔（U 盘到达/移除）走窗口消息 `WM_DEVICECHANGE`；想收特定设备的详细通知要用 `RegisterDeviceNotification` 注册设备接口类（如 USB 存储类 GUID）——GUI 程序的标配技能，控制台程序收不到。电源休眠/恢复同理是 `WM_POWERBROADCAST`。

## 18.9 易错清单

| 症状 | 原因 | 解法 |
|------|------|------|
| 版本检测"明明是 Win11 却报 Win8" | `VerifyVersionInfoW` 按 manifest 回答 | `RtlGetVersion`（18.1） |
| 直接 `if (ft1 > ft2)` 结果怪 | FILETIME 结构体直接比较是 UB | 拆 `ULARGE_INTEGER` |
| `Sleep(1)` 实际睡了 15ms | 系统时钟粒度 15.6ms | `timeBeginPeriod(1)` 或换定时器 |
| QPC 频率先验写死 3579545 | 每机不同 | 每次问 `QueryPerformanceFrequency` |
| 改了 PATH 新程序还是找不到 | 环境变量是创建时快照 | 重启进程/终端 |
| 可等待定时器等不到 | due 给了正数（绝对 1601 时间）想表达"1 秒后" | 负数才是相对时间 |
| WOW64 下核数/页大小不对 | `GetSystemInfo` 报 32 位视角 | `GetNativeSystemInfo` |
| 控制台程序收不到设备通知 | `WM_DEVICECHANGE` 只发窗口 | 要有窗口（或走服务，第 27 章） |

## 18.10 小结

1. 版本检测三代史：真相在 `RtlGetVersion`（GetProcAddress 动态取——19 章预习）。
2. 机器信息三件套：`GetSystemInfo`（WOW64 用 Native 版）、`GlobalMemoryStatusEx`、环境变量（进程快照语义）。
3. 时间三态：本地/UTC/FILETIME；**存 UTC 显本地**、比较用 `ULARGE_INTEGER`。
4. 计时用 QPC（单调+高频）；`Sleep` 粒度 15.6ms 是常识底线。
5. 定时器三选：UI 刷新 `WM_TIMER`、线程等待用可等待定时器、后台周期用线程池定时器。
