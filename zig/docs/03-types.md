# 03 · 类型与变量

> 对应示例：`examples/03_types/`

## 3.1 const 优先，var 要申请

```zig
const answer: u32 = 42; // const：赋值后不可改（默认选择）
var count: i32 = 10;    // var：可改——但从不修改会编译错
count += 5;
```

Zig 把"不可变"当默认：写了 `var` 却没改过，编译器直接提醒你改回 `const`。类型标注可省（`const x = 42` 推导），但函数签名上类型**必须**显式写——推导只发生在局部。

## 3.2 任意位宽整数：u3、i19、u128

```zig
const small: u3 = 5;                // 3 位无符号：只能装 0..7
const wide: u128 = @as(u128, 1) << 100;  // 128 位内建
const ptr_sized: usize = 1000;      // 指针宽度（平台相关），下标/长度都用它
```

整数类型是 `i`/`u` + 位宽，**位宽任意指定**（1..65535）——`u3`、`i19` 都是正经类型。这不是猎奇：协议字段、硬件寄存器、标志位天然就是非字节宽度（第 08 章 packed struct 配合食用）。`@sizeOf(u3)` 是 1（按字节对齐），`@bitSizeOf(u3)` 才是 3。

## 3.3 溢出运算符：`+` 与 `+%`

```zig
var byte: u8 = 255;
// byte += 1;   // Debug 运行期 panic：integer overflow（安全检查抓现行）
byte +%= 1;     // 环绕语义：255 → 0，永不出错
var debt: i8 = -128;
debt -%= 1;     // 环绕：-128 → 127
```

每个算术运算符都有**安全版（`+ - *`）和环绕版（`+% -% *%`）**。安全版在 Debug/ReleaseSafe 下越界即 panic（把 UB 变成崩溃），ReleaseFast 下是 UB。需要环绕语义（哈希、序列号、随机数）时显式写 `%` 版——**读代码的人能看到你承认了溢出**。

## 3.4 comptime_int：没有类型的字面量

```zig
const big = 123_456_789;   // comptime_int：任意精度，"要用时才定类型"
const hex = 0xFF;          // 十六进制
const oct = 0o77;          // 八进制（0o 不是 0）
const bin = 0b1010;        // 二进制
```

数字字面量的类型是 `comptime_int`——无符号、任意精度、只存在于编译期。它落地成什么类型由上下文决定（`const a: u8 = 300` 编译错：u8 装不下）。这让 `const mask = 1 << 40;` 合法——只要用的时候给了够宽的类型。浮点字面量同理是 `comptime_float`。

## 3.5 浮点与布尔

```zig
const pi: f64 = 3.14159265358979;  // f16 f32 f64 f128 四档
const half: f32 = 0.5;
const flag: bool = true;           // 就是 true/false，一位
```

浮点没有隐式精度提升陷阱——`f32` 和 `f64` 混算要显式转。布尔不能与整数互转（`if (1)` 编译错），这是 C 时代 `if (x = 5)` 惨案的总闸。

## 3.6 转型家族：每次转换都要点名

Zig **没有隐式数值转换**（只有"宽化"和字面量定型的少量便捷）。转换都是内建函数，各司其职：

| 内建 | 语义 | 越界行为 |
|---|---|---|
| `@as(T, x)` | 类型协调（字面量/推导定型） | 编译期已知则编译错 |
| `@intCast` | 整数间安全转换 | **panic**（Debug/ReleaseSafe） |
| `@truncate` | 整数砍位（只留低位） | 无——砍就完了；**只接受无符号** |
| `@bitCast` | 同宽重解释（位不变） | 编译期检查宽度 |
| `@intFromFloat` / `@floatFromInt` | 浮↔整 | 浮→整越界 panic |
| `@enumFromInt` / `@intFromEnum` | 枚举↔整数 | 未知值要枚举声明 `_` |

```zig
const a: i32 = 300;
const b = @as(u8, @truncate(@as(u32, @intCast(a)))); // 截断：300 → 44
// @intCast 越界会 panic；若值在编译期已知且越界，连编译都过不了（直接报错）
const fits: i32 = 200;
const c = @as(u8, @intCast(fits)); // OK：200 在值域内
```

设计意图：**每处窄化都留下视觉痕迹**。C 里 `(u8)x` 混在表达式里毫不起眼；Zig 里 `@truncate` 六个字符明晃晃。

## 3.7 @bitCast 看内存

```zig
const u: u32 = 0x41424344;
const raw: [4]u8 = @bitCast(u);  // 逐字节 reinterpret
// 小端机器输出 { 68, 67, 66, 65 }（0x44 在最低地址）
```

`@bitCast` 不改位、只换解释——序列化、网络协议、硬件寄存器的常客。**目标类型必须显式**（`@as(u64, @bitCast(p))`），且两侧宽度严格相等（`@sizeOf` 一致），否则编译错。

## 3.8 坑位清单

1. **`@intCast` 编译期已知的越界 = 编译错**：不是留到运行期 panic——值能算出来就越界，直接不让你编译。要么换宽类型，要么 `@truncate`（想清楚了）。
2. **`@truncate` 只接受无符号整数**：`@truncate(@as(i32, 300))` 编译错；先 `@intCast` 到无符号再截。
3. **函数名是 `@floatFromInt`**：0.16 里没有 `@floatFrom`——从网上抄旧代码注意。
4. **`{}` 与 `{d}` 对切片/结构体会打"类型展开"**：数组、切片、指针打印必须 `{any}`（见 02 章坑位）。
5. **u3 装不下 8**：`const x: u3 = 8;` 编译错（值域 0..7 检查在编译期）——位宽类型自带护栏。
6. **浮点别用 `==`**：和老语言一样的道理；要容差比较自己写 `@abs(a - b) < 1e-9`。
