# 18 · B 树、B+ 树与倒排索引

## 18.1 动机与直觉：外存时代为什么要"矮胖"

前面第 16、17 章讨论的字典结构——跳表、哈希表、二叉搜索树、AVL 树与红黑树——都默认一个前提：每次访问一个节点的代价与一次内存比较相当。这个前提在数据驻留内存时成立，但当数据量大到必须放在磁盘（或 SSD、网络存储）上时，它就彻底失效了。

磁盘 I/O 的代价结构与内存完全不同。读写一个字节和读写一整块（通常称为一页，典型大小 4 KB 或 8 KB）的代价几乎相同，因为机械磁盘的主要开销是寻道与旋转等待，固态硬盘的主要开销是寻址与传输启动。一次随机磁盘访问的量级通常在毫秒级，而一次内存访问在纳秒级，两者相差约十万倍。这意味着：**访问次数**才是外存数据结构的优化目标，节点内部多做几十次比较几乎不要钱。

再来看二叉搜索树的身高。一棵平衡二叉树存放 n 个键时，高度约为 log₂n。n 为一亿时高度约 27，一次点查最坏需要 27 次磁盘访问，每次都是随机 I/O——约四分之一秒就花在等磁盘上。更糟的是，二叉树一个节点只存一个键，一个磁盘页里只用到十几字节，剩下四千多字节全部浪费，空间局部性完全没有利用。

B 树（B-tree，B 通常被解释为 balanced、bayer 或 Boeing，发明者 Bayer 本人倾向于不解释）给出的思路极其直接：**让每个节点恰好占一页，在一个节点里放许多个有序键和许多个孩子**。设每个节点最多放 m−1 个键、m 个孩子，树高立刻降为 log_m n 量级。同样一亿个键、m 取 100，高度约为 4：点查只需四次 I/O。树不再"细长"，而是"矮胖"，所有叶子保持在同一深度，每条根到叶路径上的 I/O 次数几乎相同——这对数据库查询计划的稳定性至关重要。

B 树的另一个关键点是**节点半满保证**。除根之外，每个节点的键数不能少于 ⌈m/2⌉−1。这不是吝啬空间，而是删除与合并算法成立的前提：它保证任何两个兄弟节点合并不超过容量，从而删除操作可以自底向上收敛。本章只实现插入，因此对这条下界只做不变量说明，不实现删除。

B+ 树是 B 树在数据库世界的"民用型号"，它做了两处看似微小、实则影响深远的改动：

1. **所有数据只存放在叶子里**，内部节点的键只是路由用的副本；
2. **叶子自左向右串成链表**，范围查询只需一次定位加顺序扫描。

第一点让内部节点更小（不携带卫星数据），一页能容纳更多路由键，树可以更矮；第二点让"找出键在 3 到 7 之间的全部记录"这类查询不必反复回到上层，沿叶链顺序读取即可，而顺序 I/O 比随机 I/O 快一个数量级以上。主流关系数据库（MySQL InnoDB、PostgreSQL B-tree、SQL Server）和大多数文件系统（NTFS、XFS、ext4 目录索引）的索引结构都是 B+ 树的工程变体。

本章最后一个主题是**倒排索引**（inverted index）。B+ 树回答的是"这个键对应哪条记录"，而搜索引擎要回答的是"这组词出现在哪些文档里"。倒排索引把映射方向倒过来：以词为键，值是包含该词的文档编号列表（称为 postings list 或倒排表）。它本质上是一个多路集合值字典，底层同样可以用 B+ 树或哈希表组织。本章用 `std::map` 加 `std::set` 实现一个最小可用版本，重点是理解"词→文档列表"这一模型以及列表的升序不变量。

本章三个数据结构共享一条主线：**控制访问结构的层数，并让每一层的局部信息尽可能密集、有序**。B 树压缩树高，B+ 树让叶子线性相连，倒排索引让一次查询只触碰命中的文档集合。

## 18.2 ADT 合同

### 18.2.1 m 阶 B 树 `BTree<K>`

`BTree` 是类模板，键类型 K 必须满足 `std::totally_ordered`（可用 `<`、`==` 构成全序）。它提供以下操作：

- `explicit BTree(int order = 3)`：构造一棵 m 阶 B 树。默认三阶即 2-3 树；order 小于 3 属于编程错误，构造抛 `std::invalid_argument`。
- `void insert(const K& key)`：插入一个键。键必须唯一，重复插入抛 `std::invalid_argument`；插入后全部 B 树不变量成立。
- `bool contains(const K& key) const`：判断键是否在树中，不修改结构。
- `std::vector<K> all_keys() const`：返回全部键，**按升序排列**（中序遍历的结果）。
- `std::vector<K> root_keys() const`：返回根节点的键，教学观察用，用来精确断言每次分裂后根的形状。

相等性判定不要求 `operator==`，而是用 `!(a < b) && !(b < a)`，这样只要类型提供严格弱序的 `<` 即可，与标准库有序容器的口径一致。

### 18.2.2 B+ 树 `BPlusTree`

教学版 B+ 树固定扇出：每个节点最多 3 个键（叶子 3 个数据键，内部节点 3 个路由键），不做模板化。操作如下：

- `BPlusTree()`：构造空树。
- `void insert(int key)`：插入整数键，重复键抛 `std::invalid_argument`。
- `bool contains(int key) const`：点查，数据只可能在叶子命中。
- `std::vector<int> range(int lo, int hi) const`：**闭区间**范围查询，返回所有满足 lo ≤ key ≤ hi 的键，升序、不重不漏；lo > hi 或区间无命中时返回空向量。

### 18.2.3 倒排索引 `InvertedIndex`

- `void add_doc(int id, std::string_view text)`：登记一篇编号为 id 的文档，text 为其全文。同一 id 不得登记两次，否则抛 `std::invalid_argument`。
- `std::vector<int> postings(std::string_view word) const`：返回包含该词的全部文档编号，**按编号升序**；未登录词返回空向量（不抛异常，因为"没有文档包含这个词"是正常查询结果）。
- `std::size_t doc_count() const`：已登记文档数。

分词规则是教学化的：以非字母数字字符为分隔符切词，每个词统一转为小写。因此 "Data" 与 "data" 视为同一个词，标点与空白不进索引。

三类类型都遵循本教程的五法则约定：凡是拥有裸指针资源的类，都实现拷贝构造、移动构造、拷贝赋值、移动赋值、析构，拷贝为深拷贝，移动后源对象为空且可安全析构。

## 18.3 设计与不变量

### 18.3.1 B 树节点：键数的上下界

B 树节点只含三个字段：是否为叶子的标记、有序键向量、孩子指针向量。叶子的孩子向量为空，内部节点的孩子数恒等于键数加一。m 阶 B 树的核心不变量是：

- 除根节点外，每个节点的键数介于 ⌈m/2⌉−1 与 m−1 之间；
- 根节点最少可以只有一个键；
- 所有叶子位于同一深度（完美平衡）；
- 节点内键严格升序，第 i 个孩子中的全部键小于第 i 个键，第 i+1 个孩子中的全部键大于第 i 个键。

插入时先沿键的顺序找到目标叶子，把新键插入叶子的有序位置。此时叶子可能有 m 个键（超出容量 m−1），于是**分裂**：取中间位置 mid = m/2（整数除法），mid 处的键提升到父节点，左侧键留在原节点，右侧键移入新建的右兄弟；内部节点分裂时还要把孩子指针按同样的分界切开。以三阶、四阶两种情形对比：

```
m = 3，mid = 1：[a b c] → 左 [a]，提升 b，右 [c]
m = 4，mid = 2：[a b c d] → 左 [a b]，提升 c，右 [d]
```

注意两种阶数下分裂点的差异是本章最容易踩的坑（见 18.7 节坑 1）：三阶树插入第 3 个键就分裂，四阶树要到第 4 个键才分裂。

递归插入函数的返回值设计成"可选的分裂结果"（提升键 + 右兄弟指针）：子节点不分裂时返回空，父节点什么都不用做；子节点分裂时，父节点把提升键插入自己的键向量对应位置、把右兄弟插入孩子向量的对应后一位置，然后检查自己是否也因此溢出。分裂一路向上吸收，若连根都分裂了，就新建一个只含提升键、两个孩子的根——树高恰好增加一层，而所有叶子仍在同一深度。

### 18.3.2 B+ 树：副本、叶链与"相等向右"

B+ 树的节点比 B 树多一个 `next` 字段，只在叶子中使用，指向右邻叶子。它的分裂规则与 B 树有本质区别：

- **叶子分裂**：4 个键对半切成左 2 右 2，没有键"消失"；提升到父节点的是右兄弟首键的**副本**，原键仍在右叶子里。随后把新叶子织入叶链：新叶子的 next 指向原叶子的旧 next，原叶子的 next 指向新叶子。
- **内部节点分裂**：4 个路由键中，中间键真正上推（移动而非复制），左节点留 2 个，右节点取最后 1 个，孩子指针按 3 段切开。

因为路由键在叶子里也有一份，路由规则必须与 B 树不同：查找时遇到相等的路由键要**继续向右**走（数据副本在右侧子树中），即比较条件是 `key <= node->keys[i]` 时推进下标。若像 B 树那样在相等处向左，就会落到永远找不到该键的子树。

叶链有两个维护时刻。其一是叶子分裂时的织入操作，如上所述。其二是**深拷贝之后**：拷贝构造逐节点复制树，但不能原样复制 `next` 指针，否则新树叶子的 next 会指向旧树的叶子。实现上让 `clone` 一律把新节点的 next 置空，拷贝完成后调用 `relink_leaves` 中序收集新树的全部叶子，再从左到右重新串链。这样不变量"每个叶子的 next 指向键序紧随其后的叶子，最右叶子 next 为空"在任何构造方式下都成立。

范围查询 `range(lo, hi)` 借助叶链只需两步：先用路由规则找到 lo 所在的叶子，然后沿叶链向右扫描，跳过小于 lo 的键，遇到大于 hi 的键立即停止。整个过程只做一次树下降，其余全是顺序扫描。

### 18.3.3 倒排索引：让有序性自然涌现

倒排索引的实现刻意简短：内部是一张 `std::map<std::string, std::set<int>>`，词到文档编号集合。这个选择把两条不变量都"外包"给了标准库：

- map 保证词按字典序排列，定位一个词是对数时间；
- set 保证文档编号唯一且升序，同一文档重复包含一个词只记一次，postings 取出即升序。

登记文档时先用 `docs_`（一个 `std::set<int>`）检查文档编号是否已存在，存在即抛异常；然后扫描文本分词，把文档编号插入每个词对应的集合。分词器逐字符扫描，遇到字母数字就累积进当前词，遇到分隔符且当前词非空就产出一个词，末尾再补产一次。字符分类与大小写转换通过先转 `unsigned char` 再调用 `std::isalnum`、`std::tolower` 完成，避免把负的 char 值直接送入这些函数（见坑 5）。

### 18.3.4 资源管理：递归的 clone 与 destroy

B 树与 B+ 树都拥有节点的裸所有权。析构与销毁沿孩子指针递归 `delete`；拷贝用递归 `clone` 复制整棵树。移动构造与移动赋值直接偷走指针并把源对象置空，不涉及节点复制。这套写法与第 11 章二叉树的 RAII 结构一致，好处是不变量集中、控制流直观；工程实现中也常用 `std::unique_ptr` 表达孩子所有权，效果等价。

## 18.4 复杂度推导

### 18.4.1 B 树高度：为什么是 log_m n

设 t = ⌈m/2⌉。根至少有 2 个孩子（当树高大于 1 时），以下每一层每个节点至少有 t 个孩子。于是深度为 h−1（叶子层）的节点数至少为 2t^(h−2)，每个叶子至少有 t−1 个键，故总键数满足

```
n ≥ 2(t−1) t^(h−2)
```

反解得到高度上界

```
h ≤ log_t ( n / (2(t−1)) ) + 2
```

即树高为 O(log_m n)。这就是"矮胖"的数学依据：分支数从 2 提高到 m，高度分母就从 1 变成 log₂m。m=100 时，存一亿键的树高度不超过 4；而同样数据量的平衡二叉树高度约 27。

### 18.4.2 各操作代价

**点查 contains**：树高 O(log_m n) 层；每层在节点内做定位。若节点内用线性扫描则每层 O(m)，总代价 O(m·log_m n)；若用二分搜索则 O(log m · log_m n)。当 m 看作与 n 无关的常数（由页大小决定）时，两者都是 O(log n)。但真正要紧的是**磁盘 I/O 次数 = 树高层数**，这正是 B 树存在的理由。

**插入 insert**：同样下降 O(log_m n) 层；无子节点分裂时只额外写一个叶子页。最坏情况分裂沿路径一直传到根，需要 h 次页读加 h 次页写，但树高只在根分裂时增加一层。内存中的比较代价与点查同阶。

**B+ 树范围查询 range**：一次树下降 O(log_m n) 定位起始叶子，之后沿叶链顺序扫描。若区间命中 k 个键，扫描代价与命中数及跨越的叶子数成线性，总代价 O(log_m n + k)，且叶链部分是顺序 I/O。相比之下，若用 B 树做范围查询，需要反复回到上层或做中序遍历，I/O 模式差得多。

**倒排索引**：设文档长度（词数）为 L，已收录文档数为 D，词表大小为 V。登记一篇文档对每个词做一次 map 定位加 set 插入，共 O(L·(log V + log D))；查询一个词的 postings 为 O(log V + k)，k 为命中文档数，取出的列表直接有序。

**空间**：B 树、B+ 树的节点半满下界保证整体空间利用率不低于约 50%，实际随机插入下通常在 67% 上下；倒排索引每出现一次"词在文档中"的关系存一个编号，同一文档内词重复只计一次。

## 18.5 完整示例输出与逐行解读

示例程序对三种结构做固定数据的精确断言，运行后输出如下（MSVC 与 clang 两通道逐字节一致）：

```
B 树（3 阶）：插入 1..10 每步全部键有序；分裂时刻根键依次为 {2}、{2}、{2,4}、{4}、{4}、{4}
B 树：contains 1..10 全中、0 与 11 未中；重复键抛异常
B 树（4 阶）对照：插 1..4 后根键 {3}（节点可容 3 键，第 4 键触发分裂）
B+ 树：插入 1..10 后 contains 全中、11 未中
B+ 树范围查询 [3,7]：3 4 5 6 7；叶链整体不重不漏为 1..10
B+ 树：重复键抛异常
倒排索引：data→1,2,3；algorithm→1,2；structure→1,3；未登录词为空
倒排索引：重复文档 id 抛异常；共收录 3 篇
自检通过
```

逐行说明：

**第 1 行**报告三阶 B 树（2-3 树）插入 1 到 10 的全过程。每插入一个键都断言 `all_keys()` 恰为当前的 1..x，即中序遍历始终有序；并在六个关键节点断言根的形状：插入 3 后叶子首次分裂、2 提升，根为 {2}；插入 4 后 4 进入右叶子，根不变；插入 5 后右叶子再次分裂，根吸收 4 变成 {2,4}；插入 7 时下层分裂一路顶穿根，旧根分裂、4 成为新根，根变为 {4}；插入 9、10 时的下层分裂均被内部节点吸收，根保持 {4}。

**第 2 行**验证点查与唯一性合同：1 到 10 全部命中，0 与 11 不命中，再次插入 5 必须抛 `std::invalid_argument`。

**第 3 行**是刻意安排的四阶对照。四阶树（2-3-4 树）一个节点可容 3 个键，插入 1、2、3 都不分裂，直到第 4 键触发分裂、3 提升，根恰为 {3}。这行的作用是把"插入第几个键才分裂"与阶数的关系钉死：三阶在第 3 键，四阶在第 4 键。

**第 4 行**验证 B+ 树点查：插入 1..10 后全部命中，11 不命中。点查一路下降到叶子才判断，内部路由键不构成命中。

**第 5 行**验证 B+ 树的招牌能力：闭区间 [3,7] 返回恰为 3、4、5、6、7；再断言 [1,10] 的全区间扫描结果恰为 1..10，证明叶链遍历不重不漏；另断言 [8,12] 越过上界只返回 8、9、10。

**第 6 行**验证 B+ 树重复键同样抛异常。重复键在下降到叶子后才被识别（路由键是副本，不能在内部层判重）。

**第 7 行**验证倒排索引的三个固定文档：data 出现在全部三篇中，postings 为 {1,2,3}；algorithm 为 {1,2}；structure 为 {1,3}；未登录词 tree 返回空列表而非抛异常。

**第 8 行**验证文档编号唯一：用已登记的 id 2 再次登记必须抛异常；doc_count 保持为 3。

**第 9 行**是全部断言通过的收尾标记。程序退出码为 0，标准错误流为空。

## 18.6 与标准库及工程实现的对照

C++ 标准库**没有**提供 B 树或 B+ 树容器。`std::map`、`std::set`、`std::multimap`、`std::multiset` 的典型实现是红黑树——一种二叉平衡树，节点小、层数多，但每个节点只需一次指针追踪，在数据驻留内存时缓存行为尚可，且实现成熟、保证严格。`std::unordered_map` 提供哈希字典，平均 O(1) 点查但不支持范围查询。

工程中若确需 B 树，常见选择有 Abseil 的 `btree_map`（B+ 树思想的内存容器，缓存友好）、各种嵌入式数据库（RocksDB、LevelDB、SQLite，LSM 树或 B+ 树）以及各大数据库服务端。LSM 树（Log-Structured Merge-tree）是 B+ 树的"写优化对手"：写入先进内存表再批量顺序刷盘、后台合并，RocksDB、Cassandra 用此结构，代价是读放大与空间放大，选型取决于读写比例。

本章倒排索引直接用 `std::map<std::string, std::set<int>>` 表达，因为教学重点是模型。真实搜索引擎（Lucene、Tantivy 等）的倒排索引会把 postings 压成紧凑的整数数组（差值编码 + 可变长整数 + 跳表块），并用 FST（有限状态转换器）做词表，以同时满足压缩率、连词查询和随机定位；理解了"词→升序列表"这一层，再看这些工程优化都是局部替换。

另外可留意 `std::map::find` 与本 B 树 `contains` 在比较口径上的一致：两者都只依赖 `<`，相等以"互不小于"定义。若将来给 B 树换键类型（如字符串、自定义记录），只需提供严格弱序，不要在相等判定上引入浮点 NaN 一类不满足全序的值——本章模板用 `std::totally_ordered` 概念在编译期挡住了这类误用。

## 18.7 坑位

### 坑 1：三阶与四阶的首次分裂时刻

**现象**：按"插 4 后首次分裂、提升 3"的描述写三阶树断言，程序在插入 3 时就分裂、根为 {2}，断言失败。

**原因**：m 阶节点容量是 m−1 个键。三阶树容量 2，插满 3 个键即分裂，mid = 3/2 = 1，提升第 2 个键；四阶树容量 3，要到第 4 个键才分裂，mid = 4/2 = 2，提升第 3 个键。"插 4 分裂、提升 3"是四阶（2-3-4 树）的行为。

**后果**：分裂点、提升键、根形状全部错位一个键位，后续每次分裂的断言都会连环失败。对策是固定阶数后亲手推一遍首次分裂，并用本章示例中的四阶对照实验交叉验证。

### 坑 2：B+ 树在相等路由键处向左走

**现象**：B+ 树插入若干键后，明明在叶子里的键 `contains` 却返回 false。

**原因**：把 B 树的路由规则（相等即落在左侧）照搬到 B+ 树。B+ 树叶子分裂时提升的是右叶子首键的副本，该键的数据在**右侧**子树；路由必须用 `key <= keys[i]` 时继续向右推进。

**后果**：查找落入不包含该键的左子树，点查与范围定位同时出错，且错误只在分裂发生后才出现，小规模测试容易漏网。

### 坑 3：叶子分裂提升"移动"而非"复制"

**现象**：B+ 树分裂后全树键数对不上，`all_keys` 或叶链扫描丢键。

**原因**：叶子分裂时若按内部节点（或 B 树）的做法把中间键移走，叶子里就少了一个数据键；B+ 树要求数据只在叶子、且每个键都能在叶链找到，叶子分裂必须**复制**右叶首键上推，原键保留。

**后果**：树中出现"只在内部、不在叶子"的孤儿键，范围扫描与点查不一致；而内部节点分裂又恰好相反，必须移动提升——两种分裂规则不能混用。

### 坑 4：拷贝后叶链指向旧树

**现象**：拷贝构造一棵 B+ 树后，修改或销毁原树，新树的范围查询串到旧节点，甚至访问已释放内存。

**原因**：深拷贝逐节点复制了键和孩子，却把 `next` 指针原样照抄，新叶子链到的是旧叶子。

**后果**：跨对象别名导致数据竞争或悬垂指针，且通常只在"拷贝后原对象析构、再做范围查询"的序列下崩溃，极难排查。对策是 clone 时一律置空 next，拷贝完成后按中序收集叶子重新 relink。

### 坑 5：把带符号 char 直接送入字符分类函数

**现象**：分词器处理含非 ASCII 字节（中文 UTF-8、高位扩展字符）的文本时，在某些平台/编译器优化级别下触发断言或得到错误分类。

**原因**：`std::isalnum`、`std::tolower` 要求参数可表示为 unsigned char 或等于 EOF；char 为有符号类型时，负字节传入属于未定义行为。

**后果**：轻则切词结果错误（中文文本被切成空词或并词），重则在调试 CRT 下直接 abort。规范写法是先 `static_cast<unsigned char>(ch)` 再调用。本章分词器即按此实现；副作用是非 ASCII 字节统一被当作分隔符，中文词需另行按 UTF-8 解码分词。

### 坑 6：assert 宏参数中的花括号逗号

**现象**：`assert(bpt.range(8, 12) == std::vector<int>{8, 9, 10});` 在 MSVC 下报 C4002（assert 参数过多）和 C3329 语法错误。

**原因**：传统预处理器在划分宏参数时，花括号不保护逗号，`{8, 9, 10}` 中的逗号被当成了宏参数分隔符；圆括号才保护。

**后果**：仅在该编译单元、该断言处报看似不可理喻的语法错误。对策是整个比较表达式再裹一层括号：`assert((expr == std::vector<int>{...}));`。凡向 assert 传含花括号初始化的表达式，都应双括号书写。

### 坑 7：忘记根节点豁免键数下界

**现象**：实现删除或初始化校验时，只有一两个键的小树被判定为"非法 B 树"。

**原因**：半满下界（不少于 ⌈m/2⌉−1 个键）只约束**非根**节点；根节点允许从 1 个键起步，否则空树与第一次插入后无法过渡，树也永远无法从根开始生长。

**后果**：删除合并算法会错误地合并根、层数管理紊乱。本章虽未实现删除，但根分裂后新根只有一个键，正是这条豁免的直接体现，阅读不变量时应一并记住。
