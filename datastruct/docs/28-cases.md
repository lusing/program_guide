# 28 · 综合案例：把 27 章的结构用成真软件

## 28.1 动机与直觉：一场"本领盘点"

前二十七章各自为战：线性表管存储、树管层级、图管关系、算法设计策略管求解。本章不再引入新结构，而是把四个真实的软件问题放到同一张桌上，看它们各自调用哪些章的本领。这是全书唯一的"综合演练场"——只读前二十七章的正文、不打开任何示例目录，也应该能顺着本章的引用把每个解法的来龙去脉捡起来。

四个案例的"本领盘点"：

- **文件归并最小代价**：n 个有序文件两两归并成一个，归并两个长度 a、b 的文件要搬 a+b 个记录，问归并顺序如何使总搬动量最小。答案是 Huffman 归并——每次合并当前最小的两个。它正是第 15 章哈夫曼树的直接应用：把每个文件长度当叶子权，归并树的每一层对应一次搬动，最小总代价 = 最优 WPL。底层结构是第 13 章的小顶堆。
- **数岛**：01 网格里上下左右相连的 '1' 算一块陆地，数出岛数。这是《新编数据结构案例教程》第 10 章"传染病问题"（菌群向八方向扩散计数）与迷宫问题的近亲——网格即隐式图，格子是顶点、相邻是边，数岛就是数连通分量。解法是第 19 章的图遍历（BFS 洪水填充）；第 12 章的并查集是另一条路。
- **工程进度（AOE 网关键路径）**：活动有先后依赖，问总工期最短多少、哪些活动一刻不能拖延。这是第 20 章关键路径推导的完整落地：拓扑排序定次序、正序推最早时间、逆序推最晚时间、`最早==最晚` 标记关键活动。
- **多位整数计算器**：字符串表达式含四则与括号，求值。第 07 章调度场算法的完整版：操作数栈 + 运算符栈，优先级与括号一网打尽。

这四题也是 ACM 入门题与考研综合题的常客——它们不考新知识，考"把已知结构认出来"的眼力。读完本章应建立一个条件反射：看到"每次取最优"先想堆，看到"网格 + 相邻"先想图遍历，看到"先后依赖 + 最长/最短"先想拓扑排序，看到"表达式求值"先想栈。

## 28.2 ADT 合同

四个函数的全部前置/后置条款如下。编程错误（违反前提）一律抛 `std::invalid_argument`。

**`merge_file_cost(file_sizes)`**

- 前提：每个元素为正；元素个数 < 2 时视为无需归并。
- 后置：返回把全部文件合并成一个的最小总代价；输入序列不被修改。
- 合同要点：代价口径是"每次归并两堆的记录搬运量之和"，与《用C++实现数据结构程序设计》外排序一章的"归并趟数 × 记录数"口径不同——本章按逐次合并计。

**`island_count(grid)`**

- 前提：网格非空（空网格返回 0）、每行等长、只含字符 '0' 与 '1'。
- 后置：返回四连通 '1' 块的个数；不改输入。
- 合同要点：连通按**四方向**（上下左右）计；若题面改为八方向（含斜角），岛数会变——合同必须写清连通定义，这是数岛类题目最容易漏的条款。

**`project_schedule(edges, n)`**

- 前提：`n > 0`；边 `{from, to, dur}` 的顶点编号在 `[0, n)`、工期为正；顶点 0 是唯一入度为 0 的源点；图无环。
- 后置：`critical_length` 为从源点出发的最长路径长（总工期）；`critical_path` 为一条从 0 出发沿关键活动走到终点的顶点序列；等价关键路径不止一条时取"下一顶点编号最小"的那条（保证确定性）。
- 合同要点：含环抛异常——AOE 网的前提本就是 DAG，第 19 章 Kahn 排序顺便完成了环检测。

**`calculator_full(expr)`**

- 前提：表达式只含非负整数、`+ - * / ( )` 与空格；语法合法；除数非零。
- 后置：返回整型值；除法向零截断（C++ 整型除法语义）；语法错误、括号不匹配、除零均抛 `std::invalid_argument`。
- 合同要点：不支持一元负号（`-3` 属非法）——教学实现守住"操作数栈每个运算符恰好弹两个数"的简单不变量；工程扩展留给习题。

## 28.3 设计与不变量

### 28.3.1 文件归并：小顶堆上的 Huffman

把"归并两个文件"看成树里两个孩子生出父亲：叶权为文件长度，每次归并的代价是两权之和，总代价恰是所有叶子权 × 深度之和，即 WPL。第 15 章已证：WPL 最优 ⇔ 每次合并当前最小的两堆（可用交换论证：若最小两堆不在最深层，与更深处的权交换不增总代价）。于是算法一句话：小顶堆里反复"弹两个最小、合并、塞回去"。

不变量只有一条：**堆中每个元素代表"一个待归并堆的长度"**，弹两次并一次后该不变量保持，堆大小减一。堆为单元素时结束。

这个结构与第 15 章哈夫曼编码的差别只在"叶子是什么"：那里叶子是待编码的字符、权是频度；这里叶子是待归并的文件、权是文件长度。同样的"贪小并大"之所以都对，是因为两者共享同一个数学骨架——**带权路径长最小的 k 叉树必然把小权放深处**，与叶子装的是什么毫无关系。这正是"算法"高于"题解"的意义：认出骨架，题目随便换皮。

### 28.3.2 数岛：洪水填充与"visited 防

逐格扫描，遇到未访问的 '1' 就是新岛：计数加一，从这个格子做 BFS 把整块陆地全部标记，之后的格子自然跳过。两个不变量：① 任何 '1' 格要么未访问、要么已属于某个已计数的岛；② 队列里只进 '1' 格。b3-10 传染病一节反复强调的"递归向四周发散时必须排除已检查点，否则死循环"在此落地为 `visited` 数组——BFS 的入队即标记写法从根上杜绝重复入队。

与并查集的对比：并查集版把每对相邻 '1' 做 union，最后数根的个数。代码量相近；洪水填充的优势是"发现即完成"（一遍扫描内出答案），并查集的优势是支持**动态加格**（逐行流入的网格流式数岛）。静态网格本章选 BFS。

### 28.3.3 AOE 关键路径：20 章推导的三步机械动作

复用第 20 章的记号：事件最早时间 `ee[v]`（源点 0 起沿最长路）、最晚时间 `lt[v]`（终点从总工期倒推）。三步：

1. **Kahn 拓扑排序**（第 19 章）：既得处理次序，又顺手验环——排序不满 n 个顶点即有环，抛异常。
2. **正序推 ee、逆序推 lt**：`ee[v] = max(ee[u]+d)`、`lt[u] = min(lt[v]-d)`，初值 `lt = 总工期`。数组初始化与遍历方向就是这两条递推式的"代码化"。
3. **沿关键活动走**：活动 `(u,v,d)` 关键 ⟺ `lt[v] - d == ee[u]`（最早开始 == 最晚开始）。从源点 0 出发，每步在关键活动里选编号最小的下一顶点，走到无出边为止。

示例图 6 顶点 8 边：`0→1(3), 0→2(4), 1→3(5), 1→4(2), 2→3(6), 2→4(7), 3→5(4), 4→5(3)`。手推：`ee = [0,3,4,10,11,14]`，总工期 14；`lt = [0,5,4,10,11,14]`。顶点 1 的松弛 = `lt-ee = 2`——它有 2 个时间单位的缓冲；关键路径在顶点 2 处分岔（`2→3` 与 `2→4` 都关键），平局规则取编号小者，得 `0→2→3→5`。**两条关键路径长度相等是常态而非巧合**——这正是关键路径管理中"多线并行都拖不得"的数学表达。

### 28.3.4 计算器：双栈与优先级

第 07 章调度场法的求值变体，两个栈各司其职：

- **操作数栈**：只进整数（多位数边扫边累积 `v = v*10 + 位`）；
- **运算符栈**：进运算符与 `(`。入栈新运算符前，把栈顶优先级 ≥ 新者的先弹出来算掉——左结合由此保证（`100/5/2` 先算 `100/5` 得 20 再除 2）；`)` 则一路弹到 `(`。

不变量：任何时刻"已读前缀若补上若干 `)` 恰好算清"——栈里运算符与操作数的个数满足"每个待算运算符下方有两个现成操作数"。`apply` 前检查 `operands.size() >= 2`，被破坏时抛异常而非静默出错。除零在 `apply` 里拦截，抛 `std::invalid_argument`，main 里 catch 成布尔断言。

除法语义单说一句：C++ 整型除法**向零截断**（`-7/2 == -3`），与数学下取整不同；本章操作数非负所以无感，但合同里写明，防止读者拿去算负数。

## 28.4 复杂度推导

| 案例 | 时间 | 空间 | 主导项来源 |
|---|---|---|---|
| 文件归并 | O(n log n) | O(n) | n-1 次归并 × 每次 O(log n) 堆操作 |
| 数岛 | O(rows×cols) | O(rows×cols) | 每格入队出队至多一次 |
| AOE 关键路径 | O(V+E) | O(V+E) | 拓扑 + 两遍 DP + 走路径各线性 |
| 计算器 | O(len) | O(len) | 每字符进出栈至多一次 |

四个案例全部"一遍扫描 + 常数级每步"或"堆序操作"，没有一处隐性平方——这不是巧合而是选择：综合案例的意义就在于示范**结构选对了，代码自然线性**。反例是数岛的朴素"每岛重扫全网格"（O(n²)）与计算器的"每对括号重扫"（O(n²)），第 19/07 章分别给过正确姿势。

## 28.5 完整示例输出

```text
文件归并：[5 9 12 13 8] 最小总代价 107（13+21+26+47）
文件归并边界：空表与单文件代价 0
数岛：5x5 网格共 3 座岛
AOE 关键路径：总工期 14，路径 0 2 3 5
AOE 边界：含环图抛出异常
计算器：( 3 + 4 ) * 2 = 14；100 / 5 / 2 = 10；7 + 3 * 2 = 13
计算器异常：除零与非法字符均抛出 std::invalid_argument
自检通过
```

逐行解释：

- 第 1 行：归并序 5+8=13 → 9+12=21 → 13+13=26 → 21+26=47，四次代价合计 107；assert 逐位写死。
- 第 2 行：不足两个文件没有"归并"可言，返回 0——边界条款进断言。
- 第 3 行：`11000/10001/00011/00000/00100` 中 (0,0)(0,1)(1,0) 连一块、(0,4)(1,4)(2,4)(2,3) 连一块（(0,4) 与 (1,4) 上下相邻）、(4,2) 独一块，共 **3** 座。
- 第 4 行：28.3.3 的手推值——总工期 14、路径 `0 2 3 5`；顶点 1 松弛 2 被断言外的正文记账。
- 第 5 行：`{0→1, 1→0}` 有环，Kahn 排不满，异常拦截。
- 第 6 行：三组求值分别验证括号、左结合除法链、乘加优先级。
- 第 7 行：`9/0` 与 `3 + a` 两类异常均被 catch 为真。
- 第 8 行：全部断言通过后的收官标记。与全书各章一致，"自检通过"由构建脚本逐字节核对——四个案例的每个期望值都先手算再写进 assert，程序只是复核人脑。

本章是全教程最后一篇正文。回头看：案例没有引入任何新结构，却有四段全新代码——因为**软件工程的真实难度从来不在"知道结构"，而在"认出该用哪个结构、并把它的不变量守住"**。带着这个习惯去读标准库源码或设计自己的模块，二十八章的目的就达到了。

## 28.7 与标准库的对照

- `std::priority_queue<int, std::vector<int>, std::greater<int>>`：本章文件归并的现成小顶堆——三个模板参数分别是元素、底座、比较器；`std::greater` 让最小的先出队。手搓版见第 13 章。
- `std::accumulate`：归并总代价也可写成对"每次归并代价"的折叠；语义上 `total += a+b` 的循环更直白，教学保留显式循环。
- `std::max_element`：AOE 里取总工期直接用；返回迭代器注意解引用。
- `std::string_view`：计算器与数岛都以它收字符串——只读不拷贝，接口成本最低；所有权归调用方，这正是第 01 章"合同"思想的接口化。
- `std::queue` / `std::vector` 当栈：BFS 队列与计算器双栈的标准件；`std::stack` 的适配器语法见第 07 章 std 对照。
- `std::invalid_argument` / `std::runtime_error`：标准异常族的分工——参数检查失败（语法错、越界、除零）用 `invalid_argument`，运行条件不满足用 `runtime_error`；本章全部归入前者以简化 catch，工程上按语义细分更好。
- 四个案例都没有更"高级"的标准设施——表达式求值、图算法、网络流这类领域问题，标准库只给积木不给成品；本教程 27 章教的就是把积木搭成品的图纸。

## 28.8 本章坑位

- **坑 1：数岛连通方向与题面不符。** 现象：按八方向数得 2 座，题意四方向应为 3 座（或反之）。原因：合同没写清"上下左右"还是"含斜角"。后果：答案系统性偏差且不易察觉。防法：函数注释与合同先写连通定义，测试网格里放一个"斜角相邻但四向不通"的例子（本章 (0,4) 与 (2,3) 一块正因 (1,4) 充当竖桥）。
- **坑 2：BFS 入队时不标记、出队时才标记。** 现象：同一格重复入队，网格大时队列膨胀数倍。原因：标记滞后于入队。后果：性能退化，最坏 O((RC)²)。防法：入队即置 visited（28.3.2 的写法），这是与"出队标记"差一拍的经典教训。
- **坑 3：AOE 最晚时间初始化错。** 现象：`lt` 初值置 0 或置 INT_MAX 忘减。原因：`lt[u] = min(lt[v]-d)` 需要终点初值 = 总工期。后果：全部 lt 为 0 或溢出，关键活动判定全错。防法：`lt` 先整表初始化为 `critical_length` 再逆序递推。
- **坑 4：关键路径只判 `lt[v]-d == ee[u]` 不验 `ee[v]==lt[v]`。** 现象：路径走到一半拐进有松弛的支路。原因：活动关键只保证"这件事不能拖"，不保证顶点在最长路上。后果：critical_path 长度小于总工期对应的路径。防法：两个条件都查（本章实现如此）。
- **坑 5：计算器忘写"栈顶优先级 ≥ 新者才弹"中的等号。** 现象：`100/5/2` 算成 `100/(5/2)`。原因：同优先级没先弹，右结合了。后果：左结合运算符（减、除）结果错。防法：`>=` 一个字符，测试必含除法链。
- **坑 6：多位数漏了"边扫边累积"。** 现象：`100` 被当成三个操作数 1、0、0。原因：按单字符处理数字。后果：表达式语义全错。防法：读到数字后连续吞到非数字，`v = v*10 + (c-'0')`。
- **坑 7：merge_file_cost 对空/单元素抛异常。** 现象：调用方传单文件报错。原因：把"不足两个"也当编程错误。后果：合同过窄不可用。防法：返回 0（无需归并），把异常留给负数大小这类真前提违规。
- **坑 8：`std::print(" {}", v)` 循环后忘记收尾换行。** 现象：路径打印与下一行输出黏在同一行。原因：`std::print` 不带换行，循环里没有地方放 `std::println("")`。后果：输出格式破坏，逐字节比对失败。防法：循环打印后补一次 `std::println("")`（本章 main 的写法），或先拼字符串再一次 println。
