# 05 · 链表族：用指针把节点串起来

## 5.1 动机与直觉：排队时不必所有人挤在一起

上一章的 ArrayList 把元素塞进一整块连续内存，按下标访问飞快，但在中间插入要把后面的元素整体搬家。设想一个生活场景：同学们排成一队等车，队伍中间突然插入一个人，需要让后面所有人往后挪一步吗？不需要——插队的人只需站进空隙，前后两人各记住"我前面/后面现在是谁"即可。队伍里的人可以站得松松垮垮，甚至彼此相隔很远，只要每个人都知道"下一个人在哪"，队伍就没有散。

**链表（linked list）**就是按这个思想组织的线性表。每个**节点（node）**由两部分组成：存放数据的部分，和记录"下一个节点在哪"的**链接（指针）**。节点不必连续，可以散落在内存各处，元素间的关系完全由指针表达。

本章实现三种链表，它们的区别只在"每个节点握有几个方向的线索、线索在末端如何收尾"：

- **单向链表**：每个节点只知道后继，像一串只能顺着念的佛珠；
- **双向链表**：每个节点同时知道前驱和后继，可以倒着走；
- **循环链表**：最后一个节点的线索不悬空，而是绕回头节点，首尾相接。

学完本章你应该能回答三个问题：插入/删除为什么在链表里便宜；为什么单链表"找前面的元素"很别扭；环形结构在销毁时为什么必须先"断环"。

## 5.2 ADT 合同

三种链表共享同一组线性表语义，但各自允许的走法不同。

**SinglyList&lt;T&gt;（单向链表）**

- `push_front(v)` / `push_back(v)`：在表头/表尾加入元素；
- `pop_front()`：移除表头元素，前提表非空，否则抛 `runtime_error`；
- `insert(pos, v)`：在位置 `pos`（0 ≤ pos ≤ size）插入，`pos` 越界抛 `out_of_range`；
- `erase(pos)`：删除位置 `pos`（0 ≤ pos < size），越界同样抛异常；
- `front()`、`size()`、`empty()`：观察操作；
- `reverse()`：就地反转链接方向；
- 提供只能前进的前向迭代器，支持范围 for。

**DoublyList&lt;T&gt;（双向链表）**

- 合同在单向版基础上增加 `pop_back()`、`back()`，以及可前进可后退的双向迭代器（含 `rbegin()`）；
- `insert/erase` 语义相同，但在双向链上定位后，前驱后继都要重新接线；
- 自由函数 `merge_sorted(a, b)`：把两个升序双链合并成一个新的升序双链，不修改输入；平局先取 `a` 的元素，结果因此唯一。

**CircularList&lt;T&gt;（循环单链表）**

- 提供 `push_back`、`rotate`、`front`、`size`、`empty`；
- `rotate()` 把"表头"沿环推进一格：原表头变成新表尾；
- `to_vector()` 按从头到尾顺序导出内容，供观察与断言。

空容器上的 `pop`/`front` 都属于**编程错误**（调用方违反前提），按全教程约定抛标准异常，而不是返回一个哨兵值——因为对任意 T 都未必存在合适的哨兵。

## 5.3 设计与不变量

### 5.3.1 节点：数据加一根"接力棒"

单链表的节点只有两个字段：

```cpp
struct Node {
    T data;
    Node* next;   // 后继；最后一个节点为 nullptr
};
```

`next` 就是那根接力棒。注意它是**地址**而不是下标——节点之间不需要相邻，只要后继地址正确，关系就成立。链表对象自身只保存极少数"入口"指针；我们的单向实现保存 `head_`（表头入口）与 `tail_`（表尾快捷方式）以及 `size_`。

### 5.3.2 单链表的三条不变量

读链表代码，先记住对象在任何一刻必须满足的约定：

1. 从 `head_` 沿 `next` 走，恰好经过 `size_` 个节点后遇到 `nullptr`；
2. `tail_` 是那个 `next == nullptr` 的节点（空表时 `head_ == tail_ == nullptr`）；
3. 每个节点有且仅有一次被计数，不存在自交的环。

所有操作都只是"在局部改变几根指针 + 维护 size_",改完后必须复查这三条仍成立。以表头插入为例，新节点接过旧表头的地址成为新入口，顺序绝不能写反：

```cpp
head_ = new Node(v, head_);   // 新节点的后继是“旧表头”
if (tail_ == nullptr) tail_ = head_;  // 空表时它也是尾
```

若先修改了 `head_` 再去取旧表头，整条旧链的入口就永久丢失了——这是链表第一常见的错误。删除表头则相反：先把旧表头摘出来、移动入口，最后 `delete`：

```cpp
Node* dead = head_;
head_ = head_->next;   // 入口先移走，否则找不到后继链
if (head_ == nullptr) tail_ = nullptr;
delete dead;
```

### 5.3.3 定位插入与删除：单链表为什么要从表头走

在位置 `pos` 插入，本质是把新节点"夹"进 `pos-1` 号节点与其后继之间：

```cpp
Node* prev = node_at(pos - 1);
prev->next = new Node(v, prev->next);
```

右边的 `prev->next` 在赋值发生前求值，于是新节点的后继正确指向原后继；赋值再让前驱改指新节点。两行字段、两次重接，与表长无关——**前提是你已经站在 `prev` 节点上**。而单链表只能从头沿 `next` 走到 `prev`，这要 O(pos) 步。这正是链表与数组的角色互换：数组定位是 O(1)、插删要搬家 O(n)；链表走到位置要 O(n)、走到之后插删是 O(1)。

`node_at` 这个辅助函数也解释了为什么单链表删除节点需要"前驱"：节点自己不知道前驱是谁，无法把自己摘出去。要删 `pos` 号，必须先站在 `pos-1` 号上。

### 5.3.4 反转：三指针的接力

`reverse()` 不复制数据，只逐节点调转 `next` 的方向。维护三个指针：前驱 `prev`、当前 `cur`、暂存的后继 `next`。`next` 必须提前保存——因为一旦 `cur->next = prev`，原后继的地址就没别的地方可找了：

```cpp
Node* next = cur->next;  // 先保存
cur->next = prev;        // 掉头
prev = cur; cur = next;  // 整体推进
```

反转后入口互换：新表头是旧表尾，新表尾是旧表头，所以实现开头先让 `tail_ = head_`，循环结束再让 `head_ = prev`。

### 5.3.5 双向链表：多一根指针，换来自由后退

双向节点多一个 `prev` 字段。它的不变量是对称的两条"回指"：

- 对非头节点 x：`x->prev->next == x`；
- 对非尾节点 x：`x->next->prev == x`。

这意味着每次插入要接四根线、每次删除要让两侧直接相连。删除中间节点只需让它的前驱与后继互相认识，然后释放节点：

```cpp
dead->prev->next = dead->next;
dead->next->prev = dead->prev;
delete dead;
```

多占的指针空间换来两件事：可以反向遍历；删除"已知指针的节点"时不必再从头找前驱——这也是 std::list 选择双向链接的核心原因。

### 5.3.6 有序链合并

`merge_sorted` 模仿归并排序的合并步：两个迭代器分别站在两链表头，每次把较小元素追加到结果链，平局取左链。与 std::list::merge 会"掏空"右链不同，我们的版本不修改输入，便于在教学中反复断言"输入链完好"。代价是结果链是新复制的节点。

### 5.3.7 循环链表：首尾相接与"先断环再销毁"

循环链表中尾节点的 `next` 不为空，而是指回头节点，全链成环。只保存一个 `tail_` 指针就够用：头节点是 `tail_->next`，尾插 O(1)，头取也是 O(1)。旋转即让"表头"沿环前进一格：`tail_ = tail_->next`——原来的头节点就此成为新表尾。

环形结构最大的陷阱在**析构**。普通链可以 `while (p != nullptr)` 逐个删除；环上没有 `nullptr`，这样写要么永远转圈、要么漏删。正确做法是先断开环、再按普通链释放：

```cpp
Node* head = tail_->next;
tail_->next = nullptr;   // 断环：尾节点不再回头
while (head != nullptr) { ... delete ... }
```

拷贝构造同样要小心：沿环走时终止条件是"走了 size_ 步"而不是"回到某指针"，且从空表拷贝时不能进入循环。

### 5.3.8 关于哨兵节点的取舍

许多教材在链表头部放一个不存数据的**哨兵（sentinel）节点**，令"空表"与"非空表"的插入删除代码完全统一，免去大量边界判断。本教程的实现不用哨兵，理由是教学上要让"空表"这个边界可见、可讨论；代价是首尾操作要分别处理空表情形。两种写法没有对错，阅读标准库与开源代码时二者都会遇到。

## 5.4 复杂度推导

设 n 为表长。

- **表头插删（三种链共同）**：只重接常数根指针，O(1)。
- **表尾操作**：维护了 `tail_` 后，单向链表的尾插也是 O(1)；双向链表的尾删 O(1)，而单向链表若要尾删，仍需走到 n−1 号，O(n)。
- **定位 insert/erase**：走到 `pos` 需 O(pos)，重接本身 O(1)，整体 O(n)。
- **reverse**：每个节点访问一次，O(n)，额外空间 O(1)。
- **merge_sorted**：两链每个节点恰好比较处理一次，O(n₁+n₂)，结果占 O(n₁+n₂) 新空间。
- **rotate**：移动一个指针，O(1)。
- 空间：节点本身 O(n)，外加每节点 1（单向）或 2（双向）根指针。

一句话记忆：**链表把数组"定位便宜、插删贵"的账本整个翻了过来。**

## 5.5 完整示例输出

```text
单向链表增删后：1 2 3
头删后再反转：3 2
双向链表正向：1 2 3 4
双向链表反向：4 3 2 1
删除中部元素后：1 3 4
两有序链合并：1 2 3 4 7 8
旋转一格后：2 3 4 1
副本析构后原表完好：2 3 4 1
自检通过
```

逐行看验证了什么：

- 第 1 行：头插、尾插、定位插入再删除后内容精确为 `1 2 3`——每一步接线都保持了不变量；
- 第 2 行：头删去掉 1，反转把 `2 3` 掉成 `3 2`，证明三指针反转正确处理了入口互换；
- 第 3、4 行：同一条双链正向、反向走出互为镜像的序列，双向回指成立；
- 第 5 行：删除中部的 2 后，1 与 3 直接相连，`1 3 4` 无缺口；
- 第 6 行：合并结果 `1 2 3 4 7 8` 全局有序且元素总数守恒（3+3=6）；程序还断言两条输入链长度不变；
- 第 7、8 行：循环链旋转一格后序列轮转；随后在内层作用域拷贝一份并让其析构，第 8 行证明析构既没有死循环也没有误伤原表——断环逻辑正确。

## 5.6 与标准库的对照

- `std::forward_list&lt;T&gt;` 对应单向链表：只提供向前迭代器，出于空间考虑**故意不维护 size**（标准不保证 size O(1)），插入用 `insert_after`/`erase_after`——因为单链删除必须站在前驱上。
- `std::list&lt;T&gt;` 对应双向链表：双向迭代器、O(1) 的 `splice`（把一段链整体摘接到另一处，不复制元素）与 `merge`、`sort`。它选择双向，正是因为"已知节点的 O(1) 删除"和反向遍历在实际工程中需求强烈。
- 循环链表没有独立的标准容器；需要环形语义时通常用 `std::list` 加游标，或自实现。
- 标准链表的节点分配通过**分配器（allocator）**参数化，而非直接 `new`；本教程固定用 `new`/`delete`，把注意力集中在链接关系上。

选用经验：需要稳定的迭代器地址（插删不失效其他迭代器）、频繁在已知位置插删或拼接，用 `list`；只需单向且极致节省空间，用 `forward_list`；需要随机访问就回到 `vector`。

## 5.7 本章坑位

- **坑 1：修改入口前没保存旧链。** 现象：链表插入删除后整段链丢失、内存泄漏。原因：先覆盖了 `head_` 或某节点的 `next`，旧地址再无记录。后果：后继节点永远无法访问也无法释放。防法：牢记"先连新线、再断旧线",删除时先摘出节点。
- **坑 2：反转时不暂存后继。** 现象：`reverse()` 后链表断成一截。原因：`cur->next = prev` 覆盖了原后继地址。后果：只能处理一个节点。防法：循环开头先 `Node* next = cur->next`。
- **坑 3：环形析构直接 while 判空。** 现象：程序卡死或节点泄漏。原因：环上没有 nullptr 作为终止。后果：死循环或漏删。防法：先 `tail_->next = nullptr` 断环，再逐个释放。
- **坑 4：维护 tail 却忘记同步。** 现象：尾插后 `tail_` 仍指旧节点，或删除唯一节点后 `tail_` 悬空。原因：只改了局部指针，没复查全局不变量。后果：后续尾插丢链、解引用野指针。防法：每次操作后对照不变量逐条检查空表与唯一节点两种情形。
- **坑 5：误以为链表定位也很快。** 现象：在循环中反复按位置访问链表，性能比数组差几个数量级。原因：每次定位都要从头走。后果：O(n) 的操作被嵌进 O(n) 循环变成 O(n²)。防法：链表只在"一次走到、就地处理"的模式下使用，或保存目标节点的迭代器。
