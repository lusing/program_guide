# 26 · 回溯：系统性地试错

## 26.1 动机与直觉：把"所有可能"组织成一棵树

有些问题没有已知的巧妙公式：八皇后有几种摆法？图能用 3 种颜色染色吗？背包恰好装满某些物品的组合是哪些？这类问题的共同点是——解都藏在一片巨大的"可能组合"里，而有效的通用策略只有一个：**有组织地枚举**。

直觉先从生活里找：走迷宫时你不会每次都从入口重新出发。你沿一条走廊走到死胡同，**退回最近的一个岔路口**，换一条没走过的走廊继续。这条路走到头再退、再换——只要迷宫有限，你终将踏遍每条可达的路。回溯法（backtracking）就是这个过程的精确化：**深度优先地试探每一种选择，发现走不通就撤回最近的选择，换下一个候选**。

Sahni 教材把方法总结为三步，值得原文照录进脑子里：

1. 定义一个**解空间**（solution space），它包含问题的全部候选解；
2. 把解空间组织成树或图，使搜索容易进行——按"子集"组织的是**子集树**，按"排列"组织的是**排列树**；
3. 用**深度优先**搜索该空间，用**限界函数**（bounding function）避免走进不可能产生解的子树。

第 3 步里的"限界"就是回溯与朴素暴力枚举的全部区别。n 个物品的 0/1 背包解空间有 2ⁿ 个节点，n=100 时约 10³⁰——逐个枚举到宇宙热寂也跑不完；但约束与限界函数能在树的中途整枝剪掉，实际搜索的往往只是解空间的一个极小角落。**剪枝不是正确性的需要，而是可行性的需要**：不剪枝的回溯也正确，只是跑不完。

与前面章节的血脉关系：递归（第 03 章）提供了"自己调用自己处理更小子问题"的机械；图的深度优先遍历（第 19 章）提供了"沿一条路走到底再回头"的遍历次序。回溯 = 在一棵**隐式的**解空间树上做 DFS——树不必真建出来，递归调用栈就是当前路径。本章四个问题共享同一副骨架，读完应当能"认出"任意新问题里的这副骨架。

名字里的"回"字点出了方法的本质动作：前进是"做选择"，回头是"撤销选择"。学完第 14 章你再回看"撤销"二字的分量——左高树的 meld 沿右路径前进，不合适就交换左右；回溯沿树路径前进，不合适就退一步换候选。算法世界里大量"聪明的搜索"，剥开外壳都是**前进/后退两个动作加上什么时候后退的判断**。本章判断的依据是约束与限界，27 章会换成更精明的上下界，前进后退的机械完全不变。

一个工程细节贯穿全章：**枚举次序必须固定**。候选列按 0..n-1 升序、颜色按编号升序、物品按"先装后不装"——次序固定，解的产出次序才固定，程序的输出才能逐字节复现、断言才能写死。这不是洁癖：无法复现的搜索结果在测试与验收中一文不值。

最后回答"什么问题适合回溯"。三个信号：① 解是**一串决定**（每步从有限候选里挑一个），能自然排成树的一层；② 能写出**便宜的约束判定**——不用等到叶子才验收，中途就能宣判死刑；③ 需要**全部解、精确计数或保证最优**，而非一个"大概率不错"的答案。三信号齐备，回溯几乎是默认选择；只缺第 ② 条（约束只能最后验证）时剪不动枝，往往要靠分支限界的另一套限界思路补救——这正是 27 章的动机之一。

## 26.2 ADT 合同

本章四个函数都是"计数或列出解空间中合格成员"的纯函数：不改全局状态、不依赖输入次序以外的任何环境。合同如下：

| 函数 | 前提 | 后置 | 违规行为 |
|---|---|---|---|
| `queens(n)` | n ≥ 0 | 返回 n 皇后解的总数；n=0 约定为 1（空摆法），实现里 n≤0 返回 0 并在正文说明 | 无异常路径 |
| `colorings(colors, edges, n)` | colors ≥ 0；边的端点在 [0,n) 内 | 返回合法着色方案数；顶点按编号着色、颜色按升序尝试 | colors<0 或端点越界抛 `std::invalid_argument` |
| `knapsack_bt(values, weights, cap)` | 两数组等长且元素均非负 | 返回最优价值与物品下标表（升序）；等值多解取下标字典序最小者 | 长度不一致抛 `std::invalid_argument` |
| `subset_sum_lists(a, target)` | 无（含负元素自动关闭剪枝） | 返回全部解，每个解为升序下标表，解之间按字典序排列 | 无异常路径 |

两条贯穿性条款值得单独强调：

- **确定性条款**：凡"多解取哪个"的场合（背包等值平局、解的列举次序），合同直接写死规则（字典序），实现按固定枚举次序保证兑现。合同里没写的次序问题，实现里就不允许存在。
- **输入自足条款**：函数只看参数，不读时钟、不读随机源。上一章的教训反过来用——回溯天然是确定算法，任何"漂移"都来自实现者引入的额外自由度。

用三角形着色把合同的语义走一遍：`colorings(3, {(0,1),(1,2),(0,2)}, 3)` 的解空间是一棵深度 3、每层 3 个候选的树，共 27 个叶子。搜索从顶点 0 涂色 0 开始：顶点 1 的候选色 0 与邻居 0 冲突被剪，涂 1；顶点 2 的两个邻居已占色 0、1，只剩 2。这一支产出 (0,1,2) 后回溯——顶点 1 再无候选（涂 2 与什么冲突？没有，2 也可行，产出 (0,2,1)）……全树合计产出 6 个叶子，恰为 3 的排列数。注意合同没说"返回具体方案"：计数版接口不带解的载体，需要方案时把"计数 ++"换成"记录 color 数组"即可，骨架不动。

## 26.3 设计与不变量

### 26.3.1 统一骨架：做选择 → 递归 → 撤销选择

四个问题共享同一个三段式递归模式：

```text
dfs(当前状态):
    if 状态是完整解: 记录/计数; return
    for 每个 候选 ∈ 按固定次序排列的候选集:
        if 候选违反约束: continue          // 约束剪枝
        if 候选所在子树不可能优于已知最优: continue  // 限界剪枝（优化型）
        做选择（修改共享状态）
        dfs(新状态)
        撤销选择（把共享状态改回去）        // ← 这就是"回溯"
```

不变量只有一条，却是一切的根基：**递归调用返回时，共享状态必须与递归调用前完全相同**。满足它，for 循环的每一轮才面对干净的起点；违反它，兄弟分支互相污染，结果既漏又错。下面的四个实现都在做同一件事，只是"选择""约束""解的形状"不同。

### 26.3.2 n 皇后：占用数组与对角线特征

n 皇后要求 n 个皇后互不攻击地放进 n×n 棋盘。逐行放置（第 row 行必放一个）把搜索树压成"每层选一列"的形状，深度 n、每层至多 n 个候选——上界 nⁿ 而非 (n²)ⁿ。

逐对检查"之前的皇后是否与 (row,c) 同列/同对角线"要 O(n) 每候选；改用三个**占用数组**后判定降为 O(1)：

- `col[c]`：列 c 是否已有皇后；
- `diag1[r+c]`：副对角线上 r+c 为常数——同一斜线上所有格子共享一个和值；
- `diag2[r-c+n]`：主对角线上 r-c 为常数，范围 [-(n-1), n-1]，整体 +n 平移到 [1, 2n-1]。

用和值/差值做对角线编号，比"对每个旧皇后算 |r₁-r₂| 与 |c₁-c₂| 是否相等"既快又不易错——差值判定要处理绝对值与符号，`r-c` 直接做下标还会撞上负数越界。这是"把几何关系编码成数组下标"的典型手法，值得记住。

递归的不变量：**进入第 row 层时，0..row-1 行的皇后两两不攻击**。for 循环里三数组置位、递归、三数组复位，复位遗漏的后果见 26.7 坑 1。

### 4 皇后的搜索树走查

把 n=4 的搜索完整走一遍，体会"约束剪枝如何在树的中途杀死子树"。列记号 c0..c3，约束不满足的候选直接标 ✗：

| 决策序列 | 走到的局面 | 结局 |
|---|---|---|
| 行0→c0，行1→c2 | (0,0)、(1,2) | 行1 候选 c0,c1 ✗（同列/对角），c2 ✗（同列），c3 可行 |
| 行2 在 (0,0),(1,2) 下 | c0 ✗ 列、c1 ✗ 对角、c2 ✗ 列、c3 ✗ 对角 | 全灭，回溯 |
| 行1 改 c3 | (0,0)、(1,3) | 行2 唯一可行 c1；行3 剩余列 2 与 (1,3) 同对角 ✗ | 
| 回溯到行1：c0,c1,c2 均 ✗ | — | 行0 的 c0 子树全灭 |
| 行0→c1 | (0,1) | 行1 可行 c3；行2 可行 c0；行3 可行 c2 → **解 (1,3,0,2)** |
| 行1 改试 c2? | c2 与 (0,1) 同对角 ✗ | 回溯 |
| 行0→c2 | (0,2) | 镜像路径 → **解 (2,0,3,1)** |
| 行0→c3 | (0,3) | 与 c0 子树镜像，全灭 |

总计 2 个解。这张表最值得看的是第 1、3 行：**行 2 一个候选都放不下**，搜索根本没碰行 3——程序实测整棵搜索树只有 17 个节点，对照朴素枚举 4⁴=256 种摆法，一次剪枝就合并了几十个同局面的验收。棋盘越大，这个比值越悬殊（8 皇后见 26.4 节）。

### 26.3.3 图着色：按编号顺序 + 已着色前缀

给 n 个顶点 k 种颜色、相邻异色，求方案数。按顶点编号 0..n-1 顺序着色，第 v 号只需与**编号小于 v 的邻居**比较（它们才可能已被着色）——不过实现里用"全部邻居中已着色者"判定也无妨，因为未着色者的颜色是 -1，不会等于任何候选 c。约束剪枝发生在 for 循环内：某个颜色与任一已着色邻居冲突就跳过，整棵"该颜色开头"的子树消失。

无边图是重要的退化情形：没有任何约束，方案数就是 kⁿ——三角形 3 色是 3×2×1=6，无边 2 顶点 3 色是 9。计数类代码最容易在这类边界上想当然（见坑 3）。

### 26.3.4 0/1 背包：两种剪枝与平局保全

物品按序号 0..n-1 逐一决定装/不装，解空间是标准子集树，深度 n、每层恰好两个分支（装、不装）。装不下的分支被**可行性剪枝**直接砍掉——这是约束；另一个**限界剪枝**基于后缀价值和 `suffix[i]`（第 i..n-1 件全装的总价值）：若"当前价值 + 剩余全装"仍**严格低于**已知最优，这条路径没有任何前途，整枝放弃。后缀和预处理 O(n)，每次判定 O(1)。

这里有一个精微之处：限界条件必须用**严格小于**，不能用"不优于（≤）"。因为本章合同规定等值多解取**下标字典序最小**的物品表——某个与当前最优等值的子树里，可能藏着字典序更小的解；若用 ≤ 把等值子树也剪掉，平局规则就被破坏，结果依赖枚举次序的偶然。**剪枝条件与合同的平局条款必须配套设计**：合同要多严，剪枝就要多保守。这是限界函数设计的一般原则，27 章分支限界会再次出现。

叶子处的平局裁决用 `std::vector` 的字典序比较直接完成（两个都是升序表），一行写清合同。

对本章示例数据把限界走一遍。values=[3,4,5,6]、weights=[2,3,4,5]、容量 5，后缀价值和 suffix=[18,15,11,6,0]。搜索先沿"全装"深入：装 0（重 2，值 3）→ 装 1（重 5，值 7）→ 装 2？重 9 超容量，可行性剪枝 → 不装 2：上界 v+suffix[3]=7+6=13 ≥ 当前最优 0，继续 → 装 3？重 10 超容量 → 不装 3：上界 7+0 ≥ 0 → 到叶子，记录最优 7，物品 {0,1}。随后回溯展开其余分支：不装 1 的子树（v=3）上界 3+11=14 ≥ 7 照样探索，但物品 2、3 单独重量已超剩余容量，叶子只有 v=3；不装 0 的子树最好情形是只装物品 3（重 5 值 6），叶子 v=6 < 7。整个搜索访问的叶子远少于 2⁴=16，且**从未在等值处剪掉任何子树**——限界条件"严格劣才剪"在这个实例上表现为：所有被剪的子树上界都严格低于 7，等值保全条款没有付出额外代价。

### 26.3.5 子集和：start 参数去重与负数退化

列出和恰为 target 的所有子集。两个设计点：

- **去重靠 start 参数**：递归传"下一个可选下标 start"，候选从 start 起升序扫描。这样每个子集只被"下标递增"的一条路径生成一次——若每层都从头扫，{1,4} 和 {4,1} 会被当成两个解（那是排列计数，不是组合）。这与第 12 章并查集、第 03 章递归里的"组合 vs 排列"辨析同源。
- **剪枝依赖非负**：元素全非负时部分和单调不减，"已超 target"或"再加就超"的子树可整枝放弃；含负元素时部分和可能先超后回落，**任何**基于部分和的剪枝都不安全。实现自动检测 `has_negative` 并退化为完整枚举——正确性优先于速度，且对调用方透明。

解的次序由枚举次序天然保证：先取后舍、下标升序的 DFS 恰按**下标字典序**产出子集（[0,3] 在 [1,2] 前、[1,2] 在 [4] 前），无需事后排序。

这个"次序免费"的结论值得论证一遍，因为它常被误认为需要事后排序。对两条被记录的解路径 X、Y，设 DFS 中 X 先于 Y 产出，二者的下标序列第一次分岔发生在第 k 个元素（前 k−1 个相同）：X 在岔口选了 x，Y 选了 y。岔口处候选按升序扫描，x 先于 y 被尝试意味着 x<y；又因 start 单调递增，两序列各自严格递增，故第 k 位 x<y 已定胜负——X 的下标序列字典序小于 Y。归纳即得：**产出次序 = 字典序**。注意这依赖两个前提：候选升序扫描，以及"先取后舍"（同一路径上的前缀先于扩展产出——前缀是字典序中更小的）。

### 26.3.6 一致的代码形状：四个 dfs 的同构

把四个实现的签名并排放着看：`dfs(row)`、`dfs(v)`、`dfs(i, w, v)`、`dfs(start, sum)`。它们都是"当前决定点 + 已累计的状态"两元组；区别只在状态携带的分量（占用数组收在捕获里、重量价值走参数）。这不是巧合——**解空间树上的一条根到当前节点路径，就是要维护的全部状态**；路径上能 O(1) 增量维护的（和、和值、占用位）就该走参数/共享数组，而不是每次重算。读其他回溯代码时，先找"决定点在哪、状态是什么、候选怎么排"，骨架立刻清晰。

## 26.4 复杂度推导

| 问题 | 解空间大小 | 每节点开销 | 实际效果 |
|---|---|---|---|
| n 皇后 | 上界 nⁿ（每层至多 n 个候选） | O(1) 判定/候选 | n=8 时节点数远小于 8⁸≈1678 万；解仅 92 个 |
| 图着色 | 上界 kⁿ | O(n) 邻居扫描/候选 | 约束越密剪得越狠；无边图原形毕露 kⁿ |
| 0/1 背包 | 2ⁿ 叶子 | O(1) | 可行性+限界剪枝在价值分布不均时砍掉大量子树 |
| 子集和 | 2ⁿ（负数无剪枝） | O(1) | 非负时部分和剪枝实效；负数退化为全枚举 |

写清楚这些上界的来历：回溯的搜索树深度等于"需要做的决定数"（n 行、n 个顶点、n 件物品），每层的候选数由问题决定（皇后 ≤n、着色 k、背包 2）。**指数上界是解空间的属性，不是算法的缺陷**——NP 类问题目前没有多项式通用解法，回溯的价值在于把"理论指数"变成"实例上可跑"：剪枝砍掉的恰好是"注定无解/注定更差"的部分，而好实例（约束紧、限界准）常常只留下多项式规模的活节点。

n 皇后的上界值得算细一点。每层候选 ≤n、深度 n，朴素上界 nⁿ；又因每行恰放一个皇后、列互不相同，候选列随深度递减，更紧的上界是 n!。实测远小于上界：n=8 时 8!=40320 条根到叶路径、树节点共 2057 个，而 8⁸≈1678 万——三个数字相差三个数量级，中间的差距全是约束剪枝的贡献。判定开销：每个候选做 O(1) 三数组检查，每节点展开 O(n) 个候选，故总时间 = O(节点数 × n)。这也是"占用数组"改写的真实收益：若逐对检查攻击关系，每候选 O(n)，总时间翻出 n 倍。

空间上，四个实现都只维护递归栈 O(n) 加共享状态数组 O(n)（着色另需邻接矩阵 O(n²)），不计输出。这是回溯对动态规划的另一个优势：DP 背包要 O(n·cap) 的表格，回溯只要一条路径。

关于递归深度的安全性说明：四个问题的递归深度都等于决定数 n，皇后与着色 n≤几十、背包与子集和 n 到几十以内都不会触及栈上限；若把 n 推到上千（子集和的 n 千、值域大），应改显式栈迭代或把决定分块——第 14 章左高树"递归释放左链溢出"是同一教训的另一面：**递归深度必须对着最坏输入核算，而不是对着测试输入**。

## 26.5 完整示例输出

程序真实输出（MSVC 与 clang 逐字节一致）：

```text
n 皇后：queens(4) = 2、queens(8) = 92
图着色：三角形 3 色方案数 = 6（= 3!）
图着色：无边 2 顶点 3 色方案数 = 9（= 3 的平方）
0/1 背包回溯：最优价值 7，物品下标 0 1（与 25 章 DP 一致）
子集和（{1,2,3,4,5}，目标 5）：3 组解 [1,4] [2,3] [5]
自检通过
```

逐行解释：

- 第 1 行：4 皇后恰有 2 个解（两解互为镜像），8 皇后 92 个——两个教科书级经典计数，写死进 assert 兼作回归锚点；
- 第 2 行：三角形是完全图 K₃，第一个顶点 3 种选法、第二个须异色 2 种、第三个被两邻居夹死只剩 1 种，3×2×1=6；
- 第 3 行：无边图无任何约束，退化为 kⁿ=3²=9——专门构造来演示"计数前先想清楚约束是否真的存在"；
- 第 4 行：values[3,4,5,6]、weights[2,3,4,5]、容量 5，最优 7 只能由物品 {0,1}（价值 3+4、重量 2+3）取得，与第 25 章动态规划在同一数据上的结果互为印证——两章从指数与伪多项式两个方向抵达同一答案；
- 第 5 行：和为 5 的子集共三组 {1,4}、{2,3}、{5}，按下标字典序 [0,3]、[1,2]、[4] 输出；注意 {1,2,3} 和为 6 被约束剪枝拦在树的中途，从未成为叶子。

## 26.6 与标准库的对照

标准库没有回溯设施——回溯是"方法"而不是"容器"，每个问题的解空间与约束都不同，无法做成通用组件。可对照的标准件有：

- `std::next_permutation` / `std::prev_permutation`：按字典序产出全排列，是"固定枚举次序"思想的库化版本；排列树搜索可用它做迭代式枚举（但没有中途剪枝）；
- `<bit>` 的位枚举（`std::popcount` 等）：n≤63 的子集枚举可用位掩码循环替代递归，次序按数值即字典序；
- 与第 25 章动态规划的关系是本章最重要的对照，列表如下：

| 维度 | 回溯（本章） | 动态规划（第 25 章） |
|---|---|---|
| 产出 | 全部解或计数 + 最优解 | 只给最优值（构造解需回表） |
| 时间 | 指数上界、实例相关 | 伪多项式/多项式，实例无关 |
| 空间 | O(n) 路径 | O(n·cap) 表格 |
| 适用 | 需要所有解、约束复杂难表 | 最优子结构+重叠子问题成立 |

同一道背包，25 章 DP 用 O(n·cap) 拿最优值，本章回溯用 O(2ⁿ) 上界拿同样的最优值外加"列出全部可行装法"的能力——**要"全部解"时 DP 无能为力，要"快"时回溯赌不过多项式**，选型看需求而不是看谁更高级。

与第 19 章图的 DFS 的关系：图遍历是回溯的退化特例——"选择"只有走哪个邻居，"约束"由 visited 标记承担，且 visited 不撤销（每个顶点只访问一次）。回溯的撤销选择正是为了**同一节点在多条路径中反复出现**的组合搜索。

下一章分支限界（第 27 章）与回溯同属解空间搜索，差别在策略：回溯沿 DFS 深入（省内存、早达叶子），分支限界用最优优先/广度优先扩展活节点、维护全局上界下界（找最优解时常更快）。背包容积紧、价值密度均匀时，两条策略剪枝效率的差距会非常直观。

本章小结：回溯的三步法（定义解空间、组织成树、DFS+限界）是可以迁移到任何组合问题的模板；实现上只有一条铁律（递归返回时状态复原）和一条工程戒律（枚举次序固定）。剪枝条件要对着合同的平局条款设计，负数元素要关掉单调性剪枝——这两处是"算法正确"与"代码碰巧对"的分界线。

最后给一个把本章接口"升级"的练习方向：计数变枚举、枚举变最优。`queens` 的 `++count` 换成把列数组存进结果，就是"输出全部 n 皇后解"；`colorings` 的 color 数组在叶子处存下，就是"列出全部着色方案"；`knapsack_bt` 已经示范了"顺带携带解载体"。三个升级都只动叶子处一行，骨架零改动——这正是骨架/策略分离的回报：**回溯的骨架一次写对，终生只改叶子**。练习时留意输出规模：8 皇后 92 个解、每个解 8 个数，打印量尚可；n=12 的解数 14200，就该考虑把输出改为回调或迭代器了。

一条阅读建议：本章正文没有整段贴实现代码——四个实现的骨架 26.3.1 已完整给出，真正的代码在示例目录里总共百余行，且每处"做选择/撤销选择"都配了注释。读代码时对照 26.3 的四小节，每问自己三个问题：决定点是什么？状态带什么？候选什么次序？三问答得出，这段回溯就学会了。若三问里有一问答不出——多半是"状态"没看全：回溯代码里最隐蔽的状态往往不是参数，而是捕获进 lambda 的共享数组和 result 容器，把它们也画进状态图，骨架就再无秘密。

## 26.7 本章坑位

- **坑 1：忘记撤销选择（状态污染）。** 现象：皇后计数比真值小得多，或子集和解重复/丢失。原因：做选择后只推进不回退，兄弟分支继承了上一轮的残留状态。后果：结果错误且随输入规模恶化，最难查的一类 bug。防法：把"做选择/撤销选择"写成紧邻的对称两行，递归调用夹在中间；断言可用"递归前后状态快照相等"自检。
- **坑 2：对角线判定用 abs 且下标未平移。** 现象：皇后程序崩（`r-c` 为负做下标）或把同行同列误判成对角线。原因：|r₁-r₂|==|c₁-c₂| 判定本身对，但把它编码进占用数组时忘了 `r-c` 的范围含负数。后果：越界崩溃或漏解。防法：对角线按 r+c、r-c+n 编号进数组，永不现算 abs。
- **坑 3：无边图计数想当然。** 现象：给无边图着色，声称方案数是 1（"只有一种染法"）或写成与边图同式。原因：忽略"约束为零时每个顶点独立 k 种选择"。后果：kⁿ 与 1 差之千里，计数类接口直接错。防法：边界实例（无边图、单顶点、k=1）写进测试。
- **坑 4：背包枚举成排列、重复计数。** 现象：子集和解出现 {1,4} 与 {4,1} 两份，或背包某物品"装了又装"。原因：每层候选从 0 开始扫而不是从 start/当前序号开始。后果：解膨胀成排列数，指数基数翻倍且语义已错。防法：组合问题一律传 start，保证下标严格递增。
- **坑 5：剪枝条件写反或过紧。** 现象：背包返回次优值（如 6 而非 7），或等值解字典序不稳定。原因：限界条件把"等于最优"的子树也剪了（≤），或把"当前已超容量"误写成"当前已超最优"。后果：静默丢最优解，无崩溃无告警。防法：限界只剪**严格劣**；用一组已知最优值的小实例（本例 value 7）做回归。
- **坑 6：枚举次序不确定导致输出漂移。** 现象：同一程序两次运行（或两个编译器）解的排列不同。原因：候选次序依赖哈希表遍历序、指针地址或未初始化变量。后果：输出不可复现，"逐字节一致"验收失败。防法：所有 for 循环候选按固定键（下标/编号）升序；禁用地址与时间做任何比较。
- **坑 7：递归传值拷贝路径容器。** 现象：撤销选择"看起来做了"却无效，或性能按层指数拷贝。原因：把 `std::vector cur` 按值传进递归，每层各自副本，父层状态从未被修改也谈不上撤销。后果：轻微时结果仍对但内存时间双爆，严重时与引用版本混用出错。防法：路径容器按引用传递 + 显式 push/pop，或全链不可变（传值但不回改）二选一，不许混。
- **坑 8：共享状态数组的容量开错。** 现象：皇后的对角线数组按 n 开、下标 r+c 最大到 2n-2，越界写坏相邻内存。原因：把"n 行 n 列"直接套在"对角线编号范围 0..2n-2"上。后果：MSVC release 下可能"碰巧不崩"而 clang 下崩溃——未定义行为从不保证 reproducible。防法：对角线数组一律 2n，n=0 时防退化。
