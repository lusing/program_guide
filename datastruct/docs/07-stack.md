# 07 · 栈：后进先出的控制结构

## 7.1 动机与直觉：弹匣、餐盘与浏览器后退

栈（stack）是约束最强的线性表：**只允许在一端操作，这一端叫栈顶（top），另一端叫栈底（bottom）。** 放入叫入栈（push），取出叫出栈（pop）。规则只有一条：**后进先出（LIFO, Last In First Out）——最后放进去的，最先被拿出来。**

生活中这类结构随处可见：

- **步枪弹匣**：子弹从顶部一颗颗压入，射击时最后压入的最先上膛；
- **自助餐的一摞餐盘**：新盘子摞在最上面，取用时也从最上面取；想拿最底下的盘子，必须先把上面的全部移走；
- **浏览器的"后退"按钮**：每访问一个新页面，其地址被压入历史栈；点后退，弹出最近一次访问；
- **编辑器的撤销（Ctrl+Z）**：操作按发生顺序压栈，撤销从最近一次开始。

为什么要给自己加"只能动一端"的限制？因为这个限制恰好对应一大类问题的天然结构：**嵌套**。括号可以套括号、函数调用里再调函数、表达式里有子表达式——这些结构都是"最近打开的，最先闭合"。第 03 章讲过：递归调用靠调用栈执行，每一层调用现场像盘子一样叠放。本章就是把那个隐藏在语言机制里的"栈"亲手实现出来，并用它解决四类经典问题：括号匹配、表达式转换、表达式求值、迷宫寻路。

## 7.2 ADT 合同

栈的 ADT 只含五个操作。先讲语义，再给出错约定——本章的顺序栈与链式栈实现的是**同一份合同**，可以互换。

- **push(x)**：把 x 放到栈顶。事后状态：栈顶为 x，元素总数加一，其余元素相对次序不变。
- **pop()**：移除当前栈顶元素。**前提：栈非空。** 事后状态：原栈顶之下的元素成为新栈顶，总数减一。
- **top()**：返回栈顶元素但不移除。前提同样是栈非空。
- **empty()**：无前提，返回栈是否为空，不改变状态。
- **size()**：无前提，返回元素总数。

**出错行为是合同的一部分。** 对空栈执行 pop 或 top 属于编程错误（调用方违反了前提），按本教程统一约定，实现抛出 `std::runtime_error`，由调用方决定如何处理——而不是静默返回一个垃圾值。注意 pop 不返回被删元素、top 不删除元素，这是两个正交的操作；合二为一（"弹出并返回"）在异常安全上有坑，后面坑位节详述。

本章还提供三个建立在栈之上的例程：

- `balanced(expr)`：判断表达式中的圆/方/花括号是否正确配对；
- `to_postfix(infix)`：把空格分隔音 token 的中缀表达式转换成后缀表达式；
- `eval_postfix(expr)`：对后缀表达式求值。

## 7.3 设计与不变量（一）：顺序栈

顺序栈复用连续数组，把**尾部**当栈顶：入栈就是尾插，出栈就是尾删。

```cpp
void push(const T& value) { data_.push_back(value); }
void pop() {
    if (data_.empty()) throw std::runtime_error("ArrayStack::pop：栈为空");
    data_.pop_back();
}
```

这段代码要做的事情很直接，但请把注意力放在它**维持的不变量**上：

1. 有效元素恰好占据数组前缀 `[0, size)`，逻辑栈顶永远是 `data_[size-1]`；
2. push 后新元素位于 size−1、size 加一；pop 前移除 size−1、size 减一；两个操作都**不触碰其他位置的元素**；
3. 任何时刻 empty() 与 `size == 0` 等价。

为什么选尾部而不是头部？数组头部插入要把全部元素后移一位（O(n)），而尾部增删不移动任何元素（均摊 O(1)）。存储结构决定了操作该放在哪一端——这是第 01 章"两维选择"的又一次兑现。

## 7.4 设计与不变量（二）：链式栈与 RAII

链式栈用散落在堆上的节点存储，**从头部插入**，栈顶指针指向最新节点：

```cpp
void push(const T& value) {
    top_ = new Node{value, top_};  // 新节点的 next 指向旧栈顶
    ++size_;
}
```

这里有一个关键顺序：新节点先带着"旧栈顶地址"构造好，**然后**栈顶指针才改指向它。两步之间链表始终完整，即使分配抛异常，旧栈也安然无恙。

链式栈的不变量：

1. 从 `top_` 出发沿 `next` 走，恰好经过全部 size 个节点、最后以空指针收尾；
2. push 在链头加一个节点，pop 删链头节点并把 `top_` 移到 `next`，其余节点不动；
3. 空栈时 `top_ == nullptr` 且 size 为 0。

节点是动态分配的，因此类必须自己管理资源，遵守 RAII：**析构**沿链逐个 `delete`；**拷贝构造**做深复制（新栈一条全新的链，与原件互不影响——示例中特意断言"原件出栈后副本栈顶不变"）；**移动构造**直接窃取对方的链指针、把对方置空。有了这四件套，链式栈的使用者既不会遇到内存泄漏，也不会遇到两个栈共享同一串节点的别名问题。

对比两个实现：顺序栈结构最简单、每个元素无额外开销，但扩容时需要成批搬运；链式栈每节点多占一个指针，但没有扩容概念、push/pop 稳定地只动一个节点。二者操作合同完全相同。

## 7.5 设计与不变量（三）：括号匹配

判断 `{[()]}` 这样的串是否合法，只需一个栈，算法是栈思想的最简形态：

- 遇到左括号，压栈（"我打开了一个，等着闭合"）；
- 遇到右括号，栈必须非空，且栈顶必须是**同类**左括号，配对后弹出；
- 遍历结束，栈必须为空（没有未闭合的左括号）。

为什么栈是正确的工具？因为配对规则就是"最近打开的最先闭合"——右括号闭合的永远是栈顶那个左括号。串 `"([)]"` 为什么非法？处理到 `)` 时栈顶是 `[`，种类不符，立刻判负：方括号还没闭合，圆括号不可能先闭合。栈把"嵌套必须层次分明"这件事变成了机械的比较。

## 7.6 设计与不变量（四）：后缀表达式与调度场算法

### 为什么先转后缀

我们习惯的中缀写法 `3 + 4 * 2` 依赖两条额外规则：运算符优先级（先乘除后加减）和括号。而**后缀表达式（逆波兰式）**把运算符写在两个操作数之后，如 `3 4 2 *` 表示 `3 + (4*2)`——后缀式**不需要括号，也不需要优先级表，从左到右一遍即可求值**。

求值规则正是栈的经典应用：

- 遇到数字，压栈；
- 遇到运算符，弹出两个数：**先弹出的是右操作数**，后弹出的是左操作数；计算结果压回栈；
- 遍历结束，栈中恰好剩一个数，就是表达式的值。

以 `3 4 2 * 1 5 - / +` 手工推演：压入 3,4,2；`*` 弹 2 与 4 得 8 压回；压 1,5；`-` 得 −4；`/`：8/(−4) = −2；`+`：3+(−2) = 1。

这里栈维持的不变量是：**栈中每个数都代表一个已经完整求值的子表达式**；运算符永远作用于最近两个未被消费的子表达式。除零、操作数不足（弹不出两个）、结束时栈中不止一个数，三种畸形输入都会破坏不变量，实现一律抛异常。

### 中缀怎么转后缀：调度场算法

Dijkstra 的调度场算法（shunting-yard）用一个运算符栈完成转换：

- 数字直接输出；
- 左括号 `(` 压栈；
- 右括号 `)` 弹出运算符到输出，直到遇到左括号，然后丢弃这对括号；
- 遇到运算符，**只要栈顶运算符的优先级不低于当前运算符，就先弹出**；之后压入当前运算符；
- 遍历结束，把栈中剩余运算符全部弹出。

"先弹高优先级"保证了乘除在加减之前输出；括号在栈中充当"隔断"——括号内的运算符不与括号外比较，右括号一到整组弹出。这就是括号改变计算次序的机制：它临时切断了优先级传播。

## 7.7 设计与不变量（五）：迷宫寻路

在网格迷宫里找一条从起点到终点的路，是栈的另一个自然用途——**深度优先搜索（DFS）**：

1. 起点压栈；
2. 取出栈顶格子，若为终点，成功；
3. 把它尚未访问过的可通行邻格压栈，并记录每个邻格的**来路（parent）**；
4. 栈空仍未到终点，说明无路可达，返回空路径；
5. 到达终点后沿 parent 一路回溯到起点，逆置即得正向路径。

两个关键设计。第一，**邻格压栈前就标记为已访问**，而不是弹出时才标记——否则同一个格子可能被多个邻居重复压栈，路径记录会混乱。第二，parent 保证回溯出的路径必为简单路径：每个格子只有一个来路，沿 parent 链不可能出现环。示例断言只检查路径的外部性质：首格是起点、末格是终点、每步四邻接、不撞墙——这些是"路径"这份合同的全部要求。

DFS 与第 03 章的递归寻路本质相同：显式栈替代了调用栈。这兑现了那里的预告——"任何递归都能改写为显式栈"。需要注意：DFS 找到的是**一条**可行路径，不保证最短；要最短路径应换队列做广度优先（第 08 章）。

## 7.8 复杂度推导

设栈中元素数为 n。

| 操作 / 问题 | 时间 | 额外空间 |
|---|---|---|
| push / pop / top / empty / size | O(1) | — |
| 括号匹配 | O(n) | O(n) |
| 中缀转后缀 | O(n) | O(n) |
| 后缀求值 | O(n) | O(n) |
| 迷宫 DFS | O(R·C) | O(R·C) |

要点：栈的每个单操作只动栈顶，与已有元素数无关；基于栈的线性扫描问题每个 token 入栈一次、最多出栈一次，所以仍是线性时间（这种"每项至多进出各一次"的论证手法叫聚合计数）。迷宫最坏要踏遍每个格子，由格子数 R·C 决定；parent 与访问标记各占一块同尺寸空间。

逐行解释说明了什么：

## 7.10 与标准库的对照

C++ 标准库提供 `std::stack`，但它**本身不是容器，而是容器适配器**：在一个底层容器之上只暴露栈的五个操作，把其他能力（如下标、中间插入）全部封死。

```cpp
std::stack<int> s;                 // 默认底层容器是 std::deque
std::stack<int, std::vector<int>> v;  // 也可指定 vector
```

能当底层的容器只需支持 `back()`、`push_back()`、`pop_back()`，所以 deque、vector、list 都可以；默认选 deque 是因为它扩容时不搬迁已有元素。标准库没有直接提供表达式解析或迷宫搜索——这些是栈的**应用**，正是本章亲手实现的价值所在。

## 7.11 本章坑位

- **坑 1：对空栈 pop/top。** 现象：读到垃圾值或程序崩溃。原因：违反操作前提，栈中根本没有元素。后果：未定义行为、结果不可预测。防法：操作前检查 empty()，并让实现抛异常把编程错误显性化。
- **坑 2：后缀求值时操作数顺序弄反。** 现象：减法、除法结果错（`1 5 -` 算成 4 而不是 −4）。原因：先弹出的应是**右**操作数。后果：非交换运算全部出错，且 assert 难发现。防法：严格按 rhs 先弹、lhs 后弹。
- **坑 3：除零只输出错误码、不中断求值。** 现象：压入 `inf` 继续算，最终得到诡异结果。原因：除以零破坏了"栈中都是有效子表达式"的不变量。后果：错误沿计算链扩散。防法：立刻抛异常，拒绝产出值。
- **坑 4：括号不匹配时忘记弹出左括号或漏判栈空。** 现象：右括号导致栈下溢，或 `"(()"` 被判为合法。原因：右括号弹到左括号后要丢弃它，遍历结束还要检查栈空。后果：配对判定假阴假阳。
- **坑 5：DFS 在弹出时才标记访问。** 现象：同一格子被压栈多次，parent 被反复覆盖，甚至路径成环。原因：多个邻居同时把它压入时它还"未访问"。后果：回溯路径无效。防法：压栈即标记、即记录 parent。
- **坑 6：把 pop 设计成"返回并删除"。** 现象：拷贝栈顶元素时若抛异常，元素已被删除，值永久丢失。原因：删除与返回两步无法原子完成。后果：异常安全漏洞。防法：top() 与 pop() 分离，先取后删。
