# 17 · 二叉搜索树：BST、AVL 与红黑树

## 17.1 动机与直觉：在"有序"与"可插可删"之间

字典问题从第 16 章起就是主角：给定一个键，快速找到它对应的值；同时不断有新键加入、旧键删除。第 16 章给出的两种答案各有短板——跳表依赖随机层数，散列表只能按精确键查、不支持"找最小键、列出某区间全部键"这类顺序操作，而且最坏情况没有保证。

我们换个直觉。想想一本按拼音排好序的纸质通讯录，你要找"林"：随手翻到中间，看到"王"——林在王前面，于是只翻左半；再看到"陈"——林在陈后面……每翻一次，候选范围就被砍掉一半。**如果通讯录能在插入新页时始终保持拼音有序，且翻页能一次跳两份之一，查找就是对数的。**

数组保持有序，查找可以二分，但插入要搬动大批元素；链表插入便宜，但无法二分（走到中间就得从头顺）。二叉搜索树正是把"有序"编码进**结构**里，试图两头占便宜：像链表一样用节点挂接、插入删除只改局部指针，又因为有序性挂在树上，可以沿路径每次排除一棵子树。

本章沿三棵树递进：

- **BST（二叉搜索树）**：只给序性质，简单，但最坏会退化成链；
- **AVL 树**：加上高度差约束，强制平衡，插入删除靠旋转恢复；
- **红黑树**：用颜色编码较弱但更"松"的平衡，旋转更少，是工业界的主流选择。

学完应能回答：BST 的哪条性质保证中序即升序；删除双子节点时为什么取后继；AVL 的四种失衡各自怎么转；红黑树为什么只看黑高就能保证对数高度。

## 17.2 ADT 合同

三棵树对外提供同一份字典合同（红黑树本章只实现插入与观察）：

- `insert(k, v)`：键不存在则新增；键已存在则**更新值**，不新增节点；
- `search(k)`：命中返回该键的值（`optional<V>`），未命中返回 `nullopt`；
- `erase(k)`：删除该键，返回是否真的删掉；删不存在的键返回 `false`；
- `keys_sorted()`：返回全部键，按升序。

合同的关键前提只有一条：键必须**可比较全序**（代码用 `std::totally_ordered` 约束）。值没有顺序要求，只要求可拷贝。

为支持结构层面的精确验证，本章实现额外暴露观察接口：

- AVL 的 `preorder_detail()`：前序列出 `(键, 高度, 平衡因子)`；
- 红黑树的 `rb_legal()`、`root_key()`、`black_height()`、`preorder_colored()`。

这些不是字典使用者的日常需求，而是"合同的可观察证据"——树的内部形状本来无从直接查看，把它们变成值才能断言。

举几个合同行为的具体例子（键为整数、值为该键平方）：

- 空树上 `search(7)` 返回 `nullopt`，而不是抛异常——未命中是正常情形，不是错误；
- 依次插入 5、3、8 后 `keys_sorted()` 为 `{3, 5, 8}`，与插入先后无关；
- 再插入 5（值改给 100），键序列仍是 `{3, 5, 8}`，但 `search(5)` 得到新值 100；
- `erase(9)` 在任何时刻都安全返回 `false`。

真正的程序错误（如对空树取最小值）才用异常报告；"没找到"是字典查询的常态结果，因此用 `optional` 表达。

## 17.3 设计与不变量

### 17.3.1 BST 的序性质

BST 每个节点都遵守一条递归的序性质（也称 BST 不变量）：

> **左子树中所有键 < 本键 < 右子树中所有键。**

注意比较对象是"整棵子树的所有键"，不只是直接孩子。只约束"左孩子小、右孩子大"是不够的：例如根 5、右孩子 8、而 8 的左孩子若写成 3，局部看没错，3 却跑到了根 5 的右边——整树序性质被破坏，查找 3 沿根向右走便永远找不到。

这条不变量直接给出两个算法：

```cpp
if (k < node->key)      进入左子树；
else if (node->key < k) 进入右子树；
else                    命中；
```

查找如此，插入也如此：沿比较走到空位，把新节点挂在最后一条边上。比较使用双向判断（`<` 和反过来的 `<`）而非 `<=`，于是相等这第三种情况被单独识别为"更新值"。

**中序遍历必为升序**：左子树全部更小、先访问；再访问根本身；再访问全部更大的右子树——递归对每一层都成立。因此 `keys_sorted()` 就是中序收集，它同时是验证不变量是否成立的最方便手段：中序若不是严格升序，树必已损坏。

### 17.3.2 删除的三种情形

`erase` 按待删节点的孩子数分三种情形：

- **叶子（0 个孩子）**：直接摘除，父节点对应指针置空；
- **单子**：孩子"顶上来"——父节点绕过待删节点直接指向那个孩子；
- **双子**：不能简单合并两棵子树。做法是找**后继**（右子树中最小的键，即中序下紧跟本键的节点），把后继的键和值**复制**到待删位置，再删除右子树里的后继。

后继为什么一定好删？它是右子树的最小值，因此它没有左孩子，至多带一个右孩子——删除它退化成前两种情形。选前驱（左子树最大值）也对称成立。

实现采用递归形式：`erase_node` 返回删除后（子）树的根，于是"孩子顶替"只是把子树根挂回父边，无需再维护父指针。节点删除数用一个引用布尔量沿递归上报，区分"删了"与"键不存在"。

### 17.3.3 BST 的软肋

如果按 `1, 2, 3, …, n` 的顺序插入，每次新键都最大、挂在最右边，树就退化成一条右斜链：形态等同链表，查找退化 O(n)。BST 的高度在 1 到 n 之间摆动，一切复杂度都取决于高度。后面两种树的工作，就是**把高度钉死在 O(log n)**。

### 17.3.4 AVL：高度差约束

AVL 在每个节点加一个高度字段（空树高度 0，叶子高度 1），并要求：

> **任一节点的平衡因子 bf = h(左) − h(右) 必须属于 {−1, 0, 1}。**

插入只在从根到新节点的一条路径上改变高度，因此失衡节点至多需要在"归途"上处理一次。设新键落在失衡节点的左子树左边（外侧），只需一次**右单旋**：

```text
        y(3)              x(2)
       /                 /    \
     x(2)      ──►     1        3
    /
  1
```

旋转做的事是"让左孩子 x 上位，把 x 原来的右子树过继给 y 当左孩子"——这棵中间子树的键介于 x 与 y 之间，过继后序性质保持。四种情形按新键的位置区分：

- **LL**（左子树外侧）：右单旋；**RR**：左单旋；
- **LR**（左子树内侧）：先对左孩子做左单旋、转成 LL，再右单旋；
- **RL**：对称的两次旋转。

以内侧情形 LR（依次插入 3、1、2）为例，两次旋转的形状变化是：

```text
      3              3              2
     /              /              / \
    1    ──►       2    ──►      1   3
     \            /
      2          1
```

先把"内拐"的节点 2 旋到外侧，整棵树就变成熟悉的 LL 形状，第二旋与 LL 完全相同。RL 只是这张图的镜像。记住"先把内侧转成外侧"，四种情形就只需记单旋一张图。

示例断言四组三元素插入后，根一律是中间键 2、高度 2、平衡因子全 0——这正是"无论什么到达次序，三元素必被旋成同一形状"的证据。旋转后必须按先孩子后根的次序重算高度。

### 17.3.5 AVL 删除与插入的差别

删除也会沿归途失衡，但一次旋转可能让上层继续失衡，因此需要逐层处理（代码的递归自然完成）。判断单旋还是双旋时不能只看键的位置（键已被删），要看**孩子的平衡因子**：左重且左孩子也是左重（bf ≥ 0）才单旋，否则双旋。这是删除修复与插入修复最容易写混的地方。

### 17.3.6 红黑树：五条性质

红黑树不直接约束高度，而给每条边"染色"，节点非红即黑，维持五条性质（见 17.4 节复杂度处的推论）：根黑；空子按黑算；红孩子必黑；任一节点到叶的所有路径黑节点数相同。直觉上：红节点代表"这条边可以并下去"，于是最长路径至多比最短路径多绕一倍红节点——高度因此被黑高界住。

插入的新节点一律染**红**（染红不改变路径黑节点数，不破坏最关键的黑高性质），只可能违反"无连续红"。修复分三种局面，沿父链向上：

- **叔叔也是红的**：父、叔染黑、祖父染红，问题上移两层；
- **叔叔黑、新节点在外侧**：一次旋转 + 父子/祖父换色，收尾；
- **叔叔黑、新节点在内侧**：先旋转把自己转到外侧，再按上一条处理。

这与 AVL 的"四情形"结构相似，区别在于变色可以让修复在很多插入里**一次旋转都不做**——红黑树因此比 AVL 写操作更省。本章实现的旋转带父指针维护，是唯一比 AVL 多出来的簿记。

### 17.3.7 红黑合法性如何检查

`rb_legal()` 做三件事：根必须黑；递归检查每个红节点的两个孩子不能红；递归比较左右子树的黑高度必须相等。三者合一即五条性质全部成立。`black_height()` 返回根到叶路径上的黑节点数。

### 17.3.8 节点结构与值语义

BST 和 AVL 的节点不需要父指针（删除递归返回子树根即可挂回）；红黑树的修复要沿父链向上变色，因此节点多一个 `parent` 字段。这是三棵树在存储上的唯一结构性差别。

树作为容器应当具备值语义：拷贝一棵树得到的是**独立深拷贝**，对副本的插入与删除不影响原树。实现方式是沿原树逐节点 `clone`；移动则直接接过对方的根指针、把对方置空，O(1) 完成且不抛异常。析构统一用显式栈迭代释放——BST 最坏高度为 n，递归析构一条斜链本身就可能撑爆调用栈，这正是坑 7 所说的问题。

红黑树本章为聚焦插入修复，刻意删除了拷贝构造与拷贝赋值、只保留移动；这也提示一个工程事实：当深拷贝代价昂贵且暂时用不到时，显式 `= delete` 比放任编译器生成错误版本更安全。

## 17.4 复杂度推导

设树高为 h。

**BST**：插入、查找、删除沿一条根到叶的路径行走，时间 **O(h)**；删除的后继寻找也在同一条高度界内。平均情形（随机插入）期望高度 O(log n)；最坏（有序插入）h = n，**O(n)**。

**AVL**：高度约束可以推出 h ≤ 1.44·log₂(n+2)，即 **h = O(log n)**。推导梗概：设 N(h) 为高度恰为 h 的 AVL 树至少能有多少个节点，取最小情形时根的两棵子树高度为 h−1 与 h−2，于是

```text
N(h) = N(h−1) + N(h−2) + 1
```

这是 Fibonacci 递推，N(h) 以 φʰ 增长（φ≈1.618）。反解 h 便得到 h ≤ 1.44·log₂(n+2)。于是所有字典操作 O(log n)。插入至多一次（单或双）旋转，删除至多 O(log n) 次；每次旋转 O(1)。额外每节点一个 int 高度，空间开销 O(n)。

**红黑树**：最短路径全黑、长度为黑高 H；最长路径黑红相间、长度不超过 2H，故 h ≤ 2H = O(log n)（黑高本身被 n 界住）。所有操作 O(log n)；插入修复至多两次旋转，变色沿父链但总摊还代价很小。

对照可见三者时间上界的差别：BST 只平均对数，AVL 和红黑最坏也对数；红黑用较弱的约束换取更少的旋转，AVL 则在读多写少、要求严格平衡时仍有价值（其查找路径确实更短）。

## 17.5 完整示例输出

```text
BST：插入/查找/叶子·单子·双子三种删除后次序全部正确
BST：重复键更新值（不新增节点）
AVL：LL/RR/LR/RL 四情形旋转后根均为 2、子 1·3、平衡因子全 0
AVL：1..7 插入并删除 3·6 后，全部节点平衡因子不超 1
红黑树 1..7：性质全合法，根键 2，黑高 2
  前序（含颜色）：2B 1B 4R 3B 6B 5R 7R
红黑树 1..100：性质全合法，黑高 6（约为 log₂100 的一半量级）
自检通过
```

逐行解释：

- 第 1 行：BST 的三种删除情形（叶子 1、单子 3、双子 5）各走一遍后，中序始终保持升序——删除没有破坏序性质；
- 第 2 行：重复插入同键走"更新值"分支，节点数不变；
- 第 3 行：四种到达次序的三元素插入，被四种旋转统一修成同一形状，且平衡因子精确为 0；
- 第 4 行：删除两个节点之后，每个剩余节点的平衡因子仍在 ±1 内，删除修复有效；
- 红黑两行：1..7 的修复结果根为 2、黑高 2，前序指纹中可以直接核对性质——没有连续红（4R 的孩子 3B、6B；5R、7R 的父是 6B），且所有叶路径黑高一致；1..100 时黑高仅 6，印证黑高以对数增长。

## 17.6 与标准库的对照

- **`std::map<K,V>` / `std::set<K>`**：标准未规定实现，但所有主流标准库（MSVC 的 STL、libstdc++、libc++）都用**红黑树**——原因正是本章展示的：最坏对数保证 + 插入旋转次数少。它们还提供 `lower_bound`/`upper_bound` 这类顺序查询，这是散列容器给不了的。
- **`std::multimap`/`std::multiset`**：允许重复键的版本；本章教学 ADT 把重复键定义为"更新值"，因为字典语义一键只对一值。
- **AVL 没有标准库对应**：工业界多数场景选择红黑树，但读多写少的系统中 AVL 及更现代的平衡树（如 B 树风格的有序容器）仍会出现。
- 标准库容器删除键用 `erase(key)` 返回被删元素个数，语义与本章的布尔返回等价；空树操作都是安全的（返回 0），与本章"删不存在返回 false"一致。

亲手实现后再用 `std::map`，你应当能说出它每次插入在内部可能做了什么：比较、染色、至多两次旋转——而不是把它当黑盒。

## 17.7 本章坑位

- **坑 1：只约束直接孩子的大小关系。** 现象：根 5、右子树里冒出键 3，search(3) 找不到。原因：BST 不变量针对整棵子树。后果：中序不再升序、查找与插入行为全面错误。防法：插入只沿比较路径挂节点，并以中序升序做回归验证。
- **坑 2：删除双子节点时删错后继。** 现象：取成"右孩子"而非"右子树最小键"，右孩子若有左子树便被丢失。原因：后继是中序紧邻、即最小值。后果：整棵左子树失联泄漏。防法：后继沿 left 走到底，再复用删除逻辑摘除。
- **坑 3：旋转后忘记重算高度。** 现象：AVL 平衡因子随后全部失真。原因：旋转只交换了指针，高度字段不会自动更新。后果：错误判断失衡、甚至越界访问空孩子的高度。防法：先 update 下位节点、再 update 上位节点。
- **坑 4：插入与删除复用同一套旋转判定。** 现象：删除后按"键位置"选旋转方向，但键已不存在。原因：删除修复要看孩子平衡因子。后果：某些树形旋转后仍失衡。防法：删除用 bf ≥ 0 / ≤ 0 判定单双旋。
- **坑 5：红黑新节点染黑。** 现象：插入看似无冲突，黑高却悄悄变了。原因：黑节点增加所有路径的黑计数。后果：黑高不一致且难以察觉。防法：新节点一律染红，只按"连续红"修复。
- **坑 6：旋转时漏掉父指针维护。** 现象：红黑旋转后节点的 parent 指向旧父，修复沿 parent 上走时进入错误分支。原因：过继子树和新根都要改 parent。后果：树在结构上断裂、可能死循环。防法：旋转中三处 parent 逐一更新。
- **坑 7：递归析构退化树。** 现象：删斜链 BST 时递归深度 n 撑爆栈。原因：BST 不保证高度。后果：析构大容器崩溃。防法：显式栈迭代释放。
- **坑 8：拷贝时浅拷贝。** 现象：复制出的两棵树析构时同一节点被释放两次，程序崩溃。原因：默认逐成员拷贝只复制了根指针，两棵树共享同一批节点。后果：双重释放；或修改一棵树时另一棵被暗中改坏。防法：自定义深拷贝，或显式 `= delete` 拷贝。
- **坑 9：比较函数不满足严格全序。** 现象：键明明插进去了却查不到，甚至旋转时进入自相矛盾的分支。原因：比较关系若允许"a<b 且 b<a"或不自反一致，序性质无从建立。后果：树结构损坏，且错误随数据次序出现、难以复现。防法：键只用内置整数、字符串等满足全序的类型，或为自定义类型正确实现三路比较。
- **坑 10：以为红黑树的删除修复和插入差不多。** 现象：照搬插入的三局面修复删除，某些树出现连续红或黑高不等。原因：删除黑色节点会让一侧黑高减一，需要"双黑"借位，局面更多。后果：删除后树不合法。防法：本章红黑树有意只实现插入；补全删除时须单独学习补黑流程，不能复用插入修复。
