# 02 · 程序性能：怎样衡量快与慢

## 2.1 动机与直觉："能跑"为什么远远不够

上一章说，同一个问题可以用不同结构和算法解决。但"都能算出正确答案"并不意味着它们一样好。

考虑最朴素的问题：计算 `1 + 2 + … + n`。

- 写法一：老老实实用循环加 n 次；
- 写法二：用高斯公式 `n(n+1)/2`，一次乘、一次除。

`n = 100` 时两者毫无差别。`n = 10¹²` 时，循环法要做一万亿次加法（按每秒十亿次运算计需上千秒），公式法的工作量**与 n 完全无关**，永远是那几步。一个正确但低效的算法，在大数据上等于不能用。

再看一个更贴近本课的例子：在长度 n 的表中查找。顺序扫描最坏走 n 步；若数据有序、用二分查找，最坏只走约 log₂n 步。n = 100 万时，这是 100 万步与 20 步的差别——而它们的答案同样正确。

本章要建立的能力：**不依赖钟表，仅凭分析就能估出算法随输入规模增长时的资源消耗**，并用统一记号表达。这套记号是后面 26 章讨论一切结构性能的通用货币。

本章配套示例也不做任何计时——只打印可复现的操作步数。

## 2.2 ADT 合同：性能模型的四条约定

把"性能分析"本身看成一份合同——我们约定在同一个模型下说话，避免鸡同鸭讲。合同有四条。

1. **自变量是问题规模 n。** 排序的 n 是元素个数；图的规模是顶点数 V 与边数 E；矩阵乘法是矩阵的阶。离开规模谈性能没有意义。
2. **计量单位是基本操作步数，不是钟表秒数。** 一次算术运算、一次比较、一次赋值各算一步；每步的耗时由硬件决定，步数由算法决定。我们只分析后者。
3. **考察趋势，不纠缠常数。** n 翻倍、涨十倍时步数如何变化，才是可迁移的信息；"比它快 30%"会随编译器消失。
4. **声明情形。** 最好、最坏、平均是三种不同承诺，分析时必须注明是哪一种。

这四条也是考试与工程评审中"一个性能说法是否站得住"的检验标准：没有规模自变量（"这个程序很慢"）、用钟表时间下结论（"在我电脑上 0.2 秒"）、只报常数不报趋势（"比版本 A 少 15 次循环"）、不声明情形（"查找是 O(1)"），四种说法都不合格。

这份合同不规定具体结论，只规定"怎样的说法算数"。下面先学怎样数步数。

还有一个约定要先讲明：**当一个操作只调用若干其他操作时，按被调用操作的合同步数记账即可，不必穿透到汇编。** 例如说"这一步对长度 n 的数组做了一次排序，记 O(n log n)"。复杂度分析的粒度是分层的——在 ADT 的层次用 ADT 的操作记账，在实现层次数基本操作。混层记账（在讨论算法选型时去数汇编指令，或在讨论常数因子时只写大 O）是很多分析读起来别扭的根源。

## 2.3 设计与不变量：两个计数实例

### 实例一：循环求和

逐行数基本操作：

```text
total = 0;                    // 1 次赋值
for (i = 1; i <= n; ++i)      // 循环控制：n 次比较 + n 次自增
    total += i;               // n 次加法 + n 次赋值
```

总步数形如 `4n + 常数`：每一项都与 n 成正比。公式法无论 n 多大步数恒定，记为常数 C。关键不在 4 这个系数（换编译器就变），而在"一个随 n 线性增长，一个不增长"。

### 实例二：插入排序与"最坏情形"

插入排序像理一手扑克牌：把每张新牌插入前面已有序的牌堆。第 i 张牌（i 从 1 起）最坏要与前 i 个元素全部比较一次，比较次数上界是：

```text
1 + 2 + … + (n-1) = n(n-1)/2
```

示例用 8 个**完全逆序**元素触发这个最坏情形：比较恰为 `8×7/2 = 28`。程序还通过一个 `Counter` 元素类型记录搬运次数——这是一种常用的计数手法：不改算法，只让元素"被拷贝时自己加一"，于是算法的真实搬运量变成可观察的值。

### 实例三：三重嵌套与求和公式

矩阵乘法 C = A×B 的核心是三重循环：

```text
for i in 0..n:                    // n 种取值
    for j in 0..n:                // n 种取值
        for k in 0..n:            // n 种取值
            C[i][j] += A[i][k] * B[k][j];   // 最内层：O(1)
```

三层循环各 n 次，按"嵌套相乘"规则，总步数 Θ(n³)。n=1000 时是十亿次量级的内循环——这解释了为什么科学计算总在优化矩阵乘法，也解释了后面"稀疏矩阵为什么要压缩存储"（绝大多数计算其实是零的自相加）。

计数时反复出现的求和公式只有三个，值得记熟：

```text
1 + 2 + … + n = n(n+1)/2                 （等差）
1 + 3 + … + (2n-1) = n²                  （奇数列）
1 + r + r² + … + rⁿ = (rⁿ⁺¹-1)/(r-1)     （等比，r≠1）
```

插入排序的 n(n-1)/2、几何级数主导的 O(rⁿ) 指数阶，都来自这三个公式。

### 计数中的不变量

计数工作也要抓不变量：**每条语句的执行次数由循环结构唯一确定，与数据值无关的部分照常数，与数据相关的分支按所声明的情形取极值或期望。** 逆序输入下插入排序的每个内层 while 都走到头——这是取上界的条件；若输入已排好序，每次 while 比较一次即退出，总比较只有 n−1 次。同一份代码，不同数据，步数相差一个量级。

## 2.4 复杂度推导：O、Ω、Θ、o

精确统计每个操作繁琐且无必要：只关心增长趋势时，常数和低次项都会被高次项淹没。于是有四把标准的"尺子"。设 T(n) 是操作次数函数。

**（1）大 O——上界。** T(n) = O(f(n)) 表示：当 n 足够大时，T(n) 的增长**不超过** f(n) 的某个常数倍（存在常数 C 和 n₀，使 T(n) ≤ C·f(n) 对所有 n ≥ n₀ 成立）。大 O 是"最坏也坏不过这个量级"的保证书，工程中最常用。

**（2）大 Ω——下界。** 对称地，T(n) = Ω(f(n)) 表示 T(n) 的增长**不低于** f(n) 的某个常数倍，即"至少要花这么多"。

**（3）大 Θ——确界。** T(n) = Θ(f(n)) 表示 T(n) 与 f(n) **同阶**：既是 O 又是 Ω，上下界重合，是最精确的描述。

**（4）小 o——严格小于。** T(n) = o(f(n)) 表示 T(n)/f(n) → 0。大 O 允许同阶，小 o 不允许：`n = o(n²)`，但 `2n` 不是 `o(n)`。

**用定义做一次完整证明。** 设循环求和精确实测为 T(n) = 3n + 5，证明 T(n) = O(n)：按定义只需找出一组常数 C 和 n₀，使 3n+5 ≤ C·n 对所有 n ≥ n₀ 成立。取 n₀ = 5，则 3n+5 ≤ 3n+n = 4n，故 C = 4 可行，证毕。注意 C 和 n₀ 不要求最优——大 O 只关心"存在一组"。同理可证 T(n) = Ω(n)（取 C=1, n₀=1：3n+5 ≥ n），于是 T(n) = Θ(n)。这个"上界取松、下界取紧"的小动作就是 Θ 判定的完整套路。

**计算大 O 的三条实用规则：**

- 忽略常数系数：`3n → O(n)`，`n²/2 → O(n²)`。换快三倍的机器只改常数。
- 忽略低次项：`n³ + 5n² + 100n + 7 → O(n³)`。n→∞ 时高次项压倒性地大。
- 嵌套循环相乘、顺序执行相加：两层各 n 次的嵌套循环是 O(n²)；先 O(n) 再 O(n²) 的两段程序整体 O(n²)。

常见量级由好到坏（体会 n 扩大 10 倍时各自发生什么）：

| 记号 | 名称 | n=10→n=100 | 直观含义 |
|---|---|---|---|
| O(1) | 常数 | 不变 | 与规模无关 |
| O(log n) | 对数 | 3.3 → 6.6 | 每次把规模减半 |
| O(n) | 线性 | ×10 | 每个元素处理一遍 |
| O(n log n) | 线性对数 | ×约 20 | 分治类排序 |
| O(n²) | 平方 | ×100 | 每对元素处理一遍 |
| O(n³) | 立方 | ×1000 | 三重嵌套 |
| O(2ⁿ) | 指数 | 天文数字 | 枚举全部子集 |

对数底数在大 O 中可忽略（换底只差常数倍），统一写 O(log n)。指数是坏消息：2⁶⁰ 已达百亿亿级，n 再增几十便再无希望。

### 最好、最坏与平均情形

同一算法处理不同输入，耗时可能差别巨大。以数组中**顺序查找**为例：

- **最好**：目标在第一位，1 次，O(1)；
- **最坏**：目标在最后或不存在，n 次，O(n)；
- **平均**：目标等概率出现在每位，(1+2+…+n)/n = (n+1)/2，仍 O(n)。

不加说明时"时间复杂度"通常指**最坏情形**，因为它是硬保证。平均情形更贴近体验，但要先假设输入分布，分析更复杂。快速排序这类最坏与平均差距显著的算法，后面会专门标注。

### 递归式：下一章的预告

分治类算法的步数天然写成**递归式**：T(n) = 2·T(n/2) + n（归并排序：两半各递归一次，合并花 n 步），解为 T(n) = Θ(n log n)。递归式的系统解法（主定理）在 CHEATSheet 和后续分治章节给出；眼下只需认识：递归函数的复杂度分析与普通函数同理——先写出每层的步数关系，再解它。

## 2.5 再进一步：递归式与均摊分析预览

**线性表基本操作的复杂度对照。** 把第 01 章"两种存储"的说法落成具体数字，第 04–05 章会逐一验证：

| 操作 | 顺序存储 | 链接存储 |
|---|---|---|
| 访问第 k 个元素 | O(1) | O(k) |
| 在已知位置插入/删除 | O(n)（搬动后继） | O(1)（改指针） |
| 头插 | O(n) 或均摊 O(1) | O(1) |
| 查找（无序） | O(n) | O(n) |

这张表是全教程的缩影：**没有绝对优劣，只有操作频率下的取舍。** 程序以按下标随机访问为主就选顺序，以频繁插删为主就选链接；两类操作都重时才需要更复杂的结构（树、散列），这正是后续章节存在的理由。

**递归式速解两例。** 第 03 章已见递归，其复杂度可直接展开：

- `T(n) = T(n-1) + 1, T(0)=0`：展开 T(n) = T(n-2)+2 = … = n，故 O(n)。阶乘、汉诺塔的每层栈深度都是这个形状。
- `T(n) = T(n/2) + 1, T(1)=0`：每次规模减半、只付一步，层数为 log₂n，故 O(log n)。二分查找即此形状。

**均摊分析（amortized analysis）预览。** 有时"单次操作很贵，但很少发生"，看最坏单次会误判。典型是动态数组（第 04 章 ArrayList）的扩容：容量翻倍时要把全部旧元素搬到新数组，单次 push 最坏 O(n)；但连续 n 次 push 的总搬运量是 `1+2+4+…` 式的几何级数，总和不超过 2n，**平均每次 push 仍是 O(1)**。这种"一串操作的总账"分析叫均摊分析，第 04 章会完整走一遍。

## 2.6 空间复杂度

空间分析用完全相同的记号：只用一个长度 n 的辅助数组 → O(n)；只用几个与 n 无关的临时变量 → O(1)，称为**原地**算法。冒泡排序只做相邻交换、额外空间恒定，是 O(1)；归并排序需要一块同等大小的临时区，是 O(n)。递归算法还要把**调用栈深度**计入空间：朴素递归二分查找栈深 O(log n)，这个账第 03 章细算。

一个常被忽略的细节：**输入本身占的空间通常不计入辅助空间复杂度**——它是调用方给的，换算法也省不掉。所以"空间复杂度"一般指算法额外申请的部分（辅助空间）。例如就地逆置数组只用一两个临时变量做交换 → 辅助空间 O(1)；若另开一个等长数组存放结果 → O(n)，即使两份程序的输入数组同样大。读到"O(1) 空间排序"时，这个口径要清楚。

## 2.7 完整示例输出

示例程序做了两个确定性实验（全部固定数据，不依赖钟表）：

```text
1+…+100 = 5050：循环法步数与 n 成正比（100 次加法），公式法步数恒定（1 次）
8 元素全逆序插入排序：比较 28 次（最坏情形 n(n-1)/2），排序后有序
自检通过
```

逐行解释：

- 第一行对照同一问题的两种算法：**线性增长 vs 常数增长**。结果相同（断言保证都是 5050），步数的增长趋势完全不同；
- 第二行给出插入排序最坏情形的精确计数：**28 = n(n-1)/2**，验证 2.3 节推导；同时断言排序结果确实有序——计数与正确性两件事都成立。

两个例子都不打印真实耗时：秒数含硬件噪声、不可逐字节复现；"步数随 n 的增长趋势"才是可迁移知识。

## 2.8 与标准库及计时工具的对照

渐近分析是纸面推演，工程中还需**实测**验证分析、比较常数因子。C++ 的 `<chrono>` 提供高精度计时，典型模式：

```text
auto start = std::chrono::steady_clock::now();
// …被测代码…
auto elapsed = std::chrono::steady_clock::now() - start;
```

把时间差换算成具体单位时用 `std::chrono::duration_cast<毫秒或微秒>`，注意它是向零截断的整数换算——小数部分直接丢弃，极短区间应使用更小的目标单位，否则会得到一串 0。

实测纪律（全教程统一遵守）：用单调的 `steady_clock`（不受系统时钟调整影响）；重复多次取统计量以抵消缓存与调度干扰；数据固定；先 warm-up 一轮（让代码与数据进入缓存、让编译器的惰性初始化完成）再计正式轮次。但**实测只验证常数，不能替代复杂度分析**——再快的 O(n²) 在 n 足够大时也必输 O(n log n)，这是数学保证。标准库的 `std::sort` 要求平均 O(n log n)，各查找算法的复杂度也在标准中写明；亲手分析后再读这些条款，你会清楚每条承诺的分量。

小结：本章的产出不是几个公式，而是一种工作习惯——**谈性能先定规模与情形，数步数而非秒数，报趋势而非常数。** 带着这个习惯进入线性结构部分，你会发现"为什么这个操作是这个复杂度"全都有迹可循。

## 2.9 本章坑位

- **坑 1：把大 O 当精确耗时。** 现象：争论"O(n) 和 O(2n) 哪个好"。原因：大 O 忽略常数系数，二者同阶。后果：在错误层次上纠结；常数差异靠实测，量级差异靠分析。
- **坑 2：用小数据实测推断复杂度。** 现象：n=10 时插入排序比归并快，就断定插入更好。原因：小规模下低次项与常数开销主导，趋势未显。后果：上线后数据涨大，性能塌方。
- **坑 3：不声明情形。** 现象：只说"快排 O(n log n)"。原因：那是平均情形，最坏 O(n²)。后果：把平均保证当最坏保证，在对抗输入下翻车。
- **坑 4：循环边界数错。** 现象：插入排序最坏比较写成 n(n+1)/2。原因：i 的范围是 1..n−1。后果：推导基数错误。防法：数小例子（n=2 时恰 1 次）。
- **坑 5：漏掉递归栈空间。** 现象：把递归快排标为 O(1) 空间。原因：只看了显式变量，没算调用栈。后果：深递归下栈溢出，且对内存占用估计失真。防法：凡见递归，空间分析必含最大栈深一项。
