# 13 · 堆与堆排序：用一棵完全树管理"优先权"

## 13.1 动机与直觉：排队时，谁该先被服务

第 08 章的队列遵循一条铁律：先到先服务。但现实中的等待线并不总是民主的。设想：

- 急诊室同时来了三位病人——一位轻微擦伤、一位骨折、一位心脏骤停。谁先被处理？显然不是按挂号顺序，而是按**病情危急程度**；
- 操作系统里有一百个程序在等 CPU，一个马上要超时的网络包和一个后台日志压缩任务，谁先得到处理器？按**紧迫程度**；
- 打印机队列里，老板的一份合同和你的二十页会议材料同时排队——在很多公司，优先级高的用户先打印。

这些场景需要一种新结构：元素依然排队，但**出队次序由"优先权"决定，与到达时间无关**。这就是优先队列（priority queue）。它支持三个核心动作：插入一个带优先权的元素、查看当前优先权最高的元素、取出并删除它。

最直接的实现是有序数组：插入时保持有序（O(n)），取最值伸手就来（O(1)）；或者无序数组：插入 O(1)，取最值要扫描全体（O(n)）。两头总得便宜一头。有没有可能让三个动作都快？答案是堆：一棵形状规整的二叉树，插入和取出都是 O(log n)，查看最值是 O(1)，而且**不需要任何指针**——这棵树可以整个装进一个数组。

本章还会得到一个副产品：既然堆能不断取出剩余元素中的最大值，把这个过程倒着写入数组，就得到一种 O(n log n)、就地、且最坏情形也是 O(n log n) 的排序——堆排序。

## 13.2 ADT 合同：优先队列承诺什么

先写合同，再谈实现。

- **push(x)**：事后条件——元素总数加一；新集合中优先权最高者可取；其余元素不受影响。
- **top()**：前提——结构非空，否则是编程错误、实现抛异常；返回当前优先权最高的元素但不移除，可重复调用结果一致。
- **pop()**：前提同上；删除优先权最高者，元素总数减一。
- **empty() / size()**：无前提，不改变状态。

合同里有一个必须先定的方向问题："优先权最高"是指**最大**还是**最小**？两种约定都常见：急诊室取危急值最大者；而工厂仿真里事件按完成时间排序，要取时间最小者。与其写两份代码，不如把"谁比谁优先权更高"做成一个可替换的比较规则：

```cpp
template <std::totally_ordered T, class Compare = std::less<T>>
class BinaryHeap { /* … */ };
```

`std::less<T>` 表示"更小者优先权更高"，得到最小堆（默认）；传入 `std::greater<T>` 得到最大堆。本章示例两种都会用到：插入实验用最小堆，出队序列实验用最大堆。

## 13.3 设计与不变量

### 13.3.1 第一步：一棵完全二叉树

普通二叉树用指针串节点，找根到叶的路径要一步步跳。堆要快，就必须让"从根一路下到叶"的路径短且规整。堆选用的树是**完全二叉树（complete binary tree）**：除了最后一层，每一层都被节点填满；最后一层的节点从最左侧连续排起，不许中间留洞。

```text
        1                 层数 0
      /   \
     3     2              层数 1
    / \   / \
   7   5 9   8            层数 2（满）
```

完全二叉树有两个宝贵性质。其一，高度为 ⌊log₂n⌋——n=100 万时树高只有 19，这是所有操作 O(log n) 的根源。其二，**它可以原样铺平成数组，不需要任何指针**：按层、每层从左到右编号，节点的位置就唯一确定了。

### 13.3.2 下标公式：父子关系靠算术

把根放在下标 0，按层编号，父子关系完全由下标决定：

```text
节点 i 的父节点：    (i − 1) / 2     （整数除法）
节点 i 的左孩子：    2i + 1
节点 i 的右孩子：    2i + 2
```

拿上图验证：下标 1 的节点 3，父节点 `(1−1)/2 = 0`（节点 1）；它的左孩子 `2×1+1 = 3`（节点 7），右孩子 `2×1+2 = 4`（节点 5）。不必存储任何地址，一次乘除就能在父子间跳转。这就是"公式化描述"——用算术代替指针，省空间、快定位。

### 13.3.3 堆序不变量

光有完全树的形状还不够，树里的值也要守规矩。堆只需要一条规则：

> **每个节点都不比它的父节点优先权更高。**

最小堆下具体化为"父 ≤ 子"，最大堆下为"父 ≥ 子"。这条规则只约束父子两层，不约束兄弟节点之间谁大谁小。它立刻推出一个关键结论：**根是全局最值**——沿任何一条从根到叶的路径，优先权单调不增，所以最小堆的根最小、最大堆的根最大，top() 直接返回数组首元素即可。

前面 13.3.1 的图就是一棵最小堆：根 1，子 3、2；3 的子 7、5。注意 3 > 2（左子比右子大）并不违规——堆不要求兄弟有序。

### 13.3.4 入队：把新元素"浮"上去

插入位置没有选择：为了保持完全树的形状，新元素只能追加到数组末尾（最后一层最右侧的空位）。但这个位置可能违反堆序——新元素也许比父亲优先权高得多。修复手法是**上浮（sift up）**：比较新元素与父亲，若它优先权更高就和父亲交换，然后在父亲的位置继续比较，直到遇到一个优先权不低于它的父亲，或它自己成了根。

```cpp
void sift_up_(size_t i) {
    while (i > 0) {
        const size_t p = (i - 1) / 2;
        if (!comp_(data_[i], data_[p])) break;
        std::swap(data_[i], data_[p]);
        i = p;
    }
}
```

`comp_(a,b)` 表示"a 比 b 优先权更高"。交换为什么一定能恢复局部堆序？新元素与父亲交换后，它在新位置上显然合法（它比新父亲——即旧位置上的自己——优先权低的情形已被排除……更直接的论证：它一路只与优先权比自己低的父亲交换，沿途经过的父节点都比它优先权低，所以它上浮后，下面被它压着的节点都合法）。每上浮一层向上走一层，至多走树高那么多。

### 13.3.5 出队：把末元素"沉"下去

删除最值同样要兼顾形状：根被拿走后，完全树的"最后一个节点"（数组末尾）空了出来，别的位置都不能直接空着。做法是把末元素搬到根，树缩小 1。新根可能优先权比孩子低，于是反向操作——**下沉（sift down）**：与两个孩子中优先权更高的那个比较，若孩子优先权更高就与之交换，继续向下，直到两个孩子都不如自己，或自己成了叶子。

```cpp
void sift_down_(size_t i) {
    const size_t n = data_.size();
    while (true) {
        size_t best = i;
        const size_t l = 2 * i + 1, r = 2 * i + 2;
        if (l < n && comp_(data_[l], data_[best])) best = l;
        if (r < n && comp_(data_[r], data_[best])) best = r;
        if (best == i) break;
        std::swap(data_[i], data_[best]);
        i = best;
    }
}
```

为什么必须和"优先权更高的那个孩子"交换，而不是随便哪个违规的孩子？因为若只和优先权较低的孩子交换，优先权更高的那个孩子仍然违规，一层修复留下一个洞。取两个孩子中的更优者，交换后两支都合法。

### 13.3.6 批量构造：heapify 为什么只要 O(n)

若已经有了 n 个元素，朴素做法是逐个 push，成本 n log n。但有更快的路径：把元素随便放进数组（形状已是完全树），然后**从最后一个非叶节点起，自后向前逐个下沉**。

为什么这样可行？下沉一个节点时，它的两个子树必须已经是堆——自后向前处理恰好保证：孩子的下标比父亲大，处理父亲时两个孩子都已调整完毕。而所有叶子（占节点总数一半以上）没有孩子、本就合法，直接跳过。

```cpp
void heapify_() {
    for (size_t i = data_.size() / 2; i-- > 0;) {
        sift_down_(i);
    }
}
```

这里的循环写法有个玄机：`i-- > 0` 让下标 0 的根也被处理一次，同时 i 是无符号类型也不会在减到 −1 时出问题。

成本为何是 O(n) 而不是 O(n log n)？直觉上，绝大多数节点都在树的底层、下沉距离很短：n/2 个叶子下沉 0 层，n/4 个节点最多下沉 1 层，n/8 个最多 2 层……总工作量是一个几何级数 `n/4·1 + n/8·2 + n/16·3 + … ≤ n`。这是"自底向上下沉"相比"逐个上浮"的结构性优势，示例的构造函数用的就是它。

### 13.3.7 堆排序：让最大值自己走到队尾

最后把堆变成排序机。第一步把数组就地建成**最大堆**（下沉法，O(n)）。此后反复：根是当前未排序区的最大值，把它与未排序区最后一个元素交换——最大值一步到位落到它在有序结果中的最终位置；未排序区缩小 1，新根在缩小后的区间里下沉恢复堆序。n−1 轮后全体就位。

整个算法只做交换，不另开数组，额外空间 O(1)。示例代码把下沉逻辑直接写在 `heap_sort` 内部、比较方向固定为"取大"，因为这是一个不依赖堆类的自包含实现。

### 13.3.8 手工推演：把 4 插入一棵最小堆

纸上走一遍上浮全过程，这是检验理解的最好方式。设当前最小堆为 `[1, 3, 2, 7, 5, 9, 8]`，插入 4：

```text
追加到末尾：  [1, 3, 2, 7, 5, 9, 8, 4]
4 的父亲是下标 3 的 7：4 < 7，交换
            [1, 3, 2, 4, 5, 9, 8, 7]
4 的父亲是下标 1 的 3：4 < 3 不成立，停止
```

最终数组仍是合法最小堆。注意 4 只上浮了一层——插入的成本取决于它实际要越过多少个优先权更低的祖先，最坏才是 log n。

### 13.3.9 堆做不到的事：任意删除与改优先权

堆的合同只保证根上的最值，不擅长另外两类操作：删除任意一个指定元素（先要找到它，堆不支持快速查找，扫描要 O(n)）；提升某个内部元素的优先权（经典的 decrease-key，需要调用方自己持有元素位置）。图算法中的 Dijkstra（第 20 章）频繁需要 decrease-key，用本章裸堆时只能"删了重插"，或改用更专门的索引堆。读到那里时记住：**堆为"插入 + 取最值"这一对动作优化到了极致，偏离这个模式就要付额外代价**，不要因为 priority_queue 名字里有 queue 就以为它是万能字典。

工程中还有个常见误用：向 `priority_queue` 里存入元素后修改外部副本，队列内部的优先级不会更新——存的是值的拷贝。需要反映新优先级时必须显式弹出旧的、压入新的。

## 13.4 复杂度推导

| 操作 | 时间 | 理由 |
|---|---|---|
| top() | O(1) | 根固定在数组首位置 |
| push(x) | O(log n) | 上浮路径至多等于树高 ⌊log₂n⌋ |
| pop() | O(log n) | 下沉路径同理 |
| 批量构造 | O(n) | 底层节点占多数、总下沉距离为几何级数 |
| is_heap() | O(n) | 检查每个非根节点一次 |
| heap_sort | O(n log n) | 建堆 O(n) + n−1 次下沉 O(log n) |
| 额外空间 | O(1) | 堆本身之外只用常数个临时变量 |

两个值得特别记住的对比。第一，堆的**最坏情形就是 O(log n)**——不像快速排序有最坏 O(n²) 的软肋，因为完全树永远平衡，输入怎样安排都改变不了树高。第二，堆排序在比较类通用排序中是渐近最优的：任何只靠成对比较的排序都需要 Ω(n log n) 次比较，堆排序恰好达到这条下界。

## 13.5 完整示例输出

```text
逐插入 7 个元素：每次插入后 is_heap 成立，堆顶为 1
空堆 pop 抛出异常
最大堆逐个出队：9 6 5 4 3 2 1 1 
堆排序（乱序夹具）：-3 0 1 1 2 3 4 5 6 9
堆排序（降序夹具）：-2 1 3 5 7 9
自检通过
```

逐行解释：

- 第 1 行：最小堆接收 7 个元素，程序在**每一次**插入后都断言堆序成立——这验证的是"上浮"的增量正确性，而非只检查最终状态；堆顶恰为全体最小值 1；
- 第 2 行：空堆调用 pop 违反前提，异常被捕获，合同中的出错条款成立；
- 第 3 行：核心验证。8 元素 `{3,1,4,1,5,9,2,6}` 经 heapify 一次构造成最大堆，出队序列**恰为 9,6,5,4,3,2,1,1**——每次取出的都是剩余元素的最大值，两个并列的 1 在最后相邻出队，序列长度守恒；
- 第 4、5 行：堆排序对乱序夹具和全降序夹具都得到正确的升序结果。降序夹具值得注意：它一开始就已经是最大堆，建堆阶段什么都不用改——程序用它验证了"输入有利时结果仍正确"，而不是只在典型数据上成立。

## 13.6 与标准库的对照

- **`std::priority_queue<T, Container, Compare>`**：标准库的优先队列，定义在 `<queue>`。默认 `Compare = less<T>`，但注意它的语义是"**比较结果为真者排在下面**"——默认弹出的是**最大**元素，与本章最小堆默认方向恰好相反；传入 `greater<T>` 才得到最小堆。读到这里不要想当然，用之前先验证弹出方向。它是容器适配器，默认底座是 `std::vector`。
- **堆操作自由函数**：`<algorithm>` 提供 `std::make_heap / push_heap / pop_heap / sort_heap / is_heap`，直接在随机访问区间上操作，本章类的每个成员都能对应其中一个：构造对应 make_heap，push 对应 push_heap，pop 对应 pop_heap，排序对应 sort_heap。其中 `pop_heap` 只把根换到区间末尾、不缩小容器，真正移除元素要再调用 `pop_back()`——这个两步设计在初次使用时常被漏掉。
- **比较方向的工业含义**：标准库的排序与堆统一用 comp(a,b) = true 表示"a 应排在 b 前面"；本章实现沿用同一约定。亲手写完再看 priority_queue，就不会被默认方向绕进去。

## 13.7 本章坑位

- **坑 1：下标从 1 起算的公式直接搬到 0-based 数组。** 现象：写成左孩子 `2i`、右孩子 `2i+1`，根下标 0 的左孩子算成 0（指向自己）。原因：教科书公式分 1-based（2i、2i+1、⌊i/2⌋）与 0-based（2i+1、2i+2、⌊(i−1)/2⌋）两套。后果：父子关系错乱，堆序检查出现自比自的死结。防法：写下公式后用 3 个节点的小树手工验证。
- **坑 2：出队后直接删除根。** 现象：移除 data_[0] 后整体前移元素，O(n) 成本且容易写挂。原因：忘记了正确做法是"末元素搬根 + 下沉"。后果：性能退化、完全树形状被破坏。
- **坑 3：下沉时只与一个孩子比较。** 现象：只看左孩子违规就交换，右孩子优先权更高却仍违规。原因：下沉必须选两个孩子中的更优者。后果：交换后堆序未恢复，pop 出队序列错误。
- **坑 4：heapify 从根开始处理。** 现象：自上而下下沉时，子树还不是堆，调整完父亲，后面孩子的变化再次破坏父亲。原因：方向反了，应自最后一个非叶节点向前。后果：得到的数组不是堆。
- **坑 5：混淆 priority_queue 的默认方向。** 现象：以为 `priority_queue<int>` 弹出最小值。原因：标准库默认 less 弹出最大值，与直觉命名相反。后果：调度逻辑优先级颠倒。防法：切换方向后用固定数据弹出一次验证。
- **坑 6：堆排序里建错堆的方向。** 现象：想要升序结果却建了最小堆，根是最小值，换到队尾后得到降序。原因：升序排序必须建最大堆（最大值先去末尾）。后果：排序结果整体反序。防法：记住"换根到尾"这一步决定了堆的方向。
