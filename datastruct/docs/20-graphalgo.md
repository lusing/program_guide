# 20 · 图算法：最短路、最小生成树、关键路径

## 20.1 动机与直觉

第 19 章解决的是"把图存下来、把每个顶点走一遍"。但现实里我们关心的问题往往不是"能不能走到"，而是"怎么走最划算"：

- 地图导航：从公司回家有几十条路线，哪条**路程最短**、哪条**耗时最少**？
- 架光缆：要把五个城市连成一张网，每两个城市之间铺缆的造价不同，怎样布线能让**所有城市互通且总造价最低**？
- 工程排期：一场婚礼有"定酒店→发请柬→摆酒席"等先后工序，每道工序耗时不同，哪些工序一旦延误，整场婚礼就必然推迟？

这三类问题对应图论里三块基石：**最短路**（shortest path）、**最小生成树**（minimum spanning tree, MST）、**关键路径**（critical path）。它们各自都有不止一种经典算法，而本章之所以把它们放在一起，是因为它们共享同一个思维内核——**松弛（relaxation）**：

> 手里先有一个"当前最优估计"，每当发现一条新的路径/边，就检查"走这条新路会不会更好"，会就更新估计。反复松弛，直到估计收敛成精确答案。

最短路松弛的是距离，MST 松弛的是"跨进树的最便宜边"，关键路径松弛的是"最早/最晚开工时刻"。看懂松弛，这一章的五个算法只是同一句话在不同场景下的展开。

本章用一个贯穿全章的固定例子，保证每个数字你都能手算核对：

```
无向加权图 G1（顶点 0..4，共 6 条边）
  0—1 : 4     0—2 : 1     2—1 : 2
  1—3 : 1     2—3 : 5     3—4 : 3
```

先凭直觉感受：从顶点 0 到顶点 1，直接走是 4；但先花 1 走到 2，再花 2 走到 1，总共只有 3。**绕路反而更近**——这正是最短路算法存在的理由，也是人凭直觉容易选错的地方。

## 20.2 ADT 合同

本章在第 19 章两种存储结构上操作，算法对外的合同（contract）比数据结构本身更重要。合同先讲清楚"什么输入合法、出错时怎么办"，再谈怎么实现。

**单源最短路 Dijkstra**

- 输入：一个加权图 `g` 和源点 `s`，`0 ≤ s < n`。
- 前提：**所有边权非负**。这是算法成立的硬条件，不是建议。
- 返回：长度为 `n` 的距离数组，`dist[v]` 是从 `s` 到 `v` 的最短距离；不可达顶点保留"无边"哨兵值。
- 出错：`s` 越界抛 `std::out_of_range`；一旦扫描到负权边抛 `std::invalid_argument`。

**全源最短路 Floyd**

- 输入：加权图（用邻接矩阵最自然，因为答案本身就是矩阵）。
- 返回：`n × n` 距离矩阵，`at(i,j)` 是 `i` 到 `j` 的最短距离。
- 约定：`at(i,i) == 0`；无向图结果对称；不连通的两个点保留哨兵值。
- 适用：边权可正可负，但**不能有负权总长度的环**（否则最短路没有定义）。

**最小生成树 Prim / Kruskal**

- 输入：**无向**加权图，且必须**连通**。
- 返回：`n−1` 条边（恰好连通全部 `n` 个顶点、不成环）及其总权；总权在所有生成树中最小。
- 出错：有向图抛 `std::invalid_argument`（MST 定理不适用）；图不连通同样抛异常，因为生成树根本不存在。
- 一致性要求：Prim 和 Kruskal 是同一问题的两种算法，本章固定数据下它们返回的**边集必须完全相同、总权都为 7**。这是极好的交叉验证。

**关键路径 critical_path（AOE 网络）**

- 输入：**有向无环图**，顶点表示"事件"，边表示"活动"，边权是活动耗时。
- 返回：总工期 `length`，以及时差（slack）恰为 0 的关键活动列表。
- 出错：传入无向图抛异常；图中有环（无法拓扑排序）时返回 `std::nullopt`——这是"可预期失败用 optional，程序错误用异常"原则的直接应用。

## 20.3 设计与不变量

### 20.3.1 无边哨兵：先解决"没有边"怎么表示

加权算法首先要回答：矩阵里两个点之间没有边，填什么？常见做法是填一个极大的数 `INF`。本章取 `kNoEdge = 1e18`，并立下不变量：

- 任何真实路径长度都远小于 `kNoEdge`；
- 代码里凡是"经过一条不存在的边"的松弛，**先判断两段路是否已达到哨兵的一半（`kNoEdge/2`），达到就跳过，绝不把两个哨兵相加**。

为什么必须这么小心，留到 20.6 的坑位里算给你看。

### 20.3.2 Dijkstra：贪心 + 最小堆

Dijkstra 的直觉是"**最近的点先 settle**"。维护 `dist[]` 作为当前最短估计，用一个最小堆反复取出估计值最小的顶点：

```cpp
while (!pq.empty()) {
    const auto [d, u] = pq.top(); pq.pop();
    if (d != dist[u]) continue;          // 过期候选，跳过
    for (const Edge& e : g.out_edges(u)) {
        const double nd = d + e.w;       // 试探：经过 u 绕到 e.to
        if (nd < dist[e.to]) {           // 松弛成功
            dist[e.to] = nd;
            pq.emplace(nd, e.to);
        }
    }
}
```

这段代码的每一行都对应一条不变量：

- 弹出 `(d,u)` 时，`d` 是这个顶点**某次**入堆时的估计。同一个顶点可能被松弛很多次、在堆里留下多个旧条目；`if (d != dist[u]) continue` 保证只有"最新、最小"的那次被处理，旧条目全部丢弃。
- `nd < dist[e.to]` 是松弛的唯一入口：只有严格更短才更新。边权非负时，一个顶点一旦以当前最小距离出堆，它的距离就被永久确定——这是 Dijkstra 正确性的核心，称为**贪心选择性质**。
- 初始化 `dist[s]=0`、其余为哨兵，堆里先放 `(0,s)`：从零长度的源点开始生长。

为什么非负边是硬条件？因为 Dijkstra 默认"已经出堆的点不可能再被一条更短的路径经过"。若存在负边，后来者可能用一条负权边把老路变得更短，而那个点早已 settle，算法不会回头——答案就错了。负权场景的正确工具是 Bellman-Ford。

### 20.3.3 Floyd：允许"途经点集合"逐个扩大

Floyd 的思路极为精巧：`d[i][j]` 一开始只允许"直达边"；然后依次允许路径**经过顶点 0、经过顶点 0 或 1、……**。当允许经过顶点 `k` 时，只有两种可能：

- 最优路径不经过 `k`：保持 `d[i][j]`；
- 最优路径经过 `k`：拆成 `i → k → j`，即 `d[i][k] + d[k][j]`。

```cpp
for (int k = 0; k < n; ++k)
    for (int i = 0; i < n; ++i) {
        if (result.at(i, k) >= kNoEdge / 2.0) continue;
        for (int j = 0; j < n; ++j) {
            if (result.at(k, j) >= kNoEdge / 2.0) continue;
            const double nd = result.at(i, k) + result.at(k, j);
            if (nd < result.at(i, j)) result.at(i, j) = nd;
        }
    }
```

**`k` 必须在最外层**，这是 Floyd 最容易写错的地方（坑位详谈）。两个 `continue` 保证不会拿"不通的路"去做加法。就地更新矩阵是安全的：`d[i][k]` 和 `d[k][j]` 在第 `k` 轮里不会变化（最优路径不会重复经过 `k`），不存在"用半新不旧的值覆盖"的问题。

### 20.3.4 Prim：从一个点长成一棵树

Prim 像"滚雪球"：从源点开始，维护一棵树，每一步把**连接树内与树外的最轻边**拉进来。`key[v]` 记录顶点 `v` 到当前树的最便宜跨边权：

```cpp
for (int step = 0; step < n; ++step) {
    int u = -1; double best = kNoEdge;
    for (int v = 0; v < n; ++v)
        if (!in_tree[v] && key[v] < best) { best = key[v]; u = v; }
    if (u < 0) throw std::invalid_argument("prim: graph is not connected");
    in_tree[u] = true;                       // u 连同 best 这条边入树
    for (int v = 0; v < n; ++v) {            // 用 u 的边松弛其余点
        if (!in_tree[v] && g.weight(u, v) < key[v]) {
            key[v] = g.weight(u, v); parent[v] = u;
        }
    }
}
```

不变量：每次循环结束，树恰好多一个顶点；`key[v]` 始终是 `v` 到树的最轻跨边。Prim 的正确性来自图论的**割性质**：把顶点切成"树内/树外"两部分，横跨这个割的最轻边一定属于某棵最小生成树。每轮贪心选它，总结果最优。本例用邻接矩阵 + 线性扫描找最小，写法直观；若改用邻接表 + 堆，复杂度可以进一步降低。

### 20.3.5 Kruskal：全局排序 + 并查集

Kruskal 换了个视角：不维护一棵生长的树，而是把**所有边按权从小到大**摊开，依次考虑"这条边的两个端点是否已经连通"：

- 还没连通：收下这条边，把两块合并；
- 已经连通：跳过——再收就成环了。

判断"是否连通、合并两块"由第 19 章见过、这里独立实现的**并查集（Dsu）**完成：`find` 带路径压缩，`unite` 按秩合并。Kruskal 的正确性来自**环性质**：一条边若在当前森林里造成环，它一定不是必需的；而按权升序保证了我们优先用最便宜的边去连接新分量。收齐 `n−1` 条边恰好得到一棵树；若边用完还不够 `n−1`，说明图不连通。

### 20.3.6 关键路径：先拓扑，再前推后拉

工程网络（AOE）里，一个事件必须等它的**所有前导活动**都完成才能发生。算法分四步：

1. **Kahn 拓扑排序**：不断取入度为 0 的顶点。取不满 `n` 个就是有环，返回 `nullopt`。
2. **前向求最早时刻 `ve`**：沿拓扑序，`ve[v] = max(ve[u] + 活动耗时)`。取 max 是因为事件要等最慢的那条前导路径。
3. **总工期 = 所有 `ve` 的最大值**；再以它为终点的最迟时刻，**逆拓扑序**求最迟时刻 `vl[u] = min(vl[v] − 活动耗时)`。
4. 每条活动 `(u,v)` 的**时差** = `vl[v] − ve[u] − 耗时`：它最多能拖延多久而不影响总工期。时差为 0 的活动就是关键活动，它们串成关键路径。

关键路径上的任何活动延误一天，总工期就延误一天——这正是项目管理要死盯这些活动的原因。

## 20.4 复杂度推导

| 算法 | 时间复杂度 | 额外空间 | 依赖的存储 |
|---|---|---|---|
| Dijkstra（二叉堆） | O((V+E) log V) | O(V) | 邻接表 |
| Floyd | O(V³) | O(V²)（就地） | 邻接矩阵 |
| Prim（矩阵 + 线性扫描） | O(V²) | O(V) | 邻接矩阵 |
| Kruskal | O(E log E) | O(V) | 边集 + 并查集 |
| 关键路径 | O(V+E) | O(V) | 邻接表 + 拓扑 |

几个要点值得推导清楚：

- **Dijkstra**：每条边最多触发一次成功松弛、入一次堆；每个堆操作 O(log V)。总共 O(E) 次松弛、O(V) 次出堆，合计 O((V+E) log V)。稠密图上 E≈V²，此时不如矩阵法；稀疏图上它远胜 Floyd。
- **Floyd** 是整齐的三重循环，O(V³) 一目了然。它一次算出**所有点对**的距离；若只需要单源，Dijkstra 更划算。它的最大优势是代码极简、且能处理负权边。
- **Prim** 的矩阵实现里，每轮用一次 O(V) 扫描找最小顶点、再 O(V) 松弛邻点，共 `n` 轮，O(V²)。换成邻接表 + 堆可降到 O(E log V)。
- **Kruskal** 的时间几乎全花在排序上 O(E log E)；并查集每次操作接近常数（反阿克曼函数 α(V)，实际可当常数），所以后续扫描 O(E·α(V)) 可忽略。
- **关键路径**：Kahn 拓扑、前向、反向各扫一遍所有边，总共 O(V+E)，是本章最快的算法，但它只回答"工期与关键活动"这一个专门问题。

下面是示例程序的**真实运行输出**（MSVC 与 clang 两通道逐字节一致，gcc 通道因本机 `<print>` 探针失败而按既定规则跳过）：

```text
Dijkstra(0) 距离：0 3 1 4 7
Floyd 全源距离矩阵（不可达打印 -1）：
   0   3   1   4   7
   3   0   2   1   4
   1   2   0   3   6
   4   1   3   0   3
   7   4   6   3   0
Prim 最小生成树（总权 7）：
  0 ── 2
  1 ── 2
  1 ── 3
  3 ── 4
Kruskal 最小生成树（总权 7）：边集与 Prim 完全相同
AOE 总工期 5；关键活动：
  0 → 2
  2 → 3
有环 AOE：不返回关键路径
Dijkstra 遇负权边：抛异常
自检通过
```

逐行核对，每个数字都能手算出来：

- **`Dijkstra(0) 距离：0 3 1 4 7`**。到 0 是 0；到 2 走直达边为 1；到 1 不选直达的 4，而走 `0→2→1` = 1+2 = 3；到 3 走 `0→2→1→3` = 3+1 = 4（比 `0→2→3` 的 1+5=6 更短）；到 4 再加上边 `3—4` 的 3，得 7。这印证了开头"绕路更近"的直觉。
- **Floyd 矩阵第 0 行 `0 3 1 4 7`** 与 Dijkstra 完全一致——两种独立算法互相验证。矩阵对称（无向图），对角线全 0。几个值得看的格子：`(2,4) = 6` 走 `2→1→3→4` = 2+1+3；`(1,4) = 4` 走 `1→3→4` = 1+3。本例恰好全连通，所以没有出现打印 `-1` 的位置；打印规则仍在代码中保留。
- **Prim 四条边**：`0—2`(1)、`1—3`(1)、`1—2`(2)、`3—4`(3)，总权 1+1+2+3 = **7**。它们连通了 5 个点且不成环。
- **Kruskal 边集与 Prim 完全相同**：按权排序后边 `1` 的有两条（0—2、1—3），先收下；接着是权 2 的 1—2（把两块连起来）；再是权 3 的 3—4；此时已 4 条边、5 个点全连通。总权同为 7。两种算法殊途同归。
- **AOE 总工期 5，关键活动 `0→2`、`2→3`**。手算：路径 `0→1→3` 耗时 3+1=4，路径 `0→2→3` 耗时 2+3=5，最慢的 5 决定总工期。走上面那条路的活动各有 1 个单位时差（可以拖延而不影响工期），下面这条路上的活动时差为 0，必须死盯。
- **有环 AOE 不返回关键路径**：两个顶点互相指向，Kahn 无法收齐顶点，函数返回 `nullopt`。
- **Dijkstra 遇负权边抛异常**：合同里的非负前提被主动检查并拒绝。
- 最后一行 **`自检通过`** 是全教程统一的收尾信号：前面所有 `assert` 全部通过，程序才会走到这里。

## 20.6 标准库对照

C++ 标准库**没有**提供图或图算法（这是和排序、容器不同的地方），但它把搭算法所需的零件都备齐了，本章全部用标准零件自己组装：

- `std::priority_queue<T, std::vector<T>, std::greater<T>>`：Dijkstra 的最小堆。默认 `priority_queue` 是最大堆，传入 `std::greater` 才变成最小堆——这是极常见的一个考点。
- `std::queue`：Kahn 拓扑排序里存放"当前入度为 0"的顶点，先进先出。
- `std::iota`：并查集初始化时把 `parent` 填成 `0,1,2,…`，比手写循环更能表达意图。
- `std::ranges::sort / lower_bound / any_of / max_element`：边排序、邻接表有序插入、边存在性判断、求总工期，全部使用范围版本，免去手写 `begin/end`。
- `std::optional`：关键路径"有环"这一可预期失败用 `nullopt` 表达，调用方必须显式处理，而不是靠一个危险的返回值。
- 标准异常：程序错误（越界、违反非负/无向前提）用 `std::out_of_range`、`std::invalid_argument`，与"可预期失败用 optional"形成清晰分工。

标准库之外，Boost.Graph 提供了现成的 BGL 图算法框架，适合工程中直接调用；但学习阶段自己用上述零件实现一遍，才能真正理解算法的不变量。

## 20.7 坑位

**坑 1：Dijkstra 拿去跑负权边。**
现象：得到一个看起来"正常"却错误的距离。原因：负边可能让已 settle 的顶点出现更短路径，而算法不回头。后果：导航、计费类系统静默出错，最难排查。对策：扫描到负权边立即抛异常；确有负权时改用 Bellman-Ford。

**坑 2：把两个"无边"哨兵相加。**
现象：不可达的两点被判成可达，甚至距离变成奇怪的数。原因：松弛时直接 `INF + w` 或 `INF + INF`。整数下可能上溢回绕成负数，浮点下 `1e18 + 1e18 = 2e18` 反而可能被后续比较误判。后果：最短路被凭空造出来。对策：先判断任一段是否已达 `kNoEdge/2`，是则跳过，绝不相加。

**坑 3：Floyd 把 `k` 循环写进里层。**
现象：结果时对时错。原因：`k` 的语义是"当前允许经过的中间点集合"，必须保证用到的 `d[i][k]`、`d[k][j]` 已在更小的集合上算完；循环层级错了，子问题尚未求解就被引用。后果：漏掉真正的最优路径。对策：牢记"中间点 k 最外层"，写三重循环时先写 `k`。

**坑 4：不跳过堆里的过期候选。**
现象：同一顶点被反复松弛，甚至把旧的大距离当当前距离。原因：每次改进都入堆，堆里残留同一顶点的多个条目。后果：多余计算乃至错误更新。对策：弹出后用 `if (d != dist[u]) continue;` 丢弃旧条目。

**坑 5：把 Prim/Kruskal 用到有向图上。**
现象：得到一个含义不清的"树"。原因：割性质、环性质这些 MST 定理建立在无向图上，有向图的对应问题（最小树形图）是另一套算法。后果：结果不满足"连通所有顶点"的预期。对策：入口检查 `directed()`，有向即拒绝。

**坑 6：有环的 AOE 网络还硬算 ve/vl。**
现象：总工期或关键活动错误，甚至用到未正确更新的值。原因：环使拓扑序不存在，前向传播永远走不到环上的点。后果：排期结论完全失真。对策：Kahn 后核对取出的顶点数是否为 `n`，不足即返回 `nullopt`。

**坑 7：用 `==` 比较浮点距离。**
现象：同一结果在不同编译选项/平台下断言偶发失败。原因：浮点加法不满足结合律，不同求和顺序产生末位误差。后果：自检不稳定。对策：本章固定使用整数边权、断言用 `|a−b| < 1e-9` 的容差比较；工程中也应避免对浮点求精确相等。

**坑 8：忘记图可能不连通。**
现象：Prim 里选出的 `u` 一直是哨兵值，或 Kruskal 边不够 `n−1`。原因：非连通图根本不存在生成树。后果：若不检查会返回一棵残缺的"树"。对策：Prim 发现 `u < 0` 抛异常；Kruskal 收尾核对边数是否恰为 `n−1`。

**坑 9：输出不确定导致难以回归。**
现象：同样的代码多次运行，边或活动的排列顺序不同，无法逐字节比对。原因：同权边、同入度顶点的选择顺序未规定。后果：跨编译器的"逐字节一致"验证失效。对策：邻接表按终点有序插入、排序时用 `(权, u, v)` 复合键、关键活动收集后统一排序，从源头消除歧义。

**坑 10：在超大规模上用递归并查集 / 递归销毁。**
现象：罕见的栈溢出。原因：`find` 的路径压缩和树的递归析构在极端链状结构上递归深度可达 O(n)。后果：程序在大数据上崩溃，小测试却发现不了。对策：本章数据规模小、递归完全安全；生产环境对无界深度的结构应改用显式栈或迭代式路径压缩。
