# 15 · 霍夫曼编码与 LZW：两种经典压缩思想

## 15.1 动机与直觉：为什么"常用的东西该短一些"

电报时代的莫尔斯码用点和划表示字母：最常用的 E 只有一个点（·），罕见的 Q 却是划划点划（−−·−）。这个安排朴素而深刻——**让出现频繁的符号占更短的表示，整体就更省。** 本章前半的霍夫曼编码，正是把这一直觉做成可证明最优的算法。

先建立直观。假设文本只含 a、b，且 a 出现 99 次、b 只出现 1 次。若两种字符都用等长码（各 1 位即可，这里看不出差别）；换成四个字符、各需 2 位定长码时，若把频繁字符编成 1 位、罕见字符编成 3 位，总位数可能明显下降。但立刻冒出两个必须回答的问题：

1. 长短不一的码怎样保证解码不歧义？比如 `0` 和 `01` 同时存在，读到 `01…` 时到底在哪里切分？
2. 怎样给字符分配长度，才能使**总位数最小**？靠拍脑袋分配，很可能局部省、整体亏。

霍夫曼对这两个问题各给一个答案：**前缀码**消除歧义，**贪心合并**给出最优长度。

用一个最小的四字符例子把直觉算具体。设字符 a、b、c、d 频率为 8、1、1、2。定长方案每字符至少 2 位，12 个字符共 24 位。若把 a 编成 1 位、b/c 编成 3 位、d 编成 2 位，WPL = 8·1 + 1·3 + 1·3 + 2·2 = 18 位，节省四分之一。代价是必须有"前缀自由"这条纪律：a 的短码 `0` 绝不能同时又是 b 的码的开头——这正是 15.4 节要讲的第一件事。

本章后半转向另一种压缩思路 LZW：它不关心单个字符的码长，而是**把反复出现的整段字符串登记成一个号码**。读到后面你会看到，LZW 连码表都不需要随压缩文件传送——解码端仅凭码流就能把词典重建出来。两种方法在工业界都留下了深刻印记：zlib/DEFLATE 里有霍夫曼，GIF 与老式 TIFF 压缩里有 LZW。

## 15.2 ADT 合同

### 霍夫曼部分

- **构造 `Huffman(freqs)`**：输入字母表中每个字符与其出现次数。前提——频率全部为正、字符不重复、至少一个字符；违反前提抛 `std::invalid_argument`。
- **`codes()`**：按输入顺序返回每个字符的 0/1 码字；同一频率表任意时刻重建，码字逐位相同（确定性合同）。
- **`encode(text)`**：返回位串。事后条件——每个字符替换为其码字并拼接。文本含字母表外字符时抛异常。
- **`decode(bits)`**：位串还原文本。位串非法（走到不存在的分支）或在内部节点处截断时抛异常。

### LZW 部分

- **`lzw_encode(text)`**：字节流映射为整数码序列。初始词典固定为 0..255 各代表一个单字节串；空文本返回空序列。
- **`lzw_decode(codes)`**：码序列还原字节流。首码必须在 0..255；码超出"当前已重建的词典"则非法、抛异常；空序列还原为空串。

合同里值得注意的是错误类型的分工：字母表外字符、非法码流属于调用方可以避免的**编程/数据错误**，按全教程约定抛异常；这里不存在"可预期失败返回 optional"的场景，因为压缩函数对合法输入总能成功。

## 15.3 设计与不变量（一）：霍夫曼的贪心合并

### 单字符树与权重

开始时，为每个字符建一棵只有一个外部节点的树，树的**权重**就是该字符的频率。之后反复执行一个动作：

1. 从树的集合中取出权重**最小**的两棵；
2. 新建一个内部节点把它们拼成一棵新树，左孩子为先取出者；
3. 新树权重 = 两子权重之和，放回集合。

集合中只剩一棵树时停止。n 个字符恰好合并 n−1 次，每次合并节点数减少一，所以算法必然有穷。

### "最小的两棵"从哪里取：最小堆

每轮都要取最小值，第 13 章的二叉堆正是合适工具。堆元素需要同时携带权重和平局判别号，因为权重相等时"谁先被取"直接影响码字形状：

```text
堆元素 = (节点, id)
比较规则：先比权重，权重小者在堆顶；权重相同再比 id，id 小者在堆顶。
```

叶子的 id 取它在输入频率表中的位置；两棵树合并后，内部节点的 id 取两个孩子 id 的**较小值**。为什么这样取合理？内部节点代表"某个字符子集合"，用其中输入编号最小的字符作为平局代表，等于让平局按字符编号裁决——这正是本教程"平局按编号"的确定性约定。

用教材例题频率 `a..f = 6,2,3,3,4,9` 手工走一遍：

```text
b(2)+c(3)         → 权重 5
d(3)+e(4)         → 权重 7
节点5 + a(6)      → 权重 11（5 先出，为左孩子）
节点7 + f(9)      → 权重 16
节点11 + 节点16   → 权重 27（根）
```

### 不变量：每次合并后，集合里每棵树的权重等于其叶子频率之和

这条不变量把合并规则与权重含义锁死：基线上单节点树权重 = 该字符频率，成立；合并后新树权重按定义等于两子之和，而两子权重按归纳假设各等于其叶子总和，故新树权重仍等于全部叶子频率之和。读代码时所有分支都要守住它。

### 码字从树上读出来：左 0 右 1

从根出发沿树 DFS：走向左孩子在码字末尾补 `0`，走向右孩子补 `1`，到达叶子时所累积的位串就是该字符的码字。以上树得到的结果在 15.7 节的真实输出中给出（`a=01, b=000, …, f=11`）。

## 15.4 设计与不变量（二）：前缀码与最优性

### 为什么不会切分歧义：前缀自由

观察上面的码字集合，任何一个码字都不是另一个码字的开头。这不是巧合，而是树编码的必然性质：每个码字对应一片叶子，若码字 p 是码字 q 的前缀，则沿 q 的路径会在 p 的叶子处"提前终止"——叶子没有孩子，路径不可能继续，矛盾。因此**树上读出的码字两两互不为前缀**。

前缀自由直接保证解码无歧义：从根开始逐位走，每到达一片叶子，这个字符就在此处唯一确定，然后回到根继续。不会出现"再读一位也许是另一个字符"的犹豫。

示例对 6 个字符的全部 15 对码字做了双向前缀检查，还把频率表重建一次、断言两次码字表完全一致——把确定性也变成可执行的检查。

### 加权外部路径长度与最优性

定义 **WPL（加权外部路径长度）** = 所有字符的 `频率 × 码字长度` 之和。对一个文本，WPL 恰好是编码后的总位数（频率为该字符的出现次数）。对例题：

```text
WPL = 6·2 + 2·3 + 3·3 + 3·3 + 4·3 + 9·2
    = 12 + 6 + 9 + 9 + 12 + 18 = 66
```

若四个字符以上仍用定长码，每字符至少需要 3 位，27 个字符共需 81 位；霍夫曼只需 66 位。

**霍夫曼算法构造的树具有最小 WPL**（教材定理 9-3）。直觉上的原因：频率最小的两个字符最先被合并、处于树最深的位置，而频率最大的字符最后才参与合并、最靠近根。贪心在这一步是安全的——可以用"交换论证"说明：任何最优树中，最深层的两个兄弟叶子总可以交换成两个频率最小的字符而不增大 WPL，于是第一步合并可以固定，问题规模减一，归纳即得最优。这与第 23 章贪婪策略的"贪心选择性质 + 最优子结构"完全同构。

## 15.5 设计与不变量（三）：LZW 的词典规则

### 编码：不断找"词典里最长的前缀"

LZW 不做字符级的变长分配。它维护一个从字符串到号码的词典，初始只有 256 个单字节串，编码规则（LZW 规则）为：

```text
维护当前匹配串 w。对每个输入字节 c：
  若 wc 在词典中      → w 增长为 wc；
  否则                → 输出 w 的码；把 wc 以"下一个号码"登记；w 重置为 c。
文本结束时输出最后一个 w 的码。
```

关键的省钱之处：**词典不随文件传送。** 因为每条新登记的串都由"上一个已输出串 + 一个字节"构成，解码端只要按完全相同的顺序补登记，就能凭空重建同一部词典。

### 解码：唯一的"未登记码"特例

解码端逐个读码。常规情况下码所指的串已经在重建词典中，直接输出；然后登记"上一个串 + 当前串首字符"。但有一种看似矛盾的情形：**读到的码恰好等于词典当前大小**——这条目还没登记！它什么时候发生？压缩端刚为 `wc` 登记新码之后，如果输入紧接着再次出现 `wc`，压缩流立刻就会引用这个新码；而解码端要处理完这个码之后才会登记它。

此时所指的串是可以推断的：它一定是 `w + w[0]`（上一个串后面再接上它自己的首字符）。教材中称这一情形为 KWIK 特例：

```text
if (码 k 已在词典)  entry = 词典[k]；
else if (k == 词典大小) entry = w + w[0]；   // 特例
else 码流非法，抛异常；
输出 entry；登记 w + entry[0]。
```

### 不变量：处理第 i 个码之后，解码端词典与编码端登记到同一时刻的词典逐条相同

基线：双方都从同样的 256 条单字节串开始。归纳：常规码下，新登记项都是"上一串 + 当前串首字符"，双方相同；特例码下，解码端用 w+w[0] 推出的串正是编码端刚登记的那条（编码端能立刻再次引用，只可能因为新串就是 wc 而当前输入仍是 wc，其首字符等于 w 的首字符）。这条不变量就是"不传词典也能解码"的全部依据。

补充一条容易默认但应写明的约定：新码**单调递增、只登记不回收**，任何字符串一旦获得号码便永久绑定——编解码双方都依赖"号码即登记时序"这一事实来判断 KWIK 特例。

本章测试串 `ababcbababaaaaaaa` 的码流中，码 260、262、263 三次触发特例——这不是特意安排，而是长串重复（…aaaaaaa）时的自然现象。

## 15.6 复杂度推导

**霍夫曼。** 建初始堆 O(n)；n−1 次合并，每次包含两次取最小和一次插入，各 O(log n)，合计 **O(n log n)**。空间 O(n)（树与堆）。编码长度为 L 的文本需 O(L) 次查表拼接；解码走 L 位，同样 O(L)。

**LZW。** 设文本长度 L、输出码数 m。编码端每个字节做一次词典查找；用字符串键时每次比较/哈希的成本与匹配串长度相关，实测意义下近线性，教科书常按 O(L) 的词典操作记账（若用 trie 存键则严格 O(L)）。解码端每个码做一次定长向量取串与一次登记，**O(m + L)**。空间为词典大小：每条目是一个字符串，总量级 O(L)。

关于频率从哪里来，工程上有两种做法，读压缩代码时都会遇到：**静态模型**先扫一遍全文统计频率、建好码表并把它写进文件头；**半静态/自适应模型**则边读边更新码表（如自适应霍夫曼）。本章示例采用最简单的静态约定——调用方直接给出频率；测试中频率表与文本一一对应，故 WPL 分析与编码位数严格相等。

对比两者：霍夫曼是**单字符统计**模型，需要预先知道频率（或两遍扫描），压缩后必须保证码表一致；LZW 是**短语自适应**模型，单遍即可、码表自同步，但对不产生重复短语的数据可能反而膨胀。DEFLATE 把两者结合（LZ77 找重复短语，霍夫曼编码结果），正是取长补短。

## 15.7 完整示例输出

```text
霍夫曼码字（频率 a..f = 6,2,3,3,4,9，平局按输入编号）：
  a : 01
  b : 000
  c : 001
  d : 100
  e : 101
  f : 11
霍夫曼编解码往返：原文 12 字符，位串 32 位，解码完全还原
字母表外字符编码：抛异常
LZW 编码 "ababcbababaaaaaaa"（17 字节 → 10 个码）：
  [0] 97
  [1] 98
  [2] 256
  [3] 99
  [4] 257
  [5] 260
  [6] 97
  [7] 262
  [8] 263
  [9] 97
LZW 解码往返：完全还原（17 字节）
空文本：编码空、解码空
非法 LZW 码：抛异常
自检通过
```

逐行解释：

- **码字表**：频率最大的 f（9）码字只有 2 位，频率最小的 b（2）有 3 位——"频繁者短"可见；前缀自由可逐对核对（如 `01` 与 `000`、`001` 互不为前缀）。
- **位串 32 位**：12 字符的 WPL = 两轮频率之和的编码；程序断言解码文本与原文逐字符相同。
- **LZW 码流**：前两个码 97、98 是单字节字面量；第 3 个码 **256** 就是词典里第一个新串 `ab`——编号从 256 开始，与合同一致。码 260（`bab`）、262（`aa`）、263（`aaa`）在解码端都属于"码等于词典大小"的 KWIK 特例；解码端若没有特例处理，这三处必崩。
- **非法码 9999**：首码之后词典只有 257 条，9999 既不在词典也不等于 257，被异常拒绝——证明解码器不会静默产出乱码。

## 15.8 与标准库及工业实现的对照

C++ 标准库**没有**霍夫曼编码器或 LZW 设施——它们属于压缩领域而非通用容器/算法；标准库能提供的是零件：`std::priority_queue`（实现霍夫曼堆，第 13 章已对照）、`std::map`/`unordered_map`（LZW 词典）。

工业实现值得各认识一个：

- **zlib（DEFLATE）**：先用 LZ77 滑动窗找重复字节串并编码成"长度+距离"，再对其输出做霍夫曼编码；gzip 文件、PNG 内部都用它。其霍夫曼码表允许随数据预先生成或在流内动态声明。
- **GIF / 老式 Unix compress**：compress 直接使用 LZW（码长从 9 位起动态增长）；GIF 同样是 LZW 变体。读这些格式源码时会看到两个本章简化掉的工程要点：**码长随词典增长逐位扩宽**、**词典封顶后要么冻结、要么清空重建**。
还有一个概念值得知道：信息论给出的**熵**是任何单字符编码平均码长的理论下界。霍夫曼的平均码长一定落在"熵"与"熵 + 1"之间——整数码长使它有时差一小截，算术编码（fractional coding）能逼近熵本身。知道这个关系，就不会误以为"霍夫曼已是压缩的终点"。

- 现代通用压缩器（zstd、LZ4）属于 LZ77 系而非 LZW——LZW 的专利历史与短语模型局限使其逐渐退出主流，但"码表自同步"的思想仍是理解一切字典压缩的钥匙。

## 15.9 本章坑位

- **坑 1：平局不固定，码表不可复现。** 现象：同频率两次构建，b、c 的码互换。原因：堆只按权重比较，等权元素次序由实现决定。后果：正文无法粘贴固定输出，调试无法对比。防法：堆元素带 (freq, id)，内部节点 id 取两子较小值。
- **坑 2：在局部比较器里访问尚未定义完整的嵌套类型。** 现象：编译报"member access into incomplete type"。原因：函数内局部类的函数体在出现处立即解析，此时外围类的嵌套 Node 还没定义完。后果：编译失败。防法：把 Node 的定义放到构造函数之前。
- **坑 3：聚合类型直接用 `==` 比较。** 现象：`vector<HuffCode>` 的 `==` 编译报找不到调用运算符。原因：聚合不会自动生成 operator==。后果：确定性检查无法表达。防法：在结构内显式 `bool operator==(const HuffCode&) const = default;`。
- **坑 4：忘记 KWIK 特例。** 现象：解码含连续重复短语的码流时，遇到等于词典大小的码报"非法码"。原因：该码解码端尚未登记，需用 w+w[0] 推断。后果：合法文件解不开。防法：判定顺序为"已登记 → 等于词典大小的特例 → 非法"。
- **坑 5：char 直接当下标。** 现象：初始词典用 `char` 值索引，字节值 0x80 以上变成负下标而崩溃。原因：char 是否有符号由平台决定。后果：非 ASCII 数据上未定义行为。防法：词典一律以 0..255 的 int 或 string 键初始化。
- **坑 6：把频率 0 当作合法输入。** 现象：从不出现的字符占一个叶子，合并形状怪异、码表多出无用短码。原因：合同要求频率为正。后果：对真实文本的 WPL 分析与实际编码脱节。防法：构造时校验 `freq > 0`。
