# 22 · 排序（下）：希尔、堆、归并、基数、桶与外部排序

## 22.1 动机与直觉：O(n²) 为什么必须被打破

上一章的插入、冒泡、选择三排序有一个共同的天花板：**每消除一个逆序对，代价是常数级，而任意输入的逆序对可以有 n(n−1)/2 个。** 当 n 从几十个变成几百万个，O(n²) 意味着从"秒回"变成"算到下班"。本章六个算法各自用一个新招绕开这个困境：

- **希尔排序**问：为什么小元素只能一格一格地往前挪？让它一次跨过半个数组；
- **堆排序**问：选择排序每轮扫全体找最值，最值之间的比较信息能不能存下来？树就是那份信息；
- **归并排序**问：为什么不能同时有多个有序区？先让每个元素自己有序，再两两合并；
- **基数排序**问：排序一定要比较大小吗？按个位、十位逐位"排队"就行；
- **桶排序**问：如果数据本身分布均匀，直接按位置入桶，排序退化成收集；
- **外部排序**面对的是另一个世界：数据装不进内存，真正昂贵的不是比较，而是磁盘 I/O。

这六招不是六种孤立技巧，而是三条思想线索：**预整理**（希尔）、**保存已有的比较结果**（堆）、**分治合并**（归并、外部排序），外加跳出比较模型的两个分配式算法（基数、桶）。读代码时请始终抓住"它省掉的究竟是哪一类工作"。

对规模差距建立一点数量直觉：n=1000 时 n² 是一百万次操作、n log₂n 约一万次，相差百倍；n 到一百万时 n² 是一万亿——按单核每秒亿级操作算要算上千秒，而 n log₂n 约两千万、零点几秒。数据结构教材里每个"把 O(n²) 降到 O(n log n)"的故事，落到生产环境都是"能不能上线"的差距。这也是为什么排序是被研究得最透、库实现最值得直接复用的一类算法：自己手写的版本几乎不可能在常数和边界处理上赢过标准库。

## 22.2 ADT 合同

本章前五个算法与第 21 章共享同一个排序合同：

- **输入**：一个可写区间（基数排序另要求元素为非负无符号整数；桶排序另需给定值域 `[lo, hi]`）；
- **输出**：同一多重集按非降序排列，**长度严格守恒**——不丢元素、不造元素；
- **前提违规**：`bucket_sort` 的 `hi < lo`、`external_sort_sim` 的 `run_size == 0` 属于调用方编程错误，抛 `std::invalid_argument`。

外部排序模拟的合同要单独交代，因为它模拟的是内存受限场景：

- 前提：`run_size ≥ 1`；输入可以为空，空输入返回空序列；
- 后置：返回序列有序，长度与输入相同；归并段数 = ⌈n / run_size⌉。

合同没有承诺"稳定"。稳定性是各实现的具体性质（见 22.6 总表），不能因为输出升序就以为相等元素的相对次序被保住。

### 22.2.1 稳定性为什么不是洁癖

设想学生记录先按班级排好，再按成绩排序，期望"同班内成绩降序、班级次序不乱"。第二次排序若不稳定，两个成绩相同但班级不同的学生可能换位，前一次排序的成果被悄悄推翻。稳定排序保证**多趟排序可以按关键字从次到主逐次施加，每趟只重排本趟的键**：

```cpp
// 先按次关键字、再按主关键字；用稳定排序时主关键字相同的记录
// 保留着次关键字的次序
std::stable_sort(students, by_class);
std::stable_sort(students, by_score_desc);
```

在做什么：两次施加次序、后一次不破坏前一次建立的平局次序。归并排序与基数排序稳定；堆、希尔、快排不稳定——本章总表中的"稳定"一列，选型时要对着这类场景读，而不是考试后就忘。

## 22.3 设计与不变量（一）：希尔排序的"k 有序"

希尔排序最容易被写成"莫名其妙就能对"的循环。它的精确中间性质是 **k 有序**：

> 对增量 k，任意下标 i，只要 i 与 i+k 都在数组内，就有 a[i] ≤ a[i+k]。

也就是说，相隔 k 的元素构成的每一条链各自有序。算法按 `n/2, n/4, …, 1` 的增量依次工作：每轮在每条链上跑插入排序，结束后数组对当前增量有序；最后一轮增量为 1——那就是普通插入排序，但此刻数组已被前几轮"预整理"得接近有序。

为什么增量必须**严格递减且最后恰好是 1**？漏了 1，数组只保证"相隔 k 有序"，相邻元素之间仍可能逆序，整体并不有序。下面是核心循环，注意内层是标准插入排序、只是跨步为 gap：

```cpp
for (std::size_t gap = n / 2; gap > 0; gap /= 2) {
    for (std::size_t i = gap; i < n; ++i) {
        const int value = a[i];
        std::size_t j = i;
        while (j >= gap && value < a[j - gap]) {
            a[j] = a[j - gap];   // 同链上的较大元素后移 gap 位
            j -= gap;
        }
        a[j] = value;
    }
}
```

这段代码在做什么：把 a[i] 在它所属的"gap 链"上插入到正确位置。不变量是本轮结束后所有 gap 链有序，即数组对 gap 有序。跨 gap 的元素本轮互不干涉，所以早期轮次里元素可以大跨步移动。

希尔排序的复杂度没有简洁闭式，依赖增量序列；n/2 序列的常见估计约为 O(n^1.3)。工程上很少有人手搓希尔排序，但"先做廉价预整理、再跑接近有序时很快的算法"这个模式在快排（小数组转插入排序）等处反复出现。

### 22.3.1 在固定夹具上的完整轨迹

光看定义仍嫌抽象，把夹具 `{3,1,4,1,5,9,2,6,-3,0}` 在增量 5、2、1 三趟中的变化逐步列出。同一条链按下标同余分组：

| 阶段 | 五条链（按下标 mod 5 或 mod 2）的原始内容 | 排序后数组 |
|---|---|---|
| 初始 | — | `3 1 4 1 5 9 2 6 -3 0` |
| gap=5 | {3,9},{1,2},{4,6},{1,-3},{5,0} | `3 1 4 -3 0 9 2 6 1 5` |
| gap=2 | 偶下标 {3,4,0,2,1}；奇下标 {1,-3,9,6,5} | `0 -3 1 1 3 5 2 6 4 9` |
| gap=1 | 全体 {0,-3,1,1,3,5,2,6,4,9} | `-3 0 1 1 2 3 4 5 6 9` |

逐行读：gap=5 时每条链只有 2 个元素，插入排序各做至多一次比较，于是 −3 从位置 8 一下跨到位置 3；gap=2 时两条长度 5 的链各自排序，−3 又从位置 3 跨到位置 1；到 gap=1 时数组已接近有序，插入排序几乎只在相邻位置做少量工作。对比第 21 章直接插入排序在同一夹具上每个元素只能挪动一格，"预整理省下的是什么"就具体了。

### 22.3.2 正确性论证梗概

可以用不变量归纳严格说明结果正确。初始：n/2 趟开始前无须任何有序性质。归纳：假设第 k 趟结束时数组对 gap_k 有序；第 k+1 趟在每条新链上跑的是已经证明正确的插入排序（第 21 章），故趟末数组对 gap_{k+1} 有序。关键是最后一步——序列末项恒为 1，而"对 1 有序"就是任意相邻位置 a[i] ≤ a[i+1]，即全局非降序。元素守恒由插入排序只移动、不增删元素保证。证毕。

## 22.4 设计与不变量（二）：堆排序

第 13 章讲过二叉堆。堆排序把它用在原地：先把整个数组建成最大堆，堆顶即全局最大值；把堆顶换到未排序区末尾，未排序区缩小 1，新堆顶下沉恢复堆序；重复 n−1 次。

两条不变量：① 未排序区始终是最大堆；② 已排序区里的每个元素都不小于未排序区中的任何元素。第②条解释了为什么结果全局有序——每次换过去的都是未排序区的最大值。

下沉时孩子的下标是最容易写错的地方，**0-based 公式为左孩子 2i+1、右孩子 2i+2**：

```cpp
auto sift_down = [&](std::size_t i, std::size_t limit) {
    const int value = a[i];
    while (true) {
        std::size_t child = 2 * i + 1;        // 先取左孩子
        if (child >= limit) break;
        if (child + 1 < limit && a[child] < a[child + 1]) {
            ++child;                           // 改取更大的右孩子
        }
        if (value >= a[child]) break;          // 落位
        a[i] = a[child];
        i = child;
    }
    a[i] = value;
};
```

在做什么：让可能失序的根沿"更大的孩子"一路下沉。不变量是下沉路径之外的堆序从未被破坏，落位后整个区间恢复最大堆。建堆自最后一个非叶节点 n/2−1 向前做，总成本 O(n)；排序阶段 n−1 次交换各跟一次 O(log n) 下沉。

堆排序最硬的保证是**最坏情况仍是 O(n log n)**，且额外空间 O(1)。代价是缓存行为差（跳跃访问）、不稳定，所以平均常数不如快排。

### 22.4.1 前三次交换在做什么

建堆阶段可以这样直觉理解：叶子（后半数组）天然是堆，从 n/2−1 向前，每个节点在它那一亩三分地里下沉；处理位置 i 时，它的两个孩子子树都已经是堆，一次下沉就把以 i 为根的子树修好。排序阶段前三次交换的形状变化是：

```text
初始最大堆：堆顶=9，与末位交换 → 9 进入已排序区
第二次：    堆顶（未排序区最大）与倒数第二位交换
第三次：    同上，已排序区在数组右端持续向左增长
```

每次交换后只有新堆顶一个元素可能违反堆序（其余元素在交换前就满足），所以只需一次下沉而不必重新建堆——这是堆排序 O(n log n) 而不是 O(n²) 的关键。正确性梗概：归纳于未排序区大小，已排序区始终接住"未排序区的最大值"，故已排序区最终严格有序。

## 22.5 设计与不变量（三）：归并排序、基数、桶与外部排序

**归并排序。** 递归把区间平分成两半分别排序，再把两个有序半区稳定地并入一块缓冲，抄回原数组。合并不变量：从两个有序半区的队首取较小者（相等取左半区），输出必有序，且相等元素的左右来源次序保持——这正是它稳定的原因。递归深度 O(log n)，每层总工作量 O(n)，时间 O(n log n)，辅助空间 O(n)。

用 4 个元素 `{3,1,4,1}` 走一遍自底向上的形状：单元素各自有序 → 相邻两两合并得 `[1,3] [1,4]` → 两组合并，取 1（左）、1（右）、3、4，得 `[1,1,3,4]`。注意两个 1 的来源：先取左半区那个，相等时不跨区，这就是稳定性在操作层面的含义。示例实现采用递归自顶向下，合并动作完全相同。

**基数排序（LSD）。** 为什么必须从个位开始、而且每轮分配必须稳定？低位建立的次序是高位排序时的"平局决胜规则"：先按个位排队收集，再按十位排队——十位相同的元素会严格保持上一轮个位的次序。若反过来从高位起（且不递归分组），低位轮会把高位刚建立的分组全部打乱。

```cpp
for (unsigned long long exp = 1; max_value >= exp; exp *= 10) {
    for (auto& bucket : buckets) bucket.clear();
    for (unsigned int x : a)
        buckets[(static_cast<unsigned long long>(x) / exp) % 10].push_back(x);
    std::size_t out = 0;
    for (auto& bucket : buckets)
        for (unsigned int x : bucket) a[out++] = x;
}
```

在做什么：第 exp 轮按第 exp 位把元素稳定分配进 10 个桶再按桶号收集。不变量是收集完成后，数组按"已处理过的所有低位"组成的数有序。位数 d 轮后全部处理完。

**桶排序。** 把值域 `[lo, hi]` 等宽切成固定 5 桶，元素按值落入对应桶，各桶分别排序后按桶号拼接。关键不变量：桶 i 的值域整体在桶 i+1 之左，所以桶内排序 + 按序拼接即为全局有序。期望线性时间依赖**输入在值域内近似均匀**；若全挤一个桶，退化为桶内那个排序的复杂度。

**外部排序模拟。** 两阶段：① 把输入切成 ⌈n/run_size⌉ 段，各段在内存排序（模拟初始归并段）；② 用最小堆做 k 路归并——堆中每项是 `(段首值, 段号)`，弹出最小者、该段补进下一个元素。平局按段号，输出确定可复现。真实外排中数据在磁盘上，归并段通过多路归并减少 I/O 趟数；I/O 次数才是主要成本，比较次数反而次要。

### 22.5.1 基数排序的两轮中间结果

本章演示夹具是固定夹具各值 +3：`{6,4,7,4,8,12,5,9,0,3}`。逐位收集的中间序列可手工核对：

| 轮次 | 按哪一位 | 收集后序列 |
|---|---|---|
| 个位 | 个位数字 | `0 3 4 4 5 6 7 8 9 12` |
| 十位 | 十位数字 | `0 3 4 4 5 6 7 8 9 12` |

个位轮：数字 0 的桶收 0，数字 2 的桶收 12，数字 3~9 各收对应值，桶 1 为空，按桶号拼接即得第一行。十位轮：只有 12 的十位是 1，其余十位皆 0，全部落入 0 号桶且保持个位轮次序，故序列不变。注意两轮收集都依赖**桶内保持入桶顺序**——若某轮用了非稳定收集，个位轮的成果就会被抹掉。

### 22.5.2 桶排序为什么是"期望"线性

很多教材直接写"桶排序 O(n)"，这是有前提的：若 n 个元素独立均匀落在 `[lo, hi]` 上，5 个桶每桶期望 n/5 个元素，桶内排序总期望 O(n)（平方和随桶数摊薄）。反例是全部元素相等或挤在同一桶：那一桶内部仍要做完整排序，最坏列里填的是 O(n log n)。因此用桶排序前先回答一个问题：**我凭什么相信数据均匀？** 答不上来就只把它当启发式。

### 22.5.3 真实外部排序的 I/O 账目

示例模拟的是一轮多路归并；真实大文件往往要多趟：内存能容纳 k 个段时，一趟可把 k 个段合为一个；段数多于 k 就先多趟合并，趟数约 ⌈log_k R⌉（R 为初始段数）。每一趟意味着把全部数据从磁盘读出再写回，共 2n 次 I/O 量。因此外排优化的抓手与内排完全不同：增大 k（受内存限制）、缩短段数、利用并行 I/O，而不是减少比较。读懂这个背景，再看示例的 k 路堆归并，就明白它模拟的正是"一趟消化全部段"的核心动作。

补一个经典的段生成技巧：简单切分按内存容量产出 R=⌈n/M⌉ 个段；**替换选择**（replacement selection）在内存里维护一个 M 大小的堆，每输出一个最小值，就从输入补一个新值——若新值比刚输出的值大，它还属于当前段，否则冻到下一段。随机输入下这能产出平均长度约 2M 的段，段数直接减半，后续 I/O 趟数随之减少。它与本章归并思想合在一起，构成了传统外部排序的完整图景。

## 22.6 复杂度推导与九算法总表

逐个推导最坏界：希尔排序 n/2 序列约 O(n^1.3)（无简洁闭式）；堆排序建堆 O(n) + n 次下沉 O(n log n)；归并排序递推 T(n)=2T(n/2)+O(n)，主定理给 O(n log n)；基数排序每轮 O(n+r)、共 d 轮，O(d(n+r))——**当 d 不是常数时它不是 O(n)**，例如任意大的无界整数 d=O(log n)；桶排序期望 O(n) 依赖均匀假设；外部排序模拟 O(n log run_size) 的比较量，真实系统另计 I/O。

九算法总表（前五种在第 21 章）：

| 算法 | 最好 | 平均 | 最坏 | 空间 | 稳定 |
|---|---|---|---|---|---|
| 直接插入 | O(n) | O(n²) | O(n²) | O(1) | 是 |
| 冒泡 | O(n) | O(n²) | O(n²) | O(1) | 是 |
| 简单选择 | O(n²) | O(n²) | O(n²) | O(1) | 否 |
| 快速 | O(n log n) | O(n log n) | O(n²) | O(log n) | 否 |
| 希尔 | — | ≈O(n^1.3) | — | O(1) | 否 |
| 堆 | O(n log n) | O(n log n) | O(n log n) | O(1) | 否 |
| 归并 | O(n log n) | O(n log n) | O(n log n) | O(n) | 是 |
| 基数 | O(d(n+r)) | O(d(n+r)) | O(d(n+r)) | O(n+r) | 是 |
| 桶 | O(n) | O(n) | O(n log n) | O(n) | 视桶内排序 |

读这张表的正确姿势不是背数字，而是看**交换关系**：要最坏保证选堆；要稳定选归并或基数；要小常数快排；值域小、位数短才上基数；数据装不下内存才谈外部排序。

### 22.6.1 渐近之外还有常数

同是 O(n log n)，快排、堆排序、归并的实测速度可以差出两三倍，原因在渐近符号看不到的地方：快排分区时数据在相邻位置流动、缓存命中率高；堆排序沿树跳跃访问、缓存不友好，且比较次数约为快排两倍；归并排序要在原数组与缓冲之间整块搬运。工程库的默认选择（`std::sort` 用快排打底）正是这个口径：**先用渐近级别筛掉不合格者，再在同级里比常数和缓存。** 反过来，若输入规模的上界不确定、可能遇到最坏形状（如接受外部输入的服务），introsort 的堆排兜底就比"平均最快"更重要。选型结论因此不是一句"快排最快"，而是先问：规模可不可预估、最坏情况我担不担得起、要不要稳定、数据在内存还是磁盘。

## 22.8 与标准库的对照

- **`std::sort`** 不是单纯快排，而是 **introsort**：以快排分段递归为主；分段小到阈值以下改插入排序（省递归开销）；递归深度超过约 2⌊log₂n⌉ 有退化倾向时改堆排序——于是平均常数接近快排，最坏仍是 O(n log n)。
- **`std::stable_sort`**：有额外缓冲时 O(n log n)，无缓冲时就地合并退化为 O(n log² n)。需要相等元素保持原序（如先按学号排、再按成绩排）时用它。
- **`std::partial_sort` / `nth_element`**：只要前 M 小或只要第 k 名时，比整排便宜（分别约 O(n log M)、期望 O(n)）。典型写法：

```cpp
// 只要成绩最高的前 3 名，其余元素的次序不作任何保证
std::partial_sort(scores.begin(), scores.begin() + 3, scores.end(),
                  std::greater<int>{});
// 只要"中位数是谁"：调用后中点位置的值与全排序后该位置相同
std::nth_element(scores.begin(), scores.begin() + scores.size() / 2,
                 scores.end());
```

在做什么：partial_sort 内部维护一个 M 大小的堆，只对可能进前 M 的元素下功夫；nth_element 用类似划分的操作把第 k 小一次性"选"出来。不变量是调用完成后前 M 项（或第 k 项）与全排序结果一致，其余部分无承诺。需求只有"前几名"时，整排是浪费。
- 标准库没有基数排序和桶排序——它们依赖关键字的整数结构，泛型接口难以表达；高性能场景（如数据库、整数键）由专用库提供。
- 工程选型：n 很小（几十个以下）插入排序就够；通用比较排序默认 `std::sort`；要稳定 `std::stable_sort`；键值域小且定长考虑基数；数据超出内存才是外部排序的世界。

## 22.9 本章坑位

- **坑 1：增量序列漏了最后的 1。** 现象：结果"大致有序"但相邻处仍有逆序。原因：数组只保证对 k 有序，增量从未到 1 就没有总排序。后果：断言偶发失败。防法：循环条件保证 gap 整除到 1 才停。
- **坑 2：孩子下标 2i+1 / 2i+2 与 1-based 的 2i 混淆。** 现象：堆排序结果错乱或漏元素。原因：教材常用 1-based，C++ 数组 0-based，父子公式整体偏移一位。后果：建堆不变量被破坏。防法：在代码注释里钉死下标体系。
- **坑 3：归并就地写、和读出区重叠。** 现象：归并到一半元素被自己覆盖，出现重复值。原因：合并目标与源是同一块数组。后果：元素丢失、结果错。防法：单独开缓冲，合完再抄回。
- **坑 4：基数排序从高位开始。** 现象：最后一轮（个位）收集后十位、百位的分组全乱。原因：LSD 的次序依赖"低位先排且稳定"。后果：输出无序。防法：从个位起，每轮分配必须稳定。
- **坑 5：桶排序值域写反或桶数退化。** 现象：`hi < lo` 时算出负桶数/负下标；元素高度集中时 5 桶里一桶独大。原因：没有校验值域；数据不满足均匀假设。后果：越界写或退化到 O(n²)。防法：入口校验，先看数据分布再定桶数。
- **坑 6：外部排序 run_size=0。** 现象：除零或归并段数计算死循环。原因：⌈n/0⌉ 无意义。后果：崩溃。防法：入口抛 `invalid_argument`。
- **坑 7：基数排序遇到负数。** 现象：负号不参与"某位数字"，−1 被当成超大无符号值或按补码位排入错误桶。原因：十进制位分解对负数没有自然定义。后果：顺序错。防法：接口限定无符号非负，或先做整体偏移（本章演示的 +3 手法）。
- **坑 8：轮数变量用 32 位、exp×10 回绕到 0。** 现象：处理接近 `UINT_MAX` 的数据时除以零崩溃。原因：exp 溢出后回绕。后果：未定义/除零。防法：用更宽的类型承载倍率，并以 `max ≥ exp` 作停止条件。
- **坑 9：基数轮数按最大值算，全 0 数组一轮不跑。** 现象：代码里假定"至少跑一轮"，收集位置计数从未初始化就被读取。原因：max=0 时循环条件一开始就不成立。后果：边界数据上行为依赖巧合。防法：显式处理空/全零情形，或保证未初始化值不被读。
- **坑 10：桶分布在排序之后才统计却当作"原分布"报告。** 现象：打印出来的"分布"永远是排序后的落点，掩盖了原始倾斜。原因：统计与排序共用了同一数组、顺序颠倒。后果：诊断信息失真。防法：先统计原始输入再排序（示例 main 正是对夹具原件调用分布函数）。
