# 12 · 统一编译验证：七条判定与双通道

> 本章无独立示例，验证对象是 `examples/` 全部 10 个示例；入口 `./run-all.sh`（macOS/Linux）与 `.\build.ps1 -All`（Windows/MSVC）。

本教程的示例不是"能编过就算对"。每个示例都必须在两条链接通道上编译、连跑两遍、并把输出逐字节比对——这套判定协议是全部章节共用的地基（前面每章"实测输出"小节的取值标准都回指这里）。本章讲清楚七条判定**各自防的是什么**，以及新增示例时要怎么配合它。

## 12.1 两个入口，一套判定

```bash
# ═══ 12.1 macOS / Linux：run-all.sh 的四种用法 ═══
./run-all.sh            # 全部示例 × shared/static 双通道
./run-all.sh -v         # 附带每个示例的区间输出
./run-all.sh 02 06      # 只跑指定编号（两位数字或文件名都行）
./run-all.sh --one      # 只跑 shared 一条通道（省一半时间）
```

```powershell
# ═══ 12.1b Windows / MSVC：build.ps1 的四个开关 ═══
.\build.ps1 -All
.\build.ps1 -File 06_timer_fps.cpp
.\build.ps1 -CompileOnly      # 只编译，跳过运行判定
.\build.ps1 -Clean
```

两个入口的判定逻辑逐条对齐（shell 版多一条双通道比对）。工具链一律探测：`clang++`/`g++`、`sdl2-config`/`pkg-config`、`gtimeout`/`timeout`，任一必需项缺失就报"环境缺口"以退出码 2 结束（11 章 11.1）。

## 12.2 七条判定，逐条说清它在防什么

| # | 判定 | 防的是 |
|---|---|---|
| 1 | 编译退出码 0 **且编译期 stderr 为空**（`-Wall -Wextra`） | "有告警但还是编过了"的漂移示例；`SDL_RenderPresent` 返回 `void` 那次就是被这条抓出来的（05 章坑位 14） |
| 2 | 运行退出码 0 | 示例内部把失败静默吞掉；02 章原版在 `dummy` 下 `exit 1` 由它兜住 |
| 3 | 运行期 stderr 为空 | 错误信息写 stderr 却"看起来成功了"——SDL 的错误串走的就是这条路 |
| 4 | stdout 里同时出现 `==== NN 开始 ====` 与 `==== NN 结束 ====` | 没有分节标记的示例等于没有可验证输出（本次校验前有 8 个示例处于这种状态） |
| 5 | 两标记之间**非空**且不含控制字符 | 空区间、或把 `\r`/ESC/进度条之类的量打印进去 |
| 6 | 同一通道连跑两次，区间**逐字节一致** | 抖动量：帧长（06 章）、线程调度（09 章）、设备名（08 章）——它们只该出现在区间外的 `[观测]` 行 |
| 7 | shared 与 static 两条通道的区间逐字节一致（仅 shell 版） | 示例偷偷依赖动态库加载或安装前缀 |

第 7 条值得单独说：两个产物由**同一份源码**编译，比对不是为了验证"两种链接语义"，而是检验示例没有硬编码 dylib 路径、没有依赖只在动态链接下成立的行为。它同时也是对 11.2 那串 frameworks 参数的持续体检——静态通道一旦链接不回来，这条立刻红。

## 12.3 区间协议：示例作者要做的事

新增或修改示例时，输出按这个约定写（各章示例全部遵循）：

```cpp
// ═══ 12.3 区间模板：把可断言的事实夹在两个标记之间 ═══
    std::cout << "==== 07 开始 ====\n";
    std::cout << "keyboard entries=" << keyCount << ", leftPressed=" << leftPressed << '\n';
    std::cout << "stateAvailable=" << (state != nullptr) << '\n';
    std::cout << "==== 07 结束 ====\n";
    std::cout << "[观测] 只有人看、不参与比对的量\n";   // 区间外
```

三条硬规则：

1. **标记文本固定**：`==== NN 开始 ====` / `==== NN 结束 ====`，`NN` 与文件名编号一致（`tools/check_docs.py` 会核这一条）；标记本身必须各占一行，抽取用的是 `awk '/^==== [0-9]+ 开始 ====$/'`。
2. **区间内只放跨机器恒真的量**：返回码、布尔断言、驱动名、`counter=2000` 这类结构性结论。判据是"换一台机器、换一个驱动、再跑一遍，这行还成立吗"。
3. **漂移量放区间外的 `[观测]` 行**：帧长、fps、声卡/显示器名字。它们对读者有用（各章"实测输出"里都印了），但不进比对。

打印时机也归这套协议管：**所有输出都在 `SDL_Quit()` 之前**（01 章 1.5、10 章 10.4）。

## 12.4 一次全量的实测结果

`./run-all.sh`（shared + static 双通道）本机结果，留档 `build/summary.txt`：

```text
 通过 10  失败 0  （示例总数 10，通道 2 条）
```

`SDL_VIDEODRIVER=dummy ./run-all.sh --one` 同样 10/10。`-Wall -Wextra` 下编译告警 0 条（判定第 1 条要求编译期 stderr 为空，任何告警即失败）。产物布局可供人工复核：`build/<通道>/<示例名>.compile.err` / `.run.err` / `.run1` / `.run2` / `.sec1` / `.sec2`，外加 `build/toolchain.txt`、`build/dummy-driver-02.out`、`build/static-link-missing-frameworks.err` 三份证据文件。

文档侧还有一层机器核查，把"教程说的"和"二进制实际输出的"钉在一起：

```bash
python3 tools/check_docs.py
```

五关：

1. **章节对齐**：`docs/NN-*.md` ↔ `examples/NN_*.cpp` 一一对应（11/12 两章是工程侧内容，显式登记在 `NO_EXAMPLE` 里），示例源码里的 `==== NN 开始/结束 ====` 标记必须与文件名编号一致。
2. **输出对账**：各章 ```text 块必须是**当前**产物的顺序敏感子序列。
3. **坑位自洽**：每章坑位清单非空、编号全局唯一且 1..N 连续，并与 `CHEATSheet.md` 索引逐条对得上（包括"这条属于哪一章"）。
4. **导航有效**：章末导航的链接文字 == 目标章 H1，正文交叉引用的标号指向同号章节，所有 `.md` 与 `examples/*.cpp` 相对链接存在，README 分章导航覆盖全部章节。
5. **正文自足**：`examples/NN_*.cpp` 的每一行代码（注释行除外）都必须出现在该章的 ```cpp 块里。这条直接把"教程不是代码罗列、也不用回去翻源码"变成机器判定——示例的每一行都在正文里有出处。

**顺序敏感子序列**（第 2 关）是反假绿的关键：把两行输出调换顺序、或把别的示例的输出抄过来，都会判失败。第 5 关反过来管住另一种偷懒：把讲解写成"详见源码"。两关都做过变异测试——删掉正文里的一行引用、把两行输出调序，核查都从绿转红。

## 12.5 常见红法与定位顺序

| 现象 | 先看 | 多半是 |
|---|---|---|
| 编译失败，`compile.err` 非空 | 前 20 行 | 告警被判失败（未使用参数、符号转换），不是错误也要改 |
| 运行退出码非 0 | `run.err` | 少了降级分支（02 章坑位 4），或初始化子系统没开够 |
| 缺分节标记 | `.run1` 全文 | 忘了打 `==== NN 开始/结束 ====`，或标记行多了空格 |
| 两次运行区间不一致 | `.sec1` 与 `.sec2` 的 diff | 把抖动量放进了区间（06/08/09 章的三类典型） |
| 双通道不一致 | `shared/*.sec1` 与 `static/*.sec1` | 示例依赖了动态库路径或安装前缀 |
| 整链 127 退出 | 脚本头部探测 | `gtimeout` 缺失（11 章坑位里 macOS 的那条，06 章坑位 19） |

调试时不必每次全量：`./run-all.sh 06 --one -v` 只跑一个示例的一条通道并打印区间，几秒就能复现"区间抖动"这类问题。

## 坑位清单

38. **把 `[观测]` 类漂移量写进区间**：帧长、fps、设备名、线程交错后的输出顺序——判定第 6 条（两跑逐字节一致）会偶发失败，且**在你机器上多半是绿的**，最难查。写之前先问"换台机器这行还成立吗"。
39. **只判退出码就宣布通过**：本教程要求区间非空且无控制字符（判定 4/5），因为"退出 0 但什么都没打印"的示例同样满足退出码条件，却完全没有验证价值——校验前有 8 个示例正是这种状态。
40. **不设运行超时就跑回归**：一个卡在 `SDL_WaitEvent`（03 章）或等键盘的示例会把整条链挂住。`run-all.sh` 用 `gtimeout`/`timeout` 给每个示例 20 秒墙钟上限，且允许两者都缺时不设上限继续跑；`build.ps1` 侧对应 `-CompileOnly` 与超时判定。
