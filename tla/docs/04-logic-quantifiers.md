# 04 · 逻辑与量词

对应示例：`../examples/Ch04LogicQuantifiers.tla`

TLA+ 的一切都建立在**经典一阶逻辑 + 集合论**之上。这一章把联结词、量词，以及它们
和集合构造的关系讲清楚，并逐条实测（本机 `No error has been found`）。

## 联结词

| 符号 | ASCII | 含义 |
|---|---|---|
| `/\` | `\land` | 与 |
| `\/` | `\lor` | 或 |
| `~` | `\lnot` | 非 |
| `=>` | | 蕴含 |
| `<=>` | | 等价（当且仅当） |

```tla
(TRUE /\ FALSE) = FALSE
(FALSE \/ TRUE) = TRUE
~FALSE = TRUE
(TRUE => FALSE) = FALSE
(FALSE => FALSE) = TRUE       \* 假前提 => 任何结论，整体为真（实质蕴含）
(TRUE <=> TRUE) = TRUE
```

蕴含 `=>` 的"反直觉"之处全在第二行：`FALSE => 任何东西` 都为真。这叫**实质蕴含**，
是经典逻辑的规定。写规格里"如果 P 则 Q"时用 `P => Q`，当 P 不成立时整条自动为真
（vacuously true），这常是不变式能"对所有进程都成立"的原因。

## 德摩根律

```tla
~(P /\ Q) <=> (~P \/ ~Q)
~(P \/ Q) <=> (~P /\ ~Q)
```

实测用具体命题代入验证：

```tla
~( (1=1) /\ (2=2) ) = ( ~(1=1) \/ ~(2=2) )
~( (1=1) \/ (2=2) ) = ( ~(1=1) /\ (2=2) 的否定 )   \* 见示例 DeMorganOK
```

## 量词

```tla
\A x \in S : P(x)     \* 全称：S 里「每个」x 都满足 P
\E x \in S : P(x)     \* 存在：S 里「至少一个」x 满足 P
```

`\A` 读作 "for all"，`\E` 读作 "exists"。实测：

```tla
\A x \in {1,2,3} : x > 0          \* 真
~(\A x \in {1,2,3} : x > 2)       \* 「并非全都 >2」为真（1、2 不满足）
\E x \in {1,2,3} : x = 2          \* 真
~(\E x \in {1,2,3} : x = 9)       \* 真（不存在 9）
```

### 空集上的量词（vacuous truth）

```tla
\A x \in {} : x > 1000      \* 真！空集上的全称恒为真
~(\E x \in {} : TRUE)       \* 真！空集上的存在恒为假
```

这不是 bug，是逻辑规定。它的实际意义：当你写 `\A p \in Procs : P(p)` 而 `Procs`
恰好为空时，性质自动成立——建模时若发现"性质莫名其妙就过了"，先检查集合是不是空的。

### 多变量量词

把绑定并列即可：

```tla
\A x \in 1..3, y \in 1..3 : x + y >= 2
\E x \in 1..3, y \in 1..3 : x * y = 9      \* 存在 3*3=9
```

## 量词与集合构造的关系

"筛出偶数后，它们确实都是偶数"——把 `{x \in S : P}` 和 `\A` 串起来：

```tla
LET Evens == {x \in 1..10 : x % 2 = 0}
IN
  Evens = {2,4,6,8,10}
  \A e \in Evens : e % 2 = 0      \* 筛出来的当然都满足条件
  Cardinality(Evens) = 5
  \E e \in Evens : e = 6
```

这揭示了一个深层联系：**集合构造 `{x \in S : P}` 就是量词的"对象化"**。
说"`\A x \in S : P(x)`"和说"`{x \in S : ~P(x)} = {}`（没有反例）"是一回事。

## CHOOSE 再探

```tla
(CHOOSE x \in {1,2,3} : x > 2) = 3      \* 唯一 >2 的就是 3
(CHOOSE x \in 1..5 : TRUE) \in 1..5     \* 不要求唯一，只要选出来在域内
```

`CHOOSE` 在第 02 章见过。它在写"取最大值""取某个代表元"时很有用，但要小心：当满足
条件的元素**不唯一**时，`CHOOSE` 选哪个是未指定的——别依赖具体选到谁，只依赖"它满足
条件"。

## 写性质时的常用套路

- "所有进程都不在临界区"：`\A p \in Procs : pc[p] # "cs"`
- "至少有一个进程完成了"：`\E p \in Procs : pc[p] = "done"`
- "余额非负的账户集合就是全体账户"：`{a \in Accts : bal[a] < 0} = {}`
- "恰有一个 leader"：`Cardinality({p \in Procs : isLeader[p]}) = 1`

这些都是后面实战章里反复出现的形状。把 `\A`/`\E`/集合构造练成肌肉记忆，写不变式
就顺了。
