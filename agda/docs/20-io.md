# 20 · IO 与真实程序

前两章我们给「计算」建了抽象层（Monad），这一章把抽象层踩到地上：一个
真正能跑、能打印、能读文件、能带退出码结束进程的 Agda 程序长什么样。
这是 Agda 教程里最容易「只见森林不见树木」的一段——前面 19 章全在类型
层里打转，而工程世界的 Agda 其实分两半：**类型检查器里的 Agda**（纯、
必须终止）和 **`--compile` 之后的 Agda**（经 Haskell 落地成机器码，允许
副作用和无限循环）。本章把这条缝讲透：IO 值为什么是「计算的数据描述」
而不是「计算本身」；`main : Main` 和 `run` 这对包装各干什么；`--compile`
的完整流水线（Agda → MAlonzo 生成的 Haskell → GHC，实测日志原样贴上，
连产物落在哪个目录都实测）；最后以一个带文件读写、命令行参数、echo
循环和退出码的真实程序收尾——就是 `./build.sh run Ex20_io` 打出
`hello agda 42` 的那一个。

对应示例：`../examples/Ex20_io.agda`

本章所有代码片段均与示例文件一致；日志与报错文本均为 Agda 2.8.0 +
stdlib 2.3 + GHC 实测原样粘贴。

## 20.1 IO 是数据：stdlib 里的双重建模

打开 `/usr/share/agda-stdlib/src/IO/Base.agda`，`IO` 不是 postulate，
而是一个货真价实的 **data**：

```agda
data IO (A : Set a) : Set (suc a) where
  lift : (m : Prim.IO A) → IO A
  pure : (x : A) → IO A
  bind : {B : Set a} (m : ∞ (IO B)) (f : (x : B) → ∞ (IO A)) → IO A
  seq  : {B : Set a} (m₁ : ∞ (IO B)) (m₂ : ∞ (IO A)) → IO A
```

四个构造子恰好是 19 章 Monad 接口的深嵌入：`pure`、`bind`(= >>=)、
`lift`（嵌入原始 IO）、外加一个丢弃结果的 `seq`。注意 `bind` 的参数类型
是 `∞ (IO B)`——**Musical 记法**（22 章主角）的 `♯_` 延迟：子计算被装进
无限延迟盒子后才交给构造子。为什么要这么绕？文件注释里写得很直白：

> One cannot write "infinitely large" computations with the postulated
> IO monad … without turning off the termination checker. The following
> coinductive deep embedding is introduced to avoid this problem.
> Possible non-termination is isolated to the run function below.

也就是说：`IO A` 类型的值是一段**程序文本**，它是纯数据、可比较、可证明
相等，构造它必须通过终止检查；真正「执行」发生在唯一的出口 `run`：

```agda
{-# NON_TERMINATING #-}
run : IO A → Prim.IO A
run (lift m)    = m
run (pure x)    = Prim.pure x
run (bind m f)  = run (♭ m ) Prim.>>= λ x → run (♭ (f x))
run (seq m₁ m₂) = run (♭ m₁) Prim.>>= λ _ → run (♭ m₂)

Main : Set
Main = Prim.IO {0ℓ} ⊤
```

`NON_TERMINATING` Pragma 只出现在这一处——全语言的「不终止额度」集中
兑换在这一个函数里（02 章讲过 pragma 是显式免责条款）。`run` 之下才是
真正 postulate 的原始 IO（`IO/Primitive/Core.agda`）：

```agda
open import Agda.Builtin.IO public using (IO)

postulate
  pure  : A → IO A
  _>>=_ : IO A → (A → IO B) → IO B

{-# COMPILE GHC pure = \_ _ -> return    #-}
{-# COMPILE GHC _>>=_  = \_ _ _ _ -> (>>=) #-}
```

`postulate` + `COMPILE GHC`：Agda 层面它没有定义，编译时整段替换成
Haskell 的 return/>>=。整个副作用能力最终都押在这条 FFI 通道上。

顺带一句历史：更早的版本里 `IO` 走的是 `Codata.Musical.IO` 的纯余归纳
编码（甚至更早是 `Data.IORelation`），2.x 之后统一成现在这套
「guarded 深嵌入 + 单点 run」的方案；`Codata.Musical` 家族仍然活在
22 章的 Stream/Conat 里。**入场券**：任何 import IO 的文件第一行必须
`{-# OPTIONS --guardedness #-}`，实测报错：

```text
examples/Tmp20g.agda:5.1-15: error: [InfectiveImport]
Importing module IO using the --guardedness flag from a module
which does not.
when scope checking the declaration
  open import IO
```

「Infective（传染性）」这个词就是警告：这个 flag 会把你的模块变成
非严格的，别让它乱扩散。

因为 IO 值就是普通数据，下面这行等式（示例 §1）**不运行任何程序**
也能 refl——它是数据层的相等：

```agda
pure-refl : pure {A = ℕ} 42 ≡ pure 42
pure-refl = refl
```

## 20.2 IO 模块族地图（实测清单）

```text
/usr/share/agda-stdlib/src/IO/
  Base.agda        data IO、run、Main、lift、when/unless、forever、untilJust
  Finite.agda      String 版：getLine、putStr、putStrLn、readFile、writeFile、appendFile
  Infinite.agda    Costring 版：getContents、putStr∞、writeFile∞ …
  Handle.agda      文件句柄：Handle、BufferMode、hSetBuffering、hGetBuffering …
  Primitive/       Core / Finite / Infinite / Handle —— postulate + COMPILE GHC 层
  Categorical.agda Effectful.agda Instances.agda IO.agda（顶层门面）
```

日常从顶层 `open import IO` 拿到的都是**guarded 包装版**：签名
`putStrLn : String → IO {a} ⊤` 里的 `IO` 是 20.1 那个 data。注意两个
改名（读源码时容易迷路）：`IO.Finite.readFile` 在顶层 `IO` 里被
重命名为 **`readFiniteFile`**（和 Costring 版区分），而 `writeFile` /
`appendFile` 保持原名。周边系统能力（同样实测存在）：

- `System.Environment`：`getArgs : IO (List String)`、`lookupEnv`、`getEnvironment`
- `System.Exit`：`ExitCode`、`ExitSuccess`、`ExitFailure : ℤ → ExitCode`、
  `exitWith/exitFailure/exitSuccess : IO A`、`die : String → IO A`
- `System.Directory`：`doesFileExist`、`removeFile`、`createDirectory`…
- `System.Process` / `System.Clock` / `System.Random` / `System.FilePath` /
  `System.Console.ANSI`：全家桶都有，但全部走同一套 guarded IO。

## 20.3 main：入口的五级台阶

02 章给过最小可运行例子，这里把每一级展开。完整链条是：

```agda
main : Main
main = run $ do
  putStrLn "hello"
```

- `do` 块是 19 章语法糖，脱糖成 `IO.Base` 的 `_>>=_`（对 guarded IO，
  它内部就是 `bind (♯ m) λ x → ♯ f x`——♯ 是自动补的守卫）；
- `putStrLn "hello"` 得到一个 **IO 值**（此时还没打印任何东西）；
- `run` 把 guarded IO 描述翻译进 `Prim.IO`——副作用从这里开始才真实；
- `Main = Prim.IO {0ℓ} ⊤` 是编译后端认账的入口类型（`-main-is
  MAlonzo.Code.<模块名>` 找的就是它）；
- 所以 `main` 的类型不能写 `IO ⊤`——那是「还没执行的数据」。

## 20.4 --compile 流水线解剖（实测）

`./build.sh run Ex20_io` 执行的两条命令与实测输出。第一步 Agda 把每个
用到的模块生成 Haskell 到 **源文件旁边的 `MAlonzo/`**，然后调用 GHC：

```text
Compiling Ex20_io in /home/xulun/code/programming/agda/_build/2.8.0/agda/examples/Ex20_io.agdai
  to /home/xulun/code/programming/agda/examples/MAlonzo/Code/Ex20_io.hs
Calling: ghc -O -o /home/xulun/code/programming/agda/examples/Ex20_io -Werror
  -i/home/xulun/code/programming/agda/examples -main-is MAlonzo.Code.Ex20_io
  /home/xulun/code/programming/agda/examples/MAlonzo/Code/Ex20_io.hs --make
  -fwarn-incomplete-patterns
[106 of 106] Linking /home/xulun/code/programming/agda/examples/Ex20_io
```

几个必须记死的实测事实：

1. **可执行文件跟着源文件走，不跟终端 cwd 走**。实测在仓库根跑
   `agda --compile examples/Ex20_io.agda` 与在 `examples/` 里跑
   `agda --compile Ex20_io.agda`，产物都是 `examples/Ex20_io`——
   因为后端按「源文件所在目录」定位输出。想换位置用
   `--compile-dir=DIR`。README 判定标准 `./build.sh run Ex20_io`
   的 runmain 分支就按这个约定执行 `examples/Ex20_io` 并在跑完后
   `rm -rf examples/MAlonzo examples/Ex20_io`。
2. **冷编译约 35–40 秒、203 个 Agda 模块转译成 Haskell + 106 个 Haskell
   模块参与编译链接**，链接出的二进制 8.7 MB——IO 程序的编译成本比纯
   类型检查高一个量级（02 章实测结论，这里复核）。
3. GHC 是**硬依赖**：`Calling: ghc …` 这行由 agda 发起，机器上没有
   ghc 就没有第三步（Debian 的 agda 包自带 ghc 运行时依赖）。
4. 一个真实的工作流坑：`build.sh` 开头 `set -euo pipefail`，
   **程序运行失败（非零退出码）时清理不会执行**——本项目实测撞过一次，
   `examples/` 里留下一具半路 getLine 崩溃的二进制。CI 脚本里要么自己
   rm，要么 `|| true` 之后再清。

## 20.5 实战程序：参数、文件、退出码、交互循环

示例的整体骨架（与文件一致，节选编排略压缩）：

```agda
{-# OPTIONS --guardedness #-}

module Ex20_io where

open import Data.Unit.Polymorphic using (⊤; tt)
open import Data.Char.Base    using (Char; toℕ)
open import Data.Nat          using (ℕ; zero; suc; _+_; _*_; _∸_; _≤?_)
open import Relation.Nullary  using (yes; no)
open import Data.String.Base  using (String; _++_; toList; length)
open import Data.Nat.Show     using (show)
open import Function.Base     using (_$_; case_of_)
open import IO                using (IO; Main; run; pure; _>>=_; _>>_;
                                     putStr; putStrLn; getLine;
                                     writeFile; readFiniteFile)
open import System.Environment using (getArgs)
open import System.Exit        using (exitFailure; die)
```

三个细节先埋伏笔：`⊤` 必须是 **`Data.Unit.Polymorphic` 的 ⊤**（坑位 6）；
`case_of_` 要手动 import（坑位 5）；stdlib 2.3 **没有**现成的字符串→数
解析函数（坑位 7），示例手写一个：

```agda
digitToNat : Char → Maybe ℕ
digitToNat c with toℕ '0' ≤? toℕ c | toℕ c ≤? toℕ '9'
...          | yes _ | yes _ = just (toℕ c ∸ toℕ '0')
...          | _     | _     = nothing

private
  digits : ℕ → List Char → Maybe ℕ
  digits acc []       = just acc
  digits acc (c ∷ cs) with digitToNat c
  ...                  | just d  = digits (10 * acc + d) cs
  ...                  | nothing = nothing

parseNat : String → Maybe ℕ
parseNat s with toList s
...        | [] = nothing
...        | cs = digits 0 cs
```

主流程分两条：**无参数走文件演示**，**带参数进交互模式**。文件演示
「写下去再读回来」，把 `hello agda 42` 的 42 真真切切地经过了一趟磁盘：

```agda
path : String
path = "/tmp/ex20-num.txt"

contents : String
contents = "42"

demo : IO ⊤
demo = do
  writeFile path contents
  s ← readFiniteFile path
  case parseNat s of λ where
    (just n) → putStrLn ("hello agda " ++ show n)
    nothing  → die ("cannot parse file: " ++ s)
```

`die` 打印一行并以 `ExitFailure 1` 结束——Agda 的「异常处理」哲学是
**提前终止 + 退出码**，没有 try/catch（见 20.7）。交互分支：

```agda
echo : ℕ → IO ⊤
echo zero    = pure tt
echo (suc n) = do
  line ← getLine
  putStrLn ("said (" ++ show (length line) ++ " chars): " ++ line)
  echo n

interactive : List String → IO ⊤
interactive args = do
  putStr "interactive mode (demo): type lines, echoed up to 3 times\n"
  echo 3
  exitFailure {A = ⊤}   -- 演示分支以非零退出码收尾

main : Main
main = run $ do
  args ← getArgs
  case args of λ where
    []       → demo
    (a ∷ as) → interactive (a ∷ as)
```

实测运行（在仓库根，无任何参数）：

```text
$ ./build.sh run Ex20_io
== agda --compile Ex20_io
…
   | hello agda 42
```

带参数 + 空 stdin 时（`./examples/Ex20_io extra arg < /dev/null`），
getLine 撞上 EOF，得到 20.7 要讲的崩溃现场。

## 20.6 终止性：交互循环怎么写才过检

07 章的老规矩在这里依然生效，但有个好消息：**IO 的递归不需要任何
特殊技巧也能合规**。`echo (suc n)` 的递归调用在 `n` 上结构递减——
终止检查器看的是构造子出现的位置，`do` 块里 `echo n` 是 bind 的实参，
bind 是构造子参数位置的普通函数，照收不误。

真正「永不结束」的循环走的是另一条正门——IO.Base 用 ♯ 亲手造好并
摆在货架上（源码实测）：

```agda
forever : IO {a} ⊤ → IO {a} ⊤
forever act = seq (♯ act) (♯ forever act)

untilJust : IO (Maybe A) → IO A
untilJust m = bind (♯ m) λ where
  nothing  → ♯ untilJust m
  (just a) → ♯ pure a
```

核心cokernel（coinductive kernel）规则：递归调用只要被 `♯_`（force 的
逆 operation）挡住，就算**guarded**、允许无穷展开——这正是 22 章余归纳
的内容在 IO 里的提前彩排。`untilJust` 是交互程序的瑞士军刀：读一行、
解析成 `Maybe A`，失败就再读，直到成功——比 `echo` 的「固定次数」更
接近真实 REPL 的形状。

两个层次别混：`echo` 靠结构递归终止（有限次）；`forever` 靠 ♯ 守卫
合法地不终止（无限次）；而 `run` 自己标 `NON_TERMINATING`，是整个体系
里唯一「法外之地」，而且只此一处。

## 20.7 「异常处理」在 Agda 的正确姿势

stdlib 的 guarded IO **没有 catch**：Haskell 侧的异常会穿透 `run` 直取
进程。实测 `./build.sh run Tmp19c`（一个读 stdin 到 EOF 的小 demo）
得到原样输出：

```text
Tmp19c: <stdin>: hGetLine: end of file
HasCallStack backtrace:
  collectBacktraces, called at libraries/ghc-internal/src/GHC/Internal/Exception.hs:169:13 in ghc-internal:GHC.Internal.Exception
  …
```

退出码非零、栈回溯满屏——这不是 Agda 的 bug，是设计：**异常只能发生
在执行期，而执行期没有类型系统**。工程对策是三级：

1. **发生前避免**：存在性用 `doesFileExist` 预检，输入用 `parseNat :
   String → Maybe ℕ` 判定（示例正是这么做——读自己刚写的文件，
   100% 可控），循环重试交给 `untilJust`；
2. **避免不了就分级退出**：`exitSuccess/exitFailure/exitWith (ExitFailure n)`
   和 `die msg`，把状态编码进退出码给外壳（bash/CI）看；
3. **实在要捕获**：得下探到 FFI 层自己用 `{-# FOREIGN GHC #-}` 包
   `Control.Exception`——超出本教程范围，28 章见。

`exitFailure {A = ⊤}` 的显式注解不是仪式感：`exitFailure : IO A` 里
`A` 是自由变量，放在语句链末尾时没有任何约束能定住它，不写就是实测的
`UnsolvedMetaVariables`（示例 §6 的 `discard : IO {a = 0ℓ} ⊤ → IO ⊤`
同理——IO 的宇宙参数也要手动钉）。

## 20.8 与 Haskell main 的对照

| | Haskell | Agda（stdlib 2.3 实测） |
|---|---|---|
| 入口 | `main :: IO ()` | `main : Main`（= `Prim.IO {0ℓ} ⊤`） |
| IO 值 | 不透明抽象 | `data IO`（lift/pure/bind/seq），可参与等式证明 |
| 执行 | RTS 隐式 | 显式 `run : IO A → Prim.IO A`，带 NON_TERMINATING |
| 终止 | 随便递归 | 结构递归或 ♯-guarded（forever/untilJust） |
| 异常 | try/catch 类型化 | 无 catch；Maybe 判定 + 退出码 + FOREIGN GHC |
| 编译 | ghc | agda --compile → MAlonzo/*.hs → ghc |

## 20.9 坑位清单（本项目实测）

1. **第一行没有 `{-# OPTIONS --guardedness #-}` 就 import IO**：
   `InfectiveImport: Importing module IO using the --guardedness flag
   from a module which does not`——错误行号指 import 行，但修的是首行。
2. **`main : IO ⊤` 是类型错误**：入口必须是 `Main`（= 原始 `Prim.IO ⊤`），
   正确姿势是 `main = run $ …` 把 guarded IO 执行掉。
3. **产物位置跟着源文件，不跟终端**：`agda --compile examples/Ex20_io.agda`
   生成的是 `examples/Ex20_io` 和 `examples/MAlonzo/`（实测两种 cwd 相同）；
   想干净就用 `--compile-dir`，或按 build.sh 那样跑完即删。
4. **运行失败会让 build.sh 的清理不执行**（`set -e` 在运行那行就断），
   仓库里会留下悬空二进制——实测踩过；手动 `rm -rf examples/MAlonzo
   examples/Ex20_io`。
5. **case 不是关键字**：`case x of` 依赖函数名 `case_of_`，忘 import
   `Function.Base` 时报 `Not in scope: case`——和「内建语法」直觉相悖，
   背下来。
6. **两种 ⊤ 会打架**：IO 模块用 `Data.Unit.Polymorphic` 的 ⊤（`Lift
   lzero Unit0.⊤`），如果你的文件 import 了 `Agda.Builtin.Unit` 的 ⊤，
   类型标注时撞出 `Level.Lift Agda.Primitive.lzero ⊤ !=< ⊤`。示例统一
   用 polymorphic 版。
7. **stdlib 2.3 没有 String→ℕ**：`parseNat`/`digitToNat` 都不存在
   （`Data.Char.Base doesn't export … digitToNat` 警告 + NotInScope），
   21 章的文本基础设施也得自己铺——示例手写了 `digitToNat`。
8. **没有类型标注语法 `(e : T)`**：实测 `pure (42 : ℕ)` 直接
   `ParseError`（`:<ERROR>`）；要定隐式参数请写 `pure {A = ℕ} 42`。
9. **readFiniteFile 返回原文**：不剥换行、不预解析，`"42\n"` 会把你
   手写的 `parseNat` 判成 `nothing`——自己写自己读才保证格式（示例
   的 contents 刻意不带尾换行）。
10. **getLine 到 EOF 是崩溃不是 nothing**：Haskell `hGetLine` 异常直接
    穿透（20.7 实测输出），交互式程序要么 `untilJust` 配合判定读，
    要么别在可能 EOF 的 stdin 上裸奔。
