# 40 · 收官：速查表、决策树与学习路线

40 章收官。本章不再引入新代码——`examples/40_cheatsheet/` 里只有一个 main.cpp：把 23 个 GoF 模式各压成一行（意图一句话 / 现代 C++23 替代或搭档），固定文本逐行打印、行数断言 23。真正的收放在正文里：**一张模式选择决策树**（40 章正文的骨架）、**三书对照总表**（三本书怎么配合用）、**学习路线**（按目标分的三条路径）。到此为止，这本教程的完整地图拼齐了。

## 一屏速查表

示例 main.cpp 打印的 23 行速查表（每行 = 模式 / 一句话意图 / 现代替代），本节收录其压缩版——完整文本以示例输出为准：

| 模式 | 一句话意图 | 现代替代 / 搭档 |
|---|---|---|
| Abstract Factory | 产品族的成套创建 | concept 工厂 / 直接构造 |
| Builder | 分步组装复杂对象 | 聚合初始化 / 指定初始化器 |
| Factory Method | 子类决定实例化哪个类 | 构造函数私有 + 工厂函数 |
| Prototype | 按原型克隆创建 | 拷贝构造 / clone() |
| Singleton | 全局唯一实例 | Meyers 单例 / 依赖注入 |
| Adapter | 接口转换 | concept 适配 / lambda 包装 |
| Bridge | 抽象与实现两维分离 | variant × 策略双参数 |
| Composite | 树形统一接口 | variant 递归 + unique_ptr 拆环 |
| Decorator | 包装叠行为 | std::function 链 / lambda 组合 |
| Facade | 一键门面 | 自由函数封装 / make_xxx |
| Flyweight | 共享不可变内部状态 | intern 表 / shared_ptr 缓存 |
| Proxy | 控制访问（懒/守卫/远程） | operator-> 智能指针 / RAII 守卫 |
| Chain of Responsibility | 过闸链，一关否决即止 | Guard 管道（std::function 序列） |
| Command | 操作对象化可撤销 | lambda + 可逆记录 |
| Interpreter | 文法规则即类 | variant 节点 + visit 求值 |
| Iterator | 遍历与容器解耦 | range / view（已下沉语言设施） |
| Mediator | 网状交互改星型 | EventBus（话题字符串解耦） |
| Memento | 快照存取时点 | 值语义快照 / shared_ptr COW |
| Observer | 订阅名单的解耦通知 | std::function 订阅 / RAII 句柄 |
| State | 状态驱动行为切换 | variant 状态 / constexpr 转移表 |
| Strategy | 算法可整体替换 | concept 策略 / std::function |
| Template Method | 骨架固定步骤下放 | CRTP / 模板参数注入 |
| Visitor | 结构冻结操作开放 | variant + overload 组合子 |

"现代替代"栏的读法要小心：它给的是**骨架成本的压缩选项**（函数代替类、variant 代替层次），不是"老模式淘汰通知"——第 39 章刚警告过反向误用。每行替代都有自己的适用判据，散在各章"现代写法"一节。

## 23 模式的"什么会变"总表

第 28 章给行为型 11 个模式画过"集中的变化"总图，这里把 23 个模式全量补齐——**每个模式都在回答同一个问题：哪种变化会持续发生，就把哪种知识集中到一处**。速查表回答"是什么"，本表回答"为什么值得存在"：

| 模式 | 集中的变化 | 集中到哪里 |
|---|---|---|
| Abstract Factory | 产品族的成套搭配 | 具体工厂一个类 |
| Builder | 组装步骤与表示的分离 | Director 的流程 |
| Factory Method | 实例化哪个类的决定 | 子类的钩子 |
| Prototype | "造什么"的原型定义 | 原型对象的克隆 |
| Singleton | "只有一份"的约束 | 实例的持有点 |
| Adapter | 接口的不匹配 | 包装层的转换 |
| Bridge | 格式×实现两维的独立增长 | 桥两侧的类层次 |
| Composite | 树形结构的递归统一 | 叶子/容器统一接口 |
| Decorator | 行为的运行期叠放 | 包装层的逐层转发 |
| Facade | 子系统的使用入口 | 门面的一组方法 |
| Flyweight | 大量对象的重复内部状态 | 共享池与键 |
| Proxy | 访问的控制时机 | 代理的同形转发 |
| Chain of Responsibility | 谁来处理请求 | 处理者链的顺序 |
| Command | 操作的参数化与撤销 | execute/undo 成对 |
| Interpreter | 文法规则 | 规则即类/即 variant 备选项 |
| Iterator | 遍历方式 | 迭代器协议 |
| Mediator | 群体交互协议 | 中介者的星型中心 |
| Memento | 状态的存取时点 | 快照的黑箱化 |
| Observer | 通知的订阅名单 | 主题的订阅列表 |
| State | 状态转移知识 | 状态对象/转移表 |
| Strategy | 算法的选择权 | 策略对象/函数 |
| Template Method | 流程骨架 | 基类的骨架方法 |
| Visitor | 操作维度 | Visitor 子类/overload 组 |

表的用法：遇到"这里要加个 if-else"时，先问**这个 if 分支是哪种变化的表现**——在第一栏找到它，第二栏就是该集中的位置，第三栏（上一节速查表）给出集中成什么样。两表横纵互补，合起来是全书的索引。

## 40 章的知识地图

全书六篇的分工，最后串一遍：**第〇篇（1-4）**把六大原则讲成"模式背后的为什么"——不懂原则的模式是背诵，懂了原则的模式是推导。**第一篇（5-10）**创建型回答"怎么造"：从简单工厂一路走到 Builder，主线是"把 new 的决定权从调用方手里逐步专业化"。**第二篇（11-17）**结构型回答"怎么组装"：适配器换接口、桥拆两维、组合立树形、装饰叠行为、享元省内存、代理控访问——主线是"在不改双方的前提下接线"。**第三篇（18-28）**行为型回答"职责怎么分、变化往哪集中"——11 个模式按"集中的变化"各管一维（上表），28 章收官总图是第一篇以来最重要的一张图。**第四篇（29-32）**现代专题给出语言的最新表达：三副面孔、类型擦除、两个完整混编现场——前面 28 章的所有"类层次"在这里获得压缩选项。**第五篇（33-36）**实战篇把工具箱拼成系统：表驱动状态机、对象池、插件框架、表达式求值器——每章验证"前面积累的工具确实够用"。**第六篇（37-40）**收官：两个综合场景（37/38）背靠背演示多模式协作，39 章立反光镜（骨架必须被红利覆盖），40 章（本章）交地图。

## 高频组合 Top 5

40 章里反复出现的模式组合，按出场频次排——组合比单模式更接近真实设计：

1. **组合 + 访问者/解释器**（13/20/28/36 章）：树形结构 × 对结构的多趟操作——AST、文档树、场景图的地基；variant 版把两骨架压成"备选项 + overload"。
2. **策略 + 工厂/注册表**（26/31/35 章）：可替换算法 × 按名获取——规则引擎、编解码器框架的标准形；哨兵自注册把装配权交给链接期。
3. **观察者 + RAII 句柄**（24/31/32 章）：解耦通知 × 生命周期自动管理——C++ 相对 GC 语言的独特贡献，订阅与析构同源。
4. **桥 + 外观**（37 章合体，7+15 章）：两维分离 × 一键入口——"结构维度交给设计者、使用体验交给调用者"的分工。
5. **备忘录 + 命令**（23/19 章）：快照与撤销——undo 系统的两大件；值语义时代快照比 GoF 时代的黑箱化更便宜。

## 模式选择决策树

判别的顺序比判别的条目重要，一棵四问决策树按序走：

1. **问题在创建、结构还是行为？**——造东西的烦恼（构造复杂/族切换/唯一性）走创建型 1-5；组装的烦恼（接口不合/维度分离/树形/叠层/简化门面/共享/控制访问）走结构型 6-16；职责分配的烦恼（谁能处理/怎么撤销/怎么通知/怎么换算法）走行为型 17-28。
2. **这个场景的红利存在吗？**——按第 39 章三幕的判别句：产品族成套切换？运行期叠放？全局只读真资源？答否则退回朴素写法（lambda/组合/注入）。
3. **选经典骨架还是现代压缩？**——规则无状态小函数 → std::function/concept 压缩（29-32 章的现代专题）；有状态重逻辑、跨库开放 → 经典类层次。两形态合同一致时永远可以互换（25/28 章对拍手法）。
4. **扩展维度是谁？**——加操作频繁 → Visitor 系（结构冻结）；加类型频繁 → 继承系（接口开放）；两个都频繁 → 先质疑需求（第 28 章表达式问题），再选牺牲哪边显式化。

四问走完还没答案的场景，大概率问题不在模式层——回去重画需求边界。

## 学习路线（按目标选路）

**路线一：面试/快速过盘**（1-2 天）：

- 读各章"意图与动机"+"取舍表"+ 本章速查表与"什么会变"总表；
- 每个模式能按"集中的变化"句式复述（"策略 = 算法的选择权集中到策略对象"）；
- 示例代码全部跳过，39 章三幕判别句背下来（面试反问的弹药）。

**路线二：上手应用**（1-2 周）：

- 正篇 1-28 章顺序读，每章跑一次 `build.ps1 -Example NN_name`（双通道全绿可对照输出）；
- 现代专题 29-32 章精读——后续一切现代形态的地基；
- 实战篇 33-38 章各挑一个自己业务里最像的场景改造练习；
- 目标：遇到"这一堆 if-else 能不能用模式"的问题时，30 秒内定位到候选章。

**路线三：精通内化**（长期）：

- 每章"陷阱清单"逐条自查——五条全踩过（或防过）才算学过；
- 双形态对拍亲手做一遍（25/28/36 章的手法：经典版与 variant 版互为测试预言）；
- 39 章反模式拿自己项目里的真实代码对照，找出至少一处"骨架超过肉"；
- 给本书没写的场景（并行流水线、内存序敏感的池、协程管道）写一章自己的"第 41 章"——写不出来说明还有没吃透的地方。

三条路线的共同起点是同一句话：**模式是答案，先确认你拿到了正确的问题**——"什么会变"没找对，选哪个模式都是错配。

## 常见错误选型对照

决策树之外，再列五组最常被选错的"近亲模式"——错选不是因为不认识模式，而是因为两个候选的红利表面相似：

| 场景描述 | 常见错选 | 正确选择 | 一句话判据 |
|---|---|---|---|
| "包装一层，顺便加点功能" | Adapter | Decorator | 转接口用 Adapter，加行为用 Decorator——意图不同，同形不同义 |
| "只有一个实现了，要不要抽象？" | 预建接口 + 工厂 | 直接写具体类 | 第二个实现出现再抽象（39 章第一幕的教训） |
| "这些类互相调用太乱" | 到处 Observer | Mediator | 点对点通知用 Observer，多对多纠缠收中心用 Mediator |
| "对象很大，到处传" | 到处 Prototype 克隆 | Flyweight 共享 | 重复的不可变部分共享（享元），整对象复用才克隆 |
| "状态很多，用 switch 还是 State 类？" | 二选一硬挑 | 先数转移是否带动作 | 纯跳转用表（33 章），带动作/负载才 State 类 |

对照表的用法：先对场景描述一栏确认"对上号了"，再看判据栏一句话定夺——**近亲模式的差别几乎全在意图层**，结构上它们常常惊人地像（Adapter 与 Decorator 同形是 GoF 关系图里最著名的一条连线）。

## 常见问答（FAQ）

四问四答，来自 40 章写作中最常被问到的疑惑：

**问：现代写法出来后，经典模式还有必要学吗？**
答：有必要——压缩选项压缩的是**骨架**，不是**判断**。"什么时候该拆两维"（桥）、"集中的变化是什么"（全部 23 个）这些判断力与形态无关；而且判断力先于形态，不知道要拆什么，variant 写出来也只是换了语法的烂结构。经典骨架是判断力的教学道具——先在类层次里看清"为什么"，再学会用 function/variant 压缩"怎么做"。

**问：这本教程的"现代替代"是不是说 GoF 过时了？**
答：不是。GoF 过时的是**实现语汇**（1995 年的 C++ 没有移动语义、variant、concepts），不过时的是**变化的分类学**——"什么会变集中到哪"这张表今天依然成立。读 GoF 正确姿势：判据全收，实现照着 29-32 章翻译。

**问：实战篇（33-36）为什么挑这四个场景？**
答：状态机（行为型状态维的集大成）、对象池（创建型+生命周期的交汇）、插件框架（注册表+工厂+策略的组合）、求值器（解释器+备忘录+组合的联演）——四个场景合计覆盖了 23 个模式里 19 个的实际用场，且都是真实工程里高频出现的子系统。

**问：读源码（examples/）和读正文（docs/）的顺序？**
答：永远正文先行——正文把"为什么这么设计、陷阱在哪"讲完，源码只是判断力的实证材料。跳过正文直接抄示例，等于把教程降级为代码罗列——这正是本书最初拒绝的形态。

## 与"什么会变"互补的三张小图

三张不到半屏的 ASCII 图，收进速查章做长期索引——分别对应创建、结构、行为三篇的核心直觉：

```text
创建型：new 的决定权逐步上移          结构型：不改双方的前提下接线
   调用方直接 new                        ┌──Caller──┐
   └─> 简单工厂（1 个决策点）            │  Facade  │  <- 一键入口
   └─> 工厂方法（子类定品种）            ├──Adapter──┤ <- 接口转接
   └─> 抽象工厂（族成套）                ├──Bridge───┤ <- 两维分离
   └─> Builder（分步+表示分离）          └─Decorator─┘ <- 行为叠放

行为型：集中的变化
   谁处理？CoR   怎么撤销？Command   怎么通知？Observer
   怎么换算法？Strategy            状态驱动？State
   遍历？Iterator                  树上算账？Visitor
```

图的读法：创建型箭头是"决策点越来越专业化"；结构型是"接线层的花样"；行为型是"每行一个变化维度"——与"什么会变"总表纵横对齐。

## 全书验证体系的最后说明

本教程 40 章共 38 个可运行示例（39/40 章 main-only），全部通过 MSVC 与 clang 双通道编译运行、输出逐字节一致。验证体系的四条支柱，逐条展开：

- **判定六条自动化**：exit 0 / stderr 空 / stdout 非空 / 无控制字符 / 以"自检通过"结尾 / 零告警——六条全部写进 `build.ps1`，任何一条不满足即 [NG]；
- **确定性输出纪律**：所有涉及"同一性/计数/时序"的断言都转成布尔或计数比较，不打印地址、时间戳、浮点直接值、类型大小——输出不确定的教程无法对拍；
- **双通道逐字节一致**：同一示例在 MSVC 与 clang 下的 stdout 必须逐字节相同——编译器实现差异（求值顺序、告警策略）被这条合同当场暴露；
- **断言面设计**：每个示例的 assert 群覆盖"合同的正例 + 反例 + 边界"，正文各章"本章示例的断言面"一节逐一登记——断言不是装饰，是教程可信度的承重墙。

读者在自己环境复跑时，唯一的口径就是：`pwsh ./build.ps1 -All`，看到"通过 80 失败 0"即与本书一致。
