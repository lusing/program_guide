# 01 · 全景：Io 是什么，为什么值得学

> 对应示例：无（本章是地图；从 02 章起每章一个可独立运行的示例目录）

Io 是一门**纯原型（prototype-based）、纯消息传递**的动态语言，作者 Steve Dekorte，
2002 年首次发布。它的极简程度在主流语言里几乎找不到对手：**没有类、没有关键字、
没有语句——只有消息**。`if`、`while`、`for`、`return` 全都是**槽**，靠消息触发，
`1 + 2` 也不是语法，而是「把消息 `+` 发给 `1`」。

实测一下这些「关键字」到底是什么（本机 `20260302` 构建）：

```text
Object getSlot("if")      type = CFunction      ← 原生实现，但依然是槽
Object getSlot("while")   type = CFunction
Object getSlot("for")     type = CFunction
Object getSlot("return")  type = CFunction
Object getSlot("and")     type = Block          ← 用 Io 自己写的 method
Object getSlot("or")      type = true           ← ⚠️ 值槽，不是方法（05.4）
Object getSlot("not")     type = nil            ← 也是值槽，值是 nil
Number getSlot("+")       type = CFunction
```

「原生实现」不等于「语法」——`if` 是槽，所以它**能被覆盖、能被转发、能被当成值取出来**，
这正是元编程（17 章）能成立的物理基础。

这不是为了炫技。把语言拆到只剩「对象」和「消息」两块积木之后，
**你可以用消息本身去改写语言的行为**——自定义控制流、自定义运算符优先级、
给不存在的消息挂兜底处理（`forward`），都是在普通代码里完成的，不需要宏、不需要改编译器。
后面 17 章（元编程）和 24 章（实战）就是这条能力线的终点。

## 01.1 三条心智模型

学 Io 只需要先装进三句话，剩下的都是推论。

**一、一切皆消息。** 代码 `obj method(arg)` 的唯一含义是「把消息 `method(arg)` 发给 `obj`」。
没有函数调用、没有运算符、没有控制结构这一层语法糖。这句话的推论是：
**消息可以不是字面量写死的**——你可以用字符串拼一条消息出来再发出去（`Message fromString`），
也可以拦住一条没人定义过的消息（`forward`）。

**二、一切皆槽。** 对象就是一个「名字 → 值」的表（槽表）。定义槽用 `:=`，
更新已存在的槽用 `=`，两者不能混（第 07 章 7.3 有实测）。没有字段、属性、方法之分——
**槽里放的是方法，它就叫方法；槽里放的是数字，它就叫字段**。推论是：
方法可以被读出来当值传递，字段也可以被激活。

**三、一切皆原型。** 没有类。要「造一个对象」就 `Object clone`，要「造一类对象」
就 clone 一个模板再往外 clone。查槽是**沿 proto 链向左找**，赋值是**永远写在本地**
（第 07 章 7.4）。推论是：运行中的任何对象都可以被就地改造，包括 `Object` 自己——
所以本教程里很多断言要先 `Lobby removeSlot(...)` 把上一节留下的痕迹擦掉。

> **为什么重要**：这三句话是后面 23 章的共同地基。凡是遇到「Io 为什么要这么写」的疑问，
> 先回到这三条，答案通常就在里面。反过来，带着 C++ / Python 的类模型去读 Io，
> 会在第 07 章立刻撞墙。

## 01.3 工具链：两个二进制，同一份源码

本教程的验证跑在**同一份 Io 源码编译出的两条通道**上：

| 通道 | 路径 | 大小量级 | 特点 |
|---|---|---|---|
| `io` | `~/…/io/bin/io` | 十几 KB | 动态链接版，运行时按 rpath / 安装前缀找 `libiovmall.dylib` 与 addon |
| `io_static` | `~/…/io/bin/io_static` | 1.5 MB | 静态单文件版，不依赖任何外部动态库 |

两者都报同一个版本号（本机实测 `System version` 是 `20260302`，Io 用日期当版本号），
都从 `System installPrefix` 下的 `lib/io` 加载 `Object.io` / `List.io` / `Exception.io` 这些
**用 Io 自己写成的核心库**。

> **为什么重要**：`io` 与 `io_static` 语义相同，差别只在**加载方式**。
> 因此「两条通道输出逐字节一致」这条判定，检验的不是两种语义，
> 而是**示例没有偷偷依赖动态库加载或安装前缀**。这条纪律在本仓库里叫「跨通道比对」。

本机两通道都是**从源码编译**得到的（CMake + `build.sh`），没有用包管理器里的 Io——
本教程依赖的若干行为（`actorRun`、`Future`、`serialized` 的具体产物格式）在旧版二进制里
根本不存在，用包管理器装一个出来只会得到一堆对不上的实测输出。
回归脚本一律**探测**解释器路径（先看环境变量 `IO_BIN`，再看安装前缀，最后按 `io_static` / `io` 从 `PATH` 找），
**不硬编码**；找不到的通道自动跳过。

## 01.4 验证纪律：七条判定 + 观察项

`run-all.sh`（shell 入口）与 `build.ps1`（PowerShell 入口）判定逐条一致。

| # | 判定 | 为什么需要这一条 |
|---|---|---|
| 1 | 退出码为 0 | 基础 |
| 2 | stderr 为空 | 合法输出走 stdout、诊断走 stderr；这条等价于「零告警」 |
| 3 | stdout 里同时出现 `==== NN 开始 ====` 与 `==== NN 结束 ====` | **Io 的未捕获异常会中断脚本、退出码却仍是 0**，只判退出码会放过「跑到一半就死了」 |
| 4 | 两个标记之间的区间非空 | 保证真的跑了内容，不是空壳 |
| 5 | 区间不含 `\r` 或 `ESC` | 原始内存字节打出来能退 0、有标记，肉眼却看不出来 |
| 6 | 区间里没有**未捕获异常横幅** | 横幅形状是「`  Exception: …` + 紧跟一行纯 `-`」，见下 |
| 7 | 两条通道的区间逐字节一致 + 同通道连跑两次一致 | 抓 `Map` 迭代序、对象地址、墙钟时间等非确定性 |

第 6 条的判据写细了是有原因的：**单看一行判不出来**。
13 章的示例会主动打印异常消息（`try(...) error`）做演示，24 章的表格会打 26 个 `-` 当分隔线——
两者都像「溃逃痕迹」。所以判据必须是「`Exception: ` 行 + **紧邻的下一行**是纯 `-`」这个**组合**，
而不是任何单独一行。这个调整本身就是被 24 章的一次误报逼出来的。

有两类文件**不参与逐字节比对**，另立判定：

```text
examples/13_exceptions/observe_13_uncaught.io   观察「未捕获异常 + 退出码 0」
examples/15_system/observe_15_relpath.io        观察「换个调用方式，launchPath / launchScript 怎么变」
```

**观察项（`observe_*.io`）** 的判定与普通示例不同：它只要求跑到底 + 打印自己的观察标记 +
出现预期痕迹，**不要求输出确定性、不参与跨通道比对**。它专门用来装那些
「一个脚本中途死掉」「同一份代码两种调用方式结果不同」的**客观行为**——
这类东西放进普通示例会把「输出可比性」这条纪律捅个洞。

## 01.5 怎么读

- **第一次学 Io**：02 → 24 顺读。每章「先给现象（实测输出）→ 再给代码 → 最后给结论」，
  所以你可以先看输出、自己猜为什么，再往下读。
- **有 Smalltalk / Self / Lisp 背景**：02、06、07、08 快速过，直接看 09–13 和 17。
  你的类模型概念可以复用，但要注意 Io 的关键字消息优先级**与 Smalltalk 相反**（06.4）。
- **只想要语法速查**：看 [CHEATSheet.md](../CHEATSheet.md)，里面有一张覆盖全部
  240 条实测坑位（24 章 × 每章 10 条）的总索引。
- **想知道 Io 有多不靠谱**：直接翻每章末尾的「坑位清单」，或者 22 章（性能）
  和 23 章（FFI）。本教程的一大特点是**把语言的缺陷也如实写进教程**，
  而不是只教漂亮的写法。

> **为什么重要**：Io 是一门「论文级优雅、工程级粗糙」的语言。
> 它的消息模型干净得可以当教学范本，但标准库在非 ASCII、序列化、FFI 这些地方
> 有一堆能让人查一整天的坑。**本教程的目标是让你能写出正确的 Io 代码，
> 而不是相信 Io 什么都能干**——所以每章都给出「能安全写」和「刻意避开的」两类边界。

## 01.6 坑位清单

1. **带着 C++/Python 的类模型读 Io** → 没有类、没有关键字、没有函数调用，只有「对象 + 消息 + 槽」；先装 01.1 的三条心智模型再看后面。
2. **以为 `=` 和 `:=` 可以互换** → `=` 只能更新**已存在**的槽，凭空造槽报 `Slot x not found. Must define slot using := operator before updating.`（07.3）。
3. **把 `String` 当成一个实在的类型** → 字符串字面量的 `type` 是 `Sequence`，不可变只是一个**对象标志**；`ImmutableSequence` 是空壳 proto，`isKindOf` 也是 `false`（04.1）。
4. **拿 `size` 当字节数** → `size` 数码点、`sizeInBytes` 数**内部**字节、`asUTF8 size` 才是落盘字节；三个数在中文上能差好几倍（04.2）。
5. **跨编码宽度比较字符串** → 字节串（`ascii`/`uint8`）与含中文字面量（`ucs4`/`uint32`）的 `type` 都报 `Sequence`，但 `containsSeq` **不报错、只给错答案 `false`**；比较前两边都 `asUTF8`（16.2、15.6.1）。
6. **以为未捕获异常会让退出码非 0** → 横幅打到 **stdout**、脚本中断、**退出码仍是 0**；所以验证必须靠「结束标记」而不能靠退出码（13.3）。
7. **以为 `try` 会返回成功时的值** → `try` 成功也返回 `nil`，唯一判据是 `e != nil`；要值就自己写进外层槽（13.1）。
8. **以为 `do(...)` 里能用逗号分隔多个槽定义** → 逗号是实参分隔符，`do` 只求值第一个实参，**第二个连求值都不会发生**（07.9）；`do` 的作用域也只到接收者和 `Lobby`，看不到本方法的局部槽，要用 `lexicalDo`（07.10）。
9. **对非 ASCII 文本用光秃秃的 `split`** → 无参 `split` 按**字节**扫空白，码位低字节是 `0x0A`/`0x0D`/`0x20` 的汉字会被劈开（`"上" split` 得 `list("")`）；外部文本一律写 `split(" ")`（16.4）。
10. **以为 `and` 和 `or` 结构对称** → `and` 是方法（必须求值实参），`or` 在非假值对象上是**值槽** `true`（`setSlot("or", true)`），实参连求值都不发生、结果恒 `true`（05.4）。
