# 03 · 数值类型

> 对应示例：`examples/03_numbers/`

Ruby 的数值是一棵以 `Numeric` 为根的类树：`Integer`（任意精度）、`Float`（IEEE 754 双精度）、`Rational`、`Complex` 全是对象。本章主线两条：**整数不会溢出**、**整除的商向负无穷取整**——这两条与 C/Java/Python 的直觉差异最大，坑也最集中。

## 3.1 Integer：定长区间内是机器整数，超界自动升 Bignum

```ruby
ok 2**62 - 1 + 1 == 2**62                 # 63 位正好在定长轨道上
big = 2**100
ok big.is_a?(Integer) && big > 0
ok (2**100).to_s.size == 31
a = 9_223_372_036_854_775_807             # 2**63 - 1，下划线是合法分隔符
ok a + 1 == 9_223_372_036_854_775_808
```

```text
---- 3.1 Integer：定长区间内是机器整数，超界自动升 Bignum ----
Fixnum/Bignum 已合并为 Integer（1.9 起），区间切换对用户透明
2**100 = 1267650600228229401496703205376
Long.MAX_VALUE + 1 = 9223372036854775808（精确，不环绕）
```

老教材里的 `Fixnum`/`Bignum` 已在 2.4 合并为统一的 `Integer`：区间内是机器整数，超界**自动**升级为任意精度实现，切换对用户完全透明——`2**62` 与 `2**100` 是同一个类，没有「大数模式」要手动开启。**整数没有溢出**——Java 的 `Long.MAX_VALUE + 1` 会环绕成负数，Ruby 直接给出正确大数；密码学/哈希类代码里这是生死攸关的差别。

数字字面量可用下划线做分隔符（`1_000_000`），大数常量必备——数零的位数是 bug 温床。注意 `2**100` 的 `**` 是乘方运算符，右结合且优先级高于一元负号：`-2**2` 是 `-(2**2)` 即 `-4`，要平方负数得写 `(-2)**2`。

## 3.2 进制：字面量与 to_s

```ruby
ok 0b1010 == 10 && 0o17 == 15 && 0xFF == 255 && 0d42 == 42
ok 255.to_s(16) == "ff" && "ff".to_i(16) == 255
```

```text
---- 3.2 进制：字面量与 to_s ----
0xFF = 255，255.to_s(16) = ff，"ff".to_i(16) = 255
```

字面量前缀：`0b` 二进制、`0o`（或 `0`）八进制、`0x` 十六进制、`0d` 十进制。反向转换是 `to_s(进制)`（2–36 任选），正向解析是 `to_i(进制)`：

```ruby
ok 0b1010 == 10 && 0o17 == 15 && 0xFF == 255 && 0d42 == 42
ok 255.to_s(16) == "ff" && 255.to_s(2) == "11111111" && 255.to_s(36) == "73"
ok "ff".to_i(16) == 255
```

注意方向：`to_s(16)` 是「把这个数按十六进制打出来」，`"ff".to_i(16)` 是「把这串字符按十六进制解析」——参数都是进制，但一个管输出一个管输入。`to_s(36)` 是上限（10 个数字 + 26 个字母），比它直接 `ArgumentError`。

（`0o17` 这种 `0o` 前缀是 1.9 引入的规范写法，旧的 `017` 八进制仍在但易与十进制 `17` 混淆——前导零在别人的代码里可能是八进制，review 时多看一眼。）

## 3.3 Float：IEEE 754 的经典坑

```ruby
ok 0.1 + 0.2 != 0.3                       # 二进制浮点经典
ok (0.1 + 0.2 - 0.3).abs < Float::EPSILON
ok 1.0 / 0.0 == Float::INFINITY
ok (0.0 / 0.0).nan?                       # NaN 与谁都不等，包括自己
```

```text
---- 3.3 Float：IEEE 754 的经典坑 ----
0.1 + 0.2 = 0.30000000000000004（0.30000000000000004）
1.0/0.0 = Infinity，0.0/0.0 = NaN
```

Ruby 的 `Float` 不豁免 IEEE 754 的任何经典坑：`0.1 + 0.2 != 0.3`，比较要用 `Float::EPSILON` 容差；`1.0/0.0` 不抛异常而是 `Float::INFINITY`；`0.0/0.0` 得到 NaN，**NaN 与谁都不等，包括它自己**（`nan?` 才是正确判法——「任何与 NaN 的比较都是假」是 IEEE 754 的规定，不是 Ruby 的 bug）。要精确分数？见下一节——别用 Float 算钱。

注意除零行为按类型分轨：**整数 `1 / 0` 抛 `ZeroDivisionError`**（在第 13 章的异常体系里还会见到它），浮点 `1.0 / 0.0` 返回 `Infinity` 继续算——同一个「除以零」，两套世界两套规矩，写通用除法前先问自己拿到的是哪种类型。

特殊值速查：`Float::INFINITY`（含正负）、`Float::NAN`、`Float::MAX`（有限最大值，比 Infinity 小得多——所以 `Float::MAX > Float::INFINITY` 为假）、`Float::EPSILON`（1.0 与下一个可表示浮点之差，容差比较的标尺）。浮点比较的标准姿势：

```ruby
(0.1 + 0.2 - 0.3).abs < Float::EPSILON   # true —— 永远这样比，别写 ==
```

## 3.4 Rational 与 Complex

```ruby
r = Rational(1, 3)
ok r + Rational(1, 6) == Rational(1, 2)   # 精确分数，无舍入
ok Rational("3/9") == Rational(1, 3)      # 字符串直接解析并约分
c = Complex(1, 2)
ok c * Complex(1, -2) == Complex(5, 0)
ok (3 + 4i).abs == 5.0                    # i 后缀字面量
```

```text
---- 3.4 Rational 与 Complex ----
1/3 + 1/6 = 1/2
(1+2i)*(1-2i) = 5+0i，(3+4i).abs = 5.0
```

`Rational` 与 `Complex` 是一等公民，不需要 require（整章只用了标准库）。`Rational` 全程精确无舍入，字符串 `"3/9"` 都能直接解析并自动约分；复数支持 `i` 后缀字面量（`3 + 4i`），模用 `abs`。`0.1 + 0.2` 的坑在 `Rational` 世界不存在——**钱和分数一律 Rational**，这是 Ruby 少有的「开箱即正确」。

`Rational` 的构造有三条路：`Rational(1, 3)`、`Rational("3/9")`（字符串直解）、整数除法的精确形态 `1/3r`（`r` 后缀字面量，实测于 4.0.7 探针得 `(1/3)`）。反向出口是 `to_f`（转 Float，从此带上舍入误差）与 `to_r`（Float 转 Rational，得到的是**二进制近似**的精确分数——实测 `0.1.to_r` 是 `3602879701896397/36028797018963968`，不是 `1/10`，方向别搞反）。

类型混算时 Ruby 沿 `Integer → Rational → Float → Complex` 的精度阶梯自动提升：`Rational(1,2) + 1 == Rational(3,2)`，一旦混入 Float 就降级为浮点误差世界（`Rational(1,3).to_f` 的信息丢掉就找不回来）。示例收尾的自检 `Rational(1,3) + Rational(1,6) + Rational(1,2) == 1` 在 Float 下就不保证成立——同一条数学事实，两种类型两种命运。

## 3.5 整除家族：Ruby 的商向负无穷取整

```ruby
ok 7 / 2 == 3                             # 整数 / 整数 = 整数
ok 7 / -2 == -4                           # 注意！-3.5 向负无穷取整 = -4（C 是 -3）
ok 7.fdiv(-2) == -3.5                     # fdiv：强制浮点除
q, rmd = 7.divmod(-2)
ok q == -4 && rmd == -1
ok -7 % 3 == 2                            # C/Java 是 -1；Ruby 恒非负（除数为正时）
```

```text
---- 3.5 整除家族：Ruby 的商向负无穷取整 ----
7 / -2 = -4，7.divmod(-2) = [-4, -1]，-7 % 3 = 2
```

本章最大的坑在这里。整数 `/` 整数还是整数，但**商向负无穷取整**（floor），不是 C/Java 的向零截断：`7 / -2 == -4` 而 C 算出 `-3`。配套规则：**余数跟除数同号**——`-7 % 3 == 2`（C/Java 是 `-1`）、`7 % -2 == -1`。两条合起来看其实是一件事：Ruby 维护恒等式 `a == (a / b) * b + a % b`，商取 floor 后余数的符号自然由除数决定。家族成员分工：

| 方法 | 行为 | 例 |
|---|---|---|
| `/` | 常规除：整数出整数（floor）、浮点出浮点 | `7 / 2 == 3`，`7.0 / 2 == 3.5` |
| `fdiv` | 强制浮点除 | `7.fdiv(-2) == -3.5` |
| `div` | 强制整数除（floor） | `7.div(-2) == -4` |
| `divmod` | 一次返回 `[商, 余数]` | `7.divmod(-2) == [-4, -1]` |
| `%` / `modulo` | 余数跟除数同号 | `-7 % 3 == 2` |

实用红利：**除数为正时余数恒非负**，数组环形索引不用再写 `(i % n + n) % n`：

```ruby
ring = %w[甲 乙 丙 丁]
ok ring[-1 % 4] == "丁" && ring[-2 % 4] == "丙"
```

`-1 % 4 == 3`、`-2 % 4 == 2`——负索引折回正区间，恰好与数组自身的负索引 `ring[-1]` 等价，环形缓冲、轮转调度都靠它。

## 3.6 转换：to_i 宽容、Integer() 严格

```ruby
ok "42abc".to_i == 42                     # 宽容：能解析多少算多少
ok "abc".to_i == 0                        # 解析不动就 0，不抛错！
begin; Integer("42abc"); rescue ArgumentError; raised = true; end
ok 2.5.round == 3                         # .5 远离零，不是银行家舍入！
ok 3.99.to_i == 3                         # to_i = truncate，向零
```

```text
---- 3.6 转换：to_i 宽容、Integer() 严格 ----
"42abc".to_i = 42，"abc".to_i = 0；Integer("42abc") 抛 ArgumentError
2.5.round = 3，3.99.to_i = 3，(-3.5).round = -4
```

两条解析路线脾气相反：**`to_i` 宽容**——前缀能解析多少算多少（`"42abc"` → 42），解析不动**返回 0 不抛错**（`"abc".to_i == 0`，静默的数据损坏源头）；**`Integer()` 严格**——整串必须合法，否则 `ArgumentError`。边界输入一律走 `Integer()`。选型一句话：清洗用户输入、容错优先用 `to_i`；校验协议、安全优先用 `Integer()`。

取整家族四个方向，一张表定案：

| 方法 | 方向 | 例 |
|---|---|---|
| `round` | 四舍五入，`.5` **远离零** | `2.5.round == 3`，`(-3.5).round == -4` |
| `floor` | 向负无穷 | `3.99.floor == 3`，`(-3.5).floor == -4` |
| `ceil` | 向正无穷 | `3.99.ceil == 4` |
| `to_i` / `truncate` | 向零 | `3.99.to_i == 3`，`(-3.5).truncate == -3` |

注意 `round` 的 `.5` **不是银行家舍入**——Python 3 的 `round(2.5) == 2`，Ruby 是 `3`；跨语言移植统计代码时要专门核对。`to_i` 与 `truncate` 完全同义，只是 `to_i` 兼任「字符串解析」的重载身份。

## 3.7 比较链与 clamp

```ruby
ok 15.clamp(0, 10) == 10 && (-5).clamp(0, 10) == 0
ok [3, 1, 2].min == 1 && 3.gcd(18) == 3 && 4.lcm(6) == 12
```

```text
---- 3.7 比较链与 clamp ----
clamp(15, 0, 10) = 10，gcd(3,18) = 3
```

数值比较的便利件：比较运算符可链写（`(1 < 2) && (2 <= 2)`）、`between?(a, b)` 判区间、`clamp(min, max)` 把值夹进区间（越界取边界，常用于把用户输入按进合法范围——`15.clamp(0, 10) == 10`、`(-5).clamp(0, 10) == 0`）。`gcd`/`lcm` 直接挂在 Integer 上，不用导入任何数学库；`min`/`max` 在数组与数值上都有（数组的全面讲法在 09 章）。

这些方法全部定义在 `Comparable`/`Numeric` 一侧，任何实现了 `<=>` 的自定义类都能免费拿到同一套比较协议（07 章讲模块时回看这里会更有感觉）。

为什么把 `clamp` 单独立节：它是「范围收敛」的语义化写法，`[x, lo].max.min(hi)` 这类嵌套 min/max 的老写法可读性差还容易写反边界；`clamp` 一眼看出「把 x 夹进 [lo, hi]」。Ruby 社区（Rails 内置同款）已把它当惯用法。本章至此的主线复盘：整数不溢出（3.1）、除法维护 floor 恒等式（3.5）、解析分宽容/严格两派（3.6）——三条记牢，Ruby 数值层就没有暗雷了。

## 3.8 坑位清单

1. **商向负无穷取整**：`7 / -2 == -4`，与 C/Java 的 `-3` 不同；`7.divmod(-2) == [-4, -1]`（3.5）。
2. **余数跟除数同号**：`-7 % 3 == 2`、`7 % -2 == -1`——从 C/Java 移植取模逻辑必错（3.5）。
3. **`"abc".to_i == 0` 不抛错**：宽容解析把坏输入静默变 0；要严格用 `Integer()`（抛 `ArgumentError`）（3.6）。
4. **`0.1 + 0.2 != 0.3`**：二进制浮点，比较用 `Float::EPSILON` 容差；钱和精确分数用 Rational（3.3/3.4）。
5. **NaN 与谁都不等**：`x == x` 对 NaN 为假，判 NaN 只能 `nan?`（3.3）。
6. **`1.0/0.0` 不抛 ZeroDivisionError**：整数 `1/0` 才抛；浮点除零得 `Infinity`/`NaN`（3.3）。
7. **`2.5.round == 3`、`(-3.5).round == -4`**：`.5` 远离零，不是 Python 3 的银行家舍入（`2.5` → `2`）；`to_i`/`truncate` 向零，`floor` 向负无穷，四个别混（3.6）。
8. **`Fixnum`/`Bignum` 已不存在**：2.4 起统一为 `Integer`，老教材代码里 `is_a?(Fixnum)` 直接 `NameError`（3.1）。
9. **整数无溢出**：`2**63` 精确有效，Java 的环绕 bug 在 Ruby 不会发生——但别因此对 Float 放松警惕（3.1）。
10. **`to_s(16)` 与 `"ff".to_i(16)` 方向相反**：一个管输出一个管输入，参数都是进制（3.2）。
11. **`clamp` 参数顺序是 `(min, max)`**：写反成 `clamp(10, 0)` 行为无意义；负数记得加括号 `(-5).clamp(0, 10)`，`-5.clamp` 会被解析成对 `5` 取负（3.7）。
12. **`-2**2 == -4`**：`**` 优先级高于一元负号，平方负数要写 `(-2)**2`——与数学直觉相反而与 Ruby 文法一致（3.1）。
