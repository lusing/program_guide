# 02 · 第一个程序

> 对应示例：`examples/02_hello/`

Ruby 没有入口函数，`ruby main.rb` 从第一行执行到最后一行——所以「第一个程序」要解决的其实是三件事：**怎么输出、字符串怎么写、数据从哪来**。本章同时交代全书示例的通用骨架（`frozen_string_literal`、`sec` 分节、结束标记）。

先看骨架本身：每个示例顶部都有两个逐字相同的助手——`sec("N.M 标题")` 打出分节横线（节号与本书小节一一对应），`ok(条件)` 是断言自检（失败即抛错、走 stderr、退出码非 0，验证脚本直接判负）。文件第二行 `# frozen_string_literal: true` 让所有字符串字面量即冻结（01.5 节讲过为什么）。读后面各章示例时，这两个助手不再重复解释。

## 2.1 输出三件套：puts / print / p

```ruby
puts "puts 自带换行"          # 给人看：to_s 后追加 \n
print "print 不换行"          # 给人看：原样输出
p "p 是 inspect，带引号"      # 给机器看：调用 inspect，能看出类型
p 123, nil, [1, "a"]          # p 可接多个参数，逐个 inspect
```

```text
---- 2.1 输出三件套：puts / print / p ----
puts 自带换行
print 不换行
"p 是 inspect，带引号"
123
nil
[1, "a"]
```

分工记法与 julia 教程一脉相承：**puts/print 给人看（走 `to_s`），p 给机器看（走 `inspect`）**。三者差异汇总：

| 方法 | 换行 | 走哪个方法 | 数组 `[1, "a"]` | 用途 |
|---|---|---|---|---|
| `puts` | 追加 `\n` | `to_s` | 逐元素各打一行 | 面向人的正常输出 |
| `print` | 不换 | `to_s` | 原样一串 | 精确控制格式 |
| `p` | 追加 `\n` | `inspect` | 带引号整体打印 | 调试、看类型 |

调试时优先 `p`——它能看出 `"1"` 是字符串而 `1` 是整数，`puts` 看不出。另外 `p` 可以接多个参数逐个打印，`puts` 传数组会逐元素各打一行，别混用。REPL 里回显也走 `inspect`，所以 REPL 看到的 `"abc"` 带引号是正常现象。`pp`（pretty print）是 `p` 的多行美化版，属于标准库（17 章巡礼），大结构调试时换它。

## 2.2 字符串插值与转义

```ruby
name = "Ruby"
version = RUBY_VERSION
puts "你好，#{name} #{version}！"          # #{expr} 求值任意表达式
puts "求值：#{1 + 2 * 3}"                  # 7
puts "转义：\t制表符\n换行 \\ 引号\" 和 \#{不插值}"
```

```text
---- 2.2 字符串插值与转义 ----
你好，Ruby 4.0.7！
求值：7
转义：	制表符
换行 \ 引号" 和 #{不插值}
```

（注意：上面 text 块为忠实摘录，`转义：` 后是原输出中的制表符。）插值 `#{...}` 里可以放任意表达式，先求值再转成字符串；`#{}` 用 `#` 转义可以关掉插值。双引号串常用转义汇总：

| 写法 | 含义 | 写法 | 含义 |
|---|---|---|---|
| `\n` | 换行 | `\t` | 制表符 |
| `\\` | 反斜杠本身 | `\"` | 双引号本身 |
| `\#{` | 字面的 `#{`（关插值） | `\s` | 空白符 |

**单引号串只认 `\'` 和 `\\` 两种转义**，其他反斜杠原样保留——`'a\nb'.bytesize == 4`，`\n` 就是两个字面字符，这个特性常用在正则和 Windows 路径上（12 章）。选型口诀：要插值或有转义用双引号，字面文本、怕误转义用单引号。

## 2.3 命令行参数：ARGV

```ruby
puts "ARGV = #{ARGV.inspect}（ruby main.rb 后面跟的参数，全是 String）"
who = ARGV[0] || "无参数运行"    # 取参的常规写法：带默认值
```

```text
---- 2.3 命令行参数：ARGV ----
ARGV = []（ruby main.rb 后面跟的参数，全是 String）
第一个参数：无参数运行
```

三条规则：`ARGV` 是全局常量数组，**装的全是 String**（要数字自己 `to_i`，且记得 3.6 节——`to_i` 解析不动返回 0）；`ruby main.rb a b` 里 `main.rb` 之后的才是参数；**脚本里 `ARGV` 恒为数组（可能为空）**——不存在 julia `@main(args)` 那样的入口函数，也不存在 C 的 `argc`，长度问 `ARGV.size`。取参惯用法是 `ARGV[0] || "默认值"`，用 `||` 而不是 `||=`——前者兼容空数组取出的 `nil`。

（上面 text 块里 `ARGV = []` 是无参数运行的结果；带参数跑 `ruby main.rb 阿黄` 会得到 `ARGV = ["阿黄"]`——inspect 的方括号说明它就是普通 Array，别当特殊类型。）

标准库的 `optparse`（17 章）是命令行参数的正经解法：短选项/长选项/类型转换/帮助文本一次配齐。`ARGV` 裸取只适合两个以内参数的小脚本——超过这个规模还手写下标解析，就是在给自己埋雷。

## 2.4 heredoc：多行字符串

```ruby
text = <<~TEXT                # ~ 去公共缩进（写代码时不破坏缩进）
    第一行
    第二行 #{name}
  TEXT
sq = <<-'RAW'                 # ' 单引号 heredoc：不插值
  #{name} 原样输出
RAW
```

```text
---- 2.4 heredoc：多行字符串 ----
第一行
第二行 Ruby
```

heredoc 标识符前的修饰符决定行为：

| 形式 | 行为 | 适用 |
|---|---|---|
| `<<~TEXT` | 去公共缩进（内容按最浅行对齐裁掉） | 现代默认写法，代码不用左对齐 |
| `<<TEXT` | 保留全部缩进（连代码缩进一起吃进内容） | 需要精确空白时，慎用 |
| `<<-'RAW'` | 单引号版：不插值、缩进原样 | 把模板原文交给别人处理 |
| `<<-TEXT` | 结束符可缩进，内容缩进保留 | 旧代码兼容，新代码用 `~` |

heredoc 支持插值（除非单引号形式），比多个 `"...\n"` 相加干净得多；结束标记独占一行。示例用断言确认了 `<<~TEXT` 的结果恰是 `"第一行\n第二行 Ruby\n"`、单引号 heredoc 里 `#{name}` 原样保留——两条各是一个坑，值得自己改代码验证一遍。另外 heredoc 可以直接当方法实参（`puts <<~TEXT ... TEXT`），只是同一行上再写别的实参可读性极差，别这么用。

## 2.5 __END__ 与 DATA

```ruby
lines = DATA.readlines.map(&:strip)
# __END__ 之后的行：
# 甲,10
# 乙,20
```

```text
---- 2.5 __END__ 与 DATA ----
DATA 共 2 行：甲,10 | 乙,20
```

源文件里一行 `__END__` 之后的内容编译器不看，运行时却能通过 `DATA` 当文件对象读——**单文件自带测试数据的轻量做法**，写小工具脚本很顺手：一行 CSV 样例、几条 fixture、配置默认值，不必为两行数据单开一个文件。`DATA` 就是普通 IO 对象，`readlines`/`each_line`/`gets` 全都可用。

三个坑：`__END__` 必须顶格独占一行（前面有空格就成了普通代码行）；之后的内容全按行读、换行原样保留（注意 `strip`）；一个文件只能有一个 `__END__`。另外它是「源文件即数据」的魔法，`require` 别人的文件时拿到的是**那个文件**的 DATA——别跨文件取。

## 2.6 退出码与 warn

```ruby
require "stringio"
captured = StringIO.new
old_stderr = $stderr
$stderr = captured
warn "这是一条 warn（正常会打到 stderr）"
$stderr = old_stderr
puts "warn 实际输出到 stderr，捕获到：#{captured.string.strip.inspect}"
ok $PROGRAM_NAME.end_with?("main.rb")   # $0 的全名
```

```text
---- 2.6 退出码与 warn ----
warn 实际输出到 stderr，捕获到："这是一条 warn（正常会打到 stderr）"
脚本正常跑完，隐式退出码 0；显式退出用 exit / exit!(状态码)
```

`warn` 永远走 stderr——这正是全书示例把它用 StringIO 圈起来的原因：**验证脚本的判定之一就是「stderr 完全为空」**，任何告警（warn、弃用提示、实验特性告警）都会直接判负。`warn` 与 `puts` 的另一个差别：全局变量 `$stderr` 一改，`warn` 的去向跟着变（示例正是靠这个捕获的），而 `$VERBOSE` 控制的是告警级别，两者是不同的开关。

退出码规则：跑完最后一行隐式退出 0；三种显式退出方式有差别：

| 写法 | 退出码 | 收尾块（`END`/`at_exit`） |
|---|---|---|
| 跑完最后一行 | 0 | 正常执行 |
| `exit(1)` | 1 | 正常执行 |
| `exit!(1)` | 1 | **跳过** |
| 未捕获异常 | 1 | 执行后把回溯打到 stderr |

未捕获异常的回溯第一行是「文件:行号: 异常类: 消息」（走 stderr），这也是六条判定里「诊断字样」要拦的对象。

## 2.7 一切皆表达式

```ruby
x = if 3 > 2 then "大" else "小" end       # if 是表达式，有值
y = case 5 when Integer then "整数" end    # case 也是
z = [1, 2, 3].map { |n| n * 10 }
```

```text
---- 2.7 一切皆表达式 ----
if/case/块都有值：大 / 整数 / [10, 20, 30]
```

`if`/`case`/`while`/块在 Ruby 里都是**表达式**，有值，能直接赋给变量——这是与 C/Java（语句）最气质性的差别之一。`then` 关键字让单行形式合法；三元 `?:` 是 if/else 的紧凑版。这条原则贯穿全书：04 章的 `break 100` 从循环里带值、`case/when` 整体当值用，都源于此。记住「块也有值」：`map`/`each` 这类迭代器的块体最后一行就是每轮的产出，11 章的 Enumerable 全家桶全靠这条吃字面饭。

写代码的直接收益：不用「先声明临时变量 → 各分支赋值 → 再用」的 C 三段式，把分支直接写进表达式里，控制流与数据流合二为一。副作用是方法体内**随手一行的 `puts` 也是有值的**（返回 `nil`）——5.9 坑位清单里「隐式返回被调试输出顶掉」的坑就是它惹的。单行 `case/when`（如上面的 `y`）在这里合法，但同形似的 `case/in` 不合法——4.6 节有专讲。

一句话总览本章骨架：输出三件套看 `to_s`/`inspect` 之分；字符串看双引号、单引号、heredoc 三轨；数据入口是 `ARGV` 与 `DATA` 两个常量；诊断出口是 stderr。这些名字会在后面每一章的示例里反复出现，先在这里混个脸熟。

## 2.8 坑位清单

1. **裸改字符串字面量在 4.0 发弃用告警**：文件没写 `frozen_string_literal: true` 时，`s = "abc"; s << "x"` 不报错，但 stderr 打出 `warning: literal string will be frozen in the future...`（chilled strings，实测于 4.0.7 `-e` 探针）；写了魔法注释则字面量直接冻结，`upcase!` 抛 `FrozenError`。要改就 `+"abc"` 或 `.dup`（2.1/5.3）。
2. **`puts` 与 `p` 走不同方法**：`puts nil` 打空行、`puts [1,2]` 打两行，`p nil` 打 `nil`——调试永远用 `p`，别用 `puts` 看容器（2.1）。
3. **单引号串只认 `\'` 和 `\\`**：`'a\nb'` 是 4 字节，`\n` 不换行；双引号才做转义与插值（2.2）。
4. **`ARGV` 全是 String 且可能为空**：`ARGV[0]` 对空数组返回 `nil` 而不是报错，算术前必须 `to_i`（2.3）。
5. **heredoc 的 `<<TEXT`（无 `~`）保留缩进**：内容会带上代码缩进的空格；现代写法一律 `<<~`（2.4）。
6. **`__END__` 后的数据不是注释也不是字符串**：它是 `DATA` 文件对象的流，换行原样保留，通常要 `strip`；且 `__END__` 必须顶格（2.5）。
7. **`warn` 走 stderr 而不是 stdout**：管道 `| grep` 会漏掉它；本书验证层把「stderr 非空」直接判负，所以示例里演示 warn 都得先捕获（2.6）。
8. **`exit!` 不跑 `END` 块与收尾**：注册了 `at_exit` 的脚本用 `exit!` 退出会静默跳过它们（2.6）。
9. **顶层 `block_given?` 恒为假**：它只在方法体里有意义，顶层调用永远返回 `false`（实测于 4.0.7 探针）——判断「有没有传块」必须写在方法里（5.4 细讲）。
10. **`$PROGRAM_NAME`（`$0`）是脚本全名**：相对路径启动就是相对路径，比对文件名用 `end_with?` 而不是 `==`（2.6）。
11. **结束标记不可删**：每个示例末行 `puts("==== NN 结束 ====")` 是验证脚本的完整性凭据，改示例时删了它，六条判定直接挂「缺结束标记」（2.7）。
12. **插值与全局常量也能混用出坑**：`#{RUBY_VERSION}` 这类常量插值没问题，但 `#{ARGV}` 直接打整个数组的 inspect——要格式化单个参数请取下标，别把容器整体塞进插值（2.2/2.3）。
