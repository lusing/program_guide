# 13 · OOP II：继承与多态

## 1. 继承与 inherited

```pascal
TShape = class(TObject)          // 括号里是父类（省略 = TObject）
TCircle = class(TShape)          // 单继承，一个父类
```

- `inherited` 三态：`inherited;`（同名祖先方法）、`inherited Create(x);`（指定祖先方法）、
  不写（完全重写行为）。
- 子类构造器**惯例第一行** `inherited Create(...)`——先建好祖先的骨架再添自己的字段。

## 2. virtual / override：多态的地基

```pascal
TShape = class abstract                  // abstract 类：不能 new
protected
  function Area: Double; virtual; abstract;   // 抽象方法：子类必须实现
  function Perimeter: Double; virtual;        // 虚方法：子类可选实现
public
  function Describe: string;                  // 模板方法：流程定死，细节留给虚方法
end;

TCircle = class(TShape)
protected
  function Area: Double; override;            // 改写必须标 override
  function Perimeter: Double; override;
end;

function TShape.Describe: string;
begin
  Result := Format('%s：面积 %.2f，周长 %.2f', [FName, Area, Perimeter]);
  //                                              ^^^^ 编译期是 TShape.Area，
  //                                                   运行期分派到 TCircle.Area —— 多态
end;
```

**静态方法按变量类型分派，虚方法按实例类型分派**——这是初学者最容易含糊的一点：

```pascal
var s: TShape;
s := TCircle.Create(1);
s.Area;                 // virtual+override → TCircle.Area ✓（实例说了算）
```

如果不写 `virtual`（静态方法），同样代码会调 TShape 的版本——**类库作者忘写 virtual、
子类忘写 override 是两大经典 bug**（override 拼错/漏写时编译器会报错兜底，但父类
非虚时编译器无话可说）。`reintroduce` 指令用于有意隐藏祖先虚方法（少见，知道即可）。

## 3. is / as：向下转型的安全带

```pascal
Assert(shapes[1] is TRect);               // 类型测试
Assert(not (shapes[1] is TCircle));
Assert((shapes[1] as TRect).Area = 12);   // 安全转型：失败抛 EInvalidCast
Assert(TRect(shapes[1]).Area = 12);       // 硬转型：失败是未定义行为
```

能 `is` 判别就不要 `as`；能 `as` 就不要硬转。**频繁 is/as 是设计味道**——该加虚方法/接口了。
（GUI 端 `Sender as TButton` 是合理例外——事件统一签名所致，16 章。）

## 4. 类引用（class of）：类型当值传

```pascal
type
  TShapeClass = class of TShape;          // 类引用类型：装"类本身"

s := TShapeFactory.Make(TRect, '工厂矩形');    // 把 TRect 当参数传
// 工厂内部：Result := AClass.Create(AName);   // 用类引用造对象

class var Count: Integer;                 // 类级变量：全体实例共享
class function Make(...): TShape;         // 类方法：无需实例即可调（TShapeFactory.Make）
```

**细节（实测）**：类引用调构造器按**基类签名**解析——`AClass.Create(AName)` 走的是
`TShape.Create`（TRect 自己的 `Create(W, H)` 没被用上，W/H 是 0）。要让子类构造器
被类引用正确调用，需声明 `constructor Create(...); virtual;`——**LCL 的
TComponent.Create 正是 virtual**，窗体流机制（按类名建组件）全部建立在这上面。

## 5. 接口：引用计数的契约

```pascal
type
  ISpeaker = interface
    ['{1B6E9A50-...}']                    // GUID：建议写（COM 操作/流需要）
    function Speak: string;
  end;

  TDog = class(TInterfacedObject, ISpeaker)   // TInterfacedObject：自带引用计数
  public
    function Speak: string;
    destructor Destroy; override;
  end;

var
  spk: ISpeaker;
begin
  spk := TDog.Create;                     // 接口引用接管生命周期
  WriteLn(spk.Speak);
  spk := nil;                             // 引用归零 → Destroy 自动执行（实测可见析构输出）
end;
```

接口世界与类世界的三大差别：

1. **自动生命周期**：接口引用计数归零自动析构——不用（也不能）手动 Free。
2. **只能调接口声明的方法**——契约之外不可见（比 private 更强的封装）。
3. **对象引用与接口引用别混用**：`dog := TDog.Create; spk := dog;` 之后两边都管释放
   就是双重 Free。对象一交给接口，就忘掉对象指针。

`implements` 委托——把接口实现转给内部对象（组合优于继承的落地姿势）：

```pascal
TRobot = class(TInterfacedObject, ISpeaker)
private
  FDog: TDog;
public
  property Inner: TDog read FDog implements ISpeaker;   // ISpeaker 的调用直达 FDog
end;
// spk := TRobot.Create; spk.Speak → 实际是 FDog.Speak（实测）
```

LCL 里接口出场率不高（VCL 血统是类风格），但 fcl-stl/回调/插件场景常见——值得掌握。

## 6. 多态容器的标准配菜

```pascal
shapes: array[0..2] of TShape;             // 基类数组（示例）
// 或 TObjectList<TShape>（14 章，OwnsObjects 自动释放）
for i := 0 to 2 do
  shapes[i].Describe;                      // 一个调用点，三种行为
```

GUI 端同款：`TWinControl.Controls[]` 装着满窗体异质控件，绘制/布局/事件分发全靠多态。

## 8. 坑位清单（实测）

1. **忘写 virtual 的方法没有多态**——按变量类型分派；忘写 override 编译器报错（这个能兜住）。
2. 类引用构造按**基类签名**解析——除非构造器声明 virtual（LCL TComponent 的设计根源）。
3. 抽象类不能实例化；但抽象**方法**只在含 abstract 时强制子类实现，纯 virtual 有默认体。
4. 对象引用+接口引用混用 = 双重释放风险；一交给接口就丢掉对象指针。
5. `class var` 写在类声明的 var 区（objfpc 不支持在单元级补声明）。
6. 硬转 `TRect(x)` 失败是未定义行为——`as` 失败抛 EInvalidCast（可捕、可防）。
