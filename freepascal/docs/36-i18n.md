# 36 · 国际化：resourcestring 与 .po

一套代码发多语言版本，LCL 的答案是 **resourcestring + gettext 体系**：
代码里写原文，.po 文件给译文，运行时一加载全变——不用 if 语言 then 改
Caption 的大厂写法。

## 1. resourcestring：可替换的字符串常量

```pascal
resourcestring
  rsHello = 'Hello, LCL!';
  rsCount = '%d item(s) done.';
...
Msg.Caption := rsHello;                 // 读的不是字面量——是资源表的一项
```

与 const 的本质差别：const 在编译期焊死；resourcestring 编译进**资源串
表**（每单元一张），**运行时整表可换**——访问 rsHello 时查的是当前表。
带参数的串照常 `Format(rsCount, [3])`（译文必须保住 `%d` 位置，见 §4 的
fuzzy/badformat 保护）。

## 2. .po 文件：gettext 的翻译对照表

```text
#: 36_i18n.lpr:rsHello          ← 标识行（来源文件:常量名）
msgid "Hello, LCL!"             ← 原文（对号用的 key）
msgstr "你好，LCL！"             ← 译文

#: 36_i18n.lpr:rsCount
msgid "%d item(s) done."
msgstr "完成 %d 项。"
```

**坑（实测，本章头号）**：LazUtils 的 TPOFile **只认带 `#: 标识符` 行的
条目**——没有 `#:` 行的 msgid/msgstr 会被当作 header 处理（解析"成功"、
CharSet 都认出来，但条目数 0、翻译静默不生效）。IDE 生成的 .po 从不缺这
行；手写/程序生成必踩。文件头（`msgid ""` + Content-Type 那段）可以整个
省略——UTF-8 是默认。

## 3. 运行时切换：三 API 一坑

```pascal
uses Translations;

TranslateResourceStrings('lang_zh.po');            // 全表应用（推荐）
TranslateUnitResourceStrings('单元名', 'xx.po');    // 只换一个单元
TranslateResourceStrings(BaseName, Lang, Fallback); // 按语言代码找文件
```

**坑（实测）**：program **主文件**里声明的 resourcestring，用
TranslateUnitResourceStrings 按单元名匹配**不生效**（试遍 program 名/文件
名/大小写变体：返回 True 但一个字没换——文件打开成功就算 True，单元表
匹配静默 miss）。两条正路：

- 业务串放**独立单元**（resourcestring 单独一个 .pas，翻译按单元名工作）；
- 或干脆用全表版 `TranslateResourceStrings(文件)`——本章工程用它。

切换即生效：翻译加载后所有读 rsXxx 的地方自动变（已显示的 Caption 不会
自己刷——要么重启要么重读，36 工程的按钮就是重新读 rsHello）。

## 4. 回退与保护

实测语义（selftest 断言）：

- **未翻译串回退原文**——.po 里没有的 msgid 原样保留（半成品翻译也能上）；
- **缺失文件**：API 返回 False 不炸（好过猜）；
- **空 .po**（只有 # 没条目）：加载成功、全部回原文——"切回源语言"的
  合法手段；
- **fuzzy / badformat 标记**的条目被跳过（Translate 内部检查）——格式参数
  不匹配（译文丢了 %d）的翻译宁可不生效，防 Format 运行时炸。

## 5. LCL 界面文案与 IDE 工作流

控件库自己的文案（对话框按钮"All/OK/Cancel"）走同一体系：

```pascal
uses DefaultTranslator;   // 启动时按系统语言自动找 <appdir>/<lang>/LC_MESSAGES
                          // 或 lclstrconsts.zh_CN.po 之类——uses 即生效
```

IDE 全自动工作流（了解即可，命令行教程不依赖）：工程选项里勾 i18n →
IDE 扫全部 resourcestring 生成 .pot（模板）→ 翻译工具（Poedit）填译文存
.po → 放进 `languages/` 目录随程序分发。

工程实践三条：

- 原文用英文（msgid 稳定；中文原文+英文译文也行但社区 po 生态是英源）；
- **msgid 是协议**——改一个字母全部译文失配（回退原文）；
- 数字/日期本地化是另一件事（FormatSettings/DefaultFormatSettings——
  11 章 TDateTime 的显示格式跟它走）。

## 6. 示例与验证

```powershell
pwsh -File build.ps1 -Example 36_i18n
```

selftest 覆盖：资源串初值、程序生成 .po（带 #: 行）→ 加载 → 译文生效
（含带参 `%d`）、未翻译回退、缺失文件 False、空 po 回原文的完整轮回。
（临时 po 文件测试后删除。）

## 7. 坑位清单（实测）

1. **.po 条目必须带 `#: 标识符` 行**——没有就静默当 header 丢（Count=0
   不报错，翻译"成功"但不生效）。
2. **program 主文件的 resourcestring** 按单元名翻译失灵——独立单元或
   全表 API。
3. TranslateUnitResourceStrings 返回 True 只说明文件读了——单元表没匹配
   上也 True（成功≠生效）。
4. msgid 是协议：改原文=全部译文失配（回退原文）。
5. 已显示的 Caption 不随翻译自动刷新——重读一遍。
6. 译文必须保住格式占位符（%d/%s）——fuzzy/badformat 条目会被主动跳过。
