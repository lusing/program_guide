# 12 · OOP I：类与封装

## 1. class：引用语义的聚合体

```pascal
type
  TCounter = class
  private
    FCount: Integer;                    // 字段惯例 F 前缀（Field）
  public
    constructor Create(Initial: Integer = 0);
    procedure Inc_;
    function Value: Integer;
  end;

var
  cnt: TCounter;
begin
  cnt := TCounter.Create(10);           // 类变量是引用（指针），对象在堆上
  try
    cnt.Inc_;
  finally
    cnt.Free;                           // 必须手动释放（类没有引用计数）
  end;
```

与 record（08 章）的本质分界：

| | record | class |
|---|---|---|
| 变量语义 | 值（赋值即拷贝） | 引用（赋值即共享） |
| 存储 | 栈/内嵌 | 堆，必须 Create |
| 释放 | 自动 | 手动 Free |
| 继承/虚方法/接口 | 无（3.2.2） | 有 |
| 运算符重载 | 有 | 无 |

选型：**数学值对象用 record，有生命周期的实体用 class**。

## 2. property：字段的外交通道

```pascal
TBankAccount = class
private
  FBalance: Currency;
  procedure SetBalance(NewValue: Currency);
public
  property Owner: string read FOwner;                            // 只读，直通字段
  property Balance: Currency read FBalance write SetBalance;     // 读写，写走校验
end;

acct.Balance := 100;          // 表面像字段赋值，实际调 SetBalance(100)
x := acct.Balance;            // 读直通字段
```

- `read F字段` / `read GetXxx`、`write F字段` / `write SetXxx`——读写可分别直通或走方法。
- **写通道 = 校验点**：`SetBalance` 里拒绝负值，非法状态进不了对象（示例实测拦截）。
- 只写 `property X: T read FX;` 就是只读属性；两个通道都省略是"哑属性"（少见）。
- property 是 Delphi/VCL/LCL 的核心风格——IDE 对象查看器列出的就是 published 属性
  （15 章起满屏都是）。

## 3. 构造与析构

```pascal
constructor TCounter.Create(Initial: Integer);
begin
  inherited Create;              // 先造祖先——惯例第一行
  FCount := Initial;
end;

destructor TObject.Destroy;      // 析构（示例里接口章用到 override）
```

- 构造器名任意（惯例 `Create`），支持默认参数、重载。
- `inherited Create` 调祖先构造器；`inherited` 后不带名 = 调同名的祖先方法。
- 析构器 `Destroy` 是**虚方法**——经基类指针 Free 时子类析构也会被调到（13 章多态侧证）。

## 4. 访问级别：private 的"单元例外"

```pascal
TSecret = class
private
  FHidden: string;         // 外部单元不可见——但同单元内直接访问【编译通过】！
end;
```

| 级别 | 可见范围 |
|---|---|
| `private` | 本单元（跨单元不可见） |
| `protected` | 本单元 + 子类（任何单元） |
| `public` | 所有人 |
| `published` | public + 运行期类型信息（IDE 属性面板/流式存取需要，15 章） |

**大坑（实测）**：private 是**单元级**而非类级——同一个 .pas 文件里的任何代码都能摸到
private 字段。所以"测试代码和实现放同单元"会悄悄绕过封装；要真私有，把类单独放一个单元。
严格模式可用 `strict private`（类级私有，Delphi 兼容）。

## 5. TObject：万物之祖

```pascal
obj := TCounter.Create(1);         // 祖先指针引用后代
Assert(obj is TCounter);
Assert(obj.ClassName = 'TCounter');
obj.Free;
```

每个类都从 TObject 继承：`ClassName`/`ClassType`/`ToString`/`Free`/`Equals`/` GetHashCode`。
`uses System` 不用写——TObject 编译器内建。

## 6. Free / FreeAndNil：释放纪律

```pascal
cnt.Free;            // nil 上调用安全（Free 内置 if Self <> nil 检查）
FreeAndNil(cnt);     // Free + 置 nil：悬垂引用变 nil 解引用，好查
```

- `Free` 有 nil 保护——**对已置 nil 的指针再 Free 不炸**（实测）。
- 但对**悬垂**（已释放未置 nil）指针 Free 是未定义行为。纪律：**统一 FreeAndNil**，
  悬垂立刻变 nil 段错误，暴露在现场而不是千里之外。
- 释放顺序：先释放自己持有的字段，再 `inherited Destroy`（13 章析构示例实战）。

## 7. 所有权心智模型

三个释放责任的分配机制：

| 机制 | 谁负责 Free | 例 |
|---|---|---|
| 谁创建谁释放 | 你 | `obj := TX.Create; ... obj.Free;` |
| 容器持有（OwnsObjects） | 容器 | `TObjectList<T>.Create` Free 时连元素一起放（14 章） |
| 接口引用计数 | RTL | `ISpeaker := TX.Create` 归零自动析构（13 章） |

LCL 的 `TComponent.Create(Owner)` 是第四种：**Owner 组件**销毁时自动释放旗下组件——
这是 GUI 端"窗体上的控件不用手动 Free"的全部秘密（15 章）。

## 9. 坑位清单（实测）

1. **同单元无隐私**：private 是单元级不是类级——测试与实现同文件会绕过封装；
   真私有用独立单元或 `strict private`。
2. 类变量是引用——`a := b` 后改 b 的字段 a 跟着变（06 章动态数组同款语义）。
3. 忘 Free = 泄漏（-gh 可查，08 章）；重复 Free = 未定义行为——统一 FreeAndNil。
4. property 只读（只有 read）后试图赋值是**编译错误**，不是运行时错误——封装在编译期兜底。
5. 构造器里别调虚方法（子类字段还没初始化，13 章构造顺序）。
