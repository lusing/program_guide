# 02 · Hello World 与 Ada 程序的基本面貌

> 示例：[`examples/ch02_hello.adb`](../examples/ch02_hello.adb)
> 运行：`./run-all.sh 02`

本章从最小可运行的 Ada 程序出发，把一个程序"从上到下"的每个组成部分
讲清楚：`with` 与 `use` 是干什么的、过程（procedure）的骨架长什么样、
怎么编译运行。之后进入语言的地基——**词法单元**：标识符怎么写、保留字
有哪些、数值直接量的进制与下划线写法、字符与字符串直接量。这些内容
对应张丽芬《Ada 程序设计导论》§1.1–1.2（一个简单的 Ada 程序、Ada 基本
说明），但示例与工具链全部更新到 GNAT 16 / Ada 2012 之后的世界。

---

## 02.1 第一个程序

完整的示例程序开头是这样的：

```ada
with Ada.Text_IO;         use Ada.Text_IO;
with Ada.Integer_Text_IO; use Ada.Integer_Text_IO;
with Ada.Float_Text_IO;   use Ada.Float_Text_IO;

procedure Ch02_Hello is
begin
   Put_Line ("Hello, Ada!");
   Put_Line ("GNAT (GCC) 16 · Windows / Linux 通用 · 默认标准 Ada 2012");
```

逐行拆开看：

- **`with Ada.Text_IO;`** —— 上下文子句。Ada 标准库按"包"组织，
  `Ada.Text_IO` 提供正文输入输出（`Put_Line`、`Get` 等）。`with` 相当于
  声明"本编译单元要用到这个包"。与 C 的 `#include` 不同：`with` 只是
  **让名字可见**，不做文本替换。
- **`use Ada.Text_IO;`** —— 使用子句。有了 `with` 之后你必须写全名
  `Ada.Text_IO.Put_Line (...)`；加上 `use` 才能省掉前缀直接写
  `Put_Line (...)`。两者是独立的两步：`with` 管可见性，`use` 管直接
  可见性。工程代码里经常只用 `with` 不用 `use`，靠带前缀的全名避免
  名字冲突——本教程的示例为了短小，多数场合直接 `use`。
- **`procedure Ch02_Hello is ... begin ... end Ch02_Hello;`** ——
  一个过程的完整骨架。`is` 之前是名字与（可选的）参数；`is` 与
  `begin` 之间是**说明部分**（声明变量、类型、嵌套子程序）；
  `begin` 与 `end` 之间是**语句序列**；`end` 后必须重复单元名。
  Ada 的所有可执行单元（过程、函数、包体、任务体）都是这个形状。

老教材 §1.1 用一个"模拟计算器"程序展示同样的结构——它在 1992 年写的是
`with TEXT_IO; use TEXT_IO;`，如今这个包的标准名是 `Ada.Text_IO`
（Ada 95 起标准库统一挂到 `Ada` 名下），机器全大写的风格也演化成了
大小写混合。结构本身二十多年没变：**with/use → procedure is 说明部分
begin 语句 end**。

## 02.2 编译与运行

Ada 是编译型语言。GNAT 工具链（GCC 的 Ada 前端）的入口是
`gnatmake`：给它主程序文件名，它会自动编译依赖的单元、链接出可执行
文件。

```powershell
# Windows（本仓库约定：MSYS2 UCRT64 的 gnatmake）
gnatmake -o ch02_hello.exe examples/ch02_hello.adb
.\ch02_hello.exe
```

```bash
# Linux / macOS
gnatmake -o ch02_hello examples/ch02_hello.adb
./ch02_hello
```

有一条 GNAT 的硬规则要立刻记住：**文件名 = 单元名（小写）**。
`procedure Ch02_Hello` 所在的文件必须叫 `ch02_hello.adb`。
`.adb` 是包体/子程序体（body），`.ads` 是包规范（specification），
下一章之后会大量遇到。本仓库的全量构建脚本是 `run-all.sh`
（Linux/macOS）与 `build.ps1`（Windows），单跑本章：

```bash
./run-all.sh 02
```

GNAT 16 默认按 **Ada 2012** 标准编译；想用新特性（如 Ada 2022 的
delta 聚合）需显式加 `-gnat2022`。本教程示例全部保持默认标准可编译。

## 02.3 标识符与保留字

标识符由**字母打头**，后跟字母、数字，中间可嵌下横线：

```ada
Count   Count2   Max_Value   NO_LINES   X_Offset     -- 合法
2nd     _Temp    Max__Value  Value_      X-Y         -- 全部非法
```

规则细节：下横线不能连续出现两个（`Max__Value` 非法）、不能出现在
结尾（`Value_` 非法）、标识符必须写在同一行。下横线纯粹为可读性服务，
`Max_Value` 和 `MaxValue` 是两个不同的名字。

**Ada 标识符不区分大小写**——这是从 Pascal 一脉相承的设计。示例里
专门演示了这一点：

```ada
declare
   Count : Integer := 1;      -- 说明时写作 Count
begin
   COUNT := Count + 1;        -- 引用时写作 COUNT，同一个变量
   put_line ("  Count 与 COUNT 是同一个标识符，值 = "
             & Integer'Image (count));
end;
```

`Count`、`COUNT`、`count` 三种写法指同一个对象。约定俗成的风格是
"下划线蛇形命名 + 首字母大写"，但语言层面完全不敏感。字符串与字符
直接量**除外**——`"Ada"` 和 `"ada"` 是两个不同的字符串。

保留字方面，Ada 83 定义了 **63 个**保留字（老教材表 1-1 全列了），
到 Ada 2012 演化为 73 个（新增 `abstract`、`aliased`、`delegate` 等，
也淘汰了个别实现性关键字）。保留字不能当标识符用。完整的现行清单
不必背——编译器会把误用直接报成语法错误；写代码时留心 `type`、
`is`、`begin`、`end`、`in`、`out`、`range`、`access` 这些高频词即可。
另外注意 `Text_IO` 里的横线：Ada 83 年代曾把这类名字也视作保留字
风格的全大写（`TEXT_IO`），现代写法统一是 `Ada.Text_IO`。

## 02.4 数值直接量：进制、下划线与指数

Ada 的数值直接量比多数语言讲究，因为它面向嵌入式——十进制、二进制、
八进制、十六进制都是**一级语法**，不需要任何库函数。示例第一段：

```ada
declare
   Million   : constant := 1_000_000;    -- 下划线只为可读，编译器忽略
   Hex_FF    : constant := 16#FF#;       -- 基于 16：255
   Bin_Ten   : constant := 2#1010#;      -- 基于 2：10
   Oct_Thou  : constant := 8#1750#;      -- 基于 8：1000
   Exp_Form  : constant := 1E6;          -- 指数形式：1000000
   Pi        : constant := 3.14159_26;   -- 实数：小数点两边都必须有数字
begin
   ...
end;
```

规则清单：

1. **下横线分组**：`1_000_000` 与 `1000000` 完全等价，编译器忽略
   下横线。这是给十万、十六进制位组这样的人工分组用的。
2. **基于直接量**：`基数#数字#`。基数可以是 2 到 16 的任何整数，
   `16#FF#` = 255、`2#1010#` = 10、`8#1750#` = 1000。超过 9 的"数字"
   用字母（`16#CF#` = 207）。嵌入式开发里这是读写硬件寄存器的日常。
3. **指数**：`1E6` 即 10⁶；实数同样可以带指数（`1.0E-3` = 0.001）。
4. **实数直接量的小数点两边都必须有数字**：`3.` 和 `.5` 都非法，
   必须写 `3.0`、`0.5`。整数和实数的区分就靠小数点——`2` 是整数
   直接量，`2.0` 是实数直接量，两者类型不同，这个区分后面类型一章
   会反复用到。
5. 基于直接量同样可以带指数：`8#7.5#E1` 表示八进制的 7.5×10⁸？不——
   指数以"基数直接量的十进制倍数"理解，写作 `8#7.5#E1` = (7.5₈)×10¹
   = 7.625×10 = 76.25。这个冷僻形式见过即可。

示例的运行输出验证了这些值：

```text
  1_000_000   = 1000000
  16#FF#      = 255
  2#1010#     = 10
  8#1750#     = 1000
  1E6         = 1000000
  3.14159_26  =  3.14159
```

注意这些常量说明用的是 `constant :=` 而没有写类型——这是**命名数字**
（named number）：类型不固定，是"通用整数/通用实数"，用在哪里就按
哪里的类型理解（第 03 章细讲）。

## 02.5 字符与字符串直接量

- **字符直接量**：单引号包一个字符，`'A'`、`'+'`、`' '`。
- **字符串直接量**：双引号包零个或多个字符，`"Ada"`、`""`（空串）。
- 字符串**拼接**用 `&`：

```ada
declare
   Ch      : constant Character := 'A';       -- 字符直接量：单引号
   Greeting : constant String := "Hello";     -- 字符串直接量：双引号
   Long_Text : constant String :=
     "字符串太长时可用 & " & "跨行拼接成一体。";
begin
   Put_Line ("  Character'Pos ('A') = " & Integer'Image (Character'Pos (Ch)));
   Put_Line ("  Greeting & "", Ada"" = " & Greeting & ", Ada");
end;
```

两个细节：

1. `Character'Pos ('A')` 是**属性**表达式——`'Pos` 把字符转成位置号
   （ASCII 值 65）。属性是 Ada 的"反射"机制，`类型'属性(参数)` 的
   写法贯穿全书。
2. 字符串里要放双引号本身，要**双写**：`"Greeting & "", Ada"""` 中
   的 `""` 表示一个双引号字符。Ada 没有反斜杠转义——`\"` 是非法
   字符（第 05 章示例第一次编译就栽在这上面，是 C 程序员的经典
   肌肉记忆错误）。

`&` 拼接产生新字符串，原串不变。字符串本质是**字符的一维数组**，
所以 `'First`、`'Last`、`'Length`、切片 `S (1 .. 5)` 全部适用——
这个视角第 06 章展开。

老教材还讲了 Ada 83 的一个历史包袱：基本字符集只有 95 个 ASCII
图形字符，`$` 这类字符要用 `ASCII.DOLLAR` 拼写。现代 Ada
（Ada 95 之后）的字符集已扩到完整 Latin-1/ISO 10646，源文件也可
用 UTF-8 编码写中文注释与字符串——本教程的示例输出里满是中文，
就是这个能力。

## 02.6 注释

Ada 只有**行注释**：从 `--` 到行尾。没有块注释。注释可以出现在任何
允许空白的位置。示例文件的分隔条就是惯用法：

```ada
   -- ---------------------------
   -- 1. 数值直接量：十进制、下划线、基数、指数
   -- ---------------------------
```

要"临时注释掉"大段代码时，Ada 的做法是用预处理（GNAT 的 `gnatprep`）
或直接依赖编辑器的行注释快捷键——语言本身不提供 `/* */`。
一个相关的语言点：**pragma**（杂注/编用）是"给编译器的指令"，
形如 `pragma Page;`——它不是注释，下一节专讲。

## 02.7 杂注：与编译器对话

**杂注（pragma，编用）** 是 Ada 词法里一个特别的存在：它长得像
语句（以分号结尾），却不是给运行时执行的，而是**传给编译器的
命令**。何诚 §2.7 的定义今天逐字成立：以保留字 `pragma` 开头，
后跟杂注名（一个标识符），再跟可选的参数表：

```ada
pragma 杂注名 [ (参数 {, 参数}) ];
```

示例演示最轻的一种——告诉编译器"这个变量故意不用"：

```ada
declare
   Unused : Integer := 1;            -- 没人读它：编译器会警告
   pragma Unreferenced (Unused);    -- 杂注：宣告"此变量故意不用"
begin
   ...
end;
```

删掉那行杂注再编译，GNAT 就会警告 `variable "Unused" is
assigned but never read`。**注释给人看，杂注给编译器看**——
这是两者全部的区别，也是杂注存在的意义。

三个层级的事实：

1. **语言定义的杂注**是标准的一部分：`pragma Suppress`（[11 章]
   (11-exceptions.md) 关检查）、`pragma Priority`（[17 章]
   (17-select-family.md) 任务优先级）、`pragma Import/Export`
   （[21 章](21-low-level.md) 跨语言调用）、`pragma Pack`（紧缩
   表示）等。
2. **实现可以自造杂注**：GNAT 就加了不少（`Unreferenced` 本身
   是 GNAT 扩展后标准化的例子）。跨编译器移植时，实现自定义的
   杂注要么条件编译，要么查 GNAT 的 `-gnatA` 兼容性清单。
3. **杂注能出现的位置决定它的效力范围**：写在说明部分作用于
   该块（02 章示例的 `Unreferenced` 只管一个变量）；写在编译
   单元的规范前作用于整个单元（`pragma Suppress` 的单元级用法）。

**现代视角：方面（aspect）是杂注的接班人。** Ada 2005 起，凡是
"给实体附加属性"的杂注都改用方面语法写在实体声明上：
`pragma Priority (7)` 与 `with Priority => 7` 完全等价（[17 章]
(17-select-family.md) 并排演示过两种写法）。方面能表达的东西
更多（前置条件、不变式——[24 章](24-contracts.md)），新代码
优先用方面；但杂注不会消失——**开关型**指令（Suppress、
Unreferenced、Warnings）天然是杂注的形状。

## 02.9 小结

| 概念 | 要点 |
|------|------|
| 程序骨架 | `procedure 名 is 说明部分 begin 语句 end 名;` |
| `with` / `use` | `with` 让包名可见，`use` 让包内实体直接可见 |
| 文件名 | 单元名小写，`.adb` 体 / `.ads` 规范 |
| 标识符 | 字母开头、可含下横线、**不区分大小写** |
| 数值直接量 | 下横线分组、`基数#数字#`、`E` 指数、实数小数点两侧必须有数字 |
| 字符/字符串 | `'c'` 与 `"s"`；`&` 拼接；`""` 双写表示引号 |
| 注释 | `--` 到行尾，无块注释 |
| 杂注 | `pragma 名 (参数);` 给编译器的命令；开关型用杂注、属性型用方面 |

到这里，你已经能把任何 Ada 程序的"外壳"读懂了。下一章进入语言
真正的灵魂——**类型系统**：为什么说 Ada 是强类型语言，范围检查
如何从编译期一直护到运行期。
