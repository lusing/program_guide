# 38 自动机与 LTL 模型检查

> 对书：Ben-Ari 3e §16.4-16.8（程序=自动机/活性检查/NBA/同步积）
> 通道：C/L/P——baut+findLoop+旗舰 loop_accept_inf 双定理通道；
> 同一算法的 SWI-Prolog 可运行版

35 章的 CTL 标记算法与 37 章的显式实验回答「这个 Kripke 结构满足
这个时态公式吗」，但都绕开了反例的问题：**性质不成立时，反例路径
在哪里？** 本章走完 Ben-Ari 的最后一块拼图：把程序当自动机、把
性质的否定编译成 Büchi 监视自动机，「存在反例」变成「乘积自动机
非空」，而**非空 witness = 一条到达接受态又绕回自身的环**——
环读出无穷反例路径。反例不再靠运气枚举，而是搜索的直接目标。

## 从 DFS 栈到 Büchi（§16.4-16.7 的推理链）

Ben-Ari 的展开顺序值得照抄。首先（§16.4）：并发程序本来就能看成
自动机——进程的原子步合成全局迁移，状态图就是 37 章画过的那些。
然后（§16.5-16.6）：安全性检查可以 on-the-fly——DFS 每生成一个
新状态就评估性质，撞见违例即停；**DFS 栈上的状态恰好构成一条
路径**，若新生成的状态已在栈上更深处，就找到了一个「有限表示的
无穷计算」（前缀+环）。

活性性质卡在最后一步：违反 □◇p 的计算是「p 一去不返」的无穷
行为——怎么在有限搜索里认出它？**Büchi 接受条件**（定义 16.17）
就是答案：自动机读无穷输入，接受 ⟺ **无穷多次**处于接受态。
无穷条件没法直接验证，但有一个有限判据——若某个接受状态在 DFS
栈上**再次出现**，环就保证了「无穷多次」。环 = 无穷的有限证书：
这是 39 章 lasso 之后同一条暗线的第二发（34 章有限推理、22 章
有限一致集、39 章 fulfilling lasso、本章反例环、42 章 μ 不动点
的有限收敛轮数——五个成员的家族合影）。

LTL 公式到 NBA 的翻译（§16.7）：Ben-Ari 对 Peterson 活性公式
`□(waitp → ◇csp)` 手工构造 NBA（例 16.18），再构造其否定（例
16.19：状态 s1 上 csp 一旦为真就没有迁移——NFA 的「走不动即
拒绝」语义保留）。手工构造的要点是**非确定性猜测**：◇□¬p 的
自动机必须在某个时刻「猜」从现在起 ¬p 永远成立——猜错了（后来
出现 p）就死在那里。

## 同步积与空性（§16.8）

程序自动机每走一步，NBA 同步走一步（读到的输入 = 当前程序状态
的标记）——**同步自动机**。检查算法：

```
while true:
  生成程序自动机的新状态
  生成 NBA 的对应状态
  若（DFS 发现）乘积上出现「接受态 × 栈上重现」→ 反例环，报告
```

**空性 ⟺ 性质成立**：乘积上找不到接受环 ⟺ 没有任何计算无穷
多次满足 ¬φ ⟺ 一切计算满足 φ。这与 35 章 CTL 的「标记最大
不动点」殊途同归——那边对状态集合做不动点，这边对路径存在性
做环搜索；42 章将把两者统一进 μ 演算的同一套不动点语言。

## 机器件（`ex41_buechi.v` / `.lean` / `.pl`）

```coq
Record baut : Type := MkB {
  bS : list nat;          (* 状态表 *)
  bsucc : nat -> nat;     (* 后继 *)
  bI : list nat;          (* 初态 *)
  bF : list nat           (* 接受态 *) }.

Fixpoint runFrom (bs : nat -> nat) (s : nat) (t : nat) : nat :=
  match t with 0 => s | S t' => runFrom bs (bs s) t' end.

Definition findLoop (A : baut) : bool :=
  existsb (fun s => inL (bF A) s && loopsAt A s) (reachSet A).
```

三个教学版选择，各有明确理由：

**环用后继函数表示**（`bsucc`）而非路径列表——周期性引理
（`runFrom_add`：轨道的可加性）变成对步数的平凡归纳，39 章
lasso 里绕不开的列表旋转花活整个消失。设计层面的教训：
**表示的选择决定证明的难度**。

**确定性 Büchi + 相位枚举**：◇ 的非确定性猜测分解为「对每个
可达起点分别试」（`bI := [0;1;2]`——初态表就是猜测的集合）。
监视积的构造直白：活状态遇 p 落死点 9，死点自环且不入接受表
——「p 永不再真」的承诺一旦破产，自动机就永久沉入拒绝。

**接受 = 一切活状态**：对 FG¬p 型性质，任何活状态上的无穷停留
都算接受——接受表退化为「非死点」，检查浓缩为「是否存在避开
死点的可达环」。

旗舰定理把证书的「无穷内容」做实：

```coq
Theorem loop_accept_inf : forall (A : baut) s T,
  In s (bF A) -> runFrom (bsucc A) s T = s -> 0 < T ->
  forall n, exists t, n <= t /\ In (runFrom (bsucc A) s t) (bF A).
```

读法：接受态 s 经 T 步回到自身 ⟹ 从 s 出发的轨道**任意远处**
都有接受态（取 t 为 T 的足够大倍数，周期引理保证落回 s）。
「环 ⟹ 无穷多次接受」在构造性证明里就是乘法与轨道可加性的
两行组合——有限数据兑现无穷承诺的机制被完全摊开。

## 现场（三通道一致：Coq `reflexivity`/Lean `rfl`/SWI 运行输出）

```coq
Example good_no_loop : findLoop PK = false.     (* K：性质成立 *)
Example bad_loop_found : findLoop PK' = true.   (* K'：有反例 *)
Example counterex_orbit :
  map (runFrom (bsucc PK') 1) (upto 7) = [1; 2; 1; 2; 1; 2; 1].
Corollary counterex_inf : forall n,
  exists t, n <= t /\ In (runFrom (bsucc PK') 1 t) (bF PK').
```

**K**（0→1→2→0，p 只在 0）：任何起点出发迟早经过 0，监视积
在 0 落死点——没有避开死点的环，□◇p **成立**。注意三个起点
都要试：从 1、2 出发的轨道看似「暂时无 p」，三步内必回 0。

**K'**（0→1→2→1）：从 1 出发的轨道永远绕 {1,2}——活环找到，
反例轨道 `[1;2;1;2;…]` 读出：进程在 0 请求过一次 p 之后，系统
进入 p 永不出现的行为。`counterex_inf` 直接调用旗舰：这条轨道
任意远处都是接受态——它是货真价实的无穷反例，不是有限近似。

Prolog 版（`ex41_buechi.pl`）跑出同样三行结论——同一份数据
（`msucc1/msucc2`）、同一个三步检查（`reachAll`/`accepting`/
`loopsAt`），用 `call/3` 元调用切换模型。算法的可运行性在
这里最直观：改一个 `succK2` 子句，反例就换成另一个形状。

## 与全书的接线

- **39 章**：lasso 的环 = 本章的接受环——「找环」从表列构造
  的副产品升级为显式的搜索目标；两章的「兑现/接受」检查都是
  「无穷性质的有限判据」。
- **35/37/42 章**：CTL 标记（不动点）、显式实验、符号 BDD 三条
  MC 路线之外的第四条——自动机乘积；42 章的 μ 演算是四条路线
  的公共语义层。
- **36 章**：LTL 语义（路径）在本章变成自动机的无穷输入——
  「公式 ⟺ 自动机」的翻译是 LTL 理论的工程出口（SPIN 一系）。
- **34 章**：环 = 有限证书家族第二发；「无穷多次」这个不可直接
  验证的条件的有限判据，与 22 章「无穷一致集的有限矛盾」同构。
- **09 章**：DFS/可达性搜索的又一现场——SAT 的 DPLL 与 MC 的
  环检测共享「有限图上穷尽搜索」的骨架。

## 边界登记（诚实清单）

- **非确定性 NBA 的完整翻译**（39 章表列状态图 → NBA 的通用
  构造，即 tableau→Büchi 路线）未机器化：本章的监视自动机是
  按 Ben-Ari 16.18/16.19 的手工程序为 FG¬p 定制的；通用翻译
  登记为边界（需 39 章状态图的自动机化，工程量与本章主线
  不成比例）。
- **空性 ⟹ 无反例**方向（findLoop = false ⟹ 一切运行不接受）
  未证明：需要对「任意无穷运行」的量化与运行语义形式化——
  35 章 CTL 方向的完备性也是同样级别的工程，均登记。
- **Tarjan/nested-DFS**：教学版对每个可达接受态试 8 步回环——
  正确、不优；工业版的线性时间找环算法（Ben-Ari 引 Even）是
  复杂度边界，注记。

## 工程对照：SPIN 与 NuSMV 的两条路线

自动机路线的工业化身是 **SPIN**（Holzmann）：LTL 否定→Büchi
（tableau 法）、与 Promela 模型做同步积、nested-DFS 找接受环
——本章机器件的每一步都是它的教学缩影；SPIN 的功劳在于把
偏序归约（partial order reduction）做进搜索——交错等价的
轨迹只探一条，状态爆炸被系统性压缩。**NuSMV** 一系走的是
42 章的符号路线：BDD 表示迁移关系、不动点求 EF/EG——环检测
变成「EF(φ ∧ EX …)」的 μ 编译。两条路线在同一语义上分工：
显式状态+自动机适合大状态稀疏转移的系统（协议），符号 BDD
适合规则性强、变量多的电路。近年 SMT-based bounded model
checking（BMC）加进来第三条：把「k 步内无反例」编码成 SAT
公式——09 章 DPLL 的直系后代在 MC 领地收租。三路线的统一
语义层仍是 42 章的 μ 演算——表达力天梯的塔尖同时是工程方法
的公共分母。
## 本章小结

- 推理链：DFS 栈上重现 ⟹ 有限表示的无穷计算 ⟹ Büchi 的
  「无穷多次」有了有限判据 ⟹ 环 = 反例的有限证书。
- 同步积：程序一步、监视器一步；空性 ⟺ 性质成立；反例 =
  接受环上的轨道读出。
- 表示决定难度：环用后继函数，周期引理变成平凡归纳。
- ◇ 的猜测 = 初态枚举；监视积「遇 p 落死点」一行构造。
- 三通道同一现场：K 无环判真、K' 有环出反例、旗舰把环的
  无穷内容做实。

## 坑位速记（本章实测）

- **Prolog**：
  - **`:- encoding(utf8).` 必须是物理首行**——前面连注释都不行
    （指令只影响其后的读取；注释里的 UTF-8 已先按 GBK 报
    Illegal multibyte）。01 章的「首行」要按字面理解，本章
    实测后 01 与 38 一起修正；
  - 原子名不能带撇号（`succK'` 撞引号语法）——改 `succK2`；
  - `call(P, S, D)` 元调用切模型比复制两套谓词干净。
- **Lean**：
  - **`Nat.add` 在第二参数上递归**：`0 + b` 不是定义归约
    （要 `Nat.zero_add`）、`a + 1` 才是——与 Coq 相反；
    `Nat.mul_succ_l`/`mul_succ_r` 在 core 里叫 `Nat.succ_mul`/
    `Nat.mul_succ`——名字对不上就 `rw` 报 unknown constant；
  - `simp [Nat.add_succ]` 会触发「Possibly looping simp theorem」
    警告（lean 通道零警告线会挂）——改显式 `rw [Nat.succ_add]`
    + `show` 换形；
  - 结构字段定义 `def PK : Baut where …` + `PK.bsucc` 投影直用。
- **Coq/Rocq**：
  - `induction a` 泛化 s 再证可加性（`intros bs a; induction a;
    intros s b`）——先 intro s 会把递归调用的基底锁死；
  - `Nat.mul_succ_r` 匹配 `?n * S ?m`——目标是 `S k * T`（T 是
    变量）时要用 `Nat.mul_succ_l`（`S n * m` 形）；写错只报
    「no subterm matching」不提示用哪个；
  - ◇ 相位不枚举（bI 只放初始态）会把「后来才违约」的路径
    全部漏判——K' 现场第一版全 false 的教训。
