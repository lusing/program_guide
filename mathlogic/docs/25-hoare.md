# 25 霍尔逻辑程序验证：while 规则与不变式

> 对书：H&R ch4（§4.2 框架 / §4.3 部分正确演算）/ Ben-Ari 3e ch15
> 通道：C/A/L/I/H4（五通道 while 规则对照+countdown 组装）

前三卷是演算的「逻辑侧」收官：命题/谓词/时序之后，把「推理」
对象换成**程序**。霍尔三元组 `{P} c {Q}` 把「程序满足规格」
变成可推演的数学——这是 1969 年 Tony Hoare 的公理化学纲领，
也是 30 章（完全正确性）与 34 章（模型检查对照）的起点。

## 验证框架（H&R §4.2.1-4.2.2）

核心语言（H&R 定义 4.2 的教学版）：

```text
cmd := skip | x := f(state) | c1; c2 | while b do c
exec : cmd -> state -> state -> Prop   （大步语义）
hoare P c Q := ∀s1 s2. P s1 → exec c s1 s2 → Q s2
```

状态 = 变元赋值（`nat → nat`），程序变量是状态的**自变量**——
这带来了五通道共有的别名坑：`x = y` 时两个「变量」是同一格，
`x := x-1; y := y+1` 的修补项不再抵消，正确性必须以 `x ≠ y`
为前提（Coq/Lean/Isabelle/Agda 四版同款条件）。条件分支与
数组是语言的扩展（H&R 的 Min_Sum 用数组；教学版以算术函数
模拟）。

## 部分 vs 完全正确性（H&R §4.2.3，30 章的钩子）

三元组的核心歧义：**程序不终止时说什么**？两种立场
（H&R 定义 4.5/4.6）：

- **部分正确性**（partial correctness，`par ⊨ {P} c {Q}`）：
  P 成立时，**如果** c 终止则 Q 成立。「while true {x=0;}」
  这样永不停机的程序满足**一切**规格——部分正确性对发散
  程序免费放行；
- **完全正确性**（total correctness，`tot ⊨ {P} c {Q}`）：
  P 成立时 c **保证终止**且 Q 成立。发散程序不满足任何
  （非空）规格。

为什么要先学「较弱」的部分版？**方法论**：完全正确性的证明
通常拆成「部分正确性 + 终止性」两半——前者抓程序「算得对」
的结构（不变式），后者抓「算得完」的度量（变体 variant）。
两者所需的洞见不同、可分开攻克。25 章交付前者；30 章补上
变体方法把 countdown 与 Min_Sum 升级为完全正确。语义层的
对应：本章 `hoare` 定义里的 `exec c s1 s2` 是「若有终态」的
关系形态——发散自动免谈；30 章的定义要内建「存在终态」。

## 程序变量 vs 逻辑变量（H&R §4.2.4）

一个低调但要命的区分：**程序变量**出现在程序里（状态格），
**逻辑变量**只在断言里（冻结的值）。对照例（H&R 的 mid 例
形态）：要证「x 的终值等于**初值**的两倍」，写 `∃m. x = 2*m`
不够——需要逻辑变量把初值钉住：

```text
{x₀ = x}  …程序…  {x = 2*x₀}
```

x₀ 不在程序里出现（不会被赋值改掉）——它是「快照」。没有它，
前件与后件各自读的是**不同时刻**的 x，规格直接失义。机器版
里逻辑变量表现为定理的**外层全称参数**（如 countdown 的 C），
天然冻结；纸面证明里要自己当心。18 章 fv 侧条件的「谁被量词
管住」是同一户口问题的逻辑层亲戚。

## 证明演算：四条骨干+后承（H&R §4.3.1）

```
hoare_skip    {P} skip {P}
hoare_ass     {Q[x↦e]} x := e {Q}        （赋值公理：后推前件）
hoare_seq     {P} c1 {Q} / {Q} c2 {R} ⇒ {P} c1;c2 {R}
hoare_while   {P∧b} c {P} ⇒ {P} while b c {P∧¬b}
```

**赋值公理的「后推前件」**是霍尔演算最反直觉的一步：要证
赋值后的 Q，把 Q 里的 x **换成** e 当作前件——因为赋值执行后
x 就**是** e。`{x+1 = 2} x := x+1 {x = 2}` ✓。方向如果搞反
（从前件推后件），不可判定（最弱前件的计算方向性——自动
验证器「符号执行」的根据恰是逆向）。

**while 规则**是演算的灵魂：找一个不变式 P，循环体在守卫
成立时保持 P，则循环出口处 P ∧ ¬守卫。不变式是「每一轮都
真的中间事实」——它必须弱到循环体能维持、又强到蕴含后件。
**找不变式是霍尔验证中唯一真正需要智力的步骤**（其余是
机械装配），30 章 Min_Sum 案例将完整展示「从后件倒推不变式」
的手艺。相对 while 语言的部分正确性，这套演算完备
（Cook 定理，1978）——相对性在于断言语言要能表达.interpretation
的可表达关系（22 章 PA 可表示性的程序侧亲戚）。

## while 规则的三系统反应（本章最大看点）

归纳 `exec (cwhile b c) s1 s2` 时构造子头索引的处理：

| 系统 | 配方 |
|------|------|
| Coq | `remember (cwhile b c) as w` + revert → 方程进动机，`inversion Hw` 灭不可能支 |
| Lean | induction 直接拒绝构造子头索引（"consider cases"）；命令泛化为 w + 方程 `w = cwhile b c` 进 `key` 引理（remember 的直译），`Cmd.noConfusion` 灭支 |
| Isabelle | `induct "cwhile b c" s1 s2 arbitrary: HP rule: exec.induct` 显式实例化 + HP 依赖索引必须 arbitrary；不可能支自动小反转 |
| Agda | 结构递归两行——构造子头索引是常态，匹配即小反转，三套仪式全免 |
| HOL4 | 命令泛化 + 方程携带（Coq 同款）且必须 `exec_strongind`（弱 ind 的案例只有 exec' 没有 exec 副推导） |

五家的差异全在「归纳原则对非变量索引的宽容度」——Agda 的
依赖模式匹配原生支持，Coq/Isabelle 要 remember/实例化的仪式，
Lean 干脆拒绝。这是「同一数学、五种归纳原语」的最完整标本。

## 竖式证明表（H&R §4.3.2）

H&R 用「证明布景」（proof tableaux，中译本译「证明布景」）
的竖式记法组织推理：从**底部**（要证的三元组）向上推导，
每行一个中间三元组，while 的不变式写在循环体上方。以
countdown 为例的竖式骨架（H&R 图 4.13 的风格）：

```text
  要证： {x+y = C ∧ x = N} countdown {x+y = C ∧ x = 0}
  ↑ while 规则（不变式 x+y = C）
  要证： {x+y = C ∧ x ≠ 0} (x := x-1; y := y+1) {x+y = C}
  ↑ 顺序规则（中间断言：(x-1)+(y+1) = C）
  要证： {x+y = C ∧ x ≠ 0} x := x-1 {(x-1)+(y+1) = C ∧ x-1 ≥ 0}
  ↑ 赋值公理（后推）——前件化简恰为 x+y=C ∧ x ≠ 0 ✓
```

竖式的纪律是「从目标倒推」——每一步问「这条规则的前提是
什么三元组」。与机器版（正向组装 hoare_seq/hoare_while）互为
镜像：人用倒推（goal-directed），机器装正推（term-directed）。
自动验证器把倒推做成算法即「最弱前件演算」wp（Dijkstra）——
28 章注记。

## countdown 组装的机器走查

机器版（`examples/25_hoare/ex25_hoare.v`）的组装链逐层拆开——
它是竖式表的「正向镜像」，值得对照读（Coq 版骨架）：

```coq
Theorem countdown_correct : forall x y C s1 s2,
  exec (countdown x y) s1 s2 -> s1 x + s1 y = C -> s2 x + s2 y = C.
```

第一步 `hoare_while`（不变式 `inv := fun s => s x + s y = C`）：
把目标交给规则，剩下循环体的义务
`{x+y=C ∧ x≠0} (x:=x-1; y:=y+1) {x+y=C}`。第二步 `hoare_seq`
（中间断言 `fun t => t x + t y + 1 = C`）：拆成两个赋值义务。
第三步两次 `hoare_ass`：赋值公理后推——

```text
义务一：{Q[x↦x-1]} x := x-1 {Q}，其中 Q = (t x + t y + 1 = C)
   前件化简：(x-1) + y + 1 = C  ←（需 x ≠ 0：截断减法桥）= x + y = C ✓
义务二：{Q'[y↦y+1]} y := y+1 {Q'}，其中 Q' = (y + 1 = …)
   前件照搬 ✓
```

第四步（语义包装）：`exec` 关系的不动点归纳（while 规则的
可靠性证明）——remember+revert 的仪式后五分支扫平。最后
算术：`upd_read/upd_other` 两个赋值语义引理 + `lia` 收截断
减法。**五步各司其职**：规则（3 条）管形状、语义引理（2 条）
管换算、算术自动化收尾——霍尔证明的「三明治结构」。

别名前提 `x ≠ y` 藏在 `upd_other`（`m ≠ x` 时 `upd s x v m =
s m`）：若 x=y，`x := x-1` 同时改掉了「y 格」，义务一的化简
崩塌。纸面证明默认变量两两不同，机器版把这份默认写成显式
前提——又一次「侧条件文化」。

## 现场演示：倒数程序

```
countdown(x,y) := while (x ≠ 0) do (x := x-1; y := y+1)
不变式 inv := s x + s y = C
```

组装：`hoare_seq`（中间不变式选 `t x + t y + 1 = C`——先减后加
的一轮修补）+ 两次 `hoare_ass` + `hoare_while`，得到
`inv s2 ∧ s2 x = 0`（部分正确性 + 出口守卫）。

截断减法坑（五通道同病）：`s x - 1 + 1 = s x` 需要 `s x > 0`，
由循环守卫 `s x ≠ 0` 提供——Coq 用 `lia`、Lean 用 `omega`、
Isabelle 取 `Suc k` 分解、Agda `suc k` 分解后 `∸ 1` 定义式归约、
HOL4 `Cases_on` + `fs`。

## 通道边界（如实登记）

- Coq / Lean / Isabelle / Agda：完整 `countdown_correct` 组装。
- HOL4：四条规则全量 + 单步不变式引理 `countdown_step`——
  exec 双重反演（seq→cass→upd 方程链）被 `IMP_RES_THEN` 的
  实例级联污染上下文，完整组装的代价与教学价值不成比例，
  单步引理承载同一核心算术（截断减法 + 别名前提）。

## Cook 完备性与后承规则

演算的第五条（严格说外挂）规则是**后承**（consequence）：

```text
P ⟹ P'   {P'} c {Q'}   Q' ⟹ Q
-------------------------------- {P} c {Q}
```

前件加强、后件 weaken——它把「纯逻辑蕴含」接进程序演算。
Cook 定理（1978）：**相对**断言语言的可表达性，这五条规则
对 while 语言的部分正确性**完备**——一切部分正确三元组可推。
「相对」的含义：断言语言必须能表达程序语义涉及的关系
（如算术）——断言语言太弱则不变式写不出来。这个相对性与
22 章（PA 可表示性）、23 章（完备性的界限）同族：**演算的
完备永远是相对于断言表达力的完备**。完全正确性方向，
适当的变体规则（30 章）同样完备（Apt 的老结果）。

## 本章小结

- 霍尔三元组把「程序满足规格」公理化；四条骨干规则+后承
  即完备（Cook，相对 while 的部分正确性）。
- 部分 vs 完全正确性：发散的两种待遇；方法论=先部分后终止
  ——30 章的变体方法补终止半边。
- 逻辑变量=断言里的快照（冻结初值）；别名坑是状态格模型
  的固有税。
- 赋值公理后推前件（wp 的种子）；while 不变式是唯一需要
  智力的步骤——「弱到能保持、强到够用」。
- 竖式表（人倒推）与机器组装（正推）互为镜像；组装的
  「三明治」：规则管形状、语义引理管换算、算术自动化收尾。
- Cook 相对完备：断言表达力是演算完备性的前提——22/23 章
  同族的「相对性」主题。
- 五通道的归纳原语差异在 while 规则的证明上暴露最彻底。

## 坑位速记（本章实测）

- **Coq**：`remember` + `revert HP` 后方程 Hw 自动进动机（五个
  构造子分支前三支 `inversion Hw` 灭）；不 remember 直接归纳
  会把 cmd 索引完全泛化（skip 分支变得不可证）；`inv` 等
  Definition 在假设里对 `lia` 不透明——先 `unfold inv in Hinv'`。
- **Lean**：`while` 是 do 记法保留字（构造子必须叫 `cwhile`）；
  `lemma` 在本工具链（4.25 裸 core）不是命令关键字——解析器
  当标识符吃进应用参数；守卫别写 `!(s x == 0)`——BEq+decide
  强制让同一式样在守卫位与前件位 elaboration 分叉（非 defeq），
  正解 `decide (s x ≠ 0)` + `of_decide_eq_true` 桥。
- **Isabelle**：裸 `proof (induct rule: exec.induct)` 装不上
  （构造子头索引要显式实例化 + `arbitrary: HP`）；`hoare_seq`
  的 auto 深度不够——blast 一发过。
- **Agda**：upd 用 with 定义会让 upd-self/upd-other 卡
  with-under-with——换 Bool-if + cong；等价判定用 `_≡ᵇ_` 而非
  `⌊ m ≟ x ⌋`（stdlib 的 `_≟_` 走 because/Reflects 构造，
  Dec 不做定义性归约，with 抽象留悬空约束）；组装构件（first/
  second）要提为顶层显式参数——where 块的隐式 State 元变量在
  hoare-seq 应用位悬空。
- **HOL4**：战术位引文是静态上下文 elaboration（目标绑定的
  P/s1 看不见——全类型注解救命，`!s1 s2.` 加注解反而解析失败，
  DECIDE 引理绑定名 b 与上下文冲突）；metis 三雷（大定理集/
  hoare 黑盒/函数等式上下文）全部参数调制爆炸且 hol run 模式
  静默中止——RES_TAC 确定性消解是正解；Hol_reln 的 strongind/
  cmd_distinct/cmd_11 要 fetch；exec 反演只能一层（级联污染）。
