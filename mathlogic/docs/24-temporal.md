# 24 时序逻辑与模型检查：CTL、标记算法与不动点

> 对书：H&R ch3（§3.4 CTL / §3.6.1 标记算法 / §3.7 不动点）/ Ben-Ari 3e ch13-14
> 通道：C/L（语义+展开等价 ex24_temporal；标记算法新单元 ex24_label）

命题/FOL 验证「一个断言」，程序验证要问「**整个运行过程**」——
「请求终将得到应答」「电梯不会中途折返」「不会死锁」。时态逻辑
（temporal logic）把时间装进公式；模型检查（model checking）
则把验证变成**可计算的语义求值**：系统=Kripke 结构（状态+迁移+
标记），性质=时序公式，验证=算出满足公式的状态集。本章讲
H&R 的 CTL——分支时间的标准逻辑——并机器化其核心算法。

## 从迁移系统到计算树

Kripke 结构 M = (S, →, L)：状态集、迁移关系、每状态的原子
标记。从初始状态「展开」迁移系统得到**计算树**——一个状态的
所有可能未来摊开成无限树。时态逻辑的分歧从「时间是什么形状」
开始：

- **线性时间**（LTL，27 章）：时间是一条线——公式沿单条路径
  读，系统的性质=「**所有**路径满足 φ」；
- **分支时间**（CTL，本章）：时间是一棵树——公式在**状态**
  （树的节点）上读，量词显式地走在路径与时刻之间。

CTL 的量词网格（H&R 定义 3.12）：**路径量词** A（所有路径）/
E（某条路径）× **时态算子** X（下一步）/F（终将）/G（总是）/
U（直到）——成对组合（AX、EX、AF、EF、AG、EG、AU、EU）才是
完整算子（CTL 的 C=branching 即「量词必须成对」）。机器件
（`examples/24_temporal/ex24_temporal.v`）装六个代表：

```coq
Inductive ctl : Type :=
| cAtom : nat -> ctl
| cNot  : ctl -> ctl
| cAnd  : ctl -> ctl -> ctl
| cEX   : ctl -> ctl                 (* 存在后继 *)
| cEG   : ctl -> ctl                 (* 存在全局路径 *)
| cEU   : ctl -> ctl -> ctl.         (* 存在直到 *)
```

其余八个按 adequate set 化归（见下）。语义 `ctlsat` 逐算子定义
——EG 用「任意长有限前缀都存在」的紧致性风格编码无限路径，
EU 的见证是有限路径前缀。

## LTL 与 CTL 的表达力裂谷（文档主线）

**LTL 沿单条路径量化**（系统的性质=所有路径满足 φ），
**CTL 在分支点显式选择**存在/全称。`AG(req → AF ack)` 是
CTL 的经典活性性质。两者不可互相定义（29 章给机器反例），
裂谷两侧各有专长：

| 表达目标 | LTL | CTL |
|---|---|---|
| 「一切请求终将应答」（每条路径各自兑现） | `G(req → F ack)` ✓ | `AG(req → AF ack)` ✓（等价） |
| 「存在一条路径一直 p」 | ✗（LTL 全称默认，说不了「存在路径」） | `EG p` ✓ |
| 「无穷多次 p 则无穷多次 q」（路径内关联） | `GF p → GF q` ✓ | ✗（A/E 塌缩丢关联，§3.4.3 明示） |

第三行是公平性的典型形态——LTL 独有；第二行是分支性的
典型——CTL 独有。CTL*（29 章）把两者一起收编。 CTL 的
量词成对律（每个时态算子必须带路径量词）正是它表达力
受限的语法根源——也是它**多项式可判定**的代价与回报。

## 标记算法的手算 trace

把 `E[p U q]` 在两状态模型（0→1，1→1 自环，p 只在 0 真，
q 只在 1 真）上走一遍迭代（ex24_label 的 m2 改标）：

| 轮 | Z（已标记集） | 动作 |
|---|---|---|
| 0 | {1} | Z₀ = B = q 的集合 |
| 1 | {1} ∪ ({0} ∩ EX{1}) = {0,1} | 0：p 真 ∧ 后继 1 已标记 ✓ 入集 |
| 2 | {0,1} | 无新——**不动点**，fuel=2=状态数 ✓ |

答案：E[p U q] 在两个状态都成立（0 经一步到 1 的 q；
1 自己就是 q）。EU 迭代的「涨」一眼可见——每轮吸收「p 真
且一步可进旧集」的状态，直到吸干。对偶地 EG p 的「压」：
Z₀={0,1}；一轮后 = p 集 ∩ EX(旧集) = {0}∩{后继∈{0,1}} =
{0}；两轮后 {0}∩EX{0}——0 的后继 1 ∉{0}——∅。EG p 失败
（没有无穷的 p 路径：0→1 之后 p 就假了）。**同一台机器，
两个方向**——μ 涨 ν 压，这就是 §3.7 的算法化。

## 规范实践模式（H&R §3.4.3）

写规格是门手艺，H&R 的模式表是入门工具箱（原子取
busy/requested/started 一类业务词）：

| 模式 | CTL 公式 | 读法 |
|---|---|---|
| 可能性 | `EF started` | 可能到达 started 的状态 |
| 响应性 | `AG(requested → AF acknowledged)` | 任何状态发出的请求终将应答 |
| 无穷使能 | `AG(AF enabled)` | 每条路径都无穷多次使能 |
| 终将死锁 | `AF(AG deadlock)` | 无论怎么走，终会进入永久死锁 |
| 可重启 | `AG(EF restart)` | 任何状态都能走到重启点 |

注意第一条与第四条的对比：EF「有机会」vs AF(AG)「逃不掉」；
响应式是最常用的活性（liveness）模板。**CTL 表达力的裂缝**也在
这张表里：**「若无穷多次使能则无穷多次运行」**（公平性诉求）
**不可表达**——`AG AF enabled → AG AF running` 只说「若一切
路径无穷使能则一切路径无穷运行」，比「**每条**无穷使能的路径
无穷运行」弱——把 A/E 塌进同一公式就会丢失路径间的关联。这是
29 章 CTL* 的直接动机。

## 重要等价与 adequate sets（H&R §3.4.4-3.4.5）

de Morgan 律在 CTL 里完整存在（A/E 与 F/G 互为对偶）：

```text
¬AF φ ≡ EG ¬φ      ¬EF φ ≡ AG ¬φ      ¬AX φ ≡ EX ¬φ
AF φ ≡ A[⊥ U φ]    EF φ ≡ E[⊥ U φ]
```

由此算子有大量冗余——**定理 3.17**：CTL 的时态算子集 adequate
⟺ 至少含 {AX,EX} 之一、{EG,AF,AU} 之一、与 EU。两个标准
选择：**{AF, EU, EX}**（H&R 算法用）与 **{EG, EU, EX}**
（式 3.7：AU φ ψ ≡ ¬(E[¬ψ U (¬φ∧¬ψ)] ∨ EG ¬ψ)）。与 08 章
命题 adequate set 同一个游戏——**规范形的自由度是算法设计
的选材空间**。

## 模型检查工作流：互斥协议的全程（H&R §3.3.1）

一个完整的验证故事。两个并发进程共享资源，各在自己的
**临界区**（critical section）访问——需要协议保证任一时刻至多
一方在临界区内。每个进程三态循环 n→t→c→n（非临界/申请/
临界），两进程交错迁移。验证目标四条：

- **安全性**：任何时刻至多一个进程在临界区——`AG ¬(c₁∧c₂)`；
- **活性**：申请者终将进入——`AG(t₁ → AF c₁)`；
- **非阻塞**：随时可以申请——`AG(t₁ → EX n₁)` 一类；
- **无严格轮转**：不必按固定次序进入（排除「轮流坐庄」的
  无用协议）。

**第一版协议**（H&R 图 3.7 的八状态迁移系统）：模型只有
s₀=n₁n₂ 到 s₇ 的八个状态。检查安全性 `AG ¬(c₁∧c₂)`——
逐状态标记 ¬(c₁∧c₂)：没有一个状态同时标 c₁c₂ ✓ 通过。
检查活性 `AG(t₁→AF c₁)`——在 s₅（n₁t₂）之类状态标记
AF c₁……**失败**：存在路径 t₁ 后永远轮不到 c₁（比如进程 2
反复进出临界区、进程 1 卡在 t₁）——**反例路径**就是模型
检查器输出的调试线索。

修复方向：加入「先到先得」的门变量或 Peterson 型协议，
重新建模、再查。这个「建模→检查→反例→改协议」的循环是
模型检查的日常——H&R 用它演示 NuSMV 的用法（`MODULE
PROC` 参数化进程+主模块组合；`SPEC` 声明待查公式）。教学版
把这套工作流压缩进 ex24_label 的两状态玩具模型（四条 Example
对应「标记→查成员」的核心动作），工业版的故事留给 28 章
（互斥的完整状态空间+活性失败现场+公平性修复）。

**工具侧注**：NuSMV/nuXmv 是 BDD 符号模型检查器（34 章
路线的开源实现）；SPIN 走显式状态+on-the-fly（28 章路线）。
两者的分野——符号 vs 显式——正是本教程 24/28 与 34 两章的
分野。

## 标记算法（H&R §3.6.1，新单元 ex24_label）

问题形态的选取是算法的第一步智慧：与其判「M, s₀ ⊨ φ?」（单
点判断），不如算「**满足 φ 的全部状态**」——输出状态集，查
s₀ ∈ 集合即可，反例路径也从集合差里长出来。

**标记算法**：先把 φ 翻译到 adequate set（AF/EU/EX/∧/¬），
然后**自底向上**按公式的语法结构处理——子公式的标记集算好
再组装父公式：

- 原子/¬/∧：布尔/集合运算直接做；
- **EX φ**：标记 φ 的集合的**前像**（有后继落在集合里的状态）；
- **EU φ ψ / AF φ**：不动点迭代。

机器件（`examples/24_temporal/ex24_label.v`，Lean 版同构）：

```coq
Definition satEX (m : fmodel) (S : list nat) : list nat :=
  filter (fun s => existsb (fun s' => memList S s') (ftrans m s))
         (fstates m).

Fixpoint iterEU (m : fmodel) (fuel : nat) (A B : list nat) : list nat :=
  match fuel with
  | 0 => B
  | S k => unionL (iterEU m k A B)
                (interL A (satEX m (iterEU m k A B)))
  end.
```

`iterEU` 是**最小不动点迭代**：Z₀ = B（ψ 已真的状态），每轮
Z_{k+1} = Z_k ∪ (A ∩ EX Z_k)（「φ 真且有后继已标记」）——
H&R 图 3.24 的 AF 版是同一台机器的对偶方向。正确性链（全部
零公理）：

```coq
Lemma satEX_In : ... In s (satEX m S) <-> In s (fstates m) /\ ...
Lemma iterEU_In_step : ... 迭代一步的成员刻画（mono 的引擎）
Theorem eufin_to_iter : ... 语义（有限深度 EU）⟹ 迭代成员
```

`eufin_to_iter` 对迭代深度归纳：语义的 ψ 直达支走
`iterEU_mono_le`（链式单调——从 Z₀=B 出发）、φ∧后继支走
`iterEU_In_step` 的右支+IH。**反向**（迭代成员 ⟹ 语义）与
**收敛性**（fuel=|S| 够用——迭代每轮至少新增一个状态、状态
有界）登记边界：前者需要「迭代步的语义保持」，后者需要
「成员数严格增长则终止」的计数论证——与 09 章 Horn 求解器
的 `close_fixpoint` 同构，教学版交付单方向+结构构件。

EG 的机器版是**最大不动点迭代**（`iterEG`：Z₀ = 全体状态，
每轮 Z_{k+1} = A ∩ EX Z_k——从 ⊤ 往下压）：

```coq
Fixpoint iterEG (m : fmodel) (fuel : nat) (A : list nat) : list nat :=
  match fuel with
  | 0 => fstates m
  | S k => interL A (satEX m (iterEG m k A))
  end.
```

子集性（`iterEG_sub`：结果 ⊆ A）是结构构件；**反单调与无限
路径语义的完整等价**（有限模型上 EG 见证 ⟺ 可达环的鸽笼压缩
——无限路径必重复状态、掐去中段得环）登记到 34 章 μ 演算单元
统一处理。现场演示（两状态模型 0→1→1 自环）：EX 的标记
{0,1}、EU 的空迭代与命中、EG 一轮压缩到 {1}——四个 Example
全部 `reflexivity` 收口。

复杂度注记：标记算法对 |φ|×|S|×|→| 线性——**CTL 模型检查
是多项式的**（与 FOL 不可判定对照鲜明：时态逻辑是把量词「摊平
在有限图上」的精巧设计）。这是 28 章（显式算法工程）与 34 章
（符号化）的起点。

## 不动点刻画（H&R §3.7）

为什么 EU 从 ∅ 涨、EG 从 ⊤ 压？H&R §3.7 的定理给出语义的
不动点身份：

```text
E[φ U ψ] = μZ.(ψ ∨ (φ ∧ EX Z))     最小不动点
EG φ     = νZ.(φ ∧ EX Z)            最大不动点
AF φ     = μZ.(φ ∨ AX Z)            最小（对偶方向）
AG φ     = νZ.(φ ∧ AX Z)            最大
```

直觉：**μ 抓「有穷证据」的性质**（U 的见证是有限长前缀——
迭代涨到不动点恰是全部有见证者）；**ν 抓「无穷保持」的性质**
（G 要求一路保持——从全体开始压掉违约者）。`exStep_mono`
（ex24_temporal 的旗舰三）是这套理论的最小构件（20 章
`TP_mono` 同款配方）——有限状态空间 n 状态 n 轮内收敛
（Tarski + 有限性）。完整收敛定理的机器化属模型检查教程
范围，边界如实登记。20 章的 Knaster-Tarski 户口在此二度
登场——34 章 μ 演算是三度。

## EG 的完整语义（文档）

Coq 版的 `cEG` 用**紧致性风格**：`∀n. ∃path. 长度 n+1 ∧ 每步
满足 a`——无限路径编码为任意有限前缀的存在（一阶逻辑的
紧致性在这类语义中的影子）。机器化主体用有限深度版
`egfin`（教学取舍与 EU 相同）。

## 坑位速记（本章实测）

- **Coq**（ex24_temporal）：`hd` 与 stdlib 的 `hd`
  （`list A0 -> A0` 需要 default）类型冲突——路径起点用
  `nth 0 path 0` 替代；EG 的路径迁移条件
  `In (nth (S i) path 0) (k (nth i path 0))`——i 与 S i 的
  索引配对。
- **Coq**（ex24_label 新增）：
  - `in_or_app` 在 Rocq 9.1 是**单向**（右到左）——iff 要
    `split; [apply in_app_or | apply in_or_app]` 双定理拼装；
  - `rewrite filter_In` 够不到 `In s (A ++ filter …)` 的
    内层——先拆 append 再拆 filter；成员刻画引理（带
    fstates 合取版）是迭代的「一步展开」模板；
  - 递归谓词（eufin）的 mono 引理**必须对深度归纳**——直接
    apply 自身会对变量做构造子匹配（「Not an inductive
    definition」）；
  - `apply IH; auto` 的 auto 会乱吃目标——IH 显式全参应用
    `exact (IH s' HA HB Htr … Hd)`。
- **Lean**（ex24_label 新增）：
  - 迭代定义**直接 filter A**（不 filter fstates）——省掉
    域条件的携带，成员刻画引理干净一档（与 Coq 版的设计
    分岔，教学上都成立）；
  - def+match 的语义谓词在假设上要 `simp only [eufin] at h`
    才展开（match 不自动 iota 到字面量）；
  - iff 引理的方向用 `.mp/.mpr` 显式分派（HB 是 x∈B ↔
    bp x，语义→成员走 **mpr**）；
  - simp 列表里多余的引理触发 unusedSimpArgs **警告**
    （通道门禁零警告）——逐个删；
  - `induction hle` 的 step 情形 IH 已吸收成员假设——
    `exact iterEU_mono s ih`（mono 要显式给 s）。
- **Lean**（ex24_temporal）：`where s0 : Nat` 的 where 语法
  不能给递归定义的模式变量补类型——参数重排；`path[0]?` 的
  Option 索引形式让 EU 的路径条件可写但演示例复杂——降级为
  EX 的传递演示（诚实边界）。
