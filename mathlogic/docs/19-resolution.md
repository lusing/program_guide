# 19 合一与归结：自动定理证明的引擎

> 对书：Ben-Ari 3e Ch10 / EFT XI / H&R 附录（归结速览）
> 通道：C/L/I（occurs check+归结可靠性，零公理）

07 章表列是「人盯式」搜索（一棵树一棵树看），09 章 DPLL 是
命题层的「代数式」搜索（子句集上消元）。本章把它们合流并升到
FOL：**归结**（resolution）——在子句集上用一条规则做全自动
推理。它的引擎两件套：**合一**（unification，找代换使两个项
相等——16 章 =e 的算法化）与**归结规则**（从互补文字对消去
出新子句——07 章 α/β 封堵思想的子句形态）。

## 工作方式：反证式的定理证明

归结系统证 φ 的姿势是**反证**：把 ¬φ 化成子句集，若能归结出
空子句 □（矛盾），则 φ 有效。流水线（18 章预告的兑现）：

```text
φ（待证）
 → ¬φ                       经典对偶（证 ¬φ 不可满足）
 → 前束 + Skolem 化          消 ∃ 抓见证（18 章）
 → CNF                       子句集 {C₁, …, Cₙ}（08 章）
 → 反复归结：                从 Cᵢ、Cⱼ 消互补文字得新子句
 → 出现 □ ⟹ 不可满足 ⟹ φ 有效
```

为什么反证？归结规则天然「生产子句」——它只能往「矛盾」
方向收敛（子句越消越短，空子句=矛盾曝光），而不是往「证明」
方向构造。**证明的构造型推理（ND）与反驳的消元型推理（归结）
是自动化的两副面孔**——前者人用顺手（16 章），后者机器擅长
（本章）。

## 合一：=e 的算法化

16 章 =e 说「相等者可互换」；反过来问：**两个项什么时候能
相等**？合一问题：给定 t₁、t₂，找代换 σ 使 σt₁ = σt₂。

```text
f(x, y)  与  f(g(a), y)     合一于 σ = {x ↦ g(a)}（y 保持）
f(x)     与  x              不可合一——x ↦ f(x) 自我嵌套！
h(x, x)  与  h(a, b)        不可合一——a≠b 冲突
```

算法是「分歧处逐个消解」：同位置不同构造子 → 立即失败；
一变量一函数 → 该变量绑定那个函数（前提：**occurs check**
——变量不得出现在函数项内部，否则 x↦f(x) 无穷递归无解）。
合一是一阶逻辑的「解方程」，19 章 Prolog（20 章）的执行
语义就是合一搜索。

## 合一算法的走查：分歧集消解

两个项的**分歧集**（disagreement set）= 最左不匹配位置上的
一对子项。Robinson 算法循环：

```text
合一(t₁, t₂)：
  若 t₁ = t₂             → 返回恒等代换
  否则取分歧对 (u, v)：
    u 是变量且 u ∉ v      → 绑定 u ↦ v，两边施代换，继续
    v 是变量且 v ∉ u      → 对称处理
    都是函数且头不同       → 失败（f(…) vs g(…)）
    u = v 结构相同         → 递归进参数
```

手算 `f(g(x), a) =? f(y, a)`：分歧对 (g(x), y)——y 是变量
且不出现在 g(x) 里 ✓ 绑定 y ↦ g(x)；再比较（已无分歧）——
σ = {y ↦ g(x)} 收工。手算 `f(x, x) =? f(a, x)`：分歧对
(x, a) 绑定 x ↦ a；施代换后比较 f(a,a) =? f(a,a)？——右边
的 x 也被换成 a ✓ 无分歧，σ = {x ↦ a}。最阴的例子
`f(x) =? x`：分歧对 (f(x), x)——x 是变量**但出现在对方内部**，
occurs check 拦截 → 失败。

复杂度注记：朴素算法最坏指数（代换连锁膨胀），Martelli-
Montanari 的「换方程组」变形多项式——工业实现（Prolog 的
Warren 抽象机）把合一做到近线性。教学版只证 occurs check
的健全性，算法复杂度不展开。

## 旗舰一：occurs check 的结构健全性

```
occurs_sound : x ∈ t ⟹ uapply s (ufun f t) ≠ uvar x
```

occurs check 拒绝 `x ↦ f(…x…)` 的语义锚：函数项施任何
代换后**结构上**仍是函数项（ufun ≠ uvar 的构造子差异）——
这正是合一失败判定的结构基础。**反例先行**：没有 occurs
check，合一算法会对 `f(x) =? x` 给出 σ = {x ↦ f(x)}——
检验时 σx = f(x) 又含 x，再代换再含……无穷倒退，代换永远
「不完备」。完整语义论证（该方程在 Herbrand 域确实无解）
深埋于 coinduction 理论——教学版在结构层钉死（ufun 施
代换不可能变回 uvar），文档登记边界。

## 归结规则：子句层面的互补消去

命题层的归结规则（Ben-Ari 定义 10.4 一带）：

```text
C₁ ∪ {p}      C₂ ∪ {¬p}
 ------------------------- Res
        C₁ ∪ C₂
```

两个子句各有 p 的正负文字，消去这对，合并剩余——**一次
推理同时用掉 ∨e 的分情况与 ∨i 的重组**。教学版定义
（`examples/19_resolution/`）：

```
resolve C1 C2 a = filter (非 a) C1 ++ filter (非 a) C2
```

统一消去原子 a 上的正负文字（比经典的「只消互补对」简化，
机制同构）。归结的**全称性**：一阶层每条规则实例要先与
现有文字**合一**（消去的是 σ 实例后的互补对）——这是
FOL 归结与命题归结的全部差别，也是合一作为引擎的含义。

## 旗舰三：归结可靠性（侧条件版）

```
resolution_sound : l1 ∈ C1 ∧ latom l1 ≠ a ∧ eval e l1 ⟹
                   lsat e (resolve C1 C2 a) = true
```

侧条件版的含义：**非消去原子的真文字在归结中保留**。读法：
若 C₁ 里有个文字 l₁ 为真、且它不是被消去的 a-文字，那么
归结式在新赋值下仍真——因为 filter 保走了它（旗舰二的
`filter_member`），而析取里一个真文字足够。完整版（无侧
条件：「两前提满足 ⟹ 归结式满足」）需要「至少一侧的非 a
文字真」的经典分情况讨论——Ben-Ari 定理 10.8 的构造性
半边在此机器化，另一半属于归结完备性理论（Herbrand 定理
路线，20 章+23 章），文档登记。

**可靠性的证明走查**（一次就够，三通道同构）：

```text
设 eval e l1 = true（l₁ 是见证文字）
filter_member：l1 ≠ a ⟹ l1 ∈ filter (非 a) C1
∴ l1 ∈ resolve C1 C2 a（表连接的左半）
lsat 的定义：子句真 = 存在真文字
∴ lsat e (resolve C1 C2 a) = true ∎
```

四行链：见证文字 → 过滤保留 → 并集成员 → 析取真。全部
零件（filter_In/existsb 的 witness 方向）都是表操作引理——
**归结的「推理」在机器里全是表运算**，「逻辑」发生在定义层。

## 旗舰二：filter 保成员

```
filter_member : l ∈ C ∧ latom l ≠ a ⟹ l ∈ filter (非 a) C
```

一行引理单独立旗舰，是因为它是可靠性链路的**唯一桥墩**——
且实测中 `filter_In` 的取向（In+条件的单参数构造）与
`existsb_exists` 的 proj 方向（witness 在 proj2）都是
易踩的 API 方向坑（坑位速记）。

## 一个完整归结反演

证 `p ∨ q, ¬p ⊢ q`（命题层最小例子）：子句集
{[p,q], [¬p]}。归结消 p：resolve [p,q] [¬p] p = [q]
（filter 掉两边的 p-文字）。一步出 [q]——若目标子句是
空（矛盾），继续消到 □。三通道的 `value`/`compute` 现场
都是这一步的机器重演。FOL 版的同一例子加合一：{[P(x),Q(x)],
[¬P(g(a))]}——消 P 前先合一 x ↦ g(a)，归结出 [Q(g(a))]。

## 本章小结

- 归结=反证式全自动推理：¬φ → 子句集 → 消互补 → □。
  构造型（ND）与消元型（归结）是自动化的两副面孔。
- 合一是 =e 的算法化：分歧消解+occurs check；x↦f(x) 的
  无穷倒退是 check 的存在理由（结构层钉死+语义层登记）。
- 可靠性四行链：见证→过滤保留→并集成员→析取真——「推理」
  在机器里是表运算。
- 完备性属 Herbrand 路线（20/23 章）；侧条件版是构造性
  半边的诚实切片。

## 坑位速记（本章实测）

- **Coq/Rocq**：`subst (latom l)` 对函数应用位置非法（latom
  不是变量）——改用 `apply Nat.eqb_eq in E; contradiction`；
  `existsb_exists` 的 **proj2** 是「witness → existsb = true」
  （proj1 是反向——方向搞反报 unifies exists with existsb
  = true）；`filter_In` 是 stdlib 的单参数构造（In + 条件）
  ——不用手写归纳。
- **Lean**：`mlit (b a : Nat)` 的 b 应为 **Bool**（写成 Nat
  导致 lpos 类型冲突）；单行 `fun l => match l with …` 的
  箭头要提行（方程式编译器不吃单行 match 混合 lambda）；
  `List.mem_filter.mpr ⟨hin, ?_⟩` + `cases hbeq : (latom l
  == a)` 建立条件。
- **Isabelle**：`definition` 里引用的函数必须在**定义之前**
  声明（latom 后置报 Extra variables on rhs）。
