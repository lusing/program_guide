# 42 程序合成与形式语义

> 对书：Ben-Ari 3e §15.4（程序合成）/ §15.5（形式语义）/ §15.6\*（相对完备性）
> 通道：C/L——小步语义 step/steps + 倒数/乘法两程序的读出式正确性

25/30 章把霍尔规则**正向**用：给定程序与不变式，验证三元组。本章
把它**反向**用：给定规约，程序与不变式一起**长出来**——这是
Ben-Ari §15.4 的程序合成；然后给 while 配上小步操作语义，让
「霍尔规则的可靠性」从纸面走向机器。

## 合成走查：除法程序六步（§15.4）

规约：`{x≥0 ∧ y>0} div {x = y*q + r ∧ 0≤r<y}`。合成的推理
是逆向的——从后置条件倒推每条语句该做什么：

1. 后置要求 `x = y*q + r`——q、r 是新变量，说明程序要维护
   两个累加器；`0≤r<y` 说明 r 是**余数**——减法循环的残留；
2. 循环体先猜骨架：`r := r - y; q := q + 1`——检查不变式
   是否被保持：`I = (x = y*q + r ∧ r ≥ y)`（循环入口处
   r≥y 才能再减一轮）；
3. 守卫从 I 与退出条件的差集长出来：`r ≥ y`（退出即 r<y，
   正是后置的第二合取）；
4. 初始化从 I 与前置的差集长出来：`q := 0; r := x`；
5. 组装，再正向验证一遍（25 章的规则照跑）。

**不变式不是灵感，是插值**：它在前置与后置之间「补差」，
使每条边的验证条件可解。Ben-Ari 的三点观察值得背下来：
（a）合成与验证用同一套规则，方向相反；（b）不变式的选择
自由度=程序设计的自由度；（c）合成不唯一——同一规约可长出
不同程序（机器件用乘法器演示另一条生长路径，见下）。

## 小步语义：程序=状态机（§15.5）

给 while 配操作语义（`ex42_synthsem.v`，两通道同构）：

```coq
Fixpoint step (c : cmd) (s : state) : option (cmd * state) :=
  match c with
  | CSkip => None                             (* 终止：无步可走 *)
  | CAssn f => Some (CSkip, f s)
  | CSeq c1 c2 =>
      match c1 with
      | CSkip => Some (c2, s)
      | _ => match step c1 s with
             | Some (c1', s') => Some (CSeq c1' c2, s')
             | None => None end end
  | CWhile b c =>
      if b s then Some (CSeq c (CWhile b c), s)
      else Some (CSkip, s)
  end.
```

读三条规则的设计：**赋值是原子单步**（f 把状态函数整体推进）；
**序列消解左边**（c1 走完换 c2 上场——「先来后到」的状态机版）；
**while 一步展开**（守卫真则体+自身入队，假则化 skip 终止）。
`steps` 是大步包装：fuel 耗尽于非 skip 即 None（发散的近似），
终止当且仅当最终停在 skip。

这与 39 章的原子步表同构——那里是「两进程的六条全局步」，
这里是「一个进程的四条局部步」；28 章的状态图 = 本章 step
关系的展开。**操作语义是模型检查与演绎验证的公共地面**：
MC 枚举它的可达状态，霍尔规则归纳它的执行树。

## 读出式正确性：两个定理

**倒数程序**（30 章变体方法的语义面）：

```coq
Theorem countdown_correct : forall n s, s 0 = n ->
  match steps (3 * n + 2) countdown s with
  | Some s' => s' 0 = 0
  | None => False
  end.
```

注意两点工程决策。**读出式**（match Some s' => s' 0 = 0）而非
整状态相等：状态是函数，终态 `upd 0 0 s` 与字面 `(fun _ => 0)`
逐点相等但语法不等——函数外延性（funext）是经典公理，读出式
绕开它保住零公理账本。**状态泛化归纳**：IH 必须对任意满足
`s 0 = n` 的状态成立（下一轮的起点是 `upd 0 (s 0 - 1) s`，
不是什么「标准」状态）——「泛化再归纳」的又一现场。

**乘法器**（合成走查的机器收口）：规约
`{y=b ∧ z=c} mul {x = b*c ∧ y=0}`——注意这条规约**长得和
除法不同**：后置是纯等式，合成时从「b 次加 c」的分解长出
`x := x+z; y := y-1` 的循环体（`{x:=0}` 的初始化从 I 与前置
的差集来）。定理拆两层：`mulW`（循环层的规约——对轮数归纳，
读出 `s' 0 = s 0 + b*c`）与 `mul_correct`（外层——两次
`upd` 读出后直收）：

```coq
Lemma mulW : forall b c s, s 1 = b -> s 2 = c ->
  exists s', steps (5 * b + 2) (CWhile ...) s = Some s'
            /\ s' 0 = s 0 + b * c /\ s' 1 = 0.
```

exists 形态（totality+spec 合一）是绕开「match 型结论穿不过
simpl 正规化」的工程选择——exact 吃定义等价比 rewrite 吃语法
匹配可靠得多（坑位速记详述）。语义现场 `mul_3_4`：3×4 经
21 步小步语义得 `(12, 0)`，reflexivity 直收。

## 相对完备性（§15.6\*，文档级）

霍尔逻辑可靠（对操作语义：`{P}c{Q}` ∧ 执行终止 ⟹ 后置成立
——本章 step/steps 就是这条的机器底座）；但**不完备**：Cook
定理——任何可靠的霍尔系统都有它证不了的真三元组，根源是
「不变式要能表达中间值的算术性质」，而证明蕴含了算术真命题
的枚举（与 22 章 Gödel 不完备同根：PA 的表达力撑不起自身
的完全判定）。补救路线：把「证明的算术部分」外包给外部预言
机（数学家的直觉）——恰好与合成的「不变式是插值」呼应：
完备性缺口=插值的自由度=程序设计的难度。**三条暗线在
本章汇合**：不完备（22）、构造性证明=程序（12 的 Curry–
Howard）、不动点（while 的指称语义=连续泛函的最小不动点
——20/24/34 的 Knaster–Tarski 第四次会师，文档走查）。

## while 的指称语义：不动点第四次会师

小步语义回答「怎么跑」；**指称语义**回答「程序 denotes 什么」。
顺序组合与赋值直接复合状态函数；while 的指称是方程

```text
W(b,c) = λs. if b s then W(b,c)(c(s)) else s
```

的**最小不动点**——方程有多个解（如 b 恒假时任何函数都
满足 else 支），取最小的是「只做有限次循环」的那个。解法
与 20 章 T_P、24 章 iterEU/iterEG、34 章 μ 算子完全同构：
从 ⊥（恒发散）出发迭代 F，Knaster–Tarski 在连续泛函上
担保收敛——**四次会师的完整谱系**：T_P（逻辑编程的语义）、
CTL 标记算法（24）、μ/ν 编码（34）、while 指称（本章）。
操作与指称的**一致性定理**（steps 终止 ⟺ 指称非 ⊥）是
Scott 的开创性成果——程序的「跑」与「算」在不动点上重合，
这一课既是本章的尾声，也是整本教程把逻辑、算法与语义
拧成一股绳的终章注脚。顺带一提域理论（domain theory）
的入口也在这里：让「程序的集合」自身成为一个偏序域
（信息序：⊥ < 终止值 < 发散），泛函的连续性才有安身处
——35 章 interp 的域参数 D 在更高的地方再次出场，这次
承载的是「语义域」而不是「论域」——同一个类型抽象，
两次救场，首尾呼应。
## 本章小结

- 合成=逆向验证：不变式是前置与后置之间的插值；合成不唯一。
- 小步语义三规则：赋值原子、序列消左、while 单步展开——
  程序=状态机，MC 与霍尔在此分工。
- 读出式+状态泛化+exists 形态：三个工程决策保住零公理与
  归纳的可运行性。
- 相对完备性：霍尔逻辑的缺口=算术的枚举难度——与 Gödel
  同根；while 的指称=不动点（KT 第四次会师）。

## 坑位速记（本章实测）

- **Coq/Rocq**：
  - **赋值变换器的两层混淆**：`CAssn (upd 0 (fun s => …))`
    把「值级」函数塞进了「状态级」槽位——正确形状
    `CAssn (fun s => upd 0 (s 0 - 1) s)`；类型系统会报
    「product vs nat」，读错方向会浪费半轮；
  - **守卫里的绑定子挡住 rewrite**：goal 的 `s 0` 藏在
    `(fun t => 0 <? t 0) s` 的 beta 红斑里——`unfold` +
    `simpl` 先行让 rewrite 看得见；
  - **fuel 算术要用真算术**：`5*b+6 ≠ S(S(5*b+2))`（差 2）
    ——lia 报「Cannot find witness」时先怀疑自己的代数，
    别怀疑 lia；
  - **状态序不可颠倒**：`upd 1 (s 1-1) (upd 0 (s 0+s 2) s)`
    （B 在 A 之上）与反过来是两个函数——读出（0/1 分离时）
    恰好都对，但 steps 等式只认真序；
  - **exists 形态优于 match 形态**：match steps … with 的
    结论在 simpl 正规化后穿不过去（fuel 被改写成
    `b+(b+(…))`、mulBody 展开、绑定子改名三重变形）；
    exists + exact（吃定义等价）一劳永逸；
  - `rewrite E in IH` 对绑定子名敏感（`fun s` vs `fun s0`
    不匹配）——拿 goal 里打印的原名。
- **Lean**：
  - **`while`/`skip`/`seq` 全是关键字**——Cmd 构造子加
    `c` 前缀（cskip/cseq/cwhile），一步到位；
  - **`Nat.eqb_refl` 不在裸 core**——`x == x = true` 要
    自造（cases on `x == x` + 反证），或绕道
    `simp only [upd]` 后手动归约 if；
  - `replace X = Y by omega` 语法不存在——`have h : X = Y
    := by omega; rw [h]`；
  - **Bool 守卫的 decide 皮**：`(fun t => 0 < t 0) s`
    elaborate 成 `decide (0 < s 0)`——`have hg : … = false
    := by simp [h1]` 断言后 `simp only […, hg]` 消斑；
  - `match` 型结论的 rfl 失败（motive 是 lambda 对）——
    简化到 `exact hs` 靠定义等价收；`simp [Nat.mul_zero]`
    无进展时换 `rw [Nat.zero_mul]`（乘法方向：`0*c`，
    不是 `c*0`）；
  - `Nat.mul_succ`/`succ_mul` 名字按参数序区分（`b*c.succ`
    vs `b.succ*c`）——用法 `have h6 : … := Nat.succ_mul b c`
    直接做项。
