# 35 FOL 语义表列

> 对书：Ben-Ari 3e §7.5（语义表列构造）/ §7.6（可靠性与完备）
> 通道：C/L——理论层旗舰（tclo 推导对象+定理 7.42）在 Coq 通道完整
> 机器化，算法层（fuel 搜索+三现场）双通道镜像

07 章把命题逻辑的语义表列做成了判定程序：α/β 规则拆连接词，分支
互补即闭，fuel 用完还没闭就读出反模型。一到谓词逻辑，这套流水线
卡在哪里？卡在**量词的见证**上：`∃x.p(x)` 说「有个东西满足 p」——
表列必须**替这个还没现身的东西取名字**；`∀x.p(x)` 说「每个东西都
满足 p」——表列必须**对每个已现身的东西逐个核对**。取名字与核对
都是有方向、有纪律的操作，本章的全部内容就是给这两件事立规矩。

## 为什么表列比自然演绎更贴近算法

16 章的 FOL 自然演绎里，∃ 消去是「取一个新鲜变元当见证」的框；
∀ 消去是「任意取项代入」。这些是**证明**侧的纪律。表列把同样的
纪律搬进**搜索**侧：见证的取名从「推理步骤」变成「数据构造」，
于是一个公式是否可满足，从「是否存在证明」变成「搜索树是否全闭」
——算法与演算在同一种数据上工作。这就是 Ben-Ari 用表列贯穿全书
的原因：它是唯一能把「证明论结构」与「判定算法」装进同一格式的
演算（H&R 用的也是它，07 章我们已经在命题层领教过）。

## Ben-Ari 的五个现场（§7.5.1 的失败博物馆）

规则不能凭空设计。Ben-Ari 的教学法是先带读者踩五个坑，每坑立一条
纪律。我们照单全收——这五步是本章的骨架。

**现场一（7.33）：闭表列长什么样。** 取有效式
`∀x(p(x)→q(x)) → (∀x p(x) → ∃x q(x))`，对它的否定做表列。
分支长出 `T ∀x(p→q)`、`T ∀x p(x)`、`F ∃x q(x)` 三个带符号量词。
`F ∃x q(x)` 语义上等于「q 对一切元素假」——它像 ∀ 一样**要被
逐常量核对**；给常量 `a₀`，长出 `F q(a₀)`。两个 T-∀ 也用 `a₀`
实例化：`T p(a₀)`、`T p(a₀)→q(a₀)`。β 拆后者：`F p(a₀)` 分支
与 `T p(a₀)` 互补即闭；`T q(a₀)` 分支与 `F q(a₀)` 互补即闭。
全闭——原式有效。注意此例中 ∃ 否定式与 ∀ 肯定式**共享同一个
常量**——这不是巧合，是下一条纪律的反面教材。

**现场二（7.34）：常量不能复用。** 把式子换成可满足但不有效的
`∀x(p(x)∨q(x)) → (∀x p(x) ∨ ∀x q(x))`。若把 `F ∃x p(x)` 的
见证也取 `a₀`（与 `F ∃x q(x)` 的见证同名），表列会**假闭**：
`F p(a₀)` 与从 `T p(a₀)∨q(a₀)` 拆出的 `T p(a₀)` 对撞——但这两个
`a₀` 本可以指**不同的域元素**！强制同名等于强制「论域只有一个
元素」的解读。教训：**存在见证每次都取新常量**。

**现场三（7.35）：γ 公式不能被用掉。** 继续现场二的表列：
`∀x(p∨q)` 已经用 `a₀` 实例化过了，新常量 `a₁` 登场后（δ 取的），
`a₁` 也可能是任意元素——`∀` 的承诺对它同样有效。若 α/β 规则把
`∀x(p∨q)` 消耗掉了，`a₁` 就漏核对。教训：**∀ 型公式永不删除**，
它在每个后代节点上留守，约束每个新常量的解读。留守的代价是
表列可能不终止（现场五）。

**现场四（7.36）：不终止是真实的。** `∀x∃y p(x,y)` 可满足
（任何非空论域都行），但表列无限生长：`∀` 用 `a₁` 实例化得
`∃y p(a₁,y)`，δ 取新常量 `a₂`；`a₂` 又触发 ∀ 实例化……每个新
常量都带来新的存在式。**FOL 表列不是判定程序**——闭分支是
「不可满足」的有限证书，开分支却可能是无穷模型的前缀。这是
33 章半可判定性（Church 定理）的构造性预演：我们能**确认**
不可满足（全闭），却不能在有限时间内**确认**可满足。

**现场五（7.37-7.38）：构造必须系统。** 规则应用的次序不能挑食：
只对某个子公式反复应用规则，可能让真正会闭的公式永远排不上队
（7.38 给了一个「不可满足却永不闭」的挑食表列）。规则表按固定
优先级取「第一个可用规则」——07 章命题版的纪律原样继承。

## 规则总表：γ/δ 登场

命题层的 α（单分支拆解）与 β（双分支拆解）照旧。量词按**带符号
分类**（`ex19_foltableau.v` 的规则注释，Ben-Ari 表 7.6 的形状）：

| 类型 | 形状 | 行为 | 纪律 |
|---|---|---|---|
| γ | `T ∀xA(x)`、`F ∃xA(x)` | 用分支常量 c 实例化出 `A(c)` | **不消耗**；公式留守 |
| δ | `T ∃xA(x)`、`F ∀xA(x)` | 用新鲜常量 c 实例化出 `A(c)` | **消耗**；c 不见于全分支 |

读法：γ 是「逐个核对」（每个已现身常量都要过一遍），δ 是「取见证」
（新名字代表那个被断言存在的元素）。语义对偶藏在符号里：
`F ∃xA` 就是 `T ∀x¬A` 的变装，所以它按 ∀ 的方式核对——表列的
带符号设计让否定**永远不用显式翻转**（08 章 NNF 的功劳在这里
被「符号」机制预先消化了）。

## 算法层：fuel 搜索（`ex19_foltableau.v` / `.lean`）

```coq
Fixpoint tsearch (fuel : nat) (B : branch) (D : list (fform * nat))
  : option branch :=
  match fuel with
  | 0 => None
  | S k =>
      if closedB B then None else
      match extract B with
      | Some (T, fEx x a, B')  => tsearch k ((T, fsub a x (freshC B))::B') D
      | Some (F, fAll x a, B') => tsearch k ((F, fsub a x (freshC B))::B') D
      | ...（α/β 与 07 章同款）
      | None =>
          match gstep B (gconsts B) D with
          | Some (inst, pr) => tsearch k (inst :: B) (pr :: D)
          | None => Some B          (* 开饱和：只剩文字与做尽了的 γ *)
          end
      end
  end.
```

三个新部件逐一读。**`freshC B`**（δ 的新鲜常量）取分支现有常量的
最大编号加一——把 Ben-Ari 的「取一个没出现过的 a」确定性化，
同样的分支永远取同样的名字（现场二的纪律）。**`gconsts B`** 在
分支还没有任何常量时播种 `[0]`——Ben-Ari 算法 7.40 的「论域非空，
任取 a₀ 代表那个元素」（现场四的入场券）。**`D`（done 表）**是
机器件对本章最真实的贡献：γ 的「做尽」状态不记在分支上（γ 公式
留守，无法从分支看出哪些实例已经加过），而记在 `(公式体, 常量)`
对的表里——`gstep` 找到第一个「实例既不在分支、又不在 done 表」
的 γ-常量对，把实例加进分支、把对子记进 done。没有这张表，
搜索会在「γ 加实例 → β 拆掉 → γ 看不见实例 → 再加」的循环里
空转（这正是 Ben-Ari 集合语义里靠「集合同化」吸收的同款问题，
表列实现里必须显式记账——坑位速记第一条的来源）。

三现场在两个通道里都以 `reflexivity`/`rfl` 直收：

```coq
Example ex733_closed : tsearch 40 [(F, a733)] [] = None.
Example ex734_open : match tsearch 40 [(F, a734)] [] with
  | Some B => atomsOf B | None => [(99,[99])] end = [(1,[0]); (0,[1])].
Example ex736_fuel : tsearch 30 [(T, a736)] [] = None.
```

第二条读出的模型值得看第二眼：`[(1,[0]); (0,[1])]` 是 Herbrand
原子表——谓词 1（q）在 `a₀` 真、谓词 0（p）在 `a₁` 真。对照现场二
的语义分析：`p` 与 `q` **各真一个常量**，正是使 `∀(p∨q)` 真而
`∀p ∨ ∀q` 假的见证格局。开饱和分支到模型就这么一步：正文字的
地面原子直接当事实表（`atomsOf`），这个表满足分支上每个文字——
γ 留守公式也被顺带满足，因为它的每个（分支常量的）实例都作为
文字在分支上被满足过。

第三条是最诚实的现场：`None` 在这里**不代表不可满足**——
`∀x∃y p(x,y)` 有模型（比如论域 ℕ、p 解释为 <）。fuel 耗尽只是
「搜索放弃了」，读作「未判定」。算法层的类型
`option branch` 天生带这个歧义，这正是理论层存在的理由。

## 理论层：闭表列推导即数据（Coq 通道旗舰）

算法层的 `None` 有歧义；要无歧义的「不可满足」结论，需要把
「存在闭表列」本身做成一个归纳谓词——**推导证明对象**（05/06/26 章「演算作为数据」主线在表列上的落点）：

```coq
Inductive tclo : branch -> Prop :=
| tcClose : forall B p ts,
    In (T, fP p ts) B -> In (F, fP p ts) B -> tclo B
| tcSwap : forall B1 en B2,
    tclo (en :: (B1 ++ B2)) -> tclo (B1 ++ en :: B2)
| tcAndT : forall B a b, tclo ((T,a)::(T,b)::B) -> tclo ((T, fAnd a b)::B)
| ...（α/β 其余各条同形）
| tcGT : forall B x a c,
    tclo ((T, fsub a x c)::(T, fAll x a)::B) -> tclo ((T, fAll x a)::B)
| tcDT : forall B x a c,
    ~ In c (constsF (fEx x a) ++ constsB B) ->
    tclo ((T, fsub a x c)::B) -> tclo ((T, fEx x a)::B).
```

读四个要点。**`tcClose` 的前提是 `In`** 而非「表头」——闭分支的
互补对可以在任何位置。**`tcSwap`** 是唯一「无内容」的构造子：
把任意条款换到表头，可靠性只花成员重排的代价——有了它，其余
规则只需处理表头位置（「first applicable rule」的位置自由度被
这一个构造子吸收）。**`tcGT` 的前提里 γ 公式留守**（实例加在
前、γ 保留在后）——现场三的纪律直接写在推导的形状里。
**`tcDT` 的新鲜性侧条件是推导数据的一部分**——`~ In c (...)` 作为
前提字段，违反新鲜性的「推导」根本无法构造（现场二的假闭从此
在类型层就被拒绝）。

对这套构造子归纳，得到本章旗舰——Ben-Ari 定理 7.42：

```coq
Theorem tclo_unsat : forall B, tclo B ->
  forall {D} (I : interp D), ~ satB I B.
```

语义侧的 `interp` 把**域做成参数**而不是记录字段——两个解释的
域类型若各自为政，`iasg I k = iasg I' k` 连陈述都不成立（这是
本章实测的第一大坑）。证明的分水岭在 δ 案例与 γ 案例：

- **γ 案例**：`I ⊨ T ∀x a` 给出 `∀d, I[x↦d] ⊨ a`；取 `d := icon I c`
  （常量 c 指到的元素），代入引理把它转成 `I ⊨ a[c]`——前提分支
  被违反。
- **δ 案例**：`I ⊨ T ∃x a` 给出见证 `d`；**把 d 搬到新常量 c 上**
  ——构造 `setC I c d`（其余字段照抄 I，只把 c 的指派改成 d）。
  c 的新鲜性保证 I 与 `setC I c d` 在 B 的一切公式上**逐点一致**
  （外延性引理），而头公式 `a[c]` 恰好吃到新的指派。前提分支
  再次被违反。

两条支柱引理——**外延性**（`fsat_ext`：变元/常量指派逐点一致则
满足性不变）与**代入引理**（`subst_sem`：`I ⊨ a[c] ⟺ I[x↦c 的
指派] ⊨ a`，对公式结构归纳、量词处靠 setV 的换名交换）——合起来
大约是定理本身的体量。这两条引理是「项在语义里如何流动」的完整
说明书，16 章 ∀/∃ 消去的语义正确性、22 章 Henkin 构造的项模型
读出，用的都是同一套流动规则。

**推导现场**：`tclo_733` 把现场一的闭表列逐构造子搭出来——两次
α、一次聚焦、三次 γ、一次 β 两支各闭，13 步的推导项；接上
旗舰立即得到 `valid_733`：对**一切**抽象解释，`¬A` 不可满足——
有效性的完整证明，零公理（`Print Assumptions` 为空）。

## 与 22 章 Henkin 常量的同源

δ 规则「存在断言取新鲜常量作见证」与 22 章 Henkin 构造的见证
扩张是**同一机制的两副面孔**：Henkin 对一致集里每个 `∃x.A(x)`
分配专属常量 c 并把 `A(c)` 加进集——为了**项模型**能读出语义；
表列的 δ 在搜索树里做同样的事——为了闭分支能**穷尽反例**。
再往前追，16 章 =i 规则的闭项侧条件、27 章 Herbrand 宇宙的
「常量当世界」，都是「见证必须有名字、名字必须是项」这一条
底线。四个章节，一条见证线。

## 与全书的接线

- **07 章**：命题表列的全部纪律（fuel、系统性、readOff）原样
  继承；本章只加了 γ/δ 与 done 记账。
- **16 章**：ND 的 ∃ 消去见证框 = δ 的推导版；∀ 消去的「任意
  项」= γ 的分支常量。
- **34 章**：不可完备性的编码需要「可判定的证明关系」——表列
  的「闭表列可判定地验证」正是构造 ω-不一致公式族的原料。
- **22 章**：完备性构造里的见证扩张（见上节）；表列闭 ⟹ 存在
  归结反驳（28 章的桥）。
- **28 章**：表列↔归结的翻译引理把本章的完备性直接搬运给
  归结演算。
- **33 章**：现场四的不终止 = FOL 半可判定性的算法面。

## 本章小结

- 五现场五纪律：常量勿复用（δ 新鲜）、γ 勿消耗（留守核对）、
  构造要系统（first applicable）、开分支可能无穷（非判定程序）、
  闭分支是完备的有限证书。
- γ=逐常量核对（`T∀/F∃`）、δ=取见证（`T∃/F∀`）；带符号设计
  让否定永不翻转。
- 算法层：done 表防 γ 重演；`freshC` 确定性命名；`gconsts` 播种
  非空论域。`None` 的歧义（闭 vs 燃料尽）只能由理论层消除。
- 理论层：tclo 推导对象（侧条件是数据）+ tclo_unsat（外延性+
  代入引理两支柱）——「闭表列 ⟹ 一切解释下不可满足」零公理。
- δ 见证与 Henkin 常量、闭项侧条件、Herbrand 宇宙同一条见证线。

## 坑位速记（本章实测）

- **Coq/Rocq**：
  - **记录域参数化**：`interp` 若把 `idom : Type` 当字段，两个
    解释的域类型互不相干，`iasg I k = iasg I' k` 陈述层就类型
    不成立——**把域提为记录参数** `interp (D:Type)`，setV/setC
    天然同域；且记录参数在投影中是**显式参数**，须补
    `Arguments iasg {D}` 三连；
  - **隐式 {D} 的三处坑**：陈述里未标注的绑定子让 D 悬空
    （`Cannot infer the implicit parameter`）；`intros` 会把
    隐式 D 吃进名字（`intros D I` 显式过）；`induction` 后 IH
    里 D 变显式——调用点 `IHT D I` 要补；
  - **`induction` 的 as 模式必须给全**：带非变量指标的构造子
    （tcSwap 的 `en::(B1++B2)`）不给 as 模式时 IH 拿不到默认名
    `IHT`（最小复现已定位）——14 个构造子逐个列名；
  - **proj1/proj2 方向反是本章最高频翻车点**（五次）：`fsat I T
    (fsub a x c)`（代入式）是 `subst_sem` 的**左端**，`setV`
    版是右端——γ 案例从 setV 版出发要 `proj2`，δ 头部从代入式
    目标出发也要 `proj2`；写之前先默诵「iff 的哪端是目标」；
  - **`apply` 不展开定义**：目标 `satE I (T, fsub…)` 对
    `apply (proj1 (subst_sem …))` 不匹配——先 `unfold satE`；
    `exact` 反而无此问题（unification 到定义层）；
  - **`destruct … as [->]` 会消灭变量**：同一变量的第二次
    `Nat.eqb_spec` 引用炸掉——布尔情形改 `destruct (Nat.eqb k x)
    eqn:E1` 双分解 + `Nat.eqb_eq/congruence` 收尾；
  - **tauto 撞构造子等式**（`fV v = fC c`）不自动消解——显式
    `discriminate`/`injection` 分支；
  - **两入口 α 案例要三层 In 分解**：`[Heq | [Heq2 | Hin]]`，
    B 部分要 `apply (Hsat en). right.`（单层 right 够）；
  - **`simpl` 把 `snd e` 压成 let**（eta 折叠），`apply in_or_app`
    认不出 append 形状——先 `destruct e as [sg fm]` 拆对；
  - **期望值用 Compute 探针校准**：`Example … = 期望` 撞墙时，
    截断文件+追加 `Compute (…)` 独立跑，把真实值抄回来（本章
    ex734 的 `[(1,[0]);(0,[1])]` 即此法所得）；
  - `tcClose` 的 `p ts` 留白不解析——`apply (tcClose _ 0 [fC 0])`
    显式给。
- **Lean**：
  - `List.Mem` 分解用 `List.mem_cons` + `rcases`，没有 `.elim`
    这种字段；构造子等式 `fC c = fC k` 用 `injection h with h2;
    subst h2`（注意 mp/mpr 两方向的 h 形状可能不同——一边已被
    simp 压成 `c = k`，另一边还是构造子等式）；
  - `by simp [constsT]`——自定义 Fixpoint 的成员目标要手动点名
    展开函数，裸 simp 无进展；
  - 算法层大计算（tsearch 40 分支全展开）`rfl` 直收——Lean 的
    whnf 吃得下，无需 decide 化；
  - Bool 条件的 `if` 直接可用（自动 `= true` 强制），`!` 取反
    照写。
