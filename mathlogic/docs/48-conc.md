# 39 并发程序演绎验证

> 对书：Ben-Ari 3e §16.1-16.3（并发程序/正确性形式化/演绎验证）
> 通道：C/L——不变式保持 + 可达性封口，双通道同构

37 章用显式模型检查验证了互斥：算出全部可达状态，逐个核对。
当状态空间膨胀（真实协议的上亿状态）、或协议带参数（n 个进程）
时，枚举失效——**演绎验证**接手：找一个不变式，证明它在初始
成立、对每条原子步保持，互斥就是推论。一个不变式顶一个可达集：
这是 Ben-Ari §16.3 的核心主张，也是 46 章霍尔逻辑在并发世界的
续篇。

## 并发 = 交错 + 原子性（§16.1）

并发程序的形式化先要回答「语义是什么」。Ben-Ari 的选择：
**交错语义**——任意时刻恰有一个进程执行一条原子步，全局计算是
原子步的交错序列。原子步的粒度是协议正确性的命门：`await B then
S` 把「等条件+执行」打包成不可分割的一步——粒度太粗，并发度
低；拆细了，竞态进来（§16.2 的三次失败尝试就是粒度与协议的
相互作用史）。

机器件把交错语义压成最紧凑的形状（`ex48_conc.v`）：

```coq
Record st : Type := MkSt { pc1 : nat; pc2 : nat; turn : nat }.

Definition try_enter1 (s : st) : option st :=
  if (pc1 s =? 1) && (turn s =? 1)
  then Some {| pc1 := 2; pc2 := pc2 s; turn := turn s |}
  else None.

Definition asteps : list (st -> option st) :=
  [try_req1; try_enter1; try_exit1; try_req2; try_enter2; try_exit2].
```

状态是三分量记录（两进程位置 + 轮牌），每条原子步是
`state -> option state`——`None` 表示守卫不满足（此交错分支
不存在），guard 与 action 合一。**并发语义 = 六个函数的 nondeterministic
选择**——37 章的状态图就是这个函数表的展开。

## 不变式怎么长出来（§16.2 的失败博物馆）

Ben-Ari 教并发验证的方式与 19 章教表列的方式同构：先带读者踩坑。
三次尝试的谱系（docs 走查，机器件取第三次）：

**尝试一（严格轮换）**：进入条件 = 「轮到我」。安全但苛刻——
p2 若不感兴趣，p1 转完一轮就永久阻塞。活性缺陷，安全性完好。

**尝试二（标志位）**：`flag[i] := true` 后等对方标志为假。
经典竞态：两进程同时设标志、同时看到对方为真、同时进入——
互斥破产。「看到」与「进入」之间有缝，原子性粒度不够。

**尝试三（轮牌 + 辅助不变式）**：机器件采用的版本。单独的
「轮到我」守卫看似安全，直接证互斥却推不动——`¬(pc1=2 ∧
pc2=2)` 对 enter1 步的保持性卡在「pc2=2 时轮牌在谁手里」。
**辅助不变式**补上这一块拼图：

```coq
Definition inv (s : st) : Prop :=
  ~ (pc1 s = 2 /\ pc2 s = 2)          (* 互斥（目标）*)
  /\ (pc1 s = 2 -> turn s = 1)        (* 辅助一：临界者持牌 *)
  /\ (pc2 s = 2 -> turn s = 2).       (* 辅助二 *)
```

互斥不再是孤立的断言，而是一个**不变式族**的成员：两条辅助
条款把「轮牌唯一」的事实逐状态维护，enter1 的保持性证明里
它们与 `turn = 1` 的守卫直接对撞出矛盾。这是并发验证最重要的
方法论：**目标性质往往证不动，把它嵌进一个更强的归纳不变式里
就动了**——与 31 章程序合成「不变式从规约里长出来」互为镜像。

## 保持性：六条原子步的逐一核对

```coq
Theorem inv_preserved : forall f s s',
  In f asteps -> f s = Some s' -> inv s -> inv s'.
```

证明是六案例的结构核对：解出守卫布尔值（`destruct ... eqn:E`）、
把 `s'` 注入成具体的记录字面量（`injection Hstep; subst s'`——
不注入则一切关于 s' 的目标都是黑箱）、三分支逐条 lia。最具启发
的是 enter1 案例：目标 ¬(2 = 2 ∧ pc2 s = 2) 里「2 = 2」恒真，
唯一的救命稻草是辅助不变式二——`pc2 s = 2 → turn s = 2` 与
守卫里的 `turn s = 1` 矛盾。**辅助不变式在关键案例处精确兑现**，
其他案例它只是搭顺风车——不变式族的设计感正在于此。

可达性封口是标准的归纳收尾（`reachSet` 前向收集 + 对 fuel 归纳
传递保持性）：

```coq
Corollary reach_inv : forall fuel s, In s (reachSet fuel init) -> inv s.
Corollary mutual_exclusion : forall fuel,
  ~ In {| pc1 := 2; pc2 := 2; turn := 1 |} (reachSet fuel init).
```

注意推广形 `reach_inv_gen`：归纳假设必须对**任意起点**成立
（可达集的中间状态不是 init）——「泛化起点再归纳」的老配方
（47 章变体方法同款）。

## 演绎 vs 算法：同一案例的两副面孔

| | 37 章（显式 MC） | 本章（演绎） |
|---|---|---|
| 对象 | 全体可达状态 | 一个不变式 |
| 成本 | 与状态数成正比 | 与原子步数成正比 |
| 失败诊断 | 反例路径 | 「哪条步不保持」 |
| 活性 | 公平性假设下可判 | 需要时态推理（40 章 Ind 公理） |
| 规模 | 状态爆炸即失效 | 参数化可推广（n 进程同证） |

两列不是竞争而是分工：设计阶段用演绎找不变式（快、抽象），
工业验证用 MC 全面复查（准、自动）。Ben-Ari 的教材结构与
H&R 的 NuSMV 路线在此合流——42 章的符号方法把 MC 列推到
大规模，本章的演算列留给无穷与参数化。

## 活性：演绎路线的软肋

安全性（不变式）演绎得好，活性（「终将进入」）是另一回事——
严格轮换协议的活性缺陷（p2 不动则 p1 永阻）在纯不变式框架里
**表达不出来**：不变式是状态的属性，活性是路径的属性。这正是
41 章自动机路线存在的理由（公平性下的活性 = 乘积空性），也是
40 章归纳公理的应用场景（把「每步保持 + 初始」兑换「永远」，
再把「永远 + 公平」兑换「终将」）。三条路线在并发验证上拼成
完整工具箱：不变式管安全、自动机管反例、时态演算管归纳。

- **41 章**：活性的算法面（反例环）；三条路线的分工表。

  是同一枚硬币的两面。

## await 与 Owicki–Gries：完整的并发规则集

本章的原子步模型把「等条件+执行」打包成不可分割的一步；
写出显式规则就是 **await 规则**：

```text
{P ∧ B} S {Q}
-------------------------------- {P} await B then S end {Q}
```

守卫 B 为真时 S 原子执行——一步的霍尔三元组提升为语句。
当 B 取 true 时退化为纯原子区 `atomic S`；当 S 取 skip 时
退化为「忙等一步」。三条退化给出并发程序的三种粒度旋钮。
**Owicki–Gries 方法**把「全局不变式+逐步保持」精确化为一对
条件：每条语句对 I 的**局部正确性**（单进程的霍尔证明）+
对其他进程的**干扰自由**（其他进程的每一步都不破坏本证明
用到的不变式）——本章 inv_preserved 的六案例核对正是
干扰自由检查的机器形态。完整的 Owicki–Gries 要对「证明步」
而不只是「程序步」做干扰检查（辅助不变式之间也要互不干扰）
——这是并发验证比顺序验证贵一个量级的根源，也是为什么
工业界更愿意先跑 MC（37/41 章）再做演绎兜底。
## 三进程推广的形状

两进程的证明已经显出不变式方法的规模律：每个 enter 案例
要用到「对方在临界 ⟹ 轮牌在对方」的辅助条款。n 进程的
turn-类协议（如面包房算法）不变式族同步膨胀：每对 (i,j)
一条「临界者持牌」+ 一条全局互斥——**辅助条款数 O(n)**，
每条原子步的保持检查要过全部条款——演绎验证的成本随
并发度线性增长，而 MC 的成本随状态数指数增长——这正是
「一个不变式顶一个可达集」的定量版本。真正的原因在 31 章收口：不变式是插值，n 进程的插值空间指数大，但**形状
相同**（对称性归约是研究前沿）；Peterson n 进程协议的
不变式有经典的对称闭式（每层一个优先级数组），是本章
轮牌协议的自然分层推广——文档走查留作练习的进阶档。
## 本章小结

- 交错语义 = 原子步表；guard-action 合一的 `option` 编码。
- 三次尝试的谱系：轮换安全但阻塞、标志位有竞态、轮牌+辅助
  不变量成——目标性质嵌进更强的归纳不变式才证得动。
- inv_preserved：六案例结构核对；enter 案例是辅助不变式的
  精确兑现点；injection+subst 让 s' 从黑箱变字面量。
- reach_inv_gen：泛化起点再归纳——可达集的中间状态不是 init。
- 演绎与算法的分工表：不变式顶可达集；活性是演绎的软肋、
  自动机与时态演算的领地。

## 坑位速记（本章实测）

- **Coq/Rocq**：
  - **协议守卫先自审**：起草时「pc2≠1 ∨ turn=2」挡不住
    pc2=2（对方已在临界）——经典 turn 协议的正确守卫是
    「轮到我」+ 退出时交牌；写机器件前先用小例子手推一遍，
    否则证明会诚实地卡住；
  - **Prop 不变式优于 bool**：bool 版要一路 andb/orb 拆解
    （tauto 撞构造子等式），Prop 版 lia 直接吃字段算术——
    只有需要 reflexivity 的初始检查会稍啰嗦；
  - **`injection Hstep; subst s'` 是每案例的起手式**：不解出
    记录字面量，一切 `pc1 s'` 都是黑箱原子，lia 无从下手；
  - **`subst` 消不掉记录投影**（`subst pc1` 报错）——守卫
    等式 `E : pc1 s = 0` 留在上下文里让 lia 用；
  - **辅助不变式是蕴含，lia 不自动施加**——`specialize (Hb H)`
    要手写；「first [lia | destruct | specialize×2]」的组合拳
    才收得齐六案例；
  - **可达集的 flat_map 不能 simpl**：一展开成显式 append 链，
    in_flat_map 就 apply 不上了——S 臂直接对 In 做 case；
  - `in_flat_map`（不是 flat_map_In）；reach_inv 要泛化起点。
- **Lean**：
  - 具体列表的成员先 `simp only [asteps, List.mem_cons,
    List.not_mem_nil, or_false]` 摊平成或链再 rcases——直接
    rcases 具体列表会试图 subst 列表本身；
  - `simp only [reachSet]` 在 `fuel + 1` 臂可能「no progress」
    （等式引理对不上加法形状）——直接 `cases` 让 whnf 干活；
  - `List.not_mem_nil` 的元素参数是隐式的（带参应用报
    sort 不匹配）；
  - `rw` 方程进 match 会造出 `nomatch` 垃圾——`exact hout`
    靠定义等价反而干净；
  - 多轮 python 批量替换会互相踩（本章尾块重写了三次）——
    大改用「截头 + 重拼尾」的一次性重写，别在旧文本上打补丁。
