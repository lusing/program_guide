# 30 · 国际化：一套代码，多副面孔

> 对应示例：examples/30_i18n/（手写 Localizations + Delegate / flutter_localizations 全家桶 / intl 复数与格式化 / 运行时切换与持久化）

## 30.1 解决什么问题

App 要上多个国家的商店时，不能为每种语言维护一个版本。Flutter 的国际化分三层：**框架给的**（flutter_localizations：Material 自带组件的 50+ 语言翻译、RTL 文本方向）、**你自己的**（App 文案：手写 Localizations 或 gen-l10n 生成）、**格式化的**（intl：复数、日期、数字）。本章按书第 9 章的教学主线走手写路线——知其所以然，再对照现代生产标准。

```text
┌─────────────────────────────────────────────────────┐
│  MaterialApp                                        │
│  ├─ localizationsDelegates: [                       │
│  │     AppLocalizations.delegate,     ← 自家文案     │
│  │     GlobalMaterialLocalizations,   ← Material 内置│
│  │     GlobalWidgetsLocalizations,    ← 文本方向     │
│  │     GlobalCupertinoLocalizations,  ← Cupertino   │
│  │   ]                                              │
│  ├─ supportedLocales: [zh, en]                      │
│  └─ locale: _override ?? null  ← 运行时切换          │
└─────────────────────────────────────────────────────┘
```

## 30.2 识别系统的首选语言

书 9.1 的三个 MaterialApp 参数至今是正解：

```dart
// ═══ 30.2 ═══
MaterialApp(
  localizationsDelegates: const [...],       // 装载器列表（见 30.3/30.4）
  supportedLocales: const [Locale('zh'), Locale('en')],  // App 支持哪些
  localeListResolutionCallback: (locales, supported) {
    // locales：系统语言偏好列表（较新 Android 给列表，老设备单值）
    // 返回值 = App 实际采用的 locale；返回 null 交回框架默认算法
    final resolved = resolveTeaching(locales, supported);
    debugPrint('系统首选语言: $locales → 匹配: $resolved');
    return resolved;
  },
)
```

### 30.2.1 匹配算法

框架的 `basicLocaleListResolution` 简化版（示例的 `resolveTeaching` 第 33-49 行）：逐个系统语言先找**完全匹配**（`zh_CN == zh_CN`），再退到**语言码匹配**（`zh_SG` 命中 `zh`），全不中回落 `supportedLocales.first`。

**Locale 的三字段**：`languageCode`（必选，如 `zh`）、`countryCode`（可选，如 `CN`）、`scriptCode`（可选，如 `Hans`）。匹配时优先级：`languageCode + scriptCode + countryCode` > `languageCode + scriptCode` > `languageCode + countryCode` > `languageCode`。

### 30.2.2 运行时读当前 locale

- **当前生效值**：`Localizations.localeOf(context)`——框架解析后的最终 locale。
- **系统完整偏好列表**：`View.of(context).platformDispatcher.locales`（不稀释，原始列表）。示例第 152 行用它做匹配报告展示。
- **`localeResolutionCallback` vs `localeListResolutionCallback`**：前者只给单值（老 API），后者给列表（新 API，推荐）。两个都设时后者优先。

## 30.3 手写 Localizations + Delegate

书 9.2 的教学核心——两个类各司其职：**一个装字符串，一个负责装载**：

```dart
// ═══ 30.3 app_localizations.dart ═══
class AppLocalizations {
  AppLocalizations(this.locale);
  final Locale locale;

  static AppLocalizations of(BuildContext context) =>
      Localizations.of<AppLocalizations>(context, AppLocalizations)!;

  static const LocalizationsDelegate<AppLocalizations> delegate = _AppDelegate();

  bool get _zh => locale.languageCode == 'zh';
  String get title => _zh ? '国际化演示' : 'i18n Demo';
}

class _AppDelegate extends LocalizationsDelegate<AppLocalizations> {
  @override
  bool isSupported(Locale locale) =>       // 守门员：不支持的不进 load
      ['zh', 'en'].contains(locale.languageCode);

  @override
  Future<AppLocalizations> load(Locale locale) =>
      SynchronousFuture(AppLocalizations(locale));  // 同步装载的规范写法

  @override
  bool shouldReload(_AppDelegate old) => false;     // build 重跑≠重载资源
}
```

### 30.3.1 LocalizationsDelegate 三方法语义

| 方法 | 调用时机 | 返回值 |
|---|---|---|
| `isSupported(locale)` | 框架解析 locale 时 | `true` 才调 load；`false` 直接跳过 |
| `load(locale)` | locale 确定后（首次或切换） | `Future<T>`——资源装载完成 |
| `shouldReload(old)` | widget 重建时 | `true` 重新 load；`false` 复用旧实例 |

`SynchronousFuture` 是 `package:flutter/foundation.dart` 里的轻量 Future 包装——资源在内存里（如示例的 getter 分发）无需异步 I/O 时用它，**一次 pump 即可就绪**，widget 测试不用等异步。真要异步（从 assets 读 JSON、从网络拉翻译）就返回普通 `Future`，框架会等。

### 30.3.2 手写 vs 生成

与书当年的 `LanguagezhCnLocalizations`（`isZh` 布尔构造）同构；现代改良：按 `languageCode` 分发 getter，且 getter 里可以放**任意逻辑**——复数、拼接、格式化，这是手写比静态字符串表灵活的地方。

**生产标准的对照**：SDK 自带的代码生成方案（`l10n.yaml` + arb 文件 + `flutter gen-l10n`）把文案抽进 `.arb`，生成 `AppLocalizations` 类——多人协作、翻译外包时用。教学与小项目手写更直观；两套的 `of(context)` 用法完全一致，随时可迁。本示例走手写，生成物零依赖。

### 30.3.3 `of(context)` 的空断言

`Localizations.of<T>(context, T)` 找不到祖先时返回 null——示例里的 `!` 炸的是 `TypeError`（不是 FlutterError）。测试里断言用 `throwsA(isA<TypeError>())`。**触发条件**：MaterialApp 没配对应 delegate，或在 MaterialApp 之上调 `of`。

## 30.4 flutter_localizations 全家桶

只加自家 delegate，Material 内置文案（日期选择器的月份名、tooltip 的缺省文案、剪切板菜单）不会跟着变语言。三个 Global delegate 一次配齐：

```dart
// ═══ 30.4 pubspec（SDK 自带，跟 Flutter 版本走）═══
dependencies:
  flutter_localizations:
    sdk: flutter

// ═══ 30.4 main.dart ═══
localizationsDelegates: const [
  AppLocalizations.delegate,                    // 自家文案
  GlobalMaterialLocalizations.delegate,         // Material 组件翻译
  GlobalWidgetsLocalizations.delegate,          // 默认文本方向（RTL 的来源）
  GlobalCupertinoLocalizations.delegate,        // Cupertino 组件翻译
],
supportedLocales: AppLocalizations.supportedLocales,
```

### 30.4.1 三个 Global 各司其职

| Delegate | 管什么 | 验证抓手 |
|---|---|---|
| `GlobalMaterialLocalizations` | Material 组件内置文案（日期选择器、Dialog 按钮、tooltip） | `MaterialLocalizations.of(context).okButtonLabel` |
| `GlobalWidgetsLocalizations` | 默认文本方向（RTL 的来源） | `Directionality.of(context)` 在 ar 语言下返回 `rtl` |
| `GlobalCupertinoLocalizations` | Cupertino 组件内置文案（iOS 风格 DatePicker、Picker） | `CupertinoLocalizations.of(context).datePickerMediumDate` |

验证它生效的抓手：`MaterialLocalizations.of(context).okButtonLabel`——英文环境 `OK`、中文 `确定`（示例测试锁死了这对值）。`GlobalWidgetsLocalizations` 还按 locale 决定 `textDirection`——阿拉伯语等 RTL 语言整个布局自动镜像，不需要你改一行 Row。

### 30.4.2 必须显式 import

`GlobalWidgetsLocalizations` 和 `GlobalCupertinoLocalizations` 在 `package:flutter_localizations/flutter_localizations.dart` 里——`material.dart` 只透出 Material 那一个。漏 import 会报 `Undefined name`。

### 30.4.3 测试里也要全家桶

MaterialApp 测试里只挂自家 delegate 会炸：Scaffold 需要 MaterialLocalizations——测试里也要把全家桶配齐，否则 "locale zh is not supported by all of its localization delegates"。

## 30.5 intl：复数、日期、数字

书 9.3 的练习就是"用 intl 重写示例"——本节即答案。intl 是 dart.dev 第一方包，三个高频能力：

```dart
// ═══ 30.5 ═══
String tapCount(int n) => Intl.plural(
      n,
      locale: locale.toString(),   // 不传 locale 会按英文规则分叉！
      other: _zh ? '你点了 $n 次' : 'You tapped $n times',
      one: 'You tapped once',      // 中文无复数形态，恒走 other
    );

DateFormat.yMMMMd('zh').format(now);              // 2026年9月30日
NumberFormat.decimalPattern('en').format(1234567); // 1,234,567
```

### 30.5.1 Intl.plural 的 locale 陷阱

`Intl.plural(n, locale: ..., one: ..., other: ...)` 的**第一个参数 n 是数量**，`locale` 决定走哪种复数规则。英文有 `one`/`other` 两态（1 → one，其他 → other）；中文**没有复数形态**，恒走 `other`。**不传 locale 默认按英文分叉**——中文文案挂在 other 上侥幸对，但英文 one/other 定制时必错。示例第 46-51 行显式传 `locale: locale.toString()`。

### 30.5.2 DateFormat 的初始化坑

`DateFormat.yMMMMd('zh')` 需要 locale 符号表先初始化——`main()` 里 `await initializeDateFormatting('zh', null)`，漏了运行时直接 `FormatException`。`initializeDateFormatting` 来自 `package:intl/date_symbol_data_local.dart`，第二个参数是 URL（Web 用，本地传 null）。

### 30.5.3 NumberFormat 常用模式

| 模式 | 用途 | 示例（en） |
|---|---|---|
| `decimalPattern` | 分组（千分位） | 1,234,567 |
| `currency` | 货币（带符号） | $1,234.56 |
| `percentPattern` | 百分比 | 12.3% |
| `simpleCurrency` | 简单货币（符号本地化） | USD 1,234.56 |

### 30.5.4 intl 与 flutter_localizations 版本联动

`flutter_localizations` pin 了 intl 的兼容区间——`flutter pub add intl` 装最新的兼容版即可，手动钉老版本反而打架。pub.dev 上 intl 当前稳定版 0.19.x，与 Flutter 3.47 兼容。

## 30.6 运行时切换与持久化

跟随系统是默认；用户手动锁定则用 `MaterialApp.locale` 覆盖解析链：

```dart
// ═══ 30.6 ═══
locale: _override,   // null = 跟随系统；非 null = 锁定该语言
```

### 30.6.1 持久化策略

持久化用第 17 章的 shared_preferences（第 23 章的"入口 await + 启动恢复"模式）：切换时写入 `selected_language`，`initState` 读回。注意**"跟随系统"也要持久化**——用户明确选了 System，下次启动不该被旧值覆盖（示例存 null 用 `remove`，第 71-73 行）。

```dart
// ═══ 30.6 持久化：null 也写 ═══
code == null
    ? widget.prefs.remove(_prefKey)      // 跟随系统：清掉旧值
    : widget.prefs.setString(_prefKey, code);  // 锁定：写语言码
```

### 30.6.2 切换 UI

切换 UI 的控件是 `SegmentedButton<String>`（跟随系统 / 中文 / English 三段，示例第 180-189 行）。`onSelectionChanged` 回调里 `'sys'` 映射为 null（跟随系统），其他直接传语言码。

### 30.6.3 切换的传播机制

`MaterialApp.locale` 变化 → 框架重新解析 locale → 调所有 delegate 的 `load`（`shouldReload` 返回 true 时）→ 重建依赖 `Localizations.of` 的子树。示例用 `RootLocaleBinding`（InheritedWidget，第 119-136 行）把当前语言码与 setter 注入给深层 widget，避免把整份 prefs 泄进 UI 层。

## 30.7 测试策略

- **双语文案**：`pumpWidget` 后直接断言（测试环境系统语言默认 `en_US`，跟随系统落在英文）；点 SegmentedButton 切中文再断言。delegate 用了 `SynchronousFuture`，**一次 pump 就绪**，没有异步等待。
- **复数**：英文 1 → `once`、2 → `times`；中文 0/1/2 同文案。
- **内置翻译**：`MaterialLocalizations.of(context).okButtonLabel` 断言 `OK`/`确定`。
- **持久化恢复**：`SharedPreferences.setMockInitialValues({'selected_language': 'en'})` 后 pump，断言英文界面。
- **守门语义**：`locale: Locale('ja')` 且不支持日文时，框架回落 `supportedLocales.first`——delegate 照常 load。
- **`of(context)` 的空断言**：无 Localizations 祖先时，`!` 炸的是 `TypeError`（不是 FlutterError）——`throwsA(isA<TypeError>())`。

### 30.7.1 测试里的 locale 注入

widget 测试里系统 locale 默认 `en_US`。要测其他语言：在 `MaterialApp` 上显式设 `locale: Locale('zh')` + 全家桶 delegate，绕过系统解析。

## 30.8 生产标准：gen-l10n 与 ARB

手写方案适合教学与小项目；多人协作、翻译外包时，SDK 自带的代码生成方案更合适：

```yaml
# l10n.yaml（项目根目录）
arb-dir: lib/l10n
template-arb-file: app_en.arb
output-localization-file: app_localizations.dart
```

```json
// lib/l10n/app_en.arb
{
  "title": "i18n Demo",
  "tapCount": "{count, plural, =1{You tapped once} other{You tapped {count} times}}",
  "@tapCount": { "placeholders": { "count": { "type": "int" } } }
}
```

```dart
// lib/l10n/app_zh.arb
{
  "title": "国际化演示",
  "tapCount": "你点了 {count} 次"
}
```

运行 `flutter gen-l10n` 生成 `AppLocalizations` 类——用法与手写版完全一致（`AppLocalizations.of(context).title`），翻译人员只编辑 ARB 文件，不碰 Dart 代码。**迁移路径**：手写版的 getter 逻辑（复数、格式化）搬到 ARB 的 ICU 语法（`{count, plural, ...}`），delegate 自动生成。

## 坑位清单

- **字段名遮蔽 `override`**：类里定义 `final String? override;` 后，同类里 `@override` 注解解析到字段名——analyzer 报 `Undefined name 'override' used as an annotation`，且只在报错类里炸。字段改名了事。
- **`GlobalWidgetsLocalizations`/`GlobalCupertinoLocalizations` 要显式 import**：`package:flutter_localizations/flutter_localizations.dart`——material.dart 只透出 Material 那一个。
- **MaterialApp 测试里只挂自家 delegate 会炸**：Scaffold 需要 MaterialLocalizations——测试里也要把全家桶配齐，否则 "locale zh is not supported by all of its localization delegates"。
- **`Intl.plural` 不传 locale 按英文分叉**：中文文案挂在 other 上侥幸对，英文定制 one/other 时必错。
- **DateFormat 非默认 locale 不初始化就 `FormatException`**：`initializeDateFormatting('zh', null)` 进 main。
- **"跟随系统"状态不持久化**：重启后被旧的语言锁定覆盖——null 也写入（`remove`）。
- **`flutter_localizations` 与 intl 版本联动**：前者 pin 了 intl 的兼容区间，`flutter pub add intl` 装最新的兼容版即可，手动钉老版本反而打架。
- **`of(context)` 在 MaterialApp 之上调用**：找不到 Localizations 祖先返回 null，`!` 炸 TypeError——确保调用点在 MaterialApp 之下。
- **`supportedLocales` 与 `isSupported` 不一致**：delegate 的 `isSupported` 守门员与 MaterialApp 的 `supportedLocales` 必须同源（示例都指向 `AppLocalizations.supportedLocales`），否则框架解析出的 locale 被 delegate 拒绝。
- **RTL 布局没自动镜像**：漏了 `GlobalWidgetsLocalizations`——`Directionality.of(context)` 永远返回 `ltr`，阿拉伯语界面 Row/ListView 方向不对。
