# 18 · 命令式函数式：State 与 ST ⭐

> 对应示例：`examples/18_st/`（Ch18.hs + main.hs + runtests.hs）。
> 本章对应原书第 10 章〈命令式函数式程序设计〉——IO 的语义、单子定律、State 单子、
> ST 单子与 rank-2 封印、STArray 原地排序、不变数组，全部提炼。16 章手写过 State 的
> 骨架，17 章用过 mtl——本章把它们接上"真可变"，并讲清为什么能又变又纯。

## 18.1 IO 到底是什么

把 `IO a` **想象**成（不是"是"——它是抽象类型）：

```haskell
type IO a = World -> (a, World)
```

一个动作吃一个世界，产出一个值和一个**新世界**。世界不能复制、不能回退、不能拆开
看——能做的只有用原始动作（`putChar`、`getChar`）操作它，并把动作按顺序组合。
组合运算正是 16 章见过的那两件：

```haskell
return :: a -> IO a              -- 不动世界，只产值；done = return ()
(>>=)  :: IO a -> (a -> IO b) -> IO b    -- 先做 p，把结果喂给 f，再做 f x
(>>)   :: IO () -> IO b -> IO b  -- p >> q = p >>= \_ -> q（丢弃左边的结果）
```

用 `>>` 定义 `putStrLn`，函数式的全部表达力都在：

```haskell
putStrLn xs = foldr (>>) done (map putChar xs) >> putChar '\n'
```

**为什么没有 `IO a -> a`（为什么"进了 IO 就出不去"）**？原书的反例：假设有 `runIO`，
写 `int = x - y where x = runIO readInt; y = runIO readInt`——`int` 的值取决于 x、y
**哪个先求值**，而 Haskell 是惰性语言，规范不规定求值顺序。IO 动作必须有确定的顺序，
而唯一能给顺序的，就是把它们关在 `IO` 里用 `(>>=)` 串。（标准库有个后门
`unsafePerformIO`——名字就是文档，别用。）

## 18.2 单子家族与定律（要点回顾）

不止 IO 是单子。谦逊的列表（`xs >>= f = concat (map f xs)`）和 `Maybe`（`Nothing`
短路整条链）都是——16 章已经手写过。原书 10.2 的两个观察值得重申：

- **do 记法是糖**：`do { x <- p; f x }` 翻译成 `p >>= f`，就像列表概括翻译成
  `map/concat`。最后一个语句必须是动作；`do { p; stmts } = p >> do { stmts }`。
- **单子定律三种说法**（16 章讲过 do 版，这里补第三种）：

```haskell
-- ① return 是 >>= 的右单位元：   p >>= return = p
-- ② return 是 >>= 的左单位元：   return e >>= f = f e
-- ③ >>= 结合律：                 (p >>= f) >>= g = p >>= (\x -> f x >>= g)
-- 第三种：Kleisli 复合 (>=>)，像函数复合但从左到右：
f >=> g = \x -> f x >>= g
-- 定律变成：return 是单位元、(>=>) 可结合——一个幺半群。"monad" 或许就是
-- "monoid" 的双关（原书的冷知识）。
```

## 18.3 State 单子：把状态串进"隐形线程"

16 章手写过 `State s a = s -> (a, s)`；标准库（mtl/transformers）给了成品：

```haskell
put  :: s -> State s ()                -- state (\_ -> ((), s))
get  :: State s s                      -- state (\s -> (s, s))
state :: (s -> (a, s)) -> State s a
runState :: State s a -> s -> (a, s)   -- ← State 能"跑出来"，IO 不能！
evalState :: State s a -> s -> a       -- = fst . runState
```

`IO` 的"世界"不可暴露，`State` 的状态 `s` **可以**——这正是两者的本质区别。
原书的骰子例子（示例 Ch18 实测）：

```haskell
rnd :: (Int, Int) -> Seed -> (Int, Seed)      -- 伪随机原语（示例用 LCG 实现）

-- 版本一：显式串联种子——两个骰子就要两层 where
diceExplicit n = (x, y)
  where (x, s1) = rnd (1,6) (mkSeed n)
        (y, _)  = rnd (1,6) s1

-- 版本二：State 单子——种子线程被 >>= 藏起来
throwDie = do s <- get
              let (v, s') = rnd (1,6) s
              put s'
              pure v
diceState n = evalState ((,) <$> throwDie <*> throwDie) (mkSeed n)
```

两版值相同（runtests 断言）。书里的追问：**要掷五个骰子**（大话骰）呢？版本一的
where 串联五层，极易写错；版本二只是把 `throwDie` 多写几遍。**可扩展性藏在类型设计里**。
另一个细节：State 有**惰性/严格**两版（`Control.Monad.State` 默认惰性，
`.Strict` 每步 `seq` 状态）——`evalState (do { _ <- undefined; return 0 }) 1` 两版行为
不同，性能章（25）再算账。

## 18.4 ST 单子：真可变，但被封印

`ST s a` 长得像 `State s a`，**语义完全不同**：`s` 不是状态值，是**状态线程的标签**。
标签上挂着可变对象，对象只能在同一线程内被读写。第一种可变对象是**程序变量**
（命令式意义的变量——可以被赋值的东西）：`STRef s a`。

```haskell
newSTRef    :: a -> ST s (STRef s a)
readSTRef   :: STRef s a -> ST s a
writeSTRef  :: STRef s a -> a -> ST s ()
modifySTRef':: STRef s a -> (a -> a) -> ST s ()
```

原书用斐波那契对照：Python 的 `a,b = b,a+b` 循环可以**几乎逐行直译**：

```haskell
fibST :: Int -> Integer
fibST n = runST $ do
    a <- newSTRef 0
    b <- newSTRef 1
    replicateM_ n $ do
        x <- readSTRef a
        y <- readSTRef b
        writeSTRef a y
        writeSTRef b $! x + y     -- $! 强制求和，否则惰性在这里堆 thunk
    readSTRef a
```

对照纯函数版 `fibPair`（元组递推）——两者线性时间同值（runtests 断言到 fib 90），
区别在空间姿势：程序变量版常数个格子反复用。

**`runST` 的类型是本章的智力高峰，逐字读**：

```haskell
runST :: (forall s. ST s a) -> a
```

`s` 被 `forall` **钉在参数内侧**（rank-2 多态）：动作对一切 `s` 都得能跑，因此它
**不可能**依赖 s 之外的信息。反例（原书）：

```haskell
let v = runST (newSTRef True)     -- newSTRef True :: ST s (STRef s Bool)
in  runST (readSTRef v)           -- ← 这行要 v :: STRef s' Bool，但 v 已带着前一个 s
```

如果类型检查放行，第一个 `runST` 里分配的引用就能在第二个 `runST` 里使用——
跨线程读写，结果取决于线程顺序，正是 18.1 里 IO 要避免的混乱。**类型系统直接
拒绝编译**：`STRef s a` 无法从 `runST` 逃逸。于是 `runST (fibST 30)` 得到一个
纯得不能再纯的 `Integer`——**可变性的全部效应被封在表达式内部**，外部世界看到
的仍是一个数学函数。"命令式函数式"这个词组就这么自洽了。

（rank-2 的手感：`[forall a. a -> a]` 类型的列表**只有两个元素**——`id` 和
`undefined`；`forall a. a -> a` 的普通列表 `[a -> a]` 可以装 `sin/cos/tan`。量词
钉在哪一层，信息就锁死在哪一层。）

## 18.5 STArray：原地数组

函数式的默认数据结构是列表，数组让命令式程序员亲切的原因是**破坏性更新**——
改一个格子，旧数组就没了。函数式的结构是**持久的**（改了旧的还在），代价是拷贝。
ST 单子给了第三条路：**STArray s i e**——真数组、原地写、但封在 `runST` 里。

```haskell
newListArray :: (Int, Int) -> [e] -> ST s (STArray s Int e)  -- 用列表灌一个数组
readArray / writeArray / getElems                           -- 读 / 写 / 全部倒回列表
```

示例 Ch18 用它写了三件套：

```haskell
bsortST xs = runST $ do                 -- 冒泡：原地交换，O(1) 额外空间
    let n = length xs
    a <- mkArr (1, n) xs
    forM_ [n, n-1 .. 2] $ \j ->         -- 每轮把最大者冒到位置 j
        forM_ [1 .. j-1] $ \k -> do
            u <- readArray a k; v <- readArray a (k+1)
            when (u > v) $ writeArray a k v >> writeArray a (k+1) u
    getElems a

shuffleST xs seed0 = ...                -- Fisher-Yates 洗牌：种子线程化，确定性可复现
labelsST n = ...                        -- STRef 计数器自增发标签：程序变量的"i++"
```

原书 10.5 的招牌是**原地快速排序**（`qsortST` + `partition`：以首元素为枢纽、
双端收缩、最后归位）和**哈希表**（BFS 的 visited 集合用"下标 k 存哈希为 k 的位置列表"
的数组，成员测试均摊 O(1)）——思想同款、篇幅更长，值得去原书细读那两页；本教程的
`bsortST/shuffleST` 把同一套工具（`newListArray/readArray/writeArray/getElems + runST`）
完整走了一遍。数组区间的忠告照抄：**左闭右开 `[a, b)` 几乎总是处理数组的最好选择**。

## 18.6 不变数组：Data.Array

不动数组也要有：`Data.Array` 的 `Array i e` 是**纯**数组——接口纯函数式，底层实现
可变：

```haskell
listArray :: (Int, Int) -> [e] -> Array Int e    -- 列表灌数组
elems     :: Array i e -> [e]                    -- 倒回列表
(!)       :: Array i e -> i -> e                 -- 索引——部分函数（越界即 ⊥）
accumArray :: (e -> v -> e) -> e -> (Int,Int) -> [(Int,v)] -> Array Int e
-- elems (accumArray f e (l,r) ivs)  ==  [ foldl f e [v | (i,v) <- ivs, i == j] | j <- [l..r] ]
```

`accumArray` 是隐藏的宝藏：对每个下标把一串值**累积**进格子。原书的例子是图的
邻接表——`accumArray (++) [] (1,n) [ (j, [k]) | (j,k) <- edges ]` 一行把边表分组
成邻接表，线性时间。`(!)` 记得是部分函数（09 章的规矩）。

## 18.7 坑位清单

1. **`newListArray` 在多态上下文里类型歧义**：`a <- newListArray (1,n) xs` 报
   `Could not deduce MArray`——用一个具体签名的小辅助（`mkArr = newListArray`，
   签名钉死 `STArray`）消解，或开 `ScopedTypeVariables` 加类型注解（18.5，实测）。
2. **`runST`/`ST` 要从 `Control.Monad.ST` 导入**——`Data.STRef` 只带引用三件套
   （18.4，实测）。
3. **`forM_` 丢结果**：发标签要收集列表用 `forM`；`forM_` 只为副作用（18.5，实测）。
4. **`writeSTRef b $! x + y` 别忘 `$!`**：惰性求值会把未强制的和堆成 thunk——
   常数空间变线性空间（18.4，原书原话）。
5. **`STRef` 不能逃出 `runST`**：rank-2 类型是封印不是障碍——看到
   `Couldn't match type s with s1` 类错误，是在告诉你"跨线程走私被拦下"（18.4）。
6. **State 有惰性/严格两版**：`Control.Monad.State` 默认惰性；严格场景换
   `.Strict`（25 章给实测对照）（18.3）。

## 18.8 练习（选自原书第 10 章习题）

**练习 18.1（运算互定义）**：用 `(>>=)` 定义 `(>>)`；用 `foldr (>>) done . replicate`
定义 `repeatFor n`（把一个动作重复 n 次——`replicateM_` 的前身）。

**练习 18.2（Kleisli 对偶）**：`(>=>)` 从左到右复合；定义从右到左的对偶
`(<=<) = flip (>=>)`，并用它把 18.2 的三条定律各写一遍。

**练习 18.3（大话骰）**：把骰子从两个扩到五个（`dice5 :: Int -> [Int]`）：显式串联
版写一遍、State 版写一遍，体感两条路在扩展时的差别（书里的 liar dice 原题）。

**练习 18.4（诚实回答）**：`evalState (do { _ <- undefined; return 0 }) 1` 在惰性
State 和严格 State 下各返回什么？先猜再试（答案：惰性版 `0`——`_ <-` 绑定不使用的
值不强制它；严格版异常——`>>=` 先算左边）。
