被讨论的程序片段:
  x = input;        // 从输入流读一个整数
  output x / x;     // 输出 x 除以 x

== 编译器的视角 ==
  知道: 语法合法; 除法两侧类型都是 int; 可以生成可执行代码
  不知道: 运行时输入是否为 0 —— 若 x=0 则触发除零

== lint 风格规则检查器的视角 ==
  知道: 按预置规则匹配可疑模式 (硬编码常量除法、某些 API 误用)
  不知道: 本例两侧都是同一个变量, 规则库未必覆盖, 可能漏报

== 静态分析器的视角 ==
  知道: input 可能产生任意整数, 包括 0 (可靠近似)
        因而 x 的可能取值集合包含 0, 除法可能除零
  代价: 它也会把'事实上不会为 0'的情形报成可能 —— 可靠但不精确

静态分析的四类应用:
  1. 程序验证   证明程序满足性质 (如永远不会空指针解引用)
  2. 缺陷发现   在部署前找出除零、资源泄漏、缓冲区越界
  3. 编译优化   常量传播、死代码消除、寄存器分配都依赖分析
  4. 安全分析   信息流(污点)分析、恶意行为筛查
