# 第 3 章　TIP 语言：被分析的对象长什么样

## 3.1 为什么先认识被分析的语言

静态分析的每一个结论都是相对某个具体语言的语义而言的：说“这里可能除零”，
前提是这门语言把整数除以零规定为错误；说“这个函数总是返回 int”，
前提是这门语言只有整数这一种值。因此在动手构造分析之前，
必须先把被分析的语言本身看清楚：它有哪些语法构造，每个构造运行时做什么。

本书使用的 TIP（Tiny Imperative Programming Language）是《Static Program Analysis》
为教学设计的小型命令式语言。它小到可以在十几页内定义完整，
又保留了令静态分析真正困难的全部要素：循环、递归、函数参数、
一等函数值、指针、记录。本章先做一次全景导览，并把 TIP 的三个经典小程序
用 C++ 对照实现一遍，让“这些构造运行时是什么意思”在进入形式化之前先有体感。

## 3.2 TIP 的世界观：只有整数

TIP 最醒目的设计是它把世界简化成整数。

- 唯一的基本数据类型是**任意精度整数**（本书实现按机器 `int` 处理，教学示例不触边界）；
- 比较运算 `>`、`==` 的结果也是整数：成立得 `1`，不成立得 `0`，条件位置上非 0 即真；
- 程序通过特殊表达式 `input` 从输入流读取整数，通过语句 `output E` 向输出流写入整数；
- `main` 函数的参数在程序启动时从输入流依次填入，之后出现的 `input` 继续向后读。

“只有整数”带来的一个直接好处是：分析器不需要区分“这是 int 还是 float”，
类型系统（第 17–20 章）可以把注意力集中到真正有趣的地方——指针、记录与函数。

## 3.3 表达式的六个家族

TIP 的表达式可以归成六组，本章程序的总览表把它们列成三行。

1. **字面量与变量**：整数字面量（`0`、`17`）、变量引用（`x`）、`input`。
2. **二元运算**：算术 `+ - * /`，比较 `> ==`。所有二元运算都是左结合，
   乘法优先级高于加法，与常识一致。
3. **函数调用**：`E(E,...,E)`。被调位置是一个**表达式**而不只是函数名——
   因为 TIP 的函数是一等值，可以作为参数传递（见 3.6 节的 twice）。
4. **指针**：`alloc E` 分配一个新单元，初值为 `E`；`&x` 取变量的地址；
   `*E` 解引用；`null` 是空指针。
5. **记录**：`{f: E, g: E}` 构造记录，`E.f` 访问字段。字段名是静态的。
6. **括号与负号**：`(E)` 改变结合；`-E` 是一元前缀。

## 3.4 语句与程序结构

TIP 的语句有六种形状。

- **赋值**：`lvalue = E;`，赋值目标（lvalue）只能是变量 `x`、指针解引用 `*E`、
  字段访问 `E.f`，以及它们与字段的组合 `(*E).f`、`x.g`。
- **输出**：`output E;`。
- **条件**：`if (E) stmt` 或 `if (E) stmt else stmt`。
- **循环**：`while (E) stmt`。
- **块**：`{ stmt* }`，把若干语句当成一条。
- **返回**：每个函数体的最后一条必须是 `return E;`。

一个 TIP 程序就是一组**函数声明**：

```tip
name(p1, p2, ...) {
  var x, y, ...;       // 可选的局部变量声明
  语句...
  return E;
}
```

函数参数无须声明类型（世界里只有整数和它的复合），
局部变量必须先在 `var` 中列出再使用。函数可以互相调用，包括递归，
也可以在文本中先使用后定义——名字解析（第 10 章）会处理。

## 3.5 三个经典小程序与 C++ 对照

为了让上述构造的运行时含义落地，本章程序用 C++ 实现了 TIP 教材中的三个函数，
让它们都计算 `5!`，并断言三个结果都是 120。

### 3.5.1 ite：while 循环

TIP 教材的 `ite` 用循环计算阶乘：

```tip
ite(n) {
  var f;
  f = 1;
  while (n>0) { f = f*n; n = n-1; }
  return f;
}
```

C++ 对照版 `iter` 与其逐行同构：`f` 从 1 开始，`while (n > 0)` 内累乘并递减。
这对应总览表中的“语句：赋值 | if-else | while | 块 | return”。

### 3.5.2 rec：递归调用

把同一个定义换成递归形式：参数为 0 时返回 1，否则 `n * rec(n-1)`。
C++ 版 `recf` 展示了 TIP 函数可以直接按名字自调用——
函数声明在全局可见，文本先后顺序不影响。

### 3.5.3 foo：指针参数与 alloc

教材的 `foo(p,x)` 是指针路径的代表：`p` 指向一个单元，函数沿指针读条件，
用 `alloc 0` 造一个辅助单元，再把辅助单元的地址传给递归调用。
C++ 版 `foop` 用 `std::unique_ptr<int>` 模拟这一形状：

- `auto p = std::make_unique<int>(x);` 对应调用者把 `&x` 传进来；
- `if (*p == 0)` 对应沿指针读取条件；
- `auto q = std::make_unique<int>(0); *q = *p - 1;` 对应 `alloc 0` 后写入；
- `foop(*q)` 对应把辅助单元的内容作为递归参数。

三条路径——循环、递归、指针——得到同一个答案 120，
这不是巧合而是**同一个数学函数的三种表达**。第 2 章 Rice 定理所说的“语义性质只取决于
计算什么、不取决于怎么写”，在这里恰好有一个最小实例：三个写法不同，
但计算的部分递归函数相同，任何只看语法形状的规则都无法穷尽它们，
而静态分析必须对三者给出同样正确的结论。

## 3.6 一等函数：twice 与 inc

TIP 还有一个本章总览表通过“函数调用”行暗示、但值得单独点出的特性：
函数是**一等值**。教材例子：

```tip
twice(f,x) { return f(f(x)); }
inc(y)    { return y+1; }
main(z)   { return twice(inc,z); }
```

`twice` 的第一个参数 `f` 本身被当作函数调用，而 `main` 把 `inc` 当值传入。
这意味着看到 `f(...)` 时，分析器无法简单地在文本里查到唯一目标函数——
`f` 在不同调用点可能绑定不同函数。这迫使后续分析先回答
“这个被调表达式可能指向哪些函数”，即第 44 章的控制流分析（0-CFA）。
函数一等性是 TIP 虽小却能支撑过程间分析章节的关键设计。

## 3.7 从语言到分析：接下来三章的路线

认识 TIP 之后，静态分析需要的程序表示分三步建立：

1. 第 4 章用 ANTLR4 写出 TIP 的**文法**，把源文本解析成 parse tree；
2. 第 8 章在 parse tree 上构造精简的**抽象语法树（AST）**，
   去掉括号、分号、优先级等语法噪音——分析算法工作在 AST 上；
3. 第 10–11 章在 AST 上完成作用域解析与控制流图，
   把“名字指向谁”“控制从哪来到哪去”变成可查询的数据。

本章的 C++ 对照代码只服务于理解语义，它不属于分析器本身；
从下一章开始出现的代码才是分析器的组成部分。

## 3.8 工程注意点

- **语义欠定义处显式选择并写进正文**：TIP 教材对一些细节（如负数字面量、整数宽度）
  留有选择空间，本书一律在引入该构造的章节写明自己的选择，避免读者按另一套语义理解输出。
- **对照代码只为建立直觉**：C++ 版的三个函数刻意与 TIP 逐行同构，
  不引入额外抽象，否则“对照”反而变成理解负担。
- **总览表是固定文本**：TIP 语法不会在本书后续章节增删构造，
  因此总览表可以作为一张贯穿全书的参照。

## 3.9 本章代码

```cpp
// file: src/main.cpp
// 第 3 章配套程序：TIP 语法构造总览 + 用三种方式计算 5 的阶乘。
// iter  —— 对应 TIP 的 ite：while 循环
// recf  —— 对应 TIP 的 rec：递归调用
// foop  —— 模拟 TIP 的 foo：指针参数 + alloc 出来的辅助单元
#include <iostream>
#include <memory>

int iter(int n) {
    int f = 1;
    while (n > 0) {
        f = f * n;
        n = n - 1;
    }
    return f;
}

int recf(int n) {
    int f;
    if (n == 0) { f = 1; }
    else { f = n * recf(n - 1); }
    return f;
}

// 对应 foo(p, x)：p 指向输入值，沿指针读条件；
// q 模拟 alloc 0 得到的辅助单元。
int foop(int x) {
    auto p = std::make_unique<int>(x);
    int result;
    if (*p == 0) {
        result = 1;
    } else {
        auto q = std::make_unique<int>(0);
        *q = *p - 1;
        result = (*p) * foop(*q);
    }
    return result;
}

int main() {
    using namespace std;

    cout << "TIP 语法构造总览:\n";
    cout << "  表达式: 整数字面量/变量/input | 二元算术与比较 | 函数调用\n";
    cout << "          alloc/&/*/null (指针) | 记录字面量与字段访问\n";
    cout << "  语句:   赋值 | output | if-else | while | 块 | return\n";
    cout << "  程序:   函数声明的集合; main 的参数从输入流依次读入\n\n";

    int a = iter(5), b = recf(5), c = foop(5);
    cout << "factorial: " << a << ' ' << b << ' ' << c << '\n';
    if (a != 120 || b != 120 || c != 120) {
        cerr << "factorial mismatch\n";
        return 1;
    }
    cout << "[chapter 03 OK]\n";
    return 0;
}
```

## 3.11 小结

TIP 用“只有整数”的极简世界换来了定义的完整可读，同时保留了六大类表达式、
六种语句、递归、一等函数、指针与记录——静态分析面对的困难构造一个不少。
三个阶乘实现让“不同写法、同一语义”有了具体例子，也预示了分析的立场：
工具必须对所有写法一致地可靠。下一章进入工程环节，用 ANTLR4 的文法
把 TIP 文本解析成结构化的 parse tree。
