# 第 28 章　指针与别名：把"地址会流向哪里"算清楚

## 28.1 问题：名字不再等于存储

### 28.1.1 从一个最小的"意外"开始

第 8 章我们让 TIP 真正跑在 LLVM 上时，每个变量都对应一块固定的栈槽：
`x = 3;` 把整数 3 存进 `x` 的槽，`output x;` 从同一个槽里取出来。变量
名与存储位置是一一对应的——看到一个名字，就等于看到一块位置。前面所
有数据流分析（第 17 章的符号与常量、第 18 章的经典数据流框架、第 20
章的区间、第 22 章的路径敏感）都暗暗依赖这个对应：状态是一张"名字 →
抽象值"的表，赋值语句只修改左值那一个名字对应的格子。

本章的 TIP 多了三个构造，这个一一对应当场被打破。第一是动态分配
`alloc e`，它在运行时向堆要一块新存储，返回的不是整数，而是这块存储
的**地址**。第二是取地址 `&x`，变量 `x` 的栈槽地址可以像普通值一样被
读出、传递、存进别的变量。第三是空指针 `null`，一个"不指向任何位置"
的特殊地址值。配合已有的解引用 `*p`——沿地址找到那块位置并读/写——
我们可以写出这样的程序：

> `p = &x; *p = 5; output x;`

逐行看运行时发生了什么：第一行把 `x` 的槽地址存进 `p`；第二行沿 `p`
里的地址找到的正是 `x` 的槽，把 5 写进去；第三行输出 `x`，结果是 5。
请注意第二行：源码里**没有出现 `x` 的名字**，被修改的却是 `x` 的存
储。"赋值改的是左值名字"这个我们用了二十多章的直觉，在这里彻底失灵
了。赋值语句的效果取决于 `p` 里装的是哪个地址，而地址是运行时计算出
来的值。

### 28.1.2 别名：多个名字，同一块位置

上面三行程序里，`p` 与 `x` 的关系有个专门的名字：**别名**（aliasing）。
如果在某个程序点上，两个表达式可能指向同一块存储位置，就称它们互为
别名。`p = &x` 之后，`*p` 与 `x` 是别名——对 `*p` 的写就是对 `x` 的
写。别名本身不是 bug，它是指针表达力的来源：调用方把变量地址传给函
数，函数体通过形参里的地址"隔空"修改调用方的变量，靠的就是别名。

但别名也是大量程序错误与分析困难的共同根源。先看分析为什么变难。第
19 章的可能未初始化分析按 kill/generate 记账：遇到 `x = e;`，事实集里
杀掉 `x`、生成 `e` 中引用的变量。这套机制的隐含前提是"这次赋值只影
响 `x` 这一个名字"。当左值是 `*p` 时，真正被写的名字集合是"`p` 可能
指向的全部位置"对应的那些变量——可能一个，也可能十个，分析在到达这
个点之前必须先回答"p 里可能装着哪些地址"。不知道这个集合，就无法判
断一次写操作会不会波及某个看起来毫不相干的变量。

再看一个具体的精度损失场景，本章后面的 `ptr.tip` 就是它的完整版：

> `x = alloc 10; y = alloc 20; p = &x; *p = y; output x;`

没有指针分析时，保守的编译器必须假定 `*p = y` 可能改写程序中的**任何**
变量（因为不知道 `p` 指向谁）。于是 `x` 的值在这次赋值后变成"未知"，
后续所有依赖 `x` 的优化全部失效。而真实情况是 `p` 只可能指向 `x`，这
次写除了 `x` 谁也不碰。指针分析的价值就体现在这里：它把"可能改任何
变量"收紧成"只可能改这一个变量"，把被别名吓停的优化重新解放出来。

### 28.1.3 把问题倒过来看：先问"地址流向哪里"

现在把本章要解决的问题精确化。程序里有两类东西必须分开记账。一类是
**指针变量**（以及保存地址的表达式），运行时它的取值是一个地址集合中
的某一个；另一类是**位置**（location）——栈槽与堆块——它是地址所指
向的目标。一次解引用 `*p` 的语义可以拆成两步：先取 `p` 当前的地址
值，再访问这个地址对应的位置。

地址和整数在运行时都是一个字宽的值，但它的"取值空间"完全不同：整数
变量的值域是全体整数，指针变量的值域是"程序执行中真实存在的那些位
置"。这个观察是指针分析的出发点：**我们不关心地址的具体数值，只关心
它可能是程序中哪一类位置。** 真实地址由操作系统与分配器决定，每次运
行都可能不同，对它做整数式的区间分析既不可能也无意义；而"第 3 行那
次 alloc 得到的块"、"变量 x 的栈槽"这样的**位置标签**是静态可知、跨
运行稳定的。

于是指针分析（pointer analysis）可以这样概括：对程序中每个指针表达式
的每个相关程序点，静态估计它的**指向集**（points-to set，简称 pts 集）
——它可能等于哪些带标签的位置。有了指向集，别名关系立刻可以读出：
`*p` 与变量 `x` 在某点可能是别名，当且仅当 `p` 在该点的 pts 集里含有
`x` 的位置标签。本章把分析粒度取在"整个程序、合并所有路径"的层级（不
为每个程序点分别记账，也不区分调用上下文），这是最经典也最常用的设
置；第 29 章会说明如何把它重新放进按点、按上下文的一般框架。

### 28.1.4 本章的两个答案：包含与合一

同一个问题——"每个指针指向哪些位置"——历史上给出了两个风格迥异的
答案，本章把它们都实现出来并放在同一份输出里对照。

第一个答案是 **Andersen 分析**（Lars Ole Andersen，1994）。它把程序翻
译成一组**包含约束**（inclusion / subset constraints）：位置的 pts 集之
间是"左边包含右边"的关系，例如 `a = b` 被翻译成 `pts(a) ⊇ pts(b)`。
所有约束的**最小不动点**就是答案：从空集出发，反复按约束把右边的元
素并入左边，直到没有新元素可加。包含式分析保留了方向——`a` 与 `b`
并不因此等价，信息从右向左流——所以精度高；代价是最坏情况下立方的
时间复杂度。

第二个答案是 **Steensgaard 分析**（Bjarne Steensgaard，1996）。它把同
一条语句读成一个**等式**：`a = b` 意味着 `a` 与 `b` 应当是同一个东西，
于是让它们在并查集里**合一**（unify）。一旦两个变量合一，它们的 pts
集永远相同，双向影响。合一丢弃了方向，却换来近线性的时间和极简的实
现，是早期工业编译器（包括特定配置下的 GCC）能够负担整程序分析的关
键。代价是 pts 集只会更大、更不精确：两个本来只是单向流动的变量被当
成完全等价，其中一个变量指向的位置会"倒灌"给另一个。

### 28.1.5 共同的底线：两种结果都必须 sound

和第 24 章的精度阶梯一样，本章两种分析的差别是**信息量**的差别，不是
真伪的差别。在动手实现之前先把这条底线钉死：

> 运行时 `p` 真正取到的每一个地址，其位置标签都必须出现在分析给出的
> pts(p) 中。

对 Andersen 与 Steensgaard，这条要求完全相同。Steensgaard 的 pts 集可
能包含运行时永远不会发生的位置（它更不精确），但不会漏掉任何真实位
置；漏掉一个，就可能把一次"可能写 x"误判成"不可能写 x"，据此做出的
优化就是错的。本章会形式化地证明：Steensgaard 的 pts 集逐点是
Andersen pts 集的**超集**——既然 Andersen 的结果已经包含全部真实地
址，更大的 Steensgaard 结果自然也包含。两种分析的输出因此可以互相交
叉校验：若某次运行 Steensgaard 反而比 Andersen 更窄，那一定是实现出
了 bug，而不是"分析更聪明"。

为了让"包含真实地址"不停留在口头，本章还把第 8 章的 ORC JIT 执行台
扩展到指针片段：`alloc` 真实地调用 `malloc` 拿到堆块，`*p` 是真实的内
存读写。`--verify-soundness` 先静态列出每个解引用点"是否可能解引用
null"，再对若干组输入真实执行程序：凡正常跑完，就证明该组输入下没有
发生 null 解引用。静态结论与真实行为两相对照，读者可以亲眼看到"保守"
与"撒谎"的边界。

### 28.1.7 别名在真实语言里的三副面孔

别名问题不是 TIP 的发明，三副真实面孔各有各的加重方式。C 里
最阴的是数组退化与指针算术：p = a + i 之后 p 与 a+i 是否同
址，静态要看 i 的值域——第 20 章的区间分析在这里与指针分析
联姻（区间决定别名、别名决定读写集合）。Java 没有取址，但引
用的等价性把别名问题原样保留：两个名字指向同一对象时，任
何 setter 都"穿透"另一个名字的缓存假设——JIT 的逃逸分析
（判断对象是否逃出方法，决定能否栈上分配）本质是本章分析
的调用图增强版。Rust 的借用检查器从类型系统层面消灭了别名
（写借用排他），但 Box 内的堆仍然有地址、dyn 分发仍然有目
标集合——第 27 章的结尾提过的两章合流点在 Rust 编译器里同
样存在。三副面孔共同的教训：**别名是"存储的身份"问题，语
言换了皮，问题不换骨**——分析器要折叠的始终是"哪次分配可
能在这里"。

### 28.1.8 用户的视角：一条告警的生命周期

站在分析用户（而非实现者）的视角，把 possibly-null 这条告警
的一生走一遍，能看清静态分析在工程里真正的位置。出生：求
解器关账后，判定层扫描 Deref 点、查 null 成员——告警在
expected 文件里定格为第 n 行。送达：它出现在 CI 的日志、
IDE 的波浪线、或 code review 的机器人评论里——送达的形状
决定它的第一印象。被读：用户扫一眼上下文——input 守卫、
分支条件——两秒钟内做出"真/假/存疑"的直觉判定（本章程序
里守卫就在三行之内，直觉命中率极高）。被处置：假的加注
释或局部重构消掉（把守卫写进分析能看见的形状），真的改
代码，存疑的挂起。退役：下一版代码里它消失或变形。整个
生命周期里，分析器只负责"出生"一环——后面四环全是人的工
作。这就是为什么 28.9.6 说可用性由假告警率决定：送达环节
的信噪比，直接决定"被读"环节的用户耐心。教程把这条生命
周期写进正文，是因为它常被教科书省略——算法只是手段，可
被读懂的告警才是产品。

## 28.2 指针世界的形式化

### 28.2.1 抽象位置：把"每个地址"折叠成"每类地址"

先精确界定运行时语义。本章 TIP 程序执行中，地址可能指向两类位置：

- **栈位置**：每个函数的形参与局部变量各占一个槽，地址由 `&x` 取得；
- **堆位置**：每次执行 `alloc e` 表达式时新建的块。

如果把每次循环、每次递归调用里的同一个 `alloc` 表达式都当成不同位
置，位置数目在运行时无界，静态分析无法穷尽。标准做法是按**语法点**
折叠：同一个 `alloc` 表达式在概念上是同一个**抽象位置**（abstract
location），运行时它代表的全部具体块都归到这个标签下。这与第 13 章
把"全体整数"折叠成三个符号、第 24 章把"调用历史"截断成最近 k 个站点
是同一种抽象动作：**丢弃"同一句语句被执行多少遍"这一维度。**

本章的抽象位置标签采用一套简单的命名约定，约束生成器与两个求解器共
同遵守，正文读输出时也直接引用：

- 变量 `x` 的栈位置（仅在 `main` 中）标签就是 `x`；其他函数里的变量
  `x` 标签为 `函数名.x`，避免不同函数的同名变量混淆；
- 第 n 个编号到的 `alloc` 点标签为 `L1、L2、…`（生成器按遍历顺序编
  号）；
- `&x` 产生的标签写作 `&x`，但 28.2.4 节会说明它不是一个新位置；
- 空指针标签为 `null`。

一个指针变量 `p` 的 pts 集就是上述标签构成的有限集合。例如
`pts(p) = {L1, null}` 读作"`p` 在某条路径上可能指向第一次 alloc 的
块，在另一条路径上可能为空，但不会指向任何变量的栈槽"。

### 28.2.2 程序被翻译成四类约束

任何只涉及指针的语句，都可以归约成下列四类约束之一。形式化记号里
`a、b` 是程序变量（或代表表达式结果的临时位置），`s` 是一个抽象位置
标签：

- **New**：`New(a, s)`，读作 `pts(a) ⊇ {s}`。来源有三种：`a = alloc e`
  （s 是该 alloc 点的 L 标签）、`a = &z`（s = &z）、`a = null`
  （s = null）；
- **Copy**：`Copy(a, b)`，读作 `pts(a) ⊇ pts(b)`。来源是 `a = b` 这类
  指针间直接赋值，也包括调用时实参到形参的绑定；
- **Load**：`Load(a, b)`，读作 `pts(a) ⊇ pts(*b)`——`a = *b` 的语义。
  它是一条"条件"约束：只有当某个位置 `v` 进入 `pts(b)` 后，才产生具体
  的包含关系 `pts(a) ⊇ pts(v)`；
- **Store**：`Store(a, b)`，读作 `pts(*a) ⊇ pts(b)`——`*a = b` 的语
  义。同样是条件约束：`v` 进入 `pts(a)` 后产生 `pts(v) ⊇ pts(b)`。

New 与 Copy 是无条件的：约束写下来就立即生效。Load 与 Store 的右半部
分藏着一次解引用，必须等 pts 集"长出"相应位置后才能展开——这是指针
分析求解器比第 17 章单调框架微妙的根本原因：**约束的数量与形状本身随
求解过程增长。** 28.2.3 节把这种增长写成显式的闭包规则，实现时再把它
压回读者熟悉的 worklist。

### 28.2.3 Andersen 的四条闭包规则

Andersen 分析的解，是同时满足下列四条规则的最小 pts 集族。前两条对应
无条件约束，后两条把 Load/Store 的"条件"在新位置到达时当场展开：

1. **（New 规则）** 若存在约束 `New(a,s)`，则 `s ∈ pts(a)`；
2. **（Copy 规则）** 若存在 `Copy(a,b)` 且 `s ∈ pts(b)`，则
   `s ∈ pts(a)`；
3. **（Load 规则）** 若存在 `Load(a,b)` 且 `v ∈ pts(b)`，则
   `pts(a) ⊇ pts(v)`；即对每个 `s ∈ pts(v)`，有 `s ∈ pts(a)`；
4. **（Store 规则）** 若存在 `Store(a,b)` 且 `v ∈ pts(a)`，则
   `pts(v) ⊇ pts(b)`；即对每个 `s ∈ pts(b)`，有 `s ∈ pts(v)`。

这四条规则都是"把已经成立的事实从右边搬到左边"，没有任何一条能凭空
造出一个抽象位置。最小不动点可以从全体空集出发，反复应用规则直到饱
和得到。用第 14 章的术语说：每条规则都是定义在"`2^位置` 的乘积"上的
单调算子——pts 集只增不减，规则的触发条件是包含关系——因此 Knaster–
Tarski 定理保证最小不动点存在且从底迭代可达到。这就是 Andersen 分析
终止性的理论根据，28.11 节会补上有限性论证（位置与规则实例的总数都
有界）。

把规则 3、4 与规则 2 对照着看，会发现一个实现上的关键简化：Load 展开
后得到的 `pts(a) ⊇ pts(v)` 与 Store 展开后得到的 `pts(v) ⊇ pts(b)`，形
状都只是一条新的 **Copy 关系**。因此求解器不需要第四种数据结构：每当
`v` 新进入某个基址的 pts 集，就把对应的 Copy 边动态登记进去，之后全
部按 Copy 规则处理。这正是 28.5 节代码里 `copyOut` 表在循环中被不断加
入新目的的原因。

### 28.2.4 地址链接：&z 为什么不是一个新位置

这里有一个极易写错的细节，本章实现中真的栽过，值得专门形式化。看约束
`a = &z`：它生成 `New(a, &z)`，即 `pts(a) ⊇ {&z}`。如果求解器把 `&z`
当成一个与程序变量 `z` 毫无关系的独立标签，会发生什么？

设想后面有 `b = *a;`。按 Load 规则，`a` 指向 `&z`，于是
`pts(b) ⊇ pts(&z)`。可 `pts(&z)` 是什么？在"独立标签"的错误解释里，
`&z` 这个键名下从未被任何 Store 写过，pts 集是空的——于是 `b` 一无所
获。但运行时语义清清楚楚：`a` 里装的是 `z` 的槽地址，`*a` 读到的就是
`z` 的值，`pts(b)` 应当包含 `pts(z)` 指向的位置。抽象与具体在这里对不
上，分析从 sound 变成了漏报。

正确的解释是：**标签 `&z` 与程序变量 `z` 是同一个抽象位置的两个名
字。** 它们必须"链接"起来——对 `&z` 的 pts 集做的任何推导，等价于对
`z` 的 pts 集做同样的推导，反之亦然。在 Andersen 的包含式框架里，这
等价于预先登记两条 Copy 关系：

> `pts(&z) ⊇ pts(z)` 且 `pts(z) ⊇ pts(&z)`。

两条方向都要：Load 经 `&z` 要能读到 `z` 的存量，Store 经 `&z` 写入也要
能更新 `z`。链接必须在处理任何 New 种子**之前**就位，之后规则 2 的普
通传播自动让两边保持一致，求解器不需要为它写特殊代码。28.10.3 节会
回到这个细节，用具体不变式说明少了它会漏掉哪一类真实地址。

### 28.2.5 Steensgaard：用项的合一代替集合的包含

Steensgaard 分析换了一个读程序的角度。在它看来，语句陈述的不是"流向"
而是"等同"：

- `a = b` 陈述"`a` 与 `b` 是同一个东西"——把两者**合一**；
- `a = alloc e` 陈述"`a` 指向一个新块"——`a` 的指向集合里加入该
  alloc 标签；
- `a = *b` 陈述"`a` 等于 `b` 所指向的东西"——为 `b` 找一个（若还没有
  就新建的）**指向节点**，把 `a` 与它合一；
- `*a = b` 陈述"`a` 所指向的东西等于 `b`"——同样为 `a` 准备指向节
  点，把该节点与 `b` 合一。

实现这套规则的标准数据结构是带字段的并查集。每个节点有三个要素：一
个父指针（路径压缩）、一个**位置标签集**（该等价类已知指向哪些抽象位
置）、以及一个**指向节点**（该等价类的"值"指向哪个等价类——这是把
`a` 与 `*a` 的关系直接建在图里）。合一两个节点时要做三件事：小类挂
到主类、标签集取并集；若两边都有指向节点，指向节点也要递归合一；若
只有一边有，主类把它接管过来。

与 Andersen 的"一个位置一个 pts 集、按需逐元素加入"相比，这里的差别
是**时机**与**方向**。时机上，Steensgaard 在看到语句的当下就把两个变
量绑死，哪怕它们真正共享的位置要到后面才出现；方向上，`a = b` 本是
`pts(a) ⊇ pts(b)` 的单向关系，合一却让 `pts(a) = pts(b)`，于是未来进
入 `a` 的位置也会倒灌给 `b`。这两点合起来，就是 Steensgaard 更快却更
不精确的全部原因。

### 28.2.6 为什么 Steensgaard 的结果必然是超集

本章把两种结果并排打印，它们之间应当恒成立的关系值得先证清楚，因为
这正是 `--check` 输出的内在校验：

> 对每个程序变量 `v`：pts_Steen(v) ⊇ pts_Ander(v)。

论证思路是对语句逐条比较两种解释。Andersen 的每条包含关系都被
Steensgaard 的一次更"强"的关系覆盖：Copy `pts(a) ⊇ pts(b)` 被替换成等
价类合并，合并后两集相等（当然包含原来的单向关系）；Load/Store 中新
建的指向节点，在 Andersen 那边对应的是"等 pts 集真长出 v 后才登记的
Copy 边"，而 Steensgaard 提前合一时等价于把这条 Copy 边**双向**登记
——Andersen 最终会沿单方向到达的每一个标签，Steensgaard 都能到达，且
可能更多。形式化地对求解步数做归纳即得结论：Andersen 每加入一个标
签，该标签所在的等价类在 Steensgaard 解里早已（或同时）含着它。

这条关系也给了实现者一个免费的测试 oracle：跑任意程序，逐变量比对两
栏；一旦发现 Steensgaard 更窄，不必怀疑理论，一定是代码错了。本章开
发过程中，地址链接缺失的最初症状就是两栏同时变空——超集关系本身没
被破坏，但两个解一起漏掉了真实位置。这提醒我们：**超集校验能抓
"合一写错"，却抓不到"两种分析一起漏"**；后者要靠 28.9 节的真实执行
兜底。

### 28.2.7 四条规则从操作语义里长出来的方式

四类约束不是拍脑袋的清单，每一条都能从一句操作语义的规定里
推出来。规定一：`x = alloc e` 的语义是"新地址 a 装下 e 的值、
x 装下 a"。抽象化：地址按语法点折叠成 L，"x 装下 L"即
New(x,L)。规定二：`x = y` 是值的搬运，"y 装的一切 x 都可能装"
即 Copy(x,y)。规定三：`x = *p`——p 装的一切地址 o 处的内容流
向 x，即 Load：对每个 o ∈ pts(p)，Copy(x,o)。规定四：`*p =
y`——y 的内容写进 p 装的每个地址处，即 Store：对每个 o ∈
pts(p)，Copy(o,y)。四条规定（分配、搬运、链上读、链上写）就
是 TIP 指针片段的全部语义，约束系统是它们"可能世界版"的直译。
反过来读也成立：**任何一条约束都能指认出它来自哪句语义**——
这正是 28.10 的成员不变式能逐条对账的原因（28.10.2 做的就是
这件事）。读者将来给新语言写指针分析（比如带字段的对象），
同样从"语义规定 → 抽象折叠 → 约束形状"三步走：字段的
o.f 通道是"内容通道"按字段细化，四条规则各长出一个带字段的
变体，机制不变。

### 28.2.8 包含与合一：一条单向阀与一根焊条

Andersen 的 Copy(x,y) 是**单向阀**：信息从 y 流向 x，y 的集合
永不被 x 污染。Steensgaard 的 unite(x,y) 是**焊条**：两个名字
从合并那一刻起共享同一个未来。单向阀保精度（y 不陪绑）但每
条边都要反复过阀（工作表多次传播）；焊条保速度（每对节点至
多焊一次）但牺牲区分（合并即不可逆）。这对抉择在抽象解释的
语言里可以统一表述：两者都是幂集格上的单调算子，前者取**精
确的最小不动点**、后者取**它的一个上近似**（每步用更大的合并
代替精确传播）。28.2.6 证明了超集方向，这里补一句直觉：上近
似在格上就是"更高的点"，可靠性（成员不变式）对更高的点自动
保持——**保守化从不破坏 sound，只磨钝精度**。这条"单向磨
钝"原理贯穿全书：符号分析的 ⊤、区间分析的加宽、0-CFA 的集
合并、本章的合一，全是它的实例。

### 28.2.9 一个手算的最小系统

把 ptr.tip 的约束系统在求解之前完整写下来，是 28.4 与 28.5 之间
最好的桥。生成器吐出的静态约束五条：New(x, L1)、New(y, L2)、
New(p, &x)、Load(p, q)、Store(y, p)。加上地址链接的预处理产
物：双向通道 x ↔ &x。就这五行加一条通道，全部机制已在场。求
解要补的动态约束两条：Load 展开的 copy(&x, q)（当 &x 进入
pts(p)）、Store 展开的 copy(y, &x)（同一触发）。五行静态、两
行动态、一条通道——纸面上十分钟可以推完全部闭包，28.5.4 的
事件记录就是这份手算的流水账形态。给读者的建议：把 null
check.tip 的约束系统也这样写一遍（四条：两条 New、一次比较
不产约束、一次 Deref 是查询不是约束——查询与约束的区分在
28.4.3 有交代），两张纸贴在一起，生成器的行为就再无神秘。

### 28.2.11 流不敏感的精度上限：时间轴被压扁之后

流不敏感把"什么时候"折叠掉，只留"有没有"——这个取舍的精度
上限值得正面刻画。上限一：顺序无效。`p = &x; *p = y; q = *p`
与 `q = *p; *p = y; p = &x` 两个程序（后者几乎无意义）在分析
眼里相同——q 都拿到 x 的全部可能内容。上限二：分支无效。
alloc 支与 null 支并成 {L1,null}，守卫信息蒸发（28.3.4 的主
角）。上限三：重复无效。循环里十次 `*p = alloc` 只留一个
New（同一语法点），p 的集合不因次数膨胀——这反而是流不敏感
的红利：循环天然收敛，第 21 章的加宽在此免费。三个上限合
起来一句话：**pts 是"全执行历史的并集投影"，不是任何单一
时刻的快照**。要快照得加时间维（流敏感/路径敏感），要并集
的可靠性就接受投影——第 29 章的收集语义会给这句话一个严格
的数学形式（α 正是那个投影）。

### 28.2.12 把 pts 看成一个函数：域的另一种写法

pts 的类型是 Var → 2^Site，一个从变量到集合的函数——这在格
论眼里是"逐点序的函数格"：pts₁ ⊑ pts₂ 当且仅当每个变量的
集合都包含于。求解器的每次 rise 都是这个函数格上的一次上
升，最小不动点是全部约束的交……是"满足约束的最小元"。这
个视角与第 27 章"位置→标签集"的乘积格（27.5.8）完全同型，
甚至与第 13 章"变量→符号"的环境格同型——三种分析的解都是
"名字到域值的函数"，区别只在域值（符号 / 标签集 / 地址
集）与约束的形状（方程 / 传播 / 包含）。把这条线串起来，
"域"这个从第 13 章开始的词到此第三次就业：分析 = 域 + 约
束 + 不动点，三要素之外全是工程。

## 28.3 两个演示程序

### 28.3.1 ptr.tip：把别名、链上读、链上写凑齐

第一个程序刻意在十行内把本章全部要素各用一遍。它只有一个 `main`，
四个变量：两个堆块、一个栈槽地址、一次沿链的读、一次沿链的写：

#### programs/ptr.tip

主演示程序：六行凑齐 New、地址链接、Load、Store 与别名，28.3.3 逐行精读、28.5.4/28.6.5 两个 trace、28.7.2/28.9.1 两处对账的当事程序。

```cpp
// file: programs/ptr.tip
main() {
  var x, y, p, q;
  x = alloc 10;
  y = alloc 20;
  p = &x;
  q = *p;
  *p = y;
  output *q;
  return 0;
}
```

前两行先拿到两个堆块：`x` 指向装着 10 的块（标签 L1），`y` 指向装着
20 的块（L2）。第三行 `p = &x;` 让 `p` 指向 `x` 这个**栈槽本身**——
注意不是指向 L1，而是指向持有 L1 地址的那个槽。这一层区别是读懂整个
程序的钥匙。第四行 `q = *p;`：沿 `p` 找到的是 `x` 的槽，槽里装着 L1，
于是 `q` 得到 L1——此刻 `q` 与 `x` 是别名，都指向装 10 的块。

第五行 `*p = y;` 又是写 `x` 的槽：把 `y` 的值（L2）存进去。这一行之
后，`x` 改而指向 L2（装 20 的块）；但 `q` 是第四行时复制下来的地址，
它仍持 L1，不随 `x` 改变。最后 `output *q;` 沿 `q` 解引用读到的是 L1
块里的 10。所以程序真实输出是 10，而不是表面上"最后 x 指向 20"所暗
示的 20。这个程序因此同时演示了两件容易混淆的事：别名让 `*p` 的写穿
透到 `x`，而地址是按值复制的让 `q` 与后来的 `x` 脱钩。

从分析的角度预先核对期望结果。Andersen 应当算出：`p={&x}`（第三行唯
一来源）；`x={L1,L2}`（第一行赋 L1，第五行经 `*p` 写入 L2）；
`q={L1,L2}`（第四行 Load：`p` 指向 `x`，于是 `q ⊇ pts(x)`，求解到终点
时 `x` 已含 L1、L2）；`y={L2}`。注意 `q` 含 L2 是**不精确**而非错误：
静态分析不区分"`q` 在第四行复制"与"x 在第五行才改指 L2"的先后，它只
报告"可能"——真实执行走 L1，L2 永不发生，但 pts 集允许它。

### 28.3.2 nullcheck.tip：守卫过的解引用

第二个程序把 `null` 与条件守卫结合起来，回答一个工程上极常见的问题：
"这里的解引用会不会打到空指针？"

#### programs/nullcheck.tip

守卫演示程序：alloc/null 两支加空判定，28.3.4 精读、28.7.1/28.9.2 对账；它的一条假告警是流不敏感边界的活标本。

```cpp
// file: programs/nullcheck.tip
main() {
  var p;
  if (input > 0) {
    p = alloc 7;
  } else {
    p = null;
  }
  if (p == null) {
    output -1;
  } else {
    output *p;
  }
  return 0;
}
```

#### programs/ptr.tip

主演示程序：六行凑齐 New、地址链接、Load、Store 与别名，28.3.3 逐行精读、28.5.4/28.6.5 两个 trace、28.7.2/28.9.1 两处对账的当事程序。

```cpp
// file: programs/ptr.tip
main() {
  var x, y, p, q;
  x = alloc 10;
  y = alloc 20;
  p = &x;
  q = *p;
  *p = y;
  output *q;
  return 0;
}
```

`p` 的值在两条路径上二选一：输入为正时 `p = alloc 7`（L1），否则
`p = null`。随后的 `if (p == null)` 是一次显式守卫：空路径输出 -1，非
空路径才执行 `*p` 输出 7。具体语义上，进入 `output *p` 分支时 `p` 必
非空——守卫在逻辑上排除了 null。

本章的分析粒度是"合并所有路径、不利用条件中的相关性"（第 22 章意义
下的路径不敏感），所以它对 `p` 的结论是 `{L1, null}`，进而对守卫内的
`*p` 一视同仁地报"可能解引用 null"。这是一个**假告警**（false
positive）：真实执行两条路径都不会崩。它不是错误——分析承诺的是"可
能"的上界，宁可多报；要消掉它，需要把第 22 章的路径敏感（条件
`p==null` 的相反分支里，null 事实被 narrow 掉）叠加到指针分析上，这已
经是工业级路径敏感指针分析（如 Saturn、Infer 的某些检查器）的做法。
28.9 节的 JIT 会给出两组输入的真实行为，让"保守的假告警"与"真实的安
全"并排出现。

### 28.3.3 ptr.tip 逐行精读：五句程序里的全部机制

把 ptr.tip 放在眼前逐行读，每一行都对应指针分析的一种机制。第一
句 `x = alloc 10`：一个分配点诞生，New 约束 (x, L1)——L1 是这个
语法位置的抽象名，程序里再没有第二个 alloc 与它同名，所以"x 可
能指向本次分配"这句话的所有精度都押在语法点粒度上。第二句
`y = alloc 20`：又一个 New，(y, L2)。第三句 `p = &x`：地址链接
登场——&x 不是一个新地址，它就是变量 x 本身的存储；New 约束
(p, &x) 随后经地址链接双向打通：p 装着 x 的地址、x 的"地址内
容"通道也认得 p。第四句 `q = *p`：链上读，Load 约束
(p, q)——q 装的东西，从 p 指向的一切里来。此刻 p 指向 x（的
地址），所以 q 拿到 x 的内容；x 此刻装着 L1，于是 q 与 L1 挂
钩。第五句 `*p = y`：链上写，Store 约束 (y, p)——y 装的东西写
进 p 指向的一切；p 指向 x，所以 y 的 L2 流进 x。第六句
`output *q`：又一次链上读，q 指向 L1（上一步推理），读出的是
L1 里现在装的东西。顺序执行到最后，x 的内容已被改写成 L2，
*q 读的是 L1 的当前内容——静态分析不追踪"内容随时间的版本"，
它把 x 的可能内容算成 {L1, L2}（初值与新写入的并），于是 *q
的解引用安全、值可能是 10 或 20。具体执行只有一条路径，输出
10——静态的"可能"与具体的"实际"在 28.9.1 对账时握手。

这六行程序麻雀虽小：New、地址链接、Load、Store、别名（p 与
"对 x 的引用"）、内容通道（x 既是变量又是被指向者）全部出场。
读者若能不看正文复述出每行对应的约束与方向，本章的生成器就
已经掌握了一半。

### 28.3.4 nullcheck.tip 精读：守卫与两种世界

nullcheck.tip 的三句主干：`p = alloc 7` 或 `p = null`（按 input
分支）、`if (p == null) output -1 else output *p`。它考验的是
分析对"程序员的守卫"能看见多少。Andersen 侧：p 的 pts 是
{L1, null}——两支的并，流不敏感的分析不知道 if 已把两支分
开。于是 *p 处的 null 成员性检查报 possibly-null（保守）。真
实执行：input=5 走 alloc 支、p≠null、else 支解引用顺利输出
7；input=−2 走 null 支、if 命中、output −1——两条具体路径都
安全，告警是假告警。要消掉它需要路径敏感（第 22 章）或更细
的 null 分析（把"守卫后非空"做成一个谓词域）——本章的框架
故意停在流不敏感，让读者看见"守卫信息天然在控制流里、而包
含式分析只看数据流"这条鸿沟。 Steensgaard 侧的结果相同
（{L1,null} 两元素不需合并——null 与 L1 在 p 上本就共存，合
一只发生在"必须"时）。两栏输出在 nullcheck 上的一致，恰好是
28.7.1 说的"简单情形"；分歧要到 ptr.tip 的 y 上才出现。

### 28.3.5 两个程序是一对对照组

ptr.tip 与 nullcheck.tip 构成一对控制变量实验。共同点：都只有
一个函数、五六行、变量四五个以内——把噪声压到零。控制点：
ptr 有链接（&x）与链上读写，nullcheck 有分支与 null——前者
考验数据流机制（Load/Store 展开、地址链接），后者考验判定层
（成员查询、告警分级）。两个程序合起来，四类约束全部出场
（nullcheck 的 New 出场两次、ptr 的四类全齐），两台求解器的
差异（y 的分歧）与一致（nullcheck 全同）各有专属展示位。设
计演示程序的这条纪律——**每个机制配一个最小展示位、两个
程序分工不重叠**——比"一个大程序全都要"有效得多：输出短到
能逐行背、每个行为都能指认出处。读者自己写分析器时照此办
理，调试与教学两边受益。

## 28.4 约束生成器：从 AST 到 PtrCon

### 28.4.1 生成器的总体形状

从本节起进入实现，全部代码在章末 28.17 整文件收录。与第 27 章的约束
生成一样，`PtrGen` 只回答一个问题：怎样把一棵带名字绑定的 AST 翻译
成与具体语法无关的 `PtrConstraints`——四类约束的扁平列表，外加全部
位置标签与"哪些名字是待打印的程序变量"两个集合。求解器拿到这份数据
后不再接触 AST。

生成器在构造时建立 `decls` 索引（函数名 → 函数声明），遍历过程中用
`current` 记住当前所在函数，因为变量的位置标签要按函数加前缀：
`main` 中的 `x` 标签是 `x`，其他函数 `f` 中的 `x` 是 `f.x`。两个辅助
小函数值得注意。`freshAlloc` 按全局计数器给出 `L1、L2…` 标签，保证
每个 alloc 点编号唯一；`noteVar` 把"程序变量"与位置标签区分开——
`L…`、`&…`、`null` 是位置不是变量，打印双栏时不出现它们作为行名。

### 28.4.2 语句的分派与左值的两种形状

`genStmt` 是生成器的主体，它对五类语句分别处理。赋值语句最复杂，因
为左值有两种形状，必须先辨认：

- 左值是直接变量 `x`：记录标签 `lhs = loc(x)`，标志 `through=false`；
- 左值是 `*p`（且 `p` 是简单变量）：`lhs` 记的是**基址** `p` 的标
  签，标志 `through=true`——Store 约束里 `lhs` 位置装的是"被写位置
  的地址"。

辨认完左值，再按右端表达式的形状选择约束种类，这一长串 `if` 与
28.2.2 节的分类一一对应：右端是 alloc → 新 L 标签的 New；是 `&z` →
标签 `&z` 的 New；是 null → New(a,"null")；是简单变量 `v` →
Copy(lhs, loc(v))；是解引用 `*v` → Load(lhs, loc(v))。当左值为
`*p` 时（through），右端只接受简单变量，产生 Store(lhs, loc(v))。

这里可以直接读出本章教学实现的边界：左值深层嵌套（`**p = v`、字段
写）、右端复合（`a = b + 1` 里顺带取地址、`a = *p + *q`）不生成指针
约束。这不是漏算——这些形状在本章两个程序中不出现；放开它们需要
（a）为每个子表达式分配临时位置（第 27 章 `%n` 的做法），（b）把算
术与指针的数据流分开维护。28.12 节会回到这个取舍。

### 28.4.3 调用边界与"顺手走过"的子树

指针可以经函数调用流动（实参是地址、形参接收），生成器用最小的方式
处理：`callArgs` 在一次直接调用中，对每个"简单变量实参"生成一条
Copy——从调用方位置复制到 `callee.形参名`。形参名从 `decls` 索引取，
实参/形参按位置配对、超出较短一方的忽略。

`genExprs` 是一个"我不关心表达式的值，只关心里面有没有藏着调用"的
遍历：CallE 除了处理实参绑定，还递归进每个实参；Binop、Deref、
AllocE、FieldA、RecLit 都只递归子节点。`genStmt` 在处理完赋值后**无
条件**对右端再调一次 `genExprs`，正是为了不漏掉"右端整体不是指针形
状、但子树里有一次调用"的情形（例如 `output f(p)`）。这种"主分派负
责直接约束、补充遍历负责嵌套边界"的两段式结构，在手写分析生成器里
很常见：主分派保持穷举可见，补充遍历兜底语法允许的任意嵌套。

### 28.4.4 生成器逐段走读

PtrGen 的三段结构值得逐段过目。第一段 run：登记每个函数的
名字、形参与返回位置——名字表 params 是激活时"实参 i 对应形
参名"的查询源；返回位置 retLoc[fun] 是 CallE 的结果位在直接
调用下要接的目标。第二段 genStmt：分派语句——直接变量赋值
（target 是 VarRef）发 copy(x ← genExpr(v))；解引用赋值（tar
get 是 Deref）发 Store(genExpr(base), genExpr(v))；output 与
return 只是"顺手走过"子表达式（它们里面的 alloc 同样要发
New——分配无处不在）；分支与循环在流不敏感的世界里只是语
句的容器，没有控制流语义。第三段 genExpr：按表达式形状产位
置与约束——VarRef 返回变量位（名字是函数时按 27 章口径处
理？不——本章函数不是值，VarRef 一律返回变量位）；AllocE 造
新鲜 L{n} 并发 New；AddrOf 发 New(a, &z)；NullE 发 New(a,
null)；Deref 发 Load(base 位, 结果位)；Binop/CallE/FieldA/
RecLit 递归走过子表达式后返回一个临时位。三段的共同纪律：
**每个表达式一个结果位、每个值流动一条约束**，与第 27 章
genExpr 的约定逐字相同——两章生成器可以并排对读，差异只在
约束的种类（val/copy vs New/Copy/Load/Store）。

一个值得停留的细节是 callArgs：直接调用的实参按位置 copy 给
形参（copy(param ← arg)），这在指针世界等价于"传值"语义的抽
象；间接调用（callee 不是名字）本章不发任何绑定——TIP 的函
数不是指针值，遇不到这种形状。真实语言里"函数指针当实参"
是 0-CFA 与指针分析的交叉路口：先用控制流分析解析目标、再
按目标发参数 copy——两章的生成器在工业实现里就是这样拼接
的。

### 28.4.7 noteVar 的过滤名单

生成器给"谁算变量"维护一张过滤名单：L 开头的分配点名、&
开头的地址名、null——它们是位置系统的内部构造，不是程序
变量，不该出现在"变量位"的登记表里。名单看似琐屑，漏掉的
症状却很曲折：一个 L1 被当变量登记后，深度推断会给它推深
度、激活绑定会查它的形参名、输出层会把它印进双栏——三处
下游各坏一点，最难排查的是第三处（输出多了行无关变量，对
账红）。教训的形式已经超出指针分析：**生成器的名字空间卫
生是约束系统的第一道防线**，内部构造与程序实体必须分姓
名——第 27 章的 % 临时位过滤（练习七）是同一件事的函数
版。

### 28.4.8 表达式位置的编号纪律

生成器给每个表达式一个"新鲜"结果位，新鲜性由一个递增计数
器保证（L1、L2、%n……本章的实现按"遇到即造"的顺序编号）。
纪律有三条。其一，同一次遍历同一表达式只造一次——子表达
式的位置向上复用，不重复造。其二，编号一旦出炉永不复用
——删除或死代码不影响后续编号（本章生成器不删东西，这条
为扩展预留）。其三，编号与输出解耦——printPointer 不看编
号、只看集合成员名；这样未来换编号方案（比如按语句行号）
不动输出契约。三条纪律合起来是"位置系统的人体工程学"：
它让调试时"这个 L3 是哪来的"总能沿编号倒查到唯一的语法位
置。第 27 章的 %n 与本章的 L{n} 同宗，读者的肌肉记忆可以
直接迁移。

## 28.5 Andersen：包含式 worklist

### 28.5.1 求解状态：pts、工作表、三类反向索引

`Andersen` 结构体在构造函数里跑完整个求解。状态分四块，与四条闭包规
则一一对应：

- `pts`：每个名字当前的指向集（答案就在这里）；
- `wl`：工作表，元素是 `(名字 v, 新标签 s)`——"v 刚刚长出了 s，尚
  未处理其后果"；
- `copyOut[src]`：Copy 关系的反向索引，src 长出标签时要推给这些目
的，对应规则 2；
- `loadOf[b]` 与 `storeOf[a]`：Load/Store 约束的登记，等到基址真长出
位置时展开，对应规则 3、4。

唯一的入队原语 `add(v,s)` 在标签真正新进入 `pts(v)` 时计数（`rises`）
并入队。这个"先查重再入队"是所有单调 worklist 的共同形状（第 16
章）：同一条事实被多条路径推导只处理一次，保证工作表事件总数有界。

### 28.5.2 地址链接先就位，种子再入场

构造函数的第一步**不是**读约束，而是 28.2.4 节的地址链接：扫描全部
New(a,&z)，把 `z → &z` 与 `&z → z` 两个方向都登记进 `copyOut`。之所
以必须先于一切，时序上的理由很具体：随后处理 New 种子时，`a` 会立即
长出 `&z` 并出队；若此刻 `copyOut[&z]` 里还没有 `z`，存量传播就少走
一步，后面再补登记不会自动重放已出队的事件——结果静默漏报。链接先
就位后，无论哪一边先长出标签，规则 2 的传播都双向到达。

第二步才顺序读约束：New 直接 `add`（规则 1）；Copy 登记反向索引（规
则 2 在此只是待命，真正的传播发生在 src 长出标签的出队处理中）；
Load/Store 分别登记进 `loadOf/storeOf`。注意无条件约束与条件约束在这
里被统一成了同一件事——**都只是登记**；差异完全推迟到出队循环。

### 28.5.3 出队三步：Copy 传播、Load 展开、Store 展开

每个工作表事件 `(v,s)` 的处理就是把 `v` 长出 `s` 可能触发的三种后果
依次检查一遍，代码结构与 28.2.3 节的规则逐条对应：

1. **Copy**：`copyOut[v]` 中每个目的 `d` 执行 `add(d,s)`——规则 2 的
   单元素形式；
2. **Load**：对 `loadOf[v]` 中每个 `a`（即程序里有 `a = *v`）：`v` 指
   向 `s` 意味着 `a ⊇ pts(s)`。实现分两个动作：先把 `s → a` 登记进
   `copyOut`（这是规则 3 展开出的**新 Copy 边**，未来 `pts(s)` 再长
   标签照样推给 `a`），再把 `pts(s)` 的**存量**逐个 `add(a,t)`，补上
   登记之前已经存在的标签；
3. **Store**：对 `storeOf[v]` 中每个 `b`（程序里有 `*v = b`）：对称地
   把 `b → s` 登记进 `copyOut`（`pts(s) ⊇ pts(b)`），再把 `pts(b)` 的
   存量补推给 `s`。

"登记新边 + 补推存量"这一对动作是动态约束求解的通用模板：新边保证
**未来**的增量不漏，补推保证**过去**的存量不丢。漏掉前者，循环里后
到达的标签传不过去；漏掉后者，只有一条 Copy 边、没有任何事件驱动
重放。28.10.2 节论证可靠性时，每一条规则的 soundness 都归结为这两个
动作与具体执行的一次取值/写入一一对应。

### 28.5.4 Andersen 在 ptr.tip 上的事件全记录

把 28.5 的求解器在 ptr.tip 上跑一遍，事件按时间顺序记录如下，
读者可对照 28.7.2 的最终两栏输出逐条找到归宿。初始化：地址链
接先就位——(p, &x) 的 New 使 copyOut[x] ⊇ {&x}、copyOut[&x] ⊇
{x}（双向通道，28.2.4 的规则落地成两行代码）。种子入队：四条
New——(x,L1)、(y,L2)、(p,&x)、(q,null)？不对，q 的约束是 Load
不是 New；种子是三条 New：(x,L1)、(y,L2)、(p,&x)。nullcheck
里 null 是 New；ptr.tip 没有 null。

事件一：弹出 (x,L1)。pts(x) 涨 {L1}。copyOut[x] 有 &x（地址链
接），于是 L1 沿边转发：pts(&x) 涨 {L1}——"x 的地址处装着
L1"。&x 不是普通变量，它的 copyOut 有 x（链接另一半），再转
发：pts(x) 涨 {L1}（已含，无事件）。Load/Store 监听 x：没有以
x 为源或目标的链上操作，静默。事件二：弹出 (y,L2)，对称地
pts(y)={L2}。事件三：弹出 (p,&x)。pts(p) 涨 {&x}。Store 监听
(p)：约束 (y,p) 的目标集合含 p——展开：copyOut[y] ⊇ {p}？
方向反了，Store (y,p) 说"y 的内容写进 p 指向的"，展开成
copy(y → 每个被指向者)。p 指向 &x，所以 copyOut[y] ⊇ {&x}？
不——Store 展开为：对每个 o ∈ pts(p)，发 copy(y, o)。o=&x，
发 copy(y, &x)。事件四：Load 监听 (p)：约束 (p,q) 的源集合含
p——对每个 o ∈ pts(p)，发 copy(o, q)。o=&x，发 copy(&x, q)。

事件五：弹出 copy(y,&x) 的事件——y 缓存涨 &x？y 装的是地址
&x 吗？是的——`*p = y` 把 y 的**值**（L2 这个堆址？不，y 的值
是 L2，是分配点）……此处必须放慢：Store (y,p) 展开的 copy
(y,&x) 语义是"y 的内容流向 &x 的内容"，即 y 装的 L2 流进 x。
弹出 (y,&x) 传播：pts(y) 的每个成员沿 copyOut[y] 转发——
copyOut[y] 现在有 {&x}（Store 展开新加的），L2 流向 &x：
pts(&x) 涨 {L2}；再沿链接转发给 x：pts(x) 涨 {L2}——x 的内容
通道现在 {L1,L2}，第 28.3.3 预告的"初值与新写入的并"在此落
地。事件六：弹出 copy(&x,q)：pts(&x) 的成员（L1，此刻还没
L2）流向 q——pts(q) 涨 {L1}。事件七（如果事件五先于六发
生）：pts(&x)={L1,L2} 时弹出 copy(&x,q)，q 涨 {L1,L2}？——
关键在**弹出的时机**：copy(&x,q) 这条边在事件四登记，登记时
"重放过去"立即把当时 pts(&x)={L1} 转发（q 涨 L1）；此后
pts(&x) 再涨 L2 时，"登记未来"使 L2 沿已有边再转发一次（q 涨
L2）。两个动作配对，q 最终 {L1,L2}？——但 28.7.2 的输出说
Andersen 给 q={L1,L2}！对：具体执行里 *q 读到的是 L1 的当前
内容（10），而静态 q 可能装 L1 或 L2（q 在 `q=*p` 时刻只可能
拿到 L1；但静态不分时刻）。x 同理 {L1,L2}。y 保持 {L2}，p
保持 {&x}。全表与 28.7.2 的 ANDERSEN 栏逐行吻合，事件记录关
账：rises=8，读者可自行把八个涨点在上面的七个事件里数齐。

### 28.5.5 Andersen 求解器逐段走读

solvePointer 的 Andersen 半边分四段。第一段建索引：copyOut
（源→目标列表，copy 的接线）、loadAt（源→Load 约束列表）、
storeAt（目标→Store 约束列表）——三张反向索引把"谁在等这
个位置"变成 O(1) 查询。第二段地址链接预处理：对每条 New(a,
&z)，先接通双向通道再让种子入场——顺序不能反，28.5.2 讲过
理由。第三段主循环：弹出 (var, site)，pts(var) 涨 site 后做
三件事——沿 copyOut[var] 转发（Copy 语义）、对 loadAt[var]
的每条约束发 copy(o, q)（Load 展开：var 此刻被当作"被指向的
单元 o"）、对 storeAt[var] 的每条约束发 copy(y, var)（Store
展开：var 作为写入目标）。第四段提取：直接搬 pts 就是答案。
四段里只有第三段有循环，循环里的三个动作各对应一类约束的
语义——把 28.2.7 的四条规定逐条贴在代码上，一行不多一行不
少。

工作表的度量（rises）在 pts 上涨处递增。它的对账价值 28.11.4
已经用过；这里补一个调试用法：当结果可疑时，把每个 rise 连
同触发它的约束打印成事件流（本章开发时的 IDE_DUMP 就是这个
形状，正式版删去以保输出稳定）——事件流与手算系统（28.2.9）
逐条对，错位的第一条就是病灶。这种方法比断点单步快得多，因
为求解器的状态是纯数据、事件是纯日志。

### 28.5.6 反例实验：拆掉一个部件会怎样

四个思想实验，每个拆掉 Andersen 的一个部件，预测症状。拆掉
地址链接：q 的集合只剩 {L1}（copy(&x,q) 的 &x 侧永远空转，
事件六的转发无从发生——不，链接拆掉后 Load 展开的 o 遍历
pts(p)={&x} 仍然发 copy(&x,q)，但 &x 的集合再也不会从 x 涨
过来——q 拿不到 L1，集合空）。拆掉"登记未来"（新 copy 不接
旧成员）：L2 晚到时 y 的转发丢失，x 缺 L2。拆掉"重放过去"
（新成员不沿旧边）：q 缺 L1 或 L2 取决于时序。拆掉 Store 的
监听展开：*p = y 整句失效，x 保持 {L1}。四个症状各不相同，
但都能从"28.2.9 的手算系统少推一步"直接读出——**反例实验
与手算系统配对使用**，是求解器开发的单人测试法：先手算完
整解，再逐个拆部件、比对差量，差量与被拆部件的语义一一对
应，实现就是对的。这比断点单步快一个量级，因为每个反例只
需要跑一次。

### 28.5.7 监听索引的内存账

三张反向索引（copyOut、loadAt、storeAt）的内存是约束数的线
性函数，构建一次、只读不写——理想的工作集形状。值得记账
的是**间接成本**：每次 pts 上涨要做三次查表（三个监听各一
次），查表命中数为零的成本也要付。本章规模无感，立方程序
（28.11.4）里这三连查是常数项的大头。工业实现把三张索引
合并成一张"边表"按源位置分桶、一次遍历处理三类监听——
SVF 的 constraint graph 就是这个方向的终点。教学版分开写，
是为了每类约束的语义动作在代码里各占一段、与 28.2.7 的四
条规定一一对应——可读性预算再一次压过性能预算，而这个选
择在本章的 8 次 rises 面前毫无代价。

### 28.5.8 Andersen 事件表：叙述的表格化重排

28.5.4 的流水账可以重排成四列的事件表读法：时刻、事件、触
发约束、集合变化。时刻一：种子 (x,L1)，触发 New(x,L1)，
pts(x)={L1}。时刻二：(y,L2) 入，pts(y)={L2}。时刻三：
(p,&x) 入，pts(p)={&x}——同刻触发两件事：Store(y,p) 的监听
展开（因为 p 涨的是 &x，展开对 o=&x 发 copy(y,&x)），Load
(p,q) 的监听展开（对 o=&x 发 copy(&x,q) 并立即重放当时
pts(&x)={L1}，q 涨 L1）。时刻四：copy(y,&x) 的事件到达，L2
沿边走 pts(&x) 涨 L2、链接再推 pts(x) 涨 L2。时刻五：&x 涨
L2 触发"登记未来"的补推——L2 沿已有边 copy(&x,q) 再走一
次，q 涨 L2。收官：x={L1,L2}、y={L2}、q={L1,L2}、p={&x}，
rises 共 8（x 两次、y 一次、p 一次、&x 两次、q 两次）。表
格化后两个"展开即重放"与两个"涨后补推"在各自行列里对齐
——28.12 第二条注意点说的"登记与重放成对出现"，在表上就
是时刻三与时刻五的两行互为镜像。

### 28.5.10 队列的形状：FIFO、LIFO 与优先级

Andersen 的工作表是个普通 FIFO 队列，事件按"发现顺序"流动。
换成 LIFO（栈）会怎样？终态不变（单调上升 + 集合去重保证
唯一不动点），但事件分布变化：深度优先的弹出让刚展开的新
边立刻被处理，"热点变量"的传播连成串；FIFO 则广度优先，
一轮内所有源变量轮流涨。对缓存友好度与总弹出次数，实测差
异都在个位数百分比——这与第 16/25 章的结论一致：工作表顺
序是性能旋钮，不是正确性部件。真正影响总量的是去重的粒
度：按 (var,site) 去重（本章）天然免除重复，按"var 整体变
脏"去重（把 site 打包）会省队列长度但多付重放——两种取舍
在工业求解器里各有拥趸，SVF 的 wave propagation 是后者的
精细化。教学版的 FIFO + 逐事件去重，胜在与事件表（28.5.8）
的一一对应。

## 28.6 Steensgaard：近线性合一

### 28.6.1 带指向字段的并查集节点

`Steensgaard` 的状态比 Andersen 更紧凑：一个节点数组 `nodes` 与名字到
节点的映射 `id`。节点三要素在 28.2.5 节已形式化：`parent`（并查集父
指针）、`pts`（该等价类指向的标签集）、`ptr`（指向节点——把"这个
类的值解引用后是谁"直接建模为图上的一条边）。三个并查集原语是标准
的：`nodeOf` 懒建节点；`find` 带路径压缩。

`ensurePtr(rx)` 是这套算法特有的：当 `a = *b` 或 `*a = b` 需要"b 指向
的那个东西"，而等价类还没有指向节点时，新建一个节点挂到 `rx.ptr`，
返回其代表元。新建发生得越晚越好——每个类至多一个指向节点，这是
节点总数保持线性的关键。

### 28.6.2 unite：合并类、并标签、递归合并指向节点

`unite(x,y)` 是算法的核心，严格按 28.2.5 节的三件事执行：取代表元，
同类直接返回；否则 `ry` 挂到 `rx`，标签集取并。指向节点的处理分三种
情况：两边都有 → **递归 `unite` 两个指向节点**（解引用层级上的同样
关系）；只有 `ry` 有 → `rx` 原样接管；只有 `rx` 有（或都没有）→ 不
动。最后无论走了哪条路径，都重新对 `rx.ptr` 取一次 `find`：递归合
一可能已经改变了指向节点的代表元，存旧编号会让后续 `ensurePtr` 找错
类。

递归 `unite` 的终止性来自一个简单的度量：每进入一层递归，处理的都是
"指向节点"（解引用深度 +1），而程序中静态嵌套的解引用层数有界；同
层的合并不可能成环（挂接的两个类必先不同，挂完即同，第二次调用在
入口处返回）。这与第 11 章合一算法的递归下降是同一种论证。

### 28.6.3 约束到合一动作的映射，及地址链接

主循环与 Andersen 同构地分两步。**先做地址链接**，但形状不同：
`New(a,&z)` 出现时，为 `a` 的类 `ensurePtr` 出指向节点 `p`，直接
`unite(p, nodeOf(z))`——这正是 28.2.4 节"&z 与 z 是同一位置"在合一框
架里的表达：`a` 的指向节点物理上就是变量 `z` 的节点，此后任何经 `a`
的 Load/Store（对 `p` 的读写）都等同于对 `z` 节点的读写，无需双向边
——合一本来就没有方向。

随后逐条处理约束：New 把标签加进 `a` 所在代表元的 `pts`；Copy 直接
`unite(a,b)`；Load 为 `b` 取指向节点 `p`，合一 `a` 与 `p`；Store 为
`a` 取指向节点 `p`，合一 `p` 与 `b`。每个语句至多触发两次 `find`、一
次 `unite` 与至多一次新节点分配，整体近线性（28.11 节给精确口径）。

### 28.6.4 结果提取

`solvePointer` 依次跑两个求解器。Steensgaard 的结果按"变量名 → 其所
在代表元的 pts 集"提取：每个 `id` 里登记过的名字，`find` 到当前代表
元，读其 `pts`。同一个等价类里的变量因此打印出**完全相同**的集合
——这就是合一在输出上的签名：一旦在 `ptr.tip` 里看到 `y` 与 `x` 的集
合变得一模一样，就知道某次 `unite` 把它们绑在了一起。`varRep` （名字
→ 代表元编号）也保留下来，章末虽不打印，但调试时可以直接核对"谁和
谁被合了"。

### 28.6.5 Steensgaard 在 ptr.tip 上的合一记录

同一程序交给 Steensgaard，事件换成合一。节点：每个名字一个
（x、y、p、q、&x、L1、L2、null 各一）。约束逐条变动作：
New(x,L1) → unite(x, L1)：x 类 ⊇ {L1}（类内标签并集）。New
(y,L2) → unite(y,L2)。New(p,&x) → 地址链接：ensurePtr(&x) 造
一个"指向节点" P，unite(P, x)——"x 的内容通道"整个成为一个
等价类。Load(p,q) → unite(p 的指向节点, q)：p 的指向节点是
unite(P, q)——q 并进"x 的内容通道"。Store(y,p) → unite(y,
p 的指向节点)：y 也并进同一通道。结果：{x, q, y} 同类（经指
向节点 P 连通），类的标签并集 {L1,L2}——于是提取时 x={L1,
L2}、y={L1,L2}、q={L1,L2}，与 28.7.2 的 STEENSGAARD 栏吻合
（Andersen 的 y 只有 {L2}，分歧正在此）。p 自成一类 {&x}。
三次成功合一，unifications=3，账目对上输出末行。

这个记录的教学点在第三、四条：Load/Store 的合一把"源的内容
通道"与"目标"焊死——Andersen 里这是两条有向边（信息单向流），
Steensgaard 里是一根双向焊条（类合并不可逆）。焊一次，两个
名字从此共享命运；这就是"合一代价在 y 上显形"的机械成因：
y 本与 x 的内容无关，只因 Store 把它焊进了 x 的通道。

### 28.6.6 Steensgaard 求解器逐段走读

Steensgaard 半边只有三段。第一段 nodeOf：名字→节点表的惰性
建节点。第二段逐条约束映射成合一：New → unite(a, site 节
点)（类内标签并）；Copy → unite(a, b)；Load(p, q) →
unite(ptr(p), q)——ptr(p) 是 p 的"指向节点"，不存在则造（每
个等价类至多一个，28.6.1 的字段）；Store(y, p) → unite(y,
ptr(p))。地址链接的预处理在合一世界里是：New(a, &z) →
unite(ptr(&z 节点), z 节点)——"z 的地址处的内容通道"与 z 焊
成一体，与 Andersen 的双向边语义相同、形态是一根焊条。第三
段提取：每个名字的答案 = 其所在等价类的标签并集。三段的所
有"智能"都在 unite 里：按秩挂树、路径压缩、类标签并、**递
归合一指向节点**——两个类各有指向节点时，指向节点本身也要
合一（一维的 term 图合一，28.6.2 的递归）。这个递归是 Stern
gaard 表达力的全部来源：它让"指向什么"成为类型一样的东西
被合一传播，也正是它把 y 焊进 x 通道的机制出口。

并查集的三行实现（find 压缩、unite 挂接、label 并）值得背
下来——它是本教程出现的最后一个"通用数据结构武器"，此后
的分析都在用它或它的思想（集合的等价类压缩）。

### 28.6.7 两台求解器的输出层与并列打印

printPointer 把两台求解器的结果并成双栏：-- ANDERSEN -- 与
-- STEENSGAARD -- 两段，每段列具名变量的 pts、末行各带统计
（rises / unifications）。双栏的排版是教学设计：同一程序、
同一约束系统、两种解，并排让分歧（y）与一致（其余）一眼可
辨。打印顺序按变量名字典序，集合成员按生成序——两处顺序都
是输出契约的一部分，check_example 逐字节对账锁定。值得注意
打印层对"特殊成员"的处理：&x 与 null 与 L1 在输出里平权排
列，它们都是抽象位置，没有谁是二等公民——这个平权正是
28.2.1"折叠"思想的视觉呈现。



### 28.6.10 指向节点的类型论解读

Steensgaard 的 Node 里那个 ptr 字段，本质是一个一元类型构造
子的解释：每个等价类是一个"基类型"，ptr 字段指向它"所指的
内容的类型"。unite 的递归（两个类的 ptr 字段再 unite）就是
类型构造子的合一——这与第 11 章 Hindrance–Milner 的 unify
在机制上同构、在语义上是它的退化版（只有一元构造子、没有
多态、没有 let）。这个解读的价值是双头的：往回看，第 11 章
的 union-find 实现可以直接搬来当本章的并查集（教程分两次写
是为了各自自包含）；往前看，"指针类型 = 指向内容的类型"在
约束式分析里还能继续长——字段敏感就是给构造子加参数
（record(f₁…fₙ)），上下文敏感就是给类型加调用串参数——类
型系统的表达力菜单与分析的精度菜单，在这一层完全重合。

### 28.6.11 合一的不可逆性：一扇关上的门

包含式与合一式的全部差异可以浓缩成一个词：可逆。Andersen
的每条 copy 是单向通道，信息流过不改源——将来即使发现新约
束，也只是再流一次，历史不纠缠。Steensgaard 的 unite 是焊
接，两个名字从此不可区分——哪怕程序后文证明它们从无瓜
葛，焊过的类不会拆开。"不可逆"买到的是每个节点至多 log n
次合并的复杂度上界，付出的是精度的单调流逝。这个交换在
类型推断（第 11 章）里也出现过：合一同样不可逆，但类型的
"精度"在那边对应程序能否通过检查，合一的后果是全局的；这
边精度只影响假告警率，焊接的代价可以按模块隔离（分函数合
并、摘要桥接）。一扇门关上，绕路的成本取决于门后是什么
——工程判断永远跟着场景走。

### 28.6.12 提取阶段的最后一个细节

结果提取把每个名字的答案取为其所在等价类的标签并集。细节
在于"标签并集"的物化时机：可以在每次 unite 时同步维护（每
类一份并集，提取 O(1)），也可以提取时现场遍历类内成员
（unite 更快、提取慢）。本章取前者——pts 的语义是集合，同
步维护让"提取"退化成查表，教学上把复杂度全部留在合一侧、
一眼可读。工业实现对大程序取后者或混合（延迟到查询）——
又一次"教学预算 vs 工程预算"的实例，与 28.5.7 的索引账本
同一话题的两端。

## 28.7 读 --check 的双栏输出

### 28.7.1 nullcheck.tip：两栏一致的简单情形

先看结构更简单的程序，真实输出如下（嵌入在 28.13 的期望文件里，这
里只摘关键行）。ANDERSEN 栏与 STEENSGAARD 栏都给出 `p: {L1,null}`，
统计是 `andersen rises: 2, steensgaard unifications: 0`。

两个数字各自说清了求解过程。Andersen 的两次上升：`p` 先长出 L1（
then 分支），再长出 null（else 分支），集合饱和。Steensgaard 零次合
一：程序里没有 Copy/Load/Store——`p` 只被直接赋两类地址，两次 New
往同一个类的标签集里各加一个标签，标签集的增长不计入 `unifies`。两
栏一致符合 28.2.6 节的预判：没有"等同关系"出现时，合一没有机会比包
含更激进，两种算法退化成同一件事。

### 28.7.2 ptr.tip：合一代价在 y 上显形

`ptr.tip` 的两栏差异正是本章最想让读者看到的一行。ANDERSEN 栏：

> `p={&x}`，`q={L1,L2}`，`x={L1,L2}`，`y={L2}`。

逐变量核对 28.3.1 节的手算：`p` 只来自第三行；`x` 有 L1（第一行）与
L2（第五行 Store 经 `*p` 回写）；`q` 经第四行 Load 继承 `pts(x)` 的全
部；`y` 自第二行后再无写入，保持 {L2}。8 次 rises 是这四个集合逐元
素增长的总事件数。

STEENSGAARD 栏里前三行相同，**唯独 `y` 变成 `{L1,L2}`**，且
`unifications: 3`。倒推哪一次合一造成了倒灌：第四行 `q = *p` 让 `q`
与 `p` 的指向节点（经地址链接就是 `x`）合一——`q≡x`；第五行
`*p = y` 让 `p` 的指向节点（仍是 `x`）与 `y` 合一——`x≡y`。于是
`q、x、y` 同属一类，`y` 把自己的 L2 带进类，类里原有的 L1 也回灌给
`y`。L1 在运行时绝不可能是 `y` 的地址（`y` 只被赋过 L2），这就是
"丢方向"的精确代价：一条 `pts(x) ⊇ pts(y)` 的单向约束被实现成
`x≡y`，反向的 L1 凭空出现。而 28.2.6 节的超集关系在每一行上都成立
（前三行相等，`y` 行 Steensgaard 严格更大）——更不精确，但 sound。

### 28.7.3 双栏对照的事件对齐

把 28.5.4 与 28.6.5 的两份记录并排，同一程序在两台机器上的
事件可以逐条对齐：Andersen 的"转发"对应 Steensgaard 的"类内
标签并"；Andersen 的"监听展开"（Load/Store 在集合上涨时发新
copy）对应 Steensgaard 的"约束直接合一"；Andersen 需要"登记
未来 + 重放过去"的配对动作，因为边是动态长的；Steensgaard
不需要——边在合一的瞬间就"焊"进了类的形状里。精度分叉只在
一处：y。单向阀让 y 的 {L2} 与 x 的 {L1,L2} 各自安好；焊条把
y 焊进 x 的通道后，类的标签并集 {L1,L2} 被 y 无差别分享。一
个变量、两种命运——这行输出是两章算法全部差异的浓缩，值得
在屏幕上并排停一分钟。

### 28.7.4 双栏输出的完整行序契约

expected/output.txt 的行序由三层排序叠加：程序序（nullcheck
在 ptr 前——文件名字典序）、栏序（ANDERSEN 在 STEENSGAARD
前）、变量序（字典序）。三层都稳定，因此对账逐字节可复现。
写双栏打印时容易犯的错是让两栏共用一次遍历、以"变量并集"
为序——那样空缺的变量在两栏里错位。本章实现分两次独立遍
历、各自排序，栏内没有的变量干脆不出现（比如 &x 只在
ANDERSEN 栏……实际两栏都跳过纯地址名，只印程序变量）——
"缺行"本身就是信息：它说"这个分析对这个名字没有结论"。
把行序当契约还有一层好处：读者做练习时预测输出，可以直接
按三层排序手写整份文件再 diff——预测全对的那天就是出师
的日子。

### 28.7.5 两栏逐行并读（完整版）

把 output.txt 从头到尾并读一遍，作为 28.7 的收官。第一程序
nullcheck：ANDERSEN 栏，p: {L1,null}——两支的并在场，L1 与
null 平权排列；STEENSGAARD 栏同 shape——两元素不需要合并
（合一只发生在 Load/Store 把两个名字焊通时，本程序没有链上
操作）。第二程序 ptr：ANDERSEN 栏四行——p: {&x}（链接的始
发）、q: {L1,L2}（读的两次收获）、x: {L1,L2}（初值加链上
写）、y: {L2}（单向阀保住的精确）；STEENSGAARD 栏——前三
行与 ANDERSEN 相同，y: {L1,L2} 是唯一的分歧行（焊条的代
价）。统计行：rises 8 对 unifications 3——传播次数多于合
一次数，量级上印证"包含式更忙、合一式更省"。整份文件三十
行出头，三十行里压缩着两章算法、一次粒度取舍、一条可靠性
命题的全部证据。

### 28.7.6 从双栏到决策：这份输出怎么用

设想一位真实用户拿着 output.txt 要做决定：能不能把 *q 的
解引用提到循环外、能不能删掉 null 分支、能不能把两个分配
合并成一个。第一个问题的答案在 q 的集合——{L1,L2} 意味着
两次分配的内容都可能被读到，提升语义要看"两次内容是否相
同"，本章分析答不了（值分析的事，第 17/26 章）；第二个在
p 的集合——{L1,null} 含 null，删分支等于赌运气，告警拦住
了它；第三个在两栏的分歧——Andersen 说 y 只指 L2，合并分
配会把 L1 的内容并进来（等价于 Steensgaard 的保守世界），
用户若信 Andersen 的精确性就能合、若要稳妥就不能。三个决
定、三行输出——静态分析的价值从来不是"替用户决定"，而是
把决定的依据从"读全程序猜"变成"查一行集合"。双栏并排的
意义也在这个场景里显形：两个分析给出同一问题的两个价位的
答案，用户按风险偏好取用。

## 28.8 LLVM 执行台的指针片段扩展

### 28.8.1 malloc 的声明与 alloc 的翻译

第 8 章的 IRGen 只会生成 i32 世界；本章在同一个骨架上加四个分支。
构造函数里先声明 C 标准库的 `malloc`：吃一个 `i64` 字节数，返回不透明
指针（LLVM 15 以后指针不再带整型类型，统一为 `ptr`）。`alloc e` 的翻
译因此是三行：`CreateCall(malloc, i64 4)` 拿到一个四字（足够装一个
TIP 整数或地址）堆块；对返回的块 `CreateStore(expr(e))` 完成初始化语
义；块地址作为表达式的值。这个块真实存在于 JIT 进程的堆上——不模
拟、不占位——所以 28.9 节读到的每个数字都是解引用真实内存得来的。

`&x` 不需要任何新指令：取地址就是取第 8 章已有的栈槽 alloca 的地址。
代码在 `locals` 表里反查"`x` 在当前函数的符号 → alloca 指令"，直接把
alloca 指针作为值返回。`null` 对应 `ConstantPointerNull`，是一个类型
为 ptr 的常量。这两者加上 malloc 的返回，在 LLVM 眼里是同一种值
（ptr）；区分它们只靠后续比较与读写。

### 28.8.2 难点不在指令，而在类型：指针深度预推断

opaque ptr 时代 LLVM 自己不再追踪"指针指向什么"，但**我们生成的代码
仍需要类型决策**：变量的 alloca 槽该装 i32 还是 ptr？函数形参与返回
值声明成什么类型？一条 load 指令要读 i32 还是 ptr（从而 `*p` 的结果
能再被解引用）？这些问题本质是同一个：**每个符号的"指针深度"是
几？** 0 = 整数；1 = 指向整数/空；2 = 指向一个指针；以此类推。

`inferDepths` 用一个极小的不动点回答它。核心递归函数 `depthOf(e)` 按
表达式形状给深度：变量读当前表（缺省 0）；`&z` 是 `z` 的深度 +1；
`alloc/null` 恒为 1；`*e` 是 `depthOf(e) − 1`（不为负）。`raise(sym,d)`
在深度增大时更新表。然后反复扫描程序直到一轮无变化。为什么必须反复：
`*p = y` 要求 `depth(p) = depth(y)+1`，而 `depth(y)` 可能来自更后面的
`y = &z;`，第一遍还不知道。深度约束是单调的（只增不减）、最大值被
静态解引用层数封顶，所以迭代必终止，且轮数很小。

扫描覆盖三处来源：直接赋值（左值变量按右端深度提升；左值 `*p` 按
"右端深度 +1"提升 `p`）、返回表达式（提升函数的 `retDepth`）、调用边
（实参深度提升被调函数的形参深度）。`allSym` 索引把所有函数作用域
里的"名字 → 符号"扁平化，使跨函数提升无需另建形参表。

### 28.8.3 深度怎样落到代码里

深度表在三个生成位置被消费。函数创建时：形参类型按深度选 ptr/i32，
返回类型按 `retDepth` 选。`genFun` 开栈槽时同样按深度选槽内类型，并
且初值不同：深度 ≥1 的槽存 `ConstantPointerNull`（保证读出来总能与
null 比较），整数槽存 0。`expr` 读变量时：深度 ≥1 生成 `load ptr`，
否则 `load i32`。解引用时：结果类型按"基址深度 −1"决定——仍 ≥1 说明
`**p` 这一层读出来还是地址，用 `load ptr`；否则 `load i32`。

### 28.8.4 与 null 的比较：同一个 Eq 分支的两种语义

`p == null` 给二元等于运算添了一个特殊情形：两边类型不同（ptr vs
i32），不能都按整数生成。Eq 分支先检查任一侧是不是 NullE：若是，把
另一侧按指针求值，另一侧与 `ConstantPointerNull` 做 `ICmpEQ`（注意
比较顺序按标签所在侧摆好）；两侧都不是 null 才退回整数比较。这保证
了 `nullcheck.tip` 里的守卫被翻译成一条真实的指针比较——JIT 执行时
分支判定与 C 程序的 `if (p == NULL)` 语义完全相同。

### 28.8.5 opaque ptr 与"深度"的来龙去脉

LLVM 15 起 typed pointer（i32*、i32**）逐步退场，17 起只剩不透
明指针 ptr——类型上不再区分"指向什么"。这对前端是自由也是负
担：自由在 IR 更稳定（alloca 的类型可以晚定），负担在 load
什么类型必须前端自己记。本章的解法是深度推断：给每个名字一
个整数深度——0 表示纯整数、k≥1 表示 k 级指针；x 的深度 d，
&x 的深度 d+1，*x 的深度 d−1，alloc 的结果深度 1，null 深度
1。推断是个小不动点：遍历语句，遇到赋值就把右端深度提给左
端（只升不降——深度是"至少"的承诺）；遇到 *p = v 就把 p 的
深度抬到 v 的深度 +1；遇到 f(a) 就把 a 的深度提给对应形参。
nullcheck.tip 走一遍：p 在 alloc 支深度 1、null 支深度 1，
*p 要求 p ≥ 1（读出整数），p == null 是指针比较——一切在两
个语句内闭合，无需迭代。ptr.tip：x、y 深度 1（alloc）、p 深
度 1（&x，x 是 0……等等，&x 的深度是 x 深度 +1 = 1，p 装
&x，p 深度 1）、q = *p 深度 0？*p 深度 = p 深度 −1 = 0，q 装
它，q 深度 0——但 output *q 又对 q 解引用，q 被抬到 1，连带
*q 深度 0 的整数读出。这个小迭代（q 从 0 抬到 1）正是"深度
只升不降"的工作场景。深度表落到代码生成：深度 0 的名字用
i32 槽、≥1 的用 ptr 槽；Deref 在 base 深度 ≥2 时 load 出
ptr、=1 时 load 出 i32——28.8.3 的三个分支各对应这里的一种
情形。

### 28.8.6 malloc 的 ABI 细节与教学取舍

alloc e 翻译成 `ptr = call @malloc(i64 4)` 再 `store 值,
ptr`——两个细节值得说明。其一，字节数固定 4：TIP 的堆单元
就是"一个 int 的盒子"，不追踪数组与大小；真实翻译会按类型
宽度与对齐来（且 Clang 会走 operator new 的路线）。其二，
malloc 的返回值在本章不做 null 检查：教学焦点在数据流不在
健壮性；工业 IR 里此处应有一条 null 判定与失败路径，而那条
路径恰好又是静态 null 分析的用武之地——读者可以把它当作一
个自闭环的练习：给 irgen 加上 malloc 失败分支，再看本章分
析在新增 Store/分支下的输出变化。其三，本章不为 malloc 插
free：不回收意味着 L1/L2 永远有效，抽象集合不需要"死亡分
配点"概念；真实的别名分析要配一个堆模型（分配点活性、
use-after-free 检测），那是 SVF 一族工具的深水区，教程止步
于浅滩是有意的。

### 28.8.7 irgen 逐段走读：指针片段的代码生成

irgen.cpp 在第 8 章的基础上为指针长出了三块新肉，逐段走读如
下。第一块是深度推断 inferDepths：先建 allSym 索引（（函数,
名字）→Symbol），再用 std::function 包装的 depthOf 递归问深
度——VarRef 查表、AddrOf 找到 z 后 +1、AllocE/NullE 给 1、
Deref 给 base 深度 −1。主循环是"只升不降"的不动点：遍历全部
赋值，`x = e` 时把 depthOf(e) 提给 x（raise 取 max），`*p = v`
时把 p 抬到 depthOf(v)+1（写进链上要求 p 的级别够），返回语
句把返回深度记进 retDepth，直接调用把实参深度提给形参。循
环跑到不再有 raise 为止——深度单调、有上界（语法嵌套深
度），终止免费。第二块是类型选择：建函数时按形参深度选
i32 或 ptr 槽、按 retDepth 选返回类型；expr() 里 Deref 的翻
译按 base 深度分叉——≥2 时 load ptr（读出还是指针）、=1 时
load i32（读出整数）。第三块是指令：AllocE → CreateCall
(malloc, 4) 加 store 内层值；AddrOf → 直接取 x 的 alloca 槽
（地址即槽位，与 28.10.6 的语义恒等式在 IR 层的对应物）；
NullE → ConstantPointerNull；Eq 与 null 比较走 icmp eq ptr
（28.8.4 的分支）。三块合起来约两百行，是"前端私有类型系
统"的最小完整样本——opaque ptr 时代每个前端都要写一遍的
东西，教程把它压缩到了能逐行讲的尺寸。

### 28.8.8 深度推断的三个设计决定

三个决定值得单独点名，因为它们都是取舍而非必然。决定一：
深度是**全局每名字一个**，不做流敏感的深度——变量的一生只
有一个级别。若程序先把 x 当整数再当指针（TIP 的类型系统禁
止，但 IR 层无此约束），推断只能取两者最大。决定二：深度
推断**先于**代码生成整体跑完，不做边推边生成——一遍预扫
描换生成期的全知，代价是要把 AST 走两遍。决定三：Deref 的
深度 = base −1，可以为 0——这允许 `**p` 形状的程序（两次中
转）把深度算负？不——负深度会被 raise 拉回：解引用出现在
语句里时，其结果的用途（赋给谁、再解引用）会把相关名字抬
到恰好够用。三个决定合起来：一个保守、一遍式、以用途定级
别的微型类型推导——它与第 9–12 章 Hindrance–Milner 的对照
是绝佳的思考题（那边是等式合一、这边是单调下界），练习五
把它做实。

### 28.8.9 堆模型的深水区：free、数组、字段

本章的堆模型刻意停在浅滩，深水区有三片。free：不回收使分
配点"永生"，use-after-free 检测需要活性维度（分配点的生死
是时间属性，流不敏感分析天生失明——路径敏感或时间戳是解
药）。数组：alloc 只造"一个 int 的盒子"，数组需要"偏移的折
叠策略"——按元素折叠（a 与 a[i] 同址，最粗）、按区间折叠
（区间分析介入）、按分配点+字节区间（最细，FAR 用它）。字
段：练习六的 per-field 通道是"结构体字段互不别名"的精化，
它的对偶是 union（字段全别名）。三片深水各有专门的文献与
工具（SVF 的 heap abstraction 一章是地图），本章读者带走的
应该是指南针：**堆模型的一切选择，都是"把哪些具体地址折
叠成一个抽象位置"的选择**——折叠得粗，pts 集小、假告警
多；折叠得细，精度高、状态爆炸。四类约束的机制在这个选
择面前完全中立。

### 28.4.7 noteVar 的过滤名单

生成器给"谁算变量"维护一张过滤名单：L 开头的分配点名、&
开头的地址名、null——它们是位置系统的内部构造，不是程序
变量，不该出现在"变量位"的登记表里。名单看似琐屑，漏掉的
症状却很曲折：一个 L1 被当变量登记后，深度推断会给它推深
度、激活绑定会查它的形参名、输出层会把它印进双栏——三处
下游各坏一点，最难排查的是第三处（输出多了行无关变量，对
账红）。教训的形式已经超出指针分析：**生成器的名字空间卫
生是约束系统的第一道防线**，内部构造与程序实体必须分姓
名——第 27 章的 % 临时位过滤（练习七）是同一件事的函数
版。

### 28.5.7 监听索引的内存账

三张反向索引（copyOut、loadAt、storeAt）的内存是约束数的线
性函数，构建一次、只读不写——理想的工作集形状。值得记账
的是**间接成本**：每次 pts 上涨要做三次查表（三个监听各一
次），查表命中数为零的成本也要付。本章规模无感，立方程序
（28.11.4）里这三连查是常数项的大头。工业实现把三张索引
合并成一张"边表"按源位置分桶、一次遍历处理三类监听——
SVF 的 constraint graph 就是这个方向的终点。教学版分开写，
是为了每类约束的语义动作在代码里各占一段、与 28.2.7 的四
条规定一一对应——可读性预算再一次压过性能预算，而这个选
择在本章的 8 次 rises 面前毫无代价。

### 28.6.9 并查集的三行圣经

unite/find 的实现不到二十行，却是全书唯一值得背诵的数据结
构片段——它出现在第 28 章，思想却在每章值班（等价类的压缩
表示）。三行核心：find 带路径压缩（查询顺便把路径拍扁）；
unite 挂树（固定方向或按秩）；查询类标签并集（本实现的
pts 语义）。复杂度的经典结论（α(n) 摊还）依赖按秩，本章固
定方向换来 O(log n)——在 n < 百的教学与多数真实程序里两
者与常数无异。背它的理由不在复杂度，而在**形状**：任何
"合并即永久"的语义（等价、连通、同类）都该先想到它——包
含式与合一式的对峙（28.2.8）本质是"要不要把单向阀换成焊
条"的架构决策，而焊条的最便宜实现永远是这三行。

### 28.8.10 alloca 与 malloc：栈与堆的两个世界

IR 里变量槽用 alloca、堆单元用 malloc——本章分析对这两个世
界的态度不同，值得点破。栈世界（变量槽）：地址链接直接用
槽地址（AddrOf 翻译成取 alloca 的指针），每个变量一个槽、
槽即身份，&x 的抽象（变量名 x）与具体（那个 alloca）一一对
应——链接的语义恒等式在这里是严格的双射。堆世界（mal
loc）：同一 alloc 语法点在不同执行、不同循环次数下产生不
同的具体地址，抽象把它们折叠成一个 L——恒等式降级为"同
语法点即同抽象位"。两个世界的精确度差异就这一句：栈位永
不混、堆位按语法点混。真实语言的指针分析还要多一个世界
（全局/静态区），本章 TIP 没有——三个世界的折叠策略合在
一起，就是堆抽象（heap abstraction）这个词的完整外延。

#### 28.8.11 LLVM 自己的指针分析：BasicAA 一瞥

IR 生成之后，LLVM 中端自己也要回答别名问题——每条 load/store
优化前都问"这两处会不会是同一内存"。BasicAA（如今拆成若
干小 pass）的回答策略与本章形成有趣对照：它不做全程序指
针分析，而是**按需逐对判定**——两地址的支配关系、alloca
的不逃逸性、GEP 的常量偏移，几个局部事实组合出 noalias /
mayalias / mustalias 三值答案。快、准、但只答问到的对；本章
的全程序 pts 慢些、粗些，但一次算完全部问题。两种策略在工
业编译器里分层协作：BasicAA 管热路径的指令级判定，全程序
包含分析管跨函数的结构性判定——第 30 章看 opt 的流水线
时，它们会在 -passes 列表里同台。

#### 28.9.10 崩溃边界：为什么敢让 JIT 真解引用

让真实程序在分析工具里解引用可能为 null 的指针，等于邀请
它崩溃——本章敢这么做，靠的是进程边界的安排：tipa 是独立
短命进程，JIT 的崩溃（页错误）被操作系统回收，对账脚本把
非零退出码当作"观察到崩溃"的证据而不是事故。这套安排的
工程学名是故障注入（fault injection）的退化版：不注入故障，
只是不阻止它发生。对比解释器方案：树解释器里 null 解引用
可以抛异常被 catch，"崩溃"变成了数据——反而丢失了硬件级
的证据强度。教程选 JIT 的深层理由在 28.9.4 说过（IR 的裸
性），这里补上安全性的这一面：**短命进程 + 退出码契约**，
让"真崩溃"成为可对账的输出，而不是要躲的事故。

## 28.10.9 三处论证的同构清单

把本章的可靠性论证与第 25、26 章的并排放，同构到可以互相
注释。第 25 章三步：路径覆盖 / 函数忠实 / 合并不丢；第 26
章三步：同姓同款；本章三步：成员不变式 / 四规则对账 / 超
集推论——第一步都是"分析的宇宙覆盖真实执行的全部可能"
（有效路径 / 值路径 / 分配历史），第二步都是"每个机械动作
忠于一条语义规定"（流函数 / 边缘函数 / 约束映射），第三步
都是"合并只宽不窄"（路径边并 / cJoin / 集合包含）。三个框
架、三种数据结构、一个论证模板——这个模板在第 29 章将被
命名为 α(C) ⊑ A 并一次性陈述。读者的收获应当是**认模板的
眼睛**：任何新分析器到手，先找它的三步各在哪里——找不到
的那一步，就是它还没被证明的地方。

## 28.9.8 输入流的设计：覆盖什么、不覆盖什么

两份 .inputs 的行数是设计过的。ptr.inputs 一条（0）——程序
不读 input，这条流只为驱动一次执行、让"输出 10"落地；多几
条只会重复同样的 10。nullcheck.inputs 两条（5、−2）——恰
好各走一支：alloc 支验证解引用真实发生、null 支验证守卫真
实接住；第三条（0）会重复 null 支，不添信息。设计原则：**
每条输入流要么走一条没人走过的路径、要么验证一个没人验
过的输出**——多余的行只是把"no crash"的计数器加一。这个原
则在第 29 章会升级成主角：收集语义的输入流集合直接决定 α
(C) 的形状，流即覆盖，覆盖即精度。

## 28.9 读 --verify-soundness：静态结论与真实执行对账

### 28.9.1 ptr.tip：静态排除 null，真实输出 10

验证程序先静态工作：收集程序里全部解引用点（`collectDerefs/
collectDerefsS` 递归遍历赋值两侧、条件、输出与调用实参），对每个点
查其基址的 Andersen pts 集是否含 null。`ptr.tip` 的输出是三行
`cannot-be-null`：三个解引用点分别是第五行 `*p`（写）、第六行 `*q`
（读），以及第四行 `q = *p` 隐含的那次——三个基址 `p、q、p` 的 pts 集
分别是 {&x}、{L1,L2}、{&x}，均不含 null。

然后真实执行：输入行只有占位的 0（程序本身不读 input），输出 10。这
一步同时验证了 28.3.1 节手算的关键判断——`q` 持 L1、`*q` 读 10——
以及三个静态 `cannot-be-null` 的结论在该输入下确实没有崩溃。结尾
`JIT completed 1 runs: no null-deref crash observed` 是方法论上诚实
的措辞：一次（乃至若干次）成功执行只能证明**这些输入**下没有 null 解
引用，不能证明程序对所有输入安全；普适陈述靠 28.10 的静态论证。

### 28.9.2 nullcheck.tip：假告警与两条真实路径

`nullcheck.tip` 的静态部分只有一个解引用点，结论是
`possibly-null (conservative)`——pts(p) 含 null。真实执行两组输入：
`5 → 7`（走非空分支，解引用 L1）、`-2 → -1`（走空分支，守卫挡住解
引用）。两相对照，本章开头区分的两件事在同一屏里凑齐：

- 分析说"可能 null"，对**合并视角**而言成立：它看到的程序里 p 在某条
  路径上确实是 null，只是那条路径到不了解引用点；
- 真实行为在守卫保护下两路径都安全，静态告警因此是**假告警**，不是
  漏报也不是崩溃。

学会读这种对账，比"全绿"本身更重要：soundness 检验通过的意义是"真
实行为没有逃出预测"，而不是"每条预测都发生"。告警的精度（假阳性
率）要靠路径/上下文敏感去改善，这正是第 22、24 章技术与本章的组合
空间；而漏掉真实行为（假阴性/漏报）在任何组合里都不允许。

### 28.9.3 声告警逐行读与两条真实路径

--verify-soundness 的输出分两段。第一段是静态侧：每个 Deref
点一行，Andersen 的 pts 里查 null 成员——ptr.tip 的 *q 得
cannot-be-null（q 的集合 {L1,L2} 无 null），nullcheck 的 *p 得
possibly-null (conservative)（{L1,null} 含 null）。第二段是动
态侧：JIT 逐条输入流真跑——ptr.inputs 一条（0），输出 10，
一行 "inputs [0] -> outputs [10]"；nullcheck.inputs 两条
（5、−2），输出 7 与 −1；末行 "JIT completed N runs: no
null-deref crash observed"。两段合起来读：静态说"可能 null"
的三种命运里，本章程序落在"假告警"（守卫排除了真实路径）；
静态说"不可能 null"的地方，动态运行全程无解引用崩溃，机器
证据与静态结论互不反驳。这份对账的意义在 28.12 的第四条注
意点里已经说了，这里补它的方法论位置：**静态分析的自我验
证只能做到"未发现反例"，永远做不到"证实可靠"**——反例不可
穷举，能做的是把"未发现"的覆盖面扩大（更多输入、更长路径、
随机化），以及在发现反例时有明确的裁定程序。第 29 章把这件
事推到理论尽头：收集语义作为"全部具体执行"的代言人，α 与
分析的包含关系成为可陈述、可机器检验的命题。

### 28.9.4 为什么用 JIT 而不是解释器做对账

第 8 章以来执行台一直是 LLVM ORC JIT，本章多了一层理由：指针
片段的语义在 IR 层比在树解释器层更"裸"。alloc 直接翻成
malloc 调用、*p 翻成 load、&x 翻成 alloca 的地址——IR 不给
"变量"留任何面子，一切名字到执行时都是地址与寄存器。静态分
析谈论的 L1/L2/&x 在 IR 里各自对应一次真实的 malloc 或
alloca 调用实例，对账因此是"抽象事件 ↔ 具体指令"的直译，没
有中间层再解释一遍。另外，null 解引用在 JIT 下是真崩溃（页
保护），不是解释器里一个可以吞掉的异常——"no crash
observed"这行字的分量因此是硬件级的。教学之外，这也是工业
实践的形状：模糊测试 + 静态告警的联动里，执行器从不手下留
情。

### 28.9.5 verify-soundness 的判定层走读

main.cpp 的 --verify-soundness 分两步。第一步收集判定点：扫
AST 找全部 Deref 结点，每个点用 Andersen 的 pts 查 null 成
员——有则 possibly-null (conservative)、无则 cannot-be-null。
判定只看成员性、不看路径与守卫，这是 28.3.4 已钉过的边界。
第二步动态对账：对 .inputs 的每条输入流，重新生成 IR、验
证、JIT 执行，收集输出；末行汇总运行数与"no null-deref
crash observed"。两步之间没有信息往来——静态不知道动态跑
了什么、动态不受静态结论影响——对账的意义正在这份独立：
两套 reasoning 各自给出结论，人类读者把两份结论并排裁定。
这个"独立双轨"的形状比"用动态验证静态"（会引入循环依赖）
诚实得多，也是教程在 17、28、29 三章反复采用的验证拓扑。

### 28.9.6 假告警率的工程意义

把 nullcheck 的输出当作一份微型的告警质量报告来读：一个告
警、两条真实路径、零真阳性——假告警率 100%。这个数字单独
看很糟，但它来自一个刻意构造的最小对抗样本；真实代码库
里，包含式 null 分析的假告警率通常在可消化的区间（守卫模
式被读者写得很规律），工业检查器的全部工程都在压这个数字
（路径敏感、谓词域、注释断言）。教程把 100% 的样本放进书
里，是想让读者建立对"告警质量"的量感：**soundness 保证的
是下限（不漏报），工程可用性取决于上限（假告警率）**——
两个指标一硬一软，分析器的口碑由软的那个决定。28.12 的第
四条注意点说"对账常态化"，它的完整含义就是持续观测这个软
指标。

## 28.10 正确性论证的完整思路

### 28.10.1 成员不变式：pts 集只装真实地址

论证围绕一个不变式展开，它是 28.1.5 节底线的精确形式。对任意一次具
体执行（给定输入）与执行中到达的每个点，维护：

> **（成员不变式）** 若此刻变量 `v` 的槽里装着某个具体位置 ℓ（栈槽或
> 某代堆块），则 ℓ 所属的抽象标签 L(ℓ) 属于分析结果 pts(v)。

L(ℓ) 的映射即 28.2.1 节的折叠：栈槽按"函数.名字"、堆块按其 alloc 语
法点。堆的"k 有限"抽象在这里是关键一步——同一句 alloc 的第 1 次与第
1000 次调用同享 L 标签，因此不变式无需追踪代数。证明的主体是对执行
步数归纳：初始状态（所有槽为 0 或空指针，null ∈ pts(v) 由 New 规则保
证）成立；再逐类语句验证"一步具体执行后不变式保持"。每一类语句的
验证都归结为对应闭包规则把同一个标签搬进了 pts 集。

### 28.10.2 四条规则的逐一对账

- **New**：具体语义把一个确定的新位置 ℓ 存进 `a`；分析在处理同一语
  句时立即把 L(ℓ) 加入 pts(a)。标签在赋值当时就到位，无时序缺口。
- **Copy**：具体语义把 `b` 的槽值（某地址 ℓ）复制进 `a`；归纳假设给
  出 L(ℓ)∈pts(b)，Copy 规则在该标签到达 pts(b) 的同一事件里把它推进
  pts(a)——28.5.3 节出队第一步做的就是这一次搬运。
- **Load**：具体语义沿 `b` 中的地址 ℓ₁ 找到位置，再从该位置读出 ℓ₂ 存
  进 `a`。归纳假设给出 L(ℓ₁)∈pts(b)；该标签进入 pts(b) 的事件触发
  Load 展开：`copyOut[L(ℓ₁)]` 里登记了 `a`，且 pts(L(ℓ₁)) 的存量被补
  推——归纳假设对"该位置内的 ℓ₂"给出 L(ℓ₂)∈pts(L(ℓ₁))，于是
  L(ℓ₂) 到达 pts(a)。
- **Store**：具体语义沿 `a` 中的地址 ℓ₁ 找到位置，把 `b` 的值 ℓ₂ 写进
  该位置。对称地：L(ℓ₁)∈pts(a) 触发 Store 展开，登记 `b → L(ℓ₁)` 并
  补推存量；L(ℓ₂)∈pts(b)（归纳假设）保证 L(ℓ₂) 被推进 pts(L(ℓ₁))，
  即未来从该位置 Load 的分析结果含着它。

这四条对账有一个共同的结构：**分析事件在具体执行的同一步被触发，触
发后传播的标签集合恰好覆盖该步真实流动的那一个地址。** 不精确只能
以"另一路径上另一地址共享同一标签/同一位置集"的形式进入，不会以
"这一路径的真实地址缺失"的形式进入。这就是 sound 与 imprecise 在论
证里的分界线。

### 28.10.3 地址链接在不变式里的位置

地址链接的必要性现在可以精确陈述。语句 `b = *a`（其中 `a` 持有 `z` 的
栈地址）的具体语义从 `z` 的槽读出 ℓ。若分析中 `&z` 与 `z` 未链接，
Load 展开查的是 pts(&z)——该键名无存量——于是 L(ℓ) 进不了 pts(b)，
成员不变式在这一步被破坏。双向 Copy（Andersen）或节点合一
（Steensgaard）把"从 &z 读"与"从 z 读"定义为同一个 pts 集的两次访
问，归纳假设对 z 槽给出的标签因此可经 &z 取出。链接先于种子就位
（28.5.2）保证第一次事件到达时链接已生效，归纳不在任何一步落空。

### 28.10.4 Steensgaard 的超集性质作为推论

28.2.6 节的超集关系也可以在这套论证里顺手取得。对语句做归纳：
Steensgaard 的每个合一等价于把 Andersen 的一条单向包含关系**加强**
为等价类；Andersen 沿该关系最终传播到的每个标签，加强后的等价类必
含（28.6 的合并直接并标签集，递归合并覆盖多层解引用）。因此成员不
变式对 Steensgaard 同样成立，且其 pts 集可能额外包含仅在反向可达的
标签。Andersen 的 soundness 是直接论证，Steensgaard 的 soundness 是
"超集 + Andersen sound"的推论——这也是本章实现顺序（先 Andersen、
后 Steensgaard、再逐行比对）在论证里的对应。

### 28.10.5 成员不变式的完整陈述与归纳骨架

把 28.10.1 的不变式说得更完整：**对每个名字 x 与每个时刻
t，pts_t(x) 的每个成员都是"某次真实执行在 t 之前曾让 x 装
过（或可能装过）的抽象地址"**。归纳在求解器的事件序列上：
初始时刻空集平凡成立；每个事件处理一类约束——New 把语法点
对应的真实分配并入（该语句真实执行时必然发生），Copy 传播
保持（y 可能装过的 x 也可能装过），Load/Store 展开的前提
（o ∈ pts(p)）由归纳给出真实对应物，展开结论仍属"可能装
过"。归纳的每一步都**不产生新的存在性断言**，只搬运已有的
可能——这就是 soundness 的机械面目。反方向（完整性）不成立
且不追求：pts 里可能有从未同时出现的组合（x 装过 L1 的执行
与 x 装过 L2 的执行是两次不同的执行），流不敏感把时间轴压
扁是精度的主源头、可靠性的无害源。这段陈述与第 29 章的
α(C) ⊑ A 定理同构：把"每时刻的 pts"看作分析 A、把"真实执
行的全部可能"看作收集语义 C，成员不变式就是那个 ⊑。

### 28.10.6 地址链接的引理与证明草图

地址链接值得一条独立引理：**若 copyOut 里有双向边 x ↔ &x，
则分析等价于"把 x 当作一个可被指向的单元"参与一切
Load/Store**。证明思路分两步。第一步（语义侧）：TIP 里 &x
取到的地址唯一对应 x 的存储，"*(&x) 与 x 互为别名"是恒等
式，因此"p 可能装 &x"与"p 可能指向 x 的存储"是同一句话的
两种说法。第二步（机械侧）：双向边使任何流入 x 的成员（New
或 Store 写入）自动流到 &x 的集合，从而任何以 &x 为源/目标
的 Load/Store 展开都能看到它；反之任何要求"x 的内容"的查询
（如 q=*p 展开出 copy(&x,q)）都从 x 的集合取数。两步合起来：
链接边是语义恒等式的数据结构投影。这个引理在第 29 章还会
回来——收集语义的解释器里 &x 同样直接用 x 的槽实现，抽象
与具体在"地址即变量"上碰头。

### 28.10.7 从不变式到性质测试

28.10.5 的成员不变式可以直接落成随机测试：生成随机 TIP 指针
程序（约束形状的随机组合——New/Copy/Load/Store 的随机序列，
保证语法合法），跑 Andersen 得 pts，再跑 Steensgaard，断言三
件事：其一，Andersen 的每个成员在具体执行的采样里出现过
（用 ORC 执行台跑随机输入，收集每次解引用的真实分配点——
需要给解释器或 IR 加 trace）；其二，Steensgaard ⊇ Andersen
（超集性质 28.10.4 的机器版）；其三，两个求解器都终止（超
时即失败）。三个断言合起来是一台小型的性质测试机，任何回
归都以"哪条断言红"的形式自报家门。教程没有内置它（随机程
序生成器本身要写一百行），但练习七把它拆成了可以逐个完成
的台阶。

### 28.10.8 为什么不证明反方向

可靠性（不漏报）与完备性（不误报）在指针分析里是一对不可
兼得的理想：本章只证前者，把后者的缺失明码标价（假告警）。
不证完备的深层原因有两个。其一，完备性对"程序的意义"要
求过强：要证明"pts(x) 的每个成员都有真实执行对应"，必须
精确知道可达路径集——那是莱斯定理 territory（第 2 章），
不可判定。其二，即便在可达路径上，具体执行的选择（循环次
数、输入值）会让"可能"退化为"曾经"——静态的并集投影天然
大于任何单次执行的快照（28.2.11）。所以工业界的路线是把完
备性换成"相对完备"：在给定的路径抽象（比如循环不超过一
圈）下不误报——精确度的天花板由抽象层级锁死，这是第 21
章 widening 讨论的指针版回声。

### 28.10.9 三处论证的同构清单

把本章的可靠性论证与第 25、26 章的并排放，同构到可以互相
注释。第 25 章三步：路径覆盖 / 函数忠实 / 合并不丢；第 26
章三步：同姓同款；本章三步：成员不变式 / 四规则对账 / 超
集推论——第一步都是"分析的宇宙覆盖真实执行的全部可能"
（有效路径 / 值路径 / 分配历史），第二步都是"每个机械动作
忠于一条语义规定"（流函数 / 边缘函数 / 约束映射），第三步
都是"合并只宽不窄"（路径边并 / cJoin / 集合包含）。三个框
架、三种数据结构、一个论证模板——这个模板在第 29 章将被
命名为 α(C) ⊑ A 并一次性陈述。读者的收获应当是**认模板的
眼睛**：任何新分析器到手，先找它的三步各在哪里——找不到
的那一步，就是它还没被证明的地方。

## 28.11 终止性与复杂度

### 28.11.1 Andersen 为什么终止：事件有界

工作表事件 `(v,s)` 的可能总数有界：`v` 的名字数有界（程序变量 + 临时
/位置键名，均由静态语法决定），`s` 是有限标签集（每个 alloc、每个
&z、null 各一个）。`add` 的去重保证每个二元组至多入队一次；动态展开
出的新 Copy 边只在**已存在的名字**之间连接（规则 3/4 引入的位置标签
本就在标签集里），不创造新名字。所以出队处理总次数 ≤ 名字数 × 标签
数，循环必然结束。

### 28.11.2 立方复杂度的来源

最坏时间复杂度是 O(n³)，n 为程序中名字（变量与位置）的量级。直觉
上：pts 集总容量 ≤ n²（n 个集合、每个至多 n 个标签）；一次集合增长
要处理其 Copy/Load/Store 后果，单条新标签在最坏情况下可经 n 条边扇
出（O(n)）；总增长事件 O(n²) × 每事件 O(n) = O(n³)。平方规模的中间
状态（pts 与 copyOut 都可能达 n²）也决定了 O(n²) 的空间。实际程序里
pts 集通常极小（多数变量只指一两个位置），实测代价远低于立方上界
——本章程序的 rises 仅 2 与 8。

### 28.11.3 Steensgaard 的近线性

Steensgaard 的账要简单得多。节点总数线性：每个名字一个节点，每个等
价类至多一个指向节点，而指向节点由语法中的解引用/取址点决定，同样
O(n)。`unite` 每次成功合并减少一个类（至多 n−1 次成功合一）；带路径
压缩与"按秩合一时"经典并查集给出反阿克曼量级的摊还开销。本章实现没
有显式按秩（固定把 ry 挂到 rx），理论上退化到 O(n log n) 量级的路径
压缩界，但对教学规模与多数实际输入与线性不可区分。整体上 O(n·α(n))
（或 O(n log n)）时间、O(n) 空间——比 Andersen 低一个数量级，这正是
它在全程序分析场景下曾经不可替代的原因。

### 28.11.4 立方复杂度的一个具体走形

28.11.2 说了立方来自哪三个因子，这里给一个能"看着它长"的具
体程序形状。造法：n 个变量 a₁…aₙ 依次 copy（a₂=a₁; a₃=a₂;
…），再 n 个分配点 New(a₁, L₁…Lₙ) 全塞给 a₁。传播账：每个
Lᵢ 沿 n−1 条 copy 边走到底，共 O(n²) 次"涨"。再给每个 aⱼ 配
一个 `*aⱼ = z`（Store，z 装着全部 L）——每个 Lᵢ 到达每个 aⱼ
时触发一次 Store 展开、每个展开发一条新 copy、新 copy 又要
把 z 的 n 个成员送一遍……立方在此显形。实测建议：把这个形
状参数化（n=3、6、9），跑本章分析记录 rises，画出曲线看它
何时脱离线性区。这个实验把"最坏界"从课本数字变成手里的体
感——工程直觉的原料。

### 28.11.5 工程账本：SVF 与 Doop 怎么花这些复杂度

立方与近线性的对峙在工业里怎么落子，两个标杆系统给出了答
案。SVF（LLVM 上的指针分析基础设施）选包含式为主轴，用三层
优化把常数压小：位向量表示 pts 集（本章的 std::set 换成
uint64 数组）、约束图离线化（先把含 Store 的约束按 pts 展开
成纯 copy 图再跑）、以及差分传播（只转发增量成员——本章
"登记未来"的工业强化版）。Doop 选 Datalog 为引擎，把四类约
束写成十几条规则、交给 Soufflé 的半朴素求值——求解器整个
消失，复杂度交给引擎的魔集变换去优化。两条路线的共同启示
是**规格与求解分层**：本章把"四条语义规定"与"工作表实现"
写在一个文件里，工业实践把它们拆到两种语言里——规格层永
远只有十几行，性能层随时可换。读者若要继续深入，SVF 的
tutorial 文档与 Doop 的规则库是两个最好的入口，它们的一切
术语（P1/P2 精度档、context-sensitivity 开关）都能映射回本
章的四条约束与两个求解器。

### 28.11.6 复杂度主张的实验验证法

28.11.4 给了立方的构造与账本，这里把"验证一个复杂度主张"
的方法论写成四步，它比结论本身更可迁移。第一步，构造最
坏形状：让三个因子（位置数、标签数、展开次数）各自可参
数化地涨。第二步，固定其余、单拉一个因子：n=3,6,12,24 的
四次运行，记录 rises 与墙钟。第三步，看斜率：对数坐标下
拟合并距——立方主张预测斜率 3。第四步，找偏离并解释：教
学实现里 std::set 的常数、缓存友好的小图，都会让实测在
小 n 处"好于"理论——偏离不是反驳，是常数与低阶项的现场
展示。这四步对任何算法都适用（第 16 章的工作表、第 27 章
的激活、本章的双求解器），读者把它跑一遍，得到的不是三
条曲线，而是"以后见到复杂度主张先问怎么验"的反射。

## 28.12 工程注意点

**先决定"抽象位置按什么折叠"，再写约束。** 位置粒度（每个 alloc 点一
个、每个调用上下文一个、每次执行一个）直接决定分析是否终止、结果
是否可用。本章取最常用的语法点粒度；第 24 章的上下文维度可以正交叠
加（上下文敏感的指针分析是 Java 世界大型分析器的标准配置），但状态
膨胀是两者相乘，工程上往往只对"分辨不清就会出错"的少数函数开上下
文。

**动态约束 = "登记未来"加"重放过去"成对出现。** 28.5.3 的模板在任何
增量约束系统里都适用：只登记不重放，早到的事实丢失；只重放不登
记，循环里晚到的事实丢失。写这类代码时把两个动作写在相邻两行、用
同一条边，复查时最容易发现漏项。

**类型系统放弃维护的信息，编译器前端要自己维护。** opaque ptr 让
LLVM 中端承担更少、前端生成代码时必须自己回答 load/槽/形参的类型。
深度推断（28.8.2）是这类"前端私有类型系统"的最小实例；真实编译器
（Clang）在此维护完整的限定类型与对齐信息。把深度表的生成独立成一
遍预扫描、与代码生成解耦，避免在递归下降里边生成边猜类型。

**把精度告警和真实执行对账常态化。** "possibly-null"这类结论的意义只
有在具体输入面前才能校准：假告警多了，用户会忽略全部告警，分析再
sound 也失去工程价值。让每个检查器都配一个最小的真实执行/证据通道
（本章的 ORC JIT），新增告警先在真实程序上验一遍假阳性率，再决定默
认开启还是降级为提示。

**Andersen/Steensgaard 的选择本质是工程预算选择。** 对现代机器上的中
小翻译单元，立方上界很少打满，Andersen 风格的包含式分析通常负担得
起且更精确；面对数百万行的全程序分析（链接时优化的早期阶段、单核
极小的嵌入式工具链），近线性与 O(n) 空间的 Steensgaard 仍有一席之
地。也可以分层：热点模块跑包含式，其余合一后把结果作为外部摘要接
入——摘要的 pts 集放宽（取超集）即可保持 sound。

## 28.14 文献与延伸坐标

指针分析有一条自己的家谱，本章站在家谱的第二代。第一代是
Andersen 1994（包含式，本章的 28.5）与 Steensgaard 1996（合一
式，本章的 28.6）的对峙：一边精确但立方、一边近线性但粗。
第二代解决"都要"：Fähndrich 等的 online variable substitution、
Heintze–Tardieu 的 field-sensitive 包含式、以及 Pearcé 等对
包含式求解器的系统优化，把立方常数压到工程可用；SVF（Sui 与
Xue）把 LLVM 上的指针分析做成了基础设施，本章的 irgen/jitrun
小执行台就是它的微缩景观。第三代换引擎：把约束写进 Datalog、
用半朴素求值跑闭包——Whaley–Lam 的 bdatt 与开源后裔 Doop 让
"分析规格"与"求解引擎"彻底分离，同一份规则可以换后端对比性
能。教学上本章刻意停在第一代：包含与合一的原始对峙最能暴露
"精度换速度"的交易结构；第二三代的一切技巧（字段敏感、在线
代换、差分传播、Datalog 魔集）都是在这笔交易的两个端点之间
插值。读者的下一步阅读推荐：svf-docs 的 tutorial（LLVM 实战）、
Doop 的规则库（声明式规格的模样）、以及 Smaragdakis 一系列
"指针分析可扩展性"的综述——从本章的 8 个 rises 出发，那边的
文献会显得出乎意料地亲切。

与 spa 原书的对应在 28.1.6 已交代（第 11 章 + 第 4 章的格基
础）；再补一句读法建议：spa 第 11 章的叙述顺序是"约束生成 →
包含求解 → 应用"，与本章一致，但它的例子是记录字段
（record field）而非裸指针——读者若想把字段敏感补上，可以
拿 spa 的例子改造本章：FieldA/RecLit 两个 AST 结点在生成器里
已经有"顺手走过"的占位（28.4.3），把占位换成 per-field 的通
道约束即可，这是比练习更完整的一个周末项目。

## 28.15 练习

练习一：把 ptr.tip 的第五句改成 `*q = y`（写目标从 p 换成
q）。先手推 Andersen 的最终 pts（提示：Store 展开 copy(y,
o) 对 o ∈ pts(q)={L1}——y 的 L2 流向 L1 的内容通道，而"L1 的
内容"在本章粒度下没有名字……想想为什么这条约束实际上无处
落地、q 的集合不变），再运行核对。这道题暴露语法点粒度的
盲区：对堆单元的内容写需要"堆位置也有内容通道"，扩展方向
是 heap-allocated 一等位置化。

练习二：构造一个程序，让 Andersen 与 Steensgaard 的输出差
两个变量以上。提示：合一的传染沿着 Load/Store 链走——把
ptr.tip 的链加长一环（r = *q; *r = x 之类），每加一环，焊条
多焊一个名字。

练习三：给 main.cpp 的 --verify-soundness 加第四种判定："def
initely-null"（pts 恰为 {null}）。什么程序的什么解引用能拿
到这个判定？构造一个（提示：p = null; *p——注意 TIP 会不会
因为不可达分支让你白忙）。这个判定在工业检查器里对应"必然
崩溃"的静态证明，是告警分级的第一格。

练习四：把地址链接的双向边改成单向（只留 copyOut[&x] ⊇ {x}），
跑 ptr.tip。q 的集合会缺什么？用 28.10.6 的引理定位：哪条语
义恒等式被切断了。这个故障是地址链接存在的全部理由。

练习五：深度推断题。给 irgen 的 inferDepths 加一种语句
`x = &y` 其中 y 本身是指针（y 深度 1），推 x 深度；再构造
`**x` 形状的程序（TIP 无此语法，用两次中转模拟），看深度抬
升链条怎么走。目的：体会"深度是承诺不是事实"——推断给的
是下界，代码生成按它选槽类型，抬得不够 load 出错、抬得过分
只是浪费一个指针槽。

练习六：毕业题。给分析加字段通道：RecLit 与 FieldA（生成器
里已占位）造出 o.f 形状的位置，四类约束各出字段版（New 按
字段拆、Load/Store 按 o.f 通道走）。用 spa 第 11 章的记录例
子验证。做完后数一数新增代码里"通道"出现的次数——字段敏
感的全部代价就是给每个位置乘一个字段维度，机制一行没变。

## 28.16 小结

名字与存储的分家催生了指针分析，本章用两台机器回应了同一
份四条约束：Andersen 的单向阀精确到变量粒度、付出立方传播；
Steensgaard 的焊条近线性合一、把精度焊成等价类。地址链接把
"变量的地址"接进数据流，null 成员性把静态结论变成可执行的
判定，深度推断让 opaque ptr 时代的 IR 生成有了自己的小类型
系统，ORC 执行台给一切结论配上硬件级的对账。ptr.tip 的八次
rise、nullcheck 的一条假告警、y 在两栏里的不同命运——三个
数字把两章算法、一条可靠性命题、一个粒度取舍全部钉在了可
复现的输出上。

### 28.16.1 一页纸回顾

四条约束：New 装点、Copy 搬家、Load 顺链读、Store 顺链写。
包含式：监听三张表，涨了就转发，登记未来加重放过去。合一
式：并查集一根焊条，类内标签并，unite 递归焊指向。地址链
接：&x 即 x，双向边打通内容通道。null 进 pts，成员性出判
定；深度进 irgen，槽型不靠 ptr。静态说包含、执行台说事实，
possibly-null 三分：真、假、守卫消。下一章回抽象解释的老
家，把"包含"二字升格为定理。

### 28.12.6 附录对读的三条线索

二十个配套文件按"分析器 → IR/执行台 → 驱动 → 前端基础件"

### 28.14.1 把四类约束写成 Datalog 的样子

为了给"规格层只有十几行"一个具体的形状，把本章约束系统的
Datalog 化在纸上走一遍（只写规则，不写引擎）。五类关系：
new(var, site)、copy(dst, src)、load(p, q)、store(y, p)、以
及 pts(var, site) 为待求。规则四条：new(v,s) ⇒ pts(v,s)；
copy(d,s) ∧ pts(s,o) ⇒ pts(d,o)；load(p,q) ∧ pts(p,o) ∧
pts(o,w) ⇒ pts(q,w)——链上读：p 指向 o、o 装着 w，则 q 装
w；store(y,p) ∧ pts(p,o) ∧ pts(y,w) ⇒ pts(o,w)——链上写。
地址链接是 new(p,&x) 的特例化为两条：pts(&x, x)（&x 指向
x）与……实际上链接在 Datalog 里就是"把变量名当 site 用"，
pts(x,·) 与 pts(&x,·) 经 copy 规则自动互通——四条规则一个
都不用加。这个九行的规格就是本章全部语义；Soufflé 会把它编
译成 C 跑出与 28.5 相同的结果。对照的意义不在"换个引擎重
写一遍"，而在**规格一旦独立，求解策略就成了可替换件**——
包含式、合一式、Datalog、GPU 上的集合运算，都只是这九行的
不同执行器。

### 28.16.3 与第 27 章的合并阅读：约束式分析总复习

第 27 与 28 章是同一台"约束机器"的两次装载，合并阅读的清单
如下。生成器：两章的 genExpr/genStmt 形状逐段相同（27.4.5 的
自包含契约在 28.4.4 重申）；约束种类：val/copy vs New/Copy/
Load/Store——后者多的两类（Load/Store）恰好是"解引用展开"
的需要，而第 27 章的间接调用激活是它的函数版（目标集合先知
道才能展开绑定）；求解器：幂集缓存只涨 vs pts 只涨——同一
个单调骨架，Andersen 的监听展开与 0-CFA 的激活展开是同一个
"动态长边"模式；复杂度：立方对立方（27.8.4 与 28.11.4 的两
份账本可以互相注释）。合并读完，读者手里就有了"约束式分
析"的完整模板：位置、约束、闭包、展开、提取——第五次装
载（无论是你自己写的下一个分析还是读 Doop 规则库）只是换
标签。

### 28.14.2 从 spa 的记录到本章的裸指针

spa 第 11 章的素材是记录（record）与字段，本章换成裸指针，
置换的得失去向如下。失去：字段通道的精化没有展开（练习六
补回）；spa 例子里"同一记录不同字段不别名"的现象缺席。得
到：地址链接（&x）成为一等机制——记录版里字段访问天然经
变量名、不需要"变量的地址"这个概念，裸指针把它逼了出来，
而它恰是 C 系语言的真实痛点；alloc 的堆世界得以与栈世界
对照（28.8.10）；null 作为"可装进指针的值"进入 pts，守卫与
告警的故事（28.9）得以展开——记录版里 null 无处安放。两
个版本覆盖的语义面不同，机制内核（四类约束、包含/合一）
完全共享——读者拿 spa 的记录例子跑本章生成器（补上字段通
道）应当逐条对上它书里的解，这是"换皮不换骨"的又一次验

分析器接口：PtrCon 四类约束、生成器与两个求解器的结果结构。与第 27 章 cfa.hpp 的形状对照着读——约束系统的接口都长这样。

```cpp
// file: src/ptranal.hpp
// 第 28 章配套：指针分析双算法。
//   Andersen（包含式，subset constraints）：
//     pts(a) 之间是 ⊇ 关系，worklist 求最小不动点，精度高、最坏 O(n³)；
//   Steensgaard（合一式，unification）：
//     每条约束让代表元尽早合一，近线性、实现简单，但 pts 集只会更大。
//
// 与第 27 章一样分两层：AST → 与语法无关的约束 PtrCon；求解器只见约束。
#pragma once

#include <map>
#include <set>
#include <string>
#include <vector>

#include "ast.hpp"
#include "symtab.hpp"

namespace tip {

// 四类约束（地址常量 &z 与 null 都按 New 处理，site 名分别为 "&z"/"null"）：
//   New(a,s) : pts(a) ⊇ {s}        分配点/取址/空指针
//   Copy(a,b): pts(a) ⊇ pts(b)
//   Load(a,b): pts(a) ⊇ pts(*b)    若 v∈pts(b)，则 pts(a) ⊇ pts(v)
//   Store(a,b): pts(*a) ⊇ pts(b)   若 v∈pts(a)，则 pts(v) ⊇ pts(b)
struct PtrCon {
    enum K { New, Copy, Load, Store } k;
    std::string a, b;
};

struct PtrConstraints {
    std::vector<PtrCon> cons;
    std::set<std::string> sites;   // 全部抽象位置标签（分配点 + &z + null）
    std::set<std::string> vars;    // 程序中参与指针约束的变量（打印范围）
};

PtrConstraints buildPtrConstraints(const ProgramA &program,
                                   const Bindings &bindings);

struct PtrResult {
    // Andersen 结果：变量（及被引用的抽象堆位置）→ 位置集
    std::map<std::string, std::set<std::string>> andersen;
    // Steensgaard 结果：合一后的代表元 → 位置集；varRep 给出变量的代表元
    std::map<std::string, std::set<std::string>> steensgaard;
    std::map<std::string, std::string> varRep;
    long rises = 0;       // Andersen pts 集上升次数
    long unifies = 0;     // Steensgaard 成功合并次数
};

PtrResult solvePointer(const PtrConstraints &c);

std::string printPointer(const PtrConstraints &c, const PtrResult &r);

}  // namespace tip
```

#### src/ptranal.cpp

分析器实现：生成器、Andersen 包含式求解、Steensgaard 合一式求解与打印。28.4–28.7 的全部叙述以它为底稿。

```cpp
// file: src/ptranal.cpp
#include "ptranal.hpp"

#include <deque>
#include <map>
#include <set>
#include <sstream>
#include <utility>

namespace tip {
namespace {

// 约束生成：只关心"指针世界"的四类语句/表达式。
struct PtrGen {
    const Bindings &bindings;
    const ProgramA &program;
    PtrConstraints out;
    int allocCount = 0;
    std::string current;
    std::map<std::string, const FunDecl *> decls;

    PtrGen(const Bindings &b, const ProgramA &p) : bindings(b), program(p) {
        for (const auto &f : program.funs) decls[f->name] = f.get();
    }

    std::string loc(const std::string &name) {
        return current == "main" ? name : current + "." + name;
    }

    std::string freshAlloc() { return "L" + std::to_string(++allocCount); }

    void noteVar(const std::string &v) {
        if (!v.empty() && v.rfind("L", 0) != 0 && v.rfind("&", 0) != 0 &&
            v != "null")
            out.vars.insert(v);
    }

    void add(PtrCon::K k, std::string a, std::string b) {
        noteVar(a);
        if (k != PtrCon::New) noteVar(b);
        out.cons.push_back(PtrCon{k, std::move(a), std::move(b)});
    }

    // 直接调用的实参→形参（仅变量实参；其余形态本章程序不使用）。
    void callArgs(const CallE *x, const std::string &callee) {
        const auto &params = decls.at(callee)->params;
        for (size_t i = 0; i < x->args.size() && i < params.size(); ++i)
            if (const auto *v = dynamic_cast<const VarRef *>(x->args[i].get()))
                add(PtrCon::Copy, callee + "." + params[i], loc(v->name));
    }

    void genExprs(const Expr *e) {
        if (const auto *x = dynamic_cast<const CallE *>(e)) {
            if (const auto *fn = dynamic_cast<const VarRef *>(x->callee.get())) {
                auto it = bindings.uses.find(fn);
                if (it != bindings.uses.end() &&
                    it->second->kind == Symbol::Fun)
                    callArgs(x, it->second->name);
            }
            for (const auto &a : x->args) genExprs(a.get());
        } else if (const auto *x = dynamic_cast<const Binop *>(e)) {
            genExprs(x->l.get());
            genExprs(x->r.get());
        } else if (const auto *x = dynamic_cast<const Deref *>(e)) {
            genExprs(x->e.get());
        } else if (const auto *x = dynamic_cast<const AllocE *>(e)) {
            genExprs(x->e.get());
        } else if (const auto *x = dynamic_cast<const FieldA *>(e)) {
            genExprs(x->e.get());
        } else if (const auto *x = dynamic_cast<const RecLit *>(e)) {
            for (const auto &[f, v] : x->fields) genExprs(v.get());
        }
    }

    void genStmt(const Stmt *s) {
        if (const auto *x = dynamic_cast<const AssignS *>(s)) {
            std::string lhs;
            bool through = false;        // 左值是 *p
            if (const auto *t = dynamic_cast<const VarRef *>(x->target.get())) {
                lhs = loc(t->name);
            } else if (const auto *t =
                           dynamic_cast<const Deref *>(x->target.get())) {
                if (const auto *v = dynamic_cast<const VarRef *>(t->e.get())) {
                    lhs = loc(v->name);
                    through = true;
                }
            }

            const Expr *rhs = x->value.get();
            if (!lhs.empty()) {
                if (!through) {
                    if (dynamic_cast<const AllocE *>(rhs)) {
                        std::string site = freshAlloc();
                        out.sites.insert(site);
                        add(PtrCon::New, lhs, site);
                    } else if (const auto *a =
                                   dynamic_cast<const AddrOf *>(rhs)) {
                        std::string site = "&" + a->name;
                        out.sites.insert(site);
                        add(PtrCon::New, lhs, site);
                    } else if (dynamic_cast<const NullE *>(rhs)) {
                        out.sites.insert("null");
                        add(PtrCon::New, lhs, "null");
                    } else if (const auto *v =
                                   dynamic_cast<const VarRef *>(rhs)) {
                        add(PtrCon::Copy, lhs, loc(v->name));
                    } else if (const auto *d =
                                   dynamic_cast<const Deref *>(rhs)) {
                        if (const auto *v =
                                dynamic_cast<const VarRef *>(d->e.get()))
                            add(PtrCon::Load, lhs, loc(v->name));
                    }
                } else if (const auto *v =
                               dynamic_cast<const VarRef *>(rhs)) {
                    add(PtrCon::Store, lhs, loc(v->name));
                }
            }
            genExprs(rhs);   // 子结构中的调用实参仍要接线
        } else if (const auto *x = dynamic_cast<const OutputS *>(s)) {
            genExprs(x->e.get());
        } else if (const auto *x = dynamic_cast<const IfS *>(s)) {
            genExprs(x->cond.get());
            genStmt(x->then.get());
            if (x->els) genStmt(x->els.get());
        } else if (const auto *x = dynamic_cast<const WhileS *>(s)) {
            genExprs(x->cond.get());
            genStmt(x->body.get());
        } else if (const auto *x = dynamic_cast<const BlockS *>(s)) {
            for (const auto &st : x->ss) genStmt(st.get());
        }
    }

    PtrConstraints run(const ProgramA &program) {
        for (const auto &f : program.funs) {
            current = f->name;
            genStmt(f->body.get());
        }
        return std::move(out);
    }
};

// ---------------- Andersen：包含式 worklist ----------------
struct Andersen {
    std::map<std::string, std::set<std::string>> pts;
    long rises = 0;

    std::deque<std::pair<std::string, std::string>> wl;   // (变量, 新位置)
    // copyOut[src]：src 每长出位置 s，复制到这些目的（Store 动态加入的
    // 目的可能是抽象堆位置名）。
    std::map<std::string, std::set<std::string>> copyOut;
    std::map<std::string, std::vector<std::string>> loadOf;  // b → a 列表
    std::map<std::string, std::vector<std::string>> storeOf; // a → b 列表

    void add(const std::string &v, const std::string &s) {
        if (pts[v].insert(s).second) {
            ++rises;
            wl.emplace_back(v, s);
        }
    }

    explicit Andersen(const PtrConstraints &c) {
        // 地址链接：&z 与程序变量 z 是同一个抽象位置，双向 copy 边等价。
        // 必须在处理 New 种子前登记，后续传播自动双向到达。
        for (const PtrCon &k : c.cons)
            if (k.k == PtrCon::New && k.b.rfind("&", 0) == 0) {
                std::string z = k.b.substr(1);
                copyOut[z].insert(k.b);
                copyOut[k.b].insert(z);
            }

        for (const PtrCon &k : c.cons) {
            switch (k.k) {
                case PtrCon::New:
                    add(k.a, k.b);
                    break;
                case PtrCon::Copy:
                    copyOut[k.b].insert(k.a);
                    break;
                case PtrCon::Load:
                    loadOf[k.b].push_back(k.a);
                    break;
                case PtrCon::Store:
                    storeOf[k.a].push_back(k.b);
                    break;
            }
        }

        while (!wl.empty()) {
            auto [v, s] = wl.front();
            wl.pop_front();

            auto cit = copyOut.find(v);
            if (cit != copyOut.end())
                for (const std::string &d : cit->second) add(d, s);

            // Load a=*v：v 新指向 s → a ⊇ pts(s)。
            auto lit = loadOf.find(v);
            if (lit != loadOf.end())
                for (const std::string &a : lit->second) {
                    copyOut[s].insert(a);
                    auto sit = pts.find(s);
                    if (sit != pts.end())
                        for (const std::string &t : sit->second) add(a, t);
                }

            // Store *v=b：v 新指向 s → pts(s) ⊇ pts(b)。
            auto sit2 = storeOf.find(v);
            if (sit2 != storeOf.end())
                for (const std::string &b : sit2->second) {
                    copyOut[b].insert(s);
                    auto bit = pts.find(b);
                    if (bit != pts.end())
                        for (const std::string &t : bit->second) add(s, t);
                }
        }
    }
};

// ---------------- Steensgaard：近线性合一 ----------------
struct Steensgaard {
    struct Node {
        int parent;
        std::set<std::string> pts;
        int ptr = -1;      // 代表元字段：指向的代表元节点
    };
    std::vector<Node> nodes;
    std::map<std::string, int> id;
    long unifies = 0;

    int nodeOf(const std::string &name) {
        auto it = id.find(name);
        if (it != id.end()) return it->second;
        int n = static_cast<int>(nodes.size());
        nodes.push_back(Node{n, {}, -1});
        id[name] = n;
        return n;
    }

    int find(int x) {
        while (nodes[x].parent != x) {
            nodes[x].parent = nodes[nodes[x].parent].parent;
            x = nodes[x].parent;
        }
        return x;
    }

    // 确保代表元 rx 有一个指向节点，返回其代表元。
    int ensurePtr(int rx) {
        if (nodes[rx].ptr < 0) {
            int p = static_cast<int>(nodes.size());
            nodes.push_back(Node{p, {}, -1});
            nodes[rx].ptr = p;
        }
        return find(nodes[rx].ptr);
    }

    void unite(int x, int y) {
        int rx = find(x), ry = find(y);
        if (rx == ry) return;
        ++unifies;
        nodes[ry].parent = rx;
        nodes[rx].pts.insert(nodes[ry].pts.begin(), nodes[ry].pts.end());
        if (nodes[rx].ptr >= 0 && nodes[ry].ptr >= 0) {
            unite(nodes[rx].ptr, nodes[ry].ptr);
        } else if (nodes[ry].ptr >= 0) {
            nodes[rx].ptr = nodes[ry].ptr;
        }
        // unite 可能已改变 ptr 字段指向节点的代表关系，重新取代表元。
        if (nodes[rx].ptr >= 0)
            nodes[rx].ptr = find(nodes[rx].ptr);
    }

    explicit Steensgaard(const PtrConstraints &c) {
        // 地址链接：New(a,&z) 让 a 的指向节点就是程序变量 z 的节点，
        // 之后 Load/Store 经 ensurePtr 拿到的正是 z，而非凭空新建。
        for (const PtrCon &k : c.cons)
            if (k.k == PtrCon::New && k.b.rfind("&", 0) == 0) {
                int ra = find(nodeOf(k.a));
                int p = ensurePtr(ra);
                unite(p, nodeOf(k.b.substr(1)));
            }

        for (const PtrCon &k : c.cons) {
            switch (k.k) {
                case PtrCon::New:
                    nodes[find(nodeOf(k.a))].pts.insert(k.b);
                    break;
                case PtrCon::Copy:
                    unite(nodeOf(k.a), nodeOf(k.b));
                    break;
                case PtrCon::Load: {
                    int rb = find(nodeOf(k.b));
                    int p = ensurePtr(rb);
                    unite(nodeOf(k.a), p);
                    break;
                }
                case PtrCon::Store: {
                    int ra = find(nodeOf(k.a));
                    int p = ensurePtr(ra);
                    unite(p, nodeOf(k.b));
                    break;
                }
            }
        }
    }
};

}  // namespace

PtrConstraints buildPtrConstraints(const ProgramA &program,
                                   const Bindings &bindings) {
    PtrGen gen(bindings, program);
    return gen.run(program);
}

PtrResult solvePointer(const PtrConstraints &c) {
    PtrResult r;
    Andersen a(c);
    r.andersen = std::move(a.pts);
    r.rises = a.rises;

    Steensgaard s(c);
    r.unifies = s.unifies;
    for (const auto &[name, id] : s.id) {
        int rep = s.find(id);
        r.varRep[name] = std::to_string(rep);
        r.steensgaard[name] = s.nodes[rep].pts;
    }
    return r;
}
```

```cpp
IRGen::IRGen()
    : ctx(std::make_unique<LLVMContext>()),
      mod(std::make_unique<Module>("tip", *ctx)),
      b(std::make_unique<IRBuilder<>>(*ctx)) {
    // 运行时入口先声明：input 无参返回 i32，output 吃一个 i32。
    auto *i32 = Type::getInt32Ty(*ctx);

                                    false));

namespace {

// TIP 的 main 改名 tip_main：真正的 @main 是我们生成的 C 入口。
std::string emitName(const std::string &name) {
    return name == "main" ? "tip_main" : name;
}

void IRGen::inferDepths(const ProgramA &program) {
    // 符号索引：(函数名, 名字) → Symbol*，形参与局部变量都收录。
    std::map<std::pair<std::string, std::string>, const Symbol *> allSym;
    for (size_t i = 0; i < program.funs.size(); ++i) {
        const FunDecl *f = program.funs[i].get();
        for (const auto &[name, sym] : bindings->scopes[i]->table)
            allSym[{f->name, name}] = &sym;
    }

    // std::function：Deref 分支需要递归调用自身。
    std::function<int(const Expr *)> depthOf = [&](const Expr *e) -> int {
        if (const auto *x = dynamic_cast<const VarRef *>(e)) {
            auto it = bindings->uses.find(x);
            if (it != bindings->uses.end()) {
                auto dit = depth.find(it->second);
                return dit == depth.end() ? 0 : dit->second;
            }
        } else if (const auto *x = dynamic_cast<const AddrOf *>(e)) {
            // &z：在符号索引中找到 z，深度 +1。
            for (const auto &[key, sym] : allSym)
                if (key.second == x->name) {
                    auto dit = depth.find(sym);
                    return (dit == depth.end() ? 0 : dit->second) + 1;
                }
        } else if (dynamic_cast<const AllocE *>(e) ||
                   dynamic_cast<const NullE *>(e)) {
            return 1;
        } else if (const auto *x = dynamic_cast<const Deref *>(e)) {
            int d = depthOf(x->e.get());
            return d > 0 ? d - 1 : 0;
        }
        return 0;
    };

    auto raise = [&](const Symbol *s, int d) {
        auto it = depth.find(s);
        int old = it == depth.end() ? 0 : it->second;
        if (d > old) {
            depth[s] = d;
            return true;
        }
        return false;
    };

    bool changed = true;
    while (changed) {
        changed = false;

        for (const auto &fp : program.funs) {
            const FunDecl *f = fp.get();

            std::function<void(const Stmt *)> walk = [&](const Stmt *s) {
                if (const auto *x = dynamic_cast<const AssignS *>(s)) {
                    if (const auto *t =
                            dynamic_cast<const VarRef *>(x->target.get())) {
                        auto it = bindings->uses.find(t);
                        if (it != bindings->uses.end())
                            if (raise(it->second, depthOf(x->value.get())))
                                changed = true;
                    } else if (const auto *t =
                                   dynamic_cast<const Deref *>(x->target.get())) {
                        // *p = v：p 至少比 v 深一层。
                        int vd = depthOf(x->value.get());
                        if (const auto *v =
                                dynamic_cast<const VarRef *>(t->e.get())) {
                            auto pit = bindings->uses.find(v);
                            if (pit != bindings->uses.end())
                                if (raise(pit->second, vd + 1)) changed = true;
                        }
                    }
                } else if (const auto *x = dynamic_cast<const IfS *>(s)) {
                    walk(x->then.get());
                    if (x->els) walk(x->els.get());
                } else if (const auto *x = dynamic_cast<const WhileS *>(s)) {
                    walk(x->body.get());
                } else if (const auto *x = dynamic_cast<const BlockS *>(s)) {
                    for (const auto &st : x->ss) walk(st.get());
                }
            };
            walk(f->body.get());

            // 返回值深度。
            int rd = depthOf(f->ret->e.get());
            if (rd > retDepth[f->name]) {
                retDepth[f->name] = rd;
                changed = true;
            }

            // 直接调用：实参深度提升形参深度。
            std::function<void(const Expr *)> calls = [&](const Expr *e) {
                if (const auto *x = dynamic_cast<const CallE *>(e)) {
                    if (const auto *fn =
                            dynamic_cast<const VarRef *>(x->callee.get())) {
                        auto fit = bindings->uses.find(fn);
                        if (fit != bindings->uses.end() &&
                            fit->second->kind == Symbol::Fun) {
                            const std::string &calleeName = fit->second->name;
                            const auto &ps = fit->second->fun->params;
                            for (size_t i = 0;
                                 i < x->args.size() && i < ps.size(); ++i) {
                                auto pit = allSym.find(
                                    {calleeName, ps[i]});
                                if (pit != allSym.end())
                                    if (raise(pit->second,
                                              depthOf(x->args[i].get())))
                                        changed = true;
                            }
                        }
                    }
                    for (const auto &a : x->args) calls(a.get());
                } else if (const auto *x = dynamic_cast<const Binop *>(e)) {
                    calls(x->l.get());
                    calls(x->r.get());
                } else if (const auto *x = dynamic_cast<const Deref *>(e)) {
                    calls(x->e.get());
                }
            };
            calls(f->ret->e.get());
            std::function<void(const Stmt *)> cwalk = [&](const Stmt *s) {
                if (const auto *x = dynamic_cast<const AssignS *>(s))
                    calls(x->value.get());
                else if (const auto *x = dynamic_cast<const OutputS *>(s))
                    calls(x->e.get());
                else if (const auto *x = dynamic_cast<const IfS *>(s)) {
                    calls(x->cond.get());
                    cwalk(x->then.get());
                    if (x->els) cwalk(x->els.get());
                } else if (const auto *x = dynamic_cast<const WhileS *>(s)) {
                    calls(x->cond.get());
                    cwalk(x->body.get());
                } else if (const auto *x = dynamic_cast<const BlockS *>(s)) {
                    for (const auto &st : x->ss) cwalk(st.get());
                }
            };
            cwalk(f->body.get());
        }
    }
}

void IRGen::gen(const ProgramA &program, const Bindings &resolved) {
    bindings = &resolved;
    inferDepths(program);

    auto *i32 = Type::getInt32Ty(*ctx);
    for (size_t i = 0; i < program.funs.size(); ++i) {
        const auto &f = program.funs[i];
        std::vector<Type *> args;
        for (const std::string &p : f->params) {
            const Symbol *s = &resolved.scopes[i]->table.at(p);
            int d = depth.count(s) ? depth.at(s) : 0;
            args.push_back(d > 0 ? static_cast<Type *>(b->getPtrTy())
                                 : static_cast<Type *>(i32));
        }
        Type *ret = retDepth[f->name] > 0
                        ? static_cast<Type *>(b->getPtrTy())
                        : static_cast<Type *>(i32);
        Function::Create(FunctionType::get(ret, args, false),
                         Function::ExternalLinkage, emitName(f->name), *mod);
    }

    for (size_t i = 0; i < program.funs.size(); ++i) {
        const auto &f = program.funs[i];
        cur = f.get();
        genFun(f.get(), resolved.scopes[i].get());
    }

    const FunDecl *mainFun = nullptr;
    for (const auto &f : program.funs)
        if (f->name == "main") mainFun = f.get();
    if (!mainFun) throw std::runtime_error("program has no main");
    genWrapper(mainFun);
}

void IRGen::genFun(const FunDecl *f, Scope *scope) {
    auto *fn = llvm::cast<Function>(mod->getFunction(emitName(f->name)));
    auto *entry = BasicBlock::Create(*ctx, "entry", fn);
    b->SetInsertPoint(entry);

    // 形参：按深度开槽 + 存入实参；var 局部：按深度开槽 + 零初始化。
    for (size_t j = 0; j < f->params.size(); ++j) {
        const Symbol *s = &scope->table.at(f->params[j]);
        int d = depth.count(s) ? depth.at(s) : 0;
        Type *ty = d > 0 ? static_cast<Type *>(b->getPtrTy())
                         : static_cast<Type *>(b->getInt32Ty());
        auto *slot = b->CreateAlloca(ty, nullptr, f->params[j]);
        b->CreateStore(fn->getArg(j), slot);
        locals[s] = slot;
    }
    for (const std::string &v : f->vars) {
        const Symbol *s = &scope->table.at(v);
        int d = depth.count(s) ? depth.at(s) : 0;
        Type *ty = d > 0 ? static_cast<Type *>(b->getPtrTy())
                         : static_cast<Type *>(b->getInt32Ty());
        auto *slot = b->CreateAlloca(ty, nullptr, v);
        if (d > 0)
            b->CreateStore(ConstantPointerNull::get(b->getPtrTy()), slot);
        else
            b->CreateStore(b->getInt32(0), slot);
        locals[s] = slot;
    }

    stmt(f->body.get());
    b->CreateRet(expr(f->ret->e.get()));
}

Value *IRGen::expr(const Expr *e) {
    if (const auto *x = dynamic_cast<const IntLit *>(e))
        return ConstantInt::get(b->getInt32Ty(), x->v, true);

    if (const auto *x = dynamic_cast<const VarRef *>(e)) {
        const Symbol *s = bindings->uses.at(x);
        int d = depth.count(s) ? depth.at(s) : 0;
        if (d > 0)
            return b->CreateLoad(b->getPtrTy(), locals.at(s), x->name);
        return b->CreateLoad(b->getInt32Ty(), locals.at(s), x->name);
    }

    if (dynamic_cast<const InputE *>(e))
        return b->CreateCall(rtInput_);

    if (dynamic_cast<const NullE *>(e))
        return ConstantPointerNull::get(b->getPtrTy());

    if (const auto *x = dynamic_cast<const AllocE *>(e)) {
        Value *cell = b->CreateCall(malloc_, {b->getInt64(4)});
        b->CreateStore(expr(x->e.get()), cell);
        return cell;
    }

    if (const auto *x = dynamic_cast<const AddrOf *>(e)) {
        const Symbol *s = nullptr;
        for (const auto &[sym, slot] : locals)
            if (sym->fun == cur && sym->name == x->name) {
                s = sym;
                break;
            }
        if (!s) throw std::runtime_error("&z: z not found in function");
        return locals.at(s);
    }

    if (const auto *x = dynamic_cast<const Deref *>(e)) {
        Value *p = expr(x->e.get());
        // 结果深度 = 基址深度 − 1：决定 load i32 还是 ptr。
        int baseD = 0;
        if (const auto *v = dynamic_cast<const VarRef *>(x->e.get())) {
            const Symbol *s = bindings->uses.at(v);
            baseD = depth.count(s) ? depth.at(s) : 0;
        }
        if (baseD - 1 >= 1)
            return b->CreateLoad(b->getPtrTy(), p);
        return b->CreateLoad(b->getInt32Ty(), p);
    }

    if (const auto *x = dynamic_cast<const Binop *>(e)) {
        if (x->op == BOp::Eq) {
            const Expr *other = nullptr;
            if (dynamic_cast<const NullE *>(x->l.get()))
                other = x->r.get();
            else if (dynamic_cast<const NullE *>(x->r.get()))
                other = x->l.get();

            Value *lv, *rv;
            if (other) {
                Value *ov = expr(other);
                Value *nv = ConstantPointerNull::get(b->getPtrTy());
                if (other == x->l.get()) {
                    lv = ov; rv = nv;
                } else {
                    lv = nv; rv = ov;
                }
            } else {
                lv = expr(x->l.get());
                rv = expr(x->r.get());
            }
            Value *p = b->CreateICmpEQ(lv, rv);
            return b->CreateZExt(p, b->getInt32Ty());
        }

        Value *l = expr(x->l.get());
        Value *r = expr(x->r.get());
        switch (x->op) {
            case BOp::Add: return b->CreateAdd(l, r);
            case BOp::Sub: return b->CreateSub(l, r);
            case BOp::Mul: return b->CreateMul(l, r);
            case BOp::Div: return b->CreateSDiv(l, r);
            case BOp::Gt: {
                Value *p = b->CreateICmpSGT(l, r);
                return b->CreateZExt(p, b->getInt32Ty());
            }
            case BOp::Eq: break;
        }
    }

    if (const auto *x = dynamic_cast<const CallE *>(e)) {
        const auto *nameUse = dynamic_cast<const VarRef *>(x->callee.get());
        if (!nameUse)
            throw std::runtime_error("indirect call not supported");
        const Symbol *s = bindings->uses.at(nameUse);
        if (s->kind != Symbol::Fun)
            throw std::runtime_error("indirect call not supported");
        auto *callee = mod->getFunction(emitName(s->name));
        std::vector<Value *> args;
        for (const auto &a : x->args) args.push_back(expr(a.get()));
        return b->CreateCall(callee, args);
    }

    throw std::runtime_error("unsupported expression (records etc.)");
}

void IRGen::stmt(const Stmt *s) {
    if (const auto *x = dynamic_cast<const AssignS *>(s)) {
        if (const auto *target = dynamic_cast<const VarRef *>(x->target.get())) {
            const Symbol *sym = bindings->uses.at(target);
            b->CreateStore(expr(x->value.get()), locals.at(sym));
            return;
        }
        if (const auto *t = dynamic_cast<const Deref *>(x->target.get())) {
            Value *p = expr(t->e.get());
            b->CreateStore(expr(x->value.get()), p);
            return;
        }
        throw std::runtime_error("field store not supported");
    }

    if (const auto *x = dynamic_cast<const OutputS *>(s)) {
        b->CreateCall(rtOutput_, {expr(x->e.get())});
        return;
    }

    if (const auto *x = dynamic_cast<const IfS *>(s)) {
        Function *fn = b->GetInsertBlock()->getParent();
        auto *thenBB = BasicBlock::Create(*ctx, "then", fn);
        auto *elseBB = BasicBlock::Create(*ctx, "else", fn);
        auto *mergeBB = BasicBlock::Create(*ctx,"merge", fn);

        Value *cc = b->CreateICmpNE(expr(x->cond.get()), b->getInt32(0));
        b->CreateCondBr(cc, thenBB, elseBB);

        b->SetInsertPoint(thenBB);
        stmt(x->then.get());
        if (!b->GetInsertBlock()->getTerminator()) b->CreateBr(mergeBB);

        b->SetInsertPoint(elseBB);
        if (x->els) {
            stmt(x->els.get());
            if (!b->GetInsertBlock()->getTerminator()) b->CreateBr(mergeBB);
        } else {
            b->CreateBr(mergeBB);
        }
        b->SetInsertPoint(mergeBB);
        return;
    }

    if (const auto *x = dynamic_cast<const WhileS *>(s)) {
        Function *fn = b->GetInsertBlock()->getParent();
        auto *header = BasicBlock::Create(*ctx, "wh.cond", fn);
        auto *bodyBB = BasicBlock::Create(*ctx, "wh.body", fn);
        auto *exitBB = BasicBlock::Create(*ctx, "wh.exit", fn);

        b->CreateBr(header);
        b->SetInsertPoint(header);
        Value *cc = b->CreateICmpNE(expr(x->cond.get()), b->getInt32(0));
        b->CreateCondBr(cc, bodyBB, exitBB);

        b->SetInsertPoint(bodyBB);
        stmt(x->body.get());
        if (!b->GetInsertBlock()->getTerminator()) b->CreateBr(header);

        b->SetInsertPoint(exitBB);
        return;
    }

    if (const auto *x = dynamic_cast<const BlockS *>(s)) {
        for (const auto &st : x->ss) stmt(st.get());
        return;
    }

    if (const auto *x = dynamic_cast<const ReturnS *>(s))
        b->CreateRet(expr(x->e.get()));
}

void IRGen::genWrapper(const FunDecl *mainFun) {
    // C 入口：按 TIP main 形参数目读 input，再调用 tip_main。
    // 不命名为 main——MinGW 目标会向 main 注入对 CRT 符号 __main 的调用。
    auto *fn = Function::Create(FunctionType::get(b->getInt32Ty(), false),
                                Function::ExternalLinkage, "tip_entry", *mod);
    auto *entry = BasicBlock::Create(*ctx, "entry", fn);
    b->SetInsertPoint(entry);

    std::vector<Value *> args;
    for (size_t j = 0; j < mainFun->params.size(); ++j)
        args.push_back(b->CreateCall(rtInput_));
    Value *r = b->CreateCall(mod->getFunction("tip_main"), args);
    b->CreateRet(r);
}

bool IRGen::verify() const {
    std::string err;
    llvm::raw_string_ostream os(err);
    bool bad = llvm::verifyModule(*mod, &os);
    os.str();
    return !bad;
}

std::string IRGen::dump() const {
    std::string out;
    llvm::raw_string_ostream os(out);
    mod->print(os, nullptr);
    return os.str();
}
```

```cpp
// file: src/jitrun.cpp
#include "jitrun.hpp"

#include <cstdint>
#include <stdexcept>

#include "llvm/ExecutionEngine/JITSymbol.h"
#include "llvm/ExecutionEngine/Orc/Core.h"
#include "llvm/ExecutionEngine/Orc/LLJIT.h"
#include "llvm/ExecutionEngine/Orc/ThreadSafeModule.h"
#include "llvm/Support/TargetSelect.h"

using llvm::StringRef;
using llvm::JITSymbolFlags;
using llvm::orc::ExecutorSymbolDef;
using llvm::JITTargetAddress;
using llvm::jitTargetAddressToFunction;
using llvm::pointerToJITTargetAddress;
using llvm::orc::LLJITBuilder;
using llvm::orc::SymbolMap;
using llvm::orc::ThreadSafeModule;
using llvm::orc::absoluteSymbols;

namespace tip {
namespace {

// JIT 模块通过这两个宿主函数与外界交换数据。
const std::vector<int> *inQueue = nullptr;
std::vector<int> *outQueue = nullptr;
size_t inPos = 0;

extern "C" int32_t tip_input() {
    if (inPos >= inQueue->size()) return 0;
    return (*inQueue)[inPos++];
}

extern "C" void tip_output(int32_t value) {
    outQueue->push_back(value);
}

void initNative() {
    // 进程内只初始化一次。
    static const bool ready = [] {
        llvm::InitializeNativeTarget();
        llvm::InitializeNativeTargetAsmPrinter();
        return true;
    }();
    (void)ready;
}

[[noreturn]] void fail(llvm::Error e) {
    std::string text = llvm::toString(std::move(e));
    throw std::runtime_error(text);
}

}  // namespace

std::vector<int> runJit(IRGen gen, const std::vector<int> &inputs) {
    initNative();
    std::vector<int> outputs;
    inQueue = &inputs;
    outQueue = &outputs;
    inPos = 0;

    auto jitOrErr = LLJITBuilder().create();
    if (!jitOrErr) fail(jitOrErr.takeError());
    auto jit = std::move(*jitOrErr);

    auto defineHost = [&](StringRef name, void *addr) {
        SymbolMap symbols;
        symbols[jit->mangleAndIntern(name)] = ExecutorSymbolDef(
            llvm::orc::ExecutorAddr::fromPtr(addr), JITSymbolFlags());
        if (llvm::Error e =
                jit->getMainJITDylib().define(absoluteSymbols(symbols)))
            fail(std::move(e));
    };
    defineHost("tip_input", reinterpret_cast<void *>(&tip_input));
    defineHost("tip_output", reinterpret_cast<void *>(&tip_output));

    ThreadSafeModule tsm(std::move(gen.mod), std::move(gen.ctx));
    if (llvm::Error e = jit->addIRModule(std::move(tsm)))
        fail(std::move(e));

    auto mainAddr = jit->lookup("tip_entry");
    if (!mainAddr) fail(mainAddr.takeError());
    auto *entry = jitTargetAddressToFunction<int (*)()>(mainAddr->getValue());
    entry();

    return outputs;
}
```

```cpp
// file: src/main.cpp
// 第 28 章配套程序：指针分析双算法 + JIT 可靠性检验。
//   --check FILE : AST→约束，分别跑 Andersen/Steensgaard，双栏打印 pts 集
//   --verify-soundness FILE INPUTS :
//                  先静态列出每个解引用点"是否可能解引用 null"，
//                  再对 INPUTS 的每一行真实 JIT 执行：
//                  凡运行正常返回即证明该行没有触发 null 解引用，
//                  与静态结论对照
#include <fstream>
#include <iostream>
#include <memory>
#include <sstream>
#include <string>
#include <vector>

#include "TIPLexer.h"
#include "TIPParser.h"
#include "antlr4-runtime.h"

#include "ast_build.hpp"
#include "irgen.hpp"
#include "jitrun.hpp"
#include "ptranal.hpp"
#include "pretty.hpp"
#include "symtab.hpp"

class CollectErrorListener : public antlr4::BaseErrorListener {
public:
    std::vector<std::string> messages;

    void syntaxError(antlr4::Recognizer *, antlr4::Token *, size_t line,
                     size_t column, const std::string &msg,
                     std::exception_ptr) override {
        messages.push_back("syntax error line " + std::to_string(line) + ":" +
                           std::to_string(column) + " " + msg);
    }
};

namespace {

struct Parsed {
    std::unique_ptr<tip::ProgramA> ast;
    tip::Bindings bindings;
};

Parsed parseFile(const std::string &path) {
    std::ifstream src(path);
    if (!src) {
        std::cerr << "cannot open " << path << '\n';
        std::exit(1);
    }
    antlr4::ANTLRInputStream input(src);
    TIPLexer lexer(&input);
    antlr4::CommonTokenStream tokens(&lexer);
    TIPParser parser(&tokens);

    CollectErrorListener errors;
    lexer.removeErrorListeners();
    parser.removeErrorListeners();
    lexer.addErrorListener(&errors);
    parser.addErrorListener(&errors);

    TIPParser::ProgramContext *tree = parser.program();
    if (!errors.messages.empty()) {
        for (const std::string &m : errors.messages) std::cout << m << '\n';
        std::exit(2);
    }

    Parsed result;
    result.ast = tip::buildAst(tree);
    result.bindings = tip::resolveNames(*result.ast);
    if (!result.bindings.errors.empty()) {
        for (const tip::Diag &d : result.bindings.errors)
            std::cout << d.text << '\n';
        std::exit(3);
    }
    return result;
}

std::vector<int> parseRun(const std::string &line) {
    std::istringstream ss(line);
    std::vector<int> vals;
    int v;
    while (ss >> v) vals.push_back(v);
    return vals;
}

// 收集程序中全部解引用表达式（RHS/条件/输出里都算）。
void collectDerefs(const tip::Expr *e,
                   std::vector<const tip::Deref *> &out) {
    if (const auto *x = dynamic_cast<const tip::Deref *>(e)) {
        out.push_back(x);
        collectDerefs(x->e.get(), out);
    } else if (const auto *x = dynamic_cast<const tip::CallE *>(e)) {
        for (const auto &a : x->args) collectDerefs(a.get(), out);
    } else if (const auto *x = dynamic_cast<const tip::Binop *>(e)) {
        collectDerefs(x->l.get(), out);
        collectDerefs(x->r.get(), out);
    }
}
void collectDerefsS(const tip::Stmt *s,
                    std::vector<const tip::Deref *> &out) {
    if (const auto *x = dynamic_cast<const tip::AssignS *>(s)) {
        collectDerefs(x->target.get(), out);
        collectDerefs(x->value.get(), out);
    } else if (const auto *x = dynamic_cast<const tip::OutputS *>(s)) {
        collectDerefs(x->e.get(), out);
    } else if (const auto *x = dynamic_cast<const tip::IfS *>(s)) {
        collectDerefs(x->cond.get(), out);
        collectDerefsS(x->then.get(), out);
        if (x->els) collectDerefsS(x->els.get(), out);
    } else if (const auto *x = dynamic_cast<const tip::WhileS *>(s)) {
        collectDerefs(x->cond.get(), out);
        collectDerefsS(x->body.get(), out);
    } else if (const auto *x = dynamic_cast<const tip::BlockS *>(s)) {
        for (const auto &st : x->ss) collectDerefsS(st.get(), out);
    }
}

}  // namespace

int main(int argc, char **argv) {
    if (argc == 3 && std::string(argv[1]) == "--check") {
        Parsed p = parseFile(argv[2]);
        tip::PtrConstraints cons =
            tip::buildPtrConstraints(*p.ast, p.bindings);
        tip::PtrResult r = tip::solvePointer(cons);
        std::cout << tip::printPointer(cons, r);
        return 0;
    }

    if (argc == 4 && std::string(argv[1]) == "--verify-soundness") {
        std::ifstream in(argv[3]);
        if (!in) {
            std::cerr << "cannot open " << argv[3] << '\n';
            return 1;
        }
        Parsed p = parseFile(argv[2]);
        tip::PtrConstraints cons =
            tip::buildPtrConstraints(*p.ast, p.bindings);
        tip::PtrResult r = tip::solvePointer(cons);

        // 静态：每个解引用点基址的 pts 集是否含 null。
        std::vector<const tip::Deref *> derefs;
        for (const auto &f : p.ast->funs) collectDerefsS(f->body.get(), derefs);
        std::cout << "static deref sites: " << derefs.size() << "\n";
        for (const tip::Deref *d : derefs) {
            std::string status = "no-variable-base";
            if (const auto *v =
                    dynamic_cast<const tip::VarRef *>(d->e.get())) {
                auto it = r.andersen.find(v->name);
                bool mayNull = false;
                if (it != r.andersen.end())
                    mayNull = it->second.count("null") > 0;
                status = mayNull ? "possibly-null (conservative)"
                                 : "cannot-be-null";
            }
            std::cout << "  *(" << tip::printExpr(d->e.get()) << "): " << status
                      << "\n";
        }

        int runs = 0;
        std::string line;
        while (std::getline(in, line)) {
            std::string trimmed = line;
            size_t a = trimmed.find_first_not_of(" \t\r\n");
            if (a == std::string::npos) continue;
            if (trimmed[a] == '#') continue;

            std::vector<int> inputs = parseRun(trimmed);
            tip::IRGen gen;
            gen.gen(*p.ast, p.bindings);
            if (!gen.verify()) {
                std::cerr << "generated module failed verification\n";
                return 1;
            }
            std::vector<int> outputs = tip::runJit(std::move(gen), inputs);
            ++runs;
            std::cout << "run " << runs << ": inputs";
            for (int v : inputs) std::cout << " " << v;
            std::cout << " -> outputs";
            for (int v : outputs) std::cout << " " << v;
            std::cout << "\n";
        }
        std::cout << "JIT completed " << runs
                  << " runs: no null-deref crash observed\n";
        return 0;
    }

    std::cerr << "usage: tipa --check FILE | tipa --verify-soundness FILE INPUTS\n";
    return 1;
}
```

#### src/ast_build.cpp

AST 构建：把 ANTLR 树搬到 AST，指针结点的构造在此分派。

```cpp
// file: src/ast_build.cpp
#include "ast_build.hpp"

#include <utility>
#include <vector>

namespace tip {

std::unique_ptr<ProgramA> AstBuilder::build(TIPParser::ProgramContext *tree) {
    auto program = std::make_unique<ProgramA>();
    for (auto *fc : tree->function()) program->funs.push_back(buildFun(fc));
    return program;
}

std::unique_ptr<FunDecl> AstBuilder::buildFun(TIPParser::FunctionContext *ctx) {
    auto f = std::make_unique<FunDecl>();
    f->name = ctx->IDENT()->getText();
    if (ctx->params()) {
        for (auto *p : ctx->params()->IDENT()) f->params.push_back(p->getText());
    }
    if (ctx->varDecls()) {
        for (auto *v : ctx->varDecls()->IDENT()) f->vars.push_back(v->getText());
    }

    std::vector<std::unique_ptr<Stmt>> body;
    for (auto *sc : ctx->stmt()) body.push_back(buildStmt(sc));
    f->body = std::make_unique<BlockS>(std::move(body));

    f->ret = std::make_unique<ReturnS>(buildExpr(ctx->expr()));
    return f;
}

std::unique_ptr<Expr> AstBuilder::buildLvalue(TIPParser::LvalueContext *lv) {
    std::unique_ptr<Expr> base;
    std::string field;
    if (auto *d = dynamic_cast<TIPParser::DirectLvalueContext *>(lv)) {
        base = std::make_unique<VarRef>(d->IDENT(0)->getText());
        if (d->IDENT().size() == 2) field = d->IDENT(1)->getText();
    } else {
        auto *p = dynamic_cast<TIPParser::PointerLvalueContext *>(lv);
        base = std::make_unique<Deref>(buildExpr(p->expr()));
        if (p->IDENT()) field = p->IDENT()->getText();
    }
    if (!field.empty())
        return std::make_unique<FieldA>(std::move(base), std::move(field));
    return base;
}

std::unique_ptr<Expr> AstBuilder::buildExpr(TIPParser::ExprContext *ctx) {
    if (auto *c = dynamic_cast<TIPParser::IntExprContext *>(ctx))
        return std::make_unique<IntLit>(std::stoi(c->INT()->getText()));
    if (auto *c = dynamic_cast<TIPParser::VarExprContext *>(ctx))
        return std::make_unique<VarRef>(c->IDENT()->getText());
    if (dynamic_cast<TIPParser::InputExprContext *>(ctx))
        return std::make_unique<InputE>();
    if (dynamic_cast<TIPParser::NullExprContext *>(ctx))
        return std::make_unique<NullE>();
    if (auto *c = dynamic_cast<TIPParser::ParenExprContext *>(ctx))
        return buildExpr(c->expr());

    if (auto *c = dynamic_cast<TIPParser::AddExprContext *>(ctx)) {
        const BOp op = c->PLUS() ? BOp::Add : BOp::Sub;
        return std::make_unique<Binop>(op, buildExpr(c->expr(0)), buildExpr(c->expr(1)));
    }
    if (auto *c = dynamic_cast<TIPParser::MulExprContext *>(ctx)) {
        const BOp op = c->STAR() ? BOp::Mul : BOp::Div;
        return std::make_unique<Binop>(op, buildExpr(c->expr(0)), buildExpr(c->expr(1)));
    }
    if (auto *c = dynamic_cast<TIPParser::CmpExprContext *>(ctx)) {
        const BOp op = c->GT() ? BOp::Gt : BOp::Eq;
        return std::make_unique<Binop>(op, buildExpr(c->expr(0)), buildExpr(c->expr(1)));
    }
    if (auto *c = dynamic_cast<TIPParser::NegExprContext *>(ctx)) {
        // TIP 没有负数字面量 token，-E 即 0-E。
        return std::make_unique<Binop>(BOp::Sub, std::make_unique<IntLit>(0),
                                       buildExpr(c->expr()));
    }
    if (auto *c = dynamic_cast<TIPParser::CallExprContext *>(ctx)) {
        std::vector<std::unique_ptr<Expr>> args;
        if (c->args())
            for (auto *a : c->args()->expr()) args.push_back(buildExpr(a));
        return std::make_unique<CallE>(buildExpr(c->expr()), std::move(args));
    }
    if (auto *c = dynamic_cast<TIPParser::FieldExprContext *>(ctx))
        return std::make_unique<FieldA>(buildExpr(c->expr()), c->IDENT()->getText());
    if (auto *c = dynamic_cast<TIPParser::DerefExprContext *>(ctx))
        return std::make_unique<Deref>(buildExpr(c->expr()));
    if (auto *c = dynamic_cast<TIPParser::AddrExprContext *>(ctx))
        return std::make_unique<AddrOf>(c->IDENT()->getText());
    if (auto *c = dynamic_cast<TIPParser::AllocExprContext *>(ctx))
        return std::make_unique<AllocE>(buildExpr(c->expr()));
    if (auto *c = dynamic_cast<TIPParser::RecExprContext *>(ctx)) {
        std::vector<std::pair<std::string, std::unique_ptr<Expr>>> fields;
        for (auto *fc : c->field())
            fields.emplace_back(fc->IDENT()->getText(), buildExpr(fc->expr()));
        return std::make_unique<RecLit>(std::move(fields));
    }
    return nullptr;  // 解析成功时不会到达
}

std::unique_ptr<Stmt> AstBuilder::buildStmt(TIPParser::StmtContext *ctx) {
    if (auto *c = dynamic_cast<TIPParser::AssignStmtContext *>(ctx))
        return std::make_unique<AssignS>(buildLvalue(c->lvalue()), buildExpr(c->expr()));
    if (auto *c = dynamic_cast<TIPParser::OutputStmtContext *>(ctx))
        return std::make_unique<OutputS>(buildExpr(c->expr()));
    if (auto *c = dynamic_cast<TIPParser::IfStmtContext *>(ctx)) {
        std::unique_ptr<Stmt> els;
        if (c->stmt().size() == 2) els = buildStmt(c->stmt(1));
        return std::make_unique<IfS>(buildExpr(c->expr()), buildStmt(c->stmt(0)),
                                     std::move(els));
    }
    if (auto *c = dynamic_cast<TIPParser::WhileStmtContext *>(ctx))
        return std::make_unique<WhileS>(buildExpr(c->expr()), buildStmt(c->stmt()));
    if (auto *c = dynamic_cast<TIPParser::BlockStmtContext *>(ctx)) {
        std::vector<std::unique_ptr<Stmt>> ss;
        for (auto *sc : c->stmt()) ss.push_back(buildStmt(sc));
        return std::make_unique<BlockS>(std::move(ss));
    }
    return nullptr;  // 解析成功时不会到达
}

std::unique_ptr<ProgramA> buildAst(TIPParser::ProgramContext *tree) {
    return AstBuilder{}.build(tree);
}
```

#### src/cfg.cpp

CFG 构造，第 7 章的两遍算法原样。

```cpp
// file: src/cfg.cpp
#include "cfg.hpp"

#include <map>
#include <set>
#include <sstream>
#include <vector>

#include "pretty.hpp"

namespace tip {
namespace {

// 两遍构造：第一遍按 AST 先序给所有程序点分配固定编号；第二遍连边。
// 先编号再连边，是为了让编号严格按源码顺序（连边时若先构造后继节点，
// 后继会抢在前面编号），从而输出与程序点编号都是确定的。
class CfgBuilder {
public:
    explicit CfgBuilder(const ProgramA &program) : program_(program) {}

    Cfg run() {
        Cfg cfg;
        for (const auto &fun : program_.funs) {
            FunCfg fc;
            cur_ = &fc;
            cur_->name = fun->name;
            nextId_ = 1;
            stmtId_.clear();

            const int entry = addNode(CfgNode::Kind::Entry);
            cur_->entry = entry;
            numberStmt(fun->body.get());
            const int retId = addNode(CfgNode::Kind::Return, fun->ret.get());
            const int exitId = addNode(CfgNode::Kind::Exit);
            cur_->exitNode = exitId;

            // 连边：语句构造返回它自己的入口点集合；空块没有节点，直接透传后继。
            std::vector<int> bodyEntries = wireStmt(fun->body.get(), {retId});
            if (bodyEntries.empty()) bodyEntries = {retId};
            link(entry, bodyEntries);
            link(retId, {exitId});

            // set 去重并排序：CFG 边不允许重复，输出顺序固定。
            std::set<std::pair<int, int>> uniq(cur_->edges.begin(), cur_->edges.end());
            cur_->edges.assign(uniq.begin(), uniq.end());
            cfg.funs.push_back(std::move(*cur_));
        }
        return cfg;
    }

private:
    const ProgramA &program_;
    FunCfg *cur_ = nullptr;
    int nextId_ = 1;
    std::map<const Stmt *, int> stmtId_;

    int addNode(CfgNode::Kind kind, const Stmt *stmt = nullptr) {
        const int id = nextId_++;
        cur_->nodes.emplace(id, CfgNode{id, kind, stmt});
        return id;
    }

    // ---- 第一遍：编号 ----
    void numberStmt(const Stmt *s) {
        if (const auto *b = dynamic_cast<const BlockS *>(s)) {
            for (const auto &x : b->ss) numberStmt(x.get());
            return;
        }
        if (const auto *x = dynamic_cast<const IfS *>(s)) {
            stmtId_[x] = addNode(CfgNode::Kind::Branch, x);
            numberStmt(x->then.get());
            numberStmt(x->els.get());
            return;
        }
        if (const auto *x = dynamic_cast<const WhileS *>(s)) {
            stmtId_[x] = addNode(CfgNode::Kind::Branch, x);
            numberStmt(x->body.get());
            return;
        }
        if (dynamic_cast<const AssignS *>(s)) {
            stmtId_[s] = addNode(CfgNode::Kind::Assign, s);
            return;
        }
        if (dynamic_cast<const OutputS *>(s)) {
            stmtId_[s] = addNode(CfgNode::Kind::Output, s);
        }
    }

    // ---- 第二遍：连边。返回进入该语句时首先到达的程序点集合 ----
    std::vector<int> wireStmt(const Stmt *s, const std::vector<int> &succ) {
        if (const auto *b = dynamic_cast<const BlockS *>(s)) {
            std::vector<int> cur = succ;
            for (auto it = b->ss.rbegin(); it != b->ss.rend(); ++it)
                cur = wireStmt(it->get(), cur);
            return cur;
        }
        if (const auto *x = dynamic_cast<const IfS *>(s)) {
            const int n = stmtId_[x];
            std::vector<int> targets = wireStmt(x->then.get(), succ);
            if (targets.empty()) targets = succ;
            if (x->els) {
                std::vector<int> e = wireStmt(x->els.get(), succ);
                if (e.empty()) e = succ;
                targets.insert(targets.end(), e.begin(), e.end());
            } else {
                targets.insert(targets.end(), succ.begin(), succ.end());
            }
            link(n, targets);
            return {n};
        }
        if (const auto *x = dynamic_cast<const WhileS *>(s)) {
            const int n = stmtId_[x];
            // 循环体执行完回到条件点；空体时条件点连一条自边（等于死循环）。
            std::vector<int> bodyEntries = wireStmt(x->body.get(), {n});
            if (bodyEntries.empty()) bodyEntries = {n};
            link(n, bodyEntries);
            link(n, succ);
            return {n};
        }
        const int n = stmtId_[s];
        link(n, succ);
        return {n};
    }

    void link(int from, const std::vector<int> &to) {
        for (int t : to) cur_->edges.emplace_back(from, t);
    }
};

const char *kindName(CfgNode::Kind kind) {
    switch (kind) {
        case CfgNode::Kind::Entry: return "entry";
        case CfgNode::Kind::Exit: return "exit";
        case CfgNode::Kind::Assign: return "assign";
        case CfgNode::Kind::Output: return "output";
        case CfgNode::Kind::Branch: return "branch";
        case CfgNode::Kind::Return: return "return";
    }
    return "?";
}

}  // namespace

Cfg buildCfg(const ProgramA &program) { return CfgBuilder(program).run(); }

std::string printCfg(const Cfg &cfg) {
    std::ostringstream out;
    for (const FunCfg &f : cfg.funs) {
        out << "== " << f.name << " ==\n";
        out << "nodes:\n";
        for (const auto &[id, node] : f.nodes) {
            out << "  " << id << ": " << kindName(node.kind);
            if (node.stmt) out << "  " << printStmtLine(*node.stmt);
            out << "\n";
        }
        out << "edges:\n";
        for (const auto &[a, b] : f.edges) out << "  " << a << " -> " << b << "\n";
    }
    return out.str();
}
```

```cpp
// file: src/pretty.cpp
#include "pretty.hpp"

#include <string>

namespace tip {

namespace {

// 表达式打印为前缀式：运算符与符号的对照表。
std::string exprText(const Expr *e) {
    if (const auto *x = dynamic_cast<const IntLit *>(e)) return std::to_string(x->v);
    if (const auto *x = dynamic_cast<const VarRef *>(e)) return x->name;
    if (dynamic_cast<const InputE *>(e)) return "input";
    if (dynamic_cast<const NullE *>(e)) return "null";

    if (const auto *x = dynamic_cast<const Binop *>(e)) {
        const char *sym = "+";
        switch (x->op) {
            case BOp::Add: sym = "+"; break;
            case BOp::Sub: sym = "-"; break;
            case BOp::Mul: sym = "*"; break;
            case BOp::Div: sym = "/"; break;
            case BOp::Gt: sym = ">"; break;
            case BOp::Eq: sym = "=="; break;
        }
        return "(" + std::string(sym) + " " + exprText(x->l.get()) + " " +
               exprText(x->r.get()) + ")";
    }
    if (const auto *x = dynamic_cast<const CallE *>(e)) {
        std::string s = "(call " + exprText(x->callee.get());
        for (const auto &a : x->args) s += " " + exprText(a.get());
        return s + ")";
    }
    if (const auto *x = dynamic_cast<const Deref *>(e))
        return "(* " + exprText(x->e.get()) + ")";
    if (const auto *x = dynamic_cast<const AddrOf *>(e)) return "(& " + x->name + ")";
    if (const auto *x = dynamic_cast<const AllocE *>(e))
        return "(alloc " + exprText(x->e.get()) + ")";
    if (const auto *x = dynamic_cast<const FieldA *>(e))
        return "(. " + exprText(x->e.get()) + " " + x->field + ")";
    if (const auto *x = dynamic_cast<const RecLit *>(e)) {
        std::string s = "{";
        for (size_t i = 0; i < x->fields.size(); ++i) {
            if (i) s += ", ";
            s += x->fields[i].first + ": " + exprText(x->fields[i].second.get());
        }
        return s + "}";
    }
    return "<unknown expr>";
}

std::string indent(int level) { return std::string(static_cast<size_t>(level) * 2, ' '); }

// 语句打印带缩进，一条语句一行（块内多行）。
void stmtText(const Stmt *s, int level, std::string &out) {
    if (const auto *x = dynamic_cast<const AssignS *>(s)) {
        out += indent(level) + exprText(x->target.get()) + " = " +
               exprText(x->value.get()) + " ;\n";
        return;
    }
    if (const auto *x = dynamic_cast<const OutputS *>(s)) {
        out += indent(level) + "output " + exprText(x->e.get()) + " ;\n";
        return;
    }
    if (const auto *x = dynamic_cast<const ReturnS *>(s)) {
        out += indent(level) + "return " + exprText(x->e.get()) + " ;\n";
        return;
    }
    if (const auto *x = dynamic_cast<const IfS *>(s)) {
        out += indent(level) + "if (" + exprText(x->cond.get()) + ")\n";
        stmtText(x->then.get(), level + 1, out);
        if (x->els) {
            out += indent(level) + "else\n";
            stmtText(x->els.get(), level + 1, out);
        }
        return;
    }
    if (const auto *x = dynamic_cast<const WhileS *>(s)) {
        out += indent(level) + "while (" + exprText(x->cond.get()) + ")\n";
        stmtText(x->body.get(), level + 1, out);
        return;
    }
    if (const auto *x = dynamic_cast<const BlockS *>(s)) {
        out += indent(level) + "{\n";
        for (const auto &st : x->ss) stmtText(st.get(), level + 1, out);
        out += indent(level) + "}\n";
        return;
    }
    out += indent(level) + "<unknown stmt>\n";
}

}  // namespace

std::string printExpr(const Expr *e) { return exprText(e); }

std::string printProgram(const ProgramA &program) {
    std::string out;
    for (const auto &f : program.funs) {
        std::string paramList;
        for (size_t i = 0; i < f->params.size(); ++i) {
            if (i) paramList += ",";
            paramList += f->params[i];
        }
        out += f->name + "(" + paramList + ") {\n";
        if (!f->vars.empty()) {
            out += indent(1) + "var ";
            for (size_t i = 0; i < f->vars.size(); ++i) {
                if (i) out += ",";
                out += f->vars[i];
            }
            out += " ;\n";
        }
        // 函数体是 BlockS；打印其内部语句而不是再嵌一层花括号。
        const auto *body = dynamic_cast<const BlockS *>(f->body.get());
        for (const auto &st : body->ss) stmtText(st.get(), 1, out);
        stmtText(f->ret.get(), 1, out);
        out += "}\n";
    }
    return out;
}

// 单行形式：CFG 节点标签等"节点旁边写一句话"的场合使用。
std::string printStmtLine(const Stmt &stmt) {
    std::string out;
    stmtText(&stmt, 0, out);
    if (!out.empty() && out.back() == '\n') out.pop_back();
    return out;
}

}  // namespace tip
```

```cpp
// 符号表与名字解析：把 AST 上的每个 VarRef 绑定到它的声明
// （函数 / 参数 / 局部变量），同时产出未声明、重复声明诊断。
```

#### src/symtab.cpp

名字解析；FunDecl 的 params/vars 是 callArgs 接线的依据。

```cpp
// file: src/symtab.cpp
#include "symtab.hpp"

#include <utility>

namespace tip {

namespace {

// 解析器在遍历 AST 的同时完成绑定与诊断收集。
struct Resolver {
    Bindings bindings;
    Scope *current = nullptr;
    const FunDecl *owner = nullptr;

    void declare(const std::string &name, Symbol::Kind kind) {
        if (current->table.count(name)) {
            bindings.errors.push_back({"error: redeclared '" + name + "'"});
            return;  // 保留先声明者，后声明被忽略
        }
        current->table.emplace(name, Symbol{kind, name, owner});
    }

    void resolveExpr(const Expr *e) {
        if (const auto *x = dynamic_cast<const VarRef *>(e)) {
            const Symbol *s = current->lookup(x->name);
            if (!s) {
                bindings.errors.push_back({"error: undeclared '" + x->name + "'"});
            } else {
                bindings.uses[x] = s;
            }
            return;
        }
        if (const auto *x = dynamic_cast<const Binop *>(e)) {
            resolveExpr(x->l.get());
            resolveExpr(x->r.get());
            return;
        }
        if (const auto *x = dynamic_cast<const CallE *>(e)) {
            resolveExpr(x->callee.get());
            for (const auto &a : x->args) resolveExpr(a.get());
            return;
        }
        if (const auto *x = dynamic_cast<const Deref *>(e)) return resolveExpr(x->e.get());
        if (const auto *x = dynamic_cast<const AllocE *>(e)) return resolveExpr(x->e.get());
        if (const auto *x = dynamic_cast<const FieldA *>(e)) {
            resolveExpr(x->e.get());  // 字段名不是变量，无需解析
            return;
        }
        if (const auto *x = dynamic_cast<const RecLit *>(e)) {
            for (const auto &f : x->fields) resolveExpr(f.second.get());
            return;
        }
        // IntLit / InputE / AddrOf / NullE：无变量使用。
    }

    void resolveStmt(const Stmt *s) {
        if (const auto *x = dynamic_cast<const AssignS *>(s)) {
            resolveExpr(x->target.get());
            resolveExpr(x->value.get());
            return;
        }
        if (const auto *x = dynamic_cast<const OutputS *>(s)) return resolveExpr(x->e.get());
        if (const auto *x = dynamic_cast<const IfS *>(s)) {
            resolveExpr(x->cond.get());
            resolveStmt(x->then.get());
            if (x->els) resolveStmt(x->els.get());
            return;
        }
        if (const auto *x = dynamic_cast<const WhileS *>(s)) {
            resolveExpr(x->cond.get());
            resolveStmt(x->body.get());
            return;
        }
        if (const auto *x = dynamic_cast<const BlockS *>(s)) {
            for (const auto &st : x->ss) resolveStmt(st.get());
            return;
        }
        if (const auto *x = dynamic_cast<const ReturnS *>(s)) return resolveExpr(x->e.get());
    }
};

}  // namespace

const Symbol *Scope::lookup(const std::string &name) const {
    auto it = table.find(name);
    if (it != table.end()) return &it->second;
    return parent ? parent->lookup(name) : nullptr;
}

Bindings resolveNames(ProgramA &program) {
    Resolver resolver;
    resolver.bindings.global = Scope(nullptr);
    Scope *global = &resolver.bindings.global;

    // 第一遍：所有函数名进入全局作用域。
    for (const auto &f : program.funs) {
        if (global->table.count(f->name)) {
            resolver.bindings.errors.push_back({"error: redeclared '" + f->name + "'"});
            continue;
        }
        global->table.emplace(f->name, Symbol{Symbol::Fun, f->name, f.get()});
    }

    // 第二遍：每个函数开自己的作用域，父作用域是全局表；
    // 作用域所有权交给 Bindings，遍历结束后符号依然存活。
    for (const auto &f : program.funs) {
        auto functionScope = std::make_unique<Scope>(global);
        resolver.current = functionScope.get();
        resolver.owner = f.get();

        for (const std::string &p : f->params) resolver.declare(p, Symbol::Param);
        for (const std::string &v : f->vars) resolver.declare(v, Symbol::Local);

        resolver.resolveStmt(f->body.get());
        resolver.resolveStmt(f->ret.get());

        resolver.current = nullptr;
        resolver.bindings.scopes.push_back(std::move(functionScope));
    }
    return std::move(resolver.bindings);
}

}  // namespace tip
```
