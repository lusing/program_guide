# 03 简单类型 λ 演算 λ→

> 对应读本：TTAFP 第 2–3 章；Hindley 第 5 章；TAPL 第 9 章。
> 代码：`examples/03_stlc/`——三种工程路线各一家：Lean **检查器式**
> （extrinsic，类型检查是函数）、Coq **推导即数据式**（类型规则是
> Inductive 关系，还证了进展定理）、Agda **内在式**（intrinsic，
> 类型长在项的索引上，非法项无法表示）。

## 3.1 Church 式与 Curry 式：两条引进类型的路

给无类型 λ 演算加类型有两种立场，贯穿整个类型论史：

- **Church 式（项内注解）**：类型是语法的一部分，`λ(x:T). M` 写死在
  绑定器上。良式项自带类型，「无类型的项」根本不存在。本指南按
  TTAFP 的路线走 Church 式。
- **Curry 式（项外指派）**：项还是无类型的项，类型系统是一个**关系**
  `Γ ⊢ M : T`（指派/assignment）。一个项可以没有类型、也可以有多个
  类型。Hindley 全书走这条路——它通向**主类型定理**与 Hindley–Milner
  类型推断（04 章）。

λ→（Church 1940）的类型世界只有两件事：

```text
类型   T, U ::= α          基类型（本指南记 β，代码里 base / ι）
             | T → U       函数类型
项     M, N ::= x          变量
             | λ(x:T). M   抽象（注解在绑定器上）
             | M N         应用
```

## 3.2 类型规则与推导树

判断形式是 `Γ ⊢ M : T`（Γ 是「变量 ↦ 类型」的列表）。三条规则
——引入、消去、公理——正对应自然演绎的格式：

```text
(ax)  Γ(k) = T                (→I)  Γ, x:T ⊢ M : U          (→E)  Γ ⊢ M : T → U    Γ ⊢ N : T
      ─────────────                 ─────────────────             ─────────────────────────────
      Γ ⊢ var k : T                Γ ⊢ λ(x:T). M : T → U          Γ ⊢ M N : U
```

一棵完整推导（`λ(f:β→β). λ(x:β). f x` 的类型推导）：

```text
                                    [f:β→β, x:β](0) = β→β     [f:β→β, x:β](1) = β
                                    ─────────────────────────  ────────────────────
                          [f:β→β](0) = β→β           f : β→β                       x : β
                          ───────────────           ────────────────────────────────────
                          f : β→β                   f x : β
             ────────────────────────────          ─────────────────────
             λ(x:β). f x : β → β                   λ(f:β→β). … : (β→β)→β→β
```

三条规则就是 Coq 文件里的三个构造子。**推导是数据**——这是证明助手
世界观的第一次亮相：

```coq
Inductive has_ty : ctx -> tm -> ty -> Prop :=
| ty_var : forall Gamma k T, nth_error Gamma k = Some T -> has_ty Gamma (tvar k) T
| ty_abs : forall Gamma T b U, has_ty (T :: Gamma) b U -> has_ty Gamma (tlam T b) (arrow T U)
| ty_app : forall Gamma f a T U, has_ty Gamma f (arrow T U) ->
           has_ty Gamma a T -> has_ty Gamma (tapp f a) U.
```

`Example id_derivable : has_ty [] (tlam base (tvar 0)) (arrow base base).`
的证明就是用 `apply` 挂构造子——我们在**手工搭推导树**。

## 3.3 ω 之死：非法项被挡在门外

第 2 章的发散项 `ω = λx. x x` 在 λ→ 里**不可类型化**。三家的表现：

- **Lean（检查器）**：`infer [] (lam base (app (var 0) (var 0))) = none`——
  函数返回「无类型」。
- **Coq（关系）**：`omega_underivable` 是被证明的定理——对一切 T，
  `~ has_ty [] ω T`。推导树不是「没找到」，是**不存在**（反证：
  `x : β` 查表得来，但应用要求它是箭头，矛盾）。
- **Agda（内在式）**：`Tm Γ (σ ⇒ τ)` 的构造子从语法上就凑不出
  `app (var v) (var v)`——同一变量身兼 `σ ⇒ τ` 与 `σ` 两型，需要解
  `σ ≡ σ ⇒ τ`。而**类型没有不动点**（文件里两行结构归纳证掉了
  `¬fixpoint`）。

这三种「拒绝」的层次——计算失败、定理反证、语法不可表示——正是
三家设计哲学的缩影。

## 3.4 元定理：类型安全与强规范化

λ→ 有两条里程碑定理（第 24 章谈证明方法）：

- **主体归约（subject reduction）**：`Γ ⊢ M : T` 且 `M →β M'`
  则 `Γ ⊢ M' : T`。类型在计算中不丢。
- **强规范化（strong normalization, SN）**：每个良式项的**所有**
  归约序列都有限（都到范式）。ω/Ω 从此无法良式化。

两者合称**类型安全**（TAPL 的 progress + preservation；Wright–Feller
「良式程序不go wrong」）。本指南的 Coq 文件完整证明了**进展定理**
（progress）：

```coq
Theorem progress : forall t T,
  has_ty [] t T -> value t \/ exists t', step t t'.
```

证明的骨架值得背下来：

1. 对类型推导归纳（变量/抽象/应用三情形）；
2. 变量情形：封闭上下文查无此键，矛盾；
3. 抽象情形：λ 就是值；
4. 应用情形：对函数位用归纳假设分「是值/会走步」；是值则用
   **典范形式引理**（箭头类型的值必是 λ）拆出函数体，β 一步成交。

SN 的实验面：Lean 文件里任何可类型检查的封闭项，燃料内必达范式
（`stops` 函数）。注意 SN 说的是「所有序列都停」，燃料归约只是
normal order 单序列——定理的完整证明要靠**逻辑关系**法（24 章）。

## 3.5 三种工程路线对照

同一个 λ→，三家文件给出三种「把类型系统做成机器」的姿态：

| | Lean `ex03_stlc.lean` | Coq `ex03_stlc.v` | Agda `ex03_stlc.agda` |
|---|---|---|---|
| 路线 | 检查器（extrinsic） | 推导即数据 | 内在建项（intrinsic） |
| 无类型项存在吗 | 存在，`infer` 返回 `Option` | 存在，`has_ty` 是 Prop | **不存在**：`Tm Γ T` 索引即类型 |
| ω 的下场 | `infer = none` | 反证定理 | 语法不可表示 |
| 求值 | 代换 + 燃料归约 | 小步关系 `step` | 环境 + 闭包（de Bruijn 变量 = 查表函数） |
| 证明成分 | 断言式 example | progress 完整归纳证明 | 类型无不动点引理 |

三种路线各有代价：检查器式要自己处理「没有类型」的分支；推导式
的归纳要和索引搏斗（见下方坑位②③）；内在式写项啰嗦（每个变量
都要 `vs` 数层数）但求值器结构清晰——`Env Γ = ∀ {τ} → Var Γ τ → Val τ`
一行把 de Bruijn 的语义写尽了。

## 3.6 多态的饥饿：为 System F 铺路

λ→ 的天花板在本章实测里撞了两次：

1. **I I 不可类型化**（Lean 实测 `infer = none`）：`I : (β→β)→(β→β)`
   的参数要 `β→β`，自己却是 `(β→β)→(β→β)`——类型对不上。无类型
   世界里 `I I →β I` 毫无障碍；类型世界要把「I 对一切 T 都可用」
   表达出来，需要**全称量化类型** `∀α. α → α`。
2. **S K K = I 单态化失败**（Agda 实测）：两个 K 必须「身兼两个
   类型」，单态语法只能写出 K 的两个不同实例化（字面相同、类型
   不同——两份代码）。B 编码 `2^3` 里 Church 数若要在 `(T→T)→T→T`
   的每个 T 上通用，同样需要 ∀。

Church 本人在 1940 的论文里就有多态雏形；把 ∀ 类型做严是 Girard
(1972) 与 Reynolds (1974) 的 System F——下一章（06）把它实现出来。
（在那之前，04 章先走 Curry 这条线，看看「类型指派」如何长出
现代语言的类型推断。）

## 本章小结

- λ→ = 无类型 λ 演算 + 三条规则；规则即构造子，推导即数据。
- ω 的三种死法（none / 反证 / 不可表示）= 三家设计哲学。
- 类型安全 = progress + preservation；Coq 侧完整证了 progress。
- 内在式 vs 检查器式的取舍是依赖类型编程的第一课。

> **坑位速记**
> ① `I I`、`S K K` 在单态 λ→ 里都不可类型化——这不是 bug，是
> 教材素材；多态饥饿直接引出 System F；
> ② Coq 标准库 `nth_error` **递归在 n 上**：`nth_error [] k` 在 k 为
> 变量时 `simpl` 不动，须 `destruct k` 后再 discriminate；
> ③ 对 `has_ty [] t T`（索引是字面量）直接 `induction` 会丢失
> 「上下文为空」的信息——把 `Γ = []` 作为等式泛化进归纳命题；
> ④ `inversion` 自动生成的假设名随版本漂移：要么 `as` 模式点名，
> 要么 `match goal with` 按形状取；`subst` 还可能把点名的变量消掉
> （结尾用 `eexists` 兜底）；
> ⑤ Agda 自定义中缀构造子**必须声明 fixity**（`infixr 20 _⇒_`），
> 否则 `ι ⇒ ι ⇒ ι` 直接解析失败；
> ⑥ Agda 环境求值器若想在燃料耗尽时也有值可返，加一个 `bogus`
> 哨兵构造子（良式封闭项上不可达，但类型必须闭环）。
