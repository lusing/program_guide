# 48 类型重构：约束、合一与 let 多态

> 对应读本：TAPL 书第 22 章（类型重构）。代码：
> `examples/48_reconstruction/ex48_reconstruction.pl`（甲：带
> occurs check 的合一 mgu；乙：约束生成——22.3 的 CT 规则
> 直译；丙：**算法 W + let 多态**——泛化/实例化的机器兑现，
> 05 章「无 let-多态」的已知边界在此关闭）。

前面的语言（42–47）都是 Church 式：类型注释写在项上。
真实 ML/Haskell 是 Curry 式：程序员不写类型，**编译器算**。
本章就是「算」的算法——Hindley–Milner 类型重构。05 章
（Curry 指派）给了单态版的合一与主类型；这里补上三块：
约束式类型化的系统化（22.2–22.3）、let 多态（22.7）、
以及「类型变量的两个观点」的辨析（22.2）。

## 48.1 类型变量的两个观点（书 22.2）

同一个 `λx.x` 有无穷多类型（α→α、Nat→Nat、…）——但只有
一个「最一般」的。书 22.2 的辨析：**约束量化**的类型变量
（unification variable——待解的未知数）与**全称量化**的类型
变量（∀α——真正的多态 Scheme）是**两种不同的东西**。前者
在检查一个项时产生，后者在泛化一个 let 绑定时产生。混淆
这两者是把 HM 写错的第一大原因（机器件里它们是 `tv(N)`
与 `scheme(Qs, Body)` 两个构造——types vs type schemes 的
Prolog 化）。

## 48.2 合一（书 22.4）

类型等式求解：`unify(A, B, S)` 给出最一般合一子 S 或失败。
三样本：

```prolog
unify(tv(100), tv(101), S1),      % α 遇 β：S = [α↦β]
unify(arr(a, b), arr(a, b), []),  % 同构：恒等
unify(tv(102), arr(tv(102), b), fail).  % occurs check 拒绝
```

**occurs check**（α 出现在自己的解里 → 拒绝）防无限类型
——`λx. x x` 因此不可类型化（18 章 System F 的伏笔之一）。
05 章的 Lean 版合一在此有 Prolog 双胞胎——同一算法两种
宿主。

## 48.3 约束式类型化（书 22.3）

把「检查」拆成两幕：**生成约束**（CT- 规则：每个语法节点
产生一个等式）+ **求解约束**（合一）。定理（22.3 的实质）：
项可类型化 ⟺ 生成的约束可解；且最小解给主类型。机器件：

```prolog
gen_constraints(ap(F, A), G, T, Cs) :-
    gen_constraints(F, G, Tf, Cf),
    gen_constraints(A, G, Ta, Ca),
    append(Cf, [(Tf, arr(Ta, T))|Ca], Cs).
```

应用节点产生 `Tf = Ta→T`——函数侧的类型决定参数与结果的
约束。**约束式是编译器的真实架构**（先收集后求解，错误信息
可以定位到具体约束），W 的「边走边合一」是它的单遍优化。

## 48.4 算法 W 与 let 多态（书 22.5/22.7）

主类型定理（22.5）：可类型化的项有**主类型**（所有其他类型
都是它的实例）。`λx.x : α→α` 的机器见证：

```prolog
check("λx.x : α→α（22.5 主类型样本）",
       ( wtype(lm(x, v(x)), arr(tv(N), tv(N))), N >= 0 )),
```

**let 多态**是本章的高潮。`let f = λx.x in (f 1, f true)`
必须通过、而 `λf. (f 1, f true)` 必须被拒——两者的差别正是
**泛化**（generalization）：let 的右值解出的主类型中，不出现在
环境的自由变量被**全称量化**进 scheme；每次使用时**实例化**
为新鲜变量。机器件的两行对照：

```prolog
check("let f=λx.x in (f 1, f true) 双双通过", ...),
check("对照：λf. (f 1, f true) 无多态被拒", ...),
```

λ 绑定只给**单态**（mono）环境条目——函数参数在整个函数体
里必须一个类型用到底；let 绑定给**多态**（poly）条目——每次
使用一个新副本。**05 章的已知边界「无 let-多态」至此兑现**。
（ML 的值限制（value restriction）是这段故事的续集：let 右值
若含引用（44 章），泛化会被限制到「语法值」——否则
`let r = ref [] in (r := [1]; !r @ true)` 会破坏类型安全；
TAPL 22.7 注记指路 Leroy/Weis/Wright 的文献。）

## 48.5 一页总结（本章的三个公式）

> 主类型：可类型化 ⟹ 有最一般类型（其余全是实例）。
> 合一 + occurs check = 约束求解（λx.xx 被拒的原因）。
> let = 泛化 + 实例化；λ = 单态绑定——HM 的多态只在 let。

> **坑位速记**
> ① Prolog 合一器的**裸元变量**（未定的 tv）会被 tv(M)
>   模式反向绑定（M 未实例化 → `=:=` 崩溃）——replace_var
>   首句加 `var(T)` 守卫、occurs 加 ground 守卫（本批实测
>   两个连环崩）；
> ② 代换合成 compose 要**先对旧代换应用新代换**再拼接——
>   顺序反了旧绑定漏更新（05 章同一坑的 Prolog 版）；
> ③ unify 的失败**不是 Prolog 失败**而是返回 S = fail 哨兵
>   ——上层 solve 检查哨兵；`\+ unify(...)` 因此测不出拒绝
>   （本批 occurs check 见证的写法修正）；
> ④ 泛化的差集是「主类型自由变量 − 环境自由变量」——忘了
>   减环境变量会把本该单态的变量错误多态化（著名的
   unsoundness 教材案例，本件 ftv_env 的用武之地）；
> ⑤ 新鲜类型变量的计数器要 dynamic 并**每次检查前重置**——
>   不重置则两次 wtype 的变量编号冲突。
