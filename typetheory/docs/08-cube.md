# 08 Barendregt 立方体与 λC（构造演算）

> 对应读本：TTAFP 第 4–6 章（类型依赖类型 / 类型依赖项 / λC）。
> 代码：`examples/08_cube/`——**mini-PTS 内核**（Lean）：把「一个
> 类型系统」做成数据，同一 `infer` 配八张规则表跑出整个立方体；
> Coq / Agda 演示 λC 作为「顶点系统」在三家的日常形态。

## 8.1 立方体：三扇门，八个系统

前几章的系统可以统一成一个问题矩阵：**谁可以依赖谁**？

```text
                        项可以进类型？──→  λP   λC
                       ╱                ╱
            λ→  ──────╱       λ2 ──────╱
（都不依赖）              （类型可用类型变量抽象）
```

起点 λ→ 只有一条规则 `(*,*,*)`：箭头的两端互不依赖。三扇门各加
一条规则：

| 门 | 新规则 | 打开什么 | 代表能力 |
|---|---|---|---|
| 多态 | `(□,*,*)` | 类型变量被项层抽象 | `ΛX. t`（06 章 System F） |
| 依赖 | `(*,□,□)` | 项进类型 | `Π(n:Nat). P n`（07 章 λP） |
| 类型算子 | `(□,□,□)` | 类型上的类型函数 | `List : Type → Type` 层级 |

三条全开就是 λC（Coquand–Huet 1985，构造演算）。八个子系统的
规则表：

| 系统 | 规则集 | 身份 |
|---|---|---|
| λ→ | `(*,*,*)` | Church 1940 |
| λ2 | + `(□,*,*)` | Girard/Reynolds 的 F |
| λP | + `(*,□,□)` | LF 一系 |
| λω | + `(□,*,*) (□,□,□)` | Fω（类型算子） |
| λP2 | λ2+λP | |
| λPω | λP+λω | |
| **λC** | 全部四条 | 构造演算，Coq 内核的底座 |

## 8.2 PTS：把类型系统写成数据

**纯类型系统（PTS）** 是 Barendregt 的统一框架：一套语法、
一套规则模板，每个具体系统 = 一组规则三元组：

```text
语法   t ::= s | x | λ(x:A). t | t u | Π(x:A). B        （项与类型一个文法！）
公理   * : □
规则   A : s₁,  x : A ⊢ B : s₂  ⟹  Π(x:A). B : s₃       （s₁,s₂,s₃）按系统查表
```

Lean 文件 `ex08_cube.lean` 实现了这个框架的**可执行版**：

```lean
structure Conf where
  rules : List (Srt × Srt × Srt)     -- 一个类型系统 = 一张表

def lamArrow  : Conf := ⟨[(star, star, star)]⟩
def lam2      : Conf := ⟨[(star, star, star), (box, star, star)]⟩
...
def lamC      : Conf := ⟨[...]⟩       -- 四条全开
```

`infer` 是通用的推导算法（约 40 行）：上下文查表带**移位**
（第 k 条是写在尾上下文里的类型，取回要上移 k+1 位）；「A : s」
编译为「infer A 归约出某个 sort」——所以 λ/Π 的形成检查是
嵌套 `infer`，连 sortOf 都不用单独写。定义相等用统一语法的
一台归约器（项层与类型层共用——PTS 单一文法的回报）。

然后，**立方体的定理变成了测试**：

| 程序 \ 系统 | λ→ | λ2 | λP | λω | λC |
|---|---|---|---|---|---|
| 恒等 `λ(x:Nat).x` | ✓ | ✓ | ✓ | ✓ | ✓ |
| 多态恒等 `Λ(X:*). λ(x:X).x` | ✗ | **✓** | ✗ | ✓ | ✓ |
| `Π(X:*). *`（类型算子的型） | ✗ | ✗ | ✗ | **✓** | ✓ |
| 谓词量化 `Π(n:Nat). P n` | ✗ | ✗ | **✓** | ✗ | ✓ |
| 多态谓词 `Π(A:*). Π(x:A). *` | ✗ | ✗ | ✗ | ✗ | **✓** |

全部 `by rfl` 机器验证。举两个输出实况：

```lean
example : inferClosed lam2 polyId
        = some (.pi (.sort star) (.pi (.var 0) (.var 1))) := by rfl
-- ∀X:*. X→X：λ2 收下多态恒等

example : inferClosed lamArrow polyId = none := by rfl
-- λ→ 收不下：缺 (□,*,*)
```

实现过程中抓到一个**教学级 bug**：不校验上下文良构性的话，
λ→ 竟然会「接受」谓词量化 `Π(n:Nat). P n`——因为前提
`P : Nat → *` 偷渡进了上下文，而 `P` 的型 `Π(n:Nat).*` 在 λ→
里根本造不出来。于是内核加了 `ctxValid` 门禁：**上下文的每一条
都必须在尾上下文里可推导**。PTS 的「判断」不只是对项，也是对
上下文的——这是课本上一行字，做成机器就是一次真调试。

## 8.3 λC 的逻辑：构造演算作为证明语言

λC 上 Curry–Howard 的对应达到**高阶直觉主义逻辑**：

```text
Prop ≡ *      证明 ≡ 项      ∀/∃/谓词 ≡ Π/Σ/类型族
```

TTAFP 第 7 章起在 λC 里编码经典逻辑与数学；Coq 就是从这里长出来的
（Coquand–Huet 1985 的原始动机是「构造演算 + 证明检查」）。Coq
文件演示三扇门同时打开的日常：

```coq
Definition Forall {A : Type} (P : A -> Prop) : list A -> Prop := ...
Check @Forall : forall (A : Type), (A -> Prop) -> list A -> Prop.
(* Π(A:*). (A→Prop) → list A → Prop：三扇门缺一不可 *)
```

`Forall` 的类型正是 8.2 表里「唯 λC 收」的形状——在 Coq 里它
只是一个普通函数的定义。**顶点系统的特征就是：立方体的角落
不再特殊**。

## 8.4 Agda 的另一条路：直谓宇宙塔

Agda 与 Lean/Coq 的分野在此显形：Agda 走 MLTT 一系，宇宙塔
`Set₀ : Set₁ : Set₂ : …` 是**直谓**（predicative）的——`Set₀`
不能量化「所有 Set₀ 上的谓词」再把结果放回 Set₀。Coq 的 `Prop`
则是非直谓的（λC 血统）。两种立场的对比在 Agda 文件里用
`BigQuant` 的例子摆开；代价与收益（证明无关性、Girard 悖论的
防线）留到 21 章（截断层级）细算。

三家的「顶点」身份对照：

| | Coq | Lean 4 | Agda |
|---|---|---|---|
| 内核谱系 | λC + 归纳（CIC） | CIC 变体 + Quot | MLTT + 宇宙塔 |
| 非直谓层 | `Prop` | `Prop` | 无 |
| 类型算子 | `Definition Endo (A:Type) := A -> A` | `def Endo (A : Type) := A → A` | `Endo : Set → Set` |
| 依赖族 | `Vec A : nat -> Type` | `Vec α : Nat → Type` | `data Vec (A : Set) : ℕ → Set` |

## 8.5 从 λC 到真内核：还差三样

λC 是骨架，真证明助手还需要：

1. **归纳类型**：λC 纯函数式，没有 `nat`、`list` 的声明机制。
   Coq 的 CIC = λC + 归纳类型 + 递归消去子（13 章）。
2. **定义机制**：全局/局部定义、缩写、δ-展开的控制（09 章，
   TTAFP 的 λD 正是这一步的系统化）。
3. **宇宙层级**：`Type : Type` 会炼出 Girard 悖论；真系统用
   `Type₀ : Type₁ : …`（14 章）。

> **坑位速记**
> ① Coq 注释**嵌套**：注释里写 `(*,*,*)` 这种规则记号，`(*`
> 会开新层、`*)` 会提前闭层——写规则时用空格拆开（本章实测
> 两次）；
> ② Coq `Check f : T` 遇隐式参数要 `@f`；`A * A` 在 `fix` 体里
> 可能被解析成 `Nat.mul`——用 `prod A A` 免疫；
> ③ mini-PTS 的上下文查表**必须移位**（第 k 条上移 k+1），
> 否则 `Π(x:X). X` 的 codomain 会算成 `var 0`（自指）；
> ④ 上下文本身要过规则门禁（`ctxValid`），不然「非法前提」
> 能让弱系统「接受」强命题；
> ⑤ Lean 的 `Option` 上匹配写 `.sort` 模式会解析成
> `Option.sort`——要 `some (.sort s)`；
> ⑥ PTS 统一语法的红利：一台归约器同时服务项 β 和类型 β，
> conv 无需区分层级。
