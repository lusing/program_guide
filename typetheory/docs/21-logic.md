# 21 λC 中的逻辑编码：把连接词写成类型

> 对应读本：TTAFP 第 7 章全部（⊥ 与 ¬、∧ 与 ∨、命题逻辑实弹、
> 古典升级、谓词逻辑 ∀∃、proof checking = type checking）。
> 代码：`examples/21_logic/`——**Lean 主场**（连接词的二阶编码即
> 程序：intro/elim 是居留项；ET↔DN 零公理互推；一阶编码的单向
> 落差）；**Prolog 镜像**（λP2 检查器：图 7.1 证明项与书 7.4/7.6
> 的证明项逐行过检——「证明检查 = 类型检查」的字面机器版）。

20 章把八个类型系统收进一张立方体图，顶点 λC 站在那儿——
「什么都能依赖」。本章回答那个悬着的问题：**这么强的系统到底
买来什么？** 答案震撼且实用：买来**整个逻辑**。蕴涵在 λP 里已经是
函数类型（08 章 Curry–Howard）；剩下的连接词——⊥、¬、∧、∨、∃
——全部可以在 λC 里**写成类型**，而自然演绎的每条 intro/elim
规则都是**可推导的**（不是新公理，是已有的 λ 抽象与应用）。
命题逻辑与谓词逻辑就此搬进类型论；再往后（22–26 章）整个
「在类型论里做数学」的大厦都立在这块地基上。

## 21.1 ⊥ 与 ¬：荒谬即多态

一切从一个特征性质开始（书 7.1 I）：**若 ⊥ 真，则一切命题真**。
用居留的话说：若有 M : ⊥，则对任意 α : ∗ 有 α 的居留项。把这句话
本身做成类型——「给我一个 ⊥ 的居留者，我还你任何命题的居留者」
的函数住在 `Πα:∗. α` 里。反过来，这样的函数 f 一旦存在，f A、f B、…
让所有命题全真——荒谬。于是：

> **⊥ := Πα:∗. α**（⊥ 居留 ⟺ Πα:∗.α 居留）

这个编码住在 λ2 里（量词只过 ∗ 层，(□,∗) 一条 form 就够），并且
**⊥-elimination 免费**：ex falso 就是把 f 应用到目标命题上。Lean
版是四行定义加一行定理：

```lean
def Bot : Prop := ∀ p : Prop, p

theorem bot_elim (h : Bot) (A : Prop) : A := h A
```

¬A := A → ⊥ 顺水推舟。书 7.1 的观察值得咀嚼：⊥-intro、¬-intro、
¬-elim 三条自然演绎规则**全部退化成 ⇒ 规则的特例**——(¬-elim)
就是 (⇒-elim) 取 B := ⊥；(⊥-intro) 同一款规则的另一个用途。规则
没有增殖，**逻辑在类型论里「变薄」了**。书还点出 intro/elim 的
方向感：intro 规则向后用（要造 ⊥？先找个 A 与 ¬A），elim 规则
向前用（手里有 ¬A？再看 A 成不成立）。

## 21.2 ∧ 与 ∨：二阶编码

一阶编码（A∨B := ¬A→B、A∧B := ¬(A→¬B)）只在古典逻辑里等价
——构造性世界里它们残废。书 7.2 给出**构造性也成立**的二阶编码：

> **A ∧ B := ΠC:∗. (A → B → C) → C**
> **A ∨ B := ΠC:∗. (A → C) → (B → C) → C**

读法：把 Π 当 ∀——「对一切 C：若 A 与 B 合起来能推出 C，则 C」
——这逼着前提条件「A 与 B 都成立」是冗余的，除非它本来就满足。
∨ 同理：两条路都能到的目的地，你必然站在某条路上。

**编码合法性的证明方式**是本章的方法论亮点：不辩经，直接把
自然演绎规则**推导出来**。(∧-intro) 对应的问题是「在 x:A, y:B
的语境里找 `ΠC:∗.(A→B→C)→C` 的居留项」——书 7.2 的四行推导给出

```text
λC:∗. λz:A→B→C. z x y
```

(∧-elim-left) 是 `λc. c A (λa.λb.a)`；(∨-intro-left) 是
`λa. λC. λh1. λh2. h1 a`；(∨-elim) 三分支就是编码本身的应用。
**每条规则 = 一个 λ 项**——这就是本章 Prolog 检查器电池里的
第 8–11 条。

Remark 7.2.1 的负例正好用机器钉死：把连接词做成 **curried 常数**
（¬ : Πα:∗.∗ 这样的「类型构造子」）需要 Π-formation 的 (□,□)
条款——那是 λω 的领地。Prolog 检查器第 12 条：

```prolog
cond(12) :-
    db(p(al, star, star), [], K),   % Πα:∗.∗ 的 de Bruijn 形
    \+ tc([], K, star), \+ tc([], K, box).   % λP2 里无 sort
```

三条款 form（(∗,∗)(□,∗)(∗,□)）都打不中它——「常数化的连接词
住在 λω」从书上的练习变成机器否证。

## 21.3 实弹：图 7.1 的重言式

书 7.3 全文推导 (A ∨ B) ⇒ (¬A ⇒ B)。证明项（第 (10) 行）：

```text
λx:A∨B. λy:¬A. x B (λu:A. (y u) B) (λv:B. v)
```

推导的「灵光一现」在第 (1) 行：**把 x 应用到命题 B 上**——
x 的二阶 ∨ 编码于是变成 (A→B)→(B→B)→B，结尾的 B 正是目标。
剩下两块填空：A→B 的居留项用 ¬A 与 ⊥-elim（`(y u) B`——
y u : ⊥，⊥ 是 Πα:∗.α，应用一次得 B，第 (2)(3) 行）；B→B 是
恒等。两次 appl 收尾。这个证明项在本章两个机器里都原样过检：
Lean 侧是

```lean
theorem or_implies_or {A B : Prop} : Or2 A B → Not2 A → B :=
  fun x y => x B (fun u => (y u) B) (fun v => v)
```

Prolog 侧是电池第 6 条——同名项喂给 λP2 检查器，七条规则
（ax/var/form×3/abs/appl）逐层放行。

## 21.4 古典升级：ET ↔ DN

到此为止的逻辑是**构造性的**。排中 ET（A ∨ ¬A）与双否律
DN（¬¬A ⇒ A）都不可推导（Troelstra–van Dalen 的标准结果）。
书 7.4 的两条消息：

1. **加一个就够**：构造逻辑 + ET ⊢ DN，反之亦然。
2. **加法是语境前置**：`iET : Πα:∗. α∨¬α` 作为假设放语境最前。

互推的构造性证明本身就是好习题。ET→DN 的证明项（书 7.4 的
(1)–(9) 行浓缩）：

```lean
theorem dn_from_et (et : ∀ p : Prop, Or2 p (Not2 p)) {β : Prop}
    (x : Not2 (Not2 β)) : β :=
  et β β (fun y => y) (fun z => (x z) β)
```

——`iET β β (λy:β.y) (λz:¬β. x z β)` 逐符号对应。反方向 DN→ET
的引擎是**构造性奇观** `¬¬(p ∨ ¬p)`：假设 n : ¬(p∨¬p)，则
p 成立会自爆（n 应用左注入）、¬p 成立也自爆（右注入）——

```lean
theorem nn_or_nn (p : Prop) : Not2 (Not2 (Or2 p (Not2 p))) :=
  fun n => n (or2_intro_right (fun pp => n (or2_intro_left pp)))

theorem et_from_dn (dn : ∀ p : Prop, Not2 (Not2 p) → p) (p : Prop) :
    Or2 p (Not2 p) :=
  dn (Or2 p (Not2 p)) (nn_or_nn p)
```

`#print axioms` 验证：**两条互推都不依赖任何公理**——「排中与
双否等价」这件事本身是构造性定理。对照 Lean core 的
`Classical.em`（账本：choice/propext/Quot.sound）：工业实现把
ET 直接当公理发货，本章的相对定理说明这个选择不比 DN 更（或
更不）激进。

一阶编码的落差也能机器演示：`Or2 A B → (¬A → B)` 构造性可证
（电池第 14 条；Lean 侧 `or2_to_cls`）；反向 `(¬A → B) → Or2 A B`
构造性无望，借 et 一臂之力才通（`cls_to_or2`——用 `et A` 分
情况）。书 7.8 的一句话有了硬读法：**二阶编码与一阶编码的差异
恰好就是构造逻辑与古典逻辑的差异**。

## 21.5 谓词逻辑：∃ 与辖域纪律

∀ 早在 8.4 节就编码成 Π（19 章见过）；∃ 的构造性编码是

> **∃x:S. P x := Πα:∗. ((Πx:S. P x → α) → α)**

照例以规则验证：(∃-intro) 的居留项是书 7.5 给出的
`λa:S. λu:P a. λα:∗. λw. w a u`；(∃-elim) 是两行应用的
`λy.λz. y A z`。注意 (∗-elim) 的边条件 x ∉ FV(A)（Remark 7.5.2）
——在类型论里**由结构强制**：`y A z` 的 A 是固定的目标类型，
证据 x 只能穿过 w 的类型，没法漏进 A。数学文本里「设 x 满足 P」
的松散用法（Remark 7.5.1 的批评——沉默的辖域假设，甚至省略
「设」那行）在机器面无处遁形。

∃ 编码的居住地有讲究：书 Remark 7.5.3 说它需要 **λP2**（谓词
P : S→∗ 要求 (∗,□) formation）——这就是 Prolog 检查器选 λP2
三条款而非 λ2 的原因（第 5 条电池：∃ 的类型定型在 λP2 通过；
若把 (∗,□) 拿掉即 λ2，P 自己就无家可归）。curried 版
∃ : ΠS:∗.(S→∗)→∗ 更要 λC。

书 7.6 的收官例子 ¬∃ ⇒ ∀¬，证明项

```lean
theorem not_ex_all_not {S : Type} (P : S → Prop) :
    Not2 (Ex2 P) → ∀ y : S, Not2 (P y) :=
  fun u y v => u (ex2_intro y v)
```

——三层抽象后一步 ∃-intro 喂给 u 得 ⊥。Prolog 侧电池第 13 条
同款。书在同页算了一笔账：λ 不展开定义时证明项疯长、子式重复
遍地——**这正是 22/23 章定义系统的直接动机**（「λD 的精神」
要从这里读出来：δ-展开不是便利设施，是可读性的救生圈）。

## 21.6 机器面导读

**Lean（`ex21_logic.lean`）**：六个编码是 `Prop` 上的普通定义；
intro/elim 是普通定理；与原生 `And/Or/Exists` 的同构
（`and2_iff`/`or2_iff`/`ex2_iff`）说明二阶编码「够真」——
逻辑上分毫不差，只是证明项更长。古典段全部用**假设传参**而
非 `axiom`，`#print axioms` 的零公理输出是最好的板书。

**Prolog（`ex21_logic.pl`）**：一个 ~90 行的 λP2 检查器——命名
语法（`n/l/a/p`）→ de Bruijn 翻译（`db/3`）→ 七规则定型
（`tc/3`）。定义谓词（`bot/not2/and2/or2/ex2`）把连接词展开成
Π-项——**这就是 23 章 δ-展开的预告**。14 条电池覆盖：五个
编码定型（1–5）、三个书上的证明项（6/7/13）、五条 intro/elim
规则（8–11、14）、一个 λω 负例（12）。图 7.1 与书 7.4 的证明项
**逐符号**从纸上搬进检查器——这大概是「proof checking =
type checking」最直白的演示：那两页推导没有一行需要重新发明。

顺带的历史注记（书 7.8）：Coq 最初就是 λC 的实现，「在 Coq 里
做逻辑」正是本章的路数；后来 stdlib 把连接词改成**归纳定义**
（and/or/ex 是 Inductive），tactic 交互式构造证明项。所以本章
的 Church 编码在 Coq 里依然合法（它只是 Prop 上的定义），只是
不再是官方路线——46 章四家对照时再回头看这条分岔。

## 21.7 得失清单（书 7.7 的结论）

类型论式逻辑的**得**：证明必须携带完整证据（居留项），机器
可查，不容「手挥」；逻辑到数学的扩展用同一套原理（24–26 章
的等式、序、算术全部照此办理）。**失**：每个细节都要铺开，
推导比自然语言数学难读——所以真实系统都长出了 tactic、定义
管理、隐式参数这些「可读性工程」。理解了这个交换，就理解了
证明助手的全部产品逻辑。

> **坑位速记**
> ① Lean 的 `/-- -/` 文档注释不能挂在 `section` 前（报
>   unexpected token 'section'）——改普通注释；
> ② Lean `variable` 只在**签名**里被提及时自动绑定进定理，
>   只在证明体里用不算——古典假设显式作参数更稳；
> ③ `∃ x, P x` 的析构用 `Exists.elim h (fun x px => …)`，
>   匿名构造模式 `fun ⟨x, px⟩ =>` 对 Exists 不适用；
> ④ Prolog **无函数记法**：`t_arrow(A,B)` 出现在项位不会被
>   调用，留下未展开的 `t_arrow/2` 原子喂 db 即静默失败——
>   凡 `=` 构造的项先过 `ex/2` 展开遍历；
> ⑤ 应用链要**完全嵌套**：`a(a(a(x, b), u), v)`——写成
>   `a(a(x, b), u, v)` 是三元 `a/3`，db 没条款直接失败；
> ⑥ de Bruijn 语境是**统一坐标系**：压栈时全体条目（含新者）
>   在 cutoff 0 上移一位——按位置递增 cutoff（把语境当嵌套
>   绑定器）是错的；
> ⑦ 代换三分支 `k==j 换入 / k>j 减一 / k<j 不动`，且换入的项
>   由递归按深度**预抬**——基例里再 shift 一次就双重上移；
> ⑧ 语境别漏「自由类型变元」：x:A, y:B 的推导语境是四条
>   （A、B 自己也 :∗ 占两条）。
