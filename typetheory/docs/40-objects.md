# 40 命令式对象与轻量级 Java

> 对应读本：TAPL 书第 18 章（实例分析：命令式对象）与第 19 章
> （实例分析：轻量级 Java，即 Featherweight Java/FJ）。代码：
> `examples/40_objects/ex40_objects.pl`（甲：38 章存储机 + 37 章
> 记录 + 39 章子类型合体的**计数器对象**——get/inc 方法闭包
> 共享一个 ref 单元；乙：FJ 精简版类表机——extends 单继承/
> 字段继承/方法覆写/R-Field/R-Invk/R-Cast 全套小步与定型）。

本章是前三章零件的总装配：**对象 = 记录（37）+ 状态（38）+
子类型（39）**。书用两个案例分析收束「面向对象的类型论本质」
之问——命令式对象（引用式）与类式对象（FJ 式）是同一枚硬币
的两面。

## 40.1 对象是什么：三步合成（书 18.1–18.2）

书 18.1 的问题清单（「什么是面向对象编程」的九个特征）里，
类型论真正要解释的核心是：**封装**（状态藏在方法后面）、
**self**（方法互相调用经由「我自己」的晚绑定）、**开放递归**
（self 的调用在子类里可被覆写）。命令式路线的合成三步：

1. **状态**：`c = ref 0`——一个私有单元；
2. **方法记录**：`{get = λ_. !c, inc = λ_. c := succ(!c)}`——
   两个闭包**共享**同一单元（别名=封装的机制基础，38 章的
   「隐式通信通道」在此变现）；
3. **打包**：`(λr:Ref Nat. {get=…, inc=…}) (ref 0)`——单元
   被抽象进记录、外界只能通过方法名访问。

机器件把计数器程序完整跑通——两次 `inc` 之后 `get` 读得 2：

```prolog
counter_prog(P) :-
    P = ap(lm(reft(natt), ap(lm(rcdt([...]), Seq),
                             rcdobj([get=Get, inc=Inc]))),
            ref(zero)),
    Get = lm(unitt, deref(vr(1))),
    Inc = lm(unitt, assign(vr(1), succ(deref(vr(1))))),
    ...
```

注意 de Bruijn 的**深度记账**：方法闭包在 λr 与 λo 两层之下
（r = vr(1)），序列导出形式的每层 λ_ 再把 o 推深一位（38 章
坑位⑤的三连版）。

## 40.2 生成器、别名与 self（书 18.3–18.10）

**生成器**（18.3）：`newcounter = λ_. <整段>`——每调用一次
分配一个**新**单元，两个计数器互不干扰；对照 18.1 的「s = r
拷贝的是引用不是单元」——别名让多个名字**共享**状态，生成器
让多个对象**各自**持有状态。**加实例变量**（18.7）= 记录再加
一个字段；**调超类方法**（18.8）= 子类方法体里显式调用父生成
器产出的对象。真正的分水岭是 **self**（18.9–18.10）：把方法
记录自身作为参数传给生成器——

```text
fix (λself. λr. { get=…, inc=…,  even=λn. if iszero n then true
                                          else self.odd (pred n), … })
```

**fix 于方法记录**（不是于单个函数）让方法之间经由 self 互相
调用——这就是**开放递归**：self 的绑定被推迟到「运行时拿到
整个对象」之后，子类覆写 `odd` 会自动改变 `even` 的行为。
37 章 11.11 的「互递归函数记录取不动点」正是它的预演。代价
（18.11）：self 的类型是递归类型——第 41 章的入场券。**命令式
对象的完整故事到此闭环：encapsulation = 引用，dispatch = 记录
投影，inheritance = 生成器组合，open recursion = fix。**

## 40.3 轻量级 Java：FJ（书 19）

FJ（Igarashi–Pierce–Wadling 1999）把 Java 裁剪到「恰好能证
类型安全」的最小内核：类表 + 五种项——变量、字段取用、方法
调用、构造、**转型**。书 19.4 的定义里两个设计值得注意：

- **定型完全由类表驱动**：`CT ⊢ e : C` 的子类型就是类表
  extends 链的直传（39 章的记录子类型在 Java 里的化身：
  nominal vs structural——**名字子类型**与**结构子类型**的
  分野，FJ 站名字一侧）；
- **方法覆写**（override）要求子类方法的类型与父类**完全
  一致**（37 章 11.10 讨论过的「更精确覆写」在 FJ 被禁——
  静态安全的「协变返回类型」要到 45 章高阶系统才放行）。

机器件的类表与规则：

```prolog
fj_step(field(new(C, Args), L), Mu, V, Mu) :-    % R-Field
    fields(C, Fs), zipf(Fs, Args, Zs),
    member((L-_)-V, Zs).
fj_step(call(new(C, _), M, A), Mu, R, Mu) :-     % R-Invk
    fj_value(A),
    methods(C, Ms), member(m(M, _, X, _, B), Ms),
    subst_fj(B, X, A, R).
fj_step(cast(C, new(D, Args)), Mu, new(D, Args), Mu) :-
    subcl(D, C).                                  % R-Cast
```

`fields`/`methods` 沿 extends 链**继承合并**（覆写以子类为
准——`override_merge`）；R-Invk 把方法体的参数换成实参
（FJ 真版还有 this——机器件以参数直代换省去 self 链，正文的
诚注记）。**转型**是 FJ 的灵魂规则：`(C) e` 求值时若 e 是
`new D(…)` 且 D <: C 则**直接脱壳**（upcast 无代价）——
「stupid cast」（D 不 <: C）在类型检查时被拒（FJ 的定理：
良型程序里转型要么成功要么卡在调用栈上——类型安全的
Java 版措辞，19.5 的 subject reduction + 19.5.7 progress）。

## 40.4 两个案例的合流（书 18.13/19 的对照）

| | 命令式对象（ch.18） | FJ（ch.19） |
|---|---|---|
| 对象的表示 | 记录 + 引用 | 类实例 new |
| 方法的表示 | 记录字段里的闭包 | 类表里的方法 |
| 继承 | 生成器组合（λ 演算内） | extends 链（类表元级） |
| self | fix 的不动点参数 | this（隐式传参） |
| 子类型 | 结构（记录 <:） | 名义（类表 <:） |
| 定理 | 37–39 章安全性直接继承 | 19.5 的 FJ 版 progress/preservation |

书 19.1 用 FJ 复原了 18 章的那组计数器样本（19.6 的编码练习）。
**46 章纯函数对象**将给出第三种化身：存在类型包装的记录——
三条路线（引用式/类式/存在式）在「封装」上会师。

> **坑位速记**
> ① 「装配型」语言片段（本章甲）往 38 章机器里**加记录构造**
>   时 prj 的 shift/subst/step 三张表都要补——漏一张就 stuck
>   在投影上（本批实测：ref 忘加 step 直接开局卡死）；
> ② 计数器程序的三层嵌套序列里 de Bruijn 指数**逐层 +1**——
>   方法闭包（r=vr(1)）与序列体（o=vr(0)/vr(1)/vr(2)）两套
>   计账并存，写错一层语义全变（「读自己的方法」变成「读
>   自己」）；
> ③ Prolog 方法覆写合并 `override_merge` 要**子类优先**——
>   select 掉父类同名再拼，方向反了就静默调用旧方法；
> ④ FJ 的 `zipf`（字段表×实参表）配对是 R-Field 的地基——
>   nth0 按位置索引在「字段继承改变长度」后全错，zip 版天然
>   免疫；
> ⑤ R-Cast 的方向：`subcl(D, C)`（实例的类 D 是转型目标 C
>   的**子**类）才成功——写反就是「万物可转型」。
