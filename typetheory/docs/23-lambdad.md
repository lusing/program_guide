# 23 λD 形式系统：定义作为一等公民

> 对应读本：TTAFP 第 8–10 章全部（定义的本质与格式、λC 扩张为
> λD0、def/inst 两条推导规则、δ-归约与 βδ-转换、原始定义与
> 公理、λD 的性质）。
> 代码：`examples/23_lambdad/`——**Lean 主场**（mini-λD0/λD：定义
> 环境做成数据，def/inst/δ 全部可执行，`plus two three ≡ five`
> 由 βδ-范式 rfl 验证；ET 公理化为原始定义）；**Prolog 镜像**
> （同一环境 12 条电池：描述式/原始式定义良构、实例化类型替换、
> δ 引擎、三个负例）。

21 章结尾埋下了伏笔：逻辑编码的证明项疯长、子式重复遍地——
「必须做点什么才能保住推导的可读性」。22 章看了 Coq/Lean/Agda
三家的工程答案；本章回到书上的形式系统本体：把「定义」从元语言
的便利设施升格为**对象语言的原生构造**，得到 λD0；再加「原始
定义」（公理的糖衣），得到 λD。这不是锦上添花——Automath 的
整个数学形式化传统、以及今天证明助手的全局环境，都是这台机器
的工业版。

## 23.1 定义为什么要形式化（书 8.1–8.2）

数学文本的定义在做三件事：**命名**（rectangle、increasing）、
**参数化**（「f : R→R 称为递增，若 …」——定义体依赖假设 f）、
**给证明命名**（「称引理 3.1」——证明也是可命名的对象）。书 8.2
提醒定义的递归性危险：定义不能引用自己（Remark 9.2.4——本章
系统里定义常数在其定义式右部不出现），归纳/递归定义是另一台
机器的事（30 章归纳族）。

形式化后的定义长相（书 8.5 的 act-form）：

> **x : A ▷ a(x) := M : N**

读法：在假设 x:A 下，常数 a（带参数表 x）定义为 M，其类型为 N。
五个部件各有其位：x 是参数（语境）、a 是被定义常数、M 是定义项
（definiens）、N 是类型声明。**定义 = 环境条目，不是语境条目**：
语境 Γ 收假设（用后即弃），环境 Δ 收定义（永久缩写）——判断
由此升格为三段式：

> **Δ ; Γ ⊢ K : L**

## 23.2 定义的三种高级用法（书 8.4–8.8）

形式化之前，书 8 章后半把数学实践里的定义用法盘了三遍存货，
每一样都对应 λD 里的具体形态：

**依赖假设的定义（8.6）**。「在 f : R→R 的假设下，定义
increasing(f) := ∀x y. x<y ⇒ f(x)<f(y)」——参数表 x:A 就是
迷你语境，定义体在其中检查。参数表可以引用前面的参数（望远镜），
这正是 (inst) 的类型替换要滚动处理的原因。

**给证明命名（8.7）**。引理也是定义：`lemma(u,v) := λ….证明体 :
命题`。于是「引用引理 3.1」= (inst)；「展开引理看证明细节」=
δ-归约——数学文本里「由引理 3.1 得」与「把证明抄过来」的两种
读法，在 λD 里是同一个常数的两种处理方式。22 章的 Lean
`theorem` 名字、Coq 的 `Lemma`——工程系统里定理与定义共用命名
空间的道理在此。

**一般证明与特化版本（8.8）**。证过一般的「二次函数零点」，要
用的时候是具体的 f(x)=x²−4——特化 = (inst) 的又一次应用。书
9.5 的图 9.2 给了一条完整的归约路径：`lemma(u,v)` 经 δ 与 β
一路展开到算术等式——本章机器面的 `plus 2 3 ≡ 5` 就是它的
微缩版。

三件合起来读：**定义系统 = 知识的压缩格式**。名字是索引、参数
是接口、δ 是解压算法——25/26 章要在 λD 里搭建整数算术时，
这份压缩格式将承载整个「数学即定义树」的大厦。

## 23.3 两条新规则：(def) 与 (inst)（书 9.3–9.4）

λC 的七条规则原封不动（每条多个 Δ 前缀），外加两条：

> **(def)** 往环境追加一条定义——前提有二：既有判断仍成立、
> 且定义体良构 `Δ ; x:A ⊢ M : N`（a 必须新鲜）。
>
> **(inst)** 使用定义——常数必须**完全应用**：
> `Δ ; Γ ⊢ U : A[x:=U]` 可推出 `Δ ; Γ ⊢ a(U) : N[x:=U]`。

(inst) 的方括号是 9.4 节的全部难点：**实例化会改写参数表里的
类型**。定义 `α:∗ ▷ id(α) := λx:α. x : α→α`，实例化 `id(N)`
时，类型 α→α 里的 α 要替换成 N——一参数尚可，参数表是望远镜
时（第 k 个参数的类型提到前 k−1 个参数），替换必须逐级滚动。
本章机器面的 `instantiate` 按**逆参数序**连续替换——最内层参数
住在 index 0，替换后其余参数自动降位，折叠序恰好是反的：

```lean
def instantiate (t : Tm) (us : List Tm) : Tm :=
  us.reverse.foldl (fun acc u => subst 0 u acc) t
```

书 9.4 的 boxed 例子（实例化改变声明表里的类型）在电池 5 演示：
`id(N) : N→N`——N 是闭项，替换不动声色；换成依赖参数的例子
（22 章习题里的 uarg 型定义）效果立现。

## 23.4 δ-归约与 βδ-转换（书 9.5–9.7）

定义常数「代表」它的定义项——这份等同要进转换规则：

> **δ-归约（一步展开）**：若 x:A ▷ a(x) := M : N ∈ Δ，则
> `a(U) →Δ M[x:=U]`；照例兼容进子式。
>
> **βδ-转换**：β 与 δ 的对称闭包 `=Δβ`；转换规则从「β 可换」
> 扩为「βδ 可换」——但新类型 B′ 仍要单独验良构（`Δ;Γ ⊢ B′ : s`，
> 书 9.7 的 (δ-conv) 规则）。

机器面上 δ 与 β 共用一台归约器：常数完全应用就展开，与 β 红头
并列。旗舰演示（Lean 电池 6、Prolog 电池 7）：

```lean
example : (bdNf Δs (app (app (cst "plus" []) tTwo) tThree)
             == bdNf Δs tFive) = true := by native_decide
```

——plus/succ/zero 都是 Δ 里的定义常数，`plus 2 3` 与 `5` 的
βδ-范式相等由机器算出。**这就是 λD 世界里「计算」的定义**：
δ 展开是受控的抄写，β 归约是函数计算，两者的范式就是定义相等
的裁判。

## 23.5 原始定义：公理的糖衣（书 10.1–10.3）

定义要「definiens 可写出」，公理恰恰是写不出的东西——Peano 的
0 与 s、归纳公理、ZF 的外延公理、21 章的 ET。书 10.2 的分析：
这些都是**原始实体**（primitive entities）。λD 的处理优雅到
只有一个符号之差：

> **(def-prim)** `Δ ; x:A ▷ a(x) := ⊥⊥ : N`——⊥⊥ 是元符号
> 占位（「无定义项」），前提换成「N 良构且落在某个 sort」。
> **(inst-prim)** 与 (inst) 一字不差。

于是「公理化 ET」= 往 Δ 里放 `α:∗ ▷ iet(α) := ⊥⊥ : α∨¬α`。
电池 8–9 双机演示：`iet(N) : N∨¬N` 可定型（inst-prim），而它的
βδ-范式**保持自身**——原始常数永远不展开（Lean 电池 8 的
`bdNf Δs (cst "iet" [tyN]) == cst "iet" [tyN]`）。对照三家的
对应物：Lean 的 `axiom`、Coq 的 `Axiom`/`Parameter`、Agda 的
`postulate`——全部是 (def-prim) 的工程化身；17 章 Farmer 的
「公理作为特殊定义」是同一思想在简单类型论里的版本。**公理与
定义共用一套管理机制**，这就是「证明助手里公理也要记账」的
形式根源（Print Assumptions 查的就是 Δ 里的 ⊥⊥ 条目）。

## 23.6 性质速览（书 10.4–10.5）

- **包含引理**（10.4.1）：λC ⊂ λD0 ⊂ λD——旧推导原样有效；
- **自由变元与常数引理**（10.4.3）：定义体与类型只引用自己的
  参数——这正是机器面敢把「参数望远镜当前导语境」的依据；
- **规范化与合流**（10.5）：δ-展开终止（定义无递归，展开树
  严格变小）、βδ 合流——完整证明在 Severi & Poll 的框架里，
  本书引用；散文重构见 41 章元理论，那里还挂着 β 等待处理。
- **保守性**：描述式定义是保守扩张（不添新定理）——书 8.1 的
  承诺，机器面的对应物是「全部展开后 λD0 ≡ λC」。
- **语境与环境各司其职**：Γ 里的假设可以 被 abs 规则消费、
  出不了当前推导；Δ 里的定义全局可见、跨推导存活——证明助手
  的「文件级环境」就是 Δ 的直系后代，41 章元理论谈归纳时不
  出这个框架。

一句话收束：λD = λC + 一套**可执行的缩写纪律**——所有威力
来自「缩写与原文永远可互换」（βδ-转换），所有限制也来自它
（展开即膨胀，21 章已经见过长什么样）。

## 23.7 机器面导读

**Lean（`ex23_lambdad.lean`）**：~200 行 mini-λD0/λD。`Def`
结构体四字段（名/参数表/体 Option/类型），`body = none` 即
⊥⊥。核心三件：`instantiate`（逆参数序替换）、`unfoldCst`
（δ 一步，原始定义拒绝展开）、`defOk`（(def)/(def-prim) 前提
检查）。样本 Δ 五条定义与 Prolog 版逐字对齐（双机互证）。10 条
电池覆盖：良构（1）、实例化与类型替换（2–5）、δ 范式（5–6）、
原始定义（7–8）、负例（9–10）。

**Prolog（`ex23_lambdad.pl`）**：21 章 λP2 内核加 Δ 穿线——
常数项 `kk(名, 实参表)`，(inst) 规则先逐个验实参（第 k 个实参
的类型是**已替换过前 k−1 个实参**的 Ak——9.4 的滚动替换做成
了 `check_args` 的累积器），再替换出结果类型。12 条电池比
Lean 版多出两个负例：定义体类型不符被拒（电池 2）、参数不足
不可定型（电池 11）。

两个文件共享同一个已验证的项库（tyN/zero/succ/plus/id/iet 的
de Bruijn 形逐字相同）——「双机互证」在本章的字面意义：同一
份 Δ 在两台机器上过同一套检查。

> **坑位速记**
> ① Prolog 应用链要完全嵌套：`a(a(a(x,b),u),v)`——写成
>   `a(a(x,b),u,v)` 是 `a/3`，db 无条款静默失败（21 章 ④ 的
>   复发，值得点名两次）；
> ② de Bruijn 语境压栈 = 统一坐标系全体上移（cutoff 0），不能
>   只移新条目、也不能按位置递增 cutoff——同一坑在本轮 Lean
>   与 Prolog 各现形一次；
> ③ 代换三分支（==j 换入 / >j 减一 / <j 不动）里「换入项由递归
>   按深度预抬」——β 步/应用规则若再手动 shift 一次就是双重
>   上移；旧代码「预移 + 无递减 + 外移 -1」是另一套自洽公式，
>   拆一半换一半必炸；
> ④ Church 式（显式类型应用）的世界里 `n f x` 要写成
>   `n X f x`——漏喂类型实参，定型挂、归约出垃圾 λ；
> ⑤ 手写 de Bruijn 的每一层子式各有坐标：域名检查不压栈、体
>   检查压栈——iet 的类型改了三遍才对齐（C 引用 var 1/var 2
>   各归各位）；
> ⑥ Lean `do` 块内定义局部函数用 `let f : T → T := fun …`，
>   不接受 `def`；core 无 `String.replicate`/`Char.repeat`，
>   拼 n 个字符用 `List.replicate` + `foldl`；
> ⑦ Lean `l[i]?` 可用而 `List.get?` 不存在（4.25 老坑的又一面）；
> ⑧ Prolog 把 `def_ok(D,E)` 写进 format 的参数表是【打印不
>   调用】——验电池时永远真调用，别拿 term 冒充查询。
