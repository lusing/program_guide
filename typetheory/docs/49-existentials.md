# 49 存在类型：抽象数据类型

> 对应读本：TAPL 书第 24 章（存在类型）。代码：
> `examples/49_existentials/ex49_existentials.pl`（存在包
> pack/unpack 的求值与定型、ADT 三样本：计数器的两种**表示**
> 同一接口、抽象的机器面见证）。

18 章的 System F 有 ∀（多态函数：对**每个**类型都工作的
函数）；它的对偶是 **∃**（抽象数据：**存在**一个表示类型，
但我**不告诉你**是哪个）。`{∃X, T}` 读作「有一个 X 使得 T」
——X 是被封装的秘密。

## 49.1 打包与开箱（书 24.1）

两条规则对偶于 ∀ 的两条：

> **T-Pack**：t : T[X↦S] ⊢ {S, t} as {∃X, T} : {∃X, T}
> （用表示类型 S 装配，**类型只剩接口**）
> **T-Unpack**：t₁ : {∃X, T} 且 x:X, X ⊢ t₂ : T₂ ⟹
> let {x, X} = t₁ in t₂ : T₂（开箱使用，X 的**名字不出现在
> t₂ 的类型里**——这正是抽象的强制性）

机器件的 pack 与使用：

```prolog
counter_nat(pack(natt, rcdobj([new=zero,
                               up=lm(x, natt, succ(vr(0))),
                               get=lm(x, natt, vr(0))]),
                 exists(counter, rcdt([new=natt, ...])))).

check("客户代码：get(up(new)) ⇓ 1（表示被隐藏）",
       ( counter_nat(P),
         Use = ap(lm(c, cnt, ap(prj(vr(0), get),
                           ap(prj(vr(0), up), prj(vr(0), new)))), P),
         steps(Use, [], succ(zero), _) )),
```

**表示被隐藏**不是口头承诺：pack 之后类型里只剩
`exists(counter, …)`——Nat 身份在类型层**不可见**，客户代码
写不出 `succ(c.new)`（接口里没有这个类型）。本章机器件以
「投影穿透包」的教学捷径直连接口（诚注记：真版的 T-Unpack
走 `let {x,X} = …`——机器件 typeof(unpackv) 亦备）。

## 49.2 ADT：抽象数据类型（书 24.2）

书 24.2 的核心论点：**存在类型是模块与 ADT 的类型论本质**。
样本族的机器兑现——**同一接口、两种表示**：

```prolog
/* 直存表示：内部就是 count */
counter_nat(pack(natt, rcdobj([new=zero,
                               up=…succ…, get=…恒等…]), …)).
/* 移位表示：内部存 count+1（new=1、get=前驱） */
counter_shifted(pack(natt, rcdobj([new=succ(zero),
                               up=…succ…, get=…pred…]), …)).
```

两个包**同接口类型**、客户代码**逐字节相同**、答案相同——
但内部表示语义不同（一个存 count、一个存 count+1）。
**「可以换表示而不动客户」**就是抽象的全部含义——模块系统
的**签名**（signature）是存在类型的工程化身，**密封**
（sealing）是 pack 的工程化身。书 24.2 的 Counter/Stack/
Dict 展示族与「表示独立性」（representation independence）：
客户能依赖的只有接口承诺，因此**任何**满足接口的实现都
可互换——这正是 52 章存在对象编码的地基。

## 49.3 存在量词编码（书 24.3）

与 21 章（λC 逻辑编码）的二阶 ∃ 编码会师：

> {∃X, T} := ∀Y. (∀X. T → Y) → Y

**读法**：「你给我一个对任何表示 X 都适用的处理器
∀X.T→Y，我就给你一个 Y」——CPS 风格的 double-negation
式编码。pack = λY. λh. h[S] t；unpack = 直接应用。书 24.3
证明编码忠实（两边的引入/消去规则互译）——**System F 的
∀ 已经包含了 ∃**，「抽象」最终可以还原为「多态」。51 章
Fω 与 52 章对象编码都站在这块地基上。

## 49.4 一页总结（本章的三个公式）

> 存在包 = 表示 + 接口：{S, t} as {∃X, T}——表示被类型层
> 封存。
> ADT = 存在类型的模块观：签名 = 接口、密封 = pack、
> 表示独立性 = 同接口可互换。
> ∃ 是 ∀ 的对偶（编码层面 ∃ ⊆ ∀）——抽象与多态是一对
> Curry–Howard 孪生。

> **坑位速记**
> ① 「装配型」文件里 λ 的参数个数（2 参还是 3 参）要**全局
>   一致**——isvalue/shift/subst/step/typeof 五张表任何一张
>   写错元数就是无声卡死（本批三连环：isvalue、AppAbs、
>   main 的 lm 全部踩过）；
> ② Prolog 类型检查器里**命名变量与 de Bruijn 索引混用**时，
>   typeof 要两条 var 子句（atom 查名表 / nat 查 nth0）——
>   只写一条是「半数项不可定型」的无声错；
> ③ pack 后的投影走**穿透规则**（教学捷径）或走真 unpack——
>   两者别混着写求值次序（穿透版客户项短一半）；
> ④ 客户代码的 λ 需要类型注释位占位（eval 不看、但构造子
>   元数要看）——占位类型名（cnt）随便起，别省。

## 49.5 与本书其他线的接口

- 21 章（λC 逻辑编码）的二阶 ∃ Church 版——同一对象两种
  居所（构造子版 vs 编码版）；
- 18 章 System F：∀ 的引入/消去与本章 ∃ 严格对偶——两个
  规则表并排是理解 F 的最快路径；
- 43 章 11.10 单字段变式（币种例）是 ∃ 的微缩版——「包装
  类型隐藏表示」在无量化时也能干活；
- 44 章引用 + 本章存在 = **命令式 ADT**（表示是 Ref）——
  46 章命令式对象的另一种装配法；
- 52 章纯函数对象：存在包 × 记录接口 × 固定点 = 对象三合一
  ——本章是其地基层。
