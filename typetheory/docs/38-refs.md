# 38 引用与异常：状态进入类型系统

> 对应读本：TAPL 书第 13 章（引用）与第 14 章（异常）。代码：
> `examples/38_refs/`——Prolog 件 `ex38_refs.pl`（带存储的抽象机
> 全套：位置/存储/存储类型三件 + 图 13.1 全部求值规则 + 异常
> 上浮与 try 捕获 + preservation 13.5.3 的机器面：求值全程良型、
> 存储一致、Σ 只增不减）、Coq 件 `ex38_refs.v`（精简语言上
> **保持定理 13.5.3 的完整机器证明**——结论的全新形状 ∃Σ′⊇Σ；
> 存储引理 13.5.5/13.5.6；T-Loc 逆转；典型形式）。

前 37 章的语言都是**纯的**：求值只算出值，不留痕迹。真实语言
有**副作用**——赋值、输入输出、异常、非局部跳转。本章把第一种
（可变引用）装进 λ 演算，看类型安全证明**哪个零件必须重造**；
第二种（异常）作为对照：它几乎不动证明的骨架。

## 38.1 三个操作与一个模型（书 13.1）

引用的基本操作：`ref`（分配）、`!`（反引用）、`:=`（赋值）。
ML 风格把**绑定**与**赋值**分开：`r = ref 5` 之后 `r : Ref Nat`
是指向一个单元的**指针**，`!r` 才是内容；C/Java 系反引用隐式。
**别名**是引用的威力与麻烦之源：

```text
r = ref 5;  s = r;  s := 82;  !r    ⇓    82
```

`s` 拷贝的是指针不是单元——两个名字指向同一单元，「隐式通信
通道」（共享状态）由此而来。书 13.1 的计数器对象（`incc/decc`
闭包共享一个 `c = ref 0`）是第 40 章命令式对象的预演——Prolog
件把它完整跑通：

```prolog
check("计数器：三次自增后 ⇓ 3",
       ( prog_count(3, P3), run(P3, succ(succ(succ(zero)))) )),
```

`prog_count` 逐层用 37 章的序列导出形式（`(λ_:Unit. t2) t1`）
把 N 次自增串起来——**每层 λ_ 绑定器把 r 的 de Bruijn 指数
加一**，深度逐层传递（见坑位⑤）。对函数的引用（`Ref (Nat→Nat)`
当「数组」用：查找 = 应用函数，更新 = 装入一个「if equal m n
then v else 旧函数 n」的新函数——书 13.1 的优雅把戏）机器面
留作章末练习。

## 38.2 求值关系的扩容：状态进入机器（书 13.3）

纯语言的求值是 `t → t′`；带存储后变成 **`t | μ → t′ | μ′`**——
机器状态 = 程序计数器（项）+ 存储内容。三个决策：

1. **位置抽象化**：引用 = 某个无解释位置集合的元素，存储 =
   位置到值的**部分函数**（Prolog 件用 `l-V` 对的列表，位置是
   自然数；Coq 件干脆用函数 `nat -> option tm`——见 38.6 的
   工程对比）。**不做指针算术**：这是刻意的——C 的指针算术
   正是类型安全的著名破坏者（位置 n 是 Float 说明不了 n+4
   是什么）。
2. **位置进入项的语法**（作为求值中间结果，程序员不写）。
3. **规则成对携带存储**：纯规则（β）存储原样带回；副作用
   规则改写它。

新规则六条（图 13.1）：同余三条 E-Ref/E-Deref/E-Assign1/2 +
计算三条 E-RefV（挑新位置、扩展存储）、E-DerefLoc（查表）、
E-Assign（写回 `[l↦v₂]μ`、返回 unit）。Prolog 件逐条对译：

```prolog
step(ref(V), Mu, loc(L), [L-V|Mu]) :-      % E-RefV
    isvalue(V), new_loc(Mu, L).
step(deref(loc(L)), Mu, V, Mu) :- mu_get(Mu, L, V).   % E-DerefLoc
step(assign(loc(L), V), Mu, unit, Mu1) :-  % E-Assign
    isvalue(V), mu_set(Mu, L, V, Mu1).
```

**垃圾回收不做**（存储只增不减）——不影响正确性（垃圾不再
可达），练习 13.3.1 问如何建模 GC、需要证什么定理。

## 38.3 存储类型：位置的类型从哪来（书 13.4）

「位置 l 的类型是什么？」——朴素答案「看 μ(l) 里值的类型」有
两个毛病：**重复计算**（l 出现 n 次就查 n 次，函数值含位置时
指数爆炸）与**循环卡死**（`l₁ ↦ λx.(!l₂)x, l₂ ↦ λx.(!l₁)x` 的
双链表没有有限推导）。解法是本章的发明：**存储类型 Σ**——
位置到类型的有限函数，**位置分配时定死、以后不再变**：

> T-Loc：Σ(l) = T ⊢ l : Ref T

直觉：「μ 是数据，Σ 是数据的规格说明」——就像 Γ 之于自由
变量（代换引理 9.3.8 的平行）。类型关系从三元 Γ⊢t:T 变
**四元** Γ|Σ ⊢ t : T。程序员写的项不含位置，用空 Σ 检查；
求值过程中每分配一个位置，Σ 就长一格。

## 38.4 安全性的新形状（书 13.5）

保持定理的结论**变了形状**——这是本章最重要的一个技术点：

> **13.5.3 保持**：Γ|Σ ⊢ t : T 且 t|μ → t′|μ′ 且 μ : Σ，
> 则**存在 Σ′ ⊇ Σ** 使 Γ|Σ′ ⊢ t′ : T 且 μ′ : Σ′。

朴素版「同 Σ」是错的：E-RefV 分配新位置后，μ′ 的定义域比
μ 大——Σ 必须**跟着长**。这个「类型环境只增不减」的形状此后
反复出现（44 章 F<: 的局部推断、及至分离逻辑的资源共享）。
Coq 件把这个定理**完整证明**（13 个情形：同余五条用归纳假设
+ Σ 弱化、E-RefV 显式构造 Σ′ = Σ + (l↦T₀)、E-DerefLoc 靠
一致性背书、E-Assign 靠更新引理、error 五条用 T-Error 秒收）：

```coq
Theorem preservation : forall t M t' M' S T,
  step t M t' M' -> has_ty S t T -> store_ok M S ->
  exists S', sig_ext S S' /\ has_ty S' t' T /\ store_ok M' S'.
```

两条配套引理：**13.5.5 更新保一致**（写回同型值，μ : Σ 不破）
与 **13.5.6 存储类型弱化**（Σ 变大，定型不变）。一致性
（13.5.1）`μ : Σ` 的函数版：凡 Σ 认定的位置，μ 都存着同型
的值。**进展**（13.5.7）骨架照旧，典型形式引理加一条：Ref 类
型的值必是位置（Coq 件 `canonical_ref`；完整进展定理的分配
新鲜性在函数表示下需要支撑有界性条件——机器面从略，Prolog
件的 `steps_safe` 以逐步检定代替）。Prolog 侧的对应：

```prolog
steps_safe(T, Mu, Sig) :-
    step(T, Mu, Tp, Mup),
    typeof(T, Sig, [], _),          % 每步良型
    ( typeof(Tp, Sig, [], _) -> Sigp = Sig
    ; extend_sigma(Mu, Mup, Sig, Sigp),   % 新位置→Σ 长一格
      typeof(Tp, Sigp, [], _) ),
    store_ok(Mup, Sigp),            % 存储一致
    sigma_le(Sig, Sigp),            % Σ 只增不减
    steps_safe(Tp, Mup, Sigp).
```

## 38.5 异常：几乎不动证明的效应（书 14）

异常的三级装配：**error 项**（图 14.1：error 可取任何类型
——T-Error 让类型不再唯一；求值规则 E-AppErr1/2 让它沿应用
栈上浮）、**try 捕获**（图 14.2：E-TryV/E-TryError/E-Try）、
**带值异常**（图 14.3：`error(v)`，处理器是函数）。求值的
确定性靠元变量的细心排布保住（E-AppErr2 用 v 不是 t——
`(fix λx.x) error` 发散而不是终止，练习 14.1.1 的话题）。
进展定理**改一句话**：封闭良型范式 = 值 **或 error**
（14.1.2）；保持照旧（T-Error 任意类型秒收）。error 的
「任意类型」在 39 章有归宿：子类型语言的 Bot、多态语言的
∀X.X——两种把无穷类型折成一个的紧致表示（15.4/16.4 的
预告）。Prolog 件全装配：

```prolog
step(ap(err, _), Mu, err, Mu).                        % E-AppErr1
step(tryw(err, H), Mu, H, Mu).                        % E-TryError
step(tryw(error(V), H), Mu, ap(H, V), Mu) :- isvalue(H).
```

带值异常的捕获走「应用」——处理器 λ 直接吃 error 携带的值
（E-TryErrorV 写成 `ap(H,V)`，β 规则接着干活——比手工代换
更诚实的一条工程捷径）。

## 38.6 机器面导读：函数表示 vs 列表表示

Coq 件的存储用**函数** `store := nat -> option tm`——
get/set 两条引理各缩成一行（`mu_set M l v l = Some v` 即
`rewrite Nat.eqb_refl`）。代价：E_RefV 的「挑新位置」失去
「存储有限」的默认支撑（函数的定义域可以无穷），进展定理的
分配一步需要额外的有界性条件——本件因此把进展的重活留给
列表版（练习方向），保持定理完整保留（它不依赖有限性）。
Prolog 件用列表 + `new_loc = length(μ)`——书 13.3 的原始
方案。**两种表示的取舍**（函数=证明便宜、列表=分配自然）
本身就是一课。

> **坑位速记**
> ① Prolog `loc(_)` 在 shift/subst 里写成**匿名变量**会把
>   位置偷换成未绑定变量（`deref(loc(_G123))` 卡死求值）——
>   命名 `loc(L)` 铁律；
> ② 往语言里加构造子（succ/error/try）时，**shift/subst/
>   isvalue/step/typeof 五张表全要同步**——漏一张就是神秘
>   stuck（本章实测：succ 漏 subst → 赋值参数不被代换）；
> ③ Prolog 主检定里**每个 check 用全新变量**（P1/P2/Q1…）——
>   复用 P 会让后续 `prog_x(P)` 与已绑定值冲突静默失败；
> ④ 关系型谓词（seqc(A,B,R)）当**构造子**用（seqc(A,B) 出现在
>   项里）不会展开——程序构造要直接写 `ap(lm(unitt,B),A)`；
> ⑤ 嵌套序列导出形式里 de Bruijn 指数**逐层 +1**——计数器
>   程序要带深度参数 K 生成（`incr_n(N, K, ...)`)；
> ⑥ E-TryError 的结果是**处理器项**（`try error with t2 → t2`）
>   不是 error——一步之差全书语义颠倒；
> ⑦ Coq 函数表示的存储让 `reflexivity` 不能用于 sig_ext
>   （非等式关系）——`split; [intros l T H; assumption|]`；
> ⑧ `eapply`+方括号在含 evar 的目标上乱序/搁浅——**显式
>   `apply (lemma A B _ _ H)` 钉死参数**是本件保命招；
> ⑨ Coq 项内 match 分支里别用 `.` 分隔战术——用 `;` 链或
>   把重活挪到 match 外的具名引理（本件 loc_type 的由来）；
> ⑩ `constructor` 在个别上下文里对无前提构造子（T_Err）
>   意外失灵（8.20 实测）——`apply T_Err` 显式指定最稳。

## 38.7 与本书其他线的接口

- 37 章的序列导出形式在此大量服役（计数器程序的主体）——
  导出形式方法学的第一次实战；
- 40 章命令式对象 = 本章引用 + 37 章记录 + 39 章子类型三件
  合体；46 章纯函数对象是它的存在类型镜像；
- 42 章类型重构与引用的组合产生 **值限制**（value
  restriction）——ML 系语言「为什么 let x = ref [] 不多态」
  的答案在书 13.6 的文献注记（Leroy/Weis/Wright 等）；
- 33 章（MLTT 子集类型）与本章 Ref 的对照：两种「类型携带
  约束」的路线——命题化的 {x : A | P} vs 状态化的 Ref T；
- 59 章元理论的「语义即关系 + 状态」主题在此预演：四元
  Γ|Σ ⊢ t : T 是「判断依赖环境」的第一例。
