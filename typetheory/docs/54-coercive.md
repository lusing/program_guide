# 54 强制性子类型：缩写机制的完整理论

> 对应读本：罗朝晖书 2.5.1（包含式子类型及其问题）、2.5.2
> （强制性子类型理论）；6.3.2（形式化与元理论）在 62 章

> 的插入与恢复、π1 投射子类型、**双投影强制的合谐性反例

33 章见过了强制子类型的工程面（Coq 的 `Coercion`/Lean 的
`Coe`）。本章讲**完整理论**——罗朝晖的招牌工作（与
Soloviev、罗勇、薛涛、Lungu 多年合作的 [126][149] 等）：
为什么「子类型」在现代类型论里不能是包含（2.5.1 的两个
反例），只能是**缩写**（2.5.2 的 CA/CD 双规则），以及整套
理论成立的关键前提——**合谐性（coherence）**。

## 54.1 子类型基本原理与两种世界观（书 2.5.1）

子类型的基本原理一句话：**A ≤ B 时，A 的每个对象均可视为
B 的对象而使用**。分歧在「视为」怎么实现——背后是 53 章
提过的 intrinsic/extrinsic 之争：

- **类型分派观**（程序语言学界，ML/Haskell 传统）：对象
  与类型独立存在，类型是事后贴的标签——一个对象有多个
  类型很自然。子类型 = **包含**：A 的对象本来就是 B 的
  对象。规则一条：
  > (SUB)　a : A，A ≤ B ⟹ a : B
- **规范对象观**（现代类型论学界）：对象与类型不可分割
  ——`2` 之所以存在是因为 `Nat` 被引入；归纳类型的引入
  规则**造出**了它的规范对象。由此有核心性质：
  > **规范性（canonicity）**：归纳类型的每个封闭对象都
  > 与某规范对象定义性相等。

包含式子类型配上现代类型论会怎样？**规范性崩**。书给两个
反例，都是「混进来的对象没有规范形式」：

**反例一（结构性子类型，例 2.10）**：规则 `A ≤ B ⟹
List(A) ≤ List(B)` 看似无害。但若 A、B 是不同类型，则
`nil(A) : List(A) ≤ List(B)`，而 `nil(A)` 与 `List(B)` 的
任何规范对象（`nil(B)`、`cons(B,b,…)`）都**不**定义性相等
——一个「无规范形式」的对象进了 List(B)。连锁反应：
等式反射性质（75 章元理论六律之一）也失效。

**反例二（投射性子类型，例 2.11）**：`Σx:Nat.P(x) ≤ Nat`
（「满足 P 的自然数」是 Nat 的子类型）。包含式下对象
`(0,p) : Σx:Nat.P(x)` 成了 Nat 的对象，但它与任何
`succⁿ(0)` 都不定义性相等——规范形式再次落空。

两条路都指向同一结论：**包含会改变类型的内容**；要让
子类型不伤规范性，就不能让 A 的对象「变成」B 的对象。

## 54.2 强制性子类型：A ≤c B 是缩写（书 2.5.2）

强制性子类型（coercive subtyping）的宣言：**子类型关系是
一种特殊的缩写机制**。`A ≤c B` 指：存在从 A 到 B 的
**强制转换（coercion）** c——一个「特殊的函数」，特殊在
**使用时可被省略**。两条规则（y 不在 f/c 中自由出现）：

> **(CA) 应用规则**：f(y):C(y)，a:A，A ≤c B ⟹ f(a) : C(c(a))
> ——需要 B 的地方放了 A 的对象 a，实际用的是映像 c(a)，
> 强制被省略。
> **(CD) 定义规则**：f(a) 与 f(c(a)) **定义性相等**——
> 省略的强制随时可以恢复。

对比 (SUB)：包含式让 `a : B` **直接成立**（a 真成了 B 的
对象）；强制式只让 `a` **用在 B 的位置上**（实际是 c(a)，
B 的对象集合分毫未动）。规范性无恙的原因就在这——B 若是
归纳类型，混进来的不是 a 本身而是 c(a)，而 c(a) 是 B 的
正经对象。

机器件里 CA/CD 全程可见。Coq 的 `Coercion` 系统就是强制
子类型的落地（书脚注：Coq、Lego、Matita、Plastic 均实现
了它）：

```coq
Record Boxed := mkBox { unbox :> nat }.   (* :> 字段即注册强制 *)
Definition b3 : Boxed := mkBox 3.
Compute (b3 + 1).          (* = 4：(CA) unbox 被省略 *)
Set Printing Coercions.
Check (b3 + 1).            (* unbox b3 + 1：(CD) 强制可恢复 *)
```

`Compute` 出来的 4 里**没有任何 Boxed 的痕迹**——「展开
后无痕」，保守性的机器面。

## 54.3 投射性子类型：包含式做不到的那一种（书 2.5.2 末）

强制式能表达包含式**无法**表达的东西。最典型的是投射性
子类型：`Man = Σx:Human.male(x)`（男人 = 男性的人——
书式 2.30），则

> Man ≤π1 Human　——强制转换就是第一投影 π1

机器件以 Coq 记录复刻（`man_of :> Human` 字段注册投影强制）：

```coq
Inductive Human := John | Mary.
Definition male (h : Human) : Prop := h = John.
Record Man := mkMan { man_of :> Human ; male_prf : male man_of }.
Definition john_man : Man.
Proof. refine (mkMan John _). reflexivity. Defined.
Check (is_john john_man) : Prop.   (* 论域 Human 收 Man 的对象 *)
```

`(john_man, …)` 是序对、`John` 是 Human 的构造子对象——
两者类型不同、永不定义性相等，包含式下「男对象是人对象」
无从谈起；强制式下这句话**自动成立**且展开无痕。书里
说这是 (SΣ) 规则的特例，也是 MTT 语义学「男人是人」（56 章
式 3.39）的理论根基。

## 54.4 合谐性：至多一条强制（书 2.5.2 + 定义 6.8）

强制转换的集合必须**合谐（coherent）**：任意两个类型之间
**至多一条**强制转换（A ≤c B 且 A ≤d B ⟹ c = d）。为什么？
若两条都合法，`f(a)` 该展开成 `f(c(a))` 还是 `f(d(a))`？
(CD) 的「定义性相等」就崩了——同一个表达式有两个不同的
「真身」。

书 2.5.3 脚注给了经典反例：若 π1 和 π2 **同时**是积类型的
强制转换，则 `Nat×Nat ≤π1 Nat` 且 `Nat×Nat ≤π2 Nat`，两条
强制显然不等——不合谐。所以 Σ 的结构强制里 π1、π2、dΣ
不能同时用（53 章 55 章会看到**记录类型**的 [ ]、Snd、d_R
却可以同时用——这是记录类型优于 Σ 的关键点）。

机器件做了本书（大概）最有说服力的实验——让 Coq 亲口
报警：

```coq
Set Warnings "-ambiguous-paths".
Record PairNN := mkPairNN { pnn_fst :> nat ; pnn_snd :> nat }.
```

注册第二个 nat 字段的 `:>` 时，Coq 发出：

> Warning: New coercion path [pnn_snd] : PairNN >-> nat
> is ambiguous with existing [pnn_fst] : PairNN >-> nat.

使用点 `Compute (S pp)` 默默选择了 `pnn_fst`——**系统
检测到歧义但不阻止**。这就是合谐性作为**理论前提**的
机器理由：Coq 把选择权交给实现细节，理论（定义 6.8）则
直接把它排除——只有合谐的 C 才有保守扩张定理（6.3.2
定理 6.4）：**T[C] 是 T 的保守扩张**，规范性、逻辑相容性
全部保持。合谐性不是美学偏好，是元定理的入场券。

## 54.5 结构性传播与机器边界（书 2.5.2 中段）

子类型关系通过类型构造算子**传播**。书给三条：

> (1) A ≤c B ⟹ List(A) ≤map(c) List(B)——映射逐点搬运；
> (2) A′ ≤c A，B ≤c B′ ⟹ A→B ≤f(c,c′) A′→B′——**逆变**
>     （论域反向，与 45 章记录/箭头子类型同构）；
> (Sp) A ≤c B ⟹ Σx:A.P(x) ≤dprop(c) Σy:B.P(y)——
>     dprop 把 (a,p) 映到 (c(a),p)，**证明原样搬运**。

机器件验证了 Coq 的边界：**(2) 的自动传播 Coq 没有**。
`count_boxes : list Boxed -> nat` 不能直接用在
`list nat -> nat` 的位置——`Coercion` 不做结构归纳，逐
实例要手写 `map unbox`：

```coq
Compute (count_nats (map_unbox [b3; mkBox 4])).  (* = 7：手工插 map *)
```

理论的传播规则是「存在即可」；实现（Coq）只保证原子
强制的自动插入。这条缝隙是使用 Coq 做语义编码时的实际
工作量来源（56 章会反复遇到）。

(Sp) 的 dprop 是**依赖性强制转换**（dependent coercion）
的实例——值域类型依赖输入值。机器件里：

```coq
Record BlackCatOf (c : Cat) := mkBCO { bco_prf : black c }.
Definition dprop (b : BlackCat) : BlackCatOf (cat_of b) :=
  match b with mkBC c p => mkBCO c p end.
```

`BlackCatOf (cat_of b)` 的类型里嵌着 b 的投影——第二分量
（黑性证明 p）原样搬运，与书 (Sp) 的 dprop 定义逐字对上。

## 54.6 一页总结（本章的三个公式）

> 包含式 (SUB) 让 a 真成 B 的对象——规范性崩（nil(A)、
> (0,p) 两反例：混入者无规范形式）。
> 强制式 (CA)(CD)：省略的插入、可恢复的相等——A ≤c B
> 是缩写，B 的对象集合分毫未动，保守扩张（定理 6.4）。
> 合谐性 = 任意两类型间至多一条强制——π1/π2 同注册即
> 不合谐（Coq 的 ambiguous-paths 警告是现场录音）。

> **坑位速记**
> ① 记录字段 `:>` 已经注册强制——再写 `Coercion unbox :
>   Boxed >-> nat.` 报「already a coercion」（本批实测）；
> ② 双 nat 字段记录触发 `ambiguous-paths` **警告**（不是
>   error）——build 以 stderr 非空为失败，须 `Set Warnings
>   "-ambiguous-paths"` 屏蔽并在注释里保留警告原文（教学
>   信息不丢）；
> ③ Coq 强制插入**只做原子层**——函数逆变/List 传播/
>   谓词传播都要手写对应函数（理论有、实现无的边界）；
> ④ `Set Printing Coercions` 是讲 CD 规则的教具——平时
>   关掉，不然 Check 输出全是投影；
> ⑤ 依赖性强制的值域写法：`BlackCatOf (cat_of b)` 里
>   `cat_of b` 依赖 b——match 分解记录后按分量重组，
>   别试图「修改」记录（Coq 记录没有函数式更新语法）。
