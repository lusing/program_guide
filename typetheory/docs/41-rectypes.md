# 41 递归类型：μ、归纳与余归纳

> 对应读本：TAPL 书第 20 章（递归类型简介）与第 21 章
> （递归类型元理论）。代码：`examples/41_rectypes/`——
> Coq 件 `ex41_rectypes.v`（**余归纳流 + 互模拟**：CoInductive/
> cofix 的卫式条件、bisim 的双展开原则、合成律与前缀守恒的
> 余归纳证明——书 21.1「归纳=最小、余归纳=最大」的机器版）、
> Prolog 件 `ex41_rectypes.pl`（μ 的按需展开、**限界子类型**
> 检查——21.5 成员检查算法的雏形、正则树的有限图见证）。

「NatList 是什么？」——诚实的答案是一个方程：
`NatList = <nil:Unit, cons:{Nat × NatList}>`。**递归类型**
让类型层面也允许解方程。两个立场：

- **等式递归**（equi-recursive）：μX.T **就是** T[μX.T/X]——
  展开是定义等式，类型系统直接看穿；
- **同构递归**（iso-recursive）：μX.T 与展开之间有 **fold/
  unfold** 两个显式函数——ML/SML 的 datatype 是这一派。

书 20 走等式路线（「更数学、实现更重」），21 章的元理论为其
补齐算法；ML 系语言实践走同构路线（编译器便宜）。本章机器
件两边都有化身。

## 41.1 实例与形式（书 20.1–20.2）

样本族（书 20.1）：`NatList`、`Hungry = μA. A→Unit`（饥饿
函数——吃自己不饱）、`Stream = μA. Unit→{hd:Nat, tl:A}`
（产一个头再产一个自己）。**子类型遇上 μ**（20.3）：宽度/
深度规则对无限树逐层成立——需要展开后比较，这把 39 章的
记录子类型推到无限对象上。

同构版的 fold/unfold（书 20.2 注记）：μX.T 装着「Roll/
Unroll」两个方向的函数，38 章 13.4 的「存储类型」讨论里
`μ` 已经偷偷出场过（自引用对象的类型）。**诚注记**：等式
版的「μX.T ≡ T[μX.T/X]」在 de Bruijn/名义表示下需要同构
版的 roll/unroll 支撑——Prolog 件的 unf 是等式读法的直译。

## 41.2 归纳与余归纳（书 21.1）——本章的心脏

书 21.1 的二重奏是全书最漂亮的两页之一：

- **归纳定义** = 规则集的**最小**不动点——「除了规则生成的
  之外什么都没有」；证明用归纳（对生成过程）；
- **余归纳定义** = 规则集的**最大**不动点——「规则不禁止的
  都可以」；证明用余归纳（**允许假设目标本身**，只要每步
  展开一层）。

**互模拟**（bisimulation）是余归纳的旗舰：两个无限对象
「相等」当且仅当每次观察都一致。Coq 件完整实现这套：

```coq
CoInductive Stream (A : Type) : Type :=
| SCons : forall (x : A) (r : Stream A), Stream A.

CoInductive bisim : Stream nat -> Stream nat -> Prop :=
| bisim_intro : forall s1 s2,
    hd s1 = hd s2 -> bisim (tl s1) (tl s2) -> bisim s1 s2.
```

证明的样板——**合成律**（map 双层 = 复合单层）：

```coq
Theorem smap_comp : forall f g s,
  bisim (smap f (smap g s)) (smap (fun x => f (g x)) s).
Proof.
  intros f g. cofix CH. intros [x r].
  apply bisim_intro.
  - reflexivity.
  - simpl. apply CH.        (* 尾巴回到同一目标——余归纳环 *)
Qed.
```

`cofix CH` 把「目标本身」借给你当归纳假设——**卫式条件**
（每个递归出现前至少消费一个构造子）保证这个环是「余归纳
的」而不是循环论证。**归纳×余归纳的协作**（bisim ⇒ 任意
有限前缀相等）是二重奏的合鸣：对前缀长度归纳、每层用
bisim 的两条腿。Coq 的 cofix 卫式检查正是书 21.1 余归纳
证明规则的机器化。

## 41.3 成员检查与正则树（书 21.4–21.8）

等式递归的子类型检查怎么做？朴素展开会死循环
（μX.X→X 展开无限层）。书 21.4–21.6 的路线：**去掉传递律**
（39 章同款手术）后，算法按需展开双侧到结构可比为止——
**成员检查**算法；21.6 给出高效版。Prolog 件是它的雏形——
深度限界的展开比较：

```prolog
rsub(S, T, _) :- S = T, !.                 % 结构相等优先短路
rsub(mu(X, B), T, D) :- D > 0, D1 is D - 1,
    unf(mu(X, B), U), rsub(U, T, D1).      % 左侧按需展开
rsub(S, mu(X, B), D) :- ...                % 右侧对称
```

**正则树**（21.7）：μ 类型 = **有限**表示的（无限）树——
子树只有有限多个（展开终将循环）。机器件用位串地址收集
子树、验证「深度加大而集合不增」——循环即有限图的机器
见证。**同构递归的子类型**（21.11，Amadio–Cardelli 算法）
以正则树为中介——两条路线在算法层合流。

## 41.4 一页总结（本章的三个公式）

> μ 的两读法：等式（μX.T ≡ T[μX.T/X]）vs 同构
> （fold/unfold 显式）——数学 vs 工程的分账。
> 归纳 = 最小不动点；余归纳 = 最大不动点——互模拟是后者的
> 相等观（每步观察一致 ⇒ 「就是同一个」）。
> 正则树 = 有限的无限树：成员检查按需展开 + 循环短路。

> **坑位速记**
> ① Coq `CoInductive` 构造子带类型参数时要 `Set Implicit
>   Arguments`（或 @ 显式）——`SCons 0 zeros` 否则把 0 当
>   类型参报错；
> ② cofix 证明里若归纳假设**没有普遍量化目标**（CH : 目标
>   本身而非 ∀s. 目标），destruct 后尾巴对不上——`cofix
>   CH` 放在 intros s 之前让 CH 带全称量词；
> ③ cofix 的卫式条件：递归调用必须出现在「至少消费一个
>   构造子」之后——直接 `exact CH`（不 destruct）只在
>   目标本身可循环时合法（zeros_map_id 的写法）；
> ④ Prolog 展开比较的**结构相等短路子句要排在 μ 展开
>   子句之前**——否则 μ=μ 的比较被不必要展开、深度燃料
>   白白耗尽（本批实测）；
> ⑤ Prolog 删「兜底子句」时注意：`rsub(_,_,_).` 的空体
>   = **永真**——它不是失败，是把整个关系变成真（本批
>   「假命题被拒」检查当场翻车的根因）；
> ⑥ 限界算法的燃料要按「每轮 μ 消耗 2–3 层」估——两侧
>   交替展开的循环每次烧掉多个燃料单位。
