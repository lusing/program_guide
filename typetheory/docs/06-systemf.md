# 06 System F（λ2）：类型也怕重复

> 对应读本：TTAFP 第 3 章（二阶 λ 演算）；TAPL 第 23 章。
> 代码：`examples/06_systemf/`——Lean（F 求值器 + 类型检查器 +
> Church 算术带类型复活）、Coq / Agda（多态 Church 数实例化到
> **真实数据**上：`cn 5 nat S 0 = 5`、`cn 4 bool negb true = true`）。

## 6.1 03 章的饥饿，两行语法解决

λ→ 的两个痛点——`I I` 不可类型化、`S K K` 要写两份——病根相同：
**一份代码不能有多种类型**。System F（Girard 1972；Reynolds 1974
独立发现，故也称多态 λ 演算）加两条语法：

```text
类型  T ::= … | ∀X. T                 （全称类型）
项    t ::= … | ΛX. t  |  t [T]       （类型抽象 / 类型应用）
```

两条新规则：

```text
Λ-引入：  Γ ⊢ t : T          (X ∉ FV(Γ))      类型 β：  (ΛX. t) [S] → t [X := S]
          ───────────────
          Γ ⊢ ΛX. t : ∀X. T

Λ-消去：  Γ ⊢ t : ∀X. T
          ───────────────                  （加上原有的 λ/应用三条，共八条）
          Γ ⊢ t [S] : T [X := S]
```

于是 `pid = ΛX. λ(x:X). x : ∀X. X → X`，要用时实例化：
`pid [nat] 3`、`pid [bool] true`——**一份代码，无限种类型**。
Lean 文件机器验证了 03 章的死案翻案：

```lean
example : inferClosed (app pidAtBB pidAtB) = some (arrow B B) := by rfl
-- pid [B→B] (pid [B]) : B → B —— I I 合法了
```

而 `λ(x:X). x x` 依旧不可类型化（F 的强规范化不允许 Ω）——多态
不是免检通道。

## 6.2 类型 β：第二台引擎

F 的计算有两层：

```text
(λ(x:T). b) a    →  b [x := a]         项 β（03 章那台）
(ΛX.  b) [S]     →  b [X := S]         类型 β（新）
```

Lean 实现里两台引擎住在同一个 `step` 里，但**代价不对称**：
项 β 要 de Bruijn 平移（变量绑定），类型 β 不用——`ΛX` 绑定的是
类型变量，**不占项的指标位**。第一次实现这里最容易画蛇添足
（在 `Λ` 下给 `shift`/`subst` 的截止位 +1 是错的——本文件的
一个注释专门立此存照）。

另一个工程要点：`tapp (Lam …) T → …` 是**本语义**的规则，不是
宿主语言（Lean/Coq/Agda）内核的 defeq。所以断言「化简后等于 pid」
必须两侧都过 `normalizeFuel`——直接比较 `tapp` 的原式和结果，
内核告诉它们「不可定义相等」。

## 6.3 Church 数复活：从无类型戏法到多态数据

02 章的 Church 数在无类型世界里是戏法（能跑但没类型）；03 章
里它们死了（单态写不出 `∀`）；在 F 里它们**浴火重生**：

```text
2 : ∀X. (X→X) → X → X
2 = ΛX. λ(f:X→X). λ(x:X). f (f x)
```

Lean 版照 02 章的测试单重跑一遍：`2+3→5`、`2×3→6`、`2^3→8`、
`2^5→32`，全部 `by rfl` 机器验证——这次的归约器同时开两台 β 引擎。

乘幂的实例化值得看一眼：`cexp = ΛX. λ(m:X→X). λ(n : C C X). n m`
（C X 记 (X→X)→X→X）。指数位 n 要实例化在 **C B** 上——比底数
「高一层」的类型。这是 F 表达力的第一瞥：**在任意类型上量化**，
包括由量化构成的类型（非直谓性，impredicativity）。

Coq / Agda 侧更进一步——把多态 Church 数实例化到**真实数据**：

```coq
Compute (cn 5 nat S 0).               (* = 5 *)
Compute (cn 5 bool negb true).        (* = false：翻转五次 *)
Compute (cn 3 (list nat) (map S) (0 :: nil)).   (* = [3] *)
```

```agda
cn : ℕ → ∀ {X : Set} → Ch X
_ : cn 5 suc zero ≡ 5        -- refl
_ : cn 5 not true ≡ false    -- refl
```

同一个 `cn 5`，在 ℕ 上是 5、在 Bool 上是 false、在表上是 [3]——
「数据 = 迭代次数」这个抽象，多态让它一次写完。

## 6.4 F 的元理论：强而贵

| 性质 | λ→ | System F |
|---|---|---|
| 强规范化 | ✓（逻辑关系法可证） | ✓（Girard 1972，**消去剪枝**法，难得多） |
| 类型检查可判定 | ✓ | ✓（Taranishi–Mairson 1987：完整推导类型是 2-EXPTIME 完全） |
| 主体归约 | ✓ | ✓ |
| 一致性（作为逻辑） | 命题逻辑片段 | 二阶直觉主义逻辑（带 ∃/∀ 编码） |

三条注脚：

1. **类型推断不可判定**：F 的类型检查（给定注解验证）可判定，
   但**重建注解**（elaboration）不可判定（Wells 1994）——这是
   ML 只做 `let` 层面 Hindley–Milner（F 的可判定片段）的深层原因。
2. ** Reynolds 悖论**：类型擦除到无类型 λ 演算时，F 的 β 会被
   捕获破坏（Reynolds 1986 直觉主义版）——「带类型的求值器」
   不是矫情，是必需。本实现的 `tsubstTm` 连注解一起换，就是
   不擦除的立场。
3. **参数化（parametricity）**：`∀X. X → X` 的封闭项只有恒等。
   Reynolds 抽象定理：多态项的行为**不由实例化类型挑拣**——
   「免费定理」的来源。Coq 文件里 `Compute (cn 5 nat S 0)` 与
   `cn 5 bool negb true` 行为同构（同样迭代五次），正是参数性的
   体验版。

## 6.5 F 之外：还缺什么

F 有了「项 → 类型」方向的依赖（类型里能量化类型变量），但：

- 类型里还不能出现**项**：造不出 `Vec A n`（长度随项变的列表）；
- 没有「类型依赖类型」的运算符（如 `List : Type → Type` 在 F 里
  只能靠 ∀ 曲线表达）。

把这两扇门打开，就到 λ 立方体的另外两条棱——07 章开「类型依赖
项」（λP，依赖类型的正门），08 章合流到 λC。

> **坑位速记**
> ① `ΛX` 绑定类型变量，**不占 de Bruijn 项位**——shift/subst 过
> `Λ` 时截止位与索引都不动（本文件初版 +1 是实测抓出来的）；
> ② `tapp (Λ) T →` 是语义规则不是内核 defeq——断言两侧都要
> normalize 再比；
> ③ Church 数实例化到容器时**起点非空**：`map suc` 迭代 n 次
> 从 `[]` 出发永远是 `[]`（Coq/Agda 侧同日双踩）；
> ④ Coq 的 `cadd` 吃**未实例化**的多态值（`cn 2` 而非 `cn 2 nat`），
> 已实例化的值类型是具体箭头，对不上 ∀；
> ⑤ Lean 的 `INST · B` 记号必须加括号 `(INST · B)` 或写成普通
> 函数——裸点记号在 def 体里解析不稳。
