# 39 抽象数据类型规格说明：模块即依赖多元组

> 对应读本：Nordström 书第 23 章（抽象数据类型规格说明——
> 模块、栈规格说明、参数模、带可计算相等性的模）。
> 代码：`examples/39_adtspec/ex39_adtspec.agda`——栈规格说明
> Σ 链全集与列表实现、参数模、CompEq 与 FSET 有穷集模。

全书理论线的最后一站。书 ch.1 的判断 `a ∈ A` 已有四种读法
（34 章）；本章加上第五种：**A 为模块规格说明、a 为模块规格
说明的实现**。模块（Guttag [47] 的抽象数据类型的推广）是
**依赖多元组**——一些集合、一些函数、一些常量，后面的分量
可以依赖前面的。数学里的例子是群 `(G,*,inv,u)`；程序里的
例子是栈。**模块理论 = Σ/Π 的应用层**——依赖多元组正是
Σ 的形状、「对任意元素集」正是 Π 的形状。

## 39.1 栈：规格说明即集合

书 23 的栈规格说明，全集照录（U 承担「小集合之集合」）：

```text
(Σ StackN ∈ U)
(Σ empty ∈ StackN)
(Σ push ∈ N × StackN → StackN)
(Σ pop  ∈ StackN → StackN)
(Σ top  ∈ StackN → N)
(Π t ∈ StackN)(Π n ∈ N)
   ([pop·empty =s t] × [pop·(push·⟨n,t⟩) =s t]
   × [top·empty =n 0] × [top·(push·⟨n,t⟩) =n n])
```

现代 Agda 版（U 层由 Set₁ 承担——31 章「宇宙账单」的实践）：

```agda
StackSpec : Set₁
StackSpec = Σ[ St ∈ Set ]
            Σ[ empty ∈ St ]
            Σ[ push ∈ (ℕ → St → St) ]
            Σ[ pop ∈ (St → St) ]
            Σ[ top ∈ (St → ℕ) ]
            ((t : St) (n : ℕ) → (pop (push n t) ≡ t)
                              × (top (push n t) ≡ n))

ListStack : StackSpec
ListStack = List ℕ , [] , (λ n t → n ∷ t) , tail′ , head′ , props
  where …
  props t n = refl , refl      -- 两条计算规则直折叠
```

**规格说明的语义就是元素集合的语义**（书 23 的原话）：这个
集合的每个元素必等于多元组 `⟨st,es,pu,po,to,p⟩`——st 是
U 的元素、es 是 st 的解码里的元素……最后的 p 分量只含
「前面的分量具有栈性质」的信息。与代数规格说明（Guttag 派）
表面相似、**语义完全不同**：代数规格说明的语义是项商掉等式
理论；类型论的语义是典则元及其相等——**实现就是元素**，
不存在「规格说明之后再造模型」的二层结构。不可满足的规格
说明也不出类型论的地盘：「结果仅是不可能找到它的实现，
有时甚至可以**说明**一个规格说明永不能被满足——通过证明
它等价于空集合」（件里 BadSpec 占位演示形状）。

## 39.2 计算相关与计算无关：子集合版的栈

书 23 中段把规格说明的末分量（性质证明 p）换进**子集合**：

```text
{⟨l',l'',l'''⟩ ∈ Reds×Whites×Blues | l ≈p l'@l''@l'''}   -- 38 章同款
```

栈版的动机：p 分量「从计算角度来看不会令人感兴趣」——它
只记录性质成立、不参与任何运算。换成子集合（约束位）后，
规格说明等于**五元组** ⟨st,es,pu,po,to⟩，性质「只写不读」。
这与 37 章 half 的 fst 提取、33 章子集合语义三处呼应——
**证明无关性的工程学**。

书随后点到一块诚实的前沿：「我们希望表示两个栈**观察地
相等**（不能被栈上任何运算区分）——这需要商集合形成运算
重新定义相等性。**这大概是此集合理论的一个大变化，我们
在此不再进一步探讨**。」——观察相等与商类型在 HoTT 线
（69 章 HIT 的商类型）才正式落地；55 章（罗朝晖轮）的
SEq 弱等同（「指针以下存储相等」）是工程折中的另一个样本。

## 39.3 参数模：Π 把「任意元素集」装进规格

书 23.1：A 元素的栈（对**任意** A）——规格说明直接用 Π
开头：

```agda
ParamStack : Set → Set₁
ParamStack A = Σ[ St ∈ Set ] Σ[ empty ∈ St ] Σ[ push ∈ (A → St → St) ]
               Σ[ pop ∈ (St → St) ] Σ[ top ∈ (St → A) ]
               ((t : St) (a : A) → (pop (push a t) ≡ t)
                                 × (top (push a t) ≡ a))

listStackParam : (A : Set) (d : A) → ParamStack A
listStackParam A d = List A , [] , (λ a t → a ∷ t) , tail′ , head′ , props
```

`st·ℕ` 是自然数栈、`st·(ℕ×ℕ)` 是数对栈——**实现是函数**，
作用于元素集得该元素集的栈实现。35 章「前提的形式化」
（X:Set）在这里变成产品特性：参数化不是元语言技巧，是类型
论内的 Π 应用。一个诚实的细节：书式 ℕ 栈的 `top·empty = 0`
条款依赖 0 这个 ℕ 的点——任意 A 无点可用，教学件给实现
多收一个缺省参数 `d : A`（`head′ [] = d`），参数版的规格
本身只保留 push 相关两条——**规格设计跟着类型依赖走**。

## 39.4 可计算相等模与有穷集模

书 23.2 的两层结构展示「模块吃模块」：先造**可计算相等性模**
（带判等的集合），再造**有穷集模**（FSET 作用于前者）：

```agda
CompEq : Set₁
CompEq = Σ[ X ∈ Set ] Σ[ e ∈ (X → X → Bool) ]
         ((x y : X) → (e x y ≡ true) → x ≡ y)

FSetSpec : CompEq → Set₁
FSetSpec (X , e , _) =
  Σ[ F ∈ Set ] Σ[ eset ∈ F ] Σ[ add ∈ (X → F → F) ] Σ[ mem ∈ (X → F → Bool) ]
  ((t : F) (a b : X) → (mem a eset ≡ false)
                    × (mem a (add b t) ≡ (if e a b then true else mem a t)))
```

「注意此规格说明**恰好表示出**关于函数 e 的需求，而任意
的 Bool 值函数将不会做到」——CompEq 的第三分量（判等正确性）
保证 e 不是任意的 Bool 函数。FSET 的 mem 性质是**递归条款**
（mem on add = 若 a=b 则 true 否则递归 mem）——它是关于
add/mem 联动的不变量，不是一次性的输入输出关系。用列表实现
（`listFSet`，mem 按判等扫描）两条性质全 refl——递归条款的
**定义等达成**。模块的分量依赖前分量（F 的类型依赖 X、mem
的性质依赖 e）——**依赖多元组的「依赖」贯穿始终**，这正是
55 章依赖记录类型的直系前身：Nordström 的 (Σ…)(Σ…) 链 +
Π 开头，就是 Luo 记录类型与 ML 模块系统的骨架。

## 39.5 全书收官的位置

至此 Nordström 线（27–39 章）完整走过：判断与规则
（27）→ 构造子世界（28–32）→ 子集与部分性（33）→ 框架与
历史（34）→ 类型层与单型重铸（35–36）→ 例子与提取（37）→
程序推导方法学（38）→ 模块规格说明（39）。书的四部分各自
落位：第一部分多型集合论（27–33 主体）、第二部分子集合
理论（33）、第三部分单型集合（35–36）、第四部分例子
（37–39）。从 40 章起进入证明助手实战线（四家对照与提取），
那正是 34 章工具谱系的下游——书与指南在此交棒。

> **坑位速记**
> ① `Σ[ push ∈ ℕ → St → St ]` **不解析**——Σ-syntax 是
>   prefix level 2、箭头比它松，槽内箭头必须括号
>   `Σ[ push ∈ (ℕ → St → St) ]`（本件八处连环补括号）；
> ② `x ≡ if c then a else b` 同理不解析——if_then_else 是
>   prefix level 0，与 ≡ 并列时**整体括号**；
> ③ 参数模块的空栈 top 要 A 的点——规格里凡依赖「类型的
>   具体元素」（top·empty=0 的 0）在参数化时要么弱化条款、
>   要么实现多收缺省参数（本件 d : A 的处理）；
> ④ Σ 链的第五分量（性质）类型是 `(t : St) (n : ℕ) → … × …`
>   ——多个量词直接串写（依赖前分量的量词**必须在** Σ 之内
>   说明依赖已由前四分量提供）。
