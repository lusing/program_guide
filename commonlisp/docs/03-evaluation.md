# 03 · 求值模型：Lisp 到底怎么读你的代码

> 配套示例：[`examples/03_evaluation/`](../examples/03_evaluation/main.lisp)（channel: both）
>
> 本章是全书的根基。Common Lisp 的语法事实上只有一个规则，但**读入**和**求值**
> 是两个独立步骤，混淆这两步是初学者 80% 困惑的来源。

## 3.1 只有一个语法规则：前缀表达式

一个表达式要么是**原子**（数字、字符串、符号），要么是**表**：`(` 开头、`)` 结尾，
里面可以是零个或多个表达式。

```lisp
(+ 1 2)          ; => 3
(+ 1 2 3 4 5)    ; => 15
(+)              ; => 0        （+ 的零元运算是 0）
(* 3 4)          ; => 12
```

函数名写在最前面，后面是实参。嵌套时也是同样的形状，**没有运算符优先级这回事**：

```lisp
(* (+ 1 2) (- 10 4))    ; => 18
```

`(+ 1 2)` 里的 `+` 是个**符号**（symbol），`1` 和 `2` 是**数字**。这听起来像废话，
但它是后面一切的基础——宏能存在，就是因为「代码」和「由符号与数字组成的列表」
是**同一种数据结构**。

三种简写要知道，它们会一直出现：

```lisp
(car (cdr '(1 2 3)))    ; => 2    ← 标准写法
(cadr '(1 2 3))         ; => 2    ← 缩写：a/d 序列从右往左读
(second '(1 2 3))       ; => 2    ← 可读性最好
```

## 3.2 读入与求值是两件事

**这是本章最重要的一节。**

REPL 的名字已经说明了流程：Read（读入）→ Eval（求值）→ Print（打印）。这两步是分开的，
中间的产物叫**形式**（form）。

`quote` 的作用就是「读入之后不要再求值」。它的简写是单引号——单引号本身是个**读取宏**：

```lisp
'(+ 1 2)              ; => (+ 1 2)    ← 原样返回这张表，没做加法
(quote (+ 1 2))       ; => (+ 1 2)    ← 同上，前者是后者的简写
(type-of '(+ 1 2))    ; => CONS       ← 它就是一个 cons 结构（07 章）
(eval '(+ 1 2))       ; => 3          ← 要它求值，得显式调 eval
```

因为读入先发生，引号可以套娃：

```lisp
''x                   ; => 'X         ← 外层引号阻止内层引号被求值
```

**这条性质有一个非常实际的后果**：一个形式在被求值之前，它里面的**所有**符号都已经定型了。
所以你**不能**在同一个形式里「先加载一个包，再用这个包里的符号」：

```lisp
;; 错的：读入整行时 SB-BSD-SOCKETS 还不存在，read 阶段就报错
(progn (require :sb-bsd-sockets) (sb-bsd-sockets:get-host-by-name "x"))
```

必须分成两个顶层形式（两行，或两次求值）：

```lisp
(require :sb-bsd-sockets)
(sb-bsd-sockets:get-host-by-name "localhost")
```

02 章的 `#+sbcl` / `#+clisp` 分发同理——它们就是读取器的一部分。

## 3.3 大小写：读入器把符号名变成大写

读入器默认把**未转义的小写字母转成大写**：

```lisp
(read-from-string "hello")             ; => HELLO
(symbol-name 'hello)                   ; => "HELLO"
'Hello                                 ; => HELLO
```

想保留大小写要用竖线转义（很少用，但要知道）：

```lisp
(read-from-string "|hello|")                    ; => |hello|
(symbol-name (read-from-string "|hello|"))      ; => "hello"
```

打印时的大小写由 `*print-case*` 控制，默认 `:upcase`（第 10 章动态重绑它的实战）。
这就是为什么打印出来的符号都是大写——**写小写是习惯，实际符号名是大写**。
字符串是数据，不受影响：`"Hello"` 里的就是字面的小写。

## 3.4 哪些东西自己就是自己的值

不用求值、直接得到自身的叫**自求值对象**：

```lisp
42        ; => 42
"abc"     ; => "abc"
#\a       ; => #\a       ← 字符（05 章）
:key      ; => :KEY      ← 关键字，永远自求值
t         ; => T         ← 真
nil       ; => NIL       ← 假，也是空表
(eq nil '())   ; => T    ← 空表就是 NIL
```

**`nil` 和空表是同一个对象**；而 `t` 只是「恰好」被用作真的符号——严格说 CL 里
**只有 `nil` 是假，其他任何东西都是真**（12 章实测 `0` 和 `""` 都是真）。

## 3.5 实参先算完再进函数

普通函数调用遵循「先求值所有实参，再调用」：

```lisp
(list (+ 1 1) (* 2 2))       ; => (2 4)               ← 传进去的是 2 和 4
(list '(+ 1 1) '(* 2 2))     ; => ((+ 1 1) (* 2 2))   ← 传进去的是两张表
```

实参的**求值顺序** ANSI 没有规定——别写依赖顺序的代码。想调用一个「直接写在调用位置的
函数」同样合法：

```lisp
((lambda (x) (* x x)) 6)     ; => 36
```

`#'` 是 `(function ...)` 的读取宏：取函数对象本身而不是调用它：

```lisp
#'car                        ; 函数对象，打印形态实现各异（别断言它的文本）
(functionp #'car)            ; => T
```

## 3.6 特殊形式、宏、函数：三种东西，三种时机

同样是 `(if t :yes :no)`，`if` 却**不能**先求值实参——那样两个分支都会被执行。
这类不走普通求值规则的叫**特殊形式**（special form）：

```lisp
(if nil (error "不会执行") :走了另一边)   ; => :走了另一边（else 分支没被求值）
```

怎么区分三者？看它们**什么时候**工作：

| 种类 | 例子 | 实参求值 | 何时生效 |
|---|---|---|---|
| 特殊形式 | `if` `let` `quote` `setf` | 不预先求值 | 编译器内建 |
| 宏 | `when` `unless` `loop` `defun` | 收到的是**未求值的代码** | **编译/展开期** |
| 函数 | `+` `car` `mapcar` | 先求值 | 运行期 |

用 `macroexpand-1` 现场看一次宏展开（拿**自己的**宏演示——理由见下）：

```lisp
(defmacro one-plus (x) `(+ ,x 1))
(macroexpand-1 '(one-plus 41))    ; => (+ 41 1)
(one-plus 41)                     ; => 42
```

## 3.7 eval 的代价

`eval` 在运行期构造/求值代码，无法被编译器优化，而且作用域是全局词法环境——
拿不到你的局部变量。本教程只在教学演示和 REPL 实现里用它（27 章会**不用 eval**
手写一个 eval）；写程序时几乎总有更好的选择（函数、闭包、宏）。

## 3.8 SBCL 与 CLISP 的差异速记

- `''x` 的打印：SBCL 只在 `*print-pretty*` 打开时才用 `'X` 缩写（默认开，REPL 里是 `'X`；
  `*print-pretty*` 为 nil 时打印 `(QUOTE X)`）；CLISP 无论开关都用 `'X`。
  想跨实现一致地打印代码，要么开 pretty，要么接受 `(QUOTE X)` 形态。
- 内置宏的**展开形态**是各家自由：`(macroexpand-1 '(when a b))` 在 SBCL 得
  `(IF A (PROGN B))`，CLISP 形态不同。调试看展开没问题，**程序逻辑别依赖它**
  （22 章的可移植性军规第 5 条）。
- 报错文本（`car 5` 的具体措辞）实现各写各的——别拿字符串匹配去处理错误，
  用条件类型（18 章）。

## 3.9 坑位清单

1. **未绑定的符号会报错，不是返回 nil**：
   ```lisp
   (car 5)          ; SBCL: The value 5 is not of type LIST
   (+ 1 "2")        ; SBCL: "2" is not of type NUMBER
   ```
   报错里带着**原始形式**——这是 Lisp 调试体验好的原因之一。
2. **引号容易漏，也容易多**：`(car (1 2 3))` 读入没问题，求值时会去找名为 `1` 的函数。
3. **括号数对不代表嵌套对**（本仓库实测踩过）：少一个 `)` 又多一个 `)` 会互相抵消，
   报错指向别处。写完先跑一遍静态检查：
   ```bash
   sbcl --noinform --non-interactive --no-userinit \
        --eval '(compile-file "x.lisp" :output-file "/tmp/c.fasl" :print nil :verbose nil)'
   ```
   注意：`compile-file` 只做静态兜底，**不能替代真跑**。
4. **`type-of` 的输出是实现细节**：`(type-of "ab")` SBCL 给 `(SIMPLE-ARRAY CHARACTER (2))`、
   CLISP 给 `(SIMPLE-BASE-STRING 2)`。做类型判断用 `typep`（13 章），别比对 type-of。
5. **读取期 vs 求值期**：`#+`、引号、`#\`、`,@` 全是读取期的；`if`/`let` 是求值期的。
   报「no such package」基本是把读取期的东西放到了求值期。
