# 17 · 流与文件 I/O

> 配套示例：[`examples/17_io/`](../examples/17_io/main.lisp)（channel: both）
>
> 示例在 `build/17_io.<通道>/` 下运行，相对路径自产自清。

## 17.1 写文件：with-open-file

```lisp
(with-open-file (out "note.txt" :direction :output
                                   :if-exists :supersede
                                   :if-does-not-exist :create)
  (write-line "第一行" out)
  (format out "格式化写入: ~D~%" 42))
```

`with-open-file` 保证**无论如何都关闭文件**（内部是 `unwind-protect`，12 章）：

| 参数 | 取值 | 含义 |
|---|---|---|
| `:direction` | `:input`（默认）/ `:output` / `:io` / `:probe` | 读写方向 |
| `:if-exists` | `:supersede` / `:append` / `:overwrite` / `:error` / `nil` | 已存在怎么办 |
| `:if-does-not-exist` | `:create` / `:error` / `nil` | 不存在怎么办 |
| `:element-type` | `'character` / `'(unsigned-byte 8)` | 文本还是二进制 |

## 17.2 读文件：三种读法

**整行读**（最常用）：

```lisp
(with-open-file (in "note.txt")
  (loop for line = (read-line in nil :eof)
        until (eq line :eof)
        collect line))
```

`(read-line in nil :eof)` 的两个参数是「EOF 时返回什么」和「EOF 时不报错」——
**不写它们，读到末尾会抛错误**。

**按 S 表达式读**——CL 的原生解析器直接把文本读回成数据：

```lisp
(read in)                        ; 读一个完整表单
(read-from-string "(+ 1 2) 剩余")  ; => (PLUS-MARK...)→ (+ 1 2)，第二值=停在哪
```

**整块读**（一次拿全部）——藏着本教程踩过的最阴的坑：

```lisp
(defun read-file-string (filename)
  (with-open-file (in filename)
    (let* ((buf (make-string (file-length in)))
           (filled (read-sequence buf in)))
      (subseq buf 0 filled))))
```

**`file-length` 返回的是字节数，不是字符数**。文件里有中文（UTF-8 一个汉字
3 字节）时按它分配 `make-string` 会过大，SBCL 用 `#\Nul` 填充多余位置——
一打印就把 NUL 字节漏进 stdout（退出码、stderr 全正常，肉眼翻不出来，
本仓库靠「无控制字符」判定抓住过 42 个 NUL）。**正确姿势：接住
`read-sequence` 的返回值（实际填充长度）再 `subseq`**。

## 17.3 二进制

`:element-type '(unsigned-byte 8)` 把流转成字节模式：

```lisp
(with-open-file (o "data.bin" :direction :output
                                :element-type '(unsigned-byte 8)
                                :if-exists :supersede)
  (write-byte 16 o)
  (write-sequence #(1 2 3 4) o))
(with-open-file (i "data.bin" :element-type '(unsigned-byte 8))
  (read-byte i)                          ; => 16
  (let ((buf (make-array 4 :element-type '(unsigned-byte 8))))
    (read-sequence buf i)))              ; => 4（填充数），buf = #(1 2 3 4)
```

`file-position` 双向可用：读位置、跳位置（`(file-position in 0)` 回开头）。

## 17.4 字符串流

测试里非常方便（不碰磁盘）：

```lisp
(with-input-from-string (s "42 hello (1 2 3)")
  (read s) (read s) (read s))          ; => (1 2 3)   ← 前两个读到 42 和 HELLO
(with-output-to-string (s)
  (format s "姓名:~A " "李雷")
  (format s "分数:~,1F" 92.5))         ; => "姓名:李雷 分数:92.5"
```

`with-output-to-string` 是「多段输出拼字符串」最干净的写法（05 章）。

## 17.5 路径名

路径名（pathname）是独立类型：目录 + 名字 + 类型 + 版本，各取各的：

```lisp
(pathname-name #P"/tmp/a/b.txt")        ; => "b"
(pathname-type #P"/tmp/a/b.txt")        ; => "txt"
(pathname-directory #P"/tmp/a/b.txt")   ; => (:ABSOLUTE "tmp" "a")
(namestring #P"/tmp/a/b.txt")           ; => "/tmp/a/b.txt"
(file-namestring #P"dir/sub/x.lisp")    ; => "x.lisp"
(merge-pathnames "x.txt" (make-pathname :directory '(:relative "data")))
; => #P"data/x.txt"   把「相对部分」合并到基座上
```

`probe-file` 返回**路径名对象**（truename），可当布尔用；不存在给 NIL。
注意它返回的是绝对路径（随机器/目录变化）——跨实现比对输出时只打
`file-namestring` 或 `(not (null ...))`（示例 17 的做法）。

`truename` 做规范化（消 `.` 段、解析符号链接）。**比较路径用 `equal` 比
`namestring`**，别用 `string=`（相对/绝对会不相等）。

## 17.6 目录操作

```lisp
(ensure-directories-exist "work/sub/")     ; 递归建目录；返回两值：路径 + 是否新建
(directory "work/*.*")                     ; 列目录（通配）
(delete-file "work/a.txt")                 ; 删文件（不存在会报错）
```

三个坑：

1. **`directory` 的返回顺序未规定**——要确定输出必须排序；
   且返回的是绝对路径，打印时取 `file-namestring`。
2. **通配是否匹配子目录两实现不同**（实测：SBCL 把 `work/sub` 也算进
   `*.*` 的匹配、`file-namestring` 得 `""`；CLISP 不算）——过滤掉
   `(remove-if-not #'pathname-name files)` 再用。
3. **ANSI 没有可移植的「删目录」**——删除目录是扩展（SBCL 走 sb-posix:rmdir，
   CLISP 走 ext:delete-dir）。示例只清理自己生成的文件。

**`rename-file` 的第二参数是「目标的默认路径成分」，不是完整目标**：

```lisp
(rename-file "work/b.txt" "work/renamed.txt")
; 报错！目录被拼两遍：work/work/renamed.txt
(rename-file "work/b.txt" "renamed.txt")     ; 纯文件名：落在源文件旁 ✓
(rename-file "work/b.txt"
             (merge-pathnames "renamed.txt" (truename "work/")))   ; 显式目录 ✓
```

（`truename` 目录末尾必须带 `/`，否则目录被当成文件名解析。）

## 17.7 坑位清单

| 症状 | 原因 | 解法 |
|---|---|---|
| stdout 混进一堆 NUL | file-length 是字节数按字符数用了 | 接 read-sequence 返回值 |
| read-line 到末尾报错 | 没给 EOF 参数 | `(read-line in nil :eof)` |
| read-from-string 第二值两实现不同 | SBCL 指未读首字符、CLISP 指已读末字符 | 别拿它做逻辑 |
| directory 输出顺序/内容不稳 | 顺序未规定 + 子目录匹配差异 | 排序 + 过滤 pathname-name |
| rename-file 报目录不存在 | 第二参数带相对目录被拼两遍 | 纯文件名或 merge-pathnames+truename |
| 目录路径没带 `/` | 被当文件名解析 | 目录末尾加 `/` |
| 删目录代码换实现就崩 | ANSI 无删目录 | 文件自清理；目录留实现扩展 |
