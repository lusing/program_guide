# 13 · OOP II：继承与多态

> 对应示例：`examples/13_oop2/`

## 13.1 基本继承

```freebasic
Type Shape Extends Object            ' 有虚方法就必须（直接或间接）继承 Object
    Protected:
        Dim As String label
    Public:
        Declare Constructor()
        Declare Constructor(label_ As String)
        Declare Abstract Function area() As Double
        Declare Virtual Function describe() As String
End Type

Type Rect Extends Shape
    Protected:
        Dim As Double w, h
    Public:
        Declare Constructor(w As Double, h As Double)
        Declare Function area() As Double Override
End Type

Constructor Rect(w As Double, h As Double)
    Base("矩形")                      ' 调基类构造器
    This.w = w : This.h = h
End Constructor

Function Rect.area() As Double
    Return w * h
End Function
```

三条铁律（全部实测）：

| 规则 | 说明 |
|---|---|
| **要虚方法先 `Extends Object`** | 多态类型体系的根；显式写出来 |
| **`Override` 只写在 Declare 行** | 函数体定义行（`Function Rect.area()...`）再写 `Override` 是编译错误 |
| **`Virtual` 修饰的是基类声明** | 派生类实现不用再标 `Virtual`（标了也不报错，但没必要）；`Base.describe()` 可显式调基类版本 |

## 13.2 Abstract：抽象方法与"抽象类"

```freebasic
Declare Abstract Function area() As Double
```

- 含 `Abstract` 方法的 Type **不能实例化**——`Dim x As Shape` 直接编译错（"UDT has unimplemented abstract methods"），这就是 FB 的抽象类机制（没有单独的 `MustInherit` 关键字）。
- 派生类必须实现全部抽象方法，否则它自己也不能实例化。
- `Virtual` 方法有默认实现可被改写；`Abstract` 方法没有实现必须被改写。

## 13.3 多态：基类指针 + 动态派发

```freebasic
Dim As Shape Ptr shapes(1 To 3)
shapes(1) = @r                        ' 栈对象取址
shapes(3) = New Rect(2, 5)            ' 堆对象

For i As Integer = 1 To 3
    Print shapes(i)->describe()       ' 按实际类型派发到对应实现
    total += shapes(i)->area()
Next

Delete shapes(3)                      ' New 的配对 Delete
```

`->` 解引用 + 访问字段/方法；虚派发看的是**实际对象**不是指针类型。

## 13.4 基类没有默认构造器时的拷贝陷阱 ⭐

实测（error 188）：基类只有带参构造器时，派生类 `Dim r As Rect = Rect(3,4)` 这种**初始化语法会触发隐式拷贝构造**，而它无法初始化无默认构造器的基类——编译直接失败。两个解法：

1. **给基类补一个默认构造器**（本教程示例的做法，简单直接）；
2. 为派生类显式写拷贝构造 `Declare Constructor(ByRef rhs As Const Rect)`。

## 13.5 设计口味

- FB 的 OOP 是"够用的 OOP"：单继承、无接口（interface）语法——抽象基类当接口用。
- 无 RTTI 的 `dynamic_cast`/`is`；需要类型判别就自己在基类放个 `id` 或虚方法。
- 值语义拷贝是浅拷贝：UDT 里含 `Ptr` 字段时，拷贝出来的是**共享指针**——深拷贝自己写（或用 14 章的 `Let` 运算符定制赋值）。

## 13.6 坑位清单（1.10.1 实测）

1. `Extends Object` 是虚方法的前置条件；忘写编译报错。
2. `Override` 只在 `Declare` 行合法；体定义行带 `Override` 报"Expected End-of-Line"。
3. 基类无默认构造器 → 派生类初始化语法报 error 188（见 13.4，补默认构造器）。
4. 抽象方法未实现就实例化 → "UDT has unimplemented abstract methods"。
5. `Const` 方法修饰符与 `Abstract` 组合解析不过（`Declare Abstract Const Function` 语法错误）——FB 1.10 的 Const 方法别用在抽象/虚方法上。
6. 多态数组用基类 `Ptr`；`New`/`Delete` 配对，否则泄漏。
